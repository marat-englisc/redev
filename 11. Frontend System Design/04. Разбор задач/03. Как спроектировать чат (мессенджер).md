# Как спроектировать чат (мессенджер)

> [!NOTE]
> **Чат** — задача на realtime и надежность: список бесед, история сообщений с прокруткой вверх, отправка с мгновенным отображением, статусы «отправляется → отправлено → прочитано», индикатор «печатает», непрочитанные, работа при обрывах сети. Ключевые решения: **WebSocket** для двусторонних событий, **нормализованное хранилище** сообщений, **оптимистичная отправка с clientId**, **очередь неотправленных** сообщений, **догоняющая синхронизация** после переподключения и **обратная виртуализация** (лента растет вверх).

## Вопрос

Как спроектировать фронтенд чата? Как организовать realtime, отправку сообщений без потерь, историю и работу при плохой сети?

## R — требования

- список бесед с последним сообщением и счетчиком непрочитанных;
- история сообщений с подгрузкой старых при прокрутке вверх;
- отправка текста (вложения — кратко), статусы доставки и прочтения;
- «печатает…», онлайн-статус;
- нефункциональные: задержка доставки < 1 с, без потерь при обрыве сети, несколько вкладок, уведомления, a11y.

## A — архитектура

```text
<ChatApp>
 ├─ <ConversationList>       виртуализированный список бесед
 └─ <ConversationView>
      ├─ <MessageList>        обратная виртуализация, подгрузка вверх
      ├─ <TypingIndicator>
      └─ <Composer>           черновик в localStorage, отправка по Enter

Data layer
 ├─ REST: история, список бесед (cursor-пагинация)
 ├─ WebSocket-клиент: события new/updated/read/typing, переподключение
 ├─ Store: нормализованные беседы, сообщения, пользователи
 └─ Outbox: очередь неотправленных (IndexedDB)
```

## D — модель данных

```typescript
type Message = {
  id: string | null;             // серверный id, null пока не подтверждено
  clientId: string;              // uuid, создается на клиенте
  conversationId: string;
  authorId: string;
  text: string;
  createdAt: string;             // серверное время после подтверждения
  status: "sending" | "sent" | "delivered" | "read" | "failed";
};

type ChatStore = {
  conversations: Record<string, Conversation>;
  messages: Record<string, Message>;              // ключ — clientId
  messageOrder: Record<string, string[]>;         // conversationId → clientId[]
  lastEventId: string | null;                     // для догоняющей синхронизации
};
```

## I — интерфейс

```http
GET /api/conversations?cursor=...
GET /api/conversations/:id/messages?before=<messageId>&limit=50
```

```jsonc

```

## O — оптимизации

**Отправка без потерь:**

```text
1. Пользователь нажал «Отправить»
2. Сообщение с clientId и status="sending" сразу в UI и в outbox (IndexedDB)
3. Отправка по WebSocket (или HTTP fallback)
4. ack от сервера → id и createdAt, status="sent", удалить из outbox
5. нет ack за N секунд / соединение упало → повтор с тем же clientId
6. после K попыток → status="failed", кнопка «Повторить»
```

`clientId` делает отправку идемпотентной: сервер не создаст дубль при повторе.

**Realtime и переподключение:**

- WebSocket с heartbeat, переподключение с backoff + jitter;
- после переподключения — запрос событий с `lastEventId` или перезагрузка последних сообщений активной беседы;
- дедупликация по `id`/`clientId`, сортировка по серверному времени;
- одно соединение на все вкладки (`SharedWorker` или выбор «лидера» через `BroadcastChannel`), остальные получают события через канал.

**История и прокрутка:**

- обратный список: новые снизу, подгрузка старых при прокрутке к верху (cursor `before`);
- сохранять позицию при подгрузке сверху (компенсировать высоту добавленного) — react-virtuoso умеет это;
- автопрокрутка вниз только если пользователь уже внизу; иначе — кнопка «Новые сообщения ↓».

**Прочее:**

- «печатает» — throttle отправки события (раз в 2–3 с), скрытие по таймауту;
- уведомления: Notification API при скрытой вкладке, счетчик в `document.title`, Web Push для закрытой;
- черновики для каждой беседы в `localStorage`;
- вложения — загрузка заранее по presigned URL, в сообщении только ссылка;
- a11y: новые сообщения через `aria-live="polite"` (только во входящей беседе), Enter — отправка, Shift+Enter — новая строка;
- безопасность: текст выводится как текст (без HTML), ссылки — с `rel="noopener noreferrer"`.

## Что важно помнить

- Главные темы: WebSocket и переподключение, оптимистичная отправка с clientId и ack, outbox, догонка пропущенных событий, обратная прокрутка.
- Время и порядок берутся с сервера: часы клиента могут отставать.
- Обновление статуса «прочитано» отправляйте пачкой «прочитано до id», а не по каждому сообщению.
- Связанные темы: [realtime](<../02. Архитектура и данные/05. Как выбрать способ realtime - polling, SSE или WebSocket.md>), [надежность и офлайн](<../03. Нефункциональные требования/03. Как обеспечить надежность, обработку ошибок и офлайн.md>).

## Мини-шпаргалка

REST — история и беседы, WebSocket — события. Нормализованный store, сообщения по clientId. Отправка: optimistic → outbox → ack → status; повтор с тем же clientId. Переподключение + `lastEventId`. Обратная виртуализация, автоскролл только у низа. Typing — throttle. Уведомления, черновики, aria-live.
