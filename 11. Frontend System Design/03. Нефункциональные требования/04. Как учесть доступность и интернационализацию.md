# Как учесть доступность и интернационализацию

> [!NOTE]
> **Доступность (a11y)** и **интернационализация (i18n)** закладываются в архитектуру, а не добавляются в конце. Для a11y важны семантическая разметка, работа с клавиатуры, управление фокусом, ARIA для нестандартных виджетов и объявление динамических изменений скринридеру. Для i18n — вынос текстов в словари, форматирование через `Intl`, поддержка RTL (логические свойства CSS), разная длина строк и локаль в URL. На интервью достаточно показать, что вы думаете об этом при проектировании каждого компонента.

## Вопрос

Как учесть доступность и интернационализацию при проектировании фронтенд-системы? Что сказать про a11y для сложных виджетов вроде автокомплита, модалки или бесконечной ленты?

## Доступность: что проговорить

| Аспект | Решение |
| --- | --- |
| Семантика | `button`, `a`, `nav`, `main`, `h1–h6`, `ul/li`, `form/label` вместо `div` с `onClick` |
| Клавиатура | все действия доступны через Tab, Enter, Space, Esc, стрелки в виджетах |
| Фокус | видимый `:focus-visible`; ловушка фокуса в модалке и возврат после закрытия |
| ARIA | роли и состояния для кастомных виджетов: `combobox`, `listbox`, `dialog`, `tablist` |
| Объявления | `aria-live` для новых сообщений, результатов поиска, ошибок |
| Контраст и размер | WCAG AA: 4,5:1 для текста, цели касания от 24×24 |
| Движение | `prefers-reduced-motion` |
| Медиа | `alt` у изображений, субтитры у видео |

## a11y в типовых задачах

| Задача | Ключевые моменты |
| --- | --- |
| Автокомплит | паттерн combobox: `role="combobox"`, `aria-expanded`, `aria-activedescendant`, стрелки и Enter, объявление числа результатов |
| Модалка | `<dialog>` или `role="dialog"` + `aria-modal`, фокус внутрь, Esc закрывает, фокус возвращается на кнопку |
| Бесконечная лента | `role="feed"` и `article` с `aria-setsize`/`aria-posinset`, кнопка «Загрузить еще» как альтернатива автоподгрузке, футер остается достижимым |
| Чат | новые сообщения через `aria-live="polite"`, не перебивать пользователя |
| Карусель | кнопки пауза и «далее», нет автопрокрутки без остановки |

## Интернационализация: что проговорить

- тексты — в словарях по ключам (react-i18next, FormatJS), без склейки фраз из кусков;
- числа, даты, валюты, множественное число — через `Intl` и ICU MessageFormat;
- локаль в URL (`/en/catalog`) для SEO и ссылок, `hreflang`, `<html lang>`;
- RTL: `dir="rtl"`, логические свойства CSS (`margin-inline-start`), зеркальные иконки;
- верстка выдерживает длинные строки (немецкий на 30% длиннее английского);
- ленивая загрузка словарей по языку, чтобы не грузить все переводы сразу;
- часовые пояса: хранить UTC, показывать в зоне пользователя.

## Пример ответа

> «Автокомплит сделаю по паттерну WAI-ARIA combobox: стрелки двигают активный вариант через `aria-activedescendant`, фокус остается в поле, Esc закрывает список. Количество результатов объявляю через `aria-live`. Тексты интерфейса — в словарях, подсветка совпадения не ломает RTL.»

## Что важно помнить

- Нативный элемент лучше ARIA: `<button>` доступен из коробки, `div role="button"` требует ручной работы.
- Проверка: клавиатура, скринридер (NVDA, VoiceOver), axe DevTools, Lighthouse.
- i18n влияет на архитектуру: роутинг, загрузку словарей, SSR (локаль на сервере), кеш по локали.
- Не забывайте про hydration mismatch из-за форматирования дат в разных часовых поясах.

## Мини-шпаргалка

a11y: семантика, клавиатура, фокус, ARIA для кастомных виджетов (combobox, dialog, feed), `aria-live`, контраст, reduced motion. i18n: словари и ICU, `Intl`, локаль в URL, RTL и логические свойства, длинные строки, ленивые словари, UTC.
