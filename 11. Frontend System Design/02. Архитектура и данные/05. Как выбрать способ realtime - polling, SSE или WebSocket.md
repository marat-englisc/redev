# Как выбрать способ realtime: polling, SSE или WebSocket

> [!NOTE]
> Для обновлений «в реальном времени» есть четыре основных способа: **short polling** (клиент спрашивает сервер каждые N секунд), **long polling** (сервер держит запрос открытым до появления данных), **Server-Sent Events** (односторонний поток событий от сервера по HTTP) и **WebSocket** (постоянный двусторонний канал). Выбор зависит от того, **как быстро** нужны обновления, **кто отправляет** данные (только сервер или обе стороны) и **сколько** их.

## Вопрос

Как выбрать между polling, long polling, SSE и WebSocket на system design интервью? Как обработать переподключение и пропущенные события?

## Сравнение

| | Short polling | Long polling | SSE | WebSocket |
| --- | --- | --- | --- | --- |
| Направление | клиент → сервер | клиент → сервер | сервер → клиент | двустороннее |
| Задержка | до интервала опроса | низкая | низкая | минимальная |
| Нагрузка | много пустых запросов | держит соединения | одно соединение | одно соединение |
| Протокол | HTTP | HTTP | HTTP (`text/event-stream`) | свой поверх TCP после Upgrade |
| Переподключение | не нужно | вручную | автоматически, `Last-Event-ID` | вручную |
| Простота | максимальная | средняя | высокая | ниже: свой протокол сообщений |
| Через прокси и CDN | без проблем | обычно ок | обычно ок | нужна поддержка Upgrade |

## Что выбрать

| Задача | Решение |
| --- | --- |
| статус заказа, обновления раз в минуту | short polling (или refetch по фокусу окна) |
| уведомления, новые посты в ленте, прогресс задачи | SSE |
| чат, совместное редактирование, игры, курсоры других пользователей | WebSocket |
| редкие события при закрытой вкладке | Web Push |

## Надежность соединения

```typescript
function connect(url: string, onMessage: (e: ServerEvent) => void) {
  let ws: WebSocket;
  let attempt = 0;
  let lastEventId: string | null = null;

  const open = () => {
    ws = new WebSocket(`${url}?since=${lastEventId ?? ""}`);   // догнать пропущенное
    ws.onopen = () => { attempt = 0; };
    ws.onmessage = (msg) => {
      const event = JSON.parse(msg.data) as ServerEvent;
      lastEventId = event.id;
      onMessage(event);
    };
    ws.onclose = () => {
      const delay = Math.min(30_000, 1000 * 2 ** attempt++) * (0.5 + Math.random()); // backoff + jitter
      setTimeout(open, delay);
    };
  };

  open();
  return () => { ws.onclose = null; ws.close(); };
}
```

Обязательные элементы:

- **переподключение** с экспоненциальной задержкой и jitter — чтобы все клиенты не переподключились одновременно после сбоя;
- **догоняющая синхронизация**: после переподключения запросить события с последнего `id` или перезагрузить данные;
- **heartbeat** (ping/pong) — обнаружить «зависшее» соединение;
- **дедупликация** событий по id и порядок по серверному времени или номеру последовательности;
- пауза или снижение частоты в фоновой вкладке (`document.visibilityState`).

## Совмещение с кешем

Realtime-событие обновляет тот же кеш, что и обычные запросы:

```typescript
socket.on("message:new", (msg) => {
  queryClient.setQueryData(["messages", msg.conversationId], (old) => appendUnique(old, msg));
});
```

Альтернатива — событие только сигнализирует «что-то изменилось», а клиент делает `invalidateQueries` и перезапрашивает данные.

## Что важно помнить

- Начинайте с самого простого варианта, который удовлетворяет требованиям; WebSocket — не решение по умолчанию.
- SSE достаточно, если клиент только получает данные: отправку делают обычными HTTP-запросами.
- На HTTP/1.1 браузер ограничивает число соединений к домену — это важно для SSE в нескольких вкладках; HTTP/2 решает проблему. Можно также держать одно соединение на все вкладки через `SharedWorker` или `BroadcastChannel`.
- WebSocket на нескольких серверах требует общего канала рассылки (Redis pub/sub) и иногда sticky sessions.
- Связанные темы: [WebSocket](<../../04. JavaScript/05. Асинхронность и Event Loop/21. Как работает WebSocket.md>), [SSE](<../../08. Node/13. Сеть, HTTP углубленно и WebSocket/07. Что такое Server-Sent Events.md>).

## Мини-шпаргалка

Редко и просто — short polling. Только сервер → клиент — SSE. Двусторонне и быстро — WebSocket. Закрытая вкладка — Web Push. Всегда: переподключение с backoff и jitter, догонка по `lastEventId`, heartbeat, дедупликация, обновление общего кеша.
