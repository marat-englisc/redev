# Как спроектировать модель данных и состояние клиента

> [!NOTE]
> На шаге Data model определяют **сущности** клиента и их поля, разделяют **серверное состояние** (данные с API — кешируются и синхронизируются) и **клиентское** (UI, черновики, выбор пользователя), решают, что хранить **нормализованно**, что — в **URL**, что — **локально на устройстве**. Хорошая модель минимальна: производные значения вычисляются, а каждая сущность хранится в одном месте.

## Вопрос

Как спроектировать модель данных на клиенте? Как разделить серверное и клиентское состояние, когда нормализовать данные и что хранить в URL?

## Сущности

Пример — чат:

```typescript
type User = { id: UserId; name: string; avatarUrl: string; online: boolean };

type Conversation = {
  id: ConversationId;
  title: string;
  participantIds: UserId[];
  lastMessageId: MessageId | null;
  unreadCount: number;
};

type Message = {
  id: MessageId;              // для неотправленных — временный clientId
  conversationId: ConversationId;
  authorId: UserId;
  text: string;
  createdAt: string;          // ISO, с сервера
  status: "sending" | "sent" | "delivered" | "read" | "failed";
};
```

## Виды состояния

| Вид | Пример | Где хранить |
| --- | --- | --- |
| Серверное | беседы, сообщения, профили | кеш запросов (TanStack Query, RTK Query) или нормализованный store |
| Клиентское UI | открыта ли панель, выбранная беседа | `useState`, локальный store |
| URL | `/chat/:conversationId`, фильтры, поиск | роутер, `searchParams` |
| Формы и черновики | текст неотправленного сообщения | состояние формы + `localStorage` |
| Сессия | текущий пользователь, токен | httpOnly cookie, контекст |
| Офлайн-данные | история для работы без сети | IndexedDB |

## Нормализация

```typescript
type ChatState = {
  users: Record<UserId, User>;
  conversations: Record<ConversationId, Conversation>;
  messages: Record<MessageId, Message>;
  messageIdsByConversation: Record<ConversationId, MessageId[]>;  // порядок
};
```

Нормализуйте, если:

- одна сущность встречается в нескольких местах (автор в сообщениях, списке участников, шапке);
- данные часто обновляются точечно (статус сообщения, онлайн пользователя);
- приходят realtime-события по id.

Для простой ленты «только чтение» достаточно массивов в кеше запросов.

## Производные данные

Не храните то, что можно вычислить:

```typescript
// плохо: хранить unreadTotal отдельно и синхронизировать вручную
// хорошо: селектор
const selectUnreadTotal = (s: ChatState) =>
  Object.values(s.conversations).reduce((sum, c) => sum + c.unreadCount, 0);
```

## Что хранить в URL

- текущий экран и выбранную сущность (`/products/42`);
- фильтры, сортировку, поиск, страницу — чтобы можно было поделиться ссылкой и вернуться «назад»;
- открытую вкладку или модалку, если на нее дают прямую ссылку.

Не храните в URL секреты и большие объекты.

## Локальное хранение

| Хранилище | Объем | Для чего |
| --- | --- | --- |
| `localStorage` | ~5 МБ, синхронный | настройки, маленькие черновики |
| `sessionStorage` | ~5 МБ, вкладка | временное состояние вкладки |
| IndexedDB | сотни МБ, асинхронный | офлайн-кеш, большие данные, очередь отправки |
| Cache API | ответы HTTP | Service Worker, офлайн-ресурсы |
| cookie | ~4 КБ | сессия (httpOnly) |

## Что важно помнить

- Минимальное состояние: каждая сущность — в одном месте, производное — через селекторы.
- Временные id для оптимистичных сущностей заменяйте на серверные после ответа.
- Даты храните в ISO/UTC, форматируйте при отображении через `Intl`.
- Указывайте, откуда берется «источник правды»: сервер, URL или клиент.
- Связанные темы: [нормализация в RTK](<../../06. React/15. Redux Toolkit/07. Что делает createEntityAdapter и нормализация state.md>), [client-side и server-side state](<../../06. React/03. Состояние/12. client-side state VS server-side state.md>).

## Мини-шпаргалка

Сущности с id и типами полей. Серверное состояние — в кеше запросов, UI — локально, навигация и фильтры — в URL, черновики — `localStorage`, офлайн — IndexedDB. Нормализовать при повторяющихся сущностях и точечных обновлениях. Производное — вычислять.
