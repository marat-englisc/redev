2e:T396b,<div class="callout callout-note" data-callout="note">
<div class="callout-title">Кратко</div>
<div class="callout-body"><p><strong>Semantic Versioning (semver)</strong> — формат версий <code>MAJOR.MINOR.PATCH</code>: <strong>major</strong> — несовместимые изменения, <strong>minor</strong> — новые возможности без поломок, <strong>patch</strong> — исправления. В <code>package.json</code> зависимость задается <strong>диапазоном</strong>: <code>^1.4.2</code> разрешает обновления до <code>&#x3C;2.0.0</code>, <code>~1.4.2</code> — до <code>&#x3C;1.5.0</code>, <code>1.4.2</code> — только эту версию. Точные установленные версии фиксирует lockfile. Обновлять зависимости нужно регулярно и небольшими шагами — с автоматизацией (Renovate, Dependabot), тестами и чтением changelog для major-версий.</p></div>
</div>
<h2 id="вопрос">Вопрос</h2>
<p>Что такое semver? Чем отличаются <code>^</code>, <code>~</code> и точная версия и как безопасно обновлять зависимости в проекте?</p>
<h2 id="формат-версии">Формат версии</h2>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="plaintext" data-theme="mono"><code data-language="plaintext" data-theme="mono" style="display: grid;"><span data-line=""><span>  2  .  5  .  3  -beta.1</span></span>
<span data-line=""><span>major minor patch  prerelease</span></span></code></pre></figure>






























<div class="table-wrap"><table><thead><tr><th>Изменение</th><th>Пример</th><th>Совместимость</th></tr></thead><tbody><tr><td>patch</td><td>2.5.3 → 2.5.4</td><td>исправления, API не меняется</td></tr><tr><td>minor</td><td>2.5.3 → 2.6.0</td><td>новые возможности, старый код работает</td></tr><tr><td>major</td><td>2.5.3 → 3.0.0</td><td>возможны breaking changes</td></tr><tr><td>prerelease</td><td>3.0.0-beta.1</td><td>не устанавливается диапазонами по умолчанию</td></tr></tbody></table></div>
<p>Версии <code>0.x</code> особенные: в <code>0.y.z</code> любое изменение minor может ломать API, и <code>^0.5.2</code> разрешает только <code>&#x3C;0.6.0</code>.</p>
<h2 id="диапазоны">Диапазоны</h2>

































<div class="table-wrap"><table><thead><tr><th>Запись</th><th>Разрешенные версии</th></tr></thead><tbody><tr><td><code>^1.4.2</code></td><td><code>>=1.4.2 &#x3C;2.0.0</code> (по умолчанию в <code>npm install</code>)</td></tr><tr><td><code>~1.4.2</code></td><td><code>>=1.4.2 &#x3C;1.5.0</code></td></tr><tr><td><code>1.4.2</code></td><td>только 1.4.2</td></tr><tr><td><code>>=1.4.0 &#x3C;2</code></td><td>явный диапазон</td></tr><tr><td><code>*</code> / <code>latest</code></td><td>любая — опасно</td></tr><tr><td><code>^0.5.2</code></td><td><code>>=0.5.2 &#x3C;0.6.0</code></td></tr></tbody></table></div>
<p>Lockfile делает установку воспроизводимой независимо от диапазона: <code>npm ci</code> ставит ровно то, что записано.</p>
<h2 id="как-обновлять">Как обновлять</h2>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="bash" data-theme="mono"><code data-language="bash" data-theme="mono" style="display: grid;"><span data-line=""><span style="color:var(--shiki-token-function)">npm</span><span style="color:var(--shiki-token-string)"> outdated</span><span style="color:var(--shiki-token-comment)">                    # что устарело</span></span>
<span data-line=""><span style="color:var(--shiki-token-function)">npx</span><span style="color:var(--shiki-token-string)"> npm-check-updates</span><span style="color:var(--shiki-token-string)"> -i</span><span style="color:var(--shiki-token-comment)">        # интерактивное обновление диапазонов</span></span>
<span data-line=""><span style="color:var(--shiki-token-function)">npm</span><span style="color:var(--shiki-token-string)"> update</span><span style="color:var(--shiki-token-comment)">                      # обновить в пределах диапазонов</span></span>
<span data-line=""><span style="color:var(--shiki-token-function)">npm</span><span style="color:var(--shiki-token-string)"> install</span><span style="color:var(--shiki-token-string)"> react@latest</span><span style="color:var(--shiki-token-comment)">        # конкретный пакет до последней версии</span></span>

<p>Процесс для major-версии:</p>
<ol>
<li>Прочитать changelog и migration guide.</li>
<li>Обновить один пакет (или связанную группу: <code>react</code> + <code>react-dom</code> + <code>@types/react</code>).</li>
<li>Запустить typecheck, линтер, тесты, e2e.</li>
<li>Проверить вручную ключевые сценарии и размер бандла.</li>
<li>Отдельный PR — легко откатить.</li>
</ol>

<p><code>peerDependencies</code> — зависимость, которую должен установить проект-хозяин (например, <code>react</code> для UI-библиотеки), чтобы не было двух копий.</p>
<h2 id="что-важно-помнить">Что важно помнить</h2>
<ul>
<li><code>^</code> безопасен только если пакет честно следует semver; lockfile защищает от неожиданностей.</li>
<li>Обновляйтесь регулярно маленькими шагами — накопленный год обновлений превращается в дорогую миграцию.</li>
<li>Две копии React в бандле ломают хуки («Invalid hook call») — проверяйте <code>npm ls react</code>.</li>
<li>Коммитьте lockfile, в CI — <code>npm ci</code>.</li>
<li>Связанные темы: <a href="/refront/l/08/15/06/" data-internal="true">безопасность зависимостей</a>, <a href="/refront/l/08/02/03/" data-internal="true">dependencies и devDependencies</a>.</li>
</ul>
<h2 id="мини-шпаргалка">Мини-шпаргалка</h2>
<p>semver: MAJOR (ломает) . MINOR (добавляет) . PATCH (исправляет). <code>^1.4.2</code> → <code>&#x3C;2.0.0</code>, <code>~1.4.2</code> → <code>&#x3C;1.5.0</code>, <code>^0.5.2</code> → <code>&#x3C;0.6.0</code>. Lockfile — точные версии. Обновление: <code>outdated</code>, changelog, по одному, тесты, отдельный PR. Renovate/Dependabot, <code>overrides</code>, <code>dedupe</code>, <code>peerDependencies</code>.</p>
