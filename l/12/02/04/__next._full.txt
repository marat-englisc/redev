<div class="callout-title">Кратко</div>
<div class="callout-body"><p><strong>HMR (Hot Module Replacement)</strong> — замена измененного модуля в работающем приложении без полной перезагрузки страницы. Dev-сервер следит за файлами, по <strong>WebSocket</strong> сообщает браузеру, какой модуль изменился, браузер загружает новую версию, а модуль или его родитель <strong>принимает</strong> обновление (<code>import.meta.hot.accept</code>). В React это делает <strong>React Fast Refresh</strong>: компоненты перерисовываются с сохранением состояния (<code>useState</code>), а при ошибке или изменении не-компонентного кода — состояние сбрасывается или страница перезагружается.</p></div>
</div>
<h2 id="вопрос">Вопрос</h2>
<p>Как работает HMR? Чем он отличается от live reload и почему иногда состояние React сбрасывается после изменения файла?</p>

<h2 id="когда-react-fast-refresh-сбрасывает-состояние">Когда React Fast Refresh сбрасывает состояние</h2>
<ul>
<li>файл экспортирует не только компоненты (константы, утилиты вместе с компонентом) — обновление поднимется выше или будет полная перезагрузка;</li>
<li>компонент объявлен анонимно или не с заглавной буквы;</li>
<li>классовые компоненты — всегда перемонтируются;</li>
<li>изменился порядок или количество хуков;</li>
<li>ошибка в коде — после исправления компонент перемонтируется.</li>
</ul>
<p>Правило: <strong>один файл — компоненты</strong> (или явно разделять компоненты и утилиты). Линтер <code>eslint-plugin-react-refresh</code> подсказывает нарушения.</p>
<h2 id="типичные-проблемы">Типичные проблемы</h2>






























<div class="table-wrap"><table><thead><tr><th>Проблема</th><th>Причина</th><th>Решение</th></tr></thead><tbody><tr><td>HMR не работает в Docker/WSL</td><td>файловые события не доходят</td><td><code>server.watch.usePolling: true</code></td></tr><tr><td>Постоянная полная перезагрузка</td><td>модуль без границы HMR, смешанные экспорты</td><td>разделить файлы</td></tr><tr><td>Дублируются слушатели и таймеры</td><td>побочные эффекты на уровне модуля</td><td><code>import.meta.hot.dispose</code>, эффекты в компонентах</td></tr><tr><td>WebSocket не подключается за прокси</td><td>прокси не пропускает upgrade</td><td><code>server.hmr.clientPort</code>, настройка прокси</td></tr></tbody></table></div>
<h2 id="что-важно-помнить">Что важно помнить</h2>
<ul>
<li>HMR существует только в режиме разработки.</li>
<li>Состояние сохраняется для функциональных компонентов при изменении только их кода.</li>
<li>Глобальные side effects в модулях (подписки, интервалы) при HMR дублируются — держите их в эффектах с очисткой.</li>
<li>Strict Mode и Fast Refresh вместе проверяют, что эффекты корректно очищаются.</li>
</ul>
<h2 id="мини-шпаргалка">Мини-шпаргалка</h2>
<p>HMR: сервер следит за файлами → WebSocket → браузер грузит новую версию модуля → граница <code>hot.accept</code> применяет → иначе полная перезагрузка. React Fast Refresh сохраняет state функциональных компонентов. Сброс — смешанные экспорты, классы, смена хуков, ошибки. <code>dispose</code> для очистки.</p>
