Как работают переменные окружения и режимы сборки

Кратко

Во фронтенде переменные окружения подставляются в код на этапе сборки: import.meta.env.VITE_API_URL превращается в строку прямо в бандле. Поэтому всё, что попало в клиентский бандл, публично. Чтобы секреты случайно не утекли, инструменты пропускают в клиент только переменные с префиксом: VITE_* в Vite, NEXT_PUBLIC_* в Next.js, REACT_APP_* в Create React App. Значения берутся из .env-файлов по режиму (development, production, staging) и из окружения CI.

Почему секреты нельзя в клиент

Ключи платежных систем, токены API, пароли БД используются только на сервере (BFF, Route Handlers, Server Actions). В клиенте — только публичные значения: адрес API, публичный ключ аналитики, DSN Sentry.

Один образ на много окружений

Что важно помнить

  • Всё с префиксом VITE_/NEXT_PUBLIC_ — публично; секреты — только на сервере.
  • Значения — строки: "false" истинно в if; приводите типы и валидируйте схемой (Zod) при старте.
  • .env.local и .env.*.local добавляйте в .gitignore, коммитьте .env.example с именами переменных.
  • После изменения .env перезапустите dev-сервер.
  • Связанные темы: env и секреты в Node.js, Docker для фронтендера.

Мини-шпаргалка

Env во фронтенде встраивается при сборке → всё публично. Префиксы: VITE_, NEXT_PUBLIC_, REACT_APP_. Файлы: .env, .env.local, .env.[mode]. import.meta.env.MODE/DEV/PROD, --mode staging. Типизация ImportMetaEnv. Один образ — runtime config.js.
