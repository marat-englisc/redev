Что такое source maps

Кратко

Source map — файл .map, который связывает позиции в собранном и минифицированном коде с исходным кодом: файлом, строкой, колонкой и именем переменной. Благодаря нему DevTools показывает ошибки и точки останова в исходных .tsx, а Sentry — понятный stack trace. В production source maps обычно не раздают публично, а загружают в систему мониторинга ошибок.

Вопрос

Что такое source maps и как они работают? Какие варианты бывают и как правильно использовать их в production?

Как работает

mappings — закодированные (VLQ) соответствия позиций. DevTools загружает .map, только когда открыты инструменты разработчика.

Source maps и мониторинг ошибок

Плагины Sentry для Vite и webpack при сборке загружают .map с привязкой к release, после чего удаляют их из dist. В Sentry stack trace показывает src/utils/double.ts:12, а пользователи не могут скачать исходники.

Что важно помнить

  • Публичные source maps раскрывают исходный код, комментарии и иногда пути и внутреннюю логику — для закрытых проектов используйте hidden и загрузку в мониторинг.
  • Source maps не влияют на скорость загрузки для пользователей: браузер скачивает их только при открытых DevTools.
  • Release в Sentry должен совпадать с версией собранного кода, иначе карты не применятся.
  • Цепочка трансформаций (TS → Babel → минификатор) должна передавать карты дальше, иначе позиции будут неточными.
  • Карты есть и для CSS: DevTools показывает исходный .scss или CSS-модуль.

Мини-шпаргалка

Source map (.map) — соответствие собранного кода исходному. Dev — быстрые варианты (eval-*), prod — hidden + загрузка в Sentry с release, без публикации. inline только локально. Браузер грузит карты лишь при открытых DevTools.
