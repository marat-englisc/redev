<div class="callout-body"><p><strong>ESLint</strong> — статический анализатор JavaScript и TypeScript: он находит ошибки и опасные паттерны <strong>до запуска кода</strong> (неиспользуемые переменные, нарушение правил хуков, забытый <code>await</code>, отсутствие зависимостей эффекта, проблемы доступности). С ESLint 9 по умолчанию используется <strong>flat config</strong> — файл <code>eslint.config.js</code> с массивом объектов конфигурации. Форматирование (отступы, кавычки) обычно отдают Prettier.</p></div>

<h2 id="как-устроен-flat-config">Как устроен flat config</h2>





























<div class="table-wrap"><table><thead><tr><th>Часть</th><th>Назначение</th></tr></thead><tbody><tr><td>массив объектов</td><td>применяются по порядку, последующие переопределяют предыдущие</td></tr><tr><td><code>files</code> / <code>ignores</code></td><td>к каким файлам относится объект</td></tr><tr><td><code>languageOptions</code></td><td>парсер, глобальные переменные, версия ECMAScript</td></tr><tr><td><code>plugins</code></td><td>объекты плагинов, подключенные напрямую через import</td></tr><tr><td><code>rules</code></td><td><code>"off"</code> / <code>"warn"</code> / <code>"error"</code> + настройки</td></tr></tbody></table></div>
<p>Старый формат <code>.eslintrc</code> с <code>extends</code> строками и <code>env</code> устарел.</p>
<h2 id="полезные-правила-и-плагины">Полезные правила и плагины</h2>









































<div class="table-wrap"><table><thead><tr><th>Плагин / правило</th><th>Что ловит</th></tr></thead><tbody><tr><td><code>react-hooks/rules-of-hooks</code>, <code>exhaustive-deps</code></td><td>хуки в условиях, недостающие зависимости эффектов</td></tr><tr><td><code>@typescript-eslint/no-floating-promises</code></td><td>Promise без <code>await</code> / <code>.catch</code></td></tr><tr><td><code>@typescript-eslint/no-explicit-any</code></td><td><code>any</code></td></tr><tr><td><code>jsx-a11y/*</code></td><td><code>img</code> без <code>alt</code>, клик на <code>div</code> без роли и клавиатуры</td></tr><tr><td><code>import/no-cycle</code>, <code>import/order</code></td><td>циклические зависимости, порядок импортов</td></tr><tr><td><code>eslint-plugin-boundaries</code></td><td>нарушение границ модулей (FSD, слои)</td></tr><tr><td><code>@tanstack/eslint-plugin-query</code></td><td>ошибки ключей запросов</td></tr><tr><td><code>eslint-plugin-react-compiler</code></td><td>код, несовместимый с React Compiler</td></tr></tbody></table></div>
<p>Type-aware правила (<code>recommendedTypeChecked</code>) используют информацию TypeScript и находят больше ошибок, но работают медленнее.</p>
<h2 id="где-запускать">Где запускать</h2>
<ul>
<li>в редакторе (расширение ESLint) — подсветка сразу;</li>
<li>в pre-commit через lint-staged — только измененные файлы;</li>
<li>в CI — <code>eslint . --max-warnings=0</code> блокирует merge при нарушениях.</li>
</ul>
<h2 id="что-важно-помнить">Что важно помнить</h2>
<ul>
<li>ESLint — про <strong>ошибки и качество</strong>, Prettier — про <strong>форматирование</strong>; конфликты отключает <code>eslint-config-prettier</code>.</li>
<li>Не отключайте <code>exhaustive-deps</code> без причины — это основной источник багов с эффектами.</li>
<li><code>// eslint-disable-next-line rule -- причина</code> — точечно и с объяснением.</li>
<li>Альтернативы: <strong>Biome</strong> (линтер и форматтер на Rust в одном инструменте) и <strong>oxlint</strong> (очень быстрый линтер на Rust).</li>
<li>Для CSS есть Stylelint с похожей моделью.</li>
</ul>
<h2 id="мини-шпаргалка">Мини-шпаргалка</h2>
<p>ESLint — статический анализ ошибок. ESLint 9: <code>eslint.config.js</code>, массив объектов с <code>files</code>, <code>languageOptions</code>, <code>plugins</code>, <code>rules</code>. Для React+TS: <code>@eslint/js</code>, <code>typescript-eslint</code>, <code>react-hooks</code>, <code>jsx-a11y</code>, <code>react-refresh</code>, в конце <code>eslint-config-prettier</code>. Запуск: редактор, lint-staged, CI с <code>--max-warnings=0</code>.</p>
