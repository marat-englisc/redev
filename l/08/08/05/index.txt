<div class="callout-title">Кратко</div>
<div class="callout-body"><p>В Node.js есть встроенный test runner, который запускается командой <code>node --test</code>. Он позволяет писать тесты без обязательной установки Jest, Vitest или Mocha.</p><p><code>node:test</code> давно вышел за рамки минимального <code>test()</code>: есть <code>describe</code>/<code>it</code>, hooks, mocks, timers, coverage, reporters, tags, watch mode и programmatic runner. Для backend-библиотек этого часто достаточно без Jest/Vitest.</p></div>
</div>
<h2 id="вопрос">Вопрос</h2>
<p>Как писать тесты на встроенном test runner <code>node:test</code> и когда его достаточно?</p>

<p>Он хорош для:</p>
<ul>
<li>библиотек;</li>
<li>утилит;</li>
<li>backend-модулей;</li>
<li>небольших сервисов;</li>
<li>проектов, где не нужны тяжелые UI-возможности тестового фреймворка.</li>
</ul>

<h2 id="когда-брать-vitestjest">Когда брать Vitest/Jest?</h2>
<p>Бери Vitest/Jest, если нужны:</p>
<ul>
<li>frontend DOM окружение;</li>
<li>snapshot tooling привычного формата;</li>
<li>rich plugin ecosystem;</li>
<li>framework-specific utilities;</li>
<li>existing project convention.</li>
</ul>
<h2 id="что-важно-помнить">Что важно помнить</h2>
<ul>
<li>Запуск — <code>node --test</code>; файлы находятся по шаблонам <code>*.test.js</code>, <code>test/**</code> и подобным.</li>
<li>Проверки — через <code>node:assert/strict</code>: <code>equal</code>, <code>deepEqual</code>, <code>rejects</code>, <code>throws</code>.</li>
<li>Есть <code>describe</code>/<code>it</code>, хуки, <code>mock.fn</code>, <code>mock.method</code>, <code>mock.timers</code>, coverage и watch.</li>
<li>Для frontend с DOM и экосистемой плагинов обычно выбирают Vitest или Jest.</li>
</ul>
<h2 id="мини-шпаргалка">Мини-шпаргалка</h2>
<ul>
<li>Запуск: <code>node --test</code>.</li>
<li>Тесты пишутся через <code>node:test</code>.</li>
<li>Проверки удобно делать через <code>node:assert/strict</code>.</li>
<li>Поддерживаются async-тесты.</li>
<li>Для сложного frontend-окружения чаще берут Vitest или Jest.</li>
<li><code>node --test</code> - запуск.</li>
<li><code>describe</code>/<code>it</code> - BDD-style.</li>
<li><code>before</code>/<code>after</code> - lifecycle.</li>
<li><code>mock.method</code>/<code>mock.fn</code> - mocks.</li>
<li><code>mock.timers</code> - fake timers.</li>
<li>Coverage есть через CLI flag.</li>
</ul>
