<div class="callout-body"><p>Когда над фронтендом работают несколько команд, архитектура должна позволять <strong>менять код независимо</strong>: четкие <strong>границы модулей</strong> с публичным API (Feature-Sliced Design, доменные модули), <strong>монорепозиторий</strong> с общими пакетами (UI-кит, утилиты, конфиги) и инструментами сборки (Turborepo, Nx, pnpm workspaces), а при необходимости — <strong>микрофронтенды</strong>, которые собираются и деплоятся отдельно. Правило: начинать с модульного монолита и переходить к микрофронтендам только при реальной организационной необходимости.</p></div>

<h2 id="вопрос">Вопрос</h2>
<p>Как масштабировать фронтенд-приложение и кодовую базу, когда растет команда? Что такое монорепозиторий и микрофронтенды и когда они оправданы?</p>
<h2 id="ступени-масштабирования">Ступени масштабирования</h2>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="plaintext" data-theme="mono"><code data-language="plaintext" data-theme="mono" style="display: grid;"><span data-line=""><span>1. Модульный монолит      одно приложение, границы фич, публичные API модулей</span></span>
<span data-line=""><span>2. Монорепозиторий        несколько приложений и общие пакеты в одном репозитории</span></span>
<span data-line=""><span>3. Микрофронтенды         независимые сборки и деплои частей интерфейса</span></span></code></pre></figure>

<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="plaintext" data-theme="mono"><code data-language="plaintext" data-theme="mono" style="display: grid;"><span data-line=""><span>src/</span></span>

<p>Инструменты: <strong>pnpm workspaces</strong> (связывание пакетов), <strong>Turborepo</strong> или <strong>Nx</strong> (граф задач, кеш сборки и тестов, запуск только затронутого — <code>affected</code>), <strong>Changesets</strong> (версии пакетов).</p>
<h2 id="3-микрофронтенды">3. Микрофронтенды</h2>
<p>Каждая команда владеет частью интерфейса от разработки до деплоя: каталог, корзина, личный кабинет.</p>



































<div class="table-wrap"><table><thead><tr><th>Способ интеграции</th><th>Как работает</th><th>Особенности</th></tr></thead><tbody><tr><td>Разные маршруты (multi-zone)</td><td><code>/shop/*</code> — одно приложение, <code>/account/*</code> — другое</td><td>проще всего, переход между зонами — полная загрузка</td></tr><tr><td>Module Federation</td><td>приложение загружает модули другого в рантайме</td><td>общий React как singleton, сложная настройка версий</td></tr><tr><td>Web Components</td><td>части оформлены как custom elements</td><td>изоляция Shadow DOM, сложнее SSR</td></tr><tr><td>iframe</td><td>полная изоляция</td><td>плохо для UX, SEO, a11y</td></tr><tr><td>Серверная композиция</td><td>сервер или edge собирает HTML фрагментов</td><td>хорошо для SEO, сложная инфраструктура</td></tr></tbody></table></div>
<p>Обязательные договоренности: общая дизайн-система, общий способ авторизации, коммуникация через события или URL (а не через общий глобальный store), контроль размера бандла (нет пяти копий React), сквозной мониторинг.</p>
<h2 id="когда-что-выбирать">Когда что выбирать</h2>

























<div class="table-wrap"><table><thead><tr><th>Ситуация</th><th>Решение</th></tr></thead><tbody><tr><td>одна-две команды</td><td>модульный монолит</td></tr><tr><td>несколько приложений с общими компонентами</td><td>монорепозиторий</td></tr><tr><td>много автономных команд, независимые релизы, разные циклы</td><td>микрофронтенды</td></tr><tr><td>миграция legacy-приложения по частям</td><td>микрофронтенды как временный шаг</td></tr></tbody></table></div>
<h2 id="что-важно-помнить">Что важно помнить</h2>
<ul>
<li>Микрофронтенды решают <strong>организационную</strong> проблему (независимость команд), а не техническую; цена — сложность, производительность и согласованность UX.</li>
<li>Границы модулей важнее инструментов: без них и монорепо, и микрофронтенды превращаются в связанный монолит.</li>
<li>Кеш сборки и запуск только затронутого кода (affected) — основа быстрого CI в монорепозитории.</li>
<li>Связанные темы: <a href="/refront/l/06/08/05/" data-internal="true">Feature-Sliced Design</a>, <a href="/refront/l/06/08/17/" data-internal="true">микрофронтенды с React</a>, <a href="/refront/l/06/08/07/" data-internal="true">изоляция модулей</a>.</li>
</ul>
<h2 id="мини-шпаргалка">Мини-шпаргалка</h2>
<p>Модульный монолит (слои, публичные API, линтер границ) → монорепо (pnpm workspaces, Turborepo/Nx, общие пакеты, affected) → микрофронтенды (маршруты, Module Federation, Web Components, серверная композиция) только при многих автономных командах. Общие: дизайн-система, auth, события, мониторинг.</p>
