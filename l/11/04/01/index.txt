<div class="callout-title">Кратко</div>
<div class="callout-body"><p><strong>Автокомплит</strong> — поле ввода, которое по мере набора показывает подсказки: поиск товаров, городов, пользователей. Это классическая задача на <strong>UI-компонент</strong>: важны API компонента, <strong>debounce</strong> запросов, <strong>отмена устаревших ответов</strong> (race condition), <strong>кеш</strong> результатов, навигация с клавиатуры и доступность по паттерну <strong>WAI-ARIA combobox</strong>, а также поведение на медленной сети и при ошибках.</p></div>
</div>
<h2 id="вопрос">Вопрос</h2>
<p>Как спроектировать компонент автокомплита? Как избежать лишних запросов и гонок ответов, кешировать результаты и сделать компонент доступным?</p>
<h2 id="r--требования">R — требования</h2>
<ul>
<li>подсказки по мере ввода, выбор мышью и с клавиатуры;</li>
<li>источник — серверный API (большой объем данных) или локальный список;</li>
<li>подсветка совпадения, до 10 вариантов, состояния «загрузка», «ничего не найдено», «ошибка»;</li>
<li>нефункциональные: быстро (&#x3C; 100 мс на ввод), не перегружать сервер, доступность, мобильные, переиспользуемость в разных местах.</li>
</ul>

<ul>
<li>debounce 200–300 мс сокращает запросы в разы;</li>
<li><code>AbortController</code> или проверка «ответ для текущего query?» — ответ на «мо» не перезапишет «москва»;</li>
<li>кеш в памяти с ограничением размера (LRU) и TTL; повторный ввод «мос» после стирания — мгновенно;</li>
<li><code>minChars</code>, ограничение <code>limit</code>;</li>
<li>для локальных данных — фильтрация в памяти, для очень больших — Web Worker или индекс (trie).</li>
</ul>
<p><strong>Доступность (combobox):</strong></p>
<ul>
<li><code>input</code>: <code>role="combobox"</code>, <code>aria-expanded</code>, <code>aria-controls</code>, <code>aria-activedescendant</code>, <code>aria-autocomplete="list"</code>;</li>
<li><code>ul role="listbox"</code>, элементы <code>role="option"</code> с <code>aria-selected</code>;</li>
<li>стрелки — перемещение, Enter — выбор, Esc — закрыть, Tab — уйти без выбора;</li>
<li>фокус остается в поле; число результатов объявляется через <code>aria-live</code>.</li>
</ul>
<p><strong>UX:</strong></p>
<ul>
<li>подсветка совпадения без <code>innerHTML</code> (безопасно от XSS);</li>
<li>последние запросы и популярные варианты при пустом вводе;</li>
<li>позиционирование списка у края экрана (Floating UI), закрытие при клике вне;</li>
<li>на мобильных — полноэкранный режим поиска, <code>inputMode</code>, <code>enterKeyHint="search"</code>.</li>
</ul>
<h2 id="что-важно-помнить">Что важно помнить</h2>
<ul>
<li>Три главных темы, которые ждут на интервью: debounce, отмена/гонки, кеш.</li>
<li><code>isOpen</code> и <code>activeIndex</code> сбрасываются при новом вводе и закрытии.</li>
<li>Компонент должен работать и в controlled-режиме (<code>value</code> + <code>onChange</code>), и uncontrolled.</li>
<li>Ошибка сети не должна ломать ввод — показываем строку ошибки внутри списка.</li>
<li>Связанные темы: <a href="/refront/l/06/10/08/" data-internal="true">debounce и throttle</a>, <a href="/refront/l/06/10/03/" data-internal="true">отмена запросов</a>.</li>
</ul>
<h2 id="мини-шпаргалка">Мини-шпаргалка</h2>
<p>Headless-хук + разметка. debounce 200–300 мс, <code>minChars</code>, AbortController против гонок, LRU-кеш по нормализованному запросу. Combobox ARIA: <code>aria-expanded</code>, <code>aria-activedescendant</code>, listbox/option, стрелки/Enter/Esc. Состояния loading/empty/error, подсветка без innerHTML.</p>
