<div class="callout-title">Кратко</div>
<div class="callout-body"><p><strong>Чат</strong> — задача на realtime и надежность: список бесед, история сообщений с прокруткой вверх, отправка с мгновенным отображением, статусы «отправляется → отправлено → прочитано», индикатор «печатает», непрочитанные, работа при обрывах сети. Ключевые решения: <strong>WebSocket</strong> для двусторонних событий, <strong>нормализованное хранилище</strong> сообщений, <strong>оптимистичная отправка с clientId</strong>, <strong>очередь неотправленных</strong> сообщений, <strong>догоняющая синхронизация</strong> после переподключения и <strong>обратная виртуализация</strong> (лента растет вверх).</p></div>
</div>
<h2 id="вопрос">Вопрос</h2>
<p>Как спроектировать фронтенд чата? Как организовать realtime, отправку сообщений без потерь, историю и работу при плохой сети?</p>
<h2 id="r--требования">R — требования</h2>
<ul>
<li>список бесед с последним сообщением и счетчиком непрочитанных;</li>
<li>история сообщений с подгрузкой старых при прокрутке вверх;</li>
<li>отправка текста (вложения — кратко), статусы доставки и прочтения;</li>
<li>«печатает…», онлайн-статус;</li>
<li>нефункциональные: задержка доставки &#x3C; 1 с, без потерь при обрыве сети, несколько вкладок, уведомления, a11y.</li>
</ul>

<h2 id="o--оптимизации">O — оптимизации</h2>
<p><strong>Отправка без потерь:</strong></p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="plaintext" data-theme="mono"><code data-language="plaintext" data-theme="mono" style="display: grid;"><span data-line=""><span>1. Пользователь нажал «Отправить»</span></span>
<span data-line=""><span>2. Сообщение с clientId и status="sending" сразу в UI и в outbox (IndexedDB)</span></span>
<span data-line=""><span>3. Отправка по WebSocket (или HTTP fallback)</span></span>
<span data-line=""><span>4. ack от сервера → id и createdAt, status="sent", удалить из outbox</span></span>
<span data-line=""><span>5. нет ack за N секунд / соединение упало → повтор с тем же clientId</span></span>
<span data-line=""><span>6. после K попыток → status="failed", кнопка «Повторить»</span></span></code></pre></figure>
<p><code>clientId</code> делает отправку идемпотентной: сервер не создаст дубль при повторе.</p>
<p><strong>Realtime и переподключение:</strong></p>
<ul>
<li>WebSocket с heartbeat, переподключение с backoff + jitter;</li>
<li>после переподключения — запрос событий с <code>lastEventId</code> или перезагрузка последних сообщений активной беседы;</li>
<li>дедупликация по <code>id</code>/<code>clientId</code>, сортировка по серверному времени;</li>
<li>одно соединение на все вкладки (<code>SharedWorker</code> или выбор «лидера» через <code>BroadcastChannel</code>), остальные получают события через канал.</li>
</ul>
<p><strong>История и прокрутка:</strong></p>
<ul>
<li>обратный список: новые снизу, подгрузка старых при прокрутке к верху (cursor <code>before</code>);</li>
<li>сохранять позицию при подгрузке сверху (компенсировать высоту добавленного) — react-virtuoso умеет это;</li>
<li>автопрокрутка вниз только если пользователь уже внизу; иначе — кнопка «Новые сообщения ↓».</li>
</ul>
<p><strong>Прочее:</strong></p>
<ul>
<li>«печатает» — throttle отправки события (раз в 2–3 с), скрытие по таймауту;</li>
<li>уведомления: Notification API при скрытой вкладке, счетчик в <code>document.title</code>, Web Push для закрытой;</li>
<li>черновики для каждой беседы в <code>localStorage</code>;</li>
<li>вложения — загрузка заранее по presigned URL, в сообщении только ссылка;</li>
<li>a11y: новые сообщения через <code>aria-live="polite"</code> (только во входящей беседе), Enter — отправка, Shift+Enter — новая строка;</li>
<li>безопасность: текст выводится как текст (без HTML), ссылки — с <code>rel="noopener noreferrer"</code>.</li>
</ul>
<h2 id="что-важно-помнить">Что важно помнить</h2>
<ul>
<li>Главные темы: WebSocket и переподключение, оптимистичная отправка с clientId и ack, outbox, догонка пропущенных событий, обратная прокрутка.</li>
<li>Время и порядок берутся с сервера: часы клиента могут отставать.</li>
<li>Обновление статуса «прочитано» отправляйте пачкой «прочитано до id», а не по каждому сообщению.</li>
<li>Связанные темы: <a href="/refront/l/11/02/05/" data-internal="true">realtime</a>, <a href="/refront/l/11/03/03/" data-internal="true">надежность и офлайн</a>.</li>
</ul>
<h2 id="мини-шпаргалка">Мини-шпаргалка</h2>
<p>REST — история и беседы, WebSocket — события. Нормализованный store, сообщения по clientId. Отправка: optimistic → outbox → ack → status; повтор с тем же clientId. Переподключение + <code>lastEventId</code>. Обратная виртуализация, автоскролл только у низа. Typing — throttle. Уведомления, черновики, aria-live.</p>
