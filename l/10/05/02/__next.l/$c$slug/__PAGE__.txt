<div class="callout-title">Кратко</div>
<div class="callout-body"><p>Каждый компонент, загружающий данные, имеет минимум четыре состояния: загрузка, ошибка, пустой результат и данные. Тест должен проверить каждое, управляя ответом сервера через MSW: задержкой, статусом и телом ответа.</p></div>
</div>
<h2 id="вопрос">Вопрос</h2>
<p>Как протестировать индикатор загрузки, сообщение об ошибке и пустое состояние списка?</p>
<h2 id="основная-идея">Основная идея</h2>
<p>В реальном приложении ответ может прийти не сразу, вернуть 500, 401, пустой массив или данные. Разработчики чаще всего проверяют только успешный сценарий, а ошибки и пустые списки ломаются незаметно. MSW позволяет задать каждый сценарий в одну строку через <code>server.use</code>.</p>








































<div class="table-wrap"><table><thead><tr><th>Состояние</th><th>Как вызвать в тесте</th><th>Что проверить</th></tr></thead><tbody><tr><td>Loading</td><td>сразу после <code>render</code> или <code>delay()</code> в обработчике</td><td>индикатор, заблокированные действия</td></tr><tr><td>Success</td><td>обработчик по умолчанию</td><td>данные на экране, индикатор исчез</td></tr><tr><td>Empty</td><td><code>HttpResponse.json([])</code></td><td>текст пустого состояния, призыв к действию</td></tr><tr><td>Error</td><td>статус <code>500</code> или <code>HttpResponse.error()</code></td><td>сообщение, кнопка «Повторить»</td></tr><tr><td>Unauthorized</td><td>статус <code>401</code></td><td>редирект на вход или сообщение</td></tr><tr><td>Retry</td><td>ошибка, затем успех</td><td>после «Повторить» появились данные</td></tr></tbody></table></div>
<p>Для сценария «сначала ошибка, потом успех» обработчику передают опцию <code>{ once: true }</code>: он сработает один раз, после чего запросы обработает следующий подходящий обработчик.</p>

<h2 id="что-важно-помнить">Что важно помнить</h2>
<ul>
<li>Loading проверяют синхронно сразу после <code>render</code>: к первому <code>await</code> данные могут уже прийти.</li>
<li><code>HttpResponse.error()</code> и статус 500 — разные ветки кода: <code>fetch</code> отклоняется только при сетевой ошибке, а на 500 возвращает <code>response.ok === false</code>.</li>
<li>Для TanStack Query в тестах отключают <code>retry</code>, иначе ошибка появится только после повторов.</li>
<li>Проверяйте, что при ошибке не теряются введённые пользователем данные.</li>
<li>Состояния удобно показать и в Storybook с тем же MSW — так их видят дизайнеры.</li>
</ul>
<h2 id="мини-шпаргалка">Мини-шпаргалка</h2>
<p>4 состояния: loading → <code>delay</code>, success → handler по умолчанию, empty → <code>[]</code>, error → <code>status: 500</code> / <code>HttpResponse.error()</code>. Retry → <code>{ once: true }</code>.</p>
