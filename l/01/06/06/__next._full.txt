<div class="callout-title">Кратко</div>
<div class="callout-body"><p>Network tab — главный инструмент для диагностики client-server проблем. В нем видно, ушел ли request, какие method, URL и headers отправлены, какие cookies приложились, был ли preflight, откуда взялся response (сеть или cache) и сколько времени занял каждый этап.</p></div>
</div>
<h2 id="вопрос">Вопрос</h2>
<p>Как с помощью DevTools понять, почему запрос не работает: ошибка во frontend, в backend, в CORS, в cookies или в cache?</p>
<h2 id="где-смотреть">Где смотреть?</h2>
<p>Открой DevTools → Network → выбери запрос. Полезные вкладки:</p>

































<div class="table-wrap"><table><thead><tr><th>Вкладка</th><th>Что показывает</th></tr></thead><tbody><tr><td><code>Headers</code></td><td>URL, method, status, request и response headers</td></tr><tr><td><code>Payload</code></td><td>query string, form data, JSON body</td></tr><tr><td><code>Response</code> / <code>Preview</code></td><td>сырое и отформатированное тело ответа</td></tr><tr><td><code>Cookies</code></td><td>отправленные и установленные cookies, причины блокировки</td></tr><tr><td><code>Timing</code></td><td>DNS, connection, TLS, ожидание сервера (TTFB), загрузка</td></tr><tr><td><code>Initiator</code></td><td>какой код или ресурс запустил запрос</td></tr></tbody></table></div>
<p>Полезные настройки панели: <code>Preserve log</code> (не очищать при навигации и редиректах), <code>Disable cache</code> (работает, пока DevTools открыты), <code>Throttling</code> (медленная сеть), фильтры <code>Fetch/XHR</code>, <code>Doc</code>, <code>JS</code>.</p>
<h2 id="базовый-чеклист">Базовый чеклист</h2>
<ol>
<li>Найди нужный request.</li>
<li>Проверь method и URL.</li>
<li>Проверь status code.</li>
<li>Проверь request headers.</li>
<li>Проверь payload.</li>
<li>Проверь response headers.</li>
<li>Проверь response body.</li>
<li>Проверь cookies.</li>
<li>Проверь timing и cache source.</li>
</ol>
<h2 id="что-проверять-при-ошибке">Что проверять при ошибке?</h2>

<h2 id="cors">CORS</h2>
<p>Status <code>(blocked:cors)</code> или ошибка в Console означает, что browser заблокировал чтение response. Смотри:</p>
<ul>
<li><code>Origin</code> в request;</li>
<li><code>Access-Control-Allow-Origin</code> и <code>Access-Control-Allow-Credentials</code> в response;</li>
<li>preflight <code>OPTIONS</code> — отдельная строка перед основным запросом;</li>
<li>allowed methods и headers.</li>
</ul>
<p>Если preflight упал, основного запроса не будет вовсе.</p>
<h2 id="cache">Cache</h2>
<p><code>from memory cache</code> / <code>from disk cache</code> означает, что response взят из browser cache и server мог вообще не получить request. <code>304 Not Modified</code> — запрос ушел, но сервер подтвердил, что сохраненная копия актуальна. Чтобы проверить реальный request, включи <code>Disable cache</code>.</p>
<h2 id="cookies">Cookies</h2>
<p>Открой request → Headers → Request Headers:</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="http" data-theme="mono"><code data-language="http" data-theme="mono" style="display: grid;"><span data-line=""><span style="color:var(--shiki-token-string-expression)">Cookie</span><span style="color:var(--shiki-token-keyword)">:</span><span style="color:var(--shiki-token-string)"> sid=abc</span></span></code></pre></figure>
<p>Если cookie нет, смотри вкладку Cookies и attributes: <code>Domain</code>, <code>Path</code>, <code>SameSite</code>, <code>Secure</code>, expiration, credentials mode (<code>credentials: 'include'</code>). Chrome показывает причину, по которой cookie была отфильтрована.</p>
<h2 id="почему-request-может-не-появиться">Почему request может не появиться?</h2>
<p>Если ошибка произошла до сети, запроса может не быть:</p>
<ul>
<li>JavaScript exception до <code>fetch</code>;</li>
<li>browser заблокировал mixed content;</li>
<li>URL собран неправильно;</li>
<li>request отменен <code>AbortController</code>;</li>
<li>service worker перехватил запрос (смотри колонку Size: <code>(ServiceWorker)</code>);</li>
<li>фильтр Network скрывает запрос.</li>
</ul>
<h2 id="как-понять-что-ошибка-на-backend">Как понять, что ошибка на backend?</h2>
<p>Если request ушел, response пришел, status <code>500</code>, а CORS не блокирует чтение, вероятно, ошибка на server side. Но frontend все равно должен корректно обработать <code>500</code>, показать fallback и не падать всем приложением.</p>

<h2 id="что-важно-помнить">Что важно помнить</h2>
<ul>
<li>Network tab показывает факты, а не предположения: начинай отладку с него, а не с кода.</li>
<li>Timing <code>Waiting for server response</code> (TTFB) показывает медленный backend, <code>Content Download</code> — большой ответ или медленную сеть.</li>
<li>Правый клик → <code>Copy as cURL</code> / <code>Copy as fetch</code> позволяет воспроизвести запрос вне приложения.</li>
<li>HAR-файл (экспорт панели) удобно приложить к баг-репорту, но в нем есть cookies и токены — очищай перед отправкой.</li>
</ul>
<h2 id="мини-шпаргалка">Мини-шпаргалка</h2>
<ul>
<li>Всегда смотри method, URL, status, headers, payload и response.</li>
<li>CORS ищи через preflight и <code>Access-Control-*</code>.</li>
<li>Cookies проверяй в request headers и вкладке Cookies.</li>
<li>Cache source объясняет «почему данные старые».</li>
<li>Timing помогает найти DNS/TLS/server/download bottleneck.</li>
</ul>
