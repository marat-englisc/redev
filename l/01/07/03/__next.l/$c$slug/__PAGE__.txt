<div class="callout-title">Кратко</div>
<div class="callout-body"><p><strong>Docker</strong> упаковывает приложение вместе с окружением (ОС-слой, Node.js, зависимости) в <strong>образ</strong>, из которого запускаются изолированные <strong>контейнеры</strong>. Фронтендеру Docker нужен, чтобы одинаково собирать проект локально и в CI, раздавать собранную статику через nginx, запускать SSR-приложение (Next.js) и поднимать зависимости разработки — API, базу, Redis — через <code>docker compose</code>.</p></div>
</div>
<h2 id="вопрос">Вопрос</h2>
<p>Что такое Docker и чем образ отличается от контейнера? Как написать Dockerfile для фронтенд-приложения и что такое multi-stage сборка?</p>
<h2 id="основные-понятия">Основные понятия</h2>





































<div class="table-wrap"><table><thead><tr><th>Понятие</th><th>Что это</th></tr></thead><tbody><tr><td>Image (образ)</td><td>неизменяемый шаблон: слои файловой системы + команда запуска</td></tr><tr><td>Container</td><td>запущенный экземпляр образа</td></tr><tr><td>Dockerfile</td><td>инструкции сборки образа</td></tr><tr><td>Layer</td><td>слой образа; неизмененные слои берутся из кеша</td></tr><tr><td>Registry</td><td>хранилище образов (Docker Hub, GHCR)</td></tr><tr><td>Volume</td><td>данные, переживающие пересоздание контейнера</td></tr><tr><td>Docker Compose</td><td>описание нескольких сервисов в <code>compose.yaml</code></td></tr></tbody></table></div>
<p>Контейнер — не виртуальная машина: он использует ядро хоста и запускается за секунды.</p>

<h2 id="что-важно-помнить">Что важно помнить</h2>
<ul>
<li>Порядок инструкций важен для кеша: сначала <code>package*.json</code> и <code>npm ci</code>, потом остальной код.</li>
<li>Добавьте <code>.dockerignore</code> (<code>node_modules</code>, <code>.git</code>, <code>dist</code>, <code>.env</code>), иначе образ раздуется, а секреты попадут внутрь.</li>
<li>Переменные <code>VITE_*</code> и <code>NEXT_PUBLIC_*</code> встраиваются при <strong>сборке</strong>: один образ на разные окружения требует runtime-конфига (например, <code>config.js</code>, генерируемого при старте контейнера).</li>
<li>Не запускайте процесс от root (<code>USER node</code>), фиксируйте версии базовых образов.</li>
<li>Контейнер должен корректно завершаться по <code>SIGTERM</code> — важно для SSR-сервера при перезапусках.</li>
</ul>
<h2 id="мини-шпаргалка">Мини-шпаргалка</h2>
<p>Образ — шаблон, контейнер — запущенный экземпляр. Multi-stage: собрать в <code>node</code>, отдать статику через <code>nginx</code> или запустить <code>standalone</code> Next.js. Кеш слоев: lockfile → <code>npm ci</code> → код. <code>.dockerignore</code>, <code>USER node</code>. Compose — БД и сервисы для разработки.</p>
