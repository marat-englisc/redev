Настройка VS Code для React и Next.js

Кратко

Не нужно устанавливать все расширения подряд. Основной набор подходит почти любому React- или Next.js-проекту, а инструменты для Stylelint, Vitest, Jest, Playwright и Prisma нужны только тогда, когда соответствующая технология используется в проекте.

Основные расширения

VS Code из коробки понимает JSX и TSX: подсказки, переход к определению, рефакторинги и переименование парных тегов (editor.linkedEditing) работают через встроенный TypeScript без отдельного расширения для React. Поэтому основной набор — это инструменты качества кода.

  1. ESLint (dbaeumer.vscode-eslint) — показывает ошибки ESLint, включая нарушения правил хуков, и применяет безопасные автоисправления.
  2. Prettier (esbenp.prettier-vscode) — единое форматирование JavaScript, TypeScript, JSX/TSX, CSS, JSON и Markdown.
  3. EditorConfig (editorconfig.editorconfig) — синхронизирует отступы, окончания строк и другие базовые правила между разными редакторами.
  4. Tailwind CSS IntelliSense (bradlc.vscode-tailwindcss) — автодополнение классов, превью CSS при наведении и диагностика конфликтующих классов. Tailwind CSS предлагается по умолчанию в create-next-app, поэтому для Next.js-проектов это расширение почти обязательно.

Расширения ESLint и Prettier не заменяют зависимости проекта. Для воспроизводимого результата установи eslint и prettier в devDependencies и храни их конфигурацию в репозитории. Если ESLint содержит стилистические правила, используй eslint-config-prettier, чтобы линтер и форматтер не спорили друг с другом.

В Next.js-проекте ESLint настраивается через eslint-config-next: он уже включает правила React, eslint-plugin-react-hooks (rules-of-hooks, exhaustive-deps) и @next/eslint-plugin-next. Для Tailwind CSS добавь prettier-plugin-tailwindcss — он сортирует классы в рекомендуемом порядке.

Полезные расширения по ситуации

Удобство разработки

  • Error Lens (usernamehw.errorlens) — выводит ошибки и предупреждения прямо возле проблемной строки.
  • Pretty TypeScript Errors (yoavbls.pretty-ts-errors) — делает длинные ошибки TypeScript более читаемыми. Особенно помогает с ошибками в типах props и дженерик-компонентах.
  • ES7+ React/Redux/React-Native snippets (dsznajder.es7-react-js-snippets) — сниппеты для компонентов, хуков и Redux (rafce, useState, useEffect). Полезно в работе, но на лайвкодинге всё равно нужно уметь писать без них.
  • Path Intellisense (christian-kohler.path-intellisense) — дополняет пути к файлам. Для импортов JavaScript и TypeScript сначала стоит попробовать встроенные подсказки VS Code.
  • ENV (IronGeek.vscode-env) — подсветка синтаксиса .env, .env.local и других файлов окружения Next.js.

Качество кода и тесты

  • Stylelint (stylelint.vscode-stylelint) — линтинг CSS, SCSS и CSS Modules (*.module.css), если проект не ограничивается Tailwind CSS.
  • Vitest (vitest.explorer) — запуск и отладка unit-тестов и тестов компонентов на React Testing Library из панели Testing.
  • Jest (Orta.vscode-jest) — то же самое для проектов на Jest.
  • Playwright Test for VS Code (ms-playwright.playwright) — запуск, запись и пошаговая отладка E2E-тестов.
  • GitLens (eamodio.gitlens) — история строк и файлов, blame и навигация по изменениям Git. Базовые Git-операции уже встроены в VS Code.
  • GitHub Pull Requests (GitHub.vscode-pull-request-github) — просмотр и ревью pull request без выхода из редактора.

Fullstack на Next.js

  • Prisma (Prisma.prisma) — подсветка, автодополнение и форматирование schema.prisma.
  • REST Client (humao.rest-client) — отправка HTTP-запросов из .http-файлов. Удобно проверять Route Handlers (app/api/**/route.ts) без Postman.

Для этого учебного проекта

  • Markdown All in One (yzhang.markdown-all-in-one) — удобная работа со списками, таблицами, оглавлением и предпросмотром Markdown.
  • markdownlint (DavidAnson.vscode-markdownlint) — проверка единообразия Markdown. Правила лучше настроить в .markdownlint.json, прежде чем проверять весь проект.
  • Code Spell Checker и русский словарь — поиск опечаток в тексте, комментариях и названиях.

Оформление

  • Symbols — иконки файлов и папок.
  • Lucide Product Icon Theme — иконки интерфейса VS Code.
  • Vesper — цветовая тема.
  • JetBrains Mono — шрифт с лигатурами.

Пояснения к настройкам:

  • ESLint исправляет только собственные ошибки через source.fixAll.eslint, не запуская все доступные исправления без разбора. Отдельный список eslint.validate не нужен: расширение по умолчанию проверяет .js, .jsx, .ts и .tsx.
  • editor.glyphMargin включён, чтобы были видны точки останова, статусы тестов и другие служебные значки.
  • editor.linkedEditing синхронно переименовывает открывающий и закрывающий тег — в JSX это работает через встроенный TypeScript.
  • При переименовании или перемещении файла VS Code автоматически обновляет импорты, а importModuleSpecifier: non-relative заставляет автоимпорт использовать алиас @/… из tsconfig.json (в Next.js он настроен по умолчанию) вместо цепочек ../../...
  • Emmet включён для JSX/TSX: div.card>h3+p разворачивается в разметку с className.
  • files.associations для *.css нужен Tailwind CSS 4: редактор перестаёт ругаться на @theme, @apply и другие директивы. tailwindCSS.classFunctions включает подсказки классов внутри cn(), cva() и clsx() — так устроены компоненты shadcn/ui.
  • explorer.fileNesting сворачивает lock-файлы, next-env.d.ts и .env.* под основные файлы, чтобы корень Next.js-проекта не был перегружен.
  • Включена подсветка невидимых и неоднозначных Unicode-символов. Русская локаль разрешена отдельно, чтобы кириллица в документации не создавала лишний шум.
  • Для фронтенд-проектов выбраны два пробела. Если в команде принят другой стиль, .editorconfig и настройки проекта должны иметь приоритет.

Настройки проекта

Личные параметры темы, шрифта и интерфейса лучше хранить в пользовательском settings.json. Общие для команды настройки форматирования и линтинга — в .vscode/settings.json, .editorconfig и конфигурациях инструментов внутри репозитория.

Версия TypeScript из проекта и плагин Next.js

Если TypeScript установлен в devDependencies, открой файл .ts или .tsx, выполни команду TypeScript: Select TypeScript Version и выбери Use Workspace Version. Так редактор и сборка будут использовать одну версию TypeScript.

Для Next.js это особенно важно: create-next-app добавляет в tsconfig.json плагин { "name": "next" }, а он работает только с версией TypeScript из проекта. Плагин подсказывает допустимые значения dynamic, revalidate и других опций сегмента маршрута, проверяет директиву 'use client' и предупреждает об использовании клиентских хуков в серверных компонентах. Сначала запусти конфигурацию debug server-side, затем debug client-side. Для изучения дерева компонентов, props, хуков и причин ререндеров дополнительно установи в браузер расширение React Developer Tools — его вкладка Profiler нужна для разбора производительности.

Профиль и синхронизация

  • Создай профиль React через File → Preferences → Profiles, чтобы расширения для веб-разработки не смешивались с другими наборами инструментов.
  • Включи Settings Sync, если нужно переносить настройки, сочетания клавиш и расширения между компьютерами.
  • При конфликтах расширений запусти Help: Start Extension Bisect: VS Code будет отключать их группами и поможет найти проблемное.
