<div class="callout-title">Кратко</div>
<div class="callout-body"><p>Не нужно устанавливать все расширения подряд. Основной набор подходит почти любому React- или Next.js-проекту, а инструменты для Stylelint, Vitest, Jest, Playwright и Prisma нужны только тогда, когда соответствующая технология используется в проекте.</p></div>
</div>
<h2 id="основные-расширения">Основные расширения</h2>
<p>VS Code из коробки понимает JSX и TSX: подсказки, переход к определению, рефакторинги и переименование парных тегов (<code>editor.linkedEditing</code>) работают через встроенный TypeScript без отдельного расширения для React. Поэтому основной набор — это инструменты качества кода.</p>
<ol>
<li><a href="https://marketplace.visualstudio.com/items?itemName=dbaeumer.vscode-eslint" target="_blank" rel="noopener noreferrer">ESLint</a> (<code>dbaeumer.vscode-eslint</code>) — показывает ошибки ESLint, включая нарушения правил хуков, и применяет безопасные автоисправления.</li>
<li><a href="https://marketplace.visualstudio.com/items?itemName=esbenp.prettier-vscode" target="_blank" rel="noopener noreferrer">Prettier</a> (<code>esbenp.prettier-vscode</code>) — единое форматирование JavaScript, TypeScript, JSX/TSX, CSS, JSON и Markdown.</li>
<li><a href="https://marketplace.visualstudio.com/items?itemName=editorconfig.editorconfig" target="_blank" rel="noopener noreferrer">EditorConfig</a> (<code>editorconfig.editorconfig</code>) — синхронизирует отступы, окончания строк и другие базовые правила между разными редакторами.</li>
<li><a href="https://marketplace.visualstudio.com/items?itemName=bradlc.vscode-tailwindcss" target="_blank" rel="noopener noreferrer">Tailwind CSS IntelliSense</a> (<code>bradlc.vscode-tailwindcss</code>) — автодополнение классов, превью CSS при наведении и диагностика конфликтующих классов. Tailwind CSS предлагается по умолчанию в <code>create-next-app</code>, поэтому для Next.js-проектов это расширение почти обязательно.</li>
</ol>
<p>Расширения ESLint и Prettier не заменяют зависимости проекта. Для воспроизводимого результата установи <code>eslint</code> и <code>prettier</code> в <code>devDependencies</code> и храни их конфигурацию в репозитории. Если ESLint содержит стилистические правила, используй <code>eslint-config-prettier</code>, чтобы линтер и форматтер не спорили друг с другом.</p>
<p>В Next.js-проекте ESLint настраивается через <code>eslint-config-next</code>: он уже включает правила React, <code>eslint-plugin-react-hooks</code> (<code>rules-of-hooks</code>, <code>exhaustive-deps</code>) и <code>@next/eslint-plugin-next</code>. Для Tailwind CSS добавь <code>prettier-plugin-tailwindcss</code> — он сортирует классы в рекомендуемом порядке.</p>

<p>Пояснения к настройкам:</p>
<ul>
<li>ESLint исправляет только собственные ошибки через <code>source.fixAll.eslint</code>, не запуская все доступные исправления без разбора. Отдельный список <code>eslint.validate</code> не нужен: расширение по умолчанию проверяет <code>.js</code>, <code>.jsx</code>, <code>.ts</code> и <code>.tsx</code>.</li>
<li><code>editor.glyphMargin</code> включён, чтобы были видны точки останова, статусы тестов и другие служебные значки.</li>
<li><code>editor.linkedEditing</code> синхронно переименовывает открывающий и закрывающий тег — в JSX это работает через встроенный TypeScript.</li>
<li>При переименовании или перемещении файла VS Code автоматически обновляет импорты, а <code>importModuleSpecifier: non-relative</code> заставляет автоимпорт использовать алиас <code>@/…</code> из <code>tsconfig.json</code> (в Next.js он настроен по умолчанию) вместо цепочек <code>../../..</code>.</li>
<li>Emmet включён для JSX/TSX: <code>div.card>h3+p</code> разворачивается в разметку с <code>className</code>.</li>
<li><code>files.associations</code> для <code>*.css</code> нужен Tailwind CSS 4: редактор перестаёт ругаться на <code>@theme</code>, <code>@apply</code> и другие директивы. <code>tailwindCSS.classFunctions</code> включает подсказки классов внутри <code>cn()</code>, <code>cva()</code> и <code>clsx()</code> — так устроены компоненты shadcn/ui.</li>
<li><code>explorer.fileNesting</code> сворачивает lock-файлы, <code>next-env.d.ts</code> и <code>.env.*</code> под основные файлы, чтобы корень Next.js-проекта не был перегружен.</li>
<li>Включена подсветка невидимых и неоднозначных Unicode-символов. Русская локаль разрешена отдельно, чтобы кириллица в документации не создавала лишний шум.</li>
<li>Для фронтенд-проектов выбраны два пробела. Если в команде принят другой стиль, <code>.editorconfig</code> и настройки проекта должны иметь приоритет.</li>
</ul>

<p>Если TypeScript установлен в <code>devDependencies</code>, открой файл <code>.ts</code> или <code>.tsx</code>, выполни команду <code>TypeScript: Select TypeScript Version</code> и выбери <code>Use Workspace Version</code>. Так редактор и сборка будут использовать одну версию TypeScript.</p>
<p>Для Next.js это особенно важно: <code>create-next-app</code> добавляет в <code>tsconfig.json</code> плагин <code>{ "name": "next" }</code>, а он работает только с версией TypeScript из проекта. Плагин подсказывает допустимые значения <code>dynamic</code>, <code>revalidate</code> и других опций сегмента маршрута, проверяет директиву <code>'use client'</code> и предупреждает об использовании клиентских хуков в серверных компонентах. <h3 id="профиль-и-синхронизация">Профиль и синхронизация</h3>
<ul>
<li>Создай профиль <code>React</code> через <code>File → Preferences → Profiles</code>, чтобы расширения для веб-разработки не смешивались с другими наборами инструментов.</li>
<li>Включи <code>Settings Sync</code>, если нужно переносить настройки, сочетания клавиш и расширения между компьютерами.</li>
<li>При конфликтах расширений запусти <code>Help: Start Extension Bisect</code>: VS Code будет отключать их группами и поможет найти проблемное.</li>
</ul>
