implements: как класс реализует интерфейс и чем это отличается от extends

Кратко

class A implements I проверяет, что класс содержит все члены интерфейса с совместимыми типами. Класс может реализовать несколько интерфейсов. implements ничего не наследует и не добавляет в класс — это только проверка формы. extends в классах наследует реализацию: методы, поля и конструктор родителя, причем родитель может быть только один.

Вопрос

Как класс реализует интерфейс? Что делает ключевое слово implements и чем implements отличается от extends в классах?

implements

Можно реализовать и объектный type alias: class A implements SomeType {}.

implements не наследует

Типы параметров методов тоже не выводятся из интерфейса — их нужно указать в классе.

Зачем нужен implements

  • контракт: несколько реализаций одного интерфейса (MemoryStorage, LocalStorageAdapter, RedisStorage) взаимозаменяемы;
  • ранняя ошибка: если интерфейс изменится, все реализации подсветятся;
  • dependency inversion: код зависит от интерфейса, а реализацию подставляют (удобно для тестов).

Из-за структурной типизации объект подходит под Storage и без implements, если форма совпадает. implements лишь гарантирует, что класс написан правильно.

Что важно помнить

  • Интерфейс описывает только публичную часть: private члены в нем объявить нельзя.
  • Статические члены не проверяются через implements — интерфейс описывает экземпляр.
  • Абстрактный класс — компромисс: часть реализации плюс обязательные абстрактные методы.
  • Предпочитайте композицию и интерфейсы глубоким цепочкам extends.

Мини-шпаргалка

  • implements I1, I2 — проверка, что класс соответствует интерфейсам.
  • Ничего не наследует, типы нужно объявить в классе.
  • extends — наследование реализации, один родитель.
  • Можно сочетать: class A extends B implements C.
  • Интерфейс — контракт для взаимозаменяемых реализаций.
