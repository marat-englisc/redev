Динамические ключи объекта и index signature

Кратко

Если ключи объекта заранее неизвестны, используют index signature: { [key: string]: number } — любой строковый ключ со значением number. Ту же задачу решает Record<string, number>, а для известного набора ключей — Record<"a" | "b", number> или mapped types. Доступ по несуществующему ключу TypeScript по умолчанию считает безопасным — флаг noUncheckedIndexedAccess добавляет | undefined.

Вопрос

Как описать объект с динамическими ключами? Что такое index signature в интерфейсе и чем она отличается от Record?

Совмещение с обычными полями

Все явные поля должны быть совместимы с типом значения index signature. Решение — union: [key: string]: string | number.

Безопасный доступ

С noUncheckedIndexedAccess: true тип станет number | undefined и потребует проверки. Для словарей с произвольными ключами также удобна Map<string, number>: map.get() возвращает V | undefined.

Ключи из другого типа

Что важно помнить

  • {} и object не являются словарями: для произвольных ключей нужен Record или index signature.
  • Ключи объекта в runtime — строки: [key: number] описывает доступ obj[1], но Object.keys вернет строки.
  • Слишком общий Record<string, any> убивает пользу типов — указывайте тип значений.
  • satisfies Record<Status, string> проверяет, что все ключи на месте, и сохраняет литеральные типы значений.

Мини-шпаргалка

  • { [key: string]: T } — index signature.
  • Record<string, T> — то же, Record<"a" | "b", T> — точные ключи.
  • Явные поля должны быть совместимы с index signature.
  • noUncheckedIndexedAccess добавляет | undefined.
  • Для динамических словарей — Map.
