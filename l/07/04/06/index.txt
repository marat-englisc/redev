<div class="callout-body"><p><strong>Hydration, гидратация</strong>, - подключение React к уже существующей серверной разметке, чтобы клиентские компоненты получили состояние и обработчики событий.</p></div>

<h2 id="вопрос">Вопрос</h2>
<p>Как готовый HTML становится интерактивным и почему возникает hydration mismatch?</p>
<h2 id="основная-идея">Основная идея</h2>
<p>Сервер может отправить HTML кнопки «Добавлено: 0». Браузер покажет ее, даже пока JavaScript еще загружается. Затем React использует эту разметку как начальную основу для клиентского компонента и подключает его поведение.</p>
<p>Это отличается от чистого клиентского монтирования, при котором React создает интерфейс внутри пустого контейнера. В Next.js гидратацией управляет фреймворк, вручную вызывать <code>hydrateRoot</code> обычно не требуется.</p>
<p>В App Router гидратируются клиентские компоненты. Код серверных компонентов не отправляется в браузер для гидратации; браузер получает результат их работы и сведения о клиентских границах.</p>

<p>Импортируй компонент в любую страницу App Router. Сначала сервер и браузер показывают одинаковое «Здравствуйте, гость!». После гидратации эффект читает сохраненное имя. Если хранилище недоступно или имя отсутствует, остается значение по умолчанию.</p>
<p>Чтение перенесено в эффект, потому что <code>localStorage</code> существует только в браузере. Само наличие <code>"use client"</code> не делает такое чтение безопасным во время начального серверного рендера.</p>
<h2 id="что-важно-помнить">Что важно помнить</h2>
<p><strong>Hydration mismatch</strong> означает, что начальный клиентский результат не совпал с серверным HTML. Причинами бывают случайные числа, текущее время, различия локалей и неправильная вложенность HTML-тегов.</p>
<p>Первый рендер должен давать одинаковый результат в обеих средах. Браузерные изменения можно применять после подключения React. <code>suppressHydrationWarning</code> предназначен для узких неизбежных различий, а не для исправления ошибочной архитектуры.</p>
<p>Гидратация не равна загрузке данных и не делает серверный код доступным в браузере.</p>
<h2 id="мини-шпаргалка">Мини-шпаргалка</h2>
<ul>
<li>Сначала отображается HTML, затем подключается поведение.</li>
<li>Начальная серверная и клиентская разметки должны совпадать.</li>
<li>Браузерные API используй в эффектах или обработчиках.</li>
<li>Серверные компоненты отдельно не гидратируются.</li>
</ul>
