<div class="callout-title">Кратко</div>
<div class="callout-body"><p><strong>Пул промисов (concurrency limit)</strong> выполняет много асинхронных задач, но <strong>не больше <code>limit</code> одновременно</strong>: как только одна завершается, запускается следующая. Это нужно, чтобы не открыть 500 запросов сразу (лимиты браузера и сервера, rate limiting). Решение: несколько «воркеров», каждый в цикле берет следующую задачу из общей очереди; результаты сохраняются <strong>по индексу</strong>, чтобы порядок совпадал с исходным.</p></div>
</div>
<h2 id="вопрос">Вопрос</h2>
<p>Реализуйте <code>promisePool(tasks, limit)</code>, где <code>tasks</code> — массив функций, возвращающих промисы. Одновременно должно выполняться не больше <code>limit</code> задач, результат — массив в исходном порядке.</p>

<h2 id="доп-вопросы-интервьюера">Доп. вопросы интервьюера</h2>
<ul>
<li><strong>Почему задачи — функции?</strong> чтобы управлять моментом запуска.</li>
<li><strong>Есть ли гонка при <code>nextIndex++</code>?</strong> нет: JavaScript выполняет код в одном потоке, инкремент происходит синхронно между <code>await</code>.</li>
<li><strong>Как добавить отмену?</strong> проверять <code>signal.aborted</code> перед взятием следующей задачи и передавать <code>signal</code> в задачи.</li>
<li><strong>Сложность?</strong> время ≈ сумма длительностей / limit, память O(n).</li>
</ul>
<h2 id="что-важно-помнить">Что важно помнить</h2>
<ul>
<li>Результаты по индексу — порядок исходный.</li>
<li><code>Math.min(limit, tasks.length)</code> — не создавать лишних воркеров.</li>
<li>Решите, что делать при ошибке: остановить всё или собрать статусы.</li>
<li>В браузере на HTTP/1.1 есть свой лимит ~6 соединений на домен — пул все равно полезен для контроля нагрузки и порядка.</li>
</ul>
