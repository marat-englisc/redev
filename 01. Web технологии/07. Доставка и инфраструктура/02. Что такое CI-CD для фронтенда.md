# Что такое CI/CD для фронтенда

> [!NOTE]
> **CI (Continuous Integration)** — автоматическая проверка каждого изменения: установка зависимостей, линтер, проверка типов, тесты и сборка при каждом push или pull request. **CD (Continuous Delivery / Deployment)** — автоматическая доставка проверенной сборки на окружения: preview, staging, production. Для фронтенда пайплайн обычно запускается в GitHub Actions или GitLab CI, а деплой идет на Vercel, Netlify, S3 + CDN или в Docker-контейнер.

## Вопрос

Что такое CI/CD? Из каких шагов состоит пайплайн фронтенд-проекта и как организовать деплой?

## Типичный пайплайн

```text
push / pull request
  → установка зависимостей (npm ci, кеш)
  → lint (ESLint, Stylelint) + format check (Prettier)
  → typecheck (tsc --noEmit)
  → unit и integration тесты (Vitest / Jest)
  → build
  → e2e тесты (Playwright) на собранном приложении
  → preview-деплой для PR
merge в main
  → деплой на staging → проверка → production
```

## Пример: GitHub Actions

```yaml
# .github/workflows/ci.yml
name: CI

on:
  pull_request:
  push:
    branches: [main]

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version-file: .nvmrc
          cache: npm
      - run: npm ci
      - run: npm run lint
      - run: npm run typecheck
      - run: npm test -- --run
      - run: npm run build
      - uses: actions/upload-artifact@v4
        with:
          name: dist
          path: dist
```

## Continuous Delivery и Deployment

| | Continuous Delivery | Continuous Deployment |
| --- | --- | --- |
| Сборка готова к релизу | всегда | всегда |
| Выкатка в production | по кнопке / одобрению | автоматически после зеленого пайплайна |

## Стратегии выкатки

- **Preview-окружения** — отдельный URL для каждого PR (Vercel, Netlify), удобно для ревью и QA.
- **Атомарный деплой** — новая версия полностью загружается, затем переключается одним шагом.
- **Canary / постепенная выкатка** — новая версия сначала для части пользователей.
- **Feature flags** — код в production, но функция включается флагом без нового деплоя.
- **Rollback** — быстрый откат на предыдущую сборку.

## Особенности фронтенда

- **Хеши в именах файлов** (`app.3f9a1c.js`) + `Cache-Control: immutable` для статики, а `index.html` — `no-cache`, чтобы пользователи получали новую версию.
- **Переменные окружения** встраиваются в бандл на этапе сборки (`VITE_*`, `NEXT_PUBLIC_*`) — секреты туда класть нельзя.
- **Source maps** загружают в Sentry, а не раздают публично.
- **Бюджет размера бандла** и Lighthouse CI — защита от регрессий производительности.

## Что важно помнить

- `npm ci`, а не `npm install`: строгая установка по lockfile.
- Кеш зависимостей и параллельные jobs сокращают время пайплайна.
- Секреты хранят в настройках CI (Secrets), а не в репозитории и не в логах.
- Обязательные проверки (branch protection) не дают смержить PR с красным пайплайном.
- Pre-commit хуки (husky, lint-staged) ускоряют обратную связь, но не заменяют CI — их можно обойти.

## Мини-шпаргалка

CI — проверка каждого изменения: `npm ci` → lint → typecheck → test → build → e2e. CD — автоматическая доставка: preview для PR, staging, production. Delivery — релиз по кнопке, Deployment — автоматически. Хешированная статика + `no-cache` для HTML, секреты в CI Secrets.
