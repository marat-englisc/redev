# Что такое PWA (Progressive Web App)

> [!NOTE]
> **PWA** — веб-приложение, которое можно установить на устройство и которое ведет себя похоже на нативное: открывается в отдельном окне, работает офлайн или при плохой сети, может получать push-уведомления. Основа PWA — три вещи: **HTTPS**, **Web App Manifest** (описание приложения для установки) и **Service Worker** (прокси между страницей и сетью, который кеширует ресурсы и запросы).

## Вопрос

Что такое PWA и из чего оно состоит? Как Service Worker обеспечивает офлайн-режим и какие стратегии кеширования бывают?

## Web App Manifest

```json
// public/manifest.webmanifest
{
  "name": "Мои задачи",
  "short_name": "Задачи",
  "start_url": "/",
  "display": "standalone",
  "background_color": "#ffffff",
  "theme_color": "#2563eb",
  "icons": [
    { "src": "/icons/192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/icons/512.png", "sizes": "512x512", "type": "image/png", "purpose": "any maskable" }
  ]
}
```

```html
<link rel="manifest" href="/manifest.webmanifest" />
<meta name="theme-color" content="#2563eb" />
```

`display: standalone` — окно без адресной строки браузера.

## Service Worker

```javascript
// main.js — регистрация
if ("serviceWorker" in navigator) {
  navigator.serviceWorker.register("/sw.js");
}
```

```javascript
// sw.js — выполняется в отдельном потоке, без доступа к DOM
const CACHE = "app-v2";
const ASSETS = ["/", "/index.html", "/app.js", "/styles.css", "/offline.html"];

self.addEventListener("install", (event) => {
  event.waitUntil(caches.open(CACHE).then((cache) => cache.addAll(ASSETS)));
});

self.addEventListener("activate", (event) => {
  event.waitUntil(
    caches.keys().then((keys) => Promise.all(keys.filter((k) => k !== CACHE).map((k) => caches.delete(k)))),
  );
});

self.addEventListener("fetch", (event) => {
  event.respondWith(
    caches.match(event.request).then((cached) => cached ?? fetch(event.request)),
  );
});
```

Жизненный цикл: `install` (предкеширование) → `waiting` (ждет, пока закроются старые вкладки) → `activate` (очистка старых кешей) → `fetch` (перехват запросов).

## Стратегии кеширования

| Стратегия | Как работает | Для чего |
| --- | --- | --- |
| Cache First | сначала кеш, при промахе — сеть | статика с хешем в имени, шрифты |
| Network First | сначала сеть, при ошибке — кеш | HTML, API с важной свежестью |
| Stale-While-Revalidate | сразу из кеша, параллельно обновляет | аватары, некритичные данные |
| Network Only | только сеть | платежи, авторизация |
| Cache Only | только кеш | предкешированная оболочка |

На практике Service Worker генерируют через **Workbox** или плагины сборщиков (`vite-plugin-pwa`).

## Возможности PWA

- установка на главный экран и рабочий стол;
- офлайн-работа и оболочка приложения (App Shell);
- push-уведомления (Push API + Notifications API);
- фоновая синхронизация (Background Sync, поддержка ограничена);
- значки на иконке (Badging API).

## Что важно помнить

- Service Worker работает только по HTTPS (и на `localhost`) и в своей области видимости (`scope`) — обычно кладется в корень.
- Новый Service Worker не активируется, пока открыты вкладки со старым. `skipWaiting()` + `clients.claim()` ускоряют обновление, но могут смешать старый HTML и новые скрипты — показывайте пользователю «Доступна новая версия».
- Не кешируйте Cache First HTML без версионирования — пользователи застрянут на старой версии.
- На iOS возможности PWA ограничены: push работает только для установленных на экран приложений, есть лимиты хранилища.
- Service Worker — не кеш HTTP: они работают вместе, сначала запрос проходит через SW.

## Мини-шпаргалка

PWA = HTTPS + manifest + Service Worker. Manifest: имя, иконки, `display: standalone`. SW: `install` → `activate` → `fetch`, Cache API. Стратегии: Cache First, Network First, Stale-While-Revalidate. Инструменты: Workbox, `vite-plugin-pwa`.
