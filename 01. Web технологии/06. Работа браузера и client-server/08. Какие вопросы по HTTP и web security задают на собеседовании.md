# Какие вопросы по HTTP и web security задают на собеседовании?

> [!NOTE]
> На собеседовании по frontend часто проверяют не заучивание status codes, а понимание браузерной модели: HTTP, CORS, cookies, cache, auth, XSS, CSRF, HTTPS и debugging через DevTools.

## Вопрос

Какие вопросы по HTTP и web security чаще всего задают на собеседовании frontend-разработчика?

## HTTP

**Вопрос:** Чем `GET` отличается от `POST`?

**Ответ:** `GET` предназначен для чтения и не должен менять состояние. `POST` отправляет данные для создания ресурса или запуска действия и обычно не является idempotent.

**Вопрос:** Почему `fetch` не попадает в `catch` на `404`?

**Ответ:** Потому что `404` - это HTTP response. `fetch` считает promise выполненным, если response получен. Нужно проверять `response.ok`.

## Status codes

**Вопрос:** Чем `401` отличается от `403`?

**Ответ:** `401` - пользователь не authenticated. `403` - authenticated, но прав недостаточно.

**Вопрос:** Когда использовать `409`?

**Ответ:** Когда есть конфликт текущего состояния, например email уже занят или версия документа устарела.

## Cookies и sessions

**Вопрос:** Чем cookie отличается от session?

**Ответ:** Cookie хранится в браузере. Session обычно хранится на сервере, а cookie хранит session id.

**Вопрос:** Зачем `HttpOnly`?

**Ответ:** Чтобы JavaScript не мог прочитать cookie через `document.cookie`, что снижает риск кражи session/token при XSS.

## CORS

**Вопрос:** CORS защищает backend?

**Ответ:** CORS - browser mechanism. Он ограничивает чтение cross-origin response JavaScript-кодом, но не заменяет authentication/authorization и не останавливает curl/Postman/server clients.

## XSS и CSRF

**Вопрос:** Чем XSS отличается от CSRF?

**Ответ:** XSS выполняет чужой JavaScript на сайте. CSRF заставляет browser пользователя отправить authenticated request на сайт. XSS связан с injection/rendering, CSRF - с automatic credentials и state-changing requests.

## HTTPS

**Вопрос:** Что дает HTTPS?

**Ответ:** HTTPS через TLS шифрует канал, проверяет server identity и защищает данные от чтения/подмены в сети. Но он не исправляет XSS, CSRF и ошибки authorization.

## Что важно помнить

- Классический вопрос «что происходит после ввода URL» лучше отвечать по уровням и углубляться туда, куда ведет интервьюер.
- На вопрос «где хранить токен» нет единственного правильного ответа — объясните угрозы и компромиссы.
- Будьте готовы показать в DevTools, как вы отлаживаете CORS, cookies и cache.
- Связывайте теорию с практикой: «у нас на проекте был такой баг с SameSite...» ценится выше определения.

## Мини-шпаргалка

- Готовься объяснять причины, а не только определения.
- Умей читать Network tab.
- Знай `401` vs `403`, `400` vs `422`, `200` vs `201`.
- CORS - browser policy, не backend auth.
- XSS и CSRF требуют разных защит.
- HTTPS защищает транспорт, не бизнес-логику.
