# Как читать Network tab в DevTools?

> [!NOTE]
> Network tab — главный инструмент для диагностики client-server проблем. В нем видно, ушел ли request, какие method, URL и headers отправлены, какие cookies приложились, был ли preflight, откуда взялся response (сеть или cache) и сколько времени занял каждый этап.

## Вопрос

Как с помощью DevTools понять, почему запрос не работает: ошибка во frontend, в backend, в CORS, в cookies или в cache?

## Где смотреть?

Открой DevTools → Network → выбери запрос. Полезные вкладки:

| Вкладка | Что показывает |
|---|---|
| `Headers` | URL, method, status, request и response headers |
| `Payload` | query string, form data, JSON body |
| `Response` / `Preview` | сырое и отформатированное тело ответа |
| `Cookies` | отправленные и установленные cookies, причины блокировки |
| `Timing` | DNS, connection, TLS, ожидание сервера (TTFB), загрузка |
| `Initiator` | какой код или ресурс запустил запрос |

Полезные настройки панели: `Preserve log` (не очищать при навигации и редиректах), `Disable cache` (работает, пока DevTools открыты), `Throttling` (медленная сеть), фильтры `Fetch/XHR`, `Doc`, `JS`.

## Базовый чеклист

1. Найди нужный request.
2. Проверь method и URL.
3. Проверь status code.
4. Проверь request headers.
5. Проверь payload.
6. Проверь response headers.
7. Проверь response body.
8. Проверь cookies.
9. Проверь timing и cache source.

## Что проверять при ошибке?

| Симптом | Что смотреть |
|---|---|
| `401` | отправился ли `Authorization` или cookie |
| `403` | есть ли роль/permission |
| CORS error, `(blocked:cors)` | `Origin`, preflight `OPTIONS`, `Access-Control-Allow-*` |
| Не обновились данные | method, payload, status, response body |
| Cache мешает | `Cache-Control`, `ETag`, `304`, size `(memory cache)` / `(disk cache)` |
| Cookie не ставится | `Set-Cookie`, `SameSite`, `Secure`, `Domain`, `Path`, предупреждение во вкладке Cookies |
| `500` | response body, `requestId` для поиска в логах backend |

## CORS

Status `(blocked:cors)` или ошибка в Console означает, что browser заблокировал чтение response. Смотри:

- `Origin` в request;
- `Access-Control-Allow-Origin` и `Access-Control-Allow-Credentials` в response;
- preflight `OPTIONS` — отдельная строка перед основным запросом;
- allowed methods и headers.

Если preflight упал, основного запроса не будет вовсе.

## Cache

`from memory cache` / `from disk cache` означает, что response взят из browser cache и server мог вообще не получить request. `304 Not Modified` — запрос ушел, но сервер подтвердил, что сохраненная копия актуальна. Чтобы проверить реальный request, включи `Disable cache`.

## Cookies

Открой request → Headers → Request Headers:

```http
Cookie: sid=abc
```

Если cookie нет, смотри вкладку Cookies и attributes: `Domain`, `Path`, `SameSite`, `Secure`, expiration, credentials mode (`credentials: 'include'`). Chrome показывает причину, по которой cookie была отфильтрована.

## Почему request может не появиться?

Если ошибка произошла до сети, запроса может не быть:

- JavaScript exception до `fetch`;
- browser заблокировал mixed content;
- URL собран неправильно;
- request отменен `AbortController`;
- service worker перехватил запрос (смотри колонку Size: `(ServiceWorker)`);
- фильтр Network скрывает запрос.

## Как понять, что ошибка на backend?

Если request ушел, response пришел, status `500`, а CORS не блокирует чтение, вероятно, ошибка на server side. Но frontend все равно должен корректно обработать `500`, показать fallback и не падать всем приложением.

```ts
const response = await fetch('/api/users');

if (!response.ok) {
  const error = await response.json().catch(() => ({}));
  throw new Error(error.message ?? `HTTP ${response.status}`);
}
```

`fetch` не бросает ошибку на `404` или `500`: в Network status будет красным, но в коде нужно проверить `response.ok`.

## Что важно помнить

- Network tab показывает факты, а не предположения: начинай отладку с него, а не с кода.
- Timing `Waiting for server response` (TTFB) показывает медленный backend, `Content Download` — большой ответ или медленную сеть.
- Правый клик → `Copy as cURL` / `Copy as fetch` позволяет воспроизвести запрос вне приложения.
- HAR-файл (экспорт панели) удобно приложить к баг-репорту, но в нем есть cookies и токены — очищай перед отправкой.

## Мини-шпаргалка

- Всегда смотри method, URL, status, headers, payload и response.
- CORS ищи через preflight и `Access-Control-*`.
- Cookies проверяй в request headers и вкладке Cookies.
- Cache source объясняет «почему данные старые».
- Timing помогает найти DNS/TLS/server/download bottleneck.
