# Как браузер решает отправлять cookies, CORS и cache?

> [!NOTE]
> Browser перед request проверяет сразу несколько правил: есть ли cached response, подходит ли cookie по domain/path/SameSite/Secure, нужен ли CORS, нужен ли preflight и можно ли отдать response JavaScript-коду.

## Вопрос

В каком порядке браузер применяет правила cache, cookies и CORS к запросу? Как отлаживать проблемы на стыке этих механизмов?

## Упрощенный алгоритм

```txt
fetch(url)
 -> проверить cache
 -> понять origin
 -> подобрать cookies
 -> при необходимости сделать preflight
 -> отправить request
 -> получить response
 -> проверить CORS
 -> сохранить cookies/cache
 -> отдать response JS
```

Порядок в реальных браузерах сложнее, но такая модель помогает debugging.

## Cookies

Browser проверяет:

- domain;
- path;
- `Secure`;
- `SameSite`;
- expiration;
- request credentials mode.

Если условие не выполнено, cookie не уйдет.

## CORS

Если request cross-origin, browser проверяет CORS headers. Если server не разрешил origin, JavaScript не получит response.

Важно: request мог дойти до server, но browser все равно заблокирует чтение response.

## Cache

Если response fresh, browser может взять его из cache. Если нужен revalidation, browser отправит conditional request с `If-None-Match` или `If-Modified-Since`.

## Почему это сложно?

Потому что frontend bug может быть не в JavaScript-коде, а в:

- cookie attributes;
- CORS headers;
- cache headers;
- HTTPS/mixed content;
- service worker;
- redirect;
- preflight.

## Что важно помнить

- Service Worker перехватывает запрос раньше HTTP cache и может вернуть ответ, не обращаясь к сети.
- Redirect на другой origin заново запускает проверки CORS и подбор cookies для нового адреса.
- Ответ, заблокированный CORS, может всё равно сохраниться в HTTP cache и повлиять на следующий запрос, если нет `Vary: Origin`.
- Отлаживайте по одному механизму: сначала убедитесь, что запрос ушел, затем cookies, затем CORS, затем cache.

## Мини-шпаргалка

- Browser сам применяет security/cache rules.
- Cookie может не отправиться из-за `SameSite`, `Secure`, domain или credentials mode.
- CORS может заблокировать чтение response.
- Cache может вернуть старый response.
- Network tab нужен для проверки реальности, а не предположений.
