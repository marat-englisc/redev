# Какие response headers важно знать?

> [!NOTE]
> Response headers управляют тем, как browser обработает ответ: как прочитать body, сохранить cookie, применить cache, разрешить CORS, включить security policy или скачать файл.

## Вопрос

Какие response headers важно знать? Какие из них отвечают за cache, cookies, CORS и безопасность?

## Частые response headers

| Header | Пример | Зачем нужен |
|---|---|---|
| `Content-Type` | `application/json` | формат response body |
| `Set-Cookie` | `sid=abc; HttpOnly` | установить cookie |
| `Cache-Control` | `no-store` | правила кеширования |
| `ETag` | `"abc123"` | cache validation |
| `Location` | `/users/42` | redirect или созданный ресурс |
| `Access-Control-Allow-Origin` | `https://app.example.com` | CORS |
| `Content-Disposition` | `attachment` | скачать файл |
| `Strict-Transport-Security` | `max-age=31536000` | HSTS |
| `Content-Security-Policy` | `default-src 'self'` | защита от XSS impact |

## Content-Type

```http
Content-Type: application/json; charset=utf-8
```

Если server возвращает JSON, но ставит неправильный `Content-Type`, клиентские библиотеки, браузер или proxy могут обработать ответ не так, как ожидается.

## Set-Cookie

```http
Set-Cookie: sid=abc; HttpOnly; Secure; SameSite=Lax; Path=/
```

`Set-Cookie` говорит браузеру сохранить cookie. Потом browser будет отправлять ее через request header `Cookie`, если правила cookie позволяют.

## Location

После создания ресурса:

```http
HTTP/1.1 201 Created
Location: /api/users/42
```

При redirect:

```http
HTTP/1.1 302 Found
Location: /login
```

## Security headers

Security headers не заменяют исправление уязвимостей, но снижают риски:

- `Content-Security-Policy`;
- `Strict-Transport-Security`;
- `X-Content-Type-Options`;
- `Referrer-Policy`;
- `Permissions-Policy`.

## Что важно помнить

- `Content-Disposition: attachment; filename="report.pdf"` заставляет браузер скачать файл, а `inline` — открыть его.
- `Vary: Accept-Encoding, Origin` сообщает cache, от каких request headers зависит ответ; без него CDN может отдать чужую версию.
- Сервер может прислать несколько `Set-Cookie` в одном ответе — каждый устанавливает отдельную cookie.
- Header `Server` и `X-Powered-By` лучше не раскрывать в production: они помогают атакующему узнать версию ПО.

## Мини-шпаргалка

- `Content-Type` говорит, как читать body.
- `Set-Cookie` сохраняет cookie в браузере.
- `Cache-Control` управляет cache.
- `ETag` помогает понять, изменился ли ресурс.
- `Access-Control-Allow-Origin` участвует в CORS.
- Security headers - дополнительный слой защиты.
