# Что такое cookies и Set-Cookie?

> [!NOTE]
> Cookie - небольшое значение, которое browser хранит для сайта. Server устанавливает cookie через response header `Set-Cookie`, а browser потом автоматически отправляет подходящие cookies обратно через request header `Cookie`.

## Вопрос

Что такое cookies? Как сервер их устанавливает и когда браузер отправляет их обратно?

## Зачем нужны cookies?

Cookies помогают добавить состояние поверх stateless HTTP:

- session id;
- refresh token;
- выбранный язык;
- theme;
- analytics id;
- consent settings.

## Как server ставит cookie?

```http
HTTP/1.1 200 OK
Set-Cookie: sid=abc123; HttpOnly; Secure; SameSite=Lax; Path=/
```

Browser сохраняет cookie, если правила позволяют.

## Как browser отправляет cookie?

```http
GET /api/me HTTP/1.1
Cookie: sid=abc123
```

Frontend обычно не добавляет `Cookie` header вручную. Browser делает это сам.

## Cookie - это не session

Cookie хранится в браузере. Session обычно хранится на сервере.

```txt
Cookie в браузере:
sid=abc123

Session на сервере:
abc123 -> { userId: 42, role: "admin" }
```

Cookie может хранить session id, но сама session - это не cookie.

## Cookies и JavaScript

Если cookie не `HttpOnly`, ее можно прочитать:

```ts
console.log(document.cookie);
```

Для auth cookies почти всегда нужен `HttpOnly`, чтобы снизить риск кражи токена через XSS.

## Что важно помнить

- Размер одной cookie ограничен примерно 4 КБ, а количество на домен — десятками штук. Большие данные храните на сервере или в storage.
- Cookies отправляются с каждым подходящим запросом, включая картинки и CSS, поэтому лишние cookies увеличивают трафик.
- `document.cookie = 'theme=dark'` добавляет или обновляет одну cookie, а не перезаписывает все.
- Префиксы `__Host-` и `__Secure-` в имени заставляют браузер проверять безопасные атрибуты (`Secure`, `Path=/`, без `Domain`).
- Сторонние (third-party) cookies в браузерах ограничиваются, поэтому кросс-сайтовая авторизация через них ненадежна.

## Мини-шпаргалка

- `Set-Cookie` приходит от сервера.
- `Cookie` уходит от браузера к серверу.
- Browser отправляет cookies автоматически по правилам domain/path/security.
- Cookie может хранить session id или token.
- Для auth cookie обычно нужны `HttpOnly`, `Secure`, `SameSite`.
