# Что такое session?

> [!NOTE]
> Session - способ хранить состояние пользователя между HTTP-запросами. Обычно server хранит session data, а browser хранит только session id в cookie.

## Вопрос

Что такое session? Где хранятся данные сессии и чем session-подход отличается от токенов?

## Почему session вообще нужна?

HTTP stateless. После login server должен как-то узнавать пользователя в следующих запросах.

Один из классических вариантов:

```txt
1. User вводит login/password.
2. Server проверяет credentials.
3. Server создает session: sid -> userId.
4. Server отправляет sid в cookie.
5. Browser отправляет cookie в следующих requests.
6. Server по sid находит userId.
```

## Session cookie

```http
Set-Cookie: sid=s3cr3t; HttpOnly; Secure; SameSite=Lax; Path=/
```

В cookie лежит не весь пользователь, а случайный session id.

## Где хранится session?

Session data может храниться:

- в памяти server process;
- в Redis;
- в database;
- в distributed session store.

Для production memory sessions часто опасны: при рестарте они пропадают, а при нескольких backend instances пользователь может попасть на instance без своей session.

## Session vs token

| Подход | Где состояние | Как server проверяет |
|---|---|---|
| Session | server-side store | ищет session id |
| JWT access token | внутри token claims | проверяет подпись и срок |
| Opaque token | server/database/auth service | ищет token |

Session проще отозвать: удалил запись на сервере, и session больше не работает.

## Logout

При logout нужно:

1. удалить или инвалидировать session на сервере;
2. очистить cookie в браузере.

```http
Set-Cookie: sid=; Max-Age=0; Path=/; HttpOnly; Secure; SameSite=Lax
```

## Что важно помнить

- Session id должен быть длинным и криптографически случайным, иначе его можно подобрать.
- После входа session id нужно перевыпустить (regenerate), чтобы защититься от session fixation.
- Нужны два таймаута: неактивности (idle) и абсолютный срок жизни сессии.
- Session store (Redis, БД) становится зависимостью: при его недоступности все пользователи «разлогинятся».

## Мини-шпаргалка

- Session хранит состояние между запросами.
- Cookie часто хранит только session id.
- Session data лучше хранить в Redis/database для production.
- Session легко отозвать на сервере.
- Logout должен инвалидировать server session и очистить cookie.
