# Какие request headers важно знать?

> [!NOTE]
> Request headers помогают серверу понять контекст запроса: формат данных, ожидаемый ответ, credentials, origin, язык, cache behavior и техническую информацию о клиенте.

## Вопрос

Какие request headers важно знать frontend-разработчику? Чем `Accept` отличается от `Content-Type`?

## Частые request headers

| Header | Пример | Зачем нужен |
|---|---|---|
| `Accept` | `application/json` | какой response format ожидает клиент |
| `Content-Type` | `application/json` | формат request body |
| `Authorization` | `Bearer token` | credentials для auth |
| `Cookie` | `sid=abc` | cookies, которые browser отправляет автоматически |
| `Origin` | `https://app.example.com` | origin cross-origin request |
| `Referer` | `https://app.example.com/page` | страница-источник |
| `Accept-Language` | `ru-RU` | предпочитаемый язык |
| `If-None-Match` | `"etag-value"` | cache revalidation |

## Accept и Content-Type

```http
POST /api/users
Accept: application/json
Content-Type: application/json
```

`Accept` говорит: "я хочу получить JSON". `Content-Type` говорит: "я отправляю JSON".

Их часто путают.

## Authorization

```http
Authorization: Bearer eyJhbGciOi...
```

Этот header обычно отправляют вручную из frontend-кода:

```ts
fetch('/api/me', {
  headers: {
    Authorization: `Bearer ${accessToken}`,
  },
});
```

Если auth построена на cookies, `Authorization` может не использоваться.

## Cookie

```http
Cookie: sid=abc; theme=dark
```

Браузер сам формирует `Cookie` header на основе сохраненных cookies, если совпадают domain/path/security rules.

Frontend JavaScript не может вручную выставить header `Cookie` в `fetch`: это контролирует browser.

## Origin

```http
Origin: https://app.example.com
```

`Origin` важен для CORS и CSRF-защит. Сервер может разрешить или запретить request по origin.

## Что важно помнить

- При отправке `FormData` через `fetch` не указывайте `Content-Type` вручную: браузер сам поставит `multipart/form-data` с правильным `boundary`.
- `Authorization` и `Content-Type: application/json` в cross-origin запросе вызывают preflight.
- `Referer` пишется с ошибкой (историческая опечатка), а связанный header политики — `Referrer-Policy` — уже правильно.
- `Accept-Encoding` (gzip, br) браузер добавляет сам, вручную его задавать не нужно.

## Мини-шпаргалка

- `Accept` - что клиент хочет получить.
- `Content-Type` - что клиент отправляет.
- `Authorization` - bearer/basic credentials.
- `Cookie` отправляется браузером автоматически.
- `Origin` важен для CORS.
- `If-None-Match` помогает cache revalidation.
