# Что такое ETag и conditional requests?

> [!NOTE]
> `ETag` - идентификатор версии ресурса. Browser может отправить `If-None-Match`, а server ответит `304 Not Modified`, если ресурс не изменился. Так экономятся body и bandwidth.

## Вопрос

Что такое `ETag` и conditional requests? Когда сервер возвращает `304` и `412`?

## Первый запрос

```http
GET /assets/app.js
```

Ответ:

```http
HTTP/1.1 200 OK
ETag: "v1-app-js"
Cache-Control: no-cache

console.log('app');
```

Browser сохраняет body и `ETag`.

## Повторный запрос

```http
GET /assets/app.js
If-None-Match: "v1-app-js"
```

Если ресурс не изменился:

```http
HTTP/1.1 304 Not Modified
ETag: "v1-app-js"
```

Body не отправляется. Browser берет сохраненную копию.

## ETag для API

`ETag` можно использовать и для API:

```http
GET /api/profile
If-None-Match: "profile-v7"
```

Но для персональных данных нужно внимательно настроить `Cache-Control`, чтобы shared caches не сохранили приватный response.

## ETag и optimistic concurrency

Иногда `ETag` используют, чтобы не перезаписать чужие изменения:

```http
PATCH /api/articles/1
If-Match: "article-v3"
```

Если статья уже изменилась, server может вернуть:

```http
HTTP/1.1 412 Precondition Failed
```

## Что важно помнить

- Альтернатива `ETag` — пара `Last-Modified` / `If-Modified-Since`, но она точна только до секунды.
- Weak ETag (`W/"abc"`) означает смысловую эквивалентность, strong — побайтовую. Для `If-Match` нужен strong.
- За балансировщиком ETag должен быть одинаковым на всех серверах, иначе revalidation всегда будет возвращать `200`.
- `304` всё равно требует round-trip до сервера; полностью сэкономить запрос позволяет только свежий `max-age`.

## Мини-шпаргалка

- `ETag` обозначает версию ресурса.
- `If-None-Match` спрашивает, изменился ли ресурс.
- `304` означает использовать cached body.
- Conditional requests экономят трафик.
- Для private API нужно аккуратно настроить cache headers.
