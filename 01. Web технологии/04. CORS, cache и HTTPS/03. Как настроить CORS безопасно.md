# Как настроить CORS безопасно?

> [!NOTE]
> Безопасный CORS разрешает только нужные origins, методы и headers. Если запросы используют cookies, нужно включить credentials и нельзя использовать wildcard `*` в `Access-Control-Allow-Origin`.

## Вопрос

Как безопасно настроить CORS на сервере? Какие ошибки конфигурации встречаются чаще всего?

## Плохая настройка

```http
Access-Control-Allow-Origin: *
Access-Control-Allow-Credentials: true
```

Для credentialed requests такая комбинация не подходит. Browser не должен принимать wildcard origin вместе с credentials.

## Хорошая идея

Разрешай конкретные origins:

```txt
https://app.example.com
https://admin.example.com
```

Пример на backend:

```ts
app.enableCors({
  origin: ['https://app.example.com', 'https://admin.example.com'],
  credentials: true,
  methods: ['GET', 'POST', 'PATCH', 'DELETE'],
  allowedHeaders: ['Content-Type', 'Authorization'],
});
```

## Credentials

Если frontend отправляет cookies:

```ts
fetch('https://api.example.com/me', {
  credentials: 'include',
});
```

Server должен вернуть:

```http
Access-Control-Allow-Credentials: true
Access-Control-Allow-Origin: https://app.example.com
```

## CORS и security

CORS отвечает на вопрос:

```txt
Можно ли browser JavaScript с origin A читать response origin B?
```

CORS не отвечает:

- кто пользователь;
- есть ли у него права;
- можно ли выполнять действие;
- валиден ли token.

Это задачи authentication и authorization.

## Частые ошибки

| Ошибка | Что происходит |
|---|---|
| `origin: '*'` с cookies | browser блокирует response |
| забыли `credentials: 'include'` | cookies не отправляются |
| забыли `Authorization` в allowed headers | preflight падает |
| backend не отвечает на `OPTIONS` | основной request не уходит |
| CORS используют как auth | API остается доступным не-browser клиентам |

## Что важно помнить

- Опасный паттерн — «отражать» любой входящий `Origin` в `Access-Control-Allow-Origin` вместе с credentials: это равносильно отключению защиты.
- Проверяйте origin по точному списку, а не по `includes('example.com')`: `evil-example.com` тоже содержит эту строку.
- Если ответ зависит от `Origin`, сервер должен вернуть `Vary: Origin`, иначе CDN закеширует ответ для чужого origin.
- `Access-Control-Allow-Origin: null` опасен: значение `null` может прислать sandboxed iframe злоумышленника.

## Мини-шпаргалка

- Разрешай конкретные origins.
- Credentials требуют `Access-Control-Allow-Credentials: true`.
- Credentials не работают с wildcard origin.
- Разрешай только нужные methods и headers.
- CORS не заменяет auth.
