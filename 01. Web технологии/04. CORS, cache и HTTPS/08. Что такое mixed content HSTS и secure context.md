# Что такое mixed content, HSTS и secure context?

> [!NOTE]
> Mixed content возникает, когда HTTPS-страница загружает ресурсы по HTTP. HSTS заставляет browser использовать HTTPS. Secure context нужен для многих современных Web API.

## Вопрос

Что такое mixed content, HSTS и secure context? Почему некоторые Web API не работают по HTTP?

## Mixed content

```html
<!-- Страница открыта по HTTPS, но script грузится по HTTP -->
<script src="http://example.com/app.js"></script>
```

Это опасно: script можно подменить по пути. Browser может заблокировать такой resource.

Особенно критичны:

- scripts;
- iframes;
- styles;
- fetch requests;
- fonts;
- media with sensitive data.

## HSTS

```http
Strict-Transport-Security: max-age=31536000; includeSubDomains
```

HSTS говорит browser: "для этого домена используй только HTTPS".

Это помогает против downgrade attacks, когда пользователя пытаются увести на HTTP.

## Secure context

Некоторые browser APIs работают только в secure context:

- Service Workers;
- Clipboard API;
- Geolocation в большинстве сценариев;
- WebAuthn;
- Push API;
- некоторые crypto APIs.

`https://` обычно secure context. `http://localhost` часто считается исключением для разработки.

## Что важно помнить

- Первый запрос к сайту до получения HSTS-заголовка уязвим; HSTS preload list в браузерах решает эту проблему.
- `max-age` HSTS сложно отменить: если HTTPS сломается, пользователи не смогут открыть сайт до истечения срока.
- CSP-директива `upgrade-insecure-requests` автоматически переводит HTTP-ресурсы страницы на HTTPS.
- Проверить secure context из кода можно через `window.isSecureContext`.

## Мини-шпаргалка

- Mixed content - HTTPS page загружает HTTP resource.
- Browser может блокировать mixed content.
- HSTS принудительно включает HTTPS для домена.
- Secure context нужен для современных Web APIs.
- `localhost` часто имеет специальные послабления для dev.
