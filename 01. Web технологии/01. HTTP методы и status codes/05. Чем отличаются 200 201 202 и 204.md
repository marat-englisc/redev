# Чем отличаются 200, 201, 202 и 204?

> [!NOTE]
> Все эти коды означают успешную обработку, но говорят о разных сценариях: обычный успех, создание ресурса, принятие задачи в обработку и успешный ответ без body.

## Вопрос

Чем отличаются `200`, `201`, `202` и `204`? Какой код вернуть после создания, удаления и запуска долгой операции?

## 200 OK

Используй `200`, когда запрос выполнен и response содержит полезные данные.

```http
GET /api/users/1

HTTP/1.1 200 OK
Content-Type: application/json

{
  "id": 1,
  "name": "Anna"
}
```

Также `200` часто возвращают после успешного `PATCH`, если API возвращает обновленный объект.

## 201 Created

`201` используют, когда создан новый ресурс.

```http
POST /api/users

HTTP/1.1 201 Created
Location: /api/users/42
Content-Type: application/json

{
  "id": 42,
  "email": "anna@example.com"
}
```

Header `Location` может указывать URL созданного ресурса.

## 202 Accepted

`202` означает: запрос принят, но работа еще не завершена.

```http
POST /api/reports

HTTP/1.1 202 Accepted
Content-Type: application/json

{
  "jobId": "report_123",
  "status": "queued"
}
```

Подходит для очередей, долгой генерации отчетов, видео-обработки, async workflows.

## 204 No Content

`204` означает успех без response body.

```http
DELETE /api/users/42

HTTP/1.1 204 No Content
```

Часто используют для `DELETE` или `PATCH`, когда клиенту не нужен обновленный объект.

## Как выбрать?

| Сценарий | Код |
|---|---|
| Получили объект | `200` |
| Создали объект | `201` |
| Поставили задачу в очередь | `202` |
| Успешно, body не нужен | `204` |

## Что важно помнить

- При `204` вызов `response.json()` упадет: тела нет. Проверяйте status или `Content-Length` перед парсингом.
- После `202` клиент обычно опрашивает статус задачи (polling) или ждет уведомления через WebSocket/SSE.
- `201` вместе с header `Location` позволяет клиенту узнать URL нового ресурса без дополнительного запроса.
- Главное — последовательность: один API не должен возвращать для одинаковых операций то `200`, то `204`.

## Мини-шпаргалка

- `200` - успешный ответ с body.
- `201` - ресурс создан.
- `202` - запрос принят, обработка async.
- `204` - успех без body.
- Не возвращай JSON-body вместе с `204`.
