# Что такое HTTP и модель request-response?

> [!NOTE]
> HTTP - протокол обмена сообщениями между клиентом и сервером. Клиент отправляет request, сервер возвращает response. Для frontend-разработчика важно понимать структуру запроса, ответа, headers, body, методы и status codes.

## Вопрос

Что такое HTTP? Из чего состоят request и response? Почему HTTP называют stateless?

## Как выглядит обмен?

```txt
Browser / frontend
  |
  | HTTP request
  v
Server / API
  |
  | HTTP response
  v
Browser / frontend
```

Пример:

```http
GET /api/users/1 HTTP/1.1
Host: example.com
Accept: application/json
Authorization: Bearer token
```

Ответ:

```http
HTTP/1.1 200 OK
Content-Type: application/json
Cache-Control: no-store

{
  "id": 1,
  "name": "Anna"
}
```

## Из чего состоит request?

| Часть | Пример | Зачем нужна |
|---|---|---|
| Method | `GET` | намерение запроса |
| URL/path | `/api/users/1` | ресурс |
| Query string | `?page=2` | параметры выборки |
| Headers | `Accept: application/json` | metadata |
| Body | `{ "name": "Anna" }` | данные для создания/обновления |

## Из чего состоит response?

| Часть | Пример | Зачем нужна |
|---|---|---|
| Status code | `200`, `404`, `500` | результат обработки |
| Headers | `Content-Type`, `Set-Cookie` | metadata ответа |
| Body | JSON, HTML, file | полезные данные |

## Почему говорят, что HTTP stateless?

HTTP сам по себе не помнит предыдущие запросы. Два запроса от одного пользователя для протокола независимы.

Состояние добавляют поверх HTTP:

- cookies;
- sessions;
- access tokens;
- refresh tokens;
- server-side storage;
- browser storage.

Именно поэтому login почти всегда связан с cookie, session id или token.

## Что важно на собеседовании?

Нужно уметь объяснить не только "HTTP передает данные", а весь путь:

1. Browser формирует request.
2. Request уходит по сети на server.
3. Server читает method, path, headers, body.
4. Server выполняет бизнес-логику.
5. Server возвращает status, headers и body.
6. Browser решает, что делать с response: показать страницу, выполнить JS, положить cookie, сохранить cache, заблокировать CORS response.

## Что важно помнить

- HTTP — протокол прикладного уровня: он работает поверх TCP (HTTP/1.1, HTTP/2) или QUIC (HTTP/3), а за шифрование отвечает TLS.
- В HTTP/1.1 сообщения текстовые, в HTTP/2 и HTTP/3 — бинарные фреймы, но смысл (method, headers, status, body) одинаковый.
- Stateless не значит «без состояния вообще»: состояние хранится в cookies, sessions и tokens, а сам протокол каждый запрос обрабатывает независимо.
- Header `Host` обязателен в HTTP/1.1: по нему один сервер обслуживает много доменов.

## Мини-шпаргалка

- HTTP работает по модели request-response.
- Request описывает, что клиент хочет сделать.
- Response сообщает результат и возвращает данные.
- HTTP stateless: состояние добавляется cookies, sessions и tokens.
- Frontend-разработчик должен уметь читать request/response в DevTools.
