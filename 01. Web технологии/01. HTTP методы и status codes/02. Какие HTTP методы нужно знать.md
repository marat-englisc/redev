# Какие HTTP методы нужно знать?

> [!NOTE]
> HTTP method показывает намерение клиента: получить ресурс, создать, заменить, частично обновить, удалить или проверить доступность. На практике чаще всего нужны `GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `OPTIONS` и `HEAD`.

## Вопрос

Какие HTTP методы вы знаете? Чем `PUT` отличается от `PATCH`, а `GET` от `POST`?

## Основные методы

| Метод | Смысл | Пример |
|---|---|---|
| `GET` | получить данные | `GET /users/1` |
| `POST` | создать или запустить действие | `POST /users` |
| `PUT` | полностью заменить ресурс | `PUT /users/1` |
| `PATCH` | частично обновить ресурс | `PATCH /users/1` |
| `DELETE` | удалить ресурс | `DELETE /users/1` |
| `OPTIONS` | узнать возможности endpoint | CORS preflight |
| `HEAD` | получить headers без body | проверить файл/cache |

## GET

```http
GET /api/products?limit=20 HTTP/1.1
Accept: application/json
```

`GET` не должен менять состояние на сервере. Его можно кешировать, повторять и открывать через ссылку.

## POST

```http
POST /api/orders HTTP/1.1
Content-Type: application/json

{
  "productId": 10,
  "quantity": 2
}
```

`POST` часто создает ресурс, но может запускать и действие: login, payment, upload, search with complex body.

## PUT и PATCH

`PUT` обычно означает "замени ресурс целиком":

```http
PUT /api/users/1
Content-Type: application/json

{
  "email": "anna@example.com",
  "name": "Anna",
  "role": "user"
}
```

`PATCH` означает "измени только переданные поля":

```http
PATCH /api/users/1
Content-Type: application/json

{
  "name": "Ann"
}
```

## DELETE

```http
DELETE /api/users/1 HTTP/1.1
```

`DELETE` удаляет ресурс или помечает его удаленным. Если в продукте нужен soft delete, API все равно может использовать `DELETE`, а внутри ставить `deletedAt`.

## OPTIONS

`OPTIONS` часто виден в DevTools при CORS:

```http
OPTIONS /api/orders HTTP/1.1
Origin: https://app.example.com
Access-Control-Request-Method: POST
```

Browser отправляет preflight, чтобы проверить, разрешит ли server настоящий cross-origin request.

## Что важно помнить

- У `GET` по спецификации нет смысла передавать body: многие серверы и прокси его отбрасывают. Параметры передают в query string.
- Длина URL ограничена (браузеры и серверы режут слишком длинные URL), поэтому сложный поиск иногда делают через `POST /search`.
- `PUT` без части полей означает «эти поля отсутствуют» — их можно случайно стереть. Для частичных изменений используют `PATCH`.
- HTML-форма умеет отправлять только `GET` и `POST`; остальные методы доступны через `fetch` или XHR.
- `HEAD` возвращает те же headers, что и `GET`, без body — удобно проверить размер файла или актуальность cache.

## Мини-шпаргалка

- `GET` - читать.
- `POST` - создать или запустить действие.
- `PUT` - заменить целиком.
- `PATCH` - обновить частично.
- `DELETE` - удалить.
- `OPTIONS` - проверить возможности, часто CORS.
- `HEAD` - headers без body.
