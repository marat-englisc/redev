# Как защищаться от XSS?

> [!NOTE]
> Защита от XSS строится слоями: не вставлять untrusted data как HTML, использовать context-aware escaping, sanitization для разрешенного HTML, Content Security Policy, безопасные framework-паттерны и `HttpOnly` для auth cookies.

## Вопрос

Как защищаться от XSS на frontend и backend? Какие механизмы браузера помогают снизить ущерб?

## Не используй innerHTML для untrusted data

Плохо:

```ts
element.innerHTML = userInput;
```

Лучше:

```ts
element.textContent = userInput;
```

Frameworks вроде Vue/React по умолчанию экранируют текстовую интерполяцию, но escape можно обойти опасными APIs:

- `v-html`;
- `dangerouslySetInnerHTML`;
- прямой `innerHTML`;
- небезопасные template engines.

## Sanitization

Если продукт действительно должен принимать HTML, его нужно очищать через надежный sanitizer.

```ts
const safeHtml = sanitize(userHtml);
```

Самодельные regex-фильтры почти всегда недостаточны.

## Context matters

Экранирование зависит от контекста:

- HTML text;
- HTML attribute;
- URL;
- JavaScript string;
- CSS.

Один универсальный replace не защищает все случаи.

## Content Security Policy

```http
Content-Security-Policy: default-src 'self'; script-src 'self'
```

CSP может снизить impact XSS, ограничив источники scripts. Но CSP не заменяет исправление unsafe rendering.

## Auth storage

Для session/refresh cookies:

```http
Set-Cookie: sid=abc; HttpOnly; Secure; SameSite=Lax
```

`HttpOnly` снижает риск кражи cookie через XSS.

## Что важно помнить

- Для очистки HTML используют проверенные библиотеки, например DOMPurify, или встроенный Sanitizer API там, где он поддерживается.
- Проверяйте протокол пользовательских ссылок: разрешайте только `http:`, `https:`, `mailto:`.
- CSP с nonce или hash (`script-src 'nonce-...'`) надежнее, чем список доменов.
- Санитизация на входе (при сохранении) не заменяет экранирование на выходе: данные могут попасть в разные контексты.

## Мини-шпаргалка

- Не вставляй untrusted data через `innerHTML`.
- Используй `textContent` или framework interpolation.
- Для HTML нужен sanitizer.
- Escaping зависит от контекста.
- CSP - дополнительный слой.
- `HttpOnly` снижает риск кражи cookies, но не убирает XSS.
