# Какие security headers нужно знать?

> [!NOTE]
> Security headers помогают браузеру включить дополнительные ограничения: CSP против XSS impact, HSTS для HTTPS-only, `X-Content-Type-Options` против MIME sniffing, `Referrer-Policy` для контроля referrer и `Permissions-Policy` для Web APIs.

## Вопрос

Какие security headers нужно знать и от каких атак они защищают?

## Content-Security-Policy

```http
Content-Security-Policy: default-src 'self'; script-src 'self'
```

CSP ограничивает, откуда можно загружать scripts, styles, images и другие resources. Это важный дополнительный слой против XSS impact.

## Strict-Transport-Security

```http
Strict-Transport-Security: max-age=31536000; includeSubDomains
```

HSTS говорит browser использовать HTTPS для домена.

## X-Content-Type-Options

```http
X-Content-Type-Options: nosniff
```

Запрещает browser угадывать MIME type вопреки `Content-Type`.

## Referrer-Policy

```http
Referrer-Policy: strict-origin-when-cross-origin
```

Управляет тем, сколько информации отправляется в `Referer` header при переходах и requests.

## Permissions-Policy

```http
Permissions-Policy: geolocation=(), camera=(), microphone=()
```

Ограничивает доступ страницы и вложенных frames к browser APIs.

## X-Frame-Options

```http
X-Frame-Options: DENY
```

Старый, но все еще встречающийся header против clickjacking. В современных политиках похожую задачу может решать CSP `frame-ancestors`.

## Что важно помнить

- Новую CSP сначала включают в режиме `Content-Security-Policy-Report-Only`, чтобы собрать нарушения и ничего не сломать.
- `frame-ancestors 'none'` в CSP — современная замена `X-Frame-Options: DENY` для защиты от clickjacking.
- Заголовки `Cross-Origin-Opener-Policy` и `Cross-Origin-Embedder-Policy` нужны для изоляции и доступа к `SharedArrayBuffer`.
- Проверить заголовки сайта можно сервисами securityheaders.com и Mozilla Observatory.

## Мини-шпаргалка

- CSP снижает impact XSS.
- HSTS закрепляет HTTPS-only behavior.
- `nosniff` запрещает MIME sniffing.
- `Referrer-Policy` ограничивает утечки URL.
- `Permissions-Policy` ограничивает Web APIs.
- Security headers дополняют, но не заменяют безопасный код.
