# Что такое access token, refresh token и session token?

> [!NOTE]
> Access token дает доступ к API на короткое время. Refresh token нужен для получения нового access token. Session token или session id связывает browser с server-side session.

## Вопрос

Чем отличаются access token, refresh token и session token? Зачем нужна пара токенов?

## Access token

Access token отправляют к API:

```http
Authorization: Bearer access_token
```

Он обычно живет недолго: минуты или десятки минут.

Если access token украдут, короткий срок жизни уменьшает ущерб.

## Refresh token

Refresh token нужен, чтобы получить новый access token без повторного login.

```txt
refresh token -> /auth/refresh -> new access token
```

Refresh token живет дольше и должен храниться осторожнее access token.

## Session token

Session token часто выглядит как случайный id:

```txt
sid=abc123
```

Server хранит:

```txt
abc123 -> userId=42, expiresAt=...
```

## Token rotation

При refresh можно выдавать новый refresh token и инвалидировать старый.

Это помогает заметить reuse украденного refresh token:

```txt
old refresh token used twice -> possible theft -> revoke token family
```

## Сравнение

| Тип | Где проверяется | Срок жизни | Отзыв |
|---|---|---|---|
| Access token | API/auth middleware | короткий | сложнее, если stateless JWT |
| Refresh token | auth server | длинный | обязателен |
| Session id | session store | зависит от session | простой через удаление session |

## Что важно помнить

- При одновременном истечении access token несколько запросов могут параллельно вызвать refresh. Делайте один общий refresh-промис и очередь запросов.
- Refresh endpoint должен принимать токен только из `HttpOnly` cookie или защищенного хранилища, а не из URL.
- Время жизни access token — компромисс: короче — безопаснее, но больше refresh-запросов.
- Opaque token (случайная строка) нужно проверять на сервере, а JWT — по подписи.

## Мини-шпаргалка

- Access token нужен для API access.
- Refresh token нужен для обновления access token.
- Session token указывает на server-side session.
- Refresh token должен храниться особенно осторожно.
- Rotation снижает риск replay украденного refresh token.
