# Чем authentication отличается от authorization?

> [!NOTE]
> Authentication отвечает на вопрос "кто ты?", а authorization - "что тебе можно?". Эти понятия часто идут рядом, но решают разные задачи и должны проверяться в разных местах системы.

## Вопрос

Чем authentication отличается от authorization? Где и как проверять права доступа?

## Authentication

Authentication подтверждает identity пользователя.

Примеры:

- login/password;
- magic link;
- OAuth login;
- passkey/WebAuthn;
- session cookie;
- access token.

После authentication система понимает:

```txt
Это пользователь userId=42
```

## Authorization

Authorization проверяет права.

Примеры:

- user может читать только свой профиль;
- admin может удалять пользователей;
- editor может менять статью;
- paid user может открыть premium lesson.

После authorization система решает:

```txt
userId=42 может выполнить PATCH /articles/10 или нет
```

## 401 vs 403

```txt
401 Unauthorized -> пользователь не authenticated
403 Forbidden    -> пользователь authenticated, но прав не хватает
```

Да, название `401 Unauthorized` исторически сбивает с толку. На практике это про authentication.

## Пример в коде

```ts
if (!user) {
  throw new UnauthorizedException();
}

if (user.role !== 'admin') {
  throw new ForbiddenException();
}
```

## Частая ошибка

Проверить только login:

```ts
if (user) {
  deleteAnyPost();
}
```

Нужно проверить permission:

```ts
if (user.id !== post.authorId && user.role !== 'admin') {
  throw new ForbiddenException();
}
```

## Что важно помнить

- Проверки на frontend (скрытая кнопка, guard роутера) — это UX, а не безопасность. Права обязан проверять сервер.
- Самая частая уязвимость — IDOR: сервер не проверяет, что ресурс с этим id принадлежит пользователю.
- Модели прав: RBAC (по ролям), ABAC (по атрибутам), ACL (списки доступа к объектам).
- Есть третий шаг — accounting/audit: журналирование, кто и что сделал.

## Мини-шпаргалка

- Authentication - кто пользователь.
- Authorization - что ему разрешено.
- `401` - нет valid identity.
- `403` - identity есть, permission нет.
- Нельзя заменять authorization проверкой "пользователь залогинен".
