# Что такое CSRF?

> [!NOTE]
> CSRF - атака, при которой вредный сайт заставляет браузер пользователя отправить authenticated request на другой сайт. Риск появляется из-за автоматической отправки cookies и других credentials браузером.

## Вопрос

Что такое CSRF? Почему атака работает и в каких приложениях риск выше?

## Идея атаки

Пользователь залогинен на `bank.example.com`. В другой вкладке он открывает вредный сайт.

Вредный сайт может попытаться отправить:

```html
<form action="https://bank.example.com/transfer" method="POST">
  <input name="to" value="attacker" />
  <input name="amount" value="1000" />
</form>
```

Browser может автоматически приложить cookies банка, если cookie rules позволяют.

## Почему это работает?

Server видит request с valid session cookie и может подумать, что действие сделал пользователь.

Проблема в том, что authentication есть, но нет доказательства, что request был намеренно создан настоящим UI приложения.

## CSRF и CORS

CORS не является полноценной CSRF-защитой.

CORS управляет чтением response в browser JavaScript. CSRF может быть опасен даже если attacker не может прочитать response, потому что state-changing действие уже выполнено.

## Когда риск выше?

CSRF особенно важен, если:

- auth основана на cookies;
- есть state-changing endpoints;
- server принимает simple requests;
- нет CSRF token;
- `SameSite=None` или старые browser сценарии;
- dangerous actions не требуют дополнительного подтверждения.

## Что важно помнить

- Для CSRF атакующему не нужно читать ответ: достаточно, чтобы сервер выполнил действие.
- Login CSRF: атакующий входит в свой аккаунт в браузере жертвы, и жертва вводит данные уже в чужой аккаунт.
- Приложения с токеном в `Authorization` header (не в cookie) к классическому CSRF не уязвимы.
- CSRF и XSS часто путают: CSRF эксплуатирует доверие сервера к браузеру, XSS — доверие пользователя к сайту.

## Мини-шпаргалка

- CSRF заставляет browser отправить authenticated request.
- Главный фактор риска - automatic cookies.
- Attacker не обязательно должен читать response.
- CORS не равен CSRF protection.
- State-changing endpoints требуют защиты.
