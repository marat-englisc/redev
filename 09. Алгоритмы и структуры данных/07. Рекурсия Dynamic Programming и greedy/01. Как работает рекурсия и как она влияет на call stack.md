# Как работает рекурсия и как она влияет на call stack

> [!NOTE]
> Рекурсия - подход, где функция вызывает саму себя для решения меньшей версии задачи. Чтобы рекурсия была корректной, нужны base case, recursive case и движение к завершению.
>
> Рекурсия использует call stack: каждый незавершенный вызов функции занимает место в стеке. Поэтому у рекурсивного алгоритма нужно учитывать не только время, но и память на глубину рекурсии.

## Вопрос

Как работает рекурсия, как она использует call stack и когда заменить ее итерацией?

## Пример

```ts
function factorial(n: number): number {
  if (n <= 1) return 1
  return n * factorial(n - 1)
}
```

Здесь:

- base case: `n <= 1`;
- recursive case: `n * factorial(n - 1)`;
- progress: `n` уменьшается.

## Ментальная модель

```text
factorial(4)
4 * factorial(3)
4 * 3 * factorial(2)
4 * 3 * 2 * factorial(1)
4 * 3 * 2 * 1
```

## Где нужна рекурсия?

- деревья;
- DFS;
- backtracking;
- divide and conquer;
- dynamic programming top-down;
- парсинг вложенных структур.

## Что отвечать на собеседовании?

Рекурсия решает задачу через меньшие подзадачи. Для корректности нужны base case, recursive transition и гарантия, что мы приближаемся к base case. В JS нужно учитывать call stack: глубина рекурсии добавляет memory и может вызвать stack overflow.

Рекурсия добавляет память на call stack. Если глубина рекурсии `d`, то space complexity минимум `O(d)`. Для дерева это часто `O(h)`, для линейной рекурсии `O(n)`. В JavaScript слишком глубокая рекурсия может привести к `Maximum call stack size exceeded`, поэтому иногда рекурсивный DFS заменяют явным стеком.

## Что важно помнить: частые ошибки

- Нет base case.
- Base case недостижим.
- Не уменьшается задача.
- Не учитывать return value.
- Не считать memory call stack.

- Считать рекурсивное решение `O(1)` по памяти.
- Забывать base case.
- Не учитывать глубину дерева.
- Рекурсивно обходить огромный массив или список.
- Думать, что tail call optimization гарантирована в JavaScript.

## Что такое call stack?

Call stack хранит активные вызовы функций.

```ts
function countDown(n: number): void {
  if (n === 0) return
  countDown(n - 1)
}

countDown(3)
```

Упрощенно:

```text
countDown(3)
  countDown(2)
    countDown(1)
      countDown(0)
```

Глубина рекурсии `n`, значит память:

```text
O(n)
```

## Stack overflow

Если рекурсия слишком глубокая, JavaScript может выбросить ошибку:

```text
RangeError: Maximum call stack size exceeded
```

Например:

```ts
function bad(n: number): number {
  return bad(n + 1)
}
```

Здесь нет base case.

## Рекурсия для дерева

```ts
type TreeNode = {
  value: number
  left: TreeNode | null
  right: TreeNode | null
}

function sumTree(root: TreeNode | null): number {
  if (!root) return 0
  return root.value + sumTree(root.left) + sumTree(root.right)
}
```

Time:

```text
O(n)
```

Space:

```text
O(h)
```

где `h` - высота дерева.

## Когда заменить рекурсию итерацией?

Если глубина может быть большой:

- linked list на 100000 узлов;
- очень глубокое дерево;
- большой граф;
- рекурсивный DFS без контроля глубины.

Тогда можно использовать явный stack:

```ts
function sumTreeIterative(root: TreeNode | null): number {
  if (!root) return 0

  let sum = 0
  const stack = [root]

  while (stack.length > 0) {
    const node = stack.pop()!
    sum += node.value

    if (node.left) stack.push(node.left)
    if (node.right) stack.push(node.right)
  }

  return sum
}
```

## Мини-шпаргалка

- Base case.
- Recursive case.
- Progress.
- Stack memory.
- Деревья любят рекурсию.
- Большая глубина опасна в JS.
- Рекурсия использует call stack.
- Глубина `n` -> space `O(n)`.
- Дерево -> space `O(h)`.
- Нет base case -> бесконечная рекурсия.
- JS может получить stack overflow.
- Итерация с явным stack безопаснее для большой глубины.
