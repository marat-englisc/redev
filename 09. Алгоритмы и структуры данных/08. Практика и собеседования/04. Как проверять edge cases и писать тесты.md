# Как проверять edge cases и писать тесты?

> [!NOTE]
> Edge cases - крайние входные данные, на которых часто ломается решение: пустой input, один элемент, дубликаты, отрицательные числа, большие значения, отсутствие ответа и конфликт границ.

## Вопрос

Как проверять edge cases и писать тесты к алгоритмическому решению?

## Что проверять всегда?

- Пустой массив или строка.
- Один элемент.
- Два элемента.
- Все элементы одинаковые.
- Дубликаты.
- Отрицательные числа.
- Нулевые значения.
- Ответ в начале.
- Ответ в конце.
- Ответ отсутствует.
- Максимальные ограничения.

## Пример

```ts
function binarySearch(nums: number[], target: number): number {
  let left = 0
  let right = nums.length - 1

  while (left <= right) {
    const mid = left + Math.floor((right - left) / 2)

    if (nums[mid] === target) return mid
    if (nums[mid] < target) left = mid + 1
    else right = mid - 1
  }

  return -1
}
```

Тесты:

```ts
console.assert(binarySearch([], 1) === -1)
console.assert(binarySearch([1], 1) === 0)
console.assert(binarySearch([1], 2) === -1)
console.assert(binarySearch([1, 3, 5], 1) === 0)
console.assert(binarySearch([1, 3, 5], 5) === 2)
console.assert(binarySearch([1, 3, 5], 4) === -1)
```

## Как проверять руками?

1. Возьми маленький пример.
2. Пройди по переменным.
3. Проверь границы циклов.
4. Проверь empty/single.
5. Проверь отсутствие ответа.
6. Проверь duplicates, если они возможны.

## Что отвечать на собеседовании?

После написания решения я проверяю базовый пример и несколько edge cases: пустой input, один элемент, отсутствие ответа, ответ на границах, дубликаты и особые значения вроде `0` или отрицательных чисел. Это показывает, что я думаю не только о happy path.

## Что важно помнить: частые ошибки

- Проверять только пример из условия.
- Не тестировать пустой input.
- Не тестировать отсутствие ответа.
- Не проверять границы `left/right`.
- Игнорировать duplicates.
- Не проговаривать, можно ли мутировать input.

## Мини-шпаргалка

- Empty.
- Single.
- Duplicates.
- Negative/zero.
- Answer missing.
- Answer at edges.
- Max constraints.
