# Как решать алгоритмическую задачу на собеседовании?

> [!NOTE]
> На собеседовании важно не молча писать код, а вести интервьюера по процессу: уточнить задачу, разобрать примеры, назвать brute force, найти оптимизацию, написать аккуратный код, проверить edge cases и оценить сложность.

## Вопрос

Как решать алгоритмическую задачу на собеседовании по шагам?

## Порядок действий

1. Переформулировать задачу.
2. Уточнить input/output.
3. Спросить про ограничения.
4. Пройти пример руками.
5. Назвать brute force.
6. Найти паттерн.
7. Написать код.
8. Протестировать на edge cases.
9. Назвать time/space complexity.

## Шаблон объяснения

```text
Я сначала решу простым способом...
Его сложность будет...
Можно улучшить, если хранить ...
Тогда каждый элемент обрабатывается ...
Сложность станет ...
```

## Что уточнять?

- Может ли input быть пустым?
- Есть ли duplicates?
- Отсортирован ли массив?
- Есть ли отрицательные числа?
- Нужно вернуть индексы или значения?
- Можно ли мутировать input?
- Нужно ли первое решение или все решения?
- Какие ограничения по `n`?

## Что отвечать на собеседовании?

Я решаю алгоритмическую задачу по этапам: уточняю контракт и ограничения, показываю пример, предлагаю brute force, затем оптимизацию и ее идею. После кода проверяю edge cases и называю time/space complexity. Важно демонстрировать мышление, а не просто финальный код.

## Что важно помнить: частые ошибки

- Сразу писать код.
- Молчать во время решения.
- Не уточнять отсортирован ли input.
- Не проверять пустой input.
- Не оценивать сложность.
- Не объяснять trade-offs.

## Мини-шпаргалка

- Clarify.
- Example.
- Brute force.
- Optimize.
- Code.
- Test.
- Complexity.
