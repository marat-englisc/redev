# Как создать контекст и скомпилировать шейдерную программу

> [!NOTE]
> Работа с WebGL начинается с `canvas.getContext('webgl2', options)` — он вернёт `null`, если WebGL 2 недоступен. Шейдеры передаются **строками** и компилируются прямо в браузере: `createShader` → `shaderSource` → `compileShader`, затем два шейдера связываются в **программу**: `createProgram` → `attachShader` ×2 → `linkProgram`. Ошибки компиляции не бросают исключений — их нужно явно проверить через `getShaderParameter(…, COMPILE_STATUS)` и прочитать `getShaderInfoLog`. Перед рисованием задают `gl.viewport` (область вывода в пикселях буфера), очищают кадр `gl.clearColor` + `gl.clear`, выбирают программу `gl.useProgram`. Эти функции-помощники пишут один раз и переиспользуют во всех проектах.

## Вопрос

Как получить WebGL-контекст, скомпилировать шейдеры и собрать из них программу?

## Контекст

```ts
const canvas = document.querySelector<HTMLCanvasElement>('#gl')!;

const gl = canvas.getContext('webgl2', {
  antialias: true,              // сглаживание краёв треугольников (MSAA)
  alpha: false,                 // непрозрачный canvas — быстрее композитинг со страницей
  depth: true,                  // буфер глубины для 3D
  premultipliedAlpha: true,
  preserveDrawingBuffer: false, // true — кадр не очищается после показа (нужно для скриншотов toDataURL)
  powerPreference: 'high-performance', // попросить дискретную видеокарту
});

if (!gl) throw new Error('WebGL 2 не поддерживается');
```

## Компиляция шейдера

```ts
function createShader(gl: WebGL2RenderingContext, type: number, source: string) {
  const shader = gl.createShader(type)!;
  gl.shaderSource(shader, source);
  gl.compileShader(shader);

  if (!gl.getShaderParameter(shader, gl.COMPILE_STATUS)) {
    const log = gl.getShaderInfoLog(shader);
    gl.deleteShader(shader);
    throw new Error(`Ошибка компиляции ${type === gl.VERTEX_SHADER ? 'vertex' : 'fragment'}:\n${log}`);
  }
  return shader;
}
```

Лог выглядит так: `ERROR: 0:7: 'vColr' : undeclared identifier` — номер строки внутри шейдера.

## Сборка программы

```ts
function createProgram(gl: WebGL2RenderingContext, vsSource: string, fsSource: string) {
  const vs = createShader(gl, gl.VERTEX_SHADER, vsSource);
  const fs = createShader(gl, gl.FRAGMENT_SHADER, fsSource);

  const program = gl.createProgram()!;
  gl.attachShader(program, vs);
  gl.attachShader(program, fs);
  gl.linkProgram(program);

  // шейдеры больше не нужны — они уже внутри программы
  gl.deleteShader(vs);
  gl.deleteShader(fs);

  if (!gl.getProgramParameter(program, gl.LINK_STATUS)) {
    const log = gl.getProgramInfoLog(program);
    gl.deleteProgram(program);
    throw new Error(`Ошибка линковки:\n${log}`);
  }
  return program;
}
```

Линковка падает, например, если фрагментный шейдер ждёт `in vec3 vColor`, а вершинный не объявил `out vec3 vColor`.

## Шейдеры в коде

`#version 300 es` должна быть **самой первой строкой** — даже пустая строка перед ней ломает компиляцию. Поэтому шаблонные строки начинают сразу с версии:

```ts
const vertexSource = /* glsl */ `#version 300 es
in vec2 aPosition;
void main() {
  gl_Position = vec4(aPosition, 0.0, 1.0);
}`;

const fragmentSource = /* glsl */ `#version 300 es
precision highp float;
uniform vec4 uColor;
out vec4 outColor;
void main() {
  outColor = uColor;
}`;
```

Комментарий `/* glsl */` включает подсветку в редакторе (расширение для VS Code). В Vite шейдеры удобно держать в отдельных файлах: `import vs from './sprite.vert?raw'`.

## Первый кадр: залить экран цветом

```ts
function resize() {
  const dpr = Math.min(devicePixelRatio, 2);
  canvas.width = Math.round(canvas.clientWidth * dpr);
  canvas.height = Math.round(canvas.clientHeight * dpr);
  gl.viewport(0, 0, canvas.width, canvas.height); // clip space −1..1 → пиксели буфера
}
resize();

gl.clearColor(0.06, 0.09, 0.16, 1);  // RGBA 0..1
gl.clear(gl.COLOR_BUFFER_BIT);       // | gl.DEPTH_BUFFER_BIT для 3D
```

`gl.viewport` нужно вызывать после **каждого** изменения размера буфера, иначе картинка растянется или займёт угол.

## Полный каркас приложения

```ts
const program = createProgram(gl, vertexSource, fragmentSource);
const uColor = gl.getUniformLocation(program, 'uColor');

// ...буферы и VAO — в следующем уроке

function frame(time: number) {
  gl.clearColor(0, 0, 0, 1);
  gl.clear(gl.COLOR_BUFFER_BIT);

  gl.useProgram(program);
  gl.uniform4f(uColor, 0.5 + 0.5 * Math.sin(time / 500), 0.4, 0.3, 1);
  // gl.bindVertexArray(vao);
  // gl.drawArrays(gl.TRIANGLES, 0, 3);

  requestAnimationFrame(frame);
}
requestAnimationFrame(frame);
```

## Объекты WebGL и их удаление

Каждый `create*` создаёт ресурс на GPU, который сборщик мусора JS не освобождает надёжно:

| Создание | Удаление |
| --- | --- |
| `createShader` | `deleteShader` |
| `createProgram` | `deleteProgram` |
| `createBuffer` | `deleteBuffer` |
| `createTexture` | `deleteTexture` |
| `createVertexArray` | `deleteVertexArray` |
| `createFramebuffer` | `deleteFramebuffer` |

При размонтировании компонента или смене уровня ресурсы удаляют явно. Ещё один частый ресурс — сам контекст: браузер разрешает ограниченное число активных WebGL-контекстов (обычно около 16), старые теряются.

## Частые ошибки

- Пробел или перенос строки перед `#version 300 es`.
- Не проверять `COMPILE_STATUS` и `LINK_STATUS` — ошибка проявляется как «ничего не рисуется».
- Забыть `precision` во фрагментном шейдере — ошибка компиляции.
- Не вызывать `gl.viewport` после ресайза.
- Создавать программу или шейдеры каждый кадр.

## Что важно помнить

- `getContext('webgl2')` может вернуть `null` — нужен фолбэк.
- Шейдер: `createShader` → `shaderSource` → `compileShader` → проверка статуса.
- Программа: `attachShader` ×2 → `linkProgram` → проверка статуса.
- Кадр: `viewport` → `clear` → `useProgram` → uniforms → `draw*`.
- Ресурсы GPU удаляются явно через `delete*`.

## Мини-шпаргалка

```ts
const gl = canvas.getContext('webgl2')!;
const p = createProgram(gl, vs, fs);
gl.viewport(0, 0, canvas.width, canvas.height);
gl.clearColor(0, 0, 0, 1); gl.clear(gl.COLOR_BUFFER_BIT);
gl.useProgram(p);
```
