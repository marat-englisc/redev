# Чем WebGPU отличается от WebGL — первый треугольник

> [!NOTE]
> **WebGPU** — новый графический API браузера, построенный по модели Vulkan, Metal и Direct3D 12. Главное отличие от WebGL — нет глобальной машины состояний: всё состояние отрисовки заранее упаковано в неизменяемый **render pipeline** (шейдеры, формат вершин, смешивание), ресурсы передаются **bind group**-ами, а команды записываются в **command encoder** и отправляются пачкой в **очередь** (`device.queue.submit`). Это меньше накладных расходов на CPU, явный контроль и предсказуемая производительность. Шейдеры пишутся на **WGSL** — языке в стиле Rust. Плюс WebGPU умеет **compute-шейдеры** — общие вычисления на GPU (физика частиц, симуляции, ML), которых в WebGL нет. Инициализация асинхронная: `navigator.gpu.requestAdapter()` → `adapter.requestDevice()`.

## Вопрос

Чем WebGPU отличается от WebGL и как выглядит минимальная программа на WebGPU?

## WebGL vs WebGPU

| | WebGL 2 | WebGPU |
| --- | --- | --- |
| Модель | машина состояний: `enable`, `bind*` | неизменяемые pipeline + bind groups |
| Команды | выполняются по одной | записываются в encoder и отправляются пачкой |
| Шейдеры | GLSL ES 3.00 | WGSL |
| Compute-шейдеры | нет | да |
| Ошибки | `getError`, молчаливые | валидация с подробными сообщениями в консоли |
| Инициализация | синхронная | асинхронная (adapter → device) |
| Многопоточность | только OffscreenCanvas | рассчитан на запись команд из воркеров |
| Поддержка | везде | Chrome, Edge, Safari 26+, Firefox (поэтапно) — нужен фолбэк на WebGL |

## Первый треугольник

```ts
if (!navigator.gpu) throw new Error('WebGPU не поддерживается');

const adapter = await navigator.gpu.requestAdapter();          // физическая видеокарта
if (!adapter) throw new Error('Нет подходящего адаптера');
const device = await adapter.requestDevice();                  // логическое устройство

const canvas = document.querySelector<HTMLCanvasElement>('#gpu')!;
const context = canvas.getContext('webgpu')!;
const format = navigator.gpu.getPreferredCanvasFormat();       // 'bgra8unorm' или 'rgba8unorm'
context.configure({ device, format, alphaMode: 'premultiplied' });

// шейдер на WGSL: вершинный и фрагментный в одном модуле
const module = device.createShaderModule({
  code: /* wgsl */ `
    struct VSOut {
      @builtin(position) position: vec4f,
      @location(0) color: vec3f,
    };

    @vertex
    fn vs(@builtin(vertex_index) i: u32) -> VSOut {
      var pos = array<vec2f, 3>(vec2f(0.0, 0.6), vec2f(-0.6, -0.5), vec2f(0.6, -0.5));
      var col = array<vec3f, 3>(vec3f(1, 0, 0), vec3f(0, 1, 0), vec3f(0, 0, 1));
      var out: VSOut;
      out.position = vec4f(pos[i], 0.0, 1.0);
      out.color = col[i];
      return out;
    }

    @fragment
    fn fs(in: VSOut) -> @location(0) vec4f {
      return vec4f(in.color, 1.0);
    }
  `,
});

// pipeline: всё состояние отрисовки — один раз
const pipeline = device.createRenderPipeline({
  layout: 'auto',
  vertex: { module, entryPoint: 'vs' },
  fragment: { module, entryPoint: 'fs', targets: [{ format }] },
  primitive: { topology: 'triangle-list' },
});

function frame() {
  const encoder = device.createCommandEncoder();
  const pass = encoder.beginRenderPass({
    colorAttachments: [{
      view: context.getCurrentTexture().createView(),   // текстура текущего кадра canvas
      clearValue: { r: 0.06, g: 0.09, b: 0.16, a: 1 },
      loadOp: 'clear',
      storeOp: 'store',
    }],
  });
  pass.setPipeline(pipeline);
  pass.draw(3);                     // 3 вершины
  pass.end();

  device.queue.submit([encoder.finish()]);   // отправить команды на GPU
  requestAnimationFrame(frame);
}
requestAnimationFrame(frame);
```

## Буферы и uniforms

```ts
// uniform-буфер: время + разрешение (выравнивание по 16 байт)
const uniformBuffer = device.createBuffer({
  size: 16,
  usage: GPUBufferUsage.UNIFORM | GPUBufferUsage.COPY_DST,
});

// bind group — набор ресурсов для шейдера (аналог uniform + bindTexture в WebGL)
const bindGroup = device.createBindGroup({
  layout: pipeline.getBindGroupLayout(0),
  entries: [{ binding: 0, resource: { buffer: uniformBuffer } }],
});

// в кадре
device.queue.writeBuffer(uniformBuffer, 0, new Float32Array([time, 0, canvas.width, canvas.height]));
pass.setBindGroup(0, bindGroup);
```

```wgsl
struct Uniforms { time: f32, _pad: f32, resolution: vec2f };
@group(0) @binding(0) var<uniform> u: Uniforms;
```

Вершинные буферы создаются с `GPUBufferUsage.VERTEX`, их формат описывается в `vertex.buffers` pipeline, а привязываются через `pass.setVertexBuffer(0, buffer)`.

## WGSL и GLSL

| GLSL | WGSL |
| --- | --- |
| `vec2`, `vec3`, `vec4`, `mat4` | `vec2f`, `vec3f`, `vec4f`, `mat4x4f` |
| `float x = 1.0;` | `var x: f32 = 1.0;` / `let x = 1.0;` (неизменяемая) |
| `in` / `out` | параметры и возвращаемая структура с `@location(n)` |
| `gl_Position` | `@builtin(position)` |
| `gl_VertexID` | `@builtin(vertex_index)` |
| `uniform sampler2D uTex;` | `@group(0) @binding(1) var tex: texture_2d<f32>;` + `var samp: sampler;` |
| `texture(uTex, uv)` | `textureSample(tex, samp, uv)` |
| `mix`, `clamp`, `smoothstep`, `fract` | те же имена |

## Compute-шейдер: частицы на GPU

```wgsl
struct Particle { pos: vec2f, vel: vec2f };
@group(0) @binding(0) var<storage, read_write> particles: array<Particle>;

@compute @workgroup_size(64)
fn update(@builtin(global_invocation_id) id: vec3u) {
  let i = id.x;
  if (i >= arrayLength(&particles)) { return; }
  var p = particles[i];
  p.vel.y -= 0.0005;                  // гравитация
  p.pos += p.vel;
  if (p.pos.y < -1.0) { p.vel.y = abs(p.vel.y) * 0.8; }
  particles[i] = p;
}
```

```ts
const computePass = encoder.beginComputePass();
computePass.setPipeline(computePipeline);
computePass.setBindGroup(0, particlesBindGroup);
computePass.dispatchWorkgroups(Math.ceil(COUNT / 64));  // миллион частиц без JS-цикла
computePass.end();
```

Тот же storage-буфер затем используется как вершинный при отрисовке — данные не возвращаются на CPU.

## Нужно ли писать на WebGPU напрямую

Чаще всего нет. PixiJS v8 и Three.js (`WebGPURenderer`) поддерживают WebGPU с автоматическим фолбэком на WebGL:

```ts
await app.init({ preference: 'webgpu' });              // PixiJS

import { WebGPURenderer } from 'three/webgpu';          // Three.js
const renderer = new WebGPURenderer();
await renderer.init();
```

Напрямую WebGPU берут для своих движков, тяжёлых симуляций и вычислений на GPU.

## Частые ошибки

- Не проверить `navigator.gpu` и `requestAdapter()` на `null` — на неподдерживаемых устройствах падает.
- Создавать pipeline каждый кадр — это дорого, их создают заранее (и кешируют по комбинации состояния).
- Забыть `device.queue.submit` — команды записаны, но не выполнены.
- Нарушить выравнивание полей в uniform-буфере (16 байт для `vec3f`/`vec4f`) — значения «съезжают».
- Брать `context.getCurrentTexture()` один раз и хранить — она новая в каждом кадре.

## Что важно помнить

- WebGPU: adapter → device → context.configure → pipeline → encoder → pass → submit.
- Нет глобального состояния: pipeline неизменяем, ресурсы — через bind groups.
- Шейдеры на WGSL, есть compute-шейдеры.
- Поддержка ещё не везде — нужен фолбэк на WebGL; библиотеки делают его сами.
