# Как рисовать тысячи спрайтов — батчинг и инстансинг

> [!NOTE]
> Узкое место WebGL — не GPU, а **число вызовов отрисовки** (draw calls): каждый `drawArrays` с перенастройкой uniforms и текстур — работа CPU и драйвера. 10 000 спрайтов по одному вызову — 10 000 draw calls, и FPS падает. Решения два. **Батчинг**: CPU каждый кадр собирает вершины всех спрайтов (уже с применённой трансформацией) в один большой буфер и рисует одним вызовом — так работают PixiJS и Phaser. **Инстансинг** (WebGL 2): геометрия квада одна, а данные каждого экземпляра (позиция, поворот, цвет, кадр атласа) лежат в отдельном буфере с `vertexAttribDivisor(loc, 1)`, и `drawArraysInstanced` рисует все экземпляры одним вызовом; трансформацию считает вершинный шейдер. Оба подхода работают только если спрайты используют **одну текстуру** — отсюда атласы.

## Вопрос

Почему тысячи отдельных вызовов отрисовки медленные и как нарисовать много спрайтов за один draw call?

## Наивный вариант

```ts
// ❌ 10 000 draw calls
for (const s of sprites) {
  gl.uniformMatrix3fv(uMatrix, false, spriteMatrix(s));
  gl.drawElements(gl.TRIANGLES, 6, gl.UNSIGNED_SHORT, 0);
}
```

## Инстансинг

Один квад + буфер с данными экземпляров. Для каждого экземпляра шейдер получает его «личные» атрибуты.

```ts
const vs = `#version 300 es
layout(location = 0) in vec2 aQuad;        // вершина квада: -0.5..0.5 (одна на все экземпляры)
layout(location = 1) in vec2 aOffset;      // позиция экземпляра в пикселях
layout(location = 2) in float aRotation;
layout(location = 3) in float aScale;
layout(location = 4) in vec4 aColor;

uniform vec2 uResolution;
out vec2 vUV;
out vec4 vColor;

void main() {
  float c = cos(aRotation), s = sin(aRotation);
  vec2 p = mat2(c, s, -s, c) * (aQuad * aScale) + aOffset;   // поворот, масштаб, перенос
  vec2 clip = (p / uResolution) * 2.0 - 1.0;
  gl_Position = vec4(clip * vec2(1, -1), 0, 1);
  vUV = aQuad + 0.5;
  vColor = aColor;
}`;

const fs = `#version 300 es
precision mediump float;
in vec2 vUV;
in vec4 vColor;
uniform sampler2D uTexture;
out vec4 outColor;
void main() {
  outColor = texture(uTexture, vUV) * vColor;
}`;

const COUNT = 50_000;
const FLOATS = 2 + 1 + 1 + 4;                  // offset, rotation, scale, color
const instanceData = new Float32Array(COUNT * FLOATS);

const vao = gl.createVertexArray();
gl.bindVertexArray(vao);

// квад (два треугольника как TRIANGLE_STRIP)
gl.bindBuffer(gl.ARRAY_BUFFER, gl.createBuffer());
gl.bufferData(gl.ARRAY_BUFFER, new Float32Array([-0.5, -0.5, 0.5, -0.5, -0.5, 0.5, 0.5, 0.5]), gl.STATIC_DRAW);
gl.enableVertexAttribArray(0);
gl.vertexAttribPointer(0, 2, gl.FLOAT, false, 0, 0);

// данные экземпляров
const instanceBuffer = gl.createBuffer();
gl.bindBuffer(gl.ARRAY_BUFFER, instanceBuffer);
gl.bufferData(gl.ARRAY_BUFFER, instanceData.byteLength, gl.DYNAMIC_DRAW);

const stride = FLOATS * 4;
const layout: [loc: number, size: number, offset: number][] = [
  [1, 2, 0],   // aOffset
  [2, 1, 2],   // aRotation
  [3, 1, 3],   // aScale
  [4, 4, 4],   // aColor
];
for (const [loc, size, offset] of layout) {
  gl.enableVertexAttribArray(loc);
  gl.vertexAttribPointer(loc, size, gl.FLOAT, false, stride, offset * 4);
  gl.vertexAttribDivisor(loc, 1);   // ← атрибут меняется раз на ЭКЗЕМПЛЯР, а не на вершину
}
gl.bindVertexArray(null);
```

## Кадр

```ts
function frame(t: number) {
  // обновляем данные на CPU
  for (let i = 0; i < COUNT; i++) {
    const o = i * FLOATS;
    const p = particles[i];
    p.x += p.vx; p.y += p.vy;
    instanceData[o] = p.x;
    instanceData[o + 1] = p.y;
    instanceData[o + 2] = p.angle += 0.02;
    instanceData[o + 3] = p.size;
    instanceData.set(p.color, o + 4);
  }

  gl.bindBuffer(gl.ARRAY_BUFFER, instanceBuffer);
  gl.bufferSubData(gl.ARRAY_BUFFER, 0, instanceData);   // одна загрузка на кадр

  gl.clear(gl.COLOR_BUFFER_BIT);
  gl.useProgram(program);
  gl.uniform2f(uResolution, canvas.width, canvas.height);
  gl.bindVertexArray(vao);
  gl.drawArraysInstanced(gl.TRIANGLE_STRIP, 0, 4, COUNT);  // 50 000 спрайтов — 1 вызов
  requestAnimationFrame(frame);
}
```

Данные хранятся в одном `Float32Array` (Structure of Arrays/плоский массив), а не в 50 000 объектах — меньше мусора и быстрее копирование.

## Батчинг

Батчер не требует инстансинга и подходит для спрайтов разного размера, формы и кадров атласа:

```text
кадр:
  начать батч
  для каждого спрайта:
    если текстура другая или буфер полон → flush (drawElements), начать новый батч
    посчитать 4 угла с учётом трансформации (на CPU)
    записать x, y, u, v, color для 4 вершин в общий Float32Array
  flush
```

```ts
class SpriteBatch {
  private data = new Float32Array(MAX_SPRITES * 4 * 5);  // 4 вершины × (x, y, u, v, color)
  private count = 0;
  private texture: WebGLTexture | null = null;

  draw(tex: WebGLTexture, s: Sprite, frame: UVRect) {
    if (this.texture !== tex || this.count === MAX_SPRITES) this.flush();
    this.texture = tex;
    // ...вычислить 4 угла (как в уроке про матрицы) и записать в this.data
    this.count++;
  }

  flush() {
    if (!this.count) return;
    gl.bindTexture(gl.TEXTURE_2D, this.texture);
    gl.bindBuffer(gl.ARRAY_BUFFER, this.vbo);
    gl.bufferSubData(gl.ARRAY_BUFFER, 0, this.data, 0, this.count * 4 * 5);
    gl.drawElements(gl.TRIANGLES, this.count * 6, gl.UNSIGNED_SHORT, 0);
    this.count = 0;
  }
}
```

Индексный буфер для батча заполняется один раз: для спрайта `i` — `4i, 4i+1, 4i+2, 4i, 4i+2, 4i+3`. Чтобы смена текстуры реже прерывала батч, продвинутые батчеры (PixiJS) привязывают до 16 текстур одновременно и передают номер текстуры как атрибут вершины.

## Батчинг или инстансинг

| | Батчинг | Инстансинг |
| --- | --- | --- |
| Трансформации | считает CPU | считает GPU в вершинном шейдере |
| Данных на спрайт | 4 вершины × атрибуты | 1 запись экземпляра |
| Разная геометрия | да (любые четырёхугольники, текст, фигуры) | одна геометрия на вызов |
| Где применяется | PixiJS, Phaser, большинство 2D-движков | частицы, трава, толпы, `InstancedMesh` в Three.js |

## Что ещё прерывает батч

- Другая текстура (поэтому атласы).
- Другой шейдер или режим смешивания.
- Маски, фильтры, рендер в текстуру.
- Переполнение буфера.

## Частые ошибки

- Забыть `vertexAttribDivisor(loc, 1)` — данные экземпляров читаются как вершины, всё ломается.
- Оставить divisor `1` у атрибута, который потом используется для обычной геометрии в том же VAO.
- Каждый кадр создавать новый `Float32Array` вместо переиспользования.
- Рисовать спрайты из разных PNG — каждый переход текстуры сбрасывает батч.
- Ожидать, что инстансинг ускорит медленную логику на JS: обновление 50 000 объектов на CPU тоже стоит времени.

## Что важно помнить

- Узкое место — количество draw calls, а не количество треугольников.
- Батчинг: CPU собирает вершины многих спрайтов в один буфер → один вызов.
- Инстансинг: одна геометрия + буфер экземпляров + `vertexAttribDivisor` + `drawArraysInstanced`.
- Атласы — обязательное условие для обоих подходов.

## Мини-шпаргалка

```ts
gl.vertexAttribDivisor(loc, 1);
gl.bufferSubData(gl.ARRAY_BUFFER, 0, instanceData);
gl.drawArraysInstanced(gl.TRIANGLE_STRIP, 0, 4, count);
gl.drawElementsInstanced(gl.TRIANGLES, 6, gl.UNSIGNED_SHORT, 0, count);
```
