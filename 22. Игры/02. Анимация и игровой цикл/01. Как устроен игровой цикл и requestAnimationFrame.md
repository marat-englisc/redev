# Как устроен игровой цикл и requestAnimationFrame

> [!NOTE]
> Игра — это бесконечный цикл из трёх шагов: **ввод → обновление (`update`) → отрисовка (`render`)**. В браузере цикл строят на `requestAnimationFrame(callback)`: браузер вызывает колбэк перед каждой перерисовкой экрана (обычно 60 раз в секунду, на 120/144 Гц мониторах — чаще) и передаёт в него временную метку. `rAF` синхронизирован с экраном, не вызывается в фоновых вкладках и не накапливает вызовы, поэтому он лучше `setInterval`. Внутри цикла `update` меняет состояние мира, `render` рисует его заново. Цикл нужно уметь **останавливать** — `cancelAnimationFrame(id)`, иначе при уходе со страницы (или размонтировании компонента) он продолжит работать.

## Вопрос

Что такое игровой цикл и почему в браузере его строят на `requestAnimationFrame`, а не на `setInterval`?

## Схема

```text
        ┌──────────────────────────────┐
        ▼                              │
  processInput()   ← клавиши, мышь     │
        │                              │
  update(dt)       ← физика, логика    │  requestAnimationFrame
        │                              │
  render()         ← clear + draw      │
        └──────────────────────────────┘
```

## Минимальный цикл

```ts
const canvas = document.querySelector<HTMLCanvasElement>('#game')!;
const ctx = canvas.getContext('2d')!;

const ball = { x: 50, y: 100, vx: 3, r: 15 };

function update() {
  ball.x += ball.vx;
  if (ball.x + ball.r > canvas.width || ball.x - ball.r < 0) ball.vx *= -1; // отскок от стен
}

function render() {
  ctx.clearRect(0, 0, canvas.width, canvas.height);
  ctx.beginPath();
  ctx.arc(ball.x, ball.y, ball.r, 0, Math.PI * 2);
  ctx.fillStyle = 'tomato';
  ctx.fill();
}

function frame() {
  update();
  render();
  requestAnimationFrame(frame); // запланировать следующий кадр
}

requestAnimationFrame(frame);
```

У этого кода есть проблема: скорость «3 пикселя за кадр» на мониторе 144 Гц будет в 2,4 раза выше, чем на 60 Гц. Решение — **delta time**, см. следующий урок.

## Почему не setInterval

| | `setInterval(fn, 16)` | `requestAnimationFrame(fn)` |
| --- | --- | --- |
| Синхронизация с экраном | нет — кадры рвутся и дёргаются | да, вызов прямо перед отрисовкой |
| Частота | фиксированная, не знает про 120 Гц | равна частоте экрана |
| Фоновая вкладка | продолжает работать (с троттлингом) | ставится на паузу — экономит батарею |
| Перегрузка | вызовы могут накапливаться | следующий кадр не начнётся, пока не закончен текущий |
| Время кадра | надо брать самому | `timestamp` передаётся в колбэк |

## Класс Game с запуском и остановкой

```ts
export class Game {
  private rafId = 0;
  private lastTime = 0;
  private running = false;

  constructor(private ctx: CanvasRenderingContext2D) {}

  start() {
    if (this.running) return;
    this.running = true;
    this.lastTime = performance.now();
    this.rafId = requestAnimationFrame(this.loop);
  }

  stop() {
    this.running = false;
    cancelAnimationFrame(this.rafId);
  }

  // стрелочная функция — чтобы не терять this при передаче в rAF
  private loop = (now: number) => {
    const dt = Math.min((now - this.lastTime) / 1000, 0.1); // секунды, с ограничением
    this.lastTime = now;

    this.update(dt);
    this.render();

    if (this.running) this.rafId = requestAnimationFrame(this.loop);
  };

  private update(dt: number) { /* логика */ }
  private render() { /* отрисовка */ }
}
```

`Math.min(…, 0.1)` защищает от огромного `dt` после того, как вкладка была в фоне: иначе объекты «телепортируются» сквозь стены.

## Пауза при скрытии вкладки

```ts
document.addEventListener('visibilitychange', () => {

  else game.start();

```

## Счётчик FPS

```ts
let frames = 0;
let fps = 0;
let acc = 0;

function countFps(dt: number) {
  frames++;
  acc += dt;
  if (acc >= 1) {          // раз в секунду
    fps = frames;
    frames = 0;
    acc -= 1;
  }
  ctx.fillText(`FPS: ${fps}`, 10, 20);
}
```

## Частые ошибки

- Вызывать `requestAnimationFrame(frame())` — скобки вызывают функцию сразу и уходят в бесконечную рекурсию.
- Двигать объекты на фиксированное число пикселей за кадр — скорость зависит от частоты экрана.
- Не останавливать цикл при уходе со страницы или размонтировании компонента — два цикла работают одновременно, игра ускоряется вдвое.
- Делать тяжёлую логику в обработчиках событий, а не в `update` — порядок обновлений становится непредсказуемым.

## Что важно помнить

- Цикл: ввод → `update(dt)` → `render()` → следующий `rAF`.
- `requestAnimationFrame` синхронизирован с экраном и спит в фоне.
- Колбэк получает `timestamp` — из него считают `dt`.
- Всегда храните id и умейте остановить цикл через `cancelAnimationFrame`.

## Мини-шпаргалка

```ts
let last = performance.now();
function loop(now: number) {
  const dt = Math.min((now - last) / 1000, 0.1);
  last = now;
  update(dt); render();
  id = requestAnimationFrame(loop);
}
let id = requestAnimationFrame(loop);
cancelAnimationFrame(id);
```
