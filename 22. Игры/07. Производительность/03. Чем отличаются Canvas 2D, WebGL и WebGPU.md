# Чем отличаются Canvas 2D, WebGL и WebGPU

> [!NOTE]
> Все три API рисуют в `<canvas>`, но на разном уровне. **Canvas 2D** — высокоуровневый: «нарисуй прямоугольник, картинку, текст». Прост, но каждый вызов — отдельная команда, и на нескольких тысячах спрайтов упирается в CPU. **WebGL/WebGL2** — низкоуровневый доступ к GPU (на основе OpenGL ES): вы загружаете вершины и текстуры в буферы и пишете **шейдеры** на GLSL; рисует десятки тысяч объектов за несколько draw calls, даёт фильтры, освещение и 3D. **WebGPU** — современный преемник WebGL (по модели Vulkan/Metal/D3D12): меньше накладных расходов, compute-шейдеры (вычисления на GPU), язык WGSL. Напрямую WebGL/WebGPU используют редко — обычно берут библиотеку: PixiJS для 2D, Three.js/Babylon.js для 3D.

## Вопрос

Чем Canvas 2D отличается от WebGL и WebGPU, и когда что выбирать для игры?

## Сравнение

| | Canvas 2D | WebGL 2 | WebGPU |
| --- | --- | --- | --- |
| Уровень | высокий: фигуры, текст, картинки | низкий: буферы, шейдеры GLSL | низкий: пайплайны, шейдеры WGSL |
| Порог входа | минимальный | высокий | очень высокий |
| Спрайтов за кадр (ориентир) | тысячи | десятки–сотни тысяч | сотни тысяч+ |
| Шейдеры, пост-эффекты | нет (только `filter`) | да | да |
| Вычисления на GPU | нет | ограниченно | compute-шейдеры |
| 3D | нет | да | да |
| Поддержка | везде | практически везде | современные браузеры, на части устройств ещё нет |
| Типичное применение | казуальные игры, прототипы, графики | PixiJS, Three.js, Phaser | новые версии PixiJS, Three.js, Babylon.js |

## Почему WebGL быстрее для спрайтов

```text
Canvas 2D: 5000 спрайтов → 5000 вызовов drawImage → 5000 команд

WebGL:    5000 спрайтов с одной текстуры (атласа)
          → все вершины в один буфер
          → 1 draw call
```

Ключевое слово — **батчинг** (batching): GPU любит рисовать много одинакового за раз. Поэтому в WebGL-движках важно использовать **атласы** — спрайты с одной текстуры рисуются одним пакетом, а переключение текстуры прерывает пакет.

## Как выглядит «голый» WebGL

Даже треугольник требует шейдеров и буферов — поэтому почти все используют библиотеки:

```ts
const gl = canvas.getContext('webgl2')!;

const vs = `#version 300 es
in vec2 aPos;
void main() { gl_Position = vec4(aPos, 0.0, 1.0); }`;

const fs = `#version 300 es
precision mediump float;
out vec4 color;
void main() { color = vec4(1.0, 0.4, 0.3, 1.0); }`;

function compile(type: number, src: string) {
  const s = gl.createShader(type)!;
  gl.shaderSource(s, src);
  gl.compileShader(s);
  if (!gl.getShaderParameter(s, gl.COMPILE_STATUS)) throw new Error(gl.getShaderInfoLog(s)!);
  return s;
}

const program = gl.createProgram()!;
gl.attachShader(program, compile(gl.VERTEX_SHADER, vs));
gl.attachShader(program, compile(gl.FRAGMENT_SHADER, fs));
gl.linkProgram(program);
gl.useProgram(program);

const buf = gl.createBuffer();
gl.bindBuffer(gl.ARRAY_BUFFER, buf);
gl.bufferData(gl.ARRAY_BUFFER, new Float32Array([0, 0.5, -0.5, -0.5, 0.5, -0.5]), gl.STATIC_DRAW);

const loc = gl.getAttribLocation(program, 'aPos');
gl.enableVertexAttribArray(loc);
gl.vertexAttribPointer(loc, 2, gl.FLOAT, false, 0, 0);

gl.clearColor(0.06, 0.09, 0.16, 1);
gl.clear(gl.COLOR_BUFFER_BIT);
gl.drawArrays(gl.TRIANGLES, 0, 3);
```

Координаты в WebGL — от −1 до 1 (clip space), а не пиксели. Всё это — матрицы, текстуры, батчинг — берут на себя библиотеки.

## WebGPU: проверка и инициализация

```ts
if (!navigator.gpu) {
  // фолбэк на WebGL
}
const adapter = await navigator.gpu.requestAdapter();
const device = await adapter!.requestDevice();
const context = canvas.getContext('webgpu')!;
context.configure({ device, format: navigator.gpu.getPreferredCanvasFormat() });
```

В PixiJS v8 выбор рендерера делается одной опцией:

```ts
await app.init({ preference: 'webgpu' }); // попробует WebGPU, иначе WebGL
```

## Что выбрать

| Задача | Выбор |
| --- | --- |
| Простая игра, головоломка, учебный проект | Canvas 2D |
| 2D с большим количеством спрайтов, эффектами | PixiJS |
| Полноценная 2D-игра с физикой, сценами, звуком | Phaser |
| 3D | Three.js / React Three Fiber, Babylon.js |
| Свой движок, вычисления на GPU | WebGL2 / WebGPU напрямую |

## Частые ошибки

- Писать «голый» WebGL для обычной 2D-игры — месяцы на то, что даёт PixiJS.
- Использовать в WebGL-движке сотни отдельных картинок вместо атласа — батчинг ломается.
- Полагаться только на WebGPU без фолбэка на WebGL.
- Ожидать, что WebGL ускорит медленную игровую логику — он ускоряет отрисовку.

## Что важно помнить

- Canvas 2D — просто, до нескольких тысяч объектов.
- WebGL/WebGPU — GPU, шейдеры, батчинг, десятки тысяч объектов и 3D.
- Батчинг работает, когда спрайты берутся из одного атласа.
- На практике используют библиотеки: PixiJS, Phaser, Three.js.

## Мини-шпаргалка

```ts
canvas.getContext('2d');      // просто
canvas.getContext('webgl2');  // GPU, GLSL
canvas.getContext('webgpu');  // GPU нового поколения, WGSL
if (!navigator.gpu) useWebGL();
```
