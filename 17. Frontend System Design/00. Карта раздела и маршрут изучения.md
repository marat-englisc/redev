# Карта раздела «Frontend System Design»

> [!NOTE]
> Раздел готовит к frontend system design интервью: как устроено интервью и как строить ответ по фреймворку RADIO, как выбирать рендеринг, проектировать компоненты, данные, API и realtime, как обеспечивать производительность, кеширование, надежность, доступность, безопасность и наблюдаемость. Шесть разборов типовых задач показывают весь путь от требований до оптимизаций.

## Вопрос

С чего начать подготовку к frontend system design и в каком порядке читать раздел?

## Основная идея

System design на собеседовании проверяет не знание одной технологии, а умение **собрать знания из всех разделов** в решение: React и Next.js, Web, производительность, тестирование. Поэтому заметки раздела короткие по теории и много ссылаются на подробные заметки других разделов.

| Глава | Что внутри |
| --- | --- |
| 01. Основы | что такое frontend system design, ход интервью, фреймворк RADIO, сбор требований |
| 02. Архитектура и данные | выбор рендеринга, компоненты и слои, модель данных, API, realtime |
| 03. Нефункциональные требования | производительность, кеш, надежность и офлайн, a11y и i18n, безопасность, наблюдаемость |
| 04. Разбор задач | автокомплит, лента, чат, каталог и корзина, совместный редактор, таблица данных |
| 05. Масштабирование и интервью | дизайн-система, монорепозиторий и микрофронтенды, чек-лист и частые вопросы |

## Что важно помнить

- Правильного единственного ответа нет — оценивают структуру, вопросы и обоснованные компромиссы.
- Middle достаточно уверенно пройти все шаги RADIO и углубиться в 2–3 темы.
- Лучшая подготовка — проговаривать задачи вслух и связывать решения с собственным опытом.

## Мини-шпаргалка

Основы и RADIO → архитектура (рендеринг, компоненты, данные, API, realtime) → оптимизации (производительность, кеш, надежность, a11y, безопасность, мониторинг) → разборы задач → масштабирование → чек-лист и тренировка вслух.
