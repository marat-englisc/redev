# Как спроектировать ленту новостей (news feed)

> [!NOTE]
> **Лента новостей** (Facebook, VK, X) — бесконечный список постов с текстом и медиа, лайками, комментариями и созданием поста. Ключевые темы: **cursor-пагинация** и бесконечная прокрутка через `IntersectionObserver`, **виртуализация** длинного списка, **оптимистичные лайки**, **нормализованный кеш**, загрузка **изображений без CLS**, появление **новых постов** без скачков позиции и доступность паттерна `feed`.

## Вопрос

Как спроектировать ленту новостей? Как сделать бесконечную прокрутку, не потерять производительность на тысячах постов и показывать новые посты?

## R — требования

- функциональные: лента постов (текст, изображения), бесконечная прокрутка, лайк, комментарии (превью), создание поста;
- вне рамок: алгоритм ранжирования, личные сообщения, реклама;
- нефункциональные: мобильные устройства, быстрый первый экран, плавный скролл на сотнях постов, новые посты без перезагрузки, a11y, SEO не нужно (за логином).

## A — архитектура

```text
SSR-оболочка + первая страница ленты (быстрый LCP)
  └─ <FeedPage>
       ├─ <Composer>           ленивый чанк
       ├─ <NewPostsBanner>     «Показать 5 новых постов»
       ├─ <VirtualFeed>        виртуализация + IntersectionObserver-сентинел
       │    └─ <PostCard>      memo: текст, медиа, действия
       └─ <FeedStatus>         skeleton / ошибка / конец ленты
Data layer: useInfiniteQuery(["feed"]) + нормализованные посты и авторы
Realtime: SSE или polling «есть новые посты»
```

## D — модель данных

```typescript
type Post = {
  id: string;
  authorId: string;
  text: string;
  media: { url: string; width: number; height: number; blurhash?: string }[];
  likeCount: number;
  likedByMe: boolean;
  commentCount: number;
  createdAt: string;
};

type FeedPage = { items: Post[]; nextCursor: string | null };
// кеш: pages: FeedPage[], users: Record<id, User>
```

## I — интерфейс

```http
GET  /api/feed?cursor=...&limit=20      → { items, nextCursor }
GET  /api/feed/new-count?since=<postId> → { count }        (или SSE-событие)
POST /api/posts                          → Post
PUT  /api/posts/:id/like  | DELETE /api/posts/:id/like
```

Cursor вместо offset: новые посты сверху не вызывают дублей и пропусков при листании.

## O — оптимизации

**Бесконечная прокрутка:**

```tsx
const { data, fetchNextPage, hasNextPage, isFetchingNextPage } = useInfiniteQuery({
  queryKey: ["feed"],
  queryFn: ({ pageParam }) => api.getFeed({ cursor: pageParam }),
  initialPageParam: null as string | null,
  getNextPageParam: (last) => last.nextCursor,
});

const sentinelRef = useRef<HTMLDivElement>(null);
useEffect(() => {
  const io = new IntersectionObserver(([entry]) => {
    if (entry.isIntersecting && hasNextPage && !isFetchingNextPage) fetchNextPage();
  }, { rootMargin: "800px" });                      // подгружать заранее
  if (sentinelRef.current) io.observe(sentinelRef.current);
  return () => io.disconnect();
}, [hasNextPage, isFetchingNextPage]);
```

**Производительность:**

- виртуализация с динамической высотой (TanStack Virtual, react-virtuoso) — в DOM 20–30 постов вместо сотен;
- `memo` для `PostCard`, лайк обновляет только один пост в кеше;
- изображения: `width`/`height` или `aspect-ratio` из API, `srcset`, `loading="lazy"` кроме первых, blurhash-заглушка;
- видео — автозапуск только в viewport, без звука, остановка вне экрана;
- ограничение памяти: выгружать старые страницы при очень длинной ленте (`maxPages`).

**Новые посты:** не вставлять их сверху автоматически — это сдвинет экран. Показать баннер «Новые посты (5)», по клику — прокрутить вверх и добавить.

**Взаимодействия:**

- оптимистичный лайк с откатом при ошибке, защита от двойного клика;
- создание поста: сразу вверху ленты со статусом «публикуется», загрузка медиа заранее;
- восстановление позиции скролла при возврате назад (кеш страниц + сохранение индекса).

**Доступность:** `role="feed"`, каждый пост — `<article aria-labelledby>` с `aria-posinset` и `aria-setsize` (`-1`, если общее число неизвестно); кнопка «Загрузить еще» как альтернатива; футер достижим (или отключить бесконечную прокрутку для клавиатуры).

## Что важно помнить

- Главные темы: cursor-пагинация, IntersectionObserver, виртуализация, медиа без CLS, оптимистичные действия.
- Бесконечная прокрутка мешает дойти до футера — выносите ссылки футера в другое место или используйте «Загрузить еще».
- Ошибка загрузки следующей страницы не должна прятать уже загруженные посты.
- Связанные темы: [виртуализация](<../../06. React/07. Рендеринг и производительность/04. Оптимизация длинных списков и виртуализация (windowing).md>), [API и пагинация](<../02. Архитектура и данные/04. Как спроектировать API между клиентом и сервером.md>).

## Мини-шпаргалка

SSR первой страницы → `useInfiniteQuery` + cursor → IntersectionObserver с `rootMargin` → виртуализация с динамической высотой → медиа с размерами и lazy → баннер новых постов вместо вставки → оптимистичный лайк → восстановление скролла → `role="feed"`.
