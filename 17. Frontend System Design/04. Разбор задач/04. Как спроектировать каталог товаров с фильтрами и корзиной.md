# Как спроектировать каталог товаров с фильтрами и корзиной

> [!NOTE]
> **Каталог интернет-магазина** — задача, где важны **SEO** и **скорость первого показа** (поисковый трафик, Core Web Vitals влияют на продажи), **фильтры в URL** (ссылки, кнопка «назад»), **пагинация**, **корзина**, переживающая перезагрузку и вход в аккаунт, и **надежное оформление заказа** без двойных списаний. Обычно: SSR/ISR страниц каталога и товара, клиентская логика фильтров и корзины, серверная проверка цены и наличия при оплате.

## Вопрос

Как спроектировать фронтенд каталога товаров с фильтрами, карточкой товара и корзиной? Как совместить SEO, быструю фильтрацию и надежное оформление заказа?

## R — требования

- каталог категорий с фильтрами (цена, бренд, размер), сортировкой и пагинацией;
- карточка товара: галерея, варианты (цвет, размер), наличие, отзывы;
- корзина и оформление заказа;
- нефункциональные: SEO для каталога и карточек, LCP < 2,5 с на мобильных, корзина у гостя и после входа, мультивалютность и i18n (опционально), a11y.

## A — архитектура

```text
Маршруты:
  /catalog/[category]?brand=nike&price=1000-5000&sort=price&page=2   SSR (или ISR + клиентская фильтрация)
  /product/[slug]                                                     ISR (revalidate по событию изменения товара)
  /cart, /checkout                                                    CSR, без индексации

<CatalogPage>
 ├─ <Filters>            состояние в URL
 ├─ <ProductGrid>        серверный рендер карточек, изображения с приоритетом для первых
 ├─ <Pagination>         ссылки <a href> для SEO
<ProductPage>
 ├─ <Gallery>            LCP-изображение с preload
 ├─ <VariantPicker>      клиентский компонент
 ├─ <AddToCart>          клиентский компонент
 └─ <Reviews>            streaming / ленивая загрузка
<CartProvider>           store корзины + синхронизация
```

## D — модель данных

```typescript
type ProductCard = { id: string; slug: string; title: string; price: Money; image: Image; rating: number; inStock: boolean };
type Money = { amount: number; currency: "RUB" | "USD" };   // в минимальных единицах (копейки)

type CartLine = { variantId: string; qty: number };
type CartState = {
  lines: CartLine[];
  updatedAt: string;
  syncStatus: "synced" | "pending" | "conflict";
};
// цены и наличие в корзине берутся с сервера при показе, а не хранятся навсегда
```

## I — интерфейс

```http
GET  /api/catalog?category=shoes&brand=nike&price_min=1000&price_max=5000&sort=price_asc&page=2
     → { items: ProductCard[], total, facets: { brand: [{ value, count }] } }
GET  /api/products/:slug
GET  /api/cart                       (для авторизованного)
PUT  /api/cart/lines/:variantId { qty }
POST /api/cart/merge { lines }        слияние гостевой корзины после входа
POST /api/orders  (Idempotency-Key)  → { orderId, paymentUrl }
```

`facets` с количеством товаров позволяют показать «Nike (42)» и скрыть пустые варианты.

## O — оптимизации

**Фильтры и URL:**

- состояние фильтров — в `searchParams`: ссылку можно отправить, «назад» работает, сервер рендерит нужную выдачу;
- изменение фильтра — `router.replace` или `push` + `startTransition`, чтобы список не мигал; старые результаты остаются, пока грузятся новые;
- текстовые фильтры и ползунок цены — debounce;
- каноничные URL (`<link rel="canonical">`) и `noindex` для бесконечных комбинаций фильтров.

**Производительность и SEO:**

- SSR/ISR сетки и карточки, `metadata` и JSON-LD (`Product`, `Offer`, `AggregateRating`);
- изображения: CDN с ресайзом, `srcset`, `priority` для первых карточек и главного фото, остальные lazy;
- prefetch карточки товара при наведении или видимости;
- тяжелые блоки (отзывы, рекомендации, 3D-просмотр) — streaming и ленивые чанки.

**Корзина:**

- гость: `localStorage` (+ `BroadcastChannel` для синхронизации вкладок);
- вход: слияние гостевой корзины с серверной (`/cart/merge`), правило конфликта — суммировать или брать максимум;
- оптимистичное изменение количества, debounce запросов при быстром «+ + +»;
- при открытии корзины — актуальные цены и наличие с сервера, предупреждение «цена изменилась» или «нет в наличии».

**Оформление заказа:**

- итоговую цену, скидки и наличие пересчитывает и проверяет **сервер**; клиентским ценам не доверяют;
- `Idempotency-Key` и блокировка кнопки — без двойных заказов;
- адрес и шаги — многошаговая форма с черновиком, `autocomplete` для адреса и карты;
- платежные данные — только в iframe или на странице провайдера (PCI DSS), не через свой фронтенд.

**a11y и i18n:** фильтры — `fieldset`/`legend`, результат фильтрации объявляется (`aria-live`: «Найдено 42 товара»), цены — через `Intl.NumberFormat` с валютой.

## Что важно помнить

- Главные темы: SSR/ISR для SEO, фильтры в URL, facets, корзина гостя и слияние, серверная проверка цены, идемпотентный заказ.
- Пагинация ссылками лучше для SEO, бесконечная прокрутка — для мобильного UX; часто делают «Показать еще» поверх ссылок.
- Деньги храните в минимальных единицах (копейках), не в float.
- Связанные темы: [стратегии рендеринга](<../02. Архитектура и данные/01. Как выбрать стратегию рендеринга под задачу.md>), [многошаговая форма](<../../06. React/16. Формы/08. Как сделать многошаговую форму и сохранять черновик.md>).

## Мини-шпаргалка

Каталог и карточка — SSR/ISR + metadata + JSON-LD. Фильтры — в URL, transition, debounce, facets, canonical. Изображения — CDN, srcset, priority. Корзина — localStorage у гостя, merge после входа, актуальные цены с сервера. Заказ — серверный пересчет, Idempotency-Key, оплата у провайдера.
