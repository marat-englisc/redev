# Как обеспечить производительность

> [!NOTE]
> Производительность на system design интервью обсуждают через **метрики** и **приемы**. Метрики — Core Web Vitals: **LCP** (скорость показа главного контента, хорошо ≤ 2,5 с), **INP** (отзывчивость на действия, ≤ 200 мс), **CLS** (стабильность верстки, ≤ 0,1), плюс TTFB и размер JS. Приемы делятся на четыре группы: **загружать меньше** (code splitting, сжатие, оптимизация изображений), **загружать раньше** (preload, prefetch, SSR), **рендерить меньше** (виртуализация, мемоизация, `content-visibility`) и **не блокировать главный поток** (debounce, workers, transitions).

## Вопрос

Как обеспечить производительность фронтенд-приложения на system design интервью? Какие метрики назвать и какие приемы применить?

## Метрики

| Метрика | Что измеряет | Чем улучшают |
| --- | --- | --- |
| LCP | когда отрисован главный элемент | SSR/SSG, preload героя, CDN, оптимизация изображений и шрифтов |
| INP | задержка ответа на взаимодействие | меньше JS, разбиение долгих задач, transitions, workers |
| CLS | сдвиги верстки | размеры медиа, резерв места под рекламу и баннеры, `font-display` |
| TTFB | время до первого байта | кеш, CDN, edge, streaming |
| Bundle size | объем JS | code splitting, tree shaking, замена тяжелых зависимостей |

## 1. Загружать меньше

- **code splitting по маршрутам** и ленивые компоненты (`React.lazy`, `next/dynamic`) для модалок, редакторов, графиков;
- tree shaking, анализ бандла (`rollup-plugin-visualizer`, `@next/bundle-analyzer`), бюджет размера в CI;
- изображения: AVIF/WebP, `srcset` и `sizes`, правильные размеры, `loading="lazy"` для невидимых, CDN с ресайзом;
- шрифты: `woff2`, subset, `font-display: swap`, preload основного начертания;
- сжатие Brotli/gzip, HTTP/2 или HTTP/3.

## 2. Загружать раньше

- SSR/streaming для первого экрана;
- `<link rel="preload">` для LCP-изображения и критичного шрифта, `fetchpriority="high"` для героя;
- `preconnect` к CDN и API;
- prefetch следующего маршрута при наведении или появлении ссылки в viewport;
- кеш: HTTP, CDN, Service Worker, кеш запросов.

## 3. Рендерить меньше

- **виртуализация** длинных списков — в DOM только видимые элементы;
- мемоизация тяжелых компонентов (`memo`) и вычислений, React Compiler;
- colocation состояния, чтобы обновление не ререндерило всё дерево;
- `content-visibility: auto` для блоков ниже первого экрана;
- анимации через `transform` и `opacity`, а не `top`/`width`.

## 4. Не блокировать главный поток

- debounce и throttle для ввода, скролла, ресайза;
- `startTransition` и `useDeferredValue` для тяжелых обновлений UI;
- разбиение долгих задач (`scheduler.yield()`, `setTimeout`), `requestIdleCallback` для некритичного;
- Web Worker для парсинга, сортировки больших данных, обработки изображений;
- откладывание сторонних скриптов (аналитика, чаты поддержки) — `defer`, загрузка после взаимодействия.

## Пример ответа

> «Главный риск ленты — INP и память при длинном скролле. Виртуализирую список, изображения — с размерами и lazy, первую — с `fetchpriority="high"`. Композер поста и просмотрщик медиа — отдельные чанки. Лайк — оптимистично, без ожидания сети. Метрики собираю через RUM (`web-vitals`), бюджет бандла — в CI.»

## Что важно помнить

- Сначала измерить: Lighthouse и DevTools Performance — лабораторные данные, RUM (`web-vitals`, CrUX) — реальные пользователи.
- Связывайте прием с метрикой: «виртуализация улучшает INP и память», «размеры изображений — CLS».
- Самые дорогие ресурсы на мобильных — JavaScript (парсинг и выполнение), а не картинки того же размера.
- Оптимистичные обновления и skeleton улучшают **воспринимаемую** производительность.
- Связанные темы: [Core Web Vitals](<../../04. JavaScript/09. Производительность в JS/01. Метрики производительности и Core Web Vitals.md>), [виртуализация](<../../06. React/07. Рендеринг и производительность/04. Оптимизация длинных списков и виртуализация (windowing).md>).

## Мини-шпаргалка

Метрики: LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1, TTFB, размер JS. Меньше: code splitting, изображения, шрифты. Раньше: SSR, preload, prefetch, кеш. Меньше рендера: виртуализация, memo, colocation. Не блокировать поток: debounce, transitions, workers. Измерять: Lighthouse + RUM.
