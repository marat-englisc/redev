# Как выбрать стратегию рендеринга под задачу

> [!NOTE]
> Стратегию рендеринга выбирают по требованиям: **SEO и скорость первого показа**, **персонализация**, **частота изменения данных** и **интерактивность**. Публичные страницы с редкими изменениями — SSG или ISR; публичные с персонализацией или свежими данными — SSR со streaming; приложения за логином с богатой интерактивностью — CSR (SPA) или SSR оболочки + CSR данных. В одном продукте стратегии обычно комбинируют по маршрутам.

## Вопрос

Как на system design интервью выбрать между CSR, SSR, SSG, ISR и streaming? Какие требования на это влияют?

## Дерево решений

```text
Нужна индексация поисковиками или превью ссылок?
├─ нет → страница за логином?
│        ├─ да → CSR (SPA) или SSR-оболочка + клиентская загрузка
│        └─ нет → CSR допустим, если первый экран не критичен
└─ да → контент одинаков для всех?
         ├─ да → как часто меняется?
         │        ├─ редко      → SSG
         │        └─ регулярно  → ISR / revalidate по событию
         └─ нет (персонализация, свежие данные) → SSR + streaming
```

## Сравнение для интервью

| Стратегия | Сильные стороны | Слабые стороны | Типичные экраны |
| --- | --- | --- | --- |
| CSR | простая инфраструктура, быстрая навигация | медленный первый экран, слабое SEO | дашборды, редакторы, админки |
| SSR | SEO, быстрый FCP, свежие данные | нагрузка на сервер, TTFB, гидрация | карточка товара, поиск |
| SSG | максимум скорости, CDN | данные на момент сборки | документация, лендинги |
| ISR | скорость статики + обновление | временно устаревшие данные | каталог, статьи |
| Streaming SSR | быстрая оболочка, медленные блоки позже | сложнее инфраструктура | страницы с медленными виджетами |
| RSC / islands | меньше JS на клиенте | новая модель, нужен фреймворк | контентные страницы с островками интерактива |

## Примеры решений

| Задача | Решение |
| --- | --- |
| Маркетплейс: каталог и карточка | ISR/SSR для SEO, корзина и фильтры — клиентская логика |
| Лента соцсети за логином | SSR-оболочка или CSR, лента грузится курсором на клиенте |
| Google Docs | CSR: интерактивный редактор, SEO не нужно |
| Новостной сайт | SSG/ISR статей + streaming комментариев |
| Дашборд аналитики | CSR + realtime, код по маршрутам в отдельные чанки |

## Как проговорить на интервью

> «Лента за авторизацией, SEO не нужно, но важен быстрый первый экран на мобильных. Отрендерю на сервере оболочку и первую порцию постов, чтобы LCP был ранним, а дальнейшие страницы буду грузить на клиенте по курсору. Тяжелые части — редактор поста, просмотрщик изображений — вынесу в ленивые чанки.»

## Что важно помнить

- Решение принимается по маршрутам, а не для всего приложения сразу.
- SSR улучшает первый показ, но не интерактивность: следите за размером JS и гидрацией.
- Для страниц за логином SSR полезен ради скорости, а не SEO — это нормальный аргумент.
- Называйте метрики: LCP, INP, TTFB — так видно, что вы понимаете, что именно улучшаете.

SSR, CSR и SSG - сравнение стратегий рендеринга.md>) и [стратегии рендеринга в Next.js](<../../07. Next/04. Рендеринг и стратегии/01. Какие основные типы рендеринга существуют в Next.js.md>).

## Мини-шпаргалка

SEO + редко меняется → SSG. SEO + регулярно → ISR. SEO + персонально/свежо → SSR + streaming. За логином + интерактив → CSR или SSR-оболочка. Комбинировать по маршрутам, обосновывать метриками LCP, INP, TTFB.
