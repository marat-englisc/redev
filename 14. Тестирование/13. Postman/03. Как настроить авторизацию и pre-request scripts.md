# Авторизация и pre-request scripts

> [!NOTE]
> Авторизацию удобно задать на уровне коллекции и наследовать в запросах. Pre-request scripts выполняются до отправки и готовят данные, заголовки или подпись. Они не должны скрывать обязательные условия теста или случайно переносить состояние прошлого запуска.

## Вопрос

Как передавать Bearer token в Postman? Для чего нужен pre-request script и как проверять отсутствие авторизации?

## Учебная настройка

В коллекции выбери Authorization → Bearer Token → `{{token}}`. Для обычных запросов включи Inherit auth from parent. Учебный сервер принимает `qa-a` и `qa-b`; это заранее заданные идентификаторы, а не результат настоящего OAuth-входа.

Для `Health` и негативного запроса без токена выбери No Auth. Затем проверь итоговые Headers: вручную добавленный Authorization не должен случайно сохраниться.

## Генерация данных

В Pre-request запроса создания задачи:

```js
const suffix = pm.variables.replaceIn('{{$guid}}');
pm.variables.set('taskTitle', `QA задача ${suffix}`);
```

Body:

```json
{"title":"{{taskTitle}}"}
```

Разделённые данные уменьшают столкновения прогонов, но не заменяют уборку созданных записей.

## Реальный login-flow

Если API выдаёт токен через `/auth/login`, отдельный запрос отправляет тестовые учётные данные, а post-response сохраняет токен только после проверки успешного ответа. Следующие запросы используют переменную. При падении логина старый токен предварительно очищают, чтобы прогон не продолжился с чужой сессией.

Basic Auth кодирует логин и пароль, но не шифрует их; для передачи нужен защищённый транспорт. OAuth 2.0 описывает получение полномочий через соответствующий flow; нельзя заменять его произвольной строкой только потому, что заголовок называется Bearer.

## Что важно помнить

- Скрипты коллекции, папки и запроса выполняются в определённом порядке; общая генерация может неожиданно перезаписать данные.
- Истёкший и отсутствующий токен — разные условия для теста.
- Генерация уникального email не должна использовать реальные адреса случайных людей.
- В скриптах не нужно печатать пароль, token или cookie для отладки.

## Практика

Создай три запроса GET `/tasks`: с `qa-a`, с `qa-b` и без auth. Объясни, почему два первых должны видеть разные наборы, а третий — получить 401.

## Мини-шпаргалка

Auth коллекции → наследование → явные исключения → подготовка данных → запрос → проверка результата.
