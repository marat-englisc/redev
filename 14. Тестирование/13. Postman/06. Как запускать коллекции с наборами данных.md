# Collection Runner и наборы данных

> [!NOTE]
> Collection Runner выполняет выбранные запросы и показывает результаты проверок. Data-driven запуск повторяет их с разными строками JSON/CSV. В данных должны быть входные значения и конкретные ожидания, а подготовка и очистка — выполняться для каждой итерации.

## Вопрос

Как проверить несколько классов и границ одним запросом Postman? Как сохранить типы данных?

## Пример JSON-файла

Для учебного POST `/tasks` название после trim должно иметь длину 1–80:

```json
[
  {"title":"A","expectedStatus":201},
  {"title":"","expectedStatus":400},
  {"title":"   ","expectedStatus":400},
  {"title":42,"expectedStatus":400},
  {"title":null,"expectedStatus":400}
]
```

JSON удобен для различения чисел, строк и null. CSV подходит для простых таблиц, но типы после импорта нужно проверить в preview; пустая ячейка не обязательно означает отсутствие ключа.

## Скрипты запроса

Pre-request:

```js
pm.collectionVariables.unset('createdId');
pm.variables.set('payload', JSON.stringify({
  title: pm.iterationData.get('title')
}));
```

Body raw JSON: `{{payload}}`, без дополнительных кавычек. Post-response:

```js
const expected = Number(pm.iterationData.get('expectedStatus'));
pm.test(`Статус ${expected}`, () => {
  pm.response.to.have.status(expected);
});
if (pm.response.code === 201) {
  pm.collectionVariables.set('createdId', pm.response.json().id);
}
```

В Runner выбери environment, папку и data-файл, проверь число итераций и preview, затем запусти. Для позитивных строк добавь cleanup DELETE по `createdId`; при отсутствии ID запрос уборки пропускается с явной причиной. Все исходные проверки должны сохранять свой статус.

## Что добавить к набору

Длины 79/80/81, отсутствие ключа title, допустимые Unicode-строки и проверку сохранённого значения. Учебный стенд считает длину средствами JavaScript; правило про «символы» для Unicode нужно читать в контракте стенда.

## Что важно помнить

- Локальная переменная с тем же именем перекрывает data-переменную.
- Не нужно много раз прогонять один позитивный пример и называть это покрытием классов.
- Функциональный Runner с итерациями не автоматически становится корректным нагрузочным тестом.

## Мини-шпаргалка

Модель данных → файл → preview типов → сборка body → ожидания каждой строки → уборка → анализ падений.
