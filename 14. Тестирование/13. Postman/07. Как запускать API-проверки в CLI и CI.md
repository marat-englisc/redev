# Postman CLI, Newman и CI

> [!NOTE]
> CLI запускает API-проверки воспроизводимо и возвращает статус завершения для CI. Для новых коллекций ориентируйся на Postman CLI и поддерживаемый формат. Newman встречается в существующих проектах, но устарел и поддерживает коллекции v2.1, а новый формат v3 не поддерживает.

## Вопрос

Как запускать коллекцию без ручного нажатия Run? Чем отчёт отличается от exit code и почему pipeline может стать зелёным при ошибке?

## Основная идея

Pipeline должен подготовить окружение, дождаться доступности API, запустить коллекцию и сохранить результаты. Данные и секреты передаются явно. Ошибка проверки должна приводить к неуспешному шагу, а не исчезать из-за обработки команд.

## Пример для Postman CLI

После установки CLI по официальной инструкции проверь версию и справку команды. Для поддерживаемой экспортированной коллекции:

```bash
postman --version
postman collection run qa.collection.json -e qa.environment.json
```

Формат экспорта и способы работы с локальными файлами могут зависеть от версии. Перед переносом между GUI, CLI и CI проверь совместимость и доступные возможности. Сервисы аккаунта и публикация результатов могут требовать отдельной аутентификации; не сохраняй API key в репозитории.

## Как читать существующий Newman pipeline

Для коллекции именно v2.1 существующий проект может использовать:

```bash
newman run qa.collection.json -e qa.environment.json --bail --reporters cli,junit --reporter-junit-export results.xml
```

`--bail` останавливает прогон на ошибке. Для полного списка проблем команда может выбрать выполнение без ранней остановки. Не используй опции подавления неуспешного exit code ради зелёного CI. В новой настройке предпочтительнее поддерживаемый CLI; документация Postman содержит путь миграции с Newman.

## Что проверить в CI

- API доступен из runner: `localhost` runner и ноутбука — разные машины.
- Выбрано тестовое окружение и нет секретов в экспортируемом файле.
- Коллекция создаёт собственные данные и убирает их.
- Ошибка assertion делает job неуспешной.
- Отчёты сохраняются и при падении, но чувствительные ответы не публикуются.

## Практика

Намеренно поменяй ожидаемый статус 201 на 200. Убедись, что локальный CLI и шаг CI показывают ошибку. Затем верни правильное ожидание. Это проверяет, что автоматизация действительно реагирует на провал.

## Мини-шпаргалка

Формат коллекции + версия CLI + явное окружение + exit code + доступный отчёт.
