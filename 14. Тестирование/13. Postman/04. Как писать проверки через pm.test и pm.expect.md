# Проверки pm.test и pm.expect

> [!NOTE]
> Скрипты Post-response выполняют проверки ответа. `pm.test` задаёт имя проверки, `pm.expect` и `pm.response` — утверждения. Проверять нужно статус, структуру и значимые значения; запись в console или сохранение переменной сами по себе не являются тестом.

## Вопрос

Как проверить ответ API в Postman? Почему тест «статус 201» может пройти при неверных данных?

## Пример создания задачи

Для POST `{{baseUrl}}/tasks` из предыдущего урока добавь в Scripts → Post-response:

```js
pm.test('Создание возвращает 201', () => {
  pm.response.to.have.status(201);
});

pm.test('Ответ имеет JSON Content-Type', () => {
  pm.expect(pm.response.headers.get('Content-Type')).to.include('application/json');
});

pm.test('Создана задача с переданным названием', () => {
  const body = pm.response.json();
  pm.expect(body.id).to.be.a('string').and.not.empty;
  pm.expect(body.title).to.equal(pm.variables.get('taskTitle'));
  pm.expect(body.done).to.equal(false);
  pm.expect(body).not.to.have.property('token');
});
```

Название берётся из pre-request `taskTitle`. Если используешь фиксированное тело, сравнивай с тем же фиксированным значением. Нельзя ожидать случайную строку, которую запрос не отправлял.

Разбор JSON внутри `pm.test` превращает ошибку парсинга в понятное падение именованной проверки. Проверки типа и значения решают разные задачи: `done` может быть boolean, но ошибочно равняться `true`.

## Негативный ответ

Для пустого title учебный контракт требует 400:

```js
pm.test('Пустое название отклоняется', () => {
  pm.response.to.have.status(400);
  const body = pm.response.json();
  pm.expect(body.error).to.equal('title must contain 1..80 characters');
});
```

`pm.expect(true).to.equal(true)` всегда успешно и ничего не говорит о продукте. Сравнение с «любым из 200/400/500» тоже маскирует нарушение определённого контракта.

## Что важно помнить

- `204 No Content` проверяют без попытки прочитать JSON.
- Время ответа одной отправки — сигнал, а не полноценная оценка нагрузки.
- Глобальная проверка «все ответы 200» ломает корректные негативные запросы.
- JSON Schema описывает структуру; расчёты и права требуют отдельных утверждений.

## Мини-шпаргалка

Именованная проверка + конкретное утверждение + данные того же запроса + ожидаемый контракт.
