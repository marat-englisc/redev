# Карта раздела Тестирование

> [!NOTE]
> Раздел объединяет подготовку ручного QA от нуля до junior+ и основы автоматизации. Начни с теории, тест-дизайна и документации, затем переходи к web/API, Postman и Playwright. Исходные материалы Jest/Vitest, React Testing Library и MSW дополняют маршрут для тех, кто тестирует код и frontend.

## Вопрос

Как изучать тестирование с нуля и подготовиться к собеседованию на junior/junior+ QA?

## Как устроены материалы

В разделе 100 Markdown-уроков вместе с этой картой. Каждый начинается с короткого ответа и вопроса для повторения, затем раскрывает тему с примерами и ограничениями. Нумерация существующих тем сохранена; рекомендуемый порядок для QA отличается от порядка папок.

Не нужно сначала изучать React, чтобы начать ручное тестирование. Для Postman потребуются основы HTTP/JSON и немного JavaScript, для Playwright — переменные, функции, объекты, Promise и async/await. Эти знания можно добирать по мере практики.

## Как работать с примерами

- Сначала реши задачу и запиши ожидание, затем читай разбор.
- Для таблиц решений и переходов объясняй, что покрыто и что осталось.
- Для документации используй согласованный контракт: не придумывай обязательные правила продукта.
- Postman и Playwright практикуются на [локальном QA Lab](<15. Практика QA/01. Как запустить локальный учебный стенд QA.md>).
- Код сервера сохраняется в отдельной учебной папке. Пакеты Playwright устанавливаются в собственный Node-проект.
- Браузерная песочница сайта не запускает локальный Node-сервер, Postman или Playwright; эти блоки предназначены для копирования и локального выполнения.
- Режим QA_BUG включает заранее внедрённую ошибку для упражнения. Отмечай это в портфолио.

## Контрольные точки

### После основ

- [ ] Различаю QA, QC, testing и debugging.
- [ ] Объясняю семь принципов на примерах.
- [ ] Различаю уровень, вид и способ выполнения проверки.
- [ ] Уточняю требования до формулировки ожидаемого результата.
- [ ] Отличаю smoke, retest и regression.

### После Junior

- [ ] Для поля выделяю допустимые/недопустимые классы и границы.
- [ ] Строю таблицу решений и модель переходов.
- [ ] Пишу воспроизводимый кейс и баг-репорт без догадок о причине.
- [ ] Различаю severity и priority, failed и blocked.
- [ ] Читаю запрос в Network и объясняю его метод, body и статус.
- [ ] Проверяю API в Postman и передаю ID между запросами.
- [ ] Сообщаю непроверенные области и остаточные риски.

### После Junior+

- [ ] Проверяю серверные права двумя владельцами, а не только видимость кнопок.
- [ ] Использую SELECT/JOIN и request ID для диагностики.
- [ ] Понимаю, что pairwise и coverage не гарантируют отсутствие дефектов.
- [ ] Пишу небольшие Playwright-тесты с await и наблюдаемыми assertions.
- [ ] Готовлю и очищаю свои данные, объясняю изоляцию context и backend.
- [ ] Разбираю падение через trace и не маскирую проблему retries.
- [ ] Могу показать артефакты трёх практических работ и объяснить выбор проверок.
