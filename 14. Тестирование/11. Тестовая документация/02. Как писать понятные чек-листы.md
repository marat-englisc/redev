# Как писать чек-листы

> [!NOTE]
> Чек-лист — компактный набор проверок с понятным объектом и критерием успеха. Хороший пункт проверяет конкретное условие, допускает однозначный статус и связан с требованием или риском. «Проверить форму» слишком широко для полезного результата.

## Вопрос

Как составить чек-лист входа в систему? Насколько подробными должны быть его пункты?

## Основная идея

Чек-лист обычно не расписывает каждый клик, но должен содержать достаточно контекста, чтобы участники команды одинаково поняли проверку. Если без сложных шагов или подготовки контекст теряется, лучше оформить отдельный кейс.

## Пример

Контекст: тестовая сборка 1.2.0, обычный активный пользователь, вход по email/паролю. Правило блокировки согласовано отдельно.

| ID | Проверка и ожидаемое поведение | Статус |
| --- | --- | --- |
| CL-01 | Корректные данные открывают личный кабинет текущего пользователя | Not run |
| CL-02 | Неверный пароль не создаёт сессию; показана согласованная ошибка | Not run |
| CL-03 | Пустой email препятствует отправке и показывает ошибку обязательности | Not run |
| CL-04 | Пустой пароль препятствует отправке и показывает ошибку обязательности | Not run |
| CL-05 | Enter отправляет корректную форму один раз | Not run |
| CL-06 | После выхода закрытая страница недоступна при обновлении | Not run |
| CL-07 | При ошибке сервера нет ложного сообщения об успешном входе | Not run |

Для failed добавляют ссылку на дефект и фактическое наблюдение. Для blocked — причину, например недоступность сервиса авторизации. Неизвестный результат нельзя заменять успешным.

## Как улучшить плохие пункты

- «Проверить безопасность» → «Пользователь B не получает профиль A при замене ID в запросе».
- «Все ошибки» → отдельные обязательность, формат и неверные учётные данные.
- «Красиво выглядит» → согласованные размеры экрана, отсутствие перекрытий и доступность текста.

Пункты удобно группировать по функции и риску: основной путь, валидация, сессия, ошибки, совместимость. Приоритет помогает выбрать краткий smoke-набор.

## Практика

Составь 10 пунктов для корзины. Для каждого задай себе два вопроса: «какие данные нужны?» и «что именно будет считаться успехом?». Пункты без ответа уточни или преврати в кейсы.

## Мини-шпаргалка

Один пункт → конкретное условие → наблюдаемое ожидание → статус → ссылка на проблему при необходимости.
