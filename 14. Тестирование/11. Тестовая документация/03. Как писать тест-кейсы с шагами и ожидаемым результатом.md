# Как писать тест-кейсы

> [!NOTE]
> Тест-кейс задаёт цель, предусловия, данные, шаги и ожидаемые результаты. Его должно быть возможно выполнить без догадок. Сам кейс описывает проверку, а фактический результат, статус и сборка принадлежат конкретному прогону.

## Вопрос

Из чего состоит хороший тест-кейс? Чем предусловия отличаются от шагов и нужно ли писать ожидаемый результат для каждого клика?

## Основная идея

Предусловия описывают готовность к началу проверки: пользователь существует, товар доступен, корзина пуста. Шаги — действия в проверяемом сценарии. Постусловия помогают убрать данные или восстановить окружение.

## Полный пример

```text
ID: TC-CART-04
Название: скидка NEW10 ограничивается суммой 500 рублей
Требование: REQ-DISCOUNT-02
Приоритет: высокий

Предусловия:
  Новый пользователь без оплаченных заказов вошёл в систему.
  Корзина пуста. Товар A доступен, цена 3000 рублей.
  Промокод NEW10 активен: 10%, максимум 500 рублей.
  Доставка в расчёт этой проверки не входит.

Данные:
  Товар A, количество 2, промокод NEW10.

Шаг 1: добавить две единицы товара A в корзину.
Ожидание: сумма товаров 6000 рублей.

Шаг 2: применить промокод NEW10.
Ожидание: скидка 500 рублей, итог товаров 5500 рублей.

Шаг 3: обновить страницу корзины.
Ожидание: количество, промокод и суммы сохранены.

Постусловие: удалить созданную корзину или очистить её через API.
```

Ожидания нужны в контрольных точках, где наблюдаем важное поведение. Необязательно отдельно описывать появление курсора после каждого клика, если это не цель проверки.

## Как записать выполнение

```text
Прогон: RUN-2026-10-27-01
Сборка: qa-1.8.0
Окружение: staging, Chromium, Windows
Статус: Failed
Факт: скидка 600, итог 5400; после reload значения те же.
Дефект: BUG-18
```

Нельзя заменить ожидаемые суммы на фактические ради зелёного статуса. Сначала нужно выяснить, изменились ли требования.

## Что важно помнить

- Кейсы должны быть независимы: второй не должен молча требовать успеха первого.
- Данные должны существовать или создаваться понятным способом.
- «Результат корректный» не задаёт проверяемого критерия.
- Параметризация подходит для одного правила с разными данными, но не для объединения несвязанных сценариев.

## Мини-шпаргалка

Цель + источник ожидания + предусловия + данные + действия + контрольные результаты + уборка.
