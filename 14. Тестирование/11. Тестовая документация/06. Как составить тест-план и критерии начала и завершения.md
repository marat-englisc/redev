# Тест-план и критерии проверки

> [!NOTE]
> Тест-план определяет цель, объём, подход, ресурсы, окружение, сроки и риски. Entry criteria задают условия начала, exit criteria — условия достаточности проверки. Они не гарантируют отсутствие дефектов, но делают решение прозрачным.

## Вопрос

Как спланировать тестирование новой функции? Когда можно начать и когда можно закончить?

## Основная идея

План нужен, чтобы команда одинаково понимала обещанный объём. Он может занимать одну страницу для небольшой задачи. Важнее конкретные ограничения, чем длинные общие фразы.

## Пример плана релиза корзины

| Поле | Содержание |
| --- | --- |
| Цель | проверить расчёт скидки и сохранение корзины |
| В объёме | суммы, границы скидки, повтор запроса, сохранение, права |
| Вне объёма | нагрузочное тестирование платёжного провайдера |
| Подход | API для правил, UI для отображения и ключевого пути |
| Окружение | staging, версия backend и frontend зафиксированы |
| Данные | отдельные аккаунты, товары с известной ценой, активные/истёкшие коды |
| Роли | QA выполняет, аналитик уточняет правила, разработчик помогает с логами |
| Сроки | день на дизайн и данные, день на выполнение и retest |
| Риски | сервис доставки недоступен; нужен согласованный stub |

## Entry criteria

- Согласованы правила скидки и примеры расчёта.
- Нужная сборка развернута и проходит smoke.
- Доступны аккаунты, данные, логи и зависимости.

Если часть условий не выполнена, можно начать независимые проверки, явно указав ограничения. Не нужно объявлять все проверки выполненными на подменённом сервисе.

## Exit criteria

- Выполнены все согласованные критичные проверки.
- Нет открытых блокирующих дефектов по принятой шкале.
- Исправления прошли retest и выбранную регрессию.
- Непроверенные области и принятые риски перечислены в отчёте.

Правило «100% тестов зелёные» недостаточно: набор может быть неполным, а часть проверок — ошибочной. Допустимые исключения согласуют явно и сохраняют в решении.

## Что важно помнить

Definition of Done относится к готовности инкремента команды и обычно шире конкретного плана QA. Оценка времени включает подготовку, коммуникацию, повторные проверки и отчётность, а не только время кликов.

## Мини-шпаргалка

Цель, объём, подход, люди, среда, данные, сроки, риски, вход и выход.
