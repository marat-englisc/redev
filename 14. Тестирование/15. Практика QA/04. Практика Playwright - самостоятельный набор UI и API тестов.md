# Практика Playwright: UI и API

> [!NOTE]
> Учебный набор Playwright должен проверять поведение и сохранять независимость данных. API готовит или очищает ресурсы, UI выполняет проверяемые действия, а assertions подтверждают результат и сохранение после reload. Конфигурация должна явно запускать нужный стенд.

## Вопрос

Как собрать небольшой работающий набор автоматизации для портфолио junior+ QA?

## Структура и запуск

В проекте из [первого урока Playwright](<../06. E2E тестирование/06. Как установить Playwright и написать первый тест с нуля.md>) сохрани `qa-lab.mjs` из [стенда](<01. Как запустить локальный учебный стенд QA.md>) в корень. Убедись, что другой экземпляр не занимает порт.

```text
qa-playwright/
  qa-lab.mjs
  playwright.config.ts
  tests/tasks.spec.ts
```

```ts
// playwright.config.ts
import { defineConfig } from '@playwright/test';

export default defineConfig({
  testDir: './tests',
  workers: 1,
  retries: 0,
  reporter: [['list'], ['html', { open: 'never' }]],
  use: {
    baseURL: 'http://127.0.0.1:3007',
    browserName: 'chromium',
    trace: 'retain-on-failure',
  },
  webServer: {
    command: 'node qa-lab.mjs',
    url: 'http://127.0.0.1:3007/health',
    reuseExistingServer: false,
  },
});
```

Один worker здесь упрощает начало и общий учебный аккаунт. Далее стоит выделить данные по ID и проверить параллельность осознанно.

## Рабочий UI-сценарий

```ts
// tests/tasks.spec.ts
import { randomUUID } from 'node:crypto';
import { test, expect } from '@playwright/test';

test('создание и отметка сохраняются после reload', async ({ page, request }) => {
  const title = `Практика ${randomUUID()}`;
  const headers = { Authorization: 'Bearer qa-a' };
  let id: string | undefined;
  try {
    await page.goto('/');
    await expect(page.getByRole('status')).toHaveText('Готово');
    await page.getByLabel('Название', { exact: true }).fill(title);

    const responsePromise = page.waitForResponse(response =>
      new URL(response.url()).pathname === '/tasks' &&
      response.request().method() === 'POST'
    );
    await page.getByRole('button', { name: 'Добавить', exact: true }).click();
    const response = await responsePromise;
    expect(response.status()).toBe(201);
    id = (await response.json()).id;
    expect(id).toEqual(expect.any(String));

    const row = page.getByTestId(`task-${id}`);
    await expect(row).toContainText(title);
    const savedPromise = page.waitForResponse(response =>
      new URL(response.url()).pathname === `/tasks/${id}` &&
      response.request().method() === 'PATCH'
    );
    await row.getByRole('checkbox').check();
    const saved = await savedPromise;
    expect(saved.status()).toBe(200);
    expect((await saved.json()).done).toBe(true);

    await page.reload();
    await expect(row.getByRole('checkbox')).toBeChecked();
  } finally {
    if (id) {
      const response = await request.delete(`/tasks/${id}`, { headers });
      expect(response.status()).toBe(204);
    }
  }
});
```

Ожидание PATCH важно: checkbox может стать checked локально ещё до сохранения на сервере. Слишком ранний reload способен прервать запрос и сделать тест нестабильным.

## Задания для самостоятельной работы

Добавь API-кейсы длины 1/80/81 и доступа B к задаче A, UI-кейс ошибки 500 через route и сценарий удаления. Для API-валидации очищай только реально созданные ID, для прав дополнительно читай исходный объект токеном A.

## Критерии самопроверки

- `npx playwright test` запускает сервер и завершается успешно в обычном режиме.
- При QA_BUG=1 проверка 81 символа становится красной.
- Данные очищаются при неуспешном assertion.
- Можно объяснить каждый await, локатор и ожидание ответа.
- В README портфолио указаны команды, версии и границы проверки.

## Мини-шпаргалка

Запуск стенда → готовность → действие UI → ответ API → reload → assertion → уборка.
