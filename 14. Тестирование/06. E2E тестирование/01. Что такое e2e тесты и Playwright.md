# E2E-тесты и Playwright

> [!NOTE]
> E2E-тест запускает собранное приложение в настоящем браузере и проходит сценарий пользователя от начала до конца. Playwright — фреймворк от Microsoft для таких тестов: Chromium, Firefox и WebKit, автоожидание, параллельный запуск, trace viewer и генератор тестов.

## Вопрос

Что такое e2e-тесты? Что покрывать ими? Как устроен тест на Playwright?

## Основная идея

Unit и интеграционные тесты в jsdom не видят многого: настоящий layout и CSS, работу роутера с перезагрузкой страницы, cookie и редиректы, взаимодействие с бэкендом, особенности Safari. E2E-тест проверяет всё это сразу: открывает страницу, кликает, ждёт ответа сервера и проверяет результат на экране.

Цена — скорость и стабильность. Один e2e-тест длится секунды, требует запущенного приложения и данных. Поэтому e2e покрывают **критичные пользовательские пути**: регистрацию и вход, оформление заказа, оплату, ключевой CRUD. Детали валидации и редкие ветки оставляют интеграционным тестам.

Ключевые возможности Playwright:

| Возможность | Зачем |
| --- | --- |
| Три движка: Chromium, Firefox, WebKit | проверка в разных браузерах, включая Safari-подобный |
| Auto-waiting | действия ждут, пока элемент станет видимым и доступным |
| Web-first assertions | `expect(locator).toBeVisible()` повторяет проверку до таймаута |
| Изоляция через browser context | каждый тест — как новый профиль браузера |
| Параллельность | тесты идут в нескольких воркерах |
| `webServer` в конфиге | поднимает приложение перед тестами |
| Trace viewer | запись шагов, DOM, сети и консоли для разбора падения |
| `codegen` | генерирует код теста по вашим действиям в браузере |
| API testing (`request`) | запросы к API без UI для подготовки данных |

## Пример

```bash
npm init playwright@latest
npx playwright test
npx playwright test --ui
npx playwright codegen http://localhost:5173
```

```ts
// playwright.config.ts
import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  testDir: './e2e',
  fullyParallel: true,
  retries: process.env.CI ? 2 : 0,
  use: {
    baseURL: 'http://localhost:5173',
    trace: 'on-first-retry',
  },
  projects: [
    { name: 'chromium', use: { ...devices['Desktop Chrome'] } },
    { name: 'webkit', use: { ...devices['iPhone 15'] } },
  ],
  webServer: {
    command: 'npm run build && npm run preview -- --port 5173',
    url: 'http://localhost:5173',
    reuseExistingServer: !process.env.CI,
  },
});
```

```ts
// e2e/todos.spec.ts
import { test, expect } from '@playwright/test';

test('пользователь добавляет и выполняет задачу', async ({ page }) => {
  await page.goto('/');

  await page.getByLabel('Новая задача').fill('Купить хлеб');
  await page.getByRole('button', { name: 'Добавить' }).click();

  const todo = page.getByRole('listitem').filter({ hasText: 'Купить хлеб' });
  await expect(todo).toBeVisible();

  await todo.getByRole('checkbox').check();
  await expect(todo.getByRole('checkbox')).toBeChecked();
});
```

## Что важно помнить

- E2E тестирует сборку, близкую к production, а не dev-сервер с HMR.
- Тесты должны быть независимы: каждый создаёт свои данные или использует уникальные имена.
- `retries` в CI скрывает нестабильность — смотрите отчёт о flaky-тестах, а не только итоговый статус.
- Для серверных компонентов Next.js и асинхронных Server Components e2e — основной способ проверки.
- Playwright также умеет компонентные тесты и визуальные сравнения скриншотов.

## Мини-шпаргалка

E2E = собранное приложение + настоящий браузер + сценарий пользователя. Покрываем критичные пути. Playwright: локаторы по роли, auto-waiting, `webServer`, trace на retry.
