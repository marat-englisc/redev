# Trace, отчёты и CI в Playwright

> [!NOTE]
> Trace связывает шаги теста, DOM, сеть и другие данные выполнения. При падении сначала определяют нарушенное ожидание и причину: продукт, тест, данные или окружение. Retry помогает собрать диагностику, но успешный повтор не отменяет нестабильность первого запуска.

## Вопрос

Тест упал только в CI. Что делать? Какие артефакты сохранять и когда увеличивать timeout?

## Конфигурация диагностики

```ts
import { defineConfig } from '@playwright/test';

export default defineConfig({
  testDir: './tests',
  forbidOnly: !!process.env.CI,
  retries: process.env.CI ? 1 : 0,
  reporter: [['list'], ['html', { open: 'never' }]],
  use: {
    trace: 'retain-on-failure',
    screenshot: 'only-on-failure',
    video: 'retain-on-failure',
  },
});
```

`retain-on-failure` сохраняет trace неуспешного запуска и полезен даже без retries. `on-first-retry` пишет trace первого повтора, поэтому без повтора записи может не оказаться.

```bash
npx playwright test tests/task.spec.ts --project=chromium --debug
npx playwright show-report
npx playwright show-trace test-results/<папка-теста>/trace.zip
```

`--project=chromium` используется, если проект с таким именем есть в конфигурации. Имя каталога trace берут из фактического отчёта.

## Алгоритм разбора

1. Прочитать assertion и сравнить ожидаемое с фактом.
2. Посмотреть шаг до падения и DOM в trace.
3. Проверить запросы, статусы, console и доступность стенда.
4. Проверить аккаунт, данные, время и конкурирующие тесты.
5. Повторить точный spec в той же конфигурации.
6. Исправить причину и убедиться, что проверка замечает реальную поломку.

Если сервер стабильно отвечает медленно, увеличение timeout может быть оправдано контрактом. Если тест ждёт неверный локатор, увеличение только откладывает падение. `waitForTimeout` и `force: true` тоже не устраняют причину.

## CI

После `npm ci` устанавливают нужные браузеры и системные зависимости, поднимают стенд, ждут readiness и запускают тесты. Сохраняют `playwright-report` и `test-results` даже при ошибке; команда теста должна вернуть неуспешный статус при провале.

Не используй `npm start` как универсальную команду: она должна существовать именно в этом учебном проекте. Лабораторная ниже задаёт явную команду Node.

## Что важно помнить

Trace и видео могут содержать данные страницы и заголовки запросов. Используй тестовые данные и контролируй доступ к артефактам.

## Мини-шпаргалка

Ошибка → trace → сеть/DOM/данные → классификация причины → исправление → повторная проверка.
