# Browser context, проекты и параллельность

> [!NOTE]
> Browser context изолирует cookies и браузерное состояние. Проект задаёт конфигурацию прогона, например браузер или роль. Workers выполняют тесты параллельно, но серверные данные не изолируются автоматически: каждому тесту нужны собственные ресурсы или согласованное разделение.

## Вопрос

Чем browser отличается от context и page? Почему тесты проходят по одному и падают при параллельном запуске?

## Основная идея

```text
browser
  context A: cookies пользователя A → page 1, page 2
  context B: cookies пользователя B → page 3
backend / БД: могут быть общими для всех contexts
```

Context похож на отдельный профиль. Несколько page внутри одного context разделяют его cookies. Стандартная `page`-фикстура Playwright Test даёт новому тесту новый context, но не очищает таблицы сервера.

## Пример проектов

```ts
import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  testDir: './tests',
  fullyParallel: true,
  workers: process.env.CI ? 2 : undefined,
  use: { baseURL: 'http://127.0.0.1:3007' },
  projects: [
    { name: 'chromium', use: { ...devices['Desktop Chrome'] } },
    { name: 'firefox', use: { ...devices['Desktop Firefox'] } },
    { name: 'webkit', use: { ...devices['Desktop Safari'] } },
  ],
});
```

Перед запуском установи нужные движки: `npx playwright install`. Один spec выполнится для каждого выбранного проекта. Конфигурация устройства эмулирует параметры браузера и экрана, но не заменяет проверку на физическом устройстве.

## Пример столкновения

Тест A ожидает одну задачу, тест B создаёт вторую под тем же аккаунтом, тест C удаляет «все задачи». Новый context никак не спасает. Решения: отдельные аккаунты/tenant, уникальные ID, проверки своего объекта вместо общего количества, уборка только собственных данных.

По умолчанию файлы могут выполняться параллельно, а тесты внутри файла идут последовательно. `fullyParallel` меняет это. Порядок файлов нельзя использовать как механизм подготовки.

## Что важно помнить

- `workers: 1` полезен для диагностики, но не исправляет зависимость тестов.
- Общий storageState не создаёт отдельных серверных аккаунтов.
- При разных ролях нужны разные состояния или явная авторизация.
- Serial-сценарий допустим для осознанного связанного workflow, но не как маскировка общих данных.

## Мини-шпаргалка

Browser запускает движок. Context изолирует браузерное состояние. Page — вкладка. Backend изолируем отдельно.
