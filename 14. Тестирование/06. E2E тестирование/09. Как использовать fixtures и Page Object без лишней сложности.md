# Fixtures и Page Object

> [!NOTE]
> Фикстура управляет ресурсом теста: готовит данные, передаёт их через `use` и очищает после выполнения. Page Object собирает локаторы и действия страницы в одном месте. Эти подходы уменьшают повторение, но не должны скрывать смысл проверки за универсальными обёртками.

## Вопрос

Чем fixture отличается от beforeEach? Когда нужен Page Object и где писать assertions?

## Фикстура ресурса

Для запущенного [QA Lab](<../15. Практика QA/01. Как запустить локальный учебный стенд QA.md>) создай `tests/fixtures.ts`:

```ts
import { randomUUID } from 'node:crypto';
import { test as base, expect } from '@playwright/test';

type Task = { id: string; title: string; done: boolean };

export const test = base.extend<{ task: Task }>({
  task: async ({ request }, use) => {
    const url = 'http://127.0.0.1:3007/tasks';
    const headers = { Authorization: 'Bearer qa-a' };
    const response = await request.post(url, {
      headers, data: { title: `QA ${randomUUID()}` },
    });
    expect(response.status()).toBe(201);
    const task: Task = await response.json();
    try {
      await use(task);
    } finally {
      const removed = await request.delete(`${url}/${task.id}`, { headers });
      expect([204, 404]).toContain(removed.status());
    }
  },
});
export { expect };
```

404 при уборке допускается здесь осознанно: тест мог сам удалить свою задачу. В проверке бизнес-операции ожидаемый статус обычно один.

## Page Object

`tests/tasks-page.ts`:

```ts
import type { Page } from '@playwright/test';

export class TasksPage {
  constructor(private readonly page: Page) {}

  async open() {
    await this.page.goto('http://127.0.0.1:3007');
  }

  row(id: string) {
    return this.page.getByTestId(`task-${id}`);
  }
}
```

`tests/task.spec.ts`:

```ts
import { test, expect } from './fixtures';
import { TasksPage } from './tasks-page';

test('подготовленная задача видна пользователю', async ({ page, task }) => {
  const tasks = new TasksPage(page);
  await tasks.open();
  await expect(tasks.row(task.id)).toContainText(task.title);
});
```

Фикстура подключается только тестам, которым нужна. BeforeEach удобен для простой общей операции, а fixtures дают явные зависимости и teardown ресурса.

## Что важно помнить

- Проверки бизнес-результата должны читаться в тесте; Page Object может проверять собственные обязательные условия готовности.
- Не нужно строить базовый класс со всеми возможными кнопками ради двух сценариев.
- Общий page или изменяемый объект между тестами нарушает изоляцию.

## Мини-шпаргалка

Fixture — жизненный цикл ресурса. Page Object — язык действий страницы. Test — сценарий и ожидаемое поведение.
