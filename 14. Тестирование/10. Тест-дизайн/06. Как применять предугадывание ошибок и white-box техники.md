# Предугадывание ошибок и структурное покрытие

> [!NOTE]
> Error guessing использует опыт и типичные причины дефектов, а white-box техники опираются на структуру кода. Покрытие операторов и ветвей показывает выполнение кода, но не доказывает корректность результата. Эти техники дополняют проверки по требованиям.

## Вопрос

Что такое error guessing? Чем покрытие операторов отличается от покрытия ветвей? Почему 100% coverage недостаточно?

## Основная идея

Предугадывание ошибок — не случайное угадывание. Источники идей: прежние дефекты, ограничения платформы, типичные ошибки разработчиков и особенности предметной области.

| Область | Гипотеза |
| --- | --- |
| Кнопка отправки | двойной клик создаёт две записи |
| Дата рождения | 29 февраля неверно обрабатывается в невисокосный год |
| Цена | дробные значения округляются до неверной суммы |
| Файл | расширение и содержимое не совпадают |
| Список | пустой результат ломает пагинацию |

Гипотезу превращают в конкретные данные, действия и ожидаемый результат. Подход полезен для исследования, но не обеспечивает систематическое покрытие сам по себе.

## Пример white-box

```js
function shipping(isVip) {
  let price = 300;
  if (isVip) {
    price = 0;
  }
  return price;
}
```

Вызов `shipping(true)` выполняет все исполняемые операторы функции: присваивание 300, условие, присваивание 0, возврат. Но исход `false` у `if` не проверен. Для покрытия обеих ветвей нужны `true` и `false`, с проверками результатов 0 и 300.

Для условия `a && b` покрытие ветвей всего `if` не означает проверку всех сочетаний `a` и `b`. Покрытие условий и MC/DC — отдельные, более глубокие критерии; для junior+ достаточно понимать это ограничение.

## Что важно помнить

- Выполнить строку и проверить её результат — разные действия.
- Тест `shipping(true)` без `assert` может давать coverage, но не заметить неверную цену.
- Недостижимые ветви исследуют, а не создают искусственные тесты ради процента.
- Ручному QA полезно читать простые условия и связывать их с таблицами решений.

## Мини-шпаргалка

Опыт даёт гипотезы. Структура даёт критерий выполнения. Требования и оракулы дают ожидаемый результат.
