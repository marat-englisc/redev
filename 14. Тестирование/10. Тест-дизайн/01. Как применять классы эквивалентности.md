# Классы эквивалентности

> [!NOTE]
> Разбиение на классы эквивалентности группирует данные, которые по модели должны обрабатываться одинаково. Из каждого класса выбирают представителей. Нужно учитывать допустимые и недопустимые классы, а предположение об одинаковом поведении проверять по требованиям и реализации.

## Вопрос

Как сократить количество проверок поля возраста? Почему одного корректного значения недостаточно?

## Основная идея

Пусть форма принимает целый возраст от 18 до 65 включительно. Проверять каждое число необязательно: для базового принятия значения их можно объединить в классы.

| Класс | Представитель | Ожидаемый результат |
| --- | --- | --- |
| Целое от 18 до 65 | 30 | значение принято |
| Целое меньше 18 | 10 | ошибка диапазона |
| Целое больше 65 | 80 | ошибка диапазона |
| Дробное число | 25.5 | ошибка формата |
| Нечисловая строка | `двадцать` | ошибка формата |
| Значение отсутствует | пустое поле | ошибка обязательности |

В API добавляются разные представления: ключ отсутствует, `null`, `""`, число `30` и строка `"30"`. Их эквивалентность нельзя предполагать: контракт может различать типы.

## Как рассуждать

1. Выделить параметры и ограничения.
2. Определить, по какому правилу данные обрабатываются одинаково.
3. Разбить пространство без случайных пробелов.
4. Выбрать представителей и ожидаемые результаты.
5. Отдельно проверить границы классов.

Если после 60 лет меняется тариф, диапазон 18–65 придётся разделить ещё: для принятия формы он один класс, для расчёта тарифа — несколько. Класс зависит от проверяемого свойства.

## Частая ошибка

Отправить одновременно неверные email, возраст и пароль и увидеть ошибку email. Это не подтверждает валидацию остальных полей. Для диагностики негативной проверки обычно изменяют один параметр, оставляя остальные корректными, затем добавляют отдельные проверки взаимодействий.

## Практика

Для количества товара 1–99 выдели классы `0`, отрицательные, допустимые целые, больше 99, дробные, строковые и отсутствующее значение. Уточни, разрешает ли UI временно пустое поле при редактировании и когда показывает ошибку.

## Мини-шпаргалка

Класс — обоснованно одинаковая обработка. Представитель — одна проверка класса. Границы и взаимодействия требуют дополнения.
