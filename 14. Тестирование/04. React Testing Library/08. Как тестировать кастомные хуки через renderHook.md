# Тестирование кастомных хуков: renderHook

> [!NOTE]
> `renderHook(() => useMyHook())` рендерит хук внутри тестового компонента и возвращает `result.current` с актуальным значением, а также `rerender` и `unmount`. Изменения состояния вызывают внутри `act`.

## Вопрос

Как протестировать кастомный хук отдельно от компонента? Когда это нужно, а когда лучше тестировать через компонент?

## Основная идея

Хук можно вызвать только внутри компонента, поэтому `renderHook` создаёт невидимый тестовый компонент, вызывает в нём хук и сохраняет результат в `result.current`. После каждого рендера значение обновляется. Важно читать `result.current` **после** действия, а не сохранять его в переменную заранее — иначе останется старый снимок.

Функции, меняющие состояние, вызывают внутри `act(() => ...)`. Без него React может не применить обновление до проверки. Для асинхронных хуков используют `waitFor`.

`rerender(newProps)` нужен для проверки реакции на смену аргументов, `unmount()` — для проверки cleanup: отписки, отмены запроса. Опция `wrapper` оборачивает хук в провайдеры: роутер, QueryClient, контекст.

Когда тестировать хук отдельно: он переиспользуется в нескольких местах, содержит нетривиальную логику (`useDebounce`, `usePagination`, `useLocalStorage`) или является публичным API библиотеки. Если хук используется в одном компоненте, обычно достаточно теста компонента.

`renderHook` экспортируется из `@testing-library/react`. Старый пакет `@testing-library/react-hooks` устарел.

## Пример

```ts
import { renderHook, act } from '@testing-library/react';
import { useCounter } from './useCounter';

it('увеличивает и сбрасывает значение', () => {
  const { result } = renderHook(() => useCounter(5));

  expect(result.current.count).toBe(5);

  act(() => result.current.increment());
  expect(result.current.count).toBe(6);

  act(() => result.current.reset());
  expect(result.current.count).toBe(5);
});
```

Смена аргументов и fake timers:

```ts
import { useDebouncedValue } from './useDebouncedValue';

it('обновляет значение после паузы', () => {
  vi.useFakeTimers();
  const { result, rerender } = renderHook(
    ({ value }) => useDebouncedValue(value, 300),
    { initialProps: { value: 'а' } },
  );

  rerender({ value: 'анна' });
  expect(result.current).toBe('а');

  act(() => vi.advanceTimersByTime(300));
  expect(result.current).toBe('анна');
  vi.useRealTimers();
});
```

Хук с контекстом:

```tsx
const wrapper = ({ children }: { children: React.ReactNode }) => (
  <ThemeProvider initialTheme="dark">{children}</ThemeProvider>
);

it('читает тему из контекста', () => {
  const { result } = renderHook(() => useTheme(), { wrapper });
  expect(result.current.theme).toBe('dark');
});
```

## Что важно помнить

- `const { count } = result.current` до `act` — частая ошибка: значение не обновится.
- Не тестируйте через `renderHook` то, что видно в компоненте, — тест компонента ближе к пользователю.
- Для асинхронного хука: `await waitFor(() => expect(result.current.data).toEqual(...))`.
- Ошибки, брошенные хуком при рендере, проверяют через `expect(() => renderHook(...)).toThrow()` и шпион на `console.error`.

## Мини-шпаргалка

`renderHook(() => useX(args), { initialProps, wrapper })` → `result.current`. Обновления → `act`. Асинхронность → `waitFor`. Новые аргументы → `rerender`, cleanup → `unmount`.
