# Приоритет запросов в Testing Library

> [!NOTE]
> Запросы выбирают по тому, как элемент находит пользователь: сначала `getByRole` с `name`, затем `getByLabelText`, `getByPlaceholderText`, `getByText`, `getByDisplayValue`, потом `getByAltText` и `getByTitle`, и только в крайнем случае — `getByTestId`.

## Вопрос

Какие запросы есть в Testing Library и в каком порядке их использовать? Когда допустим `data-testid`?

## Основная идея

Официальная документация делит запросы на три группы.

**1. Доступные всем** — то, что видит пользователь и слышит пользователь скринридера:

| Запрос | Когда использовать |
| --- | --- |
| `getByRole` | почти всегда: кнопки, ссылки, поля, заголовки, списки, диалоги |
| `getByLabelText` | поля формы, связанные с `<label>` |
| `getByPlaceholderText` | если label нет (placeholder его не заменяет) |
| `getByText` | неинтерактивный текст: абзацы, сообщения |
| `getByDisplayValue` | текущее значение заполненного поля |

**2. Семантические** — атрибуты, которые воспринимаются не всеми:

| Запрос | Когда использовать |
| --- | --- |
| `getByAltText` | изображения, `area`, `input type="image"` |
| `getByTitle` | атрибут `title`, `<title>` в SVG |

**3. Тестовые идентификаторы** — `getByTestId` по `data-testid`. Пользователь его не видит. Используют, когда нет ни роли, ни текста: например, у canvas-графика или динамического контейнера.

`getByRole` принимает опции: `name` (доступное имя — текст, `aria-label`, связанный label), `level` для заголовков, `checked`, `selected`, `expanded`, `pressed`, `hidden`. Неявные роли берутся из HTML: `<button>` → `button`, `<a href>` → `link`, `<input type="checkbox">` → `checkbox`, `<ul>` → `list`, `<h2>` → `heading`, `<nav>` → `navigation`.

## Пример

```tsx
// Хорошо
screen.getByRole('button', { name: 'Сохранить' });
screen.getByRole('heading', { name: 'Мои задачи', level: 1 });
screen.getByRole('checkbox', { name: 'Купить хлеб' });
screen.getByRole('textbox', { name: 'Email' });
screen.getByRole('link', { name: /профиль/i });
screen.getByLabelText('Пароль'); // input type="password" не имеет роли textbox

// Списки и таблицы
const rows = screen.getAllByRole('row');
expect(within(rows[1]).getByRole('cell', { name: 'Оплачен' })).toBeInTheDocument();

// Допустимо в крайнем случае
screen.getByTestId('sales-chart');

// Плохо
container.querySelector('.btn-primary');
screen.getByText('Сохранить').closest('button');
```

## Что важно помнить

- `getByRole` медленнее других запросов на больших DOM, но его ценность — проверка доступности — обычно важнее.
- Строка в `name` и `getByText` сравнивается целиком; для частичного совпадения используйте регулярное выражение `/текст/i`.
- `<input type="password">` не имеет ARIA-роли, поэтому для него — `getByLabelText`.
- Элементы со `display: none` или `aria-hidden` не находятся через `getByRole` по умолчанию.
- Пакет `eslint-plugin-testing-library` подсказывает лучшие запросы.

## Мини-шпаргалка

Role (+ name) → Label → Placeholder → Text → DisplayValue → AltText → Title → TestId. Если элемент не находится по роли — проблема, скорее всего, в разметке.
