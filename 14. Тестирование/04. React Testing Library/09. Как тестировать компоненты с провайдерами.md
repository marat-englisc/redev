# Компоненты с провайдерами: custom render

> [!NOTE]
> Компонентам, которые используют роутер, QueryClient, store или тему, нужны провайдеры и в тестах. Вместо повторения обёрток в каждом тесте создают функцию `renderWithProviders`, которая оборачивает компонент и принимает начальные данные: маршрут, состояние, пользователя.

## Вопрос

Как тестировать компонент, который использует `useNavigate`, `useQuery` или контекст авторизации?

## Основная идея

Без провайдера хук упадёт: `useNavigate() may be used only in the context of a <Router>`, `No QueryClient set`. Копировать пять уровней провайдеров в каждый тест неудобно, а изменение структуры провайдеров потребует правки сотен тестов.

Рекомендованный подход Testing Library — **custom render**: свой модуль `test-utils`, который реэкспортирует всё из `@testing-library/react` и заменяет `render` на версию с провайдерами. Тесты импортируют `render` из `@/test/utils`, а не из библиотеки.

Важные детали:

- **Свежий экземпляр на каждый тест**: новый `QueryClient`, новый store. Иначе кеш и состояние протекут между тестами.
- **Параметры для сценария**: начальный маршрут (`MemoryRouter initialEntries`), начальное состояние store, текущий пользователь.
- **Тестовые настройки**: для QueryClient — `retry: false`, иначе запрос с ошибкой будет повторяться и тест упрётся в таймаут.

Для роутинга удобно рендерить настоящие маршруты в `MemoryRouter`: тогда переход проверяется по появлению новой страницы, а не по вызову замоканного `navigate`.

## Пример

```tsx
// src/test/utils.tsx
import { render, type RenderOptions } from '@testing-library/react';
import { QueryClient, QueryClientProvider } from '@tanstack/react-query';
import { MemoryRouter } from 'react-router-dom';
import type { ReactElement, ReactNode } from 'react';
import { AuthContext, type User } from '@/features/auth';

type Options = Omit<RenderOptions, 'wrapper'> & {
  route?: string;
  user?: User | null;
};

export function renderWithProviders(ui: ReactElement, { route = '/', user = null, ...options }: Options = {}) {
  const queryClient = new QueryClient({
    defaultOptions: { queries: { retry: false }, mutations: { retry: false } },
  });

  function Wrapper({ children }: { children: ReactNode }) {
    return (
      <QueryClientProvider client={queryClient}>
        <AuthContext.Provider value={{ user }}>
          <MemoryRouter initialEntries={[route]}>{children}</MemoryRouter>
        </AuthContext.Provider>
      </QueryClientProvider>
    );
  }

  return { queryClient, ...render(ui, { wrapper: Wrapper, ...options }) };
}

export * from '@testing-library/react';
```

```tsx
// Header.test.tsx
import { renderWithProviders, screen } from '@/test/utils';
import { Routes, Route } from 'react-router-dom';

it('гость видит кнопку «Войти»', () => {
  renderWithProviders(<Header />);
  expect(screen.getByRole('link', { name: 'Войти' })).toBeInTheDocument();
});

it('после клика по профилю открывается страница профиля', async () => {
  const user = userEvent.setup();
  renderWithProviders(
    <Routes>
      <Route path="/" element={<Header />} />
      <Route path="/profile" element={<h1>Профиль</h1>} />
    </Routes>,
    { user: { id: '1', name: 'Анна' } },
  );

  await user.click(screen.getByRole('link', { name: 'Анна' }));

  expect(screen.getByRole('heading', { name: 'Профиль' })).toBeInTheDocument();
});
```

## Что важно помнить

- Провайдеры создаются внутри функции, а не на уровне модуля — иначе состояние общее для всех тестов.
- Возвращайте из `renderWithProviders` полезные объекты (`queryClient`, store), чтобы тест мог проверить кеш или состояние.
- Для Redux Toolkit custom render принимает `preloadedState` и создаёт store через `setupStore(preloadedState)`.
- Для Next.js App Router `useRouter` из `next/navigation` обычно мокают или проверяют навигацию в e2e.

## Мини-шпаргалка

Провайдеры → свой `renderWithProviders` в `test/utils`. Новый QueryClient и store на тест. `retry: false`. Маршрут через `MemoryRouter initialEntries`. Переход проверяем по новой странице.
