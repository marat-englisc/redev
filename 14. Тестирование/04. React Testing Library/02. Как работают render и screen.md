# render и screen

> [!NOTE]
> `render(<Component />)` монтирует компонент в DOM и возвращает утилиты, включая `rerender` и `unmount`. `screen` — объект со всеми запросами, привязанными к `document.body`. Рекомендуется искать элементы через `screen`, а не через деструктуризацию результата `render`.

## Вопрос

Что возвращает `render`? Зачем нужен `screen`? Как отладить, что сейчас отрендерено?

## Основная идея

`render` создаёт контейнер `div`, добавляет его в `document.body` и рендерит туда компонент через React. Результат содержит:

| Поле | Назначение |
| --- | --- |
| `rerender(ui)` | перерендерить с новыми props (тот же экземпляр) |
| `unmount()` | размонтировать — проверка cleanup эффектов |
| `container` | DOM-узел, куда смонтирован компонент |
| `baseElement` | корень для запросов, по умолчанию `document.body` |
| `getByRole` и др. | запросы, привязанные к `baseElement` |
| `asFragment()` | DocumentFragment, например для снапшота |

**`screen`** даёт те же запросы, но не требует хранить результат `render`. Код короче и единообразнее. Кроме того, `screen` ищет по всему `document.body`, поэтому находит содержимое порталов: модальные окна, тултипы и выпадающие меню, которые рендерятся вне контейнера.

`container.querySelector` — запасной выход. Он возвращает к поиску по классам и тегам, то есть к деталям реализации.

Для отладки:

- `screen.debug()` печатает текущий DOM;
- `screen.debug(element)` — конкретный узел;
- `screen.logTestingPlaygroundURL()` даёт ссылку на Testing Playground, который подсказывает лучший запрос;
- `logRoles(container)` выводит все доступные роли и имена.

## Пример

```tsx
import { render, screen } from '@testing-library/react';
import { PriceTag } from './PriceTag';

it('обновляет цену при смене props', () => {
  const { rerender } = render(<PriceTag value={1500} />);
  expect(screen.getByText('1 500 ₽')).toBeInTheDocument();

  rerender(<PriceTag value={990} />);
  expect(screen.getByText('990 ₽')).toBeInTheDocument();
});

it('отписывается от событий при размонтировании', () => {
  const removeSpy = vi.spyOn(window, 'removeEventListener');
  const { unmount } = render(<WindowSize />);

  unmount();

  expect(removeSpy).toHaveBeenCalledWith('resize', expect.any(Function));
});
```

Модальное окно через портал:

```tsx
it('открывает модалку', async () => {
  const user = userEvent.setup();
  render(<DeleteButton />);
  await user.click(screen.getByRole('button', { name: 'Удалить' }));

  // модалка в document.body, вне container — screen её находит
  expect(screen.getByRole('dialog', { name: 'Удалить задачу?' })).toBeInTheDocument();
});
```

## Что важно помнить

- Для компонентов, которым нужны провайдеры (роутер, store, QueryClient), создают свою функцию `renderWithProviders`.
- `render` синхронный; эффекты и обновления в нём уже обёрнуты в `act`.
- Не вызывайте `cleanup` вручную при включённых globals — RTL делает это сам.
- `within(element)` ограничивает поиск частью DOM: например, конкретной строкой таблицы.

## Мини-шпаргалка

`render` → монтирование + `rerender` / `unmount`. Запросы → `screen.*` (видит порталы). Часть DOM → `within`. Отладка → `screen.debug()`, `logRoles`.
