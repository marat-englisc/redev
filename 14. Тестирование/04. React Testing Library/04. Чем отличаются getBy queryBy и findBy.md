# getBy, queryBy и findBy

> [!NOTE]
> `getBy` синхронно находит элемент или бросает ошибку. `queryBy` возвращает `null`, если элемента нет, — для проверки отсутствия. `findBy` возвращает Promise и ждёт появления элемента — для асинхронного UI. Варианты `All` возвращают массивы.

## Вопрос

Чем отличаются `getBy`, `queryBy` и `findBy`? Когда использовать каждый?

## Основная идея

У каждого запроса (`ByRole`, `ByText`, `ByLabelText` и т. д.) есть шесть вариантов:

| Вариант | Нет элемента | 1 элемент | Больше 1 | Асинхронный |
| --- | --- | --- | --- | --- |
| `getBy` | ошибка | элемент | ошибка | нет |
| `queryBy` | `null` | элемент | ошибка | нет |
| `findBy` | reject (по таймауту) | элемент | reject | да |
| `getAllBy` | ошибка | массив | массив | нет |
| `queryAllBy` | `[]` | массив | массив | нет |
| `findAllBy` | reject | массив | массив | да |

**`getBy`** — выбор по умолчанию: если элемента нет, ошибка сразу покажет текущий DOM и подскажет, что не так.

**`queryBy`** — только для проверки **отсутствия**: `expect(screen.queryByText('Ошибка')).not.toBeInTheDocument()`. Если проверять отсутствие через `getBy`, тест упадёт на поиске, а не на проверке.

**`findBy`** = `getBy` + `waitFor`. Он повторяет запрос, пока элемент не появится или не истечёт таймаут (по умолчанию 1000 мс). Используется для данных после запроса, `Suspense`, `React.lazy` и всего, что появляется после асинхронной операции. Перед ним обязателен `await`.

## Пример

```tsx
it('загружает и показывает список задач', async () => {
  render(<TodoPage />);

  // сразу видим индикатор загрузки
  expect(screen.getByRole('status')).toHaveTextContent('Загрузка...');

  // ждём данные
  expect(await screen.findByText('Купить хлеб')).toBeInTheDocument();

  // индикатора больше нет
  expect(screen.queryByRole('status')).not.toBeInTheDocument();

  // все элементы
  expect(screen.getAllByRole('listitem')).toHaveLength(3);
});
```

Исчезновение элемента после асинхронной операции:

```tsx
import { waitForElementToBeRemoved } from '@testing-library/react';

await waitForElementToBeRemoved(() => screen.queryByText('Загрузка...'));
```

## Что важно помнить

- `findBy` без `await` — частая ошибка: тест завершится раньше, чем элемент появится.
- Не используйте `queryBy` для проверки присутствия — ошибка будет менее информативной.
- `findBy` вместо `waitFor(() => getBy...)` короче и выдаёт ту же ошибку.
- Таймаут можно передать третьим аргументом: `findByText('Готово', {}, { timeout: 3000 })`. Но долгое ожидание обычно означает, что сеть не замокана.
- `getBy` бросает ошибку и при нескольких совпадениях — уточните `name` или используйте `getAllBy`.

## Мини-шпаргалка

Есть сейчас → `getBy`. Не должно быть → `queryBy` + `not.toBeInTheDocument()`. Появится позже → `await findBy`. Несколько → `*AllBy`.
