# React Testing Library и её философия

> [!NOTE]
> React Testing Library (RTL) — набор утилит для тестирования React-компонентов через DOM так, как с ним работает пользователь: искать элементы по роли, тексту и label, кликать и вводить текст. Главный принцип: чем больше тест похож на использование софта, тем больше уверенности он даёт.

## Вопрос

Что такое React Testing Library? Чем её подход отличается от Enzyme?

## Основная идея

RTL не даёт доступа к state, props и экземплярам компонентов. Это сделано намеренно. Пользователь не знает, что внутри `useReducer`, — он видит кнопку «Оформить» и текст «Итого: 1 500 ₽». Если тест работает с тем же, что видит пользователь, его не нужно переписывать при рефакторинге.

**Enzyme** — прежний популярный инструмент. Он позволял поверхностно рендерить компонент (`shallow`), читать и менять state, вызывать методы экземпляра. Тесты получались связанными с реализацией. Enzyme не поддерживает современные версии React, поэтому в новых проектах используют RTL.

RTL состоит из нескольких пакетов:

| Пакет | Назначение |
| --- | --- |
| `@testing-library/dom` | запросы к DOM (`getByRole` и др.), `waitFor`, `fireEvent` |
| `@testing-library/react` | `render`, `renderHook`, `act`, автоматический `cleanup` |
| `@testing-library/user-event` | реалистичная симуляция действий пользователя |
| `@testing-library/jest-dom` | matchers для DOM: `toBeInTheDocument`, `toBeDisabled` |

Тот же подход есть для Vue, Angular, Svelte и даже Playwright (`getByRole`) — знания переносятся между инструментами.

Побочный эффект философии — **проверка доступности**. Запрос `getByRole('button', { name: 'Сохранить' })` не найдёт `div` с `onClick`. Если элемент нельзя найти по роли и имени, скринридер, скорее всего, тоже не сможет его понять.

## Пример

```tsx
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { Counter } from './Counter';

it('увеличивает счётчик по клику', async () => {
  const user = userEvent.setup();
  render(<Counter />);

  await user.click(screen.getByRole('button', { name: 'Добавить' }));

  expect(screen.getByText('Количество: 1')).toBeInTheDocument();
});
```

Тест не знает, как реализован `Counter`: через `useState`, `useReducer` или Zustand. Он проверяет только видимое поведение.

## Что важно помнить

- RTL — не runner: тесты запускает Vitest или Jest.
- `render` монтирует компонент в `document.body`; после теста `cleanup` размонтирует его автоматически (при глобальном `afterEach`).
- Shallow rendering в RTL отсутствует: дочерние компоненты рендерятся по-настоящему.
- Если элемент трудно найти по роли или тексту, сначала стоит улучшить разметку, а не добавлять `data-testid`.

## Мини-шпаргалка

RTL = тест через DOM глазами пользователя. Нет доступа к state и props. Ищем по роли и тексту, действуем через user-event, проверяем jest-dom. Enzyme — legacy.
