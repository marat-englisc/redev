# Мок fetch, даты и браузерных API

> [!NOTE]
> Глобальные API подменяют через `vi.stubGlobal` или `vi.spyOn`, а возвращают через `vi.unstubAllGlobals` и `mockRestore`. API, которых нет в jsdom (`matchMedia`, `IntersectionObserver`, `ResizeObserver`), заглушают в setup-файле.

## Вопрос

Как замокать `fetch`, `localStorage`, `window.matchMedia` или `IntersectionObserver` в тестах?

## Основная идея

Код часто обращается к глобальным объектам: `fetch`, `window.location`, `navigator.clipboard`, `localStorage`. Есть три случая.

1. **API есть в jsdom и работает** — `localStorage`, `sessionStorage`, `document.cookie`. Их обычно не мокают, а очищают между тестами.
2. **API есть, но нужно контролировать ответ** — `fetch`, `Date`, `Math.random`, `window.scrollTo`. Используют `vi.spyOn` или `vi.stubGlobal`.
3. **API отсутствует в jsdom** — `matchMedia`, `IntersectionObserver`, `ResizeObserver`, `HTMLElement.prototype.scrollIntoView`. Без заглушки компонент упадёт с `TypeError: ... is not a function`.

Для `fetch` мок через `vi.fn` подходит в простых unit-тестах. Для компонентов лучше MSW: он перехватывает запросы на сетевом уровне, и код приложения работает без изменений.

## Пример

```ts
// fetch через vi.stubGlobal
import { it, expect, vi, afterEach } from 'vitest';
import { loadProducts } from './api';

afterEach(() => vi.unstubAllGlobals());

it('возвращает товары из API', async () => {
  const fetchMock = vi.fn().mockResolvedValue(
    new Response(JSON.stringify([{ id: 1, title: 'Чайник' }]), { status: 200 }),
  );
  vi.stubGlobal('fetch', fetchMock);

  await expect(loadProducts()).resolves.toEqual([{ id: 1, title: 'Чайник' }]);
  expect(fetchMock).toHaveBeenCalledWith('/api/products', expect.anything());
});
```

```ts
// src/test/setup.ts — заглушки отсутствующих API
import { vi } from 'vitest';

Object.defineProperty(window, 'matchMedia', {
  writable: true,
  value: vi.fn().mockImplementation((query: string) => ({
    matches: false,
    media: query,
    onchange: null,
    addEventListener: vi.fn(),
    removeEventListener: vi.fn(),
    dispatchEvent: vi.fn(),
  })),
});

class IntersectionObserverMock {
  observe = vi.fn();
  unobserve = vi.fn();
  disconnect = vi.fn();
  takeRecords = vi.fn(() => []);
}
vi.stubGlobal('IntersectionObserver', IntersectionObserverMock);

Element.prototype.scrollIntoView = vi.fn();
```

```ts
// случайность и время
vi.spyOn(Math, 'random').mockReturnValue(0.5);
vi.useFakeTimers();
vi.setSystemTime(new Date('2026-01-01'));

// буфер обмена
const writeText = vi.fn().mockResolvedValue(undefined);
vi.stubGlobal('navigator', { ...navigator, clipboard: { writeText } });
```

## Что важно помнить

- Глобальные моки обязательно откатывать: `vi.unstubAllGlobals()`, `vi.restoreAllMocks()`, `vi.useRealTimers()`.
- Мок `IntersectionObserver` по умолчанию ничего не вызывает. Для проверки бесконечной ленты сохраните колбэк и вызовите его вручную.
- `window.location` в jsdom менять сложно — лучше передавать URL через роутер (`MemoryRouter`) или абстракцию.
- Если заглушек много, это сигнал перенести тест в браузерное окружение (Playwright, Vitest Browser Mode).

## Мини-шпаргалка

Глобальное → `vi.stubGlobal` / `vi.spyOn`, откат → `unstubAllGlobals` / `restoreAllMocks`. Нет в jsdom → заглушка в setup. Сеть для компонентов → MSW.
