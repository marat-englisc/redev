# Фейковые таймеры

> [!NOTE]
> Fake timers подменяют `setTimeout`, `setInterval`, `Date` и другие API времени управляемой реализацией. Тест сам «перематывает» время через `vi.advanceTimersByTime`, поэтому debounce, polling и таймауты проверяются мгновенно и детерминированно.

## Вопрос

Как протестировать debounce или уведомление, которое исчезает через 5 секунд, не ожидая 5 секунд?

## Основная идея

Реальное ожидание в тестах плохо по двум причинам: тесты становятся медленными, а результат зависит от загрузки машины. `vi.useFakeTimers()` заменяет таймеры: колбэки не выполняются сами, пока тест не продвинет виртуальное время.

| API | Что делает |
| --- | --- |
| `vi.useFakeTimers()` | включить фейковые таймеры |
| `vi.advanceTimersByTime(ms)` | продвинуть время на `ms` и выполнить наступившие таймеры |
| `vi.advanceTimersByTimeAsync(ms)` | то же, с ожиданием промисов между таймерами |
| `vi.runAllTimers()` | выполнить все таймеры (осторожно с `setInterval`) |
| `vi.runOnlyPendingTimers()` | выполнить только уже запланированные |
| `vi.setSystemTime(date)` | зафиксировать текущую дату (`Date.now`, `new Date()`) |
| `vi.useRealTimers()` | вернуть настоящие таймеры |

С **user-event** нужно связать его внутренние задержки с фейковым временем: `userEvent.setup({ advanceTimers: vi.advanceTimersByTime })`. Иначе `await user.type()` может зависнуть, ожидая таймер, который никто не продвигает.

Если обновление состояния React происходит в колбэке таймера, продвижение времени оборачивают в `act`, чтобы React применил обновления до проверки.

## Пример

```ts
import { it, expect, vi, beforeEach, afterEach } from 'vitest';
import { debounce } from './debounce';

beforeEach(() => vi.useFakeTimers());
afterEach(() => vi.useRealTimers());

it('вызывает функцию один раз после паузы', () => {
  const fn = vi.fn();
  const debounced = debounce(fn, 300);

  debounced('а');
  debounced('ан');
  debounced('анн');

  vi.advanceTimersByTime(299);
  expect(fn).not.toHaveBeenCalled();

  vi.advanceTimersByTime(1);
  expect(fn).toHaveBeenCalledTimes(1);
  expect(fn).toHaveBeenCalledWith('анн');
});

it('показывает дату заказа относительно «сегодня»', () => {
  vi.setSystemTime(new Date('2026-03-15T12:00:00Z'));
  expect(formatRelative(new Date('2026-03-14T12:00:00Z'))).toBe('вчера');
});
```

React-компонент с исчезающим уведомлением:

```tsx
import { act, render, screen } from '@testing-library/react';

it('скрывает уведомление через 5 секунд', () => {
  vi.useFakeTimers();
  render(<Toast message="Сохранено" />);
  expect(screen.getByText('Сохранено')).toBeInTheDocument();

  act(() => vi.advanceTimersByTime(5000));

  expect(screen.queryByText('Сохранено')).not.toBeInTheDocument();
});
```

## Что важно помнить

- Всегда возвращайте реальные таймеры в `afterEach`, иначе следующие тесты и библиотеки сломаются.
- `findBy*` и `waitFor` опираются на таймеры; с fake timers ожидание может не продвигаться — продвигайте время явно.
- `vi.runAllTimers` с бесконечным `setInterval` упрётся в лимит — используйте `advanceTimersByTime`.
- Фиксация `setSystemTime` спасает от тестов, падающих в полночь или 1 января.

## Мини-шпаргалка

`useFakeTimers` → `advanceTimersByTime(ms)` → проверка → `useRealTimers`. Дата → `setSystemTime`. user-event → `advanceTimers: vi.advanceTimersByTime`. React-обновление → `act`.
