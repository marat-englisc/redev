# Проверка REST API и контракта

> [!NOTE]
> API проверяют по контракту: метод, путь, типы, обязательность полей, статусы, ошибки, права и изменения данных. Успешный код ответа не подтверждает правильность бизнес-результата. Нужны чтение созданного ресурса, негативные проверки и проверка побочных эффектов.

## Вопрос

Как протестировать создание заказа через API? Что проверять кроме статуса 201?

## Основная идея

Контракт берут из OpenAPI, документации и согласованных требований. Swagger UI — один из способов просмотра и выполнения запросов, а не само определение корректного поведения.

## Матрица проверок

Пусть `POST /orders` принимает `productId` и целое `quantity` от 1 до 99.

| Категория | Данные / действие | Ожидание по учебному контракту |
| --- | --- | --- |
| Позитивная | существующий товар, quantity=2 | 201, ID, сумма, состояние new |
| Обязательность | нет quantity | 400, понятная ошибка, заказ не создан |
| Тип | quantity="2" или null | 400, если приведение типов не предусмотрено |
| Граница | 0/1/99/100 | 400/201/201/400 |
| Ресурс | неизвестный productId | 404 |
| Доступ | отсутствует токен | 401 |
| Авторизация | пользователь B читает заказ A | 403 или скрывающий 404 согласно контракту |

Эти статусы — выбранный контракт примера. Другой API может использовать 422 для валидации или иную структуру ошибки.

## Что проверить в ответе

Типы и значения полей, `Content-Type`, отсутствие лишних приватных данных, соответствие суммы правилу. Для созданного объекта — последующий GET и количество созданных записей. При ошибке — отсутствие частично выполненной операции.

JSON Schema помогает проверить структуру, но схема `total: number` не доказывает правильность расчёта. Даже строгая схема не заменяет проверку прав на объект и последовательности действий.

## Дополнительные риски junior+

Пагинация без повторов и пропусков на фиксированных данных, сортировка с одинаковыми значениями, фильтры с пустым результатом, повторы запросов, идемпотентность и изменение одного ресурса двумя клиентами. Для асинхронного API `202 Accepted` требует дальнейшей проверки статуса задачи.

## Мини-шпаргалка

Контракт → позитив → классы/границы → ошибки → доступ → сохранение → повтор и побочные эффекты.
