# Совместимость, доступность и производительность

> [!NOTE]
> Нефункциональные проверки оценивают свойства продукта: работу в целевых средах, доступность, удобство и скорость. Для них нужны конкретные условия и критерии. Мобильный viewport не заменяет реальное устройство, а один замер времени не является нагрузочным тестированием.

## Вопрос

Какие проверки нужны кроме функциональных? Как junior QA проверяет адаптивность, доступность и скорость?

## Практическая матрица

| Область | Пример проверки | Ограничение |
| --- | --- | --- |
| Браузеры | основной путь в согласованных Chromium/Firefox/WebKit | движок WebKit не равен всем версиям Safari |
| Адаптивность | 320/768/1280 px, длинные подписи, увеличение масштаба | viewport не моделирует все особенности телефона |
| Клавиатура | Tab, Shift+Tab, Enter, Escape, видимый фокус | не заменяет проверку со скринридером |
| Доступность | имена полей, сообщения об ошибках, контраст, порядок чтения | автоматический сканер видит только часть проблем |
| Локализация | длинные переводы, даты, числа, часовые пояса | перевод текста не гарантирует корректный формат |
| Скорость | задержки на фиксированной сети и данных | DevTools — диагностика, а не модель серверной нагрузки |

## Пример измеримого критерия

«При 50 одновременных активных пользователях и заданном профиле запросов p95 ответа поиска не более 800 мс, доля ошибок менее 1% в течение 15 минут после прогрева».

Нужно определить стенд, размер каталога, интенсивность запросов, длительность и правила измерения. **p95** означает, что 95% измеренных значений не превышают этот порог. Среднее может скрывать медленные ответы.

Load testing проверяет ожидаемую нагрузку; stress — поведение при превышении; spike — резкие всплески; endurance / soak — длительную работу. Для junior+ важно объяснить цель и не запускать тяжёлый профиль на общем стенде без согласованного плана.

## Практика

Пройди оформление заказа клавиатурой. Проверь, куда попадает фокус при открытии и закрытии диалога, можно ли прочитать ошибку и добраться до исправляемого поля. Запиши конкретное препятствие вместо «плохая доступность».

## Что важно помнить

- Производительность клиента и сервера связаны, но измеряются разными средствами.
- Lighthouse и axe дают сигналы для исследования, а не сертификат качества.
- Матрица целевых устройств определяется пользователями и требованиями.

## Мини-шпаргалка

Свойство → целевая среда → условия → измеримый критерий → проверка → границы вывода.
