# Аутентификация, сессии и права доступа

> [!NOTE]
> Аутентификация отвечает «кто пользователь», авторизация — «что ему разрешено». Скрытая кнопка не защищает ресурс: сервер должен проверять права при каждом обращении. Для проверки нужны как минимум разные роли и два пользователя с одинаковой ролью, но разными объектами.

## Вопрос

Как проверить, что пользователь не видит чужие заказы? Что тестировать у входа и выхода из системы?

## Матрица прав

| Действие | Гость | Владелец A | Другой пользователь B | Администратор |
| --- | --- | --- | --- | --- |
| Прочитать заказ A | нет | да | нет | по требованиям |
| Отменить новый заказ A | нет | да | нет | по требованиям |
| Изменить роль пользователя | нет | нет | нет | только при явно выданном праве |

Проверяем каждый значимый запрет через прямой API-запрос, даже если UI не показывает действие. Замена ID своего заказа на чужой выявляет нарушения объектного доступа. Передача `role: "admin"` проверяет, не принимает ли сервер запрещённые поля.

## Сессии

Проверки: успешный и неуспешный вход, истёкший токен, выход, повторное использование отозванной сессии по контракту, доступ после смены пароля, несколько устройств. Нужно уточнить политику: stateless access token может жить до истечения, если система не поддерживает немедленный отзыв.

Cookies имеют параметры `HttpOnly`, `Secure`, `SameSite`, область Domain/Path. Их наличие и значения оценивают по модели приложения. `HttpOnly` ограничивает доступ из JS, но сам по себе не предотвращает CSRF.

## Пример проверки

1. Пользователь A создаёт заказ и получает ID.
2. Пользователь B отправляет GET этого ID своим токеном.
3. Ожидаем отказ по контракту и отсутствие данных A в теле.
4. Повторяем для изменения и удаления.
5. Пользователь A читает заказ: он существует и не изменился.

## Что важно помнить

- CORS ограничивает чтение ответа браузерным JS, но не заменяет серверную авторизацию.
- JWT — формат токена; декодированное содержимое без проверки подписи не является доверенным.
- Проверки SQL injection, XSS и CSRF требуют понимания контекста; простая отправка одной строки не доказывает безопасность.
- Практику выполняют на разрешённом учебном или тестовом окружении.

## Мини-шпаргалка

Кто вошёл → какая роль → чей объект → какое действие → проверка сервера → отсутствие утечки и изменений.
