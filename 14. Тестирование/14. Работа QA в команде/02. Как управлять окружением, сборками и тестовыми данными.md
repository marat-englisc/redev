# Окружения, сборки и тестовые данные

> [!NOTE]
> Воспроизводимая проверка требует известной версии продукта, конфигурации, зависимостей и данных. Тестовый аккаунт сам по себе не создаёт изоляцию. Данные нужно готовить повторяемо, разделять между тестами и убирать без удаления чужих ресурсов.

## Вопрос

Почему баг не повторяется у разработчика? Чем staging отличается от production и что фиксировать перед проверкой?

## Карточка окружения

```text
Frontend: 1.8.1, commit abc1234
Backend: 1.8.1, commit def5678
БД: схема migration-42, тестовый набор catalog-v3
Флаги: new_discount=true
Зависимости: payment=sandbox, delivery=stub
Клиент: ОС, браузер и версия
Дата и время: с часовым поясом
```

Staging обычно стремится быть близким к production, но не обязательно совпадает по данным, мощности и интеграциям. Разница должна быть известна: stub доставки не подтверждает поведение реального сервиса.

## Подготовка данных

| Способ | Плюсы | Ограничения |
| --- | --- | --- |
| Через UI | близко к действиям пользователя | медленно, зависит от других функций |
| Через API | быстро, соблюдает бизнес-правила API | нужен контракт и доступ |
| Seed / fixture | повторяемое начальное состояние | может устареть после миграции |
| Прямой SQL | точная диагностика | запись может обойти правила, события и кеш |

Для тестов прав нужны два владельца и объекты каждого. Для границ — известные цены и количества. Для дат — фиксированная точка отсчёта или управляемые часы. Случайное значение без записи усложняет воспроизведение.

## Пример конфликта

Два теста создают «Заказ 1» в общем аккаунте, затем один удаляет все заказы. Правильнее хранить ID собственных объектов и удалять только их. Если нужны общие фиксированные данные, их делают неизменяемыми либо выделяют отдельный стенд на прогон.

## Что важно помнить

- Очистка браузера не сбрасывает серверную БД.
- Reload не гарантирует очистку HTTP-кеша, service worker и localStorage.
- Обезличенные синтетические данные предпочтительнее копирования реальных данных пользователей.
- Версии клиента и сервера могут развернуться не одновременно.

## Мини-шпаргалка

Версия + конфигурация + зависимости + данные + клиент + время = контекст воспроизведения.
