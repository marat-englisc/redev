# Тестирование типов TypeScript

> [!NOTE]
> Типы — тоже код, особенно в утилитах, дженериках и публичных API библиотек. Их проверяют компиляцией (`tsc --noEmit`), директивой `// @ts-expect-error` для заведомо неверного кода и утверждениями `expectTypeOf` / `assertType` в Vitest.

## Вопрос

Нужно ли тестировать типы? Как проверить, что дженерик выводит правильный тип, а неправильный вызов не компилируется?

## Основная идея

Обычные тесты выполняются в runtime, где типов уже нет. Если utility type `DeepPartial<T>` сломался и стал `any`, все тесты пройдут, а автодополнение и защита от ошибок исчезнут. Типы стоит тестировать, когда они сложные: дженерики, conditional и mapped types, перегрузки, типизированные хуки и API-клиенты.

Способы:

1. **`tsc --noEmit` в CI** — базовая проверка всего проекта. Vitest и esbuild при запуске тестов **не проверяют типы**, они только удаляют их. Поэтому отдельный шаг `typecheck` обязателен.
2. **`// @ts-expect-error`** — строка ниже обязана содержать ошибку типа. Если ошибка исчезла (тип стал слишком широким), компилятор сообщит, что директива не нужна. Так проверяют, что неверный вызов запрещён.
3. **`expectTypeOf`** в Vitest — читаемые утверждения о типах: `toEqualTypeOf`, `toMatchTypeOf`, `parameter(0)`, `returns`. Файлы `*.test-d.ts` проверяются командой `vitest --typecheck`.

## Пример

```ts
// utils.ts
export function pick<T extends object, K extends keyof T>(obj: T, keys: K[]): Pick<T, K> {
  const result = {} as Pick<T, K>;
  for (const key of keys) result[key] = obj[key];
  return result;
}
```

```ts
// utils.test-d.ts
import { expectTypeOf, test } from 'vitest';
import { pick } from './utils';

const user = { id: 1, name: 'Анна', email: 'anna@example.com' };

test('pick возвращает только выбранные ключи', () => {
  expectTypeOf(pick(user, ['id', 'name'])).toEqualTypeOf<{ id: number; name: string }>();
});

test('pick не принимает несуществующий ключ', () => {
  // @ts-expect-error — ключа 'age' нет в объекте
  pick(user, ['age']);
});

test('параметры хука', () => {
  expectTypeOf(pick).parameter(0).toMatchTypeOf<object>();
});
```

```json
{
  "scripts": {
    "typecheck": "tsc --noEmit",
    "test:types": "vitest --typecheck.only"
  }
}
```

## Что важно помнить

- Проверка типов не заменяет runtime-валидацию данных с сервера: для этого Zod, Valibot и аналоги.
- `@ts-expect-error` лучше `@ts-ignore`: последний молча скрывает ошибки и не сообщит, когда они исчезнут.
- `toEqualTypeOf` — точное равенство типов, `toMatchTypeOf` — совместимость (подтип).
- Для библиотек вне Vitest популярны `tsd` и `expect-type`.
- Тесты типов имеют смысл для сложных типов; для `type User = {...}` они не нужны.

## Мини-шпаргалка

Vitest не проверяет типы → `tsc --noEmit` в CI. Запрещённый код → `@ts-expect-error`. Ожидаемый тип → `expectTypeOf(x).toEqualTypeOf<T>()` в `*.test-d.ts`.
