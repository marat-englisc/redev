# Snapshot-тесты

> [!NOTE]
> Snapshot-тест сохраняет сериализованный результат (HTML, объект) в файл и при следующих запусках сравнивает с ним. Он ловит любые изменения, но не знает, правильны ли они, поэтому большие снапшоты быстро превращаются в шум.

## Вопрос

Что такое snapshot-тестирование? Когда оно полезно, а когда вредно?

## Основная идея

При первом запуске `toMatchSnapshot()` записывает значение в файл `__snapshots__/*.snap`. При следующих запусках новое значение сравнивается с сохранённым. Если они отличаются, тест падает и показывает diff. Если изменение ожидаемое, снапшот обновляют командой `vitest -u`.

Проблема в том, что снапшот проверяет **неизменность**, а не **корректность**. Снапшот целой страницы на 300 строк меняется при любой правке вёрстки. Разработчики привыкают нажимать `-u`, не читая diff, и тест перестаёт защищать. Кроме того, снапшот DOM — это детали реализации: классы и обёртки.

Снапшоты полезны, когда результат небольшой, стабильный и его трудно описать вручную: сериализованная ошибка, сгенерированный конфиг, результат форматирования, ответ трансформации данных. **Inline-снапшоты** (`toMatchInlineSnapshot`) хранят значение прямо в тесте — их легче ревьюить.

## Пример

```ts
import { it, expect } from 'vitest';
import { buildQuery } from './buildQuery';

it('строит строку запроса из фильтров', () => {
  expect(buildQuery({ page: 2, sort: 'price', tags: ['new', 'sale'] }))
    .toMatchInlineSnapshot(`"page=2&sort=price&tags=new&tags=sale"`);
});
```

При первом запуске Vitest сам допишет значение в аргумент. Дальше изменение формата будет видно прямо в diff PR.

Пример, которого лучше избегать:

```tsx
it('рендерится', () => {
  const { container } = render(<CheckoutPage />);
  expect(container).toMatchSnapshot(); // сотни строк, никто не читает diff
});
```

Лучше проверить конкретное поведение: заголовок, сумму, доступность кнопки «Оплатить».

## Что важно помнить

- Снапшоты коммитят в репозиторий и ревьюят как код.
- Нестабильные данные (даты, случайные id) ломают снапшоты — фиксируйте их или используйте property matchers.
- `toMatchFileSnapshot` сохраняет результат в отдельный файл с нужным расширением.
- Визуальные скриншотные тесты (Playwright `toHaveScreenshot`) — другой инструмент: сравнивают пиксели, а не DOM.

## Мини-шпаргалка

Snapshot = «не изменилось», а не «правильно». Маленький и стабильный — можно, inline — лучше. Снапшот целой страницы — антипаттерн. Обновление: `vitest -u`.
