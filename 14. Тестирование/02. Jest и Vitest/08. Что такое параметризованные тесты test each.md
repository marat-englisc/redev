# Параметризованные тесты: test.each

> [!NOTE]
> `test.each` запускает один и тот же тест на наборе входных данных. Это убирает копипаст, делает таблицу случаев наглядной и упрощает добавление граничных значений.

## Вопрос

Как протестировать функцию на множестве входов без копирования тестов?

## Основная идея

Валидаторы, форматтеры и парсеры обычно проверяют на многих значениях: пустая строка, пробелы, кириллица, очень длинный ввод. Копировать `it` десять раз неудобно, а цикл `for` внутри одного теста плох тем, что при падении непонятно, какой случай сломался, и остальные случаи не выполнятся.

`test.each(table)(name, fn)` создаёт **отдельный тест для каждой строки**. В названии можно подставлять значения: `%s`, `%i`, `%o` для массивов, `$name` для объектов. Каждый случай виден в отчёте отдельно.

Есть ещё `describe.each` — повторяет целую группу тестов для каждого набора, например для разных ролей пользователя. В Vitest также доступен `test.for`: аналог с другим порядком аргументов и поддержкой контекста теста.

## Пример

Массивы:

```ts
import { describe, it, expect } from 'vitest';
import { isValidEmail } from './validation';

describe('isValidEmail', () => {
  it.each([
    ['anna@example.com', true],
    ['anna.petrova+shop@mail.ru', true],
    ['', false],
    ['anna@', false],
    ['@example.com', false],
    ['anna example@mail.ru', false],
  ])('%s → %s', (email, expected) => {
    expect(isValidEmail(email)).toBe(expected);
  });
});
```

Объекты читаются лучше, когда параметров больше двух:

```ts
it.each([
  { price: 1000, discount: 10, expected: 900 },
  { price: 1000, discount: 0, expected: 1000 },
  { price: 100, discount: 150, expected: 0 },
])('цена $price со скидкой $discount% = $expected', ({ price, discount, expected }) => {
  expect(applyDiscount(price, discount)).toBe(expected);
});
```

Для разных ролей:

```ts
describe.each(['admin', 'editor'] as const)('роль %s', (role) => {
  it('видит кнопку «Редактировать»', () => {
    render(<Article role={role} />);
    expect(screen.getByRole('button', { name: 'Редактировать' })).toBeInTheDocument();
  });
});
```

## Что важно помнить

- Не превращайте `each` в таблицу на 50 строк с разной логикой — тогда лучше отдельные тесты.
- Ожидаемый результат пишите явно в таблице, а не вычисляйте.
- Граничные значения: `0`, `-1`, пустая строка, `null`, максимальная длина, Unicode.
- Для генерации случайных входов есть property-based тестирование (`fast-check`).

## Мини-шпаргалка

`it.each(table)('название %s', fn)` → отдельный тест на строку. Объекты + `$field` для читаемости. `describe.each` — повтор группы.
