# beforeEach, afterEach и изоляция тестов

> [!NOTE]
> Хуки `beforeAll`, `beforeEach`, `afterEach`, `afterAll` выполняют общую подготовку и очистку. Их главная задача — изоляция: каждый тест начинается с чистого состояния и не зависит от порядка запуска.

## Вопрос

Для чего нужны хуки жизненного цикла тестов? Как добиться, чтобы тесты не влияли друг на друга?

## Основная идея

| Хук | Когда выполняется | Типичное применение |
| --- | --- | --- |
| `beforeAll` | один раз перед всеми тестами блока | запуск MSW-сервера, подключение к тестовой БД |
| `beforeEach` | перед каждым тестом | сброс store, создание свежих данных |
| `afterEach` | после каждого теста | сброс моков и обработчиков, возврат реальных таймеров |
| `afterAll` | один раз после всех | остановка сервера, закрытие соединений |

Хуки, объявленные внутри `describe`, действуют только на тесты этого блока. Хуки на верхнем уровне файла — на весь файл. Хуки в setup-файле — на все файлы.

**Изоляция** означает, что тест не наследует состояние предыдущего. Типичные источники утечек: модульные переменные и синглтоны (store Zustand, кеш QueryClient), моки, которые не сбросили, включённые fake timers, изменённые `localStorage` и `document.body`, переопределённые обработчики MSW. Тест, который проходит в одиночку и падает в общем прогоне (или наоборот), почти всегда страдает от утечки состояния.

Vitest запускает каждый тестовый файл в отдельном изолированном контексте, поэтому модульное состояние не протекает **между файлами**. Внутри одного файла за изоляцию отвечает разработчик.

## Пример

```ts
import { beforeAll, afterAll, afterEach, beforeEach, describe, it, expect, vi } from 'vitest';
import { server } from '@/test/server';
import { useCartStore } from './cartStore';

const initialState = useCartStore.getState();

beforeAll(() => server.listen({ onUnhandledRequest: 'error' }));
afterEach(() => {
  server.resetHandlers();
  vi.useRealTimers();
  localStorage.clear();
});
afterAll(() => server.close());

describe('корзина', () => {
  beforeEach(() => {
    useCartStore.setState(initialState, true);
  });

  it('добавляет товар', () => {
    useCartStore.getState().add({ id: '1', price: 100 });
    expect(useCartStore.getState().items).toHaveLength(1);
  });

  it('начинается с пустой корзины', () => {
    expect(useCartStore.getState().items).toHaveLength(0);
  });
});
```

Без `beforeEach` второй тест зависел бы от того, выполнился ли первый.

## Что важно помнить

- Сброс моков удобнее включить глобально: `restoreMocks`, `clearMocks` или `mockReset` в конфиге.
- Не злоупотребляйте `beforeEach`: если подготовка нужна одному тесту, держите её в тесте. Читатель не должен прыгать по файлу.
- Фабрика данных (`createUser({ ...overrides })`) часто читается лучше общих мутируемых переменных.
- Хуки могут быть асинхронными — runner дождётся Promise.
- Для проверки изоляции полезно запускать тесты в случайном порядке: `sequence.shuffle` в Vitest.

## Мини-шпаргалка

`beforeAll/afterAll` — дорогие ресурсы. `beforeEach/afterEach` — сброс состояния. Синглтоны, моки, таймеры, storage — главные источники утечек.
