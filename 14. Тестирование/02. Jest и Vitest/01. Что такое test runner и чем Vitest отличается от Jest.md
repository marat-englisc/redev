# Test runner: Vitest и Jest

> [!NOTE]
> Test runner находит тестовые файлы, запускает их, предоставляет `expect`, моки и отчёт. Jest — классический runner для JS. Vitest — современный runner на базе Vite с почти таким же API, нативной поддержкой ESM и TypeScript и быстрым watch-режимом.

## Вопрос

Что такое test runner? Чем Vitest отличается от Jest и что выбрать в новом проекте?

## Основная идея

Test runner объединяет несколько задач: поиск файлов `*.test.ts` и `*.spec.ts`, запуск в нужном окружении (Node или jsdom), изоляцию файлов друг от друга, библиотеку проверок `expect`, моки, таймеры, покрытие и вывод результата. Сюда же относится watch-режим, который перезапускает только затронутые тесты.

**Jest** (изначально от Facebook) долгое время был стандартом: всё в одном пакете, большое сообщество, интеграция с Create React App и Next.js (`next/jest`). Его слабое место — сборка: TypeScript, JSX и ESM требуют трансформации через Babel или `ts-jest`, а поддержка ESM исторически была экспериментальной.

**Vitest** использует конфигурацию и плагины Vite. Если проект уже на Vite, тесты обрабатывают код теми же алиасами и трансформациями, что и dev-сервер. TypeScript, JSX и ESM работают без дополнительной настройки. API специально сделан совместимым с Jest: `describe`, `it`, `expect`, моки (`vi.fn` вместо `jest.fn`). Поэтому миграция часто сводится к замене импортов.

## Сравнение

| Критерий | Jest | Vitest |
| --- | --- | --- |
| Основа | собственный трансформер, Babel | Vite (esbuild/Rollup-плагины) |
| TypeScript, JSX, ESM | через Babel / ts-jest | из коробки |
| API | `jest.fn`, `jest.mock` | `vi.fn`, `vi.mock`, совместимый `expect` |
| Глобальные `describe/it` | по умолчанию | опция `globals: true` |
| Watch-режим | есть | очень быстрый, по графу модулей |
| Тесты в браузере | нет (jsdom) | есть Browser Mode |
| Тестирование типов | нет | `expectTypeOf`, `--typecheck` |
| Экосистема | огромная, много legacy | быстро растёт |

## Пример

Один и тот же тест в обоих runner-ах:

```ts
// Jest: describe/it/expect/jest — глобальные
const fetchUser = jest.fn().mockResolvedValue({ name: 'Анна' });

// Vitest: импорт явный (или globals: true)
import { describe, it, expect, vi } from 'vitest';
const fetchUserV = vi.fn().mockResolvedValue({ name: 'Анна' });
```

```json
{
  "scripts": {
    "test": "vitest",
    "test:run": "vitest run"
  }
}
```

`vitest` запускает watch-режим локально, `vitest run` — однократный прогон для CI.

## Что важно помнить

- Новый проект на Vite → Vitest. Существующий проект на Jest без проблем — переезд не обязателен.
- Testing Library, jest-dom, MSW работают с обоими.
- Ни Jest, ни Vitest не являются браузером: по умолчанию DOM эмулирует jsdom или happy-dom.
- Для e2e используют отдельные инструменты: Playwright или Cypress.

## Мини-шпаргалка

Runner = поиск + запуск + `expect` + моки + отчёт. Vitest = Jest-совместимый API + Vite + ESM/TS из коробки. `vi.*` ≈ `jest.*`.
