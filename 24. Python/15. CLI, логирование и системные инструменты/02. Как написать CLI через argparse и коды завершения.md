# Как написать CLI через argparse и коды завершения

> [!NOTE]
> Argparse разбирает позиционные аргументы и опции, формирует help и сообщает об ошибках использования. CLI должен разделять stdout с результатом и stderr с диагностикой, возвращать понятный exit code и не смешивать I/O с расчётами. Ноль обычно означает успех; ненулевой код — исход по контракту программы.

## Вопрос

Как сделать скрипт с --help, типизированным аргументом и проверкой диапазона?

## Пример entry point

Сохрани как `repeat.py`:

```python
import argparse

def main(argv=None):
    parser = argparse.ArgumentParser(description="Repeat a message")
    parser.add_argument("message")
    parser.add_argument("--count", type=int, default=1)
    args = parser.parse_args(argv)
    if args.count < 1:
        parser.error("--count must be positive")
    for _ in range(args.count):
        print(args.message)
    return 0

if __name__ == "__main__":
    raise SystemExit(main())
```

```bash
python repeat.py "hello world" --count 2
python repeat.py --help
```

Кавычки в shell сохраняют message одним аргументом. Argparse проверяет преобразование int, а диапазон мы проверили отдельно. По умолчанию ошибка использования завершается кодом 2.

## Тестируемый main

Параметр argv позволяет вызвать `main(["hello", "--count", "2"])` без замены глобального sys.argv. Расчёты лучше выносить в функции, не зависящие от parser и print.

## Значения-флаги

Для bool-опции применяют действия вроде `store_true`, а не `type=bool`: строка "False" при bool-преобразовании истинна. Для набора допустимых значений можно использовать choices.

## Что важно помнить

- Ошибка ввода пользователя отличается от неожиданного бага программы.
- Не передавай токен флагом CLI, если доступен более подходящий механизм: args могут быть видны другим процессам и истории.
- Прогресс и логи отправляй в stderr, если stdout предназначен машине.

## Практика

Проверь count 0, неверную строку и отсутствие message. Зафиксируй exit codes и убедись, что help не считается аварией.
