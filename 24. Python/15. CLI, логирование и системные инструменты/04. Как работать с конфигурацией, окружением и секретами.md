# Как работать с конфигурацией, окружением и секретами

> [!NOTE]
> Настройки приходят из файлов, окружения и CLI по явно выбранному приоритету. Значения os.environ — строки; их нужно преобразовывать и валидировать один раз на границе. Секреты не хранят в исходниках и не печатают в логах. Модуль secrets подходит для криптографически значимых случайных токенов, random — для обычных симуляций и незащищённых случайных выборок.

## Вопрос

Как прочитать целый параметр из окружения и почему `bool(os.getenv(...))` может быть ошибкой?

## Разбор конфигурации

```python
import os

def read_limit(environment):
    raw = environment.get("APP_LIMIT", "100")
    try:
        limit = int(raw)
    except ValueError as error:
        raise ValueError("APP_LIMIT must be an integer") from error
    if limit <= 0:
        raise ValueError("APP_LIMIT must be positive")
    return limit

print(read_limit({}))  # 100
print(read_limit({"APP_LIMIT": "5"}))  # 5
```

Передача mapping делает функцию легко тестируемой без изменения реального окружения. В приложении можно передать os.environ.

## Булевы настройки

Строки `"0"` и `"false"` непустые, поэтому bool для них True. Определи допустимые значения явно, например true/false после strip/casefold, а неизвестные отклоняй. Не угадывай молча.

## Файл настроек

Tomllib читает TOML из стандартной библиотеки Python 3.11+. Он парсит структуру, но не валидирует схему приложения. Для .env нужна библиотека или собственный loader: Python не подхватывает его автоматически.

## Токены

```python
import secrets

token = secrets.token_urlsafe(32)
print(bool(token))  # True; сам токен в лог не выводим
```

Для сравнения некоторых секретных значений используют secrets.compare_digest. Хранение пользовательских паролей требует специализированного password hashing, а не простого SHA-256.

## Практика

Спроектируй приоритет defaults → TOML → env → CLI. Проверь отсутствие значения, пустую строку и ошибочный тип. Убедись, что сообщение об ошибке не содержит секрет.
