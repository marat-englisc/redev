# Как запускать внешние команды через subprocess

> [!NOTE]
> Subprocess.run запускает внешнюю программу и возвращает результат. Обычно передают список аргументов без shell=True, задают timeout и check=True, если ненулевой код должен быть ошибкой. Список сохраняет границы аргументов, но не отменяет опасные опции самой программы. Большой stdout нельзя бездумно целиком накапливать через capture_output.

## Вопрос

Как вызвать внешнюю команду без shell-инъекции и обработать неуспешный код?

## Воспроизводимый пример

```python
import subprocess
import sys

result = subprocess.run(
    [sys.executable, "-c", "print('hello from child')"],
    check=True,
    capture_output=True,
    text=True,
    encoding="utf-8",
    timeout=5,
)
print(result.stdout.strip())  # hello from child
print(result.returncode)  # 0
```

Используется текущий Python, поэтому пример не зависит от наличия системной утилиты ls. `text=True` включает текстовое представление потоков; без него получим bytes.

## Ошибки

- FileNotFoundError: не удалось найти исполняемый файл.
- CalledProcessError: процесс завершился неуспешно при check=True.
- TimeoutExpired: превышен timeout.

Запуск программы и успешный результат её задачи — разные этапы. Выбранные return codes нужно интерпретировать по её документации.

## Почему не строка shell

`subprocess.run("tool " + user_input, shell=True)` позволяет shell трактовать специальные символы ввода. Для обычного запуска передавай `["tool", user_input]`. При этом сама tool всё ещё может считать значение опцией или выполнить другой опасный смысл; используйте `--`, если поддерживается, и проверку аргументов.

## Окружение и cwd

Задавай cwd и env, если важна воспроизводимость. Переданный env обычно задаёт окружение процесса, а не просто автоматически дополняет текущее: при необходимости объедини с os.environ. Не логируй весь env, там могут быть секреты.

## Практика

Запусти дочерний Python с `raise SystemExit(3)` и обработай CalledProcessError. Проверь сохранение аргумента с пробелом без shell=True.
