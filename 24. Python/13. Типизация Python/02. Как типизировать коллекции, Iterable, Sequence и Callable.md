# Как типизировать коллекции, Iterable, Sequence и Callable

> [!NOTE]
> Аннотация должна обещать ровно нужные возможности. Iterable достаточно для одного обхода, Sequence даёт длину и индексацию, Mapping — чтение по ключу. List нужен, если требуется именно изменяемый список. Callable описывает вызываемый объект. Контейнерные аннотации не проверяют элементы автоматически во время исполнения.

## Вопрос

Почему параметр Iterable[str] иногда лучше list[str]? Чем tuple[int, str] отличается от tuple[int, ...]?

## Общий вход

```python
from collections.abc import Iterable, Mapping, Sequence

def total_length(values: Iterable[str]) -> int:
    return sum(len(value) for value in values)

def first_or_none(values: Sequence[str]) -> str | None:
    return values[0] if values else None

def read_limit(settings: Mapping[str, int]) -> int:
    return settings.get("limit", 10)

print(total_length(name for name in ["Anna", "Ivan"]))  # 8
print(first_or_none(("Anna", "Ivan")))  # Anna
print(read_limit({}))  # 10
```

Iterable не гарантирует повторяемость. Если сделать два прохода, generator может быть уже исчерпан. Sequence выражает более сильный контракт, поэтому не следует выбирать его без необходимости.

## Tuple и функция

```python
from collections.abc import Callable

def apply(value: int, transform: Callable[[int], str]) -> str:
    return transform(value)

print(apply(5, str))  # 5 как строка

point: tuple[int, int] = (1, 2)
numbers: tuple[int, ...] = (1, 2, 3)
```

Первый tuple имеет фиксированную длину и позиции, второй — произвольную длину с одним типом элементов. `tuple[()]` описывает пустой tuple.

## Изменяемость и совместимость

List обычно инвариантен: `list[Dog]` нельзя безопасно использовать как `list[Animal]`, если получатель может добавить туда Cat. Read-only-контракты вроде Sequence могут поддерживать более гибкую совместимость типов. Это ограничение связано с возможными операциями, а не с капризом анализатора.
