# Как работают type hints, Any, object, Union и None

> [!NOTE]
> Type hints описывают контракт для IDE и статического анализатора, например mypy или Pyright. По умолчанию интерпретатор не запрещает передать значение другого типа. Any ослабляет проверку, object обозначает произвольный объект без разрешения любых операций. `T | None` означает возможность значения None, а не автоматически необязательный аргумент вызова.

## Вопрос

Проверяет ли Python аннотации во время исполнения? Чем Any отличается от object и Optional?

## Аннотация и default

```python
def greet(name: str, prefix: str | None = None) -> str:
    actual_prefix = "Hello" if prefix is None else prefix
    return f"{actual_prefix}, {name}"

print(greet("Anna"))  # Hello, Anna
```

`prefix: str | None` разрешает два вида значений. Необязательным для вызова параметр делает **`= None`**. Без default его всё равно пришлось бы передать.

## Any и object

```python
from typing import Any

def unsafe(value: Any) -> Any:
    return value.missing_method()  # статическая проверка ослаблена

def safe(value: object) -> str:
    if isinstance(value, str):
        return value.upper()
    return str(value)

print(safe("hello"))  # HELLO
```

Object тоже принимает любой объект, но не разрешает операции, отсутствующие в общем контракте. После проверки isinstance анализатор сужает тип.

## Что не является валидацией

```python
def identity(value: int) -> int:
    return value

print(identity("text"))  # text в runtime; type checker сообщит о нарушении
```

`typing.cast` тоже не преобразует и не проверяет значение: он сообщает предположение анализатору. Для внешнего JSON нужен runtime-парсер и проверки, а не один cast.

## Версии аннотаций

Механизмы вычисления аннотаций различаются между Python 3.12 и 3.14+. Не строй логику приложения на предположении о немедленном вычислении каждой аннотации; для introspection используй документированные API и учитывай версию.

## Мини-шпаргалка

- `list[int]` — список целых по статическому контракту.
- `int | None` / Optional[int] — значение может быть None.
- Any — ослабленная проверка, object — необходимость сузить тип.
- Type hints не заменяют проверки на границе системы.

## Практика

Аннотируй функцию разбора возраста как `str -> int | None`. Проверь runtime отдельно от отчёта type checker.
