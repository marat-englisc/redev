# Как типизировать декораторы - ParamSpec, overload и Self

> [!NOTE]
> ParamSpec сохраняет список параметров callable при обёртывании, TypeVar — связь типа результата. Overload описывает несколько статических сигнатур одной runtime-реализации. Self выражает возврат экземпляра своего класса с учётом наследования. Эти инструменты применяют для реальной связи типов, а не вместо простых аннотаций каждой функции.

## Вопрос

Как сохранить сигнатуру функции после декоратора? Создаёт ли overload несколько runtime-функций?

## Декоратор с сохранением типов

```python
from collections.abc import Callable
from functools import wraps
from typing import ParamSpec, TypeVar

P = ParamSpec("P")
R = TypeVar("R")

def traced(function: Callable[P, R]) -> Callable[P, R]:
    @wraps(function)
    def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
        return function(*args, **kwargs)
    return wrapper

@traced
def greet(name: str, *, loud: bool = False) -> str:
    return name.upper() if loud else name

print(greet("Anna", loud=True))  # ANNA
```

Wraps заботится о runtime-метаданных, ParamSpec — о статической связи сигнатур. Одно не заменяет другое.

## Перегрузки

```python
from typing import overload

@overload
def repeat(value: str, count: int) -> str: ...

@overload
def repeat(value: bytes, count: int) -> bytes: ...

def repeat(value: str | bytes, count: int) -> str | bytes:
    return value * count

print(repeat("a", 3))  # aaa
```

Реально выполняется последняя реализация. Overload нужен анализатору, который выводит точный результат по входу. В этом конкретном примере можно выразить связь и ограниченным TypeVar.

## Self

Для fluent-метода `def enable(self) -> Self: ...` тип результата следует за подклассом. Не обещай Self, если метод на деле всегда создаёт экземпляр жёстко заданного базового класса. Это нарушит статический контракт.

## Практика

Запусти type checker на декорированной greet с неверным типом name и неизвестным keyword. Убедись, что wrapper не превратил интерфейс в Any.
