# Как работают TypeVar, generics и ограничения типов

> [!NOTE]
> Дженерик сохраняет связь типов между частями интерфейса. TypeVar и синтаксис параметров типов Python 3.12 позволяют выразить «вернуть тот тип, который передали». Any теряет эту связь. Ограничение bound задаёт допустимое семейство типов; типовой параметр полезен, когда действительно связывает входы, выходы или состояние контейнера.

## Вопрос

Как написать first, который возвращает тип элемента? Чем TypeVar отличается от Any?

## Совместимый синтаксис

```python
from collections.abc import Sequence
from typing import TypeVar

T = TypeVar("T")

def first(values: Sequence[T]) -> T | None:
    return values[0] if values else None

print(first([1, 2]))  # 1; статический результат int | None
print(first(["a", "b"]))  # a; str | None
```

Функция не знает конкретного T, но анализатор сохраняет связь. Any разрешил бы неподдерживаемые операции с результатом без полезной проверки.

## Синтаксис Python 3.12+

```python
from collections.abc import Sequence

def first_new[T](values: Sequence[T]) -> T | None:
    return values[0] if values else None

class Box[T]:
    def __init__(self, value: T) -> None:
        self.value = value

box = Box("hello")
print(box.value)  # hello
```

Старый синтаксис TypeVar остаётся важным для существующего кода. Не копируй новый синтаксис в среду Python 3.11.

## Bound

```python
def normalize[S: str](value: S) -> str:
    return value.strip()

print(normalize(" Anna "))  # Anna
```

Здесь generic вообще не обязателен: результат всегда str, и конкретный подтип не сохраняется. Пример показывает bound, а для реального интерфейса лучше простая `value: str`. Не вводи T только ради усложнения.

## Runtime

TypeVar — часть системы аннотаций, а не универсальный runtime-тип для `isinstance(value, T)`. `list[int]` тоже нельзя использовать как обычный второй аргумент isinstance для проверки всех элементов.

## Практика

Аннотируй функцию, выбирающую один из двух аргументов одного типа. Объясни, какая связь потеряется при замене T на Any.
