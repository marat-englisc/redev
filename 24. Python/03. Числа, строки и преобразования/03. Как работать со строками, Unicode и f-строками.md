# Как работать со строками, Unicode и f-строками

> [!NOTE]
> Str — неизменяемая последовательность Unicode-кодовых точек. Методы строки возвращают новые значения. F-строки вычисляют выражения и форматируют результат, join собирает строку из частей, split разделяет текст. Количество кодовых точек не всегда совпадает с числом видимых символов: emoji и буквы с комбинируемыми знаками могут состоять из нескольких точек.

## Вопрос

Как форматировать значения, очищать ввод и соединять строки? Почему len не всегда считает видимые символы?

## Повседневные операции

```python
raw = "  Anna, Python, SQL  "
parts = [part.strip() for part in raw.strip().split(",")]
print(parts)  # ['Anna', 'Python', 'SQL']
print(" | ".join(parts))  # Anna | Python | SQL
print("python".startswith("py"))  # True
```

`strip("ab")` удаляет набор символов a/b по краям, а не точную подстроку `ab`. Для точного префикса есть `removeprefix`, для суффикса — `removesuffix`.

## Форматирование

```python
name = "Anna"
price = 1234.5
print(f"{name}: {price:,.2f}")  # Anna: 1,234.50
print(f"{name=}")  # name='Anna'
```

Формат отображения не заменяет денежную модель и локализацию. F-строка исполняет выражение сейчас; не используй её для сборки SQL из пользовательских данных.

## Неизменяемость

```python
text = "python"
upper = text.upper()
print(text, upper)  # python PYTHON
```

`text[0] = "P"` вызовет TypeError. Для большого числа частей часто удобно накопить list и вызвать join. Но не оптимизируй небольшую читаемую f-строку без измерений.

## Unicode

```python
import unicodedata

a = "é"
b = "e\u0301"
print(len(a), len(b))  # 1 2
print(a == b)  # False
print(unicodedata.normalize("NFC", b) == a)  # True
```

Нормализация полезна, когда домен считает такие представления эквивалентными. Для caseless-сопоставления часто подходит casefold, но и оно не заменяет все правила языка и идентификации пользователей.

## Практика

Разбери строку тегов через split/strip и собери обратно через join. Отдельно реши, как обрабатывать пустые теги и дубликаты.
