# Чем bytes отличаются от str - encode и decode

> [!NOTE]
> Str хранит текст, bytes — последовательность байтов. `encode` переводит текст в байты по кодировке, `decode` восстанавливает текст из байтов. Кодировка должна соответствовать источнику. Число байтов UTF-8 может быть больше числа кодовых точек, а произвольная граница блока данных может разрезать один многобайтовый символ.

## Вопрос

Почему len текста и его UTF-8-представления различаются? Что означает UnicodeDecodeError?

## Два представления

```python
text = "кот"
payload = text.encode("utf-8")
print(len(text))  # 3
print(len(payload))  # 6
print(payload.decode("utf-8"))  # кот
print(payload[0])  # 208 — int, а не str
```

Операции сети и бинарных файлов часто работают с bytes. Парсеры текста ожидают str. Смешивание `"prefix" + b"data"` запрещено: сначала нужно выбрать нужное представление.

## Ошибка кодировки

```python
data = b"\xff"
try:
    data.decode("utf-8")
except UnicodeDecodeError:
    print("Это не корректная UTF-8-последовательность")
```

`errors="ignore"` молча теряет данные. `errors="replace"` заменяет ошибочные части маркером. Они полезны лишь при явно допустимой потере качества; нельзя автоматически «лечить» ими ключи записей или финансовые данные.

## Потоковая обработка

Если читать бинарный поток блоками, один UTF-8-символ может оказаться между двумя блоками. Независимый decode каждого блока способен упасть. Текстовый файловый объект с `encoding="utf-8"` или инкрементальный декодер учитывают незавершённые последовательности.

## Изменяемые байты

```python
buffer = bytearray(b"abc")
buffer[0] = ord("A")
print(bytes(buffer))  # b'Abc'
```

Bytearray полезен для изменяемого буфера. Base64, сжатие и шифрование — другие преобразования: base64 не является кодировкой текста в смысле UTF-8 и не скрывает секреты.

## Практика

Закодируй русское имя в UTF-8 и восстанови обратно. Сравни размеры и объясни, почему ограничение поля «20 байт» отличается от «20 символов».
