# Как работать с JSON, JSONL и проверкой схемы

> [!NOTE]
> `json.loads` разбирает строку, `json.load` читает документ из файла; dumps/dump выполняют обратное преобразование. Парсинг проверяет синтаксис, а не прикладную схему. JSONL хранит один JSON-документ на строку и удобен для потоковой обработки. Обычный json.load большого массива обычно создаёт весь объект в памяти.

## Вопрос

Чем JSON-парсер отличается от валидатора? Как обработать большой JSONL без полного list?

## Парсинг

```python
import json

record = json.loads('{"id": 7, "name": "Анна", "active": true}')
print(record["id"])  # 7
print(json.dumps(record, ensure_ascii=False, sort_keys=True))
```

JSON true/null превращаются в Python True/None. Tuple при сериализации становится массивом, а ключи JSON-объекта — строки. Не любой Python-объект сериализуется по умолчанию: datetime, Decimal и set требуют явного решения.

## Простая проверка схемы

```python
def parse_id(record):
    if not isinstance(record, dict):
        raise ValueError("expected an object")
    value = record.get("id")
    if type(value) is not int or value <= 0:
        raise ValueError("id must be a positive integer")
    return value

print(parse_id({"id": 7}))  # 7
```

Точная проверка int здесь намеренно исключает bool. Для сложных схем можно выбрать библиотеку runtime-валидации; TypedDict и cast сами эту работу не выполняют.

## JSONL

```python
import json
from io import StringIO

source = StringIO('{"id": 1}\n{"id": 2}\n')
for number, line in enumerate(source, start=1):
    record = json.loads(line)
    print(number, record["id"])
```

В рабочем коде задают политику для пустых строк, синтаксических ошибок и больших записей. Построчное чтение не ограничивает размер одной строки, а накопление всех id в set всё равно расходует память по их числу.

## Что важно помнить

- Синтаксически корректный JSON может иметь неподходящую структуру.
- Ограничивай размер недоверенного ввода.
- Строгая совместимость JSON требует учитывать NaN/Infinity: при dumps можно использовать `allow_nan=False`.
- JSONL и JSON-массив — разные форматы, их нельзя одинаково читать построчно без проверки.
