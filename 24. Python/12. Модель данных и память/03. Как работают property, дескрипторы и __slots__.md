# Как работают property, дескрипторы и __slots__

> [!NOTE]
> Property управляет чтением и записью атрибута через методы, сохраняя синтаксис `obj.attr`. В основе находится протокол дескриптора: __get__, __set__ и __delete__. Slots задаёт схему хранения атрибутов экземпляров и может уменьшить накладные расходы. Эти механизмы не превращают поля в защищённые секреты и не заменяют валидацию внешних данных.

## Вопрос

Как добавить проверку при присваивании без перехода от obj.price к set_price()? Для чего нужны дескрипторы?

## Управляемый атрибут

```python
class Product:
    def __init__(self, quantity):
        self.quantity = quantity

    @property
    def quantity(self):
        return self._quantity

    @quantity.setter
    def quantity(self, value):
        if value < 0:
            raise ValueError("quantity must be non-negative")
        self._quantity = value

product = Product(2)
product.quantity = 3
print(product.quantity)  # 3
```

Setter записывает в другое внутреннее имя, иначе `self.quantity = value` внутри setter рекурсивно вызвало бы его снова. Проверка в примере ограничивает диапазон, а полную проверку типа определяют отдельно.

## Что делает дескриптор

Property — готовый data descriptor. Методы тоже используют descriptor-механизм для привязки функции к экземпляру. Понимание этого помогает читать ORM и библиотеки валидации без необходимости сразу писать свои framework-подобные дескрипторы.

Data descriptors имеют приоритет над обычной записью атрибута в __dict__; non-data descriptors могут затеняться атрибутом экземпляра. Это уточняет простую схему «сначала экземпляр, потом класс».

## Slots

```python
class Point:
    __slots__ = ("x", "y")

    def __init__(self, x, y):
        self.x = x
        self.y = y

point = Point(1, 2)
print(point.x, point.y)  # 1 2
```

В этом простом классе произвольный `point.z = 3` вызовет AttributeError. Наследование может вернуть __dict__, поэтому эффект зависит от всей иерархии. Для weakref может потребоваться отдельный slot.

## Практика

Проверь отрицательную quantity и сохранение прежнего значения после ошибки. Объясни, почему нельзя скрывать медленный сетевой запрос за безобидно выглядящим чтением property без ясного контракта.
