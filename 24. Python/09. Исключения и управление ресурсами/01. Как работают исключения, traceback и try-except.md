# Как работают исключения, traceback и try-except

> [!NOTE]
> Исключение прерывает обычный путь выполнения и ищет подходящий except вверх по стеку. Traceback показывает цепочку вызовов до ошибки. Лови конкретные исключения там, где можешь восстановиться или добавить полезный контекст. `except Exception` не перехватывает все BaseException, например KeyboardInterrupt; голый except чаще слишком широк.

## Вопрос

Чем ValueError отличается от TypeError? Как правильно обработать ожидаемую ошибку ввода?

## Тип ошибки сообщает смысл

| Исключение | Частый сценарий |
| --- | --- |
| ValueError | Тип допустим, значение неверно: `int("abc")` |
| TypeError | Операция не подходит типу или аргументам |
| KeyError / IndexError | Нет ключа / индекса |
| FileNotFoundError | Не найден файл |
| AttributeError | Нет атрибута |
| ZeroDivisionError | Деление на ноль |

Конкретный API может использовать собственные исключения, поэтому проверяй его контракт.

```python
def parse_age(text):
    try:
        age = int(text)
    except ValueError:
        return None
    if age < 0:
        return None
    return age

print(parse_age("20"), parse_age("bad"))  # 20 None
```

Здесь None — сознательный результат неуспешного разбора. Если вызывающему нужен текст причины, лучше отдельная ошибка или структурированный результат.

## Узкий try

Помещай в try только операции, чьи ожидаемые ошибки действительно обрабатываются. Если обернуть весь большой алгоритм в `except ValueError: pass`, можно скрыть дефект совершенно другой функции.

## Читать traceback

Сначала найди тип и сообщение в конце, затем место в своём коде и входные данные. Последняя строка — место проявления, не всегда корневая причина. Не публикуй traceback с секретами и полными пользовательскими данными без проверки.

## LBYL и EAFP

Можно сначала проверить условие, а можно выполнить действие и обработать отказ. Между `exists()` и `open()` файл способен исчезнуть, поэтому предварительная проверка не устраняет необходимость обработки реального I/O.

## Практика

Проверь parser на пустой строке, отрицательном числе и корректном возрасте. Объясни, должна ли передача list вместо str считаться пользовательской ошибкой или ошибкой программиста.
