# Как создавать свои ошибки и сохранять причину через raise from

> [!NOTE]
> Прикладные исключения обычно наследуют от Exception. `raise` создаёт или передаёт ошибку, пустой raise внутри except повторно выбрасывает текущую с исходным traceback. `raise NewError(...) from error` явно связывает уровни причин. Сообщение должно объяснять контекст без секретов, а обработчик должен различать ошибки по типу, а не по тексту.

## Вопрос

Как перевести ошибку парсинга в понятную доменную ошибку, не потеряв диагностику?

## Собственный тип

```python
class InvalidRecordError(Exception):
    pass

def parse_identifier(text):
    try:
        value = int(text)
    except ValueError as error:
        raise InvalidRecordError("record id must be an integer") from error
    if value <= 0:
        raise InvalidRecordError("record id must be positive")
    return value

try:
    parse_identifier("bad")
except InvalidRecordError as error:
    print(error)
    print(type(error.__cause__).__name__)  # ValueError
```

Вызывающая сторона получает понятный интерфейс, а traceback сохраняет цепочку технической причины. Не добавляй всё содержимое входной записи в сообщение, если там могут быть личные данные.

## Повторный выброс

```python
def run():
    try:
        int("bad")
    except ValueError:
        # Здесь можно выполнить безопасную диагностику.
        raise
```

`raise error` не полностью эквивалентен пустому raise: он добавляет место повторного выброса в traceback. Если не меняешь смысл, обычно нужен просто raise.

## Скрытие контекста

`raise NewError(...) from None` подавляет показ автоматической цепочки в стандартном traceback. Это иногда уместно на пользовательской границе, но не должно лишать внутренние логи необходимых сведений.

## Assert не для валидации ввода

Assert проверяет внутренний инвариант и может быть отключён оптимизацией `python -O`. Для обязательной проверки внешних данных используй if и явный raise. Аннотация типа тоже не является runtime-проверкой.

## Практика

Создай два собственных типа: ошибка формата и ошибка недопустимого значения. Проверь, что вызывающий код может обрабатывать их раздельно, не разбирая текст сообщений.
