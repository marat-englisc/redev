# Мини-проект - потоковый JSONL-пайплайн и Decimal

> [!NOTE]
> Потоковый ETL читает запись, проверяет схему, преобразует и передаёт результат дальше без накопления всего входа. Decimal помогает сохранить десятичные значения, а номер записи делает ошибку диагностируемой. Нужно отдельно определить политику неверных строк, повторных id и публикации частичного результата: генератор сам эти решения не принимает.

## Вопрос

Как преобразовать JSONL с денежными значениями и проверить, что вход не загружается целиком?

## Контракт

Одна строка — объект с положительным целым id и строкой amount длиной от 1 до 64 символов. Синтаксис суммы соответствует Decimal, включая экспоненциальную запись вроде `"1e2"`. Значение должно быть конечным и находиться в диапазоне **от 0 до 999999999999.99 включительно до округления**. До сотых округляем по правилу ROUND_HALF_UP в отдельном контексте с точностью 28 значащих цифр. При первой ошибке обработка останавливается. Дедупликация и публикация результата не входят в функцию преобразования.

Файл `pipeline.py`:

```python
import json
from decimal import Context, Decimal, InvalidOperation, ROUND_HALF_UP, localcontext

MAX_AMOUNT = Decimal("999999999999.99")
MAX_AMOUNT_LENGTH = 64
CENT = Decimal("0.01")

def normalize(record):
    if not isinstance(record, dict):
        raise ValueError("expected an object")
    identifier = record.get("id")
    if type(identifier) is not int or identifier <= 0:
        raise ValueError("invalid id")
    raw_amount = record.get("amount")
    if not isinstance(raw_amount, str):
        raise ValueError("amount must be a decimal string")
    if not 1 <= len(raw_amount) <= MAX_AMOUNT_LENGTH:
        raise ValueError("amount must contain 1 to 64 characters")
    try:
        with localcontext(Context(prec=28)):
            amount = Decimal(raw_amount)
            if not amount.is_finite() or amount < 0:
                raise ValueError("invalid amount")
            if amount > MAX_AMOUNT:
                raise ValueError("amount exceeds 999999999999.99")
            amount = amount.quantize(CENT, rounding=ROUND_HALF_UP)
    except InvalidOperation as error:
        raise ValueError("invalid decimal amount") from error
    return {"id": identifier, "amount": str(amount)}

def transform(source, target):
    count = 0
    for number, line in enumerate(source, start=1):
        try:
            result = normalize(json.loads(line))
        except ValueError as error:
            raise ValueError(f"invalid line #{number}") from error
        target.write(json.dumps(result, ensure_ascii=False) + "\n")
        count += 1
    return count
```

Точность контекста — число значащих цифр, а не число знаков после запятой. После округления допустимая сумма содержит не более 14 значащих цифр, поэтому точности 28 достаточно. Большая конечная сумма, например `"1e26"`, отклоняется явной проверкой диапазона. Для другого домена границы и точность выбирают заново.

`localcontext(Context(prec=28))` временно использует отдельный контекст: изменение точности или traps текущего контекста во внешнем коде не меняет правило округления этой функции, а внешний контекст восстанавливается после выхода. Traps определяют, какие арифметические сигналы становятся исключениями; например, включённый Inexact запрещает неточное округление.

## Тесты test_pipeline.py

```python
from io import StringIO
from decimal import Inexact, localcontext
import json
import pytest
from pipeline import normalize, transform

def test_stream():
    source = StringIO('{"id": 1, "amount": "2.675"}\n')
    target = StringIO()
    assert transform(source, target) == 1
    assert json.loads(target.getvalue()) == {"id": 1, "amount": "2.68"}

@pytest.mark.parametrize(
    "amount",
    [
        "NaN", "Infinity", "-1", "bad", "", "0" * 65,
        "1e26", "1000000000000", "999999999999.991", 1.5,
    ],
)
def test_invalid_amount(amount):
    with pytest.raises(ValueError):
        normalize({"id": 1, "amount": amount})

@pytest.mark.parametrize(
    ("amount", "expected"),
    [
        ("0", "0.00"),
        ("0" * 64, "0.00"),
        ("1e2", "100.00"),
        ("999999999999.99", "999999999999.99"),
        ("999999999999.989", "999999999999.99"),
    ],
)
def test_amount_boundaries(amount, expected):
    assert normalize({"id": 1, "amount": amount})["amount"] == expected

def test_rounding_uses_own_context():
    with localcontext() as context:
        context.prec = 4
        context.traps[Inexact] = True
        assert normalize({"id": 1, "amount": "2.675"})["amount"] == "2.68"
        assert context.prec == 4
        assert context.traps[Inexact] is True

def test_bool_is_not_identifier():
    with pytest.raises(ValueError):
        normalize({"id": True, "amount": "1.00"})
```

## Границы решения

StringIO используется только в маленьких тестах. Для большого входа передавай реальные файловые потоки с encoding="utf-8". Пустая строка в этом контракте является ошибкой, а не пропускается молча.

Если ошибка возникнет после первой записи, target уже содержит частичный результат. Для атомарной публикации файл обычно пишут во временный путь, закрывают, проверяют и заменяют целевой в той же ФС. Для БД выбирают отдельную транзакционную политику.
