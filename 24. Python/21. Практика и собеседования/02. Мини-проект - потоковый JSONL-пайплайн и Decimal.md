# Мини-проект - потоковый JSONL-пайплайн и Decimal

> [!NOTE]
> Потоковый ETL читает запись, проверяет схему, преобразует и передаёт результат дальше без накопления всего входа. Decimal помогает сохранить десятичные значения, а номер записи делает ошибку диагностируемой. Нужно отдельно определить политику неверных строк, повторных id и публикации частичного результата: генератор сам эти решения не принимает.

## Вопрос

Как преобразовать JSONL с денежными значениями и проверить, что вход не загружается целиком?

## Контракт

Одна строка — объект с положительным целым id и строкой amount. Сумма конечная и неотрицательная; применяется явно выбранное округление до сотых. При первой ошибке обработка останавливается. Дедупликация и публикация результата не входят в функцию преобразования.

Файл `pipeline.py`:

```python
import json
from decimal import Decimal, InvalidOperation, ROUND_HALF_UP

def normalize(record):
    if not isinstance(record, dict):
        raise ValueError("expected an object")
    identifier = record.get("id")
    if type(identifier) is not int or identifier <= 0:
        raise ValueError("invalid id")
    raw_amount = record.get("amount")
    if not isinstance(raw_amount, str):
        raise ValueError("amount must be a decimal string")
    try:
        amount = Decimal(raw_amount)
        if not amount.is_finite() or amount < 0:
            raise ValueError("invalid amount")
        amount = amount.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
    except InvalidOperation as error:
        raise ValueError("invalid decimal amount") from error
    return {"id": identifier, "amount": str(amount)}

def transform(source, target):
    count = 0
    for number, line in enumerate(source, start=1):
        try:
            result = normalize(json.loads(line))
        except ValueError as error:
            raise ValueError(f"invalid line #{number}") from error
        target.write(json.dumps(result, ensure_ascii=False) + "\n")
        count += 1
    return count
```

## Тесты test_pipeline.py

```python
from io import StringIO
import json
import pytest
from pipeline import normalize, transform

def test_stream():
    source = StringIO('{"id": 1, "amount": "2.675"}\n')
    target = StringIO()
    assert transform(source, target) == 1
    assert json.loads(target.getvalue()) == {"id": 1, "amount": "2.68"}

@pytest.mark.parametrize("amount", ["NaN", "Infinity", "-1", "bad", 1.5])
def test_invalid_amount(amount):
    with pytest.raises(ValueError):
        normalize({"id": 1, "amount": amount})

def test_bool_is_not_identifier():
    with pytest.raises(ValueError):
        normalize({"id": True, "amount": "1.00"})
```

## Границы решения

StringIO используется только в маленьких тестах. Для большого входа передавай реальные файловые потоки с encoding="utf-8". Пустая строка в этом контракте является ошибкой, а не пропускается молча.

Если ошибка возникнет после первой записи, target уже содержит частичный результат. Для атомарной публикации файл обычно пишут во временный путь, закрывают, проверяют и заменяют целевой в той же ФС. Для БД выбирают отдельную транзакционную политику.
