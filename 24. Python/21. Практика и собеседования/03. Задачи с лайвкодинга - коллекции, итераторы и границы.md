# Задачи с лайвкодинга - коллекции, итераторы и границы

> [!NOTE]
> На Python-лайвкодинге важно уточнить вход, порядок, дубликаты, память и ошибки, затем выбрать структуру и объяснить сложность. Рабочее решение для обычного примера ещё не завершено без проверки пустого входа и границ. Встроенные структуры полезны, если понимаешь их контракт и стоимость.

## Вопрос

Как решать типовые задачи на коллекции и потоковый обход без скрытой потери данных?

## Задача 1: уникальные значения с сохранением порядка

Вход содержит хешируемые значения, сохраняем первое появление.

```python
def unique(values):
    seen = set()
    for value in values:
        if value not in seen:
            seen.add(value)
            yield value

assert list(unique([3, 1, 3, 2, 1])) == [3, 1, 2]
assert list(unique([])) == []
```

В среднем O(n) времени, O(k) памяти для k уникальных значений. Генератор не делает seen постоянного размера. Для изменяемых записей нужно выбрать хешируемый предметный ключ.

## Задача 2: первое повторившееся значение

Возвращаем результат в tuple «найдено, значение», чтобы None мог быть обычным элементом.

```python
def first_duplicate(values):
    seen = set()
    for value in values:
        if value in seen:
            return True, value
        seen.add(value)
    return False, None

assert first_duplicate([1, 2, 1, 2]) == (True, 1)
assert first_duplicate([None, None]) == (True, None)
assert first_duplicate([]) == (False, None)
```

Уточни, что True и 1 равны как set-элементы. Если предметная задача различает типы, нужен другой ключ сравнения.

## Задача 3: пакетирование iterator

```python
from itertools import islice

def chunks(values, size):
    if size <= 0:
        raise ValueError("size must be positive")
    iterator = iter(values)
    while batch := tuple(islice(iterator, size)):
        yield batch

assert list(chunks(iter(range(5)), 2)) == [(0, 1), (2, 3), (4,)]
assert list(chunks([], 2)) == []
```

В Python 3.12 есть готовый itertools.batched, но ручной вариант показывает протокол. Проверка размера выполняется при потреблении generator, а не при одном создании объекта.

## Как обсуждать решение

- Уточни, повторяемый вход или одноразовый iterator.
- Назови ограничения элементов и требуемый порядок.
- Объясни время и память отдельно.
- Проверь пустоту, повторения и недопустимый параметр.
- Сначала добейся ясного решения, затем обсуждай оптимизацию.
