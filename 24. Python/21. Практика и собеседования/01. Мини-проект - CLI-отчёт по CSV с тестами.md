# Мини-проект - CLI-отчёт по CSV с тестами

> [!NOTE]
> Хороший CLI отделяет расчёт от файлов и аргументов, валидирует данные и возвращает машинный результат отдельно от ошибок. Этот проект объединяет CSV, функции, типы, исключения и pytest. Успех проверяется результатом, exit code и тестами на неверный вход, а не только запуском без traceback.

## Вопрос

Как собрать небольшую утилиту отчёта по HTTP-запросам и проверить её поведение?

## Задание и формат

Сделай отдельную папку и venv. Вход `requests.csv`:

```csv
status,duration_ms
200,10
500,50
200,30
```

Нужны число запросов, число 5xx и среднее время. Статус допустим от 100 до 599, время — неотрицательное целое. Пустой файл с корректным заголовком даёт mean_ms=None. Любая неверная запись завершает операцию ошибкой.

## Реализация report.py

```python
import argparse
import csv
import json
import sys
from pathlib import Path
from typing import TextIO

def build_report(source: TextIO) -> dict[str, int | float | None]:
    reader = csv.DictReader(source, strict=True)
    if reader.fieldnames != ["status", "duration_ms"]:
        raise ValueError("expected status,duration_ms header")
    count = errors = total_ms = 0
    for number, row in enumerate(reader, start=1):
        try:
            if None in row:
                raise ValueError("too many columns")
            status = int(row["status"])
            duration = int(row["duration_ms"])
            if not 100 <= status <= 599 or duration < 0:
                raise ValueError("values outside allowed range")
        except (TypeError, ValueError) as error:
            raise ValueError(f"invalid record #{number}") from error
        count += 1
        errors += 500 <= status <= 599
        total_ms += duration
    return {"requests": count, "errors": errors, "mean_ms": total_ms / count if count else None}

def main(argv=None) -> int:
    parser = argparse.ArgumentParser(description="Build a CSV request report")
    parser.add_argument("path", type=Path)
    args = parser.parse_args(argv)
    try:
        with args.path.open(encoding="utf-8", newline="") as source:
            report = build_report(source)
    except (OSError, ValueError, csv.Error) as error:
        print(f"Cannot build report: {error}", file=sys.stderr)
        return 1
    print(json.dumps(report, allow_nan=False))
    return 0

if __name__ == "__main__":
    raise SystemExit(main())
```

Номер относится к логической записи CSV после заголовка; при quoted multiline-полях это не обязательно физический номер строки.

## Тесты test_report.py

```python
from io import StringIO
import pytest
from report import build_report

def test_report():
    source = StringIO("status,duration_ms\n200,10\n500,50\n200,30\n")
    assert build_report(source) == {"requests": 3, "errors": 1, "mean_ms": 30.0}

def test_empty_data():
    assert build_report(StringIO("status,duration_ms\n"))["mean_ms"] is None

@pytest.mark.parametrize("row", ["200,-1", "bad,10", "700,10", "200", "200,10,extra"])
def test_invalid_record(row):
    with pytest.raises(ValueError):
        build_report(StringIO("status,duration_ms\n" + row + "\n"))
```

## Запуск и самопроверка

```bash
python -m pytest -q
python report.py requests.csv
```

Ожидается JSON с 3 запросами, 1 ошибкой и средним 30.0. Добавь CLI-тест отсутствующего файла, неверного заголовка и проверку stderr/exit code. Пайплайн хранит счётчики, а не все записи; размер одной CSV-записи всё равно ограничивается отдельно.
