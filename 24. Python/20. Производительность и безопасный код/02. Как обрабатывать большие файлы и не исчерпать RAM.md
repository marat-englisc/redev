# Как обрабатывать большие файлы и не исчерпать RAM

> [!NOTE]
> Для большого входа контролируют чтение, размер одной записи, промежуточные коллекции, буферы и накопление результата. Итерация построчно или пакетами уменьшает потребление памяти, только если следующие этапы не собирают всё заново. Агрегация по уникальным ключам требует памяти по числу ключей. Иногда нужен внешний sort, БД или специализированный движок.

## Вопрос

Почему генератор не гарантирует постоянную память? Как построить действительно потоковый этап обработки?

## Минимальный pipeline

```python
from io import StringIO

def cleaned_lines(lines):
    for line in lines:
        value = line.strip()
        if value:
            yield value

source = StringIO(" first \n\nsecond\n")
target = StringIO()
count = 0
for value in cleaned_lines(source):
    target.write(value + "\n")
    count += 1
print(count)  # 2
print(target.getvalue())  # first и second на отдельных строках
```

StringIO здесь делает маленький пример воспроизводимым и **хранит весь текст в RAM**. Для большого реального входа и выхода нужны файловые объекты или другой потоковый sink.

## Скрытая материализация

```text
file iterator → generator → list(...)          → снова весь вход в памяти
file iterator → generator → sorted(...)        → полная сортировка в памяти
file iterator → Counter(уникальных id)          → память по числу разных id
```

Если нужна только сумма, передай generator в sum. Для top-k часто подходит heap, для больших группировок — подходящий внешний алгоритм или СУБД.

## CSV, JSON и Parquet

Csv.reader можно потреблять построчно по записям. JSONL удобен для независимых документов; большой JSON-массив требует специального инкрементального парсера или другой организации данных. Parquet читается специализированными библиотеками; проекция колонок и фильтры могут сократить чтение, но точное поведение зависит от движка.

## Пакеты и обратное давление

Пакет в 1000 записей не гарантирует заданный объём байтов. Ограниченная очередь полезна между producer и consumers; сохранение результатов в бесконечно растущий list отменяет выигрыш.

## Практика

Для ETL укажи верхние границы: запись, batch, очередь, уникальные ключи, результат. Отдельно реши, что делать с одной недопустимо большой строкой.
