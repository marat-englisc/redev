# Как работают timeout, отмена и CancelledError

> [!NOTE]
> Отмена asyncio кооперативна: cancel запрашивает её, а coroutine обычно получает CancelledError в точке приостановки. Cleanup делают в finally, после него отмену обычно передают дальше. Asyncio.timeout ограничивает область ожидания и преобразует собственную отмену в TimeoutError снаружи контекста. Отмена Task не гарантирует остановку внешней операции, уже отправленной серверу или потоку.

## Вопрос

Как корректно завершить задачу по таймауту? Почему нельзя бездумно проглатывать CancelledError?

## Timeout области

```python
import asyncio

async def slow():
    try:
        await asyncio.sleep(10)
    finally:
        print("cleanup")

async def main():
    try:
        async with asyncio.timeout(0.01):
            await slow()
    except TimeoutError:
        print("deadline exceeded")

asyncio.run(main())
# cleanup
# deadline exceeded
```

TimeoutError ловят снаружи async with. Timeout не прерывает CPU-цикл, который не возвращает управление loop вовремя.

## Явная отмена

```python
import asyncio

async def main():
    task = asyncio.create_task(asyncio.sleep(10))
    await asyncio.sleep(0)
    task.cancel()
    try:
        await task
    except asyncio.CancelledError:
        print("cancelled")

asyncio.run(main())
```

Ожидание после cancel позволяет получить итог и убедиться в завершении. CancelledError наследуется от BaseException в современных версиях Python и не ловится обычным except Exception.

## Граница гарантии

Клиент перестал ждать HTTP-ответ — сервер мог уже выполнить запись. Для повторения такой операции нужен idempotency key или другая предметная защита, а не просто новый запрос.

## Что важно помнить

- Finally должен освобождать ресурсы, не подавляя отмену без причины.
- Wait_for имеет свою семантику ожидания отмены; фактическое время может превысить заданное.
- Shield ограничивает распространение отмены в выбранное awaitable, но не превращает работу в бесконечно живую фоновую службу.

## Практика

Проверь cleanup при обычном успехе, timeout и явном cancel. Не используй сетевой сервис: контролируемого sleep достаточно для проверки протокола.
