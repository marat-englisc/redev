# Как работают async, await, coroutine и event loop

> [!NOTE]
> Async def создаёт coroutine-функцию; её вызов возвращает coroutine-объект, но сам по себе не запускает всю работу. Await ожидает awaitable и может дать event loop выполнять другие готовые задачи. Asyncio использует кооперативное переключение: обычный Python-код и блокирующий вызов внутри coroutine всё ещё блокируют поток loop.

## Вопрос

Чем coroutine отличается от обычной функции? Делает ли await вычисление параллельным?

## Первый пример

```python
import asyncio

async def fetch_label():
    await asyncio.sleep(0.01)  # имитация неблокирующего ожидания
    return "ready"

async def main():
    result = await fetch_label()
    print(result)

asyncio.run(main())  # ready
```

Sleep здесь моделирует ожидание, не HTTP-запрос. Asyncio.run создаёт и закрывает loop для верхнего уровня обычного скрипта. В среде с уже работающим loop, например некоторых notebook, используют её штатный способ top-level await, а не вложенный run.

## Последовательно и конкурентно

```python
import asyncio

async def job(name):
    await asyncio.sleep(0.01)
    return name

async def main():
    first = await job("a")
    second = await job("b")
    print(first, second)  # a b; ожидания последовательные

asyncio.run(main())
```

Два await по очереди не запускают задачи одновременно. Для перекрытия ожиданий нужны tasks или соответствующий комбинатор.

## Термины

| Объект | Смысл |
| --- | --- |
| Coroutine | Приостанавливаемое вычисление |
| Task | Coroutine, запланированная на loop |
| Future | Низкоуровневый результат, который станет доступен позже |

Await не обязательно переключает управление, если результат уже готов. CPU-intensive цикл без уступки продолжит занимать loop.

## Практика

Добавь print до и после await. Объясни, почему простой вызов `fetch_label()` без await/планирования не даёт готовую строку и может вызвать warning об неисполненной coroutine.
