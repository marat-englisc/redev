# Как запускать задачи - create_task, gather и TaskGroup

> [!NOTE]
> Create_task планирует coroutine как Task; задачу нужно сопровождать и получить её результат или ошибку. Gather объединяет awaitable и возвращает результаты в порядке аргументов. TaskGroup задаёт структурированную группу: при обычной ошибке одной задачи отменяет соседние и при выходе сообщает об ошибках. Семантика отказа у gather и TaskGroup различается.

## Вопрос

Как конкурентно дождаться нескольких операций? Что произойдёт с соседними задачами при ошибке?

## Группа задач

```python
import asyncio

async def load(identifier):
    await asyncio.sleep(0.01)
    return identifier * 10

async def main():
    async with asyncio.TaskGroup() as group:
        first = group.create_task(load(1))
        second = group.create_task(load(2))
    print(first.result(), second.result())  # 10 20

asyncio.run(main())
```

После успешного выхода все задачи группы завершены. TaskGroup доступен с Python 3.11. Ошибки могут быть собраны в ExceptionGroup и обработаны через except*, если нужен раздельный разбор.

## Gather

```python
import asyncio

async def load(value):
    await asyncio.sleep(0.01)
    return value * 2

async def main():
    results = await asyncio.gather(load(3), load(1))
    print(results)  # [6, 2], порядок входов

asyncio.run(main())
```

По умолчанию первая ошибка gather передаётся ожидающему коду, но остальные задачи не получают автоматическую отмену по правилу TaskGroup. При return_exceptions=True ошибки становятся элементами результата: их нельзя игнорировать как успешные значения.

## Потерянные задачи

«Fire and forget» без владельца создаёт риск незамеченного исключения и незавершённой работы при выходе приложения. Сохраняй ссылки на отдельные tasks и организуй ожидание/отмену при завершении.

## Что важно помнить

Конкурентные ожидания не равны неограниченному числу запросов. Группа из миллиона tasks всё равно расходует память и способна перегрузить внешнюю систему. Для потока нужен ограничитель или очередь workers.

## Практика

Добавь ошибку в одну операцию TaskGroup, проверь finally соседней и обработай ExceptionGroup. Сравни с явно выбранной политикой gather.
