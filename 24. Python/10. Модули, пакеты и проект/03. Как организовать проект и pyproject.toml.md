# Как организовать проект и pyproject.toml

> [!NOTE]
> Pyproject.toml описывает проект, backend сборки и настройки инструментов. Import package и distribution package — разные понятия: устанавливаемое имя не обязано совпадать с именем import. Src-layout помогает избежать случайного импорта исходников из корня вместо установленного пакета. Структуру выбирают под размер проекта, без лишних слоёв для простого скрипта.

## Вопрос

Что хранится в pyproject.toml? Зачем пакет ставят в окружение через editable install?

## Минимальная структура

```text
project/
  pyproject.toml
  src/
    study_app/
      __init__.py
      cli.py
  tests/
    test_cli.py
```

Пример для setuptools:

```toml
[build-system]
requires = ["setuptools>=68"]
build-backend = "setuptools.build_meta"

[project]
name = "study-python-app"
version = "0.1.0"
requires-python = ">=3.12"
dependencies = []

[project.scripts]
study-app = "study_app.cli:main"

[tool.setuptools.packages.find]
where = ["src"]
```

В cli.py должна существовать функция main. Это пример конфигурации, не требование использовать один backend для всех Python-проектов.

## Установка в выбранное окружение

```bash
python -m pip install -e .
```

Editable install позволяет импортировать пакет при разработке с изменениями исходников без обычной полной переустановки. Это не то же самое, что финальный wheel для доставки.

## Как делить код

Отделяй чистое преобразование данных от чтения файлов, сети и CLI. Тогда расчёт можно тестировать без реального сервера. Не создавай десятки manager/service/helper-слоёв для задачи в две функции, но и не складывай конфигурацию, SQL и HTTP в один бесконечный файл.

## Что исключают

`.venv`, `__pycache__`, локальные секреты, результаты сборки и временные данные обычно не входят в исходный репозиторий. Точные версии зависимостей и настройки инструментов сохраняются по правилам проекта.

## Практика

Создай небольшой пакет с main, установи editable и вызови entry point. Проверь импорт не только из корня репозитория, но и из другой рабочей папки.
