# Зачем нужны __main__, python -m и абсолютные импорты

> [!NOTE]
> У запускаемого entry point имя __name__ равно "__main__". Проверка `if __name__ == "__main__"` отделяет запуск от импорта. `python -m package.module` находит модуль через импортную систему и сохраняет пакетный контекст, что помогает относительным импортам. Прямой запуск внутреннего файла пакета может иметь другой sys.path и контекст.

## Вопрос

Почему импорт файла не должен запускать всю программу? Чем запуск файла отличается от python -m?

## Небольшой entry point

Содержимое `greet.py`:

```python
def greet(name):
    return f"Hello, {name}!"

def main():
    print(greet("Anna"))
    return 0

if __name__ == "__main__":
    raise SystemExit(main())
```

При `python greet.py` выполняется main. При `import greet` определятся функции, но не запустится приветствие. SystemExit передаёт системе код завершения.

## Пакет

```text
project/
  app/
    __init__.py
    cli.py
    service.py
```

Из project можно выполнить `python -m app.cli`. В cli допустим импорт `from .service import ...`, потому что известен пакет app. Для прямого `python app/cli.py` это условие не обязано выполняться.

Абсолютный импорт `from app.service import ...` явно задаёт пакет. Он тоже требует корректной установки или пути поиска. Не исправляй каждую проблему случайным `sys.path.append(...)`.

## Конфликт имён

Не называй свой файл `json.py`, `typing.py`, `random.py` или именем используемой сторонней библиотеки без причины: он может затенить ожидаемый модуль. Для диагностики проверь `module.__file__` и выбранный интерпретатор.

## Дополнительная роль guard

Main guard важен для multiprocessing со spawn: новый процесс импортирует entry point. Запуск новых процессов на верхнем уровне без guard способен рекурсивно повторять создание процессов.

## Практика

Проверь greet.py через прямой запуск и импорт. Затем создай пакет с __main__.py и запусти `python -m app`.
