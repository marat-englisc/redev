# Как работают import, модули и sys.modules

> [!NOTE]
> Модуль — единица кода с собственным namespace; пакет объединяет модули. При первом обычном импорте модуль создаётся, его верхний уровень выполняется, а результат кешируется в sys.modules. `from module import name` связывает имя в текущем namespace; это не живая ссылка на будущие переприсваивания атрибута исходного модуля.

## Вопрос

Когда исполняется код модуля? Почему циклические импорты вызывают ошибку partially initialized module?

## Обычный импорт

```python
import math
from math import sqrt

print(math.sqrt(9), sqrt(16))  # 3.0 4.0
```

Первый вариант оставляет происхождение имени явным. Импорт со звёздочкой усложняет чтение и создаёт риск конфликтов.

## Два файла

Файл `settings.py`:

```python
print("settings loaded")
limit = 10
```

Файл `main.py` в той же папке:

```python
import settings
from settings import limit

settings.limit = 20
print(settings.limit)  # 20
print(limit)  # 10
```

Импорт создал локальное имя limit, ссылающееся на прежний int. Если бы импортировали изменяемый объект и мутировали его без перепривязки, общая ссылка могла бы показать изменение.

## Пакеты

Обычный пакет содержит `__init__.py`, но существуют namespace packages без него. Не обязательно складывать все импорты и тяжёлую инициализацию в __init__: это увеличивает побочные эффекты.

## Циклы

Если a импортирует b, а b пытается прочитать ещё не определённое имя из a, модуль a может быть частично инициализирован. Часто помогает выделить общую зависимость в отдельный модуль или убрать работу при импорте. Перенос import внутрь функции иногда полезен, но не заменяет архитектурное решение.

## Практика

Создай два указанных файла и запусти main.py. Добавь повторный `import settings`: верхний print обычно не повторится в том же процессе.
