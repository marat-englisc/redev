# Как делать HTTP-запросы с timeout и ограничением ответа

> [!NOTE]
> HTTP-клиент должен учитывать сетевые ошибки, status code, размер и формат ответа. Стандартный urllib.request подходит для базовых синхронных запросов; сторонние клиенты предоставляют другие интерфейсы. Timeout конкретного API не всегда является общим deadline всей операции. HTTPS-проверку сертификата нельзя отключать как обычное исправление ошибки.

## Вопрос

Почему успешное соединение ещё не гарантирует корректный JSON-ответ? Как не прочитать неограниченный ответ в память?

## Функция клиента

```python
import json
from urllib.request import Request, urlopen

def fetch_json(url: str, *, max_bytes: int = 1_000_000) -> object:
    if max_bytes <= 0:
        raise ValueError("max_bytes must be positive")
    request = Request(url, headers={"Accept": "application/json"})
    with urlopen(request, timeout=5) as response:
        payload = response.read(max_bytes + 1)
    if len(payload) > max_bytes:
        raise ValueError("response is too large")
    return json.loads(payload)
```

Пример рассчитан на доверенный URL и JSON-кодировку, поддерживаемую парсером. Проверка прикладной схемы выполняется после загрузки отдельно. Для недоверенного URL нужна политика адресов, схем и redirect, чтобы не дать доступ к внутренним ресурсам.

## Виды отказа

| Этап | Пример |
| --- | --- |
| Разрешение имени/соединение | DNS, refused, timeout |
| TLS | Недоверенный сертификат или имя |
| HTTP | 404, 429, 500 |
| Формат | HTML вместо JSON, повреждённый JSON |
| Схема | Нет обязательного id |

Urllib может поднимать HTTPError/URLError, а другие библиотеки имеют собственные типы исключений. Не лови всё как «нет интернета».

## Поддерживаемые клиенты

Requests обычно используется синхронно, HTTPX предоставляет sync и async API. Сессия/Client помогает переиспользовать соединения. Выбор клиента не отменяет timeout, закрытие ресурсов и проверку ответа.

## Практика

Проверь fetch_json на локальном учебном HTTP-сервере: нормальный JSON, неверный JSON, 404 и слишком большой ответ. Не делай тест зависимым от доступности публичного API.
