# Как избегать N+1, читать пакетами и управлять соединениями

> [!NOTE]
> Производительность DB-кода зависит не только от Python-циклов: лишние round trips, большие fetchall и слишком длинные транзакции часто дороже. N+1 означает основной запрос и отдельный дополнительный запрос для каждой записи. Пакетное чтение и запись ограничивают накладные расходы, но размер пакета и границы транзакций выбирают по требованиям к памяти и согласованности.

## Вопрос

Почему «один запрос в цикле» может быть проблемой? Как прочитать результат, не создавая полный list?

## Пакетное чтение

```python
import sqlite3
from contextlib import closing

with closing(sqlite3.connect(":memory:")) as connection:
    with connection:
        connection.execute("CREATE TABLE events (id INTEGER PRIMARY KEY)")
        connection.executemany("INSERT INTO events VALUES (?)", ((i,) for i in range(7)))

    cursor = connection.execute("SELECT id FROM events ORDER BY id")
    total = 0
    while batch := cursor.fetchmany(3):
        total += len(batch)
    print(total)  # 7
```

Fetchmany ограничивает число возвращённых в Python записей за вызов. Реальное буферизование на стороне драйвера и сервера зависит от СУБД и типа cursor: не обещай bounded RAM только по названию метода.

## N+1

```text
SELECT users
для каждого пользователя: SELECT orders WHERE user_id = ...
```

Вместо множества запросов часто подходят JOIN, batch по набору id или предзагрузка связей ORM. Но JOIN может размножить строки: измеряй результат и трафик, не только число запросов.

## Транзакции и пул

Executemany уменьшает ручной код, но не обязательно превращается в один SQL-запрос во всех драйверах. Пул переиспользует ограниченное число соединений; он не разрешает бесконечную нагрузку на БД.

Не держи транзакцию открытой во время медленного HTTP, если в этом нет осознанной необходимости. После ошибки учитывай состояние транзакции; соединение нельзя без проверки возвращать другим задачам как заведомо здоровое.

## Практика

Для импорта 100 тысяч записей опиши размер batch, commit policy и поведение при ошибке в середине. Различи «всё атомарно» и «частично сохранённый прогресс».
