# Как работают venv, pip и виртуальные окружения

> [!NOTE]
> `venv` создаёт изолированное окружение зависимостей проекта. `python -m pip` запускает pip именно выбранным интерпретатором. Активация окружения в основном меняет PATH и удобство команд; можно напрямую вызвать его Python. Venv не является контейнером, не изолирует всю ОС и обычно не переносится копированием между машинами.

## Вопрос

Зачем отдельное окружение каждому проекту? Чем `pip install` отличается от `python -m pip install`?

## Проблема общей установки

Проект A требует одну версию библиотеки, проект B — другую. Установка всего в системный Python связывает независимые проекты и способна затронуть инструменты ОС.

Из корня нового проекта, используя подходящую команду Python:

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pip --version
.\.venv\Scripts\python.exe -m pip install pytest
```

Linux/macOS:

```bash
.venv/bin/python -m pip --version
.venv/bin/python -m pip install pytest
```

Эти команды работают без активации. Установка требует доступа к индексу пакетов; на некоторых дистрибутивах поддержку venv устанавливают отдельным системным пакетом.

## Активация

В Bash используют `source .venv/bin/activate`, в PowerShell — `.\.venv\Scripts\Activate.ps1`. После активации имя `python` обычно ведёт в окружение. Если политика PowerShell запрещает скрипт активации, можно продолжить прямым вызовом Python, не меняя системную политику.

```python
import sys

print(sys.prefix)
print(sys.base_prefix)
print(sys.prefix != sys.base_prefix)  # True для обычного venv
```

## Что хранить в Git

`.venv/` исключают. В репозиторий кладут описание проекта, зависимостей и выбранный lock/requirements-файл. Окружение восстанавливают из этих данных, а не архивируют как основной способ доставки приложения.

`pip freeze` показывает установленное, включая транзитивные пакеты; это снимок среды, а не автоматически продуманное описание прямых зависимостей.

## Частые ошибки

- Вызывать pip из одной среды, Python — из другой.
- Устанавливать рабочие библиотеки через `sudo pip`.
- Считать, что активация меняет уже запущенный процесс IDE или сервера.

## Практика

Создай venv, сравни `sys.executable` до и после выбора окружения. Проверь pip прямым вызовом его Python.
