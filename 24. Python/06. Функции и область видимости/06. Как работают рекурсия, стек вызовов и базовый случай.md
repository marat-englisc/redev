# Как работают рекурсия, стек вызовов и базовый случай

> [!NOTE]
> Рекурсивная функция вызывает себя для меньшей подзадачи. Нужны базовый случай и движение к нему; каждый вызов использует стек и сохраняет своё локальное состояние. В Python нельзя рассчитывать на устранение хвостовой рекурсии. Для глубокой обработки и обычных линейных повторений часто лучше цикл или явный стек.

## Вопрос

Как работает рекурсия и почему поднятие recursion limit не является универсальным исправлением?

## Простой пример

```python
def factorial(number):
    if number < 0:
        raise ValueError("number must be non-negative")
    if number <= 1:
        return 1
    return number * factorial(number - 1)

print(factorial(4))  # 24
```

```text
factorial(4)
  4 * factorial(3)
      3 * factorial(2)
          2 * factorial(1) → 1
      возврат результатов в обратном порядке
```

Базовый случай завершает ветку, а `number - 1` уменьшает задачу. Без одного из этих свойств вызовы могут продолжаться до RecursionError.

## Когда рекурсия естественна

Вложенные деревья каталогов, синтаксические деревья и разделение задачи на части удобно описывать рекурсивно. Для произвольного графа нужна защита от повторного посещения: уменьшение числового параметра там не всегда есть.

## Итеративный вариант

```python
def factorial_loop(number):
    if number < 0:
        raise ValueError("number must be non-negative")
    result = 1
    for value in range(2, number + 1):
        result *= value
    return result

print(factorial_loop(4))  # 24
```

Для линейной задачи цикл проще и не накапливает рекурсивные кадры. В рабочем коде для факториала существует math.factorial; здесь пример объясняет механизм вызовов.

## Типичные ошибки

- Нет базового случая или вход не приближается к нему.
- На каждом шаге копируется большой срез, что незаметно увеличивает стоимость.
- Наивный Fibonacci пересчитывает одинаковые подзадачи экспоненциально.
- Увеличение лимита подменяет выбор подходящего алгоритма.
