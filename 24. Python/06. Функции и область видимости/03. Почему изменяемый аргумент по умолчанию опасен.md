# Почему изменяемый аргумент по умолчанию опасен

> [!NOTE]
> Значения параметров по умолчанию вычисляются при выполнении определения функции, а не при каждом вызове. Поэтому list или dict в default может незаметно сохранять состояние между вызовами. Обычно используют None и создают новый контейнер внутри. Когда None — допустимый отдельный ввод, нужен собственный sentinel.

## Вопрос

Что выведут два вызова функции с `items=[]`? Как исправить проблему без потери переданного пустого списка?

## Ловушка

```python
def add(value, items=[]):
    items.append(value)
    return items

print(add(1))  # [1]
print(add(2))  # [1, 2]
```

Оба вызова без второго аргумента используют один объект default. Это не особенность append: та же проблема возникает с dict, set и изменяемыми пользовательскими объектами.

## Нормальное исправление

```python
def add_safe(value, items=None):
    if items is None:
        items = []
    items.append(value)
    return items

print(add_safe(1))  # [1]
print(add_safe(2))  # [2]
existing = []
print(add_safe(3, existing))  # [3]
print(existing)  # [3]
```

Здесь явный переданный list меняется — это часть выбранного контракта. Если нужна чистая функция, верни новый list вместо мутации аргумента.

Не заменяй проверку на `items = items or []`: переданный пустой list тогда будет отброшен, и контракт изменится.

## Default вычисляется один раз даже без мутации

```python
limit = 10
def read_limit(value=limit):
    return value

limit = 20
print(read_limit())  # 10
```

Для текущего времени, случайного значения и пользовательского контекста обычно вычисляют значение при вызове внутри функции, а не в default.

## Когда это намеренно

Сохранённое значение может использоваться сознательно, например для фиксации переменной замыкания. Но неявный кеш в изменяемом default труднее сопровождать, чем явный объект состояния или functools.cache.

## Практика

Исправь функцию `register(name, users={})`. Проверь два независимых вызова и вызов с явно переданным словарём.
