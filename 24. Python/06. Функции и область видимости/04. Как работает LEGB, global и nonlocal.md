# Как работает LEGB, global и nonlocal

> [!NOTE]
> В обычных функциях поиск имени часто описывают правилом LEGB: Local → Enclosing → Global → Builtins. Присваивание имени внутри функции делает его локальным, если не объявлены global/nonlocal. Global относится к модулю, nonlocal — к ближайшей подходящей внешней функции. Не каждая область видимости Python полностью сводится к этой мнемонике: у классов и comprehensions есть особенности.

## Вопрос

Почему чтение переменной перед локальным присваиванием вызывает UnboundLocalError? Чем global отличается от nonlocal?

## Неожиданная локальность

```python
count = 10

def broken():
    print(count)
    count = 20

try:
    broken()
except UnboundLocalError:
    print("count считается локальным во всей функции")
```

Наличие присваивания определяется при анализе функции. Python не выбирает глобальный count только потому, что локальное присваивание ещё не выполнилось.

## Global

```python
count = 0
def increment_global():
    global count
    count += 1

increment_global()
print(count)  # 1
```

Global не означает «общая переменная всех модулей программы». Речь о namespace конкретного модуля. Избыточное общее состояние осложняет тестирование и конкурентную работу.

## Nonlocal

```python
def make_counter():
    count = 0
    def increment():
        nonlocal count
        count += 1
        return count
    return increment

counter = make_counter()
print(counter(), counter())  # 1 2
```

Nonlocal перепривязывает уже существующее имя во внешней функции. Для `items.append(...)` объявление nonlocal не нужно, если сам параметр items не перепривязывается.

## Блоки if/for

Обычный if или for не создаёт отдельную локальную область как let-блок JavaScript. Однако list comprehension имеет собственную область для переменной перебора. Методы класса не получают namespace класса как обычный enclosing scope: для атрибутов используют self или имя класса.

## Практика

Предскажи результат чтения переменной после for и после list comprehension. Объясни разницу мутации list и `items = новый_list` внутри вложенной функции.
