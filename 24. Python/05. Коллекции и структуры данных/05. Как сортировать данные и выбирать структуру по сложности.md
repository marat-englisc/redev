# Как сортировать данные и выбирать структуру по сложности

> [!NOTE]
> `sorted` возвращает новый list из iterable, `list.sort` меняет существующий список и возвращает None. Сортировка стабильная: равные ключи сохраняют относительный порядок. `key` описывает, что сравнивать, и обычно вычисляется один раз на элемент за сортировку. Структуру выбирают по операциям: индекс, поиск по ключу, уникальность или очередь.

## Вопрос

Как отсортировать список словарей и почему сортировка по ключу лучше ручного сравнения? Когда set быстрее list для membership?

## Ключ сортировки

```python
users = [
    {"name": "Anna", "age": 25},
    {"name": "Ivan", "age": 20},
    {"name": "Oleg", "age": 25},
]
ordered = sorted(users, key=lambda user: (user["age"], user["name"]))
print([user["name"] for user in ordered])  # ['Ivan', 'Anna', 'Oleg']
print(users[0]["name"])  # Anna — исходный порядок сохранён
```

Tuple-ключ задаёт сначала возраст, затем имя. Если сортировать только по возрасту, Anna остаётся раньше Oleg благодаря стабильности.

## Стоимость типовых операций

Ориентиры для стандартных коллекций CPython:

| Операция | Обычная оценка |
| --- | --- |
| List по индексу | O(1) |
| Поиск значения в list | O(n) |
| Append в list | Амортизированно O(1) |
| Удаление начала list | O(n) |
| Membership dict/set | В среднем O(1), худший случай хуже |
| Сортировка n элементов | O(n log n) в худшем случае |

Построить set из list тоже стоит времени и памяти. Для одного поиска по трём значениям преобразование необязательно полезно; для тысяч повторных проверок — часто да.

## Top-k

Если нужны только несколько крупнейших значений, полная сортировка может делать лишнюю работу. `heapq.nlargest`/`nsmallest` полезны для соответствующей задачи; для одного максимума хватит max.

```python
from heapq import nlargest

print(nlargest(2, [4, 1, 9, 7]))  # [9, 7]
```

## Частые ошибки

- Присваивать результат `.sort()` обратно переменной.
- Сравнивать несопоставимые типы вроде str и int без модели ключа.
- Ускорять membership через list вместо set, когда важна уникальность.
- Выбирать структуру только по Big O, игнорируя объём и читаемость.

## Практика

Отсортируй записи по статусу, затем времени. Назови структуру для очереди, справочника по id и набора обработанных id.
