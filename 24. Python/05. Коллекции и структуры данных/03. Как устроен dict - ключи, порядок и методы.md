# Как устроен dict - ключи, порядок и методы

> [!NOTE]
> Dict сопоставляет хешируемые ключи со значениями и сохраняет порядок добавления ключей. Поиск обычно имеет среднюю сложность O(1), но не гарантированную для любого случая. `mapping[key]` требует существующий ключ, `get` возвращает значение по умолчанию. Порядок добавления не означает сортировку; равенство обычных dict не зависит от порядка ключей.

## Вопрос

Чем get отличается от обращения по ключу? Почему list нельзя сделать ключом dict?

## Чтение и обновление

```python
user = {"name": "Anna", "age": 25}
print(user["name"])  # Anna
print(user.get("city", "unknown"))  # unknown
user["age"] = 26
user["city"] = "Berlin"
print(list(user))  # ['name', 'age', 'city']
```

Обновление значения не переставляет существующий ключ. После удаления и повторного добавления ключ попадает в конец порядка.

## Отсутствие и None

```python
settings = {"limit": None}
print(settings.get("limit", 10))  # None
print(settings.get("missing", 10))  # 10
```

Default применяется при отсутствии ключа, а не при любом false-like значении. Чтобы различить отсутствие и None, используй `in` или sentinel.

## Хешируемость

Ключ должен иметь стабильный hash и согласованное равенство. Подходят строки, числа, многие tuple и frozenset. List и dict изменяемы и не хешируемы. При равенстве ключей значения объединяются:

```python
data = {True: "first", 1: "second"}
print(len(data))  # 1
print(data[True])  # second
```

`True == 1` и их hash согласованы. Типовой ввод id, где bool недопустим, нужно валидировать отдельно.

## Представления и объединение

Keys/items/values — динамические views, а не независимые списки. Не меняй размер словаря при обходе view.

```python
defaults = {"limit": 10, "mode": "safe"}
custom = {"limit": 5}
merged = defaults | custom
print(merged)  # {'limit': 5, 'mode': 'safe'}
```

Это поверхностное объединение: при совпадении ключа справа побеждает.

## Практика

Построй id → запись из списка. Реши, нужно ли обнаруживать повторный id вместо молчаливой перезаписи.
