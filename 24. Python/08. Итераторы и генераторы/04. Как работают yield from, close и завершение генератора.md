# Как работают yield from, close и завершение генератора

> [!NOTE]
> `yield from` делегирует генератору или другому iterable выдачу элементов и часть протокола взаимодействия. Для обычного перебора это удобнее ручного цикла с yield. Генератор можно завершить через close, что позволяет выполнить finally у уже запущенного генератора. Однако очистку ресурса лучше делать с явным управлением временем жизни, а не полагаться на сборщик мусора.

## Вопрос

Для чего yield from и как освободить ресурс при досрочном прекращении обхода?

## Делегирование

```python
def flatten_one_level(groups):
    for group in groups:
        yield from group

print(list(flatten_one_level([[1, 2], [3]])))  # [1, 2, 3]
```

Это разворачивает один уровень, а не произвольно глубокую структуру. Строка как group тоже iterable и выдаст символы — допустимый вход нужно определить заранее.

## Очистка

```python
from contextlib import closing

def records():
    try:
        yield 1
        yield 2
    finally:
        print("cleanup")

with closing(records()) as stream:
    print(next(stream))  # 1
# cleanup при выходе из with
```

Обычный break завершает цикл, но не является универсальной командой close для любого iterator. Если generator сохранили в переменной, он может оставаться приостановленным.

## Return и send

В generator `return value` завершает обход и помещает value в StopIteration; это не очередной элемент. В делегировании `result = yield from subgenerator()` может получить такое возвращённое значение.

`send(value)` продолжает generator и передаёт значение в приостановленное yield-выражение. Перед первой отправкой ненулевого значения генератор нужно запустить. Для большинства прикладных задач простой iterator понятнее такого двустороннего протокола.

## Что важно помнить

- Не выбрасывай StopIteration вручную из тела generator для обычного завершения: используй return.
- Close не выполнит уже никогда не начатое тело генератора как обычный вызов функции.
- После закрытия генератор не перезапускается.
- Управление открытым файлом вокруг самого потребления часто проще скрытого ресурса внутри generator.

## Практика

Прочитай один элемент и вызови close, затем попробуй next с default. Сравни с полным потреблением через list.
