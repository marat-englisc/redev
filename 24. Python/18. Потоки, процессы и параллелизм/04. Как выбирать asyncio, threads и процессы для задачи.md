# Как выбирать asyncio, threads и процессы для задачи

> [!NOTE]
> Выбор модели зависит от узкого места и API зависимостей. Asyncio удобно для неблокирующих I/O-интерфейсов, threads — для ограниченной конкуренции синхронного I/O, процессы — для подходящих CPU-задач и изоляции памяти. Пул не ускоряет работу автоматически: нужны предел конкуренции, контроль ошибок, порядок результатов и политика завершения.

## Вопрос

Что выбрать для загрузки файлов, запросов к API и тяжёлого преобразования? Чем map отличается от as_completed?

## Небольшой thread pool

```python
from concurrent.futures import ThreadPoolExecutor, as_completed

def load(identifier):
    return identifier * 10  # место синхронной I/O-операции в приложении

with ThreadPoolExecutor(max_workers=2) as pool:
    futures = {pool.submit(load, value): value for value in [1, 2, 3]}
    results = {}
    for future in as_completed(futures):
        identifier = futures[future]
        results[identifier] = future.result()

print(sorted(results.items()))  # [(1, 10), (2, 20), (3, 30)]
```

As_completed выдаёт по фактическому завершению, map сохраняет порядок входа. Медленная первая задача может задержать чтение уже готовых более поздних результатов через map.

## Матрица выбора

| Характер работы | Начальная гипотеза |
| --- | --- |
| HTTP-клиент с async API | asyncio |
| Небольшое число вызовов sync-клиента | ThreadPoolExecutor |
| Тяжёлый чистый Python-расчёт | ProcessPoolExecutor |
| Один короткий расчёт | Обычный последовательный код |

Нативная библиотека может иметь собственный пул и освобождать GIL; несколько уровней параллелизма иногда только перегружают CPU.

## Ограничение нагрузки

Max_workers ограничивает работающие workers, а не обязательно количество отправленных задач. В Python 3.12 executor.map заранее потребляет входные iterable. Для большого потока организуй ограниченную очередь/окно отправки или используй документированные возможности своей версии.

## Ошибки и отмена

Получай каждый результат, задавай timeouts реальному I/O и закрывай executor. Cancel для уже исполняющейся работы имеет ограничения; нельзя считать его полноценным rollback внешнего действия.

## Практика

Для трёх сценариев — ожидание HTTP, подсчёт хешей больших файлов, чистый Python-парсер — перечисли ожидаемые bottlenecks и измерение, которое проверит выбор модели.
