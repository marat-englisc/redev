# Как писать тесты pytest и параметризацию

> [!NOTE]
> Pytest находит тестовые функции в test_*.py или *_test.py и выполняет проверки assert с понятной диагностикой. Параметризация запускает один сценарий для нескольких входов. Тест должен проверять наблюдаемый контракт, а не копировать алгоритм реализации. Для запуска используй Python того же окружения, где установлены приложение и pytest.

## Вопрос

Как проверить обычный результат, границу и ошибочный вход без дублирования тестов?

## Функция и тесты

Файл `test_discount.py`:

```python
import pytest

def discounted_price(price: int, percent: int) -> int:
    if price < 0 or not 0 <= percent <= 100:
        raise ValueError("invalid discount input")
    return price * (100 - percent) // 100

@pytest.mark.parametrize(
    ("price", "percent", "expected"),
    [(100, 0, 100), (100, 20, 80), (100, 100, 0), (0, 20, 0)],
)
def test_discount(price, percent, expected):
    assert discounted_price(price, percent) == expected

def test_negative_price():
    with pytest.raises(ValueError, match="invalid discount"):
        discounted_price(-1, 20)
```

```bash
python -m pytest -q
```

Правило округления в примере — целочисленное вниз; для реальной цены его определяет домен. Тесты делают это поведение явным, а не доказывают универсальную финансовую корректность.

## Assert в тесте

Обычный assert уместен как проверка теста. Это отличается от обязательной runtime-валидации пользовательского ввода, для которой нужен if/raise. Не запускай приложение в режиме, где его корректность зависит от включённых assert.

## Полезный набор

Покрой обычный случай, нижнюю/верхнюю границу, пустой вход, неверный формат и ожидаемое исключение. Не нужно перебирать тысячи одинаковых чисел, если они не проверяют новое свойство.

## Частые ошибки

- Название теста говорит о реализации, а не о поведении.
- Ожидаемый результат вычисляется тем же кодом, что тестируемая функция.
- Один тест проверяет много независимых сценариев и мешает понять отказ.
- Тест требует живого внешнего API для чистого расчёта.

## Практика

Добавь проверки процентов -1 и 101. Для будущей смены округления сначала сформулируй новый контракт и обнови значимые тесты.
