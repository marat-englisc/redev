# Как выбирать unit, интеграционные тесты и граничные случаи

> [!NOTE]
> Unit-тест проверяет небольшой контракт с управляемыми зависимостями, интеграционный — совместную работу реальных компонентов, E2E — пользовательский путь через систему. Эти уровни дополняют друг друга. Для Python особенно полезно отдельно проверять формат внешних данных, отсутствие значения, пустые коллекции, исключения и побочные эффекты.

## Вопрос

Что проверит тест с mock-БД и чего он не докажет? Как подобрать небольшой, но полезный набор сценариев?

## Пример контракта

```python
def positive_identifier(value):
    if type(value) is not int or value <= 0:
        raise ValueError("expected a positive integer")
    return value
```

Тестирование:

```python
import pytest

def positive_identifier(value):
    if type(value) is not int or value <= 0:
        raise ValueError("expected a positive integer")
    return value

@pytest.mark.parametrize("value", [None, True, False, 0, -1, "7", 1.5])
def test_rejects_invalid_identifier(value):
    with pytest.raises(ValueError):
        positive_identifier(value)

def test_accepts_identifier():
    assert positive_identifier(7) == 7
```

Bool включён намеренно: isinstance(True, int) возвращает True. В реальном проекте реализацию импортируют из пакета; здесь она повторена, чтобы тестовый пример был самостоятельным.

## Уровни для загрузчика данных

| Уровень | Что проверять |
| --- | --- |
| Unit | Преобразование записи и ошибки схемы |
| Integration | CSV-парсер, реальный SQL и ограничения SQLite/PostgreSQL |
| E2E | CLI получает файл, возвращает exit code и создаёт ожидаемый отчёт |

Mock соединения не докажет, что SQL исполняется и transaction rollback действительно работает.

## Детерминизм

Время, случайность и внешние сервисы делают тесты нестабильными. Управляй ими через зависимости, seeded-генератор для симуляции или fake. Не проверяй скорость короткой операции жёстким порогом на любой машине без обоснования.

## Практика

Для загрузки JSONL составь три unit-сценария, один интеграционный и один CLI-сценарий. Для каждого напиши, какую реальную ошибку он обнаружит.
