# Как работают наследование, super и MRO

> [!NOTE]
> Наследование позволяет подклассу использовать и уточнять поведение базового класса. MRO задаёт порядок поиска методов, а super продолжает поиск после текущего класса в этой последовательности. Super — не просто синоним «вызвать непосредственного родителя»: это особенно важно при множественном наследовании. Для композиции возможностей наследование не всегда лучший выбор.

## Вопрос

Что делает super? В каком порядке ищется метод при ромбовидном наследовании?

## Простое расширение

```python
class User:
    def __init__(self, name):
        self.name = name

class Admin(User):
    def __init__(self, name, permissions):
        super().__init__(name)
        self.permissions = permissions

admin = Admin("Anna", {"read"})
print(admin.name)  # Anna
print(isinstance(admin, User))  # True
```

Если подкласс определил свой __init__, инициализация базы не вызывается автоматически. Необходимо явно организовать нужную цепочку.

## Порядок методов

```python
class A:
    def name(self):
        return "A"

class B(A):
    def name(self):
        return "B" + super().name()

class C(A):
    def name(self):
        return "C" + super().name()

class D(B, C):
    pass

print(D().name())  # BCA
print([cls.__name__ for cls in D.__mro__])  # ['D', 'B', 'C', 'A', 'object']
```

В B super продолжил поиск через C, а не прямо A. Это объясняет cooperative multiple inheritance.

## Совместимый контракт

Для цепочки super методы должны согласованно принимать и передавать аргументы. Жёсткие вызовы `A.method(self)` способны дважды выполнить часть инициализации или обойти другой класс.

Подкласс должен сохранять ожидаемый контракт базы. Наследник, который запрещает ранее допустимый вызов или неожиданно меняет смысл результата, затрудняет заменяемость.

## Практика

Предскажи результат D().name до запуска. Затем замени порядок баз на C, B и объясни изменение по __mro__, не запоминая ответ.
