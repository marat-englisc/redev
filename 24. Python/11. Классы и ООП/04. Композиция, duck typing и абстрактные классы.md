# Композиция, duck typing и абстрактные классы

> [!NOTE]
> Композиция строит объект из сотрудничающих объектов вместо глубокой иерархии. Duck typing использует нужное поведение без обязательного общего предка. ABC с abstractmethod задаёт явный номинальный интерфейс и не даёт создать экземпляр с нереализованными абстрактными методами. Статический структурный контракт можно описать Protocol, который разберём в типизации.

## Вопрос

Как заменить отправку уведомлений без наследования всего сервиса? Чем duck typing отличается от ABC?

## Зависимость от поведения

```python
class ConsoleSender:
    def send(self, message):
        print(message)

class NotificationService:
    def __init__(self, sender):
        self.sender = sender

    def welcome(self, name):
        self.sender.send(f"Welcome, {name}")

service = NotificationService(ConsoleSender())
service.welcome("Anna")  # Welcome, Anna
```

Сервису важно наличие send с подходящим смыслом. Для теста можно передать fake, который сохраняет сообщения, а не отправляет их.

## Явный абстрактный контракт

```python
from abc import ABC, abstractmethod

class Sender(ABC):
    @abstractmethod
    def send(self, message):
        raise NotImplementedError

class MemorySender(Sender):
    def __init__(self):
        self.messages = []

    def send(self, message):
        self.messages.append(message)

sender = MemorySender()
sender.send("hello")
print(sender.messages)  # ['hello']
```

Попытка создать Sender или наследника без реализации send вызовет TypeError. Проверка ABC не гарантирует правильность бизнес-поведения метода.

## Как выбирать

Наследование уместно для отношения «является разновидностью» с совместимым контрактом. Композиция — для отношения «использует» и замены стратегии. Не создавай базовый класс только ради одного общего helper: иногда нужна обычная функция.

## Практика

Передай MemorySender в NotificationService и проверь накопленное сообщение. Опиши, как это позволяет тестировать сервис без сети и секретов.
