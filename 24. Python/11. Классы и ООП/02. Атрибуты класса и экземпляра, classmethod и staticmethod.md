# Атрибуты класса и экземпляра, classmethod и staticmethod

> [!NOTE]
> Атрибут класса принадлежит классу и может быть виден через экземпляры; обычное присваивание self.attr создаёт или меняет атрибут экземпляра. Classmethod получает класс в cls и удобен для альтернативного конструктора. Staticmethod не получает ни self, ни cls: это функция, размещённая в namespace класса по смыслу задачи.

## Вопрос

Почему список в теле class общий для экземпляров? Когда нужен classmethod вместо staticmethod?

## Общий и независимый state

```python
class BadCart:
    items = []

a = BadCart()
b = BadCart()
a.items.append("book")
print(b.items)  # ['book']
```

Обращение нашло общий list в классе, append изменил его. Для независимых корзин создавай `self.items = []` в __init__.

## Альтернативный конструктор

```python
class User:
    category = "member"

    def __init__(self, name):
        self.name = name

    @classmethod
    def from_record(cls, record):
        return cls(record["name"])

    @staticmethod
    def normalize_name(name):
        return name.strip()

user = User.from_record({"name": "Anna"})
print(user.name, user.category)  # Anna member
print(User.normalize_name(" Anna "))  # Anna
```

Cls позволяет конструктору учитывать реальный класс при наследовании. Жёсткий `return User(...)` всегда создавал бы User, что иногда нарушает ожидание подкласса.

## Затенение атрибута

```python
user.category = "admin"
print(user.category)  # admin
print(User.category)  # member
```

Обычный новый атрибут экземпляра затенил значение класса; сам класс не изменился. Properties и другие дескрипторы добавляют к этой простой модели правила доступа.

## Как выбирать

- Нужны поля конкретного объекта — instance method.
- Нужен класс и полиморфное создание — classmethod.
- Нужна связанная утилита без состояния — staticmethod или отдельная функция.

## Практика

Сделай Product.from_record и сравни с отдельной функцией парсинга. Объясни, нужен ли ей доступ к cls, или staticmethod только усложнит структуру.
