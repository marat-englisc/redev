# Как работают if, условное выражение и match

> [!NOTE]
> If/elif/else выбирает ветку по условию. Условное выражение `a if condition else b` возвращает одно из значений. Match сопоставляет значение со структурным шаблоном, а не просто заменяет любой switch. Обычное имя в case может захватить значение; для wildcard используют `_`, а сложные условия добавляют через guard.

## Вопрос

Когда использовать if, а когда match? Почему `case name` не сравнивает с переменной name?

## Обычный выбор

```python
score = 75
if score >= 90:
    grade = "excellent"
elif score >= 60:
    grade = "passed"
else:
    grade = "retry"
print(grade)  # passed

label = "adult" if 20 >= 18 else "child"
print(label)  # adult
```

Выполняется первая подходящая ветка. Длинную вложенную цепочку условных выражений лучше заменить обычным if: короткая запись не всегда яснее.

## Структурный match

```python
def describe(event):
    match event:
        case {"type": "created", "id": int(item_id)} if item_id > 0:
            return f"created:{item_id}"
        case {"type": "deleted", "id": item_id}:
            return f"deleted:{item_id}"
        case _:
            return "unknown"

print(describe({"type": "created", "id": 7}))  # created:7
```

Шаблон dict проверяет требуемые ключи; дополнительные ключи могут быть допустимы. `int(item_id)` здесь — class pattern, а не преобразование строки в int. Guard выполняется после сопоставления.

## Ловушка захвата

Одиночное `case expected` обычно **связывает имя**, а не сравнивает с заранее вычисленной переменной. Для сравнения с внешним значением используй if, guard или корректный value pattern с квалифицированным именем, например enum-членом.

Match появился в Python 3.10. Для простого диапазона чисел if обычно понятнее, для вариантов события с разной структурой match может быть удобнее.

## Практика

Опиши события `created`, `deleted`, неизвестный тип и created с отрицательным id. Объясни, почему совпадение структуры ещё не заменяет полную валидацию внешнего JSON.
