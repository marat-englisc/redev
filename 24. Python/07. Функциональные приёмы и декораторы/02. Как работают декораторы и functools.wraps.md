# Как работают декораторы и functools.wraps

> [!NOTE]
> Декоратор получает объект функции и возвращает объект, который будет связан с её именем. `@decorate` эквивалентен `function = decorate(function)` после создания функции. Обёртка может добавить поведение до и после вызова. Functools.wraps переносит важные метаданные и связывает __wrapped__, но не делает любую обёртку корректной автоматически.

## Вопрос

Как написать декоратор, который сохраняет аргументы, результат и имя исходной функции?

## Пример

```python
from functools import wraps

def traced(function):
    @wraps(function)
    def wrapper(*args, **kwargs):
        print(f"calling {function.__name__}")
        return function(*args, **kwargs)
    return wrapper

@traced
def add(left, right):
    """Складывает два значения."""
    return left + right

print(add(2, right=3))  # calling add, затем 5
print(add.__name__)  # add
```

Без return внутри wrapper вызывающий код получил бы None. Без kwargs часть корректных вызовов исходной функции перестала бы работать.

## Когда что выполняется

```text
определение функции → вызов декоратора → имя получает wrapper
вызов add(...) → wrapper → исходная функция → результат
```

Сам декоратор выполняется при определении, часто при импорте модуля. Код внутри wrapper — при каждом вызове.

## Несколько декораторов

Для `@first` над `@second` замена выглядит как `first(second(function))`. Порядок влияет на кеширование, авторизацию и логирование, поэтому не меняй его без понимания.

## Что важно помнить

- Декоратор не обязательно оборачивает функцию: он может регистрировать её или возвращать другой callable.
- Wraps сохраняет метаданные, но не отменяет реальные побочные эффекты.
- Для async-функции обычно нужна async-обёртка с await: синхронная обёртка не охватывает выполнение coroutine так же.
- Логирование аргументов способно раскрыть токены и персональные данные.

## Практика

Добавь счётчик вызовов, проверь возврат значения и вызов с keyword-аргументом. Объясни, где хранится состояние счётчика.
