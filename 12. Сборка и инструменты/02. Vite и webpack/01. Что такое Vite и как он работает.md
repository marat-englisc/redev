# Что такое Vite и как он работает

> [!NOTE]
> **Vite** — инструмент сборки и dev-сервер, стандарт для новых фронтенд-проектов вне Next.js. В режиме разработки Vite **не бандлит код приложения**: браузер запрашивает нативные ES-модули, а Vite трансформирует каждый файл по запросу (TS, JSX, CSS) — поэтому старт почти мгновенный независимо от размера проекта. Зависимости из `node_modules` один раз **предварительно бандлятся** через esbuild. Для production Vite делает полноценную оптимизированную сборку через Rollup (в новых версиях — Rolldown).

## Вопрос

Что такое Vite и почему он быстрее webpack в разработке? Как устроены dev-режим и production-сборка?

## Создание проекта

```bash
npm create vite@latest my-app -- --template react-ts
```

```text
my-app/
  index.html          ← точка входа — HTML, а не JS
  src/main.tsx
  vite.config.ts
  public/             ← файлы копируются как есть
```

```html
<!-- index.html -->
<div id="root"></div>
<script type="module" src="/src/main.tsx"></script>
```

## Dev-режим

```text
Браузер: GET /src/main.tsx
  → Vite: esbuild/oxc трансформирует TSX → JS (без проверки типов)
  → ответ: import { createRoot } from "/node_modules/.vite/deps/react-dom_client.js"
Браузер: GET /src/App.tsx → трансформация по запросу …
```

- **pre-bundling зависимостей**: CommonJS-пакеты превращаются в ESM, сотни файлов `lodash-es` — в один, результат кешируется в `node_modules/.vite`;
- **трансформация по запросу**: обрабатываются только файлы, которые реально открыл браузер;
- **HMR** через WebSocket: при изменении файла заменяется только этот модуль, состояние React сохраняется (React Fast Refresh).

## Production-сборка

```bash
npm run build      # vite build → dist/
npm run preview    # локальный сервер для проверки dist
```

- полный бандлинг через Rollup: tree shaking, разбиение на чанки, минификация (esbuild), хеши в именах;
- CSS извлекается в файлы, для ленивых чанков подключается автоматически;
- `<link rel="modulepreload">` для нужных сразу чанков.

## Почему Vite быстрый

| | webpack (классический) | Vite |
| --- | --- | --- |
| Старт dev-сервера | бандлит всё приложение | почти сразу, без бандлинга |
| Изменение файла | пересборка затронутых чанков | трансформация одного модуля |
| Транспиляция | Babel/ts-loader (JS) | esbuild/oxc (нативный код) |
| Конфигурация | много loaders и plugins | разумные значения по умолчанию |

## Что Vite не делает

- **не проверяет типы** TypeScript — для этого `tsc --noEmit` в скрипте или плагин `vite-plugin-checker`;
- не заменяет фреймворк: роутинг и SSR берут из React Router, TanStack Start или используют Vite как основу (Remix, Astro, SvelteKit, Nuxt построены на Vite).

## Что важно помнить

- Различие dev (ESM без бандла) и prod (Rollup-бандл) иногда дает разное поведение — проверяйте `vite preview` перед релизом.
- В dev на холодном старте может быть много запросов модулей — это нормально, они кешируются.
- Плагины Vite совместимы с экосистемой Rollup.
- Vitest использует ту же конфигурацию и трансформации, что и Vite.
- Связанные темы: [настройка Vite](<02. Как настроить Vite - плагины, alias, proxy.md>), [HMR](<04. Как работает HMR.md>).

## Мини-шпаргалка

Vite: dev — нативный ESM, трансформация по запросу, pre-bundling зависимостей esbuild, HMR + Fast Refresh. Prod — Rollup/Rolldown: tree shaking, чанки, минификация, хеши. Типы не проверяет — `tsc --noEmit`. Точка входа — `index.html`.
