# Чем отличаются Vite, webpack, Rspack, Turbopack, esbuild и Rollup

> [!NOTE]
> Инструменты сборки делятся на **полноценные сборщики приложений** (Vite, webpack, Rspack, Turbopack, Parcel), **низкоуровневые бандлеры** (Rollup, Rolldown, esbuild) и **транспиляторы** (Babel, SWC, oxc, tsc). Тенденция последних лет — переход на инструменты, написанные на **Rust и Go**, которые в 10–100 раз быстрее JavaScript-аналогов. Для нового SPA обычно выбирают **Vite**, для Next.js — встроенный **Turbopack**, для большого legacy на webpack — миграцию на **Rspack**, для библиотек — **tsup/tsdown** или **Rollup**.

## Вопрос

Чем отличаются Vite, webpack, Rspack, Turbopack, esbuild и Rollup? Какой инструмент выбрать для приложения, а какой — для библиотеки?

## Сравнение

| Инструмент | Язык | Роль | Особенности |
| --- | --- | --- | --- |
| **Vite** | TS + esbuild/Rollup/Rolldown | сборщик приложений + dev-сервер | ESM в dev, огромная экосистема плагинов, основа многих фреймворков |
| **webpack** | JS | сборщик приложений | максимум гибкости, loaders и plugins, медленный на больших проектах |
| **Rspack** | Rust | совместимая замена webpack | те же конфиги, большинство loaders и plugins, в разы быстрее |
| **Turbopack** | Rust | сборщик Next.js | инкрементальные вычисления, встроен в Next.js |
| **Parcel** | Rust + JS | сборщик без конфигурации | «просто работает», меньше гибкости |
| **Rollup** | JS | бандлер ESM, библиотеки | лучший tree shaking и формат вывода, prod-сборка Vite |
| **Rolldown** | Rust | быстрая замена Rollup | будущее ядро Vite |
| **esbuild** | Go | бандлер и транспилятор | очень быстрый, используется внутри Vite и tsup |
| **SWC / oxc** | Rust | транспиляторы | замена Babel: Next.js, Vite-плагины, Rspack |
| **Babel** | JS | транспилятор | максимум плагинов, медленнее |
| **tsc** | TS | компилятор TypeScript | проверка типов и генерация `.d.ts` |

## Что выбрать

| Задача | Инструмент |
| --- | --- |
| Новое SPA на React | Vite |
| Приложение на Next.js | встроенный сборщик (Turbopack) |
| Большой проект на webpack, медленная сборка | Rspack (миграция с минимальными изменениями) |
| Библиотека / npm-пакет | tsup (esbuild), tsdown (Rolldown), Rollup, Vite library mode |
| Скрипт или утилита на TypeScript | esbuild, tsx, нативный запуск TS в Node.js |
| Монорепозиторий | Vite/Rspack в приложениях + Turborepo/Nx для оркестрации задач |

## Как отвечать на собеседовании

> «Сборка состоит из транспиляции, построения графа модулей, tree shaking, разбиения на чанки и минификации. webpack делает это гибко через loaders и plugins, но медленно на больших проектах. Vite в разработке не бандлит код, а отдает ESM по запросу, поэтому стартует мгновенно, а для продакшена собирает через Rollup. Сейчас инструменты переходят на Rust: Rspack, Turbopack, Rolldown, SWC.»

## Что важно помнить

- Бандлер ≠ транспилятор: esbuild и SWC умеют транспилировать быстро, но **не проверяют типы** — это делает `tsc --noEmit`.
- Скорость dev-сервера и скорость production-сборки — разные метрики; Vite быстр в первой благодаря архитектуре, Rust-инструменты — в обеих.
- Для библиотек важен формат вывода (ESM, CJS, `.d.ts`, `exports`), а не dev-сервер.
- Выбор фреймворка обычно определяет сборщик: Next.js, Nuxt, SvelteKit, Astro, Angular CLI.

## Мини-шпаргалка

Приложения: Vite (стандарт), webpack (legacy, гибкость), Rspack (быстрый webpack), Turbopack (Next.js). Бандлеры: Rollup/Rolldown (библиотеки, prod Vite), esbuild (скорость). Транспиляторы: Babel, SWC, oxc; типы — только `tsc`. Библиотеки — tsup/tsdown.
