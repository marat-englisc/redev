# Как настроить Vite: плагины, alias, proxy

> [!NOTE]
> Конфигурация Vite лежит в `vite.config.ts` и экспортирует объект через `defineConfig`. Самые частые настройки: **плагины** (React, SVG как компоненты, PWA), **alias** путей (`@/` → `src/`), **proxy** dev-сервера к бэкенду (обход CORS локально), параметры **build** (чанки, source maps, целевые браузеры), **css** (CSS Modules, препроцессоры) и **env**-переменные. Конфиг может зависеть от режима: `defineConfig(({ mode }) => ({ ... }))`.

## Вопрос

Как настроить Vite в React-проекте? Как подключить плагины, настроить алиасы путей, проксирование API и параметры production-сборки?

## Типичный конфиг

```typescript
// vite.config.ts
import { defineConfig, loadEnv } from "vite";
import react from "@vitejs/plugin-react";
import svgr from "vite-plugin-svgr";
import { fileURLToPath, URL } from "node:url";

export default defineConfig(({ mode }) => {
  const env = loadEnv(mode, process.cwd(), "");      // env-переменные внутри конфига

  return {
    plugins: [react(), svgr()],

    resolve: {
      alias: {
        "@": fileURLToPath(new URL("./src", import.meta.url)),
      },
    },

    server: {
      port: 5173,
      proxy: {
        "/api": {
          target: env.API_URL ?? "http://localhost:3000",
          changeOrigin: true,
          // rewrite: (path) => path.replace(/^\/api/, ""),
        },
      },
    },

    css: {
      modules: { localsConvention: "camelCaseOnly" },
    },

    build: {
      target: "es2022",
      sourcemap: "hidden",
      chunkSizeWarningLimit: 500,
    },
  };
});
```

Алиас нужно продублировать для TypeScript:

```json
// tsconfig.json
{ "compilerOptions": { "baseUrl": ".", "paths": { "@/*": ["src/*"] } } }
```

(или использовать плагин `vite-tsconfig-paths`, который берет пути из tsconfig).

## Proxy

```text
Браузер → http://localhost:5173/api/users  (тот же origin — CORS не нужен)
Vite dev server → http://localhost:3000/api/users
```

Proxy работает **только в dev**. В production то же делает nginx, CDN или BFF.

## Полезные плагины

| Плагин | Для чего |
| --- | --- |
| `@vitejs/plugin-react` / `-react-swc` | JSX, Fast Refresh |
| `vite-plugin-svgr` | импорт SVG как React-компонента |
| `vite-plugin-pwa` | Service Worker и manifest |
| `vite-plugin-checker` | TypeScript и ESLint в dev-сервере |
| `rollup-plugin-visualizer` | анализ размера бандла |
| `@sentry/vite-plugin` | загрузка source maps |
| `vite-tsconfig-paths` | алиасы из tsconfig |

## Импорт ассетов

```typescript
import logoUrl from "./logo.png";              // URL файла с хешем
import Logo from "./logo.svg?react";           // компонент (svgr)
import rawText from "./README.md?raw";         // содержимое строкой
import Worker from "./heavy.worker.ts?worker"; // Web Worker
const icons = import.meta.glob("./icons/*.svg", { eager: true }); // массовый импорт
```

Файлы из `public/` доступны по корневому пути (`/favicon.svg`) и не хешируются.

## Что важно помнить

- `vite.config.ts` выполняется в Node.js; `import.meta.env` клиента там недоступен — используйте `loadEnv`.
- Proxy — только для разработки; не полагайтесь на него в production.
- Алиас должен быть настроен и в Vite, и в TypeScript (и в Vitest, если конфиг отдельный).
- `base` задает публичный путь, если приложение отдается не из корня (`/app/`).
- Связанные темы: [переменные окружения](<05. Как работают переменные окружения и режимы сборки.md>), [source maps](<../01. Основы сборки/03. Что такое source maps.md>).

## Мини-шпаргалка

`defineConfig(({ mode }) => ({ plugins, resolve.alias, server.proxy, css, build }))`. Алиас `@` → `src` + `paths` в tsconfig. Proxy `/api` — только dev. Плагины: react, svgr, pwa, checker, visualizer, sentry. Ассеты: `?url`, `?raw`, `?react`, `?worker`, `import.meta.glob`.
