# Что такое semver и как обновлять зависимости

> [!NOTE]
> **Semantic Versioning (semver)** — формат версий `MAJOR.MINOR.PATCH`: **major** — несовместимые изменения, **minor** — новые возможности без поломок, **patch** — исправления. В `package.json` зависимость задается **диапазоном**: `^1.4.2` разрешает обновления до `<2.0.0`, `~1.4.2` — до `<1.5.0`, `1.4.2` — только эту версию. Точные установленные версии фиксирует lockfile. Обновлять зависимости нужно регулярно и небольшими шагами — с автоматизацией (Renovate, Dependabot), тестами и чтением changelog для major-версий.

## Вопрос

Что такое semver? Чем отличаются `^`, `~` и точная версия и как безопасно обновлять зависимости в проекте?

## Формат версии

```text
  2  .  5  .  3  -beta.1
major minor patch  prerelease
```

| Изменение | Пример | Совместимость |
| --- | --- | --- |
| patch | 2.5.3 → 2.5.4 | исправления, API не меняется |
| minor | 2.5.3 → 2.6.0 | новые возможности, старый код работает |
| major | 2.5.3 → 3.0.0 | возможны breaking changes |
| prerelease | 3.0.0-beta.1 | не устанавливается диапазонами по умолчанию |

Версии `0.x` особенные: в `0.y.z` любое изменение minor может ломать API, и `^0.5.2` разрешает только `<0.6.0`.

## Диапазоны

| Запись | Разрешенные версии |
| --- | --- |
| `^1.4.2` | `>=1.4.2 <2.0.0` (по умолчанию в `npm install`) |
| `~1.4.2` | `>=1.4.2 <1.5.0` |
| `1.4.2` | только 1.4.2 |
| `>=1.4.0 <2` | явный диапазон |
| `*` / `latest` | любая — опасно |
| `^0.5.2` | `>=0.5.2 <0.6.0` |

Lockfile делает установку воспроизводимой независимо от диапазона: `npm ci` ставит ровно то, что записано.

## Как обновлять

```bash
npm outdated                    # что устарело
npx npm-check-updates -i        # интерактивное обновление диапазонов
npm update                      # обновить в пределах диапазонов
npm install react@latest        # конкретный пакет до последней версии
npm audit                       # известные уязвимости
```

Процесс для major-версии:

1. Прочитать changelog и migration guide.
2. Обновить один пакет (или связанную группу: `react` + `react-dom` + `@types/react`).
3. Запустить typecheck, линтер, тесты, e2e.
4. Проверить вручную ключевые сценарии и размер бандла.
5. Отдельный PR — легко откатить.

## Автоматизация

```json
// renovate.json
{
  "extends": ["config:recommended"],
  "schedule": ["before 9am on monday"],
  "packageRules": [
    { "matchUpdateTypes": ["patch", "minor"], "groupName": "non-major", "automerge": true },
    { "matchPackageNames": ["react", "react-dom", "@types/react", "@types/react-dom"], "groupName": "react" }
  ],
  "minimumReleaseAge": "3 days"
}
```

- Renovate или Dependabot создают PR с обновлениями;
- patch и minor можно автоматически сливать при зеленом CI;
- задержка перед установкой новой версии (`minimumReleaseAge`) защищает от только что опубликованных вредоносных версий.

## Конфликты и дубликаты

```bash
npm ls react             # дерево: где какие версии
npm dedupe               # убрать дубликаты, если диапазоны позволяют
```

```json
// package.json — принудительная версия транзитивной зависимости
{ "overrides": { "semver": "^7.6.0" } }      // npm; pnpm — "pnpm.overrides", yarn — "resolutions"
```

`peerDependencies` — зависимость, которую должен установить проект-хозяин (например, `react` для UI-библиотеки), чтобы не было двух копий.

## Что важно помнить

- `^` безопасен только если пакет честно следует semver; lockfile защищает от неожиданностей.
- Обновляйтесь регулярно маленькими шагами — накопленный год обновлений превращается в дорогую миграцию.
- Две копии React в бандле ломают хуки («Invalid hook call») — проверяйте `npm ls react`.
- Коммитьте lockfile, в CI — `npm ci`.

## Мини-шпаргалка

semver: MAJOR (ломает) . MINOR (добавляет) . PATCH (исправляет). `^1.4.2` → `<2.0.0`, `~1.4.2` → `<1.5.0`, `^0.5.2` → `<0.6.0`. Lockfile — точные версии. Обновление: `outdated`, changelog, по одному, тесты, отдельный PR. Renovate/Dependabot, `overrides`, `dedupe`, `peerDependencies`.
