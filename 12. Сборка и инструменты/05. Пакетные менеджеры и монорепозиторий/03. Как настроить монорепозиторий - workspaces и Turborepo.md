# Как настроить монорепозиторий: workspaces и Turborepo

> [!NOTE]
> **Монорепозиторий** — один Git-репозиторий с несколькими приложениями и пакетами. Технически он строится из двух частей: **workspaces** пакетного менеджера (npm, pnpm, yarn) связывают локальные пакеты между собой без публикации в npm, а **оркестратор задач** (Turborepo, Nx) запускает `build`, `lint`, `test` в правильном порядке по графу зависимостей, параллельно, с **кешированием** результатов и только для **затронутых** пакетов.

## Вопрос

Как настроить монорепозиторий для фронтенда? Как связать пакеты через workspaces и ускорить сборку с Turborepo?

## Структура

```text
my-monorepo/
  package.json
  pnpm-workspace.yaml
  turbo.json
  apps/
    web/          Next.js
    admin/        Vite + React
  packages/
    ui/           дизайн-система
    utils/
    eslint-config/
    tsconfig/
```

## Workspaces (pnpm)

```yaml
# pnpm-workspace.yaml
packages:
  - "apps/*"
  - "packages/*"
```

```json
// packages/ui/package.json
{
  "name": "@acme/ui",
  "version": "0.0.0",
  "private": true,
  "type": "module",
  "exports": { ".": "./src/index.ts" },
  "peerDependencies": { "react": "^19.0.0" }
}
```

```json
// apps/web/package.json
{ "dependencies": { "@acme/ui": "workspace:*" } }
```

```bash
pnpm install                              # связать все пакеты
pnpm --filter web dev                     # команда в одном пакете
pnpm --filter "@acme/ui" add clsx         # зависимость в пакет
pnpm -r build                             # во всех пакетах
```

`workspace:*` — всегда локальная версия пакета. Внутренние пакеты можно отдавать **исходниками** (`exports` на `.ts`, приложение само транспилирует) или **собранными** (`dist`).

## Turborepo

```json
// turbo.json
{
  "$schema": "https://turborepo.com/schema.json",
  "tasks": {
    "build": {
      "dependsOn": ["^build"],             // сначала собрать зависимости пакета
      "outputs": ["dist/**", ".next/**", "!.next/cache/**"]
    },
    "lint": {},
    "typecheck": { "dependsOn": ["^typecheck"] },
    "test": { "outputs": ["coverage/**"] },
    "dev": { "cache": false, "persistent": true }
  }
}
```

```bash
turbo build                        # всё с учетом графа и кеша
turbo build --filter=web...        # web и его зависимости
turbo test --affected              # только пакеты, измененные относительно main
```

Turborepo хеширует входные файлы и переменные окружения задачи: если ничего не изменилось — берет результат из кеша (локального или удаленного), и сборка занимает секунды.

## Общие конфиги

```json
// packages/tsconfig/base.json
{ "compilerOptions": { "strict": true, "moduleResolution": "Bundler", "isolatedModules": true } }

// apps/web/tsconfig.json
{ "extends": "@acme/tsconfig/base.json" }
```

То же для ESLint (`@acme/eslint-config`) и Prettier.

## Версии и публикация

- внутренние пакеты часто `private: true` и не публикуются;
- для публикуемых — **Changesets**: разработчик описывает изменение в PR, при релизе версии и changelog обновляются автоматически.

## Turborepo и Nx

| | Turborepo | Nx |
| --- | --- | --- |
| Подход | легкий оркестратор задач | платформа с генераторами и плагинами |
| Настройка | `turbo.json` | `nx.json` + плагины, можно вывести задачи автоматически |
| Кеш | локальный + удаленный | локальный + удаленный |
| Граф проекта | по `package.json` | по `package.json` и анализу импортов, визуализация |
| Генераторы кода | базовые | развитые |

## Что важно помнить

- `dependsOn: ["^build"]` — главное: пакет собирается после своих зависимостей.
- Правильные `outputs` и `env` в Turborepo нужны, чтобы кеш не отдавал устаревший результат.
- В CI используйте `--affected` и удаленный кеш — иначе монорепо будет собираться всё дольше.
- Следите за границами: приложение не должно импортировать внутренние файлы пакета в обход `exports`.
- Архитектурные компромиссы монорепо и микрофронтендов — в заметке [масштабирование фронтенда](<../../11. Frontend System Design/05. Масштабирование и интервью/02. Как масштабировать фронтенд - монорепозиторий, модули и микрофронтенды.md>).

## Мини-шпаргалка

`pnpm-workspace.yaml` + `"@acme/ui": "workspace:*"` — локальные пакеты. `pnpm --filter`. Turborepo: `turbo.json` с задачами, `dependsOn: ["^build"]`, `outputs`, кеш, `--filter`, `--affected`. Общие tsconfig и eslint-config пакетами. Публикация — Changesets.
