# Какие вопросы по сборке и инструментам задают на собеседовании

> [!NOTE]
> На middle-собеседовании по сборке обычно проверяют понимание, **зачем** нужна каждая часть инструментов и **как** они связаны, а не знание конфигов наизусть: что делает бандлер, чем Vite отличается от webpack, что такое tree shaking и code splitting, как работают source maps и HMR, зачем Babel, полифилы и browserslist, как ESLint и Prettier делят обязанности, что такое lockfile, semver и фантомные зависимости, как оптимизировать бандл и кеширование. Ниже — частые вопросы с короткими ответами и ссылками на подробные заметки.

## Вопрос

Какие вопросы по сборке, инструментам и пакетным менеджерам задают на собеседовании frontend-разработчика и как на них коротко ответить?

## Сборка

| Вопрос | Короткий ответ |
| --- | --- |
| Зачем нужна сборка? | TS/JSX → JS, голые импорты, объединение модулей, tree shaking, минификация, хеши, ассеты, совместимость |
| Чем Vite отличается от webpack? | Vite в dev отдает нативный ESM без бандлинга и трансформирует по запросу (быстрый старт), в prod — Rollup; webpack бандлит всё в обоих режимах через loaders и plugins |
| Loader vs plugin в webpack? | loader преобразует отдельный файл в модуль, plugin работает со всей сборкой |
| Что такое tree shaking и когда он не работает? | удаление неиспользуемых экспортов; нужны ESM и отсутствие побочных эффектов (`sideEffects`), не работает с CommonJS и динамическим доступом к экспортам |
| Что такое code splitting? | разбиение на чанки по динамическому `import()`, ленивые маршруты и компоненты |
| Зачем хеш в имени файла? | долгий кеш с `immutable`, при изменении содержимого — новое имя |
| Что такое source maps и как их использовать в production? | соответствие собранного кода исходному; `hidden` + загрузка в Sentry |
| Как работает HMR? | сервер следит за файлами, по WebSocket сообщает об изменении, браузер заменяет модуль, Fast Refresh сохраняет state |
| Почему Vite не показывает ошибки типов? | esbuild только удаляет типы; проверка — `tsc --noEmit` |

## Транспиляция и совместимость

| Вопрос | Короткий ответ |
| --- | --- |
| Что делает Babel? | транспилирует синтаксис: TS, JSX, новый JS → поддерживаемый целевыми браузерами |
| Транспиляция vs полифил? | синтаксис переписывается при сборке, отсутствующий API добавляется полифилом в рантайме |
| Что такое browserslist? | общий список целевых браузеров для Babel/SWC, Autoprefixer, core-js |
| Зачем SWC/esbuild? | те же задачи, что у Babel, в десятки раз быстрее (Rust/Go) |
| Что делает Autoprefixer? | добавляет вендорные префиксы CSS по browserslist |

Подробнее: [Babel и SWC](<../03. Транспиляция и совместимость/01. Что такое Babel и SWC.md>), [полифилы и browserslist](<../03. Транспиляция и совместимость/02. Что такое полифилы, core-js и browserslist.md>).

## Качество кода

| Вопрос | Короткий ответ |
| --- | --- |
| ESLint vs Prettier? | ESLint ищет ошибки и плохие паттерны, Prettier только форматирует; конфликты отключает `eslint-config-prettier` |
| Зачем husky и lint-staged? | Git-хуки для команды; проверка только измененных файлов перед коммитом |
| Почему хуков недостаточно? | их можно обойти `--no-verify` — финальная проверка в CI |
| Что такое Conventional Commits? | формат `type(scope): описание` для автоматического changelog и версий |

Подробнее: [ESLint](<../04. Качество кода/01. Что такое ESLint и как его настроить.md>), [Git-хуки](<../04. Качество кода/03. Как настроить Git-хуки - husky, lint-staged и commitlint.md>).

## Пакеты

| Вопрос | Короткий ответ |
| --- | --- |
| Зачем lockfile? | фиксирует точные версии всего дерева — одинаковая установка у всех и в CI (`npm ci`) |
| `^1.2.3` vs `~1.2.3`? | `^` — до следующего major, `~` — до следующего minor |
| dependencies vs devDependencies vs peerDependencies? | рантайм / разработка и сборка / должен установить потребитель (React в UI-библиотеке) |
| Что такое фантомные зависимости? | импорт пакета, не указанного в `package.json`, работающий из-за hoisting; pnpm запрещает |
| Чем pnpm лучше npm? | общий store, экономия места и времени, строгий `node_modules`, сильные workspaces |
| Что такое монорепозиторий? | несколько пакетов в одном репозитории: workspaces + оркестратор задач с кешем (Turborepo, Nx) |

Подробнее: [npm, pnpm, yarn](<../05. Пакетные менеджеры и монорепозиторий/01. Чем отличаются npm, pnpm и yarn.md>), [semver](<../05. Пакетные менеджеры и монорепозиторий/02. ## Оптимизация

| Вопрос | Короткий ответ |
| --- | --- |
| Как уменьшить бандл? | анализ визуализатором, ленивые чанки, легкие альтернативы, точечные импорты, dedupe, узкий browserslist |

## Как рассказать о своем опыте

- какой сборщик был в проекте и почему (или как мигрировали, например CRA → Vite, webpack → Rspack);
- что ускоряло сборку и CI: кеш, SWC вместо Babel, `--affected` в монорепо;
- какой самый большой выигрыш по размеру бандла вы получили и как измеряли;
- как устроены линтеры, хуки и проверки в CI.

## Что важно помнить

- Отвечайте через «зачем»: какую проблему решает инструмент.
- Для каждого инструмента знайте одну альтернативу и компромисс.
- Конкретные цифры и пример из опыта сильно усиливают ответ.

## Мини-шпаргалка

Качество: ESLint vs Prettier, husky + lint-staged, CI. Пакеты: lockfile, semver, peer, фантомные, pnpm, монорепо. Оптимизация: анализ, кеш, Brotli, изображения.
