# Что такое Prettier и EditorConfig

> [!NOTE]
> **Prettier** — «упрямый» форматтер кода: он полностью переписывает форматирование (отступы, кавычки, переносы строк, точки с запятой) по небольшому набору настроек, поэтому в команде пропадают споры о стиле и шум в diff. Prettier работает с JS, TS, JSX, CSS, JSON, Markdown, YAML. **EditorConfig** (`.editorconfig`) задает базовые настройки редактора — кодировку, конец строки, отступы — для всех файлов и всех редакторов. Prettier отвечает за форматирование, ESLint — за ошибки; их не смешивают.

## Вопрос

Что такое Prettier и чем он отличается от ESLint? Как настроить Prettier и EditorConfig и подключить их к редактору и CI?

## Настройка Prettier

```bash
npm install --save-dev --save-exact prettier
```

```json
// .prettierrc
{
  "semi": true,
  "singleQuote": false,
  "trailingComma": "all",
  "printWidth": 100,
  "tabWidth": 2,
  "plugins": ["prettier-plugin-tailwindcss"]
}
```

```text
# .prettierignore
dist
coverage
pnpm-lock.yaml
```

```json
// package.json
{
  "scripts": {
    "format": "prettier . --write",
    "format:check": "prettier . --check"
  }
}
```

`--save-exact` фиксирует версию: разные версии Prettier форматируют по-разному.

## Prettier и ESLint

| | Prettier | ESLint |
| --- | --- | --- |
| Задача | как код **выглядит** | правильно ли код **работает** |
| Пример | кавычки, отступы, переносы | неиспользуемая переменная, хук в условии |
| Настройки | минимум | сотни правил |

Правильная связка: Prettier форматирует, а `eslint-config-prettier` отключает правила ESLint о стиле. Плагин `eslint-plugin-prettier` (запуск Prettier как правила ESLint) сейчас обычно не рекомендуют — он медленнее и дает шумные ошибки.

## EditorConfig

```ini
# .editorconfig
root = true

[*]
charset = utf-8
end_of_line = lf
indent_style = space
indent_size = 2
insert_final_newline = true
trim_trailing_whitespace = true

[*.md]
trim_trailing_whitespace = false
```

Prettier учитывает `.editorconfig` (отступы, `end_of_line`), если в `.prettierrc` эти опции не заданы.

## В редакторе

```json
// .vscode/settings.json
{
  "editor.defaultFormatter": "esbenp.prettier-vscode",
  "editor.formatOnSave": true,
  "editor.codeActionsOnSave": { "source.fixAll.eslint": "explicit" }
}
```

## Что важно помнить

- Задача Prettier — убрать обсуждения стиля; не тратьте время на тонкую настройку десятков опций.
- В CI запускайте `prettier --check`, а в pre-commit — форматирование только измененных файлов.
- Конец строки `lf` во всех файлах избавляет от проблем Windows/Linux (вместе с настройкой Git `core.autocrlf`).
- Плагин сортировки классов Tailwind делает порядок классов единообразным.
- Альтернатива — **Biome**: форматтер, совместимый с Prettier, плюс линтер, в одном быстром инструменте.

## Мини-шпаргалка

Prettier — форматирование (кавычки, отступы, переносы), минимум настроек, `--save-exact`, `prettier . --check` в CI. ESLint — ошибки, `eslint-config-prettier` убирает конфликты. EditorConfig — кодировка, `lf`, отступы для всех редакторов. VS Code: formatOnSave + fixAll.eslint.
