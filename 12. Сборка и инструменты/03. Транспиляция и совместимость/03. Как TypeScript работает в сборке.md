# Как TypeScript работает в сборке

> [!NOTE]
> В современных сборках TypeScript обрабатывается **двумя независимыми шагами**: быстрый транспилятор (esbuild, SWC, oxc, Babel) **удаляет типы** файл за файлом и не проверяет их, а **`tsc --noEmit`** отдельно **проверяет типы** во всем проекте — в редакторе, в pre-commit или в CI. Поскольку транспилятор видит только один файл, в `tsconfig` включают `isolatedModules` (или `verbatimModuleSyntax`), чтобы запретить конструкции, требующие знаний о других файлах. `tsc` с генерацией файлов используют в основном для библиотек — ради `.d.ts`.

## Вопрос

Как TypeScript обрабатывается при сборке фронтенд-проекта? Почему Vite не показывает ошибки типов и зачем нужны `isolatedModules` и `tsc --noEmit`?

## Два шага

```text
src/*.ts(x)
  ├─▶ esbuild / SWC: удалить типы → JS → бандл        (быстро, без проверки)
  └─▶ tsc --noEmit: проверить типы во всем проекте    (медленнее, отдельно)
```

```json
// package.json
{
  "scripts": {
    "dev": "vite",
    "build": "tsc --noEmit && vite build",
    "typecheck": "tsc --noEmit"
  }
}
```

Если в коде ошибка типа, `vite dev` всё равно запустится — ошибку покажет редактор, `npm run typecheck` или CI.

## Важные опции tsconfig для сборки

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "Bundler",       // разрешение импортов как у бандлера
    "jsx": "react-jsx",
    "strict": true,
    "noEmit": true,                       // файлы генерирует бандлер
    "isolatedModules": true,              // каждый файл транспилируется отдельно
    "verbatimModuleSyntax": true,         // import type сохраняется как написано
    "skipLibCheck": true,
    "paths": { "@/*": ["./src/*"] }
  },
  "include": ["src"]
}
```

## Почему isolatedModules

Транспилятор обрабатывает файл без информации о других:

```typescript
// re-export типа: транспилятор не знает, тип это или значение
export { User } from "./types";          // ошибка с isolatedModules
export type { User } from "./types";     // правильно

// const enum требует знать значения из другого файла
const enum Direction { Up, Down }        // избегайте; используйте объект as const
```

## Проектные ссылки и скорость

- `tsc --build` с `references` проверяет монорепозиторий по частям с кешем (`tsBuildInfoFile`);
- `skipLibCheck` пропускает проверку `.d.ts` библиотек;
- в Vite-шаблонах обычно несколько tsconfig: `tsconfig.app.json` (код приложения) и `tsconfig.node.json` (конфиги Vite и инструментов).

## TypeScript для библиотек

```bash
tsc --emitDeclarationOnly --declaration --outDir dist   # только .d.ts
```

Или инструменты, которые собирают JS и типы вместе: tsup, tsdown, Vite library mode + `vite-plugin-dts`.

## Что важно помнить

- Транспилятор ≠ проверка типов: сборка может пройти с ошибками типов, если не запускать `tsc`.
- Проверку типов обязательно включайте в CI.
- `moduleResolution: "Bundler"` — для проектов на Vite/webpack, `"NodeNext"` — для кода, который запускает Node.js напрямую.
- `paths` в tsconfig не меняет импорты в собранном коде — алиасы должен понимать и бандлер.
- Связанные темы: [Babel и SWC](<01. Что такое Babel и SWC.md>), [TypeScript в Node.js без сборки](<../../08. Node/16. Современные API диагностика и security/07. Как Node.js запускает TypeScript без сборки и какие ограничения.md>).

## Мини-шпаргалка

Сборка TS = транспиляция без проверки (esbuild/SWC) + `tsc --noEmit` отдельно (редактор, CI). tsconfig: `noEmit`, `isolatedModules`, `verbatimModuleSyntax`, `moduleResolution: "Bundler"`, `strict`, `paths`. `export type` для типов, без `const enum`. Библиотеки — `.d.ts` через tsc/tsup.
