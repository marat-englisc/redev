# Как настроить сжатие и кэширование ассетов

> [!NOTE]
> После сборки файлы нужно **доставить быстро**: сжать (Brotli для современных браузеров, gzip как запасной вариант), отдать с правильными заголовками кэширования (ассеты с хешем — `max-age=31536000, immutable`, `index.html` — `no-cache`) и раздать через **CDN** ближе к пользователю. Сжатие делают либо заранее при сборке (`.br`, `.gz` рядом с файлами), либо на сервере или CDN «на лету».

## Вопрос

Как настроить сжатие и кэширование статических файлов фронтенд-приложения? Почему у файлов с хешем и у `index.html` разные заголовки?

## Сжатие

| Алгоритм | Степень сжатия JS/CSS | Поддержка |
| --- | --- | --- |
| gzip | базовая | везде |
| Brotli (`br`) | на 15–25% лучше gzip | все современные браузеры по HTTPS |
| zstd | близко к Brotli, быстрее сжатие | новые браузеры |

```text
Браузер: Accept-Encoding: gzip, deflate, br, zstd
Сервер:  Content-Encoding: br
```

Предварительное сжатие при сборке (Vite):

```typescript
import viteCompression from "vite-plugin-compression2";

export default defineConfig({
  plugins: [react(), viteCompression({ algorithms: ["brotliCompress", "gzip"] })],
});
```

nginx отдает готовые `.br`/`.gz` при `brotli_static on; gzip_static on;`. Хостинги вроде Vercel, Netlify и CDN сжимают автоматически.

Не сжимайте повторно уже сжатые форматы: изображения JPEG/WebP/AVIF, видео, `woff2`.

## Кэширование

```nginx
location /assets/ {
  add_header Cache-Control "public, max-age=31536000, immutable";
}

location = /index.html {
  add_header Cache-Control "no-cache";          # всегда проверять обновление (ETag)
}

location / {
  try_files $uri /index.html;                  # SPA-роутинг
}
```

| Файл | Заголовок | Почему |
| --- | --- | --- |
| `assets/index-B3f9a1cD.js` | `max-age=31536000, immutable` | имя меняется при изменении содержимого |
| `index.html` | `no-cache` | содержит ссылки на актуальные хеши |
| `favicon.ico`, файлы из `public/` без хеша | короткий `max-age` или `no-cache` | имя не меняется |
| `sw.js` (Service Worker) | `no-cache` | браузер должен быстро увидеть новую версию |
| API с персональными данными | `private, no-store` | нельзя кешировать на CDN |

## CDN

- раздает статику с ближайшего к пользователю узла — ниже задержка;
- кеширует по тем же заголовкам (`s-maxage` — отдельный срок для CDN);
- HTTP/2 и HTTP/3, сжатие, оптимизация изображений «на лету»;
- после деплоя HTML нужно обновить в CDN (purge или короткий TTL), а ассеты с хешем не трогать.

## Деплой без поломок

1. Загрузить новые ассеты (старые не удалять).
2. Загрузить новый `index.html`.
3. Удалить старые ассеты через несколько дней — пользователи с открытыми вкладками еще могут их запросить.

## Что важно помнить

- Хеш в имени + `immutable` — главная техника: долгий кеш без риска показать старую версию.
- `index.html` с `immutable` — частая ошибка: пользователи застрянут на старой версии.
- Brotli дает заметную экономию на JS и CSS; включите его на сервере или CDN.
- Проверяйте заголовки в DevTools → Network (`Content-Encoding`, `Cache-Control`, размер «передано» и «ресурса»).
- Связанные темы: [HTTP caching](<../../01. Web технологии/04. CORS, cache и HTTPS/04. Что такое HTTP caching.md>), [кеширование в system design](<../../11. Frontend System Design/03. Нефункциональные требования/02. Как спроектировать кеширование на всех уровнях.md>).

## Мини-шпаргалка

Сжатие: Brotli (лучше) + gzip (запас), заранее при сборке или на сервере/CDN, не для изображений и `woff2`. Кеш: ассеты с хешем — `max-age=31536000, immutable`, `index.html` и `sw.js` — `no-cache`, персональное API — `private, no-store`. CDN, деплой: сначала ассеты, потом HTML, старое удалять позже.
