# Как рассчитывается специфичность и как на нее влияют псевдоклассы?

> [!NOTE]
> **Специфичность** — вес селектора, по которому каскад выбирает правило, если несколько правил задают одно свойство одному элементу. Ее записывают тройкой `A-B-C`: A — id, B — классы, атрибуты и псевдоклассы, C — теги и псевдоэлементы. Inline-стили и `!important` стоят выше специфичности. `:where()` дает 0, а `:is()`, `:not()` и `:has()` берут вес самого специфичного аргумента.

## Вопрос

Как рассчитывается специфичность селектора? Как выглядит формула? Как на специфичность влияют псевдоклассы и псевдоэлементы?

## Формула

```text
A — количество id
B — классы, атрибуты, псевдоклассы
C — теги (типы элементов) и псевдоэлементы
```

Сравнение идет слева направо: любой селектор с одним id сильнее селектора с сотней классов. Это не десятичное число — разряды не переполняются.

## Примеры

| Селектор | Специфичность |
| --- | --- |
| `*` | `0-0-0` |
| `p` | `0-0-1` |
| `p::first-line` | `0-0-2` |
| `.text` | `0-1-0` |
| `[type="email"]` | `0-1-0` |
| `button.primary:hover` | `0-2-1` |
| `#app` | `1-0-0` |
| `#app .card h2` | `1-1-1` |
| `:where(#app .card) h2` | `0-0-1` |
| `:is(#app, .card) h2` | `1-0-1` |
| `.list > li:not(.active)` | `0-2-1` |

Комбинаторы (пробел, `>`, `+`, `~`) и универсальный селектор `*` специфичность не добавляют.

## Псевдоклассы и псевдоэлементы

| Что | Вес |
| --- | --- |
| Обычный псевдокласс: `:hover`, `:focus-visible`, `:nth-child()`, `:checked`, `:root` | как класс — `0-1-0` |
| Псевдоэлемент: `::before`, `::after`, `::marker` | как тег — `0-0-1` |
| `:where(...)` | всегда `0-0-0` |
| `:is(...)`, `:not(...)`, `:has(...)` | вес самого специфичного аргумента |
| `:nth-child(2 of .item)` | `0-1-0` за псевдокласс + вес селектора внутри `of` |

```css
:root { --gap: 16px; }        /* 0-1-0: сильнее, чем html { } (0-0-1) */
:not(#main) p { color: red; } /* 1-0-1: :not дает вес id! */
```

## Порядок каскада

Специфичность — не первый критерий. Каскад сравнивает:

1. Происхождение и важность: `!important` пользователя > `!important` автора > обычные стили автора > стили браузера.
2. Контекст (Shadow DOM).
3. Cascade layers (`@layer`): стили вне слоев сильнее стилей в слоях.
4. **Специфичность** (inline-стиль считается сильнее любого селектора).
5. Порядок в коде: при равной специфичности побеждает последнее правило.

## Пример конфликта

```css
.button { color: black; }
.card .button { color: blue; } /* 0-2-0 — побеждает */
.button { color: red; }        /* 0-1-0 — проигрывает, несмотря на порядок */
```

## Как управлять специфичностью

- Писать селекторы из одного класса (BEM, CSS Modules).
- Оборачивать базовые стили в `:where()`, чтобы их было легко переопределить:

```css
:where(.prose) h2 { margin-top: 2em; } /* 0-0-1 */
```

- Поднимать вес без `!important` повтором класса: `.button.button` (`0-2-0`).
- Использовать `@layer` для разделения reset, библиотек и компонентов.

## Что важно помнить

- Наследуемое значение не имеет специфичности: любое правило, которое прямо выбирает элемент, сильнее унаследованного.
- В DevTools (Elements → Styles) при наведении на селектор показывается его специфичность.
- Inline-стиль из JS (`element.style`) переопределяет все стили из CSS, кроме `!important`.
- Высокая специфичность — главный источник «войны селекторов» и `!important`.

## Мини-шпаргалка

- `A-B-C`: id — классы/атрибуты/псевдоклассы — теги/псевдоэлементы.
- `*` и комбинаторы — 0.
- `:where()` — 0, `:is()`/`:not()`/`:has()` — максимум аргументов.
- Порядок важен только при равной специфичности.
- Выше специфичности: `!important`, слои, inline-стили.
