# Что делают padding, border и margin? Можно ли задавать отрицательный margin?

> [!NOTE]
> `padding` — внутренний отступ между содержимым и рамкой, окрашивается фоном и не бывает отрицательным. `border` — рамка вокруг padding, задается шириной, стилем и цветом. `margin` — внешний прозрачный отступ до соседей: может быть `auto` (для центрирования), отрицательным и у вертикальных блоков схлопывается.

## Вопрос

Что такое padding? Что делает border в Box Model? Что делает margin и можно ли задавать его отрицательным?

## padding

```css
.card {
  padding: 16px;          /* со всех сторон */
  padding: 8px 16px;      /* верх/низ | право/лево */
  padding: 8px 16px 24px; /* верх | право/лево | низ */
  padding: 8px 12px 16px 20px; /* по часовой: верх, право, низ, лево */
}
```

- увеличивает внутреннее пространство, фон рисуется и под ним;
- при `content-box` увеличивает итоговый размер, при `border-box` входит в `width`;
- отрицательным быть не может: `padding: -10px` — невалидное значение;
- проценты считаются **от ширины** родителя даже для `padding-top` — на этом основан старый трюк с соотношением сторон (сейчас есть `aspect-ratio`).

## border

```css
.card {
  border: 1px solid #d1d5db;     /* width style color */
  border-bottom: 2px dashed red; /* одна сторона */
  border-radius: 8px;            /* скругление углов */
}
```

Без `border-style` рамки не будет: значение по умолчанию — `none`. Стили: `solid`, `dashed`, `dotted`, `double`, `groove`, `ridge`, `inset`, `outset`.

`border` входит в размер элемента при `border-box` и добавляется к нему при `content-box`. Если рамка нужна только визуально, без влияния на layout, используют `outline` или `box-shadow: 0 0 0 1px`.

## margin

```css
.box {
  margin: 16px 0 24px;     /* верх | право/лево | низ */
  margin-block: 16px;      /* логические свойства: верх и низ */
}

.container {
  max-width: 960px;
  margin-inline: auto;     /* центрирование по горизонтали */
}
```

- прозрачный, фон элемента под ним не рисуется;
- `auto` по горизонтали делит свободное место — так центрируют блок с заданной шириной; во Flexbox и Grid `margin-left: auto` прижимает элемент вправо;
- вертикальные margin соседних блоков **схлопываются** — берется наибольший (см. заметку о collapsing margins).

## Отрицательный margin

Да, margin может быть отрицательным:

```css
.avatar { margin-top: -24px; }   /* наезжает на блок выше */
.row { margin-inline: -8px; }    /* компенсирует padding колонок */
```

Отрицательный margin сдвигает элемент и **меняет поток**: соседи тоже смещаются, а элемент может перекрыть их. Это делает layout менее предсказуемым и плохо дружит с адаптивностью.

Альтернативы:

| Задача | Лучше использовать |
| --- | --- |
| Визуальный сдвиг без влияния на соседей | `transform: translateY(-8px)` |
| Отступы между элементами сетки | `gap` |
| Наложение | `position` или `grid-area` с перекрытием |

## Логические свойства

Вместо `top/right/bottom/left` можно писать направления текста — это важно для RTL-языков:

| Физическое | Логическое |
| --- | --- |
| `margin-left` / `margin-right` | `margin-inline-start` / `margin-inline-end` |
| `margin-top` / `margin-bottom` | `margin-block-start` / `margin-block-end` |
| `padding-left` + `padding-right` | `padding-inline` |

## Что важно помнить

- Отступы между элементами внутри Flexbox и Grid задают через `gap`, а не через margin у детей.
- Правило «отступ задает родитель» (например, `.stack > * + * { margin-top: 1rem }` или `gap`) упрощает переиспользование компонентов.
- У inline-элементов вертикальные margin не работают, а padding рисуется, но не раздвигает строки.
- Проценты в `margin` тоже считаются от ширины содержащего блока.

## Мини-шпаргалка

- `padding` — внутри, с фоном, не бывает отрицательным.
- `border` — рамка, без `border-style` не видна.
- `margin` — снаружи, прозрачный, `auto` центрирует, схлопывается по вертикали.
- Отрицательный margin допустим, но сдвигает поток — часто лучше `transform` или `gap`.
- Логические свойства: `margin-inline`, `padding-block`.
