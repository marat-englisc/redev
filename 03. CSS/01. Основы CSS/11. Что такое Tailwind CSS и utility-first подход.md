# Что такое Tailwind CSS и utility-first подход

> [!NOTE]
> **Tailwind CSS** — utility-first фреймворк: вместо написания своих классов (`.card`) вы собираете стили из маленьких утилит прямо в разметке (`p-4 rounded-lg shadow`). Утилиты построены на дизайн-токенах (отступы, цвета, размеры), поэтому интерфейс получается согласованным. Tailwind генерирует только те классы, которые встречаются в коде, и итоговый CSS остается небольшим.

## Вопрос

Что такое Tailwind и utility-first подход? Какие у него плюсы и минусы по сравнению с БЭМ, CSS Modules и CSS-in-JS?

## Основная идея

```jsx
function Card({ title, featured }) {
  return (
    <article
      className={`rounded-xl p-6 shadow-sm ${featured ? "border-2 border-blue-600" : "border border-gray-200"}`}
    >
      <h2 className="text-xl font-semibold text-gray-900 md:text-2xl">{title}</h2>
      <button className="mt-4 rounded-md bg-blue-600 px-4 py-2 text-white hover:bg-blue-700 focus-visible:outline-2 disabled:opacity-50">
        Купить
      </button>
    </article>
  );
}
```

- `p-6`, `mt-4` — отступы по шкале токенов;
- `md:` — breakpoint (mobile-first: стиль применяется от `md` и шире);
- `hover:`, `focus-visible:`, `disabled:` — варианты состояний;
- `dark:` — темная тема.

## Как работает

1. Tailwind сканирует файлы проекта и находит используемые классы.
2. Генерирует CSS только для них.
3. Токены и тема настраиваются в CSS (Tailwind v4: `@theme { --color-brand: ... }`) или в конфиге (v3: `tailwind.config.js`).

Поэтому имена классов должны встречаться в коде **целиком**: `` `bg-${color}-500` `` не сработает — Tailwind не увидит класс при сканировании.

```jsx
// плохо
<div className={`bg-${color}-500`} />

// хорошо — полные имена классов
const colors = { red: "bg-red-500", blue: "bg-blue-500" };
<div className={colors[color]} />
```

## Сравнение подходов

| | БЭМ + SCSS | CSS Modules | CSS-in-JS | Tailwind |
| --- | --- | --- | --- | --- |
| Где стили | отдельные файлы | файл рядом с компонентом | в JS | классы в разметке |
| Изоляция | соглашение об именах | хеш классов | генерация классов | нет общих имен — нечему конфликтовать |
| Рантайм | нет | нет | часто есть | нет |
| Размер CSS | растет с проектом | растет | зависит | почти не растет |
| Минусы | дисциплина именования | динамика через классы | рантайм, SSR | «шумная» разметка |

## Приемы на практике

- **`clsx` / `cn`** — условные классы; **`tailwind-merge`** — разрешение конфликтов (`p-2` и `p-4`).
- **Компоненты, а не `@apply`**: повторяющийся набор утилит выносят в React-компонент `<Button>`, а не в CSS-класс через `@apply`.
- **cva / tailwind-variants** — описание вариантов компонента (size, intent).
- **Произвольные значения**: `w-[327px]`, `grid-cols-[1fr_auto]` — для исключений, но не вместо токенов.

## Что важно помнить

- Tailwind — не «инлайн-стили»: есть состояния, breakpoints, темы и токены, которых нет у `style`.
- Динамические имена классов не работают — классы должны быть статическими строками.
- Длинные списки классов читаются хуже — помогают компоненты и плагин сортировки классов для Prettier.
- Tailwind не решает доступность и семантику: правильные теги и ARIA всё равно на разработчике.
- Подходит для продуктов с дизайн-системой и быстрой разработкой; в проектах с уникальной сложной версткой и анимациями часто комбинируют с обычным CSS.

## Мини-шпаргалка

Utility-first: стили из маленьких классов в разметке. Токены → согласованность. Генерируются только использованные классы. Префиксы `md:`, `hover:`, `dark:`. Классы — статические строки. Повторение — выносить в компонент, конфликты — `tailwind-merge`.
