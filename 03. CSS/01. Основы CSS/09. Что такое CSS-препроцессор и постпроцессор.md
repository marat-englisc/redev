# Что такое CSS-препроцессор и постпроцессор?

> [!NOTE]
> **Препроцессор** (Sass/SCSS, Less, Stylus) расширяет CSS собственным синтаксисом — переменными, вложенностью, миксинами, функциями — и компилирует его в обычный CSS. **Постпроцессор** (PostCSS с плагинами вроде Autoprefixer) обрабатывает уже готовый CSS: добавляет вендорные префиксы, минифицирует, транспилирует новые возможности под старые браузеры.

## Вопрос

Что такое CSS-препроцессор? Что такое постпроцессор и чем он отличается от препроцессора? Нужен ли препроцессор в современном проекте?

## Препроцессор

Браузер не понимает SCSS напрямую — код проходит сборку:

```text
SCSS / Less / Stylus -> preprocessor -> CSS -> browser
```

```scss
$primary: #2563eb;

@mixin focus-ring($color: $primary) {
  outline: 3px solid $color;
  outline-offset: 2px;
}

.button {
  background: $primary;

  &:hover {
    background: color.adjust($primary, $lightness: -8%);
  }

  &:focus-visible {
    @include focus-ring;
  }
}
```

Что дают препроцессоры:

- переменные (`$primary`);
- вложенность и `&`;
- миксины (`@mixin` / `@include`) и наследование (`@extend`);
- функции, циклы и условия;
- модули и разделение файлов (`@use`, `@forward`);
- операции с цветами и числами.

## Постпроцессор

Постпроцессор работает с CSS, а не с другим языком:

```text
CSS source -> PostCSS + plugins -> processed CSS -> browser
```

| Плагин / инструмент | Что делает |
| --- | --- |
| Autoprefixer | добавляет `-webkit-` и другие префиксы по данным Can I Use и `browserslist` |
| postcss-preset-env | превращает современный CSS в совместимый |
| cssnano | минификация |
| Stylelint | проверка ошибок и стиля кода |
| Tailwind CSS | генерирует утилиты (исторически как плагин PostCSS) |

```css
/* вход */
.box { user-select: none; }

/* выход Autoprefixer */
.box {
  -webkit-user-select: none;
  user-select: none;
}
```

Современные сборщики (Vite, Next.js) уже используют PostCSS или Lightning CSS под капотом.

## Сравнение

| | Препроцессор | Постпроцессор |
| --- | --- | --- |
| Вход | свой синтаксис (SCSS) | CSS |
| Когда работает | до получения CSS | после |
| Задачи | удобство написания | совместимость и оптимизация |
| Примеры | Sass, Less, Stylus | PostCSS, Lightning CSS |

Они не конкурируют: часто используют оба — SCSS → CSS → PostCSS.

## Нужен ли препроцессор сейчас

Многие возможности уже есть в нативном CSS:

| Было в Sass | Есть в CSS |
| --- | --- |
| переменные | custom properties `--color` (и они работают в runtime) |
| вложенность | CSS Nesting |
| `darken()` / `lighten()` | `color-mix()`, относительный синтаксис цвета |
| математика | `calc()`, `min()`, `max()`, `clamp()` |
| организация каскада | `@layer` |

Препроцессор по-прежнему полезен для миксинов, циклов и генерации классов, а также в проектах с существующей SCSS-архитектурой.

## Что важно помнить

- Sass-переменные исчезают после компиляции, а CSS-переменные можно менять из JS и в media queries — для тем нужны именно CSS-переменные.
- `@import` в Sass устарел, используйте `@use` и `@forward`.
- Глубокая вложенность в SCSS порождает длинные селекторы с высокой специфичностью — правило «не глубже 3 уровней».
- Список поддерживаемых браузеров для Autoprefixer задают в `browserslist` (в `package.json` или `.browserslistrc`).

## Мини-шпаргалка

- Препроцессор: SCSS → CSS (переменные, вложенность, миксины).
- Постпроцессор: CSS → CSS (префиксы, минификация, совместимость).
- Популярные: Sass, PostCSS + Autoprefixer.
- Нативный CSS уже умеет переменные, nesting и `color-mix()`.
