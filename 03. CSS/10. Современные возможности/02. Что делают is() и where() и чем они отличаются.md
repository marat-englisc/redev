# Что делают :is() и :where() и чем они отличаются?

> [!NOTE]
> `:is()` и `:where()` принимают список селекторов и совпадают, если подходит любой из них — это сокращает повторяющиеся селекторы. Разница только в специфичности: `:is()` берет специфичность самого «тяжелого» аргумента, а `:where()` всегда имеет нулевую специфичность. Оба «прощают» невалидные селекторы в списке.

## Вопрос

Что делает псевдокласс `:is()`? Что делает `:where()`? Когда использовать каждый из них?

## Сокращение селекторов

```css
/* без :is() */
.article h1,
.article h2,
.article h3 {
  line-height: 1.2;
}

/* с :is() */
.article :is(h1, h2, h3) {
  line-height: 1.2;
}

/* комбинации вариантов */
:is(header, footer) :is(a, button):hover {
  text-decoration: underline;
}
```

`:where()` работает так же:

```css
:where(ul, ol) :where(ul, ol) {
  margin-block: 0;
}
```

## Разница в специфичности

| Селектор | Специфичность |
| --- | --- |
| `:is(#nav, .menu) a` | `1-0-1` — берется вес `#nav` |
| `:where(#nav, .menu) a` | `0-0-1` — аргументы не учитываются |
| `.card :is(h2)` | `0-1-1` |
| `.card :where(h2)` | `0-1-0` |

Подвох `:is()`: даже если элемент совпал по `.menu`, вес будет как у `#nav`.

## Когда что использовать

**`:where()`** — для базовых стилей, которые должно быть легко переопределить: reset, стили библиотек, «prose»-типографика.

```css
:where(.prose) :where(h2, h3) {
  margin-top: 2em;
}

/* любой класс компонента переопределит это без !important */
.custom-heading { margin-top: 0; }
```

**`:is()`** — когда нужно обычное поведение специфичности и просто короче запись.

## Устойчивость к ошибкам

```css
/* обычная группа: неизвестный :future-state отбросит всё правило, .card тоже не получит стиль */
.card, .panel:future-state { border: 1px solid #ddd; }

/* forgiving selector list: невалидный аргумент игнорируется, .card стилизуется */
:is(.card, .panel:future-state) { border: 1px solid #ddd; }
```

Это удобно для новых псевдоклассов, которые поддерживаются не во всех браузерах. Псевдоэлементы внутри `:is()` и `:where()` не работают — для префиксных псевдоэлементов (`::-webkit-...`) нужны отдельные правила.

## Родственные псевдоклассы

| Псевдокласс | Специфичность | Смысл |
| --- | --- | --- |
| `:is()` | максимум аргументов | любой из списка |
| `:where()` | 0 | любой из списка |
| `:not()` | максимум аргументов | ни один из списка |
| `:has()` | максимум аргументов | содержит потомка или соседа из списка |

## Что важно помнить

- `:is()` и `:where()` не могут выбирать псевдоэлементы (`::before`).
- Исторические аналоги: `:-webkit-any()` и `:matches()` — сейчас только `:is()`.
- CSS Nesting под капотом оборачивает родительский селектор в `:is()`, поэтому специфичность вложенных правил может оказаться выше ожидаемой.
- Поддержка всеми современными браузерами с 2021 года.

## Мини-шпаргалка

- `:is(a, b)` и `:where(a, b)` — «любой из списка».
- `:is()` — специфичность самого сильного аргумента.
- `:where()` — специфичность 0, удобно для переопределяемых базовых стилей.
- Оба прощают невалидные селекторы.
- Псевдоэлементы внутри не работают.
