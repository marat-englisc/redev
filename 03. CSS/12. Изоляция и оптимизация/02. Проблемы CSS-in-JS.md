# Проблемы CSS-in-JS?

> [!NOTE]
> **CSS-in-JS** помогает связывать стили с компонентами, но может создавать проблемы с runtime-производительностью, SSR, кешированием, размером bundle, DevTools и зависимостью от конкретной библиотеки.

## Вопрос

Какие проблемы есть у CSS-in-JS и почему от runtime-решений часто отказываются?

## Главное

CSS-in-JS - это подход, где стили описываются в JavaScript.

```js
const button = css({
  padding: "8px 12px",
  background: "#2563eb",
  color: "white",
});
```

Это может быть удобно для компонентной логики, но имеет компромиссы.

## Runtime overhead

Некоторые CSS-in-JS решения генерируют стили во время выполнения приложения.

```text
render component
  -> calculate styles
  -> generate class
  -> inject style tag
```

На больших интерфейсах это может добавлять работу JavaScript.

## SSR и hydration

При server-side rendering важно, чтобы стили на сервере и клиенте совпали. Иначе возможны:

- мигание нестилизованного контента;
- расхождение class names;
- сложная настройка extraction;
- проблемы с порядком вставки стилей.

## Bundle size и кеширование

Если много CSS живет внутри JS, браузер скачивает больше JavaScript. Кроме того, CSS может хуже кешироваться отдельно от логики.

## DevTools и DX

Сгенерированные class names и injected styles иногда сложнее отлаживать, особенно в production.

```html
<button class="css-1a2b3c">Save</button>
```

Нужно понимать tooling, source maps и порядок генерации.

## Когда подход уместен

- Дизайн тесно связан с компонентами.
- Нужна динамическая темизация.
- Команда уже использует конкретную библиотеку.
- Есть SSR-настройка и понятные performance-бюджеты.

## Что важно помнить

- Runtime CSS-in-JS (styled-components, Emotion) генерирует стили во время рендера и замедляет его.
- С React Server Components runtime CSS-in-JS работает плохо: нужен контекст на клиенте.
- Zero-runtime решения (vanilla-extract, Linaria, Panda CSS, StyleX) извлекают CSS на этапе сборки.
- styled-components с 2025 года находится в режиме поддержки — для новых проектов его обычно не выбирают.

## Мини-шпаргалка

- CSS-in-JS удобен для компонентных стилей.
- Может добавлять runtime overhead.
- SSR требует аккуратной настройки.
- CSS внутри JS может увеличить bundle.
- Отладка сгенерированных классов бывает сложнее.
- Не стоит выбирать подход без учета масштаба проекта.
