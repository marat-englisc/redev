# Что делает position fixed. К чему привязывается элемент с fixed?

> [!NOTE]
> `position: fixed` фиксирует элемент относительно viewport: он остается на одном месте окна браузера при прокрутке страницы.

## Вопрос

Что делает `position: fixed` и к чему привязывается фиксированный элемент?

## Главное

```css
.header {
  position: fixed;
  top: 0;
  left: 0;
  right: 0;
}
```

Такой header будет оставаться сверху экрана при скролле.

## К чему привязывается fixed

Обычно `fixed` позиционируется относительно viewport.

```text
viewport
  top: 0
  right: 0
  bottom: 0
  left: 0
```

Но некоторые свойства у предков, например `transform`, могут создать новый containing block и повлиять на поведение fixed-элемента.

## Fixed выпадает из потока

Как и `absolute`, fixed-элемент не занимает место в обычном потоке.

```css
.page {
  padding-top: 64px;
}

.header {
  position: fixed;
  height: 64px;
}
```

Если header фиксированный, контент может оказаться под ним. Часто нужно добавить отступ.

## Частые сценарии

- Фиксированная шапка.
- Floating action button.
- Cookie banner.
- Модальные overlay.
- Панель мобильной навигации.

## Что важно помнить

- Если у предка есть `transform`, `filter`, `perspective` или `will-change: transform`, fixed-элемент привязывается к нему, а не к viewport.
- Фиксированная шапка закрывает якоря и фокус: используйте `scroll-padding-top` у `html`.
- На мобильных fixed-элементы могут перекрываться экранной клавиатурой и адресной строкой — учитывайте `dvh` и `env(safe-area-inset-*)`.
- Для модальных окон удобнее нативный `<dialog>` с `showModal()`: он попадает в top layer и не зависит от `z-index`.

## Мини-шпаргалка

- `fixed` обычно привязан к viewport.
- Элемент остается на месте при скролле.
- Он выпадает из потока.
- Может перекрывать контент.
- Для фиксированной шапки часто нужен отступ у страницы.
- `transform` на предках может изменить containing block.
