# Почему transform лучше для анимаций чем top, left?

> [!NOTE]
> `transform` обычно лучше для анимаций, чем `top` и `left`, потому что он чаще обрабатывается на этапе compositing и не требует полного пересчета layout.

## Вопрос

Почему для анимации перемещения лучше использовать `transform`, а не `top` и `left`?

## Главное

Анимация `top` или `left` меняет layout-положение элемента.

```css
.box:hover {
  top: 10px;
}
```

Анимация `transform` меняет визуальное преобразование.

```css
.box:hover {
  transform: translateY(10px);
}
```

## Упрощенный pipeline браузера

```text
style -> layout -> paint -> composite
```

Изменение `top`/`left` может затронуть layout. Изменение `transform` часто может быть выполнено ближе к composite-этапу.

## Пример hover

```css
.card {
  transition: transform 180ms ease, box-shadow 180ms ease;
}

.card:hover {
  transform: translateY(-4px);
  box-shadow: 0 12px 24px rgb(0 0 0 / 0.16);
}
```

Такой hover обычно плавнее, чем изменение `margin-top` или `top`.

## top/left все еще нужны

`top`, `left`, `right`, `bottom` нужны для позиционирования layout: например, поставить бейдж в угол карточки.

```css
.badge {
  position: absolute;
  top: 8px;
  right: 8px;
}
```

Но для движения лучше анимировать `transform`.

## Что важно помнить

- Изменение `top`/`left` запускает layout и paint на каждом кадре, `transform` — только composite в GPU-слое.
- Цель — 60 кадров в секунду, то есть около 16 мс на кадр, а на дисплеях 120 Гц — около 8 мс.
- `will-change: transform` заранее выносит элемент в слой, но злоупотребление тратит видеопамять.
- Отдельные свойства `translate`, `rotate`, `scale` позволяют анимировать их независимо, без перезаписи всего `transform`.

## Мини-шпаргалка

- `top`/`left` меняют позицию layout.
- `transform` двигает визуально.
- `transform` часто плавнее и дешевле.
- Для анимаций выбирай `transform` и `opacity`.
- Для статического позиционирования `top`/`left` нормальны.
