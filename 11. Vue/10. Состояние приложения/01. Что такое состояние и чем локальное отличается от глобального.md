# Что такое состояние и чем локальное отличается от глобального

> [!NOTE]
> **Состояние (state)** — данные, от которых зависит отображение и поведение интерфейса и которые меняются во времени: введённый текст, открыто ли меню, текущий пользователь, корзина, результаты поиска. **Локальное** состояние принадлежит одному компоненту (`ref` в `<script setup>`, `data()` в Options API) и уничтожается вместе с ним — так хранят всё, что нужно только этому компоненту и его детям (через props). **Глобальное (общее)** состояние нужно многим компонентам из разных частей дерева и должно жить дольше отдельных экземпляров: авторизованный пользователь, корзина, настройки, кеш справочников; его хранят в **сторе** (Pinia), composable с состоянием на уровне модуля или передают через provide/inject. Отдельно выделяют **серверное состояние** (данные API — их кешируют, обновляют, инвалидируют; удобны TanStack Query, `useFetch` в Nuxt) и **состояние URL** (фильтры, страница, вкладка — в query-параметрах, чтобы ссылкой можно было поделиться). Правило: держать состояние **как можно ближе** к месту использования и поднимать выше только по необходимости.

## Вопрос

Что такое состояние во Vue и чем локальное состояние отличается от глобального?

## Виды состояния

| Вид | Пример | Где хранить |
| --- | --- | --- |
| Локальное UI | Открыт ли дропдаун, значение поля | `ref` в компоненте |
| Общее для поддерева | Активная вкладка, контекст формы | Родитель + props/events или provide/inject |
| Глобальное клиентское | Пользователь, корзина, тема | Pinia |
| Серверное | Список заказов, профиль с API | Кеш запросов (TanStack Query, `useFetch`) или Pinia |
| URL | Фильтры, сортировка, страница | `route.query` |
| Постоянное | Тема, язык, черновик | localStorage (useStorage, persisted state) |

## Локальное

```vue
<script setup lang="ts">
const isOpen = ref(false);              // нужно только этому компоненту
const query = ref('');
</script>
```

Локальное состояние независимо у каждого экземпляра и исчезает при размонтировании.

## Поднятие состояния

```text
SearchBox (query) ─┐
                   ├─ оба должны знать query → состояние поднимают в общего родителя
ResultsList ───────┘

CatalogPage: const query = ref('')
  ├── <SearchBox v-model="query" />
  └── <ResultsList :query="query" />
```

## Глобальное

```ts
// stores/cart.ts
export const useCartStore = defineStore('cart', () => {
  const items = ref<CartItem[]>([]);
  const count = computed(() => items.value.reduce((s, i) => s + i.qty, 0));
  function add(product: Product) { /* ... */ }
  return { items, count, add };
});
```

```vue
<!-- AppHeader.vue и ProductCard.vue используют одну корзину -->
const cart = useCartStore();
```

## Состояние в URL

```ts
const route = useRoute();
const router = useRouter();

const page = computed({
  get: () => Number(route.query.page ?? 1),
  set: (p) => router.replace({ query: { ...route.query, page: String(p) } }),
});
```

Фильтры в URL переживают перезагрузку, работают кнопки «назад/вперёд» и ссылки.

## Когда глобальное оправдано

- Данные нужны компонентам в **разных ветках** дерева.
- Состояние должно **пережить** переходы между страницами.
- Нужны **devtools**, история изменений, SSR-сериализация.
- Несколько компонентов меняют одни данные — нужна единая точка изменений.

## Когда лучше локальное

- Данные нужны одному компоненту или его ближайшим детям.
- Состояние временное (открытие модалки, ввод до отправки).
- Каждому экземпляру нужно своё значение.

## Частые ошибки

- Класть в глобальный стор всё подряд, включая «открыт ли дропдаун».
- Дублировать данные API в нескольких местах без единого источника.
- Хранить фильтры только в сторе — нельзя поделиться ссылкой.
- Prop drilling через 5 уровней вместо стора или provide/inject.
- Общее состояние на уровне модуля в SSR — утечка данных между пользователями.

## Что важно помнить

- Состояние — данные, от которых зависит UI и которые меняются.
- Держите локально, поднимайте выше и делайте глобальным только при необходимости.
- Серверное и URL-состояние — отдельные категории со своими инструментами.

## Мини-шпаргалка

- Локальное — `ref` в компоненте.
- Общее для поддерева — родитель или provide/inject.
- Глобальное — Pinia.
- Фильтры — `route.query`.
- Данные API — кеш запросов.
