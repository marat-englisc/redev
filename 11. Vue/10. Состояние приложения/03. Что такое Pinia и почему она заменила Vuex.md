# Что такое Pinia и почему она заменила Vuex

> [!NOTE]
> **Pinia** — официальная библиотека управления состоянием для Vue (рекомендуется вместо **Vuex**, который находится в режиме поддержки). Стор объявляется функцией **`defineStore(id, ...)`** в двух стилях: **option store** (`state`, `getters`, `actions` — похоже на Vuex и Options API) и **setup store** (функция в стиле Composition API: `ref` — state, `computed` — getters, функции — actions). Ключевые отличия от Vuex: **нет мутаций** — состояние меняют в actions или напрямую, а devtools всё равно отслеживают изменения; **нет вложенных модулей** — вместо них много плоских сторов, которые могут использовать друг друга; **полная поддержка TypeScript** без обёрток и строковых путей вида `'cart/addItem'`; actions могут быть синхронными и асинхронными; сторы **ленивые** и попадают в бандл только при импорте (tree shaking); есть плагины, HMR, SSR-гидрация и интеграция с Vue DevTools. API компактнее: стор — это просто composable `useCartStore()`.

## Вопрос

Что такое Pinia и почему она заменила Vuex в экосистеме Vue 3?

## Стор в Pinia

```ts
// setup store
export const useUserStore = defineStore('user', () => {
  const user = ref<User | null>(null);
  const isLoggedIn = computed(() => !!user.value);

  async function login(credentials: Credentials) {
    user.value = await api.login(credentials);
  }
  function logout() {
    user.value = null;
  }

  return { user, isLoggedIn, login, logout };
});
```

```vue
<script setup lang="ts">
const userStore = useUserStore();
const { user, isLoggedIn } = storeToRefs(userStore);
</script>

<template>
  <button v-if="!isLoggedIn" @click="userStore.login(form)">Войти</button>
  <span v-else>{{ user?.name }}</span>
</template>
```

## Тот же код во Vuex

```js
export default createStore({
  modules: {
    user: {
      namespaced: true,
      state: () => ({ user: null }),
      getters: { isLoggedIn: (s) => !!s.user },
      mutations: { SET_USER(state, user) { state.user = user; } },
      actions: {
        async login({ commit }, credentials) {
          commit('SET_USER', await api.login(credentials));
        },
      },
    },
  },
});

// компонент
this.$store.dispatch('user/login', form);
this.$store.getters['user/isLoggedIn'];
```

## Сравнение

| | Vuex 4 | Pinia |
| --- | --- | --- |
| Статус | Поддержка, без развития | Официальная рекомендация |
| Изменение состояния | Только через mutations | В actions или напрямую |
| Модули | Вложенные, `namespaced` | Плоские независимые сторы |
| Обращение | Строки `'user/login'` | Функции и свойства с типами |
| TypeScript | Сложно | Из коробки |
| Async | В actions, коммит в mutations | Просто `async` action |
| Стиль | Options-подобный | Option или setup store |
| Tree shaking | Все модули регистрируются | Стор попадает в бандл при использовании |
| Devtools | Да | Да (timeline, редактирование state) |

## Почему без мутаций

Мутации во Vuex существовали, чтобы devtools могли синхронно записывать каждое изменение. Pinia отслеживает изменения через реактивность и `$subscribe`/`$onAction`, поэтому отдельный слой мутаций стал лишним: actions — единственный уровень бизнес-логики, а простое изменение можно сделать напрямую (`store.count++`) или пакетно (`store.$patch({...})`).

## Сторы используют друг друга

```ts
export const useCheckoutStore = defineStore('checkout', () => {
  const cart = useCartStore();
  const user = useUserStore();

  async function placeOrder() {
    if (!user.isLoggedIn) throw new Error('Not authenticated');
    await api.createOrder({ items: cart.items, userId: user.user!.id });
    cart.clear();
  }
  return { placeOrder };
});
```

## Миграция с Vuex

1. Каждый модуль Vuex → отдельный `defineStore`.
2. `state` → `state`/`ref`, `getters` → getters/`computed`, `mutations` + `actions` → actions.
3. `this.$store.dispatch('x/y')` → `useXStore().y()`.
4. `mapState`/`mapGetters` в Options API — есть аналоги `mapState`, `mapActions` в Pinia.

## Частые ошибки

- Переносить из Vuex мутации как отдельные actions `SET_X` без необходимости.
- Деструктурировать стор без `storeToRefs`.
- Один огромный стор вместо нескольких доменных.
- Новый проект на Vuex.

## Что важно помнить

- Pinia — официальный стор Vue 3; Vuex — легаси.
- Нет мутаций и вложенных модулей, полная типизация, setup- и option-сторы.
- Стор — composable `useXStore()`, сторы могут использовать друг друга.

## Мини-шпаргалка

- `defineStore('id', () => { ...; return {...} })`.
- `storeToRefs(store)` для state и getters.
- `store.$patch`, `store.$reset` (option store), `$subscribe`, `$onAction`.
- Vuex → Pinia: модуль = стор, mutations → actions.
