# Что такое mixins и extends и почему их заменили composables

> [!NOTE]
> **Mixin** — объект с опциями компонента (`data`, `computed`, `methods`, `watch`, хуки), который **сливается** с опциями компонента через `mixins: [myMixin]`: хуки обоих выполняются (сначала миксина), `data` объединяется рекурсивно, а при конфликте имён в `methods`/`computed` побеждает компонент. **`extends`** — похожая опция для наследования одного базового компонента. Это был основной способ переиспользования логики во Vue 2, но у него три системные проблемы: **неясный источник** свойств (глядя на `this.isLoading`, непонятно, из какого миксина оно пришло), **конфликты имён** между миксинами (молча перезаписываются), **неявные зависимости** (миксин ожидает, что у компонента есть `this.userId`). Плюс плохая типизация и невозможность параметризовать два экземпляра одной логики. Во Vue 3 mixins поддерживаются для совместимости, но официально рекомендуются **composables**: функция возвращает явные значения, их можно переименовать при деструктуризации, передать аргументы, вызвать дважды, и TypeScript видит всё. Глобальные миксины (`app.mixin`) особенно опасны — влияют на каждый компонент, включая сторонние.

## Вопрос

Что такое mixins и extends во Vue и почему вместо них используют composables?

## Mixin

```js
// mixins/pagination.js
export const paginationMixin = {
  data() {
    return { page: 1, pageSize: 20 };
  },
  computed: {
    offset() { return (this.page - 1) * this.pageSize; },
  },
  methods: {
    nextPage() { this.page++; this.load(); },    // неявно ожидает, что в компоненте есть load()
  },
  mounted() { console.log('pagination mounted'); },
};

// компонент
export default {
  mixins: [paginationMixin, filtersMixin],
  methods: {
    load() { api.list({ offset: this.offset, ...this.filters }); },   // откуда offset? откуда filters?
  },
};
```

## Правила слияния

| Опция | Поведение |
| --- | --- |
| `data` | Рекурсивное слияние, при конфликте — значение компонента |
| `methods`, `computed`, `components` | Компонент перезаписывает миксин |
| Хуки (`mounted`) | Вызываются все, сначала миксины |
| `watch` | Объединяются в массив, вызываются все |

## Проблемы

```js
mixins: [paginationMixin, infiniteScrollMixin]
// оба объявляют `page` — один молча перезапишет другой

// два независимых пагинатора на одной странице — невозможно без копирования миксина
```

## То же как composable

```ts
// composables/usePagination.ts
export function usePagination(load: (offset: number, limit: number) => Promise<void>, pageSize = 20) {
  const page = ref(1);
  const offset = computed(() => (page.value - 1) * pageSize);

  async function next() {
    page.value++;
    await load(offset.value, pageSize);
  }

  return { page, offset, next };
}

// компонент — источник каждого значения виден, зависимости переданы явно
const { page: ordersPage, next: nextOrders } = usePagination(loadOrders);
const { page: logsPage, next: nextLogs } = usePagination(loadLogs, 50);   // второй экземпляр
```

## extends

```js
export default {
  extends: BaseListPage,          // наследование опций одного компонента
  methods: { load() { /* переопределение */ } },
};
```

Те же проблемы, что у миксинов, плюс жёсткая иерархия. В Composition API нужное поведение базового компонента выносят в composable или в компонент-обёртку со слотами.

## Сравнение

| | Mixins | Composables |
| --- | --- | --- |
| Источник свойств | Неявный | Явный (импорт и деструктуризация) |
| Конфликты имён | Молча перезаписываются | Переименование при деструктуризации |
| Параметры | Нет | Аргументы функции |
| Несколько экземпляров | Нет | Да |
| TypeScript | Слабо | Полностью |
| Зависимости | Неявные (`this.x`) | Явные аргументы |

## Миграция

1. Выделить из миксина состояние, computed, методы и хуки.
2. Переписать как функцию `useXxx(args)` с `ref`/`computed`/`onMounted`.
3. Неявные зависимости (`this.userId`) превратить в аргументы (`MaybeRefOrGetter`).
4. В Options API-компоненте composable можно вызвать в `setup()` и вернуть значения в шаблон — переход постепенный.

## Частые ошибки

- Глобальные миксины (`app.mixin`) для «удобства».
- Миксины, зависящие от методов и данных компонента.
- Несколько миксинов с пересекающимися именами.
- Новый код на миксинах во Vue 3.

## Что важно помнить

- Mixins сливают опции; extends наследует компонент.
- Проблемы: неявный источник, конфликты имён, скрытые зависимости, слабые типы.
- Во Vue 3 переиспользование логики — composables.

## Мини-шпаргалка

- `mixins: [m]`, `extends: Base`.
- Хуки миксина — первыми; методы компонента — побеждают.
- Замена: `export function useX(args) { return { ... } }`.
- Composable в Options API — через `setup()`.
