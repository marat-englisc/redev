# Как устроен компонент в Options API - data, methods, computed и watch

> [!NOTE]
> В **Options API** компонент описывается объектом опций, а к состоянию и методам обращаются через **`this`** — прокси экземпляра. **`data()`** — функция, возвращающая **новый** объект состояния для каждого экземпляра (поэтому функция, а не объект: иначе все экземпляры делили бы одно состояние); все его свойства становятся реактивными и доступными как `this.x`; свойства, начинающиеся с `_` или `$`, не проксируются. **`methods`** — функции с привязанным `this` (нельзя использовать стрелочные функции); вызываются из шаблона и других опций, **не кешируются**. **`computed`** — кешируемые вычисляемые значения (геттеры или объекты с `get`/`set`). **`watch`** — реакция на изменения: функция или объект с `handler`, `deep`, `immediate`, `flush`; ключ может быть путём (`'user.name'`); строка — имя метода. **`props`**, **`emits`**, хуки (`mounted`), `inject`/`provide`, `components`, `directives`, `expose` — тоже опции. Options API полностью поддерживается во Vue 3 и подходит для простых компонентов и легаси-кода, но в больших компонентах логика одной фичи разбросана по опциям, а переиспользование через mixins проблематично.

## Вопрос

Как устроен компонент в Options API и как работают `data`, `methods`, `computed` и `watch`?

## Полный пример

```vue
<script lang="ts">
import { defineComponent, type PropType } from 'vue';

export default defineComponent({
  name: 'ProductList',

  props: {
    categoryId: { type: String, required: true },
    pageSize: { type: Number, default: 20 },
  },

  emits: { select: (id: string) => typeof id === 'string' },

  data() {
    return {
      products: [] as Product[],
      query: '',
      loading: false,
      page: 1,
    };
  },

  computed: {
    filtered(): Product[] {
      const q = this.query.toLowerCase();
      return this.products.filter((p) => p.title.toLowerCase().includes(q));
    },
    pageItems(): Product[] {
      const start = (this.page - 1) * this.pageSize;
      return this.filtered.slice(start, start + this.pageSize);
    },
    searchModel: {
      get(): string { return this.query; },
      set(v: string) { this.query = v.trim(); this.page = 1; },
    },
  },

  watch: {
    categoryId: { handler: 'load', immediate: true },     // строка — имя метода
    'filtered.length'(n: number) { if (n === 0) this.page = 1; },
  },

  methods: {
    async load() {
      this.loading = true;
      try {
        this.products = await api.getProducts(this.categoryId);
      } finally {
        this.loading = false;
      }
    },
    select(id: string) {
      this.$emit('select', id);
    },
  },

  mounted() {
    (this.$refs.search as HTMLInputElement | undefined)?.focus();
  },
});
</script>

<template>
  <input ref="search" v-model="searchModel" />
  <p v-if="loading">Загрузка…</p>
  <ProductCard v-for="p in pageItems" :key="p.id" :product="p" @click="select(p.id)" />
</template>
```

## data — функция

```js
// ✗ объект — общий для всех экземпляров (Vue 3 выдаст ошибку)
data: { count: 0 }

// ✓
data() { return { count: 0 }; }
```

Все поля нужно объявить в `data` заранее — в Vue 3 добавление позже тоже реактивно, но объявление делает состояние явным.

## methods и this

```js
methods: {
  inc() { this.count++; },              // ✓
  dec: () => { this.count--; },         // ✗ стрелка: this — не экземпляр
}
```

Методы, используемые как обработчики `debounce`, создают в `created`, а не в `methods`, чтобы у каждого экземпляра был свой таймер:

```js
created() { this.debouncedSearch = debounce(this.search, 300); },
unmounted() { this.debouncedSearch.cancel(); },
```

## computed и methods

| `computed` | `methods` |
| --- | --- |
| Кешируется по зависимостям | Выполняется при каждом вызове |
| Без аргументов | Принимают аргументы |
| `{{ total }}` | `{{ formatPrice(p.price) }}` |

## watch: формы

```js
watch: {
  query(newVal, oldVal) {},                                  // функция
  filters: { handler: 'applyFilters', deep: true },          // объект + имя метода
  '$route.params.id': { handler: 'load', immediate: true },  // путь
  items: [{ handler: 'save', flush: 'post' }, 'logChange'],  // несколько обработчиков
},
```

Программно — `this.$watch('query', cb, opts)`, возвращает функцию остановки.

## Связь с Composition API

| Options API | Composition API |
| --- | --- |
| `data()` | `ref`, `reactive` |
| `computed` | `computed()` |
| `methods` | Обычные функции |
| `watch` | `watch()`, `watchEffect()` |
| `mounted` | `onMounted()` |
| `this.$emit` | `defineEmits()` |
| `this.$refs.x` | `useTemplateRef('x')` |

## Частые ошибки

- `data` объектом вместо функции.
- Стрелочные функции в `methods`, `computed`, хуках.
- Тяжёлые вычисления в методах шаблона вместо `computed`.
- Общий debounce в `methods` для всех экземпляров.
- Мутация props через `this.propName = ...`.

## Что важно помнить

- Options API — опции + `this`; `data` — фабрика состояния экземпляра.
- `computed` кеширует, `methods` — нет, `watch` — побочные эффекты.
- Каждая опция имеет прямой аналог в Composition API.

## Мини-шпаргалка

- `data() { return {...} }`.
- `methods: { fn() {} }` — без стрелок.
- `computed: { x() {}, y: { get, set } }`.
- `watch: { a: { handler, deep, immediate } }`, `this.$watch`.
