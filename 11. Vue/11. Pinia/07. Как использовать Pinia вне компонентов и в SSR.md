# Как использовать Pinia вне компонентов и в SSR

> [!NOTE]
> `useXxxStore()` ищет **активный экземпляр pinia**. Внутри `setup` компонентов он берётся из приложения автоматически; **вне компонентов** (navigation guards роутера, API-клиенты, обычные модули) стор можно вызывать только **после** `app.use(pinia)` и **внутри функций**, которые выполняются позже (в guard, обработчике, action), а не на верхнем уровне модуля при импорте. Иначе — ошибка «getActivePinia() was called but there was no active Pinia». В модулях, где экземпляр pinia доступен, его можно передать явно: `useUserStore(pinia)`. В **SSR** каждый запрос должен получать **свой** экземпляр pinia (иначе состояние одного пользователя «протечёт» к другому): на сервере создают `createPinia()` на запрос, после рендера сериализуют `pinia.state.value` в HTML, а на клиенте восстанавливают его до монтирования (`pinia.state.value = window.__PINIA__`) — это **гидрация** состояния. Nuxt с `@pinia/nuxt` делает всё это автоматически. В **тестах** для изолированных сторов используют `setActivePinia(createPinia())`, а для компонентов — `createTestingPinia()` из `@pinia/testing`.

## Вопрос

Как использовать Pinia в navigation guards и других модулях вне компонентов и как работает Pinia в SSR?

## В navigation guard

```ts
// router/index.ts
export const router = createRouter({ history: createWebHistory(), routes });

router.beforeEach(async (to) => {
  const auth = useAuthStore();              // ✓ внутри guard: pinia уже установлена (main.ts: app.use(pinia) до app.use(router))
  if (!auth.initialized) await auth.fetchMe();
  if (to.meta.requiresAuth && !auth.isLoggedIn) {
    return { name: 'login', query: { redirect: to.fullPath } };
  }
});
```

```ts
// ✗ на верхнем уровне модуля — выполнится при импорте, до app.use(pinia)
const auth = useAuthStore();
router.beforeEach(() => auth.isLoggedIn);
```

## В API-клиенте

```ts
// api/http.ts
export async function http<T>(url: string, init: RequestInit = {}): Promise<T> {
  const auth = useAuthStore();              // вызов внутри функции — при запросе
  const res = await fetch(url, { ...init, headers: { ...init.headers, 'Accept-Language': auth.locale } });
  if (res.status === 401) auth.handleUnauthorized();
  if (!res.ok) throw new ApiError(res.status, await res.json());
  return res.json();
}
```

## Явная передача экземпляра

```ts
// main.ts
export const pinia = createPinia();
app.use(pinia);

// где-то вне компонентов, где важно не зависеть от «активного» экземпляра
const settings = useSettingsStore(pinia);
```

## SSR вручную

```ts
// entry-server.ts
export async function render(url: string) {
  const app = createSSRApp(App);
  const pinia = createPinia();               // новый на каждый запрос
  const router = createAppRouter();
  app.use(pinia).use(router);

  await router.push(url);
  await router.isReady();
  const html = await renderToString(app);

  const state = devalue.uneval(pinia.state.value);    // безопасная сериализация (без XSS)
  return { html, stateScript: `<script>window.__PINIA__=${state}</script>` };
}

// entry-client.ts
const pinia = createPinia();
if (window.__PINIA__) pinia.state.value = window.__PINIA__;   // гидрация до mount
app.use(pinia).mount('#app');
```

`JSON.stringify` без экранирования в `<script>` — XSS-риск (строка `</script>` в данных); используют `devalue` или аналог.

## SSR-ограничения для сторов

- Никакого состояния на уровне модуля вне `defineStore` — оно общее для всех запросов.
- Не обращайтесь к `window`/`localStorage` в state и actions, выполняемых на сервере.
- Состояние должно быть сериализуемым (без функций, классов, DOM-узлов) — несериализуемое держите вне возвращаемого state.

## Nuxt

```ts
// nuxt.config.ts
modules: ['@pinia/nuxt']
```

Nuxt создаёт pinia на запрос, сериализует и гидрирует state автоматически; данные для SSR в сторе загружают через `callOnce` или `useAsyncData` — см. [Pinia в Nuxt](<../../12. Nuxt/04. Data fetching state и runtime config/09. Как использовать Pinia в Nuxt.md>).

## Тесты

```ts
// unit-тест стора
beforeEach(() => setActivePinia(createPinia()));

it('добавляет товар', () => {
  const cart = useCartStore();
  cart.add(product);
  expect(cart.count).toBe(1);
});

// компонент со стором
mount(CartBadge, { global: { plugins: [createTestingPinia({ initialState: { cart: { items: [item] } } })] } });
```

## Частые ошибки

- `useStore()` на верхнем уровне модуля роутера или API-клиента.
- `app.use(router)` раньше `app.use(pinia)`, когда guards используют сторы при первом переходе.
- Глобальный `createPinia()` в SSR, общий для всех запросов.
- Небезопасная сериализация state в HTML.
- Несериализуемые значения в state при SSR.

## Что важно помнить

- Вне компонентов — вызывать сторы внутри функций, после `app.use(pinia)`, или передавать экземпляр явно.
- SSR: pinia на запрос, сериализация `pinia.state.value`, гидрация до `mount`.
- Тесты: `setActivePinia(createPinia())`, `createTestingPinia()`.

## Мини-шпаргалка

- `router.beforeEach(() => { const s = useStore(); ... })`.
- `useStore(pinia)`.
- `pinia.state.value` — сериализация/гидрация.
- `@pinia/nuxt`, `setActivePinia`, `createTestingPinia`.
