# Как работать со state, getters и actions

> [!NOTE]
> **State** — источник данных стора: все поля объявляют заранее с начальными значениями (это даёт типы, DevTools и SSR-сериализацию); state можно менять напрямую (`store.count++`), пакетно через `$patch` или в actions. **Getters** — вычисляемые значения (как `computed`): кешируются, пересчитываются при изменении зависимостей, могут использовать другие getters и другие сторы; должны быть **чистыми**. Если нужен getter с параметром — он возвращает функцию (`getById: (s) => (id) => ...`), но такой getter **не кешируется** по аргументу. **Actions** — бизнес-логика: изменение state, асинхронные запросы, вызовы других сторов, обработка ошибок; возвращают значения и промисы, а их вызовы видны в DevTools и в `$onAction`. Хорошая практика: компоненты вызывают actions, а не дублируют логику изменения; запросы к API — в actions или в отдельном API-слое, который actions вызывают; состояние загрузки и ошибки — тоже часть state стора.

## Вопрос

Как работать со state, getters и actions в Pinia?

## Стор каталога

```ts
export const useCatalogStore = defineStore('catalog', () => {
  // state
  const products = ref<Product[]>([]);
  const loading = ref(false);
  const error = ref<string | null>(null);
  const filters = reactive({ q: '', categoryId: null as string | null });

  // getters
  const visible = computed(() =>
    products.value.filter((p) =>
      (!filters.categoryId || p.categoryId === filters.categoryId) &&
      p.title.toLowerCase().includes(filters.q.toLowerCase()),
    ),
  );
  const byId = computed(() => new Map(products.value.map((p) => [p.id, p])));   // кешируемый индекс
  const getById = (id: string) => byId.value.get(id);                          // функция поверх кеша

  // actions
  async function load() {
    if (loading.value) return;
    loading.value = true;
    error.value = null;
    try {
      products.value = await catalogApi.list();
    } catch (e) {
      error.value = 'Не удалось загрузить каталог';
      throw e;
    } finally {
      loading.value = false;
    }
  }

  function setCategory(id: string | null) {
    filters.categoryId = id;
  }

  return { products, loading, error, filters, visible, byId, getById, load, setCategory };
});
```

## Изменение state

```ts
const catalog = useCatalogStore();

catalog.filters.q = 'клавиатура';                         // напрямую
catalog.$patch({ loading: false, error: null });          // пакетно — объект
catalog.$patch((state) => {                               // пакетно — функция (для массивов)
  state.products.push(newProduct);
  state.error = null;
});
catalog.setCategory('keyboards');                          // через action
```

`$patch` объединяет несколько изменений в одну запись в DevTools.

## Getters с аргументом

```ts
// option store
getters: {
  getById: (state) => (id: string) => state.products.find((p) => p.id === id),   // не кешируется
}

// использование
catalog.getById('p1');
```

Для частых обращений по id лучше кешируемый `Map` (как `byId` выше).

## Getters из других сторов

```ts
export const useCheckoutStore = defineStore('checkout', () => {
  const cart = useCartStore();
  const user = useUserStore();
  const canCheckout = computed(() => user.isLoggedIn && cart.count > 0);
  return { canCheckout };
});
```

## Actions и ошибки

```ts
async function submit() {
  try {
    await checkout.placeOrder();
    router.push('/thanks');
  } catch {
    toast.error('Не получилось оформить заказ');
  }
}
```

Action может бросать исключение — решение о UI (тост, сообщение у формы) принимает компонент.

## Слои

```text
Component ──► store action ──► API service (fetch, заголовки, base URL) ──► HTTP
    ▲                │
    └── state/getters┘
```

## Частые ошибки

- Добавлять поля в state «на лету» — нет типов и SSR-сериализации.
- Запросы и мутации внутри getters.
- Getter-функции с тяжёлой логикой на каждый вызов в шаблоне.
- Дублировать логику изменения состояния в нескольких компонентах вместо action.
- Глотать ошибки в action без сигнала компоненту.

## Что важно помнить

- State объявляется заранее; меняется напрямую, `$patch` или actions.
- Getters — чистые кешируемые вычисления; getter-функции не кешируются.
- Actions — бизнес-логика и async; ошибки пробрасываются или хранятся в state.

## Мини-шпаргалка

- `store.x = v`, `store.$patch({...})`, `store.$patch((s) => {...})`.
- `computed` / `getters: { y: (s) => ... }`.
- `getById: (s) => (id) => ...`.
- `async function action() { try {...} finally {...} }`.
