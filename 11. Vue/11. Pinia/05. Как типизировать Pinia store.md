# Как типизировать Pinia store

> [!NOTE]
> Pinia написана на TypeScript и выводит типы автоматически: state — из начальных значений, getters — из возвращаемых значений, actions — из сигнатур функций. Помогать типизации нужно там, где вывод невозможен: **`null`** и **пустые массивы** (`ref<User | null>(null)`, `[] as Product[]` или интерфейс state `state: (): CartState => ({...})`), **getters через `this`** в option store (нужен явный тип возврата, иначе циклическая зависимость типов), payload-ы actions (отдельные интерфейсы). В **setup store** типизация такая же, как в обычном Composition API, поэтому она обычно проще. Тип стора целиком — `ReturnType<typeof useCartStore>`; типы state/getters/actions по отдельности можно получить хелперами. Для плагинов, которые добавляют свойства во все сторы, расширяют интерфейсы `PiniaCustomProperties` и `PiniaCustomStateProperties`, а опции `defineStore` — через `DefineStoreOptionsBase`.

## Вопрос

Как правильно типизировать Pinia store?

## Option store

```ts
interface User { id: string; email: string; role: 'user' | 'admin' }
interface AuthState { user: User | null; token: string | null; loading: boolean }
interface LoginPayload { email: string; password: string }

export const useAuthStore = defineStore('auth', {
  state: (): AuthState => ({ user: null, token: null, loading: false }),

  getters: {
    isLoggedIn: (state) => state.user !== null,       // тип выводится
    isAdmin(): boolean {                              // через this — явный тип
      return this.user?.role === 'admin';
    },
  },

  actions: {
    async login(payload: LoginPayload): Promise<void> {
      this.loading = true;
      try {
        const { user, token } = await authApi.login(payload);
        this.user = user;
        this.token = token;
      } finally {
        this.loading = false;
      }
    },
  },
});
```

## Setup store

```ts
export const useAuthStore = defineStore('auth', () => {
  const user = ref<User | null>(null);
  const items = ref<Product[]>([]);                 // явный тип пустого массива
  const isAdmin = computed(() => user.value?.role === 'admin');   // ComputedRef<boolean>

  async function login(payload: LoginPayload): Promise<void> { /* ... */ }

  return { user, items, isAdmin, login };
});
```

## Типы стора

```ts
type AuthStore = ReturnType<typeof useAuthStore>;

function useGuard(store: AuthStore) { /* ... */ }
```

## storeToRefs сохраняет типы

```ts
const { user, isAdmin } = storeToRefs(useAuthStore());   // Ref<User | null>, ComputedRef<boolean>
```

## Расширение для плагинов

```ts
// pinia-plugins.d.ts
import 'pinia';

declare module 'pinia' {
  export interface PiniaCustomProperties {
    $api: ApiClient;                     // добавлено плагином во все сторы
  }
  export interface DefineStoreOptionsBase<S, Store> {
    debounce?: Partial<Record<keyof StoreActions<Store>, number>>;   // своя опция defineStore
  }
}
```

## Без лишних аннотаций

```ts
// ✗ избыточно — Pinia выведет сама
const count: Ref<number> = ref<number>(0);

// ✓
const count = ref(0);
```

Явные типы нужны там, где TypeScript иначе выведет `null`, `never[]` или потеряет связь `this`.

## Частые ошибки

- `items: []` в state без типа — `never[]`.
- `user: null` без типа — нельзя присвоить пользователя.
- Getter через `this` без типа возврата — `any` или ошибка циклического типа.
- Ручное описание полного типа стора вместо `ReturnType<typeof useStore>`.

## Что важно помнить

- Pinia выводит типы; помогать нужно для `null`, пустых массивов и getters через `this`.
- Setup store типизируется как обычный Composition API.
- Плагины расширяют `PiniaCustomProperties`.

## Мини-шпаргалка

- `state: (): State => ({...})`, `[] as T[]`, `ref<T | null>(null)`.
- `getter(): ReturnType { return this... }`.
- `ReturnType<typeof useStore>`.
- `declare module 'pinia' { interface PiniaCustomProperties {} }`.
