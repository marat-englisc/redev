# Как использовать useFetch

> [!NOTE]
> **`useFetch(url, options?)`** из VueUse — реактивная обёртка над `fetch`: возвращает ref-ы `data`, `error`, `statusCode`, `response`, `isFetching`, `isFinished`, `aborted` и методы `execute()` (повторить запрос), `abort()`, а также хуки `onFetchResponse`/`onFetchError`. Формат и метод задаются цепочкой: `.json()`, `.text()`, `.blob()`, `.get()`, `.post(body)`, `.put()`, `.delete()`. **`url` может быть ref или геттером** — с опцией `refetch: true` запрос повторяется при его изменении, а предыдущий незавершённый запрос **отменяется** (защита от гонок). `immediate: false` — не выполнять сразу (для форм), `timeout` — отмена по времени, `initialData`. Хуки опций `beforeFetch` (добавить заголовок авторизации, отменить запрос), `afterFetch` (преобразовать данные), `onFetchError` (нормализовать ошибку). **`createFetch({ baseUrl, options, fetchOptions })`** создаёт настроенный экземпляр для API приложения. Ограничения: нет кеша, дедупликации, ретраев и инвалидации — для серверного состояния в больших приложениях лучше **TanStack Query** (`@tanstack/vue-query`) или **Pinia Colada**, а в Nuxt — встроенные `useFetch`/`useAsyncData` (это **другая** функция с SSR-поддержкой). Важно: по умолчанию ответ с HTTP-ошибкой (4xx/5xx) заполняет `error`, но `data` тоже может быть заполнен телом ответа.

## Вопрос

Как использовать `useFetch` из VueUse для загрузки данных?

## Базовый запрос

```vue
<script setup lang="ts">
import { useFetch } from '@vueuse/core';

type Product = { id: number; title: string; price: number };

const { data, error, isFetching, execute } = useFetch('/api/products').json<Product[]>();
</script>

<template>
  <p v-if="isFetching">Загрузка…</p>
  <div v-else-if="error">
    Не удалось загрузить товары. <button @click="execute()">Повторить</button>
  </div>
  <ProductGrid v-else :products="data ?? []" />
</template>
```

## Реактивный URL

```ts
const route = useRoute();
const query = ref('');
const page = computed(() => Number(route.query.page ?? 1));

const url = computed(() => `/api/products?q=${encodeURIComponent(query.value)}&page=${page.value}`);

const { data, isFetching } = useFetch(url, { refetch: true }).json<Paginated<Product>>();
// смена query/page → новый запрос, предыдущий отменяется
```

Для ввода в поиске используйте `refDebounced(query, 300)` в составе URL, чтобы не слать запрос на каждую клавишу.

## POST и формы

```ts
const form = reactive({ email: '', message: '' });

const { execute: send, isFetching: sending, error, statusCode } = useFetch('/api/feedback', { immediate: false })
  .post(form)                       // объект сериализуется в JSON
  .json<{ ok: true }>();

async function onSubmit() {
  await send();
  if (!error.value) toast.success('Отправлено');
}
```

## Настроенный клиент: createFetch

```ts
// api/useApi.ts
import { createFetch } from '@vueuse/core';

export const useApi = createFetch({
  baseUrl: import.meta.env.VITE_API_URL,
  options: {
    timeout: 10_000,
    async beforeFetch({ options, cancel }) {
      const auth = useAuthStore();
      if (!auth.isLoggedIn) cancel();                               // отменить запрос
      options.headers = { ...options.headers, 'X-Request-Id': crypto.randomUUID() };
      return { options };
    },
    afterFetch(ctx) {
      if (ctx.data?.items) ctx.data = ctx.data.items;                // развернуть обёртку ответа
      return ctx;
    },
    onFetchError(ctx) {
      if (ctx.response?.status === 401) useAuthStore().logout();
      ctx.error = new Error(ctx.data?.message ?? 'Ошибка сети');
      return ctx;
    },
  },
  fetchOptions: { credentials: 'include' },                          // cookie-сессия
});

const { data } = useApi('/orders').json<Order[]>();
```

## Возвращаемые значения

| Ref / метод | Значение |
| --- | --- |
| `data` | Тело ответа (после `.json()` — объект) |
| `error` | Ошибка сети или HTTP |
| `statusCode`, `response` | Статус и объект `Response` |
| `isFetching`, `isFinished`, `aborted` | Состояния |
| `execute(throwOnFailed?)` | Выполнить ещё раз |
| `abort()`, `canAbort` | Отмена |
| `onFetchResponse`, `onFetchError`, `onFetchFinally` | Подписки на события |

## Когда что использовать

| Задача | Инструмент |
| --- | --- |
| Простой запрос в компоненте, прототип | VueUse `useFetch` |
| Кеш, дедупликация, фоновое обновление, инвалидация, пагинация | TanStack Query, Pinia Colada |
| Nuxt + SSR | Nuxt `useFetch` / `useAsyncData` |
| Сложные клиенты (интерсепторы, загрузка файлов с прогрессом) | `ofetch`, axios + `useAxios` из integrations |

## Частые ошибки

- Ждать данных синхронно сразу после вызова — `data` заполнится позже (используйте `await useFetch(...)`, `until(isFinished)` или `watch`).
- Реактивный URL без `refetch: true` — смена параметров не вызывает запрос.
- Путать VueUse `useFetch` и Nuxt `useFetch` — разные API и поведение SSR.
- Не обрабатывать `error` и состояние загрузки.
- Использовать как замену слою кеширования серверного состояния в большом приложении.

## Что важно помнить

- Реактивные `data`/`error`/`isFetching`, цепочка `.get/.post().json()`.
- `refetch: true` + реактивный URL; отмена предыдущего запроса.
- `createFetch` — общий клиент с `beforeFetch`/`afterFetch`/`onFetchError`.

## Мини-шпаргалка

- `useFetch(url).json<T>()`.
- `useFetch(url, { immediate: false }).post(body).json()` + `execute()`.
- `{ refetch: true, timeout, initialData }`.
- `createFetch({ baseUrl, options: { beforeFetch, afterFetch, onFetchError } })`.
