# Как использовать useStorage, useLocalStorage и useSessionStorage

> [!NOTE]
> **`useStorage(key, initial, storage?, options?)`** возвращает ref, **двусторонне синхронизированный** с Web Storage: чтение берёт сохранённое значение (или `initial`, если ключа нет), запись сразу сохраняет. `useLocalStorage` и `useSessionStorage` — сокращения для конкретного хранилища (`localStorage` живёт без срока и общий для всех вкладок origin, `sessionStorage` — пока открыта вкладка). Тип сериализации определяется по `initial`: строки, числа, булевы значения, `Date`, `Map`, `Set` и объекты (через JSON) — или задаётся `serializer`. Полезные опции: `mergeDefaults` (дополнить сохранённый объект новыми полями из `initial` — важно при развитии схемы), `listenToStorageChanges` (синхронизация между вкладками через событие `storage`, включено по умолчанию), `writeDefaults`, `initOnMounted` (читать значение после монтирования — избегает расхождения гидратации в SSR), `deep`, `onError`. Есть `useStorageAsync` для асинхронных хранилищ и `useIDBKeyval` (из `@vueuse/integrations`) для IndexedDB. Выбор: `useLocalStorage` — для локального UI-состояния composable или компонента (тема, свёрнутая панель, черновик); [Pinia Persisted State](<../12. Pinia PersistedState/01. Что такое Pinia Persisted State.md>) — когда данные уже живут в сторе. Web Storage доступен любому JS на странице: **не храните там токены и персональные данные** — при XSS они будут украдены.

## Вопрос

Как работать с `useStorage`, `useLocalStorage` и `useSessionStorage` из VueUse?

## Базовое использование

```ts
import { useLocalStorage, useSessionStorage, useStorage } from '@vueuse/core';

const theme = useLocalStorage<'light' | 'dark'>('theme', 'light');
theme.value = 'dark';                        // localStorage.theme = 'dark'

const viewMode = useLocalStorage('catalog:view', 'grid');
const perPage = useLocalStorage('catalog:per-page', 24);          // число — вернётся числом
const filtersOpen = useLocalStorage('catalog:filters-open', true); // булево

const draft = useSessionStorage('review-draft', { rating: 0, text: '' });
draft.value.text = 'Отличная клавиатура';    // объект сериализуется в JSON (deep по умолчанию)

const custom = useStorage('key', 'value', localStorage);           // хранилище третьим аргументом
```

## Развитие схемы

```ts
// v1 сохранил { columns: [...] }, v2 добавил density
const tableSettings = useLocalStorage(
  'orders-table',
  { columns: ['id', 'date', 'total'], density: 'comfortable' },
  { mergeDefaults: true },                   // сохранённое + отсутствующие поля из initial
);
```

```ts
// версия ключа при несовместимых изменениях
const settings = useLocalStorage('orders-table:v2', defaults);
```

## Свой сериализатор

```ts
import { StorageSerializers } from '@vueuse/core';

const lastVisit = useLocalStorage<Date | null>('last-visit', null, {
  serializer: StorageSerializers.date,       // для null-initial тип не угадывается — задайте явно
});

const recent = useLocalStorage<Product[] | null>('recent', null, { serializer: StorageSerializers.object });
```

## Удаление

```ts
theme.value = null;          // удаляет ключ из хранилища, ref вернётся к null
```

## Синхронизация между вкладками

```ts
const cartCount = useLocalStorage('cart-count', 0);
// изменение в одной вкладке → событие storage → ref обновляется в других вкладках
```

Событие `storage` срабатывает только для `localStorage` и только в **других** вкладках.

## SSR и гидратация

```ts
// на сервере хранилища нет → рендерится initial; на клиенте — сохранённое значение → hydration mismatch
const sidebar = useLocalStorage('sidebar', false, { initOnMounted: true });   // читать после монтирования
```

В Nuxt для значений, нужных уже на сервере (тема без мигания), используют cookie (`useCookie`).

## useLocalStorage или Pinia Persisted State

| `useLocalStorage` | Pinia Persisted State |
| --- | --- |
| Состояние одного компонента/composable | Состояние стора, нужное многим |
| Простые настройки UI | Сложная модель + actions + getters |
| Без стора | Уже используется Pinia |

## Что не хранить

| Не хранить | Почему | Альтернатива |
| --- | --- | --- |
| Access/refresh-токены | Кража при XSS | httpOnly cookie |
| Персональные данные | Остаются на общем компьютере | Сервер |
| Большие массивы | Лимит ~5 МБ, синхронная запись блокирует поток | IndexedDB (`useIDBKeyval`) |
| Права и роли «для проверки» | Пользователь их изменит | Проверка на сервере |

## Частые ошибки

- `initial: null` без `serializer` — значение читается как строка.
- Изменить структуру объекта без `mergeDefaults` или версии ключа — старые данные ломают UI.
- Hydration mismatch в SSR без `initOnMounted`.
- Хранить секреты и токены.
- Одинаковые ключи в разных частях приложения — используйте префиксы (`catalog:view`).

## Что важно помнить

- `useStorage` — ref, синхронизированный с хранилищем; тип по `initial` или `serializer`.
- `mergeDefaults`, `initOnMounted`, синхронизация вкладок.
- Web Storage публичен для JS — только неконфиденциальные данные.

## Мини-шпаргалка

- `useLocalStorage('key', initial)`, `useSessionStorage(...)`.
- `{ mergeDefaults: true }`, `{ initOnMounted: true }`.
- `serializer: StorageSerializers.object | date | map | set`.
- `ref.value = null` — удалить ключ.
