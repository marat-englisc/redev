# Что делает reactive

> [!NOTE]
> `reactive(obj)` возвращает **глубоко реактивный Proxy** исходного объекта: чтение любого свойства (в том числе вложенного) отслеживается, запись, добавление и удаление — запускают эффекты; `.value` не нужен. Работает только с **объектными типами**: объектами, массивами, `Map`, `Set` (не с примитивами). У `reactive` есть ограничения, из-за которых документация рекомендует `ref` как основной инструмент: нельзя **заменить** объект целиком (переменная перестанет указывать на отслеживаемый Proxy), при **деструктуризации** и передаче отдельного свойства в функцию теряется связь, а Proxy **не равен** исходному объекту по `===`. `reactive` удобен для группы связанных полей — например, состояния формы, — которые изменяются по отдельности, а не заменяются. Повторный вызов `reactive` для того же объекта возвращает тот же Proxy, а для уже реактивного — его самого.

## Вопрос

Что делает `reactive()` и когда его использовать?

## Пример

```vue
<script setup lang="ts">
import { reactive } from 'vue';

const form = reactive({
  email: '',
  password: '',
  remember: false,
  errors: {} as Record<string, string>,
});

function validate() {
  form.errors = {};
  if (!form.email.includes('@')) form.errors.email = 'Некорректный email';
}
</script>

<template>
  <input v-model="form.email" />
  <span v-if="form.errors.email">{{ form.errors.email }}</span>
  <input v-model="form.password" type="password" />
  <label><input v-model="form.remember" type="checkbox" /> Запомнить</label>
</template>
```

## Глубина и коллекции

```ts
const state = reactive({
  user: { profile: { city: 'Москва' } },
  items: [] as Item[],
  cache: new Map<string, Item>(),
});

state.user.profile.city = 'Казань';   // реактивно
state.items.push(item);               // реактивно
state.cache.set(item.id, item);       // реактивно
state.newField = 1;                   // добавление свойства — тоже реактивно
```

## Ограничения

```ts
let state = reactive({ count: 0 });

// ✗ замена объекта — шаблон и эффекты продолжают смотреть на старый Proxy
state = reactive({ count: 1 });

// ✓ менять свойства или Object.assign
Object.assign(state, { count: 1 });

// ✗ деструктуризация — count просто число
const { count } = state;

// ✓ toRefs сохраняет связь
const { count: countRef } = toRefs(state);

// ✗ передача примитивного свойства в функцию
track(state.count);          // передано число 0, не реактивная ссылка

// ✓ передать геттер или ref
track(() => state.count);
```

## reactive и ref

```ts
const a = reactive({ list: [] as string[] });
a.list = await fetchList();           // ✓ замена свойства — ок

const b = ref<string[]>([]);
b.value = await fetchList();           // ✓ замена значения ref — ок
```

Если состояние нужно часто заменять целиком (ответ API), удобнее `ref`. Если это набор полей, меняющихся по отдельности (форма), — `reactive` или `ref` с объектом. Подробное сравнение — [ref vs reactive](<05. Чем ref отличается от reactive и как не потерять реактивность.md>).

## Идентичность

```ts
const raw = { a: 1 };
const proxy = reactive(raw);
proxy === raw;                 // false
reactive(raw) === proxy;       // true — кеширование
reactive(proxy) === proxy;     // true
toRaw(proxy) === raw;          // true
```

## Частые ошибки

- `reactive(0)` — для примитивов не работает (вернёт значение и предупреждение).
- Переприсваивание переменной с `reactive`.
- Деструктуризация без `toRefs`.
- Изменения через исходный (raw) объект.
- Использование `reactive` для данных, которые полностью заменяются ответом API.

## Что важно помнить

- `reactive` — глубокий Proxy для объектов, без `.value`.
- Нельзя заменять целиком и деструктурировать без `toRefs`.
- Для заменяемых значений — `ref`.

## Мини-шпаргалка

- `const s = reactive({ ... })` → `s.field`.
- `Object.assign(s, patch)` вместо `s = {...}`.
- `toRefs(s)` для деструктуризации.
- `toRaw(s)` — исходный объект.
