# Чем ref отличается от reactive и как не потерять реактивность

> [!NOTE]
> `ref` — контейнер для **любого** значения с доступом через `.value`, который можно заменять целиком, передавать в функции и возвращать из composables без потери связи. `reactive` — Proxy **объекта** без `.value`, но его нельзя заменить целиком и нельзя деструктурировать. Документация Vue рекомендует **`ref` как основной способ** объявления состояния. Реактивность чаще всего теряют, когда вынимают **примитивное значение** из реактивного источника: деструктуризация `reactive` или стора, копирование `props.x` в локальную переменную, передача `state.count` (число) в функцию. Способы сохранить связь: **`toRefs(obj)`** — превратить все свойства в ref-ы, **`toRef(obj, 'key')`** — один ref на свойство (для props), **геттер** `() => props.id` — для `watch` и composables (принимаются через `toValue`), **`storeToRefs(store)`** — для Pinia, **`computed`** — для производного значения, а для props в Vue 3.5+ — **реактивная деструктуризация** в `<script setup>` (`const { id } = defineProps()` компилируется в `props.id`).

## Вопрос

Чем `ref` отличается от `reactive` и как не потерять реактивность при работе с ними?

## Сравнение

| | `ref` | `reactive` |
| --- | --- | --- |
| Типы значений | Любые | Объекты, массивы, Map, Set |
| Доступ в скрипте | `.value` | Напрямую |
| Доступ в шаблоне | Без `.value` (верхний уровень) | Напрямую |
| Замена целиком | `x.value = newValue` | Нельзя (только свойства / `Object.assign`) |
| Деструктуризация | Ref-ы из объекта-результата — безопасно | Теряет реактивность (нужен `toRefs`) |
| Передача в функции | Как ref — реактивно | Только весь объект или геттер |
| Рекомендация Vue | Основной инструмент | Для групп полей, когда удобно |

## Где теряется реактивность

```ts
const state = reactive({ count: 0, user: { name: 'Ann' } });

const { count } = state;            // ✗ число
let name = state.user.name;         // ✗ строка

const props = defineProps<{ id: string }>();
const id = props.id;                // ✗ значение на момент setup (до 3.5 и без деструктуризации)

const store = useCartStore();
const { items } = store;            // ✗ теряет реактивность (state)
```

## Как сохранить

```ts
// toRefs — все свойства в ref-ы
const { count, user } = toRefs(state);
count.value++;                       // меняет state.count

// toRef — одно свойство
const idRef = toRef(props, 'id');

// геттер
watch(() => props.id, load);
useUser(() => props.id);             // composable принимает MaybeRefOrGetter и использует toValue()

// Pinia
const { items, total } = storeToRefs(store);   // state и getters
const { addItem } = store;                     // actions — можно деструктурировать напрямую

// computed
const fullName = computed(() => `${state.user.name} ${state.user.surname}`);
```

## Реактивная деструктуризация props (Vue 3.5+)

```vue
<script setup lang="ts">
const { id, size = 'md' } = defineProps<{ id: string; size?: 'sm' | 'md' }>();

watch(() => id, load);     // компилятор превращает id в props.id; в watch всё равно передают геттер
</script>
```

Работает только в `<script setup>` на верхнем уровне `defineProps`. Передавать `id` в функцию напрямую (`useUser(id)`) — значит передать значение; нужен геттер `() => id`.

## Composables: принимаем ref, геттер или значение

```ts
import { toValue, type MaybeRefOrGetter } from 'vue';

export function useProduct(id: MaybeRefOrGetter<string>) {
  const product = ref<Product | null>(null);
  watchEffect(async () => {
    product.value = await api.getProduct(toValue(id));   // отслеживает id, если это ref или геттер
  });
  return { product };
}

useProduct('p1');                    // статичное значение
useProduct(selectedId);              // ref
useProduct(() => route.params.id);   // геттер
```

## Что выбрать

| Ситуация | Выбор |
| --- | --- |
| Примитив, флаг, счётчик | `ref` |
| Данные, которые заменяются целиком (ответ API) | `ref` |
| Возвращаемые значения composable | `ref`/`computed` |
| Группа полей формы, меняющихся по отдельности | `reactive` (или `ref` с объектом) |
| Нужно деструктурировать `reactive` | `toRefs` |

## Частые ошибки

- Деструктуризация `reactive`, props (без 3.5-компиляции) и стора.
- Передача `props.x` в composable как значения.
- `watch(state.count, ...)` — передано число, нужен геттер `() => state.count`.
- Смешивать стили хаотично: в одном файле и `reactive`, и множество отдельных `ref` для одних и тех же данных.

## Что важно помнить

- `ref` — универсален и рекомендуем; `reactive` — для объектов без замены.
- Реактивность теряется при извлечении примитива из реактивного источника.
- `toRefs`, `toRef`, геттеры, `storeToRefs`, `computed`, деструктуризация props 3.5+ — способы сохранить связь.

## Мини-шпаргалка

- `const { a } = toRefs(state)`.
- `toRef(props, 'id')` или `() => props.id`.
- `storeToRefs(store)`.
- `MaybeRefOrGetter<T>` + `toValue()` в composables.
- `watch(() => obj.x, cb)`.
