# Когда компонент перерисовывается и что такое nextTick

> [!NOTE]
> Каждый компонент имеет свой **render-эффект**. Компонент перерисовывается, когда меняются реактивные данные, **прочитанные в его рендере**: собственное состояние, props, используемые в шаблоне, `computed`, состояние сторов и `inject`-значения. Изменения не применяются к DOM сразу: Vue ставит задачу обновления в **очередь** и выполняет все накопившиеся обновления **одним пакетом** в микрозадаче — десять изменений подряд дадут одну перерисовку. Обновления идут от родителей к детям; дочерний компонент перерисуется только если изменились **его** props (с поверхностным сравнением) или данные, которые читает он сам. Чтобы выполнить код **после** применения изменений к DOM (измерить элемент, поставить фокус, прокрутить), используют **`await nextTick()`**. Лишние перерисовки появляются из-за нестабильных props (новые объекты и функции на каждом рендере), больших компонентов, читающих много состояния, и отсутствующего `key` в списках.

## Вопрос

Когда Vue перерисовывает компонент и для чего нужен `nextTick`?

## Батчинг обновлений

```ts
const count = ref(0);

function burst() {
  count.value++;
  count.value++;
  count.value++;
  console.log(el.value!.textContent);   // ещё старое значение
}
// DOM обновится один раз — после завершения синхронного кода
```

## nextTick

```ts
async function addMessage(text: string) {
  messages.value.push({ id: crypto.randomUUID(), text });
  await nextTick();                                    // DOM с новым сообщением готов
  listEl.value!.scrollTop = listEl.value!.scrollHeight;
}

async function startEdit() {
  editing.value = true;
  await nextTick();                                    // input уже отрендерен
  inputEl.value?.focus();
}
```

`nextTick(cb)` также принимает колбэк. Альтернатива для эффектов — `watch(..., { flush: 'post' })`.

## Что вызывает перерисовку компонента

| Причина | Перерисуется ли |
| --- | --- |
| Изменилось состояние, прочитанное в шаблоне | Да |
| Изменилось состояние, используемое только в скрипте (не в шаблоне/computed шаблона) | Нет |
| Родитель перерисовался, props ребёнка не изменились | Ребёнок — нет |
| Родитель передаёт новый объект/функцию в prop на каждом рендере | Ребёнок — да, каждый раз |
| Изменилось содержимое слота | Ребёнок со слотом — да |

## Стабильные props

```vue
<!-- ✗ новый объект на каждый рендер родителя → ребёнок перерисуется -->
<UserCard :options="{ compact: true }" :format="(d) => d.toLocaleDateString()" />

<!-- ✓ стабильные ссылки -->
<script setup>
const cardOptions = { compact: true };
const formatDate = (d: Date) => d.toLocaleDateString();
</script>
<UserCard :options="cardOptions" :format="formatDate" />
```

Аналогично лучше передавать в элемент списка вычисленный `:active="item.id === activeId"`, а не `activeId` целиком, — тогда при смене активного элемента перерисуются только два элемента.

## Отладка перерисовок

```ts
onRenderTriggered((e) => console.log('render triggered by', e.key, e.type));   // dev-хук
onRenderTracked((e) => console.log('tracked', e.key));
```

Vue DevTools показывает, какие компоненты и как часто обновляются (вкладка Performance / Timeline).

## Принудительная перерисовка

Обычно не нужна. Если требуется пересоздать компонент (сбросить состояние) — меняют его `key`:

```vue
<CheckoutForm :key="formVersion" />
<!-- formVersion++ → компонент размонтируется и создастся заново -->
```

## Частые ошибки

- Читать DOM сразу после изменения данных без `nextTick`.
- Новые объекты и стрелочные функции в props внутри шаблона больших списков.
- Один огромный компонент, читающий весь стор, — перерисовывается от любого изменения.
- `$forceUpdate()` вместо исправления реактивности.

## Что важно помнить

- Перерисовка — когда меняются данные, прочитанные в рендере компонента.
- Обновления батчатся и применяются асинхронно.
- `await nextTick()` — код после обновления DOM.

## Мини-шпаргалка

- `await nextTick()`.
- `watch(src, cb, { flush: 'post' })`.
- Стабильные props, вычисленные булевы флаги вместо целых объектов.
- `:key` — пересоздать компонент.
- `onRenderTriggered` — отладка.
