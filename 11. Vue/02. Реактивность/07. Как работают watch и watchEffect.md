# Как работают watch и watchEffect

> [!NOTE]
> `watch` и `watchEffect` запускают **побочные эффекты** в ответ на изменение реактивных данных: запрос к API, запись в localStorage, синхронизация с URL, работа со сторонними библиотеками. **`watch(source, callback, options)`** следит за **явно указанным источником** — ref, `reactive`-объектом, геттером `() => obj.x` или массивом источников; колбэк получает новое и старое значения, по умолчанию **ленив** (не вызывается сразу). Опции: `immediate: true` — вызвать сразу, `deep: true` (или число — глубина, 3.5+) — следить за вложенными изменениями, `once: true` — сработать один раз (3.4+), `flush: 'pre' | 'post' | 'sync'` — когда вызывать относительно обновления DOM (`'post'` — после, для работы с обновлённым DOM). **`watchEffect(fn)`** выполняется **сразу** и автоматически отслеживает **всё, что прочитал**; удобен, когда зависимостей много и старое значение не нужно. Обе функции возвращают функцию остановки (и в 3.5 — `pause`/`resume`); созданные синхронно в `setup` останавливаются при размонтировании компонента. Для отмены устаревших асинхронных операций — `onCleanup` или **`onWatcherCleanup()`** (3.5+).

## Вопрос

Как работают `watch` и `watchEffect` и чем они отличаются?

## watch

```ts
const userId = ref('u1');
const user = ref<User | null>(null);

watch(userId, async (id, oldId) => {
  user.value = await api.getUser(id);
}, { immediate: true });

// геттер — для свойства reactive или props
watch(() => props.productId, (id) => loadProduct(id));

// несколько источников
watch([page, sort], ([p, s], [oldP, oldS]) => load(p, s));

// reactive-объект — неявно глубокий
const filters = reactive({ q: '', category: null as string | null });
watch(filters, () => router.replace({ query: { ...filters } }));
```

## Источники watch

| Источник | Пример | Поведение |
| --- | --- | --- |
| `ref` | `watch(count, cb)` | Срабатывает при замене `.value` |
| `ref` с объектом | `watch(form, cb, { deep: true })` | Вложенные изменения — только с `deep` |
| `reactive` | `watch(state, cb)` | Глубоко по умолчанию |
| Геттер | `watch(() => state.a.b, cb)` | Только этот путь |
| Массив | `watch([a, () => b.c], cb)` | Любой из источников |

```ts
watch(state.count, cb);          // ✗ передано число — ошибка
watch(() => state.count, cb);    // ✓
```

## watchEffect

```ts
watchEffect(async () => {
  // отслеживается всё, что прочитано синхронно до первого await
  const q = search.value;
  const cat = category.value;
  results.value = await api.search({ q, cat });
});
```

Зависимости, прочитанные **после** `await`, не отслеживаются.

## Сравнение

| | `watch` | `watchEffect` |
| --- | --- | --- |
| Зависимости | Явный источник | Автоматически из прочитанного |
| Первый запуск | Лениво (или `immediate`) | Сразу |
| Старое значение | Да | Нет |
| Когда удобно | Реакция на конкретное изменение, нужно сравнение | Эффект от многих значений |

## Отмена устаревших запросов

```ts
watch(query, async (q) => {
  const controller = new AbortController();
  onWatcherCleanup(() => controller.abort());          // Vue 3.5+; вызов при следующем срабатывании или остановке
  results.value = await fetch(`/api/search?q=${q}`, { signal: controller.signal }).then((r) => r.json());
});

// до 3.5 — третий аргумент колбэка
watch(query, async (q, _old, onCleanup) => {
  let cancelled = false;
  onCleanup(() => { cancelled = true; });
  const data = await api.search(q);
  if (!cancelled) results.value = data;
});
```

Без отмены быстрый ввод может привести к тому, что старый медленный ответ перезапишет новый (race condition).

## flush и DOM

```ts
watch(messages, () => {
  listEl.value?.scrollTo({ top: listEl.value.scrollHeight });   // DOM уже обновлён
}, { flush: 'post' });

watchPostEffect(() => { /* то же для watchEffect */ });
```

## Остановка, pause, once

```ts
const stop = watch(source, cb);
stop();

const { pause, resume } = watch(source, cb);   // 3.5+
watch(source, cb, { once: true });              // 3.4+
```

Наблюдатели, созданные асинхронно (после `await` в setup или в `setTimeout`), **не привязаны** к компоненту — их нужно останавливать вручную.

## Частые ошибки

- Передать в `watch` значение вместо ref/геттера.
- Ожидать, что `watch(refWithObject)` увидит вложенные изменения без `deep`.
- Запускать запросы без отмены/игнорирования устаревших ответов.
- Использовать `watch` для производных данных (это задача `computed`).
- Читать зависимости `watchEffect` после `await`.
- Мутировать в колбэке источник, за которым следим, — бесконечный цикл.

## Что важно помнить

- `watch` — явный источник, лениво, старое значение; `watchEffect` — автоматические зависимости, сразу.
- `immediate`, `deep`, `once`, `flush: 'post'`.
- Отменяйте устаревшие асинхронные операции (`onWatcherCleanup`/`onCleanup`).

## Мини-шпаргалка

- `watch(src, (v, old) => {}, { immediate, deep, once, flush })`.
- `watch(() => props.id, cb)`.
- `watchEffect(fn)`, `watchPostEffect(fn)`.
- `const stop = watch(...)`, `{ pause, resume }`.
- `onWatcherCleanup(() => controller.abort())`.
