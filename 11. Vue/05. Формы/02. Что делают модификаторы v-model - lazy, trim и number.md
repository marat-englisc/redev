# Что делают модификаторы v-model - lazy, trim и number

> [!NOTE]
> У `v-model` три встроенных модификатора. **`.lazy`** синхронизирует значение по событию **`change`** (уход фокуса, Enter) вместо `input` на каждый символ — полезно, когда дорогая реакция на изменение (валидация, запрос, пересчёт) не должна запускаться при каждом нажатии. **`.trim`** автоматически обрезает пробелы в начале и конце строки — для имён, email, поисковых запросов. **`.number`** приводит значение к числу через `parseFloat`; если строку нельзя разобрать, остаётся исходная строка; для `<input type="number">` применяется автоматически. Модификаторы **комбинируются** (`v-model.lazy.trim`). Важно: `.number` не превращает пустое поле в `0` — приходит пустая строка, поэтому тип состояния — `number | ''` или нужна явная обработка. На **компонентах** модификаторы передаются в prop `modelModifiers` (`titleModifiers` для `v-model:title`), и компонент сам решает, как их применить (через `set` в `defineModel`). Модификаторы — удобство UI, а не валидация: проверять данные всё равно нужно.

## Вопрос

Для чего нужны модификаторы `v-model` `.lazy`, `.trim` и `.number`?

## .lazy

```vue
<input v-model.lazy="title" />       <!-- обновится при blur или Enter -->

<script setup>
const title = ref('');
watch(title, (t) => api.saveDraft(t));    // запрос не на каждый символ
</script>
```

## .trim

```vue
<input v-model.trim="email" type="email" />
<!-- "  anna@x.com  " → "anna@x.com" -->
```

Пробелы внутри строки сохраняются; нормализацию регистра (`toLowerCase`) делают отдельно — в computed-сеттере или при отправке.

## .number

```vue
<input v-model.number="quantity" />           <!-- "3" → 3, "3.5" → 3.5, "abc" → "abc" -->
<input v-model="age" type="number" />         <!-- для type="number" .number применяется автоматически -->
```

```ts
const quantity = ref<number | ''>(1);
const total = computed(() => (typeof quantity.value === 'number' ? quantity.value * price : 0));
```

Пустое поле даёт `''`, а не `0` и не `null`.

## Комбинации

```vue
<input v-model.lazy.trim="username" />
<input v-model.lazy.number="budget" />
```

## Модификаторы на компонентах

```vue
<BaseInput v-model.trim="name" />
```

```vue
<!-- BaseInput.vue -->
<script setup lang="ts">
const [model, modifiers] = defineModel<string, 'trim'>({
  set: (v) => (modifiers.trim ? v.trim() : v),
});
</script>

<template>
  <input v-model="model" />
</template>
```

Если `BaseInput` сам не обработает `modifiers.trim`, модификатор не сработает — он не применяется к внутреннему `<input>` автоматически.

## Когда что

| Модификатор | Сценарий |
| --- | --- |
| `.lazy` | Автосохранение, дорогие вычисления, валидация «по уходу из поля» |
| `.trim` | Имена, email, логин, поиск |
| `.number` | Количество, цена, проценты в текстовых полях |

## Частые ошибки

- Ожидать `0` от пустого поля с `.number`.
- `.lazy` в поиске «по мере ввода» — пользователь не видит результатов до blur.
- Считать `.trim` валидацией (пустая строка после trim — всё ещё нужно проверить).
- Модификатор на своём компоненте без обработки `modelModifiers`.

## Что важно помнить

- `.lazy` — `change` вместо `input`, `.trim` — обрезать пробелы, `.number` — `parseFloat`.
- Модификаторы комбинируются.
- На компонентах модификаторы — prop `modelModifiers`, обработку делает сам компонент.

## Мини-шпаргалка

- `v-model.lazy`, `v-model.trim`, `v-model.number`.
- `type="number"` ⇒ `.number` автоматически.
- `defineModel({ set })` + `modifiers`.
- Пустое поле с `.number` → `''`.
