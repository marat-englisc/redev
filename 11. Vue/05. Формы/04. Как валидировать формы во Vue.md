# Как валидировать формы во Vue

> [!NOTE]
> Во Vue нет встроенной системы валидации — используют HTML-атрибуты (`required`, `type="email"`, `minlength`), собственную логику с `computed` или библиотеки. Самая распространённая — **VeeValidate**: composable `useForm({ validationSchema })` хранит значения, ошибки, состояния `touched`/`dirty`/`meta.valid`, а `defineField('email')` возвращает модель и атрибуты для поля; правила удобно описывать **схемой Zod** (через `@vee-validate/zod` и `toTypedSchema`), и ту же схему можно переиспользовать на бэкенде. Альтернативы: FormKit (компоненты форм со встроенной валидацией), Regle, Vuelidate. Хорошая UX-валидация: показывать ошибку **после взаимодействия** (blur или попытка отправки), а не при первом символе; проверять на клиенте для удобства, но **всегда** повторять проверку на сервере; отображать серверные ошибки (`422` с полями) рядом с полями; связывать сообщение с полем через `aria-describedby` и `aria-invalid`. Асинхронные проверки (свободен ли логин) — с debounce.

## Вопрос

Как валидировать формы во Vue и какие инструменты для этого есть?

## VeeValidate + Zod

```bash
npm install vee-validate @vee-validate/zod zod
```

```vue
<script setup lang="ts">
import { useForm } from 'vee-validate';
import { toTypedSchema } from '@vee-validate/zod';
import { z } from 'zod';

// @vee-validate/zod 4.15 рассчитан на Zod 3 (peerDependency zod ^3.24) — синтаксис ниже совместим с Zod 3
const schema = toTypedSchema(
  z
    .object({
      email: z.string().trim().toLowerCase().email('Некорректный email'),
      password: z.string().min(10, 'Минимум 10 символов'),
      confirm: z.string(),
    })
    .refine((v) => v.password === v.confirm, { message: 'Пароли не совпадают', path: ['confirm'] }),
);

const { defineField, errors, handleSubmit, isSubmitting, setErrors, meta } = useForm({ validationSchema: schema });

const [email, emailAttrs] = defineField('email', { validateOnModelUpdate: false });   // ошибка после blur
const [password, passwordAttrs] = defineField('password');
const [confirm, confirmAttrs] = defineField('confirm');

const onSubmit = handleSubmit(async (values) => {
  try {
    await api.signup(values);
  } catch (e) {
    if (e instanceof ApiError && e.status === 422) setErrors(e.fieldErrors);   // { email: 'Уже занят' }
  }
});
</script>

<template>
  <form novalidate @submit="onSubmit">
    <label for="email">Email</label>
    <input id="email" v-model="email" v-bind="emailAttrs" type="email"
           :aria-invalid="!!errors.email" aria-describedby="email-error" />
    <small id="email-error">{{ errors.email }}</small>

    <input v-model="password" v-bind="passwordAttrs" type="password" />
    <small>{{ errors.password }}</small>

    <input v-model="confirm" v-bind="confirmAttrs" type="password" />
    <small>{{ errors.confirm }}</small>

    <button :disabled="isSubmitting || !meta.dirty">Зарегистрироваться</button>
  </form>
</template>
```

## Версии Zod

Перед подключением проверьте совместимость: адаптер `@vee-validate/zod` (4.15) объявляет зависимость от Zod 3. Если проект уже на Zod 4 (например, общие схемы с бэкендом на NestJS 12), варианты — использовать библиотеку форм с поддержкой Standard Schema (например, Regle) или передать в VeeValidate собственную функцию валидации на `safeParse`:

```ts
import { useField } from 'vee-validate';

// валидатор поля — функция: true или текст ошибки
const zodRule = (schema: z.ZodType) => (value: unknown) => {
  const r = schema.safeParse(value);                       // Zod 4
  return r.success || r.error.issues[0]?.message || 'Некорректное значение';
};

const { value: email, errorMessage: emailError } = useField('email', zodRule(z.email('Некорректный email')));
```

## Своя валидация на computed

```ts
const email = ref('');
const touched = ref(false);

const emailError = computed(() => {
  if (!touched.value) return null;
  if (!email.value) return 'Обязательное поле';
  if (!/^\S+@\S+\.\S+$/.test(email.value)) return 'Некорректный email';
  return null;
});
// <input v-model.trim="email" @blur="touched = true" />
```

Для 2–3 полей этого достаточно; для больших форм — библиотека.

## Асинхронная проверка

```ts
const usernameSchema = z.string().min(3).refine(
  useDebounceFn(async (v: string) => !(await api.isUsernameTaken(v)), 400),   // из VueUse
  'Имя уже занято',
);
```

## Когда показывать ошибки

| Момент | Плюсы | Минусы |
| --- | --- | --- |
| При каждом вводе | Мгновенная обратная связь | Ошибка до того, как пользователь закончил |
| При blur (после касания) | Хороший баланс | — |
| При отправке | Не отвлекает | Ошибки появляются все разом |
| Комбинация: blur, затем при вводе | Ошибка исчезает сразу после исправления | — |

## Серверные ошибки

```json
// 422 от API
{ "code": "VALIDATION_FAILED", "details": [{ "field": "email", "message": "Email уже зарегистрирован" }] }
```

```ts
setErrors(Object.fromEntries(res.details.map((d) => [d.field, d.message])));
```

## Доступность

- `<label for>` у каждого поля.
- `aria-invalid="true"` на поле с ошибкой, `aria-describedby` на элемент с текстом ошибки.
- Фокус на первом поле с ошибкой после неудачной отправки.
- Ошибки — текстом, не только цветом.

## Частые ошибки

- Валидация только на клиенте.
- Ошибка «обязательное поле» при первом открытии формы.
- Разные правила на фронтенде и бэкенде (общая схема Zod решает).
- Серверные ошибки показываются тостом без привязки к полям.
- Асинхронная проверка без debounce — запрос на каждый символ.

## Что важно помнить

- VeeValidate + Zod — популярный стек; для простых форм хватит `computed`.
- Показывать ошибки после взаимодействия, серверные — у полей.
- Серверная валидация обязательна; доступность — `label`, `aria-invalid`, `aria-describedby`.

## Мини-шпаргалка

- `useForm({ validationSchema: toTypedSchema(zodSchema) })`.
- `const [field, attrs] = defineField('name')`.
- `handleSubmit(async (values) => {})`, `setErrors({...})`.
- `errors`, `meta.valid`, `meta.dirty`, `isSubmitting`.
