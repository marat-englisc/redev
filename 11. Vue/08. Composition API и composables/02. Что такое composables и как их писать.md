# Что такое composables и как их писать

> [!NOTE]
> **Composable** — функция, которая инкапсулирует **логику с состоянием** на базе Composition API и переиспользуется между компонентами: по соглашению имя начинается с `use` (`useMouse`, `useFetch`, `usePagination`). Внутри она создаёт `ref`/`reactive`, `computed`, `watch`, регистрирует хуки жизненного цикла, а возвращает **объект ref-ов** (чтобы результат можно было деструктурировать без потери реактивности) и функции. Каждый вызов создаёт **своё** состояние (если оно не объявлено на уровне модуля намеренно). Хорошие composables принимают аргументы как **`MaybeRefOrGetter<T>`** и читают их через `toValue()` внутри `watch`/`watchEffect`/`computed`, чтобы реагировать на изменения; освобождают ресурсы через `onScopeDispose`/`onCleanup`; отдают наружу `readonly`-состояние и явные функции изменения. Вызывать их нужно **синхронно в `setup`** (или внутри других composables, Pinia setup-сторов, `effectScope`) — иначе хуки и `inject` не привяжутся к компоненту. Composables заменили mixins Vue 2: источник каждого значения явный, конфликтов имён нет, отличная типизация. Большую библиотеку готовых composables даёт VueUse.

## Вопрос

Что такое composables во Vue и как правильно их писать?

## Простой composable

```ts
// composables/useCounter.ts
export function useCounter(initial = 0, { min = -Infinity, max = Infinity } = {}) {
  const count = ref(initial);
  const canInc = computed(() => count.value < max);

  const inc = () => { if (canInc.value) count.value++; };
  const dec = () => { if (count.value > min) count.value--; };
  const reset = () => (count.value = initial);

  return { count: readonly(count), canInc, inc, dec, reset };
}

// в компоненте
const { count, inc, dec } = useCounter(1, { min: 1, max: 10 });
```

## Реактивные аргументы

```ts
// composables/useProduct.ts
export function useProduct(id: MaybeRefOrGetter<string | undefined>) {
  const product = ref<Product | null>(null);
  const error = ref<Error | null>(null);
  const loading = ref(false);

  watch(
    () => toValue(id),
    async (value) => {
      if (!value) return;
      const controller = new AbortController();
      onWatcherCleanup(() => controller.abort());
      loading.value = true;
      error.value = null;
      try {
        product.value = await api.getProduct(value, { signal: controller.signal });
      } catch (e) {
        if (!controller.signal.aborted) error.value = e as Error;
      } finally {
        loading.value = false;
      }
    },
    { immediate: true },
  );

  return { product, error, loading };
}

// использование
const route = useRoute();
const { product, loading } = useProduct(() => route.params.id as string);
```

## Ресурсы и очистка

```ts
export function useOnline() {
  const online = ref(navigator.onLine);
  const update = () => (online.value = navigator.onLine);

  window.addEventListener('online', update);
  window.addEventListener('offline', update);
  onScopeDispose(() => {
    window.removeEventListener('online', update);
    window.removeEventListener('offline', update);
  });

  return { online: readonly(online) };
}
```

`onScopeDispose` срабатывает при размонтировании компонента и при остановке `effectScope`; для SSR код с `window` переносят в `onMounted` или проверяют окружение.

## Общее состояние между вызовами

```ts
// состояние на уровне модуля — общее для всех компонентов (простой глобальный стор)
const theme = ref<'light' | 'dark'>('light');

export function useTheme() {
  const toggle = () => (theme.value = theme.value === 'light' ? 'dark' : 'light');
  return { theme: readonly(theme), toggle };
}
```

В SSR такое состояние общее для всех запросов — используйте Pinia или `useState` в Nuxt. VueUse даёт `createGlobalState` / `createSharedComposable`.

## Composable с контекстом (provide/inject)

```ts
const FormKey: InjectionKey<FormContext> = Symbol('Form');
export const provideForm = (ctx: FormContext) => provide(FormKey, ctx);
export function useFormContext() {
  const ctx = inject(FormKey);
  if (!ctx) throw new Error('useFormContext() must be used inside <AppForm>');
  return ctx;
}
```

## Правила

| Правило | Почему |
| --- | --- |
| Имя `useXxx` | Соглашение, линтеры и читаемость |
| Возвращать объект ref-ов | Деструктуризация без потери реактивности |
| Принимать `MaybeRefOrGetter`, читать `toValue` | Работает со статикой, ref и геттером |
| Вызывать синхронно в setup | Хуки и inject привязываются к компоненту |
| Очищать ресурсы | Нет утечек |
| Одна ответственность | Легко комбинировать и тестировать |

## Composables и mixins

| Mixins (Vue 2) | Composables |
| --- | --- |
| Неясно, откуда свойство | Явный импорт и деструктуризация |
| Конфликты имён | Переименование при деструктуризации |
| Нельзя параметризовать экземпляры | Аргументы функции |
| Слабая типизация | Полная типизация |

## Частые ошибки

- Возвращать `reactive`-объект и деструктурировать его в компоненте.
- Принимать `props.id` (значение) вместо геттера.
- Вызывать composable в обработчике события или после `await`.
- Не снимать подписки.
- Логика без состояния и реактивности в `useXxx` — это просто утилита, не composable.

## Что важно помнить

- Composable = переиспользуемая логика с состоянием на Composition API.
- `MaybeRefOrGetter` + `toValue`, возврат ref-ов, очистка через `onScopeDispose`.
- Вызывать синхронно в `setup`; общее состояние — осознанно.

## Мини-шпаргалка

- `export function useX(arg: MaybeRefOrGetter<T>) { ...; return { a, b, fn } }`.
- `watch(() => toValue(arg), ...)`.
- `onScopeDispose(cleanup)`.
- `readonly(state)`.
- VueUse — готовые composables.
