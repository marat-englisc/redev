# Какие макросы компилятора есть в script setup

> [!NOTE]
> **Макросы компилятора** — «функции», доступные только в `<script setup>` без импорта: компилятор SFC заменяет их кодом на этапе сборки, поэтому их нельзя вызывать условно, внутри функций или передавать как значения. **`defineProps`** — объявить props (типом или runtime-объектом; в 3.5+ поддерживает реактивную деструктуризацию с умолчаниями), **`withDefaults`** — значения по умолчанию для типизированных props, **`defineEmits`** — события, **`defineModel`** (3.4+) — двусторонняя модель (prop + событие `update:*`), **`defineExpose`** — что видно родителю через template ref, **`defineSlots`** (3.3+) — типы слотов, **`defineOptions`** (3.3+) — опции компонента (`name`, `inheritAttrs`), которые раньше требовали отдельного `<script>`. Типы в макросах могут ссылаться на импортированные интерфейсы (3.3+) с некоторыми ограничениями (сложные условные типы компилятор не разрешит). Рядом с макросами в `<script setup>` используются обычные функции `useSlots()`, `useAttrs()`, `useTemplateRef()`, `useId()` (3.5+, стабильный уникальный id для `aria`/`for`, одинаковый при SSR и гидрации).

## Вопрос

Какие макросы компилятора есть в `<script setup>` и для чего они нужны?

## Все макросы вместе

```vue
<script setup lang="ts" generic="T extends { id: string }">
defineOptions({ name: 'SelectField', inheritAttrs: false });

// props: реактивная деструктуризация (3.5+)
const { options, label, placeholder = 'Выберите…', disabled = false } = defineProps<{
  options: T[];
  label: string;
  placeholder?: string;
  disabled?: boolean;
}>();

// модель
const selected = defineModel<T | null>({ default: null });

// события
const emit = defineEmits<{ open: []; search: [query: string] }>();

// слоты
defineSlots<{ option(props: { option: T; active: boolean }): any; empty?(): any }>();

const isOpen = ref(false);
const id = useId();                                   // 'v-0-1' — стабильно при SSR

function open() { isOpen.value = true; emit('open'); }
function close() { isOpen.value = false; }

defineExpose({ open, close });
</script>

<template>
  <label :for="id">{{ label }}</label>
  <button :id="id" :disabled="disabled" v-bind="$attrs" @click="open">{{ selected ? selected.id : placeholder }}</button>
  <ul v-if="isOpen" role="listbox">
    <li v-for="o in options" :key="o.id" @click="selected = o; close()">
      <slot name="option" :option="o" :active="selected?.id === o.id">{{ o.id }}</slot>
    </li>
  </ul>
</template>
```

## Таблица

| Макрос | Версия | Назначение |
| --- | --- | --- |
| `defineProps` | 3.0 | Props (тип или runtime); деструктуризация с умолчаниями — 3.5 |
| `withDefaults` | 3.0 | Умолчания для типизированных props |
| `defineEmits` | 3.0 | События (кортежный синтаксис типов — 3.3) |
| `defineExpose` | 3.0 | Публичное API экземпляра |
| `defineSlots` | 3.3 | Типы слотов |
| `defineOptions` | 3.3 | `name`, `inheritAttrs` и другие опции |
| `defineModel` | 3.4 | v-model компонента |

## withDefaults и деструктуризация

```ts
// 3.5+
const { size = 'md', tags = [] } = defineProps<{ size?: 'sm' | 'md'; tags?: string[] }>();

// до 3.5 (и если нужен объект props)
const props = withDefaults(defineProps<{ size?: 'sm' | 'md'; tags?: string[] }>(), {
  size: 'md',
  tags: () => [],          // объекты/массивы — фабрикой
});
```

## defineEmits: формы

```ts
const emit = defineEmits<{
  change: [id: number];               // 3.3+: именованные кортежи
  update: [value: string, meta?: { source: 'user' | 'api' }];
}>();

// старая форма — сигнатуры вызова
const emit2 = defineEmits<{ (e: 'change', id: number): void }>();
```

## Ограничения макросов

```ts
if (cond) defineProps<...>();                 // ✗ только на верхнем уровне
const p = isX ? defineProps<A>() : null;      // ✗
const key = 'title';
defineProps({ [key]: String });               // ✗ значения должны быть статически анализируемы
```

Аргументы макросов вычисляются **вне** `setup` (поднимаются компилятором), поэтому не могут ссылаться на локальные переменные `setup`, кроме импортов и констант модуля.

## useId

```vue
<script setup>
const id = useId();
</script>

<template>
  <label :for="id">Email</label>
  <input :id="id" :aria-describedby="`${id}-hint`" />
  <p :id="`${id}-hint`">Мы не публикуем email</p>
</template>
```

`Math.random()` для id ломает гидрацию в SSR (разные значения на сервере и клиенте) — `useId` решает это.

## Частые ошибки

- Импортировать макросы из `vue`.
- Использовать макросы в обычном `<script>` или внутри функций.
- Сложные условные типы в `defineProps`, которые компилятор не может разрешить, — выносите в простые интерфейсы.
- `defineOptions({ props })` — props и emits объявляются только своими макросами.
- Генерация id через `Math.random()` в SSR.

## Что важно помнить

- Макросы обрабатываются компилятором: только верхний уровень `<script setup>`, без импорта.
- `defineProps/Emits/Model/Expose/Slots/Options` описывают API компонента.
- `useId()` (3.5+) — стабильные id для доступности и SSR.

## Мини-шпаргалка

- `defineProps<P>()`, `withDefaults(...)`, деструктуризация (3.5+).
- `defineEmits<{ e: [a: T] }>()`.
- `defineModel<T>('name', { default })`.
- `defineExpose({...})`, `defineSlots<{...}>()`, `defineOptions({ name, inheritAttrs })`.
- `useId()`, `useTemplateRef()`, `useSlots()`, `useAttrs()`.
