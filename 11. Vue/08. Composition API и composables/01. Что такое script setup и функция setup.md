# Что такое script setup и функция setup

> [!NOTE]
> **`setup()`** — точка входа Composition API: функция, которая выполняется **один раз при создании** каждого экземпляра компонента (до `onBeforeMount`), получает `props` (реактивный объект — не деструктурировать) и `context` (`attrs`, `slots`, `emit`, `expose`) и возвращает объект с тем, что доступно шаблону, или render-функцию. **`<script setup>`** — синтаксический сахар компилятора поверх `setup()`, рекомендуемый для SFC: весь код верхнего уровня становится телом `setup`, все переменные, функции и импорты **автоматически доступны в шаблоне** (без `return`), компоненты используются без регистрации, а props, события, модель и прочее объявляются **макросами** `defineProps`, `defineEmits`, `defineModel`, `defineExpose`, `defineSlots`, `defineOptions`. Плюсы: меньше шаблонного кода, лучшая типизация, более быстрый рантайм (шаблон компилируется в ту же область видимости без прокси). Внутри можно использовать **top-level `await`** — компонент станет асинхронным и потребует `<Suspense>`. Компоненты на `<script setup>` закрыты по умолчанию — наружу открывается только то, что передано в `defineExpose`.

## Вопрос

Что такое `setup()` и `<script setup>` и чем они отличаются?

## setup()

```vue
<script lang="ts">
import { defineComponent, ref, computed } from 'vue';

export default defineComponent({
  props: { initial: { type: Number, default: 0 } },
  emits: ['change'],
  setup(props, { emit, slots, attrs, expose }) {
    const count = ref(props.initial);
    const double = computed(() => count.value * 2);

    function inc() {
      count.value++;
      emit('change', count.value);
    }

    expose({ reset: () => (count.value = props.initial) });
    return { count, double, inc };          // доступно в шаблоне
  },
});
</script>
```

## script setup

```vue
<script setup lang="ts">
import { ref, computed } from 'vue';
import BaseButton from './BaseButton.vue';      // компонент сразу доступен в шаблоне

const props = withDefaults(defineProps<{ initial?: number }>(), { initial: 0 });
const emit = defineEmits<{ change: [value: number] }>();

const count = ref(props.initial);
const double = computed(() => count.value * 2);

function inc() {
  count.value++;
  emit('change', count.value);
}

defineExpose({ reset: () => (count.value = props.initial) });
</script>

<template>
  <BaseButton @click="inc">{{ count }} × 2 = {{ double }}</BaseButton>
</template>
```

## Сравнение

| | `setup()` | `<script setup>` |
| --- | --- | --- |
| Возврат значений шаблону | Явный `return` | Автоматически |
| Регистрация компонентов | `components` или `return` | Импорт = регистрация |
| Props / emits | Опции `props`, `emits` | `defineProps`, `defineEmits` |
| TypeScript | Через `defineComponent` | Типы в макросах, generic-компоненты |
| Открытость экземпляра | Открыт (кроме `expose`) | Закрыт, `defineExpose` |
| Где применяется | Render-функции, JSX, библиотеки, смешанный Options API | SFC — по умолчанию |

## Аргументы setup

```ts
setup(props, ctx) {
  props.title;                     // реактивно; const { title } = props — теряет реактивность (используйте toRefs)
  ctx.attrs;                       // fallthrough-атрибуты (не реактивны для watch)
  ctx.slots.default?.();
  ctx.emit('change', 1);
  ctx.expose({ focus });
}
```

## Top-level await

```vue
<script setup lang="ts">
const user = await api.getMe();      // компонент становится async → нужен <Suspense> выше
</script>
```

Хуки и `watch` нужно регистрировать **до** первого `await`.

## Обычный script рядом

```vue
<script lang="ts">
// выполняется один раз на модуль: типы, константы, defineOptions-альтернатива
export const PAGE_SIZE = 20;
</script>

<script setup lang="ts">
const page = ref(1);
</script>
```

## Генерики

```vue
<script setup lang="ts" generic="T extends { id: string }, K extends keyof T">
defineProps<{ items: T[]; labelKey: K }>();
</script>
```

## Частые ошибки

- Деструктурировать `props` в `setup()` без `toRefs` (реактивная деструктуризация работает только в `<script setup>` 3.5+).
- Регистрировать хуки после `await`.
- Использовать `this` внутри `setup` — его там нет.
- Ожидать доступ родителя к переменным `<script setup>` без `defineExpose`.
- Импортировать `defineProps` из `vue`.

## Что важно помнить

- `setup` выполняется один раз на экземпляр; `<script setup>` — его краткая форма для SFC.
- Верхний уровень `<script setup>` доступен шаблону, макросы объявляют API компонента.
- Top-level `await` делает компонент асинхронным.

## Мини-шпаргалка

- `setup(props, { emit, slots, attrs, expose })` → `return {...}`.
- `<script setup lang="ts">` + `defineProps/defineEmits/defineModel/defineExpose`.
- `generic="T"`.
- Хуки до `await`.
