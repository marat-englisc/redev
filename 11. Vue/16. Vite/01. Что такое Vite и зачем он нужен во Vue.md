# Что такое Vite и зачем он нужен во Vue

> [!NOTE]
> **Vite** — инструмент сборки и dev-сервер для фронтенда, созданный автором Vue (Эван Ю) и ставший стандартом для Vue, Nuxt, а также многих других фреймворков. Две части: **dev-сервер**, который не собирает приложение в бандл заранее, а отдаёт браузеру исходные модули по запросу как **нативные ES-модули**, трансформируя каждый файл на лету (`.vue`, TypeScript, CSS) — поэтому старт почти мгновенный независимо от размера проекта, а **HMR** обновляет только изменённый модуль с сохранением состояния; и **production-сборка** — оптимизированный бандл с code splitting, минификацией, хешами в именах файлов и обработкой ассетов. С **Vite 8** обе части работают на **Rolldown** (сборщик на Rust с API, совместимым с Rollup) и **Oxc** (трансформации и минификация JS) вместо прежней пары esbuild + Rollup; CSS по умолчанию минифицируется Lightning CSS. Vue подключается официальным плагином **`@vitejs/plugin-vue`** (компиляция SFC), JSX — `@vitejs/plugin-vue-jsx`. Официальный способ создать Vue-проект — **`npm create vue@latest`** (create-vue: Vite + опционально TypeScript, Vue Router, Pinia, Vitest, Playwright, ESLint); есть и базовые шаблоны `npm create vite@latest -- --template vue-ts`. Требуется Node.js 20.19+ или 22.12+.

## Вопрос

Что такое Vite и зачем он нужен во Vue-проекте?

## Dev и production

```text
Development (vite):
  браузер запрашивает /src/main.ts
  → Vite трансформирует только этот файл
  → браузер импортирует App.vue → Vite компилирует SFC
  → зависимости из node_modules заранее собраны (pre-bundling)
  → изменения — через HMR

Production (vite build):
  Rolldown собирает граф модулей
  → tree shaking, code splitting, минификация (Oxc, Lightning CSS)
  → dist/ с хешированными файлами
```

## Чем Vite лучше классических бандлеров в разработке

| | Бандлер «собрать всё» (webpack dev server) | Vite |
| --- | --- | --- |
| Старт | Сборка всего приложения перед запуском | Сразу, модули по запросу |
| Обновление | Пересборка части бандла | HMR одного модуля |
| Зависимость от размера проекта | Растёт | Почти не растёт |
| Конфигурация | Много loaders | Разумные умолчания |

## Скрипты

```json
{
  "scripts": {
    "dev": "vite",
    "build": "vue-tsc -b && vite build",
    "preview": "vite preview",
    "test:unit": "vitest"
  }
}
```

Vite **не проверяет типы** — только удаляет их при трансформации; проверку делает `vue-tsc` (в сборке, CI или IDE).

## Экосистема Vite во Vue

| Инструмент | Роль |
| --- | --- |
| `@vitejs/plugin-vue` | Компиляция `.vue` |
| Vitest | Тесты на конфигурации Vite |
| Vue Router 5 (`vue-router/vite`) | Файловая маршрутизация |
| Nuxt | Использует Vite как сборщик |
| Vite DevTools / `vite-plugin-vue-devtools` | Отладка |

## Частые ошибки

- Ожидать, что `vite build` найдёт ошибки TypeScript.
- Сравнивать скорость dev-режима с production — в dev модули не собраны в бандл.
- Ставить старый Node.js — Vite 8 требует 20.19+/22.12+.
- Путать create-vue (официальный стартер Vue) и create-vite (общие шаблоны).

## Что важно помнить

- Dev: нативные ESM по запросу + HMR; build: Rolldown-бандл.
- Vue подключается `@vitejs/plugin-vue`.
- `npm create vue@latest` — официальный старт; типы проверяет `vue-tsc`.

## Мини-шпаргалка

- `npm create vue@latest`.
- `vite`, `vite build`, `vite preview`.
- `plugins: [vue()]`.
- Vite 8: Rolldown + Oxc.
