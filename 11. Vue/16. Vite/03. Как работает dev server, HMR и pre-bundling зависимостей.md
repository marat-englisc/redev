# Как работает dev server, HMR и pre-bundling зависимостей

> [!NOTE]
> Dev-сервер Vite (`vite` / `npm run dev`) обрабатывает **исходный код** и **зависимости** по-разному. Исходники (`.vue`, `.ts`, CSS) отдаются как нативные ES-модули и трансформируются **по запросу**: браузер встречает `import` → запрашивает файл → Vite компилирует только его и кеширует результат; файлы, которые не открыты на текущей странице, вообще не обрабатываются. Зависимости из `node_modules` проходят **pre-bundling** (оптимизацию зависимостей): при первом запуске Vite собирает их в небольшое число ESM-файлов в `node_modules/.vite` — CommonJS-пакеты превращаются в ESM, а библиотеки из сотен мелких модулей (`lodash-es`) склеиваются в один файл, чтобы браузер не делал сотни запросов; результат кешируется браузером надолго. **HMR (Hot Module Replacement)** — при сохранении файла Vite по WebSocket сообщает браузеру, какой модуль изменился; `@vitejs/plugin-vue` перезагружает только этот компонент, **сохраняя состояние** (при изменении только `<template>` — перерендер, при изменении `<script>` — пересоздание экземпляров компонента), а изменения `<style>` применяются без перерендера. Если модуль нельзя заменить «горячо» (конфиг, `main.ts` без HMR-обработчика, некоторые изменения сторов), происходит **полная перезагрузка**. `server.proxy` перенаправляет запросы `/api` на бэкенд и избавляет от CORS в разработке — но работает **только в dev**.

## Вопрос

Как работают dev-сервер Vite, HMR и pre-bundling зависимостей?

## Запрос модуля

```text
GET /src/main.ts
  → Vite: TS → JS, переписать импорты:
      import { createApp } from 'vue'   →   from '/node_modules/.vite/deps/vue.js?v=abc'
      import App from './App.vue'       →   from '/src/App.vue'
GET /src/App.vue
  → plugin-vue компилирует SFC: script + render + style (отдельный запрос ?vue&type=style)
```

## Pre-bundling

```text
Первый запуск:
  сканирование импортов → найдены vue, pinia, axios, lodash-es
  → сборка в node_modules/.vite/deps/*.js (Rolldown)
Повторный запуск:
  кеш, если не изменились lockfile, vite.config и patches
```

```ts
// vite.config.ts
optimizeDeps: {
  include: ['some-cjs-lib', 'my-lib > nested-dep'],   // зависимость, обнаруженная поздно (динамический импорт)
  exclude: ['my-local-linked-lib'],                    // не пред-собирать (например, локальный пакет в разработке)
},
```

Сбросить кеш: `vite --force` или удалить `node_modules/.vite`.

## HMR во Vue

| Что изменилось | Что происходит |
| --- | --- |
| `<template>` | Перерендер компонента, состояние сохраняется |
| `<script setup>` | Пересоздание экземпляров компонента (локальное состояние сбрасывается, состояние в сторах остаётся) |
| `<style>` | Подмена CSS без перерендера |
| Pinia store | Сохраняется при `acceptHMRUpdate` |
| `vite.config.ts`, `.env` | Перезапуск сервера |
| Модуль без HMR-границы | Полная перезагрузка страницы |

```ts
// stores/cart.ts — HMR для Pinia
import { defineStore, acceptHMRUpdate } from 'pinia';
export const useCartStore = defineStore('cart', { /* ... */ });

if (import.meta.hot) {
  import.meta.hot.accept(acceptHMRUpdate(useCartStore, import.meta.hot));
}
```

## API import.meta.hot

```ts
if (import.meta.hot) {
  import.meta.hot.accept((newModule) => { /* применить новую версию */ });
  import.meta.hot.dispose(() => { clearInterval(timer); });   // очистить побочные эффекты старой версии
}
```

Код в `if (import.meta.hot)` удаляется из production-сборки.

## Proxy

```ts
server: {
  proxy: {
    '/api': { target: 'http://localhost:3000', changeOrigin: true },
    '/ws': { target: 'ws://localhost:3000', ws: true },
    '/legacy': {
      target: 'http://localhost:8080',
      rewrite: (path) => path.replace(/^\/legacy/, ''),
    },
  },
},
```

```text
Браузер → localhost:5173/api/products → Vite proxy → localhost:3000/api/products
(один origin — нет CORS)
```

## Другие настройки сервера

```ts
server: {
  host: true,           // доступ по сети (тест на телефоне)
  port: 5173,
  strictPort: true,     // не переключаться на другой порт
  open: true,
  warmup: { clientFiles: ['./src/pages/HomePage.vue'] },   // заранее трансформировать частые файлы
},
```

## Частые ошибки

- Ожидать работу `server.proxy` в production — там нужен reverse proxy (nginx) или правильный `VITE_API_URL`.
- Не сбросить кеш `.vite` после ручной правки `node_modules` или `npm link`.
- Код с побочными эффектами (таймеры, подписки) без `dispose` — дублируется после каждого HMR.
- Смешивать именованные экспорты обычных функций и компонент в одном `.vue`-файле — ломает HMR-границы.

## Что важно помнить

- Исходники — по запросу как ESM; зависимости — pre-bundling в `.vite`.
- HMR обновляет изменённый модуль и сохраняет состояние, где возможно.
- `server.proxy` — только dev.

## Мини-шпаргалка

- `vite --force` — пересобрать зависимости.
- `optimizeDeps.include/exclude`.
- `import.meta.hot.accept/dispose`.
- `acceptHMRUpdate` для Pinia.
- `server.proxy`, `server.host: true`.
