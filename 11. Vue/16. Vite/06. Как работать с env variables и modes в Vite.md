# Как работать с env variables и modes в Vite

> [!NOTE]
> Vite загружает переменные из файлов `.env` в корне (или в `envDir`) в зависимости от **режима** (mode): `.env` (всегда), `.env.local` (всегда, не коммитится), `.env.[mode]` и `.env.[mode].local`; более специфичные файлы перекрывают общие, а переменные, уже заданные в окружении процесса (CI), имеют наивысший приоритет. Режим по умолчанию — `development` для `vite` и `production` для `vite build`; свой режим задаётся флагом `--mode staging` (тогда грузится `.env.staging`). В клиентском коде переменные доступны через **`import.meta.env`**, но только с префиксом **`VITE_`** (настраивается `envPrefix`) — это защита от случайной утечки серверных переменных. Встроенные: `import.meta.env.MODE`, `DEV`, `PROD`, `SSR`, `BASE_URL`. Значения **подставляются статически** при сборке и попадают в бандл открытым текстом — поэтому **любая `VITE_`-переменная публична**: в ней не должно быть секретов (ключей API с правами, паролей, JWT-секретов). Все значения — строки (`'false'` — истинное значение). Для типизации расширяют интерфейс `ImportMetaEnv` в `env.d.ts`. Переменные в `index.html` подставляются синтаксисом `%VITE_APP_TITLE%`. Поскольку значения вшиваются при сборке, для «одна сборка — много окружений» используют конфиг, загружаемый в рантайме (`/config.json`).

## Вопрос

Как работать с переменными окружения и режимами в Vite?

## Файлы и приоритет

```text
.env                  # всегда
.env.local            # всегда, в .gitignore
.env.development      # vite (dev)
.env.production       # vite build
.env.staging          # vite build --mode staging
.env.staging.local    # локальные переопределения staging
```

```text
Приоритет (выше — сильнее):
переменные процесса (CI) > .env.[mode].local > .env.[mode] > .env.local > .env
```

## Использование

```env
# .env
VITE_APP_TITLE=Shop

# .env.development
VITE_API_URL=/api

# .env.production
VITE_API_URL=https://api.shop.example
VITE_SENTRY_DSN=https://abc@o1.ingest.sentry.io/1     # DSN — публичный идентификатор, не секрет

# не попадёт в клиент (нет префикса), доступно только в vite.config через loadEnv
API_TARGET=http://localhost:3000
```

```ts
const api = createApiClient(import.meta.env.VITE_API_URL);

if (import.meta.env.DEV) console.debug('dev mode');          // удаляется из production-сборки
const isStaging = import.meta.env.MODE === 'staging';
```

| Встроенная | Значение |
| --- | --- |
| `MODE` | Текущий режим |
| `DEV` / `PROD` | Разработка / production-сборка |
| `SSR` | Код выполняется на сервере |
| `BASE_URL` | Значение `base` |

## Типизация

```ts
// env.d.ts
/// <reference types="vite/client" />

interface ImportMetaEnv {
  readonly VITE_API_URL: string;
  readonly VITE_APP_TITLE: string;
  readonly VITE_FEATURE_NEW_CHECKOUT?: 'true' | 'false';
}

interface ImportMeta {
  readonly env: ImportMetaEnv;
}
```

## Строки и валидация

```ts
// ✗ 'false' — непустая строка, условие истинно
if (import.meta.env.VITE_FEATURE_NEW_CHECKOUT) { /* ... */ }

// ✓
const newCheckout = import.meta.env.VITE_FEATURE_NEW_CHECKOUT === 'true';
```

```ts
// config/env.ts — упасть при старте, если переменной нет
import { z } from 'zod';
export const env = z.object({
  VITE_API_URL: z.string().min(1),
  VITE_APP_TITLE: z.string().default('Shop'),
}).parse(import.meta.env);
```

## Режимы

```json
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "build:staging": "vite build --mode staging"
  }
}
```

`--mode staging` не делает сборку «dev»: `PROD` остаётся `true`, меняется только набор `.env`-файлов и `MODE`.

## Переменные в vite.config

```ts
export default defineConfig(({ mode }) => {
  const env = loadEnv(mode, process.cwd(), '');    // '' — все переменные, не только VITE_
  return { server: { proxy: { '/api': env.API_TARGET } } };
});
```

## Одна сборка — много окружений

```ts
// main.ts — конфиг загружается в рантайме, а не вшивается при сборке
const config = await fetch('/config.json').then((r) => r.json());   // разный на staging и prod
app.provide('config', config);
```

## Частые ошибки

- Секреты в `VITE_*` — они видны в бандле любому пользователю.
- Переменная без префикса `VITE_` — `undefined` в клиенте.
- Ожидать, что изменение `.env` применится без перезапуска dev-сервера.
- Сравнивать строки как булевы значения.
- Коммитить `.env.local`.

## Что важно помнить

- Клиенту доступны только `VITE_*`, и они публичны.
- Режим выбирает набор `.env`-файлов; `--mode` для своих окружений.
- Значения вшиваются при сборке; для рантайм-конфига — отдельный JSON.

## Мини-шпаргалка

- `import.meta.env.VITE_API_URL`, `MODE`, `DEV`, `PROD`.
- `.env`, `.env.local`, `.env.[mode]`.
- `vite build --mode staging`.
- `interface ImportMetaEnv { readonly VITE_X: string }`.
- `loadEnv(mode, cwd, '')` в конфиге.
