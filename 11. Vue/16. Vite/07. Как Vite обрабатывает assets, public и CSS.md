# Как Vite обрабатывает assets, public и CSS

> [!NOTE]
> Vite различает два вида статических файлов. **Ассеты в `src`** (обычно `src/assets`) — часть графа модулей: на них ссылаются импортом (`import logoUrl from '@/assets/logo.svg'`), относительным путём в шаблоне (`<img src="@/assets/logo.png">` — plugin-vue превращает его в импорт) или в CSS (`url('./bg.jpg')`); в сборке они получают **хеш** в имени, мелкие (до `assetsInlineLimit`, 4 КБ) **инлайнятся** как data URL, а отсутствующий файл даёт ошибку сборки. Суффиксы импорта меняют результат: `?url` — URL файла, `?raw` — содержимое строкой, `?inline` — инлайн, `?worker` — Web Worker. **`public/`** — файлы, которые копируются в корень `dist` **как есть**, без хеша и обработки, и доступны по абсолютному пути от `base` (`/robots.txt`, `/favicon.ico`); туда кладут файлы с фиксированным именем: `robots.txt`, `manifest.webmanifest`, верификационные файлы, OG-картинки для внешних сервисов. **CSS** поддерживается из коробки: импорт `.css` в JS, `<style scoped>` во Vue, **CSS Modules** (`*.module.css` или `<style module>`), PostCSS (конфиг подхватывается автоматически), препроцессоры (`sass`, `less`, `stylus` — нужно только установить пакет), `@import` с алиасами; в сборке CSS извлекается в отдельные файлы по чанкам и минифицируется Lightning CSS.

## Вопрос

Как Vite обрабатывает ассеты, папку `public` и CSS?

## Ассеты из src

```vue
<script setup lang="ts">
import logoUrl from '@/assets/logo.svg';               // '/assets/logo-C8yT3e.svg' в сборке
import heroUrl from '@/assets/hero.jpg?url';
import iconSource from '@/assets/icon.svg?raw';        // содержимое SVG строкой
</script>

<template>
  <img :src="logoUrl" alt="Shop" width="120" height="32" />
  <img src="@/assets/banner.webp" alt="" />          <!-- статический путь — тоже обрабатывается -->
  <span v-html="iconSource" />                         <!-- только для собственных доверенных SVG -->
</template>
```

## Динамические пути

```ts
// ✗ Vite не знает, какие файлы включить
const src = `/src/assets/flags/${code}.svg`;

// ✓ new URL с шаблоном — Vite включит все подходящие файлы
const flagUrl = (code: string) => new URL(`../assets/flags/${code}.svg`, import.meta.url).href;

// ✓ import.meta.glob — явный набор файлов
const flags = import.meta.glob<string>('@/assets/flags/*.svg', { eager: true, import: 'default', query: '?url' });
```

## public

```text
public/
├── favicon.ico         → /favicon.ico
├── robots.txt          → /robots.txt
└── og/cover.png        → /og/cover.png
```

```html
<link rel="icon" href="/favicon.ico" />
<meta property="og:image" content="https://shop.example/og/cover.png" />
```

| `src/assets` | `public` |
| --- | --- |
| Импорт или относительный путь | Абсолютный путь `/file` |
| Хеш, инлайн, оптимизация | Копируется как есть |
| Ошибка сборки, если файла нет | Без проверки |
| Картинки компонентов, шрифты, иконки | robots.txt, favicon, manifest, файлы с фиксированным URL |

Не импортируйте файлы из `public` в JS — для этого есть `src/assets`.

## CSS

```ts
// main.ts
import './styles/main.css';
```

```vue
<style scoped>
.card { padding: 1rem; }
</style>

<style module>
.title { font-weight: 600; }
</style>

<template>
  <h2 :class="$style.title">Заголовок</h2>
</template>
```

```bash
npm i -D sass-embedded     # для <style lang="scss">; конфиг не нужен
```

```ts
// vite.config.ts
css: {
  modules: { localsConvention: 'camelCaseOnly' },
  preprocessorOptions: {
    scss: { additionalData: `@use "@/styles/tokens" as *;` },   // переменные в каждом SCSS-блоке
  },
},
```

`additionalData` подставляется в каждый файл — кладите туда только переменные и миксины, не стили (иначе они продублируются).

## Шрифты и изображения

```css
@font-face {
  font-family: 'Inter';
  src: url('@/assets/fonts/Inter.woff2') format('woff2');   /* получит хеш */
  font-display: swap;
}
```

Оптимизацию изображений (сжатие, AVIF/WebP) Vite сам не делает — используют плагины (`vite-plugin-image-optimizer`) или CDN с ресайзом.

## base

```ts
base: '/shop/',     // деплой в подпапку
```

```ts
// ассеты из src получат правильный путь автоматически; для public — через BASE_URL
const robots = `${import.meta.env.BASE_URL}robots.txt`;
```

## Частые ошибки

- Динамический путь строкой к файлу в `src/assets` — файл не попадёт в сборку.
- Картинки компонентов в `public` — нет хешей, проблемы с кешем после обновления.
- Ссылка на `/public/logo.png` — правильно `/logo.png`.
- Стили в `additionalData` — дублирование CSS в каждом компоненте.
- Абсолютные пути `/` без учёта `base` при деплое в подпапку.

## Что важно помнить

- `src/assets` — через граф модулей (хеш, инлайн, проверка); `public` — как есть.
- `?url`, `?raw`, `?inline`, `?worker`, `import.meta.glob`, `new URL(..., import.meta.url)`.
- CSS, CSS Modules, PostCSS и препроцессоры работают без лишней настройки.

## Мини-шпаргалка

- `import url from '@/assets/x.svg'`.
- `new URL(\`./img/${name}.png\`, import.meta.url).href`.
- `public/robots.txt` → `/robots.txt`.
- `<style module>` + `$style.x`.
- `css.preprocessorOptions.scss.additionalData`.
