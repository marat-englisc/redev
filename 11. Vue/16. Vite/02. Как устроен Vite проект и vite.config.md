# Как устроен Vite проект и vite.config

> [!NOTE]
> Точка входа Vite-приложения — **`index.html` в корне проекта** (а не в `public`): Vite обрабатывает его как часть графа модулей, находит `<script type="module" src="/src/main.ts">` и начинает с него. **`src/main.ts`** создаёт приложение (`createApp(App)`), подключает плагины (роутер, Pinia, i18n, UI-библиотеку), глобальные стили и монтирует его. **`vite.config.ts`** описывает конфигурацию через `defineConfig` (типизация и подсказки): `plugins` (Vue, Tailwind, Vuetify, автоимпорты), `resolve.alias` (`@` → `src`), `server` (порт, прокси на бэкенд), `build` (папка, sourcemap, цели), `css` (препроцессоры, модули), `define` (константы на этапе сборки), `base` (базовый путь при деплое не в корень), `envPrefix`. Конфиг может быть функцией `({ command, mode }) => ({...})`, чтобы различать `serve`/`build` и режимы, а `loadEnv(mode, cwd)` загружает переменные окружения внутри конфига. Алиасы нужно продублировать в `tsconfig` (`paths`), чтобы TypeScript и IDE понимали импорты. **`public/`** — файлы, копируемые как есть, **`src/assets/`** — ассеты, проходящие через сборку.

## Вопрос

Как устроен Vite-проект и что настраивается в `vite.config.ts`?

## Структура

```text
shop/
├── index.html              ← точка входа
├── vite.config.ts
├── tsconfig.json / tsconfig.app.json / tsconfig.node.json
├── env.d.ts                ← /// <reference types="vite/client" />
├── .env, .env.production
├── public/                 ← копируется в dist как есть
│   ├── favicon.svg
│   └── robots.txt
└── src/
    ├── main.ts
    ├── App.vue
    ├── assets/             ← обрабатываются Vite (хеши, инлайн)
    ├── components/
    ├── composables/
    ├── pages/
    ├── router/
    ├── stores/
    └── styles/
```

## index.html

```html
<!doctype html>
<html lang="ru">
  <head>
    <meta charset="UTF-8" />
    <link rel="icon" href="/favicon.svg" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>%VITE_APP_TITLE%</title>        <!-- подстановка env-переменной -->
  </head>
  <body>
    <div id="app"></div>
    <script type="module" src="/src/main.ts"></script>
  </body>
</html>
```

## main.ts

```ts
import { createApp } from 'vue';
import { createPinia } from 'pinia';
import App from './App.vue';
import { router } from './router';
import './styles/main.css';

createApp(App).use(createPinia()).use(router).mount('#app');
```

## vite.config.ts

```ts
import { fileURLToPath, URL } from 'node:url';
import { defineConfig, loadEnv } from 'vite';
import vue from '@vitejs/plugin-vue';
import vueDevTools from 'vite-plugin-vue-devtools';

export default defineConfig(({ command, mode }) => {
  const env = loadEnv(mode, process.cwd(), '');      // все переменные, включая без VITE_ (только для конфига)

  return {
    plugins: [vue(), command === 'serve' && vueDevTools()],
    resolve: {
      alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) },
    },
    server: {
      port: 5173,
      proxy: {
        '/api': { target: env.API_TARGET ?? 'http://localhost:3000', changeOrigin: true },
      },
    },
    build: {
      sourcemap: mode === 'staging',
      chunkSizeWarningLimit: 600,
    },
    css: {
      preprocessorOptions: { scss: { additionalData: `@use "@/styles/vars" as *;` } },
    },
    define: {
      __APP_VERSION__: JSON.stringify(process.env.npm_package_version),
    },
    base: env.BASE_PATH ?? '/',
  };
});
```

## Основные секции

| Секция | Для чего |
| --- | --- |
| `plugins` | Расширения: Vue, Tailwind, Vuetify, PWA |
| `resolve.alias` | Короткие пути импортов |
| `server` | Порт, `proxy`, `host`, `https` |
| `preview` | Настройки `vite preview` |
| `build` | `outDir`, `sourcemap`, `target`, `rolldownOptions` |
| `css` | Препроцессоры, CSS Modules, PostCSS |
| `define` | Глобальные константы, заменяемые при сборке |
| `base` | Публичный базовый путь (`/my-app/`) |
| `envDir`, `envPrefix` | Где искать `.env` и какой префикс открыт клиенту |
| `optimizeDeps` | Настройка pre-bundling зависимостей |

## Алиасы и TypeScript

```json
// tsconfig.app.json
{
  "compilerOptions": {
    "paths": { "@/*": ["./src/*"] }
  }
}
```

## Типы для define

```ts
// env.d.ts
/// <reference types="vite/client" />
declare const __APP_VERSION__: string;
```

## Частые ошибки

- Положить `index.html` в `public/`.
- Алиас в `vite.config` без `paths` в `tsconfig` — IDE не находит импорты.
- `define` без `JSON.stringify` — подставится код, а не строка.
- Использовать в клиентском коде значения из `loadEnv(mode, cwd, '')` через `define` — так секреты попадут в бандл.

## Что важно помнить

- `index.html` в корне — точка входа графа модулей.
- `vite.config.ts`: plugins, alias, server, build, css, define, base.
- Конфиг-функция `({ command, mode })` + `loadEnv` для условной конфигурации.

## Мини-шпаргалка

- `defineConfig(({ command, mode }) => ({...}))`.
- `resolve.alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) }`.
- `server.proxy: { '/api': { target, changeOrigin: true } }`.
- `define: { __X__: JSON.stringify(value) }`.
