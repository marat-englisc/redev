# Какие ошибки бывают при работе с Vite

> [!NOTE]
> Большинство проблем с Vite возникает на стыке dev и production. **Переменные окружения**: нет префикса `VITE_` (значение `undefined`), секреты в `VITE_*` (попадают в бандл), строка `'false'` как истина, изменения `.env` без перезапуска. **Пути**: неправильный `base` при деплое в подпапку (ассеты 404), разный регистр в имени файла (`Header.vue` vs `header.vue` — на Windows/macOS работает, на Linux-сервере сборка падает), динамический путь к ассету строкой. **Сервер**: `server.proxy` работает только в dev — в production нужен reverse proxy или полный URL API; history mode без fallback на `index.html` даёт 404 при обновлении страницы. **Сборка и окружение**: обращение к `window`/`document` на верхнем уровне модуля ломает SSR и пререндер, CommonJS-зависимость или зависимость, найденная поздно, вызывает перезагрузки и ошибки «does not provide an export» — помогает `optimizeDeps.include` и `vite --force`; ожидание проверки типов от `vite build` (нужен `vue-tsc`). **Кеш**: долгий кеш `index.html` и ошибки загрузки старых чанков после деплоя. **Миграция на Vite 8**: `rollupOptions` → `rolldownOptions`, устаревшие `manualChunks` и опция `esbuild` (теперь `oxc`), отсутствие некоторых Rollup-хуков у старых плагинов. Правило: регулярно проверяйте `vite build && vite preview` локально и в CI.

## Вопрос

Какие ошибки чаще всего возникают при работе с Vite и как их избежать?

## Переменные окружения

```env
API_URL=https://api.example.com          # ✗ нет VITE_ — в клиенте undefined
VITE_STRIPE_SECRET_KEY=sk_live_...       # ✗ секрет в бандле
VITE_API_URL=https://api.example.com     # ✓
```

```ts
if (import.meta.env.VITE_DEBUG) {}                     // ✗ 'false' — истина
if (import.meta.env.VITE_DEBUG === 'true') {}          // ✓
```

## base и подпапка

```text
Деплой на https://example.com/shop/
Без base: <script src="/assets/index.js"> → https://example.com/assets/index.js → 404
```

```ts
export default defineConfig({ base: '/shop/' });
// + createWebHistory(import.meta.env.BASE_URL) в роутере
```

## Регистр имён файлов

```ts
import Header from './components/header.vue';   // файл Header.vue
// Windows/macOS: работает; Linux CI: Could not resolve "./components/header.vue"
```

Включите `forceConsistentCasingInFileNames` в tsconfig и запускайте сборку в CI на Linux.

## Proxy в production

```ts
server: { proxy: { '/api': 'http://localhost:3000' } }   // только vite dev
```

```nginx
location /api/ {
  proxy_pass http://backend:3000;      # production
}
location / {
  try_files $uri $uri/ /index.html;    # fallback для history mode
}
```

## Браузерные API на верхнем уровне

```ts
// ✗ падает при SSR/пререндере и в тестах без DOM
const saved = localStorage.getItem('theme');

// ✓
const theme = ref('light');
onMounted(() => { theme.value = localStorage.getItem('theme') ?? 'light'; });
```

## Зависимости

```text
[vite] new dependencies optimized: some-lib. reloading
SyntaxError: The requested module '/node_modules/old-lib/index.js' does not provide an export named 'default'
```

```ts
optimizeDeps: { include: ['some-lib', 'old-lib'] },
```

```bash
npx vite --force
```

## Типы не проверяются

```json
{ "scripts": { "build": "vue-tsc -b && vite build", "type-check": "vue-tsc --build" } }
```

## Ошибки после деплоя

```text
TypeError: Failed to fetch dynamically imported module: /assets/CatalogPage-old123.js
```

Пользователь открыл старую версию, а файлы удалены. Решения: хранить предыдущие ассеты некоторое время, `no-cache` для `index.html`, перезагрузка в `router.onError` или по событию `vite:preloadError`:

```ts
window.addEventListener('vite:preloadError', () => {
  window.location.reload();
});
```

## Миграция на Vite 8

| Было | Стало |
| --- | --- |
| `build.rollupOptions` | `build.rolldownOptions` |
| `output.manualChunks` (объект) | Удалён — `codeSplitting.groups` |
| `output.manualChunks` (функция) | Устарел |
| `esbuild: {...}` | `oxc: {...}` |
| `optimizeDeps.esbuildOptions` | `optimizeDeps.rolldownOptions` |
| `build.minify: 'esbuild'` | Требует установить `esbuild` вручную |

## Что важно помнить

- `VITE_` — публично; `base` для подпапок; proxy — только dev.
- Регистр путей и браузерные API на верхнем уровне ломают сборку и SSR.
- Проверяйте `build` + `preview` и типы через `vue-tsc` в CI.

## Мини-шпаргалка

- `base: '/sub/'` + `createWebHistory(import.meta.env.BASE_URL)`.
- `optimizeDeps.include`, `vite --force`.
- `vue-tsc -b && vite build`.
- `vite:preloadError` — перезагрузка при устаревших чанках.
- Vite 8: `rolldownOptions`, `oxc`, `codeSplitting`.
