# Как работают Vite plugins

> [!NOTE]
> Плагин Vite — объект с именем и **хуками**, которые встраиваются в обработку модулей. Интерфейс плагинов расширяет интерфейс Rollup (с Vite 8 его исполняет Rolldown, сохраняя совместимость): `resolveId` (как найти модуль по импорту), `load` (как загрузить содержимое — в том числе **виртуальные модули**, которых нет на диске, вроде `vue-router/auto-routes`), `transform` (как преобразовать код — так `@vitejs/plugin-vue` компилирует `.vue` в JS). Есть хуки, специфичные для Vite: `config`/`configResolved` (изменить или прочитать конфигурацию), `configureServer` (добавить middleware в dev-сервер), `transformIndexHtml` (изменить `index.html`), `handleHotUpdate`/`hotUpdate` (своя логика HMR). Свойства `enforce: 'pre' | 'post'` и `apply: 'serve' | 'build'` управляют порядком и режимом. **Порядок** в массиве `plugins` важен, когда плагины обрабатывают одни файлы (плагин файловой маршрутизации — до `vue()`). Частые плагины во Vue: `@vitejs/plugin-vue`, `@vitejs/plugin-vue-jsx`, `vite-plugin-vue-devtools`, `@tailwindcss/vite`, `vite-plugin-vuetify`, `unplugin-auto-import` и `unplugin-vue-components` (автоимпорт API и компонентов), `vite-plugin-pwa`, `vite-svg-loader`, `rollup-plugin-visualizer`. Пакеты с префиксом `unplugin-` работают в нескольких сборщиках (Vite, webpack, Rolldown, esbuild).

## Вопрос

Как работают плагины Vite и какие из них часто используются во Vue-проектах?

## Подключение

```ts
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';
import tailwindcss from '@tailwindcss/vite';
import AutoImport from 'unplugin-auto-import/vite';
import Components from 'unplugin-vue-components/vite';
import VueRouter from 'vue-router/vite';

export default defineConfig({
  plugins: [
    VueRouter(),                                       // до vue(): генерирует маршруты из src/pages
    vue(),
    tailwindcss(),
    AutoImport({ imports: ['vue', 'vue-router', 'pinia'], dts: 'src/auto-imports.d.ts' }),
    Components({ dts: 'src/components.d.ts' }),        // компоненты из src/components без import
  ],
});
```

## Хуки

```text
config → configResolved → (dev) configureServer
для каждого модуля: resolveId → load → transform
build: buildStart → ... → generateBundle → writeBundle
HTML: transformIndexHtml
HMR: hotUpdate
```

## Свой плагин: виртуальный модуль

```ts
// plugins/build-info.ts
import type { Plugin } from 'vite';

export function buildInfo(): Plugin {
  const id = 'virtual:build-info';
  const resolved = '\0' + id;                       // \0 — соглашение для виртуальных модулей
  return {
    name: 'build-info',
    resolveId(source) {
      if (source === id) return resolved;
    },
    load(moduleId) {
      if (moduleId === resolved) {
        return `export const builtAt = ${JSON.stringify(new Date().toISOString())};`;
      }
    },
  };
}
```

```ts
import { builtAt } from 'virtual:build-info';
```

## Свой плагин: transform и HTML

```ts
export function stripDebug(): Plugin {
  return {
    name: 'strip-debug',
    apply: 'build',                                 // только для production-сборки
    enforce: 'post',
    transform(code, id) {
      if (!/\.(ts|js|vue)$/.test(id)) return;
      return { code: code.replace(/console\.debug\([^)]*\);?/g, ''), map: null };
    },
    transformIndexHtml(html) {
      return html.replace('</head>', '<meta name="build" content="prod"></head>');
    },
  };
}
```

## Middleware dev-сервера

```ts
export function mockApi(): Plugin {
  return {
    name: 'mock-api',
    apply: 'serve',
    configureServer(server) {
      server.middlewares.use('/api/health', (_req, res) => {
        res.setHeader('Content-Type', 'application/json');
        res.end(JSON.stringify({ ok: true }));
      });
    },
  };
}
```

## Порядок

```text
1. Плагины с enforce: 'pre'
2. Встроенные плагины Vite (alias и др.)
3. Обычные плагины (в порядке массива)
4. Встроенные плагины сборки
5. Плагины с enforce: 'post'
```

## Частые ошибки

- Неправильный порядок плагинов, работающих с `.vue`.
- Автоимпорт без генерации `.d.ts` — TypeScript не видит глобальные API.
- Подключить dev-плагин в production (DevTools) — используйте `apply: 'serve'` или условие по `command`.
- Тяжёлые `transform` для всех файлов без фильтра по `id` — медленный dev.
- Устаревшие Rollup-плагины, использующие хуки, которых нет в Rolldown.

## Что важно помнить

- Плагин = объект с хуками `resolveId`, `load`, `transform` + Vite-хуки.
- Виртуальные модули — код, сгенерированный плагином.
- `enforce`, `apply` и порядок в массиве управляют выполнением.

## Мини-шпаргалка

- `plugins: [vue(), tailwindcss()]`.
- `{ name, resolveId, load, transform, configureServer, transformIndexHtml }`.
- `virtual:x` → `'\0virtual:x'`.
- `apply: 'serve' | 'build'`, `enforce: 'pre' | 'post'`.
