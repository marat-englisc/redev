# Как работает v-for и зачем нужен key

> [!NOTE]
> `v-for` рендерит элемент или компонент для каждого элемента **массива** (`item in items`, `(item, index) in items`), **объекта** (`(value, key, index) in obj`), **числа** (`n in 10` — от 1 до 10) или любого **итерируемого** значения (`Map`, `Set`). Атрибут **`:key`** — уникальный и стабильный идентификатор элемента списка, по которому Vue сопоставляет старые и новые узлы при обновлении: с ключами Vue **переставляет** существующие DOM-узлы и экземпляры компонентов, без ключей (или с индексом в роли ключа) — обновляет «по месту» по позиции, из-за чего при вставке, удалении и сортировке состояние (введённый текст, фокус, состояние дочерних компонентов, анимации) **оказывается не у того элемента**. Ключ — это `id` из данных, не `index` и не `Math.random()` (новый ключ на каждый рендер пересоздаёт всё). Изменения массива отслеживаются для мутирующих методов (`push`, `splice`, `sort`) и при замене массива (`filter`, `toSorted` → присвоить новый). Для групп элементов — `<template v-for>`, для фильтрации — `computed`.

## Вопрос

Как работает `v-for` во Vue и зачем нужен атрибут `key`?

## Синтаксис

```vue
<li v-for="product in products" :key="product.id">{{ product.title }}</li>

<li v-for="(product, index) in products" :key="product.id">{{ index + 1 }}. {{ product.title }}</li>

<dl>
  <template v-for="(value, key) in specs" :key="key">
    <dt>{{ key }}</dt>
    <dd>{{ value }}</dd>
  </template>
</dl>

<span v-for="n in 5" :key="n">★</span>                    <!-- 1..5 -->

<UserRow v-for="user in users" :key="user.id" :user="user" @remove="remove(user.id)" />
```

## Почему index — плохой key

```text
Список: [Анна, Борис, Вера] — у каждого поле ввода с комментарием

Удаляем Анну, key = index:
  до:    0:Анна[текст А]  1:Борис[текст Б]  2:Вера[текст В]
  после: 0:Борис          1:Вера
  Vue: узел 0 переиспользован → Борис получил «текст А», узел 2 удалён → «текст В» потерян

key = id:
  Vue удаляет узел Анны, узлы Бориса и Веры сохраняются со своим текстом
```

| Ключ | Поведение |
| --- | --- |
| `item.id` | ✓ Правильное сопоставление при любых изменениях |
| `index` | Допустимо только для статичных списков без состояния |
| `Math.random()` / `crypto.randomUUID()` в шаблоне | ✗ Каждый рендер — пересоздание всех элементов |
| Нет ключа | ✗ То же, что index; в компонентах — предупреждение |

## Обновление массивов

```ts
items.value.push(newItem);                          // реактивно
items.value.splice(index, 1);                       // реактивно
items.value[i] = updated;                           // реактивно (Vue 3)
items.value = items.value.filter((i) => !i.done);   // замена — реактивно

const sorted = computed(() => items.value.toSorted((a, b) => a.price - b.price));   // не мутирует исходный
```

## Фильтрация и сортировка

```vue
<script setup lang="ts">
const visible = computed(() =>
  products.value
    .filter((p) => p.title.toLowerCase().includes(query.value.toLowerCase()))
    .toSorted((a, b) => a.price - b.price),
);
</script>

<template>
  <ProductCard v-for="p in visible" :key="p.id" :product="p" />
  <p v-if="visible.length === 0">Ничего не найдено</p>
</template>
```

## key вне списков

`key` также используется, чтобы заставить Vue пересоздать элемент или компонент: `<Comp :key="userId" />`, и для `<Transition>` при смене содержимого.

## Большие списки

Тысячи элементов в `v-for` — тяжело для рендера и памяти. Решения: пагинация, «показать ещё», [виртуализация](<../14. Оптимизация и производительность/05. Как оптимизировать большие таблицы и списки - виртуализация.md>), `v-memo`, `shallowRef` для данных.

## Частые ошибки

- `:key="index"` в списках с удалением, вставкой, сортировкой или полями ввода.
- Ключи, генерируемые в шаблоне.
- `v-if` и `v-for` на одном элементе.
- Сортировка `items.value.sort()` внутри computed — мутирует исходный массив.
- Дублирующиеся ключи — непредсказуемые обновления.

## Что важно помнить

- `v-for` + стабильный уникальный `:key` из данных.
- Ключ определяет, какие DOM-узлы и экземпляры переиспользуются.
- Фильтрация и сортировка — в `computed` без мутации исходных данных.

## Мини-шпаргалка

- `v-for="(item, i) in list" :key="item.id"`.
- `v-for="(value, key) in obj"`, `v-for="n in 10"`.
- `<template v-for>` для групп.
- `toSorted`, `filter` в `computed`.
