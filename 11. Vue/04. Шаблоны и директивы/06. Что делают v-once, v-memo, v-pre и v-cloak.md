# Что делают v-once, v-memo, v-pre и v-cloak

> [!NOTE]
> Эти редкие директивы решают узкие задачи. **`v-once`** рендерит элемент или компонент **один раз**, после чего Vue считает его статичным и пропускает при обновлениях — для контента, который не меняется после первого рендера (условия соглашения, большие статичные блоки с данными на момент загрузки). **`v-memo="[dep1, dep2]"`** мемоизирует поддерево: оно перерендеривается, только если изменилось одно из значений массива зависимостей (`v-memo="[]"` ≈ `v-once`); полезно в больших `v-for`, где при изменении одного элемента не нужно сравнивать остальные (используется вместе с `key` на том же элементе). **`v-pre`** отключает компиляцию элемента и его потомков — для вывода «сырого» синтаксиса `{{ }}` (документация, примеры кода). **`v-cloak`** остаётся на элементе до завершения компиляции и вместе с CSS `[v-cloak] { display: none }` скрывает некомпилированный шаблон — нужен только при использовании **DOM-шаблонов** без сборки; в SFC-проектах не применяется. `v-memo` и `v-once` — инструменты микрооптимизации: сначала измеряйте.

## Вопрос

Для чего используются `v-once`, `v-memo`, `v-pre` и `v-cloak`?

## v-once

```vue
<template>
  <section v-once>
    <h2>Условия оферты (версия {{ terms.version }})</h2>
    <div v-html="terms.html" />          <!-- большой блок, не меняется после загрузки -->
  </section>

  <span v-once>Открыто: {{ openedAt }}</span>   <!-- значение на момент первого рендера -->
</template>
```

После первого рендера изменения `terms` или `openedAt` в этом блоке **не отобразятся**.

## v-memo

```vue
<template>
  <div
    v-for="row in rows"
    :key="row.id"
    v-memo="[row.id === selectedId, row.updatedAt]"
    class="row"
    :class="{ selected: row.id === selectedId }"
  >
    <ExpensiveCell :row="row" />
  </div>
</template>
```

При смене `selectedId` перерендерятся только две строки (старая и новая выбранная), остальные тысячи — пропущены целиком, включая сравнение VNode.

| Использование | Эффект |
| --- | --- |
| `v-memo="[a, b]"` | Обновлять при изменении `a` или `b` |
| `v-memo="[]"` | Как `v-once` |
| Внутри `v-for` | Только на том же элементе, что `v-for` |

Если в массив зависимостей не включить значение, влияющее на рендер, UI «застынет» с устаревшими данными — это главный риск `v-memo`.

## v-pre

```vue
<p v-pre>Интерполяция пишется так: {{ variable }}</p>
<pre v-pre><code>&lt;button @click="count++"&gt;{{ count }}&lt;/button&gt;</code></pre>
```

## v-cloak (DOM-шаблоны)

```html
<!-- index.html без сборки -->
<style>[v-cloak] { display: none; }</style>

<div id="app" v-cloak>
  {{ message }}             <!-- без v-cloak на мгновение виден «{{ message }}» -->
</div>

<script type="module">
  import { createApp } from 'https://unpkg.com/vue@3/dist/vue.esm-browser.js';
  createApp({ data: () => ({ message: 'Привет' }) }).mount('#app');
</script>
```

В SFC шаблон компилируется при сборке — `v-cloak` не нужен.

## Когда что

| Директива | Задача |
| --- | --- |
| `v-once` | Неизменяемый после первого рендера контент |
| `v-memo` | Большие списки, где меняется малая часть |
| `v-pre` | Показать синтаксис шаблона как текст |
| `v-cloak` | Скрыть некомпилированный DOM-шаблон |

## Частые ошибки

- `v-once` на данных, которые позже должны обновиться.
- `v-memo` с неполным списком зависимостей — устаревший UI.
- `v-memo` «везде» без измерений — лишняя сложность.
- `v-cloak` в проекте на Vite и SFC.

## Что важно помнить

- `v-once` — один рендер, `v-memo` — рендер по зависимостям.
- `v-pre` — без компиляции, `v-cloak` — только для DOM-шаблонов.
- `v-memo` и `v-once` — точечные оптимизации после профилирования.

## Мини-шпаргалка

- `<div v-once>`.
- `v-for="r in rows" :key="r.id" v-memo="[r.id === sel]"`.
- `<span v-pre>{{ raw }}</span>`.
- `[v-cloak] { display: none }`.
