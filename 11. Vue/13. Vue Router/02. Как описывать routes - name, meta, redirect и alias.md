# Как описывать routes - name, meta, redirect и alias

> [!NOTE]
> Маршрут — объект в массиве `routes` с обязательным **`path`** и компонентом (`component` — сразу или функцией ленивой загрузки `() => import(...)`) либо `redirect`. **`name`** — уникальное имя маршрута: навигация по имени (`{ name: 'product', params }`) не ломается при изменении URL и лучше типизируется. **`meta`** — произвольные данные маршрута (требуется ли авторизация, роли, заголовок страницы, layout, анимация перехода); доступны в guards и компонентах как `route.meta` (мета родительских маршрутов объединяются). **`redirect`** — перенаправление на другой путь, имя или функцию; **`alias`** — дополнительный URL, показывающий тот же компонент без смены адреса. **`props`** передаёт параметры маршрута в компонент как props (`true`, объект или функция), отвязывая компонент от `useRoute`. **`children`** — вложенные маршруты. Маршрут «всё остальное» (`/:pathMatch(.*)*`) обрабатывает 404. Для типизации `meta` расширяют интерфейс `RouteMeta`.

## Вопрос

Как описывать маршруты во Vue Router и для чего нужны `name`, `meta`, `redirect`, `alias` и `props`?

## Пример таблицы маршрутов

```ts
export const routes: RouteRecordRaw[] = [
  { path: '/', name: 'home', component: HomePage, meta: { title: 'Главная' } },

  { path: '/login', name: 'login', component: () => import('@/pages/LoginPage.vue'), meta: { layout: 'blank', guestOnly: true } },

  {
    path: '/catalog/:category?',
    name: 'catalog',
    component: () => import('@/pages/CatalogPage.vue'),
    props: (route) => ({ category: route.params.category, page: Number(route.query.page ?? 1) }),
  },

  { path: '/product/:id', name: 'product', component: () => import('@/pages/ProductPage.vue'), props: true },

  {
    path: '/account',
    component: () => import('@/layouts/AccountLayout.vue'),
    meta: { requiresAuth: true },
    children: [
      { path: '', name: 'account', redirect: { name: 'account-orders' } },
      { path: 'orders', name: 'account-orders', component: () => import('@/pages/account/Orders.vue') },
      { path: 'settings', name: 'account-settings', component: () => import('@/pages/account/Settings.vue'), alias: '/settings' },
    ],
  },

  { path: '/admin', component: () => import('@/pages/AdminPage.vue'), meta: { requiresAuth: true, roles: ['admin'] } },

  { path: '/old-catalog', redirect: '/catalog' },
  { path: '/search', redirect: (to) => ({ name: 'catalog', query: { q: to.query.q } }) },

  { path: '/:pathMatch(.*)*', name: 'not-found', component: () => import('@/pages/NotFound.vue') },
];
```

## name

```ts
router.push({ name: 'product', params: { id: '42' } });   // URL можно поменять в одном месте
router.push('/product/42');                                // строка — ломается при смене пути
```

## meta

```ts
// типизация
declare module 'vue-router' {
  interface RouteMeta {
    title?: string;
    requiresAuth?: boolean;
    guestOnly?: boolean;
    roles?: Array<'admin' | 'manager'>;
    layout?: 'default' | 'blank';
  }
}

// использование
router.afterEach((to) => { document.title = to.meta.title ? `${to.meta.title} — Shop` : 'Shop'; });
```

`to.meta` содержит объединение `meta` всех совпавших записей (родителя и ребёнка); отдельные записи — в `to.matched`.

## props вместо useRoute

```vue
<!-- ProductPage.vue получает id как prop — легко тестировать и переиспользовать -->
<script setup lang="ts">
const props = defineProps<{ id: string }>();
const { product } = useProduct(() => props.id);
</script>
```

| `props` | Что передаётся |
| --- | --- |
| `true` | `route.params` как props |
| `{ static: 1 }` | Статичный объект |
| `(route) => ({...})` | Любое вычисление (query, приведение типов) |

## redirect и alias

| | `redirect` | `alias` |
| --- | --- | --- |
| URL в адресной строке | Меняется на целевой | Остаётся алиасом |
| Для чего | Старые адреса, переименования, дефолтная дочерняя страница | Несколько URL одной страницы |
| SEO | 301 на сервере предпочтительнее | Дубли контента — нужен canonical |

## 404

```ts
{ path: '/:pathMatch(.*)*', name: 'not-found', component: NotFound }
// to.params.pathMatch — массив сегментов исходного пути
```

В SPA сервер всё равно отдаёт 200 с `index.html` — для SEO важные страницы рендерят через SSR/SSG.

## Частые ошибки

- Одинаковые `name` у маршрутов.
- Навигация строками по всему коду вместо имён.
- Маршрут 404 не последним (в Vue Router 4+ порядок не важен благодаря ранжированию, но читаемость страдает).
- Использовать `useRoute()` в компонентах, которые проще сделать независимыми через `props`.
- `meta` без типизации — опечатки в ключах.

## Что важно помнить

- `path` + компонент (лениво) + `name`; `meta` — данные маршрута для guards и UI.
- `props` отвязывает компонент от роутера.
- `redirect` меняет URL, `alias` — нет; `/:pathMatch(.*)*` — 404.

## Мини-шпаргалка

- `{ path, name, component: () => import(...), meta, props }`.
- `redirect: '/x' | { name } | (to) => ...`, `alias: '/y'`.
- `declare module 'vue-router' { interface RouteMeta {...} }`.
- `{ path: '/:pathMatch(.*)*' }`.
