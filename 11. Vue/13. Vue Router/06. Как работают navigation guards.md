# Как работают navigation guards

> [!NOTE]
> **Navigation guards** — функции, которые роутер вызывает во время навигации, чтобы **разрешить, отменить или перенаправить** переход. Уровни: **глобальные** (`router.beforeEach` — перед каждым переходом, `router.beforeResolve` — после разрешения асинхронных компонентов и guards компонентов, `router.afterEach` — после завершения, без возможности отменить), **маршрута** (`beforeEnter` в описании маршрута — только при входе, не при смене params/query) и **компонента** (`onBeforeRouteLeave` — уход со страницы, например предупреждение о несохранённых данных, `onBeforeRouteUpdate` — смена params того же маршрута). Guard получает `to` и `from` и **возвращает** результат: `undefined`/`true` — продолжить, `false` — отменить, маршрут (`'/login'` или `{ name: 'login', query }`) — перенаправить; может быть `async`. Старый третий аргумент `next()` поддерживается, но не рекомендуется. Типичные задачи: проверка авторизации и ролей по `meta`, загрузка текущего пользователя перед первым переходом, редирект гостей, заголовок страницы, аналитика, прогресс-бар. Guards — **UX-защита**: доступ к данным всё равно проверяет сервер.

## Вопрос

Как работают navigation guards во Vue Router и как с их помощью сделать защиту маршрутов?

## Глобальный guard авторизации

```ts
// router/guards.ts
router.beforeEach(async (to) => {
  const auth = useAuthStore();

  if (!auth.initialized) await auth.fetchMe();          // один раз при старте: восстановить сессию

  if (to.meta.requiresAuth && !auth.isLoggedIn) {
    return { name: 'login', query: { redirect: to.fullPath } };
  }

  if (to.meta.guestOnly && auth.isLoggedIn) {
    return { name: 'home' };
  }

  if (to.meta.roles && !to.meta.roles.some((r) => auth.user?.roles.includes(r))) {
    return { name: 'forbidden' };
  }
  // undefined → продолжить
});

router.afterEach((to, from, failure) => {
  if (!failure) {
    document.title = to.meta.title ? `${to.meta.title} — Shop` : 'Shop';
    analytics.page(to.fullPath);
  }
});
```

## Порядок вызова

```text
1. onBeforeRouteLeave в уходящих компонентах
2. router.beforeEach
3. onBeforeRouteUpdate в переиспользуемых компонентах
4. beforeEnter маршрута
5. загрузка асинхронных компонентов маршрута
6. router.beforeResolve
7. навигация подтверждена, DOM обновлён
8. router.afterEach
```

## beforeEnter

```ts
{
  path: '/product/:id',
  component: ProductPage,
  beforeEnter: async (to) => {
    const exists = await api.productExists(to.params.id as string);
    if (!exists) return { name: 'not-found', params: { pathMatch: to.path.substring(1).split('/') }, query: to.query, hash: to.hash };
  },
}
```

Вызывается только при **входе** на маршрут, не при смене params/query/hash.

## Guards компонента

```vue
<script setup lang="ts">
const isDirty = computed(() => /* есть несохранённые изменения */ true);

onBeforeRouteLeave(() => {
  if (isDirty.value && !window.confirm('Есть несохранённые изменения. Уйти со страницы?')) return false;
});

onBeforeRouteUpdate(async (to) => {
  await load(to.params.id as string);      // /product/1 → /product/2
});
</script>
```

Для закрытия вкладки или перезагрузки страницы (вне роутера) — событие `beforeunload`.

## Возвращаемые значения

| Значение | Результат |
| --- | --- |
| `undefined` / `true` | Продолжить |
| `false` | Отменить (URL вернётся к `from`) |
| `'/path'` / `{ name, query }` | Перенаправить |
| `throw new Error()` | Отменить и вызвать `router.onError` |

## Прогресс-бар

```ts
router.beforeEach(() => { progress.start(); });
router.afterEach(() => { progress.finish(); });
router.onError(() => { progress.fail(); });
```

## Бесконечные редиректы

```ts
// ✗ /login тоже requiresAuth → вечный редирект
{ path: '/login', meta: { requiresAuth: true } }

// ✓ guard не перенаправляет туда, где уже находится, а /login помечен guestOnly
```

## Частые ошибки

- Редирект на маршрут, который снова вызывает тот же редирект.
- Использование `next()` и забытый вызов — навигация «зависает».
- Ожидать `beforeEnter` при смене params.
- Считать guards безопасностью — без проверки на сервере данные доступны через API.
- Загружать пользователя в каждом `beforeEach` вместо одного раза с кешем.

## Что важно помнить

- Guards: глобальные (`beforeEach`, `beforeResolve`, `afterEach`), маршрута (`beforeEnter`), компонента (`onBeforeRouteLeave/Update`).
- Возвращайте `false`, маршрут или ничего; `async` поддерживается.
- Права проверяет сервер, guards — UX и маршрутизация.

## Мини-шпаргалка

- `router.beforeEach(async (to, from) => {...})`.
- `return { name: 'login', query: { redirect: to.fullPath } }`.
- `beforeEnter: (to) => ...`.
- `onBeforeRouteLeave(() => confirm(...) || false)`.
- `to.meta.requiresAuth`, `to.meta.roles`.
