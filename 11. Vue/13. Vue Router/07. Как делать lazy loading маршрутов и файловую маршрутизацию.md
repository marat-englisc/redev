# Как делать lazy loading маршрутов и файловую маршрутизацию

> [!NOTE]
> **Ленивая загрузка маршрутов** — указание компонента функцией динамического импорта `component: () => import('@/pages/CatalogPage.vue')`: сборщик выносит страницу в отдельный **чанк**, который загружается только при первом переходе на маршрут. Начальный бандл уменьшается, первая загрузка ускоряется; обычно лениво грузят все страницы, кроме главной. Связанные страницы можно объединять в один чанк (`codeSplitting` в Vite 8, `manualChunks` в старых версиях), а вероятные переходы — **предзагружать** (`import()` при наведении на ссылку или в `requestIdleCallback`). Ошибку загрузки чанка (например, после деплоя старые хеши исчезли) обрабатывают в `router.onError` — перезагрузкой страницы. **Файловая маршрутизация** (как в Nuxt) генерирует маршруты из структуры папки `src/pages`: `pages/product/[id].vue` → `/product/:id`. В **Vue Router 5** она встроена в основной пакет: Vite-плагин `vue-router/vite`, маршруты импортируются из `vue-router/auto-routes`, а генерируемый файл `route-map.d.ts` даёт **типизированные** имена маршрутов и параметры; ранее то же делал пакет `unplugin-vue-router`.

## Вопрос

Как настроить ленивую загрузку маршрутов и файловую маршрутизацию во Vue Router?

## Ленивые маршруты

```ts
const routes = [
  { path: '/', name: 'home', component: HomePage },                                     // в основном бандле
  { path: '/catalog', name: 'catalog', component: () => import('@/pages/CatalogPage.vue') },
  { path: '/product/:id', name: 'product', component: () => import('@/pages/ProductPage.vue') },
  {
    path: '/admin',
    component: () => import('@/layouts/AdminLayout.vue'),
    children: [{ path: 'reports', component: () => import('@/pages/admin/Reports.vue') }],
  },
];
```

```text
dist/assets/index-a1b2.js        ← главная + общий код
dist/assets/CatalogPage-c3d4.js  ← при переходе в каталог
dist/assets/Reports-e5f6.js      ← только для админов
```

## Группировка чанков

```ts
// vite.config.ts (Vite 8, сборщик Rolldown)
build: {
  rolldownOptions: {
    output: {
      codeSplitting: {
        groups: [{ name: 'admin', test: /[\\/]pages[\\/]admin[\\/]/ }],   // все админ-страницы одним чанком
      },
    },
  },
},
```

В Vite 7 и ниже (Rollup) то же делали через `build.rollupOptions.output.manualChunks`; в Vite 8 `rollupOptions` переименован в `rolldownOptions`, а функция `manualChunks` устарела.

## Предзагрузка

```vue
<RouterLink to="/catalog" @mouseenter="() => import('@/pages/CatalogPage.vue')">Каталог</RouterLink>
```

```ts
// после загрузки главной — в простое
requestIdleCallback(() => { import('@/pages/CatalogPage.vue'); });
```

## Ошибка загрузки чанка

```ts
router.onError((error, to) => {
  if (/Failed to fetch dynamically imported module|Importing a module script failed/.test(error.message)) {
    window.location.assign(to.fullPath);       // новая версия приложения задеплоена — перезагрузить
  }
});
```

## Файловая маршрутизация (Vue Router 5)

```ts
// vite.config.ts
import VueRouter from 'vue-router/vite';
import vue from '@vitejs/plugin-vue';

export default defineConfig({
  plugins: [VueRouter({ dts: 'src/route-map.d.ts' }), vue()],   // VueRouter — до vue()
});
```

```ts
// router/index.ts
import { createRouter, createWebHistory } from 'vue-router';
import { routes } from 'vue-router/auto-routes';

export const router = createRouter({ history: createWebHistory(), routes });
```

```text
src/pages/
├── index.vue              → /
├── catalog.vue            → /catalog
├── product/
│   └── [id].vue           → /product/:id
├── account.vue            → /account (layout с <RouterView />)
├── account/
│   ├── index.vue          → /account
│   └── orders.vue         → /account/orders
└── [...path].vue          → 404
```

```vue
<!-- pages/product/[id].vue -->
<script setup lang="ts">
const route = useRoute('/product/[id]');          // типизировано: route.params.id — string
definePage({ meta: { title: 'Товар' } });         // meta и прочие опции маршрута в самом файле
</script>
```

```ts
router.push({ name: '/product/[id]', params: { id: '42' } });   // имя и параметры проверяются TypeScript
```

При миграции с `unplugin-vue-router` достаточно заменить импорты: `unplugin-vue-router/vite` → `vue-router/vite`, данные-лоадеры — `vue-router/experimental`.

## Ручные или файловые маршруты

| Ручная таблица | Файловая маршрутизация |
| --- | --- |
| Полный контроль, явная конфигурация | Меньше кода, соглашения |
| Типизация — вручную | Типизированные имена и params из коробки |
| Привычно в существующих проектах | Как в Nuxt; встроено в Vue Router 5 |

## Частые ошибки

- Статические импорты всех страниц — большой начальный бандл.
- Ленивая загрузка мелких компонентов внутри страницы вместо страниц целиком.
- Нет обработки ошибки загрузки чанка после деплоя.
- В файловой маршрутизации — плагин роутера подключён после `vue()`.

## Что важно помнить

- `component: () => import(...)` — отдельный чанк на маршрут.
- Предзагрузка вероятных переходов и обработка ошибок чанков.
- Vue Router 5: файловая маршрутизация `vue-router/vite` + `vue-router/auto-routes` с типами.

## Мини-шпаргалка

- `component: () => import('@/pages/X.vue')`.
- `codeSplitting.groups` (Vite 8) / `manualChunks` (Vite ≤ 7) — группировка.
- `router.onError` — перезагрузка при ошибке чанка.
- `VueRouter()` из `vue-router/vite`, `routes` из `vue-router/auto-routes`, `definePage`.
