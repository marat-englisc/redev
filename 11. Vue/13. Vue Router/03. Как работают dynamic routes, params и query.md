# Как работают dynamic routes, params и query

> [!NOTE]
> **Динамические сегменты** пути объявляются с двоеточием: `/product/:id` совпадёт с `/product/42`, а значение будет в `route.params.id` (всегда **строка**). Модификаторы: `?` — необязательный (`/catalog/:category?`), `+` — один или больше повторяющихся сегментов, `*` — ноль или больше (`/docs/:path*` → массив), а в скобках — регулярное выражение (`/order/:id(\\d+)` — только цифры). **Params** — часть пути, идентифицируют **ресурс** (какой товар, какой пользователь) и обязательны для совпадения маршрута. **Query** — параметры после `?` (`?page=2&sort=price&tags=a&tags=b`), описывают **состояние представления**: фильтры, сортировку, страницу, поиск; доступны в `route.query` как строки или массивы строк, не влияют на совпадение маршрута. Важная особенность: при переходе между URL одного маршрута (`/product/1` → `/product/2`) **компонент переиспользуется**, а не пересоздаётся — данные нужно перезагружать через `watch(() => route.params.id, ...)` или `onBeforeRouteUpdate`. Состояние фильтров в query делает страницу «делимой» ссылкой и сохраняет его при «назад/вперёд».

## Вопрос

Как работают динамические маршруты, `params` и `query` во Vue Router?

## Params

```ts
{ path: '/product/:id', name: 'product', component: ProductPage }
{ path: '/users/:userId/orders/:orderId', name: 'user-order', component: OrderPage }
{ path: '/catalog/:category?', name: 'catalog', component: CatalogPage }
{ path: '/docs/:slug+', name: 'docs', component: DocsPage }          // /docs/a/b → ['a', 'b']
{ path: '/order/:id(\\d+)', name: 'order', component: OrderPage }     // только цифры
```

```ts
const route = useRoute();
route.params.id;          // '42' — строка
```

## Query

```ts
// /catalog?q=клавиатура&page=2&tags=wireless&tags=rgb
route.query.q;            // 'клавиатура'
route.query.page;         // '2' — строка
route.query.tags;         // ['wireless', 'rgb'] — массив (если ключ повторяется)
```

```ts
router.push({ name: 'catalog', query: { q: 'клавиатура', page: 2 } });
```

## Params или query

| | Params | Query |
| --- | --- | --- |
| Место | Путь `/product/42` | После `?` |
| Смысл | Идентификатор ресурса | Состояние отображения |
| Влияет на совпадение маршрута | Да | Нет |
| Обязательность | Да (кроме `?`) | Нет |
| Примеры | id, slug | фильтры, сортировка, страница, поиск |

## Переиспользование компонента

```ts
// ✗ данные загрузятся только при первом входе на /product/1
onMounted(() => load(route.params.id as string));

// ✓ реагировать на смену параметра
watch(() => route.params.id as string, (id) => load(id), { immediate: true });

// или guard компонента
onBeforeRouteUpdate(async (to) => {
  await load(to.params.id as string);
});

// или пересоздать компонент
<RouterView :key="$route.fullPath" />    <!-- проще, но теряется состояние и анимация -->
```

## Фильтры в query

```ts
// composables/useQueryParam.ts
export function useQueryNumber(key: string, fallback: number) {
  const route = useRoute();
  const router = useRouter();
  return computed({
    get: () => {
      const n = Number(route.query[key]);
      return Number.isFinite(n) && n > 0 ? n : fallback;
    },
    set: (value: number) => router.replace({ query: { ...route.query, [key]: value === fallback ? undefined : String(value) } }),
  });
}

const page = useQueryNumber('page', 1);
// <Pagination v-model="page" /> — URL обновляется, «назад» работает
```

`router.replace` — без новой записи в истории для каждого изменения фильтра; `push` — если каждое состояние должно быть шагом «назад».

## Валидация

```ts
// query и params — пользовательский ввод: приводить и проверять
const sort = computed(() => (['price', 'rating', 'new'].includes(route.query.sort as string) ? route.query.sort : 'new'));
```

```ts
// или в маршруте через props-функцию
props: (route) => ({ page: Math.max(1, Number(route.query.page) || 1) }),
```

## Частые ошибки

- Ожидать число в `route.params.id`/`route.query.page`.
- Загружать данные только в `onMounted` и не реагировать на смену params.
- Хранить фильтры только в сторе — ссылкой не поделиться, «назад» не работает.
- `router.push` на каждый ввод в поиске — история засоряется.
- Не учитывать, что `route.query.x` может быть массивом.

## Что важно помнить

- `:param` — часть пути (ресурс), `?query` — состояние отображения.
- Значения — строки (или массивы); приводите и валидируйте.
- Компонент переиспользуется при смене params — реагируйте `watch`/`onBeforeRouteUpdate`.

## Мини-шпаргалка

- `/:id`, `/:id?`, `/:path*`, `/:id(\\d+)`.
- `route.params.id`, `route.query.page`.
- `watch(() => route.params.id, load, { immediate: true })`.
- `router.replace({ query: { ...route.query, page } })`.
