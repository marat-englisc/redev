# Как работают nested routes, layouts и scrollBehavior

> [!NOTE]
> **Вложенные маршруты** (`children`) отражают вложенность UI: родительский маршрут рендерит компонент-оболочку (layout раздела — шапка, меню, вкладки) со своим **`<RouterView />`**, в который подставляется компонент дочернего маршрута. Пути детей указывают **без** ведущего `/` (относительно родителя); пустой путь `''` — страница по умолчанию для раздела. Родительский компонент не пересоздаётся при переходе между детьми — сохраняются его состояние и загруженные данные. Так строят личные кабинеты, админки, разделы с вкладками. **Именованные представления** (`components: { default, sidebar }` + `<RouterView name="sidebar" />`) позволяют рендерить несколько компонентов в разные места одного layout. **`scrollBehavior(to, from, savedPosition)`** управляет прокруткой после навигации: вернуть сохранённую позицию при «назад/вперёд», прокрутить к якорю (`{ el: to.hash, behavior: 'smooth' }`), наверх для новых страниц или оставить позицию при смене только query; можно вернуть промис, чтобы дождаться загрузки данных или анимации перехода.

## Вопрос

Как работают вложенные маршруты, layouts и `scrollBehavior` во Vue Router?

## Вложенные маршруты

```ts
{
  path: '/account',
  component: () => import('@/layouts/AccountLayout.vue'),
  meta: { requiresAuth: true },
  children: [
    { path: '', name: 'account', component: () => import('@/pages/account/Overview.vue') },          // /account
    { path: 'orders', name: 'account-orders', component: () => import('@/pages/account/Orders.vue') },   // /account/orders
    { path: 'orders/:id', name: 'account-order', component: () => import('@/pages/account/OrderDetails.vue'), props: true },
    { path: 'settings', name: 'account-settings', component: () => import('@/pages/account/Settings.vue') },
  ],
}
```

```vue
<!-- AccountLayout.vue -->
<template>
  <div class="account">
    <aside>
      <RouterLink :to="{ name: 'account' }" exact-active-class="active">Обзор</RouterLink>
      <RouterLink :to="{ name: 'account-orders' }">Заказы</RouterLink>
      <RouterLink :to="{ name: 'account-settings' }">Настройки</RouterLink>
    </aside>
    <main>
      <RouterView />          <!-- сюда рендерятся дети -->
    </main>
  </div>
</template>
```

## Layout для групп маршрутов

```ts
const routes = [
  {
    path: '/',
    component: DefaultLayout,             // шапка + футер
    children: [
      { path: '', name: 'home', component: HomePage },
      { path: 'catalog', name: 'catalog', component: CatalogPage },
    ],
  },
  {
    path: '/auth',
    component: BlankLayout,               // пустой layout
    children: [{ path: 'login', name: 'login', component: LoginPage }],
  },
];
```

Альтернатива — layout по `route.meta.layout` в `App.vue` (см. [layout component](<../06. Слоты/05. Как сделать компонент-обёртку и layout component.md>)).

## Именованные представления

```ts
{
  path: '/dashboard',
  components: {
    default: DashboardMain,
    sidebar: DashboardFilters,
    header: DashboardToolbar,
  },
}
```

```vue
<RouterView name="header" />
<RouterView name="sidebar" />
<RouterView />
```

## Анимации переходов

```vue
<RouterView v-slot="{ Component, route }">
  <Transition :name="route.meta.transition ?? 'fade'" mode="out-in">
    <component :is="Component" :key="route.path" />
  </Transition>
</RouterView>
```

## scrollBehavior

```ts
const router = createRouter({
  history: createWebHistory(),
  routes,
  scrollBehavior(to, from, savedPosition) {
    if (savedPosition) return savedPosition;                         // назад/вперёд — как было
    if (to.hash) return { el: to.hash, top: 80, behavior: 'smooth' }; // якорь с учётом фиксированной шапки
    if (to.path === from.path) return false;                         // сменилась только query — не прыгать
    return { top: 0 };
  },
});
```

```ts
// дождаться загрузки данных/анимации
scrollBehavior(to, from, saved) {
  return new Promise((resolve) => setTimeout(() => resolve(saved ?? { top: 0 }), 300));
}
```

`scrollBehavior` работает с прокруткой окна; для прокручиваемого контейнера позицию сохраняют вручную (или KeepAlive).

## Частые ошибки

- Ведущий `/` в пути ребёнка (`'/orders'`) — путь станет абсолютным.
- Забыть `<RouterView />` в родительском компоненте — дети не отрендерятся.
- Именованный родитель с пустым дочерним путём: `name` лучше давать дочернему `''`-маршруту, а не родителю.
- Не обработать якоря и «назад» в `scrollBehavior` — пользователь теряет позицию в длинном списке.

## Что важно помнить

- `children` + `<RouterView />` в родителе; пути детей — относительные.
- Родительский layout не пересоздаётся при переходах между детьми.
- `scrollBehavior` — сохранённая позиция, якоря, наверх.

## Мини-шпаргалка

- `{ path: '/x', component: Layout, children: [{ path: '', ... }, { path: 'y', ... }] }`.
- `components: { default, sidebar }` + `<RouterView name="sidebar" />`.
- `<RouterView v-slot="{ Component }">` для Transition/KeepAlive.
- `scrollBehavior: (to, from, saved) => saved ?? { top: 0 }`.
