# Что такое Virtual DOM

> [!NOTE]
> **Virtual DOM** — представление интерфейса в виде дерева обычных JavaScript-объектов (**VNode**: тип, props, дети). Render-функция компонента (в которую компилируется шаблон) при каждом обновлении возвращает **новое** дерево VNode; Vue сравнивает его со старым (**diff / patch**) и применяет к реальному DOM только необходимые операции. Плюсы: декларативность (вы описываете, *как должно выглядеть*, а не какие DOM-операции выполнить), минимизация дорогих DOM-операций, независимость от платформы (тот же механизм рендерит в строку для SSR или в нативные элементы). Virtual DOM **не быстрее** идеально написанных ручных DOM-операций — у него есть накладные расходы на создание и сравнение деревьев; его ценность в том, что он даёт **достаточно быструю** производительность при простом коде. Vue сокращает эти накладные расходы с помощью компилятора (см. [patch flags и block tree](<03. Как Vue оптимизирует Virtual DOM - компилятор, block tree и patch flags.md>)) и точной реактивности: перерисовывается только компонент, чьи зависимости изменились, а не всё дерево.

## Вопрос

Что такое Virtual DOM и как он используется во Vue?

## Цикл рендера

```text
реактивное состояние изменилось
  → эффект рендера компонента в очереди (nextTick)
  → render() создаёт новое дерево VNode
  → patch(старое, новое): сравнение
  → точечные операции с DOM (setAttribute, textContent, insertBefore...)
```

## Как выглядит VNode

```vue
<template>
  <button class="btn" :disabled="loading" @click="save">{{ label }}</button>
</template>
```

```js
// упрощённо — результат render()
{
  type: 'button',
  props: { class: 'btn', disabled: false, onClick: save },
  children: 'Сохранить',
}
```

```ts
// то же вручную через h()
import { h } from 'vue';
const vnode = h('button', { class: 'btn', disabled: loading.value, onClick: save }, label.value);
```

## Что делает patch

| Ситуация | Действие |
| --- | --- |
| Тот же тип узла | Обновить изменившиеся props и детей |
| Другой тип (`div` → `span`, другой компонент) | Удалить старое поддерево, создать новое |
| Список детей | Сопоставить по `key`, переместить/создать/удалить |
| Компонент | Обновить props; ребёнок перерисуется, только если props реально изменились |

## Гранулярность обновлений во Vue

```text
App
├── Header          ← не перерисовывается
├── ProductList     ← зависит от products → перерисуется
│   └── ProductCard ← перерисуется, только если изменился его prop
└── Footer          ← не перерисовывается
```

В отличие от подхода «перерисовать всё поддерево и сравнить», реактивность Vue знает, какой компонент зависит от изменившихся данных.

## Virtual DOM и альтернативы

| Подход | Пример | Идея |
| --- | --- | --- |
| Virtual DOM + компилятор | Vue 3 | Diff с подсказками компилятора |
| Virtual DOM без компилятора-оптимизатора | React | Diff всего поддерева компонента |
| Без Virtual DOM (fine-grained) | Solid, Svelte 5, Vue Vapor Mode (экспериментальный) | Прямые обновления DOM из реактивных эффектов |

## Частые ошибки

- Считать, что Virtual DOM всегда быстрее ручной работы с DOM.
- Думать, что изменение любого состояния перерисовывает всё приложение.
- Менять DOM вручную внутри области, которой управляет Vue — patch затрёт изменения или сломается.
- Использовать индекс как `key` в изменяемых списках — Vue переиспользует не те узлы.

## Что важно помнить

- VNode — JS-описание DOM; render создаёт дерево, patch применяет разницу.
- Ценность Virtual DOM — простота и предсказуемость при достаточной скорости.
- Vue перерисовывает только компоненты с изменившимися зависимостями.

## Мини-шпаргалка

- Шаблон → render() → VNode → patch → DOM.
- `h(type, props, children)`.
- `key` — сопоставление узлов списка.
- Другой тип узла — пересоздание поддерева.
