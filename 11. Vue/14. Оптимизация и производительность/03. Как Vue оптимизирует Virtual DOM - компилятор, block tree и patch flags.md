# Как Vue оптимизирует Virtual DOM - компилятор, block tree и patch flags

> [!NOTE]
> Vue 3 использует подход **compiler-informed Virtual DOM**: компилятор шаблонов заранее видит, какие части статичны, а какие зависят от данных, и передаёт runtime подсказки. **Кеширование статики (static hoisting)** — узлы и поддеревья без динамики создаются один раз и переиспользуются между рендерами, а большие статичные куски могут превращаться в одну строку HTML. **Patch flags** — числовая битовая маска на динамическом узле, говорящая, *что именно* в нём может измениться (`TEXT`, `CLASS`, `STYLE`, `PROPS` с перечнем ключей, `FULL_PROPS` и др.): runtime проверяет только это. **Block tree** — блок (корень шаблона, а также каждая ветка `v-if` и каждый `v-for`) собирает **плоский массив** своих динамических потомков (tree flattening); при обновлении обходится этот массив, а не всё дерево, поэтому стоимость patch зависит от числа *динамических* узлов, а не от размера шаблона. Также кешируются обработчики событий (`@click="count++"` не создаёт новую функцию каждый рендер, и ребёнок не получает «новый» prop). Эти оптимизации работают **только для шаблонов**: в рукописных render-функциях/JSX компилятор подсказок не добавляет.

## Вопрос

Как Vue 3 оптимизирует Virtual DOM: что такое patch flags, block tree и кеширование статики?

## Исходный шаблон

```vue
<template>
  <section>
    <h1>Каталог</h1>                       <!-- статично -->
    <p class="hint">Выберите товар</p>     <!-- статично -->
    <p :class="{ empty: !count }">{{ count }} товаров</p>   <!-- класс + текст -->
    <button @click="refresh">Обновить</button>             <!-- кешированный обработчик -->
  </section>
</template>
```

## Что генерирует компилятор (упрощённо)

```js
import { createElementVNode as _el, toDisplayString, normalizeClass, openBlock, createElementBlock } from 'vue';

export function render(_ctx, _cache) {
  return (openBlock(), createElementBlock('section', null, [
    _cache[0] || (_cache[0] = _el('h1', null, 'Каталог', -1 /* CACHED */)),
    _cache[1] || (_cache[1] = _el('p', { class: 'hint' }, 'Выберите товар', -1 /* CACHED */)),
    _el('p', { class: normalizeClass({ empty: !_ctx.count }) }, toDisplayString(_ctx.count) + ' товаров', 3 /* TEXT, CLASS */),
    _el('button', { onClick: _cache[2] || (_cache[2] = (...args) => _ctx.refresh(...args)) }, 'Обновить'),
  ]));
}
```

Посмотреть реальный вывод можно в [Vue Template Explorer](https://template-explorer.vuejs.org/).

## Patch flags

| Флаг | Значение | Что проверяется |
| --- | --- | --- |
| `TEXT` | 1 | Только текстовое содержимое |
| `CLASS` | 2 | Только `class` |
| `STYLE` | 4 | Только `style` |
| `PROPS` | 8 | Перечисленные динамические props |
| `FULL_PROPS` | 16 | Все props (динамические ключи `v-bind="obj"`) |
| `NEED_HYDRATION` | 32 | Нужна обработка при гидратации (например, обработчики событий) |
| `STABLE_FRAGMENT` | 64 | Порядок детей фрагмента не меняется |
| `KEYED_FRAGMENT` / `UNKEYED_FRAGMENT` | 128 / 256 | Дети `v-for` с ключами / без |
| `CACHED` | -1 | Закешированный статический узел — пропускается |

```js
// runtime (идея)
if (patchFlag & PatchFlags.CLASS) {
  if (oldProps.class !== newProps.class) el.className = newProps.class;
}
if (patchFlag & PatchFlags.TEXT) {
  if (n1.children !== n2.children) el.textContent = n2.children;
}
```

## Block tree

```vue
<template>
  <div>                                   <!-- блок: корень -->
    <Header />
    <main>
      <p>{{ user.name }}</p>              <!-- динамический потомок -->
      <div v-if="isAdmin">                <!-- новый блок -->
        <span>{{ role }}</span>
      </div>
      <ul>
        <li v-for="i in items" :key="i.id">{{ i.title }}</li>   <!-- блок фрагмента -->
      </ul>
    </main>
    <Footer />
  </div>
</template>
```

```text
Корневой блок.dynamicChildren = [p (TEXT), блок v-if, фрагмент v-for]
При смене user.name: обойти 3 элемента массива, а не всё дерево
```

`v-if`/`v-for` создают отдельные блоки, потому что меняют **структуру** — внутри блока структура стабильна, и плоский список корректен.

## Почему Vue 3 рендерит быстрее Vue 2

| Механизм | Эффект |
| --- | --- |
| Кеширование статики | Меньше создания VNode и сравнений |
| Patch flags | Проверяется только изменяемое |
| Block tree | Обход только динамических узлов |
| Кеш обработчиков | Нет лишних обновлений детей |
| Proxy-реактивность | Ленивые и точные зависимости (см. [Proxy, track и trigger](<../02. Реактивность/02. Как устроена реактивность на Proxy - track и trigger.md>)) |

## Гидратация

Те же подсказки ускоряют SSR-гидратацию: статичные узлы не проверяются, а обработчики навешиваются только там, где нужно.

## Частые ошибки

- Ожидать оптимизаций компилятора в render-функциях и JSX.
- Злоупотреблять `v-bind="obj"` с динамическими ключами — получается `FULL_PROPS`.
- Думать, что эти оптимизации заменяют правильную архитектуру (стабильные props, виртуализация).

## Что важно помнить

- Компилятор помечает динамику, runtime проверяет только её.
- Block tree — плоские массивы динамических узлов; `v-if`/`v-for` — границы блоков.
- Статика и обработчики кешируются; работает только для шаблонов.

## Мини-шпаргалка

- Patch flag: `TEXT`, `CLASS`, `STYLE`, `PROPS`, `FULL_PROPS`, `CACHED`.
- `openBlock()` + `createElementBlock()` — блок с `dynamicChildren`.
- `_cache[n]` — кеш статики и обработчиков.
- Template Explorer — посмотреть вывод компилятора.
