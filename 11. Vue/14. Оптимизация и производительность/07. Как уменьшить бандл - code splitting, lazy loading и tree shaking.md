# Как уменьшить бандл - code splitting, lazy loading и tree shaking

> [!NOTE]
> Размер JavaScript напрямую влияет на скорость загрузки SPA: код нужно скачать, распарсить и выполнить до появления интерфейса. **Code splitting** — разбиение бандла на чанки по динамическим `import()`: основной чанк содержит только то, что нужно для первого экрана. Во Vue основные точки разбиения — **страницы** (`component: () => import(...)` в роутере, см. [lazy loading маршрутов](<../13. Vue Router/07. Как делать lazy loading маршрутов и файловую маршрутизацию.md>)) и **тяжёлые компоненты**, которые показываются не сразу (редактор, графики, карта, модалки) — `defineAsyncComponent`, а с Vue 3.5 для SSR — ещё и **ленивая гидратация** (`hydrateOnVisible`, `hydrateOnIdle`). **Tree shaking** — удаление неиспользуемого кода на этапе сборки по статическому анализу ES-модулей: работает с именованными импортами (`import { debounce } from 'lodash-es'`) и пакетами без побочных эффектов (`"sideEffects": false`); Vue 3 спроектирован под tree shaking — неиспользуемые `Transition`, `KeepAlive`, `v-model` для разных типов не попадают в бандл. Также помогают: замена тяжёлых библиотек лёгкими (`date-fns`/`dayjs` вместо `moment`, нативный `Intl`), импорт компонентов UI-библиотек по требованию, удаление dev-кода через флаги сборки, анализ бандла (`rollup-plugin-visualizer`) и сжатие (brotli/gzip на сервере или CDN).

## Вопрос

Как уменьшить размер бандла во Vue-приложении: что такое code splitting, lazy loading компонентов и tree shaking?

## Асинхронные компоненты

```vue
<script setup lang="ts">
import { defineAsyncComponent } from 'vue';

const RichEditor = defineAsyncComponent(() => import('@/components/RichEditor.vue'));
const SalesChart = defineAsyncComponent({
  loader: () => import('@/components/SalesChart.vue'),
  loadingComponent: ChartSkeleton,
  errorComponent: LoadError,
  delay: 200,         // не мигать скелетоном при быстрой загрузке
  timeout: 10_000,
});

const showEditor = ref(false);
</script>

<template>
  <button @click="showEditor = true">Написать отзыв</button>
  <RichEditor v-if="showEditor" />        <!-- чанк загрузится по клику -->
  <SalesChart />
</template>
```

Подробнее — [динамические и асинхронные компоненты](<../03. Компоненты/10. Что такое динамические и асинхронные компоненты.md>).

## Ленивая гидратация (Vue 3.5+, SSR)

```ts
import { defineAsyncComponent, hydrateOnVisible, hydrateOnIdle } from 'vue';

const Comments = defineAsyncComponent({
  loader: () => import('./Comments.vue'),
  hydrate: hydrateOnVisible(),           // JS загрузится и гидратирует, когда блок попадёт во viewport
});
const Footer = defineAsyncComponent({ loader: () => import('./Footer.vue'), hydrate: hydrateOnIdle() });
```

## Динамический импорт библиотек

```ts
async function exportToExcel(rows: Row[]) {
  const { utils, writeFile } = await import('xlsx');      // тяжёлая библиотека только по клику
  const sheet = utils.json_to_sheet(rows);
  // ...
}
```

## Tree shaking

```ts
// ✗ весь lodash в бандле
import _ from 'lodash';
_.debounce(fn, 300);

// ✓ только нужная функция (ESM-сборка)
import { debounce } from 'lodash-es';

// ✗ импорт всей библиотеки иконок
import * as Icons from 'lucide-vue-next';
// ✓
import { Search, X } from 'lucide-vue-next';
```

Что мешает tree shaking:

| Причина | Пример |
| --- | --- |
| CommonJS-модули | `require`, старые пакеты без ESM |
| Побочные эффекты при импорте | Модуль меняет глобальные объекты |
| Импорт «всего» | `import * as`, `import lib from` с объектом-namespace |
| Глобальная регистрация всех компонентов UI-библиотеки | `app.use(UILib)` без автоимпорта |

## Анализ бандла

```ts
// vite.config.ts
import { visualizer } from 'rollup-plugin-visualizer';

export default defineConfig({
  plugins: [vue(), visualizer({ open: true, gzipSize: true, brotliSize: true })],
});
```

Что искать:

## Флаги сборки Vue

```ts
// vite.config.ts
define: {
  __VUE_OPTIONS_API__: false,              // если Options API не используется — меньше кода
  __VUE_PROD_DEVTOOLS__: false,
  __VUE_PROD_HYDRATION_MISMATCH_DETAILS__: false,
},
```

`__VUE_OPTIONS_API__: false` безопасно только если ни ваш код, ни зависимости не используют Options API.

## Другие приёмы

- Лёгкие альтернативы: `dayjs`/`date-fns` вместо `moment`, `Intl.NumberFormat`/`Intl.DateTimeFormat` вместо библиотек форматирования.
- Автоимпорт компонентов UI-библиотеки (`unplugin-vue-components`, `vite-plugin-vuetify`).
- Изображения в современных форматах (AVIF/WebP), `loading="lazy"`, правильные размеры.
- Сжатие brotli на сервере, долгий кеш для файлов с хешем в имени.

## Частые ошибки

- Ленивая загрузка всего подряд — водопад мелких запросов и мигание скелетонов.
- Ленивая загрузка компонента первого экрана — ухудшает LCP.
- Импорт CJS-сборок библиотек (`lodash` вместо `lodash-es`).
- Никогда не смотреть на состав бандла.

## Что важно помнить

- Разбивать по страницам и тяжёлым редко используемым компонентам.
- Tree shaking требует ESM и именованных импортов.
- Измерять бандл визуализатором до и после изменений.

## Мини-шпаргалка

- `() => import('...')` в роутере.
- `defineAsyncComponent({ loader, loadingComponent, delay })`.
- `hydrate: hydrateOnVisible()` — Vue 3.5+ SSR.
- `await import('lib')` по действию.
- `rollup-plugin-visualizer`.
