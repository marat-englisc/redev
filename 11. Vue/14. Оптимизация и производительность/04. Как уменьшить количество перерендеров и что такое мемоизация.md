# Как уменьшить количество перерендеров и что такое мемоизация

> [!NOTE]
> Компонент во Vue перерисовывается, когда меняются реактивные данные, прочитанные в его render, или **props**, которые он получил (сравнение поверхностное: новый объект/массив/функция — это «изменение», даже если содержимое то же). Главные приёмы: **стабильные props** — передавать ребёнку примитивы и уже вычисленные значения вместо данных, из которых каждый ребёнок что-то вычисляет (`:active="item.id === activeId"` вместо `:active-id="activeId"` — при смене выбора обновятся два элемента, а не все); **`computed`** — мемоизированный геттер: пересчитывается только при изменении зависимостей и возвращает закешированное значение (а если результат не изменился — с Vue 3.4 зависимые эффекты не срабатывают); **не создавать новые объекты и функции в шаблоне** для дочерних компонентов; **`shallowRef`/`markRaw`** для больших структур и сторонних объектов, где глубокая реактивность не нужна; **`v-once`** для статического контента и **`v-memo`** для пропуска обновления больших списков по условию; **разбивать** большие компоненты, чтобы изменение затрагивало меньшую часть; **KeepAlive** для дорогих страниц при переключении. **Мемоизация** — кеширование результата вычисления по входным данным; во Vue её дают `computed`, `v-memo`, `v-once`, кеш обработчиков компилятора, а для чистых функций — ручной кеш.

## Вопрос

Как уменьшить количество перерендеров во Vue и что такое мемоизация?

## Стабильные props

```vue
<!-- ✗ все 1000 ListItem обновятся при смене activeId -->
<ListItem v-for="item in list" :key="item.id" :item="item" :active-id="activeId" />

<!-- ✓ обновятся только прежний и новый активный -->
<ListItem v-for="item in list" :key="item.id" :item="item" :active="item.id === activeId" />
```

```vue
<!-- ✗ новый объект/массив на каждый рендер → ребёнок обновляется всегда -->
<Chart :options="{ responsive: true, legend: false }" :series="items.filter((i) => i.visible)" />

<!-- ✓ -->
<script setup lang="ts">
const chartOptions = { responsive: true, legend: false };           // константа вне реактивности
const visibleSeries = computed(() => items.value.filter((i) => i.visible));
</script>
<template>
  <Chart :options="chartOptions" :series="visibleSeries" />
</template>
```

## computed — мемоизированный геттер

```ts
const filtered = computed(() => products.value.filter((p) => p.title.toLowerCase().includes(query.value.toLowerCase())));
const total = computed(() => filtered.value.reduce((sum, p) => sum + p.price, 0));
```

| Метод в шаблоне `{{ getTotal() }}` | `computed` |
| --- | --- |
| Вызывается на каждый рендер компонента | Пересчитывается только при смене зависимостей |
| Нет кеша | Кеш до инвалидации |

```ts
// Vue 3.4+: если значение не изменилось, зависимые не обновляются
const isEven = computed(() => count.value % 2 === 0);   // count 2 → 4: isEven остался true → без перерендера
```

## Глубокая реактивность там, где она не нужна

```ts
const rows = shallowRef<Row[]>([]);            // 50 000 строк из API: реактивна только ссылка
rows.value = await api.getRows();              // заменяем целиком

const map = markRaw(new mapboxgl.Map({...}));  // сторонний объект — не оборачивать в Proxy
```

Подробнее — [shallowRef, markRaw и readonly](<../02. Реактивность/08. Что делают shallowRef, shallowReactive, markRaw, readonly и customRef.md>).

## v-once и v-memo

```vue
<footer v-once>{{ legalText }}</footer>          <!-- отрендерить один раз -->

<!-- пропустить обновление строки, если не изменились id выбранного и сам элемент -->
<div v-for="item in list" :key="item.id" v-memo="[item.id === selectedId, item.updatedAt]">
  <p>{{ item.title }}</p>
  <Badge :active="item.id === selectedId" />
</div>
```

`v-memo` — точечная оптимизация для больших списков (1000+); в массиве должны быть **все** значения, от которых зависит разметка, иначе обновление «потеряется». Подробнее — [v-once и v-memo](<../04. Шаблоны и директивы/06. Что делают v-once, v-memo, v-pre и v-cloak.md>).

## Разделение компонентов

```vue
<!-- ✗ ввод в поиске перерисовывает весь Dashboard с графиками -->
<Dashboard> <input v-model="search" /> <HeavyCharts /> </Dashboard>

<!-- ✓ состояние поиска внутри своего компонента -->
<SearchBox @search="onSearch" />
<HeavyCharts :data="chartsData" />
```

## Мемоизация чистых функций

```ts
function memoize<A, R>(fn: (arg: A) => R) {
  const cache = new Map<A, R>();
  return (arg: A) => {
    if (!cache.has(arg)) cache.set(arg, fn(arg));
    return cache.get(arg)!;
  };
}

const formatPrice = memoize((cents: number) => new Intl.NumberFormat('ru-RU', { style: 'currency', currency: 'RUB' }).format(cents / 100));
```

Кеш без ограничения размера растёт бесконечно — для широких входов используйте LRU.

## Как найти лишние перерендеры

- Vue DevTools → Performance / Timeline: какие компоненты и как часто обновляются.
- `onRenderTriggered((e) => console.log(e))` в dev — какая зависимость вызвала перерендер.
- Chrome DevTools Performance — длинные задачи и время скриптов.

## Частые ошибки

- Методы в шаблоне для тяжёлых вычислений вместо `computed`.
- Литералы объектов/стрелочные функции в props дочерних компонентов в больших списках.
- `v-memo` с неполным списком зависимостей — устаревший UI.
- `deep: true` watch на огромных структурах.
- Оптимизировать то, что не является узким местом.

## Что важно помнить

- Перерендер — из-за прочитанных реактивных данных или изменившихся props.
- Стабильные props, `computed`, `shallowRef`/`markRaw`, разбиение компонентов.
- `v-once`/`v-memo` — точечные инструменты после профилирования.

## Мини-шпаргалка

- `:active="item.id === activeId"` вместо `:active-id`.
- `computed` вместо методов в шаблоне.
- `shallowRef` для больших данных, `markRaw` для сторонних объектов.
- `v-memo="[deps]"`, `v-once`.
- `onRenderTriggered` — отладка причин.
