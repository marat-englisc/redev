# Как оптимизировать большие таблицы и списки - виртуализация

> [!NOTE]
> Тысячи строк в DOM — это долгий первый рендер, тысячи экземпляров компонентов в памяти и медленный скролл. Стратегии по возрастанию сложности: **не показывать всё сразу** — серверная **пагинация**, «Показать ещё» или **бесконечная прокрутка** (`IntersectionObserver`), фильтрация и сортировка на сервере; **облегчить строку** — меньше вложенных компонентов (обычная разметка вместо компонента-обёртки на каждую ячейку), стабильные props, `shallowRef` для данных, `v-memo` для строк; **виртуализация (windowing)** — рендерить только видимые строки плюс небольшой запас (overscan), а остальное пространство заполнять отступами, чтобы полоса прокрутки соответствовала полному списку. При 100 000 строк в DOM находится ~30–50 элементов, и при скролле они переиспользуются. Готовые решения: `useVirtualList` из VueUse (фиксированная высота), `@tanstack/vue-virtual` (динамическая высота, горизонтальная и сеточная виртуализация, таблицы вместе с `@tanstack/vue-table`), `vue-virtual-scroller`, `v-virtual-scroll`/`v-data-table-virtual` во Vuetify. Ограничения виртуализации: поиск по странице Ctrl+F находит только отрендеренное, сложнее доступность и печать, динамические высоты требуют измерения.

## Вопрос

Как оптимизировать большие таблицы и списки во Vue и что такое виртуализация?

## Выбор стратегии

| Объём | Стратегия |
| --- | --- |
| До нескольких сотен строк | Обычный `v-for` с правильным `key` |
| Тысячи, нужен поиск и навигация по страницам | Серверная пагинация |
| Лента, каталог | Бесконечная прокрутка + серверная подгрузка |
| Тысячи–сотни тысяч на одном экране (логи, таблицы, чаты) | Виртуализация |

## Идея виртуализации

```text
Видимая область (600px, строка 40px → 15 строк)
┌──────────────────────────┐
│ padding-top: 40 000px     │  ← строки 0–999 не в DOM
├──────────────────────────┤
│ строки 1000–1019 (DOM)   │  ← видимые + overscan
├──────────────────────────┤
│ padding-bottom: 3 959 200px│ ← остальные не в DOM
└──────────────────────────┘
```

## useVirtualList (VueUse)

```vue
<script setup lang="ts">
import { useVirtualList } from '@vueuse/core';

const rows = shallowRef<LogRow[]>([]);
const { list, containerProps, wrapperProps } = useVirtualList(rows, { itemHeight: 40, overscan: 10 });
</script>

<template>
  <div v-bind="containerProps" class="h-[600px] overflow-auto">
    <div v-bind="wrapperProps">
      <div v-for="{ data, index } in list" :key="data.id" class="h-10">
        {{ index }} — {{ data.message }}
      </div>
    </div>
  </div>
</template>
```

## TanStack Virtual — динамическая высота

```vue
<script setup lang="ts">
import { useVirtualizer } from '@tanstack/vue-virtual';

const parentRef = useTemplateRef<HTMLElement>('parent');
const virtualizer = useVirtualizer(computed(() => ({
  count: messages.value.length,
  getScrollElement: () => parentRef.value,
  estimateSize: () => 60,
  overscan: 8,
})));
</script>

<template>
  <div ref="parent" class="h-[600px] overflow-auto">
    <div :style="{ height: `${virtualizer.getTotalSize()}px`, position: 'relative' }">
      <div
        v-for="row in virtualizer.getVirtualItems()"
        :key="String(row.key)"
        :ref="(el) => el && virtualizer.measureElement(el as Element)"
        :data-index="row.index"
        :style="{ position: 'absolute', top: 0, left: 0, width: '100%', transform: `translateY(${row.start}px)` }"
      >
        <MessageItem :message="messages[row.index]" />
      </div>
    </div>
  </div>
</template>
```

## Бесконечная прокрутка

```vue
<script setup lang="ts">
const sentinel = useTemplateRef<HTMLElement>('sentinel');

useIntersectionObserver(sentinel, ([entry]) => {
  if (entry?.isIntersecting && !loading.value && hasMore.value) loadNextPage();
}, { rootMargin: '300px' });
</script>

<template>
  <ProductCard v-for="p in products" :key="p.id" :product="p" />
  <div ref="sentinel" aria-hidden="true" />
</template>
```

Бесконечная прокрутка без виртуализации всё равно накапливает DOM — для очень длинных лент совмещают оба подхода.

## Облегчение строк таблицы

```vue
<!-- ✗ компонент на каждую ячейку: 1000 строк × 10 ячеек = 10 000 экземпляров -->
<TableCell v-for="col in columns" :key="col.key" :value="row[col.key]" />

<!-- ✓ разметка в строке, компонент только там, где нужна логика -->
<td v-for="col in columns" :key="col.key">{{ format(row[col.key], col) }}</td>
```

```ts
const rows = shallowRef<Row[]>([]);                 // не оборачивать 50 000 объектов в Proxy
rows.value = Object.freeze(await api.getRows());    // данные только для чтения
```

## Частые ошибки

- Загружать на клиент 100 000 строк, когда пользователю нужны первые 50.
- Виртуализация без фиксированной высоты контейнера (`overflow: auto` + высота).
- Индекс вместо стабильного `key`.
- Глубокая реактивность для огромных массивов только для отображения.
- Забыть о доступности и Ctrl+F — для документов и страниц, которые ищут, лучше пагинация.

## Что важно помнить

- Сначала уменьшить объём данных (пагинация, сервер), потом облегчить строки, потом виртуализировать.
- Виртуализация рендерит только видимое + overscan.
- `useVirtualList` — фиксированная высота, TanStack Virtual — динамическая и таблицы.

## Мини-шпаргалка

- `useVirtualList(rows, { itemHeight, overscan })`.
- `useVirtualizer({ count, getScrollElement, estimateSize })`.
- `useIntersectionObserver` — бесконечная прокрутка.
- `shallowRef` + `Object.freeze` для данных таблицы.
