# Что такое декларативный рендеринг и как Vue обновляет DOM

> [!NOTE]
> **Декларативный рендеринг** означает, что мы описываем, **как должен выглядеть UI при данном состоянии**, а не **какие шаги** нужно выполнить с DOM. Шаблон Vue компилируется в **render-функцию**, которая возвращает дерево **VNode** (виртуальный DOM). При первом рендере Vue создаёт по нему реальный DOM; при этом реактивная система запоминает, какие данные прочитал рендер каждого компонента. Когда эти данные меняются, Vue **планирует** повторный рендер затронутого компонента (обновления группируются и выполняются асинхронно, в одной микрозадаче), получает новое VNode-дерево и **патчит** DOM — меняет только отличающиеся узлы. Компилятор шаблонов помогает: статические части поднимаются и не сравниваются, а динамические узлы помечаются **patch flags**, поэтому сравнение затрагивает только то, что может измениться. Итог — меньше кода, меньше ошибок рассинхронизации и точечные обновления DOM.

## Вопрос

Что такое декларативный рендеринг и как Vue обновляет DOM при изменении данных?

## Императивно и декларативно

```js
// императивно: сами синхронизируем DOM с данными
let count = 0;
const btn = document.querySelector('#btn');
btn.addEventListener('click', () => {
  count++;
  btn.textContent = `Нажато: ${count}`;
  document.querySelector('#hint').hidden = count < 5;
});
```

```vue
<!-- декларативно: описываем результат, синхронизацию делает Vue -->
<script setup>
import { ref } from 'vue';
const count = ref(0);
</script>

<template>
  <button @click="count++">Нажато: {{ count }}</button>
  <p v-if="count >= 5">Хватит кликать</p>
</template>
```

## Конвейер

```text
template ──компилятор──► render-функция ──► VNode-дерево ──mount──► DOM
                                                ▲
состояние изменилось ──► запланировать render ──┘──► новое дерево ──diff/patch──► точечные изменения DOM
```

## Что видит компилятор

```vue
<template>
  <div class="card">
    <h2>Профиль</h2>                         <!-- статично: вынесено, не сравнивается -->
    <p :class="{ active: isActive }">{{ name }}</p>   <!-- patch flags: CLASS | TEXT -->
  </div>
</template>
```

При изменении `name` Vue сравнит только текст этого `<p>`, а не весь компонент. Подробнее — [как Vue оптимизирует Virtual DOM](<../14. Оптимизация и производительность/03. Как Vue оптимизирует Virtual DOM - компилятор, block tree и patch flags.md>).

## Асинхронные обновления и nextTick

```ts
count.value++;
count.value++;
count.value++;
// DOM обновится один раз, после текущей синхронной работы

await nextTick();
console.log(btn.textContent);   // уже обновлённый DOM
```

## Связь данных и UI

| Направление | Механизм |
| --- | --- |
| Данные → UI | Интерполяция `{{ }}`, `v-bind`, `v-if`, `v-for` |
| UI → данные | События `v-on`, `v-model` |
| Производные данные | `computed` |
| Побочные эффекты | `watch`, `watchEffect` |

## Частые ошибки

- Менять DOM вручную рядом с реактивным шаблоном — Vue перезапишет изменения при следующем патче.
- Ожидать, что DOM обновится синхронно сразу после изменения данных.
- Сложная логика прямо в шаблоне вместо `computed`.

## Что важно помнить

- Шаблон → render-функция → VNode → патч DOM.
- Обновления группируются и применяются асинхронно; `nextTick` ждёт применения.
- Компилятор помечает динамические части — Vue сравнивает только их.

## Мини-шпаргалка

- UI = f(state).
- `{{ }}` / `:attr` — данные в UI, `@event` / `v-model` — UI в данные.
- `await nextTick()` — после обновления DOM.
- Логику шаблона — в `computed`.
