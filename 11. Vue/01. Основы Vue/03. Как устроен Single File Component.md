# Как устроен Single File Component

> [!NOTE]
> **Single File Component (SFC)** — файл `.vue`, объединяющий в одном месте **шаблон** (`<template>`), **логику** (`<script setup>` и при необходимости обычный `<script>`) и **стили** (`<style>`, часто `scoped` или `module`). Сборщик (плагин `@vitejs/plugin-vue`) компилирует SFC в JavaScript-модуль: шаблон — в render-функцию, `<script setup>` — в функцию `setup()` компонента, стили — в CSS с уникальными атрибутами для `scoped`. В `<script setup>` всё, что объявлено на верхнем уровне (переменные, функции, импортированные компоненты), автоматически доступно в шаблоне, а макросы компилятора `defineProps`, `defineEmits`, `defineModel`, `defineExpose`, `defineSlots`, `defineOptions` не требуют импорта. `lang="ts"` включает TypeScript, `<style scoped>` изолирует стили от других компонентов, `v-bind()` в CSS связывает стили с реактивным состоянием. Разделение по технологиям (HTML/JS/CSS в разных файлах) заменяется разделением по **ответственности** — компонент как единица.

## Вопрос

Как устроен SFC-файл `.vue` и что можно в нём использовать?

## Структура

```vue
<script setup lang="ts">
import { computed } from 'vue';
import BaseAvatar from './BaseAvatar.vue';     // доступен в шаблоне без регистрации

const props = defineProps<{ name: string; avatarUrl?: string; online?: boolean }>();
const emit = defineEmits<{ select: [name: string] }>();

const initials = computed(() => props.name.split(' ').map((p) => p[0]).join(''));
const statusColor = computed(() => (props.online ? '#16a34a' : '#9ca3af'));
</script>

<template>
  <button class="user" @click="emit('select', name)">
    <BaseAvatar :src="avatarUrl" :fallback="initials" />
    <span>{{ name }}</span>
  </button>
</template>

<style scoped>
.user {
  display: flex;
  gap: 8px;
  border-left: 3px solid v-bind(statusColor);   /* реактивное значение в CSS */
}
</style>
```

## Блоки

| Блок | Назначение |
| --- | --- |
| `<template>` | Разметка; один на файл; может иметь несколько корневых узлов |
| `<script setup>` | Логика Composition API, выполняется для каждого экземпляра |
| `<script>` | Обычный модуль: выполняется один раз; для `export` типов и опций |
| `<style>` | Стили; `scoped`, `module`, `lang="scss"` |
| Свои блоки (`<i18n>`) | Обрабатываются плагинами сборщика |

## Scoped-стили

```vue
<style scoped>
.title { color: red; }          /* → .title[data-v-7a3f1c] */

.card :deep(.inner) { gap: 4px; }    /* стиль для дочернего компонента */
:slotted(p) { margin: 0; }           /* стиль для содержимого слота */
:global(.dark) .title { color: white; }
</style>
```

Корневой элемент дочернего компонента получает атрибут родителя, поэтому родитель может стилизовать его корень даже со `scoped`.

## CSS Modules

```vue
<template>
  <p :class="$style.error">Ошибка</p>
</template>

<style module>
.error { color: crimson; }
</style>
```

## script setup и обычный script вместе

```vue
<script lang="ts">
export interface User { id: string; name: string }    // экспорт типа для других модулей
</script>

<script setup lang="ts">
defineOptions({ name: 'UserCard', inheritAttrs: false });
const props = defineProps<{ user: User }>();
</script>
```

## Частые ошибки

- Импортировать `defineProps` из `vue` — это макрос компилятора, импорт не нужен.
- Ожидать, что `scoped` стили применятся к внутренним элементам дочернего компонента без `:deep()`.
- Использовать `export default` внутри `<script setup>`.
- Тяжёлая логика в шаблоне вместо `computed` в скрипте.

## Что важно помнить

- SFC = template + script setup + style, компилируется сборщиком.
- Верхний уровень `<script setup>` доступен в шаблоне.
- `scoped`, `:deep()`, `:slotted()`, `v-bind()` в CSS — инструменты стилизации.

## Мини-шпаргалка

- `<script setup lang="ts">`.
- `defineProps`, `defineEmits`, `defineModel`, `defineExpose`, `defineSlots`, `defineOptions` — без импорта.
- `<style scoped>` + `:deep()`.
- `<style module>` → `$style`.
