# Чем Options API отличается от Composition API

> [!NOTE]
> Это два стиля описания компонента поверх одной реактивной системы. **Options API** группирует код по **типу опции**: `data()` — состояние, `computed`, `methods`, `watch`, хуки (`mounted`), доступ через `this`. **Composition API** группирует код по **функциональности**: внутри `setup()` (обычно `<script setup>`) состояние создаётся `ref`/`reactive`, производные — `computed`, эффекты — `watch`, хуки — `onMounted`, а связанную логику выносят в **composables** — обычные функции `useXxx()`. Преимущества Composition API: логика одной фичи живёт вместе, её легко переиспользовать без конфликтов и неявности mixins, отличная типизация TypeScript, лучше минифицируется. Options API проще для новичков и небольших компонентов. Оба стиля поддерживаются и могут сосуществовать (даже в одном компоненте через `setup()` внутри Options), но для новых проектов команда Vue рекомендует Composition API с `<script setup>`.

## Вопрос

Чем Options API отличается от Composition API и что выбрать?

## Один компонент в двух стилях

```vue
<!-- Options API -->
<script>
export default {
  props: { userId: { type: String, required: true } },
  data() {
    return { user: null, loading: false };
  },
  computed: {
    displayName() { return this.user?.name ?? 'Гость'; },
  },
  watch: {
    userId: { handler: 'load', immediate: true },
  },
  methods: {
    async load() {
      this.loading = true;
      this.user = await fetchUser(this.userId);
      this.loading = false;
    },
  },
};
</script>
```

```vue
<!-- Composition API -->
<script setup lang="ts">
import { ref, computed, watch } from 'vue';

const props = defineProps<{ userId: string }>();

const user = ref<User | null>(null);
const loading = ref(false);
const displayName = computed(() => user.value?.name ?? 'Гость');

async function load() {
  loading.value = true;
  user.value = await fetchUser(props.userId);
  loading.value = false;
}

watch(() => props.userId, load, { immediate: true });
</script>
```

## Вынос логики в composable

```ts
// composables/useUser.ts
export function useUser(userId: MaybeRefOrGetter<string>) {
  const user = ref<User | null>(null);
  const loading = ref(false);

  watchEffect(async () => {
    loading.value = true;
    user.value = await fetchUser(toValue(userId));
    loading.value = false;
  });

  return { user, loading };
}

// в компоненте
const { user, loading } = useUser(() => props.userId);
```

В Options API для этого использовали mixins — с конфликтами имён и неясным источником свойств. Подробнее — [composables](<../08. Composition API и composables/02. Что такое composables и как их писать.md>).

## Сравнение

| | Options API | Composition API |
| --- | --- | --- |
| Организация кода | По типу опции | По функциональности |
| Доступ к состоянию | `this.x` | Переменные, `x.value` у ref |
| Переиспользование | Mixins (проблемные) | Composables |
| TypeScript | Хуже выводит типы | Отличная поддержка |
| Большие компоненты | Логика фичи разбросана по опциям | Логика фичи рядом |
| Порог входа | Ниже | Нужно понимать ref/reactive |

## Смешивание

```vue
<script>
import { ref } from 'vue';

export default {
  setup() {
    const counter = ref(0);          // Composition API внутри Options
    return { counter };
  },
  mounted() {
    console.log(this.counter);       // доступно через this
  },
};
</script>
```

Полезно при постепенной миграции; в новом коде лучше один стиль.

## Частые ошибки

- Забывать `.value` у `ref` в скрипте (в шаблоне ref разворачивается автоматически).
- Переносить «мышление опциями» в Composition API — один гигантский `setup` без composables.
- Деструктурировать `reactive`-объект и терять реактивность.
- Использовать стрелочные функции в `methods` Options API — `this` не будет экземпляром.

## Что важно помнить

- Оба API работают поверх одной реактивности.
- Composition API — группировка по фичам, composables, TypeScript.
- Для новых проектов — `<script setup>`.

## Мини-шпаргалка

- Options: `data`, `computed`, `methods`, `watch`, `mounted`, `this`.
- Composition: `ref`, `reactive`, `computed`, `watch`, `onMounted`, composables.
- `<script setup>` — краткий синтаксис Composition API.
- Mixins → composables.
