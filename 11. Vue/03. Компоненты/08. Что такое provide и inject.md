# Что такое provide и inject

> [!NOTE]
> `provide(key, value)` в компоненте-предке делает значение доступным **всем потомкам** на любой глубине, а `inject(key, defaultValue)` в потомке получает его — без пробрасывания props через промежуточные уровни (**prop drilling**). Это механизм **зависимостей по дереву**: значение ищется у ближайшего предка, который его предоставил, поэтому разные поддеревья могут получать разные значения (вложенные формы, темы, группы радиокнопок). Предоставлять можно что угодно: реактивные `ref`/`reactive` (тогда потомки видят изменения), функции, экземпляры сервисов. Для типобезопасности ключи создают как **`InjectionKey<T>`** (`Symbol`), а оборачивают пару в composable (`provideTabs()` / `useTabs()`), чтобы бросать понятную ошибку, если провайдера нет. Хорошая практика — отдавать наружу `readonly`-состояние и функции изменения, чтобы потомки не мутировали данные напрямую. На уровне всего приложения то же делает `app.provide` (так работают плагины). Для глобального состояния приложения обычно удобнее Pinia, а provide/inject — для **контекста поддерева** и составных компонентов.

## Вопрос

Что такое provide/inject во Vue и когда его использовать вместо props и стора?

## Составной компонент: Tabs

```ts
// tabs/context.ts
import type { InjectionKey, Ref } from 'vue';

interface TabsContext {
  active: Readonly<Ref<string>>;
  select: (id: string) => void;
  register: (id: string, title: string) => void;
}

export const TabsKey: InjectionKey<TabsContext> = Symbol('Tabs');

export function useTabs() {
  const ctx = inject(TabsKey);
  if (!ctx) throw new Error('<TabPanel> must be used inside <Tabs>');
  return ctx;
}
```

```vue
<!-- Tabs.vue -->
<script setup lang="ts">
const active = defineModel<string>({ required: true });
const titles = ref<{ id: string; title: string }[]>([]);

provide(TabsKey, {
  active: readonly(active),
  select: (id) => (active.value = id),
  register: (id, title) => titles.value.push({ id, title }),
});
</script>

<template>
  <nav>
    <button v-for="t in titles" :key="t.id" :class="{ on: t.id === active }" @click="active = t.id">
      {{ t.title }}
    </button>
  </nav>
  <slot />
</template>
```

```vue
<!-- TabPanel.vue -->
<script setup lang="ts">
const props = defineProps<{ id: string; title: string }>();
const { active, register } = useTabs();
register(props.id, props.title);
</script>

<template>
  <section v-if="active === id"><slot /></section>
</template>
```

```vue
<Tabs v-model="tab">
  <TabPanel id="info" title="Описание">...</TabPanel>
  <TabPanel id="reviews" title="Отзывы">...</TabPanel>
</Tabs>
```

## Реактивность

```ts
// предок
const theme = ref<'light' | 'dark'>('light');
provide('theme', theme);                     // ✓ потомки видят изменения
provide('themeValue', theme.value);          // ✗ передано значение, не обновится

// потомок
const theme = inject<Ref<'light' | 'dark'>>('theme', ref('light'));
```

## Значения по умолчанию

```ts
const config = inject(ConfigKey, { pageSize: 20 });          // объект по умолчанию
const service = inject(ApiKey, () => createApi(), true);     // фабрика (третий аргумент — treatDefaultAsFactory)
```

## Уровень приложения

```ts
app.provide(I18nKey, i18n);          // доступно во всех компонентах
// и вне компонентов (роутер-гарды, сторы) — app.runWithContext(() => inject(I18nKey))
```

## Props, provide/inject или стор

| Ситуация | Инструмент |
| --- | --- |
| Родитель → прямой ребёнок | Props |
| Контекст составного компонента (Tabs, Form, Accordion) | Provide / inject |
| Данные глубоко в поддереве, разные для разных поддеревьев | Provide / inject |
| Глобальное состояние приложения (пользователь, корзина) | Pinia |
| Сервис/зависимость для всего приложения | `app.provide` / плагин |

## Частые ошибки

- Передавать `ref.value` вместо ref — потеря реактивности.
- Строковые ключи без типов — опечатки и `unknown`.
- Мутировать полученное состояние в потомках вместо вызова функций провайдера.
- `inject` вне `setup` (в обработчике события или после `await`) — не работает.
- Использовать provide/inject как глобальный стор для всего приложения.

## Что важно помнить

- `provide` у предка → `inject` у любого потомка, ближайший провайдер побеждает.
- Предоставляйте ref/reactive (лучше `readonly`) и функции изменения.
- `InjectionKey` + composable `useXxx()` с проверкой наличия провайдера.

## Мини-шпаргалка

- `provide(Key, value)`, `inject(Key, default)`.
- `const Key: InjectionKey<T> = Symbol()`.
- `readonly(state)` + методы.
- `app.provide(...)`, `app.runWithContext(...)`.
