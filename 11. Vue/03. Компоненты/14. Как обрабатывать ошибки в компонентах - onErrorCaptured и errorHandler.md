# Как обрабатывать ошибки в компонентах - onErrorCaptured и errorHandler

> [!NOTE]
> Vue перехватывает ошибки, возникшие в рендере, хуках жизненного цикла, `setup`, наблюдателях (`watch`), обработчиках событий из шаблона и асинхронных компонентах, и передаёт их вверх по дереву. Хук **`onErrorCaptured((err, instance, info) => ...)`** в предке получает ошибки **потомков**: можно показать запасной UI (паттерн **error boundary**), отправить ошибку в мониторинг и вернуть `false`, чтобы остановить дальнейшее распространение. Глобальный **`app.config.errorHandler`** получает все необработанные ошибки приложения — точка подключения Sentry и аналогов (в проде без него ошибки только логируются в консоль). Важно понимать, что **не** перехватывается: ошибки в `setTimeout`, промисах без `await` внутри обработчиков, сторонних колбэках вне Vue — для них нужны `try/catch` и глобальные `window.onerror` / `unhandledrejection`. Ошибки, которые пользователь может исправить (валидация, сеть), обрабатывают локально в UI, а неожиданные — показывают безопасным запасным экраном и логируют.

## Вопрос

Как обрабатывать ошибки в компонентах Vue и сделать error boundary?

## Error boundary

```vue
<!-- ErrorBoundary.vue -->
<script setup lang="ts">
const props = defineProps<{ name: string }>();
const error = ref<Error | null>(null);

onErrorCaptured((err, instance, info) => {
  error.value = err as Error;
  reportError(err, { boundary: props.name, info });   // info: 'render function', 'setup function', ...
  return false;                                        // не передавать выше
});

function reset() {
  error.value = null;
}
</script>

<template>
  <slot v-if="!error" />
  <div v-else class="error" role="alert">
    <p>Не удалось загрузить блок «{{ name }}».</p>
    <button @click="reset">Повторить</button>
  </div>
</template>
```

```vue
<ErrorBoundary name="Рекомендации">
  <RecommendationsWidget />       <!-- ошибка внутри не уронит всю страницу -->
</ErrorBoundary>
```

## Глобальный обработчик

```ts
app.config.errorHandler = (err, instance, info) => {
  Sentry.captureException(err, { extra: { info, component: instance?.$options.name } });
};

app.config.warnHandler = (msg, instance, trace) => {
  // только в dev: предупреждения Vue
};
```

```ts
// то, что Vue не видит
window.addEventListener('unhandledrejection', (e) => report(e.reason));
window.addEventListener('error', (e) => report(e.error));
```

## Что перехватывается

| Источник ошибки | `onErrorCaptured` / `errorHandler` |
| --- | --- |
| Рендер, шаблон | Да |
| `setup`, хуки жизненного цикла | Да |
| `watch` / `watchEffect` колбэки | Да |
| Обработчик `@click` из шаблона (в том числе async, если промис возвращён) | Да |
| Асинхронный компонент, async setup | Да |
| `setTimeout`, `setInterval` | Нет |
| Промис, не возвращённый из обработчика (`.then` без await) | Нет |
| Колбэки сторонних библиотек | Нет |

```ts
// ✗ ошибка уйдёт мимо Vue
function onClick() {
  api.save().then(() => { throw new Error('x'); });
}

// ✓ промис возвращён/ожидается
async function onClick() {
  await api.save();
}
```

## Ожидаемые ошибки — в UI

```ts
const error = ref<string | null>(null);

async function submit() {
  error.value = null;
  try {
    await api.createOrder(form);
  } catch (e) {
    error.value = e instanceof ApiError && e.status === 422 ? e.message : 'Не удалось оформить заказ';
  }
}
```

## Частые ошибки

- Нет `errorHandler` в проде — ошибки пользователей никто не видит.
- Глотать все ошибки (`return false` без показа UI и логирования).
- Ожидать перехвата ошибок из таймеров и не-awaited промисов.
- Показывать пользователю стек ошибки.
- Error boundary вокруг всего приложения вместо изоляции независимых блоков.

## Что важно помнить

- `onErrorCaptured` — error boundary для поддерева; `app.config.errorHandler` — глобальный перехват.
- Таймеры и «висящие» промисы — вне механизма Vue.
- Ожидаемые ошибки — локально в UI, неожиданные — запасной экран + мониторинг.

## Мини-шпаргалка

- `onErrorCaptured((err, inst, info) => { ...; return false })`.
- `app.config.errorHandler = (err, inst, info) => {}`.
- `window.addEventListener('unhandledrejection', ...)`.
- `try/catch` вокруг `await` в действиях пользователя.
