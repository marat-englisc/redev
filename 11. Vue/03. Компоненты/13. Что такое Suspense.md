# Что такое Suspense

> [!NOTE]
> `<Suspense>` — встроенный компонент (пока помечен как **экспериментальный**), который координирует **асинхронные зависимости** в своём поддереве и показывает **запасной контент** (`#fallback`), пока все они не разрешатся, после чего рендерит основной слот (`#default`). Асинхронными зависимостями считаются компоненты с **async setup** — в `<script setup>` это любой компонент с `await` на верхнем уровне — и асинхронные компоненты (`defineAsyncComponent`), если они не отказались от этого опцией `suspensible: false`. Вместо того чтобы каждый компонент показывал свой спиннер, Suspense даёт один общий: страница появляется целиком, когда готовы все её части. События `@pending`, `@resolve`, `@fallback` и опция `timeout` позволяют управлять поведением при повторных загрузках. Ошибки асинхронного setup перехватывают через `onErrorCaptured` в родителе или `errorComponent`. Suspense часто комбинируют с `RouterView`, `KeepAlive` и `Transition`; в Nuxt эту роль во многом берут на себя `useFetch`/`useAsyncData`.

## Вопрос

Что такое `<Suspense>` во Vue и как с ним работать?

## Компонент с async setup

```vue
<!-- UserProfile.vue -->
<script setup lang="ts">
const props = defineProps<{ id: string }>();
const user = await api.getUser(props.id);            // top-level await → компонент асинхронный
const orders = await api.getOrders(props.id);
</script>

<template>
  <h2>{{ user.name }}</h2>
  <OrderList :orders="orders" />
</template>
```

```vue
<!-- родитель -->
<template>
  <Suspense>
    <UserProfile :id="userId" />
    <template #fallback>
      <ProfileSkeleton />
    </template>
  </Suspense>
</template>
```

Без `<Suspense>` выше по дереву компонент с top-level `await` не отрендерится (Vue выдаст предупреждение).

## Несколько зависимостей

```vue
<Suspense>
  <div class="dashboard">
    <RevenueWidget />      <!-- async setup -->
    <UsersWidget />        <!-- async setup -->
    <ActivityFeed />       <!-- defineAsyncComponent -->
  </div>
  <template #fallback><DashboardSkeleton /></template>
</Suspense>
```

Скелетон показывается, пока не готовы **все** три.

## Повторные загрузки

```vue
<Suspense :timeout="300" @pending="loading = true" @resolve="loading = false">
  <component :is="currentView" :key="routeKey" />
  <template #fallback><Spinner /></template>
</Suspense>
```

При смене корневого компонента Suspense снова переходит в состояние ожидания; с `timeout` он сначала продолжает показывать **старый** контент и переключается на fallback, только если загрузка дольше таймаута — меньше мерцания.

## Ошибки

```vue
<script setup lang="ts">
const error = ref<Error | null>(null);
onErrorCaptured((e) => {
  error.value = e as Error;
  return false;                 // не пробрасывать дальше
});
</script>

<template>
  <ErrorState v-if="error" :error="error" @retry="error = null" />
  <Suspense v-else>
    <UserProfile :id="id" />
    <template #fallback><Spinner /></template>
  </Suspense>
</template>
```

## С роутером, KeepAlive и Transition

```vue
<RouterView v-slot="{ Component }">
  <template v-if="Component">
    <Transition mode="out-in">
      <KeepAlive>
        <Suspense>
          <component :is="Component" />
          <template #fallback>Загрузка…</template>
        </Suspense>
      </KeepAlive>
    </Transition>
  </template>
</RouterView>
```

## Suspense или локальная загрузка

| Suspense + async setup | Локальное состояние `loading` |
| --- | --- |
| Один общий fallback для группы | Каждый компонент управляет своим UI |
| Код компонента линейный (`await`) | `ref` для данных + `v-if="loading"` |
| Экспериментальный API | Стабильно |
| Нет частичного отображения | Можно показывать готовые части |

## Частые ошибки

- Top-level `await` без `<Suspense>` выше.
- Ожидать, что Suspense поймает ошибку сам — нужен `onErrorCaptured`.
- Несколько корневых узлов в `#default` без обёртки при переключениях.
- Использовать в критичном коде, не учитывая экспериментальный статус API.

## Что важно помнить

- Suspense ждёт все асинхронные зависимости поддерева и показывает `#fallback`.
- Асинхронный setup = top-level `await` в `<script setup>`.
- Ошибки — `onErrorCaptured`; API экспериментальный.

## Мини-шпаргалка

- `<Suspense><Comp /><template #fallback>...</template></Suspense>`.
- `const data = await fetch(...)` в `<script setup>`.
- `@pending`, `@resolve`, `@fallback`, `timeout`.
- `onErrorCaptured`.
