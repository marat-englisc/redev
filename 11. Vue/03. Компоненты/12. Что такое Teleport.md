# Что такое Teleport

> [!NOTE]
> `<Teleport to="body">` — встроенный компонент, который рендерит своё содержимое **в другое место DOM** (по CSS-селектору или элементу), оставляя его **логически** внутри компонента: props, события, `provide/inject`, реактивность и Vue DevTools работают как обычно. Типичное применение — модальные окна, тосты, выпадающие меню и тултипы: если рендерить их внутри компонента, они могут обрезаться родителем с `overflow: hidden`, попадать под чужой `z-index` или ломаться из-за `transform` предка (который создаёт новый контекст для `position: fixed`). Опции: `disabled` — временно рендерить на месте (например, на мобильных), `defer` (Vue 3.5+) — дождаться, пока целевой элемент появится в том же цикле рендера. Несколько Teleport в одну цель добавляются по порядку. В SSR телепортированный контент рендерится отдельно и требует аккуратной гидрации (в Nuxt — цель `#teleports`).

## Вопрос

Что такое `<Teleport>` и когда его использовать?

## Модальное окно

```vue
<!-- BaseModal.vue -->
<script setup lang="ts">
const open = defineModel<boolean>('open', { default: false });
defineProps<{ title: string }>();

function onKeydown(e: KeyboardEvent) {
  if (e.key === 'Escape') open.value = false;
}
</script>

<template>
  <Teleport to="body">
    <Transition name="fade">
      <div v-if="open" class="backdrop" @click.self="open = false" @keydown="onKeydown">
        <div class="dialog" role="dialog" aria-modal="true" :aria-label="title" tabindex="-1">
          <header>{{ title }}</header>
          <slot />
          <button @click="open = false">Закрыть</button>
        </div>
      </div>
    </Transition>
  </Teleport>
</template>

<style scoped>
.backdrop { position: fixed; inset: 0; background: rgb(0 0 0 / 0.4); display: grid; place-items: center; z-index: 1000; }
</style>
```

```vue
<!-- где-то глубоко в карточке с overflow: hidden -->
<button @click="showModal = true">Подробнее</button>
<BaseModal v-model:open="showModal" title="Товар">...</BaseModal>
```

DOM модалки окажется последним ребёнком `<body>`, а `showModal`, слоты и события работают как будто она внутри карточки.

## Цели

```vue
<Teleport to="#modals">...</Teleport>        <!-- контейнер в index.html -->
<Teleport to=".toast-root">...</Teleport>
<Teleport :to="targetEl">...</Teleport>       <!-- элемент -->
```

Цель должна существовать в DOM к моменту монтирования Teleport (или используйте `defer`).

## disabled и defer

```vue
<Teleport to="body" :disabled="isMobile">   <!-- на мобильных — inline -->
  <FiltersPanel />
</Teleport>

<Teleport defer to="#sidebar-slot">          <!-- Vue 3.5+: цель рендерится этим же приложением позже -->
  <Widget />
</Teleport>
<aside id="sidebar-slot" />
```

## Зачем это нужно (CSS)

| Проблема без Teleport | Причина |
| --- | --- |
| Модалка обрезается | `overflow: hidden` у предка |
| Модалка под шапкой | Контекст наложения (`z-index`) предка |
| `position: fixed` позиционируется не от окна | `transform`/`filter` у предка создают containing block |

## Доступность модалок

Teleport решает только расположение в DOM. Для доступного диалога нужны `role="dialog"`, `aria-modal`, перенос фокуса внутрь и возврат при закрытии, ловушка фокуса, закрытие по Escape, блокировка прокрутки фона. Часто проще использовать нативный `<dialog>` с `showModal()` или готовые headless-компоненты (Reka UI, Headless UI).

## Частые ошибки

- Цель (`#modals`) не существует при монтировании.
- Ожидать, что scoped-стили родителя «не дотянутся» — стили компонента применяются (атрибуты scoped сохраняются).
- Забывать о фокусе и Escape в модалках.
- Teleport в SSR без учёта гидрации.

## Что важно помнить

- Teleport переносит DOM, сохраняя логическую связь с компонентом.
- Решает проблемы `overflow`, `z-index` и `transform` предков.
- `disabled` — рендер на месте, `defer` (3.5+) — отложенная цель.

## Мини-шпаргалка

- `<Teleport to="body">...</Teleport>`.
- `:disabled="cond"`.
- `defer` (3.5+).
- Модалка: Teleport + Transition + `v-model:open`.
