# Что такое компонент и дерево компонентов

> [!NOTE]
> **Компонент** — переиспользуемая изолированная единица UI со своим шаблоном, логикой, стилями и состоянием. Каждый экземпляр компонента имеет **собственное** состояние: три `<Counter />` считают независимо. Компоненты общаются по чётким правилам: родитель передаёт данные ребёнку через **props**, ребёнок сообщает о событиях через **emit**, содержимое передаётся через **слоты**, общий контекст — через **provide/inject** или стор. Приложение — это **дерево компонентов** с корнем `App`: данные текут сверху вниз, события поднимаются снизу вверх. Хорошее разбиение на компоненты снижает сложность (каждая часть понятна и тестируется отдельно), даёт переиспользование и ускоряет обновления (перерисовывается только затронутый компонент). Типичные роли: **базовые** UI-компоненты (`BaseButton`, `BaseInput`), **доменные** (`ProductCard`), **страницы** (`ProductPage`) и **layout**-компоненты; часто отделяют «умные» компоненты (данные, стор) от «презентационных» (только props и события).

## Вопрос

Что такое компонент во Vue и как устроено дерево компонентов?

## Компонент

```vue
<!-- ProductCard.vue -->
<script setup lang="ts">
const props = defineProps<{ product: Product; inCart: boolean }>();
const emit = defineEmits<{ add: [id: string] }>();
</script>

<template>
  <article class="card">
    <img :src="product.image" :alt="product.title" />
    <h3>{{ product.title }}</h3>
    <slot name="badge" />
    <button :disabled="inCart" @click="emit('add', product.id)">
      {{ inCart ? 'В корзине' : 'В корзину' }}
    </button>
  </article>
</template>
```

```vue
<!-- ProductList.vue -->
<script setup lang="ts">
import ProductCard from './ProductCard.vue';
const cart = useCartStore();
defineProps<{ products: Product[] }>();
</script>

<template>
  <ProductCard
    v-for="p in products"
    :key="p.id"
    :product="p"
    :in-cart="cart.has(p.id)"
    @add="cart.add"
  >
    <template #badge><span v-if="p.isNew">Новинка</span></template>
  </ProductCard>
</template>
```

## Дерево и поток данных

```text
App
├── AppHeader
│   └── CartBadge         ← читает стор
└── RouterView
    └── CatalogPage       ← загружает данные
        ├── FiltersPanel  ── emit('change') ──┐
        └── ProductList   ◄── props: products ┘
            └── ProductCard × N  ── emit('add') → cart.add
```

| Механизм | Направление | Когда |
| --- | --- | --- |
| Props | Родитель → ребёнок | Входные данные |
| Emit | Ребёнок → родитель | События, намерения |
| `v-model` | Двусторонняя привязка значения | Поля форм, переключатели |
| Слоты | Родитель → ребёнок (разметка) | Настраиваемое содержимое |
| Provide / inject | Предок → потомки | Контекст без пробрасывания через уровни |
| Store (Pinia) | Любой ↔ любой | Глобальное состояние |

## Изоляция экземпляров

```vue
<Counter />
<Counter />
<!-- у каждого своё состояние count -->
```

Состояние, объявленное **вне** `<script setup>` на уровне модуля (`const shared = ref(0)` в отдельном файле), будет общим для всех экземпляров — так делают простые общие сторы, но случайно это источник багов (и утечек в SSR).

## Как разбивать на компоненты

- Выделяйте часть, которая повторяется или имеет собственное поведение.
- Компонент должен иметь одну ответственность и понятный контракт (props, events, slots).
- Не дробите до бессмысленности: компонент из одной строки без логики — лишний уровень.
- Дорогие и часто обновляемые части выделяйте отдельно — это ограничивает область перерисовки.

## Умные и презентационные

| Презентационный | Умный (контейнер) |
| --- | --- |
| Только props, emit, слоты | Загружает данные, работает со стором и роутером |
| Легко переиспользовать и тестировать | Специфичен для страницы/фичи |
| `ProductCard`, `BaseModal` | `CatalogPage`, `CheckoutForm` |

## Частые ошибки

- Изменять props внутри ребёнка — см. [однонаправленный поток данных](<04. Почему props readonly и что такое однонаправленный поток данных.md>).
- Компоненты на тысячу строк со всей логикой страницы.
- Пробрасывать props через 4–5 уровней вместо provide/inject или стора.
- Состояние модуля, случайно общее для всех экземпляров.

## Что важно помнить

- Компонент — изолированная единица UI со своим состоянием.
- Props вниз, события вверх; слоты — разметка, provide/inject и стор — общий контекст.
- Разбиение по ответственности упрощает код и ограничивает перерисовки.

## Мини-шпаргалка

- `defineProps`, `defineEmits`, `<slot>`.
- `:prop="value"`, `@event="handler"`.
- PascalCase для компонентов в шаблоне: `<ProductCard />`.
- Презентационные vs умные компоненты.
