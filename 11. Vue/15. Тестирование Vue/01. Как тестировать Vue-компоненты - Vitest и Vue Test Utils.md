# Как тестировать Vue-компоненты - Vitest и Vue Test Utils

> [!NOTE]
> Стандартный стек тестирования Vue-приложения: **Vitest** — тест-раннер, который использует конфигурацию и плагины Vite (те же алиасы, обработка `.vue`, TypeScript без отдельной настройки), с API, совместимым с Jest (`describe`, `it`, `expect`, `vi.fn`, `vi.mock`); **Vue Test Utils** (`@vue/test-utils`) — официальная библиотека монтирования компонентов: `mount` (с реальными дочерними компонентами) и `shallowMount` (дети заменены заглушками), `wrapper.find`/`get`/`findComponent`, `trigger`, `setValue`, `setProps`, `emitted`; **DOM-окружение** — `happy-dom` или `jsdom`, либо **Vitest Browser Mode** для запуска в настоящем браузере; для E2E — **Playwright** или Cypress. Принцип: тестировать **поведение с точки зрения пользователя** (что отображается, что происходит при клике и вводе, какие события эмитятся), а не внутреннюю реализацию (`wrapper.vm.privateState`). Важные детали: обновления DOM асинхронны — после действий делают `await` (`await wrapper.trigger('click')`, `await nextTick()`, `flushPromises()` для промисов); глобальные зависимости (Pinia, роутер, i18n, provide) передают через `global.plugins`/`global.provide`/`global.stubs`; сетевые запросы мокают (`vi.mock` модуля API или MSW). Альтернатива VTU с упором на пользовательские запросы — `@testing-library/vue`.

## Вопрос

Как тестировать Vue-компоненты с помощью Vitest и Vue Test Utils?

## Установка

```bash
npm i -D vitest @vue/test-utils happy-dom
```

```ts
// vitest.config.ts
import { defineConfig, mergeConfig } from 'vitest/config';
import viteConfig from './vite.config';

export default mergeConfig(viteConfig, defineConfig({
  test: {
    environment: 'happy-dom',
    globals: false,
    include: ['src/**/*.test.ts'],
    coverage: { provider: 'v8', reporter: ['text', 'html'] },
  },
}));
```

## Первый тест

```vue
<!-- Counter.vue -->
<script setup lang="ts">
const props = withDefaults(defineProps<{ initial?: number; max?: number }>(), { initial: 0, max: 10 });
const emit = defineEmits<{ change: [value: number] }>();
const count = ref(props.initial);

function increment() {
  if (count.value >= props.max) return;
  count.value++;
  emit('change', count.value);
}
</script>

<template>
  <p data-testid="value">{{ count }}</p>
  <button :disabled="count >= max" @click="increment">+1</button>
</template>
```

```ts
// Counter.test.ts
import { describe, it, expect } from 'vitest';
import { mount } from '@vue/test-utils';
import Counter from './Counter.vue';

describe('Counter', () => {
  it('показывает начальное значение', () => {
    const wrapper = mount(Counter, { props: { initial: 5 } });
    expect(wrapper.get('[data-testid="value"]').text()).toBe('5');
  });

  it('увеличивает значение и эмитит change', async () => {
    const wrapper = mount(Counter);
    await wrapper.get('button').trigger('click');            // await — дождаться обновления DOM

    expect(wrapper.get('[data-testid="value"]').text()).toBe('1');
    expect(wrapper.emitted('change')).toEqual([[1]]);
  });

  it('блокирует кнопку на максимуме', async () => {
    const wrapper = mount(Counter, { props: { initial: 10, max: 10 } });
    expect(wrapper.get('button').attributes('disabled')).toBeDefined();
  });
});
```

## Основной API Vue Test Utils

| API | Для чего |
| --- | --- |
| `mount(C, { props, slots, attrs, global })` | Смонтировать компонент |
| `shallowMount` | То же, дети — заглушки |
| `find` / `get` | Найти элемент (`get` бросает ошибку, если нет) |
| `findComponent(Child)` / `findAllComponents` | Найти дочерний компонент |
| `trigger('click')` | Событие DOM |
| `setValue('text')` | Ввод в input/select/checkbox (+ `v-model`) |
| `setProps({...})` | Обновить props |
| `emitted('event')` | Массив аргументов эмитов |
| `text()`, `html()`, `attributes()`, `classes()`, `exists()`, `isVisible()` | Проверки |
| `unmount()` | Размонтировать |

## Формы и v-model

```ts
it('отправляет форму', async () => {
  const wrapper = mount(LoginForm);
  await wrapper.get('input[type="email"]').setValue('ann@example.com');
  await wrapper.get('input[type="password"]').setValue('secret123');
  await wrapper.get('form').trigger('submit.prevent');

  expect(wrapper.emitted('submit')?.[0]).toEqual([{ email: 'ann@example.com', password: 'secret123' }]);
});

it('поддерживает defineModel', async () => {
  const wrapper = mount(SearchInput, {
    props: { modelValue: '', 'onUpdate:modelValue': (v: string) => wrapper.setProps({ modelValue: v }) },
  });
  await wrapper.get('input').setValue('vue');
  expect(wrapper.props('modelValue')).toBe('vue');
});
```

## Асинхронность и запросы

```ts
import { flushPromises } from '@vue/test-utils';
import { vi } from 'vitest';
import * as api from '@/api/products';

vi.mock('@/api/products');

it('загружает и показывает товары', async () => {
  vi.mocked(api.getProducts).mockResolvedValue([{ id: 1, title: 'Клавиатура' }]);
  const wrapper = mount(ProductList);

  expect(wrapper.text()).toContain('Загрузка');
  await flushPromises();                                    // дождаться промисов и перерендера
  expect(wrapper.text()).toContain('Клавиатура');
});
```

| Ждать | Как |
| --- | --- |
| Обновление DOM после изменения состояния | `await nextTick()` или `await trigger/setValue` |
| Разрешение промисов (запросы) | `await flushPromises()` |
| Таймеры, debounce | `vi.useFakeTimers()` + `vi.advanceTimersByTime(300)` |
| Асинхронный `setup` | Обернуть в `<Suspense>` в тестовом компоненте |

## Глобальные зависимости

```ts
import { createTestingPinia } from '@pinia/testing';

const wrapper = mount(Header, {
  global: {
    plugins: [createTestingPinia({ initialState: { auth: { user: { name: 'Анна' } } } })],
    provide: { theme: 'dark' },
    stubs: { RouterLink: { template: '<a><slot /></a>' }, Teleport: true },
    mocks: { $t: (key: string) => key },
  },
});
```

## Что тестировать

| Стоит | Не стоит |
| --- | --- |
| Отображение по props и состоянию | Внутренние переменные `wrapper.vm` |
| Реакцию на действия пользователя | Что Vue правильно рендерит `v-if` |
| Эмитируемые события и их аргументы | Снапшоты больших компонентов «на всё» |
| Граничные случаи: пусто, ошибка, загрузка | Детали сторонних библиотек |

Селекторы — по ролям, тексту и `data-testid`, а не по CSS-классам вёрстки.

## Пирамида тестов во фронтенде

```text
E2E (Playwright)          ← критичные сценарии: логин, оформление заказа
Компонентные тесты        ← поведение компонентов, формы, состояния
Unit                      ← composables, утилиты, сторы, форматирование
```

## Частые ошибки

- Забыть `await` после `trigger`/`setValue` — проверка до обновления DOM.
- Тестировать реализацию (`wrapper.vm.count`) вместо результата в DOM.
- Реальные сетевые запросы в тестах.
- `shallowMount` везде — тест не проверяет интеграцию с детьми.
- Хрупкие селекторы по классам Tailwind.

## Что важно помнить

- Vitest + Vue Test Utils + happy-dom/jsdom; E2E — Playwright.
- Тестируйте поведение: DOM, события, эмиты.
- `await` для DOM, `flushPromises` для промисов, моки для API и глобальных плагинов.

## Мини-шпаргалка

- `mount(C, { props, slots, global: { plugins, stubs, provide } })`.
- `await wrapper.get('button').trigger('click')`.
- `await wrapper.get('input').setValue('x')`.
- `wrapper.emitted('change')`.
- `await flushPromises()`, `vi.mock()`, `vi.useFakeTimers()`.
