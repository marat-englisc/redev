# Как освобождать ресурсы - onBeforeUnmount и onUnmounted

> [!NOTE]
> Когда компонент удаляется (условие `v-if` стало ложным, сменился маршрут, элемент списка удалён), Vue вызывает **`onBeforeUnmount`** — компонент ещё полностью рабочий, DOM на месте — и затем **`onUnmounted`** — DOM удалён, реактивные эффекты (`computed`, `watch`, созданные синхронно в `setup`) уже **остановлены автоматически**. Vue сам освобождает только **свои** ресурсы; всё, что компонент подключил вне Vue, нужно освободить вручную: слушатели `window`/`document`, `setInterval`/`setTimeout`, `IntersectionObserver`/`ResizeObserver`/`MutationObserver`, WebSocket и `EventSource`, подписки на сторы или event emitter, экземпляры сторонних библиотек (`chart.destroy()`, `map.remove()`), незавершённые запросы (`AbortController`), а также `watch`, созданные асинхронно. Без этого появляются **утечки памяти**, «мёртвые» обработчики, которые меняют уже несуществующее состояние, и дублирующиеся подписки при повторном монтировании. Удобный приём — регистрировать очистку **рядом** с подпиской внутри composable; VueUse делает это автоматически (`useEventListener`, `useIntervalFn`).

## Вопрос

Как правильно освобождать ресурсы при удалении компонента во Vue?

## Что очищать

| Ресурс | Очистка |
| --- | --- |
| `addEventListener` на `window`/`document` | `removeEventListener` с той же функцией |
| `setInterval` / `setTimeout` | `clearInterval` / `clearTimeout` |
| Observers | `disconnect()` |
| WebSocket / EventSource | `close()` |
| Сторонние библиотеки | `destroy()`, `remove()`, `dispose()` |
| `fetch` в процессе | `AbortController.abort()` |
| `watch`, созданный после `await` или в таймере | Вызвать возвращённую функцию `stop()` |
| Подписка `store.$subscribe` с `detached: true` | Вызвать возвращённую функцию отписки |

## Пример

```vue
<script setup lang="ts">
const el = useTemplateRef<HTMLDivElement>('map');
let map: maplibregl.Map | null = null;
let socket: WebSocket | null = null;
let timer: ReturnType<typeof setInterval> | undefined;
const controller = new AbortController();

onMounted(async () => {
  map = new maplibregl.Map({ container: el.value!, style });
  socket = new WebSocket(WS_URL);
  socket.onmessage = (e) => updateMarkers(JSON.parse(e.data));
  timer = setInterval(refreshTraffic, 60_000);
  document.addEventListener('keydown', onKeydown);
  initialData.value = await api.getPoints({ signal: controller.signal });
});

onBeforeUnmount(() => {
  controller.abort();
  clearInterval(timer);
  document.removeEventListener('keydown', onKeydown);
  socket?.close();
  map?.remove();
});
</script>
```

## Очистка рядом с подпиской

```ts
export function useEventSource(url: MaybeRefOrGetter<string>) {
  const data = ref<unknown>(null);
  let source: EventSource | null = null;

  watchEffect((onCleanup) => {
    source = new EventSource(toValue(url));
    source.onmessage = (e) => (data.value = JSON.parse(e.data));
    onCleanup(() => source?.close());          // при смене url и при остановке эффекта
  });

  return { data };
}
```

Эффект, созданный синхронно в `setup`, остановится при размонтировании — и вызовет `onCleanup`.

## onScopeDispose в composables

```ts
export function useInterval(fn: () => void, ms: number) {
  const id = setInterval(fn, ms);
  onScopeDispose(() => clearInterval(id));     // работает и в компоненте, и в effectScope, и в Pinia setup store
}
```

`onScopeDispose` предпочтительнее `onUnmounted` в composables: они могут вызываться вне компонента (в сторе, `effectScope`).

## VueUse

```ts
useEventListener(window, 'resize', onResize);     // снимется автоматически
const { pause, resume } = useIntervalFn(poll, 30_000);
useIntersectionObserver(target, ([entry]) => { /* ... */ });
```

## onBeforeUnmount или onUnmounted

| `onBeforeUnmount` | `onUnmounted` |
| --- | --- |
| DOM и состояние ещё доступны | DOM удалён, эффекты остановлены |
| Сохранить черновик, прочитать позицию прокрутки, уничтожить библиотеку, использующую DOM | Финальная очистка, логирование |

## Утечки на практике

```text
Перешли со страницы карты 10 раз → 10 активных WebSocket и 10 слушателей resize
→ растёт память, дублируются события, обработчики меняют состояние удалённых экземпляров
```

Проверка — Chrome DevTools → Memory (heap snapshot), Performance monitor (JS event listeners).

## Частые ошибки

- `removeEventListener` с новой стрелочной функцией — слушатель не снимается.
- Очистка в `onUnmounted` для библиотеки, которой нужен DOM при `destroy()`.
- Забыть про таймеры и WebSocket в компонентах внутри `v-if`/маршрутов.
- `watch` после `await` без `stop()`.
- В KeepAlive: компонент не размонтируется — фоновые процессы останавливают в `onDeactivated`.

## Что важно помнить

- Vue останавливает свои эффекты; внешние ресурсы освобождаете вы.
- `onBeforeUnmount` — пока DOM жив, `onUnmounted` — после.
- В composables — `onScopeDispose` или `onCleanup` рядом с подпиской.

## Мини-шпаргалка

- `onBeforeUnmount(() => { remove...; destroy(); })`.
- `onScopeDispose(cleanup)`.
- `watchEffect((onCleanup) => ...)`, `onWatcherCleanup`.
- VueUse: `useEventListener`, `useIntervalFn`.
