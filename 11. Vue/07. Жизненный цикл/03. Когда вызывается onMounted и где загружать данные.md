# Когда вызывается onMounted и где загружать данные

> [!NOTE]
> `onMounted` вызывается **один раз**, когда компонент отрендерен и его DOM **вставлен в документ**; к этому моменту смонтированы и все **синхронные** дочерние компоненты (асинхронные и внутри `Suspense` могут ещё грузиться), а template refs заполнены. Это место для всего, что требует DOM: фокус, измерения, `IntersectionObserver`/`ResizeObserver`, инициализация сторонних библиотек (карты, графики, редакторы), подписки на события `window`/`document`. **Загрузку данных** не обязательно откладывать до `onMounted`: запрос можно начать прямо в `setup` (или через `watch(..., { immediate: true })`, если он зависит от props/маршрута) — так он стартует раньше, а DOM для него не нужен. В SSR `onMounted` на сервере **не выполняется** — серверную загрузку делают через `onServerPrefetch`, `async setup` с `Suspense` или средства фреймворка (`useAsyncData`/`useFetch` в Nuxt). Если компонент внутри `KeepAlive`, при возвращении вызывается `onActivated`, а не повторный `onMounted`.

## Вопрос

Когда вызывается `onMounted` и где правильно загружать данные во Vue-компоненте?

## Работа с DOM

```vue
<script setup lang="ts">
const searchInput = useTemplateRef<HTMLInputElement>('search');
const listEl = useTemplateRef<HTMLUListElement>('list');

const listHeight = ref(0);
let ro: ResizeObserver | undefined;

onMounted(() => {
  searchInput.value?.focus();
  ro = new ResizeObserver(([e]) => (listHeight.value = e.contentRect.height));
  ro.observe(listEl.value!);
});

onBeforeUnmount(() => ro?.disconnect());
</script>
```

## Загрузка данных: варианты

```ts
// 1. Сразу в setup — запрос стартует до монтирования
const products = ref<Product[]>([]);
const loading = ref(true);
api.getProducts().then((p) => (products.value = p)).finally(() => (loading.value = false));

// 2. Зависит от props/маршрута — watch с immediate
const route = useRoute();
watch(() => route.params.id as string, async (id) => {
  product.value = await api.getProduct(id);
}, { immediate: true });

// 3. В onMounted — допустимо, но запрос начнётся позже
onMounted(async () => { stats.value = await api.getStats(); });
```

| Где | Плюсы | Минусы |
| --- | --- | --- |
| `setup` | Раньше старт, проще | — |
| `watch` + `immediate` | Перезагрузка при смене параметров | — |
| `onMounted` | Нужно, если запрос зависит от DOM (размер viewport) | Чуть позже; не работает в SSR |
| `async setup` + `Suspense` | Линейный код, общий fallback | Экспериментальный Suspense |
| Composable (`useFetch` из VueUse, TanStack Query) | Кеш, повторы, отмена, статусы | Ещё одна зависимость |

## Отмена и устаревшие ответы

```ts
watch(() => props.userId, async (id) => {
  const controller = new AbortController();
  onWatcherCleanup(() => controller.abort());       // 3.5+
  user.value = await api.getUser(id, { signal: controller.signal });
}, { immediate: true });
```

Без отмены быстрая смена параметров может показать устаревшие данные.

## SSR

```ts
const data = ref<Stats | null>(null);

onServerPrefetch(async () => {                 // выполнится на сервере и дождётся загрузки
  data.value = await api.getStats();
});

onMounted(async () => {
  if (!data.value) data.value = await api.getStats();   // клиентская навигация
});
```

В Nuxt вместо этого — `useAsyncData`/`useFetch`, которые передают данные с сервера на клиент без повторного запроса.

## Порядок с детьми

```text
Child onMounted → Parent onMounted
```

В `onMounted` родителя уже доступны DOM и refs синхронных детей.

## Частые ошибки

- Ждать `onMounted` для запроса, которому не нужен DOM.
- Читать размеры элементов в `setup`.
- Ожидать `onMounted` при каждом возврате в KeepAlive (нужен `onActivated`).
- Обращаться к `window` вне `onMounted` в SSR-приложении.
- Не отменять запросы при размонтировании и смене параметров.

## Что важно помнить

- `onMounted` — DOM вставлен, refs готовы, один раз.
- Данные можно начинать загружать в `setup`; зависимые от параметров — через `watch` с `immediate`.
- В SSR — `onServerPrefetch` или средства фреймворка.

## Мини-шпаргалка

- `onMounted(() => el.value?.focus())`.
- `watch(() => props.id, load, { immediate: true })`.
- `onWatcherCleanup(() => controller.abort())`.
- `onServerPrefetch(async () => ...)`.
