# Что такое жизненный цикл компонента и его этапы

> [!NOTE]
> **Жизненный цикл** — последовательность этапов, через которые проходит экземпляр компонента: **создание** (выполнение `setup`, инициализация props, состояния, computed, watch), **монтирование** (компиляция/рендер, создание DOM и вставка в документ), **обновления** (повторный рендер при изменении реактивных данных) и **размонтирование** (удаление из DOM, остановка эффектов). На каждом этапе Vue вызывает **хуки**: в Composition API — `onBeforeMount`, `onMounted`, `onBeforeUpdate`, `onUpdated`, `onBeforeUnmount`, `onUnmounted` (плюс `onActivated`/`onDeactivated` для KeepAlive, `onErrorCaptured`, `onServerPrefetch` для SSR и отладочные `onRenderTracked`/`onRenderTriggered`); код самого `setup` заменяет `beforeCreate`/`created`. Порядок для дерева: `setup` и `onBeforeMount` идут от родителя к детям, а **`onMounted` — от детей к родителю** (родитель смонтирован, когда смонтированы все дети). Хуки нужно регистрировать **синхронно** во время `setup` — после `await` они не привязываются к компоненту. Понимание цикла отвечает на практические вопросы: где делать запрос, где доступен DOM, где освобождать ресурсы.

## Вопрос

Что такое жизненный цикл компонента Vue и какие у него этапы?

## Схема

```text
setup()                      ← создание: props, ref, computed, watch (DOM ещё нет)
  │
onBeforeMount                ← рендер готов, DOM ещё не вставлен
  │
onMounted                    ← DOM в документе: template refs, сторонние библиотеки, измерения
  │
  ├─► данные изменились
  │      onBeforeUpdate      ← до патча DOM
  │      onUpdated           ← DOM обновлён
  │
onBeforeUnmount              ← компонент ещё работает: снять слушатели, сохранить черновик
  │
onUnmounted                  ← удалён: эффекты остановлены
```

## Пример

```vue
<script setup lang="ts">
const chartEl = useTemplateRef<HTMLCanvasElement>('chart');
let chart: Chart | null = null;

const data = ref<Point[]>([]);
api.getPoints().then((p) => (data.value = p));       // запрос можно начать в setup — DOM не нужен

onMounted(() => {
  chart = new Chart(chartEl.value!, { data: data.value });   // нужен DOM
  window.addEventListener('resize', onResize);
});

watch(data, (d) => chart?.update(d));

onBeforeUnmount(() => {
  window.removeEventListener('resize', onResize);
  chart?.destroy();
});
</script>

<template>
  <canvas ref="chart" />
</template>
```

## Порядок в дереве

```text
Parent setup
Parent onBeforeMount
  Child setup
  Child onBeforeMount
  Child onMounted
Parent onMounted              ← родитель «смонтирован» последним
```

При размонтировании: `Parent onBeforeUnmount` → дети `onBeforeUnmount`/`onUnmounted` → `Parent onUnmounted`.

## Что где делать

| Этап | Задачи |
| --- | --- |
| `setup` | Состояние, computed, watch, начало загрузки данных, `provide/inject` |
| `onMounted` | Работа с DOM, template refs, сторонние библиотеки, подписки на `window` |
| `onUpdated` | Редко: синхронизация с DOM после обновления (лучше `watch` с `flush: 'post'`) |
| `onBeforeUnmount` / `onUnmounted` | Отписки, таймеры, `destroy()` библиотек, отмена запросов |
| `onActivated` / `onDeactivated` | Возврат/уход компонента внутри KeepAlive |
| `onServerPrefetch` | Загрузка данных при SSR |

## Синхронная регистрация

```ts
// ✗ после await хук не привязан к компоненту
const config = await loadConfig();
onMounted(() => { ... });

// ✓ регистрировать до первого await
onMounted(() => { ... });
const config = await loadConfig();
```

## SSR

На сервере выполняются только `setup` и `onServerPrefetch`; `onMounted` и далее — только в браузере. Поэтому обращения к `window`/`document` переносят в `onMounted`.

## Частые ошибки

- Обращение к DOM и template refs в `setup`.
- Нет очистки в `onBeforeUnmount`/`onUnmounted` — утечки памяти и «мёртвые» слушатели.
- Регистрация хуков после `await`.
- Изменение состояния в `onUpdated` — бесконечный цикл обновлений.
- Использовать `beforeDestroy`/`destroyed` из Vue 2.

## Что важно помнить

- Создание (`setup`) → монтирование → обновления → размонтирование.
- DOM доступен с `onMounted`; дети монтируются раньше родителя.
- Ресурсы освобождаются в `onBeforeUnmount`/`onUnmounted`.

## Мини-шпаргалка

- `onMounted`, `onBeforeUnmount`, `onUnmounted`.
- `onBeforeUpdate`, `onUpdated`.
- `onActivated`, `onDeactivated`, `onErrorCaptured`, `onServerPrefetch`.
- Хуки — синхронно в `setup`.
