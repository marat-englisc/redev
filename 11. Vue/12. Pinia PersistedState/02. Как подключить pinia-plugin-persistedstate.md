# Как подключить pinia-plugin-persistedstate

> [!NOTE]
> Плагин устанавливают пакетом `pinia-plugin-persistedstate` и регистрируют на экземпляре pinia **до** `app.use(pinia)`: `pinia.use(piniaPluginPersistedstate)`. После этого у `defineStore` появляется опция **`persist`**: `true` — сохранять весь state в `localStorage` под ключом, равным id стора; объект — с настройками (`key`, `storage`, `pick`, `omit`, `serializer`, хуки `beforeHydrate`/`afterHydrate`, `debug`); массив объектов — несколько хранилищ для разных частей стора. Для **setup store** опция передаётся **третьим** аргументом `defineStore`, для option store — полем рядом со `state`. Глобальные значения по умолчанию задают через `createPersistedState({...})`. Плагин сохраняет state при каждом изменении (через `$subscribe`) и гидрирует его при **первом создании** стора. В **Nuxt** вместо ручной регистрации подключают модуль `pinia-plugin-persistedstate/nuxt` (после `@pinia/nuxt`), где хранилище по умолчанию — **cookies**, чтобы состояние было доступно и при SSR.

## Вопрос

Как подключить `pinia-plugin-persistedstate` в Vue- и Nuxt-проекте?

## Vue + Vite

```bash
npm install pinia-plugin-persistedstate
```

```ts
// main.ts
import { createPinia } from 'pinia';
import piniaPluginPersistedstate from 'pinia-plugin-persistedstate';

const pinia = createPinia();
pinia.use(piniaPluginPersistedstate);    // сначала плагин

app.use(pinia);                           // затем pinia в приложение
app.mount('#app');
```

## Option store

```ts
export const useSettingsStore = defineStore('settings', {
  state: () => ({ theme: 'light' as 'light' | 'dark', locale: 'ru', sidebarCollapsed: false }),
  persist: true,
});
```

## Setup store

```ts
export const useSettingsStore = defineStore(
  'settings',
  () => {
    const theme = ref<'light' | 'dark'>('light');
    const sidebarCollapsed = ref(false);
    return { theme, sidebarCollapsed };
  },
  { persist: true },          // третий аргумент
);
```

```text
localStorage:
settings → {"theme":"dark","sidebarCollapsed":true}
```

## Глобальные настройки

```ts
import { createPersistedState } from 'pinia-plugin-persistedstate';

pinia.use(createPersistedState({
  key: (id) => `myapp:${id}`,            // префикс ключей
  storage: localStorage,
  debug: import.meta.env.DEV,
}));
```

Применяются к сторам с `persist: true`; локальные настройки стора их переопределяют.

## Nuxt

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['@pinia/nuxt', 'pinia-plugin-persistedstate/nuxt'],
  piniaPluginPersistedstate: {
    storage: 'cookies',                   // по умолчанию в Nuxt
    cookieOptions: { sameSite: 'lax', maxAge: 60 * 60 * 24 * 365 },
  },
});
```

```ts
// стор в Nuxt
persist: { storage: piniaPluginPersistedstate.localStorage() },   // только клиент
persist: { storage: piniaPluginPersistedstate.cookies({ maxAge: 3600 }) },
```

## Ручное управление

```ts
const settings = useSettingsStore();
settings.$hydrate();        // перечитать из storage (например, после изменения в другой вкладке)
settings.$persist();        // принудительно сохранить
```

## Частые ошибки

- `pinia.use(...)` после `app.use(pinia)` и создания сторов — гидрация не произойдёт для уже созданных сторов.
- Для setup store передать `persist` внутрь функции, а не третьим аргументом.
- `persist: true` на всех сторах «на всякий случай».
- В Nuxt использовать `localStorage` для данных, нужных при SSR (будет несовпадение гидрации).

## Что важно помнить

- `pinia.use(piniaPluginPersistedstate)` до `app.use(pinia)`.
- `persist: true | {...} | [...]`; в setup store — третьим аргументом.
- Nuxt: модуль `pinia-plugin-persistedstate/nuxt`, cookies по умолчанию.

## Мини-шпаргалка

- `pinia.use(piniaPluginPersistedstate)`.
- `defineStore('id', { state, persist: true })`.
- `defineStore('id', setup, { persist: {...} })`.
- `createPersistedState({ key, storage })`.
- `$hydrate()`, `$persist()`.
