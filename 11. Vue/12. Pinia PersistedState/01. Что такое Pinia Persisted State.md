# Что такое Pinia Persisted State

> [!NOTE]
> Состояние Pinia живёт **в памяти** JavaScript: после перезагрузки страницы сторы возвращаются к начальным значениям. **Persisted state** — сохранение выбранной части состояния во внешнее хранилище (`localStorage`, `sessionStorage`, cookies) и её **восстановление (гидрация)** при следующем запуске. Стандартное решение — плагин **`pinia-plugin-persistedstate`**: он добавляет сторам опцию `persist`, сам подписывается на изменения и записывает state, а при создании стора — читает сохранённое. Хорошие кандидаты: тема, язык, свёрнутая боковая панель, черновики, выбранные фильтры и организация, состояние онбординга, корзина гостя. Плохие: **токены и секреты** (любой XSS прочитает `localStorage`), пароли и персональные данные, **права и роли** (пользователь может их подменить — сервер обязан проверять сам), большие серверные списки (устаревают, ограничены квотой ~5 МБ, замедляют старт), временные флаги `loading`/`error`. Persisted state — удобство UX, а не безопасное хранилище и не кеш данных API.

## Вопрос

Что такое Pinia Persisted State и какие данные стоит сохранять?

## Проблема

```text
Пользователь выбрал тёмную тему → F5 → тема снова светлая
```

```text
С persistence:
store change ──► localStorage['settings'] = {"theme":"dark"}
reload ──► useSettingsStore() ──► гидрация из localStorage ──► theme = 'dark'
```

## Минимальный пример

```ts
// main.ts
import piniaPluginPersistedstate from 'pinia-plugin-persistedstate';
const pinia = createPinia();
pinia.use(piniaPluginPersistedstate);
app.use(pinia);

// stores/settings.ts
export const useSettingsStore = defineStore('settings', () => {
  const theme = ref<'light' | 'dark'>('light');
  const locale = ref<'ru' | 'en'>('ru');
  return { theme, locale };
}, {
  persist: true,          // сохранить весь state в localStorage под ключом 'settings'
});
```

## Что сохранять

| ✓ Подходит | ✗ Не подходит |
| --- | --- |
| Тема, язык, плотность интерфейса | Access/refresh-токены |
| Свёрнутые панели, порядок колонок | Пароли, платёжные данные |
| Черновик формы | Роли и права для доступа |
| Выбранная организация (id) | Большие списки с сервера |
| Гостевая корзина (id и количество) | `loading`, `error`, временные флаги |
| Состояние онбординга | Данные, которые должны быть всегда свежими |

## Хранилища

| Хранилище | Время жизни | Доступно на сервере (SSR) |
| --- | --- | --- |
| `localStorage` | До очистки пользователем | Нет |
| `sessionStorage` | До закрытия вкладки | Нет |
| Cookies | По `max-age`/`expires`, отправляются с запросами | Да (можно прочитать при SSR) |

## Альтернативы

- `useStorage`/`useLocalStorage` из VueUse — для отдельного значения без стора.
- Свой `$subscribe` с `detached: true` — если нужна особая логика.
- Серверное хранение настроек — если они должны быть общими между устройствами.

Подробнее о настройке — [подключение плагина](<02. Как подключить pinia-plugin-persistedstate.md>) и [storage, key, pick](<03. Как настроить storage, key и pick в persisted state.md>).

## Частые ошибки

- `persist: true` на сторе авторизации — токены и права в `localStorage`.
- Сохранять большие ответы API вместо повторного запроса или кеша запросов.
- Доверять сохранённой роли при решении о доступе.
- Не очищать сохранённое при выходе пользователя.

## Что важно помнить

- Pinia хранит state в памяти; persistence переносит выбранные поля в storage.
- `pinia-plugin-persistedstate` — опция `persist` у сторов.
- Сохраняйте настройки и черновики, не секреты, права и серверные данные.

## Мини-шпаргалка

- `npm i pinia-plugin-persistedstate`.
- `pinia.use(piniaPluginPersistedstate)`.
- `defineStore(id, setup, { persist: true })`.
- localStorage / sessionStorage / cookies.
