# Что происходит при загрузке и парсинге HTML?

> [!NOTE]
> Браузер получает HTML-документ, читает поток символов сверху вниз, превращает его в токены и узлы и постепенно строит DOM. По ходу парсинга он находит CSS, JavaScript, изображения и шрифты и загружает их. Затем DOM и CSSOM дают render tree, после чего идут layout, paint и composite.

## Вопрос

Что делает браузер при загрузке HTML-файла? Как работает парсинг и почему скрипты могут его блокировать?

## Общая схема

```text
HTML response
  -> parse HTML: bytes -> characters -> tokens -> nodes
  -> build DOM
  -> load CSS, JS, images, fonts
  -> build CSSOM
  -> render tree
  -> layout -> paint -> composite
```

Браузер не ждет весь файл: он начинает парсинг по мере поступления данных, поэтому верх страницы может отрисоваться раньше, чем загрузится низ.

## Токенизация и построение DOM

```html
<p>Привет, <strong>HTML</strong></p>
```

Парсер видит токены:

```text
start tag: p
text: "Привет, "
start tag: strong
text: "HTML"
end tag: strong
end tag: p
```

И строит дерево:

```text
p
  "Привет, "
  strong
    "HTML"
```

## HTML парсится терпимо

HTML-парсер исправляет ошибки по алгоритму из спецификации:

```html
<ul>
  <li>Первый
  <li>Второй
</ul>
```

Браузер закроет первый `li` перед вторым. Но полагаться на автоисправление не стоит: например, `<div>` внутри `<table>` будет вынесен из таблицы, а `<p>` внутри `<p>` превратится в два соседних абзаца. Реальный DOM всегда видно во вкладке Elements.

## Загрузка связанных ресурсов

Во время парсинга браузер встречает ссылки на ресурсы:

```html
<link rel="stylesheet" href="/styles.css" />
<script src="/app.js" defer></script>
<img src="/cover.jpg" alt="Обложка" />
```

Параллельно основной парсер работает **preload scanner**: он заранее просматривает HTML и начинает загрузку ресурсов, пока парсер стоит на скрипте.

## Скрипты могут останавливать парсинг

Обычный скрипт без `defer` и `async` блокирует парсинг: браузер должен скачать и выполнить его, потому что скрипт может изменить документ через `document.write` или DOM API.

```html
<script src="/app.js"></script>
```

Кроме того, такой скрипт ждет загрузки CSS, расположенного выше: скрипт может читать стили.

| Вариант | Загрузка | Выполнение |
| --- | --- | --- |
| `<script>` | блокирует парсинг | сразу |
| `defer` | параллельно | после парсинга, по порядку |
| `async` | параллельно | сразу после загрузки, порядок не гарантирован |
| `type="module"` | параллельно | как `defer` |

## Почему порядок важен

Браузер читает HTML сверху вниз. Если JavaScript ищет элемент до того, как он распарсен, он получит `null`:

```html
<script>
  console.log(document.querySelector("#app")); // null
</script>

<div id="app"></div>
```

Решения: `defer`, `type="module"`, скрипт в конце `body` или обработчик `DOMContentLoaded`.

## Render tree, layout и paint

DOM описывает структуру, CSSOM — стили. Вместе они дают render tree — дерево видимых элементов с вычисленными стилями. Элементы `<head>` и узлы с `display: none` в него не попадают.

- **Layout** — расчет размеров и позиций.
- **Paint** — рисование текста, фона, границ, изображений.
- **Composite** — сборка слоев в итоговую картинку.

Подробнее — в разделе Web: [Как браузер строит страницу](<../../01. Web технологии/06. Работа браузера и client-server/02. Как браузер строит страницу.md>).

## Что важно помнить

- CSS блокирует рендеринг, а синхронный JS — парсинг. Поэтому CSS подключают в `head`, а скрипты — с `defer`.
- Событие `DOMContentLoaded` срабатывает после построения DOM и выполнения `defer`-скриптов, `load` — после загрузки всех ресурсов, включая картинки.
- `document.write` после загрузки страницы стирает документ — в современном коде его не используют.
- `innerHTML` запускает тот же HTML-парсер, но скрипты, вставленные через него, не выполняются.

## Мини-шпаргалка

- Парсинг: байты → символы → токены → узлы → DOM.
- Браузер читает HTML сверху вниз и исправляет часть ошибок.
- Обычный `<script>` блокирует парсинг; `defer` и `module` — нет.
- Preload scanner заранее находит ресурсы.
- DOM + CSSOM → render tree → layout → paint → composite.
