# Что делает элемент img и как браузер загружает изображение?

> [!NOTE]
> Элемент `<img>` вставляет изображение в документ: `src` задает адрес файла, `alt` — текстовую альтернативу. Встретив `<img src>`, браузер разрешает URL, ставит ресурс в очередь загрузки с учетом приоритета, скачивает и декодирует файл, а затем рисует его в рассчитанном месте страницы.

## Вопрос

Что делает элемент `img`? Какие у него важные атрибуты и как браузер загружает изображение, указанное в `src`?

## Основная идея

```html
<img
  src="/images/profile.jpg"
  alt="Фото пользователя Анны"
  width="320"
  height="240"
>
```

`img` — void-элемент: без закрывающего тега и содержимого. По умолчанию это строчный (inline) элемент, поэтому под картинкой в блоке появляется небольшой зазор от базовой линии текста. Его убирают через `display: block` или `vertical-align: middle`.

## Важные атрибуты

| Атрибут | Назначение |
| --- | --- |
| `src` | Адрес изображения |
| `alt` | Текстовая альтернатива |
| `width`, `height` | Внутренние размеры и пропорции — защита от layout shift |
| `loading` | `lazy` — отложить загрузку, `eager` — грузить сразу |
| `decoding` | `async` — декодировать без блокировки рендера |
| `fetchpriority` | `high` / `low` — приоритет загрузки |
| `srcset`, `sizes` | Варианты для разных экранов (responsive images) |

## Alt

`alt` описывает смысл изображения:

```html
<img src="/chart.png" alt="График роста продаж за 2026 год">
```

Декоративное изображение получает пустой `alt` — скринридер его пропустит:

```html
<img src="/decor.svg" alt="">
```

Отсутствие `alt` вообще — ошибка: скринридер прочитает имя файла.

## Как браузер загружает изображение

```text
parse HTML
  -> find img src (часто раньше — preload scanner)
  -> resolve URL относительно документа
  -> request image (с учетом приоритета)
  -> download bytes
  -> decode image
  -> paint image
```

Изображения не блокируют парсинг HTML, но влияют на LCP и стабильность layout. Если файл не загрузился, браузер покажет текст `alt` — поэтому он важен не только для скринридеров.

## Приоритет и lazy loading

```html
<!-- главное изображение первого экрана -->
<img src="/hero.jpg" alt="Главный экран" fetchpriority="high" width="1200" height="600">

<!-- галерея ниже первого экрана -->
<img src="/gallery-1.jpg" alt="Фото проекта" loading="lazy" width="400" height="300">
```

`loading="lazy"` откладывает загрузку, пока картинка не приблизится к видимой области. Для изображений первого экрана lazy вредит: LCP-картинка начнет грузиться позже.

## Что важно помнить

- `width` и `height` задают пропорции до загрузки, а CSS `max-width: 100%; height: auto` делает картинку адаптивной без потери пропорций.
- Для LCP-изображения лучше `fetchpriority="high"` и отсутствие `loading="lazy"`.
- `img` для смысловых изображений, `background-image` в CSS — для декоративных.
- Событие `load` и свойство `img.complete` позволяют узнать, что изображение загружено; `img.decode()` возвращает Promise.
- В Next.js компонент `next/image` автоматически задает размеры, lazy loading и форматы.

## Мини-шпаргалка

- `img` вставляет изображение, `src` — адрес, `alt` — смысл.
- Декоративное — `alt=""`.
- `width` и `height` против layout shift.
- `loading="lazy"` ниже первого экрана, `fetchpriority="high"` — для главного.
- Браузер: URL → загрузка → декодирование → отрисовка.
