# Какие инструменты помогают проверить семантику HTML?

> [!NOTE]
> Семантику HTML проверяют через валидаторы, DevTools, Lighthouse, accessibility-инструменты, скринридеры и ручной просмотр структуры заголовков, landmarks, ссылок и форм.

## Вопрос

Какими инструментами можно проверить семантику и валидность HTML?

## Главное

Один инструмент не гарантирует идеальную семантику. Лучше сочетать автоматические проверки с ручным просмотром структуры страницы.

```text
validator
  -> catches invalid HTML
Lighthouse / axe
  -> catches many accessibility issues
manual review
  -> checks real meaning and content structure
```

## HTML Validator

Валидатор помогает найти ошибки разметки:

- незакрытые элементы;
- неправильную вложенность;
- недопустимые атрибуты;
- дублирующиеся `id`;
- проблемы с базовой структурой документа.

Валидный HTML - не гарантия хорошей семантики, но хорошая отправная точка.

## DevTools

В браузерных DevTools можно посмотреть реальный DOM, который получился после парсинга HTML и работы JavaScript.

```html
<!-- исходный HTML может выглядеть нормально -->
<table>
  <div>Ошибка вложенности</div>
</table>
```

Браузер может перестроить DOM иначе, чем ожидалось. DevTools помогает это заметить.

## Lighthouse и axe

Lighthouse и axe помогают искать accessibility-проблемы:

- отсутствующие `alt`;
- поля формы без label;
- плохую структуру landmarks;
- проблемы контраста;
- ошибки ARIA;
- некорректные имена интерактивных элементов.

## Скринридеры

Реальная проверка со скринридером помогает понять, как страница воспринимается без визуального интерфейса.

Полезно проверить:

- список заголовков;
- список landmarks;
- список ссылок;
- чтение форм;
- порядок фокуса.

## Ручной чеклист

- Есть ли понятный `h1`?
- Не перескакивают ли уровни заголовков?
- Есть ли `main`?
- Не заменены ли кнопки и ссылки на `div`?
- У значимых изображений есть `alt`?
- У полей формы есть `label`?
- Текст ссылок понятен вне контекста?

## Что важно помнить

- W3C Validator проверяет синтаксис, но не смысл: валидная страница из `div` всё равно несемантична.
- Вкладка Accessibility в Chrome DevTools показывает роли, имена и accessibility tree выбранного элемента.
- Линтеры `eslint-plugin-jsx-a11y` и `html-validate` ловят ошибки на этапе разработки.
- Быстрая ручная проверка — отключить CSS: страница должна оставаться логичной и читаемой.

## Мини-шпаргалка

- Валидатор ловит ошибки HTML.
- DevTools показывает реальный DOM.
- Lighthouse и axe находят многие accessibility-проблемы.
- Скринридер показывает реальный опыт пользователей.
- Ручная проверка смысла все равно нужна.
- Семантика - это не только отсутствие ошибок, но и правильный выбор элементов.
