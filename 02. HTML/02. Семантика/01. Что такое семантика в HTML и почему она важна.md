# Что такое семантика в HTML и почему она важна?

> [!NOTE]
> **Семантика в HTML** — использование элементов по их смыслу, а не ради внешнего вида. Семантическая разметка объясняет структуру страницы браузеру, поисковым системам, скринридерам и другим разработчикам. Она улучшает доступность, SEO, поддержку кода и дает готовое поведение нативных элементов.

## Вопрос

Что означает семантика в HTML? Почему семантическая разметка важна для веб-разработки?

## Основная идея

HTML-элемент должен отвечать на вопрос: «Что это за часть контента?»

```html
<!-- менее понятно -->
<div class="title">Новости</div>
<div class="menu">...</div>
<div class="content">...</div>

<!-- семантически лучше -->
<h1>Новости</h1>
<nav>...</nav>
<main>...</main>
```

Оба варианта можно визуально сделать одинаковыми через CSS, но смысл у них разный. Во втором варианте назначение блоков понятно без чтения CSS-классов.

Семантика не про внешний вид: `<h1>` можно сделать маленьким, а `<p>` большим, смысл от этого не изменится. Тег выбирают по назначению контента, а оформление задают CSS.

## Примеры семантических элементов

| Элемент | Смысл |
| --- | --- |
| `<header>` | Вводная часть страницы или секции |
| `<nav>` | Навигация |
| `<main>` | Основное содержимое страницы |
| `<section>` | Тематический раздел |
| `<article>` | Самостоятельная единица контента |
| `<aside>` | Дополнительный контент |
| `<footer>` | Завершающая часть страницы или секции |
| `<button>` | Кнопка действия |
| `<a href>` | Переход по ссылке |

## Почему это важно

### Доступность

Скринридеры строят из семантики карту страницы: пользователь может перейти к `main`, пролистать список заголовков или landmarks.

```html
<main>
  <h1>Личный кабинет</h1>
  <section aria-labelledby="orders-title">
    <h2 id="orders-title">Последние заказы</h2>
  </section>
</main>
```

### SEO

Поисковые системы анализируют заголовки, основной контент, ссылки, изображения и статьи. Семантика помогает им понять, что на странице главное.

### Команда

```html
<article class="post-card">
  <h2>Как работает HTML</h2>
  <p>Короткое описание статьи.</p>
</article>
```

Из кода сразу видно, что это самостоятельная карточка статьи.

### Готовое поведение браузера

- `<button>` фокусируется и нажимается с клавиатуры (Enter и Space);
- `<label>` связывается с полем и увеличивает область клика;
- `<details>` раскрывается без JavaScript;
- `<input type="email">` проверяет формат и показывает нужную клавиатуру на мобильных;
- `<dialog>` управляет фокусом модального окна.

## div и span

`div` и `span` почти не несут смысла. Они полезны как нейтральные контейнеры, но не должны заменять элементы с готовой семантикой:

```html
<!-- плохо -->
<div class="button">Сохранить</div>

<!-- лучше -->
<button type="button">Сохранить</button>
```

## Что важно помнить

- Каждый семантический элемент имеет неявную ARIA-роль: `nav` → `navigation`, `main` → `main`, `button` → `button`. Поэтому `role` для них дублировать не нужно.
- `header` и `footer` получают роли `banner` и `contentinfo`, только если они не вложены в `article`, `section` и т. п.
- Семантика проверяется не валидатором, а смыслом: валидный HTML из одних `div` всё равно несемантичен.
- В React и Vue компоненты рендерят обычный HTML — семантика выбирается в JSX и шаблонах так же.

## Мини-шпаргалка

- Семантика — смысл разметки, CSS — внешний вид.
- Тег выбирают по назначению контента.
- Семантика помогает доступности, SEO и команде.
- Нативные элементы дают готовое поведение.
- `div` и `span` нейтральны и не заменяют смысловые элементы.
