# Какие основные типы ARIA-атрибутов существуют?

> [!NOTE]
> Основные типы ARIA включают роли (`role`), свойства (`aria-label`, `aria-controls`, `aria-describedby`) и состояния (`aria-expanded`, `aria-checked`, `aria-invalid`). Они помогают assistive technologies понять назначение и текущее состояние интерфейса.

## Вопрос

Какие типы ARIA-атрибутов существуют? Чем роли отличаются от свойств и состояний?

## Главное

ARIA-атрибуты можно условно разделить на три группы:

```text
role       -> что это за элемент
property   -> какие у него связи и характеристики
state      -> в каком он сейчас состоянии
```

## Role

`role` задает семантическую роль элемента.

```html
<div role="status">Профиль сохранен</div>
```

Но `role` не добавляет поведение. Если написать `role="button"` на `div`, элемент не станет настоящей кнопкой: клавиатуру и фокус придется реализовывать вручную.

```html
<!-- обычно лучше -->
<button type="button">Сохранить</button>
```

## Accessible name

Атрибуты для доступного имени объясняют, как элемент называется для скринридера.

```html
<button type="button" aria-label="Удалить задачу">
  🗑
</button>
```

Также часто используют `aria-labelledby`, когда имя уже есть в видимом тексте.

```html
<h2 id="settings-title">Настройки</h2>
<section aria-labelledby="settings-title">
  ...
</section>
```

## Связи и описания

`aria-describedby` связывает элемент с дополнительным описанием.

```html
<label for="password">Пароль</label>
<input
  id="password"
  type="password"
  aria-describedby="password-help"
>
<p id="password-help">Минимум 8 символов.</p>
```

`aria-controls` указывает, каким элементом управляет контрол.

```html
<button type="button" aria-controls="filters" aria-expanded="false">
  Фильтры
</button>
<section id="filters" hidden>...</section>
```

## Состояния

Состояния показывают, что происходит с элементом сейчас.

| Атрибут | Что описывает |
| --- | --- |
| `aria-expanded` | Раскрыт ли связанный блок |
| `aria-checked` | Отмечен ли кастомный checkbox/radio |
| `aria-selected` | Выбран ли элемент |
| `aria-disabled` | Элемент недоступен |
| `aria-invalid` | Поле содержит ошибку |
| `aria-hidden` | Скрыть элемент от accessibility tree |

## Live regions

Live regions сообщают скринридеру о динамических обновлениях.

```html
<p role="status" aria-live="polite">
  Данные сохранены
</p>
```

`polite` не перебивает пользователя, а `assertive` стоит применять только для критичных сообщений.

## Важные ограничения

- ARIA не исправляет плохую семантику автоматически.
- ARIA не добавляет клики, клавиатуру и фокус.
- `aria-hidden="true"` скрывает элемент от скринридера, поэтому его нельзя ставить на важный контент.
- Лучше не использовать ARIA, если нативный HTML уже решает задачу.

## Что важно помнить

- Приоритет доступного имени: `aria-labelledby` > `aria-label` > `label` / содержимое > `title`.
- Состояния нужно обновлять синхронно с UI: устаревший `aria-expanded` вводит пользователя в заблуждение.
- Некоторые роли требуют определенных детей: `role="list"` — `listitem`, `tablist` — `tab`.
- `aria-label` на `div` или `span` без роли обычно игнорируется скринридерами.

## Мини-шпаргалка

- `role` описывает роль.
- `aria-label` и `aria-labelledby` дают имя.
- `aria-describedby` добавляет описание.
- `aria-expanded`, `aria-invalid`, `aria-selected` описывают состояние.
- `aria-live` сообщает о динамических изменениях.
- ARIA дополняет HTML, но не заменяет поведение.
