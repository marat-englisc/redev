# Почему важно поддерживать доступность для скринридеров?

> [!NOTE]
> Скринридеры помогают пользователям воспринимать интерфейс через озвучивание или брайлевский дисплей. Для них важны семантический HTML, правильные имена элементов, структура заголовков, label и понятные состояния.

## Вопрос

Как скринридеры воспринимают страницу и что нужно для их поддержки?

## Главное

Скринридер не "видит" дизайн как человек. Он работает с accessibility tree, который строится на основе HTML, ARIA и состояния элементов.

```text
HTML + ARIA + state
  -> accessibility tree
  -> screen reader announces UI
```

## Семантика

```html
<main>
  <h1>Настройки</h1>
  <button type="button">Сохранить</button>
</main>
```

Скринридер понимает: это основное содержимое, заголовок первого уровня и кнопка.

## Accessible name

Интерактивный элемент должен иметь понятное имя.

```html
<button type="button" aria-label="Закрыть окно">
  ×
</button>
```

Если внутри кнопки только символ или иконка, `aria-label` помогает объяснить действие.

## Формы

```html
<label for="password">Пароль</label>
<input id="password" name="password" type="password">
```

Без label пользователь может не понять, что нужно ввести.

## Динамические сообщения

Для важных сообщений можно использовать live regions.

```html
<p role="status" aria-live="polite">
  Настройки сохранены
</p>
```

Скринридер сможет озвучить изменение без ручного поиска на странице.

## Что важно помнить

- Популярные скринридеры: NVDA и JAWS на Windows, VoiceOver на macOS и iOS, TalkBack на Android.
- Текст для скринридера без визуального отображения прячут классом `visually-hidden`, а не `display: none`.
- `aria-live` должен существовать в DOM заранее: регион, добавленный вместе с текстом, часто не озвучивается.
- `aria-hidden="true"` на элементе с фокусом создает «призрачный» фокус — так делать нельзя.

## Мини-шпаргалка

- Скринридеры опираются на accessibility tree.
- Семантический HTML важнее набора `div`.
- У кнопок и ссылок должны быть понятные имена.
- Полям формы нужны label.
- Иконочные кнопки требуют текстовой альтернативы.
- Для динамических сообщений используют `aria-live` или `role="status"`.
