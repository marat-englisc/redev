# Что такое a11y и почему доступность важна?

> [!NOTE]
> **a11y** — сокращение от accessibility: между первой буквой `a` и последней `y` 11 букв. Доступность означает, что интерфейсом могут пользоваться люди с разными возможностями и способами взаимодействия: с клавиатуры, скринридера, экранной лупы, голосового управления, на слабом устройстве. Недоступный интерфейс может полностью заблокировать действие — заказ, регистрацию, оплату.

## Вопрос

Что означает термин «a11y»? Почему доступность важна в веб-разработке и кого она затрагивает?

## Основная идея

Доступность — не отдельная «фича», а качество интерфейса, как скорость или надежность.

```text
bad accessibility
  -> user cannot complete task
  -> lost conversion
  -> legal/product risk
  -> worse UX for everyone
```

## Кого затрагивает

| Группа | Примеры потребностей |
| --- | --- |
| Пользователи скринридеров | Семантика, `alt`, правильные `label` |
| Пользователи клавиатуры | Фокус, порядок табуляции, доступные кнопки |
| Люди с нарушениями зрения | Контраст, масштабирование, понятная структура |
| Люди с нарушениями слуха | Субтитры, текстовые альтернативы аудио |
| Люди с моторными ограничениями | Крупные цели клика, отсутствие ловушек фокуса |
| Люди с когнитивными особенностями | Простой язык, предсказуемость, понятные ошибки |
| Временные ситуации | Сломанная рука, яркое солнце, шум, медленный интернет |

Около 15% людей в мире живут с той или иной формой инвалидности, а временные ограничения бывают у каждого.

## Что входит в a11y

- семантическая разметка и правильные заголовки;
- подписи к полям форм и понятные ошибки;
- альтернативный текст для изображений;
- клавиатурная навигация и видимый фокус;
- достаточный контраст;
- субтитры и расшифровки;
- предсказуемое поведение и уважение к системным настройкам (`prefers-reduced-motion`, масштаб).

## Пример

```html
<label for="email">Email</label>
<input id="email" name="email" type="email" required>

<button type="button">Открыть меню</button>
```

Такой код удобнее всем: по подписи можно кликнуть, браузер понимает тип поля, скринридер озвучивает label, кнопка работает с клавиатуры. Если сделать кнопку из `div`, доступность придется восстанавливать вручную.

## Стандарты

**WCAG** (Web Content Accessibility Guidelines) — международный стандарт доступности. Он построен на четырех принципах **POUR**:

| Принцип | Смысл |
| --- | --- |
| Perceivable | контент можно воспринять: alt, субтитры, контраст |
| Operable | интерфейсом можно управлять: клавиатура, достаточно времени |
| Understandable | понятный текст и предсказуемое поведение |
| Robust | совместимость с assistive technologies |

Уровни соответствия: A, AA, AAA. Ориентир для большинства продуктов — **AA**. В ряде стран доступность закреплена законом (например, European Accessibility Act с 2025 года).

## Что важно помнить

- Доступность не сводится к ARIA: первый шаг — правильные HTML-элементы `button`, `a`, `label`, `fieldset`, `main`, `nav`.
- Доступность дешевле закладывать с начала, чем исправлять в готовом продукте.
- Accessible-интерфейс обычно означает и более качественный код: явные состояния, понятная структура компонентов.
- Автоматические инструменты (axe, Lighthouse) находят только часть проблем — нужна ручная проверка с клавиатурой и скринридером.

## Мини-шпаргалка

- `a11y` = accessibility (11 букв между `a` и `y`).
- Касается не только незрячих: клавиатура, контраст, моторика, когнитивные и временные ограничения.
- Стандарт — WCAG, принципы POUR, ориентир — уровень AA.
- Семантический HTML решает большую часть задач.
- Доступность проектируют с самого начала.
