# Что такое ARIA (Accessible Rich Internet Applications)?

> [!NOTE]
> **ARIA** (Accessible Rich Internet Applications) - это набор атрибутов, которые помогают описывать роли, состояния и свойства интерфейса для assistive technologies, когда нативной HTML-семантики недостаточно.

## Вопрос

Что такое ARIA? Когда ARIA нужна, а когда вредна?

## Главное

ARIA дополняет HTML, но не заменяет его. Сначала нужно выбрать правильный HTML-элемент, и только потом добавлять ARIA, если без него интерфейс остается непонятным.

```html
<!-- лучше: нативная кнопка -->
<button type="button">Открыть меню</button>

<!-- хуже: div требует ручного восстановления поведения -->
<div role="button" tabindex="0">Открыть меню</div>
```

Правило для собеседования: **No ARIA is better than bad ARIA**. Неправильная ARIA может ухудшить доступность.

## Что умеет ARIA

ARIA может:

- задать роль элемента;
- дать доступное имя;
- описать состояние;
- связать элемент с подсказкой или ошибкой;
- сообщить о динамическом обновлении;
- помочь описать сложный кастомный компонент.

## Пример aria-label

Если кнопка содержит только иконку, ей нужно доступное имя.

```html
<button type="button" aria-label="Закрыть окно">
  ×
</button>
```

Визуально пользователь видит символ, а скринридер озвучивает действие.

## Пример aria-expanded

```html
<button
  type="button"
  aria-expanded="false"
  aria-controls="main-menu"
>
  Меню
</button>

<nav id="main-menu" hidden>
  ...
</nav>
```

`aria-expanded` сообщает, раскрыт ли связанный блок.

## Когда ARIA нужна

- Кастомные dropdown, tabs, accordion, modal.
- Иконочные кнопки без текста.
- Динамические сообщения.
- Связь ошибки с полем формы.
- Уточнение назначения одинаковых навигационных блоков.

## Когда ARIA не нужна

Если есть нативный HTML-элемент с нужной семантикой, лучше использовать его.

```html
<!-- не нужно role="button" -->
<button type="button">Сохранить</button>
```

## Что важно помнить

- Первое правило ARIA: если есть нативный HTML-элемент с нужной семантикой и поведением, используйте его.
- Готовые проверенные паттерны виджетов (tabs, combobox, dialog) описаны в ARIA Authoring Practices Guide.
- Библиотеки Radix UI, React Aria и Headless UI реализуют ARIA-паттерны и клавиатуру — это надежнее самописных решений.
- По статистике WebAIM страницы с ARIA в среднем содержат больше ошибок доступности, чем без нее.

## Мини-шпаргалка

- ARIA описывает роли, свойства и состояния для assistive technologies.
- Сначала семантический HTML, потом ARIA.
- Плохая ARIA может навредить.
- `aria-label` дает доступное имя.
- `aria-expanded` описывает раскрытое состояние.
- ARIA не добавляет поведение: клавиатуру и фокус нужно реализовать отдельно.
