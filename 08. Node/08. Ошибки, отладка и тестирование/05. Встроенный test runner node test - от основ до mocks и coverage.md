# Встроенный test runner node test - от основ до mocks и coverage

> [!NOTE]
> В Node.js есть встроенный test runner, который запускается командой `node --test`. Он позволяет писать тесты без обязательной установки Jest, Vitest или Mocha.
>
> `node:test` давно вышел за рамки минимального `test()`: есть `describe`/`it`, hooks, mocks, timers, coverage, reporters, tags, watch mode и programmatic runner. Для backend-библиотек этого часто достаточно без Jest/Vitest.

## Вопрос

Как писать тесты на встроенном test runner `node:test` и когда его достаточно?

## Минимальный тест

```js
import test from 'node:test';
import assert from 'node:assert/strict';

test('sum adds two numbers', () => {
  assert.equal(2 + 2, 4);
});
```

Запуск:

```bash
node --test
```

Node.js найдет тестовые файлы по стандартным шаблонам и запустит их.

## Async-тест

```js
import test from 'node:test';
import assert from 'node:assert/strict';

async function getUser() {
  return { id: 1, name: 'Анна' };
}

test('getUser returns user', async () => {
  const user = await getUser();

  assert.deepEqual(user, { id: 1, name: 'Анна' });
});
```

## subtest

```js
import test from 'node:test';
import assert from 'node:assert/strict';

test('math', async (t) => {
  await t.test('addition', () => {
    assert.equal(1 + 1, 2);
  });
});
```

## Когда хватает встроенного runner?

Он хорош для:

- библиотек;
- утилит;
- backend-модулей;
- небольших сервисов;
- проектов, где не нужны тяжелые UI-возможности тестового фреймворка.

## Describe и it

```js
import { describe, it } from 'node:test';
import assert from 'node:assert/strict';

describe('calculator', () => {
  it('adds numbers', () => {
    assert.equal(2 + 2, 4);
  });
});
```

## Hooks

```js
import { before, after, beforeEach, afterEach, it } from 'node:test';

before(async () => {
  await startDatabase();
});

after(async () => {
  await stopDatabase();
});

beforeEach(async () => {
  await clearDatabase();
});

it('creates user', async () => {
  // test
});
```

## Mocks

```js
import { it, mock } from 'node:test';
import assert from 'node:assert/strict';

it('calls logger', () => {
  const logger = {
    info() {},
  };

  const spy = mock.method(logger, 'info');

  logger.info('hello');

  assert.equal(spy.mock.callCount(), 1);
});
```

## Mock timers

```js
import { it, mock } from 'node:test';
import assert from 'node:assert/strict';

it('waits', () => {
  mock.timers.enable({
    apis: ['setTimeout'],
  });

  let done = false;
  setTimeout(() => {
    done = true;
  }, 1000);

  mock.timers.tick(1000);

  assert.equal(done, true);
  mock.timers.reset();
});
```

## Coverage

```bash
node --test --experimental-test-coverage
```

В CI можно настроить coverage reporter и пороги через внешние инструменты или анализ output.

## Filtering и watch

```bash
node --test --test-name-pattern "creates user"
node --test --watch
```

## Когда брать Vitest/Jest?

Бери Vitest/Jest, если нужны:

- frontend DOM окружение;
- snapshot tooling привычного формата;
- rich plugin ecosystem;
- framework-specific utilities;
- existing project convention.

## Что важно помнить

- Запуск — `node --test`; файлы находятся по шаблонам `*.test.js`, `test/**` и подобным.
- Проверки — через `node:assert/strict`: `equal`, `deepEqual`, `rejects`, `throws`.
- Есть `describe`/`it`, хуки, `mock.fn`, `mock.method`, `mock.timers`, coverage и watch.
- Для frontend с DOM и экосистемой плагинов обычно выбирают Vitest или Jest.

## Мини-шпаргалка

- Запуск: `node --test`.
- Тесты пишутся через `node:test`.
- Проверки удобно делать через `node:assert/strict`.
- Поддерживаются async-тесты.
- Для сложного frontend-окружения чаще берут Vitest или Jest.
- `node --test` - запуск.
- `describe`/`it` - BDD-style.
- `before`/`after` - lifecycle.
- `mock.method`/`mock.fn` - mocks.
- `mock.timers` - fake timers.
- Coverage есть через CLI flag.
