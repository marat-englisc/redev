# Как отлаживать Node.js приложение?

> [!NOTE]
> Node.js-приложение можно отлаживать через логи, stack trace, встроенный inspector, breakpoints в IDE, флаг `--inspect`, профилирование и тесты, которые воспроизводят проблему.

## Вопрос

Как отлаживать Node.js-приложение?

## Логи

Самый простой инструмент - осмысленные логи.

```js
console.log('request received', {
  method: req.method,
  url: req.url,
});
```

Для production обычно используют логгеры вроде `pino` или `winston`, чтобы получать структурированные JSON-логи.

## Stack trace

Ошибка содержит стек вызовов:

```js
try {
  await run();
} catch (error) {
  console.error(error.stack);
}
```

Стек помогает понять, где ошибка была создана и через какие вызовы прошла.

## Inspector

Node.js можно запустить в режиме отладки:

```bash
node --inspect app.js
```

Для остановки на первой строке:

```bash
node --inspect-brk app.js
```

После этого можно подключиться через Chrome DevTools или IDE и ставить breakpoints.

## Debug-подход

Хорошая последовательность:

1. Воспроизвести баг стабильно.
2. Сузить место ошибки.
3. Проверить входные данные.
4. Проверить состояние перед ошибкой.
5. Написать тест на найденный сценарий.

## Что важно помнить

- `node --inspect` (или `--inspect-brk` с паузой на первой строке) открывает отладчик для Chrome DevTools и VS Code.
- Инструкция `debugger;` ставит точку останова при подключенном отладчике.
- `--watch` перезапускает процесс при изменении файлов.
- Не открывайте inspector-порт наружу в production — он дает полный доступ к процессу.

## Мини-шпаргалка

- `console.log` полезен, но не должен быть единственным инструментом.
- `error.stack` показывает цепочку вызовов.
- `node --inspect` включает debugger.
- `node --inspect-brk` останавливает выполнение на старте.
- Лучший фикс бага часто начинается с воспроизводящего теста.
