# Что такое жизненный цикл Node.js процесса?

> [!NOTE]
> Жизненный цикл Node.js процесса начинается с запуска команды, загрузки entry point, выполнения синхронного кода и регистрации асинхронных задач. Процесс завершается, когда event loop больше нечего выполнять или когда он завершен явно.

## Вопрос

Как устроен жизненный цикл Node.js-процесса от запуска до завершения?

## Базовый сценарий

```bash
node app.js
```

Что происходит:

1. ОС создает процесс.
2. Node.js инициализирует runtime.
3. Загружается entry point.
4. Выполняется верхнеуровневый код.
5. Запускается event loop.
6. Процесс живет, пока есть активные handles или tasks.

## Почему процесс не завершается?

```js
setInterval(() => {
  console.log('tick');
}, 1000);
```

Активный interval удерживает event loop живым.

HTTP-сервер тоже удерживает процесс:

```js
import http from 'node:http';

http.createServer((req, res) => {
  res.end('ok');
}).listen(3000);
```

## Завершение

```js
process.exitCode = 1;
```

`process.exitCode` говорит, с каким кодом завершиться, когда процесс естественно дойдет до конца.

Для серверов важен graceful shutdown:

```js
process.on('SIGTERM', () => {
  server.close(() => {
    process.exitCode = 0;
  });
});
```

## Что важно помнить

- Запуск: инициализация V8 и libuv → выполнение главного модуля → работа event loop.
- Процесс живет, пока есть активные handles: серверы, таймеры, сокеты; `unref()` разрешает выйти, не дожидаясь их.
- События `beforeExit` и `exit`: в `exit` можно выполнять только синхронный код.
- Сигналы `SIGTERM` и `SIGINT` обрабатывают для корректного завершения.

## Мини-шпаргалка

- Entry point - файл, который запускают командой `node`.
- Процесс живет, пока есть активные задачи, timers, servers, streams.
- `process.exitCode` мягче, чем немедленный `process.exit()`.
- Сервер нужно закрывать через `server.close`.
- Для production важны `SIGTERM` и graceful shutdown.
