# Что такое package-lock.json и зачем нужен lockfile?

> [!NOTE]
> Lockfile фиксирует точные версии установленных зависимостей и их вложенных зависимостей. В npm таким файлом является `package-lock.json`; он нужен для воспроизводимых установок на разных машинах и в CI.

## Вопрос

Что такое package-lock.json и зачем нужен lockfile?

## package.json vs package-lock.json

`package.json` описывает допустимые версии:

```json
{
  "dependencies": {
    "express": "^5.1.0"
  }
}
```

`^5.1.0` разрешает обновления внутри major-версии. Сегодня и завтра npm может выбрать разные patch/minor версии.

`package-lock.json` фиксирует конкретное дерево зависимостей.

## Почему lockfile коммитят?

Lockfile нужен, чтобы:

- разработчики получали одинаковые версии;
- CI собирал проект предсказуемо;
- деплой не зависел от случайного обновления пакета;
- быстрее искать, какое обновление сломало проект;
- точнее анализировать уязвимости.

## npm install vs npm ci

| Команда | Когда использовать |
|---|---|
| `npm install` | локальная разработка, изменение зависимостей |
| `npm ci` | чистая установка в CI по lockfile |

`npm ci` удаляет `node_modules` и ставит зависимости строго по lockfile.

## Нужно ли коммитить node_modules?

Обычно нет. Коммитят `package.json` и lockfile, а `node_modules` восстанавливают установкой.

## Что важно помнить

- Lockfile фиксирует точные версии всего дерева зависимостей, включая транзитивные.
- Lockfile коммитят в репозиторий — так у всех разработчиков и в CI одинаковые версии.
- В CI используют `npm ci`: устанавливает строго по lockfile и падает при расхождении с `package.json`.
- У pnpm и Yarn свои lockfile: `pnpm-lock.yaml`, `yarn.lock`; не смешивайте менеджеры в одном проекте.

## Мини-шпаргалка

- `package.json` задает диапазоны версий.
- `package-lock.json` фиксирует точные версии.
- Lockfile нужно коммитить для приложений.
- `npm ci` подходит для CI.
- `node_modules` обычно не коммитят.
