# Что такое LTS версия Node.js и какую версию выбирать?

> [!NOTE]
> **LTS** (Long Term Support) - это версия Node.js с долгосрочной поддержкой, которую обычно выбирают для production-проектов. Current-версии подходят для экспериментов с новыми возможностями.

## Вопрос

Что означает LTS-версия Node.js и какую версию выбирать для проекта?

## Главное

В Node.js есть разные линии релизов.

```text
Current -> новые возможности раньше
LTS     -> стабильность и долгосрочная поддержка
EOL     -> поддержка закончилась
```

Для рабочих проектов чаще выбирают активную LTS-версию.

## Почему LTS важна

- Исправления безопасности.
- Предсказуемость для production.
- Совместимость библиотек.
- Поддержка CI/CD и хостингов.
- Меньше риска неожиданных изменений.

## Как фиксировать версию

В проекте часто используют `.nvmrc` или поле `engines`.

```text
22
```

```json
{
  "engines": {
    "node": ">=22"
  }
}
```

Так команда понимает, на какой версии запускать проект.

## Почему нельзя жить на старой версии

Старые EOL-версии не получают обычные security-обновления. Это риск для backend-проектов, особенно если приложение работает с сетью, файлами, пользовательскими данными или зависимостями.

## Что сказать на собеседовании

Для production я выбираю активную LTS-версию Node.js, фиксирую ее в проекте и проверяю совместимость зависимостей. Current можно использовать, если нужна новая возможность и команда осознанно принимает риск.

## Что важно помнить

- Четные мажорные версии становятся LTS и получают поддержку около 30 месяцев.
- Для production выбирают Active или Maintenance LTS; Current — для пробы новых возможностей.
- Версию фиксируют в проекте: `.nvmrc`, `engines` в `package.json`, образ Docker.
- Используйте менеджер версий (nvm, fnm, Volta), чтобы переключаться между проектами.

## Мини-шпаргалка

- LTS = долгосрочная поддержка.
- Production обычно запускают на LTS.
- Current дает новые возможности раньше.
- EOL-версии лучше не использовать.
- Версию фиксируют через `.nvmrc`, `engines`, Docker image или CI.
