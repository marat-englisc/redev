# Что такое Node.js и для чего он используется?

> [!NOTE]
> **Node.js** - это среда выполнения JavaScript вне браузера. Она позволяет писать серверы, CLI-утилиты, скрипты автоматизации, backend-сервисы, realtime-приложения и инструменты сборки на JavaScript.

## Вопрос

Что такое Node.js, для каких задач его используют и почему он подходит для I/O-нагруженных серверов?

## Главное

Node.js запускает JavaScript на сервере или локальной машине.

```bash
node app.js
```

```js
console.log("Hello from Node.js");
```

В браузере JavaScript работает рядом с DOM и Web API. В Node.js вместо DOM есть доступ к файловой системе, процессам, сети, потокам, переменным окружения и встроенным модулям.

## Для чего используют Node.js

- HTTP API и backend-сервисы.
- CLI-инструменты.
- Скрипты автоматизации.
- Realtime через WebSocket.
- SSR и backend-for-frontend.
- Инструменты разработки: Vite, ESLint, TypeScript, npm scripts.
- Работа с файлами, очередями, интеграциями и микросервисами.

## Почему Node.js популярен

Node.js хорошо подходит для I/O-bound задач: сетевые запросы, чтение файлов, работа с базой данных, проксирование, API gateway.

```text
request
  -> async I/O
  -> callback/promise
  -> response
```

Он не создает отдельный поток на каждый запрос, а использует event loop и неблокирующие операции.

## Где Node.js не идеален

Тяжелые CPU-bound вычисления могут блокировать event loop.

```js
while (true) {
  // event loop не сможет обрабатывать другие запросы
}
```

Для CPU-heavy задач используют worker threads, отдельные сервисы, очереди или языки/рантаймы, лучше подходящие под вычисления.

## Что важно помнить

- Node.js — среда выполнения JavaScript вне браузера на базе V8 и libuv, а не язык и не фреймворк.
- Сильная сторона — много одновременных I/O-операций благодаря неблокирующей модели и event loop.
- CPU-тяжелые задачи блокируют основной поток — их выносят в worker_threads или отдельные сервисы.
- Типичные применения: API и BFF, SSR, CLI-утилиты, инструменты сборки, realtime-сервисы.

## Мини-шпаргалка

- Node.js запускает JavaScript вне браузера.
- Хорош для серверов, CLI и tooling.
- Основа модели - event loop и неблокирующий I/O.
- DOM в Node.js нет.
- Для CPU-heavy задач нужны worker threads или отдельная архитектура.
