# setTimeout, setImmediate и microtasks - порядок выполнения

> [!NOTE]
> `setTimeout()` планирует callback после минимальной задержки в фазе timers, а `setImmediate()` планирует callback в фазе check текущего или следующего цикла event loop.
>
> Timers, immediates и microtasks - разные очереди асинхронного выполнения. `setTimeout` планирует timer, `setImmediate` - callback на фазу check, а Promise microtasks и `queueMicrotask` выполняются между macrotask-этапами.

## Вопрос

Чем отличаются `setTimeout`, `setImmediate` и microtasks и в каком порядке они выполняются?

## Главное

```js
setTimeout(() => {
  console.log("timeout");
}, 0);

setImmediate(() => {
  console.log("immediate");
});
```

Порядок между ними не всегда стоит считать надежным, если они запланированы из главного модуля.

## setTimeout

```js
setTimeout(callback, delay);
```

`delay` - минимальная задержка, а не точное время выполнения. Если event loop занят, callback выполнится позже.

## setImmediate

```js
setImmediate(callback);
```

`setImmediate` выполняется в check-фазе, после poll-фазы.

## Внутри I/O callback

Внутри I/O callback `setImmediate` часто выполняется раньше `setTimeout(..., 0)`.

```js
import { readFile } from "node:fs";

readFile("file.txt", () => {
  setTimeout(() => console.log("timeout"), 0);
  setImmediate(() => console.log("immediate"));
});
```

## Что выбрать

- Нужна задержка по времени: `setTimeout`.
- Нужно выполнить callback после текущего I/O turn: `setImmediate`.
- Нужна promise-микрозадача: `queueMicrotask` или `Promise.resolve().then(...)`.

## Timers, immediates и microtasks

| API | Что делает |
|---|---|
| `setTimeout(fn, ms)` | выполнить не раньше указанной задержки |
| `setInterval(fn, ms)` | повторять с интервалом |
| `setImmediate(fn)` | выполнить на фазе check event loop |
| `queueMicrotask(fn)` | поставить microtask |
| `Promise.then(fn)` | тоже microtask |

## Пример порядка

```js
console.log('sync');

setTimeout(() => console.log('timeout'), 0);
setImmediate(() => console.log('immediate'));

Promise.resolve().then(() => console.log('promise'));
queueMicrotask(() => console.log('microtask'));

console.log('sync end');
```

Синхронный код выполнится первым, microtasks - после него, а порядок `setTimeout(0)` и `setImmediate` зависит от контекста запуска.

## Не блокировать таймеры

```js
setTimeout(() => {
  console.log('timer');
}, 0);

const end = Date.now() + 3000;

while (Date.now() < end) {}
```

Таймер не выполнится, пока синхронный цикл не освободит JS-поток.

## Что важно помнить

- Порядок: синхронный код → `process.nextTick` → Promise microtasks → фазы event loop.
- Порядок `setTimeout(fn, 0)` и `setImmediate` в главном модуле не гарантирован; внутри I/O callback `setImmediate` выполнится первым.
- Задержка таймера — минимальная, а не точная; долгий синхронный код задерживает все очереди.
- Для пауз в async-коде удобен `node:timers/promises`: `await setTimeout(1000)`.

## Мини-шпаргалка

- `setTimeout` работает через timers.
- `setImmediate` работает через check phase.
- `delay` у timeout - минимальная задержка.
- Порядок может зависеть от контекста.
- В I/O callback `setImmediate` обычно предсказуемее для "после I/O".
- Таймеры не гарантируют точное время, только минимум задержки.
- Microtasks выполняются раньше следующего macrotask-этапа.
- `setImmediate` связан с фазой check.
- Долгий синхронный код задерживает все очереди.
- Для пауз в async-коде удобно использовать `node:timers/promises`.
