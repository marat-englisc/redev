# Что такое libuv и thread pool в Node.js

> [!NOTE]
> **libuv** - низкоуровневая библиотека, на которой Node.js строит event loop, timers, async I/O и thread pool. Thread pool помогает выполнять некоторые операции, которые не могут быть полностью неблокирующими на уровне ОС.

## Вопрос

Что такое libuv и thread pool в Node.js и какие операции уходят в пул потоков?

## Главное

Node.js не выполняет всю работу только в одном JS-потоке.

```text
JavaScript thread
  -> libuv event loop
  -> OS async APIs
  -> libuv thread pool for some tasks
```

## Что может уходить в thread pool

Типичные категории:

- часть операций `fs`;
- некоторые crypto-операции;
- DNS через `dns.lookup`;
- zlib-сжатие.

```js
import { pbkdf2 } from "node:crypto";

pbkdf2("password", "salt", 100000, 64, "sha512", () => {
  console.log("done");
});
```

Такая операция не должна блокировать основной JS-поток.

## Размер thread pool

Размер thread pool можно менять через `UV_THREADPOOL_SIZE`.

```bash
UV_THREADPOOL_SIZE=8 node server.js
```

Но это не магическая оптимизация: больше потоков может помочь одним задачам и навредить другим из-за конкуренции за CPU.

## Сеть и thread pool

Сетевые операции часто используют неблокирующие возможности ОС и не обязательно занимают thread pool.

## Зачем libuv нужен Node.js?

Node.js должен одинаково работать на Windows, macOS и Linux. У разных ОС разные механизмы событий и асинхронного ввода-вывода. libuv скрывает эти различия за единым слоем.

## Что дает libuv?

| Возможность | Зачем нужна |
|---|---|
| Event loop | Управление асинхронными callback-функциями |
| Timers | `setTimeout`, `setInterval` |
| TCP/UDP | сетевые соединения |
| File system | часть операций `fs` |
| Thread pool | выполнение некоторых блокирующих задач вне JS-потока |

## Важное ограничение

libuv помогает с I/O и некоторыми native-задачами, но не спасает от тяжелого синхронного JavaScript-кода.

```js
while (true) {
  // блокирует основной JS-поток
}
```

## Что важно помнить

- По умолчанию в thread pool 4 потока; размер меняет `UV_THREADPOOL_SIZE` (задается до запуска процесса).
- В пул уходят часть `fs`, `dns.lookup`, `crypto.pbkdf2`/`scrypt`, `zlib`.
- Сетевые операции используют неблокирующие механизмы ОС (epoll, kqueue, IOCP) и пул не занимают.
- libuv не спасает от тяжелого синхронного JavaScript.

## Мини-шпаргалка

- libuv обеспечивает event loop Node.js.
- Thread pool нужен для части fs, crypto, dns, zlib.
- JS callback возвращается в основной поток.
- `UV_THREADPOOL_SIZE` меняет размер пула.
- CPU-heavy JS все равно блокирует event loop, если не вынести его в worker.
- libuv дает Node.js event loop.
- libuv абстрагирует различия ОС.
- Сеть в Node.js работает через неблокирующие механизмы ОС.
- Некоторые операции идут через thread pool.
- Тяжелый JS-код все равно блокирует event loop.
