# Что такое CORS на Node.js сервере?

> [!NOTE]
> CORS - браузерный механизм безопасности, который контролирует, может ли frontend с одного origin читать ответ сервера на другом origin. Node.js-сервер управляет CORS через HTTP-заголовки.

## Вопрос

Что такое CORS и как его настроить на Node.js-сервере?

## Что такое origin?

Origin состоит из протокола, домена и порта.

```txt
https://example.com:443
```

Эти адреса имеют разные origin:

```txt
http://localhost:3000
http://localhost:5173
https://api.example.com
```

## Главный заголовок

```js
res.setHeader('Access-Control-Allow-Origin', 'https://app.example.com');
```

Так сервер говорит браузеру: frontend с этого origin может читать ответ.

## Preflight

Для некоторых запросов браузер сначала отправляет `OPTIONS`-запрос.

```js
if (req.method === 'OPTIONS') {
  res.writeHead(204, {
    'Access-Control-Allow-Origin': 'https://app.example.com',
    'Access-Control-Allow-Methods': 'GET,POST,PUT,DELETE',
    'Access-Control-Allow-Headers': 'Content-Type, Authorization',
  });

  res.end();
  return;
}
```

## CORS не защищает сервер

CORS ограничивает браузерный JavaScript, но не мешает curl, Postman или backend-сервису отправить запрос. Поэтому авторизация и валидация все равно обязательны.

## Что важно помнить

- CORS — механизм браузера; сервер разрешает чужие origin заголовками `Access-Control-Allow-*`.
- Запросы с нестандартными методами или заголовками сначала отправляют preflight `OPTIONS`.
- С `credentials` нельзя использовать `Access-Control-Allow-Origin: *` — нужен конкретный origin.
- CORS не защищает сервер от запросов с других клиентов — это не замена авторизации.

## Мини-шпаргалка

- CORS - браузерная политика доступа к ответам.
- Настраивается HTTP-заголовками сервера.
- `OPTIONS` preflight проверяет разрешения перед сложным запросом.
- `Access-Control-Allow-Origin: *` нельзя использовать вместе с credentials.
- CORS не заменяет авторизацию.
