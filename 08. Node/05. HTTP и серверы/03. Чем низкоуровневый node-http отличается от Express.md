# Чем низкоуровневый node-http отличается от Express?

> [!NOTE]
> `node:http` дает базовые строительные блоки HTTP-сервера, а Express добавляет удобный слой: роутинг, middleware, парсинг body, обработку ошибок и привычный API для веб-приложений.

## Вопрос

Чем низкоуровневый `node:http` отличается от Express и что дает фреймворк?

## node-http

`node:http` ничего не навязывает. Ты сам проверяешь метод, путь, заголовки и тело.

```js
import http from 'node:http';

http.createServer((req, res) => {
  if (req.method === 'GET' && req.url === '/users') {
    res.end('users');
    return;
  }

  res.statusCode = 404;
  res.end('not found');
}).listen(3000);
```

Плюсы:

- нет зависимостей;
- понятно, как работает HTTP;
- хорошо для учебных задач и простых внутренних серверов.

Минусы:

- быстро появляется много ручной логики;
- неудобно масштабировать роутинг;
- больше шансов забыть обработку ошибок и edge cases.

## Express

Express строится поверх HTTP-механик Node.js, но дает более удобный интерфейс.

```js
import express from 'express';

const app = express();

app.use(express.json());

app.get('/users', (req, res) => {
  res.json([{ id: 1, name: 'Анна' }]);
});

app.listen(3000);
```

## Что важно на собеседовании?

Фреймворк не заменяет понимание HTTP. Если ты понимаешь `req`, `res`, заголовки, статус-коды и streams, Express становится просто удобной оберткой.

## Что важно помнить

- Express добавляет роутинг, middleware, парсинг body, удобные `res.json` и `res.status`.
- Express 5 сам обрабатывает отклоненные промисы в async-обработчиках.
- Альтернативы: Fastify (скорость, схемы), Koa, Hono, NestJS (архитектура).
- Под капотом все фреймворки используют тот же `node:http`.

## Мини-шпаргалка

- `node:http` - низкий уровень.
- Express - фреймворк поверх HTTP-сервера.
- Express удобнее для роутинга и middleware.
- Для обучения полезно написать сервер на чистом `node:http`.
- На production чаще берут Express, Fastify, NestJS или похожие фреймворки.
