# Лабораторная - развернуть и проверить службу demo-web

> [!NOTE]
> Полный цикл развёртывания включает подготовку пользователя и файлов, unit, проверку синтаксиса, запуск, HTTP-проверку, журнал и остановку. В стенде demo-web работает от отдельного UID и слушает только loopback. Это учебный файловый HTTP-сервер Python, не production-платформа. Все системные изменения выполняются в отдельной Ubuntu/Debian VM с systemd.

## Вопрос

Как запустить сервис после загрузки, ограничить его права и доказать, что он отвечает правильно?

## Предусловия

PID 1 — systemd, есть sudo и свободен порт 8080. В WSL сначала проверь поддержку systemd. Сохрани snapshot VM. Если имя demoapp уже занято, проверь назначение пользователя, а не переиспользуй чужую учётную запись.

```bash
sudo apt update
sudo apt install python3 curl
ss -ltn 'sport = :8080'
getent passwd demoapp
```

Для новой VM создай пользователя, если он ещё не был создан в уроке про UID:

```bash
sudo useradd --system --user-group --home-dir /nonexistent --shell /usr/sbin/nologin demoapp
```

## Подготовка содержимого

```bash
sudo install -d -o root -g root -m 755 /srv/demo-web/public
printf 'linux-lab-ok\n' | sudo tee /srv/demo-web/public/index.html > /dev/null
sudo chmod 644 /srv/demo-web/public/index.html
sudo -u demoapp cat /srv/demo-web/public/index.html
```

Служба читает публичный учебный файл, но не владеет кодом и не должна его менять. Проверка `sudo -u` подтверждает обычное чтение; sandbox systemd затем проверяется фактическим запуском.

## Unit

```bash
sudo tee /etc/systemd/system/demo-web.service > /dev/null <<'EOF'
[Unit]
Description=Linux study HTTP server

[Service]
Type=exec
User=demoapp
Group=demoapp
WorkingDirectory=/srv/demo-web/public
ExecStart=/usr/bin/python3 -m http.server 8080 --bind 127.0.0.1
Environment=PYTHONUNBUFFERED=1
Restart=on-failure
RestartSec=3
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true

[Install]
WantedBy=multi-user.target
EOF
sudo systemd-analyze verify /etc/systemd/system/demo-web.service
sudo systemctl daemon-reload
sudo systemctl enable --now demo-web.service
```

## Критерии готовности

```bash
systemctl is-active demo-web.service
systemctl is-enabled demo-web.service
systemctl show demo-web.service -p MainPID -p User
ss -ltn 'sport = :8080'
curl --fail --max-time 5 http://127.0.0.1:8080/
journalctl -u demo-web.service -n 20 --no-pager
```

Ожидается active, enabled, пользователь demoapp, listener `127.0.0.1:8080` и тело `linux-lab-ok`. Список критериев проверяет разные слои. Для доступа с клиента используй SSH-туннель из соответствующего урока.

## Остановка и очистка

После лабораторной с инцидентами можно удалить **только созданные здесь** объекты:

```bash
sudo systemctl disable --now demo-web.service
sudo rm -- /etc/systemd/system/demo-web.service
sudo systemctl daemon-reload
sudo rm -- /srv/demo-web/public/index.html
sudo rmdir /srv/demo-web/public /srv/demo-web
```

`rmdir` откажется удалять непустые каталоги, если там появилось что-то ещё. Пользователя demoapp удаляй отдельно только после проверки, что он больше нигде не используется. Установленные Python и curl могут пригодиться другим упражнениям.
