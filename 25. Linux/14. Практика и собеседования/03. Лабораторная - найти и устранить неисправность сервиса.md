# Лабораторная - найти и устранить неисправность сервиса

> [!NOTE]
> Диагностика — цикл «симптом → гипотеза → проверка → минимальное исправление → повторная проверка». Для упражнения ломают только собственный demo-web и меняют один фактор за раз. Правильный ответ включает подтверждённую причину и наблюдаемый результат восстановления, а не только команду restart.

## Вопрос

Как разобрать несколько типичных инцидентов и не спутать отсутствие процесса, неправильный HTTP-ответ и сетевую недоступность?

## Подготовка

Сначала выполни лабораторную развёртывания demo-web в отдельной VM. Убедись, что curl возвращает `linux-lab-ok`. После каждого сценария восстанови исходное состояние, прежде чем переходить дальше.

## Сценарий A: служба остановлена

```bash
sudo systemctl stop demo-web.service
curl --max-time 3 http://127.0.0.1:8080/
systemctl status demo-web.service --no-pager
ss -ltn 'sport = :8080'
```

**Наблюдение:** нет слушателя, запрос обычно получает connection refused. **Исправление:** `sudo systemctl start demo-web.service`. **Проверка:** listener и правильное тело HTTP. Enabled не означает, что служба сейчас работает.

## Сценарий B: содержимое файла недоступно

```bash
sudo chmod 000 /srv/demo-web/public/index.html
curl -i --max-time 3 http://127.0.0.1:8080/index.html
sudo -u demoapp cat /srv/demo-web/public/index.html
namei -l /srv/demo-web/public/index.html
journalctl -u demo-web.service -n 20 --no-pager
```

**Наблюдение:** процесс и порт живы, но файл не читается. Python может вернуть 404 с сообщением об отказе доступа: HTTP-код не всегда напрямую отражает Unix errno. **Исправление:** `sudo chmod 644 /srv/demo-web/public/index.html`. **Проверка:** повторный GET возвращает ожидаемое тело.

## Сценарий C: неверный cwd службы

Создай отдельный drop-in только для стенда:

```bash
sudo install -d /etc/systemd/system/demo-web.service.d
printf '[Service]\nWorkingDirectory=/srv/demo-web/missing\n' | sudo tee /etc/systemd/system/demo-web.service.d/study-broken.conf > /dev/null
sudo systemctl daemon-reload
sudo systemctl restart demo-web.service
systemctl status demo-web.service --no-pager
journalctl -u demo-web.service -n 30 --no-pager
```

**Наблюдение:** ошибка перехода в рабочий каталог, возможен `status=200/CHDIR` и повторные запуски. `systemctl cat demo-web.service` покажет и основной файл, и override.

Восстановление:

```bash
sudo systemctl stop demo-web.service
sudo rm -- /etc/systemd/system/demo-web.service.d/study-broken.conf
sudo systemctl daemon-reload
sudo systemctl reset-failed demo-web.service
sudo systemctl start demo-web.service
curl --fail --max-time 5 http://127.0.0.1:8080/
```

## Контрольные кейсы без поломки системы

| Симптом | Первая проверка | Следующий шаг |
| --- | --- | --- |
| Локально работает, с клиента нет | Bind-адрес | SSH-туннель или анализ сети |
| `No space left on device` | `df -h`, `df -i` нужной ФС | Рост файлов, открытые удалённые логи |
| Exit 137 | Журнал и cgroup events | Подтвердить или отвергнуть OOM |
| Высокий load при низком CPU | Состояния D, I/O latency | Хранилище, сетевые mount |

Не заполняй диск, не исчерпывай RAM и не отключай SSH для имитации этих случаев.

## Практика

Для каждого сценария запиши пять строк: симптом, гипотеза, доказательство, исправление, проверка. Если restart помог без найденной причины, диагностика ещё не завершена.
