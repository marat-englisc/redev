# Вопросы на собеседовании Linux - Junior и Junior+ - pre-middle

> [!NOTE]
> Сильный ответ по Linux соединяет понятие с проверкой: что происходит, какой командой это увидеть, как интерпретировать результат и где границы вывода. Для Junior важны уверенные файлы, shell, права, процессы и SSH. Для Junior+ / pre-middle — самостоятельная диагностика служб, сети и ресурсов, Bash-автоматизация и проверяемое восстановление.

## Вопрос

Как проверить готовность к Linux-интервью и отличить понимание системы от запоминания команд?

## Как тренироваться

Сначала ответь без подсказки за 30–60 секунд. Затем приведи команду и объясни возможные исходы. Колонка справа — опорная мысль, а не полный ответ. Для подробного разбора вернись в соответствующую тему курса.

## Основы и shell

| Вопрос | Что должно прозвучать |
| --- | --- |
| Linux, Ubuntu и Bash — что это? | Ядро, дистрибутив, оболочка; разные роли |
| Абсолютный и относительный путь? | `/` против cwd процесса |
| Что делает `*.log`? | Shell раскрывает glob до запуска команды |
| Почему `"$var"` важен? | Сохраняет границу аргумента, защищает от split и glob |
| Что передаёт pipe? | Stdout как поток байтов на stdin, не аргументы |
| `>out 2>&1` и `2>&1 >out`? | Последовательное копирование назначения дескрипторов |
| Что возвращает grep без совпадений? | 1; отличается от ошибки чтения |
| Почему `false | cat` может быть успешным? | Без pipefail учитывается последний этап |
| Где хранить конфиг и меняющиеся данные? | Обычно `/etc` и `/var/lib`, с учётом приложения |

## Файлы и полномочия

| Вопрос | Что должно прозвучать |
| --- | --- |
| Hard link против symlink? | Один inode против отдельной ссылки-пути |
| Что означает `640`? | Владелец rw, группа r, остальные без доступа |
| Что означает `x` у каталога? | Возможность прохода по имени |
| Почему файл с `444` можно удалить? | Проверяются права родительского каталога и дополнительные ограничения |
| Что делает umask `027`? | Снимает биты при создании; типично файл 640, каталог 750 без default ACL |
| Почему sudo не исправляет любое Permission denied? | Есть MAC, sandbox, mount flags; сначала локализовать слой |
| Зачем sticky bit в `/tmp`? | Ограничивает удаление чужих записей при общем каталоге |

## Процессы и службы

| Вопрос | Что должно прозвучать |
| --- | --- |
| TERM против KILL? | Возможность graceful shutdown; KILL не обрабатывается |
| Что такое zombie? | Уже завершён, родитель ещё не забрал статус |
| Почему 137 не доказывает OOM? | SIGKILL имеет разные причины; нужны события и журналы |
| Active и enabled? | Текущая работа против настройки включения |
| Reload, restart, daemon-reload? | Конфиг приложения, новый процесс, перечитывание unit-файлов |
| Почему работает в терминале, но не в systemd? | Другие UID, cwd, env, лимиты и sandbox |
| Где искать причину падения? | Journal нужного unit и времени, сообщения перед выходом |
| Зачем ulimit и почему shell не меняет лимит службы? | Наследуемые process limits; контексты запуска разные |

## Сеть, ресурсы и автоматизация

| Вопрос | Что должно прозвучать |
| --- | --- |
| `127.0.0.1` против `0.0.0.0` у listener? | Только loopback против всех локальных IPv4-адресов |
| Ping проходит, HTTP нет — почему? | ICMP не проверяет TCP-порт, TLS и HTTP |
| DNS, refused, timeout и 500? | Разные этапы и разные гипотезы |
| Почему dig и getent расходятся? | DNS-запрос против системного пути разрешения имён |
| Для чего SSH host key? | Проверка сервера, отдельно от пользовательского ключа |
| Почему df не совпадает с du? | Открытые удалённые файлы, mount, права, метаданные и другие причины |
| Есть место, файл не создаётся? | Inode, квота, конкретная ФС, read-only — проверить точную ошибку |
| Free мало, cached много — авария? | Смотрим available и давление, а не одну колонку |
| Load выше числа CPU — CPU точно забит? | Нет; Linux включает задачи в непрерываемом ожидании |
| Почему скрипт нельзя считать надёжным только с `set -e`? | Контекстные исключения; нужны явные проверки и сценарии отказа |
| Что доказывает успешное создание backup? | Только этап создания; требуется восстановление и проверка данных |
| Namespaces и cgroups? | Видимость против учёта и ограничений ресурсов |

## Ситуационная задача

«После релиза сервис даёт 502. Ты вошёл по SSH. Что дальше?»

Хорошая последовательность: зафиксировать время и изменения → проверить ответ proxy и прямой upstream → listener и unit → журнал → конфигурацию, права и ресурсы → минимальное исправление или подготовленный rollback → проверить реальный запрос и наблюдать.

Слабый ответ: «перезагружу сервер», без доказательств и плана проверки.

## Критерии готовности

- Ты решаешь лабораторные по файлам и demo-web с объяснением каждой команды.
- Для незнакомой опции находишь man и проверяешь синтаксис.
- Для каждой гипотезы называешь наблюдение, которое её опровергнет.
- Умеешь восстановить состояние после собственного изменения.

Названия грейдов различаются между компаниями. Этот раздел задаёт практическую базу, а не обещает результат конкретного интервью.
