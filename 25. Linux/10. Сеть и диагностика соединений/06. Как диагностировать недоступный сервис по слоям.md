# Как диагностировать недоступный сервис по слоям

> [!NOTE]
> Диагностика соединения идёт от точного симптома к проверяемой гипотезе: имя → маршрут → порт → TLS → приложение. `ping` проверяет ICMP, а не работоспособность HTTP. `Connection refused`, timeout и HTTP 500 описывают разные этапы. Сравнение запроса на сервере и с клиента помогает локализовать границу неисправности.

## Вопрос

Пользователь сообщает «сайт не работает». Какие проверки выполнить и что каждая из них действительно доказывает?

## Начни с фактов

Уточни URL, порт, время, клиента, текст ошибки и последние изменения. «Недоступно» может означать DNS timeout, TLS mismatch, 403, медленный запрос или пустую страницу.

| Этап | Проверка | Что выясняем |
| --- | --- | --- |
| Имя | `getent ahosts имя` | Какие адреса получает системный resolver |
| Маршрут | `ip route get IP` | Куда машина направит пакет |
| Локальный listener | `ss -ltnp` на сервере | Кто слушает адрес и порт |
| HTTP | curl с timeout | Устанавливается ли соединение и что вернул сервер |
| Процесс | systemctl, journalctl | Жива ли служба, что пишет журнал |
| Ресурсы | df, free, vmstat | Не ограничен ли сервер ресурсами |

## Как читать симптомы

- **Refused**: обычно соединение активно отвергнуто, например нет слушателя или сработал reject. Это не обязательно ошибка DNS.
- **Timeout**: ответа вовремя нет; возможны drop, маршрут, недоступный узел или перегрузка. Одного timeout недостаточно для вывода.
- **TLS error**: соединение дошло до TLS-проверки; изучи имя, цепочку, срок и время клиента.
- **HTTP 500**: получен HTTP-ответ об ошибке; исследуй приложение и зависимости.

## Сравнение двух точек

На сервере:

```bash
curl --fail --max-time 5 http://127.0.0.1:8080/
ss -ltn 'sport = :8080'
```

Если локально работает, а с другой машины нет, проверь bind, сеть и firewall. Если локально тоже нет — сначала процесс, порт, конфигурацию и журнал.

Для сложной проблемы можно наблюдать трафик через tcpdump на **своём стенде** с узким фильтром. Наличие SYN без ответа сужает поиск, но не даёт автоматически причину. Захват способен содержать чувствительные данные и требует контроля доступа.

## Практика

Останови свой demo-web, запиши ошибку curl, запусти службу и повтори. Затем запроси отсутствующий файл и сравни HTTP 404 с сетевым отказом. Не меняй firewall ради проверки HTTP-ошибки.
