# Как диагностировать DNS - getent, dig и resolvectl

> [!NOTE]
> DNS сопоставляет имена с записями, включая A и AAAA. Разрешение имени приложением может дополнительно учитывать `/etc/hosts`, NSS, локальный кеш и другие источники. `getent hosts` проверяет системный путь разрешения имён, `dig` делает DNS-запрос, `resolvectl` исследует systemd-resolved, если он используется. Успех одного инструмента не всегда означает одинаковое поведение всех клиентов.

## Вопрос

Почему `dig` находит адрес, а приложение всё ещё не подключается? Где Linux берёт DNS-серверы?

## Несколько уровней

```text
Приложение → resolver/NSS → hosts или локальный сервис → DNS-сервер
                                                         → ответ + TTL
```

```bash
getent hosts example.com
getent ahosts example.com
dig example.com A
dig example.com AAAA
cat /etc/resolv.conf
grep '^hosts:' /etc/nsswitch.conf
```

`dig` входит в отдельный пакет, например `dnsutils` в Debian/Ubuntu. Он не обязан учитывать `/etc/hosts` так, как это делает системный resolver.

## Локальный DNS-сервис

```bash
resolvectl status
resolvectl query example.com
```

Эти команды относятся к системам с systemd-resolved. Адрес `127.0.0.53` в resolv.conf часто указывает на локальный stub, а не на внешний DNS. Файл может быть символической ссылкой и управляться сетевой службой; ручная перезапись не всегда сохраняется.

## Как читать результат

| Исход | Возможное значение |
| --- | --- |
| `NOERROR` с ответом | Запись получена |
| `NOERROR` без нужной записи | Имя может существовать без этого типа |
| `NXDOMAIN` | Запрошенное имя не существует по ответу DNS |
| `SERVFAIL` | Ошибка обработки, например проблема upstream или DNSSEC |
| Timeout | Ответ не пришёл; проверь сеть и доступность resolver |

TTL влияет на кеширование. Изменение записи на авторитетном сервере не обязано мгновенно обновить все кеши. Отдельно проверяй IPv4/IPv6: корректный AAAA с недоступной IPv6-сетью может объяснить различие клиентов.

## Практика

Сравни `getent hosts localhost` и `dig localhost`. Объясни, почему источник ответа может различаться. Для внешнего имени запиши A, AAAA и DNS-сервер, который дал ответ.

## Частые ошибки

- Подменять проверку приложения одним `ping`.
- Считать DNS-ошибкой любое соединение по имени, включая отказ порта.
- Менять системный resolver до проверки hosts, кеша и реального DNS-ответа.
