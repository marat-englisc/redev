# Как собирать отчёты - sort, uniq, cut, tr и wc

> [!NOTE]
> Небольшие текстовые утилиты удобно соединять конвейером. `sort` сортирует строки, `uniq` объединяет только соседние одинаковые строки, `cut` выбирает поля, `tr` заменяет или удаляет символы, `wc` считает строки, слова и байты. Частотный отчёт обычно строят как `sort | uniq -c | sort -nr`.

## Вопрос

Как получить самые частые значения из лога и почему `uniq` без предварительной сортировки может дать неожиданный результат?

## От исходных данных к отчёту

```bash
mkdir -p "$HOME/linux-lab/reports"
cd "$HOME/linux-lab/reports"
printf 'anna,200\nivan,500\nanna,200\nanna,502\n' > requests.txt
cut -d, -f1 requests.txt | sort | uniq -c | sort -nr
```

```text
      3 anna
      1 ivan
```

`cut` берёт первое поле, `sort` ставит одинаковые имена рядом, `uniq -c` считает каждую группу, `sort -nr` упорядочивает численно по убыванию. Без первого `sort` две раздельные группы anna не объединились бы.

## Полезные различия

```bash
printf '2\n10\n1\n' | sort
printf '2\n10\n1\n' | sort -n
wc -l requests.txt
printf 'A B C\n' | tr '[:upper:]' '[:lower:]'
```

Обычная сортировка текстовая: `1`, `10`, `2`. `-n` включает численное сравнение. Локаль влияет на правила сортировки; `LC_ALL=C sort` задаёт воспроизводимый побайтовый порядок для технических данных.

`wc -l` считает символы перевода строки. Если последняя строка не заканчивается переводом строки, результат может быть меньше ожидаемого числа видимых строк. `wc -c` считает байты, `wc -m` — символы с учётом кодировки и локали.

## Границы подхода

Наш файл — простая таблица с запятой как разделителем. Настоящий CSV допускает кавычки, запятые и переводы строк внутри значений; `cut -d,` это не понимает. Для такого формата нужен CSV-парсер. `tr` работает с символами, а не выполняет замену произвольных подстрок: для неё подходит `sed`.

## Практика

Выведи частоты HTTP-статусов из второго поля и проверь сумму частот через `wc -l`. Добавь строку с новым пользователем и объясни каждый этап конвейера отдельно.
