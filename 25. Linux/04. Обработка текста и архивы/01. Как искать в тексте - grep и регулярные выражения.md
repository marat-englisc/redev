# Как искать в тексте - grep и регулярные выражения

> [!NOTE]
> `grep` выбирает строки по шаблону. `-F` ищет буквальный текст, `-E` включает расширенные регулярные выражения, `-i` игнорирует регистр, `-n` показывает номера строк. Регулярные выражения и shell-glob — разные языки: `.*` в regex означает произвольную последовательность, а `*.log` в glob — имена с суффиксом `.log`.

## Вопрос

Как найти ошибки в логе, получить контекст и не принять точку в IP-адресе за regex-метасимвол?

## Подготовим данные

```bash
mkdir -p "$HOME/linux-lab/text"
cd "$HOME/linux-lab/text"
cat > app.log <<'EOF'
INFO user=anna status=200
ERROR user=ivan status=500
WARN user=anna status=429
ERROR user=anna status=502
EOF
grep -n 'ERROR' app.log
grep -E 'status=5[0-9]{2}$' app.log
grep -v '^INFO' app.log
```

Второй поиск оставляет строки с трёхзначным статусом 5xx в конце. `^` — начало строки, `$` — конец, `[0-9]` — цифра, `{2}` — два повторения. `-v` инвертирует выбор.

## Выбираем режим

```bash
printf '10.0.0.1\n10x0x0x1\n' | grep -F '10.0.0.1'
grep -C 1 'WARN' app.log
grep -R -n --include='*.log' 'ERROR' .
```

`-F` трактует точки буквально. `-C 1` показывает одну соседнюю строку с каждой стороны. Рекурсивный поиск ограничивай нужным каталогом; не начинай без причины со всего `/`.

| Задача | Инструмент |
| --- | --- |
| Найти буквальную строку | `grep -F` |
| Выбрать альтернативы `ERROR` или `WARN` | `grep -E 'ERROR|WARN'` |
| Проверить наличие без вывода | `grep -q` |
| Получить имена подходящих файлов | `grep -l` |

`grep -c` считает **подходящие строки**, а не все вхождения в строках. Для структурированных форматов используй парсер: JSON с вложенностью нельзя надёжно разбирать одним regex.

## Практика

Найди только ошибки пользователя anna. Сначала отфильтруй `ERROR`, затем `user=anna`. Объясни, почему для произвольных имён пользователей такая подстрока может оказаться слишком широкой и потребовать проверки границ поля.
