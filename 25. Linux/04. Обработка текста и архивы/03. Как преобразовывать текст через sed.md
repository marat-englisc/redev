# Как преобразовывать текст через sed

> [!NOTE]
> `sed` — потоковый редактор: читает строки, применяет команды и выводит результат. `s/old/new/` заменяет первое совпадение в строке, флаг `g` — все совпадения. Без `-i` исходный файл не меняется. Надёжный порядок: посмотреть результат, проверить различия и только затем сохранять изменение.

## Вопрос

Как заменить текст, выбрать строки и изменить учебный конфиг, сохранив резервную копию?

## Пример без изменения исходника

```bash
mkdir -p "$HOME/linux-lab/sed"
cd "$HOME/linux-lab/sed"
printf 'port=3000\nmode=dev\n# local config\n' > app.conf
sed 's/^port=3000$/port=8080/' app.conf
cat app.conf
```

`sed` покажет `port=8080`, а последующий `cat` по-прежнему выведет `port=3000`: результат был только в stdout. Якоря ограничивают замену всей нужной строкой.

## Выборка и несколько команд

```bash
sed -n '1,2p' app.conf
sed '/^#/d' app.conf
printf 'dev dev\n' | sed 's/dev/prod/g'
printf '/srv/old/data\n' | sed 's|/srv/old|/srv/new|'
```

`-n` отключает автоматическую печать, `p` печатает выбранные строки, `d` исключает строку. В команде замены разделитель может быть не `/`: вариант с `|` удобнее для путей.

## Сохранение с проверкой

```bash
sed 's/^port=3000$/port=8080/' app.conf > app.conf.new
diff -u app.conf app.conf.new
```

`diff` возвращает `1`, если нашёл различия: для него это нормальный результат сравнения. В GNU sed возможен `sed -i.bak 's/.../.../' file`, который редактирует файл и сохраняет копию с суффиксом `.bak`. Синтаксис `-i` отличается у GNU и BSD sed.

## Где легко ошибиться

В шаблоне точка и другие символы имеют regex-смысл. В строке замены `&` означает полное совпадение, обратные ссылки используют специальный синтаксис. Поэтому подстановка произвольного пользовательского текста в `sed` требует экранирования сразу нескольких уровней.

Для JSON, YAML и конфигураций со сложной структурой применяй соответствующий парсер или штатный инструмент настройки. Текстовая замена строки не доказывает, что итоговый конфиг корректен.

## Практика

Замени только значение `mode=dev` в учебном файле. Сначала получи новый файл, затем проверь diff и прочитай оба файла. Объясни, почему `sed ... file > file` потеряет исходные данные.
