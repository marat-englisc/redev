# Как работают окружение, PATH и файлы запуска Bash

> [!NOTE]
> Переменная shell живёт в оболочке; `export` включает её в окружение будущих дочерних процессов. PATH — список каталогов поиска команд. Изменения окружения дочернего процесса не передаются родителю. `.bashrc` обычно читается интерактивной non-login Bash, а login Bash читает профиль по своим правилам; служба systemd не обязана читать эти файлы.

## Вопрос

Почему переменная доступна в терминале, но отсутствует у службы или в cron? Как оболочка находит команду по имени?

## Наследование на примере

```bash
APP_MODE=study
bash -c 'printf "before: %s\n" "${APP_MODE:-unset}"'
export APP_MODE
bash -c 'printf "after: %s\n" "$APP_MODE"'
APP_MODE=test bash -c 'printf "temporary: %s\n" "$APP_MODE"'
printf 'parent: %s\n' "$APP_MODE"
```

Первый дочерний Bash не получает неэкспортированную переменную. Префикс `APP_MODE=test` задаёт значение для одного запуска, а родитель сохраняет `study`.

Окружение — снимок на момент запуска. Уже работающая служба не увидит новый `export` из другого терминала.

## PATH

```bash
printf '%s\n' "$PATH"
command -v grep
type -a python3
export PATH="$HOME/.local/bin:$PATH"
```

Каталоги PATH разделяются двоеточием и проверяются по порядку. Не добавляй `.` и пустые элементы без необходимости: чужой файл из текущего каталога может перехватить привычное имя команды. Для скриптов администрирования важные исполняемые файлы иногда указывают абсолютными путями.

## Какие настройки читаются

| Режим Bash | Типичные файлы |
| --- | --- |
| Интерактивная login | `/etc/profile`, затем первый доступный из `~/.bash_profile`, `~/.bash_login`, `~/.profile` |
| Интерактивная non-login | `~/.bashrc` |
| Неинтерактивный скрипт | Обычно не `.bashrc`; возможен `BASH_ENV` |

Дистрибутивные профили могут дополнительно подключать другие файлы. `source файл` исполняет его **в текущей оболочке**, поэтому подключать незнакомый файл столь же существенно, как запускать код.

## Секреты и окружение

Не выводи всё окружение в публичный лог: там могут быть токены. `.env` сам по себе не является механизмом Bash — его должен прочитать shell или приложение. Формат dotenv и синтаксис shell не полностью взаимозаменяемы.

## Практика

Проверь пример с `export`, затем запусти `env -i /bin/bash --noprofile --norc` и посмотри на минимальное окружение. Заверши вложенную оболочку командой `exit`.
