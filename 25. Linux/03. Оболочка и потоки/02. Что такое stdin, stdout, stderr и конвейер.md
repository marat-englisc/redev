# Что такое stdin, stdout, stderr и конвейер

> [!NOTE]
> У процесса обычно есть три стандартных файловых дескриптора: stdin `0`, stdout `1`, stderr `2`. Конвейер `a | b` соединяет stdout команды a со stdin команды b. stderr в обычный конвейер не попадает. Программы могут читать и писать поток частями, поэтому большой файл необязательно целиком загружается в память.

## Вопрос

Как команды обмениваются данными через pipe? Почему сообщение об ошибке всё равно видно на экране после `| grep`?

## Потоки вместо промежуточных файлов

```text
printf ── stdout → pipe → stdin ── grep ── stdout → терминал
                                   └──── stderr → терминал
```

```bash
printf 'INFO ready\nERROR timeout\nINFO done\n' | grep ERROR | wc -l
```

Результат — `1`: `printf` создал три строки, `grep` оставил одну, `wc` посчитал её. Команды конвейера могут работать одновременно; pipe имеет ограниченный буфер, и медленный получатель замедляет отправителя.

## stderr — отдельный канал

```bash
mkdir -p "$HOME/linux-lab/streams"
cd "$HOME/linux-lab/streams"
printf 'hello\n' > exists.txt
cat exists.txt missing.txt | grep hello
```

`hello` проходит через `grep`, а ошибка про `missing.txt` идёт напрямую в stderr. Если нужно отдельно сохранить диагностику:

```bash
cat exists.txt missing.txt 2> errors.log | grep hello
cat errors.log
```

Так данные и ошибки не смешиваются. Это полезно, когда stdout предназначен следующей программе, например парсеру JSON.

## Дескриптор — не только файл на диске

Число дескриптора — индекс открытого ресурса внутри процесса. За ним может стоять файл, терминал, pipe или сокет. Команда `ls -l /proc/$$/fd` показывает дескрипторы текущей Bash, хотя реальный набор зависит от среды.

Если читатель pipe завершился, писатель при следующей записи может получить SIGPIPE. Например, `head` намеренно прекращает чтение после нужного числа строк. Это не обязательно неисправность источника данных.

## Практика

Передай пять строк в `grep`, затем в `wc -l`. Объясни, на каком этапе меняется содержимое, а на каком — только форма результата. Добавь ошибочный путь и проверь раздельное сохранение stderr.

## Частые ошибки

- Считать, что `|` передаёт аргументы или имена файлов: передаются байты потока.
- Ждать, что обычный pipe автоматически объединяет stdout и stderr.
- Считать, что весь конвейер всегда имеет успешный код завершения.
