# Что такое exit code, AND, OR и pipefail

> [!NOTE]
> Код `0` обычно означает успех, ненулевой — другой исход или ошибку по правилам программы. `$?` хранит код последней команды. `a && b` запускает b при успехе a, `a || b` — при неуспехе. По умолчанию статус конвейера — статус последней команды; Bash `pipefail` возвращает статус самой правой неуспешной команды, если такая есть.

## Вопрос

Почему `grep` без совпадений не обязательно сломан? Как ошибка раннего этапа конвейера может остаться незамеченной?

## Проверяем сразу

```bash
true
printf 'status=%s\n' "$?"
false
printf 'status=%s\n' "$?"
```

Каждая новая команда перезаписывает `$?`. Если нужен код для нескольких действий, сохрани его сразу: `status=$?`.

У `grep` три важных исхода: `0` — совпадение найдено, `1` — совпадений нет, `2` — ошибка. Поэтому «ненулевой код» не всегда означает аварийную ситуацию.

## Условное выполнение

```bash
mkdir -p "$HOME/linux-lab/status" && cd "$HOME/linux-lab/status"
test -f config.txt || printf 'config.txt пока нет\n'
```

Если переход в каталог критичен, в скрипте понятнее написать `cd "$dir" || exit 1`, чем продолжать работу в неожиданном месте.

Конструкция `a && b || c` не полностью заменяет `if`: c запустится и тогда, когда a успешна, а b завершилась неуспешно.

## Конвейер

```bash
bash -c 'false | cat; printf "default=%s\n" "$?"'
bash -o pipefail -c 'false | cat; printf "pipefail=%s\n" "$?"'
```

Первый результат — `0`, второй — `1`. `cat` успешно прочитал пустой вход, но это не делает предыдущую команду успешной.

В Bash массив `PIPESTATUS` позволяет увидеть коды отдельных частей конвейера. Считать его тоже нужно сразу: последующая команда изменит значения.

## Что pipefail не решает

Он не анализирует содержимое результата и не делает внешнюю операцию корректной. HTTP-клиент может успешно передать страницу ошибки, если не включён нужный режим проверки HTTP-кода. А намеренный ранний выход `head` может привести к SIGPIPE у отправителя и ненулевому статусу конвейера.

## Практика

Создай файл без слова `ERROR`, вызови `grep ERROR файл` и сохрани статус. Затем укажи отсутствующий файл. Объясни различие между «не найдено» и «не смогли прочитать».
