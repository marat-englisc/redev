# Как управлять фоновыми задачами - jobs, nohup и tmux

> [!NOTE]
> `&` запускает команду в фоне, `jobs` показывает задания текущего shell, `fg` возвращает их на передний план, `bg` продолжает остановленное задание в фоне. `nohup` защищает от обычного действия SIGHUP, tmux сохраняет терминальную сессию. Для постоянно работающей серверной службы нужен менеджер вроде systemd: фоновый процесс сам по себе не получает автоперезапуск и управление зависимостями.

## Вопрос

Как оставить долгую команду работать после отключения SSH? Чем фоновая задача отличается от управляемой службы?

## Job control в Bash

```bash
sleep 300
```

Нажми Ctrl Z: задача приостановится. Затем:

```bash
jobs -l
bg %1
fg %1
```

`%1` — номер задания **в этой оболочке**, а не PID. В `fg` можно завершить свой `sleep` через Ctrl C. `jobs` не показывает все процессы ОС и не обязан знать задания другого терминала.

## Одноразовая длительная команда

```bash
mkdir -p "$HOME/linux-lab/background"
nohup sleep 300 > "$HOME/linux-lab/background/job.log" 2>&1 < /dev/null &
pid=$!
printf 'PID=%s\n' "$pid"
```

Явные перенаправления отделяют ввод и вывод от терминала. Но `nohup` не защищает от перезагрузки, OOM и политики завершения пользовательских сессий. В этой лабораторной после проверки останови свой процесс: `kill -TERM "$pid"`.

## Терминальная сессия tmux

При установленном tmux:

```bash
tmux new -s study
```

Внутри можно запускать команды. Последовательность Ctrl B, затем D отсоединяет клиент, `tmux attach -t study` подключает обратно. `exit` в последней панели завершает сессию. Такая сессия переживает разрыв SSH, пока жив сервер и tmux-процесс.

## Как выбрать

| Задача | Подход |
| --- | --- |
| Недолгая команда параллельно работе | `&`, jobs |
| Одноразовая команда без интерактивности | nohup с потоками в файлы |
| Длительная ручная работа по SSH | tmux |
| API после загрузки, с restart и логами | systemd или другой менеджер служб |

## Практика

Создай tmux-сессию, запусти `date`, отсоединись и подключись снова. Объясни, что сохранится при разрыве сети, а что исчезнет после перезагрузки VM.
