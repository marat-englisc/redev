# Как Linux обеспечивает контейнеры - namespaces, cgroups и изоляция

> [!NOTE]
> Namespaces меняют видимость системных ресурсов для процессов, cgroups группируют процессы и управляют потреблением ресурсов. Контейнер использует ядро Linux-хоста, а не загружает собственное ядро как обычная VM. Безопасность требует дополнительно прав, capabilities, seccomp и MAC-политик; один namespace не является полной границей всех угроз.

## Вопрос

Почему у контейнера собственный localhost и PID 1? Почему процесс может упасть от лимита памяти при свободной RAM хоста?

## Разделение задач

| Механизм | Что меняет | Следствие |
| --- | --- | --- |
| PID namespace | Видимость и номера процессов | Один процесс может иметь разные PID снаружи и внутри |
| Network namespace | Интерфейсы, порты, маршруты | Собственный loopback |
| Mount namespace | Видимые монтирования | Свой вид файлового дерева |
| User namespace | Отображение UID/GID | Root внутри может быть непривилегированным снаружи |
| Cgroup | Учёт и лимиты CPU, RAM, PID | Лимит группы срабатывает независимо от общего ресурса |

Не каждый контейнер использует отдельный user namespace по умолчанию. Реальную конфигурацию нужно проверять.

## Наблюдение

```bash
ls -l /proc/self/ns
cat /proc/self/cgroup
findmnt /sys/fs/cgroup
```

На cgroup v2 в каталоге соответствующей группы есть файлы вроде `memory.current`, `memory.max`, `memory.events`, `cpu.max`. Не записывай значения вручную в группы, которыми управляют systemd или контейнерный runtime.

## Практические следствия

Сервер внутри контейнера, слушающий только `127.0.0.1`, может быть недоступен через публикацию порта: запрос приходит не на loopback контейнера. Порт надо привязать с учётом сети и отдельно ограничить внешний доступ.

PID 1 внутри контейнера имеет особые обязанности, включая обработку завершений дочерних процессов. Shell-обёртка без корректного `exec` и передачи сигналов может мешать graceful shutdown.

`--privileged`, host mounts и сокет Docker daemon способны резко расширить доступ контейнера к хосту. «Работает в контейнере» само по себе не означает безопасно изолировано.

## Связь с Docker

Linux объясняет базовые механизмы; Docker добавляет образы, OCI runtime, управление сетью и хранением. Продолжение — [раздел Docker](<../../13. Docker/>). Overlay и copy-on-write не заменяют отдельное хранилище для постоянных данных.

## Практика

Сравни `/proc/self/ns` в VM и уже имеющемся учебном контейнере, если он доступен. Объясни три независимых вопроса: что видно, сколько можно потребить и какие действия разрешены.
