# Как читать rwx и применять chmod к файлам и каталогам

> [!NOTE]
> Права `rwx` задаются для владельца, группы и остальных. Для файла это чтение, запись и выполнение; для каталога — просмотр имён, изменение записей и проход к объектам. Удаление файла обычно определяется правами на родительский каталог, а не правом записи в сам файл. `chmod 777` открывает слишком широкий доступ и не является универсальным исправлением.

## Вопрос

Что означает `chmod 640`? Почему читаемый файл бывает недоступен и почему файл без права записи всё равно можно удалить?

## Числовая запись

Каждая тройка — сумма `r=4`, `w=2`, `x=1`.

| Режим | Владелец | Группа | Остальные |
| --- | --- | --- | --- |
| `600` | Чтение и запись | Нет | Нет |
| `640` | Чтение и запись | Чтение | Нет |
| `755` | Всё | Чтение и выполнение | Чтение и выполнение |
| `700` | Всё | Нет | Нет |

В обычной проверке выбирается подходящий класс: владелец, иначе группа, иначе остальные. Права трёх классов не складываются. ACL и дополнительные механизмы могут усложнять проверку.

## Каталог — это отдельные разрешения

- `r` позволяет перечислить имена.
- `x` позволяет пройти по известному имени и получить доступ к дочернему объекту с учётом его прав.
- `w` вместе с `x` позволяет создавать, удалять и переименовывать записи, с дополнительными ограничениями вроде sticky bit.

Для `/srv/app/config` нужен `x` на **каждом родительском каталоге**. Поэтому `chmod 644 config` не исправит отсутствие прохода через `/srv/app`.

## Проверяем на своих файлах

```bash
mkdir -p "$HOME/linux-lab/permissions/private"
cd "$HOME/linux-lab/permissions"
printf 'study\n' > private/note.txt
chmod 700 private
chmod 600 private/note.txt
ls -ld private
ls -l private/note.txt
namei -l "$PWD/private/note.txt"
chmod u+x private/note.txt
```

Последняя команда только добавляет бит выполнения; она не превращает произвольный текст в корректную программу. Нужны понятный ОС формат или подходящий интерпретатор.

## Частые ошибки

- Рекурсивно давать один режим файлам и каталогам: обычным данным чаще не нужен `x`.
- Судить о доступе службы по собственному пользователю.
- Исправлять `Permission denied` до проверки полного пути через `namei -l`.

## Практика

Убери `x` у своего каталога командой `chmod 600 private`, попробуй прочитать вложенный файл, затем восстанови `chmod 700 private`. Выполняй опыт обычным пользователем: root способен обходить часть таких ограничений.
