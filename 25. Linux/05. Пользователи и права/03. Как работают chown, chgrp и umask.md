# Как работают chown, chgrp и umask

> [!NOTE]
> `chown` меняет владельца и, при необходимости, группу файла; `chgrp` — группу. `umask` задаёт биты, которые снимаются с запрошенных программой прав при создании. Для обычных файлов часто запрашивают `666`, для каталогов — `777`; при umask `022` получаются `644` и `755`. Это побитовая маска, а не арифметическое вычитание.

## Вопрос

Чем смена владельца отличается от chmod? Почему новые файлы не получают `x`, даже если umask равна нулю?

## Владелец и права — разные свойства

```bash
mkdir -p "$HOME/linux-lab/owners"
cd "$HOME/linux-lab/owners"
touch report.txt
ls -l report.txt
chgrp "$(id -gn)" report.txt
```

Команда `chgrp` здесь выбирает собственную основную группу. Обычный владелец может назначать файл лишь допустимым ему группам; произвольная смена владельца обычно требует повышенных прав.

В лабораторной со службой возможна команда `sudo chown demoapp:demoapp /конкретный/файл`, но не следует рекурсивно менять владельца системных деревьев ради одного отказа доступа.

## Как действует маска

```text
итоговый mode = запрошенный mode AND NOT umask
```

```bash
(
  umask 027
  touch team.txt
  mkdir team-dir
  ls -ld team.txt team-dir
)
umask
```

Без default ACL у обычного `touch` получится `640`, у `mkdir` — `750`. Скобки запускают subshell, поэтому новая umask не остаётся в родительской оболочке.

При `umask 000` обычный файл часто получает `666`, а не `777`: программа вообще не запросила выполнение. Umask только снимает биты, не добавляет их. Программа также вправе сразу запросить более строгий режим, например `600`.

## Что маска не меняет

Уже существующие файлы сохраняют права. `chmod` применяется к имеющимся объектам, umask влияет на будущие создания. ACL родительского каталога может менять правила наследования, поэтому для сложного случая проверяют `getfacl`.

При копировании и замене конфигурации учитывай владельца нового файла. Запись временного файла и `mv` поверх старого может заменить inode вместе с атрибутами; одного совпадения содержимого недостаточно.

## Практика

В двух subshell создай разные файлы с umask `022` и `077`. Сравни результат через `stat -c '%a %n' ...`. Объясни, почему смена umask после создания не закрывает старый файл.
