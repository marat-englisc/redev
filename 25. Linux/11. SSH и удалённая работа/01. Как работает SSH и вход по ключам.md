# Как работает SSH и вход по ключам

> [!NOTE]
> SSH создаёт защищённое соединение и аутентифицирует сервер и клиента. Host key сервера проверяется через known_hosts; пользовательский public key разрешает вход, если добавлен в authorized_keys на сервере. Приватный ключ остаётся у владельца и не копируется на сервер. Passphrase защищает ключ на диске, а ssh-agent помогает использовать его без повторного ввода для каждого соединения.

## Вопрос

Чем host key отличается от пользовательского SSH-ключа? Что делать при предупреждении об изменении ключа сервера?

## Две независимые проверки

```text
Клиент проверяет: это ожидаемый сервер? → host key, known_hosts
Сервер проверяет: этому пользователю разрешён вход? → authorized_keys
```

Первый вход часто требует подтвердить fingerprint. Сверяй его через доверенный канал: например, консоль VM. `ssh-keyscan` может получить публичный ключ по сети, но сам по себе не доказывает его подлинность.

## Создание отдельного учебного ключа

На клиенте, если файл с таким именем ещё не существует:

```bash
ssh-keygen -t ed25519 -f "$HOME/.ssh/id_ed25519_linux_study" -C 'linux-study'
```

Задай passphrase. Программа создаст приватный файл и публичный `.pub`. Для входа в свою VM с реальными именем и адресом:

```bash
ssh-copy-id -i "$HOME/.ssh/id_ed25519_linux_study.pub" alex@192.168.56.10
ssh -i "$HOME/.ssh/id_ed25519_linux_study" alex@192.168.56.10
```

Адрес здесь пример: он должен принадлежать твоему стенду. Если `ssh-copy-id` отсутствует, публичную строку добавляют в `~/.ssh/authorized_keys` целевого пользователя через уже доверенный канал.

## Права на сервере

Типичный безопасный режим: `~/.ssh` — `700`, `authorized_keys` — `600`, владелец — целевой пользователь. Также важны права домашнего каталога и настройки StrictModes. Приватный ключ на клиенте доступен только владельцу.

## Предупреждение о host key

Причиной может быть пересоздание VM, смена ключа или перехват соединения. Сначала выясни причину и проверь fingerprint. Не начинай с отключения `StrictHostKeyChecking` или удаления всего known_hosts.

## Практика

Подключись к своей VM, выполни `hostname` и `id`, затем `exit`. Объясни, где лежат публичный ключ пользователя, приватный ключ пользователя и запомненный ключ сервера.
