# Как передавать файлы - scp, sftp и rsync

> [!NOTE]
> `scp` удобен для разового копирования через SSH, `sftp` — для интерактивной передачи, `rsync` — для синхронизации деревьев с проверкой изменений. У rsync завершающий `/` у источника различает копирование содержимого и самого каталога. Перед `--delete` нужен dry run: эта опция удаляет лишние файлы в назначении и не является обычным «безопасным backup».

## Вопрос

Как скопировать проект на сервер и проверить список будущих изменений? Чем `rsync source/ target/` отличается от `rsync source target/`?

## Простое копирование

Для настроенного SSH-алиаса `study`:

```bash
scp report.txt study:~/report.txt
sftp study
```

В sftp доступны `ls`, `pwd`, `put`, `get`, `bye`. Современный OpenSSH scp по умолчанию использует SFTP-протокол; старые инструкции с remote shell wildcard могут вести себя иначе.

У scp порт задают большой `-P`, у ssh — маленькой `-p`. Алиас в SSH config помогает избежать этой путаницы.

## Локальный пример rsync

При установленном rsync:

```bash
mkdir -p "$HOME/linux-lab/sync/source" "$HOME/linux-lab/sync/target"
cd "$HOME/linux-lab/sync"
printf 'hello\n' > source/readme.txt
rsync -anvi source/ target/
rsync -av source/ target/
diff -r source target
```

`-n` — пробный запуск, `-i` показывает изменения, `-a` включает набор архивных режимов. В примере получается `target/readme.txt`. Источник `source` без `/` при существующем target обычно создаёт `target/source/readme.txt`.

## По SSH

```bash
rsync -anvi source/ study:~/linux-study-copy/
```

После просмотра можно убрать `-n`. Rsync должен быть установлен с обеих сторон. Режим `-a` не включает автоматически все ACL, xattrs и hard links; сохранение владельца также зависит от прав.

## Синхронизация и резервная копия

По умолчанию rsync часто сравнивает размер и время модификации, а не читает все байты для контрольной суммы. Опция `--checksum` меняет подход и увеличивает стоимость чтения.

Синхронизация с удалением способна быстро распространить ошибочное удаление или повреждение. Для backup нужны версии, отдельная область хранения и проверка восстановления.

## Практика

Добавь файл в source, измени его, каждый раз сравни dry run и фактический результат. Затем создай лишний файл в target и посмотри, что предложит `rsync -anvi --delete source/ target/`, не выполняя удаление.
