# Как написать service unit и настроить окружение

> [!NOTE]
> Service unit описывает команду запуска, пользователя, рабочий каталог, окружение, перезапуск и ограничения. Systemd запускает `ExecStart` без обычного shell-разбора: pipe, `>` и `&&` не работают как в Bash. Для долгоживущего приложения нужен foreground-процесс, а для одноразовой задачи — подходящий тип вроде oneshot.

## Вопрос

Как превратить ручной запуск в управляемую службу и почему команда из терминала может не работать в unit?

## Учебный пример

Предположим, создан пользователь `demoapp`, существует `/srv/demo-web/public`, установлен Python 3. Полная подготовка приведена в лабораторной по службе. Файл `/etc/systemd/system/demo-web.service`:

```ini
[Unit]
Description=Linux study HTTP server

[Service]
Type=exec
User=demoapp
Group=demoapp
WorkingDirectory=/srv/demo-web/public
ExecStart=/usr/bin/python3 -m http.server 8080 --bind 127.0.0.1
Environment=PYTHONUNBUFFERED=1
Restart=on-failure
RestartSec=3
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true

[Install]
WantedBy=multi-user.target
```

`Type=exec` позволяет заметить ошибку самого `exec`, но не доказывает готовность HTTP-сервера. Пример предназначен для локального обучения, не для публикации production-приложения.

## Что здесь существенно

| Настройка | Причина |
| --- | --- |
| `User`, `Group` | Ограничивают полномочия процесса |
| `WorkingDirectory` | Делают относительные пути предсказуемыми |
| Абсолютный `ExecStart` | Не зависят от пользовательского PATH |
| `RestartSec` | Предотвращает мгновенный цикл рестартов |
| `ProtectSystem` | Ограничивает запись в файловое дерево |

Если приложению нужна запись, выдели конкретный каталог и согласуй права с sandbox-настройками. Read-only файловая система не заменяет обычные права: работают оба уровня.

## Как применить

```bash
sudo systemd-analyze verify /etc/systemd/system/demo-web.service
sudo systemctl daemon-reload
sudo systemctl start demo-web.service
curl --fail http://127.0.0.1:8080/
```

`EnvironmentFile=` удобен для настроек, но не исполняет Bash-скрипт и не поддерживает все его подстановки. Секреты требуют ограниченного доступа; для подходящих приложений есть механизм systemd credentials.

## Частые ошибки

- Добавлять `&` в ExecStart: systemd должен сопровождать основной процесс.
- Ожидать, что прочитается пользовательская `.bashrc`.
- Использовать `After=` как проверку доступности внешнего сервиса.
- Считать restart policy заменой исправлению постоянной ошибки конфигурации.

## Практика

Объясни назначение каждой строки unit. Полное создание и удаление стенда выполни в лабораторной, затем проверь реальный HTTP-ответ.
