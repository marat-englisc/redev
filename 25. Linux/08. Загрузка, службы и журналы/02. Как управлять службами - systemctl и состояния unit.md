# Как управлять службами - systemctl и состояния unit

> [!NOTE]
> `start` запускает службу сейчас, `enable` настраивает её включение через зависимости при будущих запусках системы; `enable --now` делает оба действия. `restart` останавливает и запускает процесс, `reload` просит перечитать настройки, если это поддерживается. `daemon-reload` перечитывает unit-файлы systemd и не равен reload конфигурации приложения.

## Вопрос

Чем active отличается от enabled? Почему изменение `.service` и изменение конфига Nginx требуют разных действий?

## Сначала исследовать

```bash
systemctl --failed
systemctl list-units --type=service --state=running
systemctl list-unit-files --type=service
```

`list-units` показывает загруженные units, `list-unit-files` — известные unit-файлы и состояние установки. Имя службы проверяй на своей системе: например, OpenSSH может называться `ssh.service` или `sshd.service`.

После создания учебной `demo-web.service` из лабораторной можно выполнять:

```bash
systemctl status demo-web.service --no-pager
systemctl is-active demo-web.service
systemctl is-enabled demo-web.service
systemctl cat demo-web.service
systemctl show demo-web.service -p MainPID -p User -p WorkingDirectory
```

## Состояния независимы

| Состояние | Что известно |
| --- | --- |
| active, disabled | Сейчас работает, автоматическое включение не настроено |
| inactive, enabled | Сейчас не работает, включение настроено |
| failed | Запуск или работа завершились неуспешно по правилам unit |
| masked | Обычный запуск запрещён через маскирование |

У `oneshot` успешная операция может закончиться состоянием inactive. Состояние процесса и тип службы нужно интерпретировать вместе.

## Правки и перезапуск

```bash
sudo systemctl daemon-reload
sudo systemctl restart demo-web.service
journalctl -u demo-web.service -n 30 --no-pager
```

После редактирования **unit** нужен `daemon-reload`. После редактирования **конфига приложения** — его штатная проверка и `reload`, если поддерживается, либо restart. У reload может быть иной эффект и код возврата, чем у рестарта.

`disable` сам по себе не останавливает службу; `disable --now` сочетает действия. Не применяй команды остановки к SSH, сети или чужому API ради упражнения.

## Практика

Для своей учебной службы выясни active/enabled отдельно, PID и пользователя. Объясни, почему `active (running)` не гарантирует успешный ответ HTTP: процесс может быть жив, но не обслуживать нужный сценарий.
