# Как запускать задания по расписанию - cron и systemd timers

> [!NOTE]
> Cron запускает команды по календарному расписанию с ограниченным окружением. Systemd timer активирует соответствующий unit и даёт единый способ смотреть состояние и журнал. `Persistent=true` для календарного timer помогает компенсировать пропущенное срабатывание после простоя, но не воспроизводит все пропущенные запуски. Задача должна учитывать повтор, длительность и проверку результата.

## Вопрос

Почему скрипт работает вручную, но не из cron? Чем systemd timer удобнее для сопровождаемой серверной задачи?

## Формат cron

```text
минута час день-месяца месяц день-недели команда
```

Пример записи **пользовательского** crontab для пользователя alex:

```cron
15 2 * * * /home/alex/bin/report.sh >> /home/alex/report.log 2>&1
```

Это запуск в 02:15 по часовому поясу, применяемому cron. Путь нужно заменить на реальный. В `/etc/crontab` и `/etc/cron.d` дополнительно есть поле пользователя — форматы не взаимозаменяемы.

`crontab -l` показывает задания, `crontab -e` редактирует. В cron не полагайся на cwd, alias, активированное виртуальное окружение или `.bashrc`. Для дня месяца и дня недели есть особые правила сочетания; смотри реализацию cron, а не угадывай.

## Минимальная пара systemd

`study-report.service`:

```ini
[Unit]
Description=Study scheduled message
[Service]
Type=oneshot
ExecStart=/usr/bin/echo study-report
```

`study-report.timer`:

```ini
[Unit]
Description=Study daily timer
[Timer]
OnCalendar=*-*-* 02:15:00
Persistent=true
[Install]
WantedBy=timers.target
```

После размещения пары в `/etc/systemd/system` и проверки unit-файлов:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now study-report.timer
systemctl list-timers --all
journalctl -u study-report.service --no-pager
```

Включают **timer**, а не расписание через enable самого service. Удаление учебного задания начинают с `sudo systemctl disable --now study-report.timer`.

## Пересечения и пропуски

Если активируемый service ещё active, timer не создаёт автоматически вторую копию того же unit. В cron долгие задачи могут пересекаться; при необходимости применяют `flock`. Но блокировка сама по себе не делает операцию идемпотентной и не сообщает, что полезный результат получен.

Часовой пояс и переходы летнего времени влияют на календарные задания. Проверяй выражение через `systemd-analyze calendar '...выражение...'` и выбранную timezone.

## Практика

Создай учебный timer в VM, проверь следующее срабатывание и журнал, затем отключи его. Объясни, как обнаружить ситуацию «планировщик запустил команду, но резервная копия не создана».
