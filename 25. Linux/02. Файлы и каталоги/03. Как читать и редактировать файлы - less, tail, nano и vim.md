# Как читать и редактировать файлы - less, tail, nano и vim

> [!NOTE]
> `cat` выводит файл целиком, `less` позволяет читать постранично, `head` и `tail` показывают начало и конец. `tail -F` следит за именем файла и удобен при ротации логов. Для редактирования подходят nano и Vim; перед изменением системной конфигурации полезно сохранить копию и знать команду проверки её синтаксиса.

## Вопрос

Как прочитать большой лог, следить за новыми строками и изменить конфигурацию без случайной потери исходника?

## Чтение без редактирования

```bash
mkdir -p "$HOME/linux-lab/read"
cd "$HOME/linux-lab/read"
printf 'start\nready\nrequest accepted\n' > app.log
cat app.log
head -n 2 app.log
tail -n 1 app.log
less app.log
```

В `less` используй `/ready` для поиска, `n` для следующего результата, `q` для выхода. Для гигабайтного лога `less` удобнее, чем заливать терминал полным `cat`.

```bash
tail -F app.log
```

Во втором терминале из той же папки выполни `printf 'next request\n' >> app.log`. Первая команда покажет новую строку; Ctrl C остановит наблюдение. `tail -f` обычно следует открытому файлу, `-F` следует имени с повторными попытками открытия — это важно, когда старый лог переименовали, а новый создали под прежним именем.

## Минимум для редактирования

| Редактор | Ввод и сохранение | Выход |
| --- | --- | --- |
| nano | Ввод сразу; Ctrl O, Enter сохраняют | Ctrl X |
| Vim | `i` включает ввод; Esc возвращает командный режим | `:wq` сохраняет; `:q!` отбрасывает несохранённые изменения |

Редактор может потребовать установки. Для системного файла удобен `sudoedit /путь/к/файлу`: редактор работает с временной копией, затем sudo переносит изменения с необходимыми правами.

## Проверка важнее сохранения

Порядок для конфигурации: копия → небольшое изменение → проверка синтаксиса → reload службы, если поддерживается → проверка результата. Например, сохранение `sshd_config` ещё не доказывает, что SSH примет настройки.

Не редактируй бинарный файл как текст. Команда `file имя` помогает определить формат, но не является гарантией безопасности содержимого.

## Практика

Сделай `cp app.log app.log.bak`, измени одну строку в редакторе и сравни `diff -u app.log.bak app.log`. Объясни, какие строки удалены и добавлены.
