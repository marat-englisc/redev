# Что такое inode, hard link и symbolic link

> [!NOTE]
> Inode хранит метаданные файла и сведения о его данных, а имя находится в записи каталога. Hard link — ещё одно имя того же inode в одной файловой системе. Symbolic link — отдельный объект с путём к цели; он может пересекать файловые системы и стать «битым», если цель исчезнет. Удаление имени не обязательно немедленно освобождает данные.

## Вопрос

Чем жёсткая ссылка отличается от символической и почему файл может занимать место после `rm`?

## Наглядная модель

```text
original.txt ─┐
             ├── inode 1234 ── данные
another.txt ─┘

shortcut.txt ── отдельный inode ── строка "original.txt"
```

Inode не является глобальным идентификатором во всей системе: для точной идентификации учитывают и файловую систему.

## Проверяем руками

```bash
mkdir -p "$HOME/linux-lab/links"
cd "$HOME/linux-lab/links"
printf 'hello\n' > original.txt
ln original.txt another.txt
ln -s original.txt shortcut.txt
ls -li
stat original.txt
readlink shortcut.txt
rm -- original.txt
cat another.txt
cat shortcut.txt
```

`original.txt` и `another.txt` до удаления имеют одинаковый inode и счётчик ссылок 2. После удаления первого имени `another.txt` продолжает читать `hello`. Последний `cat` завершится ошибкой: символическая ссылка всё ещё указывает на исчезнувший `original.txt`.

## Относительная символическая ссылка

Путь `original.txt` в ссылке вычисляется относительно **каталога самой ссылки**, а не cwd читающей программы. Это полезно для переносимых деревьев каталогов и важно при диагностике «битых» ссылок.

| Свойство | Hard link | Symlink |
| --- | --- | --- |
| Inode цели | Тот же | Собственный inode |
| Между файловыми системами | Нет | Да |
| На каталог | Для обычного пользователя не применяется | Да |
| После удаления другого имени | Данные доступны | Может стать битой |

## Когда освобождается место

Для обычного файла данные освобождаются после удаления последней жёсткой ссылки **и** закрытия последних открытых ссылок на объект у процессов. Лог может быть удалён по имени, но служба продолжает держать его открытым и писать. Это одна из причин расхождения `df` и `du`; диагностируют через `lsof +L1`.

## Практика

Измени содержимое `another.txt`, создай к нему новую ссылку и сравни inode через `ls -li`. Объясни, почему это не резервная копия: запись через любое имя меняет те же данные.
