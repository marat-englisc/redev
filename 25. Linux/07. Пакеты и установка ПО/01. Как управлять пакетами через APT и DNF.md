# Как управлять пакетами через APT и DNF

> [!NOTE]
> Менеджер пакетов устанавливает ПО из настроенных репозиториев и разрешает зависимости. В Ubuntu/Debian обычно используют APT поверх dpkg, в Fedora и родственных системах — DNF поверх RPM. `apt update` обновляет сведения о доступных пакетах, а не сами установленные программы. Для автоматизации APT обычно выбирают apt-get, чей интерфейс предназначен для скриптов.

## Вопрос

Чем `apt update` отличается от `apt upgrade`? Почему установка отдельного `.deb` через dpkg не равна установке пакета через APT?

## Базовый сценарий Ubuntu/Debian

В своей учебной VM:

```bash
sudo apt update
apt search '^tree$'
apt show tree
sudo apt install tree
dpkg -L tree
dpkg -S /usr/bin/tree
```

Первые команды обновляют индекс и показывают сведения; `install` меняет систему. `dpkg -L` перечисляет файлы установленного пакета, `dpkg -S` ищет пакет-владелец пути.

## Соответствие задач

| Задача | Ubuntu/Debian | Fedora, интерфейс DNF |
| --- | --- | --- |
| Найти пакет | `apt search имя` | `dnf search имя` |
| Установить | `sudo apt install имя` | `sudo dnf install имя` |
| Обновить пакеты | `sudo apt upgrade` | `sudo dnf upgrade` |
| Удалить | `sudo apt remove имя` | `sudo dnf remove имя` |

У DNF4 и DNF5 есть различия команд и опций: проверь `dnf --version` и локальную справку. Таблица показывает общие операции, а не полную взаимозаменяемость.

## Почему важны зависимости

Пакет может требовать конкретную библиотеку. APT выбирает совместимый набор из репозиториев; `dpkg -i file.deb` сам не скачивает недостающие зависимости. Для локального доверенного файла в Debian-семействе удобнее `sudo apt install ./file.deb`.

`remove` обычно оставляет часть конфигурации; `purge` удаляет и управляемую пакетом конфигурацию, но не гарантирует стирание всех созданных приложением данных. Перед `autoremove` прочитай список: автоматически выбранный кандидат не обязательно больше не нужен твоему сценарию.

## Частые ошибки

- Выполнять upgrade, думая, что это только просмотр списка.
- Удалять lock-файлы пакетного менеджера, пока другой процесс установки работает.
- Ставить пакет для другой архитектуры или выпуска дистрибутива.

## Практика

Установи `tree` в стенде, выясни путь исполняемого файла через `command -v tree`, найди пакет-владелец. Перед удалением посмотри, какие изменения предлагает менеджер.
