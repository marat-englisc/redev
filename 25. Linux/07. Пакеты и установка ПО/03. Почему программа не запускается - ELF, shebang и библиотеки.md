# Почему программа не запускается - ELF, shebang и библиотеки

> [!NOTE]
> Для запуска нужны подходящий формат программы, архитектура, интерпретатор или динамический загрузчик и необходимые права. ELF — распространённый формат Linux-бинарников; shebang `#!` у скрипта указывает интерпретатор. Ошибка «No such file» при существующем файле может означать отсутствие интерпретатора или ELF-загрузчика, а не самого файла.

## Вопрос

Почему существующий исполняемый файл не запускается? Чем запуск `./script.sh` отличается от `bash script.sh`?

## Диагностический порядок

```bash
command -v python3
uname -m
file /usr/bin/env
readelf -l /usr/bin/env | grep interpreter
```

`file` определяет формат и архитектуру. `readelf` из пакета binutils показывает метаданные ELF. Для статического бинарника строки interpreter может не быть — это ожидаемо.

## Скрипт

```bash
mkdir -p "$HOME/linux-lab/exec"
cd "$HOME/linux-lab/exec"
printf '#!/usr/bin/env bash\nprintf "hello\\n"\n' > hello.sh
chmod u+x hello.sh
./hello.sh
bash hello.sh
```

При `./hello.sh` требуется выполнение файла, а ОС использует shebang. При `bash hello.sh` уже запускается Bash, который читает файл как вход: бит `x` у скрипта не обязателен, но чтение необходимо.

`#!/usr/bin/env bash` ищет Bash через PATH. Это удобно в пользовательских скриптах; в контролируемой службе явный `/bin/bash` снижает зависимость от PATH.

## Частые причины отказа

| Симптом | Что проверить |
| --- | --- |
| `Permission denied` | `x`, права родителей, `noexec`, MAC-политику |
| `Exec format error` | Архитектуру и формат |
| `bad interpreter` | Путь shebang, наличие интерпретатора |
| `...bash\r: No such file` | Windows-переводы строк CRLF |
| `error while loading shared libraries` | Версии и доступность библиотек |

Динамически связанная программа требует совместимого runtime. Копирование бинарника между glibc- и musl-системой не гарантирует запуск.

`ldd` полезен для **доверенных** бинарников, но его не следует запускать на непроверенном файле: в некоторых условиях он может привести к выполнению кода. Для первичного анализа используй `readelf` или `objdump`.

## Практика

Убери у `hello.sh` выполнение и сравни два способа запуска. Затем восстанови `chmod u+x`. Объясни, почему `chmod 777` не исправляет отсутствующий `/bin/bash` внутри минимального контейнера.
