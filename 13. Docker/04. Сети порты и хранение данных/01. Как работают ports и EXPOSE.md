# Как работают ports и EXPOSE

> [!NOTE]
> У каждого контейнера свой сетевой namespace и свои порты. `EXPOSE` в Dockerfile только **документирует**, какой порт слушает приложение. Чтобы до контейнера можно было достучаться с хоста, порт нужно **опубликовать**: `-p HOST:CONTAINER` в `docker run` или `ports` в Compose. Контейнеры в одной сети ходят друг к другу напрямую по имени сервиса и внутреннему порту — публикация для этого не нужна. Приложение должно слушать `0.0.0.0`, а не `127.0.0.1`.

## Вопрос

Как работают порты контейнера, `EXPOSE` и публикация портов?

## Основная идея

```text
браузер ──▶ localhost:8080 (хост) ──NAT──▶ 172.18.0.5:3000 (контейнер api)
                                               ▲
                     контейнер web ──api:3000──┘  (внутри сети, без публикации)
```

```bash
docker run -d -p 8080:3000 my-api
# порт 8080 хоста → порт 3000 контейнера
```

## Варианты публикации

| Запись | Смысл |
| --- | --- |
| `-p 8080:3000` | Порт 8080 на **всех** интерфейсах хоста → 3000 контейнера |
| `-p 127.0.0.1:8080:3000` | Только с самого хоста — безопасно для локальной БД |
| `-p 3000` | Случайный свободный порт хоста → 3000; узнать: `docker port` |
| `-p 5353:53/udp` | UDP-порт |
| `-P` | Опубликовать все `EXPOSE`-порты на случайные порты хоста |

## EXPOSE

```dockerfile
EXPOSE 3000
```

Не открывает и не публикует ничего. Это метаданные: подсказка для людей, флага `-P` и некоторых инструментов. Без `EXPOSE` порт всё равно доступен соседним контейнерам и публикуется через `-p`.

## ports и expose в Compose

```yaml
services:
  api:
    build: .
    ports:
      - "3000:3000"            # доступен с хоста
  db:
    image: postgres:18
    # без ports: доступен только сервисам проекта как db:5432
```

Поле `expose` в Compose, как и `EXPOSE`, — документация: сервисы в одной сети и так видят все порты друг друга.

## Приложение должно слушать 0.0.0.0

```ts
app.listen(3000, "0.0.0.0");   // доступен из-за пределов контейнера
app.listen(3000, "127.0.0.1"); // только изнутри контейнера: -p не поможет
```

Dev-серверы часто по умолчанию слушают `localhost`: для Vite нужен `--host`, для Next.js — `-H 0.0.0.0` (или переменная `HOSTNAME=0.0.0.0` для standalone-сервера).

## localhost внутри контейнера

`localhost` в контейнере — сам контейнер. Обращаться к базе из API через `localhost:5432` бесполезно: нужно имя сервиса `db:5432`. К сервису на хосте обращаются через `host.docker.internal`.

## Безопасность

На Linux Docker публикует порты через собственные правила iptables, которые срабатывают раньше `ufw`. Порт `-p 5432:5432` на сервере будет доступен из интернета, даже если `ufw` его «закрывает». В production БД не публикуют вовсе или привязывают к `127.0.0.1`.

## Частые ошибки

- Думать, что `EXPOSE` достаточно для доступа из браузера.
- Путать порядок: слева хост, справа контейнер.
- Слушать `127.0.0.1` внутри контейнера.
- Публиковать базу на `0.0.0.0` на сервере.
- Занимать один порт хоста двумя контейнерами — `port is already allocated`.

## Что важно помнить

- Публикация нужна для хоста, а не для общения контейнеров между собой.
- Между контейнерами используют **внутренний** порт: `db:5432`, даже если наружу опубликовано `15432:5432`.
- `EXPOSE` и `expose` — документация.

## Мини-шпаргалка

- `-p HOST:CONTAINER`, `ports: ["HOST:CONTAINER"]`.
- `127.0.0.1:` — только локально.
- `EXPOSE` ничего не публикует.
- Сервер слушает `0.0.0.0`.
- Внутри сети — `service:внутренний_порт`.
