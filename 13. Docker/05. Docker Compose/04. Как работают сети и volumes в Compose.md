# Как работают сети и volumes в Compose

> [!NOTE]
> Compose создаёт для проекта сеть `<проект>_default` и подключает к ней все сервисы, поэтому они видят друг друга по имени. Дополнительные сети объявляют в разделе `networks` и подключают к сервисам, чтобы изолировать, например, базу от публичного прокси. Named volumes объявляют в разделе `volumes` верхнего уровня; Compose создаёт их с префиксом проекта. `down` сохраняет volumes, `down -v` удаляет. Ресурсы, созданные вне проекта, подключают через `external: true`.

## Вопрос

Как в Compose устроены сети и volumes?

## Сеть по умолчанию

```yaml
services:
  api:
    build: .
  db:
    image: postgres:18
```

```bash
docker compose up -d
docker network ls
# shop_default   bridge
```

`api` обращается к базе по адресу `db:5432`. Имя проекта (`shop`) берётся из имени каталога, `-p` или поля `name:`.

## Несколько сетей

```yaml
services:
  proxy:
    image: nginx:1.29-alpine
    ports: ["80:80"]
    networks: [frontend, backend]

  api:
    build: .
    networks:
      backend:
        aliases: [api.internal]   # дополнительное DNS-имя

  db:
    image: postgres:18
    networks: [backend]

networks:
  frontend:
  backend:
    internal: true                 # сеть без выхода в интернет
```

`proxy` видит `api`, `api` видит `db`, а `db` недоступна из сети `frontend`. Если сервису указаны `networks`, в сеть `default` он уже не попадает.

## Named volumes

```yaml
services:
  db:
    image: postgres:18
    volumes:
      - pgdata:/var/lib/postgresql

volumes:
  pgdata:              # Compose создаст shop_pgdata
```

Volume, использованный в сервисе, обязательно объявляется в разделе `volumes` — иначе Compose выдаст ошибку.

## Внешние ресурсы

```yaml
volumes:
  pgdata:
    external: true
    name: legacy_pgdata     # существующий volume без префикса проекта

networks:
  shared:
    external: true          # сеть, общая для нескольких проектов
```

С `external: true` Compose не создаёт и не удаляет ресурс — только использует. Так несколько Compose-проектов (например, отдельные репозитории frontend и backend) подключаются к одной сети.

## Что удаляет down

| Команда | Контейнеры | Сети | Named volumes | Образы |
| --- | --- | --- | --- | --- |
| `stop` | Останавливает | — | — | — |
| `down` | Удаляет | Удаляет | Сохраняет | Сохраняет |
| `down -v` | Удаляет | Удаляет | **Удаляет** | Сохраняет |
| `down --rmi local` | Удаляет | Удаляет | Сохраняет | Удаляет собранные |

Внешние (`external`) ресурсы `down` не трогает никогда.

## Bind mounts в Compose

```yaml
services:
  api:
    volumes:
      - ./src:/app/src                          # относительно compose.yaml
      - ./nginx.conf:/etc/nginx/nginx.conf:ro
```

Относительные пути считаются от каталога с `compose.yaml`.

## Частые ошибки

- Подключаться к соседнему сервису через `localhost`.
- Забыть объявить volume в разделе верхнего уровня.
- Ждать, что volume `pgdata` из другого проекта подхватится сам: у него другой префикс.
- Удалить базу через `down -v`.
- Публиковать базу на хост вместо внутренней сети.

## Что важно помнить

- Все ресурсы проекта получают префикс его имени — у двух копий проекта в разных каталогах разные volumes.
- `internal: true` отрезает сеть от внешнего мира.
- `external: true` — способ делить сеть или volume между проектами.

## Мини-шпаргалка

- Сеть `<проект>_default` создаётся автоматически.
- `networks:` у сервиса + раздел `networks:` вверху.
- `volumes:` у сервиса + раздел `volumes:` вверху.
- `down` — данные целы, `down -v` — данных нет.
- `external: true` — использовать существующее.
