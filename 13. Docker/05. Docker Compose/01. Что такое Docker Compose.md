# Что такое Docker Compose

> [!NOTE]
> **Docker Compose** — инструмент для описания и запуска приложения из нескольких контейнеров одним YAML-файлом `compose.yaml`. В нём декларативно задают **сервисы** (образ или сборка, порты, переменные, volumes, зависимости), а также сети и volumes. `docker compose up` создаёт всё нужное и приводит окружение к описанному состоянию, `down` — удаляет контейнеры и сети. Сервисы автоматически попадают в общую сеть и видят друг друга по имени.

## Вопрос

Что такое Docker Compose и какую проблему он решает?

## Проблема

Даже небольшое приложение — это несколько процессов: frontend, API, PostgreSQL, Redis, worker. Без Compose пришлось бы помнить и запускать вручную:

```bash
docker network create app-net
docker volume create pgdata
docker run -d --name db --network app-net -v pgdata:/var/lib/postgresql -e POSTGRES_PASSWORD=secret postgres:18
docker run -d --name redis --network app-net redis:8-alpine
docker build -t api ./api
docker run -d --name api --network app-net -p 3000:3000 -e DATABASE_URL=... api
```

Compose превращает это в файл, который лежит в репозитории.

## Минимальный пример

```yaml
# compose.yaml
services:
  api:
    build: ./api
    ports:
      - "3000:3000"
    environment:
      DATABASE_URL: postgres://app:secret@db:5432/app
    depends_on:
      db:
        condition: service_healthy

  db:
    image: postgres:18
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: secret
      POSTGRES_DB: app
    volumes:
      - pgdata:/var/lib/postgresql
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U app -d app"]
      interval: 5s
      retries: 10

volumes:
  pgdata:
```

```bash
docker compose up -d
```

## Что Compose делает сам

- Создаёт сеть `<проект>_default` и подключает к ней все сервисы — имя сервиса становится DNS-именем.
- Создаёт объявленные named volumes.
- Собирает образы для сервисов с `build`.
- Запускает контейнеры с учётом `depends_on`.
- Объединяет логи всех сервисов.

Имя проекта по умолчанию — имя каталога; его меняют через `-p` или поле `name:` в файле. Все ресурсы получают префикс проекта: `myapp-api-1`, `myapp_pgdata`.

## Основные команды

```bash
docker compose up -d              # создать и запустить в фоне
docker compose up -d --build      # пересобрать образы перед запуском
docker compose ps                 # статус сервисов
docker compose logs -f api        # логи сервиса
docker compose exec api sh        # команда в работающем контейнере
docker compose run --rm api npm test   # одноразовый контейнер
docker compose restart api
docker compose stop               # остановить, не удаляя
docker compose down               # удалить контейнеры и сети
docker compose down -v            # + volumes проекта — данные пропадут
docker compose config             # итоговая конфигурация после подстановок
```

`up` идемпотентен: при повторном запуске Compose пересоздаёт только сервисы, конфигурация или образ которых изменились.

## Compose V2

Современная команда — `docker compose` (плагин CLI). Старый `docker-compose` с дефисом (V1, Python) больше не поддерживается. Поле `version:` в начале файла устарело и игнорируется, предпочтительное имя файла — `compose.yaml`.

## Где Compose уместен

- Локальная разработка и onboarding: `git clone` → `docker compose up`.
- Интеграционные и e2e-тесты в CI.
- Небольшой production на одном сервере.

Для нескольких серверов, автомасштабирования и rolling-обновлений нужен оркестратор — см. [Compose и Kubernetes](<../07. Production безопасность и отладка/08. Чем Compose отличается от Kubernetes и что такое оркестрация.md>).

## Частые ошибки

- Писать `docker-compose` и `version: "3.8"` по старым статьям.
- Подключаться между сервисами через `localhost`.
- Делать `down -v`, не понимая, что удаляются данные.
- Забывать `--build` после изменения Dockerfile — запускается старый образ.

## Что важно помнить

- Compose — декларативное описание окружения: файл в git вместо инструкций в README.
- `stop` останавливает, `down` удаляет контейнеры и сети, `down -v` — ещё и volumes.
- `docker compose config` показывает, что Compose реально применит, — первый шаг отладки YAML.

## Мини-шпаргалка

- Файл — `compose.yaml`, команда — `docker compose`.
- `services`, `volumes`, `networks` — главные разделы.
- `up -d --build`, `logs -f`, `exec`, `run --rm`, `down`.
- Имя сервиса = DNS-имя.
