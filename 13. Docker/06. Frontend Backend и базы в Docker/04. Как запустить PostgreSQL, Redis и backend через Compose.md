# Как запустить PostgreSQL, Redis и backend через Compose

> [!NOTE]
> Backend, PostgreSQL и Redis описывают отдельными сервисами одного `compose.yaml`. Backend подключается к ним **по именам сервисов** (`db:5432`, `redis:6379`), а не через `localhost`. Данные PostgreSQL хранятся в named volume, готовность базы проверяет `pg_isready` в healthcheck, а `depends_on: condition: service_healthy` не даёт API стартовать раньше времени. Порты БД публикуют только для локальных GUI-клиентов и только на `127.0.0.1`.

## Вопрос

Как поднять backend вместе с PostgreSQL и Redis через Docker Compose?

## compose.yaml

```yaml
services:
  api:
    build: .
    ports:
      - "3000:3000"
    environment:
      DATABASE_URL: postgres://app:${DB_PASSWORD}@db:5432/app
      REDIS_URL: redis://redis:6379
    depends_on:
      db:
        condition: service_healthy
      redis:
        condition: service_healthy
    restart: unless-stopped

  db:
    image: postgres:18
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: ${DB_PASSWORD}
      POSTGRES_DB: app
    volumes:
      - pgdata:/var/lib/postgresql
    ports:
      - "127.0.0.1:5432:5432"
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U app -d app"]
      interval: 5s
      timeout: 3s
      retries: 10

  redis:
    image: redis:8-alpine
    command: ["redis-server", "--appendonly", "yes"]
    volumes:
      - redisdata:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      retries: 10

volumes:
  pgdata:
  redisdata:
```

```env
# .env рядом с compose.yaml (не коммитить; в git — .env.example)
DB_PASSWORD=dev-password
```

## Работа с окружением

```bash
docker compose up -d
docker compose ps                         # все ли healthy
docker compose logs -f api
docker compose exec db psql -U app app    # консоль PostgreSQL
docker compose exec redis redis-cli       # консоль Redis
docker compose down                       # данные сохранятся
```

## Адреса изнутри и снаружи

| Кто подключается | Адрес PostgreSQL |
| --- | --- |
| Сервис `api` в Compose | `db:5432` |
| DBeaver или DataGrip на хосте | `localhost:5432` (благодаря `ports`) |
| API, запущенный на хосте через `npm run dev` | `localhost:5432` |

Частый гибридный режим: базы — в Docker, приложение — на хосте с hot reload. Тогда в `.env` приложения `localhost`, а в Compose-сервисе — `db`.

## Redis: кэш или данные

Если Redis используется только как кэш, volume не нужен. Если в нём очереди (BullMQ) или сессии, включают persistence (`--appendonly yes`) и volume `/data`.

## Тестовая база

Для интеграционных тестов удобно держать отдельный сервис без volume — данные живут только в памяти контейнера и не мешают разработке:

```yaml
  db-test:
    image: postgres:18
    environment:
      POSTGRES_PASSWORD: test
    tmpfs:
      - /var/lib/postgresql
    profiles: [test]
```

## Частые ошибки

- `localhost` в `DATABASE_URL` сервиса внутри Compose.
- PostgreSQL без volume или с неправильным путём монтирования.
- `depends_on` без healthcheck.
- Публикация портов БД на `0.0.0.0` на сервере.
- Пароль в `compose.yaml`, закоммиченный в git.

## Что важно помнить

- Внутри сети — имена сервисов и внутренние порты, снаружи — опубликованные порты.
- Healthcheck для каждой зависимости, от которой зависит старт API.
- В production БД чаще выносят в управляемый сервис, а в Compose остаются приложение и вспомогательные сервисы.

## Мини-шпаргалка

- `db:5432`, `redis:6379` — изнутри.
- `127.0.0.1:5432:5432` — для GUI-клиента.
- `pg_isready`, `redis-cli ping`.
- Named volumes для данных.
- Пароли — через `.env`, в git — `.env.example`.
