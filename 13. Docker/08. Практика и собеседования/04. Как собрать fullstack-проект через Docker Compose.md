# Как собрать fullstack-проект через Docker Compose

> [!NOTE]
> Типичный fullstack-проект в Compose: **reverse proxy** (Nginx или Caddy) — единственная точка входа с опубликованным портом, **frontend** (статика за Nginx или Next.js-сервер), **backend API**, **PostgreSQL** с volume и healthcheck, **Redis**, одноразовый сервис **миграций**. Сервисы общаются по именам в сети проекта, база и Redis наружу не публикуются. Dev-режим (bind mounts, hot reload, открытые порты) выносят в `compose.override.yaml`.

## Вопрос

Как собрать fullstack-приложение (frontend, backend, БД) через Docker Compose?

## Структура

```text
shop/
├── web/            # React + Vite
│   ├── Dockerfile
│   └── nginx.conf
├── api/            # NestJS
│   └── Dockerfile
├── proxy/
│   └── nginx.conf
├── compose.yaml            # production-like база
├── compose.override.yaml   # dev-настройки, подключаются автоматически
└── .env.example
```

## compose.yaml

```yaml
name: shop

services:
  proxy:
    image: nginx:1.29-alpine
    ports: ["80:80"]
    volumes:
      - ./proxy/nginx.conf:/etc/nginx/conf.d/default.conf:ro
    depends_on: [web, api]
    restart: unless-stopped

  web:
    build: ./web
    restart: unless-stopped

  api:
    build:
      context: ./api
      target: runner
    environment:
      DATABASE_URL: postgres://app:${DB_PASSWORD:?}@db:5432/app
      REDIS_URL: redis://redis:6379
    depends_on:
      migrate:
        condition: service_completed_successfully
      redis:
        condition: service_healthy
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://localhost:3000/health"]
      interval: 10s
      retries: 5
    init: true
    restart: unless-stopped

  migrate:
    build:
      context: ./api
      target: build                 # stage, где есть prisma CLI
    command: ["npx", "prisma", "migrate", "deploy"]
    environment:
      DATABASE_URL: postgres://app:${DB_PASSWORD:?}@db:5432/app
    depends_on:
      db:
        condition: service_healthy

  db:
    image: postgres:18
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: ${DB_PASSWORD:?}
      POSTGRES_DB: app
    volumes: [pgdata:/var/lib/postgresql]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U app -d app"]
      interval: 5s
      retries: 10
    restart: unless-stopped

  redis:
    image: redis:8-alpine
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
    restart: unless-stopped

volumes:
  pgdata:
```

## proxy/nginx.conf

```nginx
server {
  listen 80;

  location /api/ {
    proxy_pass http://api:3000/;    # завершающий / отрезает префикс /api
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }

  location / {
    proxy_pass http://web:80;
  }
}
```

Frontend и API на одном домене: нет CORS, cookie работают без `SameSite=None`.

## compose.override.yaml для разработки

```yaml
services:
  web:
    build:
      target: dev
    command: ["npm", "run", "dev", "--", "--host", "0.0.0.0"]
    ports: ["5173:5173"]
    volumes: [./web:/app, /app/node_modules]

  api:
    build:
      target: dev
    command: ["npm", "run", "start:dev"]
    ports: ["3000:3000", "9229:9229"]
    volumes: [./api:/app, /app/node_modules]

  db:
    ports: ["127.0.0.1:5432:5432"]
```

`docker compose up` берёт оба файла и запускает dev-окружение. Для production: `docker compose -f compose.yaml up -d` — без override.

## Чем production отличается

| | Dev | Production |
| --- | --- | --- |
| Образы | Собираются локально, `target: dev` | Готовые из registry по тегу |
| Код | Bind mount, hot reload | Внутри образа |
| Порты | Открыты для отладки | Только 80/443 у proxy |
| HTTPS | Нет | Caddy или Nginx с сертификатами, либо внешний балансировщик |
| Секреты | `.env` | Secret manager или Compose `secrets` |
| БД | Контейнер | Часто управляемая БД |

## Частые ошибки

- Публиковать порты всех сервисов.
- `localhost` между контейнерами.
- База без volume или без healthcheck.
- Миграции внутри `CMD` API.
- Хардкодить пароли в `compose.yaml`.
- Смешивать dev- и production-настройки в одном файле.

## Что важно помнить

- Одна точка входа — reverse proxy; всё остальное во внутренней сети.
- Граф запуска: db (healthy) → migrate (exit 0) → api → proxy.
- `${VAR:?}` заставляет явно задать секрет и не стартовать с пустым паролем.

## Мини-шпаргалка

- proxy → web, api → db, redis.
- `/api/` проксируется на `api:3000`.
- Override — dev, базовый файл — production-like.
- Healthcheck и `depends_on` с условиями.
- Наружу только proxy.
