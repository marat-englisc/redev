# Как запустить контейнер через docker run

> [!NOTE]
> `docker run` **создаёт новый** контейнер из образа и запускает его (это `docker create` + `docker start`). Главные флаги: `-d` — в фоне, `--name` — имя, `-p host:container` — публикация порта, `-e`/`--env-file` — переменные окружения, `-v` — volume или bind mount, `--rm` — удалить после остановки, `-it` — интерактивный терминал. Всё, что после имени образа, заменяет `CMD` образа.

## Вопрос

Как запустить контейнер через `docker run` и какие флаги нужно знать?

## Основная идея

```bash
docker run [флаги] образ[:тег] [команда и аргументы]
```

```bash
docker run nginx:alpine
```

1. Docker ищет образ локально, при отсутствии — скачивает из registry.
2. Создаёт контейнер со случайным именем вроде `brave_tesla`.
3. Запускает команду по умолчанию (`CMD` образа) и привязывает терминал к её выводу.

## Основные флаги

```bash
docker run -d \
  --name api \
  -p 3000:3000 \
  -e NODE_ENV=production \
  --env-file .env \
  -v uploads:/app/uploads \
  --restart unless-stopped \
  my-api:1.4.0
```

| Флаг | Что делает |
| --- | --- |
| `-d` | Detached: контейнер работает в фоне, терминал свободен |
| `--name api` | Имя для команд `logs`, `stop`, `exec`; должно быть уникальным |
| `-p 3000:3000` | Порт хоста → порт контейнера (`HOST:CONTAINER`) |
| `-p 127.0.0.1:5432:5432` | Опубликовать только на loopback хоста, не на всех интерфейсах |
| `-e KEY=value` | Переменная окружения |
| `--env-file .env` | Переменные из файла |
| `-v name:/path` | Named volume |
| `-v "$(pwd)":/app` | Bind mount каталога хоста |
| `--network app-net` | Подключить к сети |
| `--restart unless-stopped` | Политика перезапуска |
| `--rm` | Удалить контейнер после завершения |
| `-it` | `-i` держит stdin открытым, `-t` выделяет псевдотерминал |
| `--init` | Запустить лёгкий init (tini) как PID 1 для корректных сигналов |

## Переопределение команды

```bash
docker run --rm node:24-alpine node -v          # вместо CMD образа
docker run --rm -it ubuntu:24.04 bash           # интерактивная оболочка
docker run --rm --entrypoint sh my-api -c 'ls'  # заменить и ENTRYPOINT
```

`--rm` удобен для одноразовых команд: проверить версию, выполнить миграцию, запустить скрипт.

## Пример: PostgreSQL для разработки

```bash
docker run -d \
  --name db \
  -e POSTGRES_USER=app \
  -e POSTGRES_PASSWORD=secret \
  -e POSTGRES_DB=app \
  -p 127.0.0.1:5432:5432 \
  -v pgdata:/var/lib/postgresql \
  postgres:18
```

Для PostgreSQL 18+ volume монтируют в `/var/lib/postgresql` (в 17 и ниже — в `/var/lib/postgresql/data`).

## run, start и exec

| Команда | Что делает |
| --- | --- |
| `docker run` | Создаёт **новый** контейнер и запускает |
| `docker start api` | Запускает **существующий** остановленный контейнер |
| `docker exec api sh` | Выполняет дополнительную команду в **работающем** контейнере |

Повторный `docker run --name api` упадёт с ошибкой «name already in use» — контейнер уже существует.

## Частые ошибки

- Путать `8080:80` и `80:8080`: слева всегда хост.
- Запускать без `-d` и думать, что терминал «завис» — это просто вывод логов.
- Запускать базу без volume.
- Использовать `--rm` для контейнера с данными, которые нужны после остановки.
- Ожидать, что `EXPOSE` в Dockerfile сам опубликует порт.

## Что важно помнить

- Аргументы после имени образа заменяют `CMD`, а `--entrypoint` — `ENTRYPOINT`.
- `-p 5432:5432` публикует порт на всех интерфейсах хоста; для локальной базы безопаснее `127.0.0.1:5432:5432`.
- Опубликованные Docker порты обходят правила `ufw` на Linux-серверах — это частая причина «случайно открытой» базы.
- `-d` не спасёт контейнер, если главный процесс сразу завершается.

## Мини-шпаргалка

- `docker run -d --name x -p H:C -e K=V -v vol:/path image:tag`.
- `--rm` — одноразовый, `-it` — интерактивный.
- `run` создаёт, `start` запускает существующий, `exec` — команда внутри.
