# Что такое Docker

> [!NOTE]
> **Docker** — платформа для упаковки приложения вместе со всеми зависимостями в **образ** и запуска этого образа в виде изолированного **контейнера**. Окружение (версия Node.js, системные библиотеки, команда запуска) описывается кодом в `Dockerfile`, поэтому приложение одинаково запускается на ноутбуке, в CI и на сервере. Контейнер — не виртуальная машина: это обычный процесс хоста, изолированный средствами ядра Linux.

## Вопрос

Что такое Docker и какую проблему он решает?

## Основная идея

Классическая проблема — «у меня работает, а на сервере нет». Причины почти всегда в окружении:

- разные версии Node.js, npm или pnpm;
- локально PostgreSQL 16, на сервере 18;
- на сервере нет системной библиотеки для native-модуля (`sharp`, `bcrypt`);
- забытые переменные окружения или шаги установки из README.

Docker фиксирует окружение в виде артефакта:

```text
Dockerfile ──docker build──▶ образ (image) ──docker run──▶ контейнер (container)
 рецепт                       неизменяемый шаблон            запущенный процесс
```

Образ содержит runtime, зависимости, код и команду запуска. Из одного образа можно запустить сколько угодно контейнеров — на любой машине, где есть Docker Engine.

## Пример

```bash
docker run -d -p 8080:80 nginx:alpine
```

1. Docker ищет образ `nginx:alpine` локально, а если его нет — скачивает из registry (по умолчанию Docker Hub).
2. Создаёт контейнер: отдельную файловую систему, сеть и дерево процессов.
3. Запускает внутри Nginx и пробрасывает порт `8080` хоста на порт `80` контейнера.

Открываешь `http://localhost:8080` — и видишь Nginx, хотя на машине он не установлен.

## Из чего состоит экосистема

| Часть | Что делает |
| --- | --- |
| Docker Engine | Демон `dockerd`: собирает образы, запускает контейнеры, управляет сетями и volumes |
| Docker CLI | Команды `docker run`, `docker build`, `docker ps` — клиент, который отправляет запросы Engine |
| Dockerfile | Рецепт сборки образа |
| Образ | Неизменяемый шаблон из слоёв файловой системы и метаданных |
| Контейнер | Запущенный экземпляр образа с собственным записываемым слоем |
| Registry | Хранилище образов: Docker Hub, GitHub Container Registry, AWS ECR |
| Docker Compose | Описание и запуск нескольких контейнеров через `compose.yaml` |

## Зачем Docker frontend-разработчику

- Поднять локально PostgreSQL, Redis или весь backend одной командой, не устанавливая их в систему.
- Собрать production-образ Next.js или Nginx со статикой Vite.
- Запускать e2e-тесты в CI в том же окружении, что и локально.
- Понимать, как деплоится приложение, — на собеседованиях Senior это частая тема.

## Частые ошибки

- Считать контейнер виртуальной машиной.
- Хранить данные базы внутри контейнера без volume — они пропадут при пересоздании.
- Устанавливать пакеты руками внутри запущенного контейнера и ждать, что они окажутся в образе.
- Класть секреты в `Dockerfile` или образ.

## Что важно помнить

- Docker решает проблему воспроизводимости: окружение описано кодом и версионируется вместе с проектом.
- Образ — шаблон, контейнер — запущенный экземпляр; с этого различия начинается большинство вопросов.
- Контейнеры используют ядро хоста, поэтому стартуют за доли секунды, но изолированы слабее, чем VM.
- Docker не заменяет инфраструктуру: бэкапы, мониторинг и оркестрация остаются отдельными задачами.

## Мини-шпаргалка

- Dockerfile → `docker build` → образ → `docker run` → контейнер.
- Registry хранит образы, `pull` скачивает, `push` публикует.
- Compose запускает несколько сервисов одной командой.
- Данные — во volume, секреты — снаружи образа.
