# Чем контейнер отличается от виртуальной машины

> [!NOTE]
> **Виртуальная машина** эмулирует оборудование через гипервизор и запускает полноценную гостевую ОС со своим ядром. **Контейнер** — изолированный процесс, который использует ядро хоста. Поэтому контейнер стартует за доли секунды и весит мегабайты, а VM — секунды или минуты и гигабайты. Цена лёгкости — более слабая изоляция: общее ядро означает общую поверхность атаки.

## Вопрос

Чем контейнер отличается от виртуальной машины?

## Основная идея

```text
Виртуальные машины                 Контейнеры
┌──────┐ ┌──────┐                  ┌──────┐ ┌──────┐
│ App  │ │ App  │                  │ App  │ │ App  │
│ Libs │ │ Libs │                  │ Libs │ │ Libs │
│Guest │ │Guest │                  └──────┘ └──────┘
│  OS  │ │  OS  │                  ┌────────────────┐
└──────┘ └──────┘                  │ Container      │
┌────────────────┐                 │ runtime        │
│   Гипервизор   │                 ├────────────────┤
├────────────────┤                 │ Ядро ОС хоста  │
│   ОС хоста     │                 ├────────────────┤
├────────────────┤                 │ Оборудование   │
│ Оборудование   │                 └────────────────┘
└────────────────┘
```

У VM своё ядро, свои системные службы и выделенная память. Контейнер — процесс, которому ядро хоста показывает «свой» вид системы через namespaces.

## Сравнение

| Критерий | Контейнер | Виртуальная машина |
| --- | --- | --- |
| Ядро ОС | Общее с хостом | Своё гостевое |
| Старт | Миллисекунды–секунды | Секунды–минуты |
| Размер | Десятки–сотни МБ | Гигабайты |
| Изоляция | Namespaces и cgroups | Аппаратная виртуализация |
| Другая ОС | Только с тем же ядром (Linux-контейнеры на Linux) | Любая ОС |
| Плотность | Сотни на хост | Десятки на хост |

## Нюанс: в образе есть «ОС», но нет ядра

Образ `node:24-alpine` или `ubuntu:24.04` содержит userland дистрибутива: `/bin/sh`, libc, пакетный менеджер. Ядра в образе нет. Поэтому фраза «контейнер не содержит ОС» неточна: он не содержит **ядро**.

## Когда всё же нужна VM

- Нужна другая ОС или своё ядро (Windows-сервер, модули ядра).
- Нужна сильная изоляция недоверенного кода (мультиарендные платформы).
- Docker на macOS и Windows сам работает внутри лёгкой Linux-VM.

На практике их комбинируют: облако выдаёт VM, а внутри неё запускаются контейнеры. Есть и промежуточные решения — microVM вроде Firecracker и песочницы вроде gVisor: они дают привычный контейнерный интерфейс с изоляцией, близкой к VM.

## Частые ошибки

- Утверждать, что контейнер «вообще без ОС» — в нём есть userland, но нет ядра.
- Считать контейнеры такими же изолированными, как VM.
- Думать, что Docker заменяет облачную инфраструктуру.

## Что важно помнить

- Ключевое различие — общее ядро: отсюда и скорость контейнеров, и их более слабая изоляция.
- Linux-контейнер требует Linux-ядро, поэтому на macOS и Windows Docker использует VM.
- VM и контейнеры не конкуренты, а уровни одной архитектуры.

## Мини-шпаргалка

- VM: гипервизор + гостевая ОС с ядром.
- Контейнер: процесс + namespaces + cgroups на ядре хоста.
- Контейнер легче и быстрее, VM изолирует сильнее.
- Образ содержит userland, но не ядро.
