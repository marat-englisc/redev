# Что такое Docker Engine, Docker Desktop и Docker Hub

> [!NOTE]
> **Docker Engine** — демон `dockerd`, который собирает образы, запускает контейнеры и управляет сетями и volumes. **Docker CLI** — клиент, который отправляет команды Engine через API. **Docker Desktop** — приложение для macOS, Windows и Linux, которое ставит Engine, CLI, Compose и GUI, а на macOS и Windows ещё и Linux-VM для них. **Docker Hub** — публичный registry, откуда по умолчанию скачиваются образы.

## Вопрос

Что такое Docker Engine, Docker Desktop и Docker Hub и как они связаны?

## Основная идея

```text
docker CLI ──Docker API (unix socket)──▶ dockerd ──▶ containerd ──▶ runc ──▶ процесс контейнера
                                            │
                                            └──pull/push──▶ registry (Docker Hub, GHCR, ECR)
```

- **CLI** сам ничего не запускает: `docker run` — это HTTP-запрос к демону через `/var/run/docker.sock`.
- **dockerd** управляет образами, сетями, volumes и сборкой (BuildKit).
- **containerd** и **runc** — нижние уровни: runc по стандарту OCI создаёт namespaces и cgroups и запускает процесс.

Поэтому CLI может управлять и удалённым демоном: `DOCKER_HOST=ssh://user@server docker ps` или через `docker context`.

## Docker Desktop

Приложение для локальной разработки. Включает:

- Docker Engine, CLI, Compose и BuildKit;
- графический интерфейс для контейнеров, образов и volumes;
- на macOS и Windows — Linux-VM, внутри которой работает Engine (на Windows обычно через WSL 2);
- настройки ресурсов VM, опциональный Kubernetes, Docker Scout.

Для коммерческого использования в крупных компаниях Docker Desktop требует платной подписки. Альтернативы — OrbStack и Colima на macOS, Rancher Desktop, Podman Desktop. На Linux-сервере Desktop не нужен: ставят только Docker Engine.

## Docker Hub и другие registry

```bash
docker pull node:24-alpine        # = docker.io/library/node:24-alpine
docker pull ghcr.io/org/app:1.2.0 # другой registry указан в имени
```

Полное имя образа: `registry/namespace/repository:tag`. Если registry не указан, используется `docker.io`, а для официальных образов — namespace `library`.

| Registry | Где используется |
| --- | --- |
| Docker Hub | Официальные образы, open source |
| GitHub Container Registry (`ghcr.io`) | Проекты на GitHub, GitHub Actions |
| GitLab Container Registry | Проекты на GitLab |
| AWS ECR, Google Artifact Registry, Azure ACR | Деплой в соответствующее облако |
| Harbor, Nexus | Приватный registry компании |

У Docker Hub есть лимиты на анонимные `pull`, поэтому в CI обычно логинятся или используют зеркало.

## Частые ошибки

- Путать Docker Desktop и Docker Engine — на сервере нужен только Engine.
- Думать, что Docker Hub обязателен: подойдёт любой OCI-совместимый registry.
- Пушить образ без префикса registry и удивляться, что он ушёл в Docker Hub.
- Давать контейнерам доступ к `docker.sock` — это фактически root на хосте.

## Что важно помнить

- CLI — клиент, Engine — сервер; общаются через Docker API.
- Образы и контейнеры стандартизированы OCI, поэтому их запускают и Podman, и Kubernetes без Docker.
- На macOS и Windows контейнеры работают в Linux-VM — отсюда особенности с файлами и производительностью (см. [урок про macOS и Windows](<07. Как Docker работает на macOS и Windows.md>)).

## Мини-шпаргалка

- Engine (`dockerd`) запускает контейнеры.
- CLI отправляет команды Engine.
- Desktop — локальная среда с VM, GUI и Compose.
- Hub — registry по умолчанию, `docker.io/library/...`.
- `pull` — скачать, `push` — опубликовать.
