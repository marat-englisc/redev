# Задача: рендер виртуального DOM в реальный

> [!NOTE]
> Задача «напишите свой `createElement` и `render`» проверяет понимание того, что делает JSX и React: **виртуальный узел** — обычный объект `{ type, props, children }`, а `render` рекурсивно превращает его в DOM-узлы: создает элемент, выставляет атрибуты и обработчики событий, добавляет детей; строки становятся текстовыми узлами. Продвинутое продолжение — упрощенный **diff** (patch): сравнить старое и новое дерево и обновить только изменившиеся части.

## Вопрос

Реализуйте функцию `h(type, props, ...children)`, создающую виртуальные узлы, и `render(vnode)`, возвращающую реальный DOM-узел. Поддержите атрибуты, `className`, `style`-объект, обработчики `onClick` и вложенные массивы детей. Как бы выглядел простейший `patch`?

## Виртуальные узлы

```javascript
function h(type, props, ...children) {
  return {
    type,
    props: props ?? {},
    children: children.flat().filter((c) => c !== null && c !== undefined && c !== false),
  };
}

// JSX <div className="card"><h2>Привет</h2></div> компилируется примерно в:
const vnode = h("div", { className: "card" },
  h("h2", null, "Привет"),
  h("button", { onClick: () => alert("клик"), disabled: false }, "Нажми"),
);
```

## render

```javascript
function render(vnode) {
  if (typeof vnode === "string" || typeof vnode === "number") {
    return document.createTextNode(String(vnode));          // текст безопасен — не HTML
  }

  if (typeof vnode.type === "function") {
    return render(vnode.type({ ...vnode.props, children: vnode.children })); // компонент-функция
  }

  const el = document.createElement(vnode.type);

  for (const [key, value] of Object.entries(vnode.props)) {
    if (key.startsWith("on") && typeof value === "function") {
      el.addEventListener(key.slice(2).toLowerCase(), value);  // onClick → click
    } else if (key === "className") {
      el.className = value;
    } else if (key === "style" && typeof value === "object") {
      Object.assign(el.style, value);
    } else if (typeof value === "boolean") {
      el.toggleAttribute(key, value);                          // disabled, checked
    } else if (value !== null && value !== undefined) {
      el.setAttribute(key, String(value));
    }
  }

  for (const child of vnode.children) {
    el.appendChild(render(child));
  }

  return el;
}

document.getElementById("root").appendChild(render(vnode));
```

## Компоненты

```javascript
const Greeting = ({ name }) => h("p", { class: "greeting" }, "Привет, ", name, "!");

render(h(Greeting, { name: "Анна" }));   // <p class="greeting">Привет, Анна!</p>
```

## Упрощенный patch

```javascript
function patch(parent, oldVNode, newVNode, index = 0) {
  const el = parent.childNodes[index];

  if (oldVNode === undefined) {
    parent.appendChild(render(newVNode));                      // добавить
  } else if (newVNode === undefined) {
    parent.removeChild(el);                                    // удалить
  } else if (changed(oldVNode, newVNode)) {
    parent.replaceChild(render(newVNode), el);                 // заменить целиком
  } else if (typeof newVNode === "object") {
    updateProps(el, oldVNode.props, newVNode.props);
    const oldLen = oldVNode.children.length;
    const newLen = newVNode.children.length;
    for (let i = 0; i < newLen; i++) {                        // обновить и добавить — по порядку
      patch(el, oldVNode.children[i], newVNode.children[i], i);
    }
    for (let i = oldLen - 1; i >= newLen; i--) {              // лишние старые — удалить с конца
      el.removeChild(el.childNodes[i]);
    }
  }
}

function changed(a, b) {
  return typeof a !== typeof b ||
    (typeof a !== "object" && a !== b) ||
    (typeof a === "object" && a.type !== b.type);
}

function updateProps(el, oldProps, newProps) {
  for (const key of Object.keys(oldProps)) {
    if (!(key in newProps)) el.removeAttribute(key === "className" ? "class" : key);
  }
  for (const [key, value] of Object.entries(newProps)) {
    if (key.startsWith("on")) continue;                        // обработчики упрощенно не обновляем
    if (oldProps[key] !== value) {
      if (key === "className") el.className = value;
      else el.setAttribute(key, String(value));
    }
  }
}
```

Это иллюстрация идеи reconciliation: тот же тип — обновить атрибуты и рекурсивно детей, другой тип — заменить поддерево. Настоящий React дополнительно использует `key` для списков, Fiber и планирование.

## Доп. вопросы интервьюера

- **Почему текст через `createTextNode`?** не интерпретируется как HTML — защита от XSS.
- **Что такое `key` и зачем он в diff?** позволяет сопоставлять элементы списков по идентичности, а не по индексу, — без него вставка в начало пересоздаст все элементы.
- **Как обновлять обработчики?** хранить текущий обработчик на элементе и менять ссылку, либо делегировать события на корень.
- **Почему Virtual DOM не всегда быстрее прямой работы с DOM?** это слой абстракции; выгода — в декларативности и батчинге, а не в скорости одной операции.

## Что важно помнить

- JSX — синтаксис для вызовов `createElement`/`jsx`, результат — обычные объекты.
- Рекурсивный рендер — это DFS по дереву виртуальных узлов.
- Текст пользователя никогда не вставляйте через `innerHTML`.
- Теория: [Virtual DOM](<../../06. React/01. Основы React/08. Virtual DOM - что это и зачем он нужен.md>), [reconciliation](<../../06. React/01. Основы React/09. Reconciliation и diffing-алгоритм - как React решает, что обновить.md>).

## Мини-шпаргалка

`h(type, props, ...children)` → `{ type, props, children }`. `render`: строка → `createTextNode`, функция → вызвать компонент, иначе `createElement` + props (`on*` → `addEventListener`, `className`, `style`, boolean → `toggleAttribute`) + рекурсия по детям. patch: нет старого → добавить, нет нового → удалить, другой тип → заменить, иначе обновить props и детей.
