# Задача: бесконечная прокрутка и ленивые изображения

> [!NOTE]
> Задачи на **бесконечную прокрутку** и **ленивую загрузку изображений** проверяют знание `IntersectionObserver` — API, который асинхронно сообщает, когда элемент появляется в области видимости, без обработчика `scroll` и измерений `getBoundingClientRect` на каждый пиксель. Для бесконечной ленты наблюдают за **сентинелом** в конце списка и подгружают следующую страницу, защищаясь от повторной загрузки; для изображений подменяют `data-src` на `src`, когда картинка приближается к экрану (`rootMargin`).

## Вопрос

Реализуйте бесконечную прокрутку списка на чистом JavaScript с `IntersectionObserver` и защитой от параллельных загрузок. Реализуйте ленивую загрузку изображений. Почему это лучше, чем обработчик `scroll`?

## Бесконечная прокрутка

```html
<ul id="feed"></ul>
<div id="sentinel" aria-hidden="true"></div>
<p id="status" role="status"></p>
```

```javascript
const feed = document.querySelector("#feed");
const sentinel = document.querySelector("#sentinel");
const status = document.querySelector("#status");

let cursor = null;
let loading = false;
let hasMore = true;

async function loadMore() {
  if (loading || !hasMore) return;                 // защита от повторных вызовов
  loading = true;
  status.textContent = "Загрузка…";

  try {
    const res = await fetch(`/api/posts?limit=20${cursor ? `&cursor=${cursor}` : ""}`);
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    const { items, nextCursor } = await res.json();

    const fragment = document.createDocumentFragment();   // одна вставка вместо 20
    for (const post of items) {
      const li = document.createElement("li");
      li.textContent = post.title;
      fragment.append(li);
    }
    feed.append(fragment);

    cursor = nextCursor;
    hasMore = Boolean(nextCursor);
    status.textContent = hasMore ? "" : "Больше постов нет";
    if (!hasMore) observer.disconnect();
  } catch (error) {
    status.textContent = "Не удалось загрузить. Прокрутите, чтобы повторить.";
  } finally {
    loading = false;
  }
}

const observer = new IntersectionObserver(
  (entries) => {
    if (entries[0].isIntersecting) loadMore();
  },
  { rootMargin: "600px" },                         // начать загрузку заранее
);

observer.observe(sentinel);
loadMore();
```

## Ленивые изображения

```html
<img class="lazy" data-src="/photos/1.webp" width="400" height="300" alt="Закат над морем" />
```

```javascript
const imageObserver = new IntersectionObserver(
  (entries, obs) => {
    for (const entry of entries) {
      if (!entry.isIntersecting) continue;
      const img = entry.target;
      img.src = img.dataset.src;
      img.addEventListener("load", () => img.classList.add("loaded"), { once: true });
      obs.unobserve(img);                          // больше не следить
    }
  },
  { rootMargin: "200px 0px" },
);

document.querySelectorAll("img.lazy").forEach((img) => imageObserver.observe(img));
```

Сегодня для обычных изображений достаточно нативного атрибута: `<img loading="lazy" src="..." width="400" height="300">`. Свой observer нужен для фоновых изображений, видео, сложных эффектов появления.

## Почему не scroll

| | `scroll` + `getBoundingClientRect` | `IntersectionObserver` |
| --- | --- | --- |
| Частота вызовов | десятки раз в секунду | только при пересечении порога |
| Нагрузка на главный поток | вызывает layout на каждое событие | вычисления браузера вне JS |
| Код | нужны throttle и расчеты | декларативные `threshold` и `rootMargin` |

## Доп. вопросы интервьюера

- **Как не потерять производительность на тысячах элементов?** виртуализация — рендерить только видимые строки.
- **Доступность?** кнопка «Загрузить еще» как альтернатива, `role="feed"`, объявление статуса, достижимый футер.
- **Как восстановить позицию при возврате назад?** кешировать загруженные страницы и `scrollTop`.
- **В React?** хук `useInfiniteScroll` с `ref` на сентинел или `useInfiniteQuery` + observer.

## Что важно помнить

- Флаг `loading` предотвращает несколько одновременных запросов при быстром скролле.
- Отключайте observer, когда данных больше нет, и в cleanup компонента.
- Задавайте размеры изображений — иначе подгрузка вызовет сдвиги (CLS).
- Связанные темы: [лента новостей в system design](<../../11. Frontend System Design/04. Разбор задач/02. Как спроектировать ленту новостей (news feed).md>), [lazy loading](<../../04. JavaScript/09. Производительность в JS/12. Что такое “lazy loading”.md>).

## Мини-шпаргалка

Сентинел в конце + `IntersectionObserver({ rootMargin })` → `loadMore` с флагами `loading`/`hasMore`, cursor, `DocumentFragment`, `disconnect` в конце. Изображения: `data-src` → `src` при пересечении, `unobserve`; нативно — `loading="lazy"`. Лучше scroll: нет постоянных расчетов layout.
