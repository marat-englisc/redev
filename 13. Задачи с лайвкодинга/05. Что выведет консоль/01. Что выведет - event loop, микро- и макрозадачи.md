# Что выведет: event loop, микро- и макрозадачи

> [!NOTE]
> Задачи «что выведет консоль» на event loop решаются одним правилом: сначала выполняется весь **синхронный код**, затем **все микрозадачи** (`then`, `catch`, `finally`, `await`, `queueMicrotask`; в Node.js еще раньше — `process.nextTick`), и только потом **одна макрозадача** (`setTimeout`, `setInterval`, события), после которой снова все микрозадачи. Executor `new Promise(fn)` выполняется **синхронно**, а код после `await` — как микрозадача.

## Вопрос

Что выведет каждый фрагмент кода? Объясните порядок через стек вызовов, очередь микрозадач и очередь макрозадач.

## Задача 1: база

```javascript
console.log(1);
setTimeout(() => console.log(2), 0);
Promise.resolve().then(() => console.log(3));
queueMicrotask(() => console.log(4));
console.log(5);
```

> [!TIP]- Ответ
> `1 5 3 4 2`. Синхронно 1 и 5; микрозадачи по порядку постановки — 3, 4; затем макрозадача — 2.

## Задача 2: задачи внутри задач

```javascript
setTimeout(() => console.log("t1"), 0);
Promise.resolve().then(() => {
  console.log("p1");
  setTimeout(() => console.log("t2"), 0);
  Promise.resolve().then(() => console.log("p2"));
});
setTimeout(() => {
  console.log("t3");
  Promise.resolve().then(() => console.log("p3"));
}, 0);
console.log("sync");
```

> [!TIP]- Ответ
> `sync p1 p2 t1 t3 p3 t2`.
> 1. Синхронно: `sync`; в макрозадачах t1, t3; в микрозадачах p1.
> 2. Микрозадача p1: печатает p1, ставит t2 в конец макрозадач и p2 в микрозадачи. Микрозадачи выполняются, пока очередь не опустеет, — p2.
> 3. Макрозадача t1, микрозадач нет. Макрозадача t3 ставит p3 → p3 выполнится до следующей макрозадачи. Затем t2.

## Задача 3: async/await

```javascript
async function a() {
  console.log("a1");
  await b();
  console.log("a2");
}
async function b() { console.log("b"); }

console.log("start");
setTimeout(() => console.log("timeout"), 0);
a();
new Promise((resolve) => { console.log("executor"); resolve(); }).then(() => console.log("then"));
console.log("end");
```

> [!TIP]- Ответ
> `start a1 b executor end a2 then timeout`.
> Async-функция выполняется синхронно до первого `await`; `b()` тоже синхронно печатает `b`. Код после `await` (`a2`) встает в микрозадачи раньше, чем `then`, потому что был поставлен раньше. Executor промиса синхронный.

## Задача 4: две цепочки

```javascript
Promise.resolve()
  .then(() => console.log(1))
  .then(() => console.log(2));
Promise.resolve()
  .then(() => console.log(3))
  .then(() => console.log(4));
```

> [!TIP]- Ответ
> `1 3 2 4`. Следующий `then` цепочки ставится в очередь только после выполнения предыдущего, поэтому цепочки чередуются.

## Задача 5: executor и resolve

```javascript
const p = new Promise((resolve) => {
  console.log("A");
  resolve("B");
  console.log("C");
});
p.then((v) => console.log(v));
console.log("D");
```

> [!TIP]- Ответ
> `A C D B`. `resolve` не прерывает executor — `C` печатается сразу. Обработчик `then` — микрозадача.

## Задача 6: Node.js — nextTick и setImmediate

```javascript
setTimeout(() => console.log("timeout"), 0);
setImmediate(() => console.log("immediate"));
process.nextTick(() => console.log("nextTick"));
Promise.resolve().then(() => console.log("promise"));
```

> [!TIP]- Ответ
> `nextTick promise`, затем `timeout` и `immediate` **в непредсказуемом порядке** (в главном модуле зависит от времени старта цикла). Очередь `nextTick` выполняется раньше промисов. Внутри I/O-колбэка `setImmediate` всегда раньше `setTimeout(0)`.

## Как решать

```text
1. Пройти код сверху вниз: печатать синхронные логи, раскладывать задачи по очередям
2. Опустошить микрозадачи (новые микрозадачи добавляются в ту же очередь и выполняются сразу)
3. Взять одну макрозадачу → снова все микрозадачи → и так далее
```

| Синхронно | Микрозадача | Макрозадача |
| --- | --- | --- |
| executor `new Promise`, код async-функции до `await` | `then/catch/finally`, код после `await`, `queueMicrotask`, `MutationObserver` | `setTimeout`, `setInterval`, события DOM, `MessageChannel`, `setImmediate` (Node.js) |

## Что важно помнить

- `setTimeout(fn, 0)` — не «сразу», а «после всех микрозадач и не раньше следующего витка цикла».
- Бесконечное добавление микрозадач блокирует рендеринг и макрозадачи.
- Рендеринг в браузере происходит между макрозадачами — см. [event loop и рендеринг](<../../04. JavaScript/05. Асинхронность и Event Loop/04. Что такое event loop.md>).
- Порядок в Node.js: [setTimeout, setImmediate и microtasks](<../../08. Node/03. Event Loop и асинхронность/04. setTimeout, setImmediate и microtasks - порядок выполнения.md>).

## Мини-шпаргалка

Синхронный код → все микрозадачи (nextTick → промисы) → одна макрозадача → все микрозадачи → … Executor — синхронный, после `await` — микрозадача, цепочки `then` чередуются, `resolve` не прерывает executor.
