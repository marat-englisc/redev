# Что выведет: промисы и async/await

> [!NOTE]
> Задачи на цепочки промисов проверяют правила: значение, **возвращенное** из `then`, передается в следующий `then`; **брошенная** ошибка пропускает все `then` до ближайшего `catch`; `catch`, вернувший значение, **восстанавливает** цепочку; `finally` не получает аргументов и **не меняет** значение (если не бросает ошибку); async-функция всегда возвращает промис, а `await` подряд выполняет операции **последовательно**.

## Вопрос

Что выведет каждый фрагмент? Объясните, как значения и ошибки проходят по цепочке промисов.

## Задача 1: ошибка в середине цепочки

```javascript
Promise.resolve(1)
  .then((x) => x + 1)
  .then((x) => { throw new Error(String(x)); })
  .then(() => console.log("не выполнится"))
  .catch((e) => { console.log("catch", e.message); return 10; })
  .then((x) => console.log("then", x))
  .finally(() => console.log("finally"));
```

> [!TIP]- Ответ
> `catch 2`, `then 10`, `finally`. Ошибка пропускает третий `then`, `catch` возвращает 10 — цепочка снова успешная.

## Задача 2: finally и пустой catch

```javascript
Promise.resolve(1)
  .finally(() => 2)
  .then((x) => console.log(x));

Promise.reject(new Error("x"))
  .catch(() => {})
  .then((x) => console.log(x));
```

> [!TIP]- Ответ
> `undefined`, затем `1`. Обе цепочки идут параллельно, но второй цепочке нужно на один шаг меньше: `catch` возвращает `undefined` раньше, чем `finally` первой цепочки передаст значение дальше (finally внутри создает дополнительный промис). Главное: `finally` не меняет значение (`1`), а пустой `catch` дает `undefined`.

## Задача 3: async-функции

```javascript
async function f() { return 1; }
async function g() { throw new Error("g"); }

console.log(f());
console.log(f() instanceof Promise);
g().catch((e) => console.log("caught", e.message));
```

> [!TIP]- Ответ
> `Promise { 1 }` (в браузере — `Promise {<fulfilled>: 1}`), `true`, `caught g`. Async-функция всегда возвращает промис; `throw` внутри превращается в отклоненный промис, а не в синхронное исключение.

## Задача 4: последовательно или параллельно

```javascript
const sleep = (ms, v) => new Promise((r) => setTimeout(() => r(v), ms));

console.time("seq");
const a = await sleep(100, "a");
const b = await sleep(100, "b");
console.timeEnd("seq");

console.time("par");
const [c, d] = await Promise.all([sleep(100, "c"), sleep(100, "d")]);
console.timeEnd("par");
```

> [!TIP]- Ответ
> `seq: ~200ms`, `par: ~100ms`. Два `await` подряд ждут друг друга; `Promise.all` запускает оба сразу.

## Задача 5: return await и try/catch

```javascript
async function load() {
  try {
    return fetchThatFails();          // без await
  } catch {
    return "fallback";
  }
}

async function load2() {
  try {
    return await fetchThatFails();    // с await
  } catch {
    return "fallback";
  }
}

const fetchThatFails = () => Promise.reject(new Error("network"));

load().catch((e) => console.log("load:", e.message));
load2().then((v) => console.log("load2:", v));
```

> [!TIP]- Ответ
> `load: network` и `load2: fallback` (порядок строк может отличаться). Без `await` промис возвращается как есть — `try/catch` его ошибку не видит. С `await` ошибка выбрасывается внутри `try`.

## Задача 6: поздний catch

```javascript
const p = Promise.reject(new Error("oops"));
setTimeout(() => p.catch((e) => console.log("late catch", e.message)), 0);
```

> [!TIP]- Ответ
> В браузере: предупреждение `Uncaught (in promise) Error: oops`, затем `late catch oops`. В Node.js 15+ процесс **завершится** с ошибкой до вызова `catch`: обработчик не был добавлен до конца текущего цикла микрозадач, а необработанное отклонение по умолчанию роняет процесс.

## Задача 7: then с не-функцией

```javascript
Promise.resolve(1)
  .then(2)
  .then(Promise.resolve(3))
  .then(console.log);
```

> [!TIP]- Ответ
> `1`. Если в `then` передана не функция, она игнорируется, и значение проходит дальше без изменений.

## Правила

| Действие в обработчике | Следующий шаг цепочки |
| --- | --- |
| `return value` | `then` получает `value` |
| `return promise` | ждет промис и получает его результат |
| `throw error` / отклоненный промис | ближайший `catch` или второй аргумент `then` |
| ничего не вернуть | `then` получает `undefined` |
| `finally(() => ...)` | значение проходит без изменений (если `finally` не бросил) |

## Что важно помнить

- Всегда возвращайте промис из `then`, если внутри асинхронная операция, иначе цепочка не будет ее ждать.
- `return await` внутри `try` нужен, чтобы поймать ошибку.
- Необработанные отклонения роняют Node.js — добавляйте `catch` сразу.

## Мини-шпаргалка

return → следующий then, throw → ближайший catch, catch с return → восстановление, finally — без аргументов и без изменения значения, не-функция в then игнорируется. Async → всегда промис. Два await подряд — последовательно, `Promise.all` — параллельно. `return await` в `try`.
