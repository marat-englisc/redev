# Задача: curry

> [!NOTE]
> **Каррирование** превращает функцию `f(a, b, c)` в цепочку `f(a)(b)(c)`. Задача `curry(fn)` проверяет понимание замыканий, рекурсии и свойства `fn.length` (число объявленных параметров): обертка накапливает аргументы и вызывает исходную функцию, когда их стало достаточно. Частые продолжения — поддержка вызовов с несколькими аргументами сразу (`f(a, b)(c)`), плейсхолдеров и бесконечного каррирования вида `sum(1)(2)(3)()`.

## Вопрос

Реализуйте `curry(fn)`, чтобы `curry(sum)(1)(2)(3)`, `curry(sum)(1, 2)(3)` и `curry(sum)(1)(2, 3)` давали одинаковый результат. Как сделать «бесконечную» сумму `sum(1)(2)(3)() === 6`?

## Решение

```javascript
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn.apply(this, args);                     // аргументов достаточно — вызываем
    }
    return function (...next) {
      return curried.apply(this, [...args, ...next]);   // накапливаем и пробуем снова
    };
  };
}
```

## Проверка

```javascript
const sum3 = (a, b, c) => a + b + c;
const curried = curry(sum3);

curried(1)(2)(3);     // 6
curried(1, 2)(3);     // 6
curried(1)(2, 3);     // 6
curried(1, 2, 3);     // 6

const add10 = curried(10);   // частичное применение
add10(1)(2);          // 13
```

## Бесконечное каррирование

Вариант 1 — пустой вызов завершает цепочку:

```javascript
function sum(a) {
  return function next(b) {
    if (b === undefined) return a;
    return sum(a + b);
  };
}

sum(1)(2)(3)();   // 6
```

Вариант 2 — через приведение к примитиву:

```javascript
function sum(...first) {
  let total = first.reduce((s, x) => s + x, 0);
  const next = (...args) => {
    total += args.reduce((s, x) => s + x, 0);
    return next;
  };
  next.valueOf = () => total;
  next.toString = () => String(total);
  return next;
}

+sum(1)(2)(3);          // 6
`${sum(1, 2)(3)}`;      // "6"
```

## Плейсхолдеры (продвинутый вариант)

```javascript
const _ = Symbol("placeholder");

function curryWithPlaceholder(fn) {
  return function curried(...args) {
    const complete = args.length >= fn.length && !args.slice(0, fn.length).includes(_);
    if (complete) return fn.apply(this, args);

    return (...next) => {
      const merged = args.map((a) => (a === _ && next.length ? next.shift() : a));
      return curried.apply(this, [...merged, ...next]);
    };
  };
}

const f = curryWithPlaceholder((a, b, c) => `${a}-${b}-${c}`);
f(_, 2)(1, 3);   // "1-2-3"
```

## Доп. вопросы интервьюера

- **Зачем каррирование?** частичное применение и переиспользование: `const logError = log("error")`, композиция функций.
- **Почему `fn.length` ненадежен?** не учитывает rest-параметры и параметры со значением по умолчанию: `((a, b = 1) => {}).length === 1`. Решение — передавать арность вторым аргументом `curry(fn, arity)`.
- **Каррирование и частичное применение — одно и то же?** нет: частичное применение фиксирует часть аргументов (`fn.bind(null, 1)`), каррирование превращает функцию в цепочку унарных.

## Что важно помнить

- Аргументы накапливаются в новом массиве — не мутируйте общий массив, иначе разные ветки частичного применения повлияют друг на друга.
- Сохраняйте `this` через `apply`, если функция может быть методом.
- Теория: [каррирование и частичное применение](<../../04. JavaScript/02. Функции/22. Каррирование и частичное применение.md>).

## Мини-шпаргалка

`curried(...args)`: если `args.length >= fn.length` — `fn.apply`, иначе вернуть функцию, которая вызовет `curried` с `[...args, ...next]`. Бесконечная сумма — пустой вызов или `valueOf`. `fn.length` не считает rest и параметры по умолчанию.
