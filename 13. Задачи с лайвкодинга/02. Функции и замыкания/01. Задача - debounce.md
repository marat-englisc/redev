# Задача: debounce

> [!NOTE]
> **debounce** откладывает вызов функции, пока вызовы продолжаются: функция выполнится один раз через `delay` мс **после последнего вызова**. Решение — замыкание с `timerId`: каждый вызов сбрасывает таймер и ставит новый. Ключевые моменты, которые проверяют: сохранение **`this` и аргументов**, метод **`cancel`**, опции **`leading`/`trailing`** и **`flush`**.

## Вопрос

Реализуйте функцию `debounce(fn, delay)`, которая возвращает обертку: при серии вызовов `fn` вызывается один раз через `delay` мс после последнего вызова с последними аргументами. Добавьте метод `cancel`.

## Решение

```javascript
function debounce(fn, delay) {
  let timerId = null;

  function debounced(...args) {
    clearTimeout(timerId);
    timerId = setTimeout(() => {
      timerId = null;
      fn.apply(this, args);                // сохраняем this и аргументы последнего вызова
    }, delay);
  }

  debounced.cancel = () => {
    clearTimeout(timerId);
    timerId = null;
  };

  return debounced;
}
```

Обертка объявлена через `function`, а не стрелку, чтобы получить `this` вызова; внутри `setTimeout` стрелочная функция берет этот `this` из обертки.

## Проверка

```javascript
const log = debounce((x) => console.log("search:", x), 300);
log("r"); log("re"); log("rea"); log("react");
// через 300 мс после последнего вызова: "search: react" — один раз

const obj = {
  name: "Анна",
  greet: debounce(function () { console.log(this.name); }, 100),
};
obj.greet();          // через 100 мс: "Анна"
```

## Расширенная версия: leading, trailing, flush

```javascript
function debounce(fn, delay, { leading = false, trailing = true } = {}) {
  let timerId = null;
  let lastArgs = null;
  let lastThis = null;

  function invoke() {
    const args = lastArgs, ctx = lastThis;
    lastArgs = lastThis = null;
    return fn.apply(ctx, args);
  }

  function debounced(...args) {
    lastArgs = args;
    lastThis = this;
    const isFirstCall = timerId === null;

    clearTimeout(timerId);
    timerId = setTimeout(() => {
      timerId = null;
      if (trailing && lastArgs) invoke();   // не вызывать повторно, если уже вызвали на leading
      lastArgs = lastThis = null;
    }, delay);

    if (leading && isFirstCall) invoke();   // вызов в начале серии
  }

  debounced.cancel = () => {
    clearTimeout(timerId);
    timerId = null;
    lastArgs = lastThis = null;
  };

  debounced.flush = () => {
    if (timerId !== null && lastArgs) {
      clearTimeout(timerId);
      timerId = null;
      invoke();                              // выполнить отложенный вызов сразу
    }
  };

  return debounced;
}
```

## Доп. вопросы интервьюера

- **Чем отличается от throttle?** debounce ждет паузы, throttle вызывает не чаще раза в интервал.
- **Где применяют?** поиск по вводу, ресайз окна, автосохранение, валидация поля.
- **Как использовать в React?** создать один раз (`useMemo`/`useRef`) и вызывать `cancel` в cleanup; либо хук `useDebouncedValue`.
- **Как вернуть результат?** вариант с Promise: каждый вызов возвращает промис, который разрешится результатом итогового вызова.
- **Как протестировать?** fake timers: `vi.useFakeTimers()` + `vi.advanceTimersByTime(300)`.

## Что важно помнить

- `fn.apply(this, args)` — без этого теряются контекст и аргументы.
- При `leading: true, trailing: true` и единственном вызове функция не должна выполниться дважды.
- В React debounce, созданный в теле компонента без мемоизации, пересоздается каждый рендер и не работает.
- Теория и сравнение с throttle: [debounce и throttle](<../../04. JavaScript/09. Производительность в JS/15. debounce и throttle.md>).

## Мини-шпаргалка

Замыкание с `timerId`: `clearTimeout` + новый `setTimeout` на каждый вызов, `fn.apply(this, args)` в таймере. `cancel` — очистить таймер. `leading` — вызов в начале серии, `trailing` — в конце, `flush` — выполнить отложенный сразу.
