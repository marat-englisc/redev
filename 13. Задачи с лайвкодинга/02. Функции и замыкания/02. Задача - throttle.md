# Задача: throttle

> [!NOTE]
> **throttle** ограничивает частоту вызовов: функция выполняется **не чаще одного раза за `interval` мс**, как бы часто ее ни вызывали. Классическая реализация: первый вызов выполняется сразу, а вызовы во время «окна» запоминаются, и последний из них выполняется в конце окна (trailing). Проверяют сохранение `this` и аргументов, отсутствие потери последнего вызова и метод `cancel`.

## Вопрос

Реализуйте `throttle(fn, interval)`: при частых вызовах `fn` выполняется не чаще раза в `interval` мс. Первый вызов — сразу, последний вызов в окне не должен потеряться.

## Решение

```javascript
function throttle(fn, interval) {
  let timerId = null;
  let lastArgs = null;
  let lastThis = null;

  function run() {
    if (lastArgs === null) {
      timerId = null;                   // в окне не было новых вызовов — окно закончилось
      return;
    }
    fn.apply(lastThis, lastArgs);
    lastArgs = lastThis = null;
    timerId = setTimeout(run, interval); // открыть новое окно после trailing-вызова
  }

  function throttled(...args) {
    if (timerId === null) {
      fn.apply(this, args);              // leading: сразу
      timerId = setTimeout(run, interval);
    } else {
      lastArgs = args;                   // запомнить последний вызов в окне
      lastThis = this;
    }
  }

  throttled.cancel = () => {
    clearTimeout(timerId);
    timerId = null;
    lastArgs = lastThis = null;
  };

  return throttled;
}
```

## Проверка

```javascript
const log = throttle((x) => console.log(x, Date.now() % 10000), 1000);

log(1);                       // сразу: 1
setTimeout(() => log(2), 200);
setTimeout(() => log(3), 500); // 2 перезаписан
// ~1000 мс: 3 (trailing)
// если вызовов больше нет — через еще 1000 мс окно закроется без вызова
```

## Простая версия на временной метке

```javascript
function throttle(fn, interval) {
  let last = 0;
  return function (...args) {
    const now = Date.now();
    if (now - last >= interval) {
      last = now;
      fn.apply(this, args);
    }
  };
}
```

Короче, но **теряет последний вызов**: если пользователь закончил скроллить внутри окна, финальное положение не обработается. Об этом стоит сказать интервьюеру.

## Throttle через requestAnimationFrame

```javascript
function rafThrottle(fn) {
  let frameId = null;
  let lastArgs;
  return function (...args) {
    lastArgs = args;
    if (frameId !== null) return;
    frameId = requestAnimationFrame(() => {
      frameId = null;
      fn.apply(this, lastArgs);
    });
  };
}
```

Подходит для обработчиков `scroll`, `pointermove`, `resize`, которые меняют UI: не чаще одного раза за кадр.

## Доп. вопросы интервьюера

- **debounce или throttle для скролла?** throttle (или rAF): нужна реакция во время скролла, а не после.
- **для поиска?** debounce: запрос после паузы ввода.
- **Как сделать на основе debounce?** lodash реализует throttle как debounce с `maxWait = wait` и `leading: true`.

## Что важно помнить

- Версия на `Date.now()` теряет trailing-вызов; версия с таймером — нет.
- Сохраняйте `this` и аргументы последнего вызова.
- Для анимаций и измерений DOM лучше rAF, чем фиксированный интервал.
- Теория: [debounce и throttle](<../../04. JavaScript/09. Производительность в JS/15. debounce и throttle.md>), [requestAnimationFrame](<../../04. JavaScript/05. Асинхронность и Event Loop/10. Что делает requestAnimationFrame().md>).

## Мини-шпаргалка

throttle: первый вызов сразу, дальше — таймер-окно, последний вызов в окне выполняется в его конце. `fn.apply(this, args)`, `cancel`. Версия на `Date.now()` проще, но теряет trailing. Для UI — `requestAnimationFrame`.
