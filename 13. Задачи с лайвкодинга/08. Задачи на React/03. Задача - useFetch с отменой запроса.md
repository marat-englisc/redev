# Задача: useFetch с отменой запроса

> [!NOTE]
> `useFetch(url)` — классическая задача на React: хук загружает данные и возвращает `{ data, error, loading, refetch }`. Обязательные части решения: **состояния** загрузки, ошибки и данных; **отмена** запроса через `AbortController` в cleanup эффекта (смена `url` или размонтирование); **защита от гонок** — ответ на старый `url` не должен перезаписать новый; проверка `response.ok`; возможность повторить запрос. На собеседовании стоит сказать, что в production для этого используют TanStack Query или SWR.

## Вопрос

Реализуйте хук `useFetch<T>(url, options?)`, который возвращает `{ data, error, loading, refetch }`, отменяет запрос при смене `url` и размонтировании и не допускает гонок ответов.

## Решение

```tsx
import { useCallback, useEffect, useReducer, useState } from "react";

type State<T> =
  | { status: "idle" | "loading"; data?: T; error?: undefined }
  | { status: "success"; data: T; error?: undefined }
  | { status: "error"; data?: T; error: Error };

export function useFetch<T>(url: string | null, init?: RequestInit) {
  const [state, setState] = useState<State<T>>({ status: "idle" });
  const [reloadKey, reload] = useReducer((x: number) => x + 1, 0);

  useEffect(() => {
    if (!url) return;                                     // условная загрузка
    const controller = new AbortController();

    setState((s) => ({ status: "loading", data: s.data })); // старые данные оставляем, пока грузятся новые

    (async () => {
      try {
        const res = await fetch(url, { ...init, signal: controller.signal });
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        const data = (await res.json()) as T;
        setState({ status: "success", data });
      } catch (e) {
        if (controller.signal.aborted) return;            // отмена — не ошибка и не обновление state
        setState((s) => ({ status: "error", data: s.data, error: e as Error }));
      }
    })();

    return () => controller.abort();                      // смена url / reload / размонтирование
    // init намеренно не в зависимостях: объект пересоздается каждый рендер
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, [url, reloadKey]);

  const refetch = useCallback(() => reload(), []);

  return {
    data: state.data,
    error: state.error,
    loading: state.status === "loading",
    refetch,
  };
}
```

## Использование

```tsx
type User = { id: number; name: string };

function UserProfile({ id }: { id: number }) {
  const { data, error, loading, refetch } = useFetch<User>(`/api/users/${id}`);

  if (loading && !data) return <Skeleton />;
  if (error) {
    return (
      <div role="alert">
        Не удалось загрузить профиль. <button onClick={refetch}>Повторить</button>
      </div>
    );
  }
  if (!data) return null;

  return <h1 aria-busy={loading}>{data.name}</h1>;
}
```

## Почему отмена важна

```text
id=1 → запрос A (медленный)
id=2 → запрос B (быстрый) → ответ B → показали пользователя 2
     → ответ A приходит позже → без отмены показали бы пользователя 1 для id=2
```

`controller.abort()` в cleanup отменяет A при смене `id`. Даже если API не поддерживает отмену, проверка `signal.aborted` не даст обновить state устаревшим ответом.

## Доп. вопросы интервьюера

- **Почему эффект запускается дважды в dev?** Strict Mode монтирует компонент дважды; первый запрос отменяется — это проверка правильного cleanup.
- **Как добавить кеш?** `Map` url → данные на уровне модуля или контекста; дальше — дедупликация, TTL, инвалидация. Это и есть TanStack Query.
- **Почему не `async` функция эффекта?** эффект должен вернуть cleanup, а не Promise.
- **Как сделать с Suspense?** хуком `use(promise)` с кешированием промиса снаружи компонента.
- **Что не так с этим подходом в целом?** водопады запросов, нет кеша между компонентами, нет SSR — поэтому в production выбирают библиотеку или загрузку на сервере.

## Что важно помнить

- Всегда проверяйте `res.ok`: `fetch` не бросает на 404 и 500.
- Отмена в cleanup решает и гонки, и обновление state после размонтирования.
- Не кладите объект `init` в зависимости без мемоизации — будет бесконечный цикл запросов.

## Мини-шпаргалка

`useEffect([url, reloadKey])`: `AbortController` → `setState(loading)` → `fetch(url, { signal })` → `res.ok` → `success` или `error` (если не `aborted`) → cleanup `abort()`. `refetch` — счетчик в `useReducer`. Старые данные держать во время перезагрузки. В production — TanStack Query.
