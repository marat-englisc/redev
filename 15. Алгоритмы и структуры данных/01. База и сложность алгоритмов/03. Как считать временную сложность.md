# Как считать временную сложность?

> [!NOTE]
> Временная сложность показывает, сколько операций делает алгоритм при росте input. Чтобы ее считать, нужно смотреть на циклы, рекурсию, вложенные структуры, вызовы методов и то, сколько раз каждый элемент реально обрабатывается.

## Вопрос

Как посчитать временную сложность алгоритма по коду?

## Один цикл

```ts
function sum(nums: number[]): number {
  let total = 0

  for (const num of nums) {
    total += num
  }

  return total
}
```

Массив длины `n`, один проход:

```text
O(n)
```

## Два независимых цикла

```ts
function process(a: number[], b: number[]): void {
  for (const x of a) console.log(x)
  for (const y of b) console.log(y)
}
```

Если размеры разные:

```text
O(a + b)
```

Не нужно автоматически писать `O(n)`, если inputs независимы.

## Вложенные циклы

```ts
function pairs(nums: number[]): void {
  for (let i = 0; i < nums.length; i++) {
    for (let j = 0; j < nums.length; j++) {
      console.log(nums[i], nums[j])
    }
  }
}
```

Каждый элемент сравнивается с каждым:

```text
O(n^2)
```

## Цикл с делением пополам

```ts
function binarySearch(nums: number[], target: number): number {
  let left = 0
  let right = nums.length - 1

  while (left <= right) {
    const mid = Math.floor((left + right) / 2)

    if (nums[mid] === target) return mid
    if (nums[mid] < target) left = mid + 1
    else right = mid - 1
  }

  return -1
}
```

На каждом шаге отбрасываем половину:

```text
O(log n)
```

## Учитывай встроенные методы

```ts
const result = nums.filter((x) => x > 0).map((x) => x * 2)
```

`filter` проходит массив, `map` проходит новый массив:

```text
O(n)
```

Но с двумя проходами. Big O одинаковый, константа больше.

## Что отвечать на собеседовании?

Чтобы посчитать time complexity, я определяю размер input, смотрю, сколько раз каждый элемент обрабатывается, учитываю вложенные циклы, рекурсию и стоимость встроенных методов. Последовательные проходы складываются, вложенные часто перемножаются, а деление области поиска пополам дает `O(log n)`.

## Что важно помнить: частые ошибки

- Не учитывать `sort`, `slice`, `includes`, `shift`.
- Писать `O(n^2)` для любых двух циклов, даже если они не вложенные.
- Забывать, что `Array.prototype.shift()` может быть `O(n)`.
- Не различать `n` и `m` для двух inputs.
- Оценивать только happy path.

## Мини-шпаргалка

- Один проход - `O(n)`.
- Два независимых прохода - `O(n + m)` или `O(n)`.
- Вложенные циклы - часто `O(n^2)`.
- Деление пополам - `O(log n)`.
- Сортировка - часто `O(n log n)`.
- Встроенные методы тоже имеют стоимость.
