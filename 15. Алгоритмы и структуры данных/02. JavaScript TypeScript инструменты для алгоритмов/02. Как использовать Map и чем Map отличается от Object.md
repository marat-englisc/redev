# Как использовать Map и чем Map отличается от Object

> [!NOTE]
> `Map` - структура ключ-значение. В алгоритмах ее используют для частот, индексов, кеша, adjacency list, memoization и быстрого поиска по ключу.
>
> `Object` - обычный JS-объект со строковыми/symbol ключами и prototype-наследованием, а `Map` - специализированная коллекция ключ-значение, где ключом может быть любое значение. Для алгоритмов чаще удобнее `Map`.

## Вопрос

Как использовать Map в алгоритмах и почему для словаря Map часто удобнее Object?

## Базовый API

```ts
const count = new Map<string, number>()

count.set('a', 1)
count.set('a', (count.get('a') ?? 0) + 1)

console.log(count.has('a'))
console.log(count.get('a'))
console.log(count.delete('a'))
console.log(count.size)
```

## Частотный словарь

```ts
function frequency(words: string[]): Map<string, number> {
  const map = new Map<string, number>()

  for (const word of words) {
    map.set(word, (map.get(word) ?? 0) + 1)
  }

  return map
}
```

## Two Sum

```ts
function twoSum(nums: number[], target: number): [number, number] | null {
  const indexByValue = new Map<number, number>()

  for (let i = 0; i < nums.length; i++) {
    const need = target - nums[i]

    if (indexByValue.has(need)) {
      return [indexByValue.get(need)!, i]
    }

    indexByValue.set(nums[i], i)
  }

  return null
}
```

Time `O(n)`, space `O(n)`.

## Почему Map, а не обычный object?

`Map` удобнее, когда:

- ключи не только строки;
- нужен стабильный `size`;
- важна итерация по entries;
- нужно избежать конфликтов с prototype keys;
- ключами могут быть объекты.

## Что отвечать на собеседовании?

`Map` хранит пары ключ-значение и подходит для быстрого доступа по ключу. В алгоритмах я использую `Map` для frequency counter, хранения индексов, memoization, adjacency list и кешей. В отличие от object, `Map` поддерживает ключи любых типов и имеет удобные методы `set`, `get`, `has`, `delete`, `size`.

Для частот по строкам можно использовать object или `Map`, но `Map` лучше выражает намерение "словарь" и поддерживает ключи любых типов. Object хорош для простых records, особенно когда структура заранее известна. В алгоритмах я обычно выбираю `Map`, чтобы избежать проблем с prototype keys и удобно работать с `size`, `has`, `get`, `set`.

## Что важно помнить: частые ошибки

- Использовать `map.get(key) || 0`, если значение может быть `0`, `false` или пустой строкой.
- Забывать, что объектные ключи сравниваются по ссылке.
- Использовать object там, где ключ не строка.
- Не обновлять значение через `set`.
- Путать `Map.prototype.map` - такого метода нет.

- Использовать object для ключей-объектов и получать `"[object Object]"`.
- Проверять наличие через truthy-value вместо `has`.
- Не учитывать prototype keys.
- Путать `Record<string, T>` и `Map<K, V>`.
- Ожидать value equality для object keys.

## Object как словарь

```ts
const count: Record<string, number> = {}

count.apple = 1
count.apple = (count.apple ?? 0) + 1
```

Работает хорошо для простых строковых ключей.

## Сравнение Object и Map

| Критерий | Object | Map |
| --- | --- | --- |
| Ключи | string/symbol | любые значения |
| Размер | `Object.keys(obj).length` | `map.size` |
| Prototype keys | есть риск | нет такого риска |
| Итерация | через `Object.entries` | `for...of map` |
| Алгоритмы | можно | часто удобнее |

## Объектные ключи

```ts
const a = { id: 1 }
const b = { id: 1 }

const map = new Map<object, string>()
map.set(a, 'first')

console.log(map.get(a)) // first
console.log(map.get(b)) // undefined
```

Объекты сравниваются по ссылке, не по содержимому.

## Мини-шпаргалка

- `set` - записать.
- `get` - получить.
- `has` - проверить.
- `delete` - удалить.
- `size` - размер.
- Частоты: `(map.get(x) ?? 0) + 1`.
- Object - хорошо для known shape.
- Map - хорошо для dynamic dictionary.
- Map keys могут быть любыми.
- Object keys чаще string/symbol.
- `map.size` удобнее.
- Object keys с объектами опасны.
