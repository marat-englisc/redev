# Можно ли использовать Next.js только как frontend

> [!NOTE]
> Next.js можно использовать как интерфейс к отдельному backend. Собственные HTTP-обработчики, база данных и Server Actions для этого не обязательны.

## Вопрос

Зачем нужен Next.js, если API уже написан на другом языке или фреймворке?

## Основная идея

Например, отдельный сервис хранит товары и заказы, а Next.js отвечает за страницы магазина. Backend предоставляет HTTP API — адреса, по которым можно получить или изменить данные.

Next.js может обращаться к этому API на сервере и готовить HTML с результатом. Либо клиентский компонент запрашивает данные из браузера, если они нужны после действия пользователя.

Иногда между интерфейсом и основным API нужен **BFF**, Backend For Frontend: серверный слой, который объединяет ответы нескольких сервисов или подготавливает данные под конкретный экран. Next.js способен выполнять и эту роль.

## Пример: пользователи из отдельного API

JSONPlaceholder — публичный учебный API; его пользователи вымышленные.

```tsx
// app/users/page.tsx
// Пример для App Router без cacheComponents.
type User = { id: number; name: string };

export default async function UsersPage() {
  const response = await fetch(
    "https://jsonplaceholder.typicode.com/users",
    { cache: "no-store" },
  );

  if (!response.ok) throw new Error("API пользователей недоступен");
  const users: User[] = await response.json();

  return (
    <main>
      <h1>Пользователи</h1>
      <ul>
        {users.map(user => <li key={user.id}>{user.name}</li>)}
      </ul>
    </main>
  );
}
```

На `/users` появится список имен. Запрос выполняет сервер Next.js, а браузер получает интерфейс. `no-store` явно отключает сохранение ответа в постоянном Data Cache и требует актуального серверного запроса при рендеринге.

## Что важно помнить

«Только frontend» может описывать ответственность команды, но приложение с SSR все равно использует серверную среду Next.js.

Если нужен хостинг только файлов, можно рассмотреть статический экспорт. Тогда серверное выполнение при посещении, динамические Server Actions и другие серверные возможности недоступны.

Браузерные запросы к другому домену зависят от CORS — правил доступа, заданных внешним API. Серверные запросы не ограничены браузерным CORS, но по-прежнему требуют корректной авторизации.

## Мини-шпаргалка

- Отдельный backend совместим с Next.js.
- Свой `app/api` создавать необязательно.
- SSR требует серверной среды, даже при внешнем API.
- Статический экспорт подходит только для совместимых возможностей.
