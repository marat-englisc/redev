# Почему Next.js считается fullstack-фреймворком

> [!NOTE]
> **Fullstack-фреймворк** дает инструменты и для пользовательского интерфейса, и для серверной части. В Next.js обе части можно разрабатывать в одном проекте.

## Вопрос

Какие серверные задачи способен выполнять Next.js помимо отображения React-компонентов?

## Основная идея

Frontend показывает интерфейс и обрабатывает действия пользователя. Backend проверяет права, получает данные, сохраняет изменения и отвечает на HTTP-запросы.

В App Router эти задачи можно распределить так:

- **Server Components** получают данные и подготавливают интерфейс на сервере.
- **Route Handlers** принимают HTTP-запросы и возвращают JSON или другой ответ.
- **Server Actions** обрабатывают действия, например отправку формы, выполняясь на сервере.
- **Client Components** обеспечивают состояние, события и работу с браузерными API.

Next.js не содержит собственную базу данных. Он позволяет подключить подходящее хранилище или внешний сервис.

## Пример: HTTP-обработчик и страница

```ts
// app/api/health/route.ts
export async function GET() {
  return Response.json({ status: "ok", service: "book-shop" });
}
```

```tsx
// app/page.tsx
export default function HomePage() {
  return (
    <main>
      <h1>Книжный магазин</h1>
      <a href="/api/health">Проверить ответ сервера</a>
    </main>
  );
}
```

Главная страница показывает интерфейс. Открыв `/api/health`, пользователь увидит JSON с состоянием сервиса. В примере нет базы данных: обработчик возвращает заранее заданный ответ, поэтому его можно проверить сразу.

Это **Route Handler** App Router. В Pages Router аналогичный HTTP-интерфейс называется **API Route** и создается в `pages/api` с другой сигнатурой обработчика.

## Что важно помнить

Совместное расположение файлов не отменяет границу между сервером и браузером. Секретный API-ключ должен оставаться в серверном коде. Все данные, выведенные на страницу или возвращенные API, доступны получателю.

Серверная функция не проверяет права автоматически. Доступ пользователя и входные данные нужно проверять при каждой операции.

Сложная серверная система может оставаться отдельным приложением. Next.js часто выполняет только роль интерфейса и промежуточного сервера для него.

## Мини-шпаргалка

- Next.js поддерживает интерфейс и серверные обработчики.
- `route.ts` создает HTTP-ответ в App Router.
- Server Action выполняет операцию на сервере.
- База данных и правила доступа требуют отдельной реализации.
