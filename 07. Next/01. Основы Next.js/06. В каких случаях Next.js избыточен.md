# В каких случаях Next.js может быть избыточен

> [!NOTE]
> Next.js может быть избыточен, если проекту достаточно клиентского React-приложения, а серверные возможности и соглашения фреймворка не приносят заметной пользы.

## Вопрос

Как понять, оправданы ли дополнительные возможности Next.js для конкретного проекта?

## Основная идея

Выбор инструмента начинается с требований. Небольшой калькулятор, который работает полностью в браузере, может обходиться без сервера рендеринга. Для него достаточно собрать HTML, CSS и JavaScript и разместить файлы на хостинге.

Для внутреннего интерфейса с готовым API серверный рендеринг также может быть необязателен. Если команда уже умеет создавать клиентские приложения, отдельные правила серверных компонентов и кэширования потребуют времени на изучение.

Это не означает, что Next.js нельзя использовать для админки или проекта с отдельным backend. Вложенные макеты, маршруты и единая инфраструктура могут быть полезны и там. Оценивай конкретную выгоду.

## Пример: калькулятор без серверных данных

Такой компонент подходит для обычного React-проекта:

```tsx
import { useState } from "react";

export default function PriceCalculator() {
  const [quantity, setQuantity] = useState(1);
  const price = 300;

  return (
    <div>
      <label>
        Количество:
        <input
          type="number"
          min="1"
          value={quantity}
          onChange={event => {
            setQuantity(Math.max(1, Number(event.target.value)));
          }}
        />
      </label>
      <p>Стоимость: {quantity * price} ₽</p>
    </div>
  );
}
```

При изменении количества пересчитывается сумма. Компонент не получает секретные данные, не использует сервер и не нуждается в отдельной странице для каждого результата. Его можно запустить в React-проекте, например с Vite. В App Router для него потребовался бы `"use client"`.

## Что важно помнить

Число страниц само по себе ничего не решает. Даже одностраничному сайту могут быть полезны предварительный HTML, метаданные и удобная работа с изображениями.

Next.js умеет статический экспорт, поэтому его использование не всегда означает постоянно работающий сервер. Но ограничения такого режима нужно учитывать.

Учитывай требования к загрузке, публикации, работе команды и дальнейшему развитию, а не только наличие SEO.

## Мини-шпаргалка

- Сначала определи задачи приложения.
- Для полностью браузерного инструмента сервер может быть лишним.
- Админка или внешний backend не исключают Next.js.
- Дополнительные возможности должны оправдывать сложность.
