# Какие задачи лучше решать клиентскими компонентами

> [!NOTE]
> Клиентские компоненты нужны там, где интерфейс хранит локальное состояние, обрабатывает события пользователя или взаимодействует с возможностями браузера.

## Вопрос

Какие признаки подсказывают, что компоненту необходима директива `"use client"`?

## Основная идея

Кнопка раскрытия ответа должна помнить, открыт ли ответ, и менять это состояние при клике. Поле поиска хранит введенный текст. Редактор отслеживает положение курсора. Такие задачи выполняются в браузере и требуют клиентского компонента.

Типичные признаки - `useState`, `useEffect`, обработчики `onClick` и `onChange`, чтение `localStorage`, подписки на события окна. Клиентские библиотеки графиков и интерфейса тоже часто требуют отдельной клиентской обертки.

При этом обычная ссылка или HTML-форма не всегда требуют своего JavaScript. Например, навигацию можно реализовать через `Link`, а отправку серверной формы - через Server Function.

## Пример: раскрывающийся ответ

```tsx
// app/faq-item.tsx
"use client";

import { useId, useState } from "react";

type Props = { question: string; answer: string };

export default function FaqItem({ question, answer }: Props) {
  const [open, setOpen] = useState(false);
  const answerId = useId();

  return (
    <section>
      <button
        aria-expanded={open}
        aria-controls={answerId}
        onClick={() => setOpen(value => !value)}
      >
        {question}
      </button>
      <p id={answerId} hidden={!open}>{answer}</p>
    </section>
  );
}
```

```tsx
// app/faq/page.tsx
import FaqItem from "../faq-item";

export default function Page() {
  return <FaqItem question="Что такое props?" answer="Входные данные компонента." />;
}
```

Ответ сначала скрыт. Нажатие переключает `open` и видимость текста. `aria-expanded` сообщает состояние вспомогательным технологиям, а `useId` дает устойчивую связь кнопки с ответом.

## Что важно помнить

Ставь клиентскую границу вокруг той части, которой нужна интерактивность. Если весь текст статьи импортировать из клиентского файла вместе с тяжелыми библиотеками, размер браузерной сборки может вырасти.

Клиентский компонент тоже может предварительно рендериться на сервере. Поэтому браузерные объекты читают в эффекте или обработчике, а не безусловно в теле рендера.

Эффекты с таймерами и подписками должны возвращать функцию очистки. Клиентские данные также требуют обработки загрузки и ошибок.

## Мини-шпаргалка

- Локальный state, события, DOM и браузерные API - признаки клиентской задачи.
- Небольшая клиентская граница сохраняет остальной код серверным.
- Для простого раскрытия иногда достаточно нативного `<details>`.
