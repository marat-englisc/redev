# Что такое клиентские компоненты в Next.js

> [!NOTE]
> **Client Components, клиентские компоненты**, - компоненты, для которых Next.js отправляет JavaScript в браузер, чтобы поддерживать состояние, события и браузерные возможности.

## Вопрос

Когда нужен клиентский компонент и где он выполняется при первой загрузке страницы?

## Основная идея

Текст статьи обычно не требует JavaScript для каждого абзаца. А кнопке «Нравится» нужны обработчик клика и текущее количество отметок. Для такой части интерфейса создают клиентскую границу директивой `"use client"`.

Слово «клиентский» не означает «никогда не рендерится на сервере». При первой загрузке Next.js обычно предварительно создает HTML клиентского компонента. Затем браузер загружает его JavaScript и подключает поведение через гидратацию.

Поэтому `window` и `localStorage` нельзя безусловно читать прямо во время рендера. Их используют в обработчиках событий или эффектах, которые выполняются в браузере.

## Пример: кнопка с локальным состоянием

```tsx
// app/like-button.tsx
"use client";

import { useState } from "react";

export default function LikeButton() {
  const [likes, setLikes] = useState(0);

  return (
    <button onClick={() => setLikes(current => current + 1)}>
      Нравится: {likes}
    </button>
  );
}
```

```tsx
// app/page.tsx
import LikeButton from "./like-button";

export default function Page() {
  return (
    <article>
      <h1>Как учить React</h1>
      <p>Начни с компонентов и передачи props.</p>
      <LikeButton />
    </article>
  );
}
```

Страница остается серверной. В начальном HTML кнопка показывает `0`; после гидратации каждый клик увеличивает число. Это учебный счетчик: отметки хранятся в памяти компонента и сбрасываются при полной перезагрузке.

## Что важно помнить

Директива стоит перед импортами и обозначает границу клиентского графа. Импортируемые из этого файла компоненты и используемые зависимости тоже могут попасть в клиентскую сборку.

Не переноси в клиентский код запросы к базе с секретным ключом. Клиент взаимодействует с сервером через предусмотренный интерфейс, например Route Handler или Server Function.

При этом серверный родитель может передать готовое серверное содержимое клиентской обертке через `children`: визуальная вложенность не равна импорту модуля.

## Мини-шпаргалка

- `useState`, эффекты и обработчики событий требуют клиентской стороны.
- `"use client"` создает границу, а не отключает начальный HTML.
- Небольшие клиентские блоки уменьшают объем JavaScript.
- Локальный state сам по себе не сохраняется на сервере.
