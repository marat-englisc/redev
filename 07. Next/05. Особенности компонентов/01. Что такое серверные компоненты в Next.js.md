# Что такое серверные компоненты в Next.js

> [!NOTE]
> **Server Components, серверные компоненты React**, — компоненты, которые вычисляют свой результат на сервере. Их собственный код не отправляется в браузер как клиентский JavaScript.

## Вопрос

Для чего нужны серверные компоненты, чем они отличаются от клиентских и почему серверный компонент не обязательно рендерится на каждый запрос?

## Основная идея

В App Router страницы и layout по умолчанию серверные. Они могут получать данные, обращаться к серверным ресурсам и превращать результат в интерфейс. Браузеру нужен результат этой работы, а код доступа к базе, библиотеки и обработка содержимого остаются на сервере.

Представь страницу книги. Название и описание можно получить на сервере и сразу включить в результат. Кнопка «В избранное» может быть отдельным Client Component, поскольку ей нужны события и состояние. Чтобы использовать `useState`, `useEffect` или обработчики событий, интерактивную часть выделяют в компонент с `"use client"`.

Next.js передает описание серверного дерева в специальном формате — React Server Component Payload (RSC payload). При первой загрузке дополнительно формируется HTML, чтобы браузер мог быстро показать страницу; при клиентской навигации передается RSC payload.

Это механизм разделения серверного и клиентского кода. Он отличается от стратегии SSR: серверный компонент может выполняться заранее при сборке, при обновлении кэша или во время запроса.

## Пример: список книг

```tsx
// app/books/page.tsx
async function getBooks() {
  return [
    { id: 1, title: "Основы JavaScript" },
    { id: 2, title: "Первые шаги в React" },
  ];
}

export default async function Page() {
  const books = await getBooks();

  return (
    <main>
      <h1>Книги</h1>
      <ul>
        {books.map(book => <li key={book.id}>{book.title}</li>)}
      </ul>
    </main>
  );
}
```

`getBooks` — учебная асинхронная функция с заранее заданными данными. В рабочем проекте она могла бы читать базу данных. Пользователь увидит список из двух книг; реализация загрузки останется на сервере.

## Пример: серверная карточка из API

Next.js 16 App Router без `cacheComponents`. JSONPlaceholder возвращает учебную запись.

```tsx
// app/page.tsx
export default async function Page() {
  const response = await fetch(
    "https://jsonplaceholder.typicode.com/posts/1",
    { cache: "no-store" }
  );
  if (!response.ok) throw new Error("Не удалось получить описание");

  const post: { title: string; body: string } = await response.json();
  return <article><h1>{post.title}</h1><p>{post.body}</p></article>;
}
```

Компонент ожидает API на сервере, затем возвращает JSX.

## Что важно помнить

- Серверные компоненты не используют `useState`, `useEffect` и браузерные обработчики `onClick`. Интерактивную часть выносят в клиентский компонент.
- Серверный компонент может импортировать клиентский и передать ему сериализуемые props; произвольная функция-обработчик через эту границу не передается.
- `"use server"` серверному компоненту не нужна: эта директива объявляет Server Functions.
- Server Component не равен «статическая страница»: он может вычисляться при сборке или при запросе.
- Секрет остается на сервере, но выведенные данные доступны пользователю. Нельзя передавать токены в JSX или клиентские props.
- Импорт серверного модуля из клиентского файла не сохраняет его серверную природу. Для защиты модулей данных применяют `import "server-only"`.

## Мини-шпаргалка

- Страницы и layout в `app` — серверные по умолчанию.
- Код серверного компонента не попадает в клиентский бандл.
- Можно `async`/`await`, БД, секреты; нельзя state, эффекты, события.
- Серверный компонент ≠ SSR на каждый запрос.
