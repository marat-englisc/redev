# Что такое гибридный рендеринг в Next.js

> [!NOTE]
> **Гибридный рендеринг** - сочетание серверной подготовки содержимого и клиентской интерактивности, а также разных стратегий подготовки маршрутов внутри приложения.

## Вопрос

Как соединить готовое описание товара и интерактивную кнопку, не превращая всю страницу в клиентскую?

## Основная идея

У страницы товара есть разные задачи. Описание нужно показать сразу, цену получить из источника данных, а выбранное количество менять по клику. Эти задачи не обязаны выполняться в одной среде.

App Router позволяет серверному компоненту подготовить содержимое и встроить клиентские компоненты для поведения. При первой загрузке браузер получает HTML, а затем подключает JavaScript интерактивных частей.

На уровне приложения справочная страница может быть статической, публичный каталог - обновляться через ISR, а кабинет - рендериться по запросу. Это еще один смысл сочетания стратегий.

## Пример: товар и выбранное количество

```tsx
// app/quantity.tsx
"use client";

import { useState } from "react";

export default function Quantity({ productName }: { productName: string }) {
  const [count, setCount] = useState(1);

  return (
    <button onClick={() => setCount(value => value + 1)}>
      {productName}: выбрано {count}
    </button>
  );
}
```

```tsx
// app/book/page.tsx
import Quantity from "../quantity";

export default function Page() {
  const book = { name: "Введение в Next.js", description: "Учимся строить страницы." };

  return (
    <article>
      <h1>{book.name}</h1>
      <p>{book.description}</p>
      <Quantity productName={book.name} />
    </article>
  );
}
```

В примере используется локальный объект книги вместо настоящего API. Заголовок и описание подготавливает серверная страница. Кнопка сначала показывает количество `1`, а после гидратации увеличивает его по нажатию. Покупка не отправляется на сервер: это демонстрация локального состояния.

## Что важно помнить

Тип компонента и время рендеринга - разные понятия. Клиентский компонент может войти в заранее подготовленный HTML. Серверный компонент может выполняться при сборке или по запросу.

В обычном режиме без `cacheComponents` нельзя автоматически приписать каждому блоку независимый режим HTML-кэширования «этот SSG, этот SSR». Динамическая зависимость может сделать весь маршрут динамическим, даже если отдельные данные кэшируются. Частичный пререндеринг с Cache Components рассматривается отдельно.

Сочетание компонентов полезно оценивать по конкретному результату: объему JavaScript, времени показа содержимого и необходимой свежести данных.

## Мини-шпаргалка

- Сервер готовит данные и содержимое.
- Клиент поддерживает интерактивность.
- Граница компонентов не равна границе кэша HTML.
- Разные маршруты могут иметь разные стратегии.
