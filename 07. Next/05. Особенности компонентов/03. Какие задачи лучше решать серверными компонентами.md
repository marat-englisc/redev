# Какие задачи лучше решать серверными компонентами

> [!NOTE]
> Серверные компоненты подходят для загрузки и подготовки данных, доступа к серверным ресурсам и отображения содержимого, которому не нужны браузерные события.

## Вопрос

Как определить, какую логику оставить на сервере, а какую передать браузеру?

## Основная идея

Перед выбором задай два вопроса: нужны ли этой части данные или возможности сервера и должна ли она реагировать на действия без обращения к серверу?

На сервере удобно получать статьи из системы управления контентом, читать базу данных, обращаться к API с секретным ключом, преобразовывать Markdown и считать итоговые показатели. Код этих операций и соответствующие зависимости не обязательно отправлять посетителю.

Шапка, описания товаров и большая часть текста также могут оставаться серверными. Если рядом нужна кнопка, это не повод переносить всю страницу в клиентский граф: кнопка может быть отдельным клиентским компонентом.

## Пример: подготовка итоговой суммы

```tsx
// app/summary/page.tsx
async function getOrders() {
  return [
    { id: "A-1", totalCents: 125000 },
    { id: "A-2", totalCents: 75000 },
  ];
}

export default async function Page() {
  const orders = await getOrders();
  const totalCents = orders.reduce((sum, order) => {
    return sum + order.totalCents;
  }, 0);

  return (
    <main>
      <h1>Учебный отчет</h1>
      <p>Заказов: {orders.length}</p>
      <p>Общая сумма: {(totalCents / 100).toFixed(2)} ₽</p>
    </main>
  );
}
```

`getOrders` возвращает вымышленные заказы и заменяет реальный источник данных. Суммы хранятся в копейках, поэтому результат - `2000.00 ₽`. Браузер получает готовый отчет; для самого подсчета ему не нужна библиотека работы с заказами.

## Что важно помнить

Серверный компонент не делает запрос безопасным автоматически. Если данные персональные, перед загрузкой нужно проверить текущего пользователя и его права. В примере нет настоящих персональных данных.

Доступный серверу секрет не должен появляться в отображаемой разметке или props клиентского компонента. На клиент передавай только сведения, которые ему нужны.

Тяжелые вычисления способны замедлить ответ сервера. Для повторяющейся работы могут потребоваться кэш или предварительный расчет; серверный компонент сам по себе не гарантирует скорость.

## Мини-шпаргалка

- База данных, секреты, преобразование содержимого - сервер.
- Состояние интерфейса и браузерные события - клиент.
- Проверяй доступ рядом с получением защищенных данных.
- Страница может соединять оба типа компонентов.
