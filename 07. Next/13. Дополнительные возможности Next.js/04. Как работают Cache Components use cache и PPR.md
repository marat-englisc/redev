# Как работают Cache Components, use cache и PPR

> [!NOTE]
> Cache Components позволяют явно кэшировать функции и части интерфейса. Partial Prerendering, PPR, сочетает заранее подготовленную оболочку с динамическими частями, которые появляются при запросе.

## Вопрос

Как устроена современная модель кэширования и чем она отличается от предыдущих примеров?

## Основная идея

Большинство материалов раздела использует режим без Cache Components. Этот пример — **отдельный вариант для Next.js 16.3+**. Не включай его настройки в проекте задач без адаптации динамических границ.

```ts
// next.config.ts — конфигурация отдельного примера
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  cacheComponents: true,
  partialPrefetching: true,
};
export default nextConfig;
```

## Пример: кэшируемая публичная часть и свежий блок

```tsx
// app/page.tsx
import { Suspense } from "react";
import { cacheLife, cacheTag } from "next/cache";
import { connection } from "next/server";

async function PublicPosts() {
  "use cache";
  cacheLife({ stale: 60, revalidate: 300, expire: 3600 });
  cacheTag("public-posts");
  const response = await fetch("https://jsonplaceholder.typicode.com/posts?_limit=3");
  if (!response.ok) throw new Error("Публичные записи недоступны");
  const posts: { id: number; title: string }[] = await response.json();
  return <ul>{posts.map(post => <li key={post.id}>{post.title}</li>)}</ul>;
}

async function RequestTime() {
  await connection();
  return <p>Время обработки запроса: {new Date().toISOString()}</p>;
}

export default function Page() {
  return <main>
    <h1>Публичные записи</h1>
    <PublicPosts />
    <Suspense fallback={<p>Получаем время…</p>}>
      <RequestTime />
    </Suspense>
  </main>;
}
```

JSONPlaceholder — учебный публичный API. Кэшируемая часть может войти в предварительную оболочку, а время запроса требует выполнения на сервере и находится внутри Suspense.

## Что важно помнить

`use cache` обозначает сохраняемый результат. `cacheLife` задает политику: клиентское переиспользование `stale`, фоновую ревалидацию `revalidate` и срок `expire`, после которого нужен свежий результат. Это не периодический таймер.

`cacheTag` связывает результат с меткой. После реальной серверной мутации `updateTag` в Action делает запись просроченной, а `revalidateTag(tag, "max")` допускает обновление в фоне.

Cookie и другие данные запроса не читают внутри обычной `use cache`-области. Их получают снаружи, проверяют права и при необходимости передают разрешенные параметры. Для персональных задач проще сначала обойтись без постоянного кэша.

Старые настройки сегмента `dynamic`, `revalidate`, `fetchCache` нельзя механически смешивать с этой моделью. Partial Prefetching меняет предзагрузку; это не синоним PPR.

## Мини-шпаргалка

- `use cache` — сохраняемый результат, `cacheLife` — сроки.
- `cacheTag` — связь с обновлением по событию.
- Динамические части располагают в подходящих Suspense.
- Новую модель изучают отдельно от прежней.
