# Как использовать loading, error и notFound

> [!NOTE]
> `loading.tsx` описывает ожидание маршрута, `error.tsx` — запасной экран непредвиденного сбоя, а `notFound()` — ожидаемое отсутствие ресурса. Они решают разные задачи интерфейса.

## Вопрос

Как показать загрузку и ошибку, если страница обращается к БД?

## Основная идея

В приложении задач SQL может выполняться медленно или завершиться ошибкой. Next.js автоматически создает границы Suspense и Error Boundary по специальным файлам сегмента.

## Пример: состояния раздела задач

```tsx
// app/tasks/loading.tsx
export default function Loading() {
  return <p role="status">Загружаем задачи…</p>;
}
```

```tsx
// app/tasks/error.tsx — пример для Next.js 16.3+
"use client";

export default function ErrorScreen({ retry }: { retry: () => void }) {
  return <section role="alert">
    <h1>Не удалось загрузить задачи</h1>
    <button onClick={() => retry()}>Попробовать снова</button>
  </section>;
}
```

`retry` повторно запрашивает серверное содержимое и пробует отрисовать его. В старых версиях встречается `reset`: сброс Error Boundary не равен обязательной повторной загрузке серверных данных. Проверяй API своей версии.

## Что важно помнить

`error.tsx` сегмента расположен внутри его layout и не перехватит ошибку этого же layout. Для ошибки корневой оболочки существует `global-error.tsx`, уже рассмотренный в разделе структуры.

Ошибку ввода возвращают состоянием формы, отсутствие записи обрабатывают через `notFound`, отсутствие сессии — перенаправлением или HTTP 401. Не превращай все эти случаи в общий экран «Сервис сломан».

Граница загрузки не ускоряет SQL и может не появиться, если переход уже предзагружен. Для независимых медленных блоков добавляют отдельные Suspense. Сбои обработчиков событий и отдельных фоновых операций требуют собственной обработки.

## Мини-шпаргалка

- Ожидание — `loading.tsx` или Suspense.
- Непредвиденный сбой — `error.tsx`.
- Нет ресурса — `notFound()`.
- Ошибка поля — результат Action возле формы.
