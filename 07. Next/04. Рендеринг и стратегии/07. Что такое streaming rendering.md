# Что такое streaming rendering

> [!NOTE]
> **Streaming rendering, потоковый рендеринг**, - отправка готовых частей интерфейса по мере их появления, без ожидания самого медленного блока страницы.

## Вопрос

Как показать заголовок сразу, а медленные данные добавить позднее в рамках того же ответа?

## Основная идея

Представь страницу книги: описание уже известно, а отзывы загружаются две секунды. Если ждать все данные перед отправкой ответа, пользователь не увидит даже готовое описание. Streaming позволяет отправить его вместе с обозначением загрузки отзывов.

Когда отзывы готовы, сервер передает следующую часть, и React обновляет нужное место страницы. Для такого разделения используют `Suspense`: он задает границу ожидания и временный интерфейс `fallback`.

Streaming совместим с серверным рендерингом. Это способ постепенно доставлять результат, а не замена SSR.

## Пример: медленный блок отзывов

Пример для App Router без включенного `cacheComponents`:

```tsx
// app/book/page.tsx
import { Suspense } from "react";
import { connection } from "next/server";

async function Reviews() {
  await connection();
  await new Promise(resolve => setTimeout(resolve, 2000));
  return <p>Отзыв: понятная книга с хорошими примерами.</p>;
}

export default function Page() {
  return (
    <main>
      <h1>Учебник React</h1>
      <p>Практическое введение в компоненты.</p>
      <Suspense fallback={<p>Загружаем отзывы…</p>}>
        <Reviews />
      </Suspense>
    </main>
  );
}
```

`connection()` исключает последующую работу из предварительного рендеринга и переносит ее на запрос. `setTimeout` - учебная имитация медленного источника, в настоящем проекте здесь был бы запрос к API или базе.

Сначала пользователь может увидеть заголовок, описание и «Загружаем отзывы…». Затем появляется отзыв. Браузеры и промежуточные серверы иногда буферизуют маленькие ответы, поэтому фактическое время появления зависит и от окружения.

## Что важно помнить

Если сначала выполнить медленный `await` в родительской странице и только затем вернуть `Suspense`, эта граница не сможет показать загрузку во время уже завершившегося ожидания. Ожидающая работа должна находиться внутри границы.

Streaming не ускоряет сам запрос к базе данных. Он позволяет раньше показать доступную часть интерфейса.

Файл `loading.tsx` создает готовую границу ожидания для страницы и ее вложенного содержимого в соответствующем сегменте.

## Мини-шпаргалка

- Готовый каркас приходит раньше медленного блока.
- `Suspense` определяет область ожидания.
- `fallback` объясняет пользователю, что загружается.
- Медленную работу помещай внутрь границы.
