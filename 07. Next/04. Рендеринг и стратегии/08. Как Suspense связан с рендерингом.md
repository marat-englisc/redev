# Как Suspense связан с рендерингом

> [!NOTE]
> **Suspense** - компонент React, который показывает временный интерфейс, пока поддерживающий этот механизм дочерний компонент ожидает данные или код.

## Вопрос

Что делает `fallback`, где поставить границу Suspense и какие загрузки она умеет обнаруживать?

## Основная идея

`Suspense` похож на выделенное место с табличкой «Готовим результат». Остальная страница может отображаться, пока содержимое этого места еще не готово.

В Next.js App Router асинхронный серверный компонент способен приостановить рендеринг на `await`. Ближайший родительский `Suspense` разрешает показать `fallback`, затем заменить его результатом. Это основа потоковой отправки медленных частей страницы.

На клиенте Suspense также используется, например, для загрузки компонента через `React.lazy`. Он не обнаруживает произвольный запрос внутри `useEffect`: там состояние загрузки нужно организовать самостоятельно или средствами совместимой библиотеки.

## Пример: независимое ожидание одного блока

Пример для App Router без включенного `cacheComponents`:

```tsx
// app/report/page.tsx
import { Suspense } from "react";
import { connection } from "next/server";

async function Report() {
  await connection();
  const count = await new Promise<number>(resolve => {
    setTimeout(() => resolve(42), 1500);
  });
  return <p>Заказов за сегодня: {count}</p>;
}

export default function Page() {
  return (
    <main>
      <h1>Отчет магазина</h1>
      <Suspense fallback={<p role="status">Считаем заказы…</p>}>
        <Report />
      </Suspense>
      <p>Данные приведены для ознакомления.</p>
    </main>
  );
}
```

`connection()` переносит работу блока на запрос. Promise с таймером имитирует медленный подсчет и возвращает учебное число `42`. Заголовок и пояснение доступны, пока отчет ожидает; затем сообщение загрузки заменяется результатом.

## Что важно помнить

Граница должна находиться выше компонента, который ожидает. Если `Page` сначала сама выполнит подсчет, а потом вернет `Suspense`, данный `fallback` это ожидание не прикроет.

Одна граница объединяет ожидание своего содержимого. Несколько границ позволяют частям страницы появляться независимо. Делить каждый маленький элемент не обязательно: выбирай понятные пользователю блоки.

Для ошибок нужен механизм обработки ошибок, например `error.tsx`; `fallback` Suspense описывает ожидание и не заменяет полноценный интерфейс ошибки.

## Мини-шпаргалка

- Suspense управляет ожиданием, а не выбирает SSG или SSR.
- `fallback` показывает временный интерфейс.
- Запрос в обычном `useEffect` сам по себе не активирует Suspense.
- `loading.tsx` создает границу на уровне маршрута.
