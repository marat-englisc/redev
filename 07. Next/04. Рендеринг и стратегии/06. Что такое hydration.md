# Что такое hydration

> [!NOTE]
> **Hydration, гидратация**, - подключение React к уже существующей серверной разметке, чтобы клиентские компоненты получили состояние и обработчики событий.

## Вопрос

Как готовый HTML становится интерактивным и почему возникает hydration mismatch?

## Основная идея

Сервер может отправить HTML кнопки «Добавлено: 0». Браузер покажет ее, даже пока JavaScript еще загружается. Затем React использует эту разметку как начальную основу для клиентского компонента и подключает его поведение.

Это отличается от чистого клиентского монтирования, при котором React создает интерфейс внутри пустого контейнера. В Next.js гидратацией управляет фреймворк, вручную вызывать `hydrateRoot` обычно не требуется.

В App Router гидратируются клиентские компоненты. Код серверных компонентов не отправляется в браузер для гидратации; браузер получает результат их работы и сведения о клиентских границах.

## Пример: безопасное чтение localStorage

```tsx
// app/saved-name.tsx
"use client";

import { useEffect, useState } from "react";

export default function SavedName() {
  const [name, setName] = useState("гость");

  useEffect(() => {
    try {
      setName(localStorage.getItem("name") ?? "гость");
    } catch {
      setName("гость");
    }
  }, []);

  return <p>Здравствуйте, {name}!</p>;
}
```

Импортируй компонент в любую страницу App Router. Сначала сервер и браузер показывают одинаковое «Здравствуйте, гость!». После гидратации эффект читает сохраненное имя. Если хранилище недоступно или имя отсутствует, остается значение по умолчанию.

Чтение перенесено в эффект, потому что `localStorage` существует только в браузере. Само наличие `"use client"` не делает такое чтение безопасным во время начального серверного рендера.

## Что важно помнить

**Hydration mismatch** означает, что начальный клиентский результат не совпал с серверным HTML. Причинами бывают случайные числа, текущее время, различия локалей и неправильная вложенность HTML-тегов.

Первый рендер должен давать одинаковый результат в обеих средах. Браузерные изменения можно применять после подключения React. `suppressHydrationWarning` предназначен для узких неизбежных различий, а не для исправления ошибочной архитектуры.

Гидратация не равна загрузке данных и не делает серверный код доступным в браузере.

## Мини-шпаргалка

- Сначала отображается HTML, затем подключается поведение.
- Начальная серверная и клиентская разметки должны совпадать.
- Браузерные API используй в эффектах или обработчиках.
- Серверные компоненты отдельно не гидратируются.
