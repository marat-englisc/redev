# Основные стратегии рендеринга в Next.js

> [!NOTE]
> **Рендеринг** - получение интерфейса из компонентов и данных. В Next.js важно различать место выполнения кода, момент подготовки страницы и способ доставки результата.

## Вопрос

Чем отличаются SSG, SSR, ISR, CSR и streaming, и как выбрать подходящий вариант?

## Основная идея

Представь книжный магазин. Страницу «О магазине» можно подготовить заранее, каталог периодически обновлять, а личные заказы получать для конкретного посетителя. Кнопка добавления книги в корзину должна реагировать на действия в браузере.

| Подход | Что происходит | Пример задачи |
| --- | --- | --- |
| SSG, Static Site Generation | Страница заранее генерируется при сборке | Справочная статья |
| SSR, Server-Side Rendering | Сервер готовит ответ во время запроса | Личный кабинет |
| ISR, Incremental Static Regeneration | Подготовленная страница обновляется после сборки | Публичный каталог |
| CSR, Client-Side Rendering | Браузер вычисляет и обновляет интерфейс | Фильтр, редактор, чат |
| Streaming | Ответ передается частями по мере готовности | Медленный блок отзывов |

Streaming может сопровождать SSR: это способ доставки, а не взаимоисключающая стратегия. Серверный компонент тоже не означает SSR на каждый запрос: он может выполняться при сборке.

## Пример: статическая страница с интерактивной кнопкой

```tsx
// app/counter.tsx
"use client";

import { useState } from "react";

export default function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(n => n + 1)}>{count}</button>;
}
```

```tsx
// app/page.tsx
import Counter from "./counter";

export default function Page() {
  return (
    <main>
      <h1>Книжный магазин</h1>
      <Counter />
    </main>
  );
}
```

В обычном App Router без включенного `cacheComponents` такой маршрут можно пререндерить при сборке. Браузер получает HTML с заголовком и кнопкой `0`, затем React подключает поведение кнопки. Наличие `"use client"` само по себе не отменяет начальный HTML.

## Что важно помнить

Кэш данных и готовый HTML - разные вещи. Современный `fetch` по умолчанию не сохраняет ответ в постоянный Data Cache, но страница при подходящих условиях может быть пререндерена.

Не выбирай стратегию по обещанию «всегда быстрее» или «лучше SEO»: важны персонализация, допустимая задержка данных и объем JavaScript.

## Мини-шпаргалка

- Когда готовить страницу: сборка, запрос или обновление кэша.
- Где нужна интерактивность: в клиентских компонентах.
- Как доставлять медленные части: через streaming и Suspense.
