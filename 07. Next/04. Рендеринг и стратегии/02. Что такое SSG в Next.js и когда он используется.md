# Что такое SSG в Next.js и когда он используется

> [!NOTE]
> **SSG, Static Site Generation**, — предварительное создание страницы при сборке приложения. Посетитель получает уже подготовленный результат вместо повторного рендеринга страницы для каждого запроса.

## Вопрос

Как работает статическая генерация, для каких страниц она подходит и как сделать это в Next.js?

## Основная идея

SSG похожа на печать справочника: содержание готовят заранее, а читателям выдают готовые экземпляры. Серверу не нужно заново получать данные и вычислять страницу для каждого просмотра. Для страницы «О компании» не нужно заново вычислять одинаковый текст при каждом посещении.

Статическая генерация подходит для документации, инструкций, описаний услуг, публичных статей и других данных, одинаковых для всех. Если исходные данные изменились, ранее созданная страница сама об этом не узнает. Понадобится новая сборка либо отдельный механизм обновления, например ISR.

**Статический** здесь описывает способ подготовки результата. На такой странице могут работать кнопки и другие клиентские компоненты: предварительно созданный HTML не запрещает интерактивность после загрузки JavaScript.

В App Router не используют `getStaticProps`: это API Pages Router. Статичность маршрута определяется его кодом и настройками. Отсутствие пользовательских cookies и других зависимостей от запроса позволяет Next.js подготовить страницу заранее.

## Пример: справочная страница

В App Router без включенного `cacheComponents` такая страница не требует данных текущего запроса:

```tsx
// app/about/page.tsx
export default function AboutPage() {
  return (
    <main>
      <h1>О нашем учебнике</h1>
      <p>Разбираем frontend небольшими понятными темами.</p>
    </main>
  );
}
```

Во время `next build` Next.js может подготовить `/about` заранее. Результат сборки показывает, какие маршруты были пререндерены.

## Пример: динамический маршрут с известными адресами

Пример для Next.js 16 App Router без включенного `cacheComponents`:

```tsx
// app/help/[slug]/page.tsx
import { notFound } from "next/navigation";

const articles: Record<string, string> = {
  delivery: "Доставляем книги за три рабочих дня.",
  payment: "Заказ можно оплатить банковской картой.",
};

export function generateStaticParams() {
  return Object.keys(articles).map(slug => ({ slug }));
}

export const dynamicParams = false;

type Props = { params: Promise<{ slug: string }> };

export default async function Page({ params }: Props) {
  const { slug } = await params;
  const text = articles[slug];
  if (!text) notFound();

  return <article><h1>Справка</h1><p>{text}</p></article>;
}
```

`generateStaticParams` сообщает сборке известные значения `slug`. Next.js заранее готовит `/help/delivery` и `/help/payment`. Благодаря `dynamicParams = false` другие значения ведут на страницу 404.

`articles` — учебный словарь, заменяющий источник статей. В настоящем проекте список можно получить из системы управления контентом.

## Что важно помнить

- SSG не означает отсутствие клиентского JavaScript: внутри готовой страницы могут быть интерактивные клиентские компоненты.
- Обращение к cookies или другим данным текущего запроса меняет условия рендеринга. Персональное содержимое нельзя бездумно превращать в общий статический результат.
- Кэш ответа `fetch` и пререндеринг страницы — разные механизмы. В современном Next.js обычный `fetch` по умолчанию не означает постоянное сохранение данных в Data Cache.
- Статическая генерация не равна статическому экспорту (`output: "export"`): в обычном развертывании статические и серверные маршруты существуют вместе, а экспорт в файлы ограничивает серверные возможности.
- Проверять результат нужно через `next build`: поведение сервера разработки отличается.

## Мини-шпаргалка

- SSG готовит страницу до запросов посетителей.
- `generateStaticParams` перечисляет параметры динамических маршрутов.
- Зависимость от конкретного пользователя требует другого решения.
