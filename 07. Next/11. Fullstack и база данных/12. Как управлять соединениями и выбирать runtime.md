# Как управлять соединениями и выбирать runtime

> [!NOTE]
> Подключение к БД расходует ресурсы. Пул ограничивает соединения одного процесса, а runtime определяет, какие библиотеки и сетевые возможности доступны серверному коду.

## Вопрос

Почему рабочий локально запрос может перестать работать после публикации?

## Основная идея

У обычного Node.js-сервера процесс живет долго и переиспользует пул. При serverless-размещении платформа может одновременно запустить много экземпляров. У каждого будет собственная память и свой пул; глобальная переменная не объединяет их.

```text
10 экземпляров × max 5 соединений = до 50 соединений
100 экземпляров × max 5          = до 500 соединений
```

Если база допускает меньше подключений, появятся ожидания и ошибки. Помогают ограничение конкуренции, пулер провайдера или PgBouncer, а также правильно выбранные размеры пулов и таймауты.

## Пример: явный Node.js runtime

```ts
// app/api/health/route.ts
import { pool } from "@/lib/db";

export const runtime = "nodejs";

export async function GET() {
  try {
    await pool.query("SELECT 1");
    return Response.json({ status: "ok" }, {
      headers: { "Cache-Control": "no-store" },
    });
  } catch {
    return Response.json({ status: "unavailable" }, { status: 503 });
  }
}
```

Этот обработчик проверяет связь с БД и не раскрывает строку подключения. Для частых проверок добавь ограничение частоты или используй внутренний endpoint, чтобы мониторинг не создавал лишнюю нагрузку.

## Что важно помнить

Обычный `pg` требует возможностей Node.js и TCP-соединения. Его нельзя автоматически перенести в Edge Runtime. Для другой среды нужен поддерживаемый драйвер, например предоставляющий HTTP-доступ к конкретной БД.

При ручном `pool.connect()` освобождай соединение в `finally`. `pool.query()` берет и возвращает его сам. Таймаут получения соединения и ограничение времени выполнения SQL — разные настройки; для тяжелых запросов нужен также `statement_timeout` и контроль нагрузки.

Приложение и база в далеких регионах будут ждать сеть при каждом запросе. Выбор близких регионов часто полезнее добавления еще одного кэша.

## Мини-шпаргалка

- Глобальный пул общий только внутри экземпляра.
- Проверяй общий бюджет соединений.
- Драйвер должен поддерживать выбранный runtime.
- Установи таймауты и наблюдай задержки БД.
