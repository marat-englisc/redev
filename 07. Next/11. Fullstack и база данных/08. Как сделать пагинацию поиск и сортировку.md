# Как сделать пагинацию поиск и сортировку

> [!NOTE]
> Пагинация ограничивает число строк в ответе. Поиск и сортировка должны выполняться с проверенными параметрами, сохраняя ограничение доступа к данным пользователя.

## Вопрос

Как не загружать все задачи сразу и безопасно учитывать параметры адреса?

## Основная идея

Для небольших списков подойдет `LIMIT` и `OFFSET`: пропустить строки предыдущих страниц и взять следующие. Для больших и часто меняющихся списков используют курсор — значения последней показанной строки.

## Пример: серверная функция поиска

Добавь в отдельный файл рядом с DAL. Используются уже созданные пул и сессии:

```ts
// lib/task-search.ts
import "server-only";
import { z } from "zod";
import { pool } from "./db";
import { requireUser } from "./session";
import type { Task } from "./tasks";

export async function searchTasks(raw: unknown) {
  const user = await requireUser();
  const input = z.object({
    page: z.coerce.number().int().min(1).max(1000).default(1),
    query: z.string().max(100).default(""),
    sort: z.enum(["new", "title"]).default("new"),
  }).parse(raw);
  const order = input.sort === "title"
    ? "title ASC, id ASC" : "created_at DESC, id DESC";
  const result = await pool.query<Task>(
    `SELECT id, title, completed FROM tasks
     WHERE owner_id = $1 AND title ILIKE $2
     ORDER BY ${order} LIMIT 21 OFFSET $3`,
    [user.id, `%${input.query}%`, (input.page - 1) * 20],
  );
  return { items: result.rows.slice(0, 20), hasNext: result.rows.length > 20 };
}
```

Двадцать первая строка нужна только для определения следующей страницы. В SQL подставляется один из двух заранее заданных вариантов сортировки; пользовательский текст в `ORDER BY` не попадает. Поисковое значение передается параметром.

В серверной странице параметры читают через `await searchParams`. Передай в функцию объект `{ page, query, sort }` из URL `/tasks?page=2&query=React&sort=new`, а полученный список отрисуй вместо прежнего `listTasks()`.

## Что важно помнить

`searchParams` может содержать массивы при повторении параметра. Приведенная схема такие значения отвергает; покажи понятную ошибку фильтра вместо аварийного экрана.

Символы `%` и `_` в `ILIKE` имеют смысл шаблона, но параметризация не дает им стать SQL-командой. Для буквального поиска эти символы экранируют отдельно.

Большой OFFSET может быть дорогим. Курсорная пагинация по паре `(created_at, id)` лучше масштабируется, но требует такого же устойчивого порядка. Проверяй индекс и план запроса.

## Мини-шпаргалка

- Ограничивай страницу и длину поиска.
- Для сортировки используй список допустимых вариантов.
- Добавляй уникальный ключ к порядку строк.
- Условие владельца остается при любых фильтрах.
