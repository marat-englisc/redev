# Как реализовать CRUD через Server Actions

> [!NOTE]
> CRUD — создание, чтение, изменение и удаление записей. В App Router чтение удобно выполнять в Server Component, а изменения из форм — в Server Actions.

## Вопрос

Как сохранить задачу в PostgreSQL и обновить список после отправки формы?

## Основная идея

Используем DAL из темы 05. Он уже проверяет сессию, владельца и входные данные. Action связывает DAL с интерфейсом: получает `FormData`, вызывает операцию и сообщает об изменении страницы.

## Пример: три операции записи

```ts
// app/tasks/actions.ts
"use server";

import { ZodError } from "zod";
import { revalidatePath } from "next/cache";
import { createTask, updateTask, deleteTask } from "@/lib/tasks";
import { AppError } from "@/lib/errors";

export type TaskState = { message: string };

function failure(error: unknown): TaskState {
  if (error instanceof ZodError) return { message: "Проверьте поля формы" };
  if (error instanceof AppError) return { message: error.message };
  console.error("Не удалось изменить задачу");
  return { message: "Сервис временно недоступен" };
}

export async function createTaskAction(_state: TaskState, data: FormData) {
  try {
    await createTask({ title: data.get("title") });
  } catch (error) { return failure(error); }
  revalidatePath("/tasks");
  return { message: "Задача создана" };
}

export async function updateTaskAction(_state: TaskState, data: FormData) {
  try {
    await updateTask(data.get("id"), {
      title: data.get("title"),
      completed: data.get("completed") === "on",
    });
  } catch (error) { return failure(error); }
  revalidatePath("/tasks");
  return { message: "Задача обновлена" };
}

export async function deleteTaskAction(_state: TaskState, data: FormData) {
  try {
    await deleteTask(data.get("id"));
  } catch (error) { return failure(error); }
  revalidatePath("/tasks");
  return { message: "Задача удалена" };
}
```

Первый аргумент предназначен для `useActionState`, второй содержит поля формы. Клиентские формы приведены в разделе 12, теме 03. После успешного запроса `revalidatePath` позволяет получить обновленный серверный результат страницы.

## Что важно помнить

Скрытый `id` можно подменить. Защиту обеспечивает условие владельца в SQL, а не видимость поля. Введенный текст проверяется на сервере, даже если у input уже есть `required`.

Отключенная кнопка улучшает интерфейс, но не предотвращает все повторные запросы. Для платежей и других операций с серьезными последствиями нужны идемпотентность и ограничения БД.

Не возвращай пользователю текст ошибки драйвера с SQL и внутренними параметрами. Ожидаемые ошибки формы удобно возвращать как состояние; непредвиденные сбои регистрируют на сервере.

## Мини-шпаргалка

- RSC читает, Actions записывают.
- Проверки находятся в DAL и работают для всех точек входа.
- После записи обновляют соответствующий маршрут или кэш.
- FormData и скрытые поля считаются недоверенными.
