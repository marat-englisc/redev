# Как читать БД из Server Component и организовать DAL

> [!NOTE]
> Серверный компонент может обращаться к БД напрямую. В растущем приложении запросы и проверки доступа удобно объединить в DAL, чтобы страницы, Actions и API использовали одинаковые правила.

## Вопрос

Как прочитать только задачи текущего пользователя и переиспользовать эту логику?

## Основная идея

Перед примером нужны пул, схема задач и `requireUser` из предыдущих материалов и раздела 12. Сервер устанавливает владельца по сессии. Браузер не выбирает, чьи данные ему разрешено читать.

## Пример: общий слой задач

```ts
// lib/tasks.ts
import "server-only";
import { pool } from "./db";
import { requireUser } from "./session";
import { AppError } from "./errors";
import { taskIdSchema, taskSchema, taskPatchSchema } from "./task-schema";

export type Task = { id: string; title: string; completed: boolean };

export async function listTasks(): Promise<Task[]> {
  const user = await requireUser();
  const result = await pool.query<Task>(
    `SELECT id, title, completed FROM tasks
     WHERE owner_id = $1 ORDER BY created_at DESC, id DESC LIMIT 50`,
    [user.id],
  );
  return result.rows;
}

export async function createTask(raw: unknown): Promise<Task> {
  const user = await requireUser();
  const input = taskSchema.parse(raw);
  const result = await pool.query<Task>(
    `INSERT INTO tasks(owner_id, title, completed) VALUES ($1, $2, $3)
     RETURNING id, title, completed`,
    [user.id, input.title, input.completed],
  );
  return result.rows[0];
}

export async function updateTask(rawId: unknown, raw: unknown): Promise<Task> {
  const user = await requireUser();
  const id = taskIdSchema.parse(rawId);
  const input = taskPatchSchema.parse(raw);
  const result = await pool.query<Task>(
    `UPDATE tasks SET title = COALESCE($1, title),
                      completed = COALESCE($2, completed)
     WHERE id = $3 AND owner_id = $4 RETURNING id, title, completed`,
    [input.title ?? null, input.completed ?? null, id, user.id],
  );
  if (!result.rows[0]) throw new AppError(404, "Задача не найдена");
  return result.rows[0];
}

export async function deleteTask(rawId: unknown): Promise<void> {
  const user = await requireUser();
  const id = taskIdSchema.parse(rawId);
  const result = await pool.query(
    "DELETE FROM tasks WHERE id = $1 AND owner_id = $2 RETURNING id",
    [id, user.id],
  );
  if (!result.rowCount) throw new AppError(404, "Задача не найдена");
}
```

`$1`, `$2` — параметры запроса: данные передаются отдельно от SQL. Условие `owner_id` есть и у чтения, и у изменений. В ответ выбираются только поля интерфейса — это небольшой **DTO**, объект передаваемых данных.

## Пример: страница без промежуточного HTTP-запроса

```tsx
// app/tasks/page.tsx
import { redirect } from "next/navigation";
import { getCurrentUser } from "@/lib/session";
import { listTasks } from "@/lib/tasks";

export const runtime = "nodejs";

export default async function TasksPage() {
  if (!(await getCurrentUser())) redirect("/login");
  const tasks = await listTasks();
  return <main><h1>Мои задачи</h1><ul>{tasks.map(task => (
    <li key={task.id}>{task.title}{task.completed ? " — готово" : ""}</li>
  ))}</ul></main>;
}
```

Посетитель получает HTML со своими задачами. Чтение сессии использует данные запроса, поэтому эта страница не предназначена для общей статической копии.

## Что важно помнить

Этот список ограничен пятьюдесятью строками; полноценная пагинация разбирается отдельно. `pool.query<Task>` задает тип результата для TypeScript, но не проверяет фактическую схему БД.

Нельзя делать запрос в Client Component или отправлять туда весь объект пользователя с закрытыми полями. Запись в БД выполняется из Actions или Route Handlers, а не во время рендеринга.

## Мини-шпаргалка

- RSC читает DAL напрямую.
- DAL проверяет сессию и владельца при каждой операции.
- SQL-параметры отделяют данные от команды.
- Возвращай только необходимые поля.
