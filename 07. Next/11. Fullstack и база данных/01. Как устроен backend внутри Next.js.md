# Как устроен backend внутри Next.js

> [!NOTE]
> В fullstack-приложении Next.js серверные компоненты читают данные, Server Actions изменяют их из интерфейса, а Route Handlers предоставляют HTTP API. Все они могут использовать общий серверный слой работы с базой.

## Вопрос

Можно ли написать приложение с пользователями и базой данных без отдельного Express-сервера?

## Основная идея

Да. Next.js уже запускает серверный код: Express для каждого проекта не требуется. Но база данных остается отдельной системой, например PostgreSQL. Next.js подключается к ней через драйвер или ORM.

```text
Браузер → Server Component → слой доступа к данным → PostgreSQL
Форма   → Server Action   → тот же слой          → PostgreSQL
Клиент  → Route Handler   → тот же слой          → PostgreSQL
```

**Драйвер** отправляет SQL в базу. **ORM** предоставляет более высокоуровневые операции. **DAL**, Data Access Layer, объединяет запросы, проверки доступа и выбор полей ответа.

## Пример: организация приложения задач

```text
app/
  tasks/page.tsx            # список задач
  tasks/actions.ts         # изменения через формы
  api/tasks/route.ts        # GET и POST
  api/tasks/[id]/route.ts   # PATCH и DELETE
lib/
  db-pool.ts               # низкоуровневое подключение
  db.ts                    # серверная обертка
  auth.ts                  # конфигурация авторизации
  session.ts               # проверка текущего пользователя
  tasks.ts                 # запросы и правила доступа
```

Страница вызывает `listTasks()` прямо из `lib/tasks.ts`. Ей не нужно обращаться по HTTP к собственному `/api/tasks`: это добавило бы лишний сетевой переход. HTTP API нужен браузерному виджету или другому клиенту.

Реализации этих файлов приведены в следующих материалах; порядок сборки указан в [карте раздела](<../00. Карта раздела и fullstack практика.md>).

## Что важно помнить

Чтение разрешено во время рендеринга, запись выполняется в Action или обработчике. Рендер может повториться или запуститься при предзагрузке: создание заказа внутри `page.tsx` приведет к неожиданным изменениям.

Next.js подходит для многих веб-приложений. Долгие вычисления, очереди, постоянные WebSocket-соединения и сложные независимые сервисы могут потребовать отдельной инфраструктуры. Серверные возможности зависят и от хостинга.

## Мини-шпаргалка

- React отвечает за интерфейс, сервер Next.js — за обработку запросов.
- База данных работает отдельно от Next.js.
- Общую бизнес-логику выносят из страниц и обработчиков.
- Собственный HTTP API не обязателен для серверного чтения БД.
