# Чем ORM отличается от SQL и как использовать Drizzle

> [!NOTE]
> ORM и query builder помогают описывать таблицы и запросы средствами языка приложения. Они упрощают типизацию, но не заменяют ограничения БД, проверки доступа и анализ SQL.

## Вопрос

Обязательно ли писать SQL вручную и что меняется при переходе на ORM?

## Основная идея

Основной пример раздела использует `pg`, чтобы был виден сам SQL. Это полноценный способ работы с БД. Альтернативы — Drizzle с близкими к SQL операциями и Prisma с моделью данных и клиентским API. Выбирают подход под команду и проект, а не ради количества библиотек.

## Пример: альтернативное чтение через Drizzle

Пример использует уже существующую таблицу `tasks`, пул и сессии. Для него дополнительно установи пакет:

```powershell
npm install drizzle-orm
```

```ts
// lib/orm-tasks.ts — альтернативный вариант DAL
import "server-only";
import { drizzle } from "drizzle-orm/node-postgres";
import { pgTable, uuid, text, boolean } from "drizzle-orm/pg-core";
import { eq } from "drizzle-orm";
import { pool } from "./db";
import { requireUser } from "./session";

const tasks = pgTable("tasks", {
  id: uuid("id").primaryKey(),
  ownerId: text("owner_id").notNull(),
  title: text("title").notNull(),
  completed: boolean("completed").notNull(),
});
const db = drizzle({ client: pool });

export async function listTasksWithOrm() {
  const user = await requireUser();
  return db.select({ id: tasks.id, title: tasks.title, completed: tasks.completed })
    .from(tasks).where(eq(tasks.ownerId, user.id)).orderBy(tasks.id).limit(50);
}
```

Drizzle сформирует параметризованный SELECT. Поле `ownerId` в TypeScript соответствует `owner_id` в SQL. Здесь описан только используемый набор столбцов; схема приложения по-прежнему создана SQL-миграцией.

## Что важно помнить

Этот сокращенный объект таблицы предназначен для чтения, а не для генерации полной миграции. Если переходишь на миграции ORM, опиши все столбцы, ограничения, индексы и таблицы авторизации; проверь результат introspection и SQL до применения.

Не запускай два независимых инструмента, которые меняют одну схему без общего плана. ORM не дает права читать чужие задачи и не делает произвольный raw SQL безопасным. Проверки владельца и валидация сохраняются.

## Мини-шпаргалка

- `pg` с SQL уже достаточно для fullstack-приложения.
- ORM добавляет удобный API и типизацию.
- Миграции должны описывать реальную полную схему.
- Смотри сгенерированный SQL и число запросов.
