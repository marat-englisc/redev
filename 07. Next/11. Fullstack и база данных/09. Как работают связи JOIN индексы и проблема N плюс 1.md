# Как работают связи, JOIN, индексы и N плюс 1

> [!NOTE]
> Связи описывают отношения записей. JOIN объединяет связанные данные запросом, индекс помогает найти строки, а проблема N+1 возникает при множестве дополнительных запросов для уже загруженного списка.

## Вопрос

Как получить задачи с данными владельца и почему запросы в цикле могут тормозить?

## Основная идея

У одного пользователя много задач: это связь «один ко многим». В таблице `tasks` она представлена `owner_id`, который ссылается на `"user".id`.

Представь запрос двадцати задач, за которым следуют двадцать отдельных запросов пользователя. Всего получится 21 обращение — N+1. Даже быстрые запросы накапливают сетевые задержки.

## Пример: один JOIN вместо цикла

```ts
// lib/task-details.ts
import "server-only";
import { pool } from "./db";
import { requireUser } from "./session";

export async function listTaskDetails() {
  const user = await requireUser();
  const result = await pool.query<{
    id: string; title: string; owner_name: string;
  }>(
    `SELECT t.id, t.title, u.name AS owner_name
     FROM tasks t JOIN "user" u ON u.id = t.owner_id
     WHERE t.owner_id = $1
     ORDER BY t.created_at DESC, t.id DESC LIMIT 20`,
    [user.id],
  );
  return result.rows;
}
```

Результат содержит название задачи и имя ее владельца. Поля email, пароль и служебные сведения не выбираются. В нашем приложении владелец у всех строк один: JOIN здесь показывает механизм, а на практике его имя можно получить из проверенной сессии без повторных запросов.

## Что важно помнить

Индекс `(owner_id, created_at DESC, id DESC)` из миграции помогает фильтрации и сортировке списка. Индекс ускоряет не любой запрос: поиск `ILIKE '%слово%'` обычно требует отдельного решения, например триграммного индекса.

Индексы занимают место и замедляют запись. Добавляй их по плану запроса, а не на каждое поле. `EXPLAIN` показывает план; `EXPLAIN ANALYZE` действительно выполняет команду, поэтому его осторожно используют с изменяющими запросами.

ORM тоже может создать N+1. Использование ORM не заменяет понимание SQL, числа обращений и объема ответа.

## Мини-шпаргалка

- Внешний ключ защищает связь.
- JOIN объединяет данные без запросов в цикле.
- Индекс выбирают под фильтр и порядок.
- Измеряй число запросов и план выполнения.
