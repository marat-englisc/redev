# Как кэшировать запросы к БД и обновлять результат

> [!NOTE]
> Результат `pool.query()` не получает настройки кэширования `fetch`. Для БД выбирают отдельный механизм, учитывая срок хранения, обновление и права пользователя.

## Вопрос

Будет ли SQL автоматически кэшироваться в Server Component и как избежать утечки чужих данных?

## Основная идея

В учебном приложении задачи персональные: DAL проверяет сессию и выполняет SQL при обращении. После мутации `revalidatePath("/tasks")` помогает обновить интерфейс, но это не «очистка кэша PostgreSQL».

Различай три задачи:

| Механизм | Назначение |
| --- | --- |
| `React.cache` | Повторно использовать вычисление в рамках серверного запроса React |
| `unstable_cache` без Cache Components | Сохранять результат серверной функции между запросами |
| `use cache` с Cache Components | Явно кэшировать функцию или компонент в новой модели |

## Пример: не повторять чтение внутри рендера

```ts
// lib/task-summary.ts
import "server-only";
import { cache } from "react";
import { pool } from "./db";
import { requireUser } from "./session";

export const getTaskCount = cache(async () => {
  const user = await requireUser();
  const result = await pool.query<{ count: string }>(
    "SELECT count(*) FROM tasks WHERE owner_id = $1", [user.id],
  );
  return Number(result.rows[0].count);
});
```

Два серверных компонента одного рендера могут вызвать эту функцию без повторного чтения. При новом запросе проверка и чтение выполнятся снова. Здесь `count` возвращается драйвером строкой; преобразование подходит для размера учебной таблицы.

## Что важно помнить

Постоянный кэш переживает запрос. Нельзя сохранить общий результат функции, которая неявно читает cookie текущего пользователя, и отдавать его следующему посетителю.

Если персональные данные все же кэшируются между запросами, сначала проверяют сессию и права, затем включают проверенный идентификатор пользователя в ключ. Изменение прав и отзыв доступа требуют продуманной инвалидации; наличие `userId` в ключе само по себе этого не решает.

Для начала оставь личные задачи без постоянного кэша. Для публичного каталога изучи отдельную тему Cache Components: `use cache`, `cacheLife`, `cacheTag`, `updateTag`. Не включай новую модель поверх старых `dynamic` и `revalidate` без адаптации маршрутов.

## Мини-шпаргалка

- SQL-запрос не равен Next.js `fetch`.
- Мемоизация запроса не равна постоянному кэшу.
- Персональные данные требуют изоляции и проверки прав.
- Кэш добавляют после измерения проблемы.
