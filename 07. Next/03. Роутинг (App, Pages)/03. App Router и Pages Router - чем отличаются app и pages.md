# App Router и Pages Router: чем отличаются app и pages

> [!NOTE]
> **App Router** (директория `app`) и **Pages Router** (директория `pages`) — две поддерживаемые модели Next.js. Они различаются организацией страниц, загрузкой данных и устройством серверного и клиентского кода. App Router использует специальные файлы в папках, а Pages Router обычно создает страницу из отдельного файла.

## Вопрос

Почему `app/about/page.tsx` и `pages/about.tsx` создают одинаковый URL, но требуют разной организации кода, и почему при миграции недостаточно переименовать файлы?

## Основная идея

В **Pages Router** файлы внутри `pages` задают страницы: `index.tsx` — `/`, `about.tsx` — `/about`. Приложение строится вокруг компонентов страниц. Данные для серверного рендеринга получают через `getServerSideProps`, для статической генерации — через `getStaticProps` и при необходимости `getStaticPaths`.

В **App Router** папки задают части адреса, а `page.tsx` описывает экран. Рядом размещаются `layout.tsx`, `loading.tsx`, `error.tsx` и другие специальные файлы. Страницы и макеты по умолчанию — Server Components: страница может быть асинхронной и получать данные прямо во время серверного выполнения. Для интерактивной части создают клиентскую границу `"use client"`. Также App Router дает вложенные layout, интерфейсы загрузки и streaming.

## Пример: одна страница двумя способами

```tsx
// app/about/page.tsx — App Router, при наличии app/layout.tsx
export default function AboutPage() {
  return <h1>О компании</h1>;
}
```

```tsx
// pages/about.tsx — альтернативный вариант Pages Router
export default function AboutPage() {
  return <h1>О компании</h1>;
}
```

В обоих случаях открывается `/about`. Это альтернативы: не создавай оба файла для одного URL в одном проекте.

```text
Pages Router:
  pages/index.tsx              → /
  pages/blog/[slug].tsx        → /blog/react
  pages/_app.tsx               → общая инициализация

App Router:
  app/layout.tsx               → корневая оболочка
  app/page.tsx                 → /
  app/blog/layout.tsx          → оболочка раздела
  app/blog/[slug]/page.tsx     → /blog/react
```

| Задача | Pages Router | App Router |
| --- | --- | --- |
| Главная страница | `pages/index.tsx` | `app/page.tsx` |
| Чтение серверных данных | `getServerSideProps`, `getStaticProps` | Асинхронные Server Components |
| Общая и вложенные оболочки | `_app.tsx`, композиция, `getLayout` | `layout.tsx` в дереве папок |
| HTTP-обработчики | API Routes в `pages/api` | Route Handlers `route.ts` |
| Навигация из кода | `next/router` | `next/navigation` |
| Метаданные | Обычно `next/head` | Metadata API |

## Что важно помнить

- Pages Router не является «только SPA»: он поддерживает SSR и SSG и продолжает поддерживаться.
- App Router не делает каждую страницу динамической: серверные компоненты участвуют в пререндеринге.
- `"use client"` означает границу клиентского графа модулей, а не запрет серверного HTML. В Pages Router директива для `useState` не нужна.
- Для нового проекта обычно начинают с App Router. В существующем приложении возможна постепенная миграция: обе директории сосуществуют при отсутствии конфликтующих URL, а переход между ними может вызвать полную загрузку документа.
- Не смешивай импорты и функции загрузки данных двух маршрутизаторов.

## Мини-шпаргалка

- `pages`: файл = страница, `get...Props`, `_app`, `next/router`.
- `app`: папка + `page.tsx`, Server Components, `layout.tsx`, `next/navigation`.
- Одинаковые URL в обеих директориях конфликтуют.
- Миграцию можно делать постепенно.
