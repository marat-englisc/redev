# Как работает useRouter в App Router

> [!NOTE]
> `useRouter` из `next/navigation` — клиентский хук для программного перехода, управления историей браузера и обновления серверного содержимого текущего маршрута.

## Вопрос

Как перейти на другой адрес после действия пользователя и чем `push`, `replace` и `refresh` отличаются друг от друга?

## Основная идея

Обычный переход лучше описывать ссылкой `Link`: у нее есть адрес и стандартное поведение браузера. Иногда навигация зависит от результата операции — например, после сохранения формы нужно открыть страницу созданного объекта. Тогда маршрут меняют из кода.

Хук вызывают в клиентском компоненте. В App Router нужен импорт `next/navigation`; похожий `next/router` предназначен для Pages Router.

## Пример: управление адресом каталога

```tsx
// app/catalog/page.tsx
"use client";

import { useRouter } from "next/navigation";

export default function CatalogPage() {
  const router = useRouter();

  return (
    <main>
      <h1>Каталог</h1>
      <button onClick={() => router.push("/catalog?sort=price")}>
        Открыть сортировку по цене
      </button>
      <button onClick={() => router.replace("/catalog")}>
        Убрать параметры из текущего адреса
      </button>
      <button onClick={() => router.back()}>Назад</button>
      <button onClick={() => router.refresh()}>Обновить содержимое</button>
    </main>
  );
}
```

Первая кнопка меняет URL и добавляет запись истории. Вторая заменяет текущую запись, не добавляя еще одну. Кнопка «Назад» обращается к истории браузера. Пример показывает управление адресом: для реальной сортировки нужно дополнительно прочитать параметр и отсортировать товары.

## Что важно помнить

`router.refresh()` делает запрос серверного содержимого текущего маршрута и объединяет результат с интерфейсом. Он не равен полной перезагрузке документа и не очищает автоматически постоянный Data Cache. Если данные закэшированы, сервер может вернуть прежние значения. Состояние незатронутых клиентских компонентов может сохраниться.

Для чтения URL предусмотрены отдельные хуки: `usePathname`, `useParams` и `useSearchParams`. В статически рендеримых маршрутах использование `useSearchParams` может требовать границу `Suspense`.

Не передавай непроверенный пользовательский текст в `push` и `replace`: адрес нужно формировать из допустимых значений. `back()` может увести за пределы сайта, если предыдущая запись истории была внешней.

## Мини-шпаргалка

- `push` добавляет запись истории; `replace` заменяет текущую.
- `back` и `forward` перемещаются по истории.
- `refresh` обновляет серверное содержимое, но не отменяет весь кэш.
- Для чтения URL используют другие хуки.
