# Как работает prefetch

> [!NOTE]
> **Prefetch**, предзагрузка, — получение данных и ресурсов возможного следующего маршрута до перехода. Это сокращает ожидание после нажатия ссылки.

## Вопрос

Почему некоторые страницы открываются почти сразу и как управлять предварительными запросами?

## Как это работает

В production-режиме Next.js может заранее загрузить маршрут, когда `Link` попадает в видимую область экрана. Результат сохраняется в клиентском кэше навигации и используется при переходе, пока подходит для повторного использования.

В App Router речь идет не просто о загрузке HTML-файла. В числе ресурсов может быть **RSC Payload** — данные результата серверных компонентов, которые React использует для построения следующего интерфейса, а также необходимые клиентские модули.

Объем предзагрузки зависит от маршрута и настроек. Поэтому prefetch повышает вероятность быстрого перехода, но не гарантирует отсутствие любого ожидания.

## Пример: включаем и отключаем предзагрузку

При наличии соответствующих страниц:

```tsx
// app/page.tsx
import Link from "next/link";

export default function HomePage() {
  return (
    <nav>
      <Link href="/about">Об учебнике</Link>{" "}
      <Link href="/large-report" prefetch={false}>
        Большой отчет
      </Link>
    </nav>
  );
}
```

Ссылка `/about` использует стандартное поведение. Для `/large-report` автоматическая предзагрузка отключена: необходимые ресурсы запросятся при переходе. Это может быть полезно, если на экране множество дорогих и редко открываемых ссылок.

## Что важно помнить

Для обычной модели App Router без `cacheComponents` и дополнительных режимов частичной предзагрузки:

- Статический маршрут обычно предзагружается полностью.
- Для динамического маршрута стандартная предзагрузка может ограничиваться доступной оболочкой до границы `loading.tsx`; без подходящей границы полноценная предзагрузка по умолчанию может отсутствовать.
- `prefetch={true}` явно запрашивает полную предзагрузку, а `false` отключает автоматическую.

В других режимах кэширования детали меняются. Неверно считать, что для динамической страницы всегда загружается только JavaScript.

Автоматический prefetch проверяют после `next build` и `next start`: в разработке он отключен. Предзагрузка может выполняться до клика, поэтому серверный рендеринг страницы не должен сам создавать заказ или выполнять другую мутацию.

## Мини-шпаргалка

- Prefetch получает ресурсы до перехода.
- `Link` может запускать его автоматически в production.
- `prefetch={false}` отключает автоматические запросы.
- Результат зависит от маршрута, границ загрузки и настроек.
