# Какие типы роутинга существуют в Next.js

> [!NOTE]
> В Next.js есть два маршрутизатора — **App Router** и **Pages Router**. Внутри них можно создавать адреса с фиксированными и изменяемыми частями.

## Вопрос

Чем маршрутизатор отличается от типа маршрута и какие варианты нужно знать начинающему?

## Основная идея

Сначала различай две системы организации страниц. App Router использует `app` и специальные файлы вроде `page.tsx`. Pages Router использует `pages`, где страницу обычно определяет отдельный файл.

Затем различай форму адреса. **Статический сегмент** имеет фиксированное имя, например `about`. **Динамический сегмент** принимает значение из URL, например `[id]` для номера товара.

Слово «статический» в названии сегмента не означает, что страница обязательно генерируется при сборке. Здесь речь только о форме адреса.

## Пример: основные варианты App Router

```text
app/about/page.tsx
→ /about

app/products/[id]/page.tsx
→ /products/42

app/docs/[...slug]/page.tsx
→ /docs/react или /docs/react/hooks

app/help/[[...slug]]/page.tsx
→ /help или /help/account/password
```

| Запись | Что принимает | Значение параметра |
| --- | --- | --- |
| `about` | Только фиксированное имя | Параметра нет |
| `[id]` | Один сегмент | Строка `"42"` |
| `[...slug]` | Один или несколько сегментов | Массив строк |
| `[[...slug]]` | Ноль или несколько сегментов | Массив строк или `undefined` |

Например, для `/docs/react/hooks` catch-all-параметр `slug` будет равен `["react", "hooks"]`. Так одна страница может обслуживать вложенные разделы документации.

## Что важно помнить

В App Router также есть организационные и расширенные возможности:

- `(group)` группирует страницы без добавления части в URL.
- `@slot` создает параллельную область интерфейса, передаваемую в layout.
- Перехватывающие маршруты позволяют при навигации показать другой маршрут, например в модальном окне.

Это не дополнительные способы серверного рендеринга. SSR, SSG и ISR описывают подготовку результата, а группы, слоты и динамические сегменты — организацию маршрутов и интерфейса.

Начни с обычных страниц и `[id]`. Параллельные и перехватывающие маршруты нужны, когда появляется конкретная задача со сложным интерфейсом.

## Мини-шпаргалка

- `app` и `pages` — две системы маршрутизации.
- `[id]` принимает одну часть адреса.
- `[...slug]` принимает массив частей.
- `[[...slug]]` допускает отсутствие этих частей.
