# Как искать серверные ошибки и наблюдать приложение

> [!NOTE]
> Серверные запросы к БД не видны отдельными запросами браузера. Для диагностики нужны журналы сервера, измерения длительности, метрики БД и при необходимости трассировка.

## Вопрос

Где искать причину, если страница долго загружается или API возвращает 500?

## Основная идея

Раздели путь запроса на участки: браузер → Next.js → проверка сессии → ожидание соединения → SQL → подготовка ответа. Большое общее время не говорит, какой участок медленный.

Для корреляции событиям присваивают идентификатор запроса. Структурированные журналы содержат тип события, маршрут, статус и длительность; токены и пароли туда не попадают.

## Пример: перехват серверной ошибки Next.js

```ts
// instrumentation.ts — в корне проекта рядом с app
import type { Instrumentation } from "next";

export const onRequestError: Instrumentation.onRequestError = (
  _error, request, context,
) => {
  console.error(JSON.stringify({
    event: "next_request_error",
    path: request.path.split("?")[0],
    route: context.routePath,
    router: context.routerKind,
  }));
};
```

Это минимальный пример без внешнего сервиса. Он фиксирует контекст перехваченного Next.js сбоя, но не печатает тело запроса, cookie и текст SQL. В production его связывают с системой ошибок и request ID.

## Что важно помнить

Ошибки, которые приложение уже поймало и превратило в результат формы, не обязательно попадут в этот callback. Их обрабатывают на соответствующем уровне. Ожидаемая ошибка валидации не должна выглядеть как авария базы.

Следи за частотой 5xx, временем ответа, ожиданием пула, числом соединений и медленными SQL. Для SQL используй план запроса и инструменты PostgreSQL, а не только браузерный Lighthouse.

Трассировка, например OpenTelemetry, связывает участки выполнения в одну цепочку. Метрики показывают тенденцию, журналы — конкретные события. Ограничивай доступ, объем и сроки хранения журналов; URL тоже может содержать персональные данные.

## Мини-шпаргалка

- Network показывает браузерные обращения, не внутренний SQL.
- Измеряй отдельные этапы запроса.
- Собирай ошибки и метрики БД.
- Не записывай секреты и лишние персональные данные.
