# Когда нужны очереди, after и отдельный backend

> [!NOTE]
> Next.js хорошо обслуживает HTTP-запросы и серверный интерфейс. Долгие, повторяемые и постоянные процессы требуют подходящей инфраструктуры, которая переживает завершение отдельного запроса.

## Вопрос

Можно ли отправить тяжелую задачу в фон и сразу вернуть пользователю ответ?

## Основная идея

Обычный вызов `void doWork()` не гарантирует завершение: serverless-экземпляр может остановиться после ответа. API `after()` позволяет зарегистрировать работу после отправки ответа, но по-прежнему ограничен средой выполнения.

## Пример: небольшая операция после ответа

```ts
// app/api/ping/route.ts
import { after } from "next/server";
import { randomUUID } from "node:crypto";

export const runtime = "nodejs";

export async function GET() {
  const requestId = randomUUID();
  after(() => {
    console.info(JSON.stringify({ event: "ping_finished", requestId }));
  });
  return Response.json({ ok: true });
}
```

Посетитель получает ответ, после чего выполняется журналирование. Пример не обещает надежную доставку сообщения во внешнюю систему.

## Что важно помнить

Для генерации большого отчета, обработки видео или важного письма нужна надежная очередь: запись задания, отдельный worker, повторы, учет статуса и обработка окончательного сбоя. Worker выполняется независимо от маршрута Next.js.

Если изменение БД и постановка задания должны быть согласованы, используют транзакционную запись задания или outbox. Иначе процесс может завершиться между сохранением заказа и отправкой события.

**Cron** запускает задания по расписанию, но возможны повторы и пересечения запусков. **WebSocket** держит соединение открытым; обычная serverless HTTP-функция может для этого не подходить. Для realtime используют поддерживаемую платформу или отдельный сервис.

Отдельный backend полезен также при независимых командах, нескольких клиентах и сложной бизнес-логике. Это архитектурное решение, а не обязательное условие работы Next.js с БД.

## Мини-шпаргалка

- `after` подходит ограниченной работе после ответа.
- Важная фоновая задача должна быть надежно сохранена.
- Очередь и worker отвечают за повторы и длительное выполнение.
- Возможности WebSocket и cron зависят от размещения.
