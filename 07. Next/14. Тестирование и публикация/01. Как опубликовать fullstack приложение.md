# Как опубликовать fullstack-приложение

> [!NOTE]
> Fullstack-приложению нужны среда выполнения серверного кода, доступная PostgreSQL и настройки окружения. Статическая выгрузка файлов не заменяет сервер для сессий, Actions и динамических запросов к БД.

## Вопрос

Где запускать Next.js с backend и чем отличаются варианты публикации?

## Основная идея

| Вариант | Что учитывать |
| --- | --- |
| Node.js-сервер | Процесс, reverse proxy, HTTPS, перезапуск, журналирование |
| Serverless-платформа | Таймауты, конкуренцию, пул БД, поддержку функций Next.js |
| Docker | Сборку для нужной платформы, env, сеть, ресурсы контейнера |
| Static export | Подходит только совместимым статическим возможностям |

Для проекта задач нужна серверная среда. PostgreSQL может быть отдельным контейнером или управляемой БД; данные должны переживать замену экземпляра приложения.

## Пример: обычный Node.js-запуск

```powershell
npm ci
npm run build
npm run start
```

Команды предполагают стандартные scripts Next.js и сохраненный `package-lock.json`. До сборки задай нужные env-переменные: конфигурация и некоторые страницы могут обращаться к ним уже в build. Секреты передаются через механизм хостинга, а не в публичный репозиторий.

Для меньшего артефакта можно отдельно изучить:

```ts
// часть next.config.ts — сохрани остальные настройки
const nextConfig = { output: "standalone" };
export default nextConfig;
```

Standalone создает сервер и набор зависимостей. `public` и `.next/static` по умолчанию нужно доставить отдельно или разместить через CDN. Это не то же самое, что `output: "export"`.

## Что важно помнить

Сборка Linux-контейнера должна получать совместимые зависимости: не копируй Windows `node_modules` в Linux-образ. Не включай `.env` с секретами в образ или артефакт. За reverse proxy корректно настрой публичный домен и заголовки, которые нужны авторизации.

Проверь соединение с БД, примененные миграции, `BETTER_AUTH_URL`, HTTPS, регистрацию, cookie и CRUD после публикации. Локальный `localhost` в строке подключения на сервере означает сам сервер, а внутри контейнера — этот контейнер.

Масштабирование на несколько экземпляров требует общего хранилища данных и координации кэша. Файлы загрузок и очередь также не должны жить только в памяти одного процесса.

## Мини-шпаргалка

- Для backend нужен серверный runtime.
- База и файлы должны сохраняться независимо от приложения.
- Build и runtime могут требовать разных параметров.
- После публикации проверяй полный пользовательский сценарий.
