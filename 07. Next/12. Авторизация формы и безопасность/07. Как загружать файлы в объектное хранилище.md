# Как загружать файлы в объектное хранилище

> [!NOTE]
> Пользовательские файлы обычно хранят в объектном хранилище, а в БД записывают ключ, владельца и метаданные. Сервер может выдать ограниченное разрешение на прямую загрузку из браузера.

## Вопрос

Почему нельзя просто записывать загруженные изображения в папку `public`?

## Основная идея

На serverless-хостинге локальная файловая система может быть временной или недоступной для записи. Разные экземпляры также не делят общую папку. Для постоянных файлов нужен отдельный сервис хранения.

Это дополнительный пример для Amazon S3: нужен собственный приватный bucket, IAM-права на загрузку, регион и CORS для origin приложения. Он не требуется для базового CRUD задач.

## Пример: ограниченное разрешение на загрузку

```powershell
npm install @aws-sdk/client-s3 @aws-sdk/s3-presigned-post
```

На сервере задай `S3_BUCKET`, `AWS_REGION` и учетные данные AWS через стандартный механизм SDK; в production предпочтительна роль сервиса.

```ts
// app/uploads/actions.ts
"use server";

import { randomUUID } from "node:crypto";
import { S3Client } from "@aws-sdk/client-s3";
import { createPresignedPost } from "@aws-sdk/s3-presigned-post";
import { z } from "zod";
import { requireUser } from "@/lib/session";

export async function prepareUpload(rawType: unknown) {
  const user = await requireUser();
  const type = z.enum(["image/jpeg", "image/png"]).parse(rawType);
  const bucket = process.env.S3_BUCKET;
  const region = process.env.AWS_REGION;
  if (!bucket || !region) throw new Error("Не настроено хранилище");
  const key = `uploads/${user.id}/${randomUUID()}`;
  const result = await createPresignedPost(new S3Client({ region }), {
    Bucket: bucket, Key: key, Expires: 60,
    Fields: { "Content-Type": type },
    Conditions: [
      ["eq", "$Content-Type", type],
      ["content-length-range", 1, 5 * 1024 * 1024],
    ],
  });
  return { ...result, key };
}
```

```ts
// app/uploads/upload.ts — вызывается из клиентского обработчика
"use client";
import { prepareUpload } from "./actions";

export async function upload(file: File) {
  const { url, fields, key } = await prepareUpload(file.type);
  const body = new FormData();
  for (const [name, value] of Object.entries(fields)) body.append(name, value);
  body.append("file", file);
  const response = await fetch(url, { method: "POST", body });
  if (!response.ok) throw new Error("Загрузка не выполнена");
  return key;
}
```

Хранилище проверит срок, ключ, заявленный тип и предел размера. Файл не проходит целиком через сервер Next.js.

## Что важно помнить

MIME-тип можно подделать: политика POST не проверяет содержимое изображения. Перед публикацией проверяют реальные байты и при необходимости обрабатывают файл в безопасном сервисе.

Полученный ключ еще не означает, что загрузка подтверждена. Сервер проверяет наличие объекта, его владельца и метаданные, затем сохраняет ссылку в БД. Для приватного скачивания также проверяют доступ и выдают временную ссылку. Настрой очистку незавершенных и ненужных загрузок.

## Мини-шпаргалка

- Файлы — в хранилище, метаданные — в БД.
- Разрешение ограничивают ключом, сроком и размером.
- Расширение и MIME не доказывают содержимое.
- Приватное чтение требует проверки владельца.
