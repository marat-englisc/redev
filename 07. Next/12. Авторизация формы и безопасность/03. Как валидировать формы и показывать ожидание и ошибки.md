# Как валидировать формы и показывать ожидание и ошибки

> [!NOTE]
> `useActionState` хранит результат серверного действия. `useFormStatus` дает вложенному компоненту состояние отправки формы. Проверка в браузере помогает пользователю, серверная проверка защищает данные.

## Вопрос

Как собрать формы создания, изменения и удаления задач с понятным результатом?

## Основная идея

Сначала создай Actions из раздела 11, темы 06. Они возвращают `{ message }`, а Zod-схемы в DAL проверяют входные значения. Форма не должна обещать успех до ответа сервера.

## Пример: интерфейс для CRUD

```tsx
// app/tasks/task-forms.tsx
"use client";

import { useActionState } from "react";
import { useFormStatus } from "react-dom";
import { createTaskAction, updateTaskAction, deleteTaskAction } from "./actions";
import type { Task } from "@/lib/tasks";

function SubmitButton({ children }: { children: React.ReactNode }) {
  const { pending } = useFormStatus();
  return <button disabled={pending} type="submit">
    {pending ? "Подождите…" : children}
  </button>;
}

export function CreateTaskForm() {
  const [state, action] = useActionState(createTaskAction, { message: "" });
  return <form action={action}>
    <label>Новая задача <input name="title" required maxLength={200} /></label>
    <SubmitButton>Добавить</SubmitButton>
    <p role="status">{state.message}</p>
  </form>;
}

export function TaskEditor({ task }: { task: Task }) {
  const [saved, save] = useActionState(updateTaskAction, { message: "" });
  const [deleted, remove] = useActionState(deleteTaskAction, { message: "" });
  return <article>
    <form action={save}>
      <input type="hidden" name="id" value={task.id} />
      <label>Название <input name="title" defaultValue={task.title}
        required maxLength={200} /></label>
      <label><input type="checkbox" name="completed"
        defaultChecked={task.completed} /> Выполнено</label>
      <SubmitButton>Сохранить</SubmitButton>
      <p role="status">{saved.message}</p>
    </form>
    <form action={remove}>
      <input type="hidden" name="id" value={task.id} />
      <SubmitButton>Удалить</SubmitButton>
      <p role="status">{deleted.message}</p>
    </form>
  </article>;
}
```

Теперь замени серверную страницу из темы 05 следующим вариантом. Кнопка выхода создана в предыдущей теме:

```tsx
// app/tasks/page.tsx
import { redirect } from "next/navigation";
import { getCurrentUser } from "@/lib/session";
import { listTasks } from "@/lib/tasks";
import { CreateTaskForm, TaskEditor } from "./task-forms";
import LogoutButton from "./logout-button";

export const runtime = "nodejs";

export default async function TasksPage() {
  if (!(await getCurrentUser())) redirect("/login");
  const tasks = await listTasks();
  return <main>
    <h1>Мои задачи</h1>
    <LogoutButton />
    <CreateTaskForm />
    {tasks.map(task => <TaskEditor key={task.id} task={task} />)}
  </main>;
}
```

Все изменения попадут в настоящую таблицу `tasks`. Перезагрузка страницы подтвердит, что данные сохранились в БД.

## Что важно помнить

`SubmitButton` расположен внутри своей формы: вызов `useFormStatus` снаружи не наблюдает ее отправку. Подсказки `required` и `maxLength` обходятся прямым запросом, поэтому Zod и SQL-ограничения остаются обязательными.

Для более подробного интерфейса Action может возвращать ошибки отдельных полей. Сетевой сбой и неверное поле — разные состояния; не очищай заполненную форму до подтвержденного успеха.

## Мини-шпаргалка

- Сервер валидирует, клиент показывает результат.
- `useActionState` добавляет аргумент предыдущего состояния.
- `useFormStatus` работает у потомка формы.
- `pending` не заменяет защиту от повторных операций.
