# Как работают cookies, headers, redirect и Proxy

> [!NOTE]
> Cookie и заголовки передают данные HTTP-запроса, redirect меняет адрес браузера, а Proxy позволяет обработать запрос перед маршрутом. Эти механизмы дополняют серверную логику, но не заменяют DAL.

## Вопрос

Где читать cookie, где менять ее и как перенаправить посетителя?

## Основная идея

В современном App Router `cookies()` и `headers()` асинхронны. Серверный компонент может читать данные запроса. Установка cookie требует исходящего ответа: ее выполняют в Action или Route Handler, до начала отправки ответа.

`redirect("/login")` прекращает выполнение специальным исключением. Поэтому его не помещают внутрь общего `catch`, который превратит перенаправление в обычную ошибку.

## Пример: перенаправление старого адреса

```ts
// proxy.ts — рядом с app, не внутри него
import { NextResponse, type NextRequest } from "next/server";

export function proxy(request: NextRequest) {
  const target = request.nextUrl.clone();
  target.pathname = "/tasks";
  return NextResponse.redirect(target);
}

export const config = { matcher: "/old-tasks" };
```

Запрос `/old-tasks?page=2` перейдет на `/tasks?page=2`. В Next.js 16 соглашение `proxy.ts` заменяет прежнее имя `middleware.ts`; старые статьи могут показывать прежнее название.

## Пример: чтение предпочтения в серверном компоненте

```tsx
// app/preferences/page.tsx — вариант без Cache Components
import { cookies } from "next/headers";

export default async function Page() {
  const value = (await cookies()).get("theme")?.value;
  const theme = value === "dark" ? "темная" : "светлая";
  return <p>Предпочтительная тема: {theme}</p>;
}
```

Cookie пользователя недоверенная, поэтому значение проверяется. Это предпочтение интерфейса, а не доказательство входа.

## Что важно помнить

`HttpOnly` запрещает чтение cookie через JavaScript, `Secure` ограничивает передачу HTTPS, `SameSite` влияет на межсайтовые запросы. Сессионные cookie лучше настраивать средствами библиотеки авторизации.

**Rewrite** меняет внутренний адрес обработки, сохраняя адрес в браузере; **redirect** сообщает браузеру перейти. Не перенаправляй на произвольный `returnTo` из URL без списка допустимых адресов.

Proxy полезен для раннего маршрутизирования, но повторная проверка прав остается рядом с запросом БД.

## Мини-шпаргалка

- Cookie и заголовки читают с `await`.
- Cookie меняют через Action или обработчик.
- Redirect останавливает выполнение.
- Proxy управляет запросом до маршрута.
