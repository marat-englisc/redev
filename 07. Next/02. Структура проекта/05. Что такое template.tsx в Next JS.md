# Что такое template.tsx

> [!NOTE]
> `template.tsx` — обертка для вложенного интерфейса, которая получает новый экземпляр при изменении соответствующего уровня маршрута. В отличие от общего layout, она позволяет сбросить состояние вложенных клиентских компонентов.

## Вопрос

Как сбрасывать локальное состояние при переходе между страницами и чем template отличается от layout?

## Основная идея

React сохраняет состояние компонента, пока сохраняется его место и идентичность в дереве. Next.js задает template ключ, связанный с маршрутом. Когда этот ключ меняется, React удаляет прежний экземпляр и создает новый — это называется **перемонтированием**.

При этом вложенные клиентские компоненты теряют локальное состояние, а эффекты `useEffect` запускаются заново. Это бывает полезно для временного черновика или формы, которую нужно начинать с чистого состояния.

## Пример: черновик внутри раздела

Предположим, существуют `/blog/first` и `/blog/second`:

```tsx
// app/blog/template.tsx
"use client";

import { useState, type ReactNode } from "react";

export default function BlogTemplate({ children }: { children: ReactNode }) {
  const [draft, setDraft] = useState("");

  return (
    <section>
      <label>
        Временная заметка:
        <input
          value={draft}
          onChange={event => setDraft(event.target.value)}
        />
      </label>
      {children}
    </section>
  );
}
```

Введи текст на `/blog/first`, затем перейди через `Link` на `/blog/second`. Соответствующий дочерний сегмент изменится, template создастся заново, а поле очистится.

Если использовать вместо него общий `app/blog/layout.tsx`, такой макет обычно сохранит состояние при переходе между этими страницами.

## Что важно помнить

Template не пересоздается при абсолютно любом изменении URL. Поведение зависит от уровня сегмента: изменение более глубокого сегмента не обязательно перемонтирует template выше. Изменение только строки запроса, например `?sort=date`, само по себе не вызывает такое перемонтирование.

Template по умолчанию может быть серверным. В примере `"use client"` нужен из-за `useState` и обработчика ввода. Если состояние находится во вложенном клиентском компоненте, сам template можно оставить серверным.

Шапку, постоянное меню и другие части, которые должны сохраняться, удобнее помещать в layout.

## Мини-шпаргалка

- Layout сохраняет общую оболочку при переходах.
- Template получает новый экземпляр при изменении своего уровня маршрута.
- Перемонтирование сбрасывает вложенное локальное состояние.
- Изменение query-параметров само по себе не сбрасывает template.
