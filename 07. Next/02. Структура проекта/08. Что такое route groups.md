# Что такое route groups

> [!NOTE]
> **Route group**, группа маршрутов, — папка App Router с именем в круглых скобках, например `(marketing)`. Она организует файлы и общие layout, но не добавляет свою часть в URL.

## Вопрос

Как разделить маршруты по назначению, дать им разные обертки и сохранить короткие адреса?

## Основная идея

Обычно папка становится частью пути: `app/shop/about/page.tsx` создает `/shop/about`. Но иногда группировка нужна только разработчику: публичные страницы, вход и рабочую область удобно разложить по `(marketing)`, `(auth)` и `(app)`, а слова `marketing` или `auth` в адресе пользователю ничего не дают.

Скобки сообщают Next.js, что имя папки используется для организации маршрутов. Поэтому `app/(auth)/login/page.tsx` открывается по `/login`. В группе можно создать собственный `layout.tsx`, который оборачивает только маршруты этой группы.

## Пример: разные оболочки

```text
app/
  layout.tsx
  (marketing)/
    layout.tsx
    page.tsx             → /
    pricing/
      page.tsx           → /pricing
  (auth)/
    layout.tsx
    login/
      page.tsx           → /login
```

```tsx
// app/(marketing)/layout.tsx
import type { ReactNode } from "react";
import Link from "next/link";

export default function MarketingLayout({ children }: { children: ReactNode }) {
  return (
    <div>
      <nav><Link href="/pricing">Тарифы</Link></nav>
      {children}
      <footer>Информация о сервисе</footer>
    </div>
  );
}
```

```tsx
// app/(auth)/layout.tsx
import type { ReactNode } from "react";

export default function AuthLayout({ children }: { children: ReactNode }) {
  return <section><h1>Учетная запись</h1>{children}</section>;
}
```

Страницы `/` и `/pricing` получат меню и footer из `(marketing)`. `/login` будет использовать оболочку `(auth)` с заголовком «Учетная запись». Все три страницы также оборачиваются общим корневым `app/layout.tsx`. Имена групп в адресной строке отсутствуют.

## Что важно помнить

- Группа не создает пространство имен в адресе: `app/(admin)/settings/page.tsx` и `app/(user)/settings/page.tsx` конфликтуют — обе занимают `/settings`.
- Название `(private)` или `(auth)` не защищает страницы. Авторизация и проверка прав реализуются отдельным серверным кодом.
- Можно создать несколько корневых layout без общего `app/layout.tsx`. Тогда каждый должен содержать `<html>` и `<body>`, а переход между разными корнями вызовет полную загрузку документа. Для обычной группировки это не требуется.
- Группы удобно сочетать с разными layout, `loading.tsx` и `error.tsx` для частей приложения.

## Мини-шпаргалка

- `(name)` — папка для организации, не часть URL.
- Свой `layout.tsx` в группе оборачивает только ее маршруты.
- Одинаковые итоговые URL в разных группах конфликтуют.
- Группа ≠ защита доступа.
