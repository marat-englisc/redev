# Какие папки обязательны в Next.js

> [!NOTE]
> Для страниц Next.js нужна директория маршрутизатора: `app` для App Router или `pages` для Pages Router. Папки `components`, `lib`, `hooks` и `public` создают по необходимости.

## Вопрос

Как выглядит минимальная структура App Router и какие папки можно не создавать?

## Основная идея

Next.js требует конкретные соглашения для маршрутов, но не задает имена всех папок приложения. Компоненты, вспомогательные функции и стили можно организовать удобным для команды способом.

В обычном проекте App Router создают `app/layout.tsx` и хотя бы одну страницу. Корневой layout обязателен и содержит `<html>` и `<body>`. Если стартовый инструмент создал его автоматически, это не делает файл необязательным.

Директорию `app` можно расположить в корне проекта или внутри `src`. Конфигурационные файлы при этом обычно остаются в корне.

## Пример: минимальное приложение

```text
project/
  package.json
  app/
    layout.tsx
    page.tsx
```

```tsx
// app/layout.tsx
import type { ReactNode } from "react";

export default function RootLayout({ children }: { children: ReactNode }) {
  return (
    <html lang="ru">
      <body>{children}</body>
    </html>
  );
}
```

```tsx
// app/page.tsx
export default function HomePage() {
  return <h1>Мое первое приложение</h1>;
}
```

После запуска подготовленного Next.js-проекта адрес `/` покажет заголовок внутри корневого документа. `package.json` должен содержать установленные зависимости и команды проекта; приведенное дерево показывает только основные файлы.

## Что важно помнить

`public` нужен, если проект раздает собственные статические файлы. Например, `public/logo.svg` доступен по `/logo.svg`. Без таких файлов эта папка необязательна.

`components` и `lib` — соглашения команды. Next.js не требует их существования. `api` также не обязателен: приложение может использовать только внешний backend.

В Pages Router пользовательские `_app.tsx` и `_document.tsx` необязательны: есть стандартное поведение. Не следует переносить их в App Router, где используется другая модель.

В более сложной схеме возможны несколько корневых layout в группах маршрутов. Для первого проекта достаточно одного `app/layout.tsx`.

## Мини-шпаргалка

- App Router: директория `app`, корневой layout и страницы.
- Допустимо расположение `src/app`.
- `components`, `lib`, `hooks`, `public` создаются по необходимости.
- Pages Router использует директорию `pages` и другие соглашения.
