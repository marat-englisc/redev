# Можно ли использовать Feature-Sliced Design в Next.js

> [!NOTE]
> **Feature-Sliced Design**, FSD, — подход к организации кода по слоям и пользовательским задачам. Его можно применять вместе с Next.js, учитывая специальные имена папок маршрутизатора.

## Вопрос

Как разделять код по смыслу и одновременно сохранять понятную структуру маршрутов Next.js?

## Основная идея

Next.js определяет, какой файл отвечает за URL. FSD помогает решить, где хранить интерфейс, предметные данные и пользовательские сценарии. Это разные задачи, поэтому подходы совместимы.

Например, `entities/product` содержит понятия товара, `features/add-to-cart` — действие добавления в корзину, а `shared` — переиспользуемые элементы без привязки к конкретной предметной области.

Для начала достаточно нескольких слоев. Полная схема с множеством папок не нужна небольшому учебному приложению.

## Пример: отделяем сценарий от маршрута

Упрощенный вариант организации, использующий часть идей FSD:

```text
src/
  app/
    page.tsx
    layout.tsx
  features/
    add-to-cart/
      index.tsx
  shared/
    ui/
```

```tsx
// src/features/add-to-cart/index.tsx
"use client";

import { useState } from "react";

export function AddToCart() {
  const [quantity, setQuantity] = useState(0);

  return (
    <button onClick={() => setQuantity(value => value + 1)}>
      В корзине: {quantity}
    </button>
  );
}
```

```tsx
// src/app/page.tsx
import { AddToCart } from "../features/add-to-cart";

export default function HomePage() {
  return <main><h1>Учебник React</h1><AddToCart /></main>;
}
```

Страница отвечает за адрес `/`, а отдельный модуль — за интерактивный счетчик. Пример хранит количество только в состоянии компонента; настоящего сохранения корзины здесь нет.

## Что важно помнить

Имена `app` и `pages` имеют специальное значение для Next.js. При переносе полной FSD-структуры нельзя бездумно создавать FSD-слой `src/pages`: Next.js может воспринять его как Pages Router. Способ интеграции нужно выбрать явно по руководству FSD.

Расположение модуля в `features` или `entities` не делает его серверным или клиентским. Границу определяют импорты и директива `"use client"`. Серверные секреты нельзя импортировать в клиентский граф модулей.

Обычные компоненты разрешено хранить и рядом со страницами в `app`. Вынесение слоев — архитектурный выбор, а не требование маршрутизатора.

## Мини-шпаргалка

- Next.js организует маршруты; FSD организует смысловые модули.
- Начинай с структуры, соразмерной проекту.
- Учитывай специальные имена `app` и `pages`.
- Слои FSD не заменяют границу сервера и клиента.
