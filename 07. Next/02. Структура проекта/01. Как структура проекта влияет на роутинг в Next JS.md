# Как структура проекта влияет на роутинг

> [!NOTE]
> В **App Router** папки внутри `app` описывают дерево маршрутов, а специальные файлы определяют страницы, общие макеты и поведение интерфейса.

## Вопрос

Почему перемещение файла страницы может изменить ее URL, а добавление обычного компонента — нет?

## Основная идея

**Маршрут** связывает адрес с содержимым. Например, `/shop/cart` должен показать корзину. Next.js выводит эту связь из файловой структуры.

Папки `shop` и `cart` становятся частями пути, а `page.tsx` делает страницу доступной по этому пути. Сама папка без страницы не создает публичный экран.

Другие специальные файлы решают отдельные задачи: `layout.tsx` оборачивает вложенное содержимое, `loading.tsx` задает интерфейс ожидания, `error.tsx` — интерфейс при ошибке. Обычные файлы компонентов можно хранить рядом с ними.

## Пример: магазин и корзина

```text
app/
  layout.tsx
  page.tsx                 → /
  shop/
    layout.tsx
    page.tsx               → /shop
    ProductCard.tsx        → отдельного URL нет
    cart/
      page.tsx             → /shop/cart
  api/
    health/
      route.ts             → HTTP-обработчик /api/health
```

```tsx
// app/shop/cart/page.tsx
export default function CartPage() {
  return <h1>Ваша корзина</h1>;
}
```

Открыв `/shop/cart`, пользователь увидит корзину внутри корневого макета и `app/shop/layout.tsx`. `ProductCard.tsx` не станет страницей: его нужно импортировать в компонент, который его использует.

## Что важно помнить

Файловая структура не является буквальной копией URL во всех случаях. Группа `(marketing)` не добавляет часть адреса, а `[id]` обозначает изменяемое значение.

`route.ts` создает HTTP-обработчик, а не React-страницу. Его нельзя размещать на том же уровне маршрута вместе с `page.tsx`: оба претендовали бы на один URL.

Для явно внутренних папок в `app` можно использовать `_components` или `_lib`. Префикс `_` исключает папку из маршрутизации. Это удобное соглашение, а не обязательное условие хранения компонентов рядом со страницей.

В Pages Router действуют другие правила: там страницы обычно создаются самими файлами, например `pages/about.tsx`.

## Мини-шпаргалка

- Папки задают путь; `page.tsx` создает экран.
- `layout.tsx` влияет на оболочку, но не создает страницу.
- Обычный файл компонента не становится маршрутом App Router.
- `route.ts` отвечает на HTTP-запросы.
