# Как работают вложенные layout

> [!NOTE]
> **Вложенные layout** образуют цепочку общих оберток: от корневого документа до каркаса конкретного раздела и самой страницы.

## Вопрос

Как Next.js выбирает порядок layout и что сохраняется при переходах между вложенными страницами?

## Основная идея

Для страницы Next.js идет по папкам от `app` до нужного `page.tsx`. Каждый встретившийся `layout.tsx` добавляет внешний уровень интерфейса. В `children` очередного layout попадает следующий уровень либо страница.

Это похоже на матрешку: корневой layout задает документ, layout кабинета - боковую панель, layout настроек - вкладки, а страница показывает конкретную форму.

При клиентской навигации сохраняется общая часть цепочки. Если пользователь остается внутри кабинета, его общее меню остается; при выходе из кабинета соответствующая ветвь удаляется.

## Пример: каркас раздела обучения

```text
app/
├── layout.tsx
└── learn/
    ├── layout.tsx
    ├── page.tsx
    └── react/
        └── page.tsx
```

В существующем приложении корневой `app/layout.tsx` уже содержит `<html>` и `<body>`. Добавим внутренний layout и две страницы:

```tsx
// app/learn/layout.tsx
import Link from "next/link";
import type { ReactNode } from "react";

export default function LearnLayout({ children }: { children: ReactNode }) {
  return (
    <section>
      <nav><Link href="/learn">Все темы</Link>{" | "}<Link href="/learn/react">React</Link></nav>
      <div>{children}</div>
    </section>
  );
}
```

```tsx
// app/learn/page.tsx
export default function Page() {
  return <h1>Выберите тему</h1>;
}
```

```tsx
// app/learn/react/page.tsx
export default function Page() {
  return <h1>Основы React</h1>;
}
```

Для `/learn/react` порядок будет таким: Root Layout → Learn Layout → страница React. При переходе с `/learn` меняется вложенное содержимое, а общее меню продолжает отображаться.

## Что важно помнить

Не каждая папка требует собственного layout. Создавай его, когда действительно появляется новый общий каркас или окружение.

Layout не получает вложенные данные страницы автоматически. Страница и layout могут получать нужные данные самостоятельно; повторные одинаковые запросы можно объединять предусмотренными механизмами.

Метаданные тоже разрешаются по цепочке. Простые поля могут заменяться дочерним сегментом, а вложенные объекты вроде `openGraph` не объединяются глубоко автоматически.

Сохранение состояния относится к общей ветви и не заменяет постоянное хранение после перезагрузки браузера.

## Мини-шпаргалка

- Внешняя папка дает внешний layout.
- `children` содержит следующий уровень.
- При навигации сохраняется общая цепочка.
- Новый layout нужен для новой общей задачи.
