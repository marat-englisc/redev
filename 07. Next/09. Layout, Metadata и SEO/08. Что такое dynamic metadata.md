# Что такое dynamic metadata

> [!NOTE]
> **Dynamic metadata, вычисляемые метаданные**, - значения, которые возвращает функция `generateMetadata`, например заголовок по данным статьи или параметрам маршрута.

## Вопрос

Как получить отдельный title для каждой статьи и когда выполняется `generateMetadata`?

## Основная идея

Страница `/books/next` должна называться по книге, а не общим словом «Книга». Сервер может прочитать параметр `slug`, найти нужную запись и вернуть объект с title и description.

`generateMetadata` описывает вычисление, а не обязательный рендеринг на каждый запрос. Если маршрут и его данные можно подготовить заранее, метаданные тоже могут вычислиться при сборке. При динамическом рендеринге они вычисляются во время запроса.

## Пример: название из учебного справочника

Пример для Next.js 16 App Router без включенного `cacheComponents`:

```tsx
// app/books/[slug]/page.tsx
import type { Metadata } from "next";
import { notFound } from "next/navigation";

type Props = { params: Promise<{ slug: string }> };

const books: Record<string, { title: string; description: string }> = {
  next: { title: "Первые шаги в Next.js", description: "Маршруты и компоненты для новичков." },
};

async function getBook(slug: string) {
  if (!Object.hasOwn(books, slug)) notFound();
  const book = books[slug];
  return book;
}

export function generateStaticParams() {
  return [{ slug: "next" }];
}

export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const { slug } = await params;
  const book = await getBook(slug);
  return { title: book.title, description: book.description };
}

export default async function Page({ params }: Props) {
  const { slug } = await params;
  const book = await getBook(slug);
  return <article><h1>{book.title}</h1><p>{book.description}</p></article>;
}
```

`getBook` - учебная функция чтения локального справочника вместо базы. `Object.hasOwn` проверяет, что ключ принадлежит самому справочнику, а не унаследован от прототипа объекта. На `/books/next` содержимое и метаданные используют одну запись. `generateStaticParams` позволяет подготовить этот маршрут заранее; `params` в современной версии читается через `await`.

## Что важно помнить

`searchParams`, если они нужны на уровне страницы, тоже являются Promise. У layout нет такого пропа.

Одинаковые поддерживаемые `fetch`-запросы в метаданных и компонентах могут объединяться в рамках рендера. Это не означает автоматический постоянный Data Cache: его политику задают отдельно.

Для динамического ответа Next.js может отправить метаданные потоком после начального интерфейса. Для распознанных ботов, которым нужен исходный HTML, он дожидается метаданных и помещает их в `<head>`.

## Мини-шпаргалка

- `generateMetadata` возвращает объект Metadata.
- Параметры современной страницы читают асинхронно.
- Вычисляемые metadata могут быть подготовлены при сборке.
- В одном сегменте выбирают `metadata` или `generateMetadata`.
