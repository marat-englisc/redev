# Metadata API и статические метаданные

> [!NOTE]
> **Metadata API** — механизм App Router для описания заголовка документа, description, социальных превью и других метаданных через серверные экспорты и специальные файлы. **Статические метаданные** — заранее описанный объект `metadata` с фиксированными значениями.

## Вопрос

Как задать данные для вкладки браузера, поисковых систем и превью ссылок без ручного дублирования HTML-тегов? Когда достаточно объекта `metadata` и делает ли он страницу статической?

## Основная идея

Содержимое страницы отвечает на вопрос «что читает посетитель», а метаданные описывают сам документ. `<title>` задает название вкладки, description кратко характеризует содержимое, Open Graph помогает сервисам построить превью ссылки.

В App Router есть три способа описания:

| Способ | Когда |
| --- | --- |
| объект `metadata` | значения фиксированы: «Контакты», «О проекте» |
| функция `generateMetadata` | значения зависят от `params` или загруженных данных |
| файловые соглашения | `icon.png`, `opengraph-image.png`, `robots.ts`, `sitemap.ts` |

Next.js сам формирует соответствующие теги. Layout задает общие значения, а дочерние страницы их уточняют.

«Статические» описывает способ объявления. Сама страница при этом может получать динамические данные или включать клиентские компоненты: фиксированный title не заставляет маршрут генерироваться только при сборке.

## Пример: заголовок и описание страницы

```tsx
// app/contact/page.tsx
import type { Metadata } from "next";

export const metadata: Metadata = {
  title: "Контакты",
  description: "Как связаться с командой учебного проекта.",
};

export default function Page() {
  return (
    <article>
      <h1>Связаться с нами</h1>
      <p>Почта: <a href="mailto:team@example.com">team@example.com</a></p>
    </article>
  );
}
```

Если родительский layout не задает шаблон title, результат включает:

```html
<title>Контакты</title>
<meta name="description" content="Как связаться с командой учебного проекта." />
```

Тип `Metadata` подсказывает поддерживаемые поля. `<h1>` в содержимом и `<title>` документа выполняют разные задачи: Metadata API не создает видимый заголовок автоматически.

## Что важно помнить

- `metadata` и `generateMetadata` экспортируют только из серверных `page.tsx` или `layout.tsx`. Нельзя объявлять оба способа в одном сегменте и нельзя экспортировать их из файла с `"use client"`.
- Метаданные объединяются от корня к странице **поверхностно**: новый `openGraph` в дочернем сегменте заменяет родительский объект целиком; нужные поля сохраняют явно.
- Файловые метаданные имеют более высокий приоритет, чем объекты.
- `generateMetadata` не обязательно выполняется на каждый запрос: время вычисления зависит от рендеринга маршрута.
- Title и description полезны, но не гарантируют индексацию, позицию или точный текст сниппета.
- В Pages Router используют `next/head`; не смешивай его с App Router.

## Мини-шпаргалка

- Фиксированные значения — `export const metadata`.
- Вычисляемые — `generateMetadata`.
- Иконки, OG-картинки, robots, sitemap — файлы.
- Слияние поверхностное; только серверные `page`/`layout`.
