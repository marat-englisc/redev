# Какие задачи решают layout-компоненты

> [!NOTE]
> Layout объединяет общий интерфейс, настройки и окружение группы страниц. Вложенные страницы отвечают за собственное содержимое.

## Вопрос

Что стоит размещать в layout, а что лучше оставить отдельной странице?

## Основная идея

Layout удобно использовать для шапки, подвала, бокового меню и общей сетки. В корневом layout обычно подключают глобальные стили и базовые метаданные. В layout конкретного раздела можно добавить свое меню или клиентский провайдер, например состояние корзины.

**Провайдер** - компонент, который делает значение React Context доступным вложенным клиентским потребителям. Сам серверный layout не становится клиентским только из-за того, что рендерит такой провайдер.

При переходе внутри общей ветви layout сохраняется, поэтому клиентское состояние в его окружении может пережить смену страницы. Данные и интерфейс, специфичные для одного экрана, обычно остаются в `page.tsx`.

## Пример: общий раздел обучения

```tsx
// app/learn/layout.tsx
import type { Metadata } from "next";
import Link from "next/link";
import type { ReactNode } from "react";

export const metadata: Metadata = {
  title: "Обучение",
  description: "Короткие уроки для начинающих разработчиков.",
};

export default function LearnLayout({ children }: { children: ReactNode }) {
  return (
    <section>
      <aside>
        <h2>Учебные материалы</h2>
        <Link href="/learn">Все уроки</Link>
      </aside>
      <div>{children}</div>
    </section>
  );
}
```

```tsx
// app/learn/page.tsx
export default function Page() {
  return <article><h1>Начни с HTML</h1><p>Затем изучай CSS и JavaScript.</p></article>;
}
```

На `/learn` появятся общее меню и содержимое урока. Для других страниц под `learn` меню не придется копировать. Метаданные раздела используются как исходные значения, которые дочерняя страница может переопределить.

## Что важно помнить

Layout не передает свои произвольные props маршрутизируемой странице автоматически: `children` уже создается Next.js. Данные получают непосредственно там, где они нужны, либо используют подходящий провайдер для клиентского состояния.

Проверка авторизации только в layout недостаточна для защиты всех операций. Общая ветвь может сохраняться при навигации, а к серверным действиям и источникам данных можно обращаться отдельно. Права проверяют рядом с защищенной операцией.

Не размещай все провайдеры в корне по привычке: ограничивай их область теми страницами, которым они нужны.

## Мини-шпаргалка

- Layout отвечает за общую структуру раздела.
- Page отвечает за конкретный экран.
- Провайдеры создают общее клиентское окружение.
- Защиту данных проверяют в серверных операциях.
