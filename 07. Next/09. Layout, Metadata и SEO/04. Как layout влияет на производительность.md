# Как layout влияет на производительность

> [!NOTE]
> Общий layout позволяет переиспользовать ветвь интерфейса при навигации. Серверный layout также помогает оставить часть кода и зависимостей вне браузерной сборки.

## Вопрос

Почему переходы внутри раздела могут работать быстрее и какие ошибки мешают получить пользу от layout?

## Основная идея

При клиентском переходе между соседними страницами Next.js заменяет изменившиеся сегменты, сохраняя общие layout. Это уменьшает повторную работу и сохраняет состояние клиентских компонентов в общей ветви.

Layout по умолчанию серверный: его собственная реализация и серверные зависимости не нужны браузеру для гидратации. JavaScript отправляется для вложенных клиентских компонентов.

Однако layout не ускоряет все автоматически. Если до его возврата долго ждать базу, пользователь может ждать общий каркас. Для медленных вложенных частей используют подходящие границы Suspense и `loading.tsx`.

## Пример: состояние бокового меню

```tsx
// app/dashboard/sidebar.tsx
"use client";

import { useState } from "react";
import Link from "next/link";

export default function Sidebar() {
  const [open, setOpen] = useState(true);
  return (
    <aside>
      <button aria-expanded={open} onClick={() => setOpen(value => !value)}>
        Меню
      </button>
      {open && <nav><Link href="/dashboard">Обзор</Link></nav>}
    </aside>
  );
}
```

```tsx
// app/dashboard/layout.tsx
import type { ReactNode } from "react";
import Sidebar from "./sidebar";

export default function Layout({ children }: { children: ReactNode }) {
  return <section><Sidebar /><div>{children}</div></section>;
}
```

```tsx
// app/dashboard/page.tsx
export default function Page() {
  return <h1>Обзор</h1>;
}
```

Меню имеет собственное клиентское состояние, а layout остается серверным. При добавлении и посещении других страниц внутри `dashboard` через клиентскую навигацию состояние общего меню сохраняется: не нужно заново восстанавливать его при каждом переходе.

## Что важно помнить

Сохранение общей ветви не означает «этот компонент никогда не обновляется». Вложенный клиентский компонент обновляется по state, а полная перезагрузка создает дерево заново.

Layout не является автоматическим постоянным кэшем любых запросов данных. У получения данных свои правила кэширования; одинаковые запросы также могут объединяться в пределах серверного рендера.

Не превращай весь layout в клиентский ради одной кнопки. Разделение на серверный каркас и небольшие клиентские элементы помогает контролировать размер JavaScript.

## Мини-шпаргалка

- Общие layout переиспользуются при подходящих переходах.
- Состояние общей клиентской ветви сохраняется.
- Серверный код layout не требует клиентской гидратации.
- Медленные данные и кэш нужно проектировать отдельно.
