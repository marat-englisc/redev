# Клиентская и серверная загрузка данных: где выполняется запрос

> [!NOTE]
> Серверная загрузка получает данные в среде Next.js, клиентская — в браузере. Где выполняется запрос, зависит от места вызова, а не от слова `fetch`. В одном приложении оба подхода дополняют друг друга. React описывает интерфейс, а Next.js добавляет инфраструктуру для серверной загрузки: маршруты, серверное выполнение и управление кэшем.

## Вопрос

Чем отличаются оба подхода, что Next.js добавляет к React при загрузке данных и как выбрать место для конкретного запроса?

## Основная идея

В обычном React-приложении с клиентским рендерингом браузер сначала загружает JavaScript, затем компонент запрашивает данные и показывает их. Разработчик продумывает загрузку, ошибки и повторные запросы — часто с помощью SWR или TanStack Query. Утверждение «React умеет загружать данные только в браузере» неверно: React поддерживает серверные возможности, а Next.js дает для них готовую инфраструктуру.

В App Router файлы страниц и layouts по умолчанию серверные. Запрос в таком компоненте выполняется вне браузера: при сборке либо при обработке запроса, в зависимости от настроек маршрута. Для публичной статьи сервер может получить текст и включить его в результат: пользователю не понадобится отдельный браузерный запрос.

Для событий, состояния и эффектов создают Client Component с `"use client"`. Вызов `fetch` в обработчике клика выполняется в браузере. Если пользователь нажимает «Обновить курс» или вводит поисковый запрос, браузер получает новые данные через API. Действие также может изменить URL и запустить новую серверную загрузку — клиентский `fetch` не единственная возможность.

| Свойство | Серверная загрузка | Клиентская загрузка |
| --- | --- | --- |
| Где идет запрос | Сервер Next.js | Браузер |
| Приватные ключи | Можно хранить на сервере | Нельзя включать в код |
| Начальное содержимое | Можно подготовить заранее | При запросе из эффекта появляется позже |
| Интерактивные обновления | Через навигацию или серверные операции | Через события и клиентские библиотеки |
| Видно в Network браузера | Нет | Да |
| CORS | Не ограничивает | Должен разрешать внешний сервер |

## Пример: данные до показа страницы

Next.js 16 App Router без `cacheComponents`, открытый учебный API JSONPlaceholder.

```tsx
// app/page.tsx
export default async function Page() {
  const response = await fetch(
    "https://jsonplaceholder.typicode.com/users/1",
    { cache: "no-store" }
  );
  if (!response.ok) throw new Error("Пользователь не загрузился");
  const user: { name: string } = await response.json();

  return <h1>Профиль: {user.name}</h1>;
}
```

## Пример: запрос в браузере после нажатия

```tsx
// app/NameButton.tsx
"use client";

import { useState } from "react";

export default function NameButton() {
  const [message, setMessage] = useState("Нажмите кнопку");
  const [pending, setPending] = useState(false);

  async function loadName() {
    setPending(true);
    try {
      const response = await fetch(
        "https://jsonplaceholder.typicode.com/users/1"
      );
      if (!response.ok) throw new Error("Ошибка ответа");
      const user = await response.json();
      setMessage(user.name);
    } catch {
      setMessage("Не удалось загрузить имя");
    } finally {
      setPending(false);
    }
  }

  return <><button onClick={loadName} disabled={pending}>
    {pending ? "Загрузка…" : "Загрузить имя"}
  </button><p role="status">{message}</p></>;
}
```

Запрос начинается только при клике, и его видно во вкладке Network. Серверный вариант браузер напрямую не отправляет.

## Что важно помнить

- Оба подхода сочетаются: сервер показывает карточку товара, клиентский виджет обновляет доступность после нажатия.
- Client Component тоже участвует в начальном серверном рендеринге. Отсутствие данных в HTML относится только к содержимому, загружаемому в браузерном эффекте или обработчике.
- Серверная загрузка не гарантирует мгновенный ответ — для ожидания используют `loading.tsx` или `Suspense`.
- Секретный ключ можно использовать на сервере, но нельзя передавать в props клиентского компонента или выводить в HTML. Серверное выполнение не заменяет проверку прав.
- Проверяй `response.ok`: `fetch` не бросает ошибку из-за статуса 404 или 500.

## Мини-шпаргалка

- Server Component — запрос на сервере, данные в начальном результате.
- Client Component — запрос в браузере по событию или в эффекте.
- Секреты — только на сервере.
- Начальный контент — с сервера, интерактивные обновления — на клиенте.
