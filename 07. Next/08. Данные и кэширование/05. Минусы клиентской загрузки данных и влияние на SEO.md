# Минусы клиентской загрузки данных и влияние на SEO

> [!NOTE]
> Клиентская загрузка дает интерактивность, но переносит ожидание API, часть работы и обработку состояний в браузер. Если основной текст появляется только после клиентского запроса, его обработка поисковиками и сервисами предпросмотра усложняется.

## Вопрос

Какие сложности появляются, если основной контент загружается только после запуска JavaScript, и почему важное содержимое часто загружают на сервере?

## Основная идея

При загрузке из эффекта появляется последовательность: получить страницу, загрузить JavaScript, запустить компонент, запросить API, показать данные. На медленном устройстве или соединении пользователь дольше видит сообщение ожидания.

Нужно учитывать ошибки, повторные запросы и ситуации, когда компонент уже исчез, а ответ еще идет. Если запрос зависит от поискового текста, старый ответ может прийти позже нового и перезаписать результат.

**SEO.** До окончания запроса статья или карточка товара отсутствует в HTML. Некоторые поисковые системы выполняют JavaScript, но это дополнительный этап; другие роботы, например сервисы предпросмотра ссылок, обрабатывают только исходный ответ. Вывод «клиентская загрузка полностью исключает индексацию» неверен, но она добавляет зависимость от выполнения скриптов и доступности API.

Для публичной статьи полезно сразу предоставить заголовок и текст с сервера. Количество лайков, персональные рекомендации или корзину можно обновить позже: обычно они не составляют главное содержание индексируемой страницы.

## Пример: состояния и отмена запроса

Самостоятельный Client Component для App Router. JSONPlaceholder — открытый учебный API.

```tsx
// app/UserName.tsx
"use client";

import { useEffect, useState } from "react";

export default function UserName() {
  const [message, setMessage] = useState("Загрузка…");

  useEffect(() => {
    const controller = new AbortController();

    async function load() {
      try {
        const response = await fetch(
          "https://jsonplaceholder.typicode.com/users/1",
          { signal: controller.signal }
        );
        if (!response.ok) throw new Error("Ошибка ответа");
        const user = await response.json();
        if (!controller.signal.aborted) setMessage(user.name);
      } catch {
        if (!controller.signal.aborted) {
          setMessage("Не удалось загрузить пользователя");
        }
      }
    }

    void load();
    return () => controller.abort();
  }, []);

  return <p role="status">{message}</p>;
}
```

Отмена в cleanup прекращает ненужный запрос после удаления компонента. Проверка `signal.aborted` не позволяет показать ошибку отмены пользователю.

## Пример: текст статьи в серверном результате

```tsx
// app/article/page.tsx
export const metadata = {
  title: "Учебная статья",
  description: "Пример серверной загрузки текста статьи",
};

export default async function ArticlePage() {
  const response = await fetch(
    "https://jsonplaceholder.typicode.com/posts/1",
    { next: { revalidate: 3600 } }
  );
  if (!response.ok) throw new Error("Статья недоступна");

  const post: { title: string; body: string } = await response.json();
  return <article><h1>{post.title}</h1><p>{post.body}</p></article>;
}
```

Текст формируется на сервере. Для разных статей metadata вычисляют через `generateMetadata`.

## Что важно помнить

- Клиентская загрузка полезна для интерактивных виджетов и персональных обновлений. Основной публичный контент проще получить на сервере, а затем обновлять на клиенте.
- Приватные ключи нельзя помещать в клиентский код.
- Клиентские запросы тоже могут кэшироваться через HTTP/CDN или SWR и TanStack Query: утверждение «клиент не умеет кэшировать» неверно.
- Client Component в Next.js тоже участвует в начальном серверном рендеринге — проблема только в контенте, который появляется после браузерного запроса.
- Серверный HTML сам по себе не гарантирует позиции в поиске: важны полезность содержимого, ссылки, статусы, metadata и доступность.

## Мини-шпаргалка

- Цепочка: HTML → JS → эффект → запрос → данные.
- Нужны загрузка, ошибки, отмена и защита от гонок.
- Основной контент в HTML — лучше для роботов и превью.
- Персональное и интерактивное — можно на клиенте.
