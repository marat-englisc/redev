# Опции кэширования fetch

> [!NOTE]
> Серверный `fetch` в Next.js расширен настройками хранения и ревалидации. Они позволяют явно определить, когда использовать сохраненный ответ.

## Вопрос

Чем отличаются `force-cache`, `no-store`, `revalidate` и теги?

## Основная идея

Материал относится к Next.js 16 App Router **без включенного `cacheComponents`**. Здесь речь о серверном Data Cache, а не о стандартном HTTP-кэше браузера.

| Настройка | Значение |
| --- | --- |
| `cache: "force-cache"` | Использовать сохраненный ответ или получить и сохранить его |
| `cache: "no-store"` | Не сохранять ответ в постоянный Data Cache |
| `next: { revalidate: 60 }` | Сохранять данные с временной ревалидацией |
| `next: { tags: ["posts"] }` | Связать запись с тегом для обновления по событию |

Обычный `fetch(url)` по умолчанию не включает постоянный Data Cache. При этом страница может предварительно создаваться и сохраняться как статический результат — это отдельный механизм.

Тег — метка, а не срок жизни. Он сам по себе не включает кэширование. Его добавляют к запросу, который уже сохраняется через `force-cache` или положительный `revalidate`.

## Пример: сохранить данные с тегом

JSONPlaceholder — открытый учебный API.

```tsx
// app/posts/page.tsx
export default async function Page() {
  const response = await fetch(
    "https://jsonplaceholder.typicode.com/posts?_limit=3",
    {
      cache: "force-cache",
      next: { tags: ["posts"] },
    }
  );
  if (!response.ok) throw new Error("Записи не загрузились");

  const posts: { id: number; title: string }[] = await response.json();
  return <ul>{posts.map(post => (
    <li key={post.id}>{post.title}</li>
  ))}</ul>;
}
```

Ответ можно переиспользовать между серверными запросами. Чтобы пометить данные устаревшими после изменения, серверный код может вызвать `revalidateTag("posts", "max")`.

## Что важно помнить

`no-store` и положительный `revalidate` противоречат друг другу. `force-cache` не обещает физическое хранение навечно: существуют инвалидация и особенности платформы.

`no-store` не делает данные «в реальном времени» и не выключает кэш внешнего API. При Cache Components используют другую модель с `use cache`, `cacheLife`, `cacheTag`.

## Мини-шпаргалка

- Хранить: `force-cache`.
- Не хранить: `no-store`.
- Обновлять по интервалу: `next.revalidate`.
- Группировать для инвалидации: `next.tags`.
