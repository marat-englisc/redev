# getStaticProps

> [!NOTE]
> **getStaticProps** — функция Pages Router, которая получает данные на сервере для предварительного создания статической страницы.

## Вопрос

Как работает `getStaticProps` и почему ее нельзя перенести в App Router без изменений?

## Как это работает

Этот материал относится к **Pages Router**, то есть файлам в `pages`. Во время production-сборки Next.js вызывает `getStaticProps`, получает объект `props` и создает страницу с этими данными.

Посетителям можно отдавать готовый результат вместо повторного обращения к источнику данных при каждом просмотре. Подход подходит для статей, справки и другого общедоступного содержимого.

Функция не выполняется в браузере, но возвращенные `props` доступны клиенту. Нельзя помещать в них пароль базы данных или приватный токен. Также `getStaticProps` не получает текущую сессию посетителя как обычный обработчик запроса, поэтому персональные страницы требуют другого подхода.

## Пример: статический список записей

JSONPlaceholder — открытый учебный API. Пример написан на JavaScript и требует файла именно в `pages`.

```jsx
// pages/posts.jsx
export async function getStaticProps() {
  const response = await fetch(
    "https://jsonplaceholder.typicode.com/posts?_limit=3"
  );
  if (!response.ok) throw new Error("Не удалось получить записи");

  const posts = await response.json();
  return { props: { posts } };
}

export default function PostsPage({ posts }) {
  return <ul>{posts.map(post => (
    <li key={post.id}>{post.title}</li>
  ))}</ul>;
}
```

Список будет подготовлен при сборке. Изменение внешнего API само по себе не обновит уже созданную страницу. Для обновления нужна новая сборка либо механизм ISR.

## Что важно помнить

Для ISR можно вернуть `{ props: { posts }, revalidate: 60 }`. После истечения интервала обращение к странице может запустить фоновую регенерацию. Это не запуск каждую минуту по расписанию.

В App Router `getStaticProps` не используется: данные загружают в Server Components, а стратегию определяют настройками кэша и маршрута. Для динамических путей Pages Router часто дополнительно нужен `getStaticPaths`.

## Мини-шпаргалка

- Только Pages Router.
- Получает данные при предварительной генерации.
- Возвращает `{ props: ... }`.
- `revalidate` добавляет ISR.
