# Чем Next.js может быть быстрее обычного SPA?

> [!NOTE]
> Next.js даёт инструменты для раннего показа содержимого и уменьшения клиентского JavaScript. Результат зависит от архитектуры страницы: приложение не становится быстрым только потому, что использует Next.js.

## Вопрос

За счёт чего Next.js может ускорить первый показ страницы и переходы внутри сайта?

## Основная идея

**SPA**, Single Page Application, — приложение, в котором переходы обычно обновляют интерфейс без полной перезагрузки документа. Это способ навигации, а не обязательный запрет на серверный рендеринг. Next.js тоже поддерживает такие переходы.

Для сравнения возьмём SPA, где содержимое получают только в браузере после запуска JavaScript, и страницу Next.js, где данные читают на сервере:

```text
SPA с клиентской загрузкой:
HTML-оболочка → JavaScript → запрос данных → содержимое

Next.js с серверной загрузкой:
запрос данных на сервере → HTML с содержимым → гидратация кнопок
```

Второй вариант позволяет показать содержимое без ожидания клиентского запроса. Но если сервер долго ждёт данные, первый ответ тоже может задержаться.

## Пример: текст на сервере, кнопка в браузере

В App Router разделим страницу и интерактивную часть:

```tsx
// app/page.tsx — Server Component
import LikeButton from "./like-button";

export default function Page() {
  return (
    <main>
      <h1>Учимся Next.js</h1>
      <p>Этот текст можно подготовить заранее.</p>
      <LikeButton />
    </main>
  );
}
```

```tsx
// app/like-button.tsx — Client Component
"use client";

import { useState } from "react";

export default function LikeButton() {
  const [liked, setLiked] = useState(false);

  return (
    <button aria-pressed={liked} onClick={() => setLiked(value => !value)}>
      {liked ? "Нравится!" : "Мне нравится"}
    </button>
  );
}
```

Текст входит в HTML первого ответа. Код серверного компонента не требуется отправлять для выполнения в браузере; кнопке нужен JavaScript для обработчика и состояния. Её начальный HTML также может быть подготовлен на сервере.

## Что ещё помогает

Next.js делит клиентский код по маршрутам, предоставляет `Link` с предзагрузкой, оптимизацию изображений и потоковую отправку интерфейса через Suspense. Эти механизмы решают разные задачи и требуют разумной настройки.

## Что важно помнить

Обычное SPA тоже может делить код и предзагружать данные. В Next.js можно случайно перенести всю страницу в клиентский граф зависимостей, загрузить тяжёлые библиотеки или последовательно ждать независимые запросы. Тогда преимущество уменьшится.

## Мини-шпаргалка

- Серверный HTML помогает показать основное содержимое раньше.
- Server Components уменьшают объём кода для браузера.
- `Link` ускоряет некоторые последующие переходы.
- Сравнивай конкретные страницы измерениями.
