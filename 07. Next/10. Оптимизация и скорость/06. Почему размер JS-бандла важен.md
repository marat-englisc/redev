# Почему размер JS-бандла важен?

> [!NOTE]
> JS-бандл — файл или набор файлов JavaScript, подготовленных сборщиком. Браузер тратит время не только на их скачивание, но и на разбор и выполнение, поэтому лишний код может замедлять страницу.

## Вопрос

Как объём клиентского JavaScript влияет на загрузку и как уменьшать его осмысленно?

## Основная идея

**Сборщик** объединяет зависимости приложения и создаёт файлы для исполнения. Отдельные части называют чанками. В Next.js клиентский код включает интерактивные компоненты, их зависимости и необходимый код React и фреймворка.

Большой файл дольше передаётся по медленной сети. После передачи JavaScript нужно обработать и выполнить. Сжатие Brotli уменьшает объём передачи, но не устраняет работу процессора.

Поэтому сравнивай и переданный размер в Network, и длительность задач в Performance. Файл в 300 КБ не означает одинаковую задержку на всех устройствах.

## Пример: загружаем справку по требованию

Справка не нужна до нажатия кнопки. Её можно вынести в отдельный компонент:

```tsx
// app/help-panel.tsx
"use client";

export default function HelpPanel() {
  return <aside>Выбери товар и нажми «Добавить в корзину».</aside>;
}
```

```tsx
// app/help-button.tsx
"use client";

import dynamic from "next/dynamic";
import { useState } from "react";

const HelpPanel = dynamic(() => import("./help-panel"), {
  loading: () => <p>Загружаем справку…</p>,
});

export default function HelpButton() {
  const [open, setOpen] = useState(false);

  return (
    <section>
      <button aria-expanded={open} onClick={() => setOpen(value => !value)}>
        Справка
      </button>
      {open && <HelpPanel />}
    </section>
  );
}
```

Используй `HelpButton` на странице. `dynamic` объявлен на уровне модуля, а компонент показывается по условию. Его отдельный чанк может загружаться при необходимости. В реальном проекте выигрыш заметнее, если панель содержит крупную библиотеку; для одного абзаца усложнение обычно излишне.

## Что важно помнить

Обычный статический импорт вместе с условием показа не гарантирует отложенную загрузку кода. **Tree shaking** удаляет неиспользуемые экспорты, когда структура модулей это позволяет; он не обязательно удалит большую часть любой библиотеки.

Server Components помогают оставить часть зависимостей на сервере. Но их результаты всё равно передаются клиенту: сокращение JavaScript не означает отсутствие сетевого трафика.

Проверяй состав сборки анализатором, описанным в документации Next.js для своего сборщика. У Webpack и Turbopack инструменты и команды различаются.

## Мини-шпаргалка

- Смотри передачу, разбор и выполнение кода.
- Откладывай тяжёлые необязательные части интерфейса.
- Проверяй, какие импорты попали в клиентский граф.
- Подтверждай пользу разделения кода измерениями.
