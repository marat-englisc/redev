# Почему скорость важна для SEO?

> [!NOTE]
> Быстрая и удобная страница помогает посетителю добраться до содержимого. Google использует Core Web Vitals в системах ранжирования, но хорошие показатели сами по себе не обеспечивают высокое место в поиске.

## Вопрос

Как связаны производительность сайта, поисковая оптимизация и опыт посетителя?

## Основная идея

**SEO** — поисковая оптимизация: работа над тем, чтобы поисковик мог обнаружить страницу, понять её содержимое и показать подходящему пользователю.

Представь две страницы с инструкцией. На первой текст появляется быстро и остаётся на месте. На второй сначала виден загрузчик, а при появлении рекламы абзацы сдвигаются. Даже полезный материал на второй странице читать неудобно.

Производительность влияет на удобство, но не заменяет качество текста, доступность страницы для обхода, понятные заголовки и соответствие запросу. Нельзя обещать: «Снизим LCP — получим первое место».

## Пример: ускоряем страницу статьи

Пусть главным LCP-элементом стала обложка статьи. В App Router можно использовать `next/image` с локальным изображением:

```tsx
// app/articles/page.tsx
import Image from "next/image";

export default function ArticlesPage() {
  return (
    <main style={{ maxWidth: 900, margin: "0 auto" }}>
      <h1>Как начать изучать React</h1>
      <Image
        src="/images/react-guide.jpg"
        alt="Схема дерева React-компонентов"
        width={1200}
        height={630}
        sizes="(max-width: 768px) 100vw, 900px"
        preload
        style={{ width: "100%", height: "auto" }}
      />
      <p>Начни с компонентов, props и состояния.</p>
    </main>
  );
}
```

Помести файл в `public/images/react-guide.jpg`. Пример рассчитан на Next.js 16: `preload` заранее объявляет загрузку главного изображения. `width` и `height` задают пропорции, чтобы браузер мог выделить место; `sizes` помогает выбрать подходящий размер изображения.

Это кандидат на улучшение LCP и стабильности страницы. Подтверди эффект измерением до и после. Не добавляй `preload` всем картинкам: они начнут конкурировать за сеть.

## Что важно помнить

Поисковые системы могут выполнять JavaScript, но возможности и сроки обработки различаются. HTML с основным содержимым уменьшает зависимость от выполнения клиентского кода; сам по себе SSR не гарантирует индексацию.

Медленные серверные ответы могут ограничивать обход большого сайта, но универсальной формулы «в два раза быстрее — в два раза больше проиндексированных страниц» нет. Уход посетителя также нельзя автоматически объявлять прямой причиной понижения позиции.

## Мини-шпаргалка

- Скорость помогает читать и использовать страницу.
- Core Web Vitals учитываются Google вместе с другими сигналами.
- Содержимое и доступность для обхода остаются необходимыми.
- Измеряй эффект оптимизации, не обещай позиции по одной метрике.
