# Что такое waterfall fetching?

> [!NOTE]
> Waterfall fetching — последовательная загрузка данных, при которой следующий запрос начинается после завершения предыдущего. Если запросы независимы, такое ожидание зря увеличивает время загрузки.

## Вопрос

Как заметить водопад запросов и когда использовать `Promise.all`?

## Основная идея

Представь страницу, которой нужны статья и список пользователей. Если второй запрос не использует результат первого, можно запустить их одновременно.

```text
Последовательно:
статья       [──── 300 мс ────]
пользователи                  [──── 400 мс ────]
ожидание ≈ 700 мс

Параллельно:
статья       [──── 300 мс ────]
пользователи [────── 400 мс ──────]
ожидание ≈ 400 мс
```

Числа условные: время зависит от сети, серверов и ограничений соединений. Идея в том, что для независимых операций можно ждать примерно самую долгую из них вместо суммы.

## Пример: два независимых запроса

Пример для Server Component App Router без включённого `cacheComponents`. JSONPlaceholder — внешний учебный API.

```tsx
// app/page.tsx
async function loadJson<T>(url: string): Promise<T> {
  const response = await fetch(url, { cache: "no-store" });
  if (!response.ok) throw new Error(`Ошибка HTTP: ${response.status}`);
  return response.json();
}

type Post = { id: number; title: string };
type User = { id: number; name: string };

export default async function Page() {
  const [post, users] = await Promise.all([
    loadJson<Post>("https://jsonplaceholder.typicode.com/posts/1"),
    loadJson<User[]>("https://jsonplaceholder.typicode.com/users"),
  ]);

  return (
    <main>
      <h1>{post.title}</h1>
      <p>Пользователей: {users.length}</p>
    </main>
  );
}
```

Оба вызова `loadJson` начинают работу при вычислении массива. `Promise.all` ожидает их результаты. Если сначала написать `await loadJson(...)`, а потом второй `await`, получится последовательная загрузка. Тип `T` помогает редактору, но не проверяет формат внешнего JSON во время выполнения.

## Что важно помнить

Зависимые запросы нельзя просто объединить. Если сначала надо получить пользователя по сессии, а затем его заказы по `user.id`, второй запрос действительно должен ждать. Проверка прав также должна происходить до защищённой операции.

`Promise.all` отклоняется при ошибке любой операции и не отменяет остальные запросы автоматически. Если блоки страницы независимы и один может показываться раньше другого, раздели их границами Suspense. Сам Suspense не превращает уже последовательный код в параллельный.

Водопад бывает и на сервере, и в браузере. Для браузерных запросов используй DevTools Network: ищи запросы, которые стартуют только после ответа предыдущего. Запросы из Server Components выполняет сервер Next.js, поэтому отдельными запросами браузера они там не появятся. Их последовательность проверяют по серверным журналам или трассировке.

## Мини-шпаргалка

- Независимые запросы запускай до общего `await`.
- Зависимые операции оставляй последовательными.
- `Promise.all` ждёт группу; Suspense помогает показывать готовые части.
- Проверяй фактическое время начала запросов.
