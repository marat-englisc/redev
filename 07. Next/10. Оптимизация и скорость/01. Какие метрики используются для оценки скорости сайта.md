# Какие метрики используются для оценки скорости сайта?

> [!NOTE]
> Скорость сайта — это несколько характеристик: как быстро появляется содержимое, как быстро интерфейс отвечает на действия и насколько устойчиво расположение элементов. Одно число не описывает все эти свойства.

## Вопрос

Какие метрики помогают оценить скорость страницы и как понять, что именно тормозит?

## Основная идея

Представь страницу товара. Шапка появилась быстро, фотография загрузилась поздно, а кнопка покупки реагирует с задержкой. У этой страницы разные проблемы, поэтому измерять только время загрузки HTML недостаточно.

| Метрика | Что показывает | Пример проблемы |
| --- | --- | --- |
| TTFB — Time to First Byte | Время от начала запроса до первого байта ответа, включая сеть и ожидание сервера | Медленный запрос к базе задерживает ответ |
| FCP — First Contentful Paint | Когда впервые появился текст, изображение или другое содержимое | Пользователь долго видит пустой экран |
| LCP — Largest Contentful Paint | Когда появился самый крупный подходящий элемент в области просмотра | Большая фотография товара загружается последней |
| INP — Interaction to Next Paint | Задержки взаимодействий: от ввода до следующего отображения результата | После нажатия кнопка долго не меняет вид |
| CLS — Cumulative Layout Shift | Оценку неожиданных смещений элементов | Изображение раздвигает текст и сдвигает кнопку |

LCP, INP и CLS образуют **Core Web Vitals**. Для них существуют общие ориентиры; остальные показатели помогают искать причины проблем.

## Пример: читаем отчёт

Допустим, после проверки страницы получили такие учебные результаты:

```text
TTFB: 0,3 с
FCP:  0,8 с
LCP:  4,2 с
INP:  120 мс
CLS:  0,03
```

Первый ответ и первое содержимое приходят относительно быстро. Основная проблема — позднее появление крупного элемента. Открой вкладку Performance в DevTools, найди LCP-элемент и посмотри его запрос в Network. Если это фотография, проверь её размер, момент начала загрузки и формат. Переписывание обработчика кнопки эту проблему не решит.

## Как измерять

Для локальной проверки Next.js используй production-сборку, а не скорость сервера разработки:

```bash
npm run build
npm run start
```

Команды предполагают стандартные scripts проекта Next.js. Открой страницу и запусти Lighthouse. Это лабораторный замер в заданных условиях. Сравнивай результаты при одинаковой сети и устройстве, а для оценки реальных посетителей используй полевые данные, например PageSpeed Insights и свою аналитику.

## Что важно помнить

Зелёный Lighthouse не гарантирует такой же опыт на каждом телефоне. Смотри несколько запусков, страницы с реальными данными и переходы внутри приложения. TTI встречается в старых материалах, но не входит в современные Core Web Vitals.

## Мини-шпаргалка

- TTFB — начало ответа, FCP — первое содержимое, LCP — крупный элемент.
- INP — отзывчивость, CLS — смещения.
- Сначала измерь проблему, затем выбирай оптимизацию.
- Проверяй production-режим и реальные устройства.
