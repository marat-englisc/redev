# Почему Client Components могут быть дороже?

> [!NOTE]
> Client Components добавляют работу браузеру: их JavaScript и зависимости нужно загрузить, выполнить и использовать для гидратации. Это оправданно для интерактивности, но обычно не требуется всему содержимому страницы.

## Вопрос

В чём стоимость клиентских компонентов и где лучше проводить границу `use client`?

## Основная идея

В App Router компоненты по умолчанию серверные. Директива `use client` обозначает точку входа в клиентский граф модулей: её импорты тоже должны быть пригодны для браузера.

При первом открытии Next.js может подготовить HTML клиентского компонента на сервере. Затем браузер скачивает его код и выполняет **гидратацию** — подключает React к уже показанному интерфейсу, чтобы заработали состояние и обработчики.

Стоимость складывается из передачи кода, работы процессора и последующих обновлений. Маленькая кнопка не обязательно создаёт проблему; большие зависимости и частые тяжёлые вычисления важнее самого числа компонентов.

## Пример: интерактивность только там, где нужна

Статическое описание товара оставим на сервере:

```tsx
// app/page.tsx
import Quantity from "./quantity";

export default function Page() {
  return (
    <main>
      <h1>Учебник JavaScript</h1>
      <p>Бумажная книга с упражнениями для начинающих.</p>
      <Quantity />
    </main>
  );
}
```

Клиентским сделаем только управление количеством:

```tsx
// app/quantity.tsx
"use client";

import { useState } from "react";

export default function Quantity() {
  const [quantity, setQuantity] = useState(1);

  return (
    <div>
      <p aria-live="polite">Количество: {quantity}</p>
      <button onClick={() => setQuantity(value => value + 1)}>
        Добавить ещё одну
      </button>
    </div>
  );
}
```

Посетитель видит описание и начальное количество в HTML. После гидратации кнопка обновляет состояние. Код серверного описания не нужно выполнять в браузере.

## Что важно помнить

Не добавляй `use client` в общий layout только ради одной кнопки. Выдели интерактивный участок и импортируй его из серверного компонента. При этом серверное содержимое можно передавать клиентской оболочке через `children`; оно не превращается автоматически в клиентский модуль.

Клиентскому компоненту необязательно самостоятельно запрашивать данные: серверный родитель может передать разрешённые React значения через props. Секретные токены туда передавать нельзя, поскольку props доступны клиенту.

Серверный рендеринг тоже стоит ресурсов. Для выбора архитектуры сравнивай нагрузку на сервер, размер ответа и скорость устройства пользователя.

## Мини-шпаргалка

- Client Components нужны состоянию, событиям и браузерным API.
- Их начальный HTML может прийти с сервера.
- Размещай клиентскую границу вокруг нужной интерактивности.
- Смотри размер зависимостей и работу браузера.
