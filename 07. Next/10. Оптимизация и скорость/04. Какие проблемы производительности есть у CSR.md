# Какие проблемы производительности есть у CSR?

> [!NOTE]
> CSR, Client-Side Rendering, — построение интерфейса в браузере с помощью JavaScript. Если основное содержимое появляется только после загрузки кода и данных, первый показ зависит от сети и мощности устройства посетителя.

## Вопрос

Почему страница с клиентским рендерингом иногда долго загружается или медленно отвечает на действия?

## Основная идея

При полностью клиентском первом рендеринге браузеру нужно получить HTML-оболочку, скачать JavaScript, выполнить его, запросить данные и построить интерфейс. Каждый следующий шаг может ждать предыдущего.

| Причина | Что замечает пользователь | Что проверить |
| --- | --- | --- |
| Большой объём JavaScript | Долгое ожидание первого содержимого | Передачу файлов в Network |
| Тяжёлые вычисления | Задержки после нажатий | Длинные задачи в Performance |
| Запрос данных только после монтирования | Сначала загрузчик, потом содержимое | Время начала запроса к API |
| Тысячи элементов списка | Медленную прокрутку и обновления | Число DOM-узлов и длительность рендеринга |

## Пример: скрытая задержка запроса

В этом учебном Client Component данные загружаются после монтирования:

```tsx
// app/posts/post-count.tsx
"use client";

import { useEffect, useState } from "react";

type Post = { id: number; title: string };

export default function PostCount() {
  const [count, setCount] = useState<number | null>(null);
  const [error, setError] = useState(false);

  useEffect(() => {
    const controller = new AbortController();

    async function load() {
      try {
        const response = await fetch("https://jsonplaceholder.typicode.com/posts", {
          signal: controller.signal,
        });
        if (!response.ok) throw new Error("Не удалось загрузить записи");
        const posts: Post[] = await response.json();
        setCount(posts.length);
      } catch {
        if (!controller.signal.aborted) setError(true);
      }
    }

    void load();
    return () => controller.abort();
  }, []);

  if (error) return <p role="alert">Ошибка загрузки</p>;
  return <p>{count === null ? "Загрузка…" : `Записей: ${count}`}</p>;
}
```

JSONPlaceholder — внешний учебный API. Запрос начнётся после запуска JavaScript и монтирования компонента; сначала посетитель увидит «Загрузка…». Отмена запроса в cleanup предотвращает обновление по результату уже ненужной загрузки.

## Что важно помнить

Этот пример показывает клиентскую загрузку, но директива `use client` сама по себе не отключает серверный HTML в Next.js. Здесь именно эффект откладывает получение записей до браузера.

Для публичной статьи данные часто удобнее получить в Server Component. Для персонального кабинета клиентская загрузка может быть уместна. Разделение кода, кэш клиентской библиотеки и виртуализация больших списков также помогают; перенос на сервер не является обязательным решением любой задержки.

## Мини-шпаргалка

- Ищи цепочку «код → запрос → содержимое».
- Проверяй сеть и занятость основного потока отдельно.
- Client Component и полностью клиентский первый рендеринг — разные понятия.
- Выбирай место загрузки по задаче страницы.
