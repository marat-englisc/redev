# await fetch прямо в Server Component

> [!NOTE]
> В асинхронном Server Component можно написать `await fetch(...)` прямо в теле функции, проверить ответ и построить интерфейс из данных. Промежуточный клиентский запрос для этого не нужен.

## Вопрос

Когда запрос можно выполнить прямо в компоненте, как сделать это правильно и почему такой подход не подходит обычному Client Component?

## Как это работает

`fetch` возвращает Promise — обещание будущего результата. `await` позволяет дождаться его. Затем `response.json()` читает тело ответа как JSON; это тоже асинхронная операция.

В App Router серверный компонент может быть `async`. Next.js дождется его результата или отправит доступные части страницы постепенно, если настроены границы ожидания.

Client Component не объявляют асинхронной функцией для такой загрузки. Браузерные запросы запускают в обработчике события, эффекте или библиотеке загрузки данных. Клиент также может читать переданный с сервера Promise через React `use` — это отдельный прием.

В серверном коде запрос к внешнему API использует полный адрес `https://...`. Относительный адрес `/api/posts` не определяет автоматически домен приложения, как в браузере. Если данные принадлежат собственной базе, проще вызвать серверную функцию доступа к данным напрямую, без собственного HTTP API.

## Пример: список записей

Next.js 16 без `cacheComponents`. JSONPlaceholder — открытый учебный API.

```tsx
// app/posts/page.tsx
export default async function PostsPage() {
  const response = await fetch(
    "https://jsonplaceholder.typicode.com/posts?_limit=3",
    { cache: "no-store" }
  );

  if (!response.ok) {
    throw new Error(`Ошибка загрузки: HTTP ${response.status}`);
  }

  const posts: { id: number; title: string }[] = await response.json();

  return (
    <ul>
      {posts.map(post => <li key={post.id}>{post.title}</li>)}
    </ul>
  );
}
```

Сначала загружается ответ, затем читается JSON, после чего создается список. `no-store` явно не сохраняет ответ в постоянном Data Cache, и маршрут с таким запросом обрабатывается динамически. Ошибка попадет в ближайшую границу обработки ошибок, например `error.tsx`.

## Что важно помнить

- `fetch` не бросает исключение на HTTP 404 и 500 — проверяй `response.ok`. Сетевая ошибка или некорректный JSON тоже завершают загрузку исключением.
- Запрос не становится быстрым из-за расположения в компоненте. Для ожидания добавляют `loading.tsx` или `Suspense`.
- Независимые запросы запускай параллельно через `Promise.all`, чтобы не создавать водопад.
- TypeScript-аннотация описывает ожидаемый ответ, но не проверяет его во время выполнения. Для недоверенного API нужна runtime-валидация.
- `no-store` отключает постоянное кэширование этого запроса, но не все кэши приложения.

## Мини-шпаргалка

- `async` Server Component + `await fetch` — нормальный способ загрузки.
- Полный URL на сервере; свою БД — напрямую, без своего API.
- Проверяй `response.ok`.
- Client Component — не `async`: обработчик, эффект, библиотека или `use`.
