# Revalidation: как работает revalidate и обновление по событию

> [!NOTE]
> **Revalidation**, или ревалидация, — обновление сохраненных данных либо результата маршрута по времени или после события. `revalidate` задает интервал в секундах, а `revalidatePath`, `revalidateTag` и `updateTag` помечают данные устаревшими после изменений.

## Вопрос

Что означает `revalidate: 60`, почему данные не обязательно обновятся ровно через минуту и как сообщить Next.js об изменениях вручную?

## Основная идея

Примеры относятся к Next.js 16 App Router **без `cacheComponents`**. Для серверного `fetch` настройка называется `next.revalidate`.

| Значение | Поведение |
| --- | --- |
| Положительное число | Сохранение с интервалом ревалидации |
| `0` | Не сохранять ответ в постоянном Data Cache |
| `false` | Сохранение без заданного временного интервала |

Интервал определяет, когда данные могут считаться устаревшими. Он не создает фоновый таймер, который постоянно обращается к API. После истечения интервала следующий запрос может получить старую копию, пока Next.js обновляет ее в фоне. Если страницу открыли только через час, обновление не обязано было выполняться все предыдущие 55 минут.

В App Router также существует `export const revalidate = 300` для страницы или layout. Это настройка сегмента маршрута, а не полная замена индивидуальных параметров `fetch`. В статическом маршруте более короткий интервал может влиять на частоту обновления всего результата.

## Обновление по событию

| Инструмент | Назначение |
| --- | --- |
| `revalidatePath("/catalog")` | Инвалидация данных и результата указанного маршрута |
| `revalidateTag("catalog", "max")` | Пометить данные с тегом устаревшими; обновить при следующем обращении в фоне |
| `updateTag("catalog")` | Немедленно сделать данные с тегом просроченными; доступно в Server Actions |

Выбирай тег, если одни данные используются на нескольких страницах, и путь, если обновление связано с конкретным маршрутом.

## Пример: интервал и тег

JSONPlaceholder — открытый учебный API.

```tsx
// app/catalog/page.tsx
export default async function Page() {
  const response = await fetch(
    "https://jsonplaceholder.typicode.com/posts/1",
    { next: { revalidate: 300, tags: ["catalog"] } }
  );
  if (!response.ok) throw new Error("Каталог недоступен");

  const post: { title: string } = await response.json();
  return <h1>{post.title}</h1>;
}
```

Тег сам по себе не включает хранение: здесь кэширование задано положительным `revalidate`. После успешного сохранения настоящего товара серверный код может вызвать `revalidateTag("catalog", "max")`.

## Что важно помнить

- Не сочетай `cache: "no-store"` с положительным `next.revalidate`: инструкции противоречат друг другу.
- `false` не означает, что запись гарантированно проживет в кэше вечно.
- Инвалидация не изменяет базу данных: сначала выполни мутацию, затем обнови кэш. Перед изменением проверь сессию, права и входные данные.
- Однопараметрический `revalidateTag(tag)` устарел. `updateTag` нужен, когда после действия пользователь должен сразу прочитать свежие данные.
- При `cacheComponents: true` сроки задают через `cacheLife` — это другая модель.

## Мини-шпаргалка

- `next.revalidate` — интервал в секундах, не таймер.
- Первый запрос после интервала может получить старую версию.
- По событию: `revalidatePath`, `revalidateTag(tag, "max")`, `updateTag`.
- Сначала мутация, потом инвалидация.
