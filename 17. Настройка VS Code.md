# Настройка VS Code для React и Next.js

> [!NOTE]
> Не нужно устанавливать все расширения подряд. Основной набор подходит почти любому React- или Next.js-проекту, а инструменты для Stylelint, Vitest, Jest, Playwright и Prisma нужны только тогда, когда соответствующая технология используется в проекте.

## Основные расширения

VS Code из коробки понимает JSX и TSX: подсказки, переход к определению, рефакторинги и переименование парных тегов (`editor.linkedEditing`) работают через встроенный TypeScript без отдельного расширения для React. Поэтому основной набор — это инструменты качества кода.

1. [ESLint](https://marketplace.visualstudio.com/items?itemName=dbaeumer.vscode-eslint) (`dbaeumer.vscode-eslint`) — показывает ошибки ESLint, включая нарушения правил хуков, и применяет безопасные автоисправления.
2. [Prettier](https://marketplace.visualstudio.com/items?itemName=esbenp.prettier-vscode) (`esbenp.prettier-vscode`) — единое форматирование JavaScript, TypeScript, JSX/TSX, CSS, JSON и Markdown.
3. [EditorConfig](https://marketplace.visualstudio.com/items?itemName=editorconfig.editorconfig) (`editorconfig.editorconfig`) — синхронизирует отступы, окончания строк и другие базовые правила между разными редакторами.
4. [Tailwind CSS IntelliSense](https://marketplace.visualstudio.com/items?itemName=bradlc.vscode-tailwindcss) (`bradlc.vscode-tailwindcss`) — автодополнение классов, превью CSS при наведении и диагностика конфликтующих классов. Tailwind CSS предлагается по умолчанию в `create-next-app`, поэтому для Next.js-проектов это расширение почти обязательно.

Расширения ESLint и Prettier не заменяют зависимости проекта. Для воспроизводимого результата установи `eslint` и `prettier` в `devDependencies` и храни их конфигурацию в репозитории. Если ESLint содержит стилистические правила, используй `eslint-config-prettier`, чтобы линтер и форматтер не спорили друг с другом.

В Next.js-проекте ESLint настраивается через `eslint-config-next`: он уже включает правила React, `eslint-plugin-react-hooks` (`rules-of-hooks`, `exhaustive-deps`) и `@next/eslint-plugin-next`. Для Tailwind CSS добавь `prettier-plugin-tailwindcss` — он сортирует классы в рекомендуемом порядке.

## Рекомендуемый `settings.json`

Открыть файл можно через палитру команд: `Preferences: Open User Settings (JSON)`. Пример ниже является полноценным JSON-объектом и подходит как отправная точка:

```json
{
  "editor.fontSize": 14,
  "editor.fontFamily": "JetBrains Mono, Consolas, 'Courier New', monospace",
  "editor.fontLigatures": true,
  "editor.inlayHints.fontFamily": "JetBrains Mono",
  "editor.codeLensFontFamily": "JetBrains Mono",
  "editor.quickSuggestionsDelay": 0,
  "editor.wordWrap": "bounded",
  "editor.wordWrapColumn": 100,
  "editor.rulers": [100],
  "editor.insertSpaces": true,
  "editor.tabSize": 2,
  "editor.detectIndentation": true,
  "editor.folding": true,
  "editor.stickyScroll.enabled": true,
  "editor.smoothScrolling": true,
  "editor.cursorBlinking": "expand",
  "editor.cursorSmoothCaretAnimation": "explicit",
  "editor.overtypeCursorStyle": "line-thin",
  "editor.minimap.enabled": false,
  "editor.glyphMargin": true,
  "editor.linkedEditing": true,
  "editor.colorDecorators": true,
  "editor.semanticHighlighting.enabled": true,
  "editor.bracketPairColorization.enabled": true,
  "editor.guides.bracketPairs": "active",
  "editor.defaultFormatter": "esbenp.prettier-vscode",
  "editor.formatOnSave": true,
  "editor.codeActionsOnSave": {
    "source.fixAll.eslint": "explicit"
  },
  "files.eol": "\n",
  "files.insertFinalNewline": true,
  "files.trimTrailingWhitespace": true,
  "files.associations": {
    "*.css": "tailwindcss"
  },
  "typescript.updateImportsOnFileMove.enabled": "always",
  "javascript.updateImportsOnFileMove.enabled": "always",
  "typescript.preferences.importModuleSpecifier": "non-relative",
  "typescript.inlayHints.parameterNames.enabled": "literals",
  "javascript.inlayHints.parameterNames.enabled": "literals",
  "emmet.includeLanguages": {
    "javascriptreact": "html",
    "typescriptreact": "html"
  },
  "tailwindCSS.classFunctions": ["cn", "cva", "clsx"],
  "prettier.useEditorConfig": true,
  "debug.javascript.autoAttachFilter": "smart",
  "editor.unicodeHighlight.ambiguousCharacters": true,
  "editor.unicodeHighlight.invisibleCharacters": true,
  "editor.unicodeHighlight.allowedLocales": {
    "ru": true
  },
  "explorer.compactFolders": false,
  "explorer.fileNesting.enabled": true,
  "explorer.fileNesting.patterns": {
    "package.json": "package-lock.json, pnpm-lock.yaml, yarn.lock, bun.lockb, .npmrc",
    "tsconfig.json": "tsconfig.*.json, next-env.d.ts",
    ".env": ".env.*"
  },
  "scm.diffDecorations": "gutter",
  "git.autofetch": true,
  "telemetry.telemetryLevel": "off",
  "terminal.integrated.fontFamily": "JetBrains Mono",
  "terminal.integrated.fontLigatures.enabled": true,
  "terminal.integrated.fontSize": 13,
  "terminal.integrated.cursorBlinking": true,
  "terminal.integrated.cursorStyle": "line",
  "[markdown]": {
    "editor.defaultFormatter": "esbenp.prettier-vscode",
    "editor.wordWrap": "on",
    "files.trimTrailingWhitespace": false
  }
}
```

Пояснения к настройкам:

- ESLint исправляет только собственные ошибки через `source.fixAll.eslint`, не запуская все доступные исправления без разбора. Отдельный список `eslint.validate` не нужен: расширение по умолчанию проверяет `.js`, `.jsx`, `.ts` и `.tsx`.
- `editor.glyphMargin` включён, чтобы были видны точки останова, статусы тестов и другие служебные значки.
- `editor.linkedEditing` синхронно переименовывает открывающий и закрывающий тег — в JSX это работает через встроенный TypeScript.
- При переименовании или перемещении файла VS Code автоматически обновляет импорты, а `importModuleSpecifier: non-relative` заставляет автоимпорт использовать алиас `@/…` из `tsconfig.json` (в Next.js он настроен по умолчанию) вместо цепочек `../../..`.
- Emmet включён для JSX/TSX: `div.card>h3+p` разворачивается в разметку с `className`.
- `files.associations` для `*.css` нужен Tailwind CSS 4: редактор перестаёт ругаться на `@theme`, `@apply` и другие директивы. `tailwindCSS.classFunctions` включает подсказки классов внутри `cn()`, `cva()` и `clsx()` — так устроены компоненты shadcn/ui.
- `explorer.fileNesting` сворачивает lock-файлы, `next-env.d.ts` и `.env.*` под основные файлы, чтобы корень Next.js-проекта не был перегружен.
- Включена подсветка невидимых и неоднозначных Unicode-символов. Русская локаль разрешена отдельно, чтобы кириллица в документации не создавала лишний шум.
- Для фронтенд-проектов выбраны два пробела. Если в команде принят другой стиль, `.editorconfig` и настройки проекта должны иметь приоритет.

### Дополнительные настройки интерфейса

Эти параметры не влияют на качество кода и зависят только от личных предпочтений:

```json
{
  "window.density.editorTabHeight": "compact",
  "workbench.activityBar.location": "bottom",
  "workbench.layoutControl.enabled": false,
  "workbench.editor.empty.hint": "hidden",
  "workbench.editor.editorActionsLocation": "titleBar",
  "workbench.editor.customLabels.patterns": {
    "**/app/**/page.tsx": "${dirname} — page",
    "**/app/**/layout.tsx": "${dirname} — layout"
  },
  "workbench.tree.renderIndentGuides": "none",
  "workbench.tree.indent": 18,
  "terminal.integrated.tabs.enabled": false,
  "editor.scrollbar.horizontal": "auto",
```

`workbench.editor.customLabels.patterns` особенно полезен в App Router: вместо десятка одинаковых вкладок `page.tsx` редактор показывает имя папки маршрута, например `dashboard — page`.

## Настройки проекта

Личные параметры темы, шрифта и интерфейса лучше хранить в пользовательском `settings.json`. Общие для команды настройки форматирования и линтинга — в `.vscode/settings.json`, `.editorconfig` и конфигурациях инструментов внутри репозитория.

### Рекомендуемые расширения рабочей области

Файл `.vscode/extensions.json` позволяет VS Code предложить нужные расширения всем участникам проекта:

```json
{
  "recommendations": [
    "dbaeumer.vscode-eslint",
    "esbenp.prettier-vscode",
    "editorconfig.editorconfig",
    "bradlc.vscode-tailwindcss",
    "DavidAnson.vscode-markdownlint",
    "yzhang.markdown-all-in-one",
    "streetsidesoftware.code-spell-checker",
    "streetsidesoftware.code-spell-checker-russian"
  ]
}
```

### Версия TypeScript из проекта и плагин Next.js

Если TypeScript установлен в `devDependencies`, открой файл `.ts` или `.tsx`, выполни команду `TypeScript: Select TypeScript Version` и выбери `Use Workspace Version`. Так редактор и сборка будут использовать одну версию TypeScript.

Для Next.js это особенно важно: `create-next-app` добавляет в `tsconfig.json` плагин `{ "name": "next" }`, а он работает только с версией TypeScript из проекта. Плагин подсказывает допустимые значения `dynamic`, `revalidate` и других опций сегмента маршрута, проверяет директиву `'use client'` и предупреждает об использовании клиентских хуков в серверных компонентах. Чтобы VS Code сам предлагал нужную версию, добавь в `.vscode/settings.json`:

```json
{
  "typescript.tsdk": "node_modules/typescript/lib",
  "typescript.enablePromptUseWorkspaceTsdk": true
}
```

### Отладка Next.js

Файл `.vscode/launch.json` позволяет ставить точки останова прямо в VS Code — и в серверном коде (Server Components, Route Handlers, Server Actions), и в клиентских компонентах:

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Next.js: debug server-side",
      "type": "node-terminal",
      "request": "launch",
      "command": "npm run dev"
    },
    {
      "name": "Next.js: debug client-side",
      "type": "chrome",
      "request": "launch",
      "url": "http://localhost:3000"
    }
  ]
}
```

Сначала запусти конфигурацию `debug server-side`, затем `debug client-side`. Для изучения дерева компонентов, props, хуков и причин ререндеров дополнительно установи в браузер расширение React Developer Tools — его вкладка Profiler нужна для разбора производительности.

### Профиль и синхронизация

- Создай профиль `React` через `File → Preferences → Profiles`, чтобы расширения для веб-разработки не смешивались с другими наборами инструментов.
- Включи `Settings Sync`, если нужно переносить настройки, сочетания клавиш и расширения между компьютерами.
- При конфликтах расширений запусти `Help: Start Extension Bisect`: VS Code будет отключать их группами и поможет найти проблемное.

## Ошибка запуска скриптов PowerShell

Если Windows сообщает, что `npm.ps1` не может быть загружен из-за политики выполнения, сначала проверь действующие значения:

```powershell
Get-ExecutionPolicy -List
```

Затем разреши локальные скрипты только для текущего пользователя — права администратора для этого не нужны:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

## Полезные команды и сочетания клавиш

| Действие | Windows / Linux | macOS |
| --- | --- | --- |
| Палитра команд | `Ctrl + Shift + P` | `Cmd + Shift + P` |
| Быстро открыть файл | `Ctrl + P` | `Cmd + P` |
| Перейти к определению | `F12` | `F12` |
| Найти все использования | `Shift + F12` | `Shift + F12` |
| Переименовать символ во всём проекте | `F2` | `F2` |
| Быстрое исправление и рефакторинг | `Ctrl + .` | `Cmd + .` |
| Форматировать документ | `Shift + Alt + F` | `Shift + Option + F` |
| Открыть терминал | <kbd>Ctrl</kbd> + <kbd>`</kbd> | <kbd>Ctrl</kbd> + <kbd>`</kbd> |

Через «Быстрое исправление» удобно выносить JSX в отдельный компонент или функцию (`Extract to function in module scope`) и добавлять недостающие импорты.

Если подсказки TypeScript перестали обновляться (например, после `npm install` или изменения `tsconfig.json`), обычно помогают команды `TypeScript: Restart TS Server`, `ESLint: Restart ESLint Server` или `Developer: Reload Window`. Типы маршрутов Next.js генерируются в папку `.next/types` при запуске `next dev` или `next build` — если подсказки по `params` и ссылкам устарели, перезапусти dev-сервер.
