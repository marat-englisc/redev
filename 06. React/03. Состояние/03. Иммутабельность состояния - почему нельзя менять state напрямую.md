# Иммутабельность состояния: почему нельзя менять state напрямую

> [!NOTE]
> Состояние в React нужно обновлять **иммутабельно**: создавать новый объект или массив и передавать его в сеттер, а не менять существующий. React сравнивает старое и новое значение через `Object.is`: если ссылка та же, он считает, что ничего не изменилось, и может не перерендерить компонент. Мутация также ломает `memo`, `useMemo`, `useEffect`, DevTools и concurrent-рендер.

## Вопрос

Почему нельзя изменять состояние напрямую? Что такое иммутабельность состояния и зачем при обновлении создавать новый объект?

## Основная идея

```jsx
const [user, setUser] = useState({ name: "Анна", age: 25 });

// неправильно: мутация
user.age = 26;
setUser(user);          // та же ссылка → React может пропустить ререндер

// правильно: новый объект
setUser({ ...user, age: 26 });
```

Почему это важно:

- **обнаружение изменений** — React, `memo` и зависимости хуков сравнивают по ссылке; мутация невидима для них;
- **снимки рендеров** — каждый рендер видит «свою» версию state; мутация меняет прошлые снимки задним числом;
- **concurrent rendering** — React может рендерить несколько версий параллельно и отбрасывать их; общий мутируемый объект ломает эту модель;
- **отладка** — DevTools и time-travel в Redux показывают историю только при иммутабельных обновлениях.

## Объекты

```jsx
setUser((prev) => ({ ...prev, name: "Мария" }));

// вложенные объекты — копировать каждый уровень пути
setUser((prev) => ({
  ...prev,
  address: { ...prev.address, city: "Казань" },
}));
```

## Массивы

| Действие | Мутация (нельзя) | Иммутабельно |
| --- | --- | --- |
| Добавить | `push`, `unshift` | `[...arr, item]`, `[item, ...arr]` |
| Удалить | `splice`, `pop` | `filter`, `toSpliced` |
| Заменить | `arr[i] = x` | `map`, `with(i, x)` |
| Сортировать | `sort`, `reverse` | `toSorted`, `toReversed` |

```jsx
setTodos((prev) => prev.map((t) => (t.id === id ? { ...t, done: !t.done } : t)));
setTodos((prev) => prev.filter((t) => t.id !== id));
```

## Immer

Глубокие обновления удобнее с Immer: пишете «мутирующий» код, получаете новый объект.

```jsx
import { useImmer } from "use-immer";

const [state, updateState] = useImmer({ user: { address: { city: "Москва" } } });
updateState((draft) => {
  draft.user.address.city = "Казань";
});
```

## Что важно помнить

- `const` не делает объект неизменяемым — мутировать его всё равно можно.
- Копия через spread поверхностная: вложенные объекты нужно копировать отдельно.
- Глубоко вложенный state — признак, что его стоит нормализовать (плоские структуры по id).
- Мутация локального объекта, созданного в этом же обработчике, до передачи в сеттер допустима.

## Мини-шпаргалка

State обновляем новым объектом или массивом. Мутация → та же ссылка → React не видит изменений. Объекты — spread, массивы — `map`/`filter`/`toSorted`. Глубоко — Immer.
