# Чем state отличается от props

> [!NOTE]
> **Props** компонент получает извне, а **state** хранит у себя. Оба используются как неизменяемые снимки данных текущего рендера.

## Вопрос

Кто владеет props и state и может ли одно значение быть и тем и другим?

## Объяснение

Если страница хранит выбранную тему в `useState`, для страницы это state. Когда она передает тему в `<TopicCard topic={topic} />`, для карточки то же значение становится prop.

Разница определяется владельцем, а не типом данных. И state, и props могут быть числами, объектами или строками. Ребенок не должен изменять полученные props. Владелец state обновляет его через setter или dispatch.

Если ребенок должен запросить изменение, родитель передает callback. Так сохраняется понятный поток: данные вниз, сообщения о действиях к владельцу.

## Пример: общий счетчик

```jsx
import { useState } from "react";

function CounterView({ count, onIncrement }) {
  return (
    <button onClick={onIncrement}>
      Решено задач: {count}
    </button>
  );
}

export default function PracticePage() {
  const [solved, setSolved] = useState(0);

  return (
    <>
      <CounterView
        count={solved}
        onIncrement={() => setSolved(n => n + 1)}
      />
      <p>До цели осталось: {Math.max(10 - solved, 0)}</p>
    </>
  );
}
```

Для `PracticePage` значение `solved` - состояние. Для `CounterView` значение `count` - prop. Карточка вызывает callback, но решение об обновлении принадлежит родителю.

## Сравнение

| Характеристика | Props | State |
| --- | --- | --- |
| Источник | Родитель или окружение | Сам компонент-владелец |
| Способ обновления | Получить новые входные данные | Setter или dispatch |
| Прямое изменение | Запрещено контрактом React | Запрещено контрактом React |
| Назначение | Настройка и передача данных | Память между рендерами |

## Частая ошибка

Копировать каждый prop в `useState`. Инициализация не синхронизирует копию с будущими props. Если нужен именно управляемый родителем интерфейс, читай prop напрямую. Если нужен отдельный черновик, задай правила его сброса и сохранения.

## Что важно помнить

- Props приходят от родителя и доступны только для чтения; state принадлежит компоненту и меняется через сеттер.
- Изменение и props, и state вызывает ререндер.
- Не копируйте props в state без необходимости — получите рассинхронизацию.
- Одно и то же значение может быть state родителя и props ребенка.

## Мини-шпаргалка

- State принадлежит владельцу.
- Props - входы потребителя.
- Один смысловой факт не стоит дублировать без причины.
- Callback позволяет ребенку запросить обновление у родителя.
