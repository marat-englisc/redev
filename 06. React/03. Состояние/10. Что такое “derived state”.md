# Что такое derived state

> [!NOTE]
> **Derived state** - данные, полученные из props или другого state. Если их можно вычислить при рендере, отдельное хранимое состояние обычно не нужно.

## Вопрос

Почему хранение вычисляемой копии вызывает рассинхронизацию и когда отдельное значение все же оправдано?

## Основная идея

Если в state лежит массив товаров, количество можно получить через `items.length`. Хранить еще и отдельный `count` означает поддерживать два значения согласованно при каждой операции.

Особенно опасна инициализация `useState(items.length)`: она сработает при создании состояния, но не будет следовать за будущими изменениями `items`.

Вычисляемое значение само по себе полезно. Избегают прежде всего его **избыточного хранения**, а не любых вычислений из данных.

## Пример: отфильтрованные задачи

```jsx
import { useState } from "react";

const tasks = [
  { id: 1, title: "React", done: true },
  { id: 2, title: "TypeScript", done: false },
];

export default function TaskList() {
  const [onlyDone, setOnlyDone] = useState(false);
  const visible = onlyDone ? tasks.filter(task => task.done) : tasks;

  return (
    <>
      <label>
        <input
          type="checkbox"
          checked={onlyDone}
          onChange={e => setOnlyDone(e.currentTarget.checked)}
        />
        Только завершенные
      </label>
      <p>Показано: {visible.length}</p>
      <ul>{visible.map(task => <li key={task.id}>{task.title}</li>)}</ul>
    </>
  );
}
```

В state хранится выбор пользователя. Отфильтрованный список и его длина вычисляются. Они не могут отстать друг от друга из-за забытого setter.

## Когда пригодится useMemo

Если вычисление действительно дорогое, `useMemo` может сохранить результат до изменения зависимостей. Это кеш вычисления, а не дополнительный источник истины. Простому `items.length` мемоизация не нужна.

## Когда отдельное состояние оправдано

Черновик формы может намеренно отличаться от сохраненных данных. Снимок отправленного заказа должен оставаться прежним, даже если текущая корзина изменилась. Здесь у значения собственный смысл и время жизни.

Для такого состояния нужно ясно определить, когда оно создается, обновляется и сбрасывается.

## Что важно помнить

- Производное значение вычисляйте в рендере, а не храните в отдельном state.
- Синхронизация через `useEffect` дает лишний рендер и риск рассинхронизации.
- Дорогие вычисления мемоизируйте через `useMemo`.
- Сброс state при смене prop делают через `key`, а не через эффект.

## Мини-шпаргалка

- Храни минимальный набор исходных данных.
- Остальное вычисляй.
- Не синхронизируй копии эффектом без реальной необходимости.
- Черновик и исторический снимок могут быть самостоятельным состоянием.
