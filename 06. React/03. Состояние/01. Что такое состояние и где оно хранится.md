# Что такое состояние и где оно хранится

> [!NOTE]
> **Состояние (state)** — данные компонента, которые меняются со временем и влияют на то, что отображается: введенный текст, открыта ли модалка, выбранная вкладка, загруженные данные. При изменении state через сеттер React перерендеривает компонент. Состояние хранится **не в функции компонента**, а внутри React — в fiber-узле этого компонента, — поэтому переживает повторные вызовы функции и сбрасывается при размонтировании.

## Вопрос

Что такое состояние в React? Где хранится состояние компонента и почему обычная переменная не подходит?

## Основная идея

Функция компонента вызывается при каждом рендере заново. Локальные переменные создаются и исчезают вместе с вызовом:

```jsx
function Counter() {
  let count = 0;                      // каждый рендер снова 0
  return <button onClick={() => count++}>{count}</button>; // ререндера нет, значение теряется
}
```

`useState` решает обе проблемы: значение сохраняется между рендерами, а сеттер сообщает React, что нужно перерисовать компонент.

```jsx
function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}
```

## Где хранится состояние

React хранит состояние в своем внутреннем дереве — в fiber-узле, который соответствует компоненту **на конкретной позиции** дерева. Хуки внутри компонента хранятся упорядоченным списком: первый `useState` — первая ячейка, второй — вторая. Отсюда правила хуков: порядок вызовов не должен меняться между рендерами.

Следствия:

- два одинаковых компонента на разных позициях имеют независимое состояние;
- состояние живет, пока компонент смонтирован на той же позиции с тем же типом и `key`;
- при размонтировании (условный рендер, смена `key`) state сбрасывается;
- state приватен: родитель не может прочитать state ребенка — только через подъем состояния.

```jsx
function App() {
  const [showA, setShowA] = useState(true);
  return (
    <>
      <Counter />           {/* свое состояние */}
      <Counter />           {/* свое, независимое */}
      {showA && <Counter />} {/* при скрытии state будет потерян */}
    </>
  );
}
```

## Что хранить в state

| В state | Не в state |
| --- | --- |
| ввод пользователя, флаги UI | значения, которые можно вычислить из props или другого state |
| данные, влияющие на рендер | данные, не влияющие на рендер (таймеры, DOM-узлы) → `useRef` |
| выбранный id | дубли данных из props |

## Что важно помнить

- Состояние — снимок: внутри рендера значение не меняется, новое будет в следующем рендере.
- Для данных с сервера чаще используют TanStack Query или SWR, а не ручной state.
- Глобальное состояние — в контексте или внешнем store, локальное — в компоненте.
- Минимальное состояние = меньше рассинхронизаций.

## Мини-шпаргалка

State = меняющиеся данные, влияющие на UI. `useState` сохраняет значение и запускает ререндер. Хранится в fiber-узле по позиции в дереве. Сбрасывается при размонтировании. Вычисляемое — не в state.
