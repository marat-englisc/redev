# Клиентское и серверное состояние

> [!NOTE]
> **Клиентское состояние** описывает локальное взаимодействие. **Серверное состояние** представляет данные удаленного источника, клиентская копия которых может устаревать.

## Вопрос

Почему данные API отличаются от флага открытия панели и какие задачи добавляет серверное состояние?

## Основная идея

Открыта ли подсказка - решение текущего интерфейса. Список курсов, баланс или права пользователя обычно принадлежат серверу и могут измениться из-за другого пользователя или фоновой операции.

Клиент видит только копию серверных данных на определенный момент. Нужно учитывать загрузку, ошибки, кеш, повторные запросы и конфликты изменений.

Различие определяется владельцем и способом синхронизации, а не только местом хранения. Ответ API после получения тоже находится в памяти браузера, но от этого не становится исключительно локальным UI-state.

## Пример: данные курса и локальные подробности

В примере для самостоятельности API заменен учебной Promise-функцией.

```jsx
import { useEffect, useState } from "react";

function loadCourse() {
  return Promise.resolve({ title: "React", lessons: 12 });
}

export default function Course() {
  const [course, setCourse] = useState(null);
  const [expanded, setExpanded] = useState(false);

  useEffect(() => {
    let ignore = false;
    loadCourse().then(result => {
      if (!ignore) setCourse(result);
    });
    return () => { ignore = true; };
  }, []);

  if (course === null) return <p role="status">Загрузка...</p>;

  return (
    <article>
      <h2>{course.title}</h2>
      <button onClick={() => setExpanded(value => !value)}>Подробности</button>
      {expanded && <p>Уроков: {course.lessons}</p>}
    </article>
  );
}
```

`expanded` - локальное взаимодействие. `course` - клиентская копия данных внешнего источника. Для реального API понадобятся также HTTP-проверка и обработка ошибок.

## Сравнение

| Свойство | Клиентское | Серверное |
| --- | --- | --- |
| Основной владелец | Интерфейс | Сервер или удаленная система |
| Типичные задачи | Ввод, вкладки, раскрытие | Кеш, актуальность, загрузка, мутации |
| Инструменты | useState, useReducer, store | Загрузчик фреймворка, TanStack Query, SWR |
| Сохранность после reload | Требует отдельного решения | Зависит от хранения на сервере |

## Нюансы

Setter клиентского state также не меняет снимок мгновенно. Не стоит описывать разницу как «синхронный state против асинхронного».

Optimistic update временно меняет клиентскую копию до ответа сервера. Успех нужно подтвердить, ошибку - корректно обработать.

## Что важно помнить

- Серверное состояние асинхронно, разделяемо и может устареть без ведома клиента.
- Для серверного состояния нужны кеш, дедупликация, фоновое обновление, инвалидация и повторы — это дают TanStack Query, SWR, RTK Query.
- Не копируйте серверные данные в глобальный клиентский store вручную.
- Клиентское состояние (UI-флаги, ввод) остается в `useState`, контексте или Zustand.

## Мини-шпаргалка

- UI-state принадлежит взаимодействию.
- Server-state требует синхронизации с источником.
- Кеш не гарантирует актуальность.
- Одинаковое место хранения не означает одинаковые требования.
