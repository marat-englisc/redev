# Локальное и глобальное состояние

> [!NOTE]
> **Локальное состояние** ограничено конкретной областью интерфейса. **Общее, или глобальное**, доступно нескольким частям приложения через общего владельца, context или внешний store.

## Вопрос

Как выбрать область хранения state и означает ли глобальность автоматическое сохранение после перезагрузки?

## Основная идея

Флаг раскрытия одной карточки обычно локальный. Тема оформления может требоваться многим независимым блокам и быть общей.

Глобальность описывает область доступа, а не отдельный тип данных. State в провайдере по-прежнему может храниться в useState. Context доставляет значение потомкам, но не создает хранилище автоматически.

Время жизни зависит от владельца. Если провайдер размонтируется, его состояние потеряется. Внешний store может жить дольше отдельной страницы, но без сохранения во внешнее хранилище тоже не обязан переживать перезагрузку.

## Пример: локальная подсказка и общий язык

```jsx
import { createContext, useContext, useState } from "react";

const LanguageContext = createContext("ru");

function Greeting() {
  const language = useContext(LanguageContext);
  const [showHint, setShowHint] = useState(false);

  return (
    <section>
      <h2>{language === "ru" ? "Привет!" : "Hello!"}</h2>
      <button onClick={() => setShowHint(value => !value)}>Подсказка</button>
      {showHint && <p>Начните с простых вопросов.</p>}
    </section>
  );
}

export default function App() {
  const [language, setLanguage] = useState("ru");

  return (
    <LanguageContext.Provider value={language}>
      <button onClick={() => setLanguage(l => l === "ru" ? "en" : "ru")}>
        Сменить язык
      </button>
      <Greeting />
      <Greeting />
    </LanguageContext.Provider>
  );
}
```

Обе карточки читают общий язык. Раскрытие подсказки у каждой свое.

## Критерии выбора

| Вопрос | Что подсказывает |
| --- | --- |
| Кто читает и меняет данные? | Нужную область доступа |
| Как долго они должны жить? | Уровень владельца |
| Нужна ли сохранность после reload? | Отдельную персистентность |
| Данные принадлежат серверу? | Механизм синхронизации и кеша |

## Частая ошибка

Поднимать state в корень только ради удобства доступа. Это увеличивает связь компонентов. Начни с ближайшей разумной области и расширяй ее по потребности.

## Что важно помнить

- Начинайте с локального состояния и поднимайте его только при необходимости.
- Глобальное состояние нужно для данных, которые используют далекие друг от друга части приложения.
- Серверные данные лучше хранить в кеше запросов (TanStack Query), а не в глобальном store.
- Чем больше подписчиков у глобального состояния, тем важнее селекторы и разделение.

## Мини-шпаргалка

- Локальность и глобальность - про область использования.
- Context передает значение, state хранит владелец.
- Глобальное не означает вечное или сохраненное.
- Серверные данные имеют дополнительные требования синхронизации.
