# Batching и несколько вызовов setState

> [!NOTE]
> **Batching** — объединение нескольких обновлений состояния в один рендер. Если в обработчике вызвать три сеттера, React перерендерит компонент один раз. До React 18 batching работал только внутри обработчиков событий React; с React 18 и `createRoot` действует **автоматический batching** — также в промисах, `setTimeout`, нативных обработчиках. Отключить его для конкретного обновления можно через `flushSync`.

## Вопрос

Что такое batching в React? Что происходит при нескольких вызовах `setState` подряд и как изменилось поведение в React 18?

## Основная идея

```jsx
function Profile() {
  const [name, setName] = useState("");
  const [age, setAge] = useState(0);
  const [saved, setSaved] = useState(false);

  function handleSave() {
    setName("Анна");
    setAge(25);
    setSaved(true);
    // один рендер, а не три
  }
}
```

React складывает обновления в очередь и выполняет рендер после того, как обработчик завершится. Это экономит работу и предотвращает «промежуточные» состояния интерфейса.

## Несколько вызовов одного сеттера

```jsx
setCount(count + 1);
setCount(count + 1);
// итог +1: оба вызова используют одно значение count из снимка

setCount((c) => c + 1);
setCount((c) => c + 1);
// итог +2: функции применяются по очереди к актуальному значению

setCount(count + 5);
setCount((c) => c + 1);
// итог count + 6: сначала замена, затем функция над результатом
```

## React 17 и React 18

```jsx
// React 17 (ReactDOM.render): внутри setTimeout batching не было — 2 рендера
setTimeout(() => {
  setCount((c) => c + 1);
  setFlag((f) => !f);
}, 0);

// React 18 (createRoot): автоматический batching — 1 рендер
fetch("/api").then(() => {
  setData(result);
  setLoading(false);
});
```

| Где обновления | React 17 | React 18 + `createRoot` |
| --- | --- | --- |
| Обработчик события React | batch | batch |
| `setTimeout`, промисы, `await` | без batching | batch |
| Нативный `addEventListener` | без batching | batch |

## Отключение batching: flushSync

```jsx
import { flushSync } from "react-dom";

function addMessage(text) {
  flushSync(() => {
    setMessages((m) => [...m, text]);
  });
  listRef.current.lastChild.scrollIntoView(); // DOM уже обновлен
}
```

`flushSync` вредит производительности — используйте только когда нужен синхронный доступ к обновленному DOM.

## Что важно помнить

- Batching не меняет порядок обновлений: они применяются в порядке вызова.
- Старый `unstable_batchedUpdates` больше не нужен при `createRoot`.
- Классовый `setState` в React 18 тоже батчится вне обработчиков событий.
- Если код полагался на синхронный рендер после каждого `setState` (React 17), при миграции на React 18 возможны изменения поведения.

## Мини-шпаргалка

Batching = несколько обновлений → один рендер. React 18: автоматически везде. `setX(x + 1)` дважды → +1, `setX(c => c + 1)` дважды → +2. Отключить — `flushSync`.
