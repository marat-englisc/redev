# Что значит подъем состояния

> [!NOTE]
> **Lifting state up** - перенос общего состояния к ближайшему предку его потребителей, чтобы несколько компонентов использовали один источник данных.

## Вопрос

Как синхронизировать соседние компоненты и почему не стоит хранить независимые копии общего значения?

## Основная идея

Если поле поиска и список результатов должны использовать один запрос, состояние нужно разместить у их общего родителя. Поле получает значение и callback; список - данные для отображения.

Подъем не означает перенос всех данных в App. Выбирают ближайшего предка, которому доступны все потребители. Так область обновления и ответственности остается ограниченной.

Ребенок не изменяет родительский state напрямую. Он вызывает callback, а родитель решает, как обработать действие.

## Пример: поле и превью используют одно имя

```jsx
import { useState } from "react";

function NameInput({ value, onChange }) {
  return (
    <label>
      Имя для профиля
      <input value={value} onChange={e => onChange(e.currentTarget.value)} />
    </label>
  );
}

function ProfilePreview({ name }) {
  return <p>На карточке: {name || "Гость"}</p>;
}

export default function ProfileEditor() {
  const [name, setName] = useState("");

  return (
    <>
      <NameInput value={name} onChange={setName} />
      <ProfilePreview name={name} />
    </>
  );
}
```

Один ввод обновляет одно значение. Родитель передает новый снимок обоим детям, поэтому превью соответствует полю.

## Шаги переноса

1. Найти компоненты, которым нужны общие данные.
2. Выбрать ближайшего общего предка.
3. Перенести к нему state.
4. Передать значение потребителям.
5. Передать callbacks тем, кто инициирует изменения.
6. Удалить избыточные копии.

## Нюанс с преобразованиями

Если синхронизируются два разных представления - например, Цельсий и Фаренгейт, - нужно не просто передать один setter обоим полям, а выполнить соответствующее обратное преобразование.

Пользовательский ввод также может содержать промежуточные строки вроде `"-"` или пустого значения. Для редактора важно выбрать модель, которая не уничтожает такой ввод слишком рано.

## Что важно помнить

- Поднимайте state в ближайшего общего родителя компонентов, которым он нужен.
- Дети получают значение через props и меняют его через колбэки.
- Не поднимайте выше, чем требуется: это вызовет лишние ререндеры.
- Если общий родитель слишком далеко, рассмотрите композицию, контекст или store.

## Мини-шпаргалка

- Общее значение хранится один раз.
- Его владелец - ближайший подходящий предок.
- Props передают данные вниз.
- Callbacks сообщают о действиях.
- Производные представления вычисляют или преобразуют из общего источника.
