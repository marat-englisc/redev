# Как обновить элемент массива в состоянии

> [!NOTE]
> Для обновления записи обычно применяют **map**: измененную запись заменяют новым объектом, остальные возвращают без изменений.

## Вопрос

Как изменить один объект внутри массива и почему копии самого массива недостаточно?

## Основная идея

Пусть state содержит список уроков. Нужно отметить один урок завершенным, сохранив порядок и остальные поля.

Метод `map` создает новый массив. Для выбранного ID callback возвращает новую версию объекта, для остальных - прежнюю ссылку. React получает новый state, а неизменившиеся записи не копируются без необходимости.

Поиск по устойчивому ID надежнее, чем по индексу: после сортировки индекс может относиться уже к другому уроку.

## Пример: отметить урок

```jsx
import { useState } from "react";

export default function Lessons() {
  const [lessons, setLessons] = useState([
    { id: "jsx", title: "JSX", done: false },
    { id: "hooks", title: "Хуки", done: false },
  ]);

  function complete(id) {
    setLessons(previous =>
      previous.map(lesson =>
        lesson.id === id ? { ...lesson, done: true } : lesson
      )
    );
  }

  return (
    <ul>
      {lessons.map(lesson => (
        <li key={lesson.id}>
          {lesson.title}: {lesson.done ? "готово" : "в плане"}
          <button disabled={lesson.done} onClick={() => complete(lesson.id)}>
            Завершить
          </button>
        </li>
      ))}
    </ul>
  );
}
```

Первое нажатие для JSX создает новый массив. Объект JSX меняется, а объект урока про хуки остается прежним.

## Другие операции

| Задача | Подход |
| --- | --- |
| Добавить | [...previous, newItem] |
| Удалить | previous.filter(item => item.id !== id) |
| Изменить | previous.map(...) |
| Отсортировать | previous.toSorted(compare) или [...previous].sort(compare) |

`toSorted` требует подходящей поддержки среды; копия с `sort` удобна в более старом окружении.

## Частые ошибки

`previous[index].done = true` мутирует объект. Даже если затем вернуть `[...previous]`, старый снимок уже испорчен.

Не создавай новые ID для всех элементов при обновлении одного. Ключи должны оставаться стабильными, иначе компоненты строк перемонтируются и потеряют локальное состояние.

## Что важно помнить

- Заменяйте элемент через `map` и возвращайте новый объект для измененного элемента.
- `arr[i] = x`, `push`, `splice`, `sort` мутируют массив — React может не увидеть изменение.
- Современные иммутабельные методы: `with`, `toSorted`, `toSpliced`, `toReversed`.
- Для глубоких обновлений удобен Immer.

## Мини-шпаргалка

- Новый массив создается через map.
- Измененная запись получает новый объект.
- Остальные ссылки сохраняются.
- ID определяет запись, key связывает ее с интерфейсом.
- Копирование контейнера не равно копированию вложенных объектов.
