# Типы компонентов: функциональные и классовые

> [!NOTE]
> В React два способа объявить компонент: **функциональный** (функция, возвращающая JSX, с хуками для состояния и эффектов) и **классовый** (класс, наследующий `React.Component`, с `this.state`, `setState` и методами жизненного цикла). Современный React рекомендует функциональные компоненты: они короче, логика переиспользуется через хуки, а новые возможности (хуки, Server Components, Actions) работают только с ними. Классы остались в legacy-коде и для Error Boundary.

## Вопрос

Какие типы компонентов существуют в React? Чем классовый компонент отличается от функционального?

## Основная идея

```jsx
// функциональный
function Counter() {
  const [count, setCount] = useState(0);
  useEffect(() => {
    document.title = `Счет: ${count}`;
  }, [count]);
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}

// классовый
class CounterClass extends React.Component {
  state = { count: 0 };

  componentDidUpdate() {
    document.title = `Счет: ${this.state.count}`;
  }

  render() {
    return (
      <button onClick={() => this.setState({ count: this.state.count + 1 })}>
        {this.state.count}
      </button>
    );
  }
}
```

## Сравнение

| | Функциональный | Классовый |
| --- | --- | --- |
| Синтаксис | функция | класс с `render()` |
| Состояние | `useState`, `useReducer` | `this.state`, `this.setState` |
| Побочные эффекты | `useEffect` и другие хуки | `componentDidMount`, `componentDidUpdate`, `componentWillUnmount` |
| `this` | не нужен | нужен, теряется в колбэках |
| Переиспользование логики | кастомные хуки | HOC, render props |
| Error Boundary | невозможно | `getDerivedStateFromError`, `componentDidCatch` |
| Новые возможности React | да | нет (хуки, RSC, Actions) |
| Объем кода | меньше | больше |

## Другие «типы» компонентов

Иногда на собеседовании спрашивают о классификации по роли:

- **presentational и container** — отображение отдельно от данных;
- **controlled и uncontrolled** — кто управляет значением формы;
- **Server и Client Components** — где выполняется компонент (React 19, Next.js App Router);
- **pure** — компонент без побочных эффектов, `PureComponent` у классов;
- **HOC** — функция, возвращающая компонент.

## Что важно помнить

- Классовые компоненты не устарели формально, но новые API для них не появляются.
- `setState` в классе сливает объект с текущим состоянием, а сеттер `useState` заменяет значение целиком.
- Значения в функциональном компоненте — снимок конкретного рендера (замыкания), в классе `this.state` всегда текущее — отсюда разные баги.
- Error Boundary всё еще пишут классом или берут библиотеку `react-error-boundary`.

## Мини-шпаргалка

Функциональные — функции + хуки, стандарт сегодня. Классовые — `React.Component`, `this.state`, методы жизненного цикла, legacy. Классы нужны для Error Boundary.
