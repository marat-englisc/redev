# Можно ли изменять props и что будет, если изменить их напрямую

> [!NOTE]
> Props нельзя изменять внутри компонента: они принадлежат родителю и считаются **неизменяемыми**. Прямое присваивание (`props.title = "..."`) в strict mode бросит ошибку для замороженного объекта props, а мутация вложенного объекта (`props.user.name = "..."`) молча изменит данные родителя, не вызовет ререндер и нарушит однонаправленный поток данных. Чтобы «изменить» prop, ребенок вызывает колбэк, а родитель меняет свое состояние.

## Вопрос

Можно ли изменять props внутри компонента? Что произойдет, если изменить props напрямую?

## Основная идея

React строит интерфейс на однонаправленном потоке данных: родитель владеет данными и передает их вниз. Если ребенок изменит props, источник правды «раздвоится»: родитель думает, что значение одно, а в объекте уже другое. React не узнает об изменении, потому что оно произошло не через `setState`.

В dev-режиме React замораживает объект props (`Object.freeze`), поэтому:

```jsx
function Title(props) {
  props.text = "Новый"; // TypeError: Cannot assign to read only property 'text'
  return <h1>{props.text}</h1>;
}
```

Но заморозка поверхностная — вложенные объекты мутировать можно, и это еще опаснее:

```jsx
function UserBadge({ user }) {
  user.name = user.name.toUpperCase(); // мутирует объект родителя, ререндера нет
  return <span>{user.name}</span>;
}
```

Последствия: «случайно» измененные данные в других местах, пропущенные обновления, некорректная работа `memo` и `useMemo`, которые сравнивают по ссылке.

## Правильный способ: подъем состояния и колбэк

```jsx
function Parent() {
  const [title, setTitle] = useState("Черновик");
  return <TitleEditor title={title} onChange={setTitle} />;
}

function TitleEditor({ title, onChange }) {
  return <input value={title} onChange={(e) => onChange(e.target.value)} />;
}
```

Ребенок «просит» изменить значение, родитель решает и обновляет состояние, новый prop приходит вниз.

## Локальная копия

Если ребенку нужно редактировать значение до сохранения, он создает свое состояние, инициализированное из prop:

```jsx
function EditableName({ initialName, onSave }) {
  const [draft, setDraft] = useState(initialName); // initialName используется один раз
  return (
    <>
      <input value={draft} onChange={(e) => setDraft(e.target.value)} />
      <button onClick={() => onSave(draft)}>Сохранить</button>
    </>
  );
}
```

Чтобы сбросить черновик при смене исходного значения, используйте `key={initialName}` у компонента, а не синхронизацию через `useEffect`.

## Что важно помнить

- Не копируйте props в state без необходимости — получите рассинхронизацию (derived state).
- Вычисляемые значения считайте прямо в рендере: `const fullName = first + " " + last`.
- Мутация массивов из props (`props.items.sort()`) — частая скрытая ошибка; используйте `toSorted`.
- В TypeScript props можно пометить `Readonly<Props>`.

## Мини-шпаргалка

Props неизменяемы. Прямая запись — ошибка, мутация вложенных объектов — скрытый баг. Изменение — через колбэк и state родителя. Черновик — свой state + `key` для сброса.
