# Композиция компонентов

> [!NOTE]
> **Композиция** — построение сложных компонентов из простых путем вложения и передачи JSX через `children` и props, а не через наследование. React официально рекомендует композицию вместо наследования: специализированный компонент оборачивает общий (`<DangerButton>` рендерит `<Button variant="danger">`), а обертки принимают содержимое снаружи. Композиция также решает часть проблем prop drilling и лишних ререндеров.

## Вопрос

Что такое композиция компонентов? Почему в React предпочитают композицию наследованию?

## Основная идея

Вместо того чтобы создавать иерархию классов `Button → IconButton → DangerIconButton`, в React компоненты комбинируют:

```jsx
function Button({ variant = "primary", icon, children, ...props }) {
  return (
    <button className={`btn btn--${variant}`} {...props}>
      {icon}
      {children}
    </button>
  );
}

function DeleteButton(props) {
  return <Button variant="danger" icon={<TrashIcon />} {...props}>Удалить</Button>;
}
```

Приемы композиции:

| Прием | Пример |
| --- | --- |
| Вложение через `children` | `<Modal><Form /></Modal>` |
| Слоты через props | `<Layout header={<Nav />} />` |
| Специализация | `DeleteButton` оборачивает `Button` |
| Compound components | `<Tabs><Tabs.List /><Tabs.Panel /></Tabs>` |
| Render props | `<List renderItem={(i) => <Row {...i} />} />` |
| Кастомные хуки | переиспользование логики без разметки |

## Композиция против prop drilling

```jsx
// prop drilling: user проходит через три уровня, которым он не нужен
<Page user={user} /> → <Layout user={user} /> → <Header user={user} /> → <Avatar user={user} />

// композиция: компонент с данными создается наверху и передается как элемент
function App({ user }) {
  return (
    <Page header={<Header avatar={<Avatar user={user} />} />}>
      <Content />
    </Page>
  );
}
```

Промежуточные компоненты больше не знают о `user`.

## Композиция и производительность

Компонент, переданный через `children`, создается в родителе, поэтому он не перерендерится при изменении состояния обертки. Перенос состояния «вниз» в обертку, а тяжелого контента — в `children`, уменьшает ререндеры без `memo`.

## Почему не наследование

- наследование жестко связывает компоненты и затрудняет изменения;
- в React нет удобного механизма переопределения частей разметки родителя;
- функциональные компоненты не поддерживают наследование вовсе;
- композиция явная: видно, из чего состоит компонент.

## Что важно помнить

- Начинайте с простого: обертка с `children` решает большинство задач.
- Слишком гибкий компонент с десятком слотов трудно поддерживать — иногда лучше два разных компонента.
- Composition через `children` — первое, что стоит попробовать перед контекстом при prop drilling.
- Библиотеки headless UI (Radix, React Aria) построены на композиции.

## Мини-шпаргалка

Композиция = собираем компоненты из компонентов. `children`, слоты-props, специализация, compound components. Композиция вместо наследования. Помогает от prop drilling и лишних ререндеров.
