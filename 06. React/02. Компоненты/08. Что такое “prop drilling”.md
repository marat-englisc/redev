# Что такое prop drilling

> [!NOTE]
> **Prop drilling** - передача данных через промежуточные компоненты, которым эти данные нужны только для доставки более глубокому потребителю.

## Вопрос

Когда передача props становится неудобной и какие альтернативы стоит рассмотреть?

## Основная идея

Пусть имя пользователя хранится на странице, а показывается в маленьком блоке внутри панели. Если каждый промежуточный компонент должен принять `user` и передать дальше, изменение контракта затронет несколько уровней.

Это не ошибка само по себе. Явные props делают зависимости понятными. Условие «больше двух уровней - обязательно Context» не существует: решение зависит от числа потребителей и роли промежуточных компонентов.

Сначала полезно проверить границы компонентов и возможность композиции. Если оболочке не нужны данные, можно передать ей уже собранный контент.

## Пример: композиция убирает лишнюю передачу

```jsx
function Panel({ children }) {
  return <section className="panel">{children}</section>;
}

function Layout({ sidebar, children }) {
  return (
    <div className="layout">
      <aside>{sidebar}</aside>
      <main>{children}</main>
    </div>
  );
}

function UserSummary({ name }) {
  return <p>Вы вошли как {name}</p>;
}

export default function Dashboard() {
  const user = { name: "Анна" };

  return (
    <Layout sidebar={<Panel><UserSummary name={user.name} /></Panel>}>
      <h1>Ваши конспекты</h1>
    </Layout>
  );
}
```

`Layout` и `Panel` не принимают `user`. Родитель сам собрал нужное содержимое и передал его как JSX.

## Другие способы

**Context** полезен, если значение нужно разным потомкам одной области: тема, язык, текущая сессия. При изменении значения обновляются его потребители.

**Внешнее хранилище** может помочь со сложным общим состоянием и подписками на отдельные части данных. Оно добавляет свою архитектуру, поэтому не требуется только из-за глубины дерева.

**Подъем состояния** помогает соседним компонентам договориться об общем источнике, но сам по себе иногда увеличивает путь передачи.

## Что важно помнить

- Prop drilling — передача props через промежуточные компоненты, которым они не нужны.
- Два-три уровня — нормально; проблема начинается, когда цепочка длинная и часто меняется.
- Решения: композиция через `children`, контекст, state-менеджер, colocation состояния.
- Контекст не стоит использовать только чтобы избежать одного-двух уровней передачи.

## Мини-шпаргалка

- Drilling - транзит через неиспользующие данные компоненты.
- Props полезны для явных зависимостей.
- Композиция может убрать транзит.
- Context выбирают по области потребления.
- Количество уровней не является жестким критерием.
