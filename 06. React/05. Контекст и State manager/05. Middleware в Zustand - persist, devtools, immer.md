# Middleware в Zustand: persist, devtools, immer

> [!NOTE]
> **Middleware** в Zustand — функция-обертка над создателем store, которая добавляет поведение: сохранение в `localStorage` (`persist`), подключение к Redux DevTools (`devtools`), «мутирующий» синтаксис обновлений (`immer`), подписку на отдельные поля (`subscribeWithSelector`). Middleware оборачивают друг друга: `create(devtools(persist(immer(fn))))`.

## Вопрос

Что такое middleware в Zustand? Что делает middleware `immer` и какие еще middleware бывают?

## Основная идея

```js
import { create } from "zustand";
import { devtools, persist } from "zustand/middleware";
import { immer } from "zustand/middleware/immer";

export const useTodoStore = create(
  devtools(
    persist(
      immer((set) => ({
        todos: [],
        add: (title) =>
          set((state) => {
            state.todos.push({ id: crypto.randomUUID(), title, done: false });
          }),
        toggle: (id) =>
          set((state) => {
            const todo = state.todos.find((t) => t.id === id);
            if (todo) todo.done = !todo.done;
          }),
      })),
      { name: "todos" }, // ключ в localStorage
    ),
    { name: "TodoStore" },
  ),
);
```

## Основные middleware

| Middleware | Что делает |
| --- | --- |
| `persist` | сохраняет state в `localStorage`/`sessionStorage`/свое хранилище и восстанавливает при загрузке |
| `devtools` | показывает изменения в Redux DevTools, поддерживает time-travel |
| `immer` | позволяет писать «мутирующие» обновления, создавая новый state через Immer |
| `subscribeWithSelector` | `store.subscribe(selector, listener)` — подписка на конкретное поле вне React |
| `combine` | объединяет начальный state и actions с выводом типов |

## Immer: зачем

Без Immer вложенные обновления требуют копирования каждого уровня:

```js
// без immer
set((s) => ({
  user: { ...s.user, address: { ...s.user.address, city: "Казань" } },
}));

// с immer
set((s) => {
  s.user.address.city = "Казань";
});
```

Immer работает с черновиком (`draft`) — прокси над state — и по завершении создает новый неизменяемый объект только для измененных веток.

## persist: детали

```js
persist(fn, {
  name: "cart",
  storage: createJSONStorage(() => sessionStorage),
  partialize: (s) => ({ items: s.items }), // что сохранять
  version: 2,
  migrate: (old, version) => /* миграция старых данных */ old,
});
```

## Что важно помнить

- Порядок важен: `devtools` обычно снаружи, чтобы видеть итоговые изменения.
- В TypeScript типы при цепочке middleware указывают через `create<State>()(...)`.
- `persist` при SSR вызывает расхождения гидрации — восстанавливайте state после монтирования (`skipHydration`, `rehydrate`).
- Immer добавляет вес и накладные расходы — для плоского state он не нужен.

## Мини-шпаргалка

Middleware = обертка над store. `persist` — хранилище, `devtools` — Redux DevTools, `immer` — мутирующий синтаксис, `subscribeWithSelector` — подписка на поле. Оборачиваются друг в друга.
