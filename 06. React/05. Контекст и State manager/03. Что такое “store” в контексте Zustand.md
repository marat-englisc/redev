# Что такое store в Zustand

> [!NOTE]
> Store — контейнер текущего состояния с механизмом чтения, обновления и подписки. Он может существовать независимо от React-компонентов.

## Вопрос

Из чего состоит Zustand-store? Чем create отличается от createStore?

## Основная идея

В store находятся данные, например список выбранных мест, и часто функции-действия, например `reserveSeat`. У store есть текущее значение, API обновления и подписчики. Это не просто объект, из которого читают поля: уведомления позволяют внешним потребителям узнавать об изменениях.

`create` возвращает React-хук, к которому прикреплены методы store. Его вызывают в компоненте для подписки или используют `getState()` в обычной функции для разового чтения. `createStore` из `zustand/vanilla` создаёт store без React-хука; при необходимости его подключают к React через `useStore`. Такое разделение удобно для изолированных экземпляров и других сред.

Место создания определяет область жизни. Store на уровне модуля обычно общий для импортирующих его клиентских компонентов. Store, создаваемый для конкретной области приложения, может быть изолированным. Нельзя просто вызывать `create` в теле компонента на каждом рендере: получится новое хранилище, потеря состояния и нестабильные подписки.

## Пример

Для запуска примеров этого раздела нужен пакет `zustand`; API соответствует Zustand 5.

```tsx
import { create } from 'zustand';

type Seats = { reserved: number; reserve: () => void };
const useSeats = create<Seats>()(set => ({
  reserved: 0,
  reserve: () => set(state => ({ reserved: state.reserved + 1 })),
}));

// Обычная функция: React-хуки здесь не вызываются.
function reserveFromService() {
  useSeats.getState().reserve();
}

export default function SeatCounter() {
  const reserved = useSeats(state => state.reserved);
  return <button onClick={reserveFromService}>Забронировано: {reserved}</button>;
}
```

Сервисная функция берёт актуальное действие из store и вызывает его. Компонент подписан на число и получает обновление. Сам `getState` ничего не подписывает: если вывести его результат в JSX без хука, автоматического обновления при изменении store не будет.

## Что важно помнить

- `set` по умолчанию поверхностно сливает верхний уровень состояния.
- Полная замена через replace может удалить действия, если их не включить в новое значение.
- Не мутируйте возвращённый getState объект напрямую: уведомления и сравнение ссылок могут не сработать.
- Подписку `subscribe` нужно прекращать возвращённой функцией.
- Общий серверный store с пользовательскими данными способен смешать запросы; SSR требует изоляции и согласованного начального состояния.

## Мини-шпаргалка

Store: snapshot + update + subscribe. `create`: связанный React-хук. `createStore`: независимое хранилище. `getState`: чтение без подписки.
