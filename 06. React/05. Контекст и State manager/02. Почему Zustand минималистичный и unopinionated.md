# Почему Zustand минималистичный и unopinionated

> [!NOTE]
> Zustand называют **минималистичным**, потому что store — это один вызов `create` с объектом состояния и функциями, без провайдеров, actions-типов, редьюсеров и boilerplate; библиотека весит около 1 КБ. **Unopinionated** означает, что Zustand не навязывает архитектуру: можно хранить всё в одном store или в нескольких, мутировать через Immer или иммутабельно, писать логику в store или снаружи, подключать только нужные middleware.

## Вопрос

Почему Zustand называют минималистичным state-менеджером? Что означает принцип «unopinionated»?

## Минимализм

```jsx
import { create } from "zustand";

const useCounter = create((set) => ({
  count: 0,
  inc: () => set((s) => ({ count: s.count + 1 })),
  reset: () => set({ count: 0 }),
}));

function Counter() {
  const count = useCounter((s) => s.count);
  const inc = useCounter((s) => s.inc);
  return <button onClick={inc}>{count}</button>;
}
```

Чего нет по сравнению с Redux:

| Redux (классический) | Zustand |
| --- | --- |
| `<Provider store>` вокруг приложения | не нужен |
| action types, action creators | обычные функции в store |
| редьюсеры со `switch` | `set` с частичным объектом |
| `connect` / `useSelector` + `useDispatch` | один хук с селектором |
| middleware для async (thunk) | `async`-функции прямо в store |

`set` сливает переданный объект с текущим state поверхностно, поэтому не нужно копировать остальные поля.

## Unopinionated

Zustand не диктует, как организовать код:

- **один или несколько store** — по фичам (`useCartStore`, `useAuthStore`) или один со слайсами;
- **иммутабельно или с Immer** — через middleware `immer`;
- **логика в store или снаружи** — функции можно объявить вне `create` и вызывать `useStore.setState`;
- **с React или без** — `createStore` из `zustand/vanilla` работает в любом JS;
- **middleware по выбору** — `persist`, `devtools`, `immer`, `subscribeWithSelector`.

```js
// actions вне store
export const useBearStore = create(() => ({ bears: 0 }));
export const addBear = () => useBearStore.setState((s) => ({ bears: s.bears + 1 }));
```

## Плюсы и минусы

| Плюсы | Минусы |
| --- | --- |
| мало кода, быстрый старт | нет единой структуры — в большой команде нужны соглашения |
| нет лишних ререндеров благодаря селекторам | меньше встроенных инструментов, чем у Redux Toolkit |
| работает вне React | серверное состояние всё равно лучше в TanStack Query |

## Что важно помнить

- Отсутствие правил — ответственность команды: договоритесь о структуре store и слайсов.
- Для SSR (Next.js) store создают на запрос через `createStore` и контекст, иначе данные пользователей смешаются.
- `set` сливает только верхний уровень — вложенные объекты копируйте сами или используйте Immer.

## Мини-шпаргалка

Zustand = `create` + хук с селектором. Без провайдера, редьюсеров и action types, ~1 КБ. Unopinionated: структура, мутации и middleware — на ваш выбор. `set` сливает state поверхностно.
