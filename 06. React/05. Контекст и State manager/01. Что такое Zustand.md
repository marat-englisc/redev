# Zustand: внешнее хранилище состояния

> [!NOTE]
> Zustand — библиотека управления состоянием. Store хранит данные и действия, а React-компоненты подписываются на выбранные значения через хук.

## Вопрос

Что такое Zustand и какую задачу он решает по сравнению с локальным state и Context?

## Основная идея

Локальный `useState` хорошо подходит данным одного компонента. Если корзина нужна шапке, карточке товара и странице заказа, появляется задача совместного доступа. Zustand позволяет создать внешний store и читать его из разных частей приложения без передачи значений через каждый промежуточный компонент.

`create` создаёт связанный с React хук и методы доступа к хранилищу. В конфигурации обычно находятся поля состояния и действия, вызывающие `set`. При обновлении, основанном на прежних данных, используют функциональную форму `set(state => ...)`. Она получает актуальное состояние store, а не случайно сохранённый снимок из обработчика.

В обычном клиентском приложении store на уровне модуля можно использовать без Provider. Компонент передаёт селектор — функцию, выбирающую нужный фрагмент. Встроенные подписки обновляют его при изменении результата селектора. Это отличается от встроенного Context, где потребитель получает всё значение провайдера. Однако Zustand не отменяет остальные причины рендера: родителя, локальный state и контекст.

## Пример

Для запуска примеров этого раздела нужен пакет `zustand`; API соответствует Zustand 5.

```tsx
import { create } from 'zustand';

type CartStore = { count: number; add: () => void };
const useCartStore = create<CartStore>()(set => ({
  count: 0,
  add: () => set(state => ({ count: state.count + 1 })),
}));

function CartBadge() {
  const count = useCartStore(state => state.count);
  return <p>В корзине: {count}</p>;
}

export default function Shop() {
  const add = useCartStore(state => state.add);
  return <><CartBadge /><button onClick={add}>Добавить чашку</button></>;
}
```

Кнопка вызывает общее действие, а бейдж подписан на число. Оба компонента используют одно хранилище. Здесь не требуется Context.Provider. Вызов хука без селектора подписал бы компонент на весь store и сделал бы подписку шире.

## Что важно помнить

- State изменяют неизменяемо: вложенные объекты и массивы нужно копировать или применять Immer.
- Middleware `persist` позволяет сохранять выбранные данные, но по умолчанию store живёт только в памяти.
- Для SSR нельзя бездумно делить пользовательский singleton между запросами: создавайте хранилище на запрос/область и согласуйте гидратацию.
- Zustand не является автоматическим кешем серверных запросов; загрузка, ошибки и актуальность данных требуют отдельной логики.
- Поддержка TypeScript не заменяет runtime-проверку данных сервера.

## Мини-шпаргалка

Store = данные + действия + подписки. `create` → React-хук. Селектор → нужная часть. Локальное состояние оставляйте локальным, если общий доступ не требуется.
