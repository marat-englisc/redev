# Доступ к состоянию в Zustand: селекторы и подписка на поле

> [!NOTE]
> Хук store в Zustand **селективный**: компонент передает функцию-селектор `useStore((s) => s.count)` и подписывается **только на выбранный фрагмент**. Ререндер происходит, лишь когда результат селектора изменился (по `Object.is`). Без селектора компонент получает весь store и рендерится при любом изменении. Для выбора нескольких полей используют `useShallow`, вне React — `getState()` и `subscribe()`.

## Вопрос

Как получить доступ к состоянию в Zustand? Почему хуки Zustand называют «селективными» и как использовать селекторы для оптимизации?

## Основная идея

```jsx
import { create } from "zustand";

const useCartStore = create((set) => ({
  items: [],
  promo: null,
  add: (item) => set((s) => ({ items: [...s.items, item] })),
  applyPromo: (code) => set({ promo: code }),
}));

function CartCount() {
  const count = useCartStore((s) => s.items.length); // подписка на одно значение
  return <span>{count}</span>;
}

function AddButton({ item }) {
  const add = useCartStore((s) => s.add);            // функция стабильна — ререндеров нет
  return <button onClick={() => add(item)}>В корзину</button>;
}
```

При вызове `applyPromo` компоненты `CartCount` и `AddButton` не перерендерятся: их селекторы вернули то же значение.

## Способы доступа

| Способ | Что происходит |
| --- | --- |
| `useStore()` | весь state, ререндер при любом изменении |
| `useStore((s) => s.x)` | одно поле, ререндер только при изменении `x` |
| `useStore(useShallow((s) => ({ a: s.a, b: s.b })))` | несколько полей, поверхностное сравнение |
| `useStore.getState()` | чтение вне React без подписки |
| `useStore.setState(partial)` | запись вне React |
| `useStore.subscribe(listener)` | подписка вне React (логирование, синхронизация) |

## Несколько полей: useShallow

```jsx
import { useShallow } from "zustand/react/shallow";

// плохо: новый объект каждый раз → ререндер при любом изменении store
const { items, promo } = useCartStore((s) => ({ items: s.items, promo: s.promo }));

// хорошо: поверхностное сравнение полей
const { items, promo } = useCartStore(
  useShallow((s) => ({ items: s.items, promo: s.promo })),
);

// или несколько отдельных селекторов
const items = useCartStore((s) => s.items);
const promo = useCartStore((s) => s.promo);
```

## Производные значения

```jsx
const total = useCartStore((s) => s.items.reduce((sum, i) => sum + i.price, 0));
```

Примитив сравнивается по значению — ререндер только при изменении суммы. Если селектор возвращает новый массив (`s.items.filter(...)`), используйте `useShallow` или мемоизацию.

## Что важно помнить

- Селектор, возвращающий новый объект или массив без `useShallow`, ломает оптимизацию; в Zustand v5 это может вызвать бесконечный цикл.
- Экспортируйте готовые хуки-селекторы (`useCartCount`) — так проще контролировать подписки.
- `getState()` в обработчиках событий помогает не подписывать компонент на значение, нужное только при клике.
- Внутри Zustand использует `useSyncExternalStore`.

## Мини-шпаргалка

`useStore(s => s.x)` — подписка на фрагмент, ререндер только при его изменении. Несколько полей — `useShallow`. Без селектора — весь store. Вне React — `getState`, `setState`, `subscribe`.
