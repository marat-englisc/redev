# Реактивность Zustand: что происходит автоматически

> [!NOTE]
> Store-хук скрывает регистрацию и очистку подписки, но выбор данных остаётся явным через селектор. Произвольное чтение объекта не становится реактивным.

## Вопрос

Что имеют в виду под transparent reactivity? Чем Zustand отличается от автоматического отслеживания доступа к полям?

## Основная идея

Термин transparent reactivity в контексте Zustand обычно употребляют неформально: компонент вызывает хук, получает значение и автоматически обновляется при изменении результата. Разработчику не приходится вручную регистрировать listener и вызывать локальный сеттер ради каждого компонента.

Однако Zustand не отслеживает все чтения полей как Proxy-система некоторых реактивных библиотек. Выбор задаётся селектором. Если вызвать хук без селектора, подписка относится ко всему store; последующая деструктуризация не сужает её. Если прочитать getState, React-подписка не создаётся вообще.

Под капотом React-интеграция использует механизм внешнего store и snapshot. При уведомлении проверяется выбранный результат; смена по Object.is приводит к обновлению соответствующей подписки. У React Redux `useSelector` тоже есть автоматическое управление подпиской, поэтому противопоставление «там всё вручную, здесь всё автоматически» неверно. Полезнее сравнивать контракты выбора данных, равенства и организацию обновлений.

## Пример

Для запуска примеров этого раздела нужен пакет `zustand`; API соответствует Zustand 5.

```tsx
import { create } from 'zustand';

type TimerStore = { seconds: number; tick: () => void };
const useTimer = create<TimerStore>()(set => ({
  seconds: 0,
  tick: () => set(state => ({ seconds: state.seconds + 1 })),
}));

function ReactiveValue() {
  const seconds = useTimer(state => state.seconds);
  return <p>Подписанный экран: {seconds}</p>;
}

function SnapshotValue() {
  const seconds = useTimer.getState().seconds;
  return <p>Разовое чтение: {seconds}</p>;
}

export default function Demo() {
  return <>
    <button onClick={() => useTimer.getState().tick()}>Тик</button>
    <ReactiveValue /><SnapshotValue />
  </>;
}
```

Кнопка меняет store, но не состояние родителя. `ReactiveValue` получает уведомление и обновляется. `SnapshotValue` остаётся со значением последнего собственного рендера; оно изменится только при другой причине рендера. Это показывает границу автоматизма: реактивность даёт хук, а не доступ к объекту.

## Что важно помнить

- Не используйте «прозрачность» как обещание отсутствия лишних рендеров во всём дереве.
- Обновления должны идти через API store, с неизменяемыми данными.
- Новый объект в результате селектора требует стабильности, например useShallow.
- Middleware subscribeWithSelector расширяет ручные подписки, но не является обязательным для обычного селектора React-хука.
- Отписку компонента хук выполняет автоматически; у ручного subscribe ответственность остаётся у вашего кода.

## Мини-шпаргалка

Хук + selector → реактивное чтение. GetState → снимок без подписки. Автоматическая подписка не означает автоматическое отслеживание любых полей.
