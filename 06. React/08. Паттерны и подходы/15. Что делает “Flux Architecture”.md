# Flux Architecture: однонаправленный поток изменений

> [!NOTE]
> Flux — архитектурный подход, в котором пользовательское действие проходит через явный поток обновления данных, а представление читает полученное состояние.

## Вопрос

Как устроена классическая цепочка Flux и чем она отличается от Redux или `useReducer`?

## Действие объясняет изменение

В классическом Flux есть **Action** — описание события, **Dispatcher** — передача действия хранилищам, **Store** — данные и правила реакции, **View** — интерфейс. View создает следующее action, замыкая однонаправленный цикл: `Action → Dispatcher → Store → View`.

Например, нажатие «Добавить книгу» создает действие с ID книги. Хранилище обрабатывает действие и уведомляет подписчиков. UI получает актуальное состояние. Вместо неявных взаимных изменений появляется конкретное событие, по которому можно понять причину нового состояния.

Redux развивается из похожих идей, но не является точной копией классического Flux: у него один store и чистые reducer-функции, отсутствует отдельный классический Dispatcher. `useReducer` помогает показать тот же принцип локально внутри React, но не создает автоматически глобальную Flux-архитектуру и подписки внешнего store.

## Пример

```jsx
import { useReducer } from 'react';

const initial = { count: 0 };

function reducer(state, action) {
  switch (action.type) {
    case 'bookAdded':
      return { ...state, count: state.count + 1 };
    case 'cartCleared':
      return initial;
    default:
      return state;
  }
}

export default function Cart() {
  const [state, dispatch] = useReducer(reducer, initial);
  return (
    <section>
      <p>Книг в корзине: {state.count}</p>
      <button onClick={() => dispatch({ type: 'bookAdded' })}>
        Добавить книгу
      </button>
      <button onClick={() => dispatch({ type: 'cartCleared' })}>
        Очистить
      </button>
    </section>
  );
}
```

Здесь локальный reducer показывает идею: событие описано объектом, новое состояние вычисляется в одном месте, UI читает результат. Это учебная аналогия потока, а не реализация всех частей оригинального Flux.

## Нюансы

- Сам React не требует Flux или Redux: небольшому компоненту часто достаточно `useState`.
- В классическом Flux может быть несколько stores; принцип не означает обязательное единое хранилище.
- Чистые reducer-функции не выполняют HTTP-запросы и не мутируют существующее состояние.
- Прямая правка внешней переменной не сообщает React об изменении. Для внешнего store нужна корректная интеграция подписок, например через `useSyncExternalStore`.

## Что важно помнить

- Flux — однонаправленный поток: Action → Dispatcher → Store → View.
- Redux — упрощенная реализация идеи с одним store и чистыми редьюсерами.
- Однонаправленный поток делает изменения предсказуемыми и удобными для отладки.
- `useReducer` переносит ту же модель на уровень компонента.

## Мини-шпаргалка

```text
Действие → правило изменения → состояние → UI
Flux — подход; Redux — отдельная библиотека
useReducer — локальный инструмент, не весь Flux
```
