# Render Props: логика предоставляет данные, функция рисует UI

> [!NOTE]
> Render prop — prop-функция, которую компонент вызывает, передавая данные и получая React-содержимое для отображения.

## Вопрос

Как переиспользовать поведение компонента, оставив вызывающему коду выбор разметки?

## UI передается как функция

Обычный prop содержит готовое значение: строку, число или JSX. Render prop содержит функцию: компонент получает ее, вычисляет свои данные и вызывает с этими данными. Результат функции становится частью интерфейса.

Это удобно для компонента, отвечающего за поведение, а не фиксированный внешний вид. Например, счетчик может управлять количеством, а потребитель решает, показать кнопку, шкалу или текст. Имя prop необязательно должно быть `render`: встречаются `renderItem`, `renderFooter` и другие предметные имена.

Кастомные хуки часто позволяют переиспользовать ту же логику без дополнительной вложенности. Но render props остаются полезны, если компонент владеет определенной областью дерева или библиотека должна дать пользователю гибкую точку настройки интерфейса.

## Пример

```jsx
import { useState } from 'react';

function Counter({ initial = 0, render }) {
  const [count, setCount] = useState(initial);
  function increment() {
    setCount((value) => value + 1);
  }
  return <section>{render({ count, increment })}</section>;
}

export default function App() {
  return (
    <>
      <Counter
        render={({ count, increment }) => (
          <button onClick={increment}>Заказано пицц: {count}</button>
        )}
      />
      <Counter
        initial={3}
        render={({ count, increment }) => (
          <div>
            <p>В очереди {count} человек</p>
            <button onClick={increment}>Встать в очередь</button>
          </div>
        )}
      />
    </>
  );
}
```

Оба экземпляра используют одну реализацию счетчика, но отображают ее по-разному. Нажатие в первом не изменяет второй: повторно используется логика, а не единое общее состояние.

## Нюансы

- `render` вызывается при вычислении UI, поэтому сама функция должна быть чистой.
- Нельзя вызывать обычные хуки внутри callback render prop: это не самостоятельный React-компонент. Если нужен state, верните `<MyComponent />`.
- Inline render-функция создает новую ссылку и может влиять на мемоизацию принимающего компонента; сначала измерьте, является ли это проблемой.
- У каждой точки настройки должен быть понятный контракт: какие данные передаются и какой результат ожидается.

## Что важно помнить

- Render prop — функция в props, которая возвращает JSX и получает данные от компонента.
- Большинство случаев сегодня решается кастомными хуками.
- Паттерн полезен, когда нужно управлять тем, что и где рендерить (виртуализированные списки, Formik, Downshift).
- Инлайн-функция создается каждый рендер — учитывайте это при `memo`.

## Мини-шпаргалка

```text
<Component render={data => <UI data={data} />} />
Компонент владеет поведением; вызывающая сторона задает UI
```
