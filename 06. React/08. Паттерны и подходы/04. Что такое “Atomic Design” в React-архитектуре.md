# Atomic Design: уровни композиции интерфейса

> [!NOTE]
> Atomic Design описывает интерфейс как систему из атомов, молекул, организмов, шаблонов и страниц. Это метод проектирования UI, а не встроенная архитектура React.

## Вопрос

Какие пять уровней предлагает Atomic Design и как они помогают дизайн-системе?

## От базовых элементов к контексту страницы

**Атомы** — базовые детали: кнопка, поле, иконка. **Молекулы** соединяют несколько деталей для небольшой задачи, например поиск с полем и кнопкой. **Организмы** — более крупные области, например шапка сайта с поиском, навигацией и профилем.

**Шаблон** задает структуру страницы и размещение блоков. **Страница** наполняет шаблон реальными данными и состояниями. Последний уровень помогает проверить, что система выдерживает длинное название, пустой список, ошибку и другие настоящие условия, а не только красивый макет.

Эти уровни не обязаны превращаться в пять папок. Границы иногда спорны: карточка товара может считаться молекулой или организмом в зависимости от проекта. Практический результат важнее классификации — согласованные компоненты и возможность собирать новые экраны без копирования стилей.

## Пример

```jsx
import { useState } from 'react';

function Button({ children, ...props }) {
  return (
    <button type="button" {...props}>
      {children}
    </button>
  );
}

function SearchBar({ onSearch }) {
  const [query, setQuery] = useState('');
  return (
    <div>
      <input
        aria-label="Поиск"
        value={query}
        onChange={(event) => setQuery(event.target.value)}
      />
      <Button onClick={() => onSearch(query)}>Найти</Button>
    </div>
  );
}

function Header({ onSearch }) {
  return (
    <header>
      <a href="/">Книжная полка</a>
      <SearchBar onSearch={onSearch} />
    </header>
  );
}

export default function BooksPage() {
  const [query, setQuery] = useState('');
  return (
    <>
      <Header onSearch={setQuery} />
      <main>Ищем: {query || 'все книги'}</main>
    </>
  );
}
```

`Button` играет роль атома, `SearchBar` — молекулы, `Header` — организма. Страница соединяет их с данными. В большем приложении расположение `header` и `main` можно вынести в отдельный шаблон.

## Нюансы

- Atomic Design не определяет получение данных, направление бизнес-зависимостей и устройство store.
- Не выносите бизнес-логику в атом только потому, что кнопка маленькая.
- Помимо нормального состояния проверяйте loading, disabled, ошибки, длинный текст и доступность.
- Метод можно сочетать с организацией по функциональности; он решает другой уровень задачи.

## Что важно помнить

- Уровни: атомы → молекулы → организмы → шаблоны → страницы.
- Подход хорошо подходит для UI-кита и дизайн-системы, но не описывает бизнес-логику.
- Границы между уровнями бывают спорными — договоритесь в команде.
- Часто сочетают с Storybook и Feature-Sliced Design для бизнес-кода.

## Мини-шпаргалка

```text
Atom → Molecule → Organism → Template → Page
Размер/роль UI-блоков ≠ слои бизнес-архитектуры
```
