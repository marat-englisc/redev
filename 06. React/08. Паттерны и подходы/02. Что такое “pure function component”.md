# Чистый функциональный компонент

> [!NOTE]
> Чистый render возвращает одинаковое описание UI при одинаковых входных данных и не изменяет значения, существовавшие до его вызова.

## Вопрос

Что означает чистота компонента? Делают ли `useState` и `useEffect` компонент нечистым?

## Render должен быть вычислением

Входами компонента являются не только props, но также state и context. Для одного и того же снимка этих данных render должен быть предсказуемым. Нельзя во время вычисления добавлять записи в общий массив, менять переданный объект или отправлять необратимое действие на сервер.

React может повторно вызвать компонент, не подтвердить результат или начать подготовку заново. Если каждый такой вызов добавляет товар в корзину, количество покупок будет зависеть от внутреннего планирования React. Это и объясняет требование чистоты: вызов компонента не должен становиться бизнес-событием.

Хуки не нарушают принцип сами по себе. `useState` предоставляет вход текущего снимка, а эффект выполняет синхронизацию после commit. Обработчик события также является отдельным местом для действий. Локальная мутация нового объекта, созданного в текущем вычислении, допустима: проблема возникает при изменении общих входных объектов.

## Пример

```jsx
import { useState } from 'react';

function Receipt({ items }) {
  // Копия позволяет сортировать, не меняя входной массив.
  const sorted = [...items].sort((a, b) => a.name.localeCompare(b.name));
  const total = sorted.reduce((sum, item) => sum + item.price, 0);
  return (
    <section>
      <ul>
        {sorted.map((item) => (
          <li key={item.id}>{item.name}</li>
        ))}
      </ul>
      <p>Итого: {total} ₽</p>
    </section>
  );
}

export default function Shop() {
  const [items, setItems] = useState([{ id: 'tea', name: 'Чай', price: 200 }]);
  return (
    <>
      <Receipt items={items} />
      <button
        onClick={() =>
          setItems((list) => [
            ...list,
            { id: crypto.randomUUID(), name: 'Печенье', price: 100 },
          ])
        }
      >
        Добавить печенье
      </button>
    </>
  );
}
```

`Receipt` вычисляет порядок и сумму, не меняя `items`. Новый ID создается при пользовательском действии, а не в render. Повторное вычисление чека не добавляет новую покупку.

## Частые ошибки

- `items.sort()` напрямую изменяет входной массив; сначала сделайте копию.
- `Date.now()` или `Math.random()` как основа отображения делают render недетерминированным без явной модели данных.
- Чистый компонент не обязательно обернут в `memo`: чистота — требование поведения, мемоизация — оптимизация.
- Не переносите любую логику в эффекты: обычные расчеты остаются в render.

## Что важно помнить

- Чистый компонент при одинаковых props, state и контексте возвращает одинаковый JSX.
- Во время рендера нельзя мутировать внешние переменные, props и state, делать запросы.
- Strict Mode вызывает рендер дважды, чтобы выявить нечистый код.
- Побочные эффекты — в обработчиках событий и `useEffect`.

## Мини-шпаргалка

```text
Одинаковые props/state/context → одинаковый UI
Не мутировать входы; действия → события/эффекты
pure component ≠ memoized component
```
