# Feature-Sliced Design: слои, слайсы и публичные границы

> [!NOTE]
> Feature-Sliced Design, FSD, организует frontend по назначению кода и регулирует зависимости между модулями. Правильное название — Feature-Sliced, а не Feature Slided.

## Вопрос

Как устроены слои FSD? Что такое slice, segment и публичный API?

## Три уровня организации

**Layer** — слой с определенной ролью. В распространенной актуальной структуре используются `app`, `pages`, `widgets`, `features`, `entities`, `shared`. Исторический `processes` считается устаревшим: создавать его автоматически не нужно. Необязательно заводить все остальные слои заранее.

**Slice** — модуль по бизнес-смыслу внутри слоя: `entities/book`, `features/add-to-cart`, `pages/catalog`. **Segment** — часть модуля по техническому назначению: `ui`, `model`, `api`, `lib`, `config`. Например, UI кнопки и логика добавления книги находятся рядом внутри одной фичи.

Основное правило: slice может импортировать другие slices только из строго нижележащих слоев. `features/add-to-cart` может использовать `entities/book`, но не соседнюю `features/login`. Сценарий, объединяющий несколько фич, собирают выше. Для `app` и `shared` действуют особенности: они не делятся на бизнес-слайсы, а их сегменты могут взаимодействовать внутри своего слоя. Для необходимых связей между сущностями предусмотрены явные cross-reference API `@x`.

## Назначение слоев

| Слой | Что содержит | Пример |
| --- | --- | --- |
| `app` | Инициализация, провайдеры, маршруты | Настройка приложения |
| `pages` | Экраны и относящийся к ним код | Каталог |
| `widgets` | Крупные самостоятельные блоки | Шапка, панель заказа |
| `features` | Значимые действия пользователя | Добавить в корзину |
| `entities` | Бизнес-сущности и их представление | Книга, заказ |
| `shared` | Общая техническая основа | UI-kit, HTTP-клиент |

## Пример

```text
src/
  app/
  pages/catalog/ui/CatalogPage.tsx
  features/add-to-cart/
    ui/AddToCartButton.tsx
    model/useAddToCart.ts
    index.ts
  entities/book/
    model/types.ts
    index.ts
  shared/ui/button/
```

```tsx
// entities/book/model/types.ts
export type Book = { id: string; title: string };

// entities/book/index.ts
export type { Book } from './model/types';
```

```tsx
// features/add-to-cart/ui/AddToCartButton.tsx
import type { Book } from '../../../entities/book';

type Props = { book: Book; onAdd: (id: string) => void };
export function AddToCartButton({ book, onAdd }: Props) {
  return <button onClick={() => onAdd(book.id)}>Купить {book.title}</button>;
}

// features/add-to-cart/index.ts
export { AddToCartButton } from './ui/AddToCartButton';
```

Каждый комментарий с именем файла обозначает отдельный файл. Верхние уровни используют публичный `index.ts`, не импортируя произвольные внутренности фичи. Правила можно проверять линтером.

## Нюансы

- Страница может содержать много собственной логики: не нужно выносить каждый локальный блок в feature или widget.
- Публичное API должно быть небольшим и осмысленным; `export *` из всего подряд размывает границы.
- Папки сами по себе не дают изоляцию без правил импортов.

## Что важно помнить

- Правильное название — Feature-Sliced Design (FSD).
- Слои: app → pages → widgets → features → entities → shared; импорт только из нижележащих слоев.
- Каждый слайс экспортирует публичный API через `index.ts`.
- Линтер `steiger` или правила ESLint помогают контролировать границы.

## Мини-шпаргалка

```text
app → pages → widgets → features → entities → shared
Slice = бизнес-модуль; segment = назначение его кода
processes — deprecated
```
