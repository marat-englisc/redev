# Slot Pattern: именованные места для содержимого

> [!NOTE]
> Slot Pattern позволяет контейнеру определить несколько областей интерфейса, а вызывающей стороне — передать содержимое каждой области через props.

## Вопрос

Когда именованные слоты удобнее одного `children` и чем слот отличается от render prop?

## Контейнер отвечает за размещение

У карточки есть заголовок, действия и основная часть. Если передавать все одним плоским `children`, потребителю придется самостоятельно соблюдать структуру. Именованные props `header` и `actions` делают контракт явным: компонент знает, где разместить каждую часть, но не навязывает ее конкретное содержание.

Обычно слот принимает `ReactNode`: текст, элемент, фрагмент или другое допустимое содержимое. Основную область часто оставляют в `children`. Это обычная композиция средствами React, а не специальный встроенный API с регистрацией слотов.

Если контейнеру требуется передать собственные данные при создании содержимого, можно использовать функцию вместо готового узла. Тогда соответствующий prop становится render prop. Например, `footer={<Button />}` — готовое содержимое, а `renderFooter={state => <Button disabled={state.pending} />}` — функция отображения.

## Пример

```tsx
import { useState, type ReactNode } from 'react';

type PanelProps = {
  header: ReactNode;
  actions?: ReactNode;
  children: ReactNode;
  footer?: ReactNode;
};

function Panel({ header, actions, children, footer }: PanelProps) {
  return (
    <section>
      <header>
        {header}
        <div>{actions}</div>
      </header>
      <div>{children}</div>
      {footer && <footer>{footer}</footer>}
    </section>
  );
}

export default function App() {
  const [saved, setSaved] = useState(false);
  return (
    <Panel
      header={<h2>Черновик письма</h2>}
      actions={<button onClick={() => setSaved(true)}>Сохранить</button>}
      footer={<small>{saved ? 'Сохранено' : 'Изменения не сохранены'}</small>}
    >
      <p>Здравствуйте! Приглашаем на собеседование.</p>
    </Panel>
  );
}
```

`Panel` управляет расположением областей. Кнопка и статус получают поведение снаружи: контейнер можно использовать для другого содержимого без знания о сохранении письма.

## Нюансы

- `children` не ограничен одним элементом. Именованные слоты добавляют роли, а не обходят такое ограничение.
- Переданный JSX не следует без необходимости клонировать и изменять скрытым образом.
- React-слоты через props отличаются от нативного HTML `<slot>` в Shadow DOM.
- Если компонент называется `Modal`, дополнительно нужны управление фокусом, Escape и доступная диалоговая семантика; одних слотов недостаточно.

## Что важно помнить

- Слоты — передача нескольких JSX-фрагментов через именованные props: `header`, `footer`, `actions`.
- `children` — слот по умолчанию; дополнительные слоты — обычные props типа `ReactNode`.
- Слоты дают гибкость разметки без множества булевых флагов.
- Аналогичная идея есть в Vue (`<slot>`) и Web Components.

## Мини-шпаргалка

```text
header/actions/footer → именованные ReactNode props
children → основная область
Нужны данные контейнера → функция render prop
```
