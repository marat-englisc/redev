# Higher-Order Component (HOC)

> [!NOTE]
> **HOC (компонент высшего порядка)** — функция, которая принимает компонент и возвращает новый компонент с дополнительным поведением: `withAuth(Dashboard)`, `withLoading(List)`, `connect(mapState)(Component)`. Это паттерн JavaScript, а не API React. HOC был основным способом переиспользовать логику до хуков; сейчас его чаще заменяют кастомными хуками, но он всё еще встречается в библиотеках и для оберток вокруг компонентов.

## Вопрос

Что такое HOC? Как его написать, какие у него проблемы и чем его заменили хуки?

## Основная идея

```jsx
function withAuth(Component) {
  function WithAuth(props) {
    const { user, isLoading } = useSession();
    if (isLoading) return <Spinner />;
    if (!user) return <Navigate to="/login" />;
    return <Component {...props} user={user} />;
  }
  WithAuth.displayName = `withAuth(${Component.displayName || Component.name})`;
  return WithAuth;
}

const ProtectedDashboard = withAuth(Dashboard);
```

HOC:

- принимает компонент, возвращает новый;
- прокидывает все props (`{...props}`) и добавляет свои;
- не изменяет исходный компонент;
- задает `displayName` для React DevTools.

Классические примеры: `connect` из React Redux, `withRouter` из старого React Router, `withTranslation` из react-i18next, `observer` из MobX.

## Проблемы HOC

| Проблема | Пояснение |
| --- | --- |
| «Обертка ада» | `withA(withB(withC(Component)))` — глубокое дерево в DevTools |
| Конфликт имен props | два HOC добавляют prop `data` — один перезапишет другой |
| Неявность | по компоненту не видно, откуда пришел prop |
| Типизация | сложно типизировать в TypeScript |
| Ref | нужен `forwardRef` (в React 18) |
| Статические методы | не копируются автоматически |

## Хуки вместо HOC

```jsx
function Dashboard() {
  const { user, isLoading } = useSession();
  if (isLoading) return <Spinner />;
  if (!user) return <Navigate to="/login" />;
  return <h1>Привет, {user.name}</h1>;
}
```

Хук делает зависимость явной, не меняет дерево компонентов и не конфликтует с другими.

## Когда HOC всё еще уместен

- обернуть компонент целиком: защита маршрута, Error Boundary, Suspense, профилирование;
- библиотеки, которым нужно работать с произвольными компонентами (`memo`, `observer` — по сути тоже HOC);
- legacy-код с классами, где хуки недоступны.

```jsx
export default memo(ExpensiveChart); // memo — встроенный HOC
```

## Что важно помнить

- Не создавайте HOC внутри `render` — каждый вызов дает новый компонент и сбрасывает состояние.
- Прокидывайте все props, иначе обертка «съест» данные.
- HOC — функция высшего порядка для компонентов, та же идея, что и декоратор.
- В современных кодовых базах на собеседовании ожидают ответ «HOC знаю, но предпочитаю хуки и композицию».

## Мини-шпаргалка

HOC = функция Component → новый Component. Добавляет поведение, прокидывает props, задает displayName. Проблемы: вложенность, конфликты props, неявность. Замена — кастомные хуки. `memo` и `connect` — примеры HOC.
