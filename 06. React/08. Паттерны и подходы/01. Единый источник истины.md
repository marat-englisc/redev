# Единый источник истины для каждого значения

> [!NOTE]
> У каждого значимого значения должен быть понятный владелец. Другие части интерфейса получают это значение или вычисляют из него производные данные.

## Вопрос

Почему дублирование state приводит к рассинхронизации? Обязательно ли хранить все в глобальном store?

## Один владелец, несколько потребителей

Если сумма корзины записана отдельно от списка товаров, легко обновить товары и забыть сумму. Два значения описывают один факт, но могут противоречить друг другу. Часто правильнее хранить товары, а сумму вычислять из их цены и количества.

Если двум соседним компонентам нужно одно состояние, его поднимают к ближайшему общему родителю. Родитель передает значение вниз через props, а дети сообщают о намерении изменить его через callback. Это называется **lifting state up**.

Принцип не требует одного гигантского объекта на все приложение. Черновик поля может принадлежать форме, открытая вкладка — панели, пользователь — общему провайдеру. Важно не количество хранилищ, а отсутствие нескольких несогласованных владельцев одного и того же факта. Осознанный черновик редактирования тоже допустим: он является отдельным состоянием со своим жизненным циклом.

## Пример

```jsx
import { useState } from 'react';

function TicketPicker({ count, onChange }) {
  return <button onClick={() => onChange(count + 1)}>Билетов: {count}</button>;
}

function Summary({ count, price }) {
  return <p>К оплате: {count * price} ₽</p>;
}

export default function Booking() {
  const [count, setCount] = useState(1);
  return (
    <>
      <TicketPicker count={count} onChange={setCount} />
      <Summary count={count} price={500} />
    </>
  );
}
```

Количество хранится только в `Booking`. Обе части получают один снимок `count`, а сумма не имеет отдельного setter. После увеличения количества невозможно забыть обновить итог: он вычисляется из актуальных входных данных.

## Что важно помнить

- Копирование prop в `useState(prop)` не создает автоматическую синхронизацию: это только первоначальная инициализация.
- Производные данные обычно вычисляют во время render, а не обновляют через эффект.
- Серверные данные, URL и локальный черновик могут иметь разных владельцев; связь между ними должна быть явной.
- Поднимайте состояние настолько высоко, насколько нужно потребителям, а не автоматически в корень.

## Мини-шпаргалка

```text
Одно значение → один владелец
Общий родитель → props вниз, события вверх
Производное значение → вычисление, если отдельный state не нужен
```
