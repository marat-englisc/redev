# Container–Presentational и Smart–Dumb компоненты

> [!NOTE]
> Паттерн разделяет компоненты на два вида. **Container (smart)** знает, откуда брать данные и как их менять: загружает, хранит состояние, вызывает API. **Presentational (dumb)** только отображает: получает данные и колбэки через props, не знает о сети и store. Это одно и то же разделение под двумя названиями. С появлением хуков логику часто выносят в **кастомные хуки**, а не в отдельные компоненты-контейнеры.

## Вопрос

Что такое container и presentational компоненты? Что такое smart и dumb компоненты и актуален ли этот паттерн с хуками?

## Основная идея

```jsx
// presentational (dumb): только UI
function UserList({ users, isLoading, onSelect }) {
  if (isLoading) return <Spinner />;
  return (
    <ul>
      {users.map((u) => (
        <li key={u.id}>
          <button onClick={() => onSelect(u.id)}>{u.name}</button>
        </li>
      ))}
    </ul>
  );
}

// container (smart): данные и логика
function UserListContainer() {
  const { data = [], isLoading } = useQuery({ queryKey: ["users"], queryFn: fetchUsers });
  const navigate = useNavigate();
  return <UserList users={data} isLoading={isLoading} onSelect={(id) => navigate(`/users/${id}`)} />;
}
```

| | Container / Smart | Presentational / Dumb |
| --- | --- | --- |
| Задача | как работает | как выглядит |
| Данные | загружает, хранит, меняет | получает через props |
| Знает о API, store, роутере | да | нет |
| Состояние | бизнес-состояние | только UI-состояние (раскрыт ли список) |
| Переиспользование | низкое | высокое |
| Тестирование | с моками данных | просто: props → разметка |
| Storybook | неудобно | идеально |

## С хуками

Дэн Абрамов, популяризировавший паттерн, позже отметил, что не стоит применять его догматично: хуки позволяют вынести логику без лишнего компонента-обертки.

```jsx
function useUsers() {
  const query = useQuery({ queryKey: ["users"], queryFn: fetchUsers });
  return { users: query.data ?? [], isLoading: query.isLoading };
}

function UsersPage() {
  const { users, isLoading } = useUsers();
  const navigate = useNavigate();
  return <UserList users={users} isLoading={isLoading} onSelect={(id) => navigate(`/users/${id}`)} />;
}
```

Идея разделения ответственности осталась: UI-компоненты остаются «глупыми», логика живет в хуках, страницах и сервисах.

## Где разделение особенно полезно

- дизайн-система и UI-кит — только presentational-компоненты;
- компоненты, которые показывают одни данные из разных источников;
- изолированная разработка в Storybook и визуальные тесты;
- Server Components в Next.js: серверный компонент загружает данные (контейнер), клиентский отвечает за интерактивность.

## Что важно помнить

- «Dumb» не значит «без состояния»: локальный UI-state (открыт/закрыт) — нормально.
- Не создавайте контейнер ради одного `useState` — это лишний слой.
- Presentational-компонент удобно типизировать: props полностью описывают его поведение.
- Похожие идеи: MVVM, разделение на features/entities/shared в Feature-Sliced Design.

## Мини-шпаргалка

Container = Smart = данные и логика. Presentational = Dumb = UI через props. С хуками логику выносят в кастомные хуки. Цель — разделение ответственности, а не догма.
