# BrowserRouter и HashRouter

> [!NOTE]
> BrowserRouter использует обычный путь URL и браузерную историю. HashRouter хранит путь приложения во фрагменте после `#`, который не отправляется серверу.

## Вопрос

Почему BrowserRouter требует поддержки прямых URL на сервере, а HashRouter часто удобен для простого статического хостинга?

## Разница при прямом открытии

При адресе `https://example.com/books/42` сервер получает запрос `/books/42`. Для SPA он должен вернуть точку входа приложения по этому пути. Иначе переход внутри уже открытого приложения может работать, а обновление вкладки — приводить к серверному 404.

При `https://example.com/#/books/42` сервер получает путь `/`: фрагмент после `#` остается в браузере. После загрузки HTML HashRouter читает его и выбирает страницу. Хостингу достаточно корректно обслужить базовый документ и ресурсы; поддерживать каждый маршрут приложения не требуется.

Обычные пути чаще удобнее для ссылок, серверной обработки и поисковых систем. Но чистый адрес сам по себе не дает SSR, метаданные или хорошую индексацию. Выбор роутера — техническая часть доставки приложения, а не гарантия SEO или скорости.

## Пример

**React Router 7, декларативный режим.** Здесь выберите один роутер для всего приложения.

```jsx
import { BrowserRouter, HashRouter, Link, Route, Routes } from 'react-router';

function Pages() {
  return (
    <>
      <nav>
        <Link to="/">Главная</Link> <Link to="/books/42">Книга</Link>
      </nav>
      <Routes>
        <Route path="/" element={<h1>Главная</h1>} />
        <Route path="/books/42" element={<h1>Книга №42</h1>} />
      </Routes>
    </>
  );
}

export default function App() {
  const Router = HashRouter; // замените на BrowserRouter для обычных путей
  return (
    <Router>
      <Pages />
    </Router>
  );
}
```

С `HashRouter` ссылка создаст адрес `/#/books/42`. С `BrowserRouter` — `/books/42`. Определения `Route` при этом остаются одинаковыми: различается способ хранения адреса.

## Настройка и ограничения

- SPA-fallback направляют на `index.html` для маршрутов интерфейса, а не бездумно для всех запросов: API и отсутствующие assets должны обрабатываться отдельно.
- Если приложение размещено в подпапке, учтите базовый путь и адреса ресурсов.
- HashRouter не гарантирует работу «на любом сервере»: базовый HTML и assets все равно должны быть доступны.
- Фрагмент уже занят маршрутизацией, поэтому обычные якоря страницы требуют согласованного решения.

## Что важно помнить

- BrowserRouter использует History API и чистые URL `/users/42`; серверу нужна настройка fallback на `index.html`.
- HashRouter хранит путь после `#` — сервер его не видит, настройка не нужна.
- Hash-URL хуже для SEO и выглядят менее аккуратно.
- HashRouter подходит для статического хостинга без настройки и встроенных приложений.

## Мини-шпаргалка

```text
BrowserRouter: /books/42 → сервер должен обслужить путь
HashRouter: /#/books/42 → сервер не видит фрагмент
Оба поддерживают клиентскую навигацию
```
