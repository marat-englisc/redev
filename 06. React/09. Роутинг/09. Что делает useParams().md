# useParams: динамические сегменты пути

> [!NOTE]
> `useParams` читает значения именованных сегментов совпавшего маршрута. Параметры URL приходят строками и требуют проверки перед использованием.

## Вопрос

Как `/books/42` превращается в `{ bookId: '42' }` и почему TypeScript не заменяет валидацию адреса?

## Имя берется из маршрута

В `path="/books/:bookId"` двоеточие обозначает динамический сегмент. Маршрутизатор сопоставляет `/books/42`, сохраняет значение под именем `bookId` и предоставляет его компоненту через `useParams`. При нескольких сегментах доступно несколько значений.

Это именно части пути, а не query-параметры. Для `/books/42?page=2` значение `bookId` читают через `useParams`, а `page` — через `useSearchParams`. Вложенные маршруты также наследуют параметры родителей. Необязательный сегмент может отсутствовать, поэтому соответствующее значение будет `undefined`.

URL вводит пользователь, ссылка может быть ошибочной, а серверная сущность — удаленной. Приведение `Number(bookId)` само по себе не доказывает корректность. Проверяют формат, диапазон и существование данных. Типизация хука описывает ожидание разработчика, но не превращает неизвестную строку в доверенное число.

## Пример

**React Router 7, декларативный режим.**

```jsx
import { BrowserRouter, Link, Route, Routes, useParams } from 'react-router';

const books = { 42: 'Дюна', 73: 'Солярис' };

function BookPage() {
  const { bookId } = useParams();
  const id = Number(bookId);
  if (!bookId || !/^[1-9]\d*$/.test(bookId) || !Number.isSafeInteger(id)) {
    return <p>Некорректный номер книги.</p>;
  }
  const title = books[id];
  if (!title) return <p>Книга не найдена.</p>;
  return (
    <h1>
      {title}, номер {id}
    </h1>
  );
}

export default function App() {
  return (
    <BrowserRouter>
      <nav>
        <Link to="/books/42">Книга №42</Link>{' '}
        <Link to="/books/wrong">Некорректный номер</Link>
      </nav>
      <Routes>
        <Route path="/" element={<p>Выберите книгу</p>} />
        <Route path="/books/:bookId" element={<BookPage />} />
      </Routes>
    </BrowserRouter>
  );
}
```

`42` проходит проверку, `wrong` — нет, а корректный, но отсутствующий ID дает отдельное сообщение. Для API это также разные случаи: неверный адрес и отсутствие ресурса.

## Нюансы

- Не делайте дополнительный `decodeURIComponent` без необходимости: роутер уже обрабатывает параметры.
- При переходе между ID тот же тип страницы может сохранить экземпляр; запрос и вычисления должны учитывать новый параметр.
- Проверка параметра не заменяет серверную проверку полномочий на ресурс.
- Используйте `element={<BookPage />}`, не старый `component={BookPage}`.

## Что важно помнить

- `useParams` возвращает динамические сегменты пути: для `/users/:id` — `{ id }`.
- Значения всегда строки или `undefined` — приводите типы и валидируйте.
- При смене параметра компонент не размонтируется — эффекты должны зависеть от параметра.
- Чтобы сбросить state при смене id, используйте `key={id}`.

## Мини-шпаргалка

```text
/books/:bookId + /books/42 → bookId === '42'
useParams → path segments
useSearchParams → query
```
