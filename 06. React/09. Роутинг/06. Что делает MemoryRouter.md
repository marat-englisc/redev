# MemoryRouter: история маршрутов в памяти

> [!NOTE]
> MemoryRouter хранит записи истории внутри приложения и не меняет адресную строку браузера. Начальную историю можно задать явно.

## Вопрос

Почему MemoryRouter удобен для тестов и демонстраций маршрутизируемых компонентов?

## Управляемая среда навигации

Обычный BrowserRouter связан с браузерным URL. Для отдельной демонстрации формы или теста это не всегда удобно: изменение адреса влияет на окружение, а подготовка истории требует дополнительных действий.

MemoryRouter создает свою историю. `initialEntries` задает список записей, а `initialIndex` выбирает начальную позицию. Это позволяет начать сразу с `/books/42`, проверить возврат или показать определенную страницу в Storybook без изменения адреса самого Storybook.

Не нужно объяснять его пользу отсутствием `window` во всех тестах. Среда JSDOM предоставляет DOM, `window.location` и часть History API, поэтому BrowserRouter тоже может работать в соответствующих тестах. MemoryRouter выбирают за изолированную и предсказуемую историю. Для отображения DOM в тесте по-прежнему нужна подходящая среда: роутер не заменяет браузерные API целиком.

## Пример

**React Router 7, декларативный режим.** Пример можно отобразить как обычный компонент без дополнительных тестовых библиотек.

```jsx
import { Link, MemoryRouter, Route, Routes, useNavigate } from 'react-router';

function Book() {
  const navigate = useNavigate();
  return (
    <>
      <h1>Книга №42</h1>
      <button onClick={() => navigate(-1)}>Назад в каталог</button>
    </>
  );
}

export default function Preview() {
  return (
    <MemoryRouter initialEntries={['/catalog', '/books/42']} initialIndex={1}>
      <Routes>
        <Route
          path="/catalog"
          element={
            <>
              <h1>Каталог</h1>
              <Link to="/books/42">Открыть книгу</Link>
            </>
          }
        />
        <Route path="/books/42" element={<Book />} />
      </Routes>
    </MemoryRouter>
  );
}
```

Сначала отображается книга, поскольку индекс `1` указывает на вторую запись. Кнопка возвращает внутреннюю историю к каталогу. Адрес вкладки не меняется. В тесте можно нажать кнопку и проверить появление текста «Каталог».

## Нюансы

- `initialEntries` описывает начальную конфигурацию, а не реактивный способ выполнять переходы после монтирования.
- Не оборачивайте компонент одновременно MemoryRouter и уже существующим BrowserRouter.
- Для Data mode есть отдельный `createMemoryRouter`; это другой способ настройки.
- Для реального SSR выбирают предусмотренную серверную интеграцию, а не используют MemoryRouter как универсальную замену.

## Что важно помнить

- MemoryRouter хранит историю в памяти и не меняет адресную строку.
- Основное применение — тесты и Storybook: можно задать `initialEntries`.
- Также подходит для встраиваемых виджетов и React Native.
- Перезагрузка страницы сбрасывает историю MemoryRouter.

## Мини-шпаргалка

```text
История в памяти → адрес вкладки прежний
initialEntries → записи
initialIndex → стартовая позиция
```
