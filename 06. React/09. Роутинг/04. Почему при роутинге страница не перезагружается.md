# Почему клиентская навигация не перезагружает страницу

> [!NOTE]
> React Router может обработать внутренний переход, обновить историю браузера и интерфейс без загрузки нового HTML-документа.

## Вопрос

Что делает `Link` и почему `history.pushState` само по себе недостаточно для полноценного роутера?

## От клика к новому дереву

`Link` выводит настоящую ссылку с адресом. Для подходящего внутреннего клика маршрутизатор отменяет стандартную загрузку документа и проводит переход через свой механизм навигации. `BrowserRouter` использует браузерную историю, а React получает новое location и отображает совпавшую ветку маршрутов.

Одна лишь команда `history.pushState` меняет адрес и запись истории, но сама по себе не обязана сообщить React, что нужно отобразить другую страницу. Роутер связывает изменение истории с реактивным состоянием и обрабатывает движение «Назад/Вперед». Это существенно больше, чем ручная замена URL.

Внешние ссылки, открытие в новой вкладке и специальные клики сохраняют подходящее браузерное поведение. Кроме того, у `Link` есть `reloadDocument`, если нужен обычный документный переход. React не запрещает перезагрузку: ее отсутствие относится к конкретному способу навигации.

## Пример

**React Router 7, декларативный режим.**

```jsx
import { useState } from 'react';
import { BrowserRouter, Link, Route, Routes } from 'react-router';

function Shell() {
  const [count, setCount] = useState(0);
  return (
    <>
      <button onClick={() => setCount((n) => n + 1)}>
        Общий счетчик: {count}
      </button>
      <nav>
        <Link to="/catalog">Каталог без нового документа</Link>{' '}
        <Link to="/catalog" reloadDocument>
          Каталог с загрузкой документа
        </Link>
      </nav>
      <Routes>
        <Route path="/" element={<h1>Главная</h1>} />
        <Route path="/catalog" element={<h1>Каталог</h1>} />
      </Routes>
    </>
  );
}

export default function App() {
  return (
    <BrowserRouter>
      <Shell />
    </BrowserRouter>
  );
}
```

Увеличьте счетчик и перейдите первой ссылкой: `Shell` остается в дереве, поэтому число сохраняется. Вторая ссылка загружает новый документ; состояние в памяти начинается заново.

## Нюансы

- Данные и chunks страницы могут загружаться по сети даже без документного перехода.
- State покидаемой страницы может исчезнуть при ее размонтировании.
- Ненастроенный SPA-fallback вызывает ошибку при прямом открытии или обновлении URL, но не является причиной внезапной перезагрузки обычного `Link`.
- Для внешнего сайта обычно используют обычный `<a href="...">`.

## Что важно помнить

- `<Link>` перехватывает клик, отменяет поведение по умолчанию и вызывает `history.pushState`.
- Роутер слушает изменения истории (`popstate`) и перерисовывает нужный маршрут.
- Обычный `<a href>` вызовет полную перезагрузку и потерю состояния.
- Ctrl+клик и средняя кнопка мыши продолжают открывать ссылку в новой вкладке.

## Мини-шпаргалка

```text
Link → router navigation → история + location → UI
reloadDocument / обычный a → браузер запрашивает документ
Без reload ≠ без сети
```
