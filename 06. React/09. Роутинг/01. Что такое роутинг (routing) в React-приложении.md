# Роутинг в React: связь URL и интерфейса

> [!NOTE]
> Роутинг определяет, какое дерево интерфейса соответствует текущему адресу. React сам по себе не включает полноценный маршрутизатор.

## Вопрос

Зачем React-приложению маршруты и какие задачи они решают помимо переключения компонентов?

## URL как адрес состояния приложения

Если каталог и карточка книги существуют только как локальный `useState('catalog')`, пользователю трудно поделиться конкретной страницей. Маршрут `/books/dune` дает странице адрес: его можно открыть напрямую, сохранить, обновить и восстановить через историю браузера.

Маршрутизатор сопоставляет путь с описанием маршрутов, передает параметры и позволяет строить общие layout-компоненты. В клиентской навигации он меняет интерфейс без загрузки нового HTML-документа целиком. При первом открытии или обновлении вкладки сервер все равно участвует в выдаче приложения.

Роутинг не означает автоматически сохранение состояния каждой страницы. Общий layout может остаться смонтированным, а покидаемая страница — размонтироваться и потерять локальный state. Важные сохраняемые фильтры часто размещают в URL, а общие данные — у подходящего владельца.

## Пример

Пример использует **React Router 7, декларативный режим**, с импортами из `react-router`. Установка: `npm install react-router@7`.

```jsx
import { BrowserRouter, Link, Route, Routes, useParams } from 'react-router';

function Home() {
  return <h1>Книжная полка</h1>;
}
function Book() {
  const { slug } = useParams();
  return <h1>Книга: {slug}</h1>;
}

export default function App() {
  return (
    <BrowserRouter>
      <nav>
        <Link to="/">Главная</Link> <Link to="/books/dune">Дюна</Link>
      </nav>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/books/:slug" element={<Book />} />
        <Route path="*" element={<h1>Страница не найдена</h1>} />
      </Routes>
    </BrowserRouter>
  );
}
```

При `/books/dune` параметр `slug` равен строке `'dune'`. Ссылка меняет маршрут внутри приложения; кнопка браузера «Назад» возвращает предыдущую запись истории.

## Нюансы

- Для `BrowserRouter` сервер должен корректно отдавать SPA по прямым адресам страниц.
- Hooks маршрутизатора вызываются внутри его контекста.
- Клиентское скрытие маршрута не защищает API: доступ проверяется сервером.
- В v7 пакет `react-router-dom` оставлен для совместимости; новые примеры могут импортировать браузерные API из `react-router`.

## Что важно помнить

- Роутинг сопоставляет URL с тем, какой компонент показать.
- В SPA роутер меняет URL через History API без перезагрузки страницы.
- Популярные решения: React Router, TanStack Router, роутинг фреймворков (Next.js App Router).
- Сервер должен отдавать `index.html` на любые пути SPA, иначе прямой переход даст 404.

## Мини-шпаргалка

```text
URL → совпавший Route → дерево интерфейса
Link → обычная клиентская навигация
:slug → динамическая часть пути
```
