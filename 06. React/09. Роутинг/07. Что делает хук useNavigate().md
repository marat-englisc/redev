# useNavigate: программная навигация

> [!NOTE]
> `useNavigate` возвращает функцию для перехода из кода: например, после успешной отправки формы или завершения пользовательского сценария.

## Вопрос

Когда нужен `navigate`, чем отличается `replace` и почему `navigate(-1)` не всегда означает возврат на нужную страницу?

## Переход как результат действия

Для обычной ссылки обычно лучше `<Link>`: он сохраняет семантику ссылки, открытие в новой вкладке и другие возможности браузера. `navigate` подходит, когда переход зависит от результата действия — например, сохранения заказа. Ошибка сохранения должна оставить пользователя на форме.

`navigate('/orders/42')` добавляет запись истории. Опция `replace: true` заменяет текущую запись, что бывает полезно после входа или завершения одноразового шага. Она не удаляет всю историю и не отключает кнопку «Назад» в браузере.

Число задает смещение в истории: `navigate(-1)` возвращает на предыдущую запись. Но пользователь мог открыть страницу напрямую или прийти с другого сайта. Поэтому для надежной кнопки «В каталог» часто лучше явный путь. В декларативном режиме v7 функция не предоставляет Promise завершения перехода, как это может происходить в Data/Framework mode.

## Пример

**React Router 7, декларативный режим.**

```jsx
import { useState } from 'react';
import { BrowserRouter, Link, Route, Routes, useNavigate } from 'react-router';

function Booking() {
  const [pending, setPending] = useState(false);
  const navigate = useNavigate();
  async function submit(event) {
    event.preventDefault();
    setPending(true);
    // Учебное успешное сохранение вместо API.
    const order = await Promise.resolve({ id: '42' });
    navigate(`/orders/${order.id}`, {
      replace: true,
      state: { justCreated: true },
    });
  }
  return (
    <form onSubmit={submit}>
      <button disabled={pending}>Оформить заказ</button>
    </form>
  );
}

export default function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<Booking />} />
        <Route
          path="/orders/:id"
          element={
            <>
              <h1>Заказ принят</h1>
              <Link to="/">Новый заказ</Link>
            </>
          }
        />
      </Routes>
    </BrowserRouter>
  );
}
```

После учебного сохранения текущая запись заменяется адресом заказа. В настоящем запросе нужно обработать ошибку и снять `pending`, если переход не состоялся.

## Нюансы

- Hook вызывается внутри компонента или кастомного хука под роутером; сам `navigate` затем используют в обработчике.
- Не вызывайте переход произвольно во время render. Для декларативного перенаправления предусмотрен `<Navigate>`.
- `location.state` не секретное хранилище и не замена URL для разделяемых параметров.
- Относительные переходы разрешаются с учетом структуры маршрутов; при сомнении используйте явный путь.

## Что важно помнить

- `useNavigate` возвращает функцию для программной навигации: `navigate('/path')`, `navigate(-1)`.
- Опция `replace: true` заменяет текущую запись истории — например, после логина.
- Через `state` можно передать данные, доступные в `useLocation().state`.
- Для обычных ссылок предпочтительнее `<Link>` — он доступнее и поддерживает открытие в новой вкладке.

## Мини-шпаргалка

```text
Link → пользователь выбирает ссылку
navigate(path) → переход после логики
replace → заменить текущую запись
navigate(-1) → предыдущая запись, не гарантированная страница
```
