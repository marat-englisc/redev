# useLocation: текущий адрес и запись истории

> [!NOTE]
> `useLocation` возвращает location маршрутизатора: путь, строку запроса, фрагмент, navigation state и ключ записи истории. Компонент реагирует на навигацию через React Router.

## Вопрос

Чем `useLocation` отличается от чтения `window.location` и какие данные содержатся в возвращаемом объекте?

## Адрес как реактивные данные

`window.location` — браузерный объект с полным адресом и методами документной навигации. Простое чтение этого объекта не подписывает компонент на изменения маршрутизатора. `useLocation` предоставляет location из контекста React Router и обновляет потребителя при соответствующей навигации.

`pathname` содержит путь, `search` — строку после `?` вместе с этим знаком, `hash` — фрагмент после `#`. Чтобы разобрать query, используйте `URLSearchParams` или `useSearchParams`. `state` содержит дополнительные данные, переданные через `Link` или `navigate`, а `key` помогает различать записи истории, в том числе с похожими URL.

Navigation state не отображается в адресной строке, но не является секретным. Ссылка, скопированная другому пользователю, не переносит это состояние. При прямом открытии страницы его может не быть. Перезагрузка при этом не обязана уничтожать browser history state, поэтому считать его гарантированно исчезающим тоже неверно.

## Пример

**React Router 7, декларативный режим.**

```jsx
import { BrowserRouter, Link, Route, Routes, useLocation } from 'react-router';

function Catalog() {
  const location = useLocation();
  const params = new URLSearchParams(location.search);
  return (
    <section>
      <h1>Каталог</h1>
      <p>Путь: {location.pathname}</p>
      <p>Сортировка: {params.get('sort') ?? 'обычная'}</p>
      <p>
        {location.state?.fromMenu ? 'Переход из меню' : 'Другой способ входа'}
      </p>
    </section>
  );
}

export default function App() {
  return (
    <BrowserRouter>
      <Link to="/catalog?sort=price" state={{ fromMenu: true }}>
        Недорогие книги
      </Link>
      <Routes>
        <Route path="/" element={<p>Выберите каталог</p>} />
        <Route path="/catalog" element={<Catalog />} />
      </Routes>
    </BrowserRouter>
  );
}
```

Переход по ссылке задает query и navigation state. При передаче только адреса `/catalog?sort=price` другому пользователю сортировка сохранится, а информация `fromMenu` не переносится.

## Нюансы

- Для изменения location используйте `Link`, `navigate` или `setSearchParams`, а не мутируйте объект.
- Эффект аналитики может зависеть от `pathname` или всего location — выбирайте, какие изменения считать новым просмотром.
- `useLocation` не заменяет `useParams`: динамические параметры берут из сопоставленного маршрута.
- Переданные данные рассматривают как недоверенные и проверяют перед использованием.

## Что важно помнить

- `useLocation` возвращает текущий объект location: `pathname`, `search`, `hash`, `state`, `key`.
- Компонент перерендеривается при каждом изменении location.
- Удобно для аналитики просмотров страниц и анимаций переходов.
- Для query-параметров удобнее `useSearchParams`.

## Мини-шпаргалка

```text
pathname → /catalog
search → ?sort=price
hash → #details
state → дополнительные данные записи
key → идентификатор записи истории
```
