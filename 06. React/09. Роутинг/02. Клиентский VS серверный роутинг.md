# Клиентский и серверный роутинг

> [!NOTE]
> Серверный роутинг обрабатывает запрос адреса на сервере. Клиентский роутинг меняет представление в текущем документе средствами JavaScript. Эти подходы могут сочетаться.

## Вопрос

Что происходит при переходе на серверном сайте и при клиентской навигации в SPA?

## Кто обрабатывает переход

При обычном переходе по ссылке браузер запрашивает новый документ. Сервер выбирает обработчик по URL и возвращает ответ. Браузер создает новую страницу. Это не обязательно заметный «белый экран» или медленная работа: результат зависит от сети, кеширования, сервера и браузера.

При клиентской навигации маршрутизатор обрабатывает подходящий клик, меняет запись истории и показывает другое дерево компонентов в существующем документе. HTML целиком не запрашивается заново. Но данные и код новой страницы по-прежнему могут требовать сетевых запросов, поэтому «без перезагрузки» не означает «без сервера» или «мгновенно».

Способ навигации отличается от стратегии рендеринга. Приложение может получить начальный HTML через SSR, затем гидратироваться и выполнять следующие переходы на клиенте. Обычный клиентский React Router тоже требует, чтобы сервер выдавал приложение при прямом открытии URL.

## Сравнение

| Свойство | Переход с новым документом | Клиентская навигация |
| --- | --- | --- |
| Основной переход | Запрос HTML-документа | Обновление текущего UI |
| Состояние в памяти JS | Начинается в новом документе | Сохраняется у оставшихся экземпляров |
| Запросы данных | Могут быть на сервере и клиенте | Тоже возможны |
| Прямое открытие ссылки | Обрабатывает сервер | Сервер должен выдать точку входа |

## Пример

**React Router 7, декларативный режим.**

```jsx
import { BrowserRouter, Link, Route, Routes } from 'react-router';

export default function App() {
  return (
    <BrowserRouter>
      <nav>
        <Link to="/about">Клиентский переход</Link>{' '}
        <a href="/about">Открыть новый документ</a>
      </nav>
      <Routes>
        <Route path="/" element={<h1>Главная</h1>} />
        <Route path="/about" element={<h1>О магазине</h1>} />
      </Routes>
    </BrowserRouter>
  );
}
```

Обе ссылки ведут на один адрес, но используют разный механизм. Первая сохраняет текущий документ. Вторая выполняет обычную браузерную навигацию и проверяет, умеет ли сервер обслужить `/about`.

## Нюансы

- SEO определяется доступным содержимым, рендерингом и метаданными, а не только наличием `BrowserRouter`.
- Локальный state размонтированной страницы не сохраняется автоматически даже при клиентской навигации.
- Полноценная серверная обработка маршрутов и SPA-fallback — разные серверные стратегии.

## Что важно помнить

- Серверный роутинг: каждый переход — новый HTTP-запрос и полная загрузка страницы.
- Клиентский роутинг: JS перехватывает переход и рендерит новую страницу без перезагрузки.
- Клиентский быстрее при навигации, но первый показ и SEO лучше с серверным или SSR.
- Современные фреймворки комбинируют оба: первый запрос на сервере, дальше — клиентская навигация.

## Мини-шпаргалка

```text
Серверный переход → новый документ
Клиентский переход → текущий документ, новое дерево
SSR + client navigation → совместимая комбинация
```
