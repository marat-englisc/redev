# Вложенные маршруты (nested routes) и Outlet

> [!NOTE]
> **Вложенные маршруты** — маршруты, которые отображаются **внутри** родительского маршрута: родитель рендерит общую часть (шапку, меню, вкладки), а дочерний маршрут — изменяемую область. Место, куда React Router подставляет дочерний маршрут, обозначают компонентом `<Outlet />`. URL вложенного маршрута складывается из путей родителя и ребенка: `/dashboard` + `settings` = `/dashboard/settings`.

## Вопрос

Что такое nested routes? Что делает `Outlet` и как устроены вложенные маршруты?

## Основная идея

```jsx
import { BrowserRouter, Routes, Route, Outlet, NavLink } from "react-router";

function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<RootLayout />}>
          <Route index element={<Home />} />                {/* "/" */}
          <Route path="dashboard" element={<DashboardLayout />}>
            <Route index element={<Overview />} />          {/* "/dashboard" */}
            <Route path="settings" element={<Settings />} /> {/* "/dashboard/settings" */}
            <Route path="users/:id" element={<User />} />    {/* "/dashboard/users/42" */}
          </Route>
          <Route path="*" element={<NotFound />} />
        </Route>
      </Routes>
    </BrowserRouter>
  );
}

function DashboardLayout() {
  return (
    <div className="dashboard">
      <nav>
        <NavLink to="." end>Обзор</NavLink>
        <NavLink to="settings">Настройки</NavLink>
      </nav>
      <main>
        <Outlet />   {/* сюда подставится Overview, Settings или User */}
      </main>
    </div>
  );
}
```

## Как это работает

```text
URL: /dashboard/settings

RootLayout
 └─ <Outlet/> → DashboardLayout
                 └─ <Outlet/> → Settings
```

- при переходе между дочерними маршрутами layout **не размонтируется** — сохраняет state и не перезагружает данные;
- `index`-маршрут рендерится в `Outlet`, когда путь совпадает с родительским;
- относительные ссылки (`to="settings"`) строятся от текущего маршрута.

## Outlet: дополнительно

```jsx
// передать данные дочерним маршрутам
<Outlet context={{ user }} />

// в дочернем маршруте
const { user } = useOutletContext();
```

Если дочерний маршрут не совпал, `<Outlet />` ничего не рендерит.

## Layout-маршруты без пути

```jsx
<Route element={<AuthGuard />}>        {/* нет path — только обертка */}
  <Route path="profile" element={<Profile />} />
  <Route path="orders" element={<Orders />} />
</Route>

function AuthGuard() {
  const user = useAuth();
  return user ? <Outlet /> : <Navigate to="/login" replace />;
}
```

## Что важно помнить

- Вложенность маршрутов повторяет вложенность UI — это удобнее, чем дублировать layout на каждой странице.
- Каждому уровню можно назначить свой `errorElement` и загрузчик данных (data routers).
- В Next.js App Router тот же принцип реализован папками и файлами `layout.tsx`, а роль `Outlet` играет `children`.
- `NavLink` с `end` активен только при точном совпадении пути.

## Мини-шпаргалка

Nested routes: дочерний `<Route>` внутри родительского. Родитель рендерит общий layout и `<Outlet />` — место для ребенка. `index` — маршрут по умолчанию. Layout не размонтируется при переходах. `useOutletContext` — данные вниз.
