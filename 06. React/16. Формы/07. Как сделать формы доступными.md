# Как сделать формы доступными

> [!NOTE]
> Доступная форма понятна без мыши и без зрения: у каждого поля есть видимый `<label>`, связанные поля сгруппированы в `<fieldset>` с `<legend>`, подсказки и ошибки связаны с полем через `aria-describedby`, неверное поле помечено `aria-invalid`, ошибки объявляются скринридеру (`role="alert"` или `aria-live`), а после неудачной отправки фокус переходит на первое поле с ошибкой. Правильные `type` и `autocomplete` помогают клавиатуре на телефоне и автозаполнению.

## Вопрос

Как сделать форму в React доступной? Как связать поле с подписью, подсказкой и ошибкой и как сообщить об ошибке пользователю скринридера?

## Поле с подписью, подсказкой и ошибкой

```tsx
function EmailField({ error }: { error?: string }) {
  const id = useId();
  const hintId = `${id}-hint`;
  const errorId = `${id}-error`;

  return (
    <div>
      <label htmlFor={id}>
        Email <span aria-hidden="true">*</span>
      </label>
      <input
        id={id}
        name="email"
        type="email"
        autoComplete="email"
        inputMode="email"
        required
        aria-invalid={error ? true : undefined}
        aria-describedby={[hintId, error && errorId].filter(Boolean).join(" ")}
      />
      <p id={hintId}>На этот адрес придет подтверждение</p>
      {error && <p id={errorId} role="alert">{error}</p>}
    </div>
  );
}
```

`useId` генерирует стабильный id, одинаковый на сервере и клиенте.

## Группы полей

```tsx
<fieldset>
  <legend>Способ доставки</legend>
  <label><input type="radio" name="delivery" value="courier" /> Курьер</label>
  <label><input type="radio" name="delivery" value="pickup" /> Самовывоз</label>
</fieldset>
```

Скринридер прочитает «Способ доставки, Курьер, переключатель 1 из 2».

## Сводка ошибок после отправки

```tsx
function ErrorSummary({ errors }: { errors: { field: string; message: string }[] }) {
  const ref = useRef<HTMLDivElement>(null);
  useEffect(() => { if (errors.length) ref.current?.focus(); }, [errors]);

  if (!errors.length) return null;
  return (
    <div ref={ref} tabIndex={-1} role="alert">
      <h2>Исправьте ошибки ({errors.length})</h2>
      <ul>
        {errors.map((e) => <li key={e.field}><a href={`#${e.field}`}>{e.message}</a></li>)}
      </ul>
    </div>
  );
}
```

Для длинных форм сводка с ссылками на поля помогает быстро найти проблему; для коротких достаточно фокуса на первое поле с ошибкой.

## autocomplete и type

| Поле | Атрибуты |
| --- | --- |
| Email | `type="email" autoComplete="email"` |
| Телефон | `type="tel" autoComplete="tel"` |
| Новый пароль | `type="password" autoComplete="new-password"` |
| Текущий пароль | `type="password" autoComplete="current-password"` |
| Код из SMS | `inputMode="numeric" autoComplete="one-time-code"` |
| Адрес | `autoComplete="street-address"`, `postal-code`, `address-level2` |
| Имя | `autoComplete="given-name"`, `family-name` |

## Чек-лист

- видимый `<label>` у каждого поля; `placeholder` — не замена подписи;
- обязательность видна текстом или символом и передана через `required` / `aria-required`;
- ошибка: текст + цвет + иконка (не только красная рамка), связь через `aria-describedby`;
- `aria-invalid` только после проверки, а не при первом рендере пустой формы;
- форма проходит с клавиатуры: Tab по порядку, Enter отправляет, видимый `:focus-visible`;
- кнопка отправки — `<button type="submit">`, а не `div` с `onClick`;
- состояние отправки объявлено (`role="status"`), заблокированная кнопка не теряет понятность;
- достаточный контраст и размер цели касания (не меньше 24×24 CSS-пикселя, лучше 44×44).

## Что важно помнить

- `role="alert"` объявляется сразу и прерывает речь — используйте для ошибок; для статусов («Сохранено») — `role="status"` (вежливое объявление).
- Не валидируйте на каждый символ с объявлением ошибки — скринридер будет постоянно перебивать пользователя; `onBlur` или `onTouched` удобнее.
- Не отключайте вставку в поля пароля и подтверждения email — это мешает менеджерам паролей.
- Проверяйте формы с клавиатуры, скринридером (NVDA, VoiceOver) и axe DevTools.
- В тестах ищите поля через `getByRole("textbox", { name: "Email" })` — если тест не находит поле по имени, у поля проблема с доступностью.

## Мини-шпаргалка

`<label htmlFor>` + `useId`. Группы — `fieldset` + `legend`. Подсказка и ошибка — `aria-describedby`, неверное поле — `aria-invalid`, ошибка — `role="alert"`, статус — `role="status"`. Фокус на первую ошибку. Правильные `type`, `inputMode`, `autoComplete`.
