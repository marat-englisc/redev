# Как работать с формами в React: подходы и выбор

> [!NOTE]
> В React есть четыре основных подхода к формам: **управляемые поля** (`value` + `onChange` в state), **неуправляемые поля** с чтением через `FormData` при отправке, **библиотеки** (react-hook-form, TanStack Form, Formik) и **Actions в React 19** (`<form action={fn}>` + `useActionState`). Выбор зависит от сложности: для одного поля поиска хватит `useState`, для формы регистрации с валидацией и динамическими полями — react-hook-form + Zod, для форм с серверной обработкой в Next.js — Server Actions.

## Вопрос

Какие есть подходы к работе с формами в React? Чем они отличаются и как выбрать подход под задачу?

## 1. Управляемые поля

```tsx
function SearchForm({ onSearch }: { onSearch: (q: string) => void }) {
  const [query, setQuery] = useState("");

  return (
    <form onSubmit={(e) => { e.preventDefault(); onSearch(query); }}>
      <input value={query} onChange={(e) => setQuery(e.target.value)} />
      <button disabled={!query.trim()}>Найти</button>
    </form>
  );
}
```

Плюсы: значение всегда в React, легко форматировать и блокировать кнопку. Минусы: ререндер на каждый символ, много кода при большом числе полей.

## 2. Неуправляемые поля и FormData

```tsx
function FeedbackForm() {
  function handleSubmit(e: React.FormEvent<HTMLFormElement>) {
    e.preventDefault();
    const data = Object.fromEntries(new FormData(e.currentTarget));
    console.log(data); // { name: "...", message: "..." }
  }

  return (
    <form onSubmit={handleSubmit}>
      <input name="name" required />
      <textarea name="message" minLength={10} required />
      <button>Отправить</button>
    </form>
  );
}
```

Плюсы: нет ререндеров при вводе, работает встроенная браузерная валидация. Минусы: сложнее реагировать на значения во время ввода.

## 3. Библиотека: react-hook-form

```tsx
const { register, handleSubmit, formState: { errors } } = useForm<{ email: string }>();

<form onSubmit={handleSubmit(onSubmit)}>
  <input {...register("email", { required: "Укажите email" })} />
  {errors.email && <p role="alert">{errors.email.message}</p>}
</form>
```

Неуправляемые поля внутри, минимум ререндеров, валидация, ошибки, состояние отправки, динамические поля и интеграция с Zod.

## 4. Actions в React 19

```tsx
function Subscribe() {
  const [state, formAction, isPending] = useActionState(async (_prev: string | null, formData: FormData) => {
    const res = await subscribe(formData.get("email") as string);
    return res.ok ? "Готово!" : "Не удалось подписаться";
  }, null);

  return (
    <form action={formAction}>
      <input name="email" type="email" required />
      <button disabled={isPending}>Подписаться</button>
      {state && <p role="status">{state}</p>}
    </form>
  );
}
```

Подробнее — в заметках [Actions в React 19](<../13. React 18+/04. Actions в React 19.md>) и [useFormStatus](<../13. React 18+/05. Что такое useFormStatus.md>).

## Как выбрать

| Задача | Подход |
| --- | --- |
| 1–2 поля, поиск, фильтр | `useState` |
| простая форма без живой валидации | `FormData` + атрибуты HTML |
| регистрация, профиль, оформление заказа | react-hook-form + Zod |
| динамические списки полей, многошаговые формы | react-hook-form (`useFieldArray`) |
| форма с серверной обработкой в Next.js | Server Action + `useActionState`, валидация Zod на сервере |

## Что важно помнить

- Всегда используйте `<form>` и `type="submit"`: Enter отправляет форму, работают autofill и доступность.
- Клиентская валидация — для удобства, серверная — обязательна: клиентскую можно обойти.
- Поле не должно переключаться между управляемым и неуправляемым: `value={undefined}` → `value="..."` вызывает предупреждение.
- У каждого поля должен быть `<label>`, у ошибки — связь с полем через `aria-describedby`.
- Защищайте от двойной отправки: блокируйте кнопку на время запроса.

## Мини-шпаргалка

Управляемые (`value` + `onChange`) — простые формы с живой логикой. `FormData` — простая отправка без ререндеров. react-hook-form + Zod — сложные формы. React 19 `action` + `useActionState` — серверные формы. Серверная валидация обязательна.
