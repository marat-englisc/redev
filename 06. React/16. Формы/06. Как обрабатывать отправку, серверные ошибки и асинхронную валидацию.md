# Как обрабатывать отправку, серверные ошибки и асинхронную валидацию

> [!NOTE]
> Отправка формы — асинхронная операция с несколькими состояниями: ожидание, успех, ошибка поля с сервера («email уже занят»), общая ошибка («сервер недоступен»). Нужно: блокировать повторную отправку, показывать ошибки сервера рядом с нужным полем (`setError`), переводить фокус на первую ошибку, а проверки, которым нужен сервер (свободен ли логин), выполнять асинхронно с debounce и отменой устаревших запросов.

## Вопрос

Как правильно обработать отправку формы в React? Как показать ошибку, пришедшую с сервера, защититься от двойной отправки и сделать асинхронную валидацию поля?

## Отправка и ошибки сервера

```tsx
type Values = { email: string; password: string };
type ApiError = { field?: keyof Values; message: string };

export function LoginForm() {
  const {
    register,
    handleSubmit,
    setError,
    formState: { errors, isSubmitting, isSubmitSuccessful },
  } = useForm<Values>({ defaultValues: { email: "", password: "" }, shouldFocusError: true });

  const onSubmit = async (values: Values) => {
    try {
      await api.login(values);
    } catch (e) {
      const err = e as ApiError;
      if (err.field) {
        setError(err.field, { type: "server", message: err.message }, { shouldFocus: true });
      } else {
        setError("root.server", { type: "server", message: err.message ?? "Попробуйте позже" });
      }
    }
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)} noValidate>
      <input {...register("email", { required: "Укажите email" })} />
      {errors.email && <p role="alert">{errors.email.message}</p>}

      <input type="password" {...register("password", { required: "Укажите пароль" })} />
      {errors.password && <p role="alert">{errors.password.message}</p>}

      {errors.root?.server && <div role="alert">{errors.root.server.message}</div>}

      <button disabled={isSubmitting}>{isSubmitting ? "Входим…" : "Войти"}</button>
      {isSubmitSuccessful && <p role="status">Добро пожаловать!</p>}
    </form>
  );
}
```

- `isSubmitting` — `true`, пока выполняется async `onSubmit`: кнопка заблокирована, двойного запроса не будет.
- `setError(field)` — ошибка конкретного поля; `root.*` — общая ошибка формы, не привязанная к полю.
- Ошибки `root` сбрасываются при следующей отправке, ошибки полей — при изменении поля и повторной валидации.

## Асинхронная валидация поля

```tsx
function useUsernameCheck() {
  const controller = useRef<AbortController | null>(null);

  return useMemo(
    () =>
      debounceAsync(async (username: string) => {
        controller.current?.abort();                         // отменить предыдущую проверку
        controller.current = new AbortController();
        const res = await fetch(`/api/username-available?u=${encodeURIComponent(username)}`, {
          signal: controller.current.signal,
        });
        const { available } = await res.json();
        return available || "Это имя уже занято";
      }, 400),
    [],
  );
}

// в форме
const checkUsername = useUsernameCheck();
<input {...register("username", { required: true, validate: checkUsername })} />
{formState.isValidating && <span>Проверяем…</span>}
```

`debounceAsync` — функция, которая откладывает вызов и возвращает Promise последнего результата. Без debounce запрос уходил бы на каждый символ, без отмены — ответ на «ann» мог бы прийти после ответа на «anna».

Правило: асинхронная проверка на клиенте — подсказка. Уникальность всё равно проверяет сервер при отправке (условие гонки: имя могли занять между проверкой и отправкой).

## Повторная отправка и идемпотентность

- блокируйте кнопку на время запроса (`isSubmitting`, `useFormStatus`, `isPending`);
- на сервере используйте идемпотентный ключ для критичных операций (оплата, создание заказа): повторный запрос с тем же ключом не создаст дубль;
- после успешного создания — переход на страницу результата или `reset()`, чтобы обновление страницы не отправило форму снова.

## Предупреждение о несохраненных данных

```tsx
useEffect(() => {
  if (!isDirty) return;
  const handler = (e: BeforeUnloadEvent) => e.preventDefault();
  window.addEventListener("beforeunload", handler);
  return () => window.removeEventListener("beforeunload", handler);
}, [isDirty]);
```

Для переходов внутри SPA используют блокировку навигации роутера (например, `useBlocker` в React Router).

## Что важно помнить

- Различайте ошибки полей, общую ошибку формы и сетевую ошибку — у каждой свое место в UI.
- Сообщение об ошибке должно говорить, что сделать, а не «Ошибка 422».
- Не стирайте введенные данные при ошибке сервера.
- Фокус на первое поле с ошибкой (`shouldFocusError` по умолчанию `true`) и `role="alert"` делают ошибки заметными для скринридеров.
- Подробнее о текстах и показе ошибок — в заметке [Ошибки валидации форм](<../11. Обработка ошибок/07. Ошибки валидации форм.md>).

## Мини-шпаргалка

`isSubmitting` — блокировать кнопку. Ошибка с сервера — `setError("email", { message })`, общая — `setError("root.server", ...)`. Асинхронная проверка — `validate: async` + debounce + AbortController, но финальная проверка на сервере. `isDirty` + `beforeunload` — предупредить о несохраненных данных.
