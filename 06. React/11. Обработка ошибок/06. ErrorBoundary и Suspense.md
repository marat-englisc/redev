# Error Boundary и Suspense

> [!NOTE]
> Suspense показывает ожидание совместимого ресурса, а Error Boundary показывает ошибку. Вместе они описывают разные состояния одного блока.

## Вопрос

Как совместить ожидание загрузки и обработку ошибки lazy-компонента?

## Основная идея

Для асинхронного блока есть как минимум три исхода: ресурс ещё ожидается, ресурс готов и ресурс получить не удалось. У Suspense и Error Boundary разные задачи. Первая граница показывает fallback ожидания, вторая — резервный UI ошибки.

При `lazy` React ожидает динамический импорт модуля. Пока Promise импорта не завершён, срабатывает Suspense. Если импорт отклонён, например JS-файл недоступен после деплоя, ошибка попадёт в Error Boundary. У обычного запроса из эффекта такой интеграции нет: ожидание и ошибка остаются состоянием компонента.

Часто Error Boundary размещают снаружи Suspense, чтобы защитить весь блок, включая его fallback. Это удобная композиция, а не единственная законная вложенность. Можно иметь одну границу ошибки вокруг нескольких независимых Suspense-блоков или несколько локальных границ по смысловым областям.

## Пример

Клиентский проект с динамическими импортами и установленным пакетом `react-error-boundary`; пример состоит из двух файлов.

### App.jsx

```jsx
import { lazy, Suspense } from 'react';
import { ErrorBoundary } from 'react-error-boundary';

const Recommendations = lazy(() => import('./Recommendations.jsx'));
export default function App() {
  return <>
    <h1>Каталог книг</h1>
    <ErrorBoundary fallback={<p role="alert">Рекомендации недоступны</p>}>
      <Suspense fallback={<p role="status">Подбираем рекомендации...</p>}>
        <Recommendations />
      </Suspense>
    </ErrorBoundary>
  </>;
}
```

### Recommendations.jsx

```jsx
export default function Recommendations() {
  return <p>Вам может понравиться «React без паники»</p>;
}
```

Заголовок появляется независимо от загрузки модуля. Успех открывает рекомендации, а ошибка импорта показывает сообщение только для этого блока.

## Что важно помнить

- Пример требует `react-error-boundary` и двух отдельных модулей.
- Сброс Error Boundary не обязательно повторяет кешированный `lazy`-импорт: для ошибки чанка часто нужна перезагрузка или отдельная стратегия восстановления.
- Не пишите собственный протокол «бросать Promise» ради учебного fetch; используйте поддерживаемый источник.

## Мини-шпаргалка

Ожидание → Suspense. Ошибка → Error Boundary. Готовность → компонент. Внешние блоки продолжают работать.
