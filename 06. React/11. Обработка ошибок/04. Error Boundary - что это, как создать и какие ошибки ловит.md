# Error Boundary: что это, как создать и какие ошибки ловит

> [!NOTE]
> **Error Boundary** — компонент, который ловит ошибки JavaScript **при рендере, в методах жизненного цикла и конструкторах** своих потомков, показывает запасной UI и не дает упасть всему приложению. Без него ошибка в любом компоненте размонтирует всё дерево. Error Boundary пишется только **классом** с `static getDerivedStateFromError` (показать fallback) и/или `componentDidCatch` (залогировать). Он **не ловит** ошибки в обработчиках событий, асинхронном коде, SSR и в самом себе.

## Вопрос

Что такое Error Boundary? Как создать его вручную и какие типы ошибок он ловит?

## Создание вручную

```jsx
import { Component } from "react";

class ErrorBoundary extends Component {
  state = { error: null };

  static getDerivedStateFromError(error) {
    return { error };                          // render phase: переключиться на fallback
  }

  componentDidCatch(error, info) {
    logToSentry(error, info.componentStack);   // commit phase: побочные эффекты
  }

  reset = () => this.setState({ error: null });

  render() {
    if (this.state.error) {
      return this.props.fallback ?? (
        <div role="alert">
          <p>Что-то пошло не так.</p>
          <button onClick={this.reset}>Попробовать снова</button>
        </div>
      );
    }
    return this.props.children;
  }
}

// использование
<ErrorBoundary fallback={<WidgetError />}>
  <Widget />
</ErrorBoundary>
```

На практике используют библиотеку `react-error-boundary`:

```jsx
import { ErrorBoundary } from "react-error-boundary";

<ErrorBoundary
  FallbackComponent={({ error, resetErrorBoundary }) => (
    <div role="alert">
      <p>{error.message}</p>
      <button onClick={resetErrorBoundary}>Повторить</button>
    </div>
  )}
  onError={(error, info) => logToSentry(error, info)}
  resetKeys={[userId]}        // сброс при смене userId
>
  <Profile userId={userId} />
</ErrorBoundary>
```

## Какие ошибки ловит

| Ловит | Не ловит |
| --- | --- |
| ошибки при рендере потомков | обработчики событий (`onClick`) |
| ошибки в конструкторах и методах жизненного цикла | асинхронный код: `setTimeout`, промисы, `fetch` |
| ошибки в `useEffect` / `useLayoutEffect` потомков | ошибки при SSR |
| ошибки `React.lazy` (не загрузился чанк) | ошибки в самом Error Boundary |
| отклоненный Promise в `use()` / Suspense | ошибки вне React-дерева |

Ошибки из обработчиков и асинхронного кода можно передать в Error Boundary, сохранив их в state и бросив при рендере, или через `showBoundary` из `react-error-boundary`:

```jsx
const { showBoundary } = useErrorBoundary();
fetchData().catch(showBoundary);
```

## Где ставить границы

- корневая — вокруг всего приложения: последняя линия защиты;
- на уровне маршрута — ошибка страницы не ломает навигацию;
- вокруг независимых виджетов — упавший график не скрывает весь дашборд;
- вместе с `<Suspense>` — для асинхронных частей.

## Что важно помнить

- Хукового аналога пока нет — нужен класс или библиотека.
- В разработке React всё равно покажет overlay с ошибкой — это не значит, что граница не сработала.
- React 19 добавил `onCaughtError` и `onUncaughtError` в `createRoot` для централизованного логирования.
- В Next.js файл `error.tsx` — встроенный Error Boundary сегмента маршрута (с `"use client"`).

## Мини-шпаргалка

Error Boundary — класс с `getDerivedStateFromError` (fallback) и `componentDidCatch` (лог). Ловит ошибки рендера, жизненного цикла и эффектов потомков. Не ловит обработчики, async, SSR, себя. На практике — `react-error-boundary`.
