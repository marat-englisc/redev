# Логирование ошибок

> [!NOTE]
> Логи связывают пользовательский сбой с технической причиной: стеком, версией приложения, маршрутом и контекстом операции.

## Вопрос

Что логировать в React-приложении и как не потерять ошибки за пределами Error Boundary?

## Основная идея

Пользователь пишет «не открывается карточка», но у разработчика всё работает. Для расследования нужны сведения о конкретном сбое: какая версия была загружена, в каком блоке произошла ошибка, какой запрос завершился неуспешно. Одного текста `Something went wrong` для этого недостаточно.

Для ошибки React-поддерева `componentDidCatch` предоставляет `componentStack`, дополняющий обычный JavaScript stack. Для API-ошибок полезны безопасное имя операции, HTTP-статус и request ID. Sourcemaps помогают сопоставить минифицированный стек с исходниками; их публикацию и доступ настраивают осознанно.

Граница не охватывает все источники. SDK мониторинга обычно дополняет её обработкой глобальных `error`, `unhandledrejection` и серверными интеграциями. При этом не нужно бездумно отправлять всё подряд: персональные данные, токены и содержимое форм могут оказаться в URL, заголовках и сообщениях ошибок.

## Пример

Пример для клиентского React-приложения с поддержкой JSX. API в примере возвращает JSON; его адрес замените на адрес своего сервера.

```jsx
import { Component } from 'react';

function reportError(error, info) {
  const event = {
    message: error instanceof Error ? error.message : 'Неизвестная ошибка',
    componentStack: info.componentStack,
    release: 'training-1',
    area: 'recommendations',
  };
  console.error('Событие мониторинга', event);
  // В реальном приложении здесь вызов настроенного SDK с фильтрацией данных.
}
class ErrorBoundary extends Component {
  state = { failed: false };
  static getDerivedStateFromError() { return { failed: true }; }
  componentDidCatch(error, info) { reportError(error, info); }
  render() {
    return this.state.failed ? <p role="alert">Блок недоступен</p>
      : this.props.children;
  }
}
function Widget() { throw new Error('Некорректный формат рекомендации'); }
export default function App() {
  return <ErrorBoundary><Widget /></ErrorBoundary>;
}
```

Пример показывает структуру события в консоли. Он не отправляет данные наружу и не является готовой настройкой мониторинга; SDK добавляют отдельно.

## Что важно помнить

- Сбой отправки лога не должен вызывать новую цепочку аварий.
- Группируйте дубликаты, учитывайте версию релиза и частоту затронутых пользователей.
- Для обработанных и необработанных ошибок React 19 доступны также соответствующие callbacks корня; избегайте двойной отправки одного события.

## Мини-шпаргалка

Ошибка + stack + componentStack + release + безопасный контекст. Пользователю → понятное сообщение, разработчику → диагностика.
