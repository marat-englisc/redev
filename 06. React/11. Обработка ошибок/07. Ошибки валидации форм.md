# Ошибки валидации форм

> [!NOTE]
> Ошибка валидации объясняет, какое поле нужно исправить. Она является ожидаемым результатом пользовательского ввода, а не аварией React-дерева.

## Вопрос

Как показывать ошибки формы понятно и доступно?

## Основная идея

Сообщение «Неверные данные» заставляет пользователя угадывать причину. Лучше указать конкретное поле и требование: «Введите email в формате name@example.com». Клиентская проверка помогает быстро исправить ввод, серверная защищает данные и проверяет правила, которые неизвестны браузеру.

Обычно первую ошибку показывают после blur или попытки отправки, а после этого обновляют по мере исправления. Для большого количества полей используют touched и errors либо библиотеку форм. Не стоит пересчитывать критичную финальную валидацию только в эффекте: при submit проверяйте актуальные значения непосредственно.

Доступность требует связать поле с текстом ошибки через `aria-describedby`, отметить `aria-invalid` и перевести фокус к первому проблемному полю. Общая ошибка сервера располагается отдельно от полевых. Текст должен помогать продолжить действие, а не показывать внутренний стек исключения.

## Пример

Пример для клиентского React-приложения с поддержкой JSX. API в примере возвращает JSON; его адрес замените на адрес своего сервера.

```jsx
import { useRef, useState } from 'react';

export default function EmailForm() {
  const inputRef = useRef(null);
  const [email, setEmail] = useState('');
  const [error, setError] = useState('');
  const [saved, setSaved] = useState(false);
  function submit(event) {
    event.preventDefault();
    setSaved(false);
    const message = /^[^@\s]+@[^@\s]+\.[^@\s]+$/.test(email)
      ? '' : 'Введите email в формате name@example.com';
    setError(message);
    if (message) { inputRef.current?.focus(); return; }
    setSaved(true); // Здесь можно вызвать API и обработать серверные ошибки.
  }
  return <form noValidate onSubmit={submit}>
    <label htmlFor="email">Email</label>
    <input id="email" type="email" ref={inputRef} value={email}
      onChange={e => { setEmail(e.target.value); setSaved(false); }}
      aria-invalid={Boolean(error)} aria-describedby={error ? 'email-error' : undefined} />
    {error && <p id="email-error" role="alert">{error}</p>}
    <button>Сохранить</button>
    {saved && <p role="status">Клиентская проверка пройдена</p>}
  </form>;
}
```

Submit проверяет текущий email. При ошибке фокус возвращается к полю; при успехе демонстрируется только результат клиентской проверки, а не реальное сохранение на сервере.

## Что важно помнить

- Регулярное выражение здесь учебное; оно не подтверждает существование адреса.
- `noValidate` отключает встроенную браузерную проверку ради демонстрации собственной.
- Сервер обязан повторно проверить входные данные, даже если клиент уже проверил их.

## Мини-шпаргалка

Поле → конкретная ошибка. Общая проблема → баннер. Submit → проверить сейчас. Ошибка → фокус + aria.
