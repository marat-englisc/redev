# Асинхронные ошибки в useEffect

> [!NOTE]
> Асинхронная операция внутри эффекта должна самостоятельно обработать отклонение Promise и не обновлять UI после потери актуальности.

## Вопрос

Как правильно обработать сетевую ошибку, отмену и завершение загрузки в эффекте?

## Основная идея

Эффект вызывает async-функцию, которая возвращает Promise. Если ошибка произойдёт после `await`, она не станет обычной синхронной ошибкой callback эффекта. Без внутреннего `try/catch` или `.catch()` появится необработанное отклонение, а экран может навсегда остаться в загрузке.

Отдельно проверяйте HTTP-статус. `fetch` отклоняется при некоторых сетевых проблемах и отмене, но успешно возвращает `Response` при 404 и 500. Ошибка преобразования JSON тоже возможна: например, прокси вернул HTML вместо ожидаемого объекта.

После смены параметров старый результат не должен менять новый экран. Это касается не только `setData`, но и `setError`, и `setLoading(false)` внутри `finally`. Частая ошибка — отменить предыдущую загрузку, но позволить её `finally` выключить индикатор свежего запроса.

## Пример

Пример для клиентского React-приложения с поддержкой JSX. API в примере возвращает JSON; его адрес замените на адрес своего сервера.

```jsx
import { useEffect, useState } from 'react';

export default function Profile({ id = 1 }) {
  const [result, setResult] = useState({ status: 'loading' });

  useEffect(() => {
    const controller = new AbortController();
    let active = true;
    setResult({ status: 'loading' });

    async function load() {
      try {
        const response = await fetch(`/api/users/${id}`, {
          signal: controller.signal,
        });
        if (!response.ok) throw new Error(`HTTP ${response.status}`);
        const user = await response.json();
        if (active) setResult({ status: 'success', user });
      } catch (error) {
        if (active) setResult({ status: 'error', error });
      }
    }

    load();
    return () => {
      active = false;
      controller.abort();
    };
  }, [id]);

  if (result.status === 'loading') return <p role="status">Загрузка...</p>;
  if (result.status === 'error') return <p role="alert">Не удалось загрузить профиль</p>;
  return <h2>{result.user.name}</h2>;
}
```

Модель `status` заменяет отдельные флаги. Все успешные и ошибочные обновления проверяют `active`; cleanup сначала делает операцию неактуальной, затем отменяет запрос.

## Что важно помнить

- Отмена при уходе со страницы не требует сообщения пользователю о сетевом сбое.
- Не объявляйте сам callback эффекта `async`: React ожидает функцию cleanup, а не Promise.
- Повторы должны учитывать тип операции и временную природу ошибки; бесконечный retry может перегрузить сервер.
- Не выводите внутренний стек сервера в публичное сообщение.

## Мини-шпаргалка

await внутри try → проверить response.ok → JSON → актуальность → success/error. Cleanup → ignore + abort.
