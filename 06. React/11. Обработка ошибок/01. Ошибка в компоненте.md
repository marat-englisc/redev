# Ошибка в компоненте

> [!NOTE]
> Необработанная ошибка рендера нарушает построение дерева. Error Boundary позволяет заменить повреждённую область резервным интерфейсом.

## Вопрос

Почему ошибка одного компонента может привести к исчезновению всего приложения?

## Основная идея

Компонент пытается показать `user.name`, но `user` оказался `null`. JavaScript выбрасывает исключение до завершения рендера. React не получает корректное описание этой части интерфейса и ищет ближайшую подходящую границу ошибок среди родителей.

Если граница найдена, React переключает её на fallback. Если её нет, ошибка достигает корня и приводит к удалению дерева интерфейса этого корня. Пользователь может увидеть пустую страницу, хотя проблема находилась в маленьком виджете рекомендаций.

Границы удобно ставить вокруг самостоятельных областей: маршрута, чата, редактора или карточки аналитики. Тогда сбой рекомендаций не закрывает меню и форму поиска. Одной общей границы на корне недостаточно для хорошего UX, но она полезна как последняя защита от полного белого экрана.

## Пример

Пример для клиентского React-приложения с поддержкой JSX. API в примере возвращает JSON; его адрес замените на адрес своего сервера.

```jsx
import { Component } from 'react';

class ErrorBoundary extends Component {
  state = { failed: false };
  static getDerivedStateFromError() {
    return { failed: true };
  }
  componentDidCatch(error, info) {
    console.error(error, info.componentStack);
  }
  render() {
    if (this.state.failed) return <p role="alert">Виджет временно недоступен</p>;
    return this.props.children;
  }
}
function BrokenWidget() {
  throw new Error('Не удалось построить виджет');
}
export default function App() {
  return <>
    <header>Моя библиотека</header>
    <ErrorBoundary><BrokenWidget /></ErrorBoundary>
    <footer>Служба поддержки</footer>
  </>;
}
```

`BrokenWidget` специально выбрасывает исключение. Вместо него появляется сообщение, а шапка и подвал сохраняются. Запись в консоли ожидаема: граница локализует сбой, но не скрывает его от разработчика.

## Что важно помнить

- Не используйте исключение как нормальное состояние загрузки или валидации: предусмотрите явные состояния UI.
- TypeScript уменьшает часть ошибок, но не проверяет автоматически ответ API в runtime.
- Граница не исправляет причину сбоя; для расследования нужны логи и понятный сценарий воспроизведения.

## Мини-шпаргалка

Ошибка рендера → ближайшая граница → fallback. Границы нет → ошибка достигает корня.
