# Типы ошибок в React-приложении

> [!NOTE]
> Обработка ошибки зависит от места возникновения: рендер, синхронный эффект, событие, асинхронное продолжение или сервер.

## Вопрос

Какие ошибки возникают в React и как выбрать подходящий способ обработки?

## Основная идея

Не всякая ошибка в React-приложении является ошибкой React-рендера. Неуспешный пароль — ожидаемый ответ бизнес-логики. `TypeError` при чтении поля `null` — дефект построения UI. Сетевой тайм-аут — проблема внешней операции. Если всё отправлять в один fallback, пользователь потеряет возможность исправить ввод или повторить запрос.

Error Boundary локализует ошибки React-поддерева: рендера, конструкторов и жизненного цикла, включая синхронные ошибки запуска эффектов. Обычный обработчик `onClick` выполняется отдельно и требует локальной обработки. Отклонённый Promise нужно обрабатывать через `await` с `try/catch` или `.catch()`.

Ошибки сборки и TypeScript возникают до запуска приложения, а ошибки SSR — на сервере. Их нельзя исправить клиентской границей. Глобальный мониторинг помогает обнаружить пропущенные проблемы, но не заменяет корректную обработку в месте, где известен контекст операции.

## Пример

Пример для клиентского React-приложения с поддержкой JSX. API в примере возвращает JSON; его адрес замените на адрес своего сервера.

```jsx
import { useState } from 'react';

export default function SaveButton() {
  const [message, setMessage] = useState('');
  const [pending, setPending] = useState(false);
  async function save() {
    setPending(true);
    try {
      const response = await fetch('/api/draft', { method: 'PUT' });
      if (!response.ok) throw new Error(`HTTP ${response.status}`);
      setMessage('Черновик сохранён');
    } catch {
      setMessage('Не удалось сохранить. Попробуйте ещё раз.');
    } finally { setPending(false); }
  }
  return <>
    <button onClick={save} disabled={pending}>Сохранить</button>
    <p role="status">{message}</p>
  </>;
}
```

Ошибка запроса превращается в сообщение рядом с действием. Остальная страница продолжает работать; пользователю не приходится закрывать редактор из-за временного сбоя сети.

## Что важно помнить

- `fetch` на 500 не отклоняет Promise автоматически.
- React 19 Actions интегрируются с границами ошибок, но это не делает любой `async onClick` автоматически защищённым.
- Валидация, авторизация и инфраструктурная ошибка требуют разных текстов и дальнейших действий.

## Мини-шпаргалка

| Где ошибка | Что использовать |
| --- | --- |
| Рендер/React lifecycle | Error Boundary |
| Событие/обычный Promise | try/catch, catch |
| SSR/сборка | Серверная обработка, диагностика сборки |
| Ожидаемая валидация | Ошибка поля или формы |
