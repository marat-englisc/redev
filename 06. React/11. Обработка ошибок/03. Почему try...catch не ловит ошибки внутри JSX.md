# try...catch и JSX

> [!NOTE]
> Создание JSX-элемента не вызывает дочерний компонент немедленно. Поэтому try...catch вокруг return JSX не ловит будущую ошибку рендера потомка.

## Вопрос

Почему try...catch вокруг <Child /> не заменяет Error Boundary?

## Основная идея

JSX компилируется в создание объектов React-элементов. Выражение `<UserCard user={null} />` описывает тип компонента и props, но не означает прямой вызов `UserCard()`. React позже сам обходит дерево и вызывает нужные компоненты в своём процессе рендера.

Когда дочерний компонент обращается к `user.name` и падает, `try` в родителе уже завершился. Исключение возникает в другом вызове, поэтому локальный `catch` родителя его не видит. Error Boundary подключён к механизму обхода React и предназначен именно для такого случая.

При этом синхронное выражение, которое вычисляется непосредственно внутри `try`, будет поймано обычным JavaScript. Например, ошибка в `JSON.parse(text)` при вычислении props возникает ещё до создания элемента. Важно различать вычисление выражения сейчас и рендер дочернего компонента позже.

## Пример

Пример для клиентского React-приложения с поддержкой JSX. API в примере возвращает JSON; его адрес замените на адрес своего сервера.

```jsx
import { Component } from 'react';

class ErrorBoundary extends Component {
  state = { error: false };
  static getDerivedStateFromError() { return { error: true }; }
  render() {
    return this.state.error ? <p role="alert">Не удалось показать карточку</p>
      : this.props.children;
  }
}
function UserCard({ user }) {
  return <p>{user.name}</p>;
}
function Parent() {
  try {
    return <UserCard user={null} />;
  } catch {
    return <p>Этот catch не поймает ошибку UserCard</p>;
  }
}
export default function App() {
  return <ErrorBoundary><Parent /></ErrorBoundary>;
}
```

Ошибка возникает внутри `UserCard`, поэтому показывается fallback границы. В реальном приложении отсутствие пользователя лучше обработать проверкой данных до обращения к его полям.

## Что важно помнить

- Не вызывайте компоненты вручную ради `try/catch`: это нарушает модель React и может сломать хуки.
- `try { fetch(url); }` не ловит будущий reject; требуется `await fetch(url)` внутри async-функции.
- JSX содержит обычные JavaScript-выражения, поэтому утверждение «try никогда не ловит ошибку в JSX» слишком широкое.

## Мини-шпаргалка

Создать `<Child />` ≠ вызвать Child. Будущий рендер → Error Boundary. Вычисление сейчас → обычный catch.
