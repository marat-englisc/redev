# useSelector, useDispatch и мемоизированные селекторы createSelector

> [!NOTE]
> `useSelector(selector)` подписывает компонент на часть Redux state и перерендеривает его, только когда **результат селектора изменился** (сравнение по ссылке `===`). `useDispatch()` возвращает `dispatch` для отправки actions. Если селектор вычисляет производные данные и возвращает **новый массив или объект**, компонент будет рендериться при любом изменении store — для этого нужны мемоизированные селекторы `createSelector` (reselect).

## Вопрос

Как работают `useSelector` и `useDispatch`? Почему селектор, возвращающий новый массив, вызывает лишние ререндеры и как это исправить через `createSelector`?

## Основное использование

```tsx
function TodoList() {
  const todos = useAppSelector((state) => state.todos.items);
  const dispatch = useAppDispatch();

  return (
    <ul>
      {todos.map((t) => (
        <li key={t.id} onClick={() => dispatch(todoToggled(t.id))}>
          {t.text}
        </li>
      ))}
    </ul>
  );
}
```

`useSelector` вызывается после каждого `dispatch`. Если `state.todos.items` — та же ссылка, ререндера не будет.

## Проблема: новый объект в селекторе

```tsx
// ререндер при ЛЮБОМ изменении store: filter возвращает новый массив
const done = useAppSelector((state) => state.todos.items.filter((t) => t.done));

// тоже: новый объект каждый раз
const { items, status } = useAppSelector((state) => ({ items: state.todos.items, status: state.todos.status }));
```

Решения:

```tsx
// 1. Несколько отдельных селекторов
const items = useAppSelector((s) => s.todos.items);
const status = useAppSelector((s) => s.todos.status);

// 2. shallowEqual для объекта из полей
import { shallowEqual } from "react-redux";
const { items, status } = useAppSelector((s) => ({ items: s.todos.items, status: s.todos.status }), shallowEqual);
```

## createSelector

```typescript
import { createSelector } from "@reduxjs/toolkit";
import type { RootState } from "../../app/store";

export const selectTodos = (state: RootState) => state.todos.items;
export const selectFilter = (state: RootState) => state.filters.status;

export const selectVisibleTodos = createSelector(
  [selectTodos, selectFilter],                 // входные селекторы
  (todos, filter) =>                           // результат пересчитывается, только если вход изменился
    filter === "all" ? todos : todos.filter((t) => (filter === "done" ? t.done : !t.done)),
);

export const selectDoneCount = createSelector([selectTodos], (todos) => todos.filter((t) => t.done).length);
```

```tsx
const visible = useAppSelector(selectVisibleTodos);
```

Пока `todos` и `filter` те же ссылки, `createSelector` возвращает сохраненный массив — компонент не ререндерится.

## Селекторы с параметром

```typescript
export const selectTodoById = (state: RootState, id: string) =>
  state.todos.items.find((t) => t.id === id);

const todo = useAppSelector((state) => selectTodoById(state, id));
```

Для мемоизированного селектора с аргументом кеш по умолчанию хранит одно значение; если компонентов с разными `id` много, создают селектор на экземпляр через `useMemo` или используют `weakMapMemoize` (по умолчанию в Reselect 5).

## Что важно помнить

- Выбирайте минимально необходимую часть state: чем уже селектор, тем реже ререндер.
- Не возвращайте из `useSelector` новые объекты и массивы без мемоизации — это самая частая причина лишних ререндеров.
- `createSelector` с функцией-результатом `x => x` бесполезен: мемоизация нужна только для вычислений.
- Храните в state минимум, а производные данные (суммы, фильтры, сортировки) вычисляйте селекторами.
- `dispatch` стабилен — его можно не добавлять в зависимости хуков.
- Классический `connect(mapStateToProps)` — устаревший API, в новом коде используют хуки.

## Мини-шпаргалка

`useSelector(fn)` — подписка, ререндер при новой ссылке результата. `useDispatch()` — отправка actions. Новый массив/объект в селекторе → лишние ререндеры. Решение: несколько селекторов, `shallowEqual`, `createSelector([inputs], combiner)`.
