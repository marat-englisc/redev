# Как настроить store: configureStore, Provider и типизация

> [!NOTE]
> `configureStore` создает Redux store: объединяет reducers, подключает middleware по умолчанию (thunk, проверки мутаций и сериализуемости в dev-режиме) и Redux DevTools. Компонент `<Provider store={store}>` из `react-redux` делает store доступным всему дереву. В TypeScript из store выводят типы `RootState` и `AppDispatch` и создают типизированные хуки `useAppSelector` и `useAppDispatch`.

## Вопрос

Как создать и подключить Redux store в React-приложении? Как правильно типизировать state, dispatch и хуки?

## Создание store

```typescript
// app/store.ts
import { configureStore } from "@reduxjs/toolkit";
import todosReducer from "../features/todos/todosSlice";
import filtersReducer from "../features/filters/filtersSlice";

export const store = configureStore({
  reducer: {
    todos: todosReducer,
    filters: filtersReducer,
  },
  // middleware: (getDefaultMiddleware) => getDefaultMiddleware().concat(logger),
  // devTools: process.env.NODE_ENV !== "production",
});

export type RootState = ReturnType<typeof store.getState>;
export type AppDispatch = typeof store.dispatch;
```

Ключи объекта `reducer` становятся ключами state: `state.todos`, `state.filters`.

## Типизированные хуки

```typescript
// app/hooks.ts
import { useDispatch, useSelector } from "react-redux";
import type { AppDispatch, RootState } from "./store";

export const useAppDispatch = useDispatch.withTypes<AppDispatch>();
export const useAppSelector = useSelector.withTypes<RootState>();
```

`AppDispatch` знает о thunk-ах: `dispatch(fetchTodos())` типизирован, а обычный `useDispatch` — нет. В компонентах используйте только типизированные хуки.

## Подключение к React

```tsx
// main.tsx
import { Provider } from "react-redux";
import { store } from "./app/store";

createRoot(document.getElementById("root")!).render(
  <Provider store={store}>
    <App />
  </Provider>,
);
```

## Что дает configureStore по умолчанию

| Возможность | Зачем |
| --- | --- |
| `combineReducers` из объекта | не нужно вызывать вручную |
| thunk middleware | `dispatch` функций и `createAsyncThunk` |
| immutability check (dev) | ошибка при мутации state вне Immer |
| serializability check (dev) | предупреждение о несериализуемых значениях |
| Redux DevTools | история actions, diff state, time-travel |

## Структура проекта

```text
src/
  app/
    store.ts
    hooks.ts
  features/
    todos/
      todosSlice.ts
      TodoList.tsx
      selectors.ts
    filters/
      filtersSlice.ts
```

Рекомендуемый подход — **feature folders**: slice, компоненты и селекторы фичи лежат вместе.

## Store в SSR (Next.js)

На сервере один модульный store был бы общим для всех пользователей. Поэтому store создают **на запрос**:

```typescript
export const makeStore = () => configureStore({ reducer: { todos: todosReducer } });
export type AppStore = ReturnType<typeof makeStore>;
```

```tsx
"use client";
export function StoreProvider({ children }: { children: React.ReactNode }) {
  const storeRef = useRef<AppStore | null>(null);
  if (!storeRef.current) storeRef.current = makeStore();
  return <Provider store={storeRef.current}>{children}</Provider>;
}
```

## Что важно помнить

- Один store на приложение; разделение — через slices, а не через несколько store.
- Проверки мутаций и сериализуемости работают только в dev и не замедляют production.
- Несериализуемые значения (Date, Map, функции) вызывают предупреждения — храните ISO-строки и обычные объекты.
- В Next.js App Router store создается внутри клиентского провайдера; Server Components к store доступа не имеют.
- `withTypes` появился в react-redux 9.1; раньше писали `TypedUseSelectorHook<RootState>`.

## Мини-шпаргалка

`configureStore({ reducer: { todos, filters } })` → `<Provider store>`. Типы: `RootState = ReturnType<typeof store.getState>`, `AppDispatch = typeof store.dispatch`. Хуки: `useSelector.withTypes<RootState>()`, `useDispatch.withTypes<AppDispatch>()`. SSR — `makeStore` на запрос.
