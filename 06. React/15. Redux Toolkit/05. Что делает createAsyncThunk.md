# Что делает createAsyncThunk

> [!NOTE]
> `createAsyncThunk(type, payloadCreator)` создает **thunk** — функцию для асинхронной логики, которую можно отправить через `dispatch`. Он автоматически отправляет три action: `pending` перед запуском, `fulfilled` с результатом и `rejected` с ошибкой. Slice обрабатывает их в `extraReducers`, сохраняя статус загрузки, данные и ошибку. Thunk поддерживает отмену через `AbortSignal`, `rejectWithValue` для своих ошибок и `condition` для отказа от лишних запросов.

## Вопрос

Как работает `createAsyncThunk`? Какие actions он отправляет, как обработать ошибку, отменить запрос и получить результат в компоненте?

## Thunk

**Thunk** — функция, которая получает `dispatch` и `getState`. Middleware `redux-thunk` (включен в `configureStore`) позволяет передавать в `dispatch` функции:

```typescript
const logout = (): AppThunk => (dispatch, getState) => {
  dispatch(userLoggedOut());
  localStorage.removeItem("token");
};
```

`createAsyncThunk` — стандартный способ написать асинхронный thunk.

## Создание

```typescript
import { createAsyncThunk } from "@reduxjs/toolkit";

type Todo = { id: string; text: string; done: boolean };

export const fetchTodos = createAsyncThunk<
  Todo[],                                   // тип результата
  { page: number },                         // тип аргумента
  { state: RootState; rejectValue: string } // доп. типы
>(
  "todos/fetchTodos",
  async ({ page }, { signal, rejectWithValue }) => {
    const res = await fetch(`/api/todos?page=${page}`, { signal });
    if (!res.ok) return rejectWithValue(`Ошибка сервера: ${res.status}`);
    return (await res.json()) as Todo[];
  },
  {
    condition: (_arg, { getState }) => getState().todos.status !== "loading", // не запускать повторно
  },
);
```

## Обработка в slice

```typescript
type TodosState = { items: Todo[]; status: "idle" | "loading" | "succeeded" | "failed"; error: string | null };

const todosSlice = createSlice({
  name: "todos",
  initialState: { items: [], status: "idle", error: null } as TodosState,
  reducers: {},
  extraReducers: (builder) => {
    builder
      .addCase(fetchTodos.pending, (state) => {
        state.status = "loading";
        state.error = null;
      })
      .addCase(fetchTodos.fulfilled, (state, action) => {
        state.status = "succeeded";
        state.items = action.payload;
      })
      .addCase(fetchTodos.rejected, (state, action) => {
        state.status = "failed";
        state.error = action.payload ?? action.error.message ?? "Неизвестная ошибка";
      });
  },
});
```

`action.payload` в `rejected` — значение из `rejectWithValue`; `action.error` — сериализованное исключение.

## Использование в компоненте

```tsx
function TodosPage() {
  const dispatch = useAppDispatch();
  const { items, status, error } = useAppSelector((s) => s.todos);

  useEffect(() => {
    const promise = dispatch(fetchTodos({ page: 1 }));
    return () => promise.abort();                 // отмена при размонтировании
  }, [dispatch]);

  async function handleSave(todo: Todo) {
    try {
      await dispatch(saveTodo(todo)).unwrap();     // unwrap: результат или throw
      toast("Сохранено");
    } catch (err) {
      toast(`Ошибка: ${err}`);
    }
  }

  if (status === "loading") return <Spinner />;
  if (status === "failed") return <p role="alert">{error}</p>;
  return <TodoList items={items} onSave={handleSave} />;
}
```

`dispatch(thunk)` возвращает Promise, который **всегда выполняется** (с action `fulfilled` или `rejected`). `.unwrap()` превращает его в обычный Promise, который отклоняется при ошибке.

## Что важно помнить

- Thunk подходит для простой асинхронности; для загрузки и кеширования серверных данных лучше RTK Query — не нужно вручную хранить `status`, `error` и обновлять кеш.
- Передавайте `signal` в `fetch` — тогда `promise.abort()` действительно отменит запрос.
- Ошибка внутри payload creator не роняет приложение: она превращается в action `rejected`.
- В Strict Mode эффект запустится дважды — отмена в cleanup защищает от двойной загрузки.
- Сложные цепочки побочных эффектов (реакции на actions, debounce) удобнее писать через `createListenerMiddleware`.

## Мини-шпаргалка

`createAsyncThunk(type, async (arg, { signal, rejectWithValue, getState }) => ...)` → actions `pending` / `fulfilled` / `rejected`, обработка в `extraReducers`. `dispatch(thunk).unwrap()` — результат или throw. `promise.abort()` — отмена. `condition` — не запускать лишний раз.
