# Что такое middleware в Redux и listener middleware

> [!NOTE]
> **Middleware** — функция, которая встает между `dispatch` и reducer и может перехватить, изменить, задержать или дополнить каждый action: логировать, отправлять аналитику, выполнять асинхронную логику. Сигнатура — `store => next => action => {}`. В Redux Toolkit для побочных эффектов в ответ на actions рекомендуется **`createListenerMiddleware`** — более простая альтернатива redux-saga и redux-observable.

## Вопрос

Что такое middleware в Redux и как он устроен? Как с помощью listener middleware реагировать на actions и чем он отличается от thunk и saga?

## Как устроен middleware

```typescript
import type { Middleware } from "@reduxjs/toolkit";

export const logger: Middleware = (store) => (next) => (action) => {
  console.log("dispatch", action);
  const result = next(action);              // передать дальше по цепочке → reducer
  console.log("next state", store.getState());
  return result;
};
```

```text
dispatch(action) → middleware 1 → middleware 2 → ... → reducer → новый state
```

Подключение:

```typescript
configureStore({
  reducer,
  middleware: (getDefaultMiddleware) => getDefaultMiddleware().concat(logger),
});
```

`getDefaultMiddleware()` уже содержит thunk и dev-проверки — не теряйте их, переопределяя массив целиком.

## Listener middleware

```typescript
import { createListenerMiddleware, isAnyOf } from "@reduxjs/toolkit";

export const listenerMiddleware = createListenerMiddleware();

// сохранять корзину в localStorage после любых изменений
listenerMiddleware.startListening({
  matcher: isAnyOf(itemAdded, itemRemoved, cartCleared),
  effect: (_action, listenerApi) => {
    const { cart } = listenerApi.getState() as RootState;
    localStorage.setItem("cart", JSON.stringify(cart.items));
  },
});

// поиск с debounce: отменяет предыдущий запуск
listenerMiddleware.startListening({
  actionCreator: searchChanged,
  effect: async (action, listenerApi) => {
    listenerApi.cancelActiveListeners();
    await listenerApi.delay(300);
    listenerApi.dispatch(fetchSearchResults(action.payload));
  },
});
```

```typescript
configureStore({
  reducer,
  middleware: (gDM) => gDM().prepend(listenerMiddleware.middleware),
});
```

Способы указать, на что реагировать: `actionCreator`, `type`, `matcher` (`isAnyOf`, `isFulfilled`), `predicate(action, currentState, previousState)`.

## Thunk, listener, saga

| | Thunk | Listener middleware | redux-saga |
| --- | --- | --- | --- |
| Запускается | явным `dispatch(thunk)` | автоматически в ответ на action | автоматически в ответ на action |
| Синтаксис | async/await | async/await | генераторы |
| Отмена, debounce | вручную | `cancelActiveListeners`, `delay`, `condition` | `takeLatest`, `debounce` |
| Порог входа | низкий | низкий | высокий |
| Входит в RTK | да | да | нет |

## Типичные задачи для middleware

- логирование и отправка ошибок в Sentry;
- аналитика по actions;
- синхронизация с `localStorage` и между вкладками;
- WebSocket: открыть соединение по action и диспатчить входящие сообщения;
- реакция одной фичи на события другой без прямых зависимостей.

## Что важно помнить

- Middleware видит **каждый** action — держите его быстрым.
- Обязательно вызывайте `next(action)`, иначе action не дойдет до reducer.
- Побочные эффекты — в middleware и thunk-ах, а не в reducers.
- Listener middleware обычно подключают через `prepend`, чтобы он стоял раньше остальных.
- redux-saga встречается в старых проектах; для нового кода RTK рекомендует listener middleware и RTK Query.

## Мини-шпаргалка

Middleware: `store => next => action => { ...; return next(action) }`, цепочка между dispatch и reducer. Подключение: `getDefaultMiddleware().concat(...)`. Listener: `createListenerMiddleware().startListening({ actionCreator | matcher | predicate, effect })`, есть `delay`, `cancelActiveListeners`, `condition`.
