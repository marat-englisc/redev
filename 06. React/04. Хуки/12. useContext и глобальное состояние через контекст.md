# useContext и глобальное состояние через контекст

> [!NOTE]
> `useContext(MyContext)` читает значение ближайшего провайдера контекста выше по дереву. Контекст передает данные «сквозь» компоненты без prop drilling: тему, язык, текущего пользователя, store. Глобальное состояние на контексте делают так: держат state (`useState`/`useReducer`) в компоненте-провайдере и передают значение и функции изменения через `value`. Контекст — механизм **передачи** данных, а не state manager: при изменении `value` перерендериваются все потребители.

## Вопрос

Что делает `useContext()`? Как создать глобальное состояние с помощью `useContext`?

## Основная идея

```jsx
import { createContext, useContext, useState, useMemo } from "react";

const ThemeContext = createContext("light"); // значение по умолчанию — если провайдера нет

function App() {
  return (
    <ThemeContext value="dark">   {/* React 19; в 18 — <ThemeContext.Provider value="dark"> */}
      <Toolbar />
    </ThemeContext>
  );
}

function Button() {
  const theme = useContext(ThemeContext); // "dark"
  return <button className={`btn btn--${theme}`}>OK</button>;
}
```

`useContext` ищет ближайший провайдер **выше** компонента. Провайдер в том же компоненте не учитывается.

## Глобальное состояние на контексте

```jsx
const AuthContext = createContext(null);

export function AuthProvider({ children }) {
  const [user, setUser] = useState(null);

  const value = useMemo(
    () => ({
      user,
      login: async (credentials) => setUser(await api.login(credentials)),
      logout: () => setUser(null),
    }),
    [user],
  );

  return <AuthContext value={value}>{children}</AuthContext>;
}

export function useAuth() {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error("useAuth должен использоваться внутри AuthProvider");
  return ctx;
}

// использование
function Header() {
  const { user, logout } = useAuth();
  return user ? <button onClick={logout}>Выйти, {user.name}</button> : <LoginLink />;
}
```

Приемы:

- кастомный хук `useAuth` скрывает контекст и проверяет наличие провайдера;
- `useMemo` для `value`, чтобы объект не пересоздавался при каждом рендере провайдера;
- для сложной логики — `useReducer` в провайдере и `dispatch` в контексте.

## Когда контекст подходит

| Подходит | Лучше другое |
| --- | --- |
| тема, язык, пользователь, настройки | часто меняющиеся данные (ввод, позиция мыши) |
| зависимости (API-клиент, роутер) | большое состояние с многими подписчиками |
| данные compound-компонентов | серверные данные → TanStack Query |
| | сложный глобальный state → Zustand, Redux Toolkit |

## Что важно помнить

- При изменении `value` перерендериваются **все** компоненты, вызывающие `useContext`, — `memo` их не спасает.
- Разделяйте контексты по частоте изменений: данные и функции-действия можно держать в разных контекстах.
- В React 19 `<Context>` можно использовать как провайдер напрямую, а `use(Context)` читает контекст в том числе в условиях.
- В Server Components контекст недоступен — провайдеры размещают в клиентских компонентах.

## Мини-шпаргалка

`createContext(default)` → провайдер с `value` → `useContext(Ctx)`. Глобальный state: `useState`/`useReducer` в провайдере + `useMemo` для `value` + свой хук. Все потребители перерендериваются при смене `value`.
