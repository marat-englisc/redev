# Зависимости эффекта и устаревшие замыкания

> [!NOTE]
> В зависимости включают реактивные значения, которые читает эффект. Пропущенная зависимость может оставить эффект привязанным к старому снимку данных.

## Вопрос

Почему нужно указывать все зависимости useEffect? Как убрать лишнюю зависимость без отключения линтера?

## Основная идея

Функция эффекта создаётся во время рендера и замыкает его значения. Если эффект запустился с `count = 0`, вложенный callback продолжает видеть этот ноль, пока соответствующая синхронизация не будет заменена. Это обычные замыкания JavaScript, а не неисправность React.

Массив зависимостей описывает, когда внешний процесс должен перестать использовать прежние данные. React сравнивает каждый элемент через `Object.is`. Для чисел и строк сравнивается значение, для объектов и функций важна ссылка. Поэтому объект, создаваемый в теле компонента, может перезапускать эффект при каждом рендере даже при одинаковых полях.

Не подбирайте зависимости ради желаемого расписания. Сначала включите всё, что читает эффект: props, state и локальные функции. Затем изменяйте код, если синхронизация получается слишком частой. Например, updater `setCount(c => c + 1)` не читает `count` из замыкания. Объект настроек можно создать внутри setup, а функцию, не зависящую от компонента, вынести в модуль.

## Пример

```tsx
import { useEffect, useState } from 'react';

export default function StepTimer({ step = 1 }: { step?: number }) {
  const [count, setCount] = useState(0);

  useEffect(() => {
    const id = window.setInterval(() => {
      setCount(previous => previous + step);
    }, 1000);
    return () => window.clearInterval(id);
  }, [step]);

  return <p>Прошло условных шагов: {count}</p>;
}
```

`count` не нужен в массиве: обновление получает актуальное предыдущее состояние от React. `step` нужен, поскольку callback использует prop. При смене шага таймер заменяется. Если написать `[]`, таймер продолжит прибавлять первоначальный шаг.

## Что важно помнить

- Функция из `useCallback` обычно должна оставаться зависимостью, если эффект её вызывает. Она стабильна только пока не меняются её собственные deps.
- Сеттеры состояния и `dispatch` из React стабильны; линтер позволяет опустить их.
- `ref.current` не является реактивной зависимостью: изменение поля не вызывает рендер.
- Отключение `exhaustive-deps` скрывает рассогласование. Исправляйте причину, а не предупреждение.

## Мини-шпаргалка

Deps следуют из кода. `Object.is` сравнивает значения/ссылки. Updater убирает чтение прошлого state, но не отменяет остальные зависимости.
