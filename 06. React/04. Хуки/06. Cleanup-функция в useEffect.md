# Cleanup-функция в useEffect

> [!NOTE]
> **Cleanup** — функция, которую возвращает эффект. React вызывает ее **перед повторным запуском эффекта** (когда изменились зависимости) и **при размонтировании** компонента. В очистке отменяют то, что сделал эффект: отписываются от событий, очищают таймеры, закрывают соединения, отменяют запросы. Без cleanup появляются утечки памяти, дублирующиеся подписки и обновления state у размонтированных компонентов.

## Вопрос

Что делает cleanup-функция в `useEffect()` и когда она вызывается?

## Основная идея

```jsx
useEffect(() => {
  const id = setInterval(tick, 1000);
  return () => clearInterval(id);       // cleanup
}, []);
```

Каждой операции в эффекте должна соответствовать обратная:

| Эффект | Cleanup |
| --- | --- |
| `addEventListener` | `removeEventListener` |
| `setInterval` / `setTimeout` | `clearInterval` / `clearTimeout` |
| `connection.connect()` | `connection.disconnect()` |
| `subscribe()` | `unsubscribe()` |
| `fetch` | `controller.abort()` |
| `new IntersectionObserver` | `observer.disconnect()` |

## Когда вызывается

```jsx
function Chat({ roomId }) {
  useEffect(() => {
    console.log("подключение к", roomId);
    return () => console.log("отключение от", roomId);
  }, [roomId]);
}
```

```text
mount roomId=1     → подключение к 1
update roomId=2    → отключение от 1 → подключение к 2
unmount            → отключение от 2
```

Cleanup видит значения **своего** рендера — того, в котором был создан эффект.

## Отмена запроса

```jsx
useEffect(() => {
  const controller = new AbortController();

  fetch(`/api/users/${id}`, { signal: controller.signal })
    .then((r) => r.json())
    .then(setUser)
    .catch((e) => {
      if (e.name !== "AbortError") setError(e);
    });

  return () => controller.abort(); // смена id или размонтирование
}, [id]);
```

Так ответ на старый запрос не перезапишет данные нового (race condition).

## Сравнение с классами

`useEffect` с cleanup заменяет пару `componentDidMount` + `componentWillUnmount`, а с зависимостями — еще и `componentDidUpdate`. Логика подписки и отписки хранится рядом, а не разнесена по разным методам.

## Что важно помнить

- В Strict Mode эффект запускается, очищается и запускается снова — это проверка, что cleanup корректен.
- Cleanup предыдущего эффекта выполняется после commit нового рендера, перед запуском нового эффекта.
- Возвращать из эффекта можно только функцию или ничего; `async`-эффект возвращает Promise — это ошибка.
- `useLayoutEffect` тоже поддерживает cleanup и вызывает его синхронно.

## Мини-шпаргалка

Cleanup = функция из эффекта. Вызывается перед перезапуском и при размонтировании. Отменяет подписки, таймеры, запросы. Без нее — утечки и гонки. Strict Mode проверяет ее двойным запуском.
