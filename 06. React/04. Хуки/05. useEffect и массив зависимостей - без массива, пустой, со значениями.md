# useEffect и массив зависимостей: без массива, пустой, со значениями

> [!NOTE]
> `useEffect(setup, deps?)` запускает побочный эффект **после того, как React применил изменения к DOM и браузер отрисовал экран**. Эффекты синхронизируют компонент с внешним миром: подписки, таймеры, запросы, работа с не-React виджетами. Массив зависимостей определяет, когда эффект перезапускается: без массива — после каждого рендера, `[]` — один раз после монтирования, `[a, b]` — когда изменилось `a` или `b`. Перед перезапуском и при размонтировании вызывается функция очистки.

## Вопрос

Что делает `useEffect()`? Когда выполняется эффект без зависимостей, с пустым массивом и с массивом значений?

## Основная идея

```jsx
import { useEffect, useState } from "react";

function ChatRoom({ roomId }) {
  const [messages, setMessages] = useState([]);

  useEffect(() => {
    const connection = createConnection(roomId);
    connection.on("message", (m) => setMessages((prev) => [...prev, m]));
    connection.connect();

    return () => connection.disconnect(); // очистка
  }, [roomId]);                          // перезапуск при смене комнаты

  return <MessageList messages={messages} />;
}
```

## Три варианта зависимостей

| Запись | Когда выполняется | Типичное применение |
| --- | --- | --- |
| `useEffect(fn)` | после **каждого** рендера | редко нужно; логирование |
| `useEffect(fn, [])` | один раз после монтирования, очистка при размонтировании | подписка на глобальное событие, инициализация виджета |
| `useEffect(fn, [a, b])` | после монтирования и после рендеров, где изменились `a` или `b` | запрос по `id`, синхронизация с props |

Сравнение зависимостей — `Object.is` по каждому элементу. Объект или функция, созданные в рендере, каждый раз новые, и эффект будет перезапускаться постоянно.

```jsx
useEffect(() => {
  document.title = `Сообщений: ${count}`;
}); // каждый рендер

useEffect(() => {
  const onResize = () => setWidth(window.innerWidth);
  window.addEventListener("resize", onResize);
  return () => window.removeEventListener("resize", onResize);
}, []); // один раз

useEffect(() => {
  fetchUser(userId).then(setUser);
}, [userId]); // при смене userId
```

## Порядок выполнения

```text
render → commit (DOM обновлен) → браузер рисует → useEffect
следующий рендер → commit → cleanup предыдущего эффекта → новый эффект
размонтирование → cleanup
```

## Почему указывать все зависимости

Эффект замыкает значения из рендера. Если не указать зависимость, эффект будет работать со **старыми** props и state (stale closure):

```jsx
useEffect(() => {
  const id = setInterval(() => console.log(count), 1000); // всегда первый count
  return () => clearInterval(id);
}, []); // count пропущен
```

Решения: добавить зависимость, использовать функциональное обновление `setCount(c => c + 1)`, перенести функцию внутрь эффекта, хранить значение в `useRef`, а для обработчиков — `useEffectEvent` (React 19.2).

## Когда эффект не нужен

- вычисление данных из props/state — делайте в рендере;
- реакция на действие пользователя — в обработчике события;
- сброс state при смене prop — через `key`;
- загрузка данных — лучше TanStack Query, SWR или фреймворк.

## Что важно помнить

- В Strict Mode в разработке эффект запускается дважды (mount → cleanup → mount) для проверки очистки.
- Функцию эффекта нельзя делать `async` — она должна вернуть функцию очистки или ничего.
- Правило `react-hooks/exhaustive-deps` подсказывает недостающие зависимости — не отключайте его без причины.
- Для измерения DOM до отрисовки используйте `useLayoutEffect`.

## Мини-шпаргалка

`useEffect` — синхронизация с внешним миром после отрисовки. Без массива — каждый рендер, `[]` — после монтирования, `[a]` — при изменении `a`. Указывайте все зависимости. Возвращайте cleanup. Вычисления и обработчики — не в эффектах.
