# useReducer, dispatch и сравнение с useState

> [!NOTE]
> `useReducer(reducer, initialState)` управляет состоянием через **редьюсер** — чистую функцию `(state, action) => newState`. Компонент вызывает `dispatch(action)`, описывая, **что произошло**, а редьюсер решает, **как** изменить состояние. `useReducer` удобен для сложного состояния с многими связанными полями и переходами, `useState` — для простых независимых значений. `dispatch` стабилен и ничего не возвращает.

## Вопрос

Что делает `useReducer()` и `dispatch()`? Когда выбрать `useReducer`, а когда `useState`?

## Основная идея

```jsx
import { useReducer } from "react";

const initialState = { items: [], promo: null, status: "idle" };

function cartReducer(state, action) {
  switch (action.type) {
    case "added":
      return { ...state, items: [...state.items, action.item] };
    case "removed":
      return { ...state, items: state.items.filter((i) => i.id !== action.id) };
    case "promo_applied":
      return { ...state, promo: action.code };
    case "checkout_started":
      return { ...state, status: "loading" };
    default:
      throw new Error(`Неизвестное действие: ${action.type}`);
  }
}

function Cart() {
  const [state, dispatch] = useReducer(cartReducer, initialState);

  return (
    <>
      <button onClick={() => dispatch({ type: "added", item: { id: 1, title: "Чайник" } })}>
        Добавить
      </button>
      <p>Товаров: {state.items.length}</p>
    </>
  );
}
```

## dispatch

- ставит action в очередь, как сеттер `useState`; новое состояние будет в следующем рендере;
- стабилен между рендерами — его безопасно передавать детям и не указывать в зависимостях;
- возвращает `undefined`;
- если редьюсер вернул то же состояние (`Object.is`), рендер может быть пропущен.

Action — обычный объект, по соглашению с полем `type` и данными (`payload`, `id`). Имена лучше давать в прошедшем времени: `added`, `removed` — событие, а не команда.

## useReducer или useState

| | `useState` | `useReducer` |
| --- | --- | --- |
| Объем кода | меньше | больше (редьюсер, actions) |
| Сложное состояние | неудобно | удобно |
| Логика обновлений | разбросана по обработчикам | собрана в одном месте |
| Тестирование | через компонент | редьюсер — чистая функция |
| Отладка | — | легко логировать actions |
| Передача вниз | несколько сеттеров | один `dispatch` |

Признаки, что пора перейти на `useReducer`:

- несколько полей state меняются вместе;
- следующее состояние зависит от нескольких предыдущих значений;
- одинаковые обновления вызываются из разных мест;
- появились «невозможные» комбинации флагов (`isLoading && isError`).

## Ленивая инициализация

```jsx
const [state, dispatch] = useReducer(reducer, userId, (id) => loadDraft(id));
```

Третий аргумент — функция-инициализатор, вызывается один раз.

## Что важно помнить

- Редьюсер должен быть чистым: без запросов, таймеров и мутаций — эффекты выполняют в обработчиках или `useEffect`.
- В Strict Mode редьюсер вызывается дважды для проверки чистоты.
- `useReducer` + `Context` — простой способ сделать небольшой глобальный store.
- В TypeScript actions описывают discriminated union — редьюсер получает точные типы в каждой ветке.

## Мини-шпаргалка

`useReducer(reducer, init)` → `[state, dispatch]`. `dispatch({ type, ... })` — что произошло, редьюсер — как изменить. Для сложного связанного состояния. `dispatch` стабилен. Редьюсер чистый.
