# Transitions: useTransition и startTransition

> [!NOTE]
> **Transition** — обновление состояния, помеченное как **несрочное**. React выполняет его с низким приоритетом и может прервать, если пришло срочное обновление (ввод, клик). `useTransition()` возвращает `[isPending, startTransition]`: флаг ожидания и функцию, внутри которой вызываются сеттеры. Отдельная функция `startTransition` из `react` делает то же самое без флага — ее можно вызывать вне компонентов. Transitions — часть Concurrent Rendering из React 18.

## Вопрос

Что такое transition updates? Что делают `useTransition()` и `startTransition()` и чем они отличаются?

## Проблема

```jsx
function Search() {
  const [query, setQuery] = useState("");
  const [results, setResults] = useState([]);

  const handleChange = (e) => {
    setQuery(e.target.value);
    setResults(filterHugeList(e.target.value)); // тяжелый рендер блокирует ввод
  };
}
```

Пока React рендерит тысячи результатов, поле ввода «залипает».

## useTransition

```jsx
import { useState, useTransition } from "react";

function Search() {
  const [query, setQuery] = useState("");
  const [results, setResults] = useState([]);
  const [isPending, startTransition] = useTransition();

  const handleChange = (e) => {
    setQuery(e.target.value);              // срочно: поле обновится сразу
    startTransition(() => {
      setResults(filterHugeList(e.target.value)); // несрочно, можно прервать
    });
  };

  return (
    <>
      <input value={query} onChange={handleChange} />
      {isPending && <Spinner />}
      <ResultList items={results} />
    </>
  );
}
```

Если пользователь печатает дальше, React бросит незаконченный рендер результатов и начнет новый с актуальным `query`.

## startTransition без хука

```jsx
import { startTransition } from "react";

router.subscribe((url) => {
  startTransition(() => {
    setPage(url);  // вне компонента: в роутере, store, утилите
  });
});
```

| | `useTransition` | `startTransition` |
| --- | --- | --- |
| Где вызывать | в компоненте или хуке | где угодно |
| `isPending` | есть | нет |
| Применение | индикатор ожидания в UI | библиотеки, роутеры, store |

## Transitions и Suspense

Если обновление внутри transition вызывает приостановку (Suspense), React **не показывает fallback** для уже видимого контента, а оставляет старый экран, пока новый не будет готов. Так навигация не превращается в мигающий спиннер.

## Async-transitions (React 19)

```jsx
startTransition(async () => {
  const error = await updateName(name);
  if (error) setError(error);
  else startTransition(() => redirect("/profile"));
});
```

Функция может быть асинхронной: `isPending` остается `true`, пока Promise не завершится. На этом построены Actions и `useActionState`.

## Что важно помнить

- Внутри `startTransition` должны быть вызовы сеттеров; сам по себе тяжелый синхронный JS не станет прерываемым.
- Управляемые поля ввода нельзя обновлять в transition — ввод должен быть срочным.
- Transitions не замена debounce: они не уменьшают количество запросов к серверу.
- Работают только с `createRoot` (конкурентный режим React 18+).

## Мини-шпаргалка

Transition = несрочное, прерываемое обновление. `useTransition` → `[isPending, startTransition]`. `startTransition` из `react` — без флага, вне компонентов. Срочное — ввод, несрочное — тяжелые списки и навигация. Не скрывает контент fallback-ом.
