# Ререндеры от контекста и как их оптимизировать

> [!NOTE]
> Когда значение провайдера меняется (сравнение `Object.is`), React перерендеривает **все** компоненты, которые читают этот контекст через `useContext`, — даже если им нужна лишь часть значения, и даже если они обернуты в `memo`. Основные способы оптимизации: мемоизировать `value`, разделять контексты по смыслу и частоте изменений, отделять данные от функций-действий, опускать провайдер ниже по дереву и переносить часто меняющееся состояние во внешний store с селекторами.

## Вопрос

Происходит ли ререндер при изменении контекста? Как оптимизировать работу с контекстом?

## Проблема

```jsx
function AppProvider({ children }) {
  const [user, setUser] = useState(null);
  const [theme, setTheme] = useState("light");

  // новый объект при каждом рендере провайдера → ререндер всех потребителей
  return (
    <AppContext value={{ user, setUser, theme, setTheme }}>
      {children}
    </AppContext>
  );
}

function ThemeToggle() {
  const { theme, setTheme } = useContext(AppContext); // перерендерится и при смене user
}
```

## 1. Мемоизировать value

```jsx
const value = useMemo(() => ({ user, setUser, theme, setTheme }), [user, theme]);
```

Теперь потребители не рендерятся, когда провайдер перерендерился по другой причине. Но любое изменение `user` всё еще затронет потребителей темы.

## 2. Разделить контексты

```jsx
<UserContext value={userValue}>
  <ThemeContext value={themeValue}>
    {children}
  </ThemeContext>
</UserContext>
```

Каждый компонент подписывается только на то, что ему нужно.

## 3. Отделить данные от действий

```jsx
const CartStateContext = createContext(null);
const CartDispatchContext = createContext(null);

function CartProvider({ children }) {
  const [state, dispatch] = useReducer(cartReducer, initialState);
  return (
    <CartDispatchContext value={dispatch}>   {/* dispatch стабилен — эти потребители не ререндерятся */}
      <CartStateContext value={state}>{children}</CartStateContext>
    </CartDispatchContext>
  );
}
```

Кнопки «Добавить в корзину» читают только `dispatch` и не перерендериваются при изменении корзины.

## 4. Опустить провайдер ниже

Если состояние нужно только внутри одной секции страницы, оборачивайте провайдером её, а не всё приложение.

## 5. Внешний store с селекторами

Для часто меняющихся данных с многими подписчиками используйте Zustand, Jotai, Redux Toolkit или `useSyncExternalStore`: компонент подписывается на конкретный фрагмент и рендерится только при его изменении.

```jsx
const count = useCartStore((state) => state.items.length);
```

## memo и контекст

`memo` защищает от ререндера из-за родителя, но не от изменения контекста, который компонент читает сам. Прием: читать контекст в маленькой обертке, а тяжелую часть передавать мемоизированной.

```jsx
function PriceContainer() {
  const { currency } = useContext(SettingsContext);
  return <ExpensivePrice currency={currency} />; // ExpensivePrice в memo, рендерится только при смене currency
}
```

## Что важно помнить

- Сначала измерьте: контекст с редко меняющимися данными (тема, пользователь) обычно не проблема.
- React Compiler мемоизирует `value` автоматически, но разделение контекстов остается полезным.
- Предложение «context selectors» в React пока не реализовано — для селекторов нужны внешние библиотеки.
- В DevTools Profiler причина рендера «Context changed» указывает на эту проблему.

## Мини-шпаргалка

Изменение `value` → ререндер всех потребителей, даже в `memo`. Оптимизация: `useMemo` для `value`, разделение контекстов, отдельный контекст для `dispatch`, провайдер ниже, store с селекторами.
