# Почему в новых компонентах используют хуки

> [!NOTE]
> Хуки сделали переиспользование логики и группировку связанных эффектов проще. Классовые компоненты при этом остаются поддерживаемыми.

## Вопрос

Какие проблемы классов решают хуки? Нужно ли переписывать все существующие классы?

## Основная идея

В классе состояние хранится в экземпляре, а обработчики могут зависеть от `this`. Обычный метод, переданный как callback, теряет нужный контекст, если его не привязать. Поля класса со стрелочными функциями решают эту проблему, но функциональному компоненту `this` для обращения к состоянию вообще не нужен: данные доступны через замыкание.

Вторая проблема — организация эффектов. Одна подписка часто требует установки в `componentDidMount`, замены в `componentDidUpdate` и удаления в `componentWillUnmount`. В компоненте с несколькими подписками каждый метод объединяет несвязанные задачи. Эффект позволяет держать настройку и очистку одной синхронизации рядом.

Третья причина — повторное использование поведения. Раньше применяли HOC и render props, добавляющие компоненты-обёртки. Кастомный хук позволяет извлечь, например, таймер, не меняя структуру JSX. Это не делает HOC неправильными: у них по-прежнему есть задачи. Главное преимущество хуков — удобная композиция логики, а не автоматическое ускорение программы.

## Пример

```tsx
import { useEffect, useState } from 'react';

function useSeconds() {
  const [seconds, setSeconds] = useState(0);
  useEffect(() => {
    const id = window.setInterval(() => setSeconds(s => s + 1), 1000);
    return () => window.clearInterval(id);
  }, []);
  return seconds;
}

export default function TeaTimer() {
  const seconds = useSeconds();
  return <p>Чай заваривается: {seconds} с</p>;
}
```

Компонент отвечает за текст, хук — за отсчёт времени. Подписка и очистка находятся в одном эффекте. Другой компонент может вызвать `useSeconds`, получив собственный независимый таймер без дополнительной обёртки в дереве.

## Что важно помнить

- Хуки не отменяют необходимость понимать замыкания, зависимости и чистоту рендера.
- `useEffect` не является точной копией всех методов жизненного цикла; для измерений перед paint нужен `useLayoutEffect`.
- Стабильные классы можно оставить. Для некоторых задач, например собственного Error Boundary, всё ещё используют класс или готовую библиотеку.
- Не выносите каждую строку в хук: извлекайте понятное самостоятельное поведение.

## Мини-шпаргалка

Хуки помогают убрать `this`, объединить setup и cleanup, переиспользовать логику. Классы поддерживаются; миграция нужна по практическим причинам.
