# useSyncExternalStore: подписка на внешний store

> [!NOTE]
> `useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot?)` подписывает компонент на **внешний источник данных**, которым React не управляет: store библиотеки (Redux, Zustand), браузерные API (`navigator.onLine`, `matchMedia`, `localStorage`). Хук появился в React 18, чтобы при конкурентном рендеринге все компоненты видели **одинаковое** значение store (защита от tearing — «разрыва» UI).

## Вопрос

Что делает `useSyncExternalStore()` и зачем он появился в React 18?

## Основная идея

```jsx
import { useSyncExternalStore } from "react";

function subscribe(callback) {
  window.addEventListener("online", callback);
  window.addEventListener("offline", callback);
  return () => {
    window.removeEventListener("online", callback);
    window.removeEventListener("offline", callback);
  };
}

function useOnlineStatus() {
  return useSyncExternalStore(
    subscribe,                 // как подписаться (должна быть стабильной)
    () => navigator.onLine,    // текущее значение на клиенте
    () => true,                // значение на сервере
  );
}

function StatusBar() {
  const isOnline = useOnlineStatus();
  return <p>{isOnline ? "В сети" : "Нет соединения"}</p>;
}
```

## Аргументы

| Аргумент | Что делает |
| --- | --- |
| `subscribe(callback)` | подписывается на изменения, вызывает `callback` при каждом изменении, возвращает функцию отписки |
| `getSnapshot()` | возвращает текущее значение; при неизменных данных — **ту же ссылку** |
| `getServerSnapshot()` | значение для SSR и гидрации |

## Проблема tearing

При конкурентном рендеринге React может прервать рендер на середине. Если внешний store изменился за это время, часть компонентов отрендерится со старым значением, часть — с новым. `useSyncExternalStore` обнаруживает изменение и делает обновление синхронным, чтобы UI был согласован.

## Свой простой store

```jsx
let state = { count: 0 };
const listeners = new Set();

export const store = {
  getSnapshot: () => state,
  subscribe: (l) => { listeners.add(l); return () => listeners.delete(l); },
  increment: () => {
    state = { ...state, count: state.count + 1 }; // новая ссылка
    listeners.forEach((l) => l());
  },
};

function Counter() {
  const { count } = useSyncExternalStore(store.subscribe, store.getSnapshot);
  return <button onClick={store.increment}>{count}</button>;
}
```

## Что важно помнить

- `getSnapshot` не должен возвращать новый объект при каждом вызове — будет бесконечный цикл ререндеров.
- `subscribe` объявляйте вне компонента или мемоизируйте, иначе подписка будет пересоздаваться.
- Для собственного state React используйте `useState`; хук нужен для данных **вне** React.
- Zustand, Redux (`react-redux` v8+), Jotai используют этот хук внутри.

## Мини-шпаргалка

`useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot)` — подписка на внешний store. Защищает от tearing при concurrent-рендере. Snapshot — стабильная ссылка. Для браузерных API и state-менеджеров.
