# useRef: доступ к DOM и хранение значений между рендерами

> [!NOTE]
> `useRef(initial)` возвращает объект `{ current: initial }`, который **живет всё время жизни компонента** и остается тем же между рендерами. Изменение `ref.current` **не вызывает ререндер**. Два основных применения: доступ к DOM-узлу через атрибут `ref` и хранение мутируемых значений, которые не влияют на отображение: id таймера, предыдущее значение, флаг, экземпляр стороннего виджета.

## Вопрос

Что делает `useRef()`? Как получить доступ к DOM-элементу и чем `useRef` отличается от `useState`?

## Доступ к DOM

```jsx
import { useRef } from "react";

function SearchForm() {
  const inputRef = useRef(null);

  return (
    <>
      <input ref={inputRef} />
      <button onClick={() => inputRef.current.focus()}>Найти</button>
    </>
  );
}
```

React записывает DOM-узел в `ref.current` в фазе commit и обнуляет при размонтировании. Во время рендера `ref.current` еще может быть `null`, поэтому работают с ним в обработчиках и эффектах.

Типичные задачи: фокус, прокрутка, измерение размеров, воспроизведение видео, интеграция с картами и графиками.

## Хранение значений

```jsx
function Stopwatch() {
  const [time, setTime] = useState(0);
  const intervalRef = useRef(null);

  const start = () => {
    intervalRef.current = setInterval(() => setTime((t) => t + 1), 1000);
  };
  const stop = () => clearInterval(intervalRef.current);

  return (
    <>
      <p>{time}</p>
      <button onClick={start}>Старт</button>
      <button onClick={stop}>Стоп</button>
    </>
  );
}

// предыдущее значение
function usePrevious(value) {
  const ref = useRef();
  useEffect(() => {
    ref.current = value;
  });
  return ref.current;
}
```

## useRef и useState

| | `useState` | `useRef` |
| --- | --- | --- |
| Изменение вызывает ререндер | да | нет |
| Значение | снимок рендера | всегда актуальное `.current` |
| Изменение | через сеттер, в следующем рендере | присваиванием, сразу |
| Читать в рендере | да | не рекомендуется |
| Для чего | данные для UI | DOM, таймеры, служебные значения |

## Вопросы на глубину

- **Почему не читать `ref.current` в рендере?** Рендер должен быть чистым: изменение ref не вызывает ререндер, и UI рассинхронизируется. Исключение — ленивая инициализация `if (ref.current === null) ref.current = new Heavy()`.
- **Чем `useRef` отличается от переменной вне компонента?** Модульная переменная общая для всех экземпляров, ref — свой у каждого.
- **Как передать ref в дочерний компонент?** В React 19 `ref` — обычный prop; в React 18 — `forwardRef`.
- **Callback ref** — функция `ref={(node) => ...}`; вызывается при подключении узла, удобна для измерений и списков.
- **`useImperativeHandle`** ограничивает, какие методы ребенка видны родителю через ref.

## Что важно помнить

- Ref — «запасной выход» из декларативной модели; для данных, влияющих на UI, используйте state.
- Изменение `ref.current` не отслеживается — указывать `ref.current` в зависимостях эффектов бессмысленно.
- `useRef(new Heavy())` создает объект при каждом рендере; используйте ленивую инициализацию.
- В TypeScript: `useRef<HTMLInputElement>(null)` для DOM, `useRef<number | null>(null)` для значений.

## Мини-шпаргалка

`useRef` → стабильный `{ current }`. Изменение не вызывает ререндер. DOM: `ref={inputRef}` → `inputRef.current.focus()`. Значения: таймеры, предыдущее значение. В рендере не читать и не писать.
