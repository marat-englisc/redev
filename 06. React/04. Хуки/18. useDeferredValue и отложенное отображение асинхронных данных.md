# useDeferredValue и отложенное отображение асинхронных данных

> [!NOTE]
> `useDeferredValue(value)` возвращает «отстающую» копию значения. При срочном обновлении React сначала рендерит UI со **старым** отложенным значением, а затем в фоне — с новым, прерывая этот фоновый рендер, если значение снова изменилось. Это аналог transition, но для случая, когда у вас нет доступа к сеттеру — только к значению (например, из props). С Suspense хук позволяет показывать старые результаты вместо fallback, пока грузятся новые.

## Вопрос

Что делает `useDeferredValue()`? Чем он отличается от `useTransition` и как помогает при работе с асинхронными данными?

## Основная идея

```jsx
import { useState, useDeferredValue, memo } from "react";

function Search() {
  const [query, setQuery] = useState("");
  const deferredQuery = useDeferredValue(query);
  const isStale = query !== deferredQuery;

  return (
    <>
      <input value={query} onChange={(e) => setQuery(e.target.value)} />
      <div style={{ opacity: isStale ? 0.5 : 1 }}>
        <SlowList query={deferredQuery} />
      </div>
    </>
  );
}

const SlowList = memo(function SlowList({ query }) {
  /* тяжелый рендер */
});
```

Поле ввода обновляется мгновенно, а `SlowList` догоняет в фоне. `memo` обязателен: иначе `SlowList` перерендерится при каждом рендере родителя.

## С Suspense и загрузкой данных

```jsx
function SearchPage() {
  const [query, setQuery] = useState("");
  const deferredQuery = useDeferredValue(query);

  return (
    <>
      <input value={query} onChange={(e) => setQuery(e.target.value)} />
      <Suspense fallback={<Spinner />}>
        <SearchResults query={deferredQuery} /> {/* использует use() или suspense-запрос */}
      </Suspense>
    </>
  );
}
```

Пока новые результаты загружаются, пользователь видит предыдущие, а не спиннер.

## useDeferredValue и useTransition

| | `useTransition` | `useDeferredValue` |
| --- | --- | --- |
| Что откладываем | обновление state (сеттер) | значение |
| Нужен доступ к сеттеру | да | нет — подходит для props |
| Флаг ожидания | `isPending` | сравнение `value !== deferred` |
| Начальное значение | — | `useDeferredValue(value, initialValue)` (React 19) |

## Отличие от debounce

| | debounce | `useDeferredValue` |
| --- | --- | --- |
| Задержка | фиксированная | нет: на быстром устройстве почти мгновенно |
| Прерывание рендера | нет | да |
| Сокращает запросы к API | да | нет |

Для сетевых запросов debounce остается нужен; `useDeferredValue` оптимизирует **рендеринг**.

## Что важно помнить

- Передавайте примитивы или стабильные объекты: новый объект каждый рендер сделает отложенный рендер бесполезным.
- Фоновый рендер можно прервать, но эффекты выполняются только после его commit.
- Работает только при конкурентном рендеринге (`createRoot`).

## Мини-шпаргалка

`useDeferredValue(value)` — отстающая копия значения. Срочный UI сразу, тяжелая часть догоняет в фоне. Вместе с `memo`. С Suspense показывает старые данные вместо fallback. Не заменяет debounce запросов.
