# useMemo: мемоизация вычислений и когда она вредна

> [!NOTE]
> `useMemo(calculate, deps)` кеширует **результат вычисления** между рендерами и пересчитывает его, только когда изменились зависимости. Применяют в двух случаях: 1) дорогое вычисление (фильтрация и сортировка больших массивов); 2) сохранение **стабильной ссылки** на объект или массив, которые передаются в `memo`-компонент или в зависимости другого хука. Для дешевых вычислений `useMemo` не нужен — он сам добавляет накладные расходы.

## Вопрос

Что делает `useMemo()`? Когда стоит его использовать, а когда мемоизация вредна?

## Основная идея

```jsx
import { useMemo } from "react";

function ProductList({ products, query, sort }) {
  const visible = useMemo(() => {
    return products
      .filter((p) => p.title.toLowerCase().includes(query.toLowerCase()))
      .toSorted((a, b) => (sort === "price" ? a.price - b.price : a.title.localeCompare(b.title)));
  }, [products, query, sort]);

  return visible.map((p) => <ProductCard key={p.id} product={p} />);
}
```

При рендере React сравнивает зависимости с прошлыми через `Object.is`. Совпали — возвращает закешированное значение, нет — вызывает функцию заново.

## Стабильная ссылка

```jsx
const Chart = memo(function Chart({ options }) { /* ... */ });

function Dashboard({ color }) {
  // без useMemo options — новый объект каждый рендер, memo бесполезен
  const options = useMemo(() => ({ color, animate: true }), [color]);
  return <Chart options={options} />;
}

// зависимость эффекта
const filters = useMemo(() => ({ status, page }), [status, page]);
useEffect(() => { load(filters); }, [filters]);
```

## Когда использовать

| Применять | Не применять |
| --- | --- |
| вычисление заметно медленное (замерьте `console.time`) | простая арифметика, конкатенация строк |
| значение передается в `memo`-компонент | значение используется только в JSX этого компонента |
| значение — зависимость `useEffect`/`useCallback` | зависимости меняются каждый рендер |
| создание дорогого объекта (парсер, индекс) | «на всякий случай» везде |

## Когда мемоизация вредна

- **Накладные расходы**: хранение предыдущего значения и сравнение зависимостей при каждом рендере.
- **Ложное чувство оптимизации**: если зависимость — новый объект из родителя, кеш никогда не срабатывает.
- **Сложность кода**: лишние обертки и массивы зависимостей усложняют чтение и порождают баги с устаревшими значениями.
- **Память**: большой кешированный результат держится в памяти.

Сначала улучшайте структуру: опускайте state ниже, передавайте JSX через `children`, разбивайте компоненты. Мемоизация — после замера в Profiler.

## Что важно помнить

- `useMemo` — подсказка для производительности, а не гарантия: React может сбросить кеш.
- Функция внутри `useMemo` должна быть чистой.
- В Strict Mode функция вызывается дважды.
- React Compiler автоматически мемоизирует значения и компоненты — с ним ручной `useMemo` чаще не нужен.

## Мини-шпаргалка

`useMemo(fn, deps)` кеширует результат. Для дорогих вычислений и стабильных ссылок в `memo` и deps. Для дешевых вычислений — лишний. Сначала замерить, потом мемоизировать.
