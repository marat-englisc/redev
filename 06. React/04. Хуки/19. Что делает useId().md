# useId: доступные связи и согласованные идентификаторы

> [!NOTE]
> useId создаёт идентификатор для связей HTML и ARIA, который сохраняется между рендерами и согласуется при SSR и гидратации одинакового дерева.

## Вопрос

Для чего нужен useId? Почему нельзя использовать его вместо key элементов списка?

## Основная идея

У label должен быть `htmlFor`, совпадающий с `id` поля. Для подсказки используется `aria-describedby`, для сообщения об ошибке — другая связь. Если несколько экземпляров формы используют одинаковый жёстко заданный ID, label может активировать чужое поле, а скринридер прочитает неправильное описание.

`useId` предоставляет идентификатор конкретному вызову хука. От него удобно построить несколько связанных ID с суффиксами. В отличие от случайных чисел, генерация учитывает структуру React-дерева и может согласоваться между серверным HTML и клиентской гидратацией. Для этого сервер и клиент должны рендерить соответствующее дерево.

Это идентификатор интерфейсной связи, а не сущности данных. `key` помогает React сопоставлять элементы списка между обновлениями, поэтому ключ берут из стабильного ID записи. Генерировать ключ вызовом хука в цикле нельзя и по правилам хуков. ID базы данных и идентификатор для `label` решают разные задачи.

## Пример

```tsx
import { useId } from 'react';

function EmailField() {
  const id = useId();
  return <div>
    <label htmlFor={`${id}-input`}>Почта</label>
    <input id={`${id}-input`} type="email" aria-describedby={`${id}-hint`} />
    <p id={`${id}-hint`}>Пришлём только билет, без рекламы.</p>
  </div>;
}

export default function Registration() {
  return <>
    <h2>Первый участник</h2><EmailField />
    <h2>Второй участник</h2><EmailField />
  </>;
}
```

Два поля получают разные наборы ID. Нажатие на подпись фокусирует соответствующее поле, а описание относится к нужному input. Один вызов useId обеспечивает общий префикс группы связей внутри экземпляра.

## Что важно помнить

- Не полагайтесь на конкретный строковый формат ID: это деталь реализации.
- Не используйте useId для key, URL сущности или постоянного значения в базе.
- Случайный ID в рендере может отличаться между сервером и клиентом и при каждом обновлении.
- Для нескольких независимых React-корней задавайте согласованный `identifierPrefix` серверу и клиенту.
- Хук вызывают на верхнем уровне. По текущей документации он недоступен в async Server Components.
- Уникальность относится к интерфейсной генерации React, а не ко всем внешним системам.

## Мини-шпаргалка

useId → HTML/ARIA-связи. ID записи → key и данные. Одинаковое SSR-дерево → корректная гидратация.
