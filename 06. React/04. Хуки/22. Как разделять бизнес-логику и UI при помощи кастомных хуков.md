# Разделение логики и UI с кастомными хуками

> [!NOTE]
> Кастомный хук может предоставлять данные и действия предметной области, а компонент — выбирать разметку и пользовательское взаимодействие. Это полезная граница, а не запрет любой логики в UI.

## Вопрос

Как вынести правила работы с задачами в хук и сохранить понятный компонент?

## Основная идея

Удобно разделять то, что меняется по разным причинам. Правило «пустую задачу нельзя добавить» относится к данным. Цвет кнопки и расположение формы — к отображению. Хук может управлять задачами, проверять вход и предоставлять действия; компонент решает, как получить текст и показать список.

Не нужно механически выносить весь код из компонента. Локальный флаг открытия меню или простое форматирование подписи часто понятнее рядом с JSX. Кастомный хук особенно полезен, когда правило повторяется или компонент разрастается из-за нескольких внешних процессов. Чистую бизнес-функцию без React-зависимостей можно вынести обычной утилитой и использовать внутри хука.

Иногда хук предоставляет prop-getters: функции, возвращающие `onClick`, `aria-expanded` и связанные props для доступного UI. Это подход для headless-компонентов, но контракт должен корректно объединять пользовательские обработчики и атрибуты. Возвращать JSX технически возможно, однако тогда граница между поведением и представлением становится менее прозрачной.

## Пример

```tsx
import { useCallback, useState, type FormEvent } from 'react';

type Todo = { id: string; title: string; done: boolean };
function useTodos() {
  const [todos, setTodos] = useState<Todo[]>([]);
  const add = useCallback((rawTitle: string) => {
    const title = rawTitle.trim();
    if (!title) return;
    const todo = { id: crypto.randomUUID(), title, done: false };
    setTodos(previous => [...previous, todo]);
  }, []);
  const toggle = useCallback((id: string) => {
    setTodos(previous => previous.map(t => t.id === id ? { ...t, done: !t.done } : t));
  }, []);
  return { todos, add, toggle };
}

export default function TodoList() {
  const { todos, add, toggle } = useTodos();
  const [draft, setDraft] = useState('');
  function submit(event: FormEvent) {
    event.preventDefault();
    add(draft);
    setDraft('');
  }
  return <>
    <form onSubmit={submit}>
      <input value={draft} onChange={e => setDraft(e.target.value)} />
      <button>Добавить</button>
    </form>
    {todos.map(todo => <label key={todo.id}>
      <input type="checkbox" checked={todo.done} onChange={() => toggle(todo.id)} />
      {todo.title}
    </label>)}
  </>;
}
```

Хук управляет неизменяемыми обновлениями и проверкой названия. Компонент хранит черновик поля и выбирает форму отображения. ID создаётся до updater, чтобы updater оставался чистым. Тот же хук можно использовать для другой разметки задач.

## Что важно помнить

- Два вызова useTodos не делят список автоматически: для общего списка нужен общий источник.
- При загрузке с сервера нужны состояния ожидания и ошибки, отмена или проверка актуальности ответа.
- Не храните отдельно активные задачи, если их можно вычислить из todos; useMemo добавляйте по измеренной необходимости.
- Не превращайте архитектурную договорённость «хук обычно без JSX» в ограничение языка.

## Мини-шпаргалка

Хук: правила, данные, действия. UI: разметка и локальное взаимодействие. Чистые правила без React: обычные функции. Общие данные: отдельный владелец.
