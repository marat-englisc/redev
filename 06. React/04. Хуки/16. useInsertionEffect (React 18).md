# useInsertionEffect (React 18)

> [!NOTE]
> `useInsertionEffect` — хук для **авторов CSS-in-JS библиотек**. Он выполняется **до** `useLayoutEffect` и до того, как другие эффекты читают layout, — чтобы вставить теги `<style>` в документ раньше, чем кто-то измерит элементы. В прикладном коде он почти не нужен: внутри нельзя обновлять state, а ref еще не подключены.

## Вопрос

Что делает `useInsertionEffect()` и зачем он появился в React 18?

## Основная идея

Библиотеки вроде styled-components и Emotion генерируют стили во время рендера. Если вставить `<style>` в `useLayoutEffect`, другой `useLayoutEffect` может успеть измерить элемент без стилей, а браузеру придется пересчитывать стили несколько раз.

```jsx
import { useInsertionEffect } from "react";

const inserted = new Set();

function useCSS(rule) {
  useInsertionEffect(() => {
    if (!inserted.has(rule)) {
      inserted.add(rule);
      const style = document.createElement("style");
      style.textContent = rule;
      document.head.appendChild(style);
    }
  });
  return rule;
}
```

## Порядок эффектов

```text
render → useInsertionEffect → изменения DOM → useLayoutEffect → отрисовка → useEffect
```

React 18 и новее вызывают `useInsertionEffect` до мутаций DOM: стили уже на месте, когда layout-эффекты читают размеры.

## Ограничения

| Можно | Нельзя |
| --- | --- |
| вставлять `<style>`, `<link>` | обновлять state |
| читать значения из замыкания | использовать ref — они еще не подключены |
| возвращать cleanup | рассчитывать на актуальный layout |

## Что важно помнить

- Хук работает только на клиенте; на сервере стили собирают отдельно.
- Подход «рантайм CSS-in-JS» постепенно уступает статической экстракции (CSS Modules, vanilla-extract, Tailwind), поэтому хук нужен всё реже.
- В React 19 для стилей есть встроенная поддержка `<link rel="stylesheet" precedence>`.

## Мини-шпаргалка

`useInsertionEffect` — для CSS-in-JS. Срабатывает раньше layout-эффектов, чтобы вставить стили. Без setState и ref. В обычном коде не нужен.
