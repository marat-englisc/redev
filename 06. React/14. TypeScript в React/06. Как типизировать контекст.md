# Как типизировать контекст

> [!NOTE]
> Тип контекста описывает его value. Если провайдер обязателен, отсутствие значения нужно выразить через undefined или null и проверить в кастомном хуке.

## Вопрос

Как получить безопасный контекст без фиктивного default-объекта и утверждений null! ?

## Основная идея

Значение по умолчанию используется, когда выше нет подходящего провайдера. Если приложение без него работать не должно, «пустая заглушка» с неработающими функциями только скроет ошибку.

Честный тип `ThemeValue | undefined` заставляет обработать отсутствие провайдера. Кастомный хук выполняет проверку один раз и возвращает потребителям уже суженный тип.

Контекст объявляют на уровне модуля. Его value должен соответствовать контракту, а state провайдера типизируется отдельно.

## Пример: тема с обязательным провайдером

```tsx
import { createContext, useContext, useState } from "react";
import type { ReactNode } from "react";

type Mode = "light" | "dark";
type ThemeValue = {
  mode: Mode;
  toggle: () => void;
};

const ThemeContext = createContext<ThemeValue | undefined>(undefined);

function useTheme(): ThemeValue {
  const value = useContext(ThemeContext);
  if (value === undefined) throw new Error("Нужен ThemeProvider");
  return value;
}

function ThemeProvider({ children }: { children: ReactNode }) {
  const [mode, setMode] = useState<Mode>("light");
  const toggle = () => setMode(m => m === "light" ? "dark" : "light");

  return (
    <ThemeContext.Provider value={{ mode, toggle }}>
      {children}
    </ThemeContext.Provider>
  );
}

function ThemeButton() {
  const { mode, toggle } = useTheme();
  return <button onClick={toggle}>{mode}</button>;
}

export default function App() {
  return <ThemeProvider><ThemeButton /></ThemeProvider>;
}
```

В `ThemeButton` проверка больше не нужна. Ошибка неверного размещения будет понятной и возникнет в одном месте.

## Когда допустим настоящий default

Если значение вне провайдера имеет смысл, например язык `"ru"`, можно задать его напрямую и обойтись без union.

Если `null` означает «пользователь не вошел», это допустимое бизнес-значение. Для отличия от отсутствующего провайдера можно использовать отдельный `undefined`.

Для reducer-контекста dispatch описывают как `Dispatch<Action>`. Не нужно заменять его произвольным any.

## Производительность

Типизация не меняет правила рендера context. Новый value-объект может обновить потребителей. Memoization или разделение контекстов применяют по потребности, сохраняя корректные зависимости.

## Что важно помнить

- Передавайте тип в `createContext<AuthValue | null>(null)`.
- Создайте хук `useAuth`, который бросает ошибку при отсутствии провайдера и возвращает тип без `null`.
- Не используйте пустой объект с приведением `{} as AuthValue` — это скрывает ошибки.
- Тип значения провайдера проверяется автоматически по типу контекста.

## Мини-шпаргалка

- Опиши форму value.
- Вырази отсутствие провайдера честным типом.
- Сузь тип проверкой в хуке.
- Не подменяй проверку утверждением null!.
- Default должен иметь реальный смысл.
