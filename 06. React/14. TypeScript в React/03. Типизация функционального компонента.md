# Как типизировать функциональный компонент

> [!NOTE]
> Обычно достаточно описать **тип props** и указать его у параметра функции. Тип возвращаемого значения TypeScript часто выводит сам.

## Вопрос

Как описывать props, children, нативные атрибуты и generic-компоненты без лишних утверждений типов?

## Базовый подход

Тип props - контракт компонента. Обязательное поле нужно передать, необязательное отмечается `?`. Для вложенного отображаемого контента обычно подходит `ReactNode`.

Можно использовать `type` или `interface`. Выбор обычно определяется соглашениями проекта, а не разницей в рендеринге.

## Пример: карточка и нативная кнопка

```tsx
import type { ComponentPropsWithoutRef, ReactNode } from "react";

type CardProps = {
  title: string;
  children: ReactNode;
};

function Card({ title, children }: CardProps) {
  return <section><h2>{title}</h2>{children}</section>;
}

type ButtonProps = ComponentPropsWithoutRef<"button"> & {
  variant?: "primary" | "ghost";
};

function Button({ variant = "primary", type = "button", ...rest }: ButtonProps) {
  return <button {...rest} type={type} data-variant={variant} />;
}

export default function App() {
  return (
    <Card title="Практика">
      <Button onClick={() => console.log("Старт")}>Начать</Button>
    </Card>
  );
}
```

Нативные `disabled`, `onClick` и `children` берутся из типа кнопки. `variant` остается собственным prop и не утекает случайно в DOM.

## Generic-компонент

Фрагмент для переиспользуемого списка:

```tsx
import type { ReactNode } from "react";

type ListProps<T> = {
  items: readonly T[];
  getKey: (item: T) => string;
  renderItem: (item: T) => ReactNode;
};

function List<T>({ items, getKey, renderItem }: ListProps<T>) {
  return <ul>{items.map(item => (
    <li key={getKey(item)}>{renderItem(item)}</li>
  ))}</ul>;
}
```

Тип `T` сохраняет связь между элементом массива и callback.

## React.FC, memo и ref

`React.FC<Props>` допустим, но не обязателен. В актуальных типах он не добавляет children автоматически; это поле нужно описать явно. Утверждение «FC всегда запрещен» некорректно.

`memo` обычно сохраняет простой контракт props. Для ref в React 19 можно описать prop с типом `Ref<HTMLInputElement>`; в React 18 обычно используют `forwardRef<HTMLInputElement, Props>`. Версии React и типов должны соответствовать выбранному API.

## Что важно помнить

- Предпочтительно типизировать props параметра: `function Button({ label }: ButtonProps)`.
- `React.FC` не обязателен; в React 18 он больше не добавляет `children` неявно.
- Расширяйте нативные props через `ComponentProps<'button'>`.
- Возвращаемый тип обычно выводится, явно его указывать не нужно.

## Мини-шпаргалка

- Начни с обычной функции и Props.
- Children описывай явно.
- Нативные props переиспользуй через ComponentProps.
- Generic сохраняет отношения типов.
- Не добавляй ручной return type без необходимости.
