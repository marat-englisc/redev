# Типизация хуков: useState, useRef, useMemo, useCallback

> [!NOTE]
> Хуки React — дженерики, и в большинстве случаев TypeScript **выводит тип сам** из начального значения или возвращаемого результата. Явный параметр типа нужен, когда начальное значение не описывает все возможные: `useState<User | null>(null)`, `useState<string[]>([])`. Для `useRef` важно различать ref к DOM-элементу (`useRef<HTMLInputElement>(null)`) и ref для мутируемого значения. `useMemo` и `useCallback` выводят тип из функции — типизируют аргументы колбэка.

## Вопрос

Как типизировать состояние в `useState()`? Как типизировать `useRef()`, `useMemo()` и `useCallback()`?

## useState

```tsx
const [count, setCount] = useState(0);                 // number — выведено
const [name, setName] = useState("");                  // string

const [user, setUser] = useState<User | null>(null);   // без дженерика был бы тип null
const [items, setItems] = useState<Product[]>([]);     // без дженерика — never[]

type Status = "idle" | "loading" | "success" | "error";
const [status, setStatus] = useState<Status>("idle");  // без дженерика — string

// ленивая инициализация
const [draft, setDraft] = useState<Draft>(() => loadDraft());
```

Дискриминированное объединение для связанного состояния:

```tsx
type RequestState<T> =
  | { status: "loading" }
  | { status: "error"; error: Error }
  | { status: "success"; data: T };

const [state, setState] = useState<RequestState<User>>({ status: "loading" });

if (state.status === "success") state.data.name; // TS знает, что data есть
```

Тип сеттера при передаче в props: `React.Dispatch<React.SetStateAction<User | null>>`.

## useRef

```tsx
// 1. DOM-элемент: начальное значение null, current — readonly-ссылка, React заполняет сам
const inputRef = useRef<HTMLInputElement>(null);
inputRef.current?.focus();          // current: HTMLInputElement | null

// 2. Мутируемое значение
const timerRef = useRef<number | null>(null);
timerRef.current = window.setTimeout(tick, 1000);

const renderCount = useRef(0);       // number — выведено
renderCount.current += 1;
```

| Запись | Тип `current` | Для чего |
| --- | --- | --- |
| `useRef<HTMLDivElement>(null)` | `HTMLDivElement \| null` | DOM |
| `useRef<number \| null>(null)` | `number \| null`, изменяемый | таймеры, значения |
| `useRef(0)` | `number` | счетчики, флаги |

В React 19 `useRef` требует аргумент, а `RefObject.current` всегда изменяемый.

## useMemo

```tsx
const total = useMemo(
  () => items.reduce((sum, i) => sum + i.price, 0),
  [items],
); // number — выведено

const options = useMemo<ChartOptions>(() => ({ color, animate: true }), [color]);
```

Явный дженерик нужен, когда хотите проверить литерал на соответствие типу.

## useCallback

```tsx
const handleChange = useCallback((e: React.ChangeEvent<HTMLInputElement>) => {
  setName(e.target.value);
}, []); // (e: ChangeEvent<HTMLInputElement>) => void

const handleSelect = useCallback((id: string) => onSelect(id), [onSelect]);
```

Типизируйте параметры колбэка — иначе они будут `any` (при `noImplicitAny` — ошибка).

## Что важно помнить

- Не указывайте дженерик там, где тип выводится, — лишний шум.
- `useState<User>()` без аргумента даст `User | undefined`.
- Для `useReducer` типизируют `state` и `action` (discriminated union) — остальное выводится.
- Используйте `ComponentProps<"input">` и `ComponentRef<typeof Comp>` для получения типов существующих компонентов.

## Мини-шпаргалка

`useState` — тип выводится, явно для `null`, `[]` и union: `useState<User | null>(null)`. `useRef<HTMLInputElement>(null)` — DOM, `useRef<number | null>(null)` — значение. `useMemo`/`useCallback` — выводят тип, типизировать аргументы колбэка.
