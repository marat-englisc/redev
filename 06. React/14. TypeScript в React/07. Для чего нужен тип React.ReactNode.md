# Для чего нужен ReactNode

> [!NOTE]
> **ReactNode** описывает значения, поддерживаемые React как отображаемое содержимое. Обычно его используют для children и именованных областей интерфейса.

## Вопрос

Чем ReactNode отличается от ReactElement и React.JSX.Element и когда нужен более узкий тип?

## Основная идея

Карточка может принимать текст, один элемент, несколько элементов или пустое значение. Если задать children тип `ReactElement`, обычная строка уже не подойдет. `ReactNode` выражает более широкий контракт.

В привычных случаях в него входят React-элементы, строки, числа, коллекции узлов, порталы и пустые значения. Boolean, null и undefined не добавляют видимого содержимого.

В типах React 19 поддержка шире, чем в старых версиях: например, учитываются bigint и поддерживаемые Promise-значения. Но тип не означает, что создание нового Promise в каждом клиентском рендере является корректной стратегией загрузки.

## Пример: разные виды контента

```tsx
import type { ReactElement, ReactNode } from "react";

function Card({ children }: { children: ReactNode }) {
  return <section className="card">{children}</section>;
}

function IconFrame({ icon }: { icon: ReactElement }) {
  return <span className="icon">{icon}</span>;
}

export default function App() {
  return (
    <>
      <Card>Обычный текст</Card>
      <Card><strong>Важная мысль</strong></Card>
      <Card>{null}</Card>
      <IconFrame icon={<span aria-label="Успех">✓</span>} />
    </>
  );
}
```

Card принимает все три варианта. IconFrame намеренно требует элемент, поэтому строка в `icon` не подойдет.

## Сравнение типов

| Тип | Для чего обычно подходит |
| --- | --- |
| ReactNode | Произвольное отображаемое содержимое |
| ReactElement | Конкретный объект React-элемента |
| React.JSX.Element | Тип результата JSX-выражения |
| (data: T) => ReactNode | Функция создания содержимого по данным |

В актуальных типах используют `React.JSX` либо импорт `JSX` из React, а не рассчитывают на старое глобальное пространство имен `JSX`.

## Ограничения

Обычный объект данных или callback сам по себе не является отображаемым содержимым. Функцию для render prop нужно типизировать отдельно и вызывать.

Тип `ReactElement` не гарантирует наличие одного конкретного DOM-тега или нужную семантику. Это объект описания React, который может представлять и пользовательский компонент.

## Что важно помнить

- `ReactNode` — всё, что можно отрендерить: JSX, строки, числа, массивы, `null`, `undefined`, булевы.
- Используйте его для `children` и слотов.
- `ReactElement` — только JSX-элемент; `JSX.Element` — результат JSX-выражения.
- Для render props типизируйте функцию: `(value: T) => ReactNode`.

## Мини-шпаргалка

- Children и слоты обычно имеют тип ReactNode.
- ReactElement подходит для намеренно узкого контракта.
- Null и boolean могут быть узлами без видимого результата.
- Функцию рендера описывают отдельной сигнатурой.
- Набор типов зависит от версии @types/react.
