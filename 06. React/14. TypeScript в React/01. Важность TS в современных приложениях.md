# Зачем TypeScript в React-приложении

> [!NOTE]
> **TypeScript** описывает контракты props, state, событий и данных. Проверка типов помогает найти часть ошибок до запуска приложения.

## Вопрос

Какие задачи TypeScript решает в React и почему типы не заменяют проверку данных API?

## Основная идея

Если кнопке нужен текст, а карточке - объект с именем и ID, эти требования можно выразить типами. Редактор подскажет обязательные поля и обнаружит неподходящий аргумент.

Особенно полезны типы при изменениях: если переименовать prop или поменять формат результата, компилятор покажет места, которые нужно исправить. Для fullstack TypeScript это помогает описывать контракты между слоями, но не обеспечивает их соблюдение удаленной системой автоматически.

Типы удаляются при преобразовании в JavaScript. Сервер может вернуть неожиданный JSON, пользователь - прислать неверные данные. Для таких границ нужна runtime-валидация.

## Пример: контракт карточки

```tsx
type Course = {
  id: string;
  title: string;
  lessons: number;
};

type CourseCardProps = {
  course: Course;
  onOpen: (id: string) => void;
};

function CourseCard({ course, onOpen }: CourseCardProps) {
  return (
    <article>
      <h2>{course.title}</h2>
      <p>Уроков: {course.lessons}</p>
      <button onClick={() => onOpen(course.id)}>Открыть</button>
    </article>
  );
}

export default function App() {
  return (
    <CourseCard
      course={{ id: "react", title: "React", lessons: 12 }}
      onOpen={id => console.log("Открываем", id)}
    />
  );
}
```

Параметр callback автоматически имеет тип `string`. Передача `lessons: "12"` вместо числа вызовет ошибку проверки типов, если не обходить ее через `any` или утверждения.

## Что нужно для проекта

Файлы с JSX и TypeScript имеют расширение `.tsx`. Нужны совместимые версии `typescript`, `@types/react` и `@types/react-dom`, а также настройка JSX в сборке.

Важно реально запускать проверку, например `tsc --noEmit`: некоторые сборщики только удаляют типы и не проверяют их.

## Ограничения

TypeScript не доказывает правильность бизнес-алгоритма и не предотвращает все исключения. `response.json() as Course` - обещание компилятору, а не проверка ответа.

## Что важно помнить

- TypeScript ловит ошибки props, состояния и API на этапе компиляции.
- Типы служат документацией и улучшают автодополнение и рефакторинг.
- Типы исчезают при сборке — проверку данных из сети делают в рантайме (Zod, Valibot).
- Включайте `strict: true` с самого начала проекта.

## Мини-шпаргалка

- Типизируй внешние контракты.
- Используй вывод типов внутри понятного кода.
- Не обходи ошибки через any без причины.
- Проверяй недоверенные данные во время выполнения.
- Добавь typecheck в проверки проекта.
