# Несовпадение HTML при гидрации

> [!NOTE]
> Hydration mismatch возникает, когда первый клиентский рендер отличается от HTML сервера. Причину нужно исправлять, а не считать предупреждение безвредным.

## Вопрос

Почему серверная и клиентская разметка расходятся и как это предотвращать?

## Основная идея

Если сервер показывает текущее время, а клиент вычисляет `new Date()` позднее, текст может отличаться. Аналогично работают `Math.random()`, разные часовые пояса, содержимое `localStorage` и данные API, изменившиеся между запросами. Даже одинаковый компонент даст разные деревья при разных входных данных.

Есть и структурные причины: неправильная вложенность HTML заставляет браузер перестроить DOM до запуска React. Например, браузер исправляет `<div>` внутри `<p>`. Расширения тоже могут изменить документ, но сначала следует исключить собственные ошибки приложения.

React рассматривает совпадение как обязательный контракт. Восстановление может включать клиентский рендер поддерева, а несовпадающие атрибуты не гарантированно исправляются. Безопасный подход — один сериализованный исходный снимок данных и детерминированный первый рендер. Клиентские особенности добавляют эффектом после гидрации.

## Пример

Компонент для SSR и последующей гидрации; сервер и клиент передают одинаковый `initialTime`.

```jsx
import { useEffect, useState } from 'react';

export default function Clock({ initialTime = '2026-10-15T12:00:00.000Z' }) {
  const [time, setTime] = useState(initialTime);
  useEffect(() => {
    const timer = setInterval(() => setTime(new Date().toISOString()), 1000);
    return () => clearInterval(timer);
  }, []);
  return <time dateTime={time}>{time}</time>;
}
```

Первое значение фиксировано и совпадает на сервере и клиенте. Часы начинают обновляться только после клиентского эффекта. В реальном SSR `initialTime` формирует сервер и передаёт то же значение браузеру.

## Что важно помнить

- `suppressHydrationWarning` — узкое исключение для неизбежного локального расхождения, а не ремонт всего дерева.
- Проверяйте валидность HTML, локаль и одинаковые начальные props.
- `typeof window !== "undefined"` в render может создать mismatch, даже если предотвращает серверную ошибку.

## Мини-шпаргалка

Детерминированный render + общий снимок данных + валидный HTML. Клиентские изменения → после гидрации.
