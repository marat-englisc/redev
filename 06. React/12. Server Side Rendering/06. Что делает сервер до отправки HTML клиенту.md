# Что делает сервер до отправки HTML

> [!NOTE]
> Сервер сопоставляет запрос с маршрутом, проверяет доступ, загружает нужные данные и рендерит ответ с правильными статусом и заголовками.

## Вопрос

Какие этапы проходит SSR-запрос до отправки страницы браузеру?

## Основная идея

SSR начинается не с вызова React. Сначала HTTP-сервер или фреймворк разбирает адрес, cookies и заголовки, выбирает маршрут и определяет контекст пользователя. Приватные данные разрешено загружать только после проверки доступа. Затем получают данные страницы и решают, какой статус нужен: успех, редирект или отсутствие ресурса.

Дальше React создаёт HTML. Для гидрации браузеру понадобится тот же исходный снимок данных и клиентский bundle. Сериализация этого снимка должна быть безопасной: обычный JSON нельзя без подготовки вставлять в script-тег. Фреймворки обычно скрывают большую часть инфраструктурной работы.

При streaming сервер может отправить оболочку раньше, чем завершены все блоки. Поэтому статус, cookies и критичные заголовки нужно определить до начала потока: после отправки заголовков изменить HTTP-код уже нельзя. Параллельная загрузка независимых данных уменьшает серверный водопад.

## Пример

Серверный JSX-модуль Node.js; экспортируемый `handleProfile` передают в HTTP-сервер после настройки преобразования JSX.

```jsx
import { renderToString } from 'react-dom/server';

function Profile({ name }) {
  return <main><h1>Профиль: {name}</h1></main>;
}

export async function handleProfile(request, response) {
  // Учебные данные. В реальном маршруте здесь проверка сессии и запрос к БД.
  const url = new URL(request.url, 'http://localhost');
  if (url.pathname !== '/profile') {
    response.writeHead(404, { 'Content-Type': 'text/html; charset=utf-8' });
    response.end('<h1>Страница не найдена</h1>');
    return;
  }
  const html = renderToString(<Profile name="Анна" />);
  response.writeHead(200, { 'Content-Type': 'text/html; charset=utf-8' });
  response.end('<!doctype html>' + html);
}
```

Функция предназначена для подключения к Node HTTP-серверу. Она выбирает маршрут и статус до отправки тела. Для упрощения страница статическая и не подключает гидрацию.

## Что важно помнить

- Не загружайте приватные данные до авторизации и не храните их в общем глобальном объекте.
- API-ошибки обрабатывайте до начала ответа либо предусмотрите поведение незавершённого потока.
- React экранирует текстовые JSX-значения, но ручные HTML-вставки требуют отдельного анализа.

## Мини-шпаргалка

Request → маршрут/доступ → данные → статус/headers → render → безопасный ответ.
