# Как SSR влияет на SEO и время первой отрисовки

> [!NOTE]
> SSR улучшает **SEO**, потому что поисковый робот сразу получает HTML с контентом, заголовками, мета-тегами и ссылками — ему не нужно выполнять JS. SSR ускоряет **первую отрисовку контента** (FCP, LCP): браузер начинает рисовать по мере получения HTML, не дожидаясь загрузки и выполнения бандла. Но SSR может увеличить **TTFB**, а интерактивность (TTI, INP) по-прежнему зависит от размера JS и гидрации.

## Вопрос

Почему SSR может улучшить SEO? Как SSR влияет на Time to First Paint и другие метрики?

## SEO

С CSR робот получает пустой `<div id="root">`:

- Googlebot рендерит JS, но **во второй волне**, с задержкой и ограничениями по ресурсам;
- Bing, Яндекс и другие поисковики выполняют JS хуже;
- боты соцсетей и мессенджеров (превью ссылок) JS не выполняют вообще.

С SSR в первом ответе есть всё, что нужно:

```html
<head>
  <title>iPhone 16 — купить в Москве</title>
  <meta name="description" content="Цена, характеристики, отзывы" />
  <meta property="og:image" content="https://shop.ru/img/iphone16.jpg" />
  <link rel="canonical" href="https://shop.ru/iphone-16" />
</head>
<body>
  <h1>iPhone 16</h1>
  <a href="/iphone-16/reviews">Отзывы</a>
</body>
```

Что еще важно для SEO помимо SSR: семантическая разметка, корректные статусы (404, 301), `sitemap.xml`, структурированные данные (JSON-LD), скорость (Core Web Vitals — фактор ранжирования).

## Метрики загрузки

```text
CSR:  [TTFB]→[загрузка JS]→[выполнение]→[запрос данных]→ FCP/LCP → TTI
SSR:  [TTFB (дольше)]→ FCP/LCP →[загрузка JS]→[гидрация]→ TTI
```

| Метрика | Влияние SSR |
| --- | --- |
| TTFB (Time to First Byte) | хуже: сервер загружает данные и рендерит |
| FCP (First Contentful Paint) | лучше: контент в HTML |
| LCP (Largest Contentful Paint) | обычно лучше |
| TTI / INP | не лучше: нужен JS и гидрация; может быть «мертвый» период |
| CLS | лучше: размеры элементов известны сразу |

## Как улучшить TTFB при SSR

- **Streaming SSR**: отдать оболочку сразу, медленные части — по мере готовности;
- кеширование на CDN (`s-maxage`, `stale-while-revalidate`);
- кеширование данных и параллельные запросы;
- edge-рендеринг ближе к пользователю;
- SSG/ISR для страниц, не требующих свежих данных.

## Что важно помнить

- «Time to First Paint» — устаревшее название; сейчас ориентируются на FCP и LCP.
- SSR без оптимизации JS дает быстрый показ, но медленную интерактивность — пользователь кликает, а ничего не происходит.
- Для SEO важно, чтобы контент был в HTML, а не только в JSON для гидрации.
- Измеряйте в Lighthouse, PageSpeed Insights и полевых данных (CrUX).

## Мини-шпаргалка

SSR → HTML с контентом и мета-тегами → роботы и превью видят страницу сразу. FCP и LCP лучше, TTFB хуже, TTI зависит от JS. TTFB лечат streaming, кешем, CDN, SSG/ISR.
