# JSON.stringify и безопасность SSR

> [!NOTE]
> JSON.stringify создаёт корректный JSON, но не делает строку безопасной для вставки в HTML. В script-контексте пользовательское значение может преждевременно закрыть тег.

## Вопрос

Почему обычная сериализация данных внутри script-тега может привести к XSS?

## Основная идея

Допустим, сервер передаёт имя пользователя в `<script>window.DATA = ...</script>`. В имени содержится `</script><script>...`. Для JSON это обычная допустимая строка, но HTML-парсер увидит закрытие script-тега раньше, чем JavaScript начнёт разбирать JSON. В результате злоумышленник получает возможность добавить исполняемую разметку.

Даже `type="application/json"` сам по себе не решает проблему: HTML-парсер всё равно распознаёт закрывающий тег. Нужно сериализовать данные с учётом HTML-контекста. В учебном варианте замена символа `<` на текстовую последовательность `\u003c` предотвращает появление `</script` внутри полезной нагрузки.

В продакшене предпочитают механизм передачи данных фреймворка или проверенный сериализатор. Контекст важен: решение для JSON в script-теге не является универсальным экранированием HTML-атрибутов, URL и произвольных вставок. Серверные секреты нельзя передавать клиенту даже в идеально экранированном JSON.

## Пример

Учебный JSX-модуль, выполняемый на сервере Node.js после преобразования JSX сборщиком. `renderToString` здесь используется для наглядности; клиентский bundle и HTTP-сервер добавляются отдельно.

```jsx
import { renderToString } from 'react-dom/server';

const data = { name: '</script><script>alert("xss")</script>' };
const safeJson = JSON.stringify(data).replace(/</g, '\\u003c');

function Document() {
  return <html lang="ru">
    <head><title>Безопасный снимок данных</title></head>
    <body>
      <p>{data.name}</p>
      <script id="initial-data" type="application/json"
        dangerouslySetInnerHTML={{ __html: safeJson }} />
    </body>
  </html>;
}
console.log('<!doctype html>' + renderToString(<Document />));

// В отдельном клиентском модуле:
// const initialData = JSON.parse(document.getElementById('initial-data').textContent);
```

Имя в `<p>` React экранирует как текст. Для содержимого script-тега ответственность берёт `safeJson`: опасного символа `<` в нём уже нет, а JSON.parse восстановит исходное значение.

## Что важно помнить

- Не вставляйте сырые пользовательские строки через `dangerouslySetInnerHTML`.
- CSP полезна как дополнительная защита, но не заменяет корректную сериализацию.
- Не передавайте пароли, приватные токены и серверные ключи в начальном снимке.
- JSON не сохраняет автоматически Date, Map и другие специальные типы.

## Мини-шпаргалка

Корректный JSON ≠ безопасный HTML. Сначала выбрать контекст, затем использовать подходящую сериализацию.
