# Hydration: SSR + гидрация и что изменилось в React 18

> [!NOTE]
> **Гидрация (hydration)** — процесс, при котором React на клиенте «оживляет» HTML, пришедший с сервера: строит дерево компонентов, сопоставляет его с существующими DOM-узлами (не создавая их заново), навешивает обработчики событий и запускает эффекты. Связка **SSR + Hydration** дает быстрый первый показ контента (HTML готов сразу) и полноценную интерактивность после загрузки JS. В React 18 появились `hydrateRoot`, **streaming** и **selective hydration**: части страницы гидрируются независимо, в приоритете — та, с которой взаимодействует пользователь.

## Вопрос

Что такое гидрация в контексте SSR? Что означает «SSR + Hydration» и как гидрация изменилась в React 18?

## Как это работает

```text
1. Сервер: renderToPipeableStream(<App />) → HTML
2. Браузер: показывает HTML (контент виден, но кнопки не работают)
3. Загружается JS-бандл
4. hydrateRoot(container, <App />)
   - React рендерит дерево в памяти
   - сопоставляет его с DOM
   - подключает обработчики и ref
   - запускает эффекты
5. Страница интерактивна
```

```jsx
// server.js
import { renderToPipeableStream } from "react-dom/server";

const { pipe } = renderToPipeableStream(<App />, {
  bootstrapScripts: ["/client.js"],
  onShellReady() {
    res.setHeader("content-type", "text/html");
    pipe(res);
  },
});

// client.js
import { hydrateRoot } from "react-dom/client";
hydrateRoot(document.getElementById("root"), <App />);
```

## Почему важно совпадение HTML

Клиентский рендер при гидрации должен дать **тот же результат**, что и сервер. Иначе — hydration mismatch: предупреждение и перерендер поддерева на клиенте.

Частые причины:

- `Date.now()`, `Math.random()`, `new Date().toLocaleString()` в рендере;
- проверка `typeof window !== "undefined"` в рендере;
- данные из `localStorage` при первом рендере;
- невалидная вложенность HTML (`<div>` внутри `<p>`);
- расширения браузера, меняющие DOM.

Решения: вычислять клиентские значения в `useEffect`, использовать `useSyncExternalStore` с `getServerSnapshot`, `suppressHydrationWarning` для неизбежных различий (время).

## React 17 и React 18

| | React 17 | React 18+ |
| --- | --- | --- |
| API | `ReactDOM.hydrate` | `hydrateRoot` |
| Порядок | вся страница целиком, за один проход | по границам Suspense, независимо |
| Ожидание | весь HTML и весь JS до начала гидрации | streaming: HTML и JS частей приходят по мере готовности |
| Приоритет | нет | **selective hydration**: часть, по которой кликнули, гидрируется первой |
| Блокировка | гидрация блокирует поток | гидрация прерываема |
| Ошибки mismatch | тихо исправлялись | ошибка и клиентский рендер ближайшей границы Suspense |

```jsx
<Layout>
  <NavBar />
  <Suspense fallback={<Spinner />}>
    <Comments />   {/* гидрируется отдельно; клик сюда поднимет приоритет */}
  </Suspense>
</Layout>
```

## Проблемы гидрации

- **Uncanny valley**: страница выглядит готовой, но не реагирует до завершения гидрации.
- **Двойная работа**: компоненты рендерятся на сервере и снова на клиенте.
- **Размер JS**: для гидрации нужен код всех компонентов.

Ответы экосистемы: selective hydration, React Server Components (код серверных компонентов не гидрируется), islands-архитектура (Astro), resumability (Qwik).

## Что важно помнить

- Эффекты не выполняются на сервере — первые данные для рендера должны прийти с HTML (сериализованный state).
- Данные для гидрации вставляют в HTML через безопасную сериализацию (экранирование `</script>`).
- `useId` генерирует одинаковые id на сервере и клиенте — для a11y-атрибутов.
- В React 19 улучшены сообщения о mismatch и терпимость к сторонним скриптам в `<head>`.

## Мини-шпаргалка

Гидрация = React подключается к серверному HTML: обработчики, эффекты, без пересоздания DOM. HTML должен совпадать. React 18: `hydrateRoot`, streaming, selective hydration по границам Suspense, прерываемость. Клиентские значения — в эффектах.
