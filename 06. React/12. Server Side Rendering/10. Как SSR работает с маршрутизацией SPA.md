# SSR и маршрутизация SPA

> [!NOTE]
> SSR отвечает за первоначальный документ, а клиентский роутер может обслуживать последующие переходы без полной перезагрузки страницы.

## Вопрос

Как совмещаются серверный первый рендер и клиентская навигация?

## Основная идея

При прямом открытии `/books/42` сервер должен распознать маршрут, загрузить книгу и вернуть подходящий HTML. Если он отдаёт только пустую оболочку и ждёт клиентский код, это уже другой сценарий первоначального рендера. Неизвестный маршрут должен получить корректный статус и страницу ошибки.

После гидрации клиентский роутер перехватывает внутренние переходы, обновляет URL и подгружает данные или код следующего маршрута. При этом полный HTML-документ не обязательно запрашивается заново. Фреймворк может использовать отдельный протокол данных и серверного дерева.

Сервер и клиент должны одинаково понимать маршруты и исходные данные. Иначе прямое открытие, обновление страницы и внутренний переход будут вести себя по-разному. Ссылки с настоящим `href` сохраняют базовую семантику браузера; специализированный Link добавляет клиентскую навигацию и может поддерживать предзагрузку.

## Пример

Пример для Next.js App Router; каждый блок кода сохраните в файл, указанный над ним.

### app/page.jsx

```jsx
import Link from 'next/link';

export default function Home() {
  return <main>
    <h1>Библиотека</h1>
    <Link href="/books">Открыть каталог</Link>
  </main>;
}
```

### app/books/page.jsx

```jsx
export default function BooksPage() {
  return <main><h1>Каталог книг</h1><p>React без паники</p></main>;
}
```

Прямое открытие `/books` обслуживает серверная инфраструктура Next.js. Переход по Link внутри уже загруженного приложения использует клиентскую навигацию. Стратегия подготовки конкретного маршрута может быть статической или динамической.

## Что важно помнить

- Пример требует Next.js App Router и двух файлов в показанных каталогах.
- Наличие Link не означает, что приватные данные можно загружать без серверной авторизации.
- Предзагрузка полезна, но её поведение зависит от фреймворка и типа маршрута.
- SSR не требует полной перезагрузки на каждый переход.

## Мини-шпаргалка

Первый URL → серверный маршрут. Hydration → клиентский роутер. Link → переход. Reload → снова сервер.
