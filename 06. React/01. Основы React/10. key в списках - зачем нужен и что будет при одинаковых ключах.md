# key в списках: зачем нужен и что будет при одинаковых ключах

> [!NOTE]
> `key` — специальный атрибут, по которому React сопоставляет элементы списка между рендерами. Стабильный уникальный ключ позволяет понять, какой элемент добавился, удалился или переместился, и сохранить состояние нужного компонента. Индекс массива в качестве ключа ломается при вставке, удалении и сортировке, а одинаковые ключи приводят к предупреждению и непредсказуемому поведению.

## Вопрос

Что делает `key` в списках? Почему нельзя использовать индекс и что произойдет при одинаковых ключах?

## Основная идея

Когда React рендерит список, он должен понять, какой элемент нового списка соответствует какому элементу старого. Без ключей он сравнивает по позиции: первый с первым, второй со вторым. Если вставить элемент в начало, все позиции сдвинутся, и React «обновит» каждый элемент вместо одной вставки. Хуже того — состояние компонентов (введенный текст, раскрытый аккордеон) останется на старых позициях и окажется у чужих элементов.

С `key` React сопоставляет элементы по идентификатору. Ключ должен быть **стабильным** (не меняться между рендерами), **уникальным среди соседей** и, желательно, взятым из данных (`id` из базы).

Одинаковые ключи нарушают уникальность: React выводит предупреждение `Encountered two children with the same key`, а при обновлениях может перепутать элементы — дублировать, терять или оставлять старые узлы.

## Пример

```jsx
function TodoList({ todos }) {
  return (
    <ul>
      {todos.map((todo) => (
        <li key={todo.id}>
          <input type="checkbox" defaultChecked={todo.done} />
          {todo.title}
        </li>
      ))}
    </ul>
  );
}
```

С `key={index}` после удаления первой задачи галочка первой задачи «переедет» на следующую: React решит, что удалился последний элемент, а у остальных просто поменялся текст.

## Когда индекс допустим

Только если список статичен: элементы не переставляются, не удаляются из середины и не имеют собственного состояния. Например, список пунктов меню из константы.

## Что важно помнить

- `Math.random()` или `crypto.randomUUID()` прямо в `map` — плохие ключи: они новые на каждом рендере, и React пересоздает все элементы.
- Ключ генерируют при создании данных, а не при рендере.
- Ключ нужен на верхнем элементе внутри `map`; для `<>...</>` используйте `<Fragment key={id}>`.
- `key` не передается в props компонента — если id нужен внутри, передайте его отдельным пропом.
- Смена `key` у компонента вне списка сбрасывает его состояние — удобный способ «перезапустить» форму.

## Мини-шпаргалка

`key` = идентичность элемента списка. Стабильный и уникальный, лучше `id` из данных. Индекс — только для статичных списков. Одинаковые ключи → предупреждение и путаница элементов.
