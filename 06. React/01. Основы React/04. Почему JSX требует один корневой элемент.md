# Почему соседние JSX-элементы нужно объединять

> [!NOTE]
> Соседние JSX-теги необходимо объединить в **одно JavaScript-выражение**. Это можно сделать фрагментом, общим элементом или массивом.

## Вопрос

Почему нельзя написать два соседних тега после return? Обязательно ли создавать общий DOM-элемент?

## Причина ограничения

Функция JavaScript возвращает одно значение. Выражение `<h1>...</h1>` создает одно описание React-элемента. Если сразу за ним без объединяющей конструкции стоит `<p>...</p>`, такой код не соответствует грамматике JSX и завершится синтаксической ошибкой при сборке.

Это ограничение записи, а не требование иметь один HTML-узел на компонент. Одним возвращаемым значением может быть массив React-узлов или Fragment с несколькими детьми.

Важно не объяснять ошибку через оператор запятая: соседние JSX-теги сами по себе в него не превращаются. Если вручную написать `return (a, b)`, JavaScript вернет последнее выражение `b`, но это уже другой код.

## Пример: заголовок и описание

```jsx
export default function AboutCourse() {
  return (
    <>
      <h1>Подготовка к собеседованию</h1>
      <p>Разбираем React на примерах.</p>
    </>
  );
}
```

Фрагмент группирует элементы на уровне React. В DOM появятся `h1` и `p`, без дополнительного `div`.

Если нужен смысловой контейнер или общий фон, подойдет обычный элемент:

```jsx
function CourseSection() {
  return (
    <section className="course">
      <h2>React</h2>
      <p>Компоненты, состояние и хуки.</p>
    </section>
  );
}
```

Также допустим массив:

```jsx
function ShortFacts() {
  return [
    <p key="components">UI состоит из компонентов.</p>,
    <p key="state">State хранит изменяемые данные.</p>,
  ];
}
```

Для элементов массива нужны устойчивые ключи.

## Как выбрать обертку

Если у группы есть смысл в HTML или нужны стили контейнера, используй подходящий тег. Если нужна только группировка JSX, выбери Fragment.

Лишний `div` может изменить поведение grid или flex и нарушить допустимую структуру таблицы. Поэтому механически добавлять его везде не стоит.

## Что важно помнить

- Функция может вернуть одно значение, поэтому JSX-выражение должно иметь один корень.
- Чтобы не добавлять лишний `<div>`, используйте Fragment `<>...</>`.
- Лишние обертки ломают CSS-раскладки (flex, grid) и семантику таблиц и списков.
- Массив элементов тоже можно вернуть, но каждому нужен `key`.

## Мини-шпаргалка

- Соседние теги без объединения - синтаксическая ошибка.
- Одно возвращаемое значение может содержать несколько узлов.
- Fragment не добавляет обычный контейнер в DOM.
- Массив узлов - тоже допустимый результат.
