# Декларативный подход в React

> [!NOTE]
> React называют декларативным, потому что разработчик описывает, **как должен выглядеть интерфейс** при текущем состоянии, а React сам вычисляет и выполняет нужные изменения DOM. В императивном подходе нужно вручную указывать шаги: найти элемент, поменять текст, добавить класс, удалить узел.

## Вопрос

Почему React называют декларативной библиотекой? Что такое декларативный подход и чем он отличается от императивного?

## Основная идея

В императивном коде вы управляете процессом: «найди кнопку, если товар добавлен — поменяй текст на „В корзине“, добавь класс, обнови счетчик в шапке». Каждый новый сценарий добавляет ветки, и легко забыть одно из мест, где нужно синхронизировать DOM с данными.

В декларативном коде вы описываете результат как функцию состояния: `UI = f(state)`. Когда состояние меняется, React заново вызывает компонент, сравнивает новое описание с предыдущим и применяет минимальные изменения к DOM. Разработчик думает о том, **что** показать, а не **как** перевести экран из одного состояния в другое.

Декларативность не означает отсутствие императивного кода вообще: React внутри работает императивно с DOM, а в эффектах и обработчиках вы по-прежнему пишете шаги. Но описание интерфейса остается декларативным, а значит предсказуемым и легко тестируемым.

## Пример

Императивно, на чистом DOM:

```javascript
const button = document.querySelector("#add");
const counter = document.querySelector("#count");
let count = 0;

button.addEventListener("click", () => {
  count++;
  counter.textContent = String(count);
  button.textContent = count > 0 ? "Добавить еще" : "В корзину";
  counter.classList.toggle("hidden", count === 0);
});
```

Декларативно, в React:

```jsx
import { useState } from "react";

export default function AddToCart() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <button onClick={() => setCount(count + 1)}>
        {count > 0 ? "Добавить еще" : "В корзину"}
      </button>
      {count > 0 && <span>В корзине: {count}</span>}
    </div>
  );
}
```

Компонент описывает оба состояния сразу. Переход между ними — забота React.

## Что важно помнить

- Декларативный UI проще читать: глядя на JSX, видно все возможные состояния экрана.
- Источник правды — состояние, а не DOM; читать данные из DOM в React обычно не нужно.
- Прямые изменения DOM в обход React ломают синхронизацию — используйте их только через `ref` для точечных задач (фокус, измерения, сторонние библиотеки).
- Та же идея лежит в основе Vue, Svelte, SwiftUI и Jetpack Compose.

## Мини-шпаргалка

UI = f(state). Описываем результат, а не шаги. React сам применяет изменения к DOM. Императивный код — в обработчиках и эффектах.
