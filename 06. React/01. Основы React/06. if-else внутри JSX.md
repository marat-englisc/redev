# Как использовать if-else при работе с JSX

> [!NOTE]
> Внутри JSX-скобок нужны **выражения**, поэтому if-else размещают до return, а для выбора прямо в разметке используют тернарный оператор или &&.

## Вопрос

Почему if нельзя вставить прямо в JSX и какие способы условного рендеринга существуют?

## Объяснение

Выражение вычисляет значение: `count + 1`, `getTitle()`, `isOpen ? "Да" : "Нет"`. Инструкция `if` управляет выполнением кода, но сама не является значением. Поэтому запись `{if (...) ...}` синтаксически неверна.

Условный рендеринг означает, что компонент возвращает разное описание интерфейса при разных данных. React не требует специального языка шаблонов - используются обычные конструкции JavaScript.

Для нескольких состояний удобно делать ранние возвраты. Для небольшого выбора между двумя фрагментами подойдет тернарный оператор.

## Пример: состояния списка уроков

```jsx
function Lessons({ isLoading, error, lessons }) {
  if (isLoading) {
    return <p role="status">Загружаем уроки...</p>;
  }

  if (error) {
    return <p role="alert">Не удалось загрузить: {error}</p>;
  }

  return (
    <section>
      <h2>Уроки</h2>
      {lessons.length > 0 ? (
        <ul>
          {lessons.map(lesson => (
            <li key={lesson.id}>{lesson.title}</li>
          ))}
        </ul>
      ) : (
        <p>Пока нет уроков.</p>
      )}
    </section>
  );
}

export default function App() {
  return <Lessons isLoading={false} error={null} lessons={[]} />;
}
```

Сначала проверяются особые состояния. Если загрузки и ошибки нет, компонент выбирает список либо сообщение о пустом результате.

## Нюанс с &&

```jsx
function Notifications({ count }) {
  return (
    <div>
      {count > 0 && <span>Уведомлений: {count}</span>}
    </div>
  );
}
```

Условие `count > 0` дает boolean. Запись `count && <span>...` при нуле вернет число `0`, которое React покажет на странице. Значения `false`, `null` и `undefined` ничего видимого не добавляют.

## Частые ошибки

Не вызывай обычные хуки после условного раннего возврата: их порядок должен сохраняться между рендерами. Сложные цепочки вложенных тернарных операторов лучше заменить отдельной функцией или понятными ветками `if`.

## Что важно помнить

- Внутри JSX нельзя использовать `if` — только выражения: тернарный оператор, `&&`, вызов функции.
- `{count && <List />}` при `count = 0` отрисует `0` — используйте `count > 0 &&`.
- Сложные условия выносите в переменные или ранний `return` до JSX.
- `null`, `undefined`, `false` и `true` ничего не рендерят.

## Мини-шпаргалка

- `if` - до JSX или в отдельной функции.
- `condition ? a : b` - выбор внутри JSX.
- `condition && node` - показ при условии.
- `return null` - отсутствие видимого результата.
