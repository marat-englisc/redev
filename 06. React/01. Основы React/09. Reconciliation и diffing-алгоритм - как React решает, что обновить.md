# Reconciliation и diffing-алгоритм: как React решает, что обновить

> [!NOTE]
> **Reconciliation** — процесс, в котором React сравнивает новое дерево элементов с предыдущим и решает, какие компоненты сохранить, обновить или пересоздать и какие изменения внести в DOM. Полное сравнение деревьев стоило бы `O(n³)`, поэтому React использует эвристический **diffing-алгоритм** за `O(n)`: элементы разных типов пересоздаются целиком, элементы одного типа обновляются, а дети в списках сопоставляются по `key`.

## Вопрос

Что такое reconciliation и diffing algorithm? Как React определяет, какие компоненты нужно обновить, и как это связано с Virtual DOM?

## Основная идея

После вызова `setState` React заново рендерит компонент и его потомков, получает новое дерево React-элементов и сравнивает его с деревом из прошлого рендера. Сравнение идет по позиции в дереве и строится на двух предположениях.

**1. Разные типы — разные деревья.** Если на одной позиции `<div>` сменился на `<section>` или `<UserCard>` на `<AdminCard>`, React не пытается сравнивать содержимое: старое поддерево размонтируется вместе с состоянием, новое монтируется с нуля.

**2. Одинаковый тип — обновление.** Для DOM-элемента одного тега React меняет только изменившиеся атрибуты. Для компонента одного типа сохраняется экземпляр и его state, компонент получает новые props.

**3. Списки сопоставляются по key.** Без ключей React сравнивает детей по индексу: вставка в начало списка заставит обновить все элементы. С ключами React понимает, какой элемент переместился, какой добавился и какой исчез.

Результат reconciliation — список изменений, которые React применяет к DOM в фазе commit.

## Пример

```jsx
function Page({ isAdmin }) {
  return isAdmin ? <AdminPanel /> : <UserPanel />;
  // смена isAdmin: разные типы → UserPanel размонтирован, AdminPanel создан с чистым state
}

function Profile({ editing }) {
  return editing ? <input defaultValue="Анна" /> : <input disabled defaultValue="Анна" />;
  // один тип input → обновится только атрибут disabled, введенный текст сохранится
}

function Form({ step }) {
  return <Wizard key={step} />; // смена key принудительно пересоздает компонент и сбрасывает state
}
```

## Как React решает, кого перерендерить

- компонент рендерится заново, если изменился его state или контекст, который он читает, либо перерендерился родитель;
- `React.memo` пропускает рендер, если props поверхностно равны;
- React сравнивает результат, но не DOM: если JSX не изменился, DOM не трогается.

## Что важно помнить

- Не объявляйте компоненты внутри других компонентов: при каждом рендере это новый тип, и React будет пересоздавать поддерево и терять state.
- Позиция в дереве определяет «идентичность» компонента: условный рендер `{show && <A />}` перед другим элементом меняет позиции.
- `key` можно использовать вне списков — чтобы сбросить состояние компонента.
- Reconciliation выполняется в фазе render и может быть прерван в concurrent-режиме; commit — синхронный.

## Мини-шпаргалка

Reconciliation = сравнение старого и нового дерева. Разный тип → пересоздать. Тот же тип → обновить props и атрибуты. Списки → по `key`. Смена `key` → сброс state.
