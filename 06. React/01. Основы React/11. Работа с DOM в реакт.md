# Как работать с DOM в React

> [!NOTE]
> Содержимое страницы обычно описывают через JSX и state. Для необходимых императивных операций с DOM-узлом используют **ref**.

## Вопрос

Когда нужен прямой доступ к DOM и почему не стоит вручную менять элементы, которыми управляет React?

## Основная идея

React DOM создает и обновляет узлы по результату рендера. Если параллельно менять их содержимое вручную, появятся два независимых источника управления. React может перезаписать такую правку при следующем обновлении.

Но некоторые действия естественно императивны: установить фокус, прокрутить элемент в видимую область, измерить его размеры, подключить библиотеку графиков. Для них React предоставляет refs.

`useRef` возвращает объект с полем `current`. После размещения DOM-элемента React присваивает туда узел, а после удаления - `null`. Изменение ref само по себе не запускает рендер.

## Пример: фокус на поиске

```jsx
import { useRef, useState } from "react";

export default function SearchPanel() {
  const inputRef = useRef(null);
  const [query, setQuery] = useState("");

  function focusSearch() {
    inputRef.current?.focus();
  }

  return (
    <section>
      <label>
        Поиск по конспекту
        <input
          ref={inputRef}
          value={query}
          onChange={event => setQuery(event.currentTarget.value)}
        />
      </label>
      <button onClick={focusSearch}>Перейти к поиску</button>
      <p>Запрос: {query || "не введен"}</p>
    </section>
  );
}
```

Значением поля управляет state, а фокусом - вызов DOM-метода. Эти обязанности не конфликтуют: `focus()` не переписывает описание интерфейса.

## Когда использовать эффект

Если внешнюю библиотеку нужно подключить после появления узла, это обычно делают в эффекте с cleanup, который отключает библиотеку при удалении. Для измерения, влияющего на расположение до показа кадра, иногда нужен `useLayoutEffect`.

DOM недоступен на сервере. Во время рендера нельзя рассчитывать на заполненный ref или выполнять браузерные побочные действия.

## Частые ошибки

Не удаляй вручную React-узлы и не заменяй их `innerHTML`. Вместо `querySelector` для собственного элемента обычно надежнее ref: он явно связан с конкретным экземпляром компонента.

## Что важно помнить

- Ручные изменения DOM-узлов, которыми управляет React, могут быть перезаписаны при следующем рендере.
- Ref — для императивных операций: фокус, прокрутка, измерения, интеграция со сторонними библиотеками.
- Работайте с ref в обработчиках и эффектах, а не во время рендера.
- Не удаляйте и не перемещайте вручную узлы, созданные React, — это приводит к ошибкам reconciliation.

## Мини-шпаргалка

- Данные и содержимое - JSX и state.
- Фокус, прокрутка, измерения - ref и DOM API.
- `ref.current` может быть `null`.
- Подключение внешнего ресурса требует отключения.
