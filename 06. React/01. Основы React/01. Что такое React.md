# Что такое React

> [!NOTE]
> **React** - JavaScript-библиотека для создания пользовательских интерфейсов из компонентов. Компонент описывает, что показать при текущих данных, а React согласует это описание с интерфейсом.

## Вопрос

Что такое React, какие задачи он решает и на каких основных идеях построен?

## Основная идея

Представь интернет-магазин: в нем есть шапка, поиск, карточки товаров и корзина. Вместо одной большой функции, которая вручную меняет страницу, можно создать отдельный компонент для каждой части. Компоненты вкладываются друг в друга и образуют дерево приложения.

React использует **декларативный подход**: разработчик описывает результат для текущего состояния. Например, если корзина пуста, показать сообщение; если в ней есть товары, показать список и итоговую сумму. Не нужно отдельно писать команды «найди сообщение», «удали его», «создай список».

Три базовых понятия: **компоненты** делят интерфейс на части, **props** передают входные данные, **state** хранит данные, которые меняются во время работы. **JSX** помогает записывать описание интерфейса рядом с JavaScript-логикой.

## Пример: счетчик товаров

Пример для клиентского React-приложения:

```jsx
import { useState } from "react";

function CartButton({ productName }) {
  const [quantity, setQuantity] = useState(0);

  return (
    <button onClick={() => setQuantity(q => q + 1)}>
      {productName}: в корзине {quantity}
    </button>
  );
}

export default function App() {
  return (
    <>
      <h1>Книжный магазин</h1>
      <CartButton productName="Учебник TypeScript" />
      <CartButton productName="Сборник задач" />
    </>
  );
}
```

Каждая кнопка хранит собственное количество. Нажатие обновляет state соответствующего компонента. React снова вычисляет его результат и применяет нужное изменение к DOM.

## Что важно понимать

React сам по себе не задает маршрутизацию, сервер API или схему хранения данных. Для этих задач используют другие библиотеки либо фреймворк.

Virtual DOM - удобный термин для описаний интерфейса в памяти, а не полная копия браузерного DOM. Его наличие само по себе не гарантирует скорость. Производительность зависит и от кода приложения.

React DOM работает с веб-страницей; React Native использует идеи React для интерфейсов мобильных приложений, но его элементы отличаются от HTML.

## Что важно помнить

- React — библиотека для UI, а не фреймворк: роутинг, загрузку данных и сборку добавляют отдельно или берут из Next.js, React Router и т.п.
- UI = f(state): описываем результат, а React сам обновляет DOM.
- React DOM — рендерер для браузера; тот же React работает с React Native и другими рендерерами.
- Современный React — функциональные компоненты и хуки; классы нужны в основном для легаси и Error Boundary.

## Мини-шпаргалка

- React собирает интерфейс из компонентов.
- Props приходят извне, state принадлежит конкретному месту в дереве.
- JSX описывает интерфейс, но не является обязательным HTML-шаблоном.
- Обновление state запускает вычисление следующего интерфейса.
