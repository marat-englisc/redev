# Virtual DOM: что это и зачем он нужен

> [!NOTE]
> **Virtual DOM** — легковесное описание интерфейса в памяти: дерево обычных JavaScript-объектов (React-элементов), которые возвращают компоненты. При изменении состояния React строит новое дерево, сравнивает его с предыдущим (reconciliation) и применяет к настоящему DOM только найденные отличия. Это позволяет писать декларативный код, не думая о ручных обновлениях DOM.

## Вопрос

Что такое Virtual DOM и что он делает? Зачем используют Virtual DOM и правда ли, что он всегда быстрее прямой работы с DOM?

## Основная идея

JSX `<h1 className="title">Привет</h1>` компилируется в вызов, который создает объект вида `{ type: "h1", props: { className: "title", children: "Привет" } }`. Это и есть узел «виртуального DOM». Создать такой объект дешево, а изменить настоящий DOM — дорого: браузер пересчитывает стили, layout и перерисовывает страницу.

Когда состояние меняется, React вызывает компоненты заново и получает новое дерево элементов. Затем он сравнивает его со старым и формирует список минимальных операций: изменить текст, поменять атрибут, вставить или удалить узел. Эти операции применяются к DOM за одну фазу commit.

Важно понимать, **зачем** это нужно. Virtual DOM — не магический ускоритель: точечное ручное изменение DOM почти всегда быстрее, чем «построить дерево + сравнить + применить». Ценность в другом: разработчик описывает весь интерфейс декларативно, а React автоматически находит, что поменялось, и делает это достаточно быстро для большинства приложений. Кроме того, описание в памяти позволяет рендерить не только в браузерный DOM: React Native, рендер на сервере, canvas.

## Пример

```jsx
function Counter({ count }) {
  return (
    <div className="counter">
      <h2>Счетчик</h2>
      <p>Значение: {count}</p>
    </div>
  );
}
```

При смене `count` с 1 на 2 React получит новое дерево, где отличается только текст внутри `<p>`. В DOM изменится один текстовый узел — `div` и `h2` останутся нетронутыми.

## Что важно помнить

- Virtual DOM в React — это дерево React-элементов и связанные с ним Fiber-узлы, а не копия всего DOM браузера.
- Перерендер компонента не означает изменение DOM: если результат совпал, DOM не трогается.
- Лишние ререндеры всё равно стоят времени на вызов компонентов и сравнение — поэтому существуют `memo`, `useMemo` и React Compiler.
- Есть фреймворки без Virtual DOM (Svelte, SolidJS): они на этапе компиляции генерируют точечные обновления.

## Мини-шпаргалка

Virtual DOM = дерево JS-объектов. Новое дерево → сравнение → минимальные изменения DOM. Польза — декларативность, а не «быстрее DOM». Ререндер ≠ изменение DOM.
