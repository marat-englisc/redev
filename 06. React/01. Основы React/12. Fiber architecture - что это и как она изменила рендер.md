# Fiber architecture: что это и как она изменила рендер

> [!NOTE]
> **Fiber** — внутренняя архитектура React (с версии 16), в которой каждый компонент и элемент представлен узлом-«файбером» с информацией о типе, props, state, эффектах и связях с соседями. Работа над деревом разбивается на маленькие единицы, которые React может приостанавливать, возобновлять, отбрасывать и выполнять с разным приоритетом. На Fiber построены concurrent rendering, transitions, Suspense и streaming SSR.

## Вопрос

Что такое Fiber architecture? Почему Fiber делает рендер «асинхронным» и какую роль играет Fiber в жизненном цикле и в React 18?

## Основная идея

До React 16 работал **stack reconciler**: обход дерева шел рекурсивно и синхронно. Если обновление затрагивало тысячи компонентов, основной поток был занят до конца, и интерфейс «подвисал» — нельзя было ввести текст, пока не закончится рендер.

Fiber заменил рекурсию на обход связанного дерева узлов. Каждый fiber хранит ссылки на ребенка, соседа и родителя, поэтому React может остановиться на любом узле и продолжить позже. Работа делится на две фазы:

- **render (reconciliation)** — вычисление нового дерева; может быть прервана, повторена или отброшена;
- **commit** — применение изменений к DOM и запуск эффектов; выполняется синхронно и целиком.

React поддерживает два дерева: текущее (то, что на экране) и рабочее (work-in-progress). Новое дерево строится «в фоне» и подменяет текущее только при commit.

**«Асинхронность»** здесь означает не потоки и промисы, а **прерываемость**: React может уступить основной поток браузеру (обработать клик, нарисовать кадр) и вернуться к рендеру. Обновлениям назначаются приоритеты (lanes): ввод текста срочный, перерисовка большого списка по фильтру — нет.

В React 18 эти возможности стали доступны приложениям через concurrent features: `startTransition`, `useDeferredValue`, Suspense для данных и streaming SSR.

## Пример

```jsx
import { useState, useTransition } from "react";

function Search({ items }) {
  const [query, setQuery] = useState("");
  const [filter, setFilter] = useState("");
  const [isPending, startTransition] = useTransition();

  return (
    <>
      <input
        value={query}
        onChange={(e) => {
          setQuery(e.target.value);                      // срочное обновление
          startTransition(() => setFilter(e.target.value)); // несрочное, можно прервать
        }}
      />
      {isPending && <p>Обновляем...</p>}
      <HeavyList items={items} filter={filter} />
    </>
  );
}
```

Благодаря Fiber рендер `HeavyList` можно прервать новым вводом — поле не «залипает».

## Что важно помнить

- Компоненты могут рендериться несколько раз до commit — поэтому функция компонента должна быть чистой, без побочных эффектов.
- Эффекты и изменения DOM происходят только в commit.
- Fiber — внутренняя деталь: напрямую с файберами не работают, но знание модели объясняет Strict Mode, transitions и Suspense.
- React DevTools Profiler показывает рендеры и коммиты, построенные на Fiber.

## Мини-шпаргалка

Fiber = единица работы на каждый компонент. Render прерываемый, commit синхронный. Два дерева: current и work-in-progress. Приоритеты обновлений. Основа concurrent features React 18.
