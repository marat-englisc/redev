# Что появилось в React 18

> [!NOTE]
> React 18 добавил современный API корня, расширенный batching, transitions и streaming SSR с Suspense, опираясь на конкурентную подготовку интерфейса.

## Вопрос

Какие изменения React 18 важно понимать на собеседовании?

## Основная идея

Главная идея React 18 — возможность готовить часть обновлений так, чтобы более срочное действие пользователя могло её прервать. Это база для transitions и отложенных значений. Речь о планировании работы React, а не о параллельном выполнении JavaScript в нескольких потоках.

Новый `createRoot` заменил прежний клиентский вход и включил поведение современного корня. Automatic batching распространился на обновления из Promise, таймеров и нативных обработчиков: несколько связанных установок состояния чаще приводят к одному commit. `useTransition` и `useDeferredValue` позволяют отделять срочную работу от менее важного обновления UI.

На сервере появились streaming API и улучшенная интеграция Suspense с гидрацией. Для библиотек добавили `useSyncExternalStore` и `useInsertionEffect`; `useId` помогает создавать согласованные идентификаторы. Важно не приписывать React 18 всё современное React API: Actions, `useActionState`, `useOptimistic` и `use` относятся к React 19.

## Пример

Клиентский JSX-компонент для React 18 или новее. Корень приложения создан через `createRoot`.

```jsx
import { useState } from 'react';

export default function ReadingCounter() {
  const [count, setCount] = useState(0);
  const [message, setMessage] = useState('Начните читать');
  function finishBook() {
    Promise.resolve().then(() => {
      setCount(value => value + 1);
      setMessage('Ещё одна книга прочитана!');
    });
  }
  return <>
    <button onClick={finishBook}>Завершить книгу</button>
    <p>Прочитано: {count}</p>
    <p>{message}</p>
  </>;
}
```

Две установки состояния находятся в одном Promise callback. Современный корень группирует их, поэтому число и сообщение обновляются вместе. В Strict Mode вызовы render в разработке могут создавать дополнительные диагностические наблюдения.

## Что важно помнить

- Старый `ReactDOM.render` в React 18 сохранял прежнее поведение корня; в React 19 он удалён.
- Suspense не превратил произвольный fetch в эффекте в автоматическую загрузку.
- Strict Mode дополнительно проверяет чистоту рендера и корректность cleanup в разработке.
- React Compiler — отдельный инструмент, а не автоматически включённая функция React 18.

## Мини-шпаргалка

18: roots, batching, transitions, streaming, библиотечные хуки. 19: Actions, use, optimistic/form API.
