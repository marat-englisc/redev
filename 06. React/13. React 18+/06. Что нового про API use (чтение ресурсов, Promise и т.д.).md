# API use в React 19

> [!NOTE]
> use читает Promise или Context во время рендера. Для Promise он интегрируется с Suspense и Error Boundary; источник Promise должен быть стабильным.

## Вопрос

Как работает use и чем его правила отличаются от правил обычных хуков?

## Основная идея

`use(promise)` возвращает разрешённое значение. Пока Promise ожидается, компонент приостанавливается и ближайший Suspense показывает fallback. При отклонении ошибка доходит до Error Boundary. Это чтение существующего ресурса, а не универсальная команда автоматически создать, кешировать и повторять запрос.

Для клиентского компонента особенно важна стабильная ссылка. `use(fetch(url).then(...))` создаёт новый Promise при каждой попытке рендера и может постоянно возвращать приложение к ожиданию. Promise передают из Server Component, loader, поддерживаемого кеша или события. Сохранять такой Promise в state допустимо, если его создание не происходит безусловно в render.

`use(Context)` читает контекст, подобно `useContext`. В отличие от обычных хуков, `use` разрешён в условиях и циклах, но только во время выполнения компонента или собственного хука. Вызов `use(promise)` не оборачивают в `try/catch`: для обработки ошибки используют границу либо заранее преобразуют Promise.

## Пример

Самодостаточный клиентский пример React 19 с фиксированными учебными данными и react-error-boundary.

```jsx
import { createContext, Suspense, use } from 'react';
import { ErrorBoundary } from 'react-error-boundary';

const Theme = createContext('light');
const bookPromise = Promise.resolve({ title: 'React без паники' });

function Book({ visible }) {
  if (!visible) return null;
  const theme = use(Theme);
  const book = use(bookPromise);
  return <article className={theme}><h2>{book.title}</h2></article>;
}
export default function App() {
  return <Theme.Provider value="light">
    <ErrorBoundary fallback={<p role="alert">Книга недоступна</p>}>
      <Suspense fallback={<p role="status">Загрузка...</p>}>
        <Book visible />
      </Suspense>
    </ErrorBoundary>
  </Theme.Provider>;
}
```

Учебный Promise создан один раз на уровне клиентского модуля. Условный ранний return допустим для `use`, но такое правило нельзя переносить на `useState` или `useEffect`.

## Что важно помнить

- Пример требует React 19 и установленного react-error-boundary.
- Общий модульный Promise с персональными данными нельзя бездумно использовать на сервере между запросами.
- На сервере в async-компоненте обычно предпочтительнее await.
- Actions сами не инвалидируют произвольный Promise-кеш: обновление ресурса проектируют отдельно.

## Мини-шпаргалка

Promise → use → result/Suspense/Error Boundary. Context → use → ближайшее значение. Создание ресурса ≠ чтение ресурса.
