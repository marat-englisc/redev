# React Server Components (RSC) и Server Components в React 19

> [!NOTE]
> **React Server Components** — компоненты, которые выполняются **только на сервере** (или во время сборки) и не попадают в клиентский бандл. Они могут быть `async`, напрямую читать базу данных и файлы, использовать секреты. Результат передается клиенту в виде сериализованного дерева (RSC payload), а интерактивные части помечаются `"use client"` и гидрируются как обычные компоненты. В React 19 Server Components и Server Actions (`"use server"`) стали стабильной частью React, реализованной во фреймворках (Next.js App Router и др.).

## Вопрос

Что такое React Server Components? Чем они отличаются от SSR и от клиентских компонентов и что они дают в React 19?

## Основная идея

```jsx
// app/products/[id]/page.jsx — Server Component (по умолчанию)
import { db } from "@/lib/db";
import { AddToCart } from "./AddToCart";

export default async function ProductPage({ params }) {
  const { id } = await params;
  const product = await db.product.findUnique({ where: { id } }); // прямо на сервере

  return (
    <article>
      <h1>{product.title}</h1>
      <p>{product.description}</p>
      <AddToCart productId={product.id} />   {/* клиентский остров */}
    </article>
  );
}
```

```jsx
// AddToCart.jsx — Client Component
"use client";
import { useState } from "react";

export function AddToCart({ productId }) {
  const [added, setAdded] = useState(false);
  return <button onClick={() => setAdded(true)}>{added ? "В корзине" : "Купить"}</button>;
}
```

## Server и Client Components

| | Server Component | Client Component (`"use client"`) |
| --- | --- | --- |
| Где выполняется | сервер / сборка | сервер (SSR) + браузер |
| Попадает в бандл | нет | да |
| `async`/`await` в компоненте | да | нет (используют `use`) |
| Доступ к БД, файлам, секретам | да | нет |
| `useState`, `useEffect`, обработчики | нет | да |
| Браузерные API | нет | да |
| Контекст | нет | да |

Правила композиции:

- Server Component может импортировать Client Component;
- Client Component **не может импортировать** Server Component, но может получить его через `children` или props;
- props от сервера к клиенту должны быть сериализуемы (без функций, кроме Server Actions).

## RSC и SSR — не одно и то же

| | SSR | RSC |
| --- | --- | --- |
| Результат | HTML | RSC payload (описание дерева) |
| Код компонентов на клиенте | весь, для гидрации | только клиентских |
| Повторный запрос при навигации | новая страница или JSON | payload нового дерева, клиентский state сохраняется |
| Совместно | RSC payload рендерится в HTML через SSR при первом запросе | |

## Server Actions (React 19)

```jsx
// actions.js
"use server";
export async function addComment(formData) {
  await db.comment.create({ data: { text: formData.get("text") } });
  revalidatePath("/posts");
}

// в компоненте
<form action={addComment}>
  <input name="text" />
  <button>Отправить</button>
</form>
```

## Преимущества и ограничения

| Плюсы | Минусы |
| --- | --- |
| меньше JS на клиенте | нужен фреймворк и сервер (или сборка) |
| данные загружаются рядом с местом использования, без API-слоя | новая ментальная модель, граница `"use client"` |
| секреты и тяжелые зависимости остаются на сервере | ограничения сериализации props |
| streaming через Suspense | отладка и кеширование сложнее |

## Что важно помнить

- `"use client"` помечает **границу**: всё, что импортирует этот модуль, тоже становится клиентским.
- Не помечайте «клиентскими» большие деревья — выносите в клиент только интерактивные листья.
- `"use server"` — не «серверный компонент», а метка Server Functions (Actions).
- Чтобы серверный код не утек в клиент, используют пакет `server-only`.

## Мини-шпаргалка

RSC — компоненты только на сервере: `async`, доступ к БД, ноль JS в бандле. Интерактив — `"use client"`. Server → Client через импорт, Client → Server только через `children`/props. RSC ≠ SSR: payload дерева, а не HTML. React 19: стабильные RSC и Server Actions.
