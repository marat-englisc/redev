# createRoot и старый render

> [!NOTE]
> createRoot создаёт современный клиентский корень React и возвращает объект с render/unmount. Старый ReactDOM.render устарел в React 18 и удалён в React 19.

## Вопрос

Как перейти на createRoot и почему он не подходит для гидрации готового HTML?

## Основная идея

Корень — точка, в которой React начинает управлять частью DOM. Старый API одновременно принимал компонент и контейнер: `ReactDOM.render(<App />, container)`. Современный API разделяет создание корня и передачу дерева: `createRoot(container).render(<App />)`.

Корень обычно создают один раз при запуске, а не после каждого события. Для дальнейших изменений используют state, props или вызов `root.render` с новым деревом, если это действительно нужно внешней интеграции. `root.unmount()` освобождает React-дерево и эффекты, например при удалении виджета со страницы.

Если контейнер уже содержит HTML этого React-приложения с сервера, выбирают `hydrateRoot`. `createRoot` предназначен для клиентского создания интерфейса и не сохраняет SSR-разметку как гидратируемое дерево. Перепутанные API лишают приложение корректного продолжения серверного рендера.

## Пример

Клиентский вход React 18+; документ содержит `<div id="root"></div>`, сборщик преобразует JSX.

```jsx
import { useState } from 'react';
import { createRoot } from 'react-dom/client';

function App() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(value => value + 1)}>
    Кликнули {count} раз
  </button>;
}

const container = document.getElementById('root');
if (!container) throw new Error('Не найден контейнер #root');
const root = createRoot(container);
root.render(<App />);
// Когда внешний владелец виджета завершает его работу: root.unmount().
```

HTML должен содержать контейнер `root`. После `render` React создаёт кнопку и управляет её обновлениями. Проверка контейнера даёт понятную ошибку, если вход подключён к неправильной странице.

## Что важно помнить

- Нельзя передавать JSX вместо DOM-контейнера в `createRoot`.
- Настройки корня передают в `createRoot(container, options)`, а не вторым аргументом `root.render`.
- Фреймворк обычно сам создаёт корень; не добавляйте второй поверх него.
- `root.render` не обещает, что эффекты уже завершились к следующей строке кода.

## Мини-шпаргалка

Пустой клиентский контейнер → createRoot. Серверный HTML → hydrateRoot. Завершение интеграции → root.unmount.
