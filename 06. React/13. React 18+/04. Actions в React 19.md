# Actions в React 19

> [!NOTE]
> Actions — функции, выполняемые в контексте Transition или через Action API, чтобы согласовать асинхронное действие, pending-состояние и обновление UI.

## Вопрос

Как Actions связаны с формами, useActionState и серверными функциями?

## Основная идея

Сохранение профиля требует проверить ввод, дождаться сервера, показать загрузку и сообщить результат. React 19 предоставляет связанный набор API: async Actions, функцию в `form action`, `useActionState` для результата и pending, `useFormStatus` для потомков формы и `useOptimistic` для временного UI.

В функции `action` формы React передаёт FormData. Если действие используется через `useActionState`, первым аргументом становится предыдущее состояние, вторым — FormData. Возвращённое значение становится новым состоянием хука. Ожидаемые ошибки валидации удобно возвращать как данные, а не аварийно закрывать всю форму.

Action не обязательно является серверной функцией. Обычная клиентская Action может вызывать существующий HTTP API. Server Function с директивой `use server` требует фреймворка и серверной инфраструктуры; она не появляется автоматически у любой async-функции с именем action.

## Пример

Клиентский компонент React 19; серверный API `/api/profile` принимает PATCH с JSON.

```jsx
import { useActionState } from 'react';

async function saveName(previous, formData) {
  const name = String(formData.get('name') ?? '').trim();
  if (!name) return { error: 'Введите имя', saved: '' };
  try {
    const response = await fetch('/api/profile', {
      method: 'PATCH',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ name }),
    });
    if (!response.ok) throw new Error('Сохранение не удалось');
    return { error: '', saved: name };
  } catch {
    return { error: 'Не удалось сохранить. Повторите попытку.', saved: '' };
  }
}
export default function ProfileForm() {
  const [state, formAction, pending] = useActionState(saveName, { error: '', saved: '' });
  return <form action={formAction}>
    <label>Имя <input name="name" required /></label>
    <button disabled={pending}>{pending ? 'Сохраняем...' : 'Сохранить'}</button>
    {state.error && <p role="alert">{state.error}</p>}
    {state.saved && <p role="status">Сохранено: {state.saved}</p>}
  </form>;
}
```

Форма передаёт данные в `saveName`, pending блокирует повторную отправку, а возвращённое состояние показывает результат. API в примере отвечает на PATCH; сохранение подтверждается успешным HTTP-статусом.

## Что важно помнить

- Пример требует React 19. `useActionState` импортируется из react.
- При успешной Action React сбрасывает неконтролируемые поля формы; ожидаемую ошибку, возвращённую как данные, учитывайте при проектировании UX.
- Сервер обязан повторно проверить входные данные и доступ пользователя.
- Для собственных setter после await учитывайте требование дополнительного startTransition.

## Мини-шпаргалка

form action → FormData. useActionState → previousState + FormData → новый state и pending. Server Function → отдельная серверная интеграция.
