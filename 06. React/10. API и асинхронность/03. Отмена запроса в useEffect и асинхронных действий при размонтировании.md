# Отмена запроса в useEffect и асинхронных действий при размонтировании

> [!NOTE]
> Асинхронные операции, запущенные в эффекте, нужно отменять в функции очистки — при размонтировании компонента и при смене зависимостей. Для `fetch` используют `AbortController`: передают `signal` в запрос и вызывают `controller.abort()` в cleanup. Для операций, которые нельзя отменить, ставят флаг `ignore` и не обновляют state после очистки. Так предотвращаются гонки (ответ старого запроса перезаписывает новый), лишняя сетевая нагрузка и утечки.

## Вопрос

Как отменить запрос внутри `useEffect()`? Как отменять асинхронные действия при размонтировании компонента?

## AbortController

```jsx
function UserProfile({ userId }) {
  const [user, setUser] = useState(null);
  const [error, setError] = useState(null);

  useEffect(() => {
    const controller = new AbortController();

    fetch(`/api/users/${userId}`, { signal: controller.signal })
      .then((res) => {
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        return res.json();
      })
      .then(setUser)
      .catch((e) => {
        if (e.name === "AbortError") return; // отмена — не ошибка
        setError(e);
      });

    return () => controller.abort();         // размонтирование или смена userId
  }, [userId]);
}
```

После `abort()` промис `fetch` отклоняется с `AbortError`, браузер прерывает сетевой запрос.

## Флаг ignore

```jsx
useEffect(() => {
  let ignore = false;

  someLibrary.load(id).then((data) => {
    if (!ignore) setData(data);
  });

  return () => {
    ignore = true;
  };
}, [id]);
```

Флаг не отменяет сам запрос, но не дает обновить state устаревшими данными. Подходит для API без поддержки `AbortSignal`.

## Что еще отменять

| Операция | Отмена в cleanup |
| --- | --- |
| `fetch`, `axios` | `controller.abort()` (axios поддерживает `signal`) |
| `setTimeout`, `setInterval` | `clearTimeout`, `clearInterval` |
| WebSocket, EventSource | `socket.close()` |
| подписка на store | `unsubscribe()` |
| debounce-функция | `debounced.cancel()` |
| `requestAnimationFrame` | `cancelAnimationFrame(id)` |

## Несколько запросов с одним сигналом

```jsx
useEffect(() => {
  const controller = new AbortController();
  const { signal } = controller;

  Promise.all([
    fetch("/api/user", { signal }),
    fetch("/api/orders", { signal }),
  ]).then(/* ... */);

  return () => controller.abort();
}, []);
```

Также пригодятся `AbortSignal.timeout(5000)` и `AbortSignal.any([s1, s2])`.

## Что важно помнить

- В React 18 убрано предупреждение «Can't perform a React state update on an unmounted component» — но отменять запросы всё равно нужно ради гонок и трафика.
- В Strict Mode первый запрос будет отменен сразу — это проверка корректной очистки.
- TanStack Query передает `signal` в `queryFn` и сам отменяет запросы, если они больше не нужны.
- Отмена на клиенте не отменяет работу на сервере — для мутаций учитывайте идемпотентность.

## Мини-шпаргалка

Cleanup эффекта отменяет асинхронную работу. `fetch` — `AbortController` + `signal` + `abort()`, игнорировать `AbortError`. Неотменяемое — флаг `ignore`. Таймеры, сокеты, подписки — тоже в cleanup.
