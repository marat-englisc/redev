# Optimistic update и хук useOptimistic

> [!NOTE]
> **Оптимистичное обновление** — изменение UI **до ответа сервера**, как будто запрос уже прошел успешно. Если сервер вернул ошибку, изменение откатывают и показывают сообщение. Так интерфейс ощущается мгновенным: лайк, добавление в корзину, отправка сообщения. В React 19 для этого есть хук `useOptimistic`, в TanStack Query — `onMutate` с откатом в `onError`.

## Вопрос

Что такое optimistic update? Как его реализовать вручную, через TanStack Query и через `useOptimistic` в React 19?

## Основная идея

```text
Обычно:         клик → запрос → ждем 500 мс → UI обновлен
Оптимистично:   клик → UI обновлен сразу → запрос → (ошибка? → откат)
```

## useOptimistic (React 19)

```jsx
import { useOptimistic } from "react";

function Thread({ messages, sendMessage }) {
  const [optimisticMessages, addOptimistic] = useOptimistic(
    messages,
    (state, newText) => [...state, { id: crypto.randomUUID(), text: newText, sending: true }],
  );

  async function formAction(formData) {
    const text = formData.get("text");
    addOptimistic(text);          // сразу показываем сообщение
    await sendMessage(text);      // настоящий запрос; после него messages обновятся
  }

  return (
    <>
      {optimisticMessages.map((m) => (
        <p key={m.id} style={{ opacity: m.sending ? 0.5 : 1 }}>{m.text}</p>
      ))}
      <form action={formAction}>
        <input name="text" />
        <button>Отправить</button>
      </form>
    </>
  );
}
```

- `useOptimistic(state, updateFn)` возвращает оптимистичное состояние и функцию добавления;
- оптимистичное значение живет, пока выполняется Action или transition;
- после завершения React показывает реальный `state` — при ошибке изменение исчезнет само.

## TanStack Query

```jsx
const queryClient = useQueryClient();

useMutation({
  mutationFn: toggleLike,
  onMutate: async (postId) => {
    await queryClient.cancelQueries({ queryKey: ["post", postId] });
    const previous = queryClient.getQueryData(["post", postId]);
    queryClient.setQueryData(["post", postId], (p) => ({ ...p, liked: !p.liked, likes: p.likes + (p.liked ? -1 : 1) }));
    return { previous };                         // контекст для отката
  },
  onError: (_err, postId, context) => {
    queryClient.setQueryData(["post", postId], context.previous); // откат
  },
  onSettled: (_data, _err, postId) => {
    queryClient.invalidateQueries({ queryKey: ["post", postId] }); // синхронизация с сервером
  },
});
```

## Когда применять

| Подходит | Не подходит |
| --- | --- |
| лайки, избранное, отметки «прочитано» | платежи, заказы |
| добавление комментария, сообщения | операции с высокой вероятностью отказа |
| перетаскивание, сортировка | действия с необратимыми последствиями |
| переключатели настроек | когда сервер вычисляет результат (цена со скидкой) |

## Что важно помнить

- Всегда предусматривайте откат и понятное сообщение об ошибке.
- Временные id заменяйте на настоящие из ответа сервера.
- Отменяйте текущие запросы перед оптимистичным обновлением, чтобы фоновый refetch не перезаписал его.
- Повторные клики: мутации лучше делать идемпотентными.

## Мини-шпаргалка

Optimistic update: UI меняется до ответа, при ошибке — откат. React 19: `useOptimistic(state, update)` внутри Action. TanStack Query: `onMutate` (снимок + обновление кеша) → `onError` (откат) → `onSettled` (инвалидация). Не для платежей.
