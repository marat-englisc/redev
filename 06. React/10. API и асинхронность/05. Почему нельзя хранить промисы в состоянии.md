# Promise в состоянии React

> [!NOTE]
> Хранить Promise в state технически можно. Однако обычный state не подписывается на его завершение; для UI нужны результат и статус либо React 19 use со стабильным Promise.

## Вопрос

Действительно ли запрещено хранить Promise в состоянии и когда это имеет смысл?

## Основная идея

Promise представляет будущий результат, а не сами данные. Если положить его в `useState`, разрешение Promise не вызывает `setState`: ссылка остаётся прежней. Компонент автоматически не узнает, что теперь можно показать имя пользователя. Попытка вывести Promise как обычный дочерний элемент тоже не является способом загрузки данных.

Обычно проще хранить данные, загрузку и ошибку. Но абсолютный запрет неверен: в React 19 API `use(promise)` умеет читать результат, взаимодействовать с Suspense и передавать отклонение Error Boundary. Promise можно сохранить при событии и передать читающему компоненту.

Критически важна стабильность: `use(fetch(...))` создаёт новую операцию при каждой попытке рендера. Даже локальный `useMemo` не является надёжным кешем при начальном suspension. Источник Promise должен жить вне повторяемого рендера: loader, серверный компонент, кеш библиотеки или событие.

## Пример

Самодостаточный пример для React 19; библиотека `react-error-boundary` установлена в проекте.

```jsx
import { Suspense, use, useState } from 'react';
import { ErrorBoundary } from 'react-error-boundary';

function Result({ promise }) {
  const message = use(promise);
  return <p>{message}</p>;
}

export default function Fortune() {
  const [promise, setPromise] = useState(null);
  function reveal() {
    setPromise(new Promise(resolve => {
      setTimeout(() => resolve('Сегодня вы разберётесь с Promise!'), 700);
    }));
  }
  return <>
    <button onClick={reveal}>Открыть предсказание</button>
    <ErrorBoundary fallback={<p>Не удалось открыть</p>}>
      <Suspense fallback={<p role="status">Открываем...</p>}>
        {promise && <Result promise={promise} />}
      </Suspense>
    </ErrorBoundary>
  </>;
}
```

Promise создаётся по клику, а повторные рендеры читают ту же ссылку. `use` уведомляет React о готовности ресурса; state сам такой подписки не предоставляет.

## Что важно помнить

- Пример требует React 19 и установленного `react-error-boundary`.
- `useState(fetch(url))` вызывает `fetch` при каждом вычислении аргумента.
- Promise нельзя переслать обычным JSON; передача Promise через RSC использует специальный протокол React.

## Мини-шпаргалка

State может хранить Promise. Автоматическое чтение результата → `use` + Suspense. Стабильная ссылка обязательна.
