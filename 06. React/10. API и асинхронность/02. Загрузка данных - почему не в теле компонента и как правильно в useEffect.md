# Загрузка данных: почему не в теле компонента и как правильно в useEffect

> [!NOTE]
> Запрос нельзя делать прямо в теле компонента: тело выполняется при каждом рендере, а `setState` после ответа вызовет новый рендер и новый запрос — бесконечный цикл. Запрос при первом рендере делают в `useEffect` с зависимостями. Сама функция эффекта не может быть `async` (она должна вернуть cleanup, а не Promise), поэтому асинхронную функцию объявляют внутри и вызывают. Обязательно обрабатывают загрузку, ошибки и гонки запросов. В продакшене вместо ручного кода обычно используют TanStack Query, SWR или загрузчики фреймворка.

## Вопрос

Почему нельзя делать запросы в теле компонента? Как выполнить запрос при первом рендере и правильно использовать асинхронный код в `useEffect`?

## Почему не в теле компонента

```jsx
function Users() {
  const [users, setUsers] = useState([]);
  fetch("/api/users").then((r) => r.json()).then(setUsers); // ❌
  // рендер → запрос → setUsers → рендер → запрос → ...
  return <UserList users={users} />;
}
```

Тело компонента должно быть чистым: рендер может вызываться многократно (Strict Mode, конкурентный режим), и побочные эффекты в нем непредсказуемы.

## Правильно: useEffect

```jsx
function Users() {
  const [users, setUsers] = useState([]);
  const [status, setStatus] = useState("loading");
  const [error, setError] = useState(null);

  useEffect(() => {
    let ignore = false;

    async function load() {
      try {
        const res = await fetch("/api/users");
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        const data = await res.json();
        if (!ignore) {
          setUsers(data);
          setStatus("success");
        }
      } catch (e) {
        if (!ignore) {
          setError(e);
          setStatus("error");
        }
      }
    }

    load();
    return () => {
      ignore = true;      // ответ устаревшего запроса будет проигнорирован
    };
  }, []);                 // [] — при первом рендере (монтировании)

  if (status === "loading") return <Spinner />;
  if (status === "error") return <ErrorMessage error={error} />;
  return <UserList users={users} />;
}
```

## Почему эффект не может быть async

```jsx
useEffect(async () => {          // ❌ возвращает Promise вместо cleanup
  const data = await fetchData();
}, []);
```

React ожидает от эффекта функцию очистки или `undefined`. Promise он не сможет вызвать при размонтировании, и в консоли будет предупреждение.

## Гонки (race conditions)

```jsx
useEffect(() => {
  let ignore = false;
  fetchUser(userId).then((u) => {
    if (!ignore) setUser(u);
  });
  return () => { ignore = true; };
}, [userId]);
```

Если `userId` быстро меняется 1 → 2, ответ на запрос 1 может прийти позже ответа 2. Флаг `ignore` (или `AbortController`) не даст старому ответу перезаписать новый.

## Минусы ручной загрузки в эффектах

- нет кеша — повторные монтирования повторяют запрос;
- водопады: ребенок начнет грузиться только после рендера родителя;
- нет SSR: эффекты не выполняются на сервере;
- много шаблонного кода для loading, error, retry, refetch.

```jsx
// то же с TanStack Query
const { data: users, isPending, error } = useQuery({
  queryKey: ["users"],
  queryFn: () => fetch("/api/users").then((r) => r.json()),
});
```

## Что важно помнить

- В Strict Mode эффект запустится дважды — запрос тоже; это нормально, если есть очистка.
- Не забывайте `res.ok`: `fetch` не бросает ошибку на 404 и 500.
- Запрос в ответ на действие пользователя (отправка формы) делают в обработчике, а не в эффекте.
- В Server Components данные загружаются прямо в `async`-компоненте — без эффектов.

## Мини-шпаргалка

Запросы — не в теле компонента (бесконечный цикл), а в `useEffect` с deps. Эффект не `async`: async-функция внутри. Loading + error + отмена гонок (`ignore` или `AbortController`). В реальных проектах — TanStack Query, SWR, загрузчики фреймворка.
