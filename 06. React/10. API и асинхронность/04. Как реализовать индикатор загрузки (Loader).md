# Индикатор загрузки

> [!NOTE]
> Loader сообщает, что операция выполняется. Он должен отличаться от пустого результата и ошибки, а также быть доступным для вспомогательных технологий.

## Вопрос

Как организовать состояния загрузки, успеха, пустого ответа и ошибки?

## Основная идея

«Пока массива нет, показывай спиннер» кажется достаточным правилом, пока API не вернёт пустой массив или ошибку. Пустая библиотека означает успешный запрос без книг, а недоступный сервер означает неуспех. Пользователь должен понимать разницу и знать, что делать дальше.

Удобно описать интерфейс конечным набором состояний: loading, success, error. Данные существуют в успешном состоянии, ошибка — в ошибочном. В TypeScript такую модель можно оформить discriminated union: компилятор поможет не обратиться к данным до их появления.

При первом запросе допустима заглушка всего блока. При фоновом обновлении чаще полезнее сохранить уже показанные данные и добавить небольшой индикатор. Иначе каждая ревалидация заставляет интерфейс мигать и терять контекст. Для скелетона заранее резервируют место, чтобы уменьшить сдвиги страницы.

## Пример

Пример для клиентского React-приложения с поддержкой JSX. API в примере возвращает JSON; его адрес замените на адрес своего сервера.

```jsx
import { useEffect, useState } from 'react';

export default function Profile({ id = 1 }) {
  const [result, setResult] = useState({ status: 'loading' });

  useEffect(() => {
    const controller = new AbortController();
    let active = true;
    setResult({ status: 'loading' });

    async function load() {
      try {
        const response = await fetch(`/api/users/${id}`, {
          signal: controller.signal,
        });
        if (!response.ok) throw new Error(`HTTP ${response.status}`);
        const user = await response.json();
        if (active) setResult({ status: 'success', user });
      } catch (error) {
        if (active) setResult({ status: 'error', error });
      }
    }

    load();
    return () => {
      active = false;
      controller.abort();
    };
  }, [id]);

  if (result.status === 'loading') return <p role="status">Загрузка...</p>;
  if (result.status === 'error') return <p role="alert">Не удалось загрузить профиль</p>;
  return <h2>{result.user.name}</h2>;
}
```

`role="status"` объявляет загрузку, а `role="alert"` сообщает об ошибке. Единственное поле `status` не позволяет случайно одновременно показать успех и первоначальный loader.

## Что важно помнить

- Не выводите объект ответа напрямую в JSX: выбирайте поля или отображайте список элементов.
- `finally` старого запроса не должен сбрасывать `loading` нового. Проверяйте актуальность операции.
- В TanStack Query `isPending` означает отсутствие успешных данных, `isFetching` — выполняющийся запрос; это разные ситуации.

## Мини-шпаргалка

Loading → ожидание. Error → объяснение/повтор. Success + [] → пустое состояние. Refetch → сохранить данные.
