# Работа с асинхронными операциями

> [!NOTE]
> Асинхронная операция возвращает результат позже. React показывает текущий интерфейс, а после получения результата обновляет состояние и выполняет новый рендер.

## Вопрос

Как выполнять запросы к API и связывать их результат с интерфейсом React?

## Основная идея

Представьте страницу профиля: серверу требуется полсекунды, чтобы найти пользователя. Браузер не должен всё это время зависать. Компонент сначала показывает загрузку, запускает запрос, а после ответа отображает имя. При ошибке он показывает понятное сообщение вместо бесконечного индикатора.

Для ручной загрузки при появлении компонента подходит `useEffect`. Эффект синхронизирует экран с внешней системой и выполняется после commit. Для действия пользователя, например сохранения формы, запрос обычно запускают в обработчике события. Эффект не является единственным допустимым местом для асинхронного кода.

Нужно продумать четыре вещи: состояние загрузки, успешные данные, ошибку и устаревший результат. Если пользователь переключился с профиля Анны на профиль Бориса, медленный ответ об Анне уже не должен заменять данные Бориса. Для этого нужны cleanup и отмена или игнорирование старой операции.

## Пример

Пример для клиентского React-приложения с поддержкой JSX. API в примере возвращает JSON; его адрес замените на адрес своего сервера.

```jsx
import { useEffect, useState } from 'react';

export default function Profile({ id = 1 }) {
  const [result, setResult] = useState({ status: 'loading' });

  useEffect(() => {
    const controller = new AbortController();
    let active = true;
    setResult({ status: 'loading' });

    async function load() {
      try {
        const response = await fetch(`/api/users/${id}`, {
          signal: controller.signal,
        });
        if (!response.ok) throw new Error(`HTTP ${response.status}`);
        const user = await response.json();
        if (active) setResult({ status: 'success', user });
      } catch (error) {
        if (active) setResult({ status: 'error', error });
      }
    }

    load();
    return () => {
      active = false;
      controller.abort();
    };
  }, [id]);

  if (result.status === 'loading') return <p role="status">Загрузка...</p>;
  if (result.status === 'error') return <p role="alert">Не удалось загрузить профиль</p>;
  return <h2>{result.user.name}</h2>;
}
```

При изменении `id` React очищает предыдущий эффект и запускает новый. `active` защищает состояние от устаревшего результата, а `AbortController` просит браузер прекратить запрос.

## Что важно помнить

- `fetch` не отклоняет Promise из-за HTTP 404 или 500: проверяйте `response.ok`.
- Клиентский компонент не объявляют `async`; асинхронные Server Components относятся к другому окружению.
- Для общего кеша, повторов и фонового обновления удобно использовать TanStack Query или SWR.

## Мини-шпаргалка

Запуск → loading → success/error. Смена параметров → cleanup → новый запрос.
