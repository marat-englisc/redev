# SWR

> [!NOTE]
> SWR — библиотека кеширования и загрузки данных для React. Название отражает подход stale-while-revalidate: показать кеш и обновить его в фоне.

## Вопрос

Как SWR использует кеш и какие состояния возвращает useSWR?

## Основная идея

Когда пользователь возвращается к профилю, полезно сразу показать последнее известное имя и проверить обновления в фоне. Если ответ изменился, интерфейс обновится. Если сети нет, старые данные могут остаться полезными, но это не гарантирует полноценную работу приложения офлайн.

`useSWR` получает ключ и fetcher. Ключ описывает данные: URL, массив с параметрами или другое поддерживаемое значение. Fetcher выполняет реальную загрузку и должен выбрасывать ошибку при неуспешном HTTP-ответе. Сам SWR не угадывает, что статус 500 означает проблему вашей функции.

Библиотека предоставляет данные, ошибку и признаки загрузки. `isLoading` описывает начальную загрузку без полученных данных, `isValidating` — любой выполняющийся запрос, включая фоновый. Для записи на сервер используют мутации, после которых обновляют кеш или инициируют ревалидацию.

## Пример

Клиентское React-приложение с установленным пакетом `swr`; `/api/users/me` возвращает `{ name: string }`.

```jsx
import useSWR from 'swr';

async function fetcher(url) {
  const response = await fetch(url);
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return response.json();
}

export default function Profile() {
  const { data, error, isLoading, isValidating, mutate } = useSWR(
    '/api/users/me', fetcher
  );
  if (isLoading) return <p role="status">Загрузка профиля...</p>;
  if (error && !data) return <p role="alert">Профиль недоступен</p>;
  return <>
    <h2>{data.name}</h2>
    {isValidating && <small>Проверяем обновления...</small>}
    {error && <p role="alert">Показаны последние известные данные</p>}
    <button onClick={() => mutate()}>Обновить</button>
  </>;
}
```

Первый запрос показывает loader. Следующий `mutate()` проверяет тот же ресурс и сохраняет профиль на экране. Ошибка фонового запроса не уничтожает полезные кешированные данные.

## Что важно помнить

- Пример требует установленного SWR 2.
- Дедупликация действует по ключу и настройкам библиотеки; это не обещание единственного запроса навсегда.
- Ревалидация при фокусе и восстановлении сети настраивается.
- Изменение кеша не записывает данные на сервер: мутацию нужно выполнить отдельно.

## Мини-шпаргалка

Ключ + fetcher → данные/ошибка. isLoading → первый результат. isValidating → сеть. mutate → обновление.
