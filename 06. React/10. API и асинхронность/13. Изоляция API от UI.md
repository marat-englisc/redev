# Изоляция API от UI

> [!NOTE]
> API-слой описывает обращение к серверу, а компонент — отображение данных и действия пользователя. Разделение уменьшает дублирование и упрощает изменения.

## Вопрос

Зачем выносить fetch в отдельные функции и что должен возвращать API-слой?

## Основная идея

Если три экрана показывают профиль, копировать URL, заголовки, проверку статуса и преобразование ответа в каждый компонент неудобно. При изменении API легко исправить два места и забыть третье. Функция `getProfile` собирает правила загрузки в одном месте.

Компоненту обычно нужны предметные данные, например `{ name }`, а не низкоуровневый `Response`. API-функция должна вернуть данные или выбросить понятную ошибку, а также принять параметры вроде `id` и `signal`. Тогда её одинаково удобно вызывать из эффекта, loader или `queryFn`.

Это разделение не требует сложной архитектуры. Для маленького приложения достаточно файла `api/users.js`. Кеширование и состояние UI при этом остаются отдельными слоями. Замена REST на другой транспорт может потребовать изменений контрактов, но компоненты меньше зависят от технических деталей.

## Пример

Пример состоит из двух файлов в клиентском React-проекте; `/api/users/:id` возвращает объект пользователя.

### api/users.js

```jsx
export async function getUser(id, signal) {
  const response = await fetch(`/api/users/${encodeURIComponent(id)}`, { signal });
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return response.json();
}
```

### UserCard.jsx

```jsx
import { useEffect, useState } from 'react';
import { getUser } from './api/users.js';

export default function UserCard({ id = 1 }) {
  const [name, setName] = useState('Загрузка...');
  useEffect(() => {
    const controller = new AbortController();
    let active = true;
    setName('Загрузка...');
    getUser(id, controller.signal).then(
      user => { if (active) setName(user.name); },
      () => { if (active) setName('Профиль недоступен'); },
    );
    return () => { active = false; controller.abort(); };
  }, [id]);
  return <p>{name}</p>;
}
```

API-файл ничего не знает о JSX. Компонент ничего не знает о конкретной проверке HTTP-статуса. Для теста функцию загрузки можно подменить тестовым ответом.

## Что важно помнить

- TypeScript-тип не проверяет JSON во время выполнения: недоверенный ответ при необходимости валидируют схемой.
- Не помещайте секретные серверные ключи в клиентский API-слой: его код доступен браузеру.
- Сохраняйте отмену и исходную причину ошибки при оборачивании запросов.

## Мини-шпаргалка

API → транспорт, статус, данные. Query/loader → жизненный цикл загрузки. Компонент → представление.
