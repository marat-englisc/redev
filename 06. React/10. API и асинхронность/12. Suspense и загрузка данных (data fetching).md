# Suspense и загрузка данных (data fetching)

> [!NOTE]
> Suspense может ждать не только код, но и **данные** — если источник данных умеет приостанавливать рендер. Компонент читает данные как будто они уже есть, а состояние загрузки описывается декларативно границей `<Suspense>`. Поддерживаемые источники: `use(promise)` в React 19, Server Components с `async`/`await`, `useSuspenseQuery` в TanStack Query, SWR с `suspense: true`, загрузчики фреймворков. Обычный `useEffect` + `fetch` Suspense не активирует.

## Вопрос

Как Suspense работает с загрузкой данных? Чем этот подход отличается от загрузки в `useEffect`?

## Подход «fetch-on-render» и Suspense

```jsx
// классический подход: каждый компонент сам управляет loading
function Profile({ id }) {
  const [user, setUser] = useState(null);
  useEffect(() => {
    fetchUser(id).then(setUser);
  }, [id]);
  if (!user) return <Spinner />;
  return <h1>{user.name}</h1>;
}

// Suspense: компонент описывает только успешный случай
function Profile({ id }) {
  const { data: user } = useSuspenseQuery({
    queryKey: ["user", id],
    queryFn: () => fetchUser(id),
  });
  return <h1>{user.name}</h1>;
}

<ErrorBoundary fallback={<ErrorMessage />}>
  <Suspense fallback={<ProfileSkeleton />}>
    <Profile id={42} />
  </Suspense>
</ErrorBoundary>
```

## React 19: use(promise)

```jsx
import { use, Suspense } from "react";

function Comments({ commentsPromise }) {
  const comments = use(commentsPromise);   // приостанавливает до выполнения Promise
  return comments.map((c) => <p key={c.id}>{c.text}</p>);
}

// Promise создается выше (в Server Component, загрузчике или кеше), а не в рендере
function Post({ id }) {
  const commentsPromise = getCommentsCached(id);
  return (
    <Suspense fallback={<p>Загрузка комментариев...</p>}>
      <Comments commentsPromise={commentsPromise} />
    </Suspense>
  );
}
```

Promise нельзя создавать прямо в рендере клиентского компонента: при каждом рендере будет новый Promise и бесконечная приостановка. Его нужно кешировать или получать извне.

## Сравнение подходов

| | `useEffect` + state | Suspense |
| --- | --- | --- |
| Состояние загрузки | `if (loading)` в каждом компоненте | граница `<Suspense>` |
| Ошибки | `if (error)` | Error Boundary |
| Водопады запросов | часто: ребенок ждет рендера родителя | можно запускать заранее (render-as-you-fetch) |
| Гонки при смене параметров | вручную | решаются кешем/библиотекой |
| Согласованность UI | сложно координировать | несколько компонентов ждут одной границы |
| SSR streaming | нет | да |

## Избегаем водопадов

```jsx
// плохо: Comments начнет загрузку только после загрузки Post
<Suspense><Post id={id}><Suspense><Comments id={id} /></Suspense></Post></Suspense>

// хорошо: запросы стартуют параллельно
const postPromise = fetchPost(id);
const commentsPromise = fetchComments(id);
```

## Что важно помнить

- Suspense для данных требует поддержки от библиотеки или фреймворка; самописный «бросить Promise» не рекомендуется.
- Вместе с Suspense всегда нужен Error Boundary.
- Для перехода между данными без fallback используйте `startTransition` или `useDeferredValue`.
- В Next.js App Router: `async` Server Components + `loading.tsx` + `<Suspense>` для streaming.

## Мини-шпаргалка

Suspense для данных: компонент читает данные, граница показывает fallback. Источники: `use(promise)`, RSC, `useSuspenseQuery`, SWR suspense. Promise — кешировать, не создавать в рендере. Ошибки — Error Boundary. Запросы — параллельно.
