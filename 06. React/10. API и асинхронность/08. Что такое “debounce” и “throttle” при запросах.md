# Debounce и throttle при запросах

> [!NOTE]
> Debounce ждёт паузу после серии событий, а throttle ограничивает частоту вызовов во время непрерывного потока.

## Вопрос

Чем debounce отличается от throttle и какой подход нужен для поиска?

## Основная идея

Когда пользователь печатает «реакт», запрос на каждую букву часто не нужен. Debounce сбрасывает таймер после каждого изменения и запускает работу, только когда наступила заданная пауза. Если интервал 300 мс, а пользователь печатает быстрее, сервер получит один запрос на готовую строку.

Throttle нужен для непрерывного процесса: например, сохранять позицию прокрутки не чаще раза в секунду. При постоянных событиях работа всё равно выполняется периодически. Детали первого и последнего вызова зависят от реализации: существуют leading и trailing варианты.

Ограничение частоты не заменяет управление гонками. Запрос для старой строки уже мог начаться до следующего ввода. Его нужно отменить либо проигнорировать результат. Для бесконечной прокрутки часто удобнее IntersectionObserver, чем ручной обработчик каждого scroll.

## Пример

Пример для клиентского React-приложения с поддержкой JSX. API в примере возвращает JSON; его адрес замените на адрес своего сервера.

```jsx
import { useEffect, useState } from 'react';

export default function Search() {
  const [text, setText] = useState('');
  const [message, setMessage] = useState('Введите название');
  useEffect(() => {
    const controller = new AbortController();
    let active = true;
    const timer = setTimeout(async () => {
      if (!text.trim()) { setMessage('Введите название'); return; }
      try {
        const response = await fetch(`/api/books?q=${encodeURIComponent(text)}`, {
          signal: controller.signal,
        });
        if (!response.ok) throw new Error('Поиск недоступен');
        const books = await response.json();
        if (active) setMessage(`Найдено: ${books.length}`);
      } catch {
        if (active) setMessage('Не удалось выполнить поиск');
      }
    }, 300);
    return () => { active = false; clearTimeout(timer); controller.abort(); };
  }, [text]);
  return <>
    <input aria-label="Поиск" value={text} onChange={e => setText(e.target.value)} />
    <p role="status">{message}</p>
  </>;
}
```

Каждый новый символ очищает предыдущий таймер. Сеть запускается после паузы; если текст изменится во время запроса, cleanup делает его результат неактуальным.

## Что важно помнить

- Не создавайте новый debounced-wrapper на каждом рендере без очистки: его таймеры будут жить независимо.
- Debounce добавляет намеренную задержку; выбирайте её по сценарию, а не по универсальному числу.
- `useDeferredValue` управляет рендером и не гарантирует уменьшение количества запросов.

## Мини-шпаргалка

Поиск → debounce. Непрерывные события → throttle. Устаревшие ответы → abort/ignore.
