# React.Suspense: что делает и что изменилось в React 18

> [!NOTE]
> `<Suspense fallback={...}>` показывает запасной UI, пока какой-либо компонент внутри **приостановлен** — ждет загрузки кода (`React.lazy`) или данных (`use(promise)`, suspense-режим TanStack Query, RSC). Когда всё готово, fallback заменяется содержимым. В React 18 Suspense стал работать на сервере (streaming SSR, selective hydration), согласован с transitions и при `createRoot` ведет себя последовательно: соседние компоненты не монтируются, пока граница не будет готова.

## Вопрос

Что делает `React.Suspense`? Как Suspense работает при загрузке компонентов и что изменилось в React 18?

## Основная идея

```jsx
import { Suspense, lazy } from "react";

const Comments = lazy(() => import("./Comments"));

function Post() {
  return (
    <article>
      <PostBody />
      <Suspense fallback={<CommentsSkeleton />}>
        <Comments />
      </Suspense>
    </article>
  );
}
```

Механизм: приостановленный компонент «бросает» Promise. React находит ближайшую границу `<Suspense>`, показывает ее fallback и повторяет рендер, когда Promise выполнится.

## Вложенные границы

```jsx
<Suspense fallback={<PageSpinner />}>
  <Header />
  <Suspense fallback={<SidebarSkeleton />}>
    <Sidebar />
  </Suspense>
  <Suspense fallback={<FeedSkeleton />}>
    <Feed />
  </Suspense>
</Suspense>
```

Каждая часть появляется по мере готовности. Если границ мало — долго ждем всё; если слишком много — интерфейс «прыгает». Границы ставят по смысловым блокам.

## Что изменилось в React 18

| Аспект | До React 18 | React 18+ |
| --- | --- | --- |
| SSR | Suspense не поддерживался | streaming HTML + selective hydration |
| Источники приостановки | только `React.lazy` | lazy, фреймворки, библиотеки данных, позже `use` и RSC |
| Transitions | — | при `startTransition` уже видимый контент не заменяется fallback |
| Соседи приостановленного компонента | монтировались (эффекты срабатывали) | не коммитятся, пока граница не готова |
| Повторное появление fallback | — | throttle, чтобы избежать мигания |

## Suspense и transitions

```jsx
function Tabs() {
  const [tab, setTab] = useState("posts");
  const [isPending, startTransition] = useTransition();

  return (
    <>
      <TabButtons onSelect={(t) => startTransition(() => setTab(t))} pending={isPending} />
      <Suspense fallback={<Spinner />}>
        {tab === "posts" ? <Posts /> : <Photos />}
      </Suspense>
    </>
  );
}
```

Без transition при переключении вкладки контент исчез бы за спиннером. С transition остается старая вкладка, пока новая не загрузится.

## Что важно помнить

- Suspense не ловит ошибки — вместе с ним ставят Error Boundary.
- `useEffect` + `fetch` не активирует Suspense: нужен suspense-совместимый источник данных.
- Сброс границы: смена `key` у `<Suspense>` снова покажет fallback.
- В Next.js `loading.tsx` — это автоматическая граница Suspense для сегмента маршрута.

## Мини-шпаргалка

`<Suspense fallback>` показывает запасной UI, пока дети ждут код или данные. Ближайшая граница ловит «брошенный» Promise. React 18: SSR streaming, selective hydration, интеграция с transitions. Ошибки — Error Boundary.
