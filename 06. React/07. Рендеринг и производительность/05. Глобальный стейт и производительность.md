# Глобальное состояние и производительность

> [!NOTE]
> Производительность глобального состояния зависит от расположения данных и точности подписок. Изменение одного значения не обязано обновлять все приложение.

## Вопрос

Почему хранение каждого символа input в общем контексте может быть дорогим?

## Область состояния и область подписки

Состояние полезно держать рядом с теми, кому оно нужно. Черновик локального поиска обычно принадлежит поисковому компоненту, а сведения о текущем пользователе действительно нужны нескольким независимым частям приложения.

У стандартного Context потребитель подписывается на все `value`. Если провайдер передает `{ theme, query }`, изменение `query` создает новое значение и обновляет потребителей этого контекста, даже если конкретный потребитель читает только `theme`. `memo` не блокирует обновление используемого контекста.

Однако нельзя переносить это правило на любое внешнее хранилище. Redux, Zustand и другие инструменты могут поддерживать селекторы: компонент подписывается на определенный результат, например число товаров. Тогда поведение зависит от выбранных данных и правил сравнения. Нормальная архитектура — локальные данные локально, общие данные с понятными подписками.

## Пример

```jsx
import { createContext, useContext, useState } from 'react';

const ThemeContext = createContext('light');

function Header() {
  const theme = useContext(ThemeContext);
  return <header>Тема: {theme}</header>;
}

function Search() {
  const [query, setQuery] = useState('');
  return (
    <input
      aria-label="Поиск"
      value={query}
      onChange={(event) => setQuery(event.target.value)}
    />
  );
}

export default function App() {
  const [theme, setTheme] = useState('light');
  return (
    <ThemeContext.Provider value={theme}>
      <Header />
      <button
        onClick={() => setTheme((t) => (t === 'light' ? 'dark' : 'light'))}
      >
        Сменить тему
      </button>
      <Search />
    </ThemeContext.Provider>
  );
}
```

Каждый ввод обновляет только `Search` и его поддерево. Он не меняет `ThemeContext` и не запускает render родителя. Смена темы, напротив, должна обновить `Header`.

## Что важно помнить

- Разделяйте независимые контексты по причинам изменения, а не создавайте один гигантский объект.
- Мемоизация `value` предотвращает случайно новые ссылки, но не устраняет обновления при настоящем изменении данных.
- Подписывайтесь на минимально нужные значения внешнего store.
- Локальность упрощает не только скорость, но и поиск владельца данных.

## Мини-шпаргалка

```text
Чем ближе state к потребителю, тем меньше область обновления
Context → весь value
Store с селекторами → выбранные данные по правилам библиотеки
```
