# Оптимизация длинных списков и виртуализация (windowing)

> [!NOTE]
> Длинный список (тысячи строк) тормозит из-за количества DOM-узлов: долгий первый рендер, тяжелая reconciliation, много памяти и медленный скролл. Основной прием — **виртуализация (windowing)**: рендерить только строки, видимые в окне прокрутки, плюс небольшой запас, а остальное заменять пустым пространством нужной высоты. Дополнительно помогают стабильные `key`, `memo` для строк, пагинация или бесконечная подгрузка и CSS `content-visibility`.

## Вопрос

Как оптимизировать рендер длинных списков? Что такое windowing (virtualization) и как он работает?

## Как работает виртуализация

```text
Всего 10 000 строк × 40px = 400 000px высоты

┌───────── контейнер (height: 600px, overflow: auto) ─────────┐
│  [пустое место: scrollTop]                                   │
│  строка 250                                                  │
│  ... видимые ~15 строк + overscan ...                        │
│  строка 270                                                  │
│  [пустое место до конца]                                     │
└──────────────────────────────────────────────────────────────┘
```

При прокрутке вычисляются индексы видимых строк: `start = floor(scrollTop / rowHeight)`, `end = start + ceil(height / rowHeight)`. В DOM всегда ~20–30 узлов вместо 10 000.

## Пример с TanStack Virtual

```jsx
import { useVirtualizer } from "@tanstack/react-virtual";
import { useRef } from "react";

function UserList({ users }) {
  const parentRef = useRef(null);
  const virtualizer = useVirtualizer({
    count: users.length,
    getScrollElement: () => parentRef.current,
    estimateSize: () => 48,
    overscan: 5,
  });

  return (
    <div ref={parentRef} style={{ height: 600, overflow: "auto" }}>
      <div style={{ height: virtualizer.getTotalSize(), position: "relative" }}>
        {virtualizer.getVirtualItems().map((row) => (
          <div
            key={users[row.index].id}
            style={{ position: "absolute", top: 0, transform: `translateY(${row.start}px)`, height: row.size, width: "100%" }}
          >
            {users[row.index].name}
          </div>
        ))}
      </div>
    </div>
  );
}
```

Библиотеки: TanStack Virtual, react-window, react-virtuoso (динамическая высота, группы из коробки).

## Другие приемы

| Прием | Что дает |
| --- | --- |
| стабильный `key` (id, не индекс) | React переиспользует узлы, а не пересоздает |
| `memo` для строки + `useCallback` для обработчиков | обновление одной строки не рендерит весь список |
| пагинация / «Показать еще» / infinite scroll | меньше данных за раз |
| `content-visibility: auto` | браузер пропускает layout и paint скрытых блоков |
| `useDeferredValue` для фильтра | ввод не блокируется перерисовкой списка |
| нормализация данных | обновление одного элемента не меняет весь массив |

## Минусы виртуализации

- поиск браузера (Ctrl+F) не находит невидимые строки;
- сложнее с динамической высотой и якорями;
- нужно заботиться о доступности: `aria-rowcount`, `aria-rowindex`, фокус при прокрутке;
- SEO: невидимые элементы не попадают в HTML.

## Что важно помнить

- Виртуализация оправдана примерно от сотен-тысяч элементов; для 50 строк она избыточна.
- Профилируйте в React DevTools Profiler: часто проблема в лишних ререндерах строк, а не в количестве.
- Для таблиц используют TanStack Table + TanStack Virtual.

## Мини-шпаргалка

Длинный список → много DOM. Виртуализация: рендерить только видимое + overscan, остальное — пустая высота. TanStack Virtual, react-window, react-virtuoso. Плюс: стабильные `key`, `memo` строк, пагинация, `content-visibility`.
