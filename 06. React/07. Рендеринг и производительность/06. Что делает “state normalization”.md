# Нормализация состояния: сущности по идентификаторам

> [!NOTE]
> Нормализация хранит каждую сущность в одном месте, обычно в словаре по ID, а отношения между сущностями выражает идентификаторами.

## Вопрос

Как избежать нескольких расходящихся копий одного автора или товара в состоянии?

## Данные похожи на небольшую базу

Пусть у двух статей один автор. Если каждая статья содержит свою копию `{ id, name }`, изменение имени требует найти и обновить все копии. Пропущенная запись покажет старое имя. Чем больше связей, тем сложнее поддерживать вложенную структуру.

Нормализованное состояние разделяет статьи и авторов. Статья хранит `authorId`, а имя находится в `usersById[authorId]`. Теперь существует одна запись автора. Порядок статей можно хранить отдельным массивом ID, независимо от самих объектов.

Такое представление упрощает неизменяемые обновления и сохраняет ссылки неизменившихся сущностей. Это полезно для селекторов и мемоизации. Но нормализация сама по себе не делает рендеры точечными: необходимо также правильно организовать подписки и props. Для маленькой независимой коллекции плоский массив часто понятнее.

## Пример

```jsx
import { useState } from 'react';

const initial = {
  postIds: ['p1', 'p2'],
  postsById: {
    p1: { id: 'p1', title: 'React', authorId: 'u1' },
    p2: { id: 'p2', title: 'TypeScript', authorId: 'u1' },
  },
  usersById: { u1: { id: 'u1', name: 'Анна' } },
};

export default function Blog() {
  const [data, setData] = useState(initial);
  function rename() {
    setData((previous) => ({
      ...previous,
      usersById: {
        ...previous.usersById,
        u1: { ...previous.usersById.u1, name: 'Анна Петрова' },
      },
    }));
  }
  return (
    <>
      <button onClick={rename}>Полное имя автора</button>
      {data.postIds.map((id) => {
        const post = data.postsById[id];
        const author = data.usersById[post.authorId];
        return (
          <p key={id}>
            {post.title} — {author.name}
          </p>
        );
      })}
    </>
  );
}
```

Меняется одна запись `u1`, а обе статьи показывают новое имя. Объекты статей сохраняют свои ссылки: их содержимое не изменялось.

## Нюансы

- Не мутируйте `usersById.u1.name` прямо в существующем состоянии.
- После удаления сущности нужно обработать оставшиеся ссылки на ее ID.
- Отсутствующая запись возможна при частичной загрузке: интерфейс должен учитывать ее.
- Нормализация и глобальное хранение — независимые решения; локальный state тоже может быть нормализован.

## Что важно помнить

- Нормализация — хранение сущностей по id без дублирования.
- Обновление сущности меняет одно место, а не все копии во вложенных структурах.
- Селекторы собирают нужную форму данных из нормализованного state.
- Для серверных данных библиотеки кеширования часто избавляют от ручной нормализации.

## Мини-шпаргалка

```text
entitiesById → данные
ids → порядок
authorId/productId → связи
Одна сущность → одна актуальная запись
```
