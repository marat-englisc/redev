# Рендеринг в React: от состояния до экрана

> [!NOTE]
> Рендеринг — это вызов компонентов, во время которого React вычисляет описание интерфейса. Изменение DOM происходит на отдельном этапе — commit.

## Вопрос

Что React называет рендерингом? Всегда ли повторный вызов компонента изменяет страницу?

## Как появляется интерфейс

Представьте электронное табло кафе. Данные сообщают, сколько заказов готово, компонент описывает нужную надпись, а React приводит страницу к этому описанию. Разработчику не нужно самостоятельно искать текстовый узел и менять его.

Обновление проходит три этапа. Сначала возникает **триггер**: первоначальный запуск приложения либо обновление состояния компонента или его предка. Затем React вызывает компоненты и вычисляет JSX. Наконец, на этапе **commit** React применяет необходимые изменения к DOM. После этого браузер выполняет собственную работу по отображению страницы.

При обходе дерева React обычно вызывает и дочерние компоненты. Они получают props от родителя. Потребители контекста также обновляются при изменении значения контекста. При этом вызов функции компонента и реальное изменение DOM — разные события: одинаковый результат вычислений может не требовать изменений узлов.

## Пример

```jsx
import { useState } from 'react';

export default function Orders() {
  const [ready, setReady] = useState(0);
  const [checks, setChecks] = useState(0);

  return (
    <section>
      <h2>Готово заказов: {ready}</h2>
      <button onClick={() => setReady((n) => n + 1)}>Заказ готов</button>
      <button onClick={() => setChecks((n) => n + 1)}>
        Проверок: {checks}
      </button>
    </section>
  );
}
```

При нажатии любой кнопки `Orders` вычисляется заново. При изменении `checks` надпись с количеством заказов остается прежней: React не обязан пересоздавать `section` и `h2`. Меняется текст второй кнопки.

## Что важно помнить

- Во время рендера нельзя отправлять заказы на сервер или изменять чужие объекты: вычисление может быть повторено.
- React render и browser paint — разные процессы.
- Новое состояние задает следующий снимок интерфейса; setter не переписывает текущую переменную на месте.
- Быстрые повторные рендеры — нормальная работа React, а не обязательно проблема производительности.

## Мини-шпаргалка

```text
Триггер → render: вычислить UI → commit: обновить DOM → paint
Вызов компонента ≠ обязательное изменение DOM
```
