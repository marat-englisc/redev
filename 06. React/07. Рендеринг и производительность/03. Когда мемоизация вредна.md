# Когда мемоизация не помогает и может навредить

> [!NOTE]
> Мемоизация приносит пользу, если сохраненная работа дороже проверки зависимостей и содержания кэша. Она не исправляет ошибки в модели данных.

## Вопрос

Почему нельзя автоматически ускорить приложение, добавив `memo`, `useMemo` и `useCallback` везде?

## Цена кэширования

React должен хранить результат, сравнивать зависимости и поддерживать дополнительную логику. Для простого сложения или маленького текстового компонента эта работа часто не оправдана. Точный эффект зависит от приложения: утверждать, что любой такой хук обязательно делает код заметно медленнее, тоже некорректно.

Другой случай — зависимости постоянно меняются. Если в зависимостях `useMemo` находится новый объект, кэш не используется. Сам массив зависимостей можно создавать заново: React сравнивает его **элементы**, а не ссылку на массив. Важна стабильность конкретных значений внутри.

Более серьезный риск — неправильная логика ради «стабильности». Пропущенные зависимости создают устаревшие замыкания. Неполный пользовательский comparator у `memo` может сохранить старый обработчик. Программа выглядит оптимизированной, но пользователь получает неправильное поведение.

## Пример

```jsx
import { useMemo, useState } from 'react';

const books = ['Дюна', 'Солярис', 'Основание'];

export default function Search() {
  const [query, setQuery] = useState('');
  const [checks, setChecks] = useState(0);

  // Объект создается внутри вычисления и не ломает зависимости.
  const visible = useMemo(() => {
    const options = { query: query.toLowerCase() };
    return books.filter((title) => title.toLowerCase().includes(options.query));
  }, [query]);

  return (
    <>
      <input
        aria-label="Название книги"
        value={query}
        onChange={(event) => setQuery(event.target.value)}
      />
      <button onClick={() => setChecks((n) => n + 1)}>
        Проверок: {checks}
      </button>
      <p>{visible.join(', ')}</p>
    </>
  );
}
```

Если вынести `options` в тело компонента и указать `[options]`, каждое нажатие «Проверок» создаст новую зависимость и запустит фильтрацию. В примере кэш работает, но для трех строк проще обойтись обычным `.filter()`.

## Как принимать решение

- Измерьте медленное действие в Profiler и браузерных Performance tools.
- Уменьшите область состояния и исправьте ненужные эффекты.
- Мемоизируйте обнаруженную дорогую работу и сравните результат.
- Не игнорируйте lint-правило зависимостей.

`memo` не замораживает контекст: мемоизированный потребитель получает новое context-значение как обычно. Обратное утверждение — фактическая ошибка.

## Что важно помнить

- Мемоизация имеет цену: память и сравнение зависимостей при каждом рендере.
- Если зависимости меняются каждый рендер, кеш никогда не срабатывает.
- Сначала измерьте в Profiler, затем мемоизируйте узкие места.
- React Compiler снимает большую часть ручной мемоизации.

## Мини-шпаргалка

```text
Дешево считать / зависимости всегда новые → выгода мала
Неполные зависимости → ошибки, а не оптимизация
```
