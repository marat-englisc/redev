# React.memo и связь с shouldComponentUpdate

> [!NOTE]
> `React.memo(Component, arePropsEqual?)` — компонент высшего порядка, который **пропускает повторный рендер**, если props не изменились. По умолчанию props сравниваются поверхностно (`Object.is` по каждому ключу). Это функциональный аналог `PureComponent` и `shouldComponentUpdate`. `memo` не защищает от ререндера из-за собственного state и контекста и бесполезен, если родитель каждый раз передает новые объекты или функции.

## Вопрос

Что делает `React.memo()`? Чем он похож на `shouldComponentUpdate()` и когда он работает?

## Основная идея

```jsx
import { memo, useState } from "react";

const Avatar = memo(function Avatar({ user }) {
  console.log("render Avatar");
  return <img src={user.photo} alt={user.name} />;
});

function Profile({ user }) {
  const [likes, setLikes] = useState(0);
  return (
    <>
      <Avatar user={user} />                      {/* не рендерится при смене likes */}
      <button onClick={() => setLikes(likes + 1)}>❤ {likes}</button>
    </>
  );
}
```

## Своя функция сравнения

```jsx
const Chart = memo(ChartImpl, (prev, next) => {
  return prev.data.length === next.data.length && prev.color === next.color;
  // true → props «равны» → рендер пропускается
});
```

## memo и shouldComponentUpdate

| | `shouldComponentUpdate` | `PureComponent` | `React.memo` |
| --- | --- | --- | --- |
| Для | классов | классов | функций |
| Что сравнивает | что угодно, вручную | props и state поверхностно | только props |
| Возврат `true` означает | рендерить | — | **не** рендерить |
| State компонента | учитывает | учитывает | не учитывает: свой state всегда вызывает ререндер |

## Когда memo не работает

```jsx
function Parent() {
  return (
    <Avatar
      user={{ name: "Анна" }}          // новый объект каждый рендер
      onClick={() => {}}               // новая функция каждый рендер
      style={{ width: 40 }}            // новый объект
    />
  );
}
```

Решения: `useMemo` для объектов, `useCallback` для функций, вынос констант за пределы компонента, передача примитивов.

Также `memo` не помогает, когда:

- компонент сам читает изменившийся контекст;
- меняется его собственный state;
- `children` — JSX, который каждый раз создается заново.

## Когда применять

- компонент тяжелый и часто рендерится с теми же props;
- компонент — элемент длинного списка;
- родитель часто обновляется по не связанным с ребенком причинам.

## Что важно помнить

- Сравнение props тоже стоит времени: для дешевых компонентов `memo` не дает выигрыша.
- Сначала попробуйте перенести state вниз или передать JSX через `children`.
- React Compiler автоматически мемоизирует компоненты.
- `memo` — оптимизация, а не гарантия: логика не должна зависеть от того, пропущен ли рендер.

## Мини-шпаргалка

`memo(Component)` пропускает рендер при равных props (поверхностно). Аналог `PureComponent`/`shouldComponentUpdate`. Ломается от новых объектов и функций в props — нужны `useMemo`/`useCallback`. Не спасает от state и контекста.
