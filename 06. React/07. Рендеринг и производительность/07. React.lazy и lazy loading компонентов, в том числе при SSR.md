# React.lazy и lazy loading компонентов, в том числе при SSR

> [!NOTE]
> **Lazy loading компонентов** — загрузка кода компонента только тогда, когда он нужен. `React.lazy(() => import("./Page"))` создает компонент, который при первом рендере запускает динамический `import()`. Бандлер выносит модуль в отдельный чанк, а пока он грузится, ближайший `<Suspense>` показывает fallback. Так уменьшается начальный бандл и ускоряется первая загрузка. При SSR `React.lazy` поддерживается streaming-рендером React 18; во фреймворках обычно используют их обертки (`next/dynamic`).

## Вопрос

Что делает `React.lazy()`? Как работает lazy loading компонентов и как он сочетается с SSR?

## Основная идея

```jsx
import { lazy, Suspense } from "react";

const Settings = lazy(() => import("./pages/Settings"));
const Chart = lazy(() => import("./components/Chart"));

function App() {
  return (
    <Suspense fallback={<PageSkeleton />}>
      <Routes>
        <Route path="/settings" element={<Settings />} />
      </Routes>
    </Suspense>
  );
}
```

Модуль должен экспортировать компонент по умолчанию (`export default`). Для именованного экспорта:

```jsx
const Chart = lazy(() => import("./charts").then((m) => ({ default: m.Chart })));
```

## Что делить на чанки

| Хорошие кандидаты | Плохие кандидаты |
| --- | --- |
| страницы и маршруты | маленькие и часто используемые компоненты |
| модалки, вкладки, которые открывают не все | компоненты первого экрана |
| тяжелые библиотеки: графики, редакторы, карты | кнопки, иконки |
| админка, редкие разделы | |

## Предзагрузка

```jsx
const loadSettings = () => import("./pages/Settings");
const Settings = lazy(loadSettings);

<Link to="/settings" onMouseEnter={loadSettings}>Настройки</Link>
```

Импорт кешируется: при наведении чанк начнет загружаться, а к клику будет готов.

## Обработка ошибок

Если чанк не загрузился (сеть, новый деплой удалил старые файлы), `lazy` бросает ошибку — ее ловит Error Boundary:

```jsx
<ErrorBoundary fallback={<p>Не удалось загрузить. Обновите страницу.</p>}>
  <Suspense fallback={<Spinner />}>
    <Settings />
  </Suspense>
</ErrorBoundary>
```

## Lazy loading и SSR

- В React 17 `React.lazy` не работал с `renderToString` — использовали `@loadable/component`.
- В React 18 `renderToPipeableStream` поддерживает `lazy` и Suspense: сервер отправляет fallback, а затем дописывает HTML, когда компонент готов (streaming SSR).
- На клиенте нужно загрузить тот же чанк до гидрации этой части; React 18 гидрирует участки по мере готовности (selective hydration).
- В Next.js используют `next/dynamic`; `ssr: false` отключает серверный рендер для компонентов, зависящих от `window`.

```jsx
import dynamic from "next/dynamic";
const Map = dynamic(() => import("./Map"), { ssr: false, loading: () => <p>Карта...</p> });
```

## Что важно помнить

- Объявляйте `lazy` на уровне модуля, а не внутри компонента — иначе state будет сбрасываться при каждом рендере.
- Слишком мелкое дробление создает много запросов — объединяйте связанное.
- Оборачивайте переходы в `startTransition`, чтобы при навигации не показывать fallback вместо уже видимой страницы.
- Lazy loading картинок — отдельная тема: `loading="lazy"` у `<img>`.

## Мини-шпаргалка

`lazy(() => import(...))` + `<Suspense fallback>` = отдельный чанк, загружаемый по требованию. Делить маршруты, модалки, тяжелые библиотеки. Ошибки — Error Boundary. SSR: React 18 streaming поддерживает lazy; в Next.js — `next/dynamic`.
