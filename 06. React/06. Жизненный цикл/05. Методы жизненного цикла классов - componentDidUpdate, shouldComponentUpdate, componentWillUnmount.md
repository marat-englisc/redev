# Методы жизненного цикла классов: componentDidUpdate, shouldComponentUpdate, componentWillUnmount

> [!NOTE]
> `componentDidUpdate(prevProps, prevState, snapshot)` вызывается после каждого обновления (не после первого рендера) — для реакции на изменения props/state: запросов, работы с DOM. `shouldComponentUpdate(nextProps, nextState)` вызывается перед рендером и, вернув `false`, отменяет обновление — это ручная оптимизация. `componentWillUnmount()` вызывается перед удалением компонента — для отписок и очистки таймеров. В функциональных компонентах им соответствуют `useEffect` с зависимостями, `React.memo` и cleanup эффекта.

## Вопрос

Что делают `componentDidUpdate()`, `shouldComponentUpdate()` и `componentWillUnmount()`? Какие у них аналоги в хуках?

## componentDidUpdate

```jsx
class UserProfile extends React.Component {
  componentDidUpdate(prevProps) {
    if (prevProps.userId !== this.props.userId) {   // обязательно сравнивать
      this.loadUser(this.props.userId);
    }
  }
}
```

- Без проверки `prevProps` setState внутри метода вызовет бесконечный цикл.
- Третий аргумент `snapshot` приходит из `getSnapshotBeforeUpdate` — например, позиция прокрутки до изменения DOM.

Аналог:

```jsx
useEffect(() => {
  loadUser(userId);
}, [userId]);
```

## shouldComponentUpdate

```jsx
class Row extends React.Component {
  shouldComponentUpdate(nextProps) {
    return nextProps.value !== this.props.value; // false → рендер пропускается
  }
}

// то же поверхностное сравнение всех props и state
class Row2 extends React.PureComponent {}
```

Аналог:

```jsx
const Row = memo(function Row({ value }) { /* ... */ });
const Row3 = memo(Row, (prev, next) => prev.value === next.value); // true → НЕ рендерить
```

Обратите внимание: `shouldComponentUpdate` возвращает `true`, чтобы рендерить, а функция сравнения `memo` — `true`, чтобы **пропустить** рендер.

## componentWillUnmount

```jsx
class Chat extends React.Component {
  componentDidMount() {
    this.connection = connect(this.props.roomId);
  }
  componentWillUnmount() {
    this.connection.disconnect();
  }
}
```

Аналог:

```jsx
useEffect(() => {
  const connection = connect(roomId);
  return () => connection.disconnect();
}, [roomId]);
```

Хуковая версия заодно правильно обрабатывает смену `roomId` — в классе для этого нужен еще и `componentDidUpdate`.

## Сводка

| Классовый метод | Когда | Хуковый аналог |
| --- | --- | --- |
| `componentDidMount` | после первого commit | `useEffect(fn, [])` |
| `componentDidUpdate` | после каждого обновления | `useEffect(fn, [deps])` |
| `componentWillUnmount` | перед удалением | cleanup эффекта |
| `shouldComponentUpdate` | перед рендером обновления | `React.memo` |
| `getSnapshotBeforeUpdate` | перед изменением DOM | нет прямого аналога |
| `componentDidCatch` | ошибка в потомке | нет — только классы |

## Что важно помнить

- `shouldComponentUpdate` — подсказка, а не гарантия: React может рендерить и при `false` в будущих версиях.
- Неправильная реализация `shouldComponentUpdate` приводит к «застывшему» UI.
- В `componentWillUnmount` нельзя вызывать `setState` — компонент больше не будет рендериться.
- Новый код пишется на функциях; знание классов нужно для легаси и Error Boundary.

## Мини-шпаргалка

`componentDidUpdate` — после обновления, сравнивать `prevProps`. `shouldComponentUpdate` — `false` отменяет рендер, аналог `memo`. `componentWillUnmount` — очистка, аналог cleanup. Хуки объединяют mount, update и unmount в одном эффекте.
