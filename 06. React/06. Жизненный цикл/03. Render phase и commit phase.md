# Render phase и commit phase

> [!NOTE]
> Обновление в React проходит две фазы. **Render phase** — React вызывает компоненты, получает новый JSX и сравнивает его с предыдущим деревом (reconciliation). Эта фаза **чистая**: без изменений DOM и побочных эффектов, ее можно прервать, повторить или отбросить. **Commit phase** — React синхронно применяет вычисленные изменения к DOM, подключает ref и запускает layout-эффекты, а затем (после отрисовки) обычные эффекты. Commit нельзя прервать.

## Вопрос

Что такое render phase и commit phase? Чем они отличаются?

## Основная идея

```text
Триггер (setState, props, контекст)
   ↓
RENDER PHASE (чистая, прерываемая)
   - вызов функций компонентов
   - вычисление нового дерева fiber
   - diff со старым деревом, список изменений
   ↓
COMMIT PHASE (синхронная, непрерываемая)
   - мутации DOM
   - подключение/обнуление ref
   - useLayoutEffect, componentDidMount/DidUpdate
   ↓
Браузер рисует кадр
   ↓
useEffect (пассивные эффекты)
```

## Сравнение

| | Render phase | Commit phase |
| --- | --- | --- |
| Что делает | вычисляет, что изменить | применяет изменения |
| Работа с DOM | нет | да |
| Побочные эффекты | запрещены | разрешены (эффекты) |
| Прерывание | можно (concurrent rendering) | нельзя |
| Может повториться | да (Strict Mode, прерывания) | ровно один раз на обновление |
| Код | тело компонента, `render()`, `useMemo`, инициализаторы state, редьюсеры | `useLayoutEffect`, `useEffect`, ref-колбэки |

## Почему рендер должен быть чистым

```jsx
function Item({ item }) {
  analytics.track("render", item.id); // плохо: может вызваться несколько раз или для отброшенного рендера
  return <li>{item.title}</li>;
}

function Item2({ item }) {
  useEffect(() => {
    analytics.track("shown", item.id); // хорошо: только после реального commit
  }, [item.id]);
  return <li>{item.title}</li>;
}
```

В конкурентном режиме React может начать рендер, прерваться на срочное обновление и выбросить результат. Побочный эффект в рендере выполнится, хотя на экране ничего не изменится.

## Что важно помнить

- Strict Mode вызывает функции render phase дважды, чтобы выявить нечистый код.
- Рендер компонента не означает изменение DOM: если результат совпал, commit ничего не меняет.
- `useLayoutEffect` блокирует отрисовку, `useEffect` — нет.
- В Profiler видно время render phase каждого компонента и время commit.

## Мини-шпаргалка

Render — вычисление, чистое, прерываемое, может повторяться. Commit — изменения DOM, ref, эффекты, синхронно и один раз. Побочные эффекты — только в commit (эффекты и обработчики).
