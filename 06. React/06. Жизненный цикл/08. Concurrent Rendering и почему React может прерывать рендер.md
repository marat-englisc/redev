# Concurrent Rendering и почему React может прерывать рендер

> [!NOTE]
> **Concurrent Rendering** (раньше «Concurrent Mode») — возможность React 18+ готовить несколько версий UI одновременно и **прерывать** рендер. React разбивает работу на небольшие единицы (fiber) и между ними проверяет, нет ли более срочной задачи — например, ввода с клавиатуры. Если есть, он откладывает или выбрасывает текущий рендер и обрабатывает срочное обновление. Конкурентный рендеринг включается при `createRoot` и используется функциями `startTransition`, `useDeferredValue`, Suspense.

## Вопрос

Что такое Concurrent Rendering? Почему React теперь может прерывать рендер и как это изменилось в React 18?

## Синхронный и конкурентный рендер

```text
Синхронный (React 17):
[====== рендер 300 мс ======] ← ввод ждет, интерфейс «залипает»

Конкурентный (React 18):
[== рендер ==] → ввод! → [ввод] → [== рендер (заново) ==]
```

В синхронном режиме начатый рендер всегда доводится до конца. В конкурентном React работает квантами (~5 мс), отдает управление браузеру и может переключиться на более важное обновление.

## Почему это возможно

- **Fiber-архитектура**: дерево — связный список узлов, работу можно приостановить на любом узле и продолжить позже.
- **Чистая render phase**: рендер не меняет DOM, поэтому незаконченный результат можно выбросить без последствий.
- **Приоритеты (lanes)**: каждое обновление получает приоритет — дискретный ввод, непрерывный ввод, обычный, transition, idle.
- **Commit атомарен**: пользователь видит только завершенное дерево, без промежуточных состояний.

## Как это использовать

```jsx
const [isPending, startTransition] = useTransition();

function onTabClick(tab) {
  startTransition(() => setTab(tab)); // несрочное: можно прервать
}

const deferredQuery = useDeferredValue(query); // отложенная копия значения
```

Конкурентность — не отдельный режим всего приложения, а **свойство конкретных обновлений**: обычные `setState` остаются срочными, transitions — прерываемыми.

## Что изменилось в React 18

| Возможность | Описание |
| --- | --- |
| `createRoot` | включает конкурентные возможности |
| Автоматический batching | во всех контекстах |
| Transitions | `useTransition`, `startTransition` |
| `useDeferredValue` | отложенные значения |
| Suspense на сервере | streaming SSR, selective hydration |
| `useSyncExternalStore` | защита внешних store от tearing |
| Strict Mode | двойной mount эффектов в разработке |

## Последствия для кода

- Рендер может вызываться несколько раз и не дойти до commit — побочные эффекты в рендере недопустимы.
- Внешние мутируемые store должны подключаться через `useSyncExternalStore`.
- Методы `UNSAFE_componentWillMount` и подобные небезопасны — они могут выполниться для отброшенного рендера.

## Что важно помнить

- Конкурентный рендеринг не делает JS многопоточным — всё по-прежнему в одном потоке, просто с прерываниями.
- Тяжелая синхронная функция (цикл на 500 мс) внутри одного компонента всё равно заблокирует поток.
- Прирост виден на тяжелых деревьях; для мелких обновлений разницы нет.

## Мини-шпаргалка

Concurrent Rendering: рендер разбит на кванты, может прерываться ради срочных обновлений и выбрасываться. Возможно благодаря Fiber и чистому рендеру. Включается `createRoot`, используется через transitions, `useDeferredValue`, Suspense.
