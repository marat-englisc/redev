# Почему useEffect объединяет несколько lifecycle-задач

> [!NOTE]
> Один эффект может объединить создание, замену и очистку конкретной синхронизации. Он не является буквальным эквивалентом всех методов жизненного цикла.

## Вопрос

Как заменить три классовых метода одной моделью setup/cleanup и где аналогия перестаёт работать?

## Основная идея

В классе подписку обычно создают в componentDidMount, заменяют в componentDidUpdate при смене параметров и удаляют в componentWillUnmount. Это три момента жизни, но одна предметная задача. В эффекте setup описывает актуальную подписку, deps определяют её входы, cleanup закрывает результат предыдущего setup.

React автоматически вызывает предыдущую очистку при смене зависимостей и затем устанавливает новую синхронизацию. Поэтому нет необходимости вручную сравнивать prevProps для каждой подписки. Важно указать все реактивные входы, иначе внешняя система останется связана с прежними данными.

Но effect с `[id]` запускается и на первом commit, а не только на update. Cleanup выполняется при смене id, а не только при unmount. UseEffect не выполняется во время SSR и не предоставляет измерение до paint. Для последнего выбирают useLayoutEffect. У Error Boundary и getSnapshotBeforeUpdate также нет прямой универсальной замены одним useEffect.

## Пример

```tsx
import { useEffect, useState } from 'react';

function KeyboardShortcut({ enabled }: { enabled: boolean }) {
  useEffect(() => {
    if (!enabled) return;
    const handler = (event: KeyboardEvent) => {
      if (event.key === '?') console.log('Открыть справку');
    };
    window.addEventListener('keydown', handler);
    return () => window.removeEventListener('keydown', handler);
  }, [enabled]);
  return <p>Горячая клавиша ?: {enabled ? 'включена' : 'выключена'}</p>;
}

export default function HelpSettings() {
  const [enabled, setEnabled] = useState(true);
  return <>
    <button onClick={() => setEnabled(v => !v)}>Переключить</button>
    <KeyboardShortcut enabled={enabled} />
  </>;
}
```

После монтирования с enabled=true появляется слушатель. При выключении прежний cleanup снимает его, а новый setup ничего не создаёт. При включении появляется новая подписка. При удалении активного компонента снимается последняя. Все ветви одной задачи находятся рядом.

## Что важно помнить

- Не создавайте отдельный «mount-effect» с захваченным prop и отдельный «update-effect», если это одна синхронизация: легко дублировать действия.
- `[]` отражает отсутствие реактивных чтений, а не желание «вызвать один раз любой код».
- Разные внешние процессы лучше разделять отдельными эффектами.
- Пользовательское действие, например отправку заказа, обычно выполняют по событию.
- Setup и cleanup должны выдерживать дополнительный разработческий цикл StrictMode.

## Мини-шпаргалка

Класс: didMount + условный didUpdate + willUnmount. Эффект: setup + реальные deps + cleanup. Сходна задача, но не точное расписание всех методов.
