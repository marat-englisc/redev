# Жизненный цикл компонента: стадии, классы и функции

> [!NOTE]
> **Жизненный цикл** — последовательность этапов, через которые проходит компонент: **монтирование** (первое появление в DOM), **обновление** (повторные рендеры при изменении props, state или контекста) и **размонтирование** (удаление из дерева). В классовых компонентах на каждый этап есть методы (`componentDidMount`, `componentDidUpdate`, `componentWillUnmount`), в функциональных — одна модель: компонент рендерится, а эффекты синхронизируют его с внешним миром и очищаются.

## Вопрос

Что такое жизненный цикл компонента в React? Какие у него стадии и чем жизненный цикл классового компонента отличается от функционального?

## Стадии

```text
Монтирование:   render → commit (DOM создан) → эффекты
Обновление:     render → commit (DOM изменен) → cleanup старых эффектов → новые эффекты
Размонтирование: cleanup эффектов → удаление из DOM
```

Каждая стадия делится на две фазы:

- **render phase** — React вызывает компонент и вычисляет новое дерево; чистая, может быть прервана;
- **commit phase** — React применяет изменения к DOM и запускает эффекты; синхронная.

## Классовый компонент

```jsx
class Clock extends React.Component {
  state = { now: new Date() };

  componentDidMount() {                  // после монтирования
    this.id = setInterval(() => this.setState({ now: new Date() }), 1000);
  }

  componentDidUpdate(prevProps) {        // после обновления
    if (prevProps.zone !== this.props.zone) this.sync();
  }

  componentWillUnmount() {               // перед удалением
    clearInterval(this.id);
  }

  render() {
    return <p>{this.state.now.toLocaleTimeString()}</p>;
  }
}
```

## Функциональный компонент

```jsx
function Clock({ zone }) {
  const [now, setNow] = useState(new Date());

  useEffect(() => {
    const id = setInterval(() => setNow(new Date()), 1000);
    return () => clearInterval(id);      // размонтирование
  }, []);

  useEffect(() => {
    sync(zone);                          // монтирование + изменение zone
  }, [zone]);

  return <p>{now.toLocaleTimeString()}</p>;
}
```

## Сравнение

| Задача | Класс | Функция |
| --- | --- | --- |
| Инициализация state | `constructor`, `state = {}` | `useState(init)` |
| После монтирования | `componentDidMount` | `useEffect(fn, [])` |
| После обновления | `componentDidUpdate` | `useEffect(fn, [deps])` |
| Перед размонтированием | `componentWillUnmount` | cleanup эффекта |
| Пропустить рендер | `shouldComponentUpdate`, `PureComponent` | `React.memo` |
| Перед commit (снимок DOM) | `getSnapshotBeforeUpdate` | нет аналога (`useLayoutEffect` частично) |
| Ловить ошибки | `componentDidCatch` | нет — только классы |

Главное отличие в мышлении: классы думают **событиями жизненного цикла**, функции — **синхронизацией**. Эффект описывает «что должно быть синхронизировано с текущими props/state», а React сам решает, когда запускать и очищать его.

## Что важно помнить

- Error Boundary по-прежнему можно написать только классом.
- Устаревшие методы `componentWillMount`, `componentWillReceiveProps`, `componentWillUpdate` помечены `UNSAFE_` — они небезопасны при конкурентном рендеринге.
- В Strict Mode React в разработке монтирует компонент дважды (mount → unmount → mount), чтобы проверить очистку.
- Компонент может отрендериться, но не попасть в commit — в конкурентном режиме рендер можно отбросить.

## Мини-шпаргалка

Жизненный цикл: монтирование → обновления → размонтирование. Фазы: render (чистая) и commit (DOM, эффекты). Класс: `didMount`/`didUpdate`/`willUnmount`. Функция: `useEffect` + cleanup + зависимости.
