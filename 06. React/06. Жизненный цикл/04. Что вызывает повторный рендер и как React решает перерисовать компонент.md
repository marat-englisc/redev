# Что вызывает повторный рендер и как React решает перерисовать компонент

> [!NOTE]
> Компонент рендерится заново в трех случаях: изменился его **state** (`setState`, `dispatch`), изменился **контекст**, который он читает, или перерендерился **родитель**. Изменение props само по себе не причина — props меняются только потому, что перерендерился родитель. Ререндер — это вызов функции компонента и сравнение результата; DOM меняется, только если результат отличается.

## Вопрос

Что вызывает повторный рендер компонента? Как React принимает решение о перерисовке?

## Основная идея

**State.** Вызов сеттера ставит обновление в очередь. Если новое значение равно старому по `Object.is`, React может пропустить рендер (bailout). Поэтому мутация объекта без создания нового (`state.items.push(x); setState(state)`) не вызовет ререндер — ссылка та же.

**Родитель.** Когда рендерится компонент, по умолчанию рендерятся **все его дети**, даже если их props не изменились. Это главный источник «лишних» ререндеров. `React.memo` позволяет ребенку пропустить рендер, если его props поверхностно равны.

**Контекст.** Компонент, вызвавший `useContext(Ctx)`, перерендерится при изменении значения провайдера — независимо от `memo`.

**Не вызывают ререндер:** изменение `ref.current`, изменение обычной переменной внутри компонента, мутация объектов, изменения во внешнем store без подписки (для этого — `useSyncExternalStore`).

После рендера React сравнивает новое дерево элементов со старым, и в DOM попадают только реальные отличия.

## Пример

```jsx
function Parent() {
  const [count, setCount] = useState(0);
  return (
    <>
      <button onClick={() => setCount(count + 1)}>{count}</button>
      <Child />                 {/* рендерится при каждом клике */}
      <MemoChild />             {/* пропускает рендер — props не менялись */}
    </>
  );
}

const MemoChild = memo(function MemoChild() {
  return <p>Я не перерисовываюсь без причины</p>;
});
```

## Как уменьшить лишние ререндеры

- держать state ближе к месту использования (colocation);
- выносить «тяжелые» части в отдельные компоненты и передавать их через `children`;
- `memo` + стабильные пропсы (`useCallback`, `useMemo`);
- разделять контексты и мемоизировать их значения;
- селекторы во внешних store (Zustand, Redux).

## Что важно помнить

- Ререндер — нормальная работа React; оптимизируйте только измеренные проблемы (React Profiler).
- React Compiler автоматически мемоизирует компоненты и значения, снижая потребность в ручном `memo`.
- В Strict Mode в dev-режиме компоненты рендерятся дважды — это не реальные ререндеры в production.
- Кнопка «Highlight updates» в React DevTools подсвечивает рендерящиеся компоненты.

## Мини-шпаргалка

Причины ререндера: state, контекст, рендер родителя. Props меняются только через родителя. `ref` и переменные не вызывают ререндер. Ререндер ≠ изменение DOM. `memo` — пропуск при равных props.
