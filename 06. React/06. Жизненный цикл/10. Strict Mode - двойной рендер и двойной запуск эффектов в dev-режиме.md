# Strict Mode: двойной рендер и двойной запуск эффектов в dev-режиме

> [!NOTE]
> В режиме разработки `<StrictMode>` намеренно **вызывает функции рендера дважды** и **монтирует компонент дважды** (mount → unmount → mount), запуская эффекты, их очистку и снова эффекты. Так React выявляет нечистый рендер и эффекты без корректной очистки — ошибки, которые проявятся при конкурентном рендеринге, Fast Refresh и будущих возможностях вроде `<Activity>`. В продакшене двойных вызовов нет.

## Вопрос

Почему эффекты вызываются дважды в dev-режиме? Что делает Strict Mode и как с этим работать?

## Что вызывается дважды

| Что | Зачем |
| --- | --- |
| тело компонента, `render()` | проверка чистоты рендера |
| инициализаторы `useState`, `useMemo`, `useReducer` | проверка чистоты |
| функции-апдейтеры `setX(prev => ...)`, редьюсеры | проверка чистоты |
| эффекты: setup → cleanup → setup | проверка, что очистка отменяет эффект |
| ref-колбэки (React 19) | проверка очистки ref |

## Пример проблемы

```jsx
useEffect(() => {
  const connection = createConnection(roomId);
  connection.connect();
  // нет cleanup → в dev будет два соединения, в проде — утечка при смене roomId
}, [roomId]);
```

Исправление — не «отключить Strict Mode», а добавить очистку:

```jsx
useEffect(() => {
  const connection = createConnection(roomId);
  connection.connect();
  return () => connection.disconnect();
}, [roomId]);
```

## Типичные случаи

- **Запрос данных** — двойной запрос в dev нормален. Чтобы ответ не перезаписывал state, отменяйте запрос (`AbortController`) или игнорируйте устаревший ответ флагом.
- **Аналитика** — двойной лог в dev допустим; в продакшене событие одно.
- **Одноразовая инициализация приложения** — вынесите на уровень модуля или используйте флаг вне компонента.
- **Анимации** — в cleanup сбрасывайте состояние анимации.

```jsx
let didInit = false;

function App() {
  useEffect(() => {
    if (didInit) return;
    didInit = true;
    loadDataFromStorage();
  }, []);
}
```

## Что важно помнить

- Двойные логи в консоли — ожидаемы; React DevTools может приглушать второй вызов.
- Strict Mode не влияет на продакшен-сборку.
- Если код ломается от двойного запуска, он сломается и в реальных сценариях: смена props, Fast Refresh, переходы назад-вперед с сохранением state.
- Strict Mode также предупреждает об устаревших API (`findDOMNode`, `UNSAFE_*` методы).

## Мини-шпаргалка

Strict Mode в dev: рендер ×2, эффекты setup → cleanup → setup. Цель — найти нечистый рендер и эффекты без очистки. Решение — правильный cleanup, а не отключение. В проде двойных вызовов нет.
