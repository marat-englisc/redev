# Почему useEffect не имеет точного расписания после paint

> [!NOTE]
> useEffect — пассивная синхронизация после фиксации результата. Он не предоставляет гарантии немедленного вызова после commit или обязательного ожидания paint во всех случаях.

## Вопрос

Почему нельзя полагаться на цепочку «DOM → paint → useEffect» как на универсальное правило?

## Основная идея

React сначала должен зафиксировать результат, прежде чем запускать его эффект. Но сам факт commit означает изменение DOM, а не уже показанный браузером кадр. Планирование пассивных эффектов устроено так, чтобы часто позволять браузеру показать интерфейс, однако это не абсолютный порядок для любых обновлений.

Для обновления от пользовательского взаимодействия React может выполнить эффект до paint. Если layout-эффект обновляет state, пассивные эффекты также могут обрабатываться раньше ожидаемого. Поэтому лог внутри useEffect нельзя считать доказательством, что пользователь уже видел кадр. Он доказывает запуск синхронизации соответствующего зафиксированного результата.

Если работа обязана завершиться до показа кадра, например позиционирование измеренного popover, нужен useLayoutEffect. Если действие обязательно должно ждать другого браузерного этапа, используйте подходящий браузерный механизм с пониманием его контракта; простая замена на useEffect этого не гарантирует. Не переносите тяжёлые вычисления в эффекты в надежде автоматически сделать их неблокирующими.

## Пример

```tsx
import { useEffect, useLayoutEffect, useRef, useState } from 'react';

export default function PhaseLog() {
  const [count, setCount] = useState(0);
  const ref = useRef<HTMLParagraphElement>(null);
  console.log('Render:', count);

  useLayoutEffect(() => {
    console.log('Layout: DOM-текст', ref.current?.textContent);
  }, [count]);
  useEffect(() => {
    console.log('Passive effect:', count);
  }, [count]);

  return <>
    <p ref={ref}>Клики: {count}</p>
    <button onClick={() => setCount(c => c + 1)}>Клик</button>
  </>;
}
```

Для соответствующего обновления render-лог предшествует layout-логу. Layout читает уже новый DOM. Passive-лог появляется при обработке эффекта, но по консоли нельзя установить точную границу paint. Для изучения отображения используйте запись Performance с кадрами.

## Что важно помнить

- Render не должен идти после layout-эффекта того же самого результата: он вычисляет этот результат заранее.
- Setup useEffect не запускается для отброшенной render-попытки.
- «Асинхронный эффект» не означает выполнение в другом потоке.
- Layout-эффект блокирует paint и должен быть коротким.
- Не используйте порядок логов разных компонентов как публичный контракт всего дерева.
- В StrictMode дополнительные проверки увеличивают число сообщений.

## Мини-шпаргалка

Commit ≠ paint. Passive effect — после фиксации, точный момент гибкий. Layout effect — работа до paint. Логи показывают вызовы, а не появление пикселей.
