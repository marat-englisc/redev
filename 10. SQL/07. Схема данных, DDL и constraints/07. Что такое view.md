# Что такое view

> [!NOTE]
> **Представление (view)** — сохранённый в базе именованный `SELECT`, к которому обращаются как к таблице. Обычный view **не хранит данные**: при каждом запросе PostgreSQL подставляет его определение и оптимизирует вместе с внешним запросом. Зачем: спрятать сложные JOIN и вычисления за простым именем, дать стабильный интерфейс отчётам и другим сервисам при изменении таблиц, ограничить доступ (выдать права на view, а не на таблицу с чувствительными столбцами). Простые view на одну таблицу **обновляемые** (`INSERT`/`UPDATE` через них работают), `WITH CHECK OPTION` запрещает изменения, выпадающие из условия view. Для хранения результата тяжёлого запроса есть [materialized view](<../10. Индексы и оптимизация запросов/09. Что такое materialized view.md>).

## Вопрос

Что такое view и когда его использовать?

## Создание

```sql
CREATE VIEW active_customers AS
SELECT u.id, u.email, u.name,
       count(o.id)               AS orders_count,
       COALESCE(sum(o.total), 0) AS revenue
FROM users u
LEFT JOIN orders o ON o.user_id = u.id AND o.status = 'paid'
WHERE u.deleted_at IS NULL
GROUP BY u.id;

SELECT * FROM active_customers WHERE revenue > 10000 ORDER BY revenue DESC;
```

## Изменение и удаление

```sql
CREATE OR REPLACE VIEW active_customers AS ...   -- можно добавлять столбцы в конец, но не менять типы/порядок
DROP VIEW active_customers;
```

## Безопасность

```sql
CREATE VIEW public_users AS
SELECT id, name, avatar_url FROM users;          -- без email и password_hash

GRANT SELECT ON public_users TO analytics;
REVOKE ALL ON users FROM analytics;

-- PostgreSQL 15+: проверять права вызывающего на базовые таблицы
CREATE VIEW v WITH (security_invoker = true) AS SELECT ...;
```

По умолчанию view выполняется с правами **владельца**, что позволяет открыть часть таблицы, не давая к ней прямого доступа. С RLS это важно учитывать: без `security_invoker` политики проверяются для владельца view.

## Обновляемые view

```sql
CREATE VIEW published_posts AS
SELECT id, title, body, is_published FROM posts WHERE is_published
WITH CHECK OPTION;

UPDATE published_posts SET title = 'Новый заголовок' WHERE id = 1;   -- ✓
INSERT INTO published_posts (title, body, is_published) VALUES ('x', 'y', false);  -- ✗ CHECK OPTION
```

View с `JOIN`, `GROUP BY`, `DISTINCT`, агрегатами автоматически не обновляются — нужны `INSTEAD OF` триггеры.

## View и materialized view

| | View | Materialized view |
| --- | --- | --- |
| Хранит данные | Нет | Да |
| Актуальность | Всегда свежие | До `REFRESH` |
| Скорость | Как исходный запрос | Как чтение таблицы |
| Индексы | Нет (используются индексы таблиц) | Можно создавать |

## Частые ошибки

- Считать, что view ускоряет запрос — он не кеширует результат.
- View поверх view поверх view — сложные планы и трудная отладка.
- `SELECT *` в определении: при добавлении столбца в таблицу view его не увидит (список фиксируется при создании).
- Забыть про права владельца и RLS.

## Что важно помнить

- View — сохранённый запрос, не копия данных.
- Удобен для инкапсуляции логики и разграничения доступа.
- Для кеширования тяжёлых агрегатов — materialized view.

## Мини-шпаргалка

- `CREATE [OR REPLACE] VIEW name AS SELECT ...`.
- `WITH CHECK OPTION`.
- `WITH (security_invoker = true)` (PG 15+).
- `GRANT SELECT ON view TO role`.
