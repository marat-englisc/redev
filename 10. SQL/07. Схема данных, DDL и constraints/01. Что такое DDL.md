# Что такое DDL

> [!NOTE]
> **DDL (Data Definition Language)** — команды, которые описывают **структуру** базы: `CREATE`, `ALTER`, `DROP`, `TRUNCATE`, `COMMENT` для таблиц, индексов, представлений, схем, типов. Рядом стоят **DML** (`SELECT`, `INSERT`, `UPDATE`, `DELETE` — работа с данными), **DCL** (`GRANT`, `REVOKE` — права) и **TCL** (`BEGIN`, `COMMIT`, `ROLLBACK`). В PostgreSQL DDL **транзакционный**: миграцию из нескольких `ALTER` можно откатить целиком (в MySQL DDL вызывает неявный `COMMIT`). Изменения схемы в продакшене делают через версионируемые **миграции** и с оглядкой на блокировки: многие `ALTER TABLE` берут `ACCESS EXCLUSIVE` lock.

## Вопрос

Что такое DDL и чем он отличается от DML?

## Категории SQL-команд

| Категория | Команды | Назначение |
| --- | --- | --- |
| DDL | `CREATE`, `ALTER`, `DROP`, `TRUNCATE` | Структура |
| DML | `SELECT`, `INSERT`, `UPDATE`, `DELETE`, `MERGE` | Данные |
| DCL | `GRANT`, `REVOKE` | Права |
| TCL | `BEGIN`, `COMMIT`, `ROLLBACK`, `SAVEPOINT` | Транзакции |

## CREATE TABLE

```sql
CREATE TABLE products (
  id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  sku         text NOT NULL UNIQUE,
  title       text NOT NULL,
  price       numeric(12, 2) NOT NULL CHECK (price >= 0),
  category_id bigint REFERENCES categories (id),
  attrs       jsonb NOT NULL DEFAULT '{}',
  created_at  timestamptz NOT NULL DEFAULT now()
);

COMMENT ON COLUMN products.attrs IS 'Произвольные характеристики товара';
```

## ALTER TABLE

```sql
ALTER TABLE products ADD COLUMN is_published boolean NOT NULL DEFAULT false;
ALTER TABLE products RENAME COLUMN title TO name;
ALTER TABLE products ALTER COLUMN name TYPE varchar(300);
ALTER TABLE products ADD CONSTRAINT products_name_not_empty CHECK (name <> '');
ALTER TABLE products DROP COLUMN attrs;
```

## DROP и IF EXISTS

```sql
DROP TABLE IF EXISTS tmp_import;
DROP TABLE categories;            -- ошибка, если на неё ссылаются FK
DROP TABLE categories CASCADE;    -- удалит и зависимые FK/представления — осторожно
```

## Транзакционный DDL (PostgreSQL)

```sql
BEGIN;
ALTER TABLE orders ADD COLUMN currency char(3) NOT NULL DEFAULT 'RUB';
CREATE INDEX orders_currency_idx ON orders (currency);
-- что-то пошло не так
ROLLBACK;   -- и столбец, и индекс исчезли
```

Исключения: `CREATE INDEX CONCURRENTLY`, `VACUUM`, `CREATE DATABASE` нельзя выполнять внутри транзакции.

## DDL и блокировки

| Операция | Риск |
| --- | --- |
| `ADD COLUMN` (nullable или с константным `DEFAULT`, PG 11+) | Быстро, короткая блокировка |
| `ALTER COLUMN TYPE` | Часто перезапись всей таблицы под `ACCESS EXCLUSIVE` |
| `ADD CONSTRAINT ... CHECK/FK` | Проверка всех строк; `NOT VALID` + `VALIDATE` смягчает |
| `CREATE INDEX` | Блокирует запись; `CONCURRENTLY` — нет |

Даже короткая операция может «повесить» прод, если ждёт блокировку за долгим запросом — ставят `SET lock_timeout = '5s'`. Подробнее — [безопасное изменение большой таблицы](<../11. Практика Backend и собеседования/04. Как безопасно изменить большую таблицу.md>).

## Частые ошибки

- Менять схему вручную в проде, а не миграцией.
- `DROP ... CASCADE` без проверки зависимостей.
- Считать, что DDL откатывается в MySQL так же, как в PostgreSQL.
- Долгий `ALTER TABLE` в час пик.

## Что важно помнить

- DDL — структура, DML — данные.
- В PostgreSQL DDL можно откатить в транзакции.
- Изменения схемы — через миграции с учётом блокировок.

## Мини-шпаргалка

- `CREATE TABLE`, `ALTER TABLE ... ADD/DROP/ALTER COLUMN`.
- `DROP ... IF EXISTS`.
- `COMMENT ON`.
- `SET lock_timeout` перед миграцией.
