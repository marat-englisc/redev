# Что такое CHECK constraint

> [!NOTE]
> `CHECK (условие)` запрещает строки, для которых условие равно `false`. Важная деталь: если условие равно `NULL` (например, столбец пуст), проверка **проходит** — поэтому `CHECK` комбинируют с `NOT NULL`. Ограничение может касаться одного столбца (`price >= 0`) или нескольких в строке (`ends_at > starts_at`, «заполнено ровно одно из полей»). `CHECK` не может обращаться к другим строкам или таблицам — для этого нужны `UNIQUE`, `FOREIGN KEY`, `EXCLUDE` или триггеры. Для перечислений `CHECK (status IN (...))` проще в изменении, чем `ENUM`-тип, а для большого или меняющегося справочника лучше отдельная таблица с FK.

## Вопрос

Что такое `CHECK` constraint и когда его использовать?

## Примеры

```sql
CREATE TABLE bookings (
  id         bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  guests     int    NOT NULL CHECK (guests BETWEEN 1 AND 10),
  price      numeric(12, 2) NOT NULL CHECK (price >= 0),
  starts_at  timestamptz NOT NULL,
  ends_at    timestamptz NOT NULL,
  status     text NOT NULL DEFAULT 'pending',
  email      text,
  phone      text,

  CONSTRAINT bookings_period_check  CHECK (ends_at > starts_at),
  CONSTRAINT bookings_status_check  CHECK (status IN ('pending', 'confirmed', 'cancelled')),
  CONSTRAINT bookings_contact_check CHECK (email IS NOT NULL OR phone IS NOT NULL)
);
```

## NULL проходит проверку

```sql
CREATE TABLE t (discount int CHECK (discount BETWEEN 0 AND 100));
INSERT INTO t VALUES (NULL);   -- ✓ условие NULL → строка принята
INSERT INTO t VALUES (150);    -- ✗ check_violation
```

## Условные правила

```sql
-- если заказ отменён — должна быть причина
CHECK (status <> 'cancelled' OR cancel_reason IS NOT NULL)

-- ровно одна из ссылок заполнена
CHECK (num_nonnulls(post_id, photo_id, video_id) = 1)

-- формат (простая проверка)
CHECK (email ~* '^[^@\s]+@[^@\s]+\.[^@\s]+$')
CHECK (char_length(slug) BETWEEN 3 AND 100)
```

## Чего CHECK не умеет

| Правило | Инструмент |
| --- | --- |
| Уникальность | `UNIQUE` |
| Ссылка на другую таблицу | `FOREIGN KEY` |
| Непересекающиеся интервалы | `EXCLUDE USING gist` |
| Сравнение с другими строками («не больше 5 активных») | Триггер или логика с блокировкой |

`CHECK` с функцией, читающей другие таблицы, технически возможен, но не гарантирует целостность: при изменении другой таблицы проверка не перезапустится.

## CHECK, ENUM или справочник

| Подход | Плюсы | Минусы |
| --- | --- | --- |
| `CHECK (status IN (...))` | Просто, легко изменить миграцией | Значения дублируются в коде |
| `CREATE TYPE ... AS ENUM` | Компактно, тип в схеме | Нельзя удалить значение без пересоздания типа |
| Таблица + FK | Можно хранить подписи, порядок, флаги | Лишний JOIN |

## Добавление к существующей таблице

```sql
ALTER TABLE orders ADD CONSTRAINT orders_total_check CHECK (total >= 0) NOT VALID;
ALTER TABLE orders VALIDATE CONSTRAINT orders_total_check;
```

## Частые ошибки

- `CHECK` без `NOT NULL` и удивление, что `NULL` проходит.
- Сложная бизнес-логика в `CHECK` с функциями, обращающимися к другим таблицам.
- Безымянные ограничения.
- Сложная проверка email в `CHECK` вместо разумной валидации в приложении.

## Что важно помнить

- `CHECK` отклоняет только `false`, `NULL` проходит.
- Проверяет одну строку, не другие строки и таблицы.
- Отличен для диапазонов, статусов и связей полей внутри строки.

## Мини-шпаргалка

- `CHECK (price >= 0)`.
- `CHECK (ends_at > starts_at)`.
- `CHECK (a IS NOT NULL OR b IS NOT NULL)`.
- `num_nonnulls(...) = 1`.
- `NOT VALID` + `VALIDATE`.
