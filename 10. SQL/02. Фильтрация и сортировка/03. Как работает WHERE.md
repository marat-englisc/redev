# Как работает WHERE

> [!NOTE]
> `WHERE` фильтрует строки **до** группировки и вычисления `SELECT`: в результат попадают только строки, для которых условие равно `true` (а не `false` и не `NULL`). Условия комбинируют через `AND`, `OR`, `NOT` (у `AND` приоритет выше — используйте скобки), используют операторы сравнения, `IN`, `BETWEEN`, `LIKE`, `IS NULL`, `EXISTS`. Агрегаты в `WHERE` недопустимы — для них есть `HAVING`. Для производительности важно, чтобы условие было **sargable**: столбец не оборачивается в функцию, а тип значения совпадает с типом столбца — тогда работает индекс.

## Вопрос

Как работает `WHERE` и как писать условия правильно?

## Базовые условия

```sql
SELECT id, email
FROM users
WHERE is_active
  AND country = 'RU'
  AND created_at >= now() - interval '30 days';
```

## Операторы

| Оператор | Пример |
| --- | --- |
| Сравнение | `price > 100`, `status <> 'cancelled'` |
| Список | `status IN ('paid', 'shipped')` |
| Диапазон | `total BETWEEN 100 AND 500` |
| Шаблон | `email LIKE '%@example.com'` |
| NULL | `deleted_at IS NULL` |
| Существование | `EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id)` |
| Массив (PostgreSQL) | `id = ANY($1::bigint[])` |

## Приоритет AND и OR

```sql
-- ✗ читается как: status = 'paid' OR (status = 'shipped' AND total > 1000)
WHERE status = 'paid' OR status = 'shipped' AND total > 1000

-- ✓ явно
WHERE (status = 'paid' OR status = 'shipped') AND total > 1000
-- или
WHERE status IN ('paid', 'shipped') AND total > 1000
```

## NULL в условиях

```sql
WHERE deleted_at IS NULL                         -- ✓
WHERE deleted_at = NULL                          -- ✗ всегда пусто
WHERE status IS DISTINCT FROM 'cancelled'        -- включает NULL-статусы
```

## Sargable-условия

```sql
-- ✗ функция над столбцом: индекс по created_at не используется
WHERE date(created_at) = '2026-10-24'
WHERE lower(email) = 'anna@x.com'           -- (поможет только индекс по lower(email))
WHERE price * 1.2 > 1000

-- ✓ столбец «чистый», вычисления — над константой
WHERE created_at >= '2026-10-24' AND created_at < '2026-10-25'
WHERE price > 1000 / 1.2
```

Несовпадение типов (`WHERE user_id = '42'` для `bigint`) тоже может помешать индексу — параметры передают правильного типа.

## Параметры из приложения

```ts
await db.query("SELECT * FROM users WHERE email = $1 AND is_active = $2", [email, true]);
```

Значения всегда передают параметрами, а не склейкой строк — защита от [SQL-инъекций](<../11. Практика Backend и собеседования/07. Что такое SQL injection.md>).

## Частые ошибки

- `OR` без скобок рядом с `AND`.
- `= NULL` вместо `IS NULL`.
- Агрегат в `WHERE` (`WHERE count(*) > 5`) — нужен `HAVING`.
- Функции над индексируемым столбцом.
- Фильтр по правой таблице `LEFT JOIN` в `WHERE` — превращает его в `INNER JOIN`.

## Что важно помнить

- `WHERE` пропускает только строки с условием `true`.
- `AND` связывает сильнее `OR`.
- Условие должно позволять использовать индекс: столбец без функций, совпадающие типы.

## Мини-шпаргалка

- `AND`, `OR`, `NOT` + скобки.
- `IN`, `BETWEEN`, `LIKE`, `IS NULL`, `EXISTS`, `= ANY`.
- Агрегаты — в `HAVING`.
- Без функций над столбцом.
- Только параметры, без склейки строк.
