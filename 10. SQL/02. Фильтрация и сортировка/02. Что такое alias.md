# Что такое alias

> [!NOTE]
> **Алиас (alias)** — временное имя внутри запроса. **Алиас столбца** (`price * qty AS total`) задаёт имя колонки результата — оно попадёт в ответ драйвера и в объект на стороне приложения. **Алиас таблицы** (`FROM users AS u`) сокращает запись, а в self join и при нескольких подзапросах обязателен, чтобы различать «роли» одной таблицы. У подзапроса в `FROM` алиас обязателен. Алиас столбца доступен в `ORDER BY`, но не в `WHERE`, `GROUP BY` (в стандарте) и `HAVING`, потому что они логически выполняются раньше `SELECT`.

## Вопрос

Что такое алиасы в SQL и где их можно использовать?

## Алиас столбца

```sql
SELECT
  email        AS user_email,
  created_at   AS registered_at,
  price * qty  AS total,
  count(*)     AS orders_count
FROM ...
```

Без алиаса выражение получит служебное имя (`?column?`, `count`), и в коде придётся писать `row["?column?"]`. Алиасы в `snake_case` или в кавычках для `camelCase`:

```sql
SELECT created_at AS "createdAt" FROM users;   -- PostgreSQL без кавычек приведёт к createdat
```

## Алиас таблицы

```sql
SELECT u.email, o.total
FROM users AS u
JOIN orders AS o ON o.user_id = u.id;
```

`AS` для таблиц можно опускать (`FROM users u`). Когда у таблицы есть алиас, обращаться по полному имени (`users.email`) уже нельзя.

## Когда алиас обязателен

```sql
-- self join: одна таблица в двух ролях
SELECT e.name AS employee, m.name AS manager
FROM employees e
LEFT JOIN employees m ON m.id = e.manager_id;

-- подзапрос в FROM
SELECT s.status, s.avg_total
FROM (
  SELECT status, avg(total) AS avg_total
  FROM orders
  GROUP BY status
) AS s;
```

## Где доступен алиас столбца

| Часть запроса | Доступен? | Почему |
| --- | --- | --- |
| `WHERE` | Нет | Выполняется до `SELECT` |
| `GROUP BY` | В PostgreSQL и MySQL — да (расширение), в стандарте — нет | |
| `HAVING` | Нет | |
| `ORDER BY` | Да | Выполняется после `SELECT` |

```sql
SELECT date_trunc('month', created_at) AS month, sum(total) AS revenue
FROM orders
GROUP BY month          -- PostgreSQL разрешает
ORDER BY month;
```

Чтобы использовать вычисление в `WHERE`, его повторяют или выносят в CTE/подзапрос.

## Хорошие имена

```sql
-- ✗ непонятно
FROM orders a JOIN users b ON a.x = b.id JOIN products c ...

-- ✓ понятно
FROM orders o JOIN users u ON o.user_id = u.id JOIN products p ...
```

## Частые ошибки

- Алиас столбца в `WHERE`.
- Обращение к таблице по полному имени после назначения алиаса.
- Одинаковые имена столбцов результата после `JOIN` (`id` из обеих таблиц) — драйвер оставит только одно.
- `camelCase` без кавычек в PostgreSQL.

## Что важно помнить

- Алиас столбца — имя в ответе приложению, алиас таблицы — короткая ссылка в запросе.
- Подзапросу в `FROM` и self join алиас нужен обязательно.
- Алиас столбца виден в `ORDER BY`, но не в `WHERE`.

## Мини-шпаргалка

- `expr AS name`, `table AS t`.
- Self join и подзапрос в `FROM` — с алиасом.
- `WHERE` — нет, `ORDER BY` — да.
- `"camelCase"` — в кавычках.
