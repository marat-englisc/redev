# Как работает SELECT

> [!NOTE]
> `SELECT` читает данные и возвращает **результирующий набор** — новую «виртуальную таблицу». В списке выборки можно указать столбцы, выражения, вызовы функций, подзапросы и задать им имена через `AS`. Полная форма: `SELECT … FROM … JOIN … WHERE … GROUP BY … HAVING … ORDER BY … LIMIT …`. Логически запрос выполняется не в порядке записи, а начиная с `FROM`: поэтому алиас из `SELECT` недоступен в `WHERE`. В коде приложения вместо `SELECT *` явно перечисляют нужные столбцы.

## Вопрос

Как работает `SELECT` и из каких частей он состоит?

## Базовый запрос

```sql
SELECT id, email
FROM users;
```

## Выражения в списке выборки

```sql
SELECT
  id,
  first_name || ' ' || last_name AS full_name,
  price * quantity               AS line_total,
  upper(country)                 AS country,
  now() - created_at             AS account_age,
  (SELECT count(*) FROM orders o WHERE o.user_id = u.id) AS orders_count
FROM users u;
```

`SELECT` может вычислять что угодно для каждой строки: арифметику, конкатенацию, функции, условные выражения (`CASE`), скалярные подзапросы.

## SELECT без таблицы

```sql
SELECT now(), version(), 2 + 2 AS answer;
```

## Полная структура

```sql
SELECT   u.country, count(*) AS users      -- 5. что вывести
FROM     users u                           -- 1. откуда
JOIN     orders o ON o.user_id = u.id      -- 1. с чем соединить
WHERE    o.status = 'paid'                 -- 2. какие строки оставить
GROUP BY u.country                         -- 3. как сгруппировать
HAVING   count(*) > 10                     -- 4. какие группы оставить
ORDER BY users DESC                        -- 6. как отсортировать
LIMIT    5;                                -- 7. сколько вернуть
```

Номера — логический порядок обработки. Поэтому:

```sql
SELECT price * 0.2 AS tax FROM orders WHERE tax > 100;          -- ✗ tax ещё не существует
SELECT price * 0.2 AS tax FROM orders WHERE price * 0.2 > 100;  -- ✓
SELECT price * 0.2 AS tax FROM orders ORDER BY tax;             -- ✓ ORDER BY после SELECT
```

## Почему не SELECT *

```sql
SELECT * FROM users;              -- удобно в консоли
SELECT id, email, name FROM users; -- в коде приложения
```

- Лишние данные по сети и в памяти (большие `text`, `jsonb`).
- Невозможен index-only scan.
- Добавление столбца в таблицу молча меняет ответ API, а в `JOIN` появляются конфликты имён.
- Утечка чувствительных полей (`password_hash`).

## DISTINCT и вычисления

```sql
SELECT DISTINCT country FROM users;
```

## Частые ошибки

- Использовать алиас из `SELECT` в `WHERE`.
- `SELECT *` в коде приложения.
- Ожидать порядок без `ORDER BY`.
- Скалярный подзапрос, возвращающий больше одной строки, — ошибка выполнения.

## Что важно помнить

- `SELECT` возвращает новый набор строк и не меняет данные.
- Логический порядок: `FROM` → `WHERE` → `GROUP BY` → `HAVING` → `SELECT` → `ORDER BY` → `LIMIT`.
- Явный список столбцов — стандарт для кода приложения.

## Мини-шпаргалка

- `SELECT выражения FROM источник`.
- `AS` — имя для столбца результата.
- Выражения, функции, подзапросы в списке выборки.
- Алиасы доступны в `ORDER BY`, но не в `WHERE`.
- Без `SELECT *` в приложении.
