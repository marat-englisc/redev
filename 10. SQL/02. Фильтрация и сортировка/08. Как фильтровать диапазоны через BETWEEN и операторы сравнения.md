# Как фильтровать диапазоны через BETWEEN и операторы сравнения

> [!NOTE]
> Диапазоны фильтруют операторами `>`, `>=`, `<`, `<=` или `BETWEEN a AND b`, который **включает обе границы** (`x >= a AND x <= b`). Для целых чисел `BETWEEN` удобен, а для **времени** почти всегда правильнее **полуоткрытый интервал** `x >= начало AND x < следующее_начало`: он не теряет события с дробными секундами в конце периода и без зазоров стыкуется с соседними периодами. Диапазонные условия по «чистому» столбцу эффективно используют B-tree индекс. В PostgreSQL есть и **range-типы** (`tstzrange`, `int4range`) с операторами пересечения — для бронирований и расписаний.

## Вопрос

Как правильно фильтровать по диапазонам значений и дат?

## BETWEEN

```sql
SELECT * FROM orders WHERE total BETWEEN 100 AND 500;   -- 100 и 500 включены
SELECT * FROM orders WHERE total NOT BETWEEN 100 AND 500;
```

Если перепутать границы (`BETWEEN 500 AND 100`), результат будет пустым. `BETWEEN SYMMETRIC` (PostgreSQL) сам упорядочит границы.

## Явные операторы

```sql
SELECT * FROM orders WHERE total >= 100 AND total < 500;
```

Так сразу видно, какая граница включена.

## Даты и время

```sql
-- ✗ BETWEEN с датами для timestamptz: '2026-08-31' = 31 августа 00:00:00
WHERE created_at BETWEEN '2026-08-01' AND '2026-08-31'
-- события 31 августа после полуночи потеряются

-- ✗ «конец дня» вручную: теряются 23:59:59.5
WHERE created_at BETWEEN '2026-08-01 00:00' AND '2026-08-31 23:59:59'

-- ✓ полуоткрытый интервал
WHERE created_at >= '2026-08-01' AND created_at < '2026-09-01'
```

Полуоткрытые интервалы складываются без пересечений: `[1 авг; 1 сен)` + `[1 сен; 1 окт)` — каждое событие ровно в одном периоде.

## Не оборачивайте столбец в функцию

```sql
-- ✗ индекс по created_at не используется
WHERE date_trunc('month', created_at) = '2026-08-01'
WHERE extract(year FROM created_at) = 2026

-- ✓ диапазон
WHERE created_at >= '2026-01-01' AND created_at < '2027-01-01'
```

## Сравнение кортежей

```sql
-- всё, что после позиции (created_at, id) — основа keyset-пагинации
WHERE (created_at, id) > ('2026-08-01 10:00', 123)
```

Сравнение строк-кортежей идёт лексикографически и может использовать составной индекс `(created_at, id)`.

## Range-типы (PostgreSQL)

```sql
CREATE TABLE bookings (
  room_id bigint,
  during  tstzrange NOT NULL,
  EXCLUDE USING gist (room_id WITH =, during WITH &&)  -- запрет пересекающихся бронирований
);

SELECT * FROM bookings WHERE during && tstzrange('2026-10-24 10:00', '2026-10-24 12:00');
```

`&&` — пересечение диапазонов, `@>` — содержит. Ограничение `EXCLUDE` (нужно расширение `btree_gist` для `room_id WITH =`) гарантирует отсутствие двойного бронирования на уровне базы.

## Частые ошибки

- `BETWEEN` с датами для столбцов со временем.
- «23:59:59» как конец дня.
- Функции над столбцом в условии диапазона.
- Перепутанные границы `BETWEEN`.

## Что важно помнить

- `BETWEEN` включает обе границы.
- Для времени — полуоткрытые интервалы `[start, end)`.
- Диапазон по «чистому» столбцу использует B-tree индекс.

## Мини-шпаргалка

- `x BETWEEN a AND b` = `x >= a AND x <= b`.
- Время: `>= start AND < next_start`.
- `(a, b) > (x, y)` — сравнение кортежей.
- `tstzrange`, `&&`, `EXCLUDE` — для интервалов.
