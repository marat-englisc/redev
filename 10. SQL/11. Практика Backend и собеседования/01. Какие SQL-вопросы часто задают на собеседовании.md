# Какие SQL-вопросы часто задают на собеседовании

> [!NOTE]
> SQL-собеседование для frontend/fullstack/backend разработчика обычно проверяет три слоя. **Язык запросов**: JOIN (особенно разница `INNER`/`LEFT` и ловушка с условием в `WHERE`), `GROUP BY`/`HAVING`, `NULL`-логика, подзапросы и `EXISTS`, оконные функции (top-N per group, накопительные суммы, вторая по величине зарплата). **Проектирование**: ключи и связи, нормализация, constraints, когда JSON, выбор PK. **Работа в продакшене**: индексы и `EXPLAIN`, транзакции, уровни изоляции, блокировки, lost update, N+1, пагинация, миграции без простоя, SQL-инъекции. Ниже — карта типичных вопросов со ссылками на уроки этого раздела для быстрого повторения.

## Как отвечать

- Сначала короткое определение, затем пример запроса, затем подводный камень («а вот с `NULL` будет…»).
- Называйте СУБД: «в PostgreSQL так, в MySQL иначе» — это показывает практический опыт.
- На вопросы о производительности отвечайте через измерение: «посмотрю `EXPLAIN ANALYZE`, проверю оценку строк».

## Частые ошибки

- Учить определения без умения написать запрос.
- Не знать поведения `NULL` в `NOT IN`, `count`, `avg`.
- Отвечать «добавлю индекс» без уточнения, какой и почему.

## Что важно помнить

- Проверяют язык, проектирование и эксплуатацию.
- Самые частые темы: JOIN, GROUP BY, окна, индексы, транзакции.
- Ответ = определение + пример + нюанс.

## Мини-шпаргалка

- JOIN + `NULL` + `GROUP BY` — база.
- `row_number` + `PARTITION BY` — top-N.
- Индекс: равенство → диапазон.
- Lost update → атомарный `UPDATE` или `FOR UPDATE`.
- Параметры вместо склейки строк.
