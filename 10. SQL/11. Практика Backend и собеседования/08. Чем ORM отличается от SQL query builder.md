# Чем ORM отличается от SQL query builder

> [!NOTE]
> Это три уровня абстракции над базой. **Сырой SQL** через драйвер (`pg`, `postgres.js`, `mysql2`) — полный контроль и все возможности СУБД, но типы результатов и сборку динамических запросов приходится делать самому. **Query builder** (Knex, Kysely, Drizzle в SQL-подобном API) строит SQL из вызовов функций: запрос остаётся «видимым» и близким к SQL, удобно собирать динамические фильтры, а Kysely и Drizzle дают строгую типизацию. **ORM** (Prisma, TypeORM, MikroORM, Sequelize) отображает таблицы на сущности/модели: связи, `include`, миграции, валидация схемы, иногда Unit of Work и change tracking — быстрая разработка CRUD ценой меньшего контроля над SQL и риска N+1 и неэффективных запросов. На практике сочетают: ORM или builder для обычных операций и сырой SQL (`$queryRaw`, `sql\`\``) для отчётов, оконных функций, `ON CONFLICT`, CTE.

## Вопрос

Чем отличаются ORM, query builder и сырой SQL и что выбрать?

## Один запрос тремя способами

```ts
// сырой SQL (node-postgres)
const { rows } = await db.query(
  `SELECT u.id, u.email, count(o.id)::int AS orders
   FROM users u LEFT JOIN orders o ON o.user_id = u.id
   WHERE u.created_at >= $1
   GROUP BY u.id ORDER BY orders DESC LIMIT 20`,
  [since],
);

// query builder (Kysely)
const rows = await db
  .selectFrom("users as u")
  .leftJoin("orders as o", "o.user_id", "u.id")
  .select(["u.id", "u.email", (eb) => eb.fn.count<number>("o.id").as("orders")])
  .where("u.created_at", ">=", since)
  .groupBy("u.id")
  .orderBy("orders", "desc")
  .limit(20)
  .execute();

// ORM (Prisma)
const users = await prisma.user.findMany({
  where: { createdAt: { gte: since } },
  select: { id: true, email: true, _count: { select: { orders: true } } },
  orderBy: { orders: { _count: "desc" } },
  take: 20,
});
```

## Сравнение

| | Сырой SQL | Query builder | ORM |
| --- | --- | --- | --- |
| Контроль над SQL | Полный | Высокий | Средний |
| Возможности СУБД (CTE, окна, `LATERAL`, `ON CONFLICT`) | Все | Большинство | Часть, остальное через raw |
| Типизация результата | Вручную / генераторы (pgTyped, sqlc) | Kysely, Drizzle — строгая | Генерируется из схемы |
| Динамические фильтры | Неудобно | Удобно | Удобно |
| Связи, вложенные объекты | Вручную | Вручную | `include`, `relations` |
| Миграции | Отдельный инструмент | Knex/Drizzle Kit | Встроены |
| Риск N+1 и тяжёлых запросов | Низкий | Низкий | Выше |
| Порог входа | Нужно знать SQL | SQL + API | Можно начать без глубокого SQL |

## Популярные инструменты в Node.js

| Инструмент | Тип | Особенность |
| --- | --- | --- |
| Prisma | ORM | Schema-first, генерация клиента, удобные связи |
| TypeORM | ORM | Декораторы, Active Record / Data Mapper, популярен с NestJS |
| MikroORM | ORM | Unit of Work, Identity Map |
| Drizzle | ORM-lite / builder | TS-схема, SQL-подобный API, лёгкий |
| Kysely | Query builder | Строгая типизация без генерации |
| Knex | Query builder | Классика, миграции, слабая типизация |

## Ловушки ORM

```ts
// N+1 при ленивой загрузке
for (const post of posts) await post.author;

// загрузка всего объекта ради одного поля
const user = await prisma.user.findUnique({ where: { id } });   // SELECT все столбцы
// ✓ select: { email: true }

// read-modify-write вместо атомарного обновления
const p = await repo.findOneBy({ id }); p.stock -= 1; await repo.save(p);
// ✓ prisma.product.update({ where: { id }, data: { stock: { decrement: 1 } } })
```

Включайте логирование SQL в разработке и смотрите, что реально уходит в базу.

## Как выбрать

- CRUD-приложение, быстрый старт, команда с разным уровнем SQL → ORM (Prisma, TypeORM).
- Много сложных и динамических запросов, важна типизация → Kysely или Drizzle.
- Отчёты, аналитика, тонкая оптимизация → сырой SQL рядом с любым из вариантов.

## Частые ошибки

- Считать, что ORM избавляет от необходимости знать SQL и индексы.
- Писать сложный отчёт через цепочку ORM-вызовов вместо одного SQL-запроса.
- `raw`-методы с конкатенацией строк — [SQL-инъекции](<07. Что такое SQL injection.md>).
- `synchronize: true` в продакшене вместо миграций.

## Что важно помнить

- Сырой SQL — контроль, builder — SQL с типами и композицией, ORM — модели и связи.
- ORM ускоряет CRUD, но требует контроля генерируемых запросов.
- Комбинирование подходов — норма.

## Мини-шпаргалка

- ORM: Prisma, TypeORM, MikroORM.
- Builder: Kysely, Knex, Drizzle.
- Raw: `pg`, `postgres.js`, `$queryRaw`.
- Логи SQL в dev — всегда.
