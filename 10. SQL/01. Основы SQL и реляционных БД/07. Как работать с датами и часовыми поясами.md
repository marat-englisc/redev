# Как работать с датами и часовыми поясами

> [!NOTE]
> Для моментов времени (создан, оплачен, вошёл) в PostgreSQL используют **`timestamptz`**: он хранит абсолютный момент в UTC и при выводе переводит его в часовой пояс сессии. `timestamp` без пояса — «часы на стене» без привязки ко времени на Земле, подходит только для локальных расписаний. `date` — календарная дата, `interval` — длительность. Правила: хранить `timestamptz`, отдавать клиенту в ISO 8601 с поясом, фильтровать **полуоткрытыми интервалами** (`>= начало AND < конец`), а «день», «неделю» и «месяц» для отчётов считать в часовом поясе бизнеса через `AT TIME ZONE`.

## Вопрос

Как правильно хранить и обрабатывать даты и часовые пояса в SQL?

## timestamp и timestamptz

```sql
SET TIME ZONE 'Europe/Moscow';

SELECT '2026-10-24 12:00:00+00'::timestamptz;   -- 2026-10-24 15:00:00+03 (тот же момент)
SELECT '2026-10-24 12:00:00+00'::timestamp;     -- 2026-10-24 12:00:00 (пояс отброшен!)
```

| | `timestamptz` | `timestamp` |
| --- | --- | --- |
| Что хранит | Абсолютный момент (UTC) | Дату и время без пояса |
| Вывод | В поясе сессии | Как есть |
| Для чего | События, логи, сроки | Локальное расписание («каждый день в 9:00 по местному») |

Название обманчиво: `timestamptz` не хранит сам пояс, только момент. Если пояс пользователя важен (например, для повторяющихся событий), его хранят отдельным столбцом: `timezone text` со значением `Europe/Moscow`.

## Текущее время

```sql
SELECT now();                 -- начало текущей транзакции (одинаково внутри транзакции)
SELECT clock_timestamp();     -- реальное текущее время
SELECT current_date;          -- дата в поясе сессии
```

## Арифметика и интервалы

```sql
SELECT now() + interval '7 days';
SELECT now() - interval '1 hour';
SELECT age(timestamptz '2026-10-24', timestamptz '1990-05-15');   -- 36 years 5 mons 9 days
SELECT extract(epoch FROM interval '2 hours');                     -- 7200
SELECT date_trunc('month', now());                                 -- начало месяца
```

## Фильтрация по периодам

```sql
-- ✓ полуоткрытый интервал: включает весь октябрь, работает с индексом
WHERE created_at >= timestamptz '2026-10-01 00:00 Europe/Moscow'
  AND created_at <  timestamptz '2026-11-01 00:00 Europe/Moscow'

-- ✗ теряет события после 00:00:00 31 октября
WHERE created_at BETWEEN '2026-10-01' AND '2026-10-31'

-- ✗ функция над столбцом мешает индексу
WHERE date(created_at) = '2026-10-24'
```

## Группировка по дням в поясе бизнеса

```sql
SELECT
  date_trunc('day', created_at AT TIME ZONE 'Europe/Moscow') AS day,
  count(*) AS orders
FROM orders
GROUP BY day
ORDER BY day;
```

`created_at AT TIME ZONE 'Europe/Moscow'` переводит момент в местное время Москвы, и `date_trunc` режет по московским суткам. Без этого заказ в 01:00 по Москве попадёт во «вчерашний» UTC-день.

## Взаимодействие с приложением

- Драйверы Node.js возвращают `timestamptz` как `Date` (UTC внутри) — сериализуйте в ISO 8601: `2026-10-24T12:00:00.000Z`.
- На клиенте форматируйте в поясе пользователя (`Intl.DateTimeFormat` с `timeZone`).
- Сравнивайте и вычисляйте даты в UTC, переводите в местное время только для отображения и бизнес-границ периодов.
- Переход на летнее/зимнее время делает сутки длиной 23 или 25 часов — `interval '1 day'` и `interval '24 hours'` в `timestamptz`-арифметике дают разное.

## Частые ошибки

- `timestamp` без пояса для событий — после переезда сервера в другой пояс данные «сдвигаются».
- `BETWEEN` с датами для `timestamp`-столбцов.
- Группировка по UTC-дням в отчёте для бизнеса в другом поясе.
- Хранить даты строками.
- Использовать смещение (`+03:00`) вместо имени пояса (`Europe/Moscow`) для будущих событий — правила перехода меняются.

## Что важно помнить

- Моменты времени — `timestamptz`, пояс пользователя — отдельно, если нужен.
- Фильтр по периоду — полуоткрытый интервал.
- Границы бизнес-периодов считают в поясе бизнеса через `AT TIME ZONE`.

## Мини-шпаргалка

- `timestamptz` для событий, `date` для дат, `interval` для длительностей.
- `now()` — начало транзакции, `clock_timestamp()` — реальное время.
- `>= start AND < end`.
- `date_trunc('day', ts AT TIME ZONE 'Europe/Moscow')`.
- Наружу — ISO 8601.
