# Что такое SQL

> [!NOTE]
> **SQL (Structured Query Language)** — декларативный язык для работы с реляционными базами данных: вы описываете, **какой результат** нужен, а СУБД сама выбирает, **как** его получить (какие индексы использовать, в каком порядке соединять таблицы). Команды делятся на группы: **DQL** (`SELECT`), **DML** (`INSERT`, `UPDATE`, `DELETE`), **DDL** (`CREATE`, `ALTER`, `DROP`), **TCL** (`BEGIN`, `COMMIT`, `ROLLBACK`) и **DCL** (`GRANT`, `REVOKE`). Есть стандарт SQL, но у каждой СУБД свой диалект — примеры в этом разделе даны для **PostgreSQL**.

## Вопрос

Что такое SQL и какие группы команд в нём есть?

## Основная идея

```sql
SELECT name, email
FROM users
WHERE is_active = true
ORDER BY created_at DESC
LIMIT 10;
```

Мы не пишем цикл по строкам и не выбираем индекс — только описываем набор данных. Как его получить, решает **планировщик** запросов: тот же запрос на маленькой таблице выполнится полным перебором, а на большой — через индекс.

Для сравнения то же на JavaScript:

```js
users
  .filter((u) => u.isActive)
  .sort((a, b) => b.createdAt - a.createdAt)
  .slice(0, 10)
  .map(({ name, email }) => ({ name, email }));
```

Здесь вы задаёте алгоритм. В SQL — только результат.

## Группы команд

| Группа | Назначение | Команды |
| --- | --- | --- |
| DQL | Чтение данных | `SELECT` |
| DML | Изменение данных | `INSERT`, `UPDATE`, `DELETE`, `MERGE` |
| DDL | Изменение структуры | `CREATE`, `ALTER`, `DROP`, `TRUNCATE` |
| TCL | Транзакции | `BEGIN`, `COMMIT`, `ROLLBACK`, `SAVEPOINT` |
| DCL | Права доступа | `GRANT`, `REVOKE` |

## Диалекты

| СУБД | Где встречается | Особенности |
| --- | --- | --- |
| PostgreSQL | Самая популярная open-source СУБД для веба | `jsonb`, `RETURNING`, `ILIKE`, богатые типы и индексы |
| MySQL / MariaDB | Классический веб, WordPress | `AUTO_INCREMENT`, `GROUP_CONCAT`, `ON DUPLICATE KEY UPDATE` |
| SQLite | Встраиваемая БД: мобильные, десктоп, тесты, edge (Turso, D1) | Файл вместо сервера, динамическая типизация |
| SQL Server, Oracle | Корпоративные системы | `TOP`, T-SQL, PL/SQL |

База языка общая, но функции, типы, синтаксис пагинации, upsert и JSON различаются.

## SQL для frontend-разработчика

- Next.js и Nuxt-приложения с собственным backend работают с PostgreSQL через ORM (Prisma, Drizzle) — понимать генерируемый SQL нужно для производительности.
- Supabase, Neon, Vercel Postgres — это PostgreSQL, и часть логики (политики доступа, функции) пишется на SQL.
- Аналитика и отчёты почти всегда требуют SQL.

## Частые ошибки

- Думать, что порядок строк без `ORDER BY` предсказуем.
- Переносить синтаксис из одной СУБД в другую без проверки.
- Считать ORM заменой знания SQL.

## Что важно помнить

- SQL декларативен: результат описываете вы, план выполнения выбирает СУБД.
- Запрос записывается начиная с `SELECT`, но логически выполняется начиная с `FROM` — см. [порядок выполнения](<../11. Практика Backend и собеседования/09. Каков логический порядок выполнения SQL-запроса.md>).
- Примеры всегда соотносят с диалектом.

## Мини-шпаргалка

- SQL — декларативный язык реляционных БД.
- DQL, DML, DDL, TCL, DCL.
- Диалекты: PostgreSQL, MySQL, SQLite.
- План выполнения выбирает оптимизатор.
