# Какие бывают типы данных SQL

> [!NOTE]
> Тип столбца определяет допустимые значения, операции, размер хранения и то, как работают индексы и сравнения. Базовые группы в PostgreSQL: **целые** (`integer`, `bigint`), **точные десятичные** (`numeric` — для денег), **с плавающей точкой** (`real`, `double precision` — для измерений), **строки** (`text`, `varchar(n)`), **дата и время** (`date`, `timestamptz`, `interval`), `boolean`, `uuid`, **JSON** (`jsonb`), массивы, `bytea`, перечисления (`enum`). Правила: деньги — `numeric` или целые копейки, время — `timestamptz`, идентификаторы — `bigint` или `uuid`, строки — `text` с `CHECK` вместо произвольного `varchar(255)`.

## Вопрос

Какие типы данных бывают в SQL и как их выбирать?

## Основные типы PostgreSQL

| Группа | Типы | Для чего |
| --- | --- | --- |
| Целые | `smallint`, `integer`, `bigint` | Счётчики, идентификаторы, количества |
| Точные десятичные | `numeric(p, s)` | Деньги, проценты, точные расчёты |
| С плавающей точкой | `real`, `double precision` | Измерения, координаты, научные данные |
| Строки | `text`, `varchar(n)`, `char(n)` | Имена, email, описания |
| Логический | `boolean` | Флаги |
| Дата и время | `date`, `time`, `timestamp`, `timestamptz`, `interval` | События, сроки, длительности |
| Идентификаторы | `uuid` | Глобально уникальные ключи |
| JSON | `json`, `jsonb` | Гибкие структуры, payload интеграций |
| Массивы | `text[]`, `integer[]` | Небольшие списки значений |
| Бинарные | `bytea` | Небольшие бинарные данные (файлы — в объектном хранилище) |
| Перечисления | `CREATE TYPE ... AS ENUM` | Фиксированный набор статусов |
| Сетевые, геометрия, диапазоны | `inet`, `point`, `tstzrange` | Специальные задачи |

## Деньги

```sql
price numeric(12, 2) NOT NULL       -- ✓ точное значение
price double precision              -- ✗ 0.1 + 0.2 = 0.30000000000000004
price_kopecks bigint NOT NULL       -- ✓ альтернатива: целое в минимальных единицах
```

Типа `money` в PostgreSQL лучше избегать: он зависит от настроек локали.

## Дата и время

```sql
created_at timestamptz NOT NULL DEFAULT now()   -- ✓ момент времени
birth_date date                                 -- ✓ календарная дата без времени
duration   interval                             -- ✓ длительность
```

`timestamptz` хранит абсолютный момент (внутри — UTC) и корректно переводит его в часовой пояс сессии; `timestamp` без пояса — просто «часы на стене», по нему нельзя понять, когда событие произошло. Подробнее — в уроке [о датах и часовых поясах](<07. Как работать с датами и часовыми поясами.md>).

## Строки

В PostgreSQL `text` и `varchar(n)` хранятся одинаково и одинаково быстры. Ограничение длины лучше задавать осмысленно:

```sql
username text NOT NULL CHECK (char_length(username) BETWEEN 3 AND 32)
```

`varchar(255)` «по привычке» из MySQL ничего не даёт. `char(n)` дополняет строку пробелами — почти никогда не нужен.

## Целые

| Тип | Диапазон |
| --- | --- |
| `integer` | ±2,1 млрд |
| `bigint` | ±9,2 × 10¹⁸ |

Для первичных ключей таблиц, которые могут расти, выбирают `bigint`: переполнение `integer` на живой таблице — болезненная миграция.

## Как тип влияет на работу

- Сравнение `'10' < '9'` для строк истинно (лексикографически), для чисел — нет.
- Индекс работает, если тип параметра совпадает с типом столбца.
- JSON-поля сложнее валидировать и индексировать, чем обычные столбцы.

## Частые ошибки

- `float` для денег.
- `timestamp` без часового пояса для событий.
- `integer` для ключа большой таблицы.
- Числа и даты в `text`.
- JSON вместо нормальных столбцов для часто используемых полей.

## Что важно помнить

- Тип — часть контракта данных и основа корректных сравнений и индексов.
- Деньги — `numeric` или целые минимальные единицы, время — `timestamptz`.
- В PostgreSQL `text` — нормальный выбор для строк.

## Мини-шпаргалка

- `bigint` или `uuid` — ключи.
- `numeric` — деньги, `double precision` — измерения.
- `text` + `CHECK` — строки.
- `timestamptz` — моменты, `date` — даты, `interval` — длительности.
- `jsonb` — гибкие данные, не основа модели.
