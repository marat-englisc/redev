# Что такое таблица, строка и столбец

> [!NOTE]
> **Таблица** — набор однотипных записей со схемой: именем, списком столбцов и ограничениями. **Строка** (row, кортеж) — одна запись, например один товар. **Столбец** (column, атрибут) — именованное свойство записи с **типом** данных, значением по умолчанию (`DEFAULT`) и ограничениями (`NOT NULL`, `CHECK`, `UNIQUE`). Порядок строк в таблице не определён — его задаёт только `ORDER BY` в запросе. Имена таблиц и столбцов отражают бизнес-смысл и следуют единому соглашению (обычно `snake_case`).

## Вопрос

Что такое таблица, строка и столбец в реляционной базе?

## Пример

```sql
CREATE TABLE products (
  id         bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  title      text NOT NULL,
  price      numeric(10, 2) NOT NULL CHECK (price >= 0),
  in_stock   boolean NOT NULL DEFAULT true,
  created_at timestamptz NOT NULL DEFAULT now()
);
```

| Элемент | Пример | Смысл |
| --- | --- | --- |
| Таблица | `products` | Все товары |
| Строка | Товар «Keychron K2» | Одна запись |
| Столбец | `price` | Свойство записи |
| Тип | `numeric(10, 2)` | Формат и допустимые операции |
| Значение по умолчанию | `DEFAULT true` | Подставляется, если не передано |
| Ограничение | `NOT NULL`, `CHECK` | Правило корректности |

## Строка как факт

```sql
INSERT INTO products (title, price)
VALUES ('Keychron K2', 9990.00)
RETURNING id, in_stock, created_at;
```

`in_stock` и `created_at` заполнились значениями по умолчанию, `id` — автоматически.

## Порядок строк

```sql
SELECT * FROM products;              -- порядок не гарантирован
SELECT * FROM products ORDER BY id;  -- гарантирован
```

Таблица — это множество, а не массив. Без `ORDER BY` СУБД вправе вернуть строки в любом порядке, и он может меняться после обновлений и между запусками.

## Именование

```sql
-- ✓ понятно
created_at timestamptz
user_id    bigint
is_active  boolean

-- ✗ непонятно
date1      timestamp
uid        int
flag       boolean
```

Соглашения: `snake_case`, таблицы во множественном числе (`users`) или в единственном — главное единообразие; внешние ключи — `<сущность>_id`, булевы — `is_`/`has_`, временные метки — `_at`. PostgreSQL приводит идентификаторы без кавычек к нижнему регистру, поэтому `CamelCase` потребует кавычек везде (`"UserId"`).

## Частые ошибки

- Ожидать порядок строк без `ORDER BY`.
- Использовать имена в `CamelCase` и потом писать кавычки в каждом запросе.
- Хранить несколько значений в одной ячейке.
- Не задавать `NOT NULL` для обязательных полей.

## Что важно помнить

- Схема таблицы — контракт для всех, кто пишет и читает данные.
- Тип и ограничения столбца — первая линия защиты корректности.
- Таблица не упорядочена: порядок — свойство запроса.

## Мини-шпаргалка

- Таблица — записи одного вида.
- Строка — запись, столбец — атрибут с типом.
- `DEFAULT`, `NOT NULL`, `CHECK`, `UNIQUE`.
- Порядок — только через `ORDER BY`.
- `snake_case`, понятные имена.
