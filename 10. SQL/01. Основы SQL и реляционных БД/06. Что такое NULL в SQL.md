# Что такое NULL в SQL

> [!NOTE]
> `NULL` — маркер **отсутствующего или неизвестного** значения. Это не `0`, не пустая строка и не `false`. Любое сравнение с `NULL` (`=`, `<>`, `>`) даёт не `true`/`false`, а **`UNKNOWN`** — SQL использует **трёхзначную логику**, а `WHERE` пропускает только строки с `true`. Поэтому проверяют через `IS NULL` / `IS NOT NULL` (или `IS DISTINCT FROM`), подставляют значения по умолчанию через `COALESCE`, а `NOT NULL` ставят везде, где значение обязательно. `NULL` влияет на агрегаты, `NOT IN`, `UNIQUE`, сортировку и `JOIN`.

## Вопрос

Что такое `NULL` и почему с ним нужно быть осторожным?

## Сравнение с NULL

```sql
SELECT * FROM users WHERE deleted_at = NULL;   -- ✗ всегда пусто: NULL = NULL → UNKNOWN
SELECT * FROM users WHERE deleted_at IS NULL;  -- ✓
```

```sql
SELECT NULL = NULL;      -- NULL (unknown)
SELECT NULL <> 1;        -- NULL
SELECT NULL + 10;        -- NULL: арифметика с NULL даёт NULL
SELECT 'a' || NULL;      -- NULL: конкатенация тоже
```

## Трёхзначная логика

| A | B | A AND B | A OR B |
| --- | --- | --- | --- |
| true | NULL | NULL | true |
| false | NULL | false | NULL |
| NULL | NULL | NULL | NULL |

`NOT NULL` (как выражение) — тоже `NULL`. Строка попадает в результат, только если условие `WHERE` равно `true`.

## Ловушка с отрицанием

```sql
-- статус NULL не попадёт ни в одну из выборок
SELECT * FROM orders WHERE status = 'paid';
SELECT * FROM orders WHERE status <> 'paid';
```

```sql
SELECT * FROM orders WHERE status IS DISTINCT FROM 'paid';  -- ✓ включает NULL
```

`IS DISTINCT FROM` / `IS NOT DISTINCT FROM` сравнивают, считая `NULL` обычным значением.

## Полезные функции

```sql
SELECT COALESCE(nickname, name, 'Без имени') AS display_name FROM users; -- первое не-NULL
SELECT NULLIF(discount, 0) FROM orders;      -- 0 → NULL (защита от деления на ноль)
SELECT total / NULLIF(quantity, 0) FROM items;
```

## NULL в других местах

| Где | Поведение |
| --- | --- |
| `COUNT(column)`, `SUM`, `AVG` | `NULL` игнорируются |
| `NOT IN (подзапрос с NULL)` | Возвращает пусто — используйте `NOT EXISTS` |
| `UNIQUE` | Несколько `NULL` допустимы (в PostgreSQL 15+ можно запретить: `UNIQUE NULLS NOT DISTINCT`) |
| `ORDER BY` | В PostgreSQL `NULL` больше любых значений: в конце при `ASC`; управляется `NULLS FIRST/LAST` |
| `JOIN ... ON a.x = b.x` | Строки с `NULL` не соединяются |
| `GROUP BY` | Все `NULL` попадают в одну группу |

## Когда NULL уместен

- Значение необязательно или ещё неизвестно: `deleted_at`, `middle_name`, `paid_at`.
- Внешний ключ необязательной связи.

Когда значение обязательно по смыслу — `NOT NULL` и, при необходимости, `DEFAULT`. Меньше `NULL` — меньше неожиданных багов.

## Частые ошибки

- `= NULL` вместо `IS NULL`.
- `NOT IN` с подзапросом, который может вернуть `NULL`.
- Забыть, что `status <> 'paid'` не включает `NULL`.
- `SUM` по пустому набору возвращает `NULL`, а не `0` — нужен `COALESCE(SUM(x), 0)`.

## Что важно помнить

- `NULL` — «неизвестно», любое сравнение с ним — `UNKNOWN`.
- `WHERE` пропускает только `true`.
- `NOT NULL` по умолчанию для обязательных полей.

## Мини-шпаргалка

- `IS NULL`, `IS NOT NULL`, `IS DISTINCT FROM`.
- `COALESCE(a, b, default)`, `NULLIF(a, b)`.
- `NOT EXISTS` вместо `NOT IN`.
- `NULLS FIRST/LAST` в сортировке.
- `COALESCE(SUM(x), 0)`.
