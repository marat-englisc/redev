# Чем SQL-базы отличаются от NoSQL

> [!NOTE]
> **Реляционные (SQL) БД** — PostgreSQL, MySQL, SQLite — хранят данные в таблицах со строгой схемой, связывают их ключами, дают произвольные запросы с `JOIN`, сильные гарантии целостности и ACID-транзакции. **NoSQL** — общее название других моделей: **документные** (MongoDB), **ключ-значение** (Redis, DynamoDB), **колоночные** (Cassandra, ClickHouse как аналитическая), **графовые** (Neo4j), **поисковые** (Elasticsearch). Они оптимизированы под конкретные шаблоны доступа и горизонтальное масштабирование, часто ценой гибкости запросов и гарантий. Для большинства веб-приложений разумный выбор по умолчанию — PostgreSQL, а NoSQL добавляют под конкретные задачи (кэш, поиск, очереди, аналитика).

## Вопрос

Чем SQL-базы отличаются от NoSQL и когда что выбирать?

## Модели данных

| Модель | Примеры | Сильная сторона | Типичная задача |
| --- | --- | --- | --- |
| Реляционная | PostgreSQL, MySQL, SQLite | Целостность, JOIN, транзакции, гибкие запросы | Пользователи, заказы, платежи, большинство бизнес-данных |
| Документная | MongoDB, Firestore | Вложенные документы, гибкая схема | Каталоги с разнородными атрибутами, контент |
| Ключ-значение | Redis, Memcached, DynamoDB | Сверхбыстрый доступ по ключу | Кэш, сессии, rate limiting, очереди |
| Колоночная / аналитическая | ClickHouse, BigQuery | Агрегации по миллиардам строк | Аналитика, логи, метрики |
| Широкие столбцы | Cassandra, ScyllaDB | Огромные объёмы записи, распределённость | IoT, телеметрия, ленты событий |
| Графовая | Neo4j | Обход связей | Соцграфы, рекомендации |
| Поисковая | Elasticsearch, Meilisearch | Полнотекстовый поиск, релевантность | Поиск по каталогу и документам |

## Ключевые различия

| | SQL | NoSQL (обобщённо) |
| --- | --- | --- |
| Схема | Строгая, задаётся заранее | Гибкая или отсутствует (schema-on-read) |
| Связи | `JOIN`, внешние ключи | Вложенность, денормализация, связи в коде |
| Запросы | Произвольные, декларативные | Оптимизированы под заранее известные шаблоны |
| Транзакции | ACID по умолчанию | Часто ограниченные (в пределах документа или ключа) |
| Масштабирование | Вертикальное + реплики; шардирование сложнее | Горизонтальное «из коробки» |
| Консистентность | Сильная | Часто eventual (настраивается) |

## Один и тот же заказ

```sql
-- SQL: нормализованные таблицы
SELECT o.id, u.email, p.title, i.quantity
FROM orders o
JOIN users u ON u.id = o.user_id
JOIN order_items i ON i.order_id = o.id
JOIN products p ON p.id = i.product_id
WHERE o.id = 42;
```

```json
// MongoDB: документ со вложенными данными
{
  "_id": 42,
  "user": { "id": 1, "email": "anna@x.com" },
  "items": [{ "productId": 7, "title": "Keychron K2", "quantity": 1 }]
}
```

Документ читается одним обращением, но email пользователя и название товара скопированы — при их изменении нужно обновлять все документы.

## Границы стираются

- PostgreSQL умеет `jsonb` с индексами, полнотекстовый поиск, геоданные (PostGIS), векторы (pgvector) — часто это избавляет от отдельной NoSQL-базы.
- MongoDB поддерживает многодокументные транзакции и схемы валидации.
- Distributed SQL (CockroachDB, YugabyteDB, Spanner) дают горизонтальное масштабирование с SQL и ACID.

## Как выбирать

- По умолчанию для бизнес-данных — PostgreSQL.
- Кэш, сессии, счётчики, очереди — Redis.
- Поиск с опечатками и фасетами — Elasticsearch/Meilisearch поверх основной БД.
- Аналитика на миллиардах событий — ClickHouse.
- Документная БД — когда данные действительно документные и почти не связаны между собой.

## Частые ошибки

- Выбирать MongoDB «потому что не нужно думать о схеме» — схема всё равно появится, но в коде и неявно.
- Отказываться от SQL из-за мифа о плохом масштабировании — PostgreSQL обслуживает очень большие нагрузки.
- Использовать Redis как основное хранилище без понимания модели персистентности.

## Что важно помнить

- NoSQL — не «лучше» и не «новее», а разные модели под разные шаблоны доступа.
- Реальные системы обычно комбинируют несколько хранилищ (polyglot persistence).
- Выбор определяется связями данных, требованиями к консистентности и шаблонами запросов.

## Мини-шпаргалка

- SQL: схема, JOIN, ACID, гибкие запросы.
- NoSQL: документ, ключ-значение, колонки, граф, поиск.
- По умолчанию — PostgreSQL, плюс Redis и поиск по необходимости.
- `jsonb` закрывает многие «документные» задачи.
