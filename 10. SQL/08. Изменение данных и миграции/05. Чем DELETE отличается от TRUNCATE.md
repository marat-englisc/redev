# Чем DELETE отличается от TRUNCATE

> [!NOTE]
> `DELETE` удаляет строки **по одной** (можно с `WHERE`), для каждой создаёт запись в WAL, вызывает построчные триггеры и проверяет внешние ключи; место освобождается позже через `VACUUM`. `TRUNCATE` мгновенно очищает **всю таблицу**, заменяя её файлы новыми пустыми: без `WHERE`, без построчных триггеров (есть только `ON TRUNCATE`), место возвращается сразу. В PostgreSQL `TRUNCATE` **транзакционный** — его можно откатить `ROLLBACK`, но он берёт `ACCESS EXCLUSIVE` блокировку (никто не может даже читать таблицу до конца транзакции). Если на таблицу ссылаются FK, нужен `TRUNCATE … CASCADE` (очистит и ссылающиеся таблицы) — опасная операция. `RESTART IDENTITY` сбрасывает счётчики identity/sequence.

## Вопрос

Чем отличаются `DELETE` и `TRUNCATE`?

## Сравнение

| | `DELETE` | `TRUNCATE` |
| --- | --- | --- |
| `WHERE` | Да | Нет — только вся таблица |
| Скорость на больших таблицах | Медленно, пропорционально числу строк | Мгновенно |
| Построчные триггеры | Срабатывают | Нет (только `ON TRUNCATE`) |
| Освобождение места | После `VACUUM` | Сразу |
| Откат в транзакции (PostgreSQL) | Да | Да |
| Блокировка | `ROW EXCLUSIVE` — чтение и запись других строк не блокируются | `ACCESS EXCLUSIVE` — блокирует всё |
| Таблица, на которую ссылаются FK | Проверяет FK построчно | Ошибка без `CASCADE` |
| Сброс identity | Нет | `RESTART IDENTITY` |
| `RETURNING` | Да | Нет |

## Примеры

```sql
DELETE FROM sessions WHERE expires_at < now();   -- выборочно

TRUNCATE TABLE import_staging;                   -- очистить промежуточную таблицу
TRUNCATE TABLE import_staging RESTART IDENTITY;  -- и сбросить счётчик id
TRUNCATE orders, order_items;                    -- несколько таблиц сразу
```

## Транзакционность в PostgreSQL

```sql
BEGIN;
TRUNCATE import_staging;
-- ... загрузили новые данные, что-то пошло не так
ROLLBACK;     -- старые данные на месте
```

В MySQL (InnoDB) `TRUNCATE` вызывает неявный `COMMIT` и не откатывается — частая путаница на собеседованиях.

## TRUNCATE и FK

```sql
TRUNCATE users;
-- ERROR: cannot truncate a table referenced in a foreign key constraint

TRUNCATE users CASCADE;   -- очистит ВСЕ таблицы, ссылающиеся на users (orders, payments...)
```

## Когда что

| Задача | Команда |
| --- | --- |
| Удалить часть строк | `DELETE` |
| Очистить staging/temp таблицу перед загрузкой | `TRUNCATE` |
| Сбросить тестовую БД между тестами | `TRUNCATE ... RESTART IDENTITY CASCADE` |
| Удалить старые данные из большой таблицы журналов | Партиции + `DROP`/`DETACH` |
| Нужен аудит удалений через триггеры | `DELETE` |

## Частые ошибки

- `TRUNCATE` в проде на таблице, которую активно читают, — все запросы встанут в очередь за блокировкой.
- `CASCADE` без понимания, какие таблицы будут очищены.
- Ожидать срабатывания `AFTER DELETE` триггеров при `TRUNCATE`.
- Думать, что `TRUNCATE` нельзя откатить в PostgreSQL.

## Что важно помнить

- `DELETE` — построчно, выборочно, с триггерами.
- `TRUNCATE` — вся таблица, мгновенно, с жёсткой блокировкой.
- В PostgreSQL обе операции транзакционны.

## Мини-шпаргалка

- `DELETE FROM t WHERE ...`.
- `TRUNCATE t [RESTART IDENTITY] [CASCADE]`.
- `TRUNCATE` = `ACCESS EXCLUSIVE`.
