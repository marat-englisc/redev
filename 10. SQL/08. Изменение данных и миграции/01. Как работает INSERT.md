# Как работает INSERT

> [!NOTE]
> `INSERT INTO таблица (столбцы) VALUES (...)` добавляет строки. Столбцы перечисляют **явно** — так запрос не сломается при изменении порядка или добавлении столбцов, а пропущенные получат `DEFAULT` (или `NULL`). Можно вставить несколько строк одним `VALUES`, результат `SELECT` (`INSERT … SELECT`), а в PostgreSQL — сразу получить сгенерированные значения через `RETURNING` (id, `created_at`). Для массовой загрузки один многострочный `INSERT` или `COPY` в десятки раз быстрее цикла по одной строке. При конфликте уникальности помогает `ON CONFLICT` ([UPSERT](<03. Что такое UPSERT.md>)). Значения передают только параметрами.

## Вопрос

Как работает `INSERT` и как быстро вставлять много строк?

## Базовая вставка

```sql
INSERT INTO users (email, name)
VALUES ('anna@x.com', 'Anna')
RETURNING id, created_at;
```

`RETURNING` избавляет от второго запроса «получить id только что вставленной строки».

## Несколько строк

```sql
INSERT INTO tags (name)
VALUES ('sql'), ('postgres'), ('indexes');
```

## INSERT ... SELECT

```sql
-- скопировать подходящие строки
INSERT INTO orders_archive (id, user_id, total, created_at)
SELECT id, user_id, total, created_at
FROM orders
WHERE created_at < '2024-01-01';
```

## DEFAULT

```sql
INSERT INTO orders (user_id, total) VALUES (1, 500);            -- status, created_at — по DEFAULT
INSERT INTO orders (user_id, total, status) VALUES (1, 500, DEFAULT);
INSERT INTO audit_events DEFAULT VALUES;                         -- все столбцы по умолчанию
```

## Массовая вставка из приложения

```ts
// ✗ N запросов и N сетевых round-trip
for (const p of products) await db.query("INSERT INTO products (sku, title) VALUES ($1, $2)", [p.sku, p.title]);

// ✓ один запрос через массивы (PostgreSQL)
await db.query(
  `INSERT INTO products (sku, title)
   SELECT * FROM unnest($1::text[], $2::text[])`,
  [products.map((p) => p.sku), products.map((p) => p.title)],
);
```

Многострочные `VALUES` тоже работают, но число параметров в одном запросе ограничено (65 535 в протоколе PostgreSQL) — большие объёмы бьют на пачки по 500–5000 строк.

## COPY

```sql
COPY products (sku, title, price) FROM '/data/products.csv' WITH (FORMAT csv, HEADER true);
-- из psql с клиентской машины
\copy products (sku, title, price) FROM 'products.csv' WITH (FORMAT csv, HEADER true)
```

`COPY` — самый быстрый способ загрузки миллионов строк; драйверы (`pg-copy-streams`, `psycopg`) поддерживают его из кода.

## Вставка и транзакции

```sql
BEGIN;
INSERT INTO orders (user_id, total) VALUES (1, 800) RETURNING id;   -- допустим, 42
INSERT INTO order_items (order_id, product_id, qty, unit_price) VALUES (42, 7, 2, 400);
COMMIT;
```

Заказ и позиции — атомарно: либо всё, либо ничего. В одном запросе это делают через CTE: `WITH o AS (INSERT ... RETURNING id) INSERT INTO order_items SELECT o.id, ... FROM o`.

## Частые ошибки

- `INSERT INTO t VALUES (...)` без списка столбцов.
- Вставка в цикле по одной строке.
- Повторный `SELECT max(id)` вместо `RETURNING` — гонка с параллельными вставками.
- Склейка значений в SQL-строку вместо параметров.

## Что важно помнить

- Всегда перечисляйте столбцы.
- `RETURNING` возвращает сгенерированные значения.
- Для объёмов — многострочный `INSERT`, `unnest` или `COPY`.

## Мини-шпаргалка

- `INSERT INTO t (a, b) VALUES (...), (...) RETURNING id`.
- `INSERT INTO t (...) SELECT ...`.
- `unnest($1::text[], ...)` — пачка из приложения.
- `COPY ... FROM ... (FORMAT csv)`.
