# Чем отличаются UNION и UNION ALL

> [!NOTE]
> `UNION` и `UNION ALL` объединяют результаты нескольких запросов **по вертикали** (строки одного под строками другого). `UNION ALL` просто склеивает наборы, сохраняя все строки, включая повторы, — это быстро. `UNION` дополнительно **удаляет дубли** во всём результате, что требует сортировки или хеширования. Поэтому по умолчанию используют `UNION ALL`, а `UNION` — только когда дубли действительно нужно убрать. Требования: одинаковое число столбцов, совместимые типы по позициям; имена столбцов берутся из первого запроса. `ORDER BY` и `LIMIT` применяются ко всему результату и ставятся в конце.

## Вопрос

Чем отличаются `UNION` и `UNION ALL`?

## Пример

```sql
SELECT email FROM customers
UNION ALL
SELECT email FROM newsletter_subscribers;
-- anna@x.com, ivan@x.com, anna@x.com   ← дубль сохранён

SELECT email FROM customers
UNION
SELECT email FROM newsletter_subscribers;
-- anna@x.com, ivan@x.com
```

## Сравнение

| | `UNION ALL` | `UNION` |
| --- | --- | --- |
| Дубли | Сохраняет | Удаляет |
| Стоимость | Минимальная | Сортировка или хеш всего результата |
| Когда | Наборы не пересекаются или дубли важны | Нужен список уникальных значений |

## Лента событий из разных таблиц

```sql
SELECT 'order'   AS kind, id, created_at, total::text AS info FROM orders  WHERE user_id = $1
UNION ALL
SELECT 'review'  AS kind, id, created_at, left(body, 50)      FROM reviews WHERE user_id = $1
UNION ALL
SELECT 'ticket'  AS kind, id, created_at, subject             FROM tickets WHERE user_id = $1
ORDER BY created_at DESC
LIMIT 20;
```

Столбец-дискриминатор `kind` помогает различать источники; `UNION` здесь не нужен — строки разных таблиц и так различаются.

## Правила

```sql
-- ✗ разное число столбцов
SELECT id, email FROM users UNION ALL SELECT id FROM admins;

-- ✗ несовместимые типы
SELECT id FROM users UNION ALL SELECT email FROM admins;

-- ORDER BY для отдельной части — в скобках
(SELECT id, created_at FROM orders ORDER BY created_at DESC LIMIT 5)
UNION ALL
(SELECT id, created_at FROM refunds ORDER BY created_at DESC LIMIT 5);
```

## UNION как замена OR

```sql
-- иногда OR по разным столбцам мешает использовать индексы
SELECT * FROM users WHERE email = $1 OR phone = $2;

-- каждая ветка — свой индекс
SELECT * FROM users WHERE email = $1
UNION
SELECT * FROM users WHERE phone = $2;
```

PostgreSQL часто сам справляется через `BitmapOr`, но приём полезно знать.

## Частые ошибки

- `UNION` «по привычке» там, где дублей быть не может.
- Ожидать, что `UNION` уберёт дубли только между запросами — он убирает их и внутри каждого.
- Несовпадающий порядок столбцов (значения окажутся «не в тех» колонках).
- `ORDER BY` в середине без скобок.

## Что важно помнить

- `UNION ALL` — склеить, `UNION` — склеить и убрать дубли.
- По умолчанию — `UNION ALL`.
- Столбцы сопоставляются по позиции, имена — из первого запроса.

## Мини-шпаргалка

- `q1 UNION ALL q2`.
- `q1 UNION q2` — уникальные строки.
- Одинаковое число и типы столбцов.
- `ORDER BY` / `LIMIT` — в конце или в скобках.
