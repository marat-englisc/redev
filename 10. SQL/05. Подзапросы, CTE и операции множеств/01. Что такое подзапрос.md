# Что такое подзапрос

> [!NOTE]
> **Подзапрос** — `SELECT` внутри другого запроса. По результату бывают: **скалярный** (одна строка, один столбец — можно использовать как значение), **табличный** (набор строк в `FROM`, нужен алиас) и **подзапрос-условие** (`IN`, `EXISTS`, `ANY`/`ALL`). По зависимости: **некоррелированный** вычисляется один раз, **коррелированный** ссылается на столбцы внешнего запроса и логически выполняется для каждой его строки. Современные планировщики часто переписывают подзапросы в соединения, поэтому выбор формы — прежде всего вопрос читаемости, но коррелированный подзапрос без индекса на больших данных может быть дорогим.

## Вопрос

Что такое подзапрос и какие виды подзапросов бывают?

## Скалярный подзапрос

```sql
-- заказы дороже среднего
SELECT id, total
FROM orders
WHERE total > (SELECT avg(total) FROM orders);

-- в списке выборки
SELECT u.id, u.email,
       (SELECT count(*) FROM orders o WHERE o.user_id = u.id) AS orders_count
FROM users u;
```

Если скалярный подзапрос вернёт больше одной строки — ошибка, если ни одной — `NULL`.

## Подзапрос в FROM (derived table)

```sql
SELECT s.user_id, s.revenue
FROM (
  SELECT user_id, sum(total) AS revenue
  FROM orders
  GROUP BY user_id
) AS s
WHERE s.revenue > 10000;
```

## Подзапрос в условии

```sql
SELECT * FROM products
WHERE category_id IN (SELECT id FROM categories WHERE is_active);

SELECT * FROM users u
WHERE EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id);

SELECT * FROM products
WHERE price > ALL (SELECT price FROM products WHERE category_id = 5);  -- дороже всех в категории 5
```

## Коррелированный и некоррелированный

| | Некоррелированный | Коррелированный |
| --- | --- | --- |
| Зависит от внешней строки | Нет | Да |
| Логически выполняется | Один раз | Для каждой внешней строки |
| Пример | `WHERE total > (SELECT avg(total) FROM orders)` | `WHERE total > (SELECT avg(total) FROM orders o2 WHERE o2.user_id = o.user_id)` |

```sql
-- заказы дороже среднего чека ЭТОГО пользователя
SELECT o.*
FROM orders o
WHERE o.total > (SELECT avg(o2.total) FROM orders o2 WHERE o2.user_id = o.user_id);

-- часто то же, но эффективнее, через окно
SELECT * FROM (
  SELECT o.*, avg(total) OVER (PARTITION BY user_id) AS user_avg FROM orders o
) t
WHERE total > user_avg;
```

## Подзапрос, CTE или JOIN

| Задача | Удобная форма |
| --- | --- |
| Одно значение для сравнения | Скалярный подзапрос |
| Проверка наличия | `EXISTS` |
| Промежуточный результат, используемый несколько раз или в цепочке | [CTE](<03. Что такое CTE.md>) |
| Нужны столбцы обеих таблиц | `JOIN` |
| Top-N для каждой строки | [LATERAL](<../03. JOIN и связи таблиц/09. Что такое LATERAL JOIN.md>) |

## Частые ошибки

- Скалярный подзапрос, который иногда возвращает несколько строк.
- `NOT IN (подзапрос)` при возможных `NULL` — пустой результат.
- Коррелированный подзапрос в `SELECT` для тысяч строк без индекса.
- Вложенность в 4–5 уровней вместо CTE.

## Что важно помнить

- Подзапрос может быть значением, таблицей или условием.
- Коррелированный подзапрос зависит от внешней строки.
- Читаемость важнее: сложное — в CTE, наличие — в `EXISTS`.

## Мини-шпаргалка

- `(SELECT agg ...)` — скаляр.
- `FROM (SELECT ...) AS t` — алиас обязателен.
- `IN`, `EXISTS`, `ANY`, `ALL`.
- Коррелированный: ссылка на внешний алиас.
