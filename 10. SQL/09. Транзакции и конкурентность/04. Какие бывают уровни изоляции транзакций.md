# Какие бывают уровни изоляции транзакций

> [!NOTE]
> Стандарт SQL определяет четыре уровня изоляции по тому, какие аномалии они допускают: **Read Uncommitted**, **Read Committed**, **Repeatable Read**, **Serializable**. В PostgreSQL: Read Uncommitted фактически работает как **Read Committed** (грязного чтения нет вообще); **Read Committed** (по умолчанию) — каждый оператор видит данные, зафиксированные к его началу; **Repeatable Read** — вся транзакция видит один снимок на момент первого запроса, при этом в PostgreSQL он защищает и от фантомов, а при конфликте записи выдаёт ошибку сериализации; **Serializable** — результат как при последовательном выполнении, реализован через SSI и может откатывать транзакции с ошибкой `40001`. На уровнях выше Read Committed приложение **обязано уметь повторять** транзакцию.

## Вопрос

Какие бывают уровни изоляции транзакций и чем они отличаются в PostgreSQL?

## Таблица аномалий (стандарт)

| Уровень | Dirty read | Non-repeatable read | Phantom read | Serialization anomaly |
| --- | --- | --- | --- | --- |
| Read Uncommitted | Возможно | Возможно | Возможно | Возможно |
| Read Committed | Нет | Возможно | Возможно | Возможно |
| Repeatable Read | Нет | Нет | Возможно | Возможно |
| Serializable | Нет | Нет | Нет | Нет |

## В PostgreSQL

| Уровень | Фактическое поведение |
| --- | --- |
| Read Uncommitted | = Read Committed |
| Read Committed | Новый снимок для каждого оператора |
| Repeatable Read | Один снимок на транзакцию; фантомов нет; конкурентное изменение той же строки → ошибка `40001` |
| Serializable | Repeatable Read + отслеживание зависимостей чтения/записи (SSI) → откат при опасных пересечениях |

Подробно об аномалиях — в уроке [аномалии чтения](<05. Какие бывают аномалии чтения.md>).

## Установка уровня

```sql
BEGIN ISOLATION LEVEL REPEATABLE READ;
-- ...
COMMIT;

SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;  -- первой командой внутри транзакции
SHOW transaction_isolation;
```

## Read Committed: разные данные в одной транзакции

```sql
-- T1
BEGIN;
SELECT sum(balance) FROM accounts;      -- 1000
                                         -- T2: UPDATE accounts ... ; COMMIT;
SELECT sum(balance) FROM accounts;      -- 1200 — другое значение в той же транзакции
COMMIT;
```

Для отчёта, состоящего из нескольких запросов, нужен согласованный снимок — `REPEATABLE READ` (часто `READ ONLY`).

## Repeatable Read: ошибка при конфликте

```sql
-- T1                                       -- T2
BEGIN ISOLATION LEVEL REPEATABLE READ;      BEGIN ISOLATION LEVEL REPEATABLE READ;
SELECT stock FROM products WHERE id = 1;    UPDATE products SET stock = stock - 1 WHERE id = 1;
                                            COMMIT;
UPDATE products SET stock = stock - 1 WHERE id = 1;
-- ERROR: could not serialize access due to concurrent update
```

## Serializable: write skew

```sql
-- правило: хотя бы один врач на дежурстве
-- T1: SELECT count(*) FROM doctors WHERE on_call;  → 2;  UPDATE doctors SET on_call = false WHERE id = 1;
-- T2: SELECT count(*) FROM doctors WHERE on_call;  → 2;  UPDATE doctors SET on_call = false WHERE id = 2;
-- Repeatable Read: обе зафиксируются → никого на дежурстве
-- Serializable: одна получит 40001
```

## Повтор транзакции

```ts
async function withRetry<T>(fn: () => Promise<T>, attempts = 3): Promise<T> {
  for (let i = 1; ; i++) {
    try {
      return await fn();
    } catch (e: any) {
      if ((e.code === "40001" || e.code === "40P01") && i < attempts) continue;  // serialization / deadlock
      throw e;
    }
  }
}
```

## Что выбрать

| Задача | Уровень |
| --- | --- |
| Обычные CRUD-операции, атомарные `UPDATE` | Read Committed |
| Согласованный отчёт из нескольких запросов, бэкап (`pg_dump`) | Repeatable Read |
| Сложные инварианты между строками без явных блокировок | Serializable + retry |

## Частые ошибки

- Ожидать, что `READ UNCOMMITTED` в PostgreSQL покажет незафиксированные данные.
- Повышать уровень без кода повтора транзакции.
- Думать, что Read Committed защищает от lost update при read-modify-write.
- Путать поведение MySQL InnoDB (по умолчанию Repeatable Read с next-key locks) и PostgreSQL.

## Что важно помнить

- По умолчанию в PostgreSQL — Read Committed.
- Repeatable Read в PostgreSQL — снимок на всю транзакцию и без фантомов.
- Serializable требует повторов при ошибке `40001`.

## Мини-шпаргалка

- `BEGIN ISOLATION LEVEL REPEATABLE READ | SERIALIZABLE`.
- `40001` — serialization failure → повторить.
- `40P01` — deadlock → повторить.
- Отчёты — `REPEATABLE READ READ ONLY`.
