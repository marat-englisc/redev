# Какие бывают аномалии чтения

> [!NOTE]
> **Аномалии** — эффекты параллельного выполнения транзакций, которых не было бы при последовательном. **Dirty read** — чтение незафиксированных изменений другой транзакции (в PostgreSQL невозможно). **Non-repeatable read** — повторное чтение той же строки даёт другое значение, потому что её изменили и зафиксировали. **Phantom read** — повторный запрос с тем же условием возвращает другой **набор** строк (появились или исчезли строки). **Lost update** — два read-modify-write перезаписывают друг друга. **Write skew** — две транзакции читают пересекающиеся данные и меняют **разные** строки, нарушая общий инвариант. **Read skew** — несогласованное чтение связанных данных в разные моменты. Уровни изоляции различаются тем, какие аномалии они исключают.

## Вопрос

Какие бывают аномалии параллельных транзакций?

## Dirty read

```text
T1: UPDATE accounts SET balance = 0 WHERE id = 1;   (не зафиксировано)
T2: SELECT balance FROM accounts WHERE id = 1;      → 0  (грязное чтение)
T1: ROLLBACK;                                        T2 работал с несуществующими данными
```

В PostgreSQL невозможно ни на одном уровне.

## Non-repeatable read

```text
T1: SELECT price FROM products WHERE id = 1;   → 100
T2: UPDATE products SET price = 120 WHERE id = 1; COMMIT;
T1: SELECT price FROM products WHERE id = 1;   → 120   (Read Committed)
```

## Phantom read

```text
T1: SELECT count(*) FROM orders WHERE status = 'new';   → 10
T2: INSERT INTO orders (..., status) VALUES (..., 'new'); COMMIT;
T1: SELECT count(*) FROM orders WHERE status = 'new';   → 11
```

## Lost update

```text
T1: SELECT stock → 5            T2: SELECT stock → 5
T1: UPDATE SET stock = 4        T2: UPDATE SET stock = 4
итог: 4 вместо 3
```

Подробно — в уроке [lost update](<09. Что такое lost update.md>).

## Write skew

```text
инвариант: хотя бы один врач на дежурстве (сейчас двое)
T1: SELECT count(*) WHERE on_call → 2 → UPDATE doctor 1 SET on_call = false
T2: SELECT count(*) WHERE on_call → 2 → UPDATE doctor 2 SET on_call = false
итог: 0 дежурных
```

Каждая транзакция меняет свою строку, поэтому конфликт записи не возникает — защищает только `SERIALIZABLE` или явная блокировка (`SELECT ... FOR UPDATE` проверяемых строк).

## Read skew

```text
T1: SELECT balance FROM accounts WHERE id = 1;   → 500
T2: перевод 100 со счёта 1 на счёт 2; COMMIT;
T1: SELECT balance FROM accounts WHERE id = 2;   → 600 (уже после перевода)
сумма в отчёте: 1100 вместо 1000
```

## Какие уровни что исключают (PostgreSQL)

| Аномалия | Read Committed | Repeatable Read | Serializable |
| --- | --- | --- | --- |
| Dirty read | Нет | Нет | Нет |
| Non-repeatable read | Да | Нет | Нет |
| Phantom read | Да | Нет | Нет |
| Read skew | Да | Нет | Нет |
| Lost update | Да (при read-modify-write) | Нет — ошибка `40001` | Нет |
| Write skew | Да | Да | Нет |

## Способы защиты

| Аномалия | Решение |
| --- | --- |
| Lost update | Атомарный `UPDATE ... SET x = x - 1`, `FOR UPDATE`, версия строки |
| Write skew | `SERIALIZABLE`, `FOR UPDATE` проверяемых строк, ограничение в БД |
| Read skew в отчётах | `REPEATABLE READ` или один запрос |

## Частые ошибки

- Считать, что транзакция сама по себе защищает от всех аномалий.
- Не знать о write skew — он проходит даже на Repeatable Read.
- Повышать изоляцию без механизма повторов.

## Что важно помнить

- Dirty read в PostgreSQL отсутствует.
- Read Committed допускает non-repeatable, phantom, lost update и write skew.
- Write skew исключает только Serializable или явные блокировки.

## Мини-шпаргалка

- Dirty — чужое незафиксированное.
- Non-repeatable — изменилась строка.
- Phantom — изменился набор строк.
- Lost update — перезапись.
- Write skew — разные строки, общий инвариант.
