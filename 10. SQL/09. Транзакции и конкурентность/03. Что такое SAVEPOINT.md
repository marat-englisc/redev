# Что такое SAVEPOINT

> [!NOTE]
> `SAVEPOINT name` создаёт **точку сохранения** внутри транзакции. `ROLLBACK TO SAVEPOINT name` отменяет только изменения, сделанные после неё, и — что особенно важно в PostgreSQL — **выводит транзакцию из состояния ошибки**, позволяя продолжить работу. `RELEASE SAVEPOINT` удаляет точку (её изменения остаются частью транзакции). Это вложенные «частичные откаты», а не независимые транзакции: итог всё равно решает внешний `COMMIT` или `ROLLBACK`. ORM используют savepoint'ы для вложенных вызовов `transaction()`. Злоупотреблять ими не стоит: каждый savepoint создаёт подтранзакцию, а их большое количество (больше 64 в одной транзакции) заметно снижает производительность PostgreSQL.

## Вопрос

Что такое `SAVEPOINT` и когда он нужен?

## Пример

```sql
BEGIN;

INSERT INTO orders (user_id, total) VALUES (1, 500);

SAVEPOINT before_bonus;
INSERT INTO bonuses (user_id, amount) VALUES (1, 50);
-- ERROR: duplicate key — бонус уже начисляли
ROLLBACK TO SAVEPOINT before_bonus;     -- транзакция снова рабочая, заказ на месте

INSERT INTO order_logs (message) VALUES ('Бонус уже был начислен');
COMMIT;                                  -- заказ и лог сохранены
```

Без savepoint после ошибки пришлось бы откатывать всю транзакцию.

## Импорт с пропуском плохих строк

```ts
await client.query("BEGIN");
for (const row of rows) {
  await client.query("SAVEPOINT row_sp");
  try {
    await client.query("INSERT INTO products (sku, title, price) VALUES ($1, $2, $3)", [row.sku, row.title, row.price]);
    await client.query("RELEASE SAVEPOINT row_sp");
  } catch (e) {
    await client.query("ROLLBACK TO SAVEPOINT row_sp");
    errors.push({ sku: row.sku, error: e.message });
  }
}
await client.query("COMMIT");
```

Для больших импортов эффективнее заранее проверить данные или использовать `INSERT … ON CONFLICT DO NOTHING` — savepoint на каждую строку дорог.

## Команды

| Команда | Действие |
| --- | --- |
| `SAVEPOINT sp` | Создать точку |
| `ROLLBACK TO SAVEPOINT sp` | Откатиться к точке (точка остаётся) |
| `RELEASE SAVEPOINT sp` | Удалить точку, сохранив изменения |

## Вложенные транзакции в ORM

```ts
await prisma.$transaction(async (tx) => {
  await tx.order.create({ data: { ... } });
  // TypeORM, Sequelize, Drizzle и др. для вложенного transaction() создают SAVEPOINT
});
```

## Частые ошибки

- Ожидать, что `ROLLBACK TO SAVEPOINT` фиксирует предыдущие изменения — фиксирует только `COMMIT`.
- Savepoint на каждую из тысяч строк — деградация производительности.
- Использовать savepoint, чтобы «не думать» об ошибках, вместо `ON CONFLICT` или валидации.

## Что важно помнить

- Savepoint — частичный откат внутри транзакции.
- В PostgreSQL это способ продолжить транзакцию после ошибки.
- Итог по-прежнему решает внешний `COMMIT`/`ROLLBACK`.

## Мини-шпаргалка

- `SAVEPOINT sp`.
- `ROLLBACK TO SAVEPOINT sp`.
- `RELEASE SAVEPOINT sp`.
- Вложенные `transaction()` в ORM = savepoint.
