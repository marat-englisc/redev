# Что такое транзакция

> [!NOTE]
> **Транзакция** — группа операций, которая выполняется как единое целое: либо все изменения фиксируются (`COMMIT`), либо все отменяются (`ROLLBACK`). Пример — перевод денег: списание и зачисление не могут выполниться по отдельности. Транзакция также задаёт, **какие изменения других транзакций она видит** (уровень изоляции). В PostgreSQL каждый оператор без явного `BEGIN` выполняется в собственной транзакции (autocommit). Правила работы из приложения: транзакция должна быть **короткой** и использовать **одно соединение** для всех своих запросов; внутри неё не делают сетевых вызовов во внешние сервисы; ошибка внутри переводит транзакцию в состояние «aborted» — дальше можно только `ROLLBACK`.

## Вопрос

Что такое транзакция и как правильно работать с транзакциями из приложения?

## Перевод денег

```sql
BEGIN;

UPDATE accounts SET balance = balance - 1000 WHERE id = 1 AND balance >= 1000;
-- приложение проверяет: затронута 1 строка, иначе ROLLBACK
UPDATE accounts SET balance = balance + 1000 WHERE id = 2;
INSERT INTO transfers (from_id, to_id, amount) VALUES (1, 2, 1000);

COMMIT;
```

Если сервер упадёт между двумя `UPDATE`, после перезапуска не будет ни списания, ни зачисления.

## Autocommit

```sql
UPDATE users SET name = 'Anna' WHERE id = 1;   -- сам по себе транзакция: BEGIN; ...; COMMIT;
```

## Ошибка внутри транзакции

```sql
BEGIN;
INSERT INTO users (email) VALUES ('anna@x.com');
INSERT INTO users (email) VALUES ('anna@x.com');   -- ERROR: unique_violation
SELECT 1;   -- ERROR: current transaction is aborted, commands ignored until end of transaction block
ROLLBACK;
```

Чтобы продолжить после ожидаемой ошибки, используют [SAVEPOINT](<03. Что такое SAVEPOINT.md>).

## Транзакции в коде (Node.js)

```ts
const client = await pool.connect();          // одно соединение на всю транзакцию
try {
  await client.query("BEGIN");
  const { rows } = await client.query(
    "INSERT INTO orders (user_id, total) VALUES ($1, $2) RETURNING id", [userId, total]);
  await client.query(
    "INSERT INTO order_items (order_id, product_id, qty) SELECT $1, * FROM unnest($2::bigint[], $3::int[])",
    [rows[0].id, productIds, quantities]);
  await client.query("COMMIT");
} catch (e) {
  await client.query("ROLLBACK");
  throw e;
} finally {
  client.release();
}
```

`pool.query("BEGIN")` и затем `pool.query(...)` — ошибка: каждый вызов может уйти в разное соединение. ORM дают обёртки: `prisma.$transaction`, `dataSource.transaction`, `db.transaction` в Drizzle.

## Почему транзакции должны быть короткими

| Длинная транзакция | Последствие |
| --- | --- |
| Держит блокировки строк | Другие запросы ждут |
| Держит снимок данных | `VACUUM` не может удалить старые версии строк — таблицы раздуваются |
| Занимает соединение пула | Пул исчерпывается под нагрузкой |
| Внутри HTTP-вызов к платёжке | Секунды ожидания с открытыми блокировками |

Внешние вызовы делают до или после транзакции, а надёжность обеспечивают через идемпотентность и паттерн outbox.

```sql
SET idle_in_transaction_session_timeout = '30s';   -- защита от «забытых» открытых транзакций
```

## Частые ошибки

- Запросы одной транзакции через разные соединения пула.
- Нет `ROLLBACK` в обработке ошибок — соединение возвращается в пул в состоянии aborted.
- Внешние HTTP-вызовы внутри транзакции.
- Транзакция на весь HTTP-запрос «на всякий случай».

## Что важно помнить

- Транзакция — «всё или ничего».
- Одно соединение, короткая длительность, никаких внешних вызовов.
- После ошибки — только `ROLLBACK` (или откат к savepoint).

## Мини-шпаргалка

- `BEGIN; ...; COMMIT;` / `ROLLBACK;`.
- `pool.connect()` → `client.query(...)` → `release()`.
- `idle_in_transaction_session_timeout`.
- Внешние вызовы — вне транзакции.
