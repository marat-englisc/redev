# Что такое window frame

> [!NOTE]
> **Рамка окна (window frame)** — подмножество строк раздела, по которому агрегатная или value-функция считает значение для **текущей** строки. Задаётся как `ROWS | RANGE | GROUPS BETWEEN начало AND конец` с границами `UNBOUNDED PRECEDING`, `n PRECEDING`, `CURRENT ROW`, `n FOLLOWING`, `UNBOUNDED FOLLOWING`. Ключевой нюанс: если в окне есть `ORDER BY`, рамка по умолчанию — `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`, то есть от начала до текущей строки **включая все строки с тем же значением ключа** (peers). Поэтому `sum() OVER (ORDER BY …)` даёт накопительную сумму, а `last_value()` «не работает» без явной рамки. `ROWS` считает физические строки, `RANGE` — по значению ключа (например, `interval '7 days' PRECEDING`), `GROUPS` — по группам равных значений.

## Вопрос

Что такое window frame и как он влияет на результат?

## Рамка по умолчанию

| Окно | Рамка по умолчанию |
| --- | --- |
| `OVER ()` или `OVER (PARTITION BY ...)` | Весь раздел |
| `OVER (... ORDER BY ...)` | `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW` |

```sql
SELECT day, amount,
       sum(amount) OVER ()               AS total,     -- весь набор
       sum(amount) OVER (ORDER BY day)   AS running    -- накопительно
FROM daily_sales;
```

## Скользящее среднее

```sql
-- среднее за текущий и 6 предыдущих дней (7 строк)
SELECT day, amount,
       avg(amount) OVER (ORDER BY day ROWS BETWEEN 6 PRECEDING AND CURRENT ROW) AS ma7
FROM daily_sales;
```

Если в данных бывают пропущенные дни, «7 строк» ≠ «7 дней». Тогда используют `RANGE` по дате:

```sql
avg(amount) OVER (ORDER BY day RANGE BETWEEN interval '6 days' PRECEDING AND CURRENT ROW)
```

## ROWS, RANGE, GROUPS

| Режим | Единица смещения | Пример |
| --- | --- | --- |
| `ROWS` | Физические строки | `ROWS 2 PRECEDING` — две предыдущие строки |
| `RANGE` | Значение ключа сортировки | `RANGE interval '1 hour' PRECEDING` |
| `GROUPS` | Группы строк с равным ключом | `GROUPS 1 PRECEDING` — предыдущая группа равных |

## Peers и неожиданные результаты

```text
day        | amount | sum OVER (ORDER BY day) | sum OVER (ORDER BY day ROWS ...)
2026-10-01 | 10     | 30                      | 10
2026-10-01 | 20     | 30                      | 30     ← RANGE включает обе строки с тем же днём
2026-10-02 | 5      | 35                      | 35
```

Для строгой построчной накопительной суммы используйте `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW` и уникальный ключ сортировки.

## last_value и рамка

```sql
-- ✗ вернёт текущую строку (рамка заканчивается на CURRENT ROW)
last_value(price) OVER (PARTITION BY product_id ORDER BY changed_at)

-- ✓ вся группа
last_value(price) OVER (
  PARTITION BY product_id ORDER BY changed_at
  ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
)
-- часто проще: first_value(price) OVER (PARTITION BY product_id ORDER BY changed_at DESC)
```

## EXCLUDE

```sql
-- среднее соседей без текущей строки
avg(score) OVER (ORDER BY id ROWS BETWEEN 2 PRECEDING AND 2 FOLLOWING EXCLUDE CURRENT ROW)
```

## Частые ошибки

- Не знать о рамке по умолчанию при `ORDER BY`.
- `last_value` без явной рамки.
- `ROWS` для «последних 7 дней» при пропусках в данных.
- Неуникальный ключ сортировки + `RANGE` — «скачки» накопительной суммы.

## Что важно помнить

- С `ORDER BY` рамка по умолчанию — от начала до текущей строки и её peers.
- `ROWS` — по строкам, `RANGE` — по значениям, `GROUPS` — по группам равных.
- Для `last_value`, `nth_value` рамку задают явно.

## Мини-шпаргалка

- `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW` — накопительно.
- `ROWS BETWEEN 6 PRECEDING AND CURRENT ROW` — скользящее окно.
- `RANGE BETWEEN interval '7 days' PRECEDING AND CURRENT ROW`.
- `... AND UNBOUNDED FOLLOWING` — до конца раздела.
