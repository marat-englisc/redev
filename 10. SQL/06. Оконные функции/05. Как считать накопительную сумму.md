# Как считать накопительную сумму

> [!NOTE]
> **Накопительная сумма (running total)** — сумма всех значений от начала до текущей строки. В SQL её считают оконным агрегатом `sum(x) OVER (ORDER BY …)`, при необходимости с `PARTITION BY` (отдельно для каждого пользователя или месяца). Для корректного результата важны: **уникальный порядок** (иначе строки с равным ключом получат одинаковое значение из-за рамки `RANGE`) или явная рамка `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`; **агрегация до окна**, если нужна накопительная сумма по дням, а не по отдельным заказам; заполнение **пустых периодов**. Тот же приём даёт баланс счёта, прогресс к цели, накопительную долю (ABC-анализ).

## Вопрос

Как посчитать накопительную сумму в SQL?

## Базовый вариант

```sql
SELECT id, created_at, total,
       sum(total) OVER (ORDER BY created_at, id) AS running_total
FROM orders
WHERE status = 'paid';
```

## По дням

```sql
WITH daily AS (
  SELECT created_at::date AS day, sum(total) AS revenue
  FROM orders
  WHERE status = 'paid'
  GROUP BY 1
)
SELECT day, revenue,
       sum(revenue) OVER (ORDER BY day) AS cumulative_revenue
FROM daily
ORDER BY day;
```

Можно и без CTE: `sum(sum(total)) OVER (ORDER BY created_at::date)` — окно поверх агрегата.

## Сброс по группам

```sql
-- накопительная выручка внутри каждого месяца
SELECT day, revenue,
       sum(revenue) OVER (PARTITION BY date_trunc('month', day) ORDER BY day) AS mtd
FROM daily;

-- баланс по каждому счёту
SELECT account_id, created_at, amount,
       sum(amount) OVER (
         PARTITION BY account_id
         ORDER BY created_at, id
         ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
       ) AS balance
FROM transactions;
```

## Равные ключи сортировки

```text
created_at | total | ORDER BY created_at | ORDER BY created_at, id
10:00      | 100   | 300                 | 100
10:00      | 200   | 300                 | 300
10:05      | 50    | 350                 | 350
```

С неуникальным ключом рамка `RANGE` по умолчанию включает все строки с тем же значением.

## Накопительная доля — ABC-анализ

```sql
SELECT product_id, revenue,
       round(sum(revenue) OVER (ORDER BY revenue DESC, product_id)
             / sum(revenue) OVER () * 100, 1) AS cumulative_share,
       CASE
         WHEN sum(revenue) OVER (ORDER BY revenue DESC, product_id) / sum(revenue) OVER () <= 0.8 THEN 'A'
         WHEN sum(revenue) OVER (ORDER BY revenue DESC, product_id) / sum(revenue) OVER () <= 0.95 THEN 'B'
         ELSE 'C'
       END AS abc
FROM product_revenue;
```

## Без оконных функций

```sql
-- коррелированный подзапрос: O(n²), только для очень маленьких наборов
SELECT o.id, (SELECT sum(total) FROM orders o2 WHERE o2.created_at <= o.created_at) FROM orders o;
```

## Частые ошибки

- Неуникальный ключ сортировки без явной рамки `ROWS`.
- Накопление по сырым строкам, когда нужна сумма по дням.
- Пропущенные дни на графике — их добавляют через `generate_series`.
- Забыть `PARTITION BY` для баланса по нескольким счетам.

## Что важно помнить

- `sum(x) OVER (ORDER BY ...)` — накопительная сумма.
- Уникальный порядок или `ROWS` — для построчной точности.
- `PARTITION BY` сбрасывает накопление для каждой группы.

## Мини-шпаргалка

- `sum(x) OVER (ORDER BY t, id)`.
- `sum(x) OVER (PARTITION BY g ORDER BY t ROWS UNBOUNDED PRECEDING)`.
- `sum(sum(x)) OVER (ORDER BY day)`.
- Доля: `sum(...) OVER (ORDER BY ...) / sum(...) OVER ()`.
