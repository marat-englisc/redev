# Что такое LAG и LEAD

> [!NOTE]
> `lag(x, n, default)` возвращает значение `x` из строки, которая находится на `n` позиций **раньше** текущей в порядке окна, `lead(x, n, default)` — на `n` позиций **позже** (по умолчанию `n = 1`, `default = NULL`). Это позволяет сравнивать строку с соседней без self join: изменение выручки к прошлому месяцу, время между событиями, длительность статуса, поиск «разрывов» в последовательностях. Порядок задаёт `ORDER BY` внутри `OVER`, а `PARTITION BY` не даёт перескочить в чужую группу. Для первой строки раздела `lag` вернёт `NULL` (или `default`).

## Вопрос

Что такое `LAG` и `LEAD` и для чего их используют?

## Изменение к предыдущему месяцу

```sql
WITH monthly AS (
  SELECT date_trunc('month', created_at) AS month, sum(total) AS revenue
  FROM orders WHERE status = 'paid'
  GROUP BY 1
)
SELECT month, revenue,
       lag(revenue) OVER (ORDER BY month)                 AS prev_revenue,
       revenue - lag(revenue) OVER (ORDER BY month)       AS diff,
       round((revenue / NULLIF(lag(revenue) OVER (ORDER BY month), 0) - 1) * 100, 1) AS growth_pct
FROM monthly
ORDER BY month;
```

```text
month   | revenue | prev_revenue | diff | growth_pct
2026-08 | 1000    | NULL         | NULL | NULL
2026-09 | 1200    | 1000         | 200  | 20.0
2026-10 | 900     | 1200         | -300 | -25.0
```

## Время между событиями

```sql
-- через сколько пользователь сделал следующий заказ
SELECT user_id, id, created_at,
       lead(created_at) OVER (PARTITION BY user_id ORDER BY created_at) - created_at AS until_next
FROM orders;
```

## Длительность статуса

```sql
SELECT ticket_id, status, changed_at,
       COALESCE(lead(changed_at) OVER w, now()) - changed_at AS duration
FROM ticket_status_history
WINDOW w AS (PARTITION BY ticket_id ORDER BY changed_at);
```

## Год к году

```sql
lag(revenue, 12) OVER (ORDER BY month)    -- то же значение 12 месяцев назад
```

Работает, только если в ряду нет пропущенных месяцев — иначе сначала строят сетку через `generate_series`.

## Значение по умолчанию

```sql
lag(balance, 1, 0) OVER (PARTITION BY account_id ORDER BY day)   -- 0 вместо NULL
```

## first_value и last_value

```sql
SELECT user_id, created_at, total,
       first_value(total) OVER (PARTITION BY user_id ORDER BY created_at) AS first_order_total
FROM orders;
```

Для `last_value` нужна явная рамка — см. [window frame](<03. Что такое window frame.md>).

## Частые ошибки

- Забыть `PARTITION BY` — первая строка пользователя сравнивается с последней строкой предыдущего.
- `lag(x, 12)` при пропусках в данных.
- Деление на `NULL`/ноль при расчёте процента без `NULLIF`.
- Неуникальный порядок — «предыдущая» строка выбирается случайно.

## Что важно помнить

- `lag` — назад, `lead` — вперёд.
- Порядок — `ORDER BY` в окне, границы групп — `PARTITION BY`.
- Заменяет self join для сравнения соседних строк.

## Мини-шпаргалка

- `lag(x) OVER (ORDER BY t)`.
- `lead(x, n, default) OVER (PARTITION BY g ORDER BY t)`.
- `x - lag(x) OVER w` — дельта.
- `lead(t) OVER w - t` — интервал до следующего.
