# Чем отличается WHERE от HAVING

> [!NOTE]
> `WHERE` фильтрует **строки до группировки** и не может использовать агрегаты. `HAVING` фильтрует **группы после группировки** и обычно содержит агрегатное условие (`HAVING count(*) > 5`). Условия, не зависящие от агрегатов, всегда ставят в `WHERE`: так в группировку попадает меньше строк и могут работать индексы. `HAVING` без `GROUP BY` превращает весь набор в одну группу. В PostgreSQL алиас из `SELECT` в `HAVING` использовать нельзя — выражение повторяют.

## Вопрос

Чем отличается `WHERE` от `HAVING` и когда что использовать?

## Пример

```sql
-- покупатели, потратившие больше 10 000 на оплаченные заказы в 2026 году
SELECT user_id, sum(total) AS spent
FROM orders
WHERE status = 'paid'                         -- фильтр строк
  AND created_at >= '2026-01-01'
  AND created_at <  '2027-01-01'
GROUP BY user_id
HAVING sum(total) > 10000                     -- фильтр групп
ORDER BY spent DESC;
```

## Сравнение

| | `WHERE` | `HAVING` |
| --- | --- | --- |
| Когда работает | До `GROUP BY` | После `GROUP BY` |
| Что фильтрует | Строки | Группы |
| Агрегаты | Нельзя | Можно |
| Использует индексы | Да | Нет (работает с результатом агрегации) |

## Неправильное место условия

```sql
-- ✗ агрегат в WHERE — ошибка
WHERE count(*) > 5

-- ✗ работает, но неэффективно: все статусы группируются, потом отбрасываются
SELECT status, count(*) FROM orders GROUP BY status HAVING status = 'paid';

-- ✓
SELECT status, count(*) FROM orders WHERE status = 'paid' GROUP BY status;
```

Планировщик PostgreSQL часто сам переносит такие условия в `WHERE`, но писать нужно явно правильно.

## Популярные задачи с HAVING

```sql
-- дубли email
SELECT lower(email), count(*) FROM users GROUP BY lower(email) HAVING count(*) > 1;

-- пользователи, купившие во всех трёх категориях
SELECT o.user_id
FROM orders o JOIN products p ON p.id = o.product_id
WHERE p.category_id IN (1, 2, 3)
GROUP BY o.user_id
HAVING count(DISTINCT p.category_id) = 3;

-- группы, где все заказы оплачены
SELECT user_id FROM orders GROUP BY user_id HAVING bool_and(status = 'paid');
```

## Частые ошибки

- Агрегат в `WHERE`.
- Фильтр по обычному столбцу в `HAVING`.
- Алиас агрегата в `HAVING` (`HAVING spent > 100` в PostgreSQL — ошибка).
- Путать `HAVING` с фильтром после оконных функций — для них нужен подзапрос или CTE.

## Что важно помнить

- `WHERE` — строки, `HAVING` — группы.
- Всё, что можно отфильтровать до группировки, фильтруйте в `WHERE`.
- `HAVING` + `count(DISTINCT)` — классика задач «во всех категориях».

## Мини-шпаргалка

- `WHERE cond GROUP BY k HAVING agg_cond`.
- `HAVING count(*) > 1` — дубли.
- `HAVING bool_and(...)` — все строки группы удовлетворяют условию.
