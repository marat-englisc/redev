# Как работает GROUP BY

> [!NOTE]
> `GROUP BY` разбивает строки на группы с одинаковыми значениями указанных выражений и превращает каждую группу в **одну** строку результата. В `SELECT` после этого можно использовать только выражения из `GROUP BY` и агрегаты (исключение: если группировка идёт по первичному ключу, PostgreSQL разрешает остальные столбцы этой таблицы — они функционально зависят от PK). `NULL` образуют одну общую группу. Группы фильтруют через `HAVING`, а порядок результата задаётся только явным `ORDER BY`. Для промежуточных итогов есть `GROUPING SETS`, `ROLLUP` и `CUBE`.

## Вопрос

Как работает `GROUP BY` и какие у него правила?

## Пример

```sql
SELECT status, count(*) AS orders, sum(total) AS revenue
FROM orders
GROUP BY status
ORDER BY revenue DESC;
```

```text
orders                       результат
status    | total            status    | orders | revenue
paid      | 500              paid      | 2      | 800
paid      | 300              cancelled | 1      | 200
cancelled | 200
```

## Несколько столбцов

```sql
SELECT country, city, count(*) AS users
FROM users
GROUP BY country, city;        -- группа = уникальная пара (country, city)
```

## Правило списка выборки

```sql
-- ✗ name не в GROUP BY и не агрегат
SELECT user_id, name, sum(total) FROM orders GROUP BY user_id;

-- ✓ группировка по PK — можно брать столбцы этой таблицы
SELECT u.id, u.name, u.email, sum(o.total)
FROM users u
JOIN orders o ON o.user_id = u.id
GROUP BY u.id;
```

MySQL без `ONLY_FULL_GROUP_BY` разрешает «лишние» столбцы и возвращает значение из случайной строки группы — источник тихих ошибок.

## Группировка по выражению

```sql
SELECT date_trunc('month', created_at) AS month, sum(total)
FROM orders
GROUP BY date_trunc('month', created_at);   -- или GROUP BY month / GROUP BY 1
```

## NULL в группировке

```sql
SELECT country, count(*) FROM users GROUP BY country;
-- все пользователи с country IS NULL — в одной группе
```

## Порядок обработки

```text
FROM / JOIN → WHERE → GROUP BY → агрегаты → HAVING → SELECT → ORDER BY → LIMIT
```

`WHERE` уменьшает количество строк до группировки — это дешевле, чем отбрасывать группы в `HAVING`.

## Как это выполняется

PostgreSQL использует `HashAggregate` (хеш-таблица групп) или `GroupAggregate` (по заранее отсортированному входу, например из индекса). При большом числе групп hash может уйти на диск — это видно в `EXPLAIN ANALYZE`.

## Частые ошибки

- Ожидать отсортированный результат без `ORDER BY`.
- Фильтровать строки в `HAVING` вместо `WHERE`.
- Группировать по `name` вместо `id` — разные люди с одним именем склеятся.
- Агрегировать после JOIN нескольких one-to-many таблиц ([дубли от JOIN](<../03. JOIN и связи таблиц/04. Почему JOIN может создавать дубли.md>)).

## Что важно помнить

- Одна группа = одна строка результата.
- В `SELECT` — только ключи группировки, агрегаты и столбцы, зависящие от PK.
- Группируйте по идентификаторам, а не по отображаемым названиям.

## Мини-шпаргалка

- `GROUP BY a, b`.
- `GROUP BY 1` / алиас (PostgreSQL).
- `NULL` — одна группа.
- `WHERE` до, `HAVING` после.
- Итоги — `ROLLUP`, `GROUPING SETS`.
