# Чем COUNT со звёздочкой отличается от COUNT по столбцу

> [!NOTE]
> `count(*)` считает **строки** — все, независимо от содержимого. `count(column)` считает строки, где значение столбца **не `NULL`**. `count(DISTINCT column)` — количество уникальных не-`NULL` значений. `count(1)` в PostgreSQL эквивалентен `count(*)` и не быстрее (`count(*)` даже немного оптимальнее). Разница критична после `LEFT JOIN`: `count(*)` посчитает строку-заглушку без пары как 1, а `count(right.id)` — как 0. Точный `count(*)` по большой таблице в PostgreSQL дорог из-за MVCC (нужно проверить видимость каждой строки), поэтому для «примерно сколько» используют статистику `pg_class.reltuples`.

## Вопрос

Чем отличаются `count(*)`, `count(column)` и `count(DISTINCT column)`?

## Пример

```text
users
id | phone
1  | +7999...
2  | NULL
3  | +7999...   (тот же номер)
```

```sql
SELECT
  count(*)              AS rows,          -- 3
  count(phone)          AS with_phone,    -- 2
  count(DISTINCT phone) AS unique_phones  -- 1
FROM users;
```

## После LEFT JOIN

```sql
SELECT u.id, count(*) AS wrong, count(o.id) AS orders
FROM users u
LEFT JOIN orders o ON o.user_id = u.id
GROUP BY u.id;
```

```text
id | wrong | orders
1  | 2     | 2
3  | 1     | 0       ← у пользователя нет заказов, но count(*) = 1
```

## count(1) и count(*)

```sql
SELECT count(*) FROM orders;   -- рекомендуемая форма
SELECT count(1) FROM orders;   -- то же самое по результату
```

Миф «`count(1)` быстрее» к PostgreSQL не относится.

## Почему count(*) медленный в PostgreSQL

Из-за MVCC разные транзакции видят разное число строк, поэтому счётчик нельзя хранить в метаданных таблицы. Ускорить можно:

```sql
-- приблизительно, мгновенно (обновляется VACUUM/ANALYZE)
SELECT reltuples::bigint AS approx_rows FROM pg_class WHERE relname = 'orders';

-- точно, но по индексу (index-only scan при свежей visibility map)
SELECT count(*) FROM orders WHERE status = 'new';
```

Для UI «найдено ~1,2 млн» часто достаточно оценки, а точный счётчик по фильтру — поддерживать в отдельной таблице или кеше.

## Частые ошибки

- `count(*)` после `LEFT JOIN` для подсчёта связанных записей.
- `count(nullable_column)` там, где нужно число строк.
- Точный `count(*)` по огромной таблице на каждый запрос страницы.
- Ожидать, что `count(DISTINCT x)` учитывает `NULL`.

## Что важно помнить

- `count(*)` — строки, `count(col)` — не-`NULL` значения.
- После `LEFT JOIN` считайте по PK правой таблицы.
- Для больших таблиц точный счёт дорог — используйте оценки или счётчики.

## Мини-шпаргалка

- `count(*)` — все строки.
- `count(col)` — без `NULL`.
- `count(DISTINCT col)` — уникальные.
- `count(o.id)` после `LEFT JOIN`.
- `pg_class.reltuples` — оценка.
