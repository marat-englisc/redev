# Что такое агрегатные функции

> [!NOTE]
> **Агрегатная функция** сворачивает множество строк в одно значение: `count`, `sum`, `avg`, `min`, `max`, а также `string_agg`, `array_agg`, `json_agg`, `bool_and`/`bool_or`, статистические (`percentile_cont`, `stddev`). Без `GROUP BY` агрегат считается по всем строкам и возвращает **одну** строку, с `GROUP BY` — по строке на группу. Все агрегаты, кроме `count(*)`, **игнорируют `NULL`**; по пустому набору `count` вернёт `0`, а `sum`/`avg`/`max` — `NULL` (оборачивают в `COALESCE`). Агрегаты можно уточнять: `DISTINCT` внутри, `FILTER (WHERE …)`, `ORDER BY` внутри для упорядоченных (`string_agg(name, ', ' ORDER BY name)`).

## Вопрос

Что такое агрегатные функции и как они работают с `NULL`?

## Основные функции

```sql
SELECT
  count(*)                 AS orders,
  count(DISTINCT user_id)  AS customers,
  sum(total)               AS revenue,
  avg(total)               AS avg_check,
  min(created_at)          AS first_order,
  max(created_at)          AS last_order
FROM orders
WHERE status = 'paid';
```

## NULL и пустые наборы

```text
total: 100, NULL, 300
count(*)     = 3
count(total) = 2
sum(total)   = 400
avg(total)   = 200     ← (100 + 300) / 2, а не / 3
```

```sql
SELECT COALESCE(sum(total), 0) AS revenue      -- по пустому набору sum = NULL
FROM orders WHERE created_at > now();
```

Если `NULL` должен считаться нулём в среднем — `avg(COALESCE(total, 0))`, но обычно это искажает метрику; решение зависит от смысла `NULL`.

## Другие полезные агрегаты (PostgreSQL)

| Функция | Пример |
| --- | --- |
| `string_agg(x, ', ')` | Список имён через запятую |
| `array_agg(x)` | Массив значений |
| `json_agg(row)` / `jsonb_agg` | JSON-массив для API |
| `bool_and(x)`, `bool_or(x)` | Все ли / хотя бы один `true` |
| `percentile_cont(0.5) WITHIN GROUP (ORDER BY x)` | Медиана |
| `mode() WITHIN GROUP (ORDER BY x)` | Самое частое значение |

```sql
SELECT
  percentile_cont(0.5)  WITHIN GROUP (ORDER BY total) AS median_check,
  percentile_cont(0.95) WITHIN GROUP (ORDER BY response_ms) AS p95
FROM orders;
```

Медиана и перцентили устойчивее среднего к выбросам — для времени ответа и чеков это обычно честнее.

## Модификаторы

```sql
SELECT
  count(DISTINCT user_id),
  count(*) FILTER (WHERE status = 'cancelled')         AS cancelled,
  string_agg(DISTINCT city, ', ' ORDER BY city)         AS cities
FROM orders;
```

## Агрегат и обычные столбцы

```sql
SELECT user_id, sum(total) FROM orders;              -- ✗ user_id не в GROUP BY
SELECT user_id, sum(total) FROM orders GROUP BY user_id;  -- ✓
```

Нужен агрегат и сохранить строки — [оконные функции](<../06. Оконные функции/01. Что такое оконная функция.md>): `sum(total) OVER (PARTITION BY user_id)`.

## Частые ошибки

- Ожидать, что `avg` учитывает `NULL` как ноль.
- Не обрабатывать `NULL` от `sum` по пустому набору.
- `sum` по `integer` и деление целых: `sum(a) / count(*)` в целых числах (нужен `::numeric`).
- Деньги в `float` — ошибки округления (используйте `numeric`).

## Что важно помнить

- Агрегаты игнорируют `NULL`, кроме `count(*)`.
- По пустому набору `count` = 0, остальные — `NULL`.
- `DISTINCT`, `FILTER`, `ORDER BY` внутри агрегата уточняют расчёт.

## Мини-шпаргалка

- `count`, `sum`, `avg`, `min`, `max`.
- `COALESCE(sum(x), 0)`.
- `percentile_cont(...) WITHIN GROUP (ORDER BY x)`.
- `string_agg`, `array_agg`, `json_agg`.
- `bool_and`, `bool_or`.
