# Что такое partial и expression index

> [!NOTE]
> **Частичный индекс (partial index)** содержит только строки, удовлетворяющие условию `WHERE` в определении индекса: `CREATE INDEX … WHERE status = 'pending'`. Он меньше, быстрее обновляется и идеален для перекошенных данных (активные задачи, неудалённые записи) и условной уникальности. Планировщик использует его, только если условие запроса **логически влечёт** условие индекса. **Индекс по выражению (expression index)** хранит результат функции или выражения: `lower(email)`, `(attrs->>'brand')`, `date(created_at AT TIME ZONE 'UTC')`; он используется, когда запрос содержит **то же выражение**. Выражение должно быть `IMMUTABLE` — поэтому, например, `date(timestamptz)` без явного часового пояса проиндексировать нельзя.

## Вопрос

Что такое partial и expression index и когда их использовать?

## Частичный индекс

```sql
-- 99% заказов завершены, интересны только активные
CREATE INDEX orders_active_idx ON orders (created_at)
WHERE status IN ('new', 'processing');

SELECT * FROM orders WHERE status = 'new' ORDER BY created_at LIMIT 50;      -- ✓ использует
SELECT * FROM orders WHERE status = 'done' ORDER BY created_at LIMIT 50;     -- ✗ не подходит
```

## Условная уникальность

```sql
-- уникальный slug среди неудалённых
CREATE UNIQUE INDEX articles_slug_uniq ON articles (slug) WHERE deleted_at IS NULL;

-- только одна активная подписка на пользователя
CREATE UNIQUE INDEX subscriptions_one_active ON subscriptions (user_id) WHERE status = 'active';
```

## Параметры и частичные индексы

```sql
-- условие индекса: WHERE deleted_at IS NULL
SELECT * FROM articles WHERE deleted_at IS NULL AND author_id = $1;   -- ✓
SELECT * FROM articles WHERE status = $1;    -- если индекс WHERE status = 'pending', а status передан параметром,
                                             -- generic plan может его не использовать
```

Условие частичного индекса должно быть в запросе в явном виде (литералом), а не через параметр.

## Индекс по выражению

```sql
CREATE INDEX users_email_lower_idx ON users (lower(email));
SELECT * FROM users WHERE lower(email) = lower($1);   -- ✓ то же выражение

CREATE INDEX products_brand_idx ON products ((attrs->>'brand'));   -- двойные скобки для выражений
SELECT * FROM products WHERE attrs->>'brand' = 'Lenovo';           -- ✓
```

## IMMUTABLE и даты

```sql
-- ✗ ERROR: functions in index expression must be marked IMMUTABLE
CREATE INDEX ON orders (date(created_at));               -- created_at timestamptz: зависит от TimeZone сессии

-- ✓ явный часовой пояс делает выражение неизменным
CREATE INDEX orders_day_msk_idx ON orders (((created_at AT TIME ZONE 'Europe/Moscow')::date));
SELECT * FROM orders WHERE (created_at AT TIME ZONE 'Europe/Moscow')::date = '2026-10-24';
```

Часто проще вообще не использовать выражение, а фильтровать полуоткрытым диапазоном по обычному индексу `created_at`.

## Комбинация

```sql
CREATE INDEX users_active_email_idx ON users (lower(email)) WHERE deleted_at IS NULL;
```

## Альтернатива — генерируемый столбец

```sql
ALTER TABLE products ADD COLUMN brand text GENERATED ALWAYS AS (attrs->>'brand') STORED;
CREATE INDEX ON products (brand);
```

Запросы проще (`WHERE brand = ...`), и столбец виден в ORM.

## Частые ошибки

- Запрос использует выражение, отличающееся от индекса (`LOWER(email)` vs `lower(trim(email))`).
- Частичный индекс с условием, которое запрос не повторяет.
- Индекс по `date(timestamptz)` — ошибка `IMMUTABLE`.
- Слишком много частичных индексов под каждую комбинацию фильтров.

## Что важно помнить

- Partial — индекс по части строк; запрос должен включать его условие.
- Expression — индекс по результату выражения; запрос должен содержать то же выражение.
- Функции в индексе — только `IMMUTABLE`.

## Мини-шпаргалка

- `CREATE INDEX ... ON t (col) WHERE cond`.
- `CREATE UNIQUE INDEX ... WHERE deleted_at IS NULL`.
- `CREATE INDEX ... ON t (lower(col))`.
- `((expr))` — выражение в двойных скобках.
