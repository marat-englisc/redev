# Какие бывают типы индексов - GIN, GiST, BRIN, Hash

> [!NOTE]
> Кроме B-tree, PostgreSQL предлагает специализированные индексы. **GIN** (Generalized Inverted Index) — обратный индекс «элемент → строки», для составных значений: `jsonb` (`@>`, `?`), массивы (`@>`, `&&`), полнотекстовый поиск (`tsvector @@ tsquery`), trigram-поиск подстрок (`pg_trgm`); быстро читает, но дороже обновляется. **GiST** — сбалансированное дерево для «пересекающихся» данных: геометрия и PostGIS, диапазоны (`&&`), поиск ближайших соседей (`ORDER BY point <-> $1`), ограничения `EXCLUDE`. **BRIN** (Block Range Index) хранит min/max для диапазонов страниц — крошечный индекс для огромных таблиц, где значения коррелируют с физическим порядком (логи и события по времени). **Hash** — только равенство; с PostgreSQL 10 он надёжен, но B-tree почти всегда не хуже. **SP-GiST** — для неравномерно распределённых данных (IP-адреса, префиксные деревья).

## Вопрос

Какие типы индексов есть в PostgreSQL и когда какой использовать?

## Обзор

| Тип | Для чего | Операторы |
| --- | --- | --- |
| B-tree | Почти всё: равенство, диапазоны, сортировка | `=`, `<`, `>`, `BETWEEN`, `LIKE 'x%'` |
| GIN | Составные значения: JSON, массивы, текст | `@>`, `?`, `&&`, `@@`, `%` / `ILIKE` (trgm) |
| GiST | Геометрия, диапазоны, ближайшие соседи | `&&`, `@>`, `<->` |
| BRIN | Огромные таблицы с естественным порядком | `=`, `<`, `>` по диапазонам блоков |
| Hash | Только равенство | `=` |
| SP-GiST | Неравномерные данные, `inet`, префиксы | `<<`, `>>`, `^@` |

## GIN

```sql
-- jsonb
CREATE INDEX products_attrs_gin ON products USING gin (attrs jsonb_path_ops);
SELECT * FROM products WHERE attrs @> '{"color": "black"}';

-- массивы
CREATE INDEX posts_tags_gin ON posts USING gin (tags);
SELECT * FROM posts WHERE tags @> ARRAY['sql'];

-- полнотекстовый поиск
CREATE INDEX articles_fts_gin ON articles USING gin (to_tsvector('russian', title || ' ' || body));
SELECT * FROM articles WHERE to_tsvector('russian', title || ' ' || body) @@ websearch_to_tsquery('russian', 'индексы postgres');

-- подстроки
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE INDEX users_name_trgm ON users USING gin (name gin_trgm_ops);
SELECT * FROM users WHERE name ILIKE '%иван%';
```

GIN медленнее обновляется: изменения сначала копятся в «pending list» (`fastupdate`), что ускоряет вставку, но может замедлять чтение до очистки.

## GiST

```sql
-- бронирования без пересечений
CREATE EXTENSION IF NOT EXISTS btree_gist;
CREATE TABLE bookings (
  room_id int,
  during tstzrange,
  EXCLUDE USING gist (room_id WITH =, during WITH &&)
);

-- ближайшие точки (KNN)
CREATE INDEX places_location_gist ON places USING gist (location);
SELECT name FROM places ORDER BY location <-> point(37.62, 55.75) LIMIT 5;
```

Для trigram есть и `gist_trgm_ops`: компактнее GIN и поддерживает KNN по похожести (`ORDER BY name <-> 'ивн'`), но обычно медленнее на поиске.

## BRIN

```sql
-- миллиард строк логов, вставляемых по времени
CREATE INDEX events_created_brin ON events USING brin (created_at);
SELECT count(*) FROM events WHERE created_at >= '2026-10-01' AND created_at < '2026-10-02';
```

| | B-tree | BRIN |
| --- | --- | --- |
| Размер на 1 млрд строк | Десятки ГБ | Единицы МБ |
| Точность | Точные указатели на строки | Диапазоны страниц, затем перепроверка |
| Условие эффективности | Любое | Физический порядок ≈ порядку значений |

Если строки в таблице перемешаны по времени (частые `UPDATE`, вставка задним числом), BRIN почти бесполезен.

## Hash

```sql
CREATE INDEX sessions_token_hash ON sessions USING hash (token);
SELECT * FROM sessions WHERE token = $1;
```

Может быть компактнее B-tree для длинных значений, но не поддерживает диапазоны, сортировку и уникальность.

## Как выбрать

```text
Сравнение, сортировка, диапазоны     → B-tree
JSON, массивы, полнотекст, ILIKE '%x%' → GIN
Пересечение интервалов, гео, KNN       → GiST
Огромный append-only журнал по времени → BRIN
```

## Частые ошибки

- GIN по `jsonb` для запросов `attrs->>'x' = 'y'` — нужен индекс по выражению (GIN работает с `@>`).
- BRIN на таблице без корреляции с физическим порядком.
- Ожидать от GIN поддержки сортировки.
- Много GIN-индексов на таблице с интенсивной записью.

## Что важно помнить

- Тип индекса определяется операторами в запросе.
- GIN — «что внутри значения», GiST — «пересекается/рядом», BRIN — «где на диске».
- B-tree — выбор по умолчанию.

## Мини-шпаргалка

- `USING gin (col jsonb_path_ops)`.
- `USING gin (col gin_trgm_ops)`.
- `USING gist (range_col)`, `EXCLUDE USING gist`.
- `USING brin (created_at)`.
- `USING hash (col)`.
