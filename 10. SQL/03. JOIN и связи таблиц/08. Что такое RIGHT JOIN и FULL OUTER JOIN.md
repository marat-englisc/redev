# Что такое RIGHT JOIN и FULL OUTER JOIN

> [!NOTE]
> `RIGHT JOIN` — зеркало `LEFT JOIN`: сохраняет все строки **правой** таблицы. На практике его почти не используют — меняют таблицы местами и пишут `LEFT JOIN`, потому что так запрос читается слева направо. `FULL OUTER JOIN` сохраняет строки **обеих** сторон: совпавшие соединяет, а для несовпавших заполняет противоположную сторону `NULL`. Основное применение `FULL JOIN` — **сверка двух наборов** (импорт против текущих данных, план против факта, данные двух систем): одним запросом видно, что есть только слева, только справа и что различается.

## Вопрос

Что такое `RIGHT JOIN` и `FULL OUTER JOIN` и когда они нужны?

## RIGHT JOIN

```sql
SELECT u.name, o.id
FROM orders o
RIGHT JOIN users u ON u.id = o.user_id;

-- то же, читается проще
SELECT u.name, o.id
FROM users u
LEFT JOIN orders o ON o.user_id = u.id;
```

## FULL OUTER JOIN

```text
plan               fact
month | amount     month | amount
2026-08 | 100      2026-08 | 90
2026-09 | 120      2026-10 | 50
```

```sql
SELECT
  COALESCE(p.month, f.month) AS month,
  p.amount AS planned,
  f.amount AS actual
FROM plan p
FULL JOIN fact f ON f.month = p.month
ORDER BY month;
```

```text
2026-08 | 100  | 90
2026-09 | 120  | NULL    ← только в плане
2026-10 | NULL | 50      ← только в факте
```

`COALESCE` по ключу нужен, потому что в несовпавших строках одна из сторон — `NULL`.

## Сверка данных

```sql
-- сравнить импортированный прайс с текущим
SELECT
  COALESCE(i.sku, p.sku) AS sku,
  CASE
    WHEN p.sku IS NULL THEN 'new'
    WHEN i.sku IS NULL THEN 'removed'
    WHEN i.price <> p.price THEN 'changed'
    ELSE 'same'
  END AS diff,
  p.price AS old_price,
  i.price AS new_price
FROM import_prices i
FULL JOIN products p ON p.sku = i.sku;
```

## Ограничения

- `FULL JOIN` в PostgreSQL поддерживает только условия соединения, пригодные для merge или hash join (обычно равенство).
- В MySQL `FULL JOIN` нет — эмулируют через `LEFT JOIN UNION RIGHT JOIN` (с исключением дублей).
- Фильтр по любой стороне в `WHERE` превращает `FULL JOIN` в `LEFT`/`RIGHT`/`INNER`.

## Частые ошибки

- Использовать `RIGHT JOIN` в цепочке с `LEFT JOIN` — запрос становится трудно читать.
- Забыть `COALESCE` для ключа в `FULL JOIN`.
- Фильтровать в `WHERE` по столбцу одной стороны и потерять строки «только с другой стороны».

## Что важно помнить

- `RIGHT JOIN` = `LEFT JOIN` с переставленными таблицами — предпочитайте `LEFT`.
- `FULL JOIN` — инструмент сверки двух наборов.
- Ключ в результате `FULL JOIN` собирают через `COALESCE`.

## Мини-шпаргалка

- `a RIGHT JOIN b` ≡ `b LEFT JOIN a`.
- `FULL JOIN ... ON a.k = b.k`.
- `COALESCE(a.k, b.k)`.
- `a.k IS NULL` — только справа, `b.k IS NULL` — только слева.
