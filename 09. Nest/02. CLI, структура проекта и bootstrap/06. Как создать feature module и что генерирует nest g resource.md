# Как создать feature module и что генерирует nest g resource

> [!NOTE]
> **Feature module** — модуль одной доменной области (`users`, `orders`, `products`), который содержит её контроллер, сервис, DTO, работу с данными и тесты и экспортирует наружу только то, что нужно другим модулям. Быстрее всего создать его командой `nest g resource users`: CLI спросит транспорт (REST, GraphQL code first/schema first, микросервис, WebSockets) и генерировать ли CRUD, а затем создаст модуль, контроллер с пятью CRUD-эндпоинтами, сервис-заглушку, `CreateUserDto`, `UpdateUserDto` (через `PartialType`), entity и spec-файлы, и зарегистрирует модуль в `AppModule`. Сгенерированный код — **заготовка**: сервис возвращает строки-заглушки, DTO пустые, данных нет; дальше добавляют валидацию, репозиторий, обработку ошибок и тесты.

## Вопрос

Как создать feature module и что именно генерирует `nest g resource`?

## Генерация

```bash
nest g resource users
```

## Что внутри

```ts
// users.controller.ts (сгенерировано)
@Controller('users')
export class UsersController {
  constructor(private readonly usersService: UsersService) {}

  @Post()       create(@Body() createUserDto: CreateUserDto) { return this.usersService.create(createUserDto); }
  @Get()        findAll() { return this.usersService.findAll(); }
  @Get(':id')   findOne(@Param('id') id: string) { return this.usersService.findOne(+id); }
  @Patch(':id') update(@Param('id') id: string, @Body() updateUserDto: UpdateUserDto) { return this.usersService.update(+id, updateUserDto); }
  @Delete(':id') remove(@Param('id') id: string) { return this.usersService.remove(+id); }
}

// users.service.ts (сгенерировано)
@Injectable()
export class UsersService {
  create(createUserDto: CreateUserDto) { return 'This action adds a new user'; }
  findAll() { return `This action returns all users`; }
  // ...
}

// dto/update-user.dto.ts
export class UpdateUserDto extends PartialType(CreateUserDto) {}
```

## Как довести заготовку до рабочей фичи

```ts
// 1. DTO с валидацией
export class CreateUserDto {
  @IsEmail() email: string;
  @IsString() @Length(2, 100) name: string;
}

// 2. Контроллер: парсинг id через pipe вместо +id
@Get(':id')
findOne(@Param('id', ParseIntPipe) id: number) {
  return this.usersService.findOne(id);
}

// 3. Сервис: данные и ошибки
@Injectable()
export class UsersService {
  constructor(private readonly prisma: PrismaService) {}

  async findOne(id: number) {
    const user = await this.prisma.user.findUnique({ where: { id } });
    if (!user) throw new NotFoundException(`User ${id} not found`);
    return user;
  }
}

// 4. Модуль: зависимости и публичный API
@Module({
  imports: [PrismaModule],
  controllers: [UsersController],
  providers: [UsersService],
  exports: [UsersService],
})
export class UsersModule {}
```

## Чек-лист новой фичи

- [ ] Модуль импортирован в `AppModule` (или в родительский модуль).
- [ ] DTO запроса с валидацией; DTO ответа без чувствительных полей.
- [ ] Параметры маршрута парсятся pipes (`ParseIntPipe`, `ParseUUIDPipe`).
- [ ] Сервис бросает доменные HTTP-исключения (`NotFoundException`, `ConflictException`).
- [ ] Доступ к данным — через репозиторий или ORM-провайдер.
- [ ] Защита: guards, роли, проверка владельца.
- [ ] Swagger-декораторы или CLI-плагин.
- [ ] Unit-тесты сервиса и e2e-тест основных сценариев.
- [ ] Экспортируется только то, что нужно другим модулям.

## Когда не использовать resource

Для модуля без HTTP (например, `MailModule`, `PaymentsGatewayModule`) достаточно `nest g module` + `nest g service`: CRUD-контроллер там не нужен.

## Частые ошибки

- Оставить сгенерированные заглушки и `+id` без валидации.
- Возвращать entity целиком вместе с `passwordHash`.
- Хранить в `entities/` класс, который не используется ни ORM, ни ответом API.
- Делать resource для каждой таблицы вместо доменной области.

## Что важно помнить

- Feature module — граница доменной области.
- `nest g resource` создаёт полный CRUD-скелет и регистрирует модуль.
- Заготовку нужно дополнить валидацией, данными, ошибками и тестами.

## Мини-шпаргалка

- `nest g resource <name>` — модуль, контроллер, сервис, DTO, entity, specs.
- `UpdateDto extends PartialType(CreateDto)`.
- `--no-spec` — без тестов.
- Без HTTP — `nest g module` + `nest g service`.
