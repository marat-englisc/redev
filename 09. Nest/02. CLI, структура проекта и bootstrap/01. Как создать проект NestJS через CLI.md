# Как создать проект NestJS через CLI

> [!NOTE]
> **Nest CLI** (`@nestjs/cli`) создаёт проект, генерирует строительные блоки и собирает приложение. `nest new my-api` разворачивает стартовый проект: `main.ts`, `AppModule`, пример контроллера и сервиса, настройки TypeScript, ESLint/Prettier и тесты (в NestJS 12 — Vitest). Генераторы (`nest g module|controller|service|resource|guard|pipe|interceptor|filter`) создают файлы по соглашениям и **сразу регистрируют** их в нужном модуле. Команды `start:dev` (watch-режим), `build` и `start:prod` уже прописаны в `package.json`. CLI можно не ставить глобально — достаточно `npx @nestjs/cli`. Для монорепозитория есть режим workspace (`nest g app`, `nest g library`).

## Вопрос

Как создать проект NestJS и какие команды CLI нужно знать?

## Создание проекта

```bash
npx @nestjs/cli new my-api
```

```bash
cd my-api
npm run start:dev       # watch-режим, перезапуск при изменениях
```

`GET http://localhost:3000` → `Hello World!`.

Полезные флаги `nest new`: `--package-manager pnpm`, `--strict` (строгий TypeScript), `--skip-git`, `--language ts`.

## Скрипты package.json

| Скрипт | Что делает |
| --- | --- |
| `start:dev` | `nest start --watch` — разработка |
| `start:debug` | Watch + inspector для отладчика |
| `build` | Компиляция в `dist/` |
| `start:prod` | `node dist/main` |
| `test`, `test:e2e`, `test:cov` | Unit, e2e и покрытие |
| `lint`, `format` | ESLint и Prettier |

## Генераторы

```bash
nest g module users               # users/users.module.ts + импорт в AppModule
nest g controller users           # users/users.controller.ts + spec, регистрация в UsersModule
nest g service users              # users/users.service.ts + spec
nest g resource orders            # модуль, контроллер, сервис, DTO, entity — CRUD-заготовка
nest g guard auth/roles           # roles.guard.ts
nest g interceptor common/logging
nest g pipe common/parse-object-id
```

| Флаг | Значение |
| --- | --- |
| `--no-spec` | Без файла теста |
| `--flat` | Без отдельной папки |
| `--dry-run` / `-d` | Показать, что будет создано, без записи |

Подробнее о `nest g resource` — в уроке [feature module и nest g resource](<06. Как создать feature module и что генерирует nest g resource.md>).

## nest-cli.json

```json
{
  "$schema": "https://json.schemastore.org/nest-cli",
  "collection": "@nestjs/schematics",
  "sourceRoot": "src",
  "compilerOptions": {
    "deleteOutDir": true,
    "builder": "swc",
    "plugins": ["@nestjs/swagger"]
  }
}
```

- `builder: "swc"` — значительно более быстрая компиляция, чем `tsc`.
- `plugins` — например, [Swagger CLI plugin](<../15. Swagger и OpenAPI подробно/10. Что такое Swagger CLI plugin.md>), который генерирует метаданные для DTO.

## Монорепозиторий

```bash
nest g app admin-api       # второе приложение в apps/
nest g library shared      # библиотека в libs/ с алиасом @app/shared
```

## Частые ошибки

- Создавать файлы вручную и забывать зарегистрировать их в модуле.
- Запускать в проде `start:dev` вместо сборки и `node dist/main`.
- Разные мажорные версии `@nestjs/cli` и `@nestjs/core`.

## Что важно помнить

- `nest new` — стартовый проект, `nest g` — генерация с регистрацией в модуле.
- `--dry-run` показывает изменения заранее.
- В проде запускается собранный `dist/main.js`.

## Мини-шпаргалка

- `npx @nestjs/cli new app`.
- `nest g module|controller|service|resource name`.
- `--no-spec`, `--flat`, `--dry-run`.
- `npm run start:dev`, `build`, `start:prod`.
