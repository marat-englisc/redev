# Что происходит в main.ts и что такое NestFactory

> [!NOTE]
> `main.ts` — точка входа (bootstrap): функция `bootstrap()` вызывает `NestFactory.create(AppModule)`, а затем `app.listen(port)`. **`NestFactory`** — фабрика, которая по корневому модулю строит **граф модулей**, создаёт DI-контейнер, инстанцирует провайдеры, регистрирует маршруты контроллеров, вызывает lifecycle hooks (`onModuleInit`, `onApplicationBootstrap`) и возвращает объект приложения (`INestApplication`). Между созданием и `listen` настраивают глобальное поведение: pipes, filters, interceptors, guards, префикс, CORS, версионирование, Swagger, shutdown hooks, Helmet. Помимо HTTP-приложения фабрика умеет `createMicroservice()` (транспорт без HTTP) и `createApplicationContext()` (только DI-контейнер — для CLI-скриптов, cron-воркеров, миграций).

## Вопрос

Что происходит в `main.ts` и как работает `NestFactory`?

## Типичный main.ts

```ts
import { NestFactory } from '@nestjs/core';
import { ValidationPipe, Logger } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';
import helmet from 'helmet';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule, { bufferLogs: true });

  const config = app.get(ConfigService);

  app.use(helmet());
  app.setGlobalPrefix('api');
  app.enableCors({ origin: config.getOrThrow<string>('CORS_ORIGIN').split(','), credentials: true });
  app.useGlobalPipes(new ValidationPipe({ whitelist: true, forbidNonWhitelisted: true, transform: true }));
  app.enableShutdownHooks();                       // SIGTERM → onModuleDestroy / beforeApplicationShutdown

  const port = config.get<number>('PORT', 3000);
  await app.listen(port, '0.0.0.0');
  Logger.log(`API listening on :${port}`, 'Bootstrap');
}

bootstrap();
```

## Что делает NestFactory.create

```text
1. Сканирует AppModule и рекурсивно все imports → граф модулей
2. Регистрирует провайдеры, контроллеры, экспорты
3. Разрешает зависимости и создаёт экземпляры (синглтоны)
4. Вызывает onModuleInit у провайдеров и модулей
5. Строит роутер из метаданных контроллеров (RoutesResolver)
6. Вызывает onApplicationBootstrap
7. Возвращает INestApplication
```

Если зависимость не найдена, приложение падает на этом этапе с `UnknownDependenciesException` — см. [почему NestJS не видит provider](<../03. Модули, провайдеры и Dependency Injection/11. Почему NestJS не видит provider.md>).

## Опции create

| Опция | Назначение |
| --- | --- |
| `logger` | Уровни логов или свой логгер (`['error', 'warn']`, `false`) |
| `bufferLogs` | Копить логи до подключения своего логгера (`app.useLogger(...)`) |
| `cors` | Включить CORS сразу |
| `bodyParser` | Отключить встроенный парсер (нужно, например, для Better Auth) |
| `rawBody` | Сохранять сырое тело для проверки подписей вебхуков (`req.rawBody`) |
| `abortOnError` | `false` — бросать ошибку вместо `process.exit` при сбое инициализации |

## Глобальные элементы: main.ts или модуль

```ts
// в main.ts — нет доступа к DI
app.useGlobalGuards(new RolesGuard(new Reflector()));

// через модуль — с DI
@Module({
  providers: [
    { provide: APP_GUARD, useClass: RolesGuard },
    { provide: APP_FILTER, useClass: AllExceptionsFilter },
    { provide: APP_INTERCEPTOR, useClass: LoggingInterceptor },
    { provide: APP_PIPE, useValue: new ValidationPipe({ whitelist: true }) },
  ],
})
export class AppModule {}
```

Регистрация через `APP_*` токены предпочтительна, когда глобальному элементу нужны зависимости, и она же работает в e2e-тестах, которые собирают модуль без `main.ts`.

## Другие режимы

```ts
// только DI-контейнер: скрипт, миграция данных, cron-процесс
const ctx = await NestFactory.createApplicationContext(AppModule);
const users = ctx.get(UsersService);
await users.recalculateStats();
await ctx.close();

// микросервис без HTTP
const ms = await NestFactory.createMicroservice(AppModule, { transport: Transport.REDIS, options: { host: 'redis' } });
await ms.listen();
```

## Частые ошибки

- Настроить глобальный pipe/filter только в `main.ts` и удивляться, что в e2e-тестах его нет.
- Читать `process.env` в `main.ts` вместо `ConfigService`.
- Забыть `enableShutdownHooks()` — соединения не закрываются при остановке контейнера.
- Слушать только `localhost` в Docker.

## Что важно помнить

- `NestFactory.create` строит граф модулей и DI-контейнер.
- Глобальная настройка — между `create` и `listen`.
- Глобальные элементы с зависимостями — через `APP_GUARD`/`APP_PIPE`/... в модуле.

## Мини-шпаргалка

- `NestFactory.create(AppModule, options)`.
- `app.useGlobalPipes/Filters/Interceptors/Guards`.
- `app.enableShutdownHooks()`.
- `createApplicationContext` — без HTTP.
- `createMicroservice` — транспорт без HTTP.
