# Что такое NestJS

> [!NOTE]
> **NestJS** — фреймворк для серверных приложений на Node.js и TypeScript, который задаёт **архитектуру**: приложение собирается из **модулей**, бизнес-логика живёт в **провайдерах** (сервисах), HTTP-слой — в **контроллерах**, а зависимости связывает встроенный **DI-контейнер**. Сквозную логику выносят в стандартные «точки расширения» запроса: middleware, guards, interceptors, pipes, exception filters. Под капотом Nest работает поверх HTTP-фреймворка (Express по умолчанию или Fastify) и не заменяет его, а добавляет структуру. Плюс — предсказуемая организация кода в больших командах, тестируемость через DI и готовые интеграции (конфиг, ORM, очереди, WebSockets, GraphQL, микросервисы, OpenAPI). Минусы — порог входа (декораторы, DI, много «церемоний») и избыточность для маленьких сервисов. Актуальная версия — **NestJS 12**.

## Вопрос

Что такое NestJS и какие задачи он решает?

## Минимальное приложение

```ts
// cats.service.ts
@Injectable()
export class CatsService {
  private readonly cats = [{ id: 1, name: 'Tom' }];

  findAll() {
    return this.cats;
  }
}

// cats.controller.ts
@Controller('cats')
export class CatsController {
  constructor(private readonly catsService: CatsService) {}   // DI

  @Get()
  findAll() {
    return this.catsService.findAll();                         // объект → JSON
  }
}

// cats.module.ts
@Module({
  controllers: [CatsController],
  providers: [CatsService],
})
export class CatsModule {}

// main.ts
const app = await NestFactory.create(AppModule);
await app.listen(3000);
```

`GET /cats` → `[{ "id": 1, "name": "Tom" }]`.

## Строительные блоки

| Блок | Роль |
| --- | --- |
| Module | Группирует фичу: контроллеры, провайдеры, импорты и экспорты |
| Controller | Принимает HTTP-запрос, вызывает сервис, возвращает ответ |
| Provider / Service | Бизнес-логика, доступ к данным, интеграции |
| Middleware | Код до роутинга (логирование, `cookie-parser`) |
| Guard | Можно ли выполнить запрос (auth, роли) |
| Pipe | Валидация и преобразование входных данных |
| Interceptor | Логика вокруг обработчика (трансформация ответа, тайминги, кеш) |
| Exception filter | Превращение ошибок в HTTP-ответы |

## Что даёт фреймворк

- Единую структуру проекта — новый разработчик быстро находит нужный код.
- DI — сервисы легко подменять в тестах и переиспользовать.
- Декларативность — роли, валидация, документация описываются декораторами.
- Экосистему: `@nestjs/config`, TypeORM/Prisma, `@nestjs/swagger`, `@nestjs/bullmq`, `@nestjs/websockets`, `@nestjs/graphql`, `@nestjs/microservices`, `@nestjs/terminus`.
- Транспортную независимость: одни и те же сервисы работают за HTTP, WebSocket, GraphQL или очередью.

## Когда NestJS — хороший выбор

| Подходит | Избыточен |
| --- | --- |
| Средние и крупные API, несколько команд | Небольшой сервис из пары эндпоинтов |
| Долгоживущий проект, важна поддерживаемость | Прототип «на выходные» |
| Команда знакома с Angular / Spring / DI | Serverless-функции с жёстким холодным стартом |

## Частые ошибки

- Считать NestJS заменой Express — это слой поверх него.
- Писать бизнес-логику в контроллерах.
- Тянуть Nest в крошечный сервис, где хватило бы Fastify или Hono.

## Что важно помнить

- NestJS = архитектура + DI поверх Express/Fastify.
- Основа — модули, контроллеры и провайдеры.
- Сквозная логика — в guards, pipes, interceptors, filters.

## Мини-шпаргалка

- `@Module`, `@Controller`, `@Injectable`.
- `NestFactory.create(AppModule)`.
- Express по умолчанию, Fastify — через адаптер.
- Текущая версия — NestJS 12.
