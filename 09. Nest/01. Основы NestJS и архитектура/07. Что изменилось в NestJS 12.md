# Что изменилось в NestJS 12

> [!NOTE]
> **NestJS 12** — текущая мажорная версия. Главное: **core-пакеты стали ESM-only** (CommonJS-приложения продолжают работать через `require(esm)` в современных Node.js, переводить свой код на ESM не обязательно); минимальный Node.js — **20.19+ / 22.12+** (CLI — 22.22.3+ / 24.15+ / 26+); новые проекты по умолчанию тестируются **Vitest**; появилась встроенная **валидация через Standard Schema** — `StandardSchemaValidationPipe` и опция `@Body({ schema })` для Zod, Valibot, ArkType, а `ConfigModule` принимает Standard Schema в `validationSchema`; **lifecycle hooks** выполняются по уровням иерархии компонентов (порядок мог измениться); логгер по умолчанию пишет **структурированные параметры**; в Terminus удалён старый `HealthIndicator` в пользу `HealthIndicatorService`; GraphQL-подписки — только `graphql-ws`; NATS-транспорт — на NATS v3.

## Вопрос

Что изменилось в NestJS 12 и на что обратить внимание при обновлении?

## Основные изменения

| Область | Что изменилось |
| --- | --- |
| Модули | Core-пакеты — ESM-only; CommonJS-приложения работают через `require(esm)` |
| Node.js | Runtime: 20.19+ или 22.12+; CLI и schematics: 22.22.3+, 24.15+ или 26+ |
| Тесты | Vitest по умолчанию в новых ESM-проектах; Jest требует Node 24.9+ для загрузки ESM-пакетов |
| Валидация | `StandardSchemaValidationPipe`, `@Body({ schema })`, `@Query({ schema })`, `@Param('id', { schema })` |
| Конфигурация | `validationSchema` — Standard Schema; Joi нужен v18+, опции Joi — в `validationOptions.libraryOptions` |
| Lifecycle hooks | Порядок по уровням иерархии компонентов |
| `@Optional()` | Наследник, переобъявивший конструктор, не наследует optional-маркеры родителя |
| Логирование | Структурированные параметры по умолчанию (`structuredParams: false` — старое поведение) |
| Terminus | `HealthIndicator`/`HealthCheckError` удалены → `HealthIndicatorService` |
| GraphQL | Удалён `subscriptions-transport-ws`, используйте `graphql-ws` |
| Микросервисы | NATS v3, пакет `@nats-io/transport-node` |
| Сборка | Флаги webpack устарели, рекомендуется `--builder rspack` |
| Pipes | Уточнены сигнатуры `transform` и `ArgumentMetadata` — кастомным пайпам может понадобиться правка типов |

## Валидация через Standard Schema

```ts
// main.ts
app.useGlobalPipes(new StandardSchemaValidationPipe());

// controller
const createUserSchema = z.object({ email: z.email(), name: z.string().min(2) });
type CreateUserDto = z.infer<typeof createUserSchema>;

@Post()
create(@Body({ schema: createUserSchema }) dto: CreateUserDto) {
  return this.usersService.create(dto);
}
```

## Конфигурация через Zod

```ts
ConfigModule.forRoot({
  isGlobal: true,
  validationSchema: z.object({
    NODE_ENV: z.enum(['development', 'production', 'test']).default('development'),
    PORT: z.coerce.number().default(3000),
    DATABASE_URL: z.url(),
  }),
});
```

## Чек-лист обновления с v11

1. Обновить Node.js до поддерживаемой версии в CI, Docker-образах и локально.
2. Обновить все `@nestjs/*` пакеты одновременно на одну мажорную версию.
3. Проверить тестовый раннер: перейти на Vitest или обновить Node для Jest.
4. Проверить кастомные pipes (типы), health checks (Terminus), GraphQL-подписки, NATS.
5. Проверить порядок `onModuleInit`/`onApplicationBootstrap`, если код на него полагался.
6. Если логи парсятся системой сбора — проверить новый формат структурированных параметров.
7. Прогнать e2e-тесты.

## Частые ошибки

- Обновить только `@nestjs/core`, оставив другие `@nestjs/*` на v11.
- Забыть обновить Node.js в Dockerfile и CI.
- Полагаться на порядок инициализации провайдеров между модулями.

## Что важно помнить

- NestJS 12 — ESM-пакеты, новый минимальный Node.js, Vitest.
- Встроенная валидация Standard Schema делает Zod «первоклассным гражданином».
- Обновление — через официальный migration guide и прогон тестов.

## Мини-шпаргалка

- `StandardSchemaValidationPipe` + `@Body({ schema })`.
- `ConfigModule.forRoot({ validationSchema: zodSchema })`.
- `HealthIndicatorService` вместо `HealthIndicator`.
- `structuredParams: false` — старый формат логов.
