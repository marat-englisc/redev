# Что такое pipe в NestJS

> [!NOTE]
> **Pipe** — класс с методом `transform(value, metadata)`, который Nest вызывает **для аргумента обработчика непосредственно перед** вызовом метода контроллера. У pipe две задачи: **преобразование** (строку `'42'` в число, строку в `Date`, объект в экземпляр DTO) и **валидация** (данные некорректны → исключение, обычно `BadRequestException`, и обработчик не вызывается). Pipes подключаются на уровне **параметра** (`@Param('id', ParseIntPipe)`), **метода** или **контроллера** (`@UsePipes`) и **глобально** (`app.useGlobalPipes` или `APP_PIPE`). Pipe получает `metadata`: тип источника (`body`, `query`, `param`, `custom`), имя поля и `metatype` — класс, указанный в аннотации типа параметра, по которому `ValidationPipe` понимает, какой DTO применять. В NestJS 12 метаданные содержат и `schema` — Standard Schema, переданную через `@Body({ schema })`.

## Вопрос

Что такое pipe в NestJS и как работают пайпы?

## Где в конвейере

```text
Middleware → Guards → Interceptors (до) → Pipes → Handler → Interceptors (после)
```

Pipes выполняются после guards: неавторизованный запрос не дойдёт до валидации тела.

## Уровни подключения

```ts
// параметр
@Get(':id')
findOne(@Param('id', ParseIntPipe) id: number) {}

// параметр с экземпляром и опциями
@Get(':id')
findOne(@Param('id', new ParseUUIDPipe({ version: '4' })) id: string) {}

// метод / контроллер
@UsePipes(new ValidationPipe({ transform: true }))
@Post()
create(@Body() dto: CreateDto) {}

// глобально
app.useGlobalPipes(new ValidationPipe({ whitelist: true, transform: true }));
// или с DI
{ provide: APP_PIPE, useClass: ValidationPipe }
```

## Свой pipe

```ts
@Injectable()
export class ParseObjectIdPipe implements PipeTransform<string, string> {
  transform(value: string, metadata: ArgumentMetadata): string {
    if (!/^[a-f\d]{24}$/i.test(value)) {
      throw new BadRequestException(`${metadata.data ?? 'value'} must be a valid ObjectId`);
    }
    return value;
  }
}

@Get(':id')
findOne(@Param('id', ParseObjectIdPipe) id: string) {}
```

```ts
// трансформирующий pipe с зависимостью: id → сущность
@Injectable()
export class UserByIdPipe implements PipeTransform<string, Promise<User>> {
  constructor(private readonly users: UsersService) {}
  async transform(id: string) {
    return this.users.findOneOrFail(id);       // NotFoundException, если нет
  }
}

@Get(':id')
findOne(@Param('id', UserByIdPipe) user: User) {}
```

## ArgumentMetadata

| Поле | Значение |
| --- | --- |
| `type` | `'body' \| 'query' \| 'param' \| 'custom'` |
| `metatype` | Класс из аннотации типа (`CreateUserDto`), `undefined` для интерфейсов |
| `data` | Имя поля: `'id'` в `@Param('id')` |
| `schema` | Standard Schema из `@Body({ schema })` (NestJS 12) |

## Pipe или guard или interceptor

| Задача | Инструмент |
| --- | --- |
| Валидировать и преобразовать аргумент | Pipe |
| Решить, разрешён ли запрос | Guard |
| Изменить ответ, замерить время, кешировать | Interceptor |

## Частые ошибки

- Ожидать, что pipe сработает для интерфейса-DTO (`metatype` будет `Object`).
- Тяжёлые запросы к БД в pipe для каждого параметра.
- Глобальный pipe только в `main.ts` — в e2e-тестах его нет.
- Бросать `Error` вместо HTTP-исключения — клиент получит 500.

## Что важно помнить

- Pipe = преобразование + валидация аргумента до вызова обработчика.
- Уровни: параметр, метод/контроллер, глобально.
- Ошибка в pipe — исключение, обработчик не вызывается.

## Мини-шпаргалка

- `implements PipeTransform` → `transform(value, metadata)`.
- `@Param('id', ParseIntPipe)`.
- `@UsePipes(...)`, `app.useGlobalPipes(...)`, `APP_PIPE`.
- Исключение → 400.
