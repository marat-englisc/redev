# Как использовать class-validator и class-transformer

> [!NOTE]
> **`class-validator`** проверяет экземпляр класса по декораторам свойств: типы (`@IsString`, `@IsInt`, `@IsBoolean`, `@IsDate`), форматы (`@IsEmail`, `@IsUUID`, `@IsUrl`, `@Matches`), ограничения (`@Length`, `@Min`, `@Max`, `@ArrayMaxSize`), перечисления (`@IsIn`, `@IsEnum`), опциональность (`@IsOptional`), условия (`@ValidateIf`) и вложенность (`@ValidateNested`). **`class-transformer`** превращает plain-объект в экземпляр класса и обратно: `@Type(() => X)` — тип вложенного объекта или приведение примитива, `@Transform()` — произвольное преобразование значения (trim, lowercase, парсинг boolean), `@Exclude`/`@Expose` — управление полями при сериализации. В NestJS обе библиотеки работают через `ValidationPipe`. Для правил, которых нет из коробки, пишут **свой декоратор** через `registerDecorator` или класс `ValidatorConstraint` (в том числе асинхронный, с DI).

## Вопрос

Как описывать валидацию и трансформацию DTO через `class-validator` и `class-transformer`?

## Основные декораторы

```ts
export class CreateEventDto {
  @IsString() @Transform(({ value }) => value?.trim()) @Length(3, 120)
  title: string;

  @IsOptional() @IsString() @MaxLength(5000)
  description?: string;

  @IsDateString()                         // ISO 8601 строка
  startsAt: string;

  @Type(() => Date) @IsDate() @MinDate(() => new Date())
  registrationDeadline: Date;

  @IsInt() @Min(1) @Max(10_000)
  capacity: number;

  @IsEnum(EventType)
  type: EventType;

  @IsArray() @ArrayMaxSize(10) @IsString({ each: true })
  tags: string[] = [];

  @ValidateIf((o) => o.type === EventType.Online)
  @IsUrl({ require_protocol: true })
  streamUrl?: string;

  @ValidateNested() @Type(() => AddressDto)
  @ValidateIf((o) => o.type === EventType.Offline)
  address?: AddressDto;
}
```

| Группа | Декораторы |
| --- | --- |
| Типы | `@IsString`, `@IsInt`, `@IsNumber`, `@IsBoolean`, `@IsDate`, `@IsArray`, `@IsObject` |
| Форматы | `@IsEmail`, `@IsUUID`, `@IsUrl`, `@IsDateString`, `@IsPhoneNumber`, `@Matches(regex)` |
| Длина и диапазон | `@Length`, `@MinLength`, `@MaxLength`, `@Min`, `@Max`, `@IsPositive` |
| Массивы | `@ArrayMinSize`, `@ArrayMaxSize`, `@ArrayUnique`, `{ each: true }` |
| Значения | `@IsIn([...])`, `@IsEnum(E)`, `@Equals`, `@IsNotEmpty` |
| Логика | `@IsOptional`, `@ValidateIf`, `@ValidateNested` |

## Трансформации

```ts
export class SignupDto {
  @Transform(({ value }) => (typeof value === 'string' ? value.trim().toLowerCase() : value))
  @IsEmail()
  email: string;

  @Transform(({ value }) => value === 'true' || value === true)   // boolean из query/form-data
  @IsBoolean()
  marketing: boolean;
}
```

Декораторы `@Transform` применяются до валидации (на этапе `plainToInstance`).

## Свой валидатор

```ts
export function IsStrongPassword(options?: ValidationOptions) {
  return (object: object, propertyName: string) =>
    registerDecorator({
      name: 'isStrongPassword',
      target: object.constructor,
      propertyName,
      options: { message: 'password is too weak', ...options },
      validator: {
        validate: (v: unknown) => typeof v === 'string' && v.length >= 10 && /\d/.test(v) && /[A-Z]/.test(v),
      },
    });
}
```

```ts
// сравнение полей
@ValidatorConstraint({ name: 'matchField' })
export class MatchField implements ValidatorConstraintInterface {
  validate(value: unknown, args: ValidationArguments) {
    return value === (args.object as any)[args.constraints[0]];
  }
  defaultMessage(args: ValidationArguments) {
    return `${args.property} must match ${args.constraints[0]}`;
  }
}

class ChangePasswordDto {
  @IsStrongPassword() password: string;
  @Validate(MatchField, ['password']) confirmPassword: string;
}
```

Асинхронные валидаторы с DI (например, «email не занят») возможны через `useContainer(app.select(AppModule), { fallbackOnErrors: true })`, но проверку уникальности надёжнее делать в сервисе + уникальным индексом: валидатор не защищает от гонки двух запросов.

## Сообщения

```ts
@Length(2, 100, { message: 'Имя должно быть от $constraint1 до $constraint2 символов' })
name: string;
```

## Частые ошибки

- `@IsOptional()` не пропускает пустую строку `''` — она проверяется остальными декораторами.
- Вложенный объект без `@Type` — `@ValidateNested` ничего не проверяет.
- `@IsNumber()` для query без `@Type(() => Number)`.
- Порядок ожиданий: `@Transform` выполняется до валидации, а не после.
- Проверка уникальности email в валидаторе вместо БД.

## Что важно помнить

- `class-validator` — правила, `class-transformer` — превращение в экземпляры и типы.
- Вложенность: `@ValidateNested` + `@Type`.
- Свои правила — `registerDecorator` или `ValidatorConstraint`.

## Мини-шпаргалка

- `@IsString() @Length(a, b)`, `@IsInt() @Min() @Max()`.
- `@IsOptional()`, `@ValidateIf(fn)`.
- `@Type(() => Dto)`, `@Transform(({ value }) => ...)`.
- `{ each: true }` для массивов.
