# Что такое exception filter

> [!NOTE]
> **Exception filter** — класс с методом `catch(exception, host)`, который перехватывает исключения, выброшенные в любом месте обработки запроса (guards, pipes, interceptors, контроллер, сервисы), и формирует ответ. У Nest есть встроенный глобальный filter: он превращает `HttpException` в JSON со статусом, а остальные ошибки — в 500. Свой filter помечается `@Catch(ТипИсключения)` — тогда он ловит только этот тип (и наследников) — или `@Catch()` без аргументов, чтобы ловить всё. Подключение: на метод или контроллер (`@UseFilters`), глобально (`app.useGlobalFilters` или `{ provide: APP_FILTER }` — второй вариант поддерживает DI). Через `ArgumentsHost` filter работает с разными контекстами (HTTP, WebSocket, RPC), а через `HttpAdapterHost` — с любой платформой. Filters вызываются от наиболее специфичного уровня к глобальному; первым подходящим будет обработано исключение.

## Вопрос

Что такое exception filter и как его написать?

## Filter для HttpException

```ts
@Catch(HttpException)
export class HttpExceptionFilter implements ExceptionFilter {
  catch(exception: HttpException, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const res = ctx.getResponse<Response>();
    const req = ctx.getRequest<Request>();
    const status = exception.getStatus();

    res.status(status).json({
      statusCode: status,
      message: exception.message,
      path: req.url,
      timestamp: new Date().toISOString(),
    });
  }
}
```

## Catch-all, независимый от платформы

```ts
@Catch()
export class AllExceptionsFilter implements ExceptionFilter {
  private readonly logger = new Logger(AllExceptionsFilter.name);

  constructor(private readonly adapterHost: HttpAdapterHost) {}

  catch(exception: unknown, host: ArgumentsHost) {
    const { httpAdapter } = this.adapterHost;
    const ctx = host.switchToHttp();

    const status = exception instanceof HttpException ? exception.getStatus() : HttpStatus.INTERNAL_SERVER_ERROR;
    if (status >= 500) this.logger.error(exception);

    httpAdapter.reply(ctx.getResponse(), {
      statusCode: status,
      message: exception instanceof HttpException ? exception.getResponse() : 'Internal server error',
      path: httpAdapter.getRequestUrl(ctx.getRequest()),
    }, status);
  }
}
```

## Подключение

```ts
// метод или контроллер
@UseFilters(HttpExceptionFilter)
@Controller('orders')
export class OrdersController {}

// глобально с DI
@Module({ providers: [{ provide: APP_FILTER, useClass: AllExceptionsFilter }] })
export class AppModule {}
```

Несколько `APP_FILTER`: более специфичные (`@Catch(PrismaClientKnownRequestError)`) регистрируют **после** общих — Nest проверяет глобальные фильтры в обратном порядке регистрации.

## Расширение встроенного

```ts
@Catch()
export class SentryFilter extends BaseExceptionFilter {
  catch(exception: unknown, host: ArgumentsHost) {
    Sentry.captureException(exception);
    super.catch(exception, host);           // стандартный ответ Nest
  }
}
// app.useGlobalFilters(new SentryFilter(app.get(HttpAdapterHost).httpAdapter));
```

## Контексты

```ts
catch(exception: unknown, host: ArgumentsHost) {
  switch (host.getType()) {
    case 'http': /* res.status().json() */ break;
    case 'ws':   host.switchToWs().getClient().emit('exception', { message: '...' }); break;
    case 'rpc':  return throwError(() => new RpcException('...'));
  }
}
```

## Filter, interceptor или try/catch

| Задача | Инструмент |
| --- | --- |
| Единый формат всех ошибок | Глобальный filter |
| Перевод ошибок ORM/домена в HTTP | Filter на тип исключения |
| Повтор, fallback, таймаут | Interceptor (`catchError`, `retry`) |
| Конкретная ожидаемая ошибка в сервисе | `try/catch` в сервисе |

## Частые ошибки

- `@Catch()` без логирования 500 — ошибки «пропадают».
- Отдавать клиенту `exception.stack` или текст ошибки БД.
- Глобальный filter через `useGlobalFilters` без доступа к DI, когда нужен логгер/конфиг.
- Использовать Express-объекты в filter, который должен работать и с Fastify.

## Что важно помнить

- Filter перехватывает исключения всего конвейера запроса.
- `@Catch(Type)` — конкретные ошибки, `@Catch()` — все.
- Глобальные filters с DI — через `APP_FILTER`.

## Мини-шпаргалка

- `@Catch(X) class F implements ExceptionFilter { catch(e, host) {} }`.
- `host.switchToHttp().getResponse()`.
- `HttpAdapterHost` — платформенно-независимый ответ.
- `BaseExceptionFilter` — расширить стандартное поведение.
