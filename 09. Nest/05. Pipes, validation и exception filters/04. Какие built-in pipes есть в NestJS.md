# Какие built-in pipes есть в NestJS

> [!NOTE]
> В `@nestjs/common` есть готовые пайпы: **`ValidationPipe`** (DTO на `class-validator`), **`StandardSchemaValidationPipe`** (NestJS 12: схемы Zod, Valibot, ArkType через опцию `schema` декораторов), парсеры примитивов **`ParseIntPipe`**, **`ParseFloatPipe`**, **`ParseBoolPipe`**, **`ParseUUIDPipe`**, **`ParseEnumPipe`**, **`ParseDatePipe`**, **`ParseArrayPipe`**, **`DefaultValuePipe`** (подставить значение при `undefined`) и **`ParseFilePipe`** (валидация загружаемых файлов). Парсеры при неверном значении бросают 400 (статус меняется опцией `errorHttpStatusCode`), а при отсутствующем значении — тоже ошибку, если не указать `optional: true` или не поставить перед ними `DefaultValuePipe`. Порядок нескольких pipes в одном параметре важен: они выполняются **слева направо**.

## Вопрос

Какие встроенные pipes есть в NestJS и как их использовать?

## Обзор

| Pipe | Что делает | Пример |
| --- | --- | --- |
| `ValidationPipe` | Валидирует DTO через `class-validator` | `@Body() dto: CreateDto` |
| `StandardSchemaValidationPipe` | Валидирует по Standard Schema | `@Body({ schema }) dto` |
| `ParseIntPipe` | Строка → целое | `@Param('id', ParseIntPipe)` |
| `ParseFloatPipe` | Строка → число | `@Query('lat', ParseFloatPipe)` |
| `ParseBoolPipe` | `'true'`/`'false'` → boolean | `@Query('active', ParseBoolPipe)` |
| `ParseUUIDPipe` | Проверка UUID (версия опционально) | `@Param('id', ParseUUIDPipe)` |
| `ParseEnumPipe` | Значение из enum | `@Query('status', new ParseEnumPipe(Status))` |
| `ParseDatePipe` | Строка → `Date` | `@Query('from', ParseDatePipe)` |
| `ParseArrayPipe` | Строка `'a,b'` или массив → массив, валидация элементов | `@Query('ids', new ParseArrayPipe({ items: Number }))` |
| `DefaultValuePipe` | Значение по умолчанию | `@Query('page', new DefaultValuePipe(1), ParseIntPipe)` |
| `ParseFilePipe` | Валидация файла (размер, тип) | `@UploadedFile(new ParseFilePipe({...}))` |

## Примеры

```ts
@Get()
list(
  @Query('page', new DefaultValuePipe(1), ParseIntPipe) page: number,
  @Query('status', new ParseEnumPipe(OrderStatus, { optional: true })) status?: OrderStatus,
  @Query('ids', new ParseArrayPipe({ items: Number, separator: ',', optional: true })) ids?: number[],
  @Query('from', new ParseDatePipe({ optional: true })) from?: Date,
  @Query('withDeleted', new DefaultValuePipe(false), ParseBoolPipe) withDeleted?: boolean,
) {}

@Get(':id')
findOne(@Param('id', new ParseUUIDPipe({ version: '4', errorHttpStatusCode: HttpStatus.NOT_FOUND })) id: string) {}
```

`GET /orders?ids=1,2,3&status=paid&page=2` → `ids = [1, 2, 3]`, `status = 'paid'`, `page = 2`.

## ParseArrayPipe для тела

```ts
@Post('bulk')
createMany(
  @Body(new ParseArrayPipe({ items: CreateProductDto, whitelist: true, forbidNonWhitelisted: true }))
  dtos: CreateProductDto[],
) {}
```

`ValidationPipe` сам по себе не валидирует элементы массива верхнего уровня — для этого и нужен `ParseArrayPipe` с `items`.

## StandardSchemaValidationPipe

```ts
app.useGlobalPipes(new StandardSchemaValidationPipe());

const idSchema = z.coerce.number().int().positive();

@Get(':id')
findOne(@Param('id', { schema: idSchema }) id: number) {}
```

## Общие опции парсеров

| Опция | Назначение |
| --- | --- |
| `errorHttpStatusCode` | Статус при ошибке (по умолчанию 400) |
| `exceptionFactory` | Своё исключение |
| `optional` | Пропускать `undefined` / `null` |

## Порядок pipes

```ts
// ✓ сначала подставить значение, потом парсить
@Query('limit', new DefaultValuePipe(20), ParseIntPipe) limit: number

// ✗ ParseIntPipe получит undefined и бросит 400
@Query('limit', ParseIntPipe, new DefaultValuePipe(20)) limit: number
```

## Частые ошибки

- `ParseIntPipe` для необязательного query без `DefaultValuePipe` или `optional`.
- `ParseBoolPipe` ожидает именно `'true'`/`'false'` — `'1'`/`'yes'` дадут 400.
- Десятки парсеров в одном методе вместо query DTO.
- Ожидать, что `ValidationPipe` проверит `@Body() dtos: Dto[]`.

## Что важно помнить

- Для примитивов — `Parse*Pipe`, для объектов — `ValidationPipe` или Standard Schema.
- Pipes в параметре выполняются слева направо.
- `optional` и `DefaultValuePipe` — для необязательных значений.

## Мини-шпаргалка

- `ParseIntPipe`, `ParseUUIDPipe`, `ParseEnumPipe(E)`, `ParseDatePipe`.
- `new DefaultValuePipe(x), ParseIntPipe`.
- `new ParseArrayPipe({ items: Dto | Number, separator: ',' })`.
- `errorHttpStatusCode`, `optional`.
