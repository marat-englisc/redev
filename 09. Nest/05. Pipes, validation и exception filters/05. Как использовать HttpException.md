# Как использовать HttpException

> [!NOTE]
> `HttpException` — базовый класс исключений, которые встроенный exception filter Nest превращает в HTTP-ответ с нужным статусом. Конструктор принимает **ответ** (строку или объект) и **статус**, а третьим аргументом — опции `{ cause, description }` (`cause` сохраняет исходную ошибку для логов, но не отправляется клиенту). Для частых случаев есть готовые подклассы: `BadRequestException` (400), `UnauthorizedException` (401), `ForbiddenException` (403), `NotFoundException` (404), `ConflictException` (409), `GoneException` (410), `PayloadTooLargeException` (413), `UnprocessableEntityException` (422), `InternalServerErrorException` (500), `ServiceUnavailableException` (503) и др. Любое исключение, **не** унаследованное от `HttpException`, превращается в 500 с сообщением `Internal server error` — детали не утекают клиенту. Доменные ошибки удобно оформлять своими классами и переводить в HTTP в одном месте.

## Вопрос

Как работать с `HttpException` и встроенными HTTP-исключениями?

## Базовое использование

```ts
async findOne(id: string) {
  const order = await this.repo.findById(id);
  if (!order) throw new NotFoundException(`Order ${id} not found`);
  return order;
}
```

```json
{ "statusCode": 404, "message": "Order 42 not found", "error": "Not Found" }
```

## Свой ответ и cause

```ts
throw new ConflictException(
  { code: 'EMAIL_TAKEN', message: 'Email already registered', field: 'email' },
  { cause: prismaError, description: 'Unique constraint on users.email' },
);

throw new HttpException({ code: 'PAYMENT_REQUIRED', message: 'Subscription expired' }, HttpStatus.PAYMENT_REQUIRED);
```

Если передать объект, он станет телом ответа целиком.

## Встроенные исключения

| Класс | Статус | Когда |
| --- | --- | --- |
| `BadRequestException` | 400 | Некорректный ввод |
| `UnauthorizedException` | 401 | Нет или невалидна аутентификация |
| `ForbiddenException` | 403 | Аутентифицирован, но нет прав |
| `NotFoundException` | 404 | Ресурса нет (или скрываем его) |
| `ConflictException` | 409 | Конфликт состояния: дубль, версия |
| `UnprocessableEntityException` | 422 | Бизнес-правило нарушено |
| `PayloadTooLargeException` | 413 | Слишком большое тело или файл |
| `InternalServerErrorException` | 500 | Явный внутренний сбой |
| `ServiceUnavailableException` | 503 | Зависимость недоступна |

## Доменные ошибки

```ts
// domain/errors.ts — без зависимости от HTTP
export class DomainError extends Error {}
export class InsufficientStockError extends DomainError {
  constructor(public readonly productId: string) { super(`Insufficient stock for ${productId}`); }
}

// сервис бросает доменную ошибку
if (product.stock < qty) throw new InsufficientStockError(product.id);

// фильтр переводит в HTTP
@Catch(InsufficientStockError)
export class DomainErrorFilter implements ExceptionFilter {
  catch(e: InsufficientStockError, host: ArgumentsHost) {
    host.switchToHttp().getResponse<Response>().status(422).json({ code: 'INSUFFICIENT_STOCK', productId: e.productId });
  }
}
```

Так сервис можно вызывать из очереди или CLI, а HTTP-детали живут в одном месте.

## Ошибки ORM

```ts
try {
  return await this.prisma.user.create({ data });
} catch (e) {
  if (e instanceof Prisma.PrismaClientKnownRequestError && e.code === 'P2002') {
    throw new ConflictException('Email already registered', { cause: e });
  }
  throw e;
}
```

Или централизованно — фильтром для `PrismaClientKnownRequestError` (P2002 → 409, P2025 → 404).

## Не-HTTP исключения

```ts
throw new Error('boom');   // → 500 { "statusCode": 500, "message": "Internal server error" }
```

Встроенный filter логирует такую ошибку и скрывает детали от клиента.

## Частые ошибки

- `throw new HttpException('Not found', 400)` — статус не соответствует смыслу.
- Возвращать `{ error: ... }` с кодом 200 вместо исключения.
- Передавать в сообщение клиенту детали БД, стек или SQL.
- Бросать HTTP-исключения глубоко в доменном коде, который используется не только из HTTP.

## Что важно помнить

- `HttpException` и подклассы → ответ с нужным статусом.
- Не-HTTP исключения → 500 без деталей.
- `cause` — для логов, не для клиента.

## Мини-шпаргалка

- `throw new NotFoundException(msg)`.
- `new HttpException(body, status, { cause })`.
- Prisma P2002 → 409, P2025 → 404.
- Доменные ошибки → свой filter.
