# Как работает ValidationPipe

> [!NOTE]
> `ValidationPipe` — встроенный pipe, который по классу DTO из аннотации типа параметра (`metatype`) превращает пришедший plain-объект в экземпляр класса (`class-transformer`, `plainToInstance`) и проверяет его декораторами `class-validator`. При ошибках он бросает `BadRequestException` со списком сообщений. Ключевые опции: **`whitelist: true`** — удалить свойства без декораторов; **`forbidNonWhitelisted: true`** — вместо удаления вернуть ошибку; **`transform: true`** — передать в обработчик экземпляр DTO с преобразованными типами (и привести примитивы `@Param('id') id: number`); `transformOptions.enableImplicitConversion` — неявное приведение по TS-типам (удобно, но с подвохами); `stopAtFirstError`, `exceptionFactory` (свой формат ошибок), `validateCustomDecorators`, `disableErrorMessages` (для проды без деталей). Пакеты `class-validator` и `class-transformer` устанавливаются отдельно.

## Вопрос

Как работает `ValidationPipe` и какие опции важны?

## Установка и подключение

```bash
npm install class-validator class-transformer
```

```ts
app.useGlobalPipes(
  new ValidationPipe({
    whitelist: true,
    forbidNonWhitelisted: true,
    transform: true,
    transformOptions: { enableImplicitConversion: false },
  }),
);
```

## Что происходит

```text
body: { "email": "a@b.co", "name": "Ann", "role": "admin" }
  │  metatype = CreateUserDto
  ▼
plainToInstance(CreateUserDto, body)        ← @Transform, @Type
  ▼
validate(instance, { whitelist, forbidNonWhitelisted })
  ├─ ошибки → BadRequestException(messages)
  └─ ok     → handler(instance)               (если transform: true)
```

С `forbidNonWhitelisted` поле `role` вызовет ошибку `property role should not exist`.

## Ответ при ошибке

```json
{
  "statusCode": 400,
  "message": ["email must be an email", "name must be longer than or equal to 2 characters"],
  "error": "Bad Request"
}
```

## Опции

| Опция | Эффект |
| --- | --- |
| `whitelist` | Удалить поля без декораторов валидации |
| `forbidNonWhitelisted` | Ошибка при лишних полях |
| `transform` | Отдавать экземпляр DTO, приводить примитивы параметров |
| `transformOptions.enableImplicitConversion` | Приводить типы по TS-аннотациям без `@Type` |
| `skipMissingProperties` | Не проверять отсутствующие поля |
| `stopAtFirstError` | Одна ошибка на поле |
| `exceptionFactory` | Свой формат исключения |
| `disableErrorMessages` | Не раскрывать детали |
| `groups` | Группы валидации |
| `validateCustomDecorators` | Проверять аргументы своих param-декораторов |

## Свой формат ошибок

```ts
new ValidationPipe({
  whitelist: true,
  transform: true,
  exceptionFactory: (errors) =>
    new BadRequestException({
      message: 'Validation failed',
      details: flatten(errors).map((e) => ({ field: e.path, messages: Object.values(e.constraints ?? {}) })),
    }),
});

function flatten(errors: ValidationError[], parent = ''): { path: string; constraints?: Record<string, string> }[] {
  return errors.flatMap((e) => {
    const path = parent ? `${parent}.${e.property}` : e.property;
    return [{ path, constraints: e.constraints }, ...flatten(e.children ?? [], path)].filter((x) => x.constraints);
  });
}
```

## Подводные камни enableImplicitConversion

```ts
class Query {
  @IsBoolean() active: boolean;   // '?active=false' → Boolean('false') === true
  @IsInt() page: number;          // '?page=abc' → NaN → ошибка IsInt (это хорошо)
}
```

Для boolean из query нужна явная трансформация (`@Transform(({ value }) => value === 'true')`), поэтому многие держат `enableImplicitConversion: false` и пишут `@Type(() => Number)` явно.

## Массивы и вложенные объекты

```ts
class CreateOrderDto {
  @ValidateNested({ each: true })
  @Type(() => OrderItemDto)                // без @Type вложенный объект не станет экземпляром и не проверится
  @ArrayMinSize(1) @ArrayMaxSize(50)
  items: OrderItemDto[];
}
```

`ValidationPipe` не проверяет массив DTO на верхнем уровне (`@Body() dtos: Dto[]`) — нужен `ParseArrayPipe({ items: Dto })`.

## Частые ошибки

- DTO-интерфейс или `any` — валидация не выполняется.
- Нет `whitelist` — клиент передаёт `role`, `isAdmin`, и ORM их сохраняет.
- Вложенный DTO без `@Type()`.
- Ожидать, что без `transform: true` `@Param('id') id: number` будет числом.
- `enableImplicitConversion` + boolean из query.

## Что важно помнить

- `ValidationPipe` = `class-transformer` + `class-validator` по `metatype`.
- `whitelist` + `forbidNonWhitelisted` + `transform` — стандарт.
- Вложенные DTO — `@ValidateNested` + `@Type`.

## Мини-шпаргалка

- `new ValidationPipe({ whitelist: true, forbidNonWhitelisted: true, transform: true })`.
- `exceptionFactory` — свой формат.
- `ParseArrayPipe({ items: Dto })` — массив в теле.
- `@Type(() => Number)` для query.
