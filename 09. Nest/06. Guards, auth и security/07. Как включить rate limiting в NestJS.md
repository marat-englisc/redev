# Как включить rate limiting в NestJS

> [!NOTE]
> **Rate limiting** ограничивает число запросов от одного клиента за промежуток времени: защищает от перебора паролей, злоупотреблений API, скрейпинга и случайных «штормов» запросов. В NestJS это пакет **`@nestjs/throttler`**: `ThrottlerModule.forRoot([{ ttl, limit }])` задаёт лимиты (в актуальных версиях `ttl` — в **миллисекундах**, можно задать несколько именованных лимитов: «10 в секунду» и «100 в минуту»), `ThrottlerGuard` применяет их (обычно глобально через `APP_GUARD`), `@Throttle({ default: { limit, ttl } })` переопределяет лимиты для маршрута, `@SkipThrottle()` отключает. По умолчанию счётчики хранятся **в памяти процесса** — при нескольких инстансах нужен общий **Redis-storage**. За прокси важно правильно определить IP клиента (`trust proxy`), а для авторизованных пользователей лимит лучше считать по id пользователя или API-ключу, переопределив `getTracker`.

## Вопрос

Как настроить rate limiting в NestJS?

## Подключение

```bash
npm install @nestjs/throttler
```

```ts
@Module({
  imports: [
    ThrottlerModule.forRoot({
      throttlers: [
        { name: 'short', ttl: 1_000, limit: 10 },     // 10 запросов в секунду
        { name: 'long', ttl: 60_000, limit: 200 },    // 200 в минуту
      ],
    }),
  ],
  providers: [{ provide: APP_GUARD, useClass: ThrottlerGuard }],
})
export class AppModule {}
```

Превышение → **429 Too Many Requests** и заголовки `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `Retry-After`.

## Переопределение для маршрутов

```ts
@Controller('auth')
export class AuthController {
  @Throttle({ short: { limit: 3, ttl: 1_000 }, long: { limit: 5, ttl: 60_000 } })   // строже для логина
  @Post('login')
  login() {}
}

@SkipThrottle()
@Controller('health')
export class HealthController {}
```

## Ключ клиента

```ts
@Injectable()
export class UserThrottlerGuard extends ThrottlerGuard {
  protected async getTracker(req: Record<string, any>): Promise<string> {
    return req.user?.id ?? req.ip;      // авторизованных — по пользователю, остальных — по IP
  }
}
```

```ts
// за nginx / балансировщиком
app.set('trust proxy', 1);              // Express: req.ip из X-Forwarded-For от доверенного прокси
```

Без `trust proxy` все клиенты получат IP балансировщика и общий лимит.

## Несколько инстансов

```ts
ThrottlerModule.forRootAsync({
  inject: [ConfigService],
  useFactory: (config: ConfigService) => ({
    throttlers: [{ ttl: 60_000, limit: 100 }],
    storage: new ThrottlerStorageRedisService(config.getOrThrow('REDIS_URL')),   // @nest-lab/throttler-storage-redis
  }),
});
```

## Многоуровневая защита

| Уровень | Инструмент | Что ловит |
| --- | --- | --- |
| Edge / CDN | Cloudflare, AWS WAF | DDoS, боты |
| Прокси | nginx `limit_req` | Грубые всплески |
| Приложение | `@nestjs/throttler` | Логика по пользователям и маршрутам |
| Домен | Блокировка аккаунта после N неудачных логинов, капча | Перебор паролей |

Rate limiting в приложении не защищает от DDoS: запросы всё равно доходят до Node.js.

## Частые ошибки

- In-memory storage при нескольких репликах — лимит фактически умножается.
- Нет `trust proxy` — общий лимит для всех пользователей.
- `ttl` в секундах по старой документации (сейчас — миллисекунды).
- Одинаковый лимит для логина и чтения каталога.
- Лимитировать health check, из-за чего оркестратор считает сервис мёртвым.

## Что важно помнить

- `ThrottlerModule` + глобальный `ThrottlerGuard`.
- `@Throttle` и `@SkipThrottle` для отдельных маршрутов.
- Для кластера — Redis-storage, за прокси — `trust proxy`.

## Мини-шпаргалка

- `ThrottlerModule.forRoot({ throttlers: [{ ttl: 60000, limit: 100 }] })`.
- `{ provide: APP_GUARD, useClass: ThrottlerGuard }`.
- `@Throttle({ default: { limit, ttl } })`, `@SkipThrottle()`.
- `getTracker()` — свой ключ.
- 429 + `Retry-After`.
