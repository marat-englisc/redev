# Как хранить токены в cookies

> [!NOTE]
> Хранение токена в **`httpOnly`-cookie** защищает его от кражи через XSS: JavaScript страницы не может прочитать такую cookie, а браузер сам отправляет её на сервер. Обязательные атрибуты: **`HttpOnly`**, **`Secure`** (только HTTPS), **`SameSite`** (`Lax` — разумный дефолт, `Strict` — строже, `None` — только для кросс-сайтовых сценариев и обязательно с `Secure`), ограничивающий **`Path`** (например, refresh-cookie только для `/auth`), срок (`Max-Age`). Поскольку браузер отправляет cookie автоматически, появляется риск **CSRF**: `SameSite=Lax` закрывает большую часть сценариев, а для изменяющих запросов с `SameSite=None` или при поддоменах нужны CSRF-токен (double submit) или проверка `Origin`. В NestJS cookie выставляют через `@Res({ passthrough: true })`, читают через `cookie-parser` (`req.cookies`) или `@fastify/cookie`. Для SPA на другом origin нужны CORS с `credentials: true` и `fetch(..., { credentials: 'include' })`.

## Вопрос

Как безопасно хранить токены в cookies в NestJS-приложении?

## Подключение

```bash
npm install cookie-parser
npm install -D @types/cookie-parser
```

```ts
app.use(cookieParser());
app.enableCors({ origin: ['https://app.example.com'], credentials: true });
```

## Установка cookie

```ts
const REFRESH_COOKIE = 'refresh_token';

@Public(true)
@Post('login')
@HttpCode(200)
async login(@Body() dto: LoginDto, @Res({ passthrough: true }) res: Response) {
  const { accessToken, refreshToken } = await this.auth.login(dto);

  res.cookie(REFRESH_COOKIE, refreshToken, {
    httpOnly: true,
    secure: true,
    sameSite: 'lax',
    path: '/auth',                       // cookie уходит только на /auth/*
    maxAge: 30 * 24 * 60 * 60 * 1000,    // 30 дней
  });

  return { accessToken };                // access — в памяти фронтенда
}
```

## Чтение и обновление

```ts
@Public(true)
@Post('refresh')
@HttpCode(200)
async refresh(@Req() req: Request, @Res({ passthrough: true }) res: Response) {
  const token = req.cookies?.[REFRESH_COOKIE];
  if (!token) throw new UnauthorizedException();

  const { accessToken, refreshToken } = await this.auth.rotate(token);
  res.cookie(REFRESH_COOKIE, refreshToken, refreshCookieOptions);
  return { accessToken };
}

@Post('logout')
@HttpCode(204)
async logout(@Req() req: Request, @Res({ passthrough: true }) res: Response) {
  await this.auth.revoke(req.cookies?.[REFRESH_COOKIE]);
  res.clearCookie(REFRESH_COOKIE, { path: '/auth' });   // path должен совпадать
}
```

## Атрибуты

| Атрибут | Зачем |
| --- | --- |
| `HttpOnly` | Недоступна из JS → защита от кражи при XSS |
| `Secure` | Только по HTTPS |
| `SameSite=Lax` | Не отправляется в кросс-сайтовых POST/fetch → защита от CSRF |
| `SameSite=None; Secure` | Нужна для кросс-сайтовых сценариев (API на другом сайте) |
| `Path` | Ограничить, куда отправляется |
| `Domain` | Поделиться между поддоменами (`.example.com`) — расширяет поверхность атаки |
| `Max-Age` / `Expires` | Срок жизни |

Префикс `__Host-` (например, `__Host-session`) заставляет браузер требовать `Secure`, `Path=/` и отсутствие `Domain`.

## Схемы хранения

| Вариант | XSS | CSRF | Комментарий |
| --- | --- | --- | --- |
| Access и refresh в `localStorage` | Крадутся | Нет | Не рекомендуется |
| Access в памяти, refresh в `httpOnly`-cookie | Access живёт недолго | Refresh-эндпоинт защищён `SameSite` | Частый выбор для SPA |
| Сессионная `httpOnly`-cookie (BFF или сессии) | Защищена | Нужны `SameSite`/CSRF-токен | Самый простой для веб-клиентов |

## CSRF

```ts
// проверка Origin для изменяющих запросов
@Injectable()
export class OriginGuard implements CanActivate {
  canActivate(ctx: ExecutionContext) {
    const req = ctx.switchToHttp().getRequest<Request>();
    if (['GET', 'HEAD', 'OPTIONS'].includes(req.method)) return true;
    return ALLOWED_ORIGINS.includes(req.headers.origin ?? '');
  }
}
```

Если cookie `SameSite=None` (фронтенд и API на разных сайтах) — добавляют CSRF-токен (double submit cookie) или кастомный заголовок, который нельзя отправить кросс-сайтово без preflight.

## Частые ошибки

- Cookie без `HttpOnly` или `Secure`.
- `SameSite=None` без необходимости.
- `clearCookie` с другим `path` — cookie не удаляется.
- Забыть `credentials: true` в CORS и на фронтенде.
- Считать, что `httpOnly` защищает от XSS вообще — злоумышленник всё ещё может делать запросы от имени пользователя, пока скрипт на странице.

## Что важно помнить

- `HttpOnly` + `Secure` + `SameSite` + узкий `Path`.
- Cookies автоматически отправляются → думайте о CSRF.
- Для SPA: access в памяти, refresh в `httpOnly`-cookie.

## Мини-шпаргалка

- `app.use(cookieParser())`.
- `res.cookie(name, value, { httpOnly, secure, sameSite: 'lax', path, maxAge })`.
- `req.cookies[name]`, `res.clearCookie(name, { path })`.
- CORS `credentials: true` + `fetch(..., { credentials: 'include' })`.
