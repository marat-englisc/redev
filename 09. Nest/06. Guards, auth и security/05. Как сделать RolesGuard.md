# Как сделать RolesGuard

> [!NOTE]
> **RolesGuard** реализует RBAC: декоратор `@Roles([...])` записывает в метаданные метода или контроллера список допустимых ролей, а guard читает их через `Reflector` и сравнивает с ролями `request.user`. Если метаданных нет — маршрут доступен любому аутентифицированному пользователю; если у пользователя нет подходящей роли — `ForbiddenException` (403). Guard должен выполняться **после** аутентификации (иначе `request.user` пуст): глобальные guards регистрируют в порядке `AuthGuard` → `RolesGuard`. Метаданные удобно читать через `getAllAndOverride` (метод переопределяет контроллер) или `getAllAndMerge` (объединение списков). Для детальных правил («редактировать только свои статьи») ролей недостаточно — нужны **permissions/policies** (например, CASL) и проверки владельца в сервисе.

## Вопрос

Как реализовать проверку ролей в NestJS?

## Роли и декоратор

```ts
export enum Role {
  User = 'user',
  Editor = 'editor',
  Admin = 'admin',
}

export const Roles = Reflector.createDecorator<Role[]>();
```

## Guard

```ts
@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private readonly reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const required = this.reflector.getAllAndOverride(Roles, [context.getHandler(), context.getClass()]);
    if (!required?.length) return true;                       // ролей не требуется

    const { user } = context.switchToHttp().getRequest<{ user?: AuthUser }>();
    if (!user) throw new UnauthorizedException();             // защитный случай

    const allowed = required.some((role) => user.roles.includes(role));
    if (!allowed) throw new ForbiddenException('Insufficient role');
    return true;
  }
}
```

## Подключение

```ts
// app.module.ts — порядок важен
providers: [
  { provide: APP_GUARD, useClass: JwtAuthGuard },
  { provide: APP_GUARD, useClass: RolesGuard },
]

@Controller('articles')
@Roles([Role.Editor, Role.Admin])                   // по умолчанию для контроллера
export class ArticlesController {
  @Get()
  @Roles([Role.User, Role.Editor, Role.Admin])      // переопределяет контроллер
  findAll() {}

  @Delete(':id')
  @Roles([Role.Admin])
  remove() {}
}
```

## getAllAndOverride и getAllAndMerge

| Метод | Результат для `@Roles([Admin])` на методе и `@Roles([Editor])` на контроллере |
| --- | --- |
| `getAllAndOverride` | `[Admin]` — метод важнее |
| `getAllAndMerge` | `[Admin, Editor]` — объединение |

## Иерархия ролей

```ts
const HIERARCHY: Record<Role, Role[]> = {
  [Role.Admin]: [Role.Admin, Role.Editor, Role.User],
  [Role.Editor]: [Role.Editor, Role.User],
  [Role.User]: [Role.User],
};

const effective = new Set(user.roles.flatMap((r) => HIERARCHY[r]));
const allowed = required.some((r) => effective.has(r));
```

## Права вместо ролей

```ts
export const RequirePermissions = Reflector.createDecorator<Permission[]>();

@RequirePermissions(['article:publish'])
@Post(':id/publish')
publish() {}

// роль → набор прав хранится в БД или конфиге; guard проверяет права, а не роли
```

Права проще менять (новая роль = новый набор прав), и код не зависит от названий ролей.

## Роли — не всё

```ts
// RolesGuard пропустит любого editor-а, но редактировать можно только свою статью
async update(id: string, dto: UpdateArticleDto, user: AuthUser) {
  const article = await this.repo.findById(id);
  if (article.authorId !== user.id && !user.roles.includes(Role.Admin)) throw new ForbiddenException();
}
```

## Частые ошибки

- `RolesGuard` зарегистрирован раньше аутентификации — `user` всегда `undefined`.
- Забыть `context.getClass()` — роли контроллера игнорируются.
- `@Roles` без guard — декоратор сам ничего не проверяет.
- Роли в JWT, которые нельзя быстро отозвать, для критичных прав.
- Проверка `user.role === 'admin'` строками по всему коду.

## Что важно помнить

- `@Roles` — метаданные, `RolesGuard` — проверка через `Reflector`.
- Порядок: аутентификация → роли.
- Детальные правила — права и проверки владельца.

## Мини-шпаргалка

- `Reflector.createDecorator<Role[]>()`.
- `reflector.getAllAndOverride(Roles, [handler, class])`.
- Нет ролей в метаданных → пропустить.
- Нет роли у пользователя → 403.
