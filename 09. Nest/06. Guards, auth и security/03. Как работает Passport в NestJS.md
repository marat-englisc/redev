# Как работает Passport в NestJS

> [!NOTE]
> **Passport** — популярная библиотека аутентификации для Node.js, в которой каждый способ входа оформлен **стратегией** (`passport-local` — логин/пароль, `passport-jwt` — Bearer-токен, `passport-google-oauth20` — OAuth и сотни других). Пакет `@nestjs/passport` встраивает её в Nest: стратегию описывают классом, наследующим `PassportStrategy(Strategy, 'name')`, с методом **`validate()`** — его результат Passport кладёт в `request.user`; защиту включают guard-ом `AuthGuard('name')` (обычно в виде подкласса `JwtAuthGuard`). Стратегии — обычные провайдеры, поэтому получают зависимости через DI. Passport удобен, когда нужно несколько способов входа, особенно OAuth-провайдеры; для простой JWT-проверки можно обойтись собственным guard с `JwtService`, а для полноценной auth-системы с сессиями — готовыми решениями вроде [Better Auth](<../13. Better Auth в NestJS/01. Что такое Better Auth и зачем он в NestJS.md>).

## Вопрос

Как работает Passport в NestJS?

## Установка

```bash
npm install @nestjs/passport passport passport-local passport-jwt @nestjs/jwt
npm install -D @types/passport-local @types/passport-jwt
```

## Local strategy — логин по паролю

```ts
@Injectable()
export class LocalStrategy extends PassportStrategy(Strategy, 'local') {
  constructor(private readonly auth: AuthService) {
    super({ usernameField: 'email' });
  }

  async validate(email: string, password: string): Promise<AuthUser> {
    const user = await this.auth.validateCredentials(email, password);
    if (!user) throw new UnauthorizedException('Invalid credentials');
    return user;                         // → req.user
  }
}

@Controller('auth')
export class AuthController {
  constructor(private readonly auth: AuthService) {}

  @Public(true)
  @UseGuards(AuthGuard('local'))
  @Post('login')
  @HttpCode(200)
  login(@CurrentUser() user: AuthUser) {
    return this.auth.issueTokens(user);
  }
}
```

## JWT strategy — защищённые маршруты

```ts
@Injectable()
export class JwtStrategy extends PassportStrategy(Strategy, 'jwt') {
  constructor(config: ConfigService) {
    super({
      jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken(),
      secretOrKey: config.getOrThrow<string>('JWT_ACCESS_SECRET'),
      ignoreExpiration: false,
      algorithms: ['HS256'],
    });
  }

  validate(payload: { sub: string; role: Role }): AuthUser {
    return { id: payload.sub, role: payload.role };   // подпись и срок уже проверены
  }
}

@Injectable()
export class JwtAuthGuard extends AuthGuard('jwt') {
  constructor(private readonly reflector: Reflector) { super(); }

  canActivate(ctx: ExecutionContext) {
    const isPublic = this.reflector.getAllAndOverride(Public, [ctx.getHandler(), ctx.getClass()]);
    return isPublic ? true : super.canActivate(ctx);
  }
}
```

## Модуль

```ts
@Module({
  imports: [UsersModule, PassportModule, JwtModule.register({})],
  providers: [AuthService, LocalStrategy, JwtStrategy, { provide: APP_GUARD, useClass: JwtAuthGuard }],
  controllers: [AuthController],
})
export class AuthModule {}
```

## Поток

```text
POST /auth/login { email, password }
  → AuthGuard('local') → LocalStrategy.validate() → req.user
  → AuthController.login → access + refresh токены

GET /orders  Authorization: Bearer <jwt>
  → JwtAuthGuard → passport-jwt проверяет подпись и exp → JwtStrategy.validate(payload) → req.user
  → OrdersController
```

## OAuth

```ts
@Injectable()
export class GoogleStrategy extends PassportStrategy(GoogleOAuthStrategy, 'google') {
  constructor(config: ConfigService, private readonly auth: AuthService) {
    super({
      clientID: config.getOrThrow('GOOGLE_CLIENT_ID'),
      clientSecret: config.getOrThrow('GOOGLE_CLIENT_SECRET'),
      callbackURL: config.getOrThrow('GOOGLE_CALLBACK_URL'),
      scope: ['email', 'profile'],
    });
  }
  validate(_at: string, _rt: string, profile: Profile) {
    return this.auth.findOrCreateFromGoogle(profile);
  }
}
```

## Passport или свой guard

| Passport | Свой guard + `JwtService` |
| --- | --- |
| Много стратегий, особенно OAuth | Только JWT |
| Стандартный, знакомый подход | Меньше абстракций, проще отладка |
| Колбэк-API стратегий | Полный контроль |

## Частые ошибки

- Возвращать из `validate` всю сущность пользователя с `passwordHash` — она окажется в `req.user`.
- Не указывать `algorithms` — риск атак с подменой алгоритма.
- Один секрет для access и refresh токенов.
- Ходить в БД в `JwtStrategy.validate` на каждый запрос без необходимости (или, наоборот, не проверять блокировку пользователя там, где это важно).

## Что важно помнить

- Стратегия = способ аутентификации, `validate()` → `req.user`.
- `AuthGuard('name')` запускает стратегию.
- Стратегии — провайдеры, регистрируются в модуле.

## Мини-шпаргалка

- `class X extends PassportStrategy(Strategy, 'name') { validate() }`.
- `@UseGuards(AuthGuard('local'))`.
- `JwtAuthGuard extends AuthGuard('jwt')`.
- `ExtractJwt.fromAuthHeaderAsBearerToken()`.
