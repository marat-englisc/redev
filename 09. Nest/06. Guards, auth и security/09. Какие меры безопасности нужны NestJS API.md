# Какие меры безопасности нужны NestJS API

> [!NOTE]
> Безопасность API — набор слоёв, а не одна библиотека. Базовый минимум для NestJS: **HTTPS** и безопасные заголовки (`helmet`); строгий **CORS** со списком origin; **аутентификация и авторизация** на каждом маршруте («закрыто по умолчанию» через глобальный guard + проверка владельца ресурса против IDOR); **валидация входа** с `whitelist`/`forbidNonWhitelisted` и ограничением размеров (тело, массивы, строки, файлы, `limit` пагинации); **rate limiting**; **параметризованные запросы** к БД (ORM, без конкатенации в `$queryRawUnsafe`); **секреты** только в переменных окружения или secret manager, с валидацией при старте; ответы без лишних полей и без деталей 5xx; защита cookies (`HttpOnly`, `Secure`, `SameSite`) и CSRF; логирование событий безопасности без паролей и токенов; обновление зависимостей (`npm audit`, Dependabot). Ориентир — **OWASP API Security Top 10**.

## Вопрос

Какие меры безопасности нужны API на NestJS?

## Заголовки и CORS

```ts
import helmet from 'helmet';

app.use(helmet());                                   // HSTS, X-Content-Type-Options, frameguard и др.
app.enableCors({ origin: config.getOrThrow<string>('CORS_ORIGINS').split(','), credentials: true });
app.getHttpAdapter().getInstance().disable('x-powered-by');   // Express
```

Для Fastify — `@fastify/helmet`. Для API, отдающего только JSON, CSP почти не влияет, но для Swagger UI его иногда приходится ослабить.

## Аутентификация и авторизация

```ts
providers: [
  { provide: APP_GUARD, useClass: ThrottlerGuard },
  { provide: APP_GUARD, useClass: JwtAuthGuard },     // всё закрыто, @Public() — исключения
  { provide: APP_GUARD, useClass: RolesGuard },
]

// IDOR: фильтровать по владельцу в самом запросе
this.prisma.order.findFirst({ where: { id, userId: user.id } });
```

## Валидация и ограничения размеров

```ts
app.useGlobalPipes(new ValidationPipe({ whitelist: true, forbidNonWhitelisted: true, transform: true }));
app.useBodyParser('json', { limit: '100kb' });        // Express-адаптер

class CreateOrderDto {
  @IsArray() @ArrayMaxSize(50) @ValidateNested({ each: true }) @Type(() => ItemDto) items: ItemDto[];
  @IsOptional() @IsString() @MaxLength(500) comment?: string;
}
```

Mass assignment: без `whitelist` клиент может прислать `role: 'admin'` или `balance`.

## База данных

```ts
// ✓
await this.prisma.$queryRaw`SELECT * FROM users WHERE email = ${email}`;
// ✗
await this.prisma.$queryRawUnsafe(`SELECT * FROM users WHERE email = '${email}'`);
```

Роль БД приложения — без прав на DDL; сортировка — по белому списку полей.

## Секреты и конфигурация

- Секреты — в env или secret manager, не в репозитории и не в образе Docker.
- Валидация env при старте: длина секретов, формат URL ([валидация env](<../08. Config, database и интеграции/02. Как валидировать env в NestJS.md>)).
- Разные секреты для окружений и типов токенов, ротация.

## Ответы и ошибки

- DTO ответа или `select` — без `passwordHash`, служебных флагов, внутренних id.
- 5xx — без стека и текста ошибки БД; детали — в логах с `requestId`.
- Swagger в проде — закрыт авторизацией или отключён.

## Логи

```ts
// pino: маскировать чувствительные поля
redact: ['req.headers.authorization', 'req.headers.cookie', '*.password', '*.token']
```

Логировать: неудачные входы, смену пароля, изменения ролей, отказ в доступе (403) — без самих секретов.

## OWASP API Security Top 10 — что закрывает NestJS-код

| Риск | Мера |
| --- | --- |
| Broken Object Level Authorization (IDOR) | Проверка владельца в сервисе/запросе |
| Broken Authentication | Короткие токены, ротация refresh, rate limit на логин |
| Broken Object Property Level Authorization | `whitelist`, DTO ответа |
| Unrestricted Resource Consumption | Лимиты размеров, пагинация, throttler, таймауты |
| Broken Function Level Authorization | Глобальный guard + роли/права |
| Security Misconfiguration | helmet, CORS, отключённые debug-эндпоинты |
| Unsafe Consumption of APIs | Валидация ответов внешних API (Zod), таймауты |

## Частые ошибки

- `enableCors()` без параметров и `origin: true` в проде.
- Новый контроллер без guard, потому что guards подключаются вручную.
- Открытый Swagger и `/metrics` наружу.
- Логирование тела запросов с паролями.
- Устаревшие зависимости с известными CVE.

## Что важно помнить

- Защита многоуровневая: транспорт, заголовки, auth, валидация, лимиты, данные, логи.
- «Закрыто по умолчанию» + проверка владельца каждого ресурса.
- Ориентир — OWASP API Security Top 10.

## Мини-шпаргалка

- `helmet()`, строгий CORS.
- Глобальные `ThrottlerGuard`, `JwtAuthGuard`, `RolesGuard`.
- `ValidationPipe({ whitelist, forbidNonWhitelisted })` + лимиты.
- Параметризованные запросы, белые списки сортировки.
- Секреты в env, redact в логах, `npm audit`.
