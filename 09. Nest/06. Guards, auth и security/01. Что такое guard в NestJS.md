# Что такое guard в NestJS

> [!NOTE]
> **Guard** — класс с методом `canActivate(context)`, который решает, **будет ли запрос обработан**: возвращает `true` (продолжить), `false` (Nest ответит `403 Forbidden`) или бросает своё исключение (`UnauthorizedException` → 401). Guards выполняются **после middleware и до interceptors и pipes**, и, в отличие от middleware, имеют доступ к `ExecutionContext` — знают, какой **контроллер и метод** будут вызваны, и могут прочитать их **метаданные** (`@Roles`, `@Public`) через `Reflector`. Типичные задачи: аутентификация (проверить токен/сессию и положить пользователя в `request.user`), авторизация по ролям и правам, проверка API-ключа, feature flags, ограничения по тарифу. Подключаются на метод или контроллер (`@UseGuards`) и глобально (`APP_GUARD`); несколько guards выполняются по порядку, и первый отказ останавливает цепочку. `canActivate` может быть асинхронным.

## Вопрос

Что такое guard в NestJS и как он работает?

## Простой guard

```ts
@Injectable()
export class ApiKeyGuard implements CanActivate {
  constructor(private readonly config: ConfigService) {}

  canActivate(context: ExecutionContext): boolean {
    const req = context.switchToHttp().getRequest<Request>();
    const key = req.header('x-api-key');
    if (!key || !timingSafeEqualStr(key, this.config.getOrThrow('PARTNER_API_KEY'))) {
      throw new UnauthorizedException('Invalid API key');
    }
    return true;
  }
}

@UseGuards(ApiKeyGuard)
@Controller('partners')
export class PartnersController {}
```

## Глобальный guard + публичные маршруты

```ts
export const Public = Reflector.createDecorator<boolean>();

@Injectable()
export class AuthGuard implements CanActivate {
  constructor(private readonly reflector: Reflector, private readonly tokens: TokenService) {}

  async canActivate(context: ExecutionContext) {
    const isPublic = this.reflector.getAllAndOverride(Public, [context.getHandler(), context.getClass()]);
    if (isPublic) return true;

    const req = context.switchToHttp().getRequest();
    const token = req.headers.authorization?.replace(/^Bearer /, '');
    if (!token) throw new UnauthorizedException();

    req.user = await this.tokens.verifyAccessToken(token);   // бросит 401 при невалидном токене
    return true;
  }
}

// app.module.ts
providers: [
  { provide: APP_GUARD, useClass: AuthGuard },     // сначала аутентификация
  { provide: APP_GUARD, useClass: RolesGuard },    // затем роли
]

@Public(true)
@Post('login')
login() {}
```

«Закрыто по умолчанию» безопаснее, чем помнить `@UseGuards` на каждом новом контроллере.

## Порядок и уровни

```text
Middleware → Global guards → Controller guards → Method guards → Interceptors → Pipes → Handler
```

```ts
@UseGuards(JwtAuthGuard, RolesGuard)   // слева направо
```

## Guard или middleware

| | Middleware | Guard |
| --- | --- | --- |
| Знает обработчик и его метаданные | Нет | Да (`ExecutionContext`) |
| Работает с WebSocket, RPC | Нет | Да |
| Типичная задача | Логи, парсинг, CORS, request id | Аутентификация, авторизация |

## Что вернуть

| Результат | Ответ клиенту |
| --- | --- |
| `true` | Запрос продолжается |
| `false` | `403 Forbidden` |
| `throw new UnauthorizedException()` | 401 |
| `throw new ForbiddenException('...')` | 403 со своим сообщением |

## Частые ошибки

- Возвращать `false` при отсутствии токена — клиент получит 403 вместо 401.
- Проверять роли в guard, который выполняется **раньше** guard аутентификации (`req.user` ещё пуст).
- Забыть `getClass()` при чтении метаданных — `@Public` на контроллере не сработает.
- Тяжёлые запросы к БД в guard на каждый запрос без кеша.

## Что важно помнить

- Guard решает «пускать или нет» и видит метаданные обработчика.
- Глобальный guard + `@Public` — «закрыто по умолчанию».
- `false` → 403, для 401 бросают `UnauthorizedException`.

## Мини-шпаргалка

- `implements CanActivate` → `canActivate(ctx)`.
- `@UseGuards(A, B)`, `{ provide: APP_GUARD, useClass }`.
- `context.switchToHttp().getRequest()`.
- `reflector.getAllAndOverride(Key, [handler, class])`.
