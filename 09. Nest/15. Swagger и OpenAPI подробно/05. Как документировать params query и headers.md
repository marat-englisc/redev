# Как документировать params, query и headers

> [!NOTE]
> Параметры пути, строки запроса и заголовки описываются декораторами `@ApiParam`, `@ApiQuery` и `@ApiHeader` (или `@ApiHeaders` для нескольких). Многое `@nestjs/swagger` выводит сам: параметры из `@Param('id')`, `@Query('page')` и **query-DTO** (`@Query() query: ListDto` — каждое свойство класса станет отдельным query-параметром), поэтому ручные декораторы нужны в основном для **уточнений**: тип и формат (`uuid`, `integer`), описание, пример, перечисление (`enum`, `enumName`), `required`, значение по умолчанию, массивы (`isArray` + `style`/`explode` для формата `?ids=1&ids=2` или `?ids=1,2`). Заголовки, которые читаются не через `@Headers()` (например, `Idempotency-Key`, `X-Request-Id`, `Accept-Language`), документируют явно — иначе клиент о них не узнает. Описание параметров должно совпадать с валидацией (пайпы, DTO), иначе документация вводит в заблуждение.

## Вопрос

Как документировать параметры пути, query и заголовки в Swagger?

## Параметры пути

```ts
@ApiParam({ name: 'id', format: 'uuid', description: 'ID заказа', example: '0192f0a1-7c3e-7000-8000-000000000001' })
@Get(':id')
findOne(@Param('id', ParseUUIDPipe) id: string) {}

@ApiParam({ name: 'status', enum: OrderStatus, enumName: 'OrderStatus' })
@Get('by-status/:status')
byStatus(@Param('status', new ParseEnumPipe(OrderStatus)) status: OrderStatus) {}
```

## Query через DTO

```ts
export class ListOrdersQueryDto {
  @ApiPropertyOptional({ minimum: 1, default: 1 })
  @Type(() => Number) @IsInt() @Min(1) page = 1;

  @ApiPropertyOptional({ minimum: 1, maximum: 100, default: 20 })
  @Type(() => Number) @IsInt() @Min(1) @Max(100) limit = 20;

  @ApiPropertyOptional({ enum: OrderStatus, enumName: 'OrderStatus', isArray: true })
  @IsOptional() @IsEnum(OrderStatus, { each: true }) @Transform(({ value }) => [].concat(value))
  status?: OrderStatus[];

  @ApiPropertyOptional({ enum: ['createdAt', 'total'], default: 'createdAt' })
  @IsIn(['createdAt', 'total']) sortBy: 'createdAt' | 'total' = 'createdAt';
}

@Get()
list(@Query() query: ListOrdersQueryDto) {}     // Swagger покажет page, limit, status, sortBy
```

## Отдельные query-параметры

```ts
@ApiQuery({ name: 'q', required: false, description: 'Поиск по названию', example: 'клавиатура' })
@ApiQuery({ name: 'ids', required: false, type: [String], style: 'form', explode: false, description: 'Через запятую' })
@Get('search')
search(@Query('q') q?: string, @Query('ids', new ParseArrayPipe({ optional: true })) ids?: string[]) {}
```

## Заголовки

```ts
@ApiHeader({ name: 'Idempotency-Key', required: true, description: 'UUID; повтор с тем же ключом вернёт тот же результат', schema: { type: 'string', format: 'uuid' } })
@ApiHeader({ name: 'Accept-Language', required: false, enum: ['ru', 'en'] })
@Post()
create(@Body() dto: CreateOrderDto, @Headers('idempotency-key') key: string) {}

// для всего контроллера
@ApiHeader({ name: 'X-Tenant-Id', required: true })
@Controller('tenants/projects')
export class TenantProjectsController {}
```

Заголовок авторизации документируют не `@ApiHeader`, а схемой безопасности — см. [авторизация в Swagger](<06. Как документировать авторизацию в Swagger.md>).

## Что выводится автоматически

| Источник | Результат в документе |
| --- | --- |
| `@Param('id')` | Path-параметр `id` (string) |
| `@Query('page')` | Query-параметр `page` |
| `@Query() dto: ListDto` | Все свойства DTO как query-параметры |
| `@Headers('x')` | Не документируется автоматически — нужен `@ApiHeader` |
| `ParseIntPipe` | Тип не уточняется без плагина/декоратора |

## Частые ошибки

- Query-DTO без `@ApiPropertyOptional` (и без плагина) — параметры не видны.
- Документирован `required: true`, а в коде параметр необязательный.
- Массивы без `style`/`explode` — клиент шлёт другой формат, чем ждёт API.
- `Authorization` как `@ApiHeader` вместо `addBearerAuth` + `@ApiBearerAuth`.

## Что важно помнить

- Path и query по большей части выводятся автоматически; декораторы — для уточнений.
- Query-DTO даёт документацию и валидацию одним классом.
- Важные кастомные заголовки документируйте явно.

## Мини-шпаргалка

- `@ApiParam({ name, format, enum, example })`.
- `@ApiQuery({ name, required, type, isArray, style, explode })`.
- `@ApiHeader({ name, required, description, schema })`.
- `@Query() dto: QueryDto` + `@ApiPropertyOptional`.
