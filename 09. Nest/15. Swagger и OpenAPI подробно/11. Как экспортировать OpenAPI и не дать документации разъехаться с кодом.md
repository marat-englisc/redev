# Как экспортировать OpenAPI и не дать документации разъехаться с кодом

> [!NOTE]
> OpenAPI-документ ценен, пока **совпадает с реальным поведением API**. Чтобы так и было, документ генерируют **из кода** (DTO-классы, декораторы, CLI-плагин), **экспортируют в файл** (`openapi.json`) скриптом без запуска HTTP-сервера и **проверяют в CI**: файл коммитят и сравнивают с заново сгенерированным (если отличается — разработчик забыл обновить), прогоняют **линтер** спецификации (Spectral, Redocly) и **детектор ломающих изменений** (oasdiff, openapi-diff) между веткой и `main`. Из того же файла фронтенд генерирует типизированный клиент — тогда расхождения проявляются ошибками компиляции. Дополнительно помогают: общие композиционные декораторы (`@Auth`, `@ApiPaginatedResponse`, `@ApiStandardErrors`), e2e-тесты, проверяющие, что ответы соответствуют схеме, и одно место истины для формата ошибок. Ручная документация, живущая отдельно от кода, почти всегда устаревает.

## Вопрос

Как экспортировать OpenAPI-документ и обеспечить его соответствие коду?

## Экспорт без запуска сервера

```ts
// scripts/export-openapi.ts
import { writeFileSync } from 'node:fs';
import { NestFactory } from '@nestjs/core';
import { SwaggerModule } from '@nestjs/swagger';
import { AppModule } from '../src/app.module';
import { buildSwaggerConfig, configureApp } from '../src/app.setup';

async function main() {
  const app = await NestFactory.create(AppModule, { logger: false, abortOnError: false });
  configureApp(app);                                        // prefix, versioning — как в main.ts
  const document = SwaggerModule.createDocument(app, buildSwaggerConfig());
  writeFileSync('openapi.json', JSON.stringify(document, null, 2) + '\n');
  await app.close();
}
main();
```

```json
// package.json
{ "scripts": { "openapi:export": "ts-node -r tsconfig-paths/register scripts/export-openapi.ts" } }
```

`NestFactory.create` без `listen` не открывает порт, но инициализирует модули: подключения к БД и внешним сервисам в `onModuleInit` нужно либо мокать переменными окружения, либо делать ленивыми.

## Проверки в CI

```yaml
# .github/workflows/api-contract.yml (фрагмент)
- run: npm run openapi:export
- name: Документ закоммичен и актуален
  run: git diff --exit-code openapi.json
- name: Линтер спецификации
  run: npx @stoplight/spectral-cli lint openapi.json
- name: Ломающие изменения относительно main
  run: |
    git show origin/main:openapi.json > openapi.main.json
    oasdiff breaking openapi.main.json openapi.json --fail-on ERR
```

## Правила Spectral (пример)

```yaml
# .spectral.yaml
extends: ['spectral:oas']
rules:
  operation-operationId: error
  operation-tags: error
  operation-description: warn
  oas3-schema: error
```

## Генерация клиента на фронтенде

```bash
npx openapi-typescript ../api/openapi.json -o src/api/schema.d.ts
```

Если бэкенд переименовал поле, фронтенд не скомпилируется — расхождение заметно до релиза.

## Что ещё помогает

| Приём | Эффект |
| --- | --- |
| CLI-плагин + `classValidatorShim` | Документация следует за DTO и валидацией |
| Композиционные декораторы | Guard, роли и Swagger в одном месте |
| Общий `ErrorResponseDto` + exception filter | Формат ошибок совпадает |
| E2E-проверка ответа по схеме (`jest-openapi`, ajv) | Реальные ответы соответствуют документу |
| Code review изменений `openapi.json` | Контракт обсуждается явно |
| Версионирование API | Ломающие изменения — новая версия |

## Публикация

- Внутренняя документация — Swagger UI/Scalar в staging, закрытые авторизацией.
- Публичный API — статический портал (Redocly, Scalar) из `openapi.json`, собираемый в CI.
- Партнёрам — файл спецификации и changelog изменений контракта.

## Частые ошибки

- Документ генерируется только в рантайме, и никто не замечает изменений контракта.
- Экспорт без `setGlobalPrefix`/versioning — пути отличаются от реальных.
- Ломающее изменение (удалили поле) без новой версии и предупреждения клиентов.
- Ручные правки `openapi.json`, которые перетираются при следующей генерации.

## Что важно помнить

- Документ — из кода, экспорт — в файл, проверка — в CI.
- Diff-проверка, линтер и детектор ломающих изменений ловят расхождения.
- Сгенерированный клиент на фронтенде превращает расхождения в ошибки компиляции.

## Мини-шпаргалка

- `SwaggerModule.createDocument(app, config)` → `writeFileSync('openapi.json', ...)`.
- `git diff --exit-code openapi.json`.
- `spectral lint`, `oasdiff breaking`.
- `openapi-typescript` на фронтенде.
