# Как документировать responses и ошибки

> [!NOTE]
> Ответы операции описываются декораторами `@ApiResponse({ status, description, type })` или их сокращениями: `@ApiOkResponse` (200), `@ApiCreatedResponse` (201), `@ApiNoContentResponse` (204), `@ApiBadRequestResponse` (400), `@ApiUnauthorizedResponse` (401), `@ApiForbiddenResponse` (403), `@ApiNotFoundResponse` (404), `@ApiConflictResponse` (409), `@ApiUnprocessableEntityResponse` (422), `@ApiTooManyRequestsResponse` (429) и др. В `type` передают **класс** ответа (массив — `type: [ProductDto]` или `isArray`), при необходимости — `schema` вручную и `examples`. Для ошибок полезно один раз описать **общий класс ошибки** (`ErrorResponseDto` со `statusCode`, `code`, `message`, `details`, `requestId`) и подключать его ко всем операциям через композиционный декоратор или на уровне контроллера. CLI-плагин может автоматически выводить успешный ответ из возвращаемого типа метода, но ошибки всегда описывают явно. Документация ответов — контракт для фронтенда: без неё сгенерированные клиенты получают `unknown`.

## Вопрос

Как документировать успешные ответы и ошибки в Swagger?

## Успешные ответы

```ts
@ApiOkResponse({ type: ProductDto, description: 'Товар' })
@Get(':id')
findOne() {}

@ApiOkResponse({ type: [ProductDto] })
@Get()
list() {}

@ApiCreatedResponse({ type: ProductDto, headers: { Location: { description: 'URL созданного ресурса', schema: { type: 'string' } } } })
@Post()
create() {}

@ApiNoContentResponse({ description: 'Удалено' })
@HttpCode(204)
@Delete(':id')
remove() {}
```

## Общая схема ошибки

```ts
export class FieldErrorDto {
  @ApiProperty({ example: 'email' }) field: string;
  @ApiProperty({ example: 'email must be an email' }) message: string;
}

export class ErrorResponseDto {
  @ApiProperty({ example: 400 }) statusCode: number;
  @ApiProperty({ example: 'VALIDATION_FAILED' }) code: string;
  @ApiProperty({ example: 'Validation failed' }) message: string;
  @ApiPropertyOptional({ type: [FieldErrorDto] }) details?: FieldErrorDto[];
  @ApiProperty({ example: '6c1f9b1e-0d1a-4a3b-9b1d-7f2a1c3e5d10' }) requestId: string;
}
```

```ts
export function ApiStandardErrors() {
  return applyDecorators(
    ApiBadRequestResponse({ type: ErrorResponseDto, description: 'Невалидные данные' }),
    ApiUnauthorizedResponse({ type: ErrorResponseDto }),
    ApiForbiddenResponse({ type: ErrorResponseDto }),
    ApiInternalServerErrorResponse({ type: ErrorResponseDto }),
  );
}

@ApiStandardErrors()
@Controller('orders')
export class OrdersController {
  @ApiNotFoundResponse({ type: ErrorResponseDto })
  @ApiConflictResponse({ type: ErrorResponseDto, description: 'Заказ уже оплачен' })
  @ApiUnprocessableEntityResponse({ type: ErrorResponseDto, description: 'INSUFFICIENT_STOCK' })
  @Post(':id/pay')
  pay() {}
}
```

## Примеры ответов

```ts
@ApiConflictResponse({
  type: ErrorResponseDto,
  examples: {
    alreadyPaid: { summary: 'Уже оплачен', value: { statusCode: 409, code: 'ORDER_ALREADY_PAID', message: 'Order already paid', requestId: '...' } },
    cancelled: { summary: 'Отменён', value: { statusCode: 409, code: 'ORDER_CANCELLED', message: 'Order is cancelled', requestId: '...' } },
  },
})
```

## Схема вручную

```ts
@ApiOkResponse({
  schema: {
    type: 'object',
    properties: { status: { type: 'string', example: 'ok' }, uptime: { type: 'number' } },
  },
})
@Get('status')
status() {}
```

Обёрнутые и пагинированные ответы — через generic-схемы, см. [пагинация и generic-ответы](<08. Как документировать пагинацию и generic-ответы.md>).

## Частые ошибки

- Ответ без `type` — клиент получает `unknown`.
- Документирован 200, а `POST` возвращает 201.
- Описан только успешный ответ — фронтенд не знает формат ошибок и коды.
- Формат ошибок в документации не совпадает с реальным exception filter.
- Интерфейс вместо класса в `type`.

## Что важно помнить

- Каждой операции — успешный ответ с типом и ожидаемые ошибки.
- Общий `ErrorResponseDto` + композиционный декоратор.
- Формат в документации совпадает с exception filter.

## Мини-шпаргалка

- `@ApiOkResponse({ type })`, `@ApiCreatedResponse`, `@ApiNoContentResponse`.
- `@ApiBadRequestResponse`, `@ApiNotFoundResponse`, `@ApiConflictResponse`…
- `type: [Dto]` — массив.
- `examples: { name: { summary, value } }`.
