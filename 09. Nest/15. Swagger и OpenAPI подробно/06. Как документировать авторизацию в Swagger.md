# Как документировать авторизацию в Swagger

> [!NOTE]
> Авторизация в OpenAPI описывается **схемами безопасности** (`components.securitySchemes`) и требованиями к операциям (`security`). В `@nestjs/swagger` схему регистрируют в `DocumentBuilder`: `addBearerAuth()` (JWT в заголовке `Authorization: Bearer`), `addCookieAuth('session')` (сессионная cookie), `addApiKey({ type: 'apiKey', in: 'header', name: 'X-API-Key' })`, `addOAuth2({...})`, `addBasicAuth()`; каждой схеме можно дать имя. Затем операции помечают соответствующим декоратором: `@ApiBearerAuth('access-token')`, `@ApiCookieAuth('session')`, `@ApiSecurity('api-key')`, `@ApiOAuth2(['scope'])` — на контроллер или метод. После этого в Swagger UI появляется кнопка **Authorize**, а генераторы клиентов знают, как передавать токен. Хорошая практика — объединить guard, роли и Swagger-описание в один декоратор через `applyDecorators` (например, `@Auth('admin')`), а также документировать ответы **401** и **403**. Если API закрыт глобальным guard-ом, требование безопасности можно задать **для всего документа** и снимать его на публичных маршрутах.

## Вопрос

Как описать в Swagger авторизацию API?

## Регистрация схем

```ts
const config = new DocumentBuilder()
  .setTitle('Shop API')
  .addBearerAuth({ type: 'http', scheme: 'bearer', bearerFormat: 'JWT', description: 'Access token' }, 'access-token')
  .addCookieAuth('better-auth.session_token', { type: 'apiKey', in: 'cookie' }, 'session')
  .addApiKey({ type: 'apiKey', in: 'header', name: 'X-API-Key' }, 'api-key')
  .build();
```

## Требования к операциям

```ts
@ApiTags('orders')
@ApiBearerAuth('access-token')                 // для всех методов контроллера
@ApiUnauthorizedResponse({ description: 'Нет или невалидный токен' })
@Controller('orders')
export class OrdersController {
  @Get()
  list() {}
}

@ApiSecurity('api-key')
@Controller('partners')
export class PartnersController {}
```

## Глобальное требование и публичные маршруты

```ts
const document = SwaggerModule.createDocument(app, config);
document.security = [{ 'access-token': [] }];   // всё закрыто по умолчанию

// публичная операция — пустой список требований
@ApiSecurity({})                                 // или задать security: [] через @ApiOperation({ security: [] })
@Public()
@Get('catalog')
catalog() {}
```

Проверьте результат в `docs-json`: у публичных операций должно быть `"security": []`.

## Один декоратор для guard, ролей и документации

```ts
export function Auth(...roles: Role[]) {
  return applyDecorators(
    Roles(roles),
    UseGuards(JwtAuthGuard, RolesGuard),
    ApiBearerAuth('access-token'),
    ApiUnauthorizedResponse({ description: 'Unauthorized' }),
    ApiForbiddenResponse({ description: `Requires role: ${roles.join(', ') || 'any'}` }),
  );
}

@Auth(Role.Admin)
@Delete(':id')
remove() {}
```

Так документация не расходится с реальной защитой маршрута.

## Удобство в UI

```ts
SwaggerModule.setup('docs', app, documentFactory, {
  swaggerOptions: { persistAuthorization: true },   // токен сохраняется при перезагрузке страницы
});
```

Для cookie-сессий Swagger UI на том же домене отправит cookie автоматически (после входа через `/api/auth/...`); на другом домене — понадобится CORS с `credentials`.

## OAuth2

```ts
new DocumentBuilder().addOAuth2({
  type: 'oauth2',
  flows: { authorizationCode: { authorizationUrl: 'https://auth.example.com/authorize', tokenUrl: 'https://auth.example.com/token', scopes: { 'orders:read': 'Чтение заказов' } } },
});

@ApiOAuth2(['orders:read'])
@Get()
list() {}
```

## Частые ошибки

- `@ApiBearerAuth()` без имени, а схема зарегистрирована с именем — UI не подставляет токен.
- Документирован Bearer, а реально используется cookie (или наоборот).
- Защищённые маршруты без `@ApiBearerAuth` — генераторы клиентов не добавляют токен.
- Не указаны 401/403 ответы.

## Что важно помнить

- Схемы — в `DocumentBuilder`, требования — декораторами на операциях.
- Имена схем в `add*` и `@Api*` должны совпадать.
- Объединяйте guard, роли и Swagger в один декоратор.

## Мини-шпаргалка

- `addBearerAuth(opts, 'access-token')` + `@ApiBearerAuth('access-token')`.
- `addCookieAuth(name, opts, 'session')` + `@ApiCookieAuth('session')`.
- `addApiKey(...)` + `@ApiSecurity('api-key')`.
- `persistAuthorization: true`.
