# Как использовать ApiTags и ApiOperation

> [!NOTE]
> `@ApiTags('products')` группирует операции контроллера (или метода) в разделы документации — в Swagger UI они становятся сворачиваемыми группами, а генераторы клиентов часто создают по тегу отдельный сервис. `@ApiOperation({ summary, description, operationId, deprecated })` описывает конкретную операцию: `summary` — короткое название в списке, `description` — подробности (поддерживается Markdown: бизнес-правила, побочные эффекты, коды ошибок), `operationId` — стабильный идентификатор для генерации методов клиента, `deprecated: true` — пометка устаревшей операции. Описание и группировка — то, что превращает список путей в понятную документацию; описывать нужно **поведение и правила**, а не повторять название метода. Служебные эндпоинты (health, метрики, вебхуки) исключают из документа через `@ApiExcludeController()` / `@ApiExcludeEndpoint()`.

## Вопрос

Как группировать и описывать операции в Swagger через `@ApiTags` и `@ApiOperation`?

## Пример

```ts
@ApiTags('orders')
@ApiBearerAuth('access-token')
@Controller('orders')
export class OrdersController {
  @ApiOperation({
    summary: 'Оформить заказ',
    description: [
      'Создаёт заказ из корзины текущего пользователя и резервирует товары.',
      '',
      '- Повторный запрос с тем же `Idempotency-Key` вернёт уже созданный заказ.',
      '- Если товара не хватает — `422 INSUFFICIENT_STOCK`.',
    ].join('\n'),
    operationId: 'createOrder',
  })
  @Post()
  create(@Body() dto: CreateOrderDto) {}

  @ApiOperation({ summary: 'Отменить заказ', description: 'Доступно только для заказов в статусе `PENDING`.' })
  @Post(':id/cancel')
  cancel() {}

  @ApiOperation({ summary: 'Список заказов (устарел)', deprecated: true, description: 'Используйте `GET /v2/orders`.' })
  @Get('legacy')
  legacyList() {}
}
```

## Описание тегов

```ts
new DocumentBuilder()
  .addTag('orders', 'Оформление и управление заказами')
  .addTag('catalog', 'Товары и категории', { url: 'https://docs.example.com/catalog', description: 'Подробнее' })
```

Порядок `addTag` определяет порядок разделов в UI.

## Исключение из документа

```ts
@ApiExcludeController()
@Controller('health')
export class HealthController {}

@ApiExcludeEndpoint()
@Post('webhooks/stripe')
stripe() {}
```

## operationId

```ts
// глобально в createDocument
operationIdFactory: (controllerKey: string, methodKey: string) => methodKey   // createOrder, cancel...
```

Стабильные `operationId` важны для генерации клиентов: при переименовании метода в контроллере клиентский код не должен ломаться неожиданно.

## Что писать в description

- Бизнес-правила и ограничения («только владелец», «только в статусе PENDING»).
- Побочные эффекты (письмо, событие, списание денег).
- Идемпотентность и повторы.
- Коды ошибок и когда они возникают.
- Права доступа.

## Частые ошибки

- `summary: 'Create'` — повторяет название метода и ничего не объясняет.
- Все операции в одном теге `default` (теги не заданы).
- Служебные эндпоинты в публичной документации.
- Удалить операцию без периода `deprecated`.

## Что важно помнить

- `@ApiTags` — группировка, `@ApiOperation` — смысл операции.
- В `description` — правила, эффекты, ошибки (Markdown).
- `operationId` стабилен — от него зависят сгенерированные клиенты.

## Мини-шпаргалка

- `@ApiTags('x')` на контроллере.
- `@ApiOperation({ summary, description, operationId, deprecated })`.
- `addTag(name, description)` в `DocumentBuilder`.
- `@ApiExcludeController()`, `@ApiExcludeEndpoint()`.
