# Что такое Swagger CLI plugin

> [!NOTE]
> **Swagger CLI plugin** — плагин компилятора Nest (`"plugins": ["@nestjs/swagger"]` в `nest-cli.json`), который во время сборки анализирует TypeScript-код и **автоматически добавляет метаданные OpenAPI**: для свойств DTO — тип, обязательность по `?`, массивы, enum, значения по умолчанию; для методов контроллеров — тип ответа по возвращаемому значению и статус по умолчанию. С опцией **`classValidatorShim`** он переносит ограничения `class-validator` (`@Length`, `@Min`, `@IsEmail`…) в схему, с **`introspectComments`** — берёт `description` и `example` из JSDoc-комментариев. Плагин обрабатывает файлы с суффиксами из `dtoFileNameSuffix` (по умолчанию `.dto.ts`, `.entity.ts`) и `controllerFileNameSuffix` (`.controller.ts`) — DTO в файлах с другими именами он не увидит. Ручные `@ApiProperty` остаются для уточнений (формат, примеры, `enumName`). При сборке через SWC метаданные плагина генерируются отдельным шагом (`PluginMetadataGenerator` / `--type-check`), а в тестах с ts-jest/vitest может понадобиться их подключение.

## Вопрос

Что делает Swagger CLI plugin и как его настроить?

## Подключение

```json
// nest-cli.json
{
  "compilerOptions": {
    "plugins": [
      {
        "name": "@nestjs/swagger",
        "options": {
          "classValidatorShim": true,
          "introspectComments": true,
          "dtoFileNameSuffix": [".dto.ts", ".entity.ts", ".response.ts"]
        }
      }
    ]
  }
}
```

## До и после

```ts
// без плагина
export class CreateProductDto {
  @ApiProperty({ description: 'Название', minLength: 2, maxLength: 120 })
  @Length(2, 120)
  title: string;

  @ApiPropertyOptional({ type: [String] })
  @IsOptional()
  tags?: string[];
}

// с плагином
export class CreateProductDto {
  /**
   * Название товара
   * @example 'Клавиатура'
   */
  @Length(2, 120)
  title: string;

  @IsOptional()
  tags?: string[];
}
```

Обе версии дают одинаковую схему.

## Контроллеры

```ts
@Get(':id')
findOne(@Param('id') id: string): Promise<ProductDto> {   // плагин добавит 200 → ProductDto
  return this.products.findOne(id);
}
```

Тип должен быть **классом**: для `Promise<Product>`, где `Product` — интерфейс или тип Prisma, схемы не будет — используйте DTO-класс ответа.

## Опции

| Опция | Назначение |
| --- | --- |
| `dtoFileNameSuffix` | Какие файлы анализировать как DTO |
| `controllerFileNameSuffix` | Какие файлы — контроллеры |
| `classValidatorShim` | Перенос правил `class-validator` |
| `introspectComments` | Описание и примеры из JSDoc |
| `controllerKeyOfComment` | Куда писать комментарий метода (`summary`/`description`) |
| `skipAutoHttpCode` | Не выводить статус ответа автоматически |

## SWC и тесты

```bash
nest build -b swc --type-check     # SWC + генерация метаданных плагина
```

При использовании SWC метаданные Swagger-плагина собираются отдельно (файл `metadata.ts`, который подгружается через `SwaggerModule.loadPluginMetadata`). Если e2e-тест проверяет документ, тестовая сборка должна применять плагин, иначе схемы будут пустыми.

## Частые ошибки

- DTO в файле `create-product.ts` без суффикса `.dto.ts` — плагин его пропускает.
- Типы ответов — интерфейсы или типы Prisma, а не классы.
- Ожидать, что плагин выведет формат `uuid` или `enumName` — это уточняют вручную.
- SWC без генерации метаданных — пустая документация.

## Что важно помнить

- Плагин убирает большую часть `@ApiProperty` и выводит ответы из типов.
- Работает по суффиксам файлов и только с классами.
- `classValidatorShim` и `introspectComments` синхронизируют документацию с валидацией и комментариями.

## Мини-шпаргалка

- `"plugins": [{ "name": "@nestjs/swagger", "options": {...} }]`.
- `.dto.ts`, `.entity.ts`, `.controller.ts`.
- JSDoc `/** описание @example ... */`.
- SWC: `--type-check`, `loadPluginMetadata`.
