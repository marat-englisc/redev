# Как тестировать guards, pipes и interceptors

> [!NOTE]
> Guards, pipes, interceptors и filters — обычные классы с одним методом, поэтому их удобно тестировать **изолированно**, создавая экземпляр напрямую и подавая на вход подготовленные данные. Для **guard** нужен фейковый `ExecutionContext` (`switchToHttp().getRequest()`, `getHandler()`, `getClass()`) и, если guard читает метаданные, — настоящий или замоканный `Reflector`; проверяют результат `true`/`false` и выброшенные исключения. **Pipe** тестируется вызовом `transform(value, metadata)` — особенно полезно для `ValidationPipe` с конкретным DTO: так проверяется валидация без HTTP. **Interceptor** — вызовом `intercept(context, { handle: () => of(value) })` и проверкой результирующего `Observable` (`firstValueFrom`/`lastValueFrom`). **Filter** — вызовом `catch(exception, host)` с моком `ArgumentsHost` и проверкой `status().json()`. Готовые моки контекста дают библиотеки вроде `@golevelup/ts-vitest` (`createMock<ExecutionContext>()`).

## Вопрос

Как писать тесты для guards, pipes, interceptors и exception filters?

## Фейковый ExecutionContext

```ts
function httpContext(req: Partial<Request> & { user?: unknown }, handler = () => {}, cls = class {}): ExecutionContext {
  return {
    switchToHttp: () => ({ getRequest: () => req, getResponse: () => ({}), getNext: () => undefined }),
    getHandler: () => handler,
    getClass: () => cls,
    getType: () => 'http',
  } as unknown as ExecutionContext;
}
```

## Guard

```ts
describe('RolesGuard', () => {
  const reflector = new Reflector();
  const guard = new RolesGuard(reflector);

  it('пропускает, если ролей не требуется', () => {
    vi.spyOn(reflector, 'getAllAndOverride').mockReturnValue(undefined);
    expect(guard.canActivate(httpContext({ user: { roles: [] } }))).toBe(true);
  });

  it('403 без нужной роли', () => {
    vi.spyOn(reflector, 'getAllAndOverride').mockReturnValue([Role.Admin]);
    expect(() => guard.canActivate(httpContext({ user: { roles: [Role.User] } }))).toThrow(ForbiddenException);
  });

  it('пропускает admin', () => {
    vi.spyOn(reflector, 'getAllAndOverride').mockReturnValue([Role.Admin]);
    expect(guard.canActivate(httpContext({ user: { roles: [Role.Admin] } }))).toBe(true);
  });
});
```

## Метаданные «по-настоящему»

```ts
class TestController {
  @Roles([Role.Admin]) adminOnly() {}
}

const ctx = httpContext({ user: { roles: [Role.User] } }, TestController.prototype.adminOnly, TestController);
expect(() => new RolesGuard(new Reflector()).canActivate(ctx)).toThrow(ForbiddenException);
```

Так тест проверяет и сам декоратор, и чтение метаданных.

## Pipe и DTO

```ts
describe('CreateUserDto validation', () => {
  const pipe = new ValidationPipe({ whitelist: true, forbidNonWhitelisted: true, transform: true });
  const meta: ArgumentMetadata = { type: 'body', metatype: CreateUserDto };

  it('нормализует email', async () => {
    const dto = await pipe.transform({ email: ' Anna@X.com ', name: 'Anna', password: 'Secret123!' }, meta);
    expect(dto.email).toBe('anna@x.com');
  });

  it('отклоняет лишние поля', async () => {
    await expect(pipe.transform({ email: 'a@x.com', name: 'A', password: 'Secret123!', role: 'admin' }, meta))
      .rejects.toBeInstanceOf(BadRequestException);
  });
});
```

## Interceptor

```ts
describe('TransformInterceptor', () => {
  const interceptor = new TransformInterceptor(new Reflector());

  it('оборачивает ответ в { data }', async () => {
    const result$ = interceptor.intercept(httpContext({}), { handle: () => of({ id: 1 }) });
    await expect(lastValueFrom(result$)).resolves.toEqual({ data: { id: 1 } });
  });
});
```

## Exception filter

```ts
it('скрывает детали 500', () => {
  const json = vi.fn();
  const status = vi.fn(() => ({ json }));
  const host = {
    switchToHttp: () => ({ getResponse: () => ({ status }), getRequest: () => ({ url: '/x' }) }),
    getType: () => 'http',
  } as unknown as ArgumentsHost;

  new SafeErrorFilter().catch(new Error('db password leaked'), host);

  expect(status).toHaveBeenCalledWith(500);
  expect(json).toHaveBeenCalledWith(expect.objectContaining({ message: 'Internal server error' }));
});
```

## Частые ошибки

- Проверять guard только через e2e — медленно и сложно перебрать все ветки.
- Мокать `Reflector` так, что тест не проверяет реальные метаданные декоратора.
- Забыть, что `intercept` возвращает `Observable` — тест завершается до результата.
- Тестировать `ValidationPipe` без `metatype` — валидация не выполняется.

## Что важно помнить

- Компоненты конвейера — классы с одним методом, тестируются напрямую.
- Guard — фейковый `ExecutionContext` + `Reflector`; pipe — `transform`; interceptor — `handle: () => of(...)`.
- Интеграцию с маршрутами подтверждают e2e-тесты.

## Мини-шпаргалка

- `guard.canActivate(fakeCtx)`.
- `pipe.transform(value, { type: 'body', metatype: Dto })`.
- `lastValueFrom(interceptor.intercept(ctx, { handle: () => of(v) }))`.
- `filter.catch(err, fakeHost)`.
