# Как использовать overrideProvider

> [!NOTE]
> `overrideProvider(token)` подменяет провайдер в уже собранном графе модулей тестового приложения: можно импортировать реальный `AppModule` (или feature-модуль) со всеми его связями, а отдельные зависимости — внешний платёжный шлюз, почту, очередь, часы — заменить через `.useValue(mock)`, `.useClass(FakeClass)` или `.useFactory({ factory, inject })`. Это ключевой инструмент интеграционных и e2e-тестов: приложение собирается как в проде, но без обращений к внешним системам. Аналогично работают `overrideGuard`, `overrideInterceptor`, `overridePipe`, `overrideFilter` (подмена компонентов конвейера) и `overrideModule` (замена целого модуля). В отличие от `{ provide, useValue }` в `providers` тестового модуля, `overrideProvider` подменяет провайдер **внутри** импортированных модулей, где он реально используется.

## Вопрос

Как подменять зависимости в тестах NestJS через `overrideProvider`?

## Пример

```ts
describe('Checkout (e2e)', () => {
  let app: INestApplication;
  const payments = { charge: vi.fn().mockResolvedValue({ id: 'ch_test' }) };
  const mailer = { send: vi.fn() };

  beforeAll(async () => {
    const moduleRef = await Test.createTestingModule({ imports: [AppModule] })
      .overrideProvider(PAYMENTS_GATEWAY).useValue(payments)        // токен
      .overrideProvider(MailService).useClass(FakeMailService)      // класс-фейк
      .overrideProvider(Clock).useValue({ now: () => new Date('2026-10-24T10:00:00Z') })
      .overrideGuard(ThrottlerGuard).useValue({ canActivate: () => true })
      .compile();

    app = moduleRef.createNestApplication();
    app.useGlobalPipes(new ValidationPipe({ whitelist: true, transform: true }));
    await app.init();
  });

  afterAll(() => app.close());

  it('списывает оплату при оформлении', async () => {
    await request(app.getHttpServer()).post('/orders').set(auth).send(order).expect(201);
    expect(payments.charge).toHaveBeenCalledWith(expect.any(Number), expect.any(String));
  });
});
```

## Варианты подмены

| Метод | Когда |
| --- | --- |
| `.useValue(obj)` | Простой мок с `vi.fn()` |
| `.useClass(Fake)` | Фейк с поведением (in-memory репозиторий, фейковая почта) |
| `.useFactory({ factory, inject })` | Мок, которому нужны другие провайдеры |

## Подмена компонентов конвейера и модулей

```ts
Test.createTestingModule({ imports: [AppModule] })
  .overrideGuard(JwtAuthGuard).useClass(TestAuthGuard)          // пользователь из заголовка X-Test-User
  .overrideInterceptor(LoggingInterceptor).useValue({ intercept: (_c, n) => n.handle() })
  .overrideModule(RedisModule).useModule(FakeRedisModule)
  .compile();
```

```ts
@Injectable()
export class TestAuthGuard implements CanActivate {
  canActivate(ctx: ExecutionContext) {
    const req = ctx.switchToHttp().getRequest();
    const id = req.headers['x-test-user'];
    if (!id) throw new UnauthorizedException();
    req.user = { id, roles: (req.headers['x-test-roles'] ?? 'user').split(',') };
    return true;
  }
}
```

Так e2e-тесты не зависят от выпуска настоящих JWT, а проверки 401/403 остаются.

## Глобальные guards через APP_GUARD

Guard, зарегистрированный как `{ provide: APP_GUARD, useClass: JwtAuthGuard }`, подменяется через `overrideProvider`, если его зарегистрировать с отдельным токеном:

```ts
// app.module.ts
providers: [JwtAuthGuard, { provide: APP_GUARD, useExisting: JwtAuthGuard }]

// тест
.overrideProvider(JwtAuthGuard).useClass(TestAuthGuard)
```

## Частые ошибки

- Добавлять мок в `providers` тестового модуля, ожидая, что он заменит провайдер внутри импортированного модуля, — не заменит.
- Подменять слишком много — тест перестаёт проверять реальную интеграцию.
- Забыть `app.close()` — открытые соединения не дают завершиться тестам.
- Подменять глобальный `APP_GUARD` напрямую — нужен регистрационный приём с `useExisting`.

## Что важно помнить

- `overrideProvider` подменяет провайдер в реальном графе модулей.
- Есть аналоги для guards, interceptors, pipes, filters и модулей.
- Подменяйте только внешние и недетерминированные зависимости.

## Мини-шпаргалка

- `.overrideProvider(T).useValue(m) | useClass(F) | useFactory({ factory, inject })`.
- `.overrideGuard(G)`, `.overrideInterceptor(I)`, `.overridePipe(P)`, `.overrideFilter(F)`.
- `.overrideModule(M).useModule(FakeM)`.
- `APP_GUARD` + `useExisting` для подменяемости.
