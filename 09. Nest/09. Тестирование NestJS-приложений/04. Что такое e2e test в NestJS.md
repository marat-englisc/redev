# Что такое e2e test в NestJS

> [!NOTE]
> **E2E-тест** в NestJS поднимает приложение (обычно весь `AppModule`) в процессе теста и отправляет ему **настоящие HTTP-запросы** через `supertest` (`request(app.getHttpServer())`), проверяя статусы, тела ответов, заголовки и побочные эффекты. В отличие от unit-тестов, он проходит весь конвейер: middleware, guards, pipes, interceptors, filters, сериализацию, DI и — если подключена тестовая база — реальные запросы к БД. Важно, чтобы тестовое приложение было настроено **как в проде**: глобальные pipes, filters, prefix и versioning, заданные в `main.ts`, нужно повторить в тесте или, лучше, вынести в общую функцию `configureApp(app)` / регистрировать через `APP_*` токены. Внешние системы подменяются `overrideProvider`, данные изолируются между тестами (транзакции, очистка таблиц, отдельная схема/база на воркер). E2E-тесты медленнее unit-тестов, поэтому ими покрывают ключевые пользовательские сценарии.

## Вопрос

Что такое e2e-тест в NestJS и как его написать?

## Общая настройка приложения

```ts
// src/app.setup.ts — используется и в main.ts, и в тестах
export function configureApp(app: INestApplication) {
  app.setGlobalPrefix('api');
  app.enableVersioning({ type: VersioningType.URI, defaultVersion: '1' });
  app.useGlobalPipes(new ValidationPipe({ whitelist: true, forbidNonWhitelisted: true, transform: true }));
  return app;
}
```

## Тест

```ts
// test/users.e2e-spec.ts
import request from 'supertest';

describe('Users (e2e)', () => {
  let app: INestApplication;

  beforeAll(async () => {
    const moduleRef = await Test.createTestingModule({ imports: [AppModule] })
      .overrideProvider(MailService).useValue({ send: vi.fn() })
      .compile();

    app = configureApp(moduleRef.createNestApplication());
    await app.init();
  });

  afterAll(async () => {
    await app.close();
  });

  it('POST /api/v1/users → 201 без passwordHash', async () => {
    const res = await request(app.getHttpServer())
      .post('/api/v1/users')
      .send({ email: 'anna@x.com', name: 'Anna', password: 'Secret123!' })
      .expect(201);

    expect(res.body).toMatchObject({ email: 'anna@x.com', name: 'Anna' });
    expect(res.body).not.toHaveProperty('passwordHash');
  });

  it('POST /api/v1/users → 400 при невалидном email', async () => {
    const res = await request(app.getHttpServer())
      .post('/api/v1/users')
      .send({ email: 'not-an-email', name: 'A', password: '1' })
      .expect(400);

    expect(res.body.message).toEqual(expect.arrayContaining([expect.stringContaining('email')]));
  });

  it('GET /api/v1/users/me → 401 без токена', () =>
    request(app.getHttpServer()).get('/api/v1/users/me').expect(401));
});
```

## Что покрывать e2e

- Регистрация, логин, refresh, logout.
- Доступ: 401 без токена, 403 без роли, 404 к чужому ресурсу (IDOR).
- Создание ресурса → чтение → изменение → удаление.
- Валидация и единый формат ошибок.
- Критичные бизнес-сценарии (оформление заказа, оплата с фейковым шлюзом).

## Изоляция данных

| Способ | Плюсы | Минусы |
| --- | --- | --- |
| `TRUNCATE` таблиц перед каждым тестом | Просто | Медленнее при многих таблицах |
| Транзакция на тест с откатом | Быстро | Сложно, если код сам открывает транзакции |
| База/схема на тестовый воркер | Параллельность | Нужна инфраструктура (Testcontainers) |
| Уникальные данные в каждом тесте | Без очистки | Мусор копится |

Подробнее — [тестирование с реальной базой данных](<06. Как тестировать с реальной базой данных.md>).

## Частые ошибки

- В тесте нет глобального `ValidationPipe` из `main.ts` — проверки «проходят», а в проде нет.
- Тесты зависят от порядка выполнения и общих данных.
- Нет `app.close()` — тестовый процесс не завершается.
- Обращение к реальным внешним API (почта, платежи) из тестов.
- Проверка только статуса без тела ответа.

## Что важно помнить

- E2E = приложение + HTTP-запросы через supertest + весь конвейер.
- Конфигурация приложения в тесте должна совпадать с продом.
- Внешние системы — `overrideProvider`, данные — изолированы.

## Мини-шпаргалка

- `Test.createTestingModule({ imports: [AppModule] }).compile()`.
- `app = moduleRef.createNestApplication(); configureApp(app); await app.init()`.
- `request(app.getHttpServer()).post(url).send(body).expect(201)`.
- `afterAll(() => app.close())`.
