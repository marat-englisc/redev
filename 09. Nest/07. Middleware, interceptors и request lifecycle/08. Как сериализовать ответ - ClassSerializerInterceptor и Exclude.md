# Как сериализовать ответ - ClassSerializerInterceptor и Exclude

> [!NOTE]
> **Сериализация** — превращение объекта, который вернул обработчик, в то, что уйдёт клиенту. В NestJS для этого есть `ClassSerializerInterceptor`: он вызывает `instanceToPlain()` из `class-transformer` и применяет декораторы класса ответа — `@Exclude()` (скрыть поле, например `passwordHash`), `@Expose()` (показать вычисляемое свойство или поле при стратегии `excludeAll`), `@Transform()` (изменить значение), `@Type()` (вложенные объекты), а также **группы** (`groups: ['admin']`) для разных представлений одной сущности. Ключевое условие: interceptor работает только с **экземплярами классов** — если сервис вернул plain-объект из Prisma, декораторы не сработают, поэтому оборачивают результат (`new UserEntity(user)` или `plainToInstance`). Альтернативы — явный `select` полей в запросе к БД или маппинг в response DTO в сервисе: они проще и надёжнее для Prisma-проектов.

## Вопрос

Как скрывать поля и управлять формой ответа через сериализацию в NestJS?

## Класс ответа

```ts
export class UserEntity {
  id: string;
  email: string;
  name: string;

  @Exclude()
  passwordHash: string;

  @Exclude()
  deletedAt: Date | null;

  @Expose({ groups: ['admin'] })
  lastLoginIp: string;

  @Expose()
  get displayName() {
    return this.name || this.email.split('@')[0];
  }

  @Transform(({ value }) => value.toISOString())
  createdAt: Date;

  constructor(partial: Partial<UserEntity>) {
    Object.assign(this, partial);
  }
}
```

## Подключение

```ts
// глобально
providers: [{ provide: APP_INTERCEPTOR, useClass: ClassSerializerInterceptor }]

// или на контроллер с опциями
@UseInterceptors(ClassSerializerInterceptor)
@SerializeOptions({ excludeExtraneousValues: false })
@Controller('users')
export class UsersController {
  @Get(':id')
  async findOne(@Param('id') id: string) {
    const user = await this.users.findOne(id);       // plain-объект из Prisma
    return new UserEntity(user);                     // ← обязательно экземпляр
  }

  @Get(':id/admin-view')
  @SerializeOptions({ groups: ['admin'] })
  @Roles([Role.Admin])
  async adminView(@Param('id') id: string) {
    return new UserEntity(await this.users.findOne(id));
  }
}
```

```json
{ "id": "u1", "email": "anna@x.com", "name": "Anna", "displayName": "Anna", "createdAt": "2026-10-24T10:00:00.000Z" }
```

## SerializeOptions с типом (без ручного new)

```ts
@Get(':id')
@SerializeOptions({ type: UserEntity })        // interceptor сам превратит plain в экземпляр
findOne(@Param('id') id: string) {
  return this.users.findOne(id);
}
```

## Стратегия excludeAll

```ts
@Exclude()
export class PublicProfile {
  @Expose() id: string;
  @Expose() name: string;
  @Expose() avatarUrl: string;
  // всё остальное скрыто по умолчанию — безопаснее для публичных ответов
}
```

## Сравнение подходов

| Подход | Плюсы | Минусы |
| --- | --- | --- |
| `ClassSerializerInterceptor` + `@Exclude` | Декларативно, группы, вычисляемые поля | Работает только с экземплярами классов, легко забыть обёртку |
| `select` в запросе Prisma/TypeORM | Не читаем лишнее из БД, надёжно | Нужно повторять выбор полей |
| Ручной маппинг в response DTO | Явно, типобезопасно | Больше кода |
| Zod-схема ответа (`parse`) | Валидация формы ответа | Дополнительные затраты на каждый ответ |

## Частые ошибки

- Вернуть plain-объект — `@Exclude` молча не сработал, `passwordHash` ушёл клиенту.
- Использовать один класс и для входа, и для ответа.
- `@Exclude` на поле, которое нужно при сохранении в БД через тот же класс (TypeORM entity) — путаница слоёв.
- Не включить interceptor глобально и полагаться на декораторы.

## Что важно помнить

- `ClassSerializerInterceptor` применяет `class-transformer` к экземплярам классов.
- `@Exclude`, `@Expose`, `@Transform`, группы управляют формой ответа.
- Для Prisma-проектов часто проще `select` или маппинг в DTO.

## Мини-шпаргалка

- `{ provide: APP_INTERCEPTOR, useClass: ClassSerializerInterceptor }`.
- `@Exclude()`, `@Expose({ groups })`, `@Transform()`.
- `return new Entity(plain)` или `@SerializeOptions({ type: Entity })`.
- `@SerializeOptions({ groups: ['admin'] })`.
