# Что такое custom decorator в NestJS

> [!NOTE]
> В NestJS есть три вида своих декораторов. **Param decorators** через `createParamDecorator((data, ctx) => ...)` извлекают значение для аргумента обработчика — классический пример `@CurrentUser()`, который возвращает `request.user` (положенный туда guard-ом аутентификации), или `@CurrentUser('id')` — одно поле. Такие декораторы делают контроллер независимым от `@Req()` и платформы, к ним можно подключать pipes (`@CurrentUser(new ValidationPipe(...))` с `validateCustomDecorators: true`). **Metadata decorators** (`Reflector.createDecorator`, `SetMetadata`) помечают маршруты для guards и interceptors (`@Roles`, `@Public`). **Композиция** через `applyDecorators(...)` объединяет несколько декораторов в один (`@Auth('admin')` = guards + роли + Swagger-описание). Свои декораторы убирают повторение и делают контроллеры декларативными.

## Вопрос

Как создавать свои декораторы в NestJS, например для получения текущего пользователя?

## @CurrentUser

```ts
export interface AuthUser {
  id: string;
  email: string;
  roles: Role[];
}

export const CurrentUser = createParamDecorator(
  (field: keyof AuthUser | undefined, ctx: ExecutionContext) => {
    const request = ctx.switchToHttp().getRequest<{ user?: AuthUser }>();
    const user = request.user;
    if (!user) throw new UnauthorizedException();     // защита, если guard не подключён
    return field ? user[field] : user;
  },
);
```

```ts
@Get('me')
me(@CurrentUser() user: AuthUser) {
  return this.users.findProfile(user.id);
}

@Post()
create(@Body() dto: CreateOrderDto, @CurrentUser('id') userId: string) {
  return this.orders.create(userId, dto);
}
```

## Для разных транспортов

```ts
export const CurrentUser = createParamDecorator((_: unknown, ctx: ExecutionContext) => {
  switch (ctx.getType<GqlContextType>()) {
    case 'graphql': return GqlExecutionContext.create(ctx).getContext().req.user;
    case 'ws':      return ctx.switchToWs().getClient().data.user;
    default:        return ctx.switchToHttp().getRequest().user;
  }
});
```

## Другие полезные param-декораторы

```ts
export const RequestId = createParamDecorator((_: unknown, ctx: ExecutionContext) =>
  ctx.switchToHttp().getRequest().headers['x-request-id'],
);

export const ClientIp = createParamDecorator((_: unknown, ctx: ExecutionContext) =>
  ctx.switchToHttp().getRequest<Request>().ip,
);

export const Tenant = createParamDecorator((_: unknown, ctx: ExecutionContext) => {
  const tenant = ctx.switchToHttp().getRequest().headers['x-tenant-id'];
  if (!tenant) throw new BadRequestException('x-tenant-id header is required');
  return tenant;
});
```

## Метаданные и композиция

```ts
export const Roles = Reflector.createDecorator<Role[]>();

export function Auth(...roles: Role[]) {
  return applyDecorators(
    UseGuards(JwtAuthGuard, RolesGuard),
    Roles(roles),
    ApiBearerAuth(),
    ApiUnauthorizedResponse(),
    ApiForbiddenResponse(),
  );
}

@Auth(Role.Admin)
@Delete(':id')
remove(@Param('id', ParseUUIDPipe) id: string) {}
```

## Pipes в param-декораторах

```ts
@Get()
list(@CurrentUser(new ValidationPipe({ validateCustomDecorators: true })) user: AuthUserDto) {}
```

По умолчанию глобальный `ValidationPipe` **не** валидирует значения своих декораторов — нужен флаг `validateCustomDecorators`.

## Частые ошибки

- `@CurrentUser()` на маршруте без guard аутентификации — `undefined`.
- Доступ к `request.user` через `@Req()` в каждом методе вместо декоратора.
- Сложная логика (запросы к БД) внутри param-декоратора — у него нет DI; используйте pipe или guard.
- Забыть `GqlExecutionContext` для GraphQL.

## Что важно помнить

- `createParamDecorator` — значение аргумента, `Reflector.createDecorator` — метаданные, `applyDecorators` — композиция.
- `@CurrentUser()` читает то, что положил guard.
- Param-декоратор без DI — тяжёлая логика в pipes/guards.

## Мини-шпаргалка

- `createParamDecorator((data, ctx) => ctx.switchToHttp().getRequest().user)`.
- `@CurrentUser('id')` — поле.
- `applyDecorators(UseGuards(...), Roles(...), ApiBearerAuth())`.
- `validateCustomDecorators: true`.
