# Что такое caching в NestJS

> [!NOTE]
> Кеширование сохраняет результат дорогой операции (запроса к БД, внешнего API, расчёта), чтобы повторно отдавать его быстрее. В NestJS для этого есть `@nestjs/cache-manager` поверх `cache-manager`, который в актуальных версиях использует хранилища **Keyv** (`@keyv/redis` для Redis); **TTL задаётся в миллисекундах**. Два способа: **автоматический** `CacheInterceptor` для `GET`-ответов (ключ по URL, `@CacheKey`, `@CacheTTL` для настройки) и **ручной** — внедрить `CACHE_MANAGER` и вызывать `get`/`set`/`del` в сервисе (паттерн **cache-aside**), что гибче и позволяет инвалидировать кеш при изменении данных. In-memory кеш годится для одного процесса; при нескольких инстансах нужен **Redis**. Главная сложность — **инвалидация**: устаревшие данные, персональные ответы под общим ключом, «штурм» базы при одновременном истечении ключа (cache stampede).

## Вопрос

Как работает кеширование в NestJS и как его правильно применять?

## Подключение с Redis

```bash
npm install @nestjs/cache-manager cache-manager @keyv/redis
```

```ts
@Module({
  imports: [
    CacheModule.registerAsync({
      isGlobal: true,
      inject: [ConfigService],
      useFactory: (config: ConfigService) => ({
        ttl: 60_000,                                            // мс
        stores: [createKeyv(config.getOrThrow('REDIS_URL'))],  // из @keyv/redis
      }),
    }),
  ],
})
export class AppModule {}
```

## Cache-aside в сервисе

```ts
@Injectable()
export class ProductsService {
  constructor(@Inject(CACHE_MANAGER) private readonly cache: Cache, private readonly repo: ProductsRepository) {}

  async findOne(id: string) {
    const key = `product:${id}`;
    const cached = await this.cache.get<ProductDto>(key);
    if (cached) return cached;

    const product = await this.repo.findById(id);
    if (!product) throw new NotFoundException();
    await this.cache.set(key, product, 5 * 60_000);
    return product;
  }

  async update(id: string, dto: UpdateProductDto) {
    const product = await this.repo.update(id, dto);
    await this.cache.del(`product:${id}`);          // инвалидация при изменении
    return product;
  }
}
```

## CacheInterceptor

```ts
@Controller('catalog')
@UseInterceptors(CacheInterceptor)
export class CatalogController {
  @Get('categories')
  @CacheTTL(10 * 60_000)
  categories() { return this.catalog.categories(); }      // кешируется по URL

  @Get('featured')
  @CacheKey('catalog:featured')
  featured() { return this.catalog.featured(); }
}
```

`CacheInterceptor` кеширует только `GET` и не подходит для персональных данных: ответ одного пользователя может уйти другому. Для таких случаев переопределяют `trackBy()` (добавить userId в ключ) или кешируют в сервисе.

## Что и где кешировать

| Уровень | Пример | Инструмент |
| --- | --- | --- |
| HTTP-кеш клиента/CDN | Публичный каталог, статика | `Cache-Control`, `ETag` |
| Ответ эндпоинта | Список категорий | `CacheInterceptor` |
| Данные в сервисе | Товар, настройки, курсы валют | `CACHE_MANAGER` |
| Результат внешнего API | Геокодер, курсы | `CACHE_MANAGER` + TTL |
| Тяжёлый отчёт | Агрегаты | Materialized view / предрасчёт |

## Проблемы

| Проблема | Решение |
| --- | --- |
| Устаревшие данные | Инвалидация `del` при записи, разумный TTL |
| Персональные данные под общим ключом | userId в ключе или не кешировать |
| Cache stampede | Случайный разброс TTL, блокировка на пересчёт, `stale-while-revalidate` |
| Инвалидация группы ключей | Версия в ключе (`catalog:v42:*`), теги |
| Кеш в памяти при нескольких репликах | Redis |

## Частые ошибки

- TTL в секундах по старой документации (сейчас — миллисекунды).
- `CacheInterceptor` на эндпоинтах с данными пользователя.
- Кешировать без инвалидации при изменении.
- Кешировать ошибки или `null` надолго.
- In-memory кеш в кластере — разные инстансы отдают разные данные.

## Что важно помнить

- `@nestjs/cache-manager` + Keyv-хранилище; TTL — мс.
- Cache-aside в сервисе гибче, `CacheInterceptor` — для простых публичных `GET`.
- Самое сложное — инвалидация и персональные данные.

## Мини-шпаргалка

- `CacheModule.registerAsync({ isGlobal, useFactory: () => ({ ttl, stores: [createKeyv(url)] }) })`.
- `@Inject(CACHE_MANAGER) cache: Cache` → `get/set/del`.
- `@UseInterceptors(CacheInterceptor)`, `@CacheTTL(ms)`, `@CacheKey(key)`.
- Ключи с версией и userId.
