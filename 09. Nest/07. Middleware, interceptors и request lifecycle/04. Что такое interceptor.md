# Что такое interceptor

> [!NOTE]
> **Interceptor** — класс с методом `intercept(context, next)`, который **оборачивает** вызов обработчика: код до `next.handle()` выполняется перед обработчиком (после guards, до pipes), а `next.handle()` возвращает **RxJS `Observable`** с результатом, к которому можно применить операторы — `map` (преобразовать ответ), `tap` (побочный эффект: лог, метрика, аудит), `catchError` (перехватить и заменить ошибку), `timeout` (ограничить время), `retry`. Можно и вовсе не вызывать `next.handle()`, а вернуть значение из кеша. Interceptor получает `ExecutionContext`, поэтому знает обработчик и его метаданные. Подключение — `@UseInterceptors` на метод/контроллер или глобально (`APP_INTERCEPTOR`). Типичные задачи: замер времени, логирование, обёртка ответа `{ data }`, сериализация (`ClassSerializerInterceptor`), кеширование (`CacheInterceptor`), таймауты, загрузка файлов (`FileInterceptor`).

## Вопрос

Что такое interceptor в NestJS и для чего он используется?

## Структура

```ts
@Injectable()
export class LoggingInterceptor implements NestInterceptor {
  private readonly logger = new Logger('Handler');

  intercept(context: ExecutionContext, next: CallHandler): Observable<unknown> {
    const name = `${context.getClass().name}.${context.getHandler().name}`;
    const start = performance.now();                       // ← до обработчика

    return next.handle().pipe(                              // ← обработчик
      tap({
        next: () => this.logger.log(`${name} ${Math.round(performance.now() - start)}ms`),
        error: (e) => this.logger.warn(`${name} failed: ${e.message}`),
      }),
    );
  }
}
```

## Таймаут

```ts
@Injectable()
export class TimeoutInterceptor implements NestInterceptor {
  intercept(_ctx: ExecutionContext, next: CallHandler) {
    return next.handle().pipe(
      timeout(5_000),
      catchError((err) =>
        err instanceof TimeoutError ? throwError(() => new RequestTimeoutException()) : throwError(() => err),
      ),
    );
  }
}
```

Таймаут прерывает ожидание ответа, но не отменяет уже начатую операцию (запрос к БД продолжит выполняться) — для отмены нужен `AbortSignal` в сервисе.

## Кеш в обход обработчика

```ts
@Injectable()
export class SimpleCacheInterceptor implements NestInterceptor {
  constructor(private readonly cache: Cache) {}

  async intercept(ctx: ExecutionContext, next: CallHandler) {
    const req = ctx.switchToHttp().getRequest();
    if (req.method !== 'GET') return next.handle();

    const key = `http:${req.originalUrl}`;
    const cached = await this.cache.get(key);
    if (cached) return of(cached);                       // обработчик не вызывается

    return next.handle().pipe(tap((data) => this.cache.set(key, data, 30_000)));
  }
}
```

## Подключение

```ts
@UseInterceptors(LoggingInterceptor)              // контроллер или метод
@Controller('orders')
export class OrdersController {}

// глобально с DI
providers: [
  { provide: APP_INTERCEPTOR, useClass: LoggingInterceptor },
  { provide: APP_INTERCEPTOR, useClass: TimeoutInterceptor },
]
```

На входе interceptors выполняются от глобальных к методу, на выходе (операторы `pipe`) — в обратном порядке.

## Interceptor и другие элементы

| Нужно | Инструмент |
| --- | --- |
| Изменить ответ, замерить время обработчика | Interceptor |
| Отклонить запрос до обработчика | Guard |
| Поймать любую ошибку и сформировать ответ | Exception filter |
| Логировать все HTTP-запросы, включая 404 | Middleware |

## Частые ошибки

- Забыть `return` перед `next.handle()` — ответ не придёт.
- Использовать `@Res()` в обработчике — interceptor не увидит результат.
- Ожидать, что interceptor поймает ошибку guard-а (guards раньше).
- Тяжёлая синхронная работа в `map` для больших ответов.

## Что важно помнить

- Interceptor оборачивает обработчик: до — синхронный код, после — RxJS-операторы.
- `map`, `tap`, `catchError`, `timeout` — основные инструменты.
- Глобально с DI — `APP_INTERCEPTOR`.

## Мини-шпаргалка

- `intercept(ctx, next) { return next.handle().pipe(...) }`.
- `tap` — лог, `map` — трансформация, `timeout` + `catchError`.
- `of(value)` — вернуть без вызова обработчика.
- `@UseInterceptors(...)`, `APP_INTERCEPTOR`.
