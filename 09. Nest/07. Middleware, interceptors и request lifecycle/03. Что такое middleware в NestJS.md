# Что такое middleware в NestJS

> [!NOTE]
> **Middleware** в NestJS — функция или класс с методом `use(req, res, next)`, который выполняется **до роутинга к обработчику**, как в Express: может прочитать и изменить запрос и ответ, завершить запрос или передать управление дальше через `next()`. Классовые middleware (`@Injectable() implements NestMiddleware`) поддерживают DI. Подключаются глобально через `app.use()` (без DI, для любых маршрутов — включая 404) или в модуле, реализующем `NestModule`, через `MiddlewareConsumer`: `consumer.apply(X).exclude(...).forRoutes(...)` — с выбором маршрутов, методов и контроллеров. Middleware **не знает**, какой обработчик будет вызван, и не имеет доступа к метаданным — поэтому авторизацию делают guards, а middleware оставляют для «низкоуровневых» задач: request id, логирование, парсинг cookies/тела, заголовки безопасности, CORS, контекст запроса (CLS). Middleware работает только для HTTP, не для WebSocket и микросервисов.

## Вопрос

Что такое middleware в NestJS и когда его использовать?

## Классовый middleware

```ts
@Injectable()
export class RequestIdMiddleware implements NestMiddleware {
  use(req: Request, res: Response, next: NextFunction) {
    const id = (req.headers['x-request-id'] as string) ?? randomUUID();
    req.headers['x-request-id'] = id;
    res.setHeader('x-request-id', id);
    next();
  }
}

@Injectable()
export class HttpLoggerMiddleware implements NestMiddleware {
  private readonly logger = new Logger('HTTP');

  use(req: Request, res: Response, next: NextFunction) {
    const start = performance.now();
    res.on('finish', () => {
      this.logger.log(`${req.method} ${req.originalUrl} ${res.statusCode} ${Math.round(performance.now() - start)}ms`);
    });
    next();
  }
}
```

## Подключение в модуле

```ts
@Module({ /* ... */ })
export class AppModule implements NestModule {
  configure(consumer: MiddlewareConsumer) {
    consumer
      .apply(RequestIdMiddleware, HttpLoggerMiddleware)
      .exclude({ path: 'health', method: RequestMethod.GET })
      .forRoutes('*');                                    // все маршруты

    consumer.apply(WebhookSignatureMiddleware).forRoutes({ path: 'webhooks/*path', method: RequestMethod.POST });
    consumer.apply(LegacyHeadersMiddleware).forRoutes(UsersController);
  }
}
```

## Функциональный и глобальный

```ts
export function securityHeaders(req: Request, res: Response, next: NextFunction) {
  res.setHeader('X-Content-Type-Options', 'nosniff');
  next();
}

// main.ts — без DI, для всех запросов
app.use(helmet());
app.use(cookieParser());
app.use(securityHeaders);
```

## Middleware или guard или interceptor

| Задача | Где |
| --- | --- |
| Request id, логирование HTTP, CLS-контекст | Middleware |
| `helmet`, `cookie-parser`, `compression` | Middleware (`app.use`) |
| Аутентификация, роли | Guard |
| Время выполнения обработчика, трансформация ответа | Interceptor |
| Проверка подписи вебхука по сырому телу | Middleware или guard (с `rawBody: true`) |

## Fastify

Middleware в Fastify-адаптере получает «сырые» `IncomingMessage`/`ServerResponse` Node.js, а не Express-объекты — Express-специфичные методы (`res.json`, `req.originalUrl`) не работают. Для Fastify часто лучше использовать хуки и плагины.

## Частые ошибки

- Забыть `next()` — запрос «повисает».
- Авторизация в middleware — нет доступа к `@Public()`/`@Roles()`.
- Ожидать, что middleware сработает для WebSocket-событий.
- `forRoutes('users')` и удивление, что `users/:id` не покрыт — используйте wildcard или контроллер.

## Что важно помнить

- Middleware — до роутинга, без знания обработчика.
- Подключение: `app.use()` глобально или `MiddlewareConsumer` с маршрутами.
- Для auth — guards, для работы с результатом — interceptors.

## Мини-шпаргалка

- `@Injectable() class X implements NestMiddleware { use(req, res, next) }`.
- `configure(consumer) { consumer.apply(X).exclude(...).forRoutes(...) }`.
- `app.use(fn)` — глобально, без DI.
- Всегда `next()` или ответ.
