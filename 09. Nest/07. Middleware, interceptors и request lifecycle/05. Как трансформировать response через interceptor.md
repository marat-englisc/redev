# Как трансформировать response через interceptor

> [!NOTE]
> Чтобы все успешные ответы API имели единую форму (например, `{ data, meta }`), используют **глобальный interceptor** с оператором `map` над результатом `next.handle()`. Он может обернуть данные, добавить метаданные (requestId, время), преобразовать `null` в 404, привести даты к ISO или удалить служебные поля. Важно не ломать особые ответы: файлы (`StreamableFile`), SSE, `204 No Content`, ответы, отправленные через `@Res()`, и уже обёрнутые пагинированные результаты. Для исключений обёртку делает не interceptor, а **exception filter**. Решение «оборачивать или нет» — договорённость API: обёртка `{ data }` упрощает расширение ответа метаданными, но добавляет уровень вложенности; многие API отдают ресурс как есть, а `{ items, meta }` — только для списков.

## Вопрос

Как привести ответы API к единому формату с помощью interceptor?

## Обёртка ответа

```ts
export interface ApiResponse<T> {
  data: T;
  meta?: Record<string, unknown>;
}

export const SkipTransform = Reflector.createDecorator<boolean>({ transform: (v) => v ?? true });

@Injectable()
export class TransformInterceptor<T> implements NestInterceptor<T, ApiResponse<T> | T> {
  constructor(private readonly reflector: Reflector) {}

  intercept(ctx: ExecutionContext, next: CallHandler<T>): Observable<ApiResponse<T> | T> {
    const skip = this.reflector.getAllAndOverride(SkipTransform, [ctx.getHandler(), ctx.getClass()]);
    if (skip || ctx.getType() !== 'http') return next.handle();

    return next.handle().pipe(
      map((value) => {
        if (value instanceof StreamableFile || value === undefined) return value;      // файлы, 204
        if (isPaginated(value)) return { data: value.items, meta: value.meta };         // списки
        return { data: value };
      }),
    );
  }
}

function isPaginated(v: unknown): v is { items: unknown[]; meta: Record<string, unknown> } {
  return typeof v === 'object' && v !== null && 'items' in v && 'meta' in v;
}

// app.module.ts
providers: [{ provide: APP_INTERCEPTOR, useClass: TransformInterceptor }]
```

```json
// GET /api/products/1
{ "data": { "id": 1, "title": "Keyboard" } }

// GET /api/products?page=2
{ "data": [ ... ], "meta": { "page": 2, "limit": 20, "total": 134 } }
```

## null → 404

```ts
@Injectable()
export class NotFoundInterceptor implements NestInterceptor {
  intercept(_ctx: ExecutionContext, next: CallHandler) {
    return next.handle().pipe(
      map((value) => {
        if (value === null) throw new NotFoundException();
        return value;
      }),
    );
  }
}
```

Удобно, но неявно; часто понятнее бросать `NotFoundException` в сервисе.

## Заголовки из interceptor

```ts
intercept(ctx: ExecutionContext, next: CallHandler) {
  const res = ctx.switchToHttp().getResponse<Response>();
  return next.handle().pipe(
    tap((value) => {
      if (isPaginated(value)) res.setHeader('X-Total-Count', String(value.meta.total));
    }),
  );
}
```

## Swagger и обёртка

Если ответы обёрнуты, документация должна это отражать — через generic-схему `ApiResponse<T>` (`ApiExtraModels` + `getSchemaPath`), иначе клиентские типы будут неверными. См. [generic-ответы в Swagger](<../15. Swagger и OpenAPI подробно/08. Как документировать пагинацию и generic-ответы.md>).

## Частые ошибки

- Оборачивать `StreamableFile` и ломать скачивание.
- Двойная обёртка: сервис уже вернул `{ data }`, interceptor добавил ещё.
- Пытаться форматировать ошибки interceptor-ом (`catchError` → `of({ error })` со статусом 200).
- Обёртка в REST-ответах, но не в Swagger — фронтенд генерирует неверные типы.

## Что важно помнить

- Единый формат успешных ответов — глобальный interceptor с `map`.
- Исключения — особые типы ответов (файлы, 204, SSE) и `@SkipTransform()`.
- Формат ошибок — в exception filter, формат в документации — в Swagger.

## Мини-шпаргалка

- `next.handle().pipe(map((v) => ({ data: v })))`.
- `APP_INTERCEPTOR` — глобально.
- Пропускать `StreamableFile`, `undefined`.
- Метаданные-флаг `@SkipTransform()`.
