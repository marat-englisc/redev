# Как создать auth.ts для Better Auth

> [!NOTE]
> `auth.ts` создаёт и экспортирует экземпляр `auth = betterAuth({...})` — центральную конфигурацию аутентификации. Основные опции: **`database`** — адаптер (Prisma, Drizzle, Kysely/pg), **`secret`** и **`baseURL`** (по умолчанию берутся из `BETTER_AUTH_SECRET` / `BETTER_AUTH_URL`), **`basePath`** (по умолчанию `/api/auth`), **`trustedOrigins`** — allowlist origin-ов фронтенда (защита от CSRF и open redirect), **`emailAndPassword`** (вход по паролю, `requireEmailVerification`, `sendResetPassword`), **`emailVerification`** (`sendVerificationEmail`), **`socialProviders`** (Google, GitHub…), **`session`** (`expiresIn`, `updateAge`, `cookieCache`), **`rateLimit`**, **`advanced`** (cookies, IP-заголовки за прокси, генерация id, joins), **`plugins`** (admin, organization, twoFactor, apiKey, bearer, jwt и др.), а также `hooks`/`databaseHooks`. Файл должен находиться там, где его найдёт Better Auth CLI, или путь передают флагом `--config`.

## Вопрос

Как настроить `auth.ts` для Better Auth?

## Пример

```ts
// src/auth/auth.ts
import { betterAuth } from 'better-auth';
import { prismaAdapter } from 'better-auth/adapters/prisma';
import { admin, organization, twoFactor } from 'better-auth/plugins';
import { prisma } from '../database/prisma.client';
import { sendMail } from '../mail/send-mail';

export const auth = betterAuth({
  appName: 'Shop',
  baseURL: process.env.BETTER_AUTH_URL,
  secret: process.env.BETTER_AUTH_SECRET,
  database: prismaAdapter(prisma, { provider: 'postgresql' }),

  trustedOrigins: [process.env.FRONTEND_URL!],

  emailAndPassword: {
    enabled: true,
    minPasswordLength: 10,
    requireEmailVerification: true,
    sendResetPassword: async ({ user, url }) => {
      await sendMail(user.email, 'Сброс пароля', `Перейдите по ссылке: ${url}`);
    },
  },

  emailVerification: {
    sendOnSignUp: true,
    sendVerificationEmail: async ({ user, url }) => {
      await sendMail(user.email, 'Подтвердите email', url);
    },
  },

  socialProviders: {
    github: { clientId: process.env.GITHUB_CLIENT_ID!, clientSecret: process.env.GITHUB_CLIENT_SECRET! },
  },

  session: {
    expiresIn: 60 * 60 * 24 * 7,        // 7 дней
    updateAge: 60 * 60 * 24,            // продлевать раз в сутки при активности
    cookieCache: { enabled: true, maxAge: 5 * 60 },   // меньше запросов к БД за сессией
  },

  plugins: [admin(), organization(), twoFactor()],
});

export type Auth = typeof auth;
```

## Ключевые опции

| Опция | Назначение |
| --- | --- |
| `database` | Адаптер хранения пользователей, сессий, аккаунтов |
| `secret`, `baseURL`, `basePath` | Подпись, публичный URL, префикс эндпоинтов |
| `trustedOrigins` | Разрешённые origin-ы для запросов и редиректов |
| `emailAndPassword` | Вход по паролю, требования, сброс |
| `emailVerification` | Отправка писем подтверждения |
| `socialProviders` | OAuth |
| `session` | Срок жизни, продление, кеш в cookie |
| `rateLimit` | Встроенное ограничение запросов к auth-эндпоинтам |
| `advanced` | Cookies (`useSecureCookies`, `crossSubDomainCookies`), IP-заголовки, `database.joins` |
| `plugins` | Расширения: admin, organization, twoFactor, passkey, apiKey, bearer, jwt |
| `hooks`, `databaseHooks` | Логика до/после эндпоинтов и операций с БД |

## Prisma-клиент для auth.ts

`auth.ts` создаётся на этапе загрузки модулей, вне DI Nest, поэтому ему нужен свой экземпляр клиента. Чтобы не плодить пулы, клиент выносят в модуль и переиспользуют в `PrismaService`/провайдере:

```ts
// src/database/prisma.client.ts
export const prisma = new PrismaClient({ adapter: new PrismaPg({ connectionString: process.env.DATABASE_URL }) });

// PrismaModule
providers: [{ provide: PrismaService, useValue: prisma }]
```

`process.env` здесь должен быть уже загружен (`import 'dotenv/config'` в начале `main.ts`) — `auth.ts` читает env раньше, чем `ConfigModule`.

## Отправка писем

Колбэки `sendResetPassword` и `sendVerificationEmail` не должны блокировать ответ надолго: в проде их делают через очередь (BullMQ), а в колбэке только ставят задачу.

## Частые ошибки

- `localhost` в `trustedOrigins` продакшена.
- Отсутствие `sendResetPassword` при включённом сбросе — ссылка не дойдёт.
- Новый `PrismaClient` в `auth.ts` при уже существующем в приложении — два пула соединений.
- Изменение плагинов без повторной генерации схемы (`auth generate`) — не хватает таблиц/столбцов.

## Что важно помнить

- `auth.ts` экспортирует `auth` — им пользуются Nest и CLI.
- `trustedOrigins` — строгий allowlist.
- Плагины добавляют эндпоинты и таблицы — после изменений обновить схему.

## Мини-шпаргалка

- `betterAuth({ database, trustedOrigins, emailAndPassword, socialProviders, session, plugins })`.
- `prismaAdapter(prisma, { provider: 'postgresql' })`.
- `session: { expiresIn, updateAge, cookieCache }`.
- `export type Auth = typeof auth`.
