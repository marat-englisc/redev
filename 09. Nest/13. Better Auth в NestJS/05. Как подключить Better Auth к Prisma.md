# Как подключить Better Auth к Prisma

> [!NOTE]
> Better Auth хранит пользователей, сессии, аккаунты (пароли и OAuth-связки) и токены верификации в **вашей базе**. С Prisma это делается адаптером: пакет **`@better-auth/prisma-adapter`**, функция `prismaAdapter(prisma, { provider: 'postgresql' })`, импортируемая (по документации) из `better-auth/adapters/prisma`. `provider` должен соответствовать СУБД (`postgresql`, `mysql`, `sqlite`…). Модели для `schema.prisma` генерирует **Better Auth CLI** (`npx auth@latest generate`), а применяются они обычной **миграцией Prisma** (`prisma migrate dev` / `deploy`) — Better Auth сам миграции Prisma не выполняет. Если клиент Prisma генерируется в свой путь (в Prisma 7 это стандарт), в `auth.ts` его импортируют из этого пути и создают с driver adapter. С версии 1.4 адаптер поддерживает **joins** — загрузку связанных данных одним запросом: включаются опцией `advanced.database.joins: true` и требуют описанных связей в схеме.

## Вопрос

Как подключить Better Auth к базе через Prisma?

## auth.ts с Prisma (Prisma 7)

```ts
import { betterAuth } from 'better-auth';
import { prismaAdapter } from 'better-auth/adapters/prisma';
import { prisma } from '../database/prisma.client';     // PrismaClient({ adapter: new PrismaPg(...) })

export const auth = betterAuth({
  database: prismaAdapter(prisma, { provider: 'postgresql' }),
  emailAndPassword: { enabled: true },
  advanced: {
    database: { joins: true },            // Better Auth 1.4+: связи одним запросом
  },
});
```

## Генерация моделей и миграция

```bash
npx auth@latest generate                 # добавит модели User, Session, Account, Verification (+ плагины)
npx prisma migrate dev --name better_auth
npx prisma generate
```

```prisma
model User {
  id            String    @id
  name          String
  email         String    @unique
  emailVerified Boolean   @default(false)
  image         String?
  createdAt     DateTime  @default(now())
  updatedAt     DateTime  @updatedAt
  sessions      Session[]
  accounts      Account[]
  @@map("user")
}

model Session {
  id        String   @id
  expiresAt DateTime
  token     String   @unique
  ipAddress String?
  userAgent String?
  userId    String
  user      User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  // ...
  @@map("session")
}
```

(Фрагмент; точный набор полей определяет CLI и подключённые плагины.)

## Свои поля пользователя

```ts
export const auth = betterAuth({
  database: prismaAdapter(prisma, { provider: 'postgresql' }),
  user: {
    additionalFields: {
      locale: { type: 'string', required: false, defaultValue: 'ru' },
    },
  },
});
```

После изменения — снова `auth generate` и миграция. Доменные данные (заказы, проекты) хранят в своих моделях со ссылкой на `User.id`, а не в таблице `user`.

## Связь с доменными моделями

```prisma
model Order {
  id     String @id @default(uuid(7)) @db.Uuid
  userId String
  user   User   @relation(fields: [userId], references: [id])
  @@index([userId])
}
```

## Имена таблиц и полей

Better Auth позволяет переименовать модели и поля (`user: { modelName: 'users', fields: { email: 'email_address' } }`), если нужно вписаться в существующую схему; генерация схемы учтёт эти настройки.

## Частые ошибки

- `provider` адаптера не совпадает с СУБД.
- Ожидать, что `auth generate` применит миграцию.
- Изменить плагины или `additionalFields` и забыть перегенерировать схему.
- `experimental.joins` из старых примеров вместо `advanced.database.joins`.
- Отдельный `PrismaClient` в `auth.ts` при уже существующем — лишний пул соединений.

## Что важно помнить

- `prismaAdapter(prisma, { provider })` из `better-auth/adapters/prisma`.
- Схема — `auth generate`, миграции — Prisma.
- Joins — `advanced.database.joins: true` (1.4+), нужны связи в схеме.

## Мини-шпаргалка

- `npm i @better-auth/prisma-adapter`.
- `database: prismaAdapter(prisma, { provider: 'postgresql' })`.
- `npx auth@latest generate` → `prisma migrate dev` → `prisma generate`.
- `user.additionalFields` для своих полей.
