# Как установить Better Auth в NestJS

> [!NOTE]
> Для NestJS устанавливают основной пакет **`better-auth`**, интеграцию **`@thallesp/nestjs-better-auth`** и адаптер базы данных — для Prisma это пакет **`@better-auth/prisma-adapter`** (при этом в коде `prismaAdapter` импортируется из пути `better-auth/adapters/prisma` — так указано в документации). Нужны переменные окружения: **`BETTER_AUTH_SECRET`** — длинный случайный секрет (используется для подписи cookies и токенов; не короче 32 символов, генерируется, например, `openssl rand -base64 32`) и **`BETTER_AUTH_URL`** — публичный базовый URL API. Экземпляр `auth` создаётся в отдельном файле (`src/auth/auth.ts` или `src/auth.ts`) — его использует и Nest-интеграция, и Better Auth CLI для генерации схемы. Порядок: установить пакеты → задать env → создать `auth.ts` → отключить body parser в `main.ts` → подключить `AuthModule.forRoot({ auth })` → сгенерировать и применить схему.

## Вопрос

Как установить и подготовить Better Auth в NestJS-проекте?

## Пакеты

```bash
npm install better-auth @thallesp/nestjs-better-auth
npm install @better-auth/prisma-adapter          # при Prisma
```

Prisma и её адаптер для БД должны уже быть настроены — см. [установку Prisma](<../12. Prisma в NestJS/02. Как установить и инициализировать Prisma в NestJS.md>).

## Переменные окружения

```env
BETTER_AUTH_SECRET="<openssl rand -base64 32>"
BETTER_AUTH_URL="http://localhost:3000"
DATABASE_URL="postgresql://app:secret@localhost:5432/app"
FRONTEND_URL="http://localhost:5173"
```

```ts
// env.schema.ts — валидация при старте
BETTER_AUTH_SECRET: z.string().min(32),
BETTER_AUTH_URL: z.url(),
FRONTEND_URL: z.url(),
```

## Шаги

```text
1. src/auth/auth.ts       — betterAuth({ database, emailAndPassword, trustedOrigins, ... })
2. main.ts                — NestFactory.create(AppModule, { bodyParser: false })
3. app.module.ts          — AuthModule.forRoot({ auth })
4. npx auth@latest generate  — модели Better Auth в schema.prisma
5. npx prisma migrate dev --name better_auth && npx prisma generate
6. Пометить публичные маршруты @AllowAnonymous()
```

Подробно: [auth.ts](<03. Как создать auth.ts для Better Auth.md>), [подключение к AppModule](<04. Как подключить Better Auth к AppModule.md>), [Prisma](<05. Как подключить Better Auth к Prisma.md>), [CLI](<08. Как работать со схемой Better Auth через CLI.md>).

## Клиент на фронтенде

```bash
npm install better-auth          # в проекте фронтенда
```

```ts
import { createAuthClient } from 'better-auth/react';

export const authClient = createAuthClient({ baseURL: 'http://localhost:3000' });

await authClient.signUp.email({ email, password, name });
await authClient.signIn.email({ email, password });
const { data: session } = authClient.useSession();
```

Запросы с фронтенда на другом origin должны отправлять cookies (`credentials: 'include'` делает клиент Better Auth), а API — разрешать этот origin в `trustedOrigins`.

## Частые ошибки

- Короткий или общий для окружений секрет; секрет в репозитории.
- `BETTER_AUTH_URL` не совпадает с реальным адресом API за прокси — OAuth-callback и cookies ломаются.
- Установить `@better-auth/prisma-adapter` и искать импорт из этого же пакета — в документации импорт из `better-auth/adapters/prisma`.
- Разные версии `better-auth` на сервере и клиенте.

## Что важно помнить

- `better-auth` + `@thallesp/nestjs-better-auth` + адаптер БД.
- `BETTER_AUTH_SECRET` (≥ 32 символов) и `BETTER_AUTH_URL` — обязательны и валидируются.
- `auth.ts` — общий для Nest и CLI.

## Мини-шпаргалка

- `npm i better-auth @thallesp/nestjs-better-auth @better-auth/prisma-adapter`.
- `openssl rand -base64 32`.
- `createAuthClient({ baseURL })` на фронтенде.
- После схемы — миграция Prisma и `prisma generate`.
