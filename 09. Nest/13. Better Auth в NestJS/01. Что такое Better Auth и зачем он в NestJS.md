# Что такое Better Auth и зачем он в NestJS

> [!NOTE]
> **Better Auth** — framework-agnostic библиотека аутентификации для TypeScript, которая работает **внутри вашего приложения** и с **вашей базой данных** (в отличие от внешних сервисов вроде Auth0/Clerk). Из коробки: вход по email и паролю, OAuth-провайдеры (Google, GitHub и др.), **сессии в БД с cookie**, подтверждение email, сброс пароля, встроенный rate limiting, а через **плагины** — 2FA, passkeys, magic link, организации и роли участников, admin (системные роли, бан, имперсонация), API-ключи, JWT/bearer и многое другое. Better Auth сам монтирует HTTP-эндпоинты (по умолчанию `/api/auth/*`), генерирует схему таблиц (`user`, `session`, `account`, `verification`) и даёт серверный API `auth.api.*`. В NestJS его подключают через community-интеграцию **`@thallesp/nestjs-better-auth`**: `AuthModule.forRoot({ auth })` регистрирует обработчик маршрутов, **глобальный `AuthGuard`** (все маршруты защищены по умолчанию), декораторы `@Session()`, `@AllowAnonymous()`, `@OptionalAuth()`, `@Roles()`, `@OrgRoles()` и `AuthService`.

## Вопрос

Что такое Better Auth и зачем использовать его в NestJS?

## Что берёт на себя

| Задача | Без библиотеки | Better Auth |
| --- | --- | --- |
| Регистрация, вход, выход | Свои эндпоинты, хеширование паролей | Готовые `/api/auth/sign-up/email`, `/sign-in/email`, `/sign-out` |
| Сессии | JWT + refresh-ротация или свой store | Сессии в БД, cookie, продление |
| OAuth | Passport-стратегии, callback-и | `socialProviders: { google, github }` |
| Email-верификация, сброс пароля | Токены, таблицы, письма | Встроено, письма отправляете вы |
| 2FA, passkeys, организации | Отдельные проекты | Плагины |
| Rate limiting на auth-эндпоинтах | Throttler | Встроено |

## Как выглядит в проекте

```text
src/
├── auth/
│   └── auth.ts            # betterAuth({...}) — экземпляр auth
├── app.module.ts          # AuthModule.forRoot({ auth })
├── main.ts                # NestFactory.create(AppModule, { bodyParser: false })
└── users/
    └── users.controller.ts  # @Session() session: UserSession
```

```ts
@Controller('me')
export class MeController {
  @Get()
  me(@Session() session: UserSession) {        // маршрут защищён глобальным AuthGuard
    return session.user;
  }
}
```

## Better Auth или своя реализация JWT

| Better Auth | Свой JWT + Passport |
| --- | --- |
| Быстрый старт, проверенные потоки (верификация, сброс, OAuth) | Полный контроль, меньше зависимостей |
| Сессии с мгновенным отзывом | Stateless-токены, удобно для микросервисов |
| Плагины для 2FA, организаций | Всё нужно писать самим |
| Community-интеграция с Nest (Fastify — beta) | Официальные `@nestjs/passport`, `@nestjs/jwt` |

## Что остаётся на вас

- **Авторизация** бизнес-уровня: проверка владельца ресурса, права в домене.
- Отправка писем (верификация, сброс) — колбэки, которые вы реализуете.
- Настройка cookies, trusted origins, прокси, секретов.
- Миграции таблиц через ваш ORM.

## Частые ошибки

- Считать, что Better Auth решает авторизацию к данным — он даёт личность и сессию.
- Забыть, что после подключения интеграции **все** маршруты требуют сессию (публичные помечают `@AllowAnonymous()`).
- Не отключить встроенный body parser Nest — запросы auth-эндпоинтов ломаются.

## Что важно помнить

- Better Auth — auth-библиотека внутри приложения с вашей БД.
- В NestJS — через `@thallesp/nestjs-better-auth` (`AuthModule.forRoot({ auth })`).
- Глобальный guard + декораторы `@Session`, `@AllowAnonymous`, `@OptionalAuth`, `@Roles`.

## Мини-шпаргалка

- `betterAuth({ database, emailAndPassword, socialProviders, plugins })`.
- Эндпоинты: `/api/auth/*`.
- Таблицы: `user`, `session`, `account`, `verification`.
- Nest: `AuthModule.forRoot({ auth })`, `bodyParser: false`.
