# Как защищать маршруты через Better Auth

> [!NOTE]
> Интеграция `@thallesp/nestjs-better-auth` регистрирует **глобальный `AuthGuard`**: каждый маршрут по умолчанию требует действующую сессию (иначе 401). Публичные маршруты помечают **`@AllowAnonymous()`** (на методе или контроллере), маршруты, где пользователь может быть, а может не быть, — **`@OptionalAuth()`** (сессия тогда может быть `null`). Данные сессии получают декоратором **`@Session()`** с типом `UserSession` — внутри есть `session.user` и `session.session`. Для ролей есть **`@Roles(['admin'])`** — проверяет системную роль `user.role` (плагин admin), **`@OrgRoles(['owner', 'admin'])`** и **`@RequireActiveOrg()`** — для плагина organization, а также `@UserHasPermission` / `@MemberHasPermission` для прав. Если guard нужен не глобально, модуль подключают с `disableGlobalAuthGuard: true` и вешают `AuthGuard` вручную. Сессия передаётся cookie — клиенту на другом origin нужно отправлять запросы с `credentials: 'include'`.

## Вопрос

Как защищать маршруты NestJS с помощью Better Auth?

## Сессия в обработчике

```ts
import { Session, UserSession, AllowAnonymous, OptionalAuth } from '@thallesp/nestjs-better-auth';

@Controller('profile')
export class ProfileController {
  @Get()
  me(@Session() session: UserSession) {          // 401 без сессии
    return { id: session.user.id, email: session.user.email, name: session.user.name };
  }
}
```

## Публичные и опциональные маршруты

```ts
@AllowAnonymous()
@Controller('catalog')
export class CatalogController {
  @Get() list() {}                               // доступно всем
}

@Controller('feed')
export class FeedController {
  @OptionalAuth()
  @Get()
  feed(@Session() session: UserSession | null) {
    return this.feed.forViewer(session?.user.id); // персонализация, если вошёл
  }
}

@AllowAnonymous()
@Get('health/live')
live() { return { status: 'ok' }; }
```

## Роли и организации

```ts
import { Roles, OrgRoles, RequireActiveOrg } from '@thallesp/nestjs-better-auth';

@Roles(['admin'])                                // user.role (плагин admin)
@Get('admin/users')
listUsers() {}

@RequireActiveOrg()                              // нужна активная организация в сессии
@Get('org/projects')
orgProjects(@Session() s: UserSession) {}

@OrgRoles(['owner', 'admin'])                    // роль участника активной организации
@Delete('org/projects/:id')
removeProject() {}
```

`@Roles()` проверяет только системную роль: администратор организации не получает доступ к системным admin-маршрутам.

## Без глобального guard

```ts
AuthModule.forRoot({ auth, disableGlobalAuthGuard: true });

@UseGuards(AuthGuard)                            // из @thallesp/nestjs-better-auth
@Controller('orders')
export class OrdersController {}
```

## Свой декоратор пользователя

```ts
export const CurrentUser = createParamDecorator((_: unknown, ctx: ExecutionContext) => {
  const session = ctx.switchToHttp().getRequest().session as UserSession | undefined;
  return session?.user;
});
```

Встроенного `@Session()` обычно достаточно; свой декоратор удобен, чтобы контроллеры не зависели от типов библиотеки.

## Фронтенд

```ts
const res = await fetch('https://api.example.com/api/orders', { credentials: 'include' });   // cookie сессии
```

## Частые ошибки

- Забыть `@AllowAnonymous()` на health check, вебхуках, публичном каталоге — 401.
- Использовать `@Roles()` для ролей в организации (нужен `@OrgRoles()`).
- Ожидать сессию при `@OptionalAuth()` без проверки на `null`.
- CORS без `credentials: true` и фронтенд без `credentials: 'include'` — cookie не отправляется.

## Что важно помнить

- Глобальный guard: всё закрыто, публичное — `@AllowAnonymous()`.
- `@Session()` даёт `user` и `session`; `@OptionalAuth()` — сессия может быть `null`.
- `@Roles`, `@OrgRoles`, `@RequireActiveOrg` — для плагинов admin и organization.

## Мини-шпаргалка

- `@Session() session: UserSession`.
- `@AllowAnonymous()`, `@OptionalAuth()`.
- `@Roles(['admin'])`, `@OrgRoles([...])`, `@RequireActiveOrg()`.
- `disableGlobalAuthGuard: true` + `@UseGuards(AuthGuard)`.
