# Как совместить Better Auth с authorization в NestJS

> [!NOTE]
> Better Auth отвечает на вопрос **«кто пользователь и действительна ли его сессия»**, а также даёт грубые роли (плагин admin: `user.role`) и роли участников организации (плагин organization) с системой прав (`access control`). **Бизнес-авторизация** — «может ли этот пользователь изменить этот заказ», «видит ли участник этот проект», «можно ли отменить оплаченный заказ» — остаётся на стороне приложения. Слои: глобальный `AuthGuard` Better Auth (аутентификация) → декораторы ролей/прав (`@Roles`, `@OrgRoles`, `@UserHasPermission`, `@MemberHasPermission`) для грубых проверок → **проверка владельца и состояния ресурса в сервисе** (или фильтр `where: { id, userId }` прямо в запросе), а сложные правила — политиками (CASL или своя функция `can(user, action, resource)`). Важно не путать системные роли и роли в организации и не доверять ролям из клиента.

## Вопрос

Как совместить аутентификацию Better Auth с авторизацией в NestJS-приложении?

## Слои проверки

```text
1. AuthGuard (Better Auth)      — есть ли сессия → 401
2. @Roles / @OrgRoles / permissions — подходит ли роль → 403
3. Сервис                       — владелец ли, допустимо ли действие в текущем состоянии → 404/403/409
```

## Проверка владельца

```ts
@Controller('orders')
export class OrdersController {
  constructor(private readonly orders: OrdersService) {}

  @Get(':id')
  findOne(@Param('id', ParseUUIDPipe) id: string, @Session() session: UserSession) {
    return this.orders.findForUser(id, session.user.id);
  }

  @Post(':id/cancel')
  cancel(@Param('id', ParseUUIDPipe) id: string, @Session() session: UserSession) {
    return this.orders.cancel(id, session.user);
  }
}

@Injectable()
export class OrdersService {
  async findForUser(id: string, userId: string) {
    const order = await this.prisma.order.findFirst({ where: { id, userId } });   // фильтр по владельцу в запросе
    if (!order) throw new NotFoundException();
    return order;
  }

  async cancel(id: string, user: { id: string; role?: string | null }) {
    const order = await this.prisma.order.findFirst({
      where: user.role === 'admin' ? { id } : { id, userId: user.id },
    });
    if (!order) throw new NotFoundException();
    if (order.status !== 'PENDING') throw new ConflictException('Only pending orders can be cancelled');
    return this.prisma.order.update({ where: { id }, data: { status: 'CANCELLED' } });
  }
}
```

## Системные роли (плагин admin)

```ts
// auth.ts
plugins: [admin({ defaultRole: 'user', adminRoles: ['admin'] })]

// контроллер
@Roles(['admin'])
@Get('admin/orders')
allOrders() {}
```

Роль назначает администратор через API плагина (`auth.api.setRole`), а не пользователь при регистрации.

## Роли в организации (плагин organization)

```ts
@OrgRoles(['owner', 'admin'])
@Patch('org/settings')
updateSettings(@Session() s: UserSession) {
  return this.orgs.update(s.session.activeOrganizationId!, ...);
}

@MemberHasPermission({ permissions: { project: ['create'] } })
@Post('org/projects')
createProject() {}
```

## Политики

```ts
type Action = 'read' | 'update' | 'delete';

export function canProject(user: { id: string; role?: string | null }, action: Action, project: { ownerId: string; archived: boolean }) {
  if (user.role === 'admin') return true;
  if (project.ownerId !== user.id) return false;
  if (action === 'update' && project.archived) return false;
  return true;
}

if (!canProject(session.user, 'update', project)) throw new ForbiddenException();
```

Для большого числа правил — CASL (`@casl/ability`) с guard-ом политик.

## Частые ошибки

- Считать, что наличие сессии = право на ресурс (IDOR).
- Позволять задавать `role` при регистрации через `additionalFields`.
- Использовать `@Roles(['admin'])` вместо `@OrgRoles` для администратора организации.
- Проверять права только на фронтенде.
- Отвечать 403 на чужой ресурс, раскрывая его существование (часто лучше 404).

## Что важно помнить

- Better Auth — аутентификация, сессии и роли; бизнес-права — в приложении.
- Слои: guard → роли/права → проверка ресурса в сервисе.
- Фильтр по владельцу в самом запросе к БД — надёжная защита от IDOR.

## Мини-шпаргалка

- `@Session() s` → `s.user.id`, `s.user.role`, `s.session.activeOrganizationId`.
- `findFirst({ where: { id, userId } })`.
- `@Roles`, `@OrgRoles`, `@UserHasPermission`, `@MemberHasPermission`.
- Политики: `can(user, action, resource)` или CASL.
