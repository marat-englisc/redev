# Как работать со схемой Better Auth через CLI

> [!NOTE]
> Better Auth CLI (`npx auth@latest`) читает конфигурацию из `auth.ts` и знает, какие таблицы и поля нужны выбранным опциям и **плагинам**. Команда **`generate`** выводит схему под ваш адаптер: для **Prisma** и **Drizzle** — модели в их формате (для Prisma — изменения в `schema.prisma`), для встроенного Kysely-адаптера — SQL-файл. Команда **`migrate`** применяет изменения напрямую, но работает **только со встроенным Kysely-адаптером**; для Prisma схему применяют **миграциями Prisma** (`prisma migrate dev` / `deploy`). Если CLI не находит конфиг (он ищет `auth.ts` в стандартных местах вроде `./`, `src/`, `lib/`), путь указывают `--config`, файл вывода — `--output`. Схему регенерируют **после каждого изменения** плагинов, `additionalFields` и имён моделей, а результат коммитят вместе с миграцией.

## Вопрос

Как генерировать и обновлять схему базы для Better Auth?

## generate для Prisma

```bash
npx auth@latest generate --config src/auth/auth.ts --output prisma/schema.prisma
```

```text
✔ Schema was generated successfully: prisma/schema.prisma
```

Затем — обычный цикл Prisma:

```bash
npx prisma migrate dev --name add_better_auth
npx prisma generate
```

## После добавления плагина

```ts
// auth.ts
plugins: [admin(), organization(), twoFactor()]
```

```bash
npx auth@latest generate        # добавит поля role/banned у User, модели Organization, Member, Invitation, TwoFactor
npx prisma migrate dev --name better_auth_plugins
npx prisma generate
```

Перед применением просмотрите diff `schema.prisma` и SQL миграции.

## migrate (только Kysely)

```bash
npx auth@latest migrate         # встроенный Kysely-адаптер: создаёт недостающие таблицы и столбцы
```

Для Prisma и Drizzle `migrate` не применяется — используются инструменты этих ORM.

## Опции CLI

| Флаг | Назначение |
| --- | --- |
| `--config <path>` | Путь к файлу с `auth` |
| `--output <path>` | Куда записать схему |
| `--yes` | Без интерактивных подтверждений (CI) |

## Рабочий процесс в команде

```text
1. Изменили auth.ts (плагин, поле)
2. npx auth@latest generate
3. npx prisma migrate dev --name ...
4. Закоммитили auth.ts + schema.prisma + prisma/migrations/*
5. В CI/CD: prisma migrate deploy
```

## Проблемы

| Проблема | Решение |
| --- | --- |
| CLI не находит конфиг | `--config src/auth/auth.ts` |
| CLI падает на импорте env | `import 'dotenv/config'` в начале `auth.ts` или задать переменные перед запуском |
| CLI не понимает алиасы путей (`@/…`) | Относительные импорты в `auth.ts` или поддержка tsconfig paths |
| Конфликт с существующей моделью `User` | `user.modelName` / `fields` в конфиге Better Auth |

## Частые ошибки

- Ожидать, что `auth migrate` применит изменения к Prisma-схеме.
- Не перегенерировать схему после добавления плагина — ошибки «column does not exist».
- Править сгенерированные модели вручную и терять изменения при следующем `generate`.
- Применить `migrate dev` в продакшене.

## Что важно помнить

- `generate` — схема под адаптер, `migrate` — только для Kysely.
- Для Prisma: `auth generate` → `prisma migrate` → `prisma generate`.
- Регенерировать после каждого изменения конфигурации.

## Мини-шпаргалка

- `npx auth@latest generate --config ... --output ...`.
- `npx auth@latest migrate` — только встроенный Kysely.
- `prisma migrate dev` / `deploy`.
- Коммитить схему и миграции.
