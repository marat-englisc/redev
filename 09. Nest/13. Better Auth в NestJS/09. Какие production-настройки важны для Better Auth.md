# Какие production-настройки важны для Better Auth

> [!NOTE]
> В продакшене для Better Auth важны: сильный уникальный **`BETTER_AUTH_SECRET`** (только из secret manager, отдельный для каждого окружения) и корректный **`BETTER_AUTH_URL`** — публичный HTTPS-адрес API (от него зависят OAuth-callback и cookies); строгий **`trustedOrigins`** без `localhost`; **cookies** только `Secure` и `HttpOnly` (Better Auth включает secure-cookies на HTTPS, принудительно — `advanced.useSecureCookies`), при фронтенде на поддомене — `advanced.crossSubDomainCookies`, при разных сайтах — осознанный `SameSite=None`; правильное определение **IP за прокси** (`advanced.ipAddress.ipAddressHeaders`, доверять только своему балансировщику) — от него зависит встроенный **rate limiting**, который для кластера хранят в общем хранилище (`rateLimit.storage: 'database'` или secondary storage вроде Redis); **срок жизни и продление сессий** (`session.expiresIn`, `updateAge`, `cookieCache`); отзыв сессий при смене пароля; надёжная **отправка писем** через очередь; обновление библиотеки и мониторинг подозрительных входов.

## Вопрос

Какие настройки Better Auth важны для продакшена?

## Конфигурация

```ts
export const auth = betterAuth({
  baseURL: process.env.BETTER_AUTH_URL,                // https://api.example.com
  secret: process.env.BETTER_AUTH_SECRET,
  database: prismaAdapter(prisma, { provider: 'postgresql' }),

  trustedOrigins: ['https://app.example.com', 'https://admin.example.com'],

  session: {
    expiresIn: 60 * 60 * 24 * 14,                      // 14 дней
    updateAge: 60 * 60 * 24,
    cookieCache: { enabled: true, maxAge: 5 * 60 },
  },

  rateLimit: {
    enabled: true,
    window: 60,
    max: 100,
    storage: 'database',                               // общий для всех реплик
    customRules: { '/sign-in/email': { window: 60, max: 5 } },
  },

  advanced: {
    useSecureCookies: true,
    crossSubDomainCookies: { enabled: true, domain: '.example.com' },   // app. и api. на одном домене
    ipAddress: { ipAddressHeaders: ['x-forwarded-for'] },               // только если прокси доверенный
  },

  emailAndPassword: {
    enabled: true,
    requireEmailVerification: true,
    revokeSessionsOnPasswordReset: true,
    sendResetPassword: ({ user, url }) => mailQueue.add('reset-password', { to: user.email, url }),
  },
});
```

## Чек-лист

| Область | Настройка |
| --- | --- |
| Секрет | ≥ 32 символов, свой на окружение, из secret manager |
| URL | `BETTER_AUTH_URL` = публичный HTTPS-адрес; OAuth redirect URI зарегистрированы для прод-домена |
| Origins | Только прод-домены фронтенда |
| Cookies | `Secure`, `HttpOnly`, разумный `SameSite`, домен при поддоменах |
| Прокси | `trust proxy`, IP-заголовки только от своего балансировщика |
| Rate limit | Включён, общий storage для кластера, строгие правила для входа и сброса |
| Сессии | Срок жизни, продление, отзыв при смене пароля, список активных сессий для пользователя |
| Письма | Через очередь, с повторами |
| Пароли | Минимальная длина, проверка утечек (плагин haveIBeenPwned) по желанию |
| 2FA | Для админов обязательно |
| Обновления | Следить за релизами и advisory библиотеки |

## Ротация секрета

Смена `BETTER_AUTH_SECRET` делает недействительными подписанные им данные (cookie-кеш сессий, токены верификации). Планируйте ротацию: окно, когда пользователям, возможно, потребуется войти заново, и уведомление команды поддержки. Детали поддержки нескольких секретов уточняйте в актуальной документации.

## Наблюдаемость

```ts
// hooks в auth.ts — аудит событий безопасности
databaseHooks: {
  session: {
    create: { after: async (session) => audit.log('session.created', { userId: session.userId, ip: session.ipAddress }) },
  },
},
```

Логируйте входы, неудачные попытки, сброс пароля, изменение ролей — без паролей и токенов.

## Частые ошибки

- `localhost` в `trustedOrigins` или `BETTER_AUTH_URL` в проде.
- Rate limit в памяти процесса при нескольких репликах.
- Доверять `X-Forwarded-For` от любого клиента — подмена IP обходит лимиты.
- Синхронная отправка писем в колбэке — медленные и падающие запросы.
- Один секрет на все окружения.

## Что важно помнить

- Секрет, URL и origins — первое, что проверяют перед релизом.
- Cookies, прокси и rate limit настраиваются под инфраструктуру.
- Сессии: срок, продление, отзыв; письма — через очередь.

## Мини-шпаргалка

- `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL` (HTTPS).
- `trustedOrigins: [prod...]`.
- `advanced.useSecureCookies`, `crossSubDomainCookies`, `ipAddress.ipAddressHeaders`.
- `rateLimit: { storage: 'database', customRules }`.
- `revokeSessionsOnPasswordReset: true`.
