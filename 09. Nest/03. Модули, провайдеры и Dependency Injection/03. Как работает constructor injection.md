# Как работает constructor injection

> [!NOTE]
> **Constructor injection** — основной способ DI в NestJS: зависимости объявляются параметрами конструктора, а контейнер при создании класса подставляет нужные экземпляры. Запись `constructor(private readonly usersService: UsersService) {}` одновременно объявляет параметр и поле класса (TypeScript parameter property). Контейнер берёт **токен** из типа параметра (через `emitDecoratorMetadata`) или из `@Inject(TOKEN)`, если тип — интерфейс или значение. Дополнительно есть `@Optional()` (не падать, если провайдера нет), `forwardRef()` (для циклических зависимостей) и **property injection** (`@Inject() private readonly x: X` на поле) — последний используют редко, в основном в базовых классах. Constructor injection делает зависимости явными, а объект — полностью готовым после создания.

## Вопрос

Как работает внедрение зависимостей через конструктор в NestJS?

## Базовый пример

```ts
@Injectable()
export class OrdersService {
  constructor(
    private readonly ordersRepo: OrdersRepository,       // токен = класс
    private readonly users: UsersService,
    private readonly config: ConfigService,
    @Inject(PAYMENTS_GATEWAY) private readonly payments: PaymentsGateway,  // токен = Symbol
  ) {}

  async checkout(userId: number) {
    const user = await this.users.findOne(userId);
    // ...
  }
}
```

## Как контейнер находит зависимость

```text
OrdersService
  design:paramtypes → [OrdersRepository, UsersService, ConfigService, Object]
  @Inject для 4-го параметра → PAYMENTS_GATEWAY
  для каждого токена:
    1. провайдер в своём модуле?
    2. экспорт импортированного модуля?
    3. глобальный модуль?
    → нет нигде → UnknownDependenciesException при старте
```

## @Optional

```ts
@Injectable()
export class NotificationsService {
  constructor(@Optional() @Inject(SLACK_CLIENT) private readonly slack?: SlackClient) {}

  notify(text: string) {
    this.slack?.post(text);    // в окружении без Slack — просто пропускаем
  }
}
```

## Наследование

```ts
@Injectable()
export abstract class BaseCrudService<T> {
  constructor(protected readonly prisma: PrismaService) {}
}

@Injectable()
export class ProductsService extends BaseCrudService<Product> {
  constructor(prisma: PrismaService, private readonly search: SearchService) {
    super(prisma);
  }
}
```

В NestJS 12, если наследник переобъявляет конструктор, он **не наследует** `@Optional()`-маркеры родителя — их нужно повторить.

## Property injection

```ts
export abstract class BaseController {
  @Inject(Logger) protected readonly logger: Logger;   // без необходимости менять конструкторы наследников
}
```

Используйте только когда constructor injection неудобен: свойство доступно уже после конструктора, и такие зависимости хуже видны.

## Циклические зависимости

```ts
constructor(@Inject(forwardRef(() => OrdersService)) private readonly orders: OrdersService) {}
```

Это обходной путь; лучше устранить цикл архитектурно — см. [circular dependency](<../11. Production, архитектура и собеседования/03. Что такое circular dependency в NestJS.md>).

## Почему не new

```ts
// ✗ обход контейнера: нет синглтона, нет подмены в тестах, нет зависимостей самого UsersService
private readonly users = new UsersService();
```

## Частые ошибки

- `import type { X }` для класса, который внедряется, — токен стирается.
- Использовать зависимость в конструкторе базового класса до вызова `super()`.
- Перегруженный конструктор с 10+ зависимостями — признак, что сервис надо разделить.
- Внедрять интерфейс без `@Inject(TOKEN)`.

## Что важно помнить

- Зависимости — параметры конструктора, токен — тип или `@Inject`.
- Ошибки разрешения видны при старте приложения.
- `@Optional`, `forwardRef`, property injection — для особых случаев.

## Мини-шпаргалка

- `constructor(private readonly x: X) {}`.
- `@Inject(TOKEN)` для интерфейсов и значений.
- `@Optional()` — необязательная зависимость.
- `forwardRef(() => X)` — разрыв цикла (временно).
