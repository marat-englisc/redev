# Что такое imports и exports в module

> [!NOTE]
> `exports` определяет **публичный API модуля**: какие из его провайдеров (или каких импортированных модулей) смогут использовать другие. `imports` подключает модули, **экспорты** которых нужны текущему модулю. Связь работает только в паре: чтобы `OrdersService` внедрил `UsersService`, `UsersModule` должен экспортировать `UsersService`, а `OrdersModule` — импортировать `UsersModule`. Импорт **не транзитивен**: если `A` импортирует `B`, а `B` импортирует `C`, то `A` не видит экспорты `C`, пока `B` не реэкспортирует `C`. В `imports` указывают **модули**, а не сервисы; в `exports` — провайдеры (по классу или токену) или модули. Глобальные модули (`@Global()`, `isGlobal: true`) видны без импорта.

## Вопрос

Как работают `imports` и `exports` в модулях NestJS?

## Пара imports + exports

```ts
@Module({
  providers: [UsersService, UsersRepository],
  exports: [UsersService],              // UsersRepository — приватный
})
export class UsersModule {}

@Module({
  imports: [UsersModule],               // получаем экспорт UsersService
  providers: [OrdersService],
})
export class OrdersModule {}

@Injectable()
export class OrdersService {
  constructor(private readonly users: UsersService) {}       // ✓
  // constructor(private readonly repo: UsersRepository) {}  // ✗ не экспортирован
}
```

## Нетранзитивность

```text
AppModule ─imports─► OrdersModule ─imports─► UsersModule (exports UsersService)

AppController может внедрить UsersService?  ✗ — AppModule импортирует только OrdersModule
```

```ts
// решение 1: импортировать UsersModule напрямую там, где нужен
// решение 2: реэкспортировать
@Module({
  imports: [UsersModule],
  providers: [OrdersService],
  exports: [OrdersService, UsersModule],   // реэкспорт модуля
})
export class OrdersModule {}
```

## Экспорт токенов

```ts
export const REDIS = Symbol('REDIS');

@Module({
  providers: [{ provide: REDIS, useFactory: () => new Redis(process.env.REDIS_URL!) }],
  exports: [REDIS],                      // экспортируется токен
})
export class RedisModule {}
```

## Что можно указывать

| Поле | Можно | Нельзя |
| --- | --- | --- |
| `imports` | Модули, динамические модули (`X.forRoot()`), `forwardRef(() => X)` | Сервисы, контроллеры |
| `exports` | Свои провайдеры (класс или токен), импортированные модули | Контроллеры; провайдеры, которых нет ни в `providers`, ни в импортированных модулях |

## Принцип минимального экспорта

- Экспортируйте **фасад** (`UsersService`), а не репозитории и вспомогательные классы.
- Если другому модулю нужен доступ к внутренностям — возможно, граница проведена неверно.
- Много модулей импортируют друг друга по кругу — выделите общий модуль или используйте события.

## Частые ошибки

- `imports: [UsersService]` — сервис вместо модуля.
- Забыть `exports` — ошибка DI в соседнем модуле.
- Ожидать транзитивности импортов.
- Добавить провайдер чужого модуля в свои `providers` «чтобы заработало» — получится второй экземпляр.

## Что важно помнить

- `exports` — публичный API, `imports` — потребление чужого API.
- Импорт не транзитивен; для передачи дальше — реэкспорт.
- Экспортируйте минимум.

## Мини-шпаргалка

- Нужен `X` из `XModule` → `XModule` экспортирует `X`, мы импортируем `XModule`.
- Реэкспорт: `exports: [XModule]`.
- Токены экспортируются так же, как классы.
- Глобальные модули — без импорта.
