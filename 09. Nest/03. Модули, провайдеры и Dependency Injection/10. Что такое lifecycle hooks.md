# Что такое lifecycle hooks

> [!NOTE]
> **Lifecycle hooks** — методы, которые Nest вызывает у провайдеров, контроллеров и модулей на этапах жизни приложения. При старте: **`onModuleInit`** — после разрешения зависимостей модуля (подключиться к БД, прогреть кеш), **`onApplicationBootstrap`** — когда все модули инициализированы, но до начала приёма соединений. При остановке (если включены `app.enableShutdownHooks()` или вызван `app.close()`): **`onModuleDestroy`** — получен сигнал завершения, **`beforeApplicationShutdown`** — после того как все `onModuleDestroy` отработали (можно дождаться завершения задач; получает сигнал), **`onApplicationShutdown`** — после закрытия HTTP-сервера (закрыть соединения). Хуки могут быть **асинхронными**: Nest дождётся промиса. В NestJS 12 хуки выполняются **по уровням иерархии компонентов**, поэтому не стоит полагаться на порядок между независимыми модулями. Для request-scoped провайдеров хуки не вызываются.

## Вопрос

Какие lifecycle hooks есть в NestJS и как их использовать?

## Порядок

```text
Старт:
  создание экземпляров (конструкторы)
  → onModuleInit()
  → onApplicationBootstrap()
  → app.listen()

Остановка (SIGTERM / app.close()):
  → onModuleDestroy()
  → beforeApplicationShutdown(signal)
  → закрытие HTTP-сервера и соединений
  → onApplicationShutdown(signal)
```

## Пример

```ts
@Injectable()
export class PrismaService extends PrismaClient implements OnModuleInit, OnModuleDestroy {
  async onModuleInit() {
    await this.$connect();          // упасть при старте, если БД недоступна
  }
  async onModuleDestroy() {
    await this.$disconnect();
  }
}

@Injectable()
export class QueueWorker implements OnApplicationBootstrap, BeforeApplicationShutdown {
  private running = true;

  onApplicationBootstrap() {
    void this.loop();               // стартуем фоновую обработку, не блокируя bootstrap
  }

  async beforeApplicationShutdown(signal?: string) {
    this.running = false;
    await this.waitForCurrentJob(); // дать доделать текущую задачу
  }
}
```

## Shutdown hooks

```ts
// main.ts
app.enableShutdownHooks();          // подписка на SIGTERM, SIGINT и др.
```

Без этого при `docker stop`/rolling deploy в Kubernetes хуки остановки не вызовутся: соединения оборвутся, задачи прервутся. Подписка на сигналы потребляет слушатели процесса — в тестах с множеством приложений её обычно не включают. Подробнее — [graceful shutdown](<../11. Production, архитектура и собеседования/04. Что такое graceful shutdown в NestJS.md>).

## Что где делать

| Хук | Подходит для | Не подходит для |
| --- | --- | --- |
| Конструктор | Сохранить зависимости | Асинхронной работы, I/O |
| `onModuleInit` | Подключения, проверка доступности, загрузка справочников | Долгих операций, блокирующих старт надолго |
| `onApplicationBootstrap` | Старт фоновых процессов, регистрация в discovery | — |
| `onModuleDestroy` | Остановить приём новых задач | — |
| `beforeApplicationShutdown` | Дождаться завершения текущей работы | — |
| `onApplicationShutdown` | Закрыть соединения, сбросить буферы логов | — |

## Частые ошибки

- Асинхронная инициализация в конструкторе (промис никто не ждёт).
- Забыть `enableShutdownHooks()` — хуки остановки не вызываются.
- Полагаться на порядок `onModuleInit` между независимыми модулями (в v12 порядок определяется иерархией).
- Бесконечный цикл в `onApplicationBootstrap` через `await` — приложение не начнёт слушать порт.
- Ожидать хуков у request-scoped провайдеров.

## Что важно помнить

- Старт: `onModuleInit` → `onApplicationBootstrap`.
- Остановка: `onModuleDestroy` → `beforeApplicationShutdown` → `onApplicationShutdown`.
- Хуки остановки работают только с `enableShutdownHooks()` или `app.close()`.

## Мини-шпаргалка

- `implements OnModuleInit` → `async onModuleInit()`.
- `app.enableShutdownHooks()`.
- `beforeApplicationShutdown(signal)` — дождаться задач.
- `onApplicationShutdown` — закрыть ресурсы.
