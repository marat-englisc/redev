# Что такое dynamic module

> [!NOTE]
> **Dynamic module** — модуль, который **настраивается при импорте**: статический метод (`forRoot`, `forFeature`, `register`, их async-версии) возвращает объект `DynamicModule` с теми же полями, что `@Module` (`providers`, `exports`, `imports`), плюс обязательным `module`. Так работают `ConfigModule.forRoot()`, `TypeOrmModule.forRootAsync()`, `JwtModule.register()`, `BullModule.registerQueue()`. Соглашения: **`forRoot`** — один раз в корне с глобальной конфигурацией; **`forFeature`** — в feature-модулях, чтобы добавить что-то своё (репозитории, очередь) к уже настроенному корню; **`register`** — новая независимая конфигурация при каждом импорте. **`*Async`** принимает `useFactory` + `inject`, чтобы опции зависели от `ConfigService`. Писать свой dynamic module удобнее всего через **`ConfigurableModuleBuilder`**, который генерирует `register`/`registerAsync` и токен опций.

## Вопрос

Что такое dynamic module и как его создать?

## Использование готовых

```ts
@Module({
  imports: [
    ConfigModule.forRoot({ isGlobal: true }),
    TypeOrmModule.forRootAsync({
      inject: [ConfigService],
      useFactory: (config: ConfigService) => ({
        type: 'postgres',
        url: config.getOrThrow('DATABASE_URL'),
        autoLoadEntities: true,
      }),
    }),
    BullModule.forRoot({ connection: { host: 'redis', port: 6379 } }),
  ],
})
export class AppModule {}

@Module({
  imports: [
    TypeOrmModule.forFeature([User]),            // репозиторий User для этого модуля
    BullModule.registerQueue({ name: 'emails' }),
  ],
})
export class UsersModule {}
```

## Свой dynamic module вручную

```ts
export interface MailModuleOptions {
  from: string;
  transport: 'smtp' | 'console';
}
export const MAIL_OPTIONS = Symbol('MAIL_OPTIONS');

@Module({})
export class MailModule {
  static register(options: MailModuleOptions): DynamicModule {
    return {
      module: MailModule,
      providers: [{ provide: MAIL_OPTIONS, useValue: options }, MailService],
      exports: [MailService],
    };
  }

  static registerAsync(opts: {
    imports?: any[];
    inject?: any[];
    useFactory: (...args: any[]) => MailModuleOptions | Promise<MailModuleOptions>;
  }): DynamicModule {
    return {
      module: MailModule,
      imports: opts.imports ?? [],
      providers: [
        { provide: MAIL_OPTIONS, useFactory: opts.useFactory, inject: opts.inject ?? [] },
        MailService,
      ],
      exports: [MailService],
    };
  }
}

@Injectable()
export class MailService {
  constructor(@Inject(MAIL_OPTIONS) private readonly options: MailModuleOptions) {}
}
```

## ConfigurableModuleBuilder

```ts
// mail.module-definition.ts
export const { ConfigurableModuleClass, MODULE_OPTIONS_TOKEN, OPTIONS_TYPE, ASYNC_OPTIONS_TYPE } =
  new ConfigurableModuleBuilder<MailModuleOptions>()
    .setClassMethodName('forRoot')      // forRoot / forRootAsync вместо register
    .setExtras({ isGlobal: false }, (definition, extras) => ({ ...definition, global: extras.isGlobal }))
    .build();

// mail.module.ts
@Module({ providers: [MailService], exports: [MailService] })
export class MailModule extends ConfigurableModuleClass {}

// mail.service.ts
@Injectable()
export class MailService {
  constructor(@Inject(MODULE_OPTIONS_TOKEN) private readonly options: MailModuleOptions) {}
}

// app.module.ts
MailModule.forRootAsync({
  inject: [ConfigService],
  useFactory: (c: ConfigService) => ({ from: c.getOrThrow('MAIL_FROM'), transport: 'smtp' }),
  isGlobal: true,
});
```

## forRoot, forFeature, register

| Метод | Сколько раз | Пример |
| --- | --- | --- |
| `forRoot` / `forRootAsync` | Один раз в корне | Подключение к БД, глобальный конфиг |
| `forFeature` | В каждом feature-модуле | Репозитории сущностей, конфиг-namespace |
| `register` / `registerAsync` | Каждый импорт — своя конфигурация | HTTP-клиент для конкретного внешнего API |

## Частые ошибки

- Вызывать `forRoot` в нескольких модулях — несколько подключений.
- Забыть `module` в возвращаемом объекте.
- Читать `process.env` прямо в `register` вместо `registerAsync` + `ConfigService`.
- Не экспортировать сервис из dynamic module.

## Что важно помнить

- Dynamic module = модуль + конфигурация при импорте.
- `forRoot` — корень, `forFeature` — фичи, `register` — независимые экземпляры.
- `ConfigurableModuleBuilder` избавляет от шаблонного кода.

## Мини-шпаргалка

- `static forRoot(opts): DynamicModule { return { module, providers, exports } }`.
- `*Async({ imports, inject, useFactory })`.
- `MODULE_OPTIONS_TOKEN` из `ConfigurableModuleBuilder`.
- `global: true` в объекте — глобальный dynamic module.
