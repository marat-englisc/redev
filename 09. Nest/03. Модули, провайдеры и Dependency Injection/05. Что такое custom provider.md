# Что такое custom provider

> [!NOTE]
> **Custom provider** — явная регистрация провайдера в виде объекта `{ provide: TOKEN, use... }`, когда сокращённой записи `providers: [ServiceClass]` недостаточно. Четыре варианта: **`useValue`** — готовое значение или объект (константы, конфигурация, мок в тестах); **`useClass`** — подставить другой класс под тем же токеном (разные реализации для окружений, абстрактный класс как контракт); **`useFactory`** — создать значение функцией, в том числе **асинхронной**, с зависимостями из `inject` (клиент БД, Redis, SDK внешнего сервиса после чтения конфига); **`useExisting`** — псевдоним, указывающий на уже существующий провайдер. Custom providers — основа адаптеров к внешним системам, dynamic modules и подмены зависимостей в тестах.

## Вопрос

Что такое custom provider и какие варианты есть в NestJS?

## useValue

```ts
export const APP_CONFIG = Symbol('APP_CONFIG');

@Module({
  providers: [{ provide: APP_CONFIG, useValue: { name: 'shop', maxUploadMb: 10 } }],
})
export class AppModule {}

// тесты
Test.createTestingModule({
  providers: [OrdersService, { provide: OrdersRepository, useValue: { findById: vi.fn() } }],
});
```

## useClass

```ts
// абстрактный класс как контракт — это одновременно и тип, и токен
export abstract class FileStorage {
  abstract upload(key: string, body: Buffer): Promise<string>;
}

@Injectable() export class S3Storage extends FileStorage { ... }
@Injectable() export class LocalStorage extends FileStorage { ... }

@Module({
  providers: [
    { provide: FileStorage, useClass: process.env.NODE_ENV === 'production' ? S3Storage : LocalStorage },
  ],
  exports: [FileStorage],
})
export class StorageModule {}

@Injectable()
export class AvatarsService {
  constructor(private readonly storage: FileStorage) {}   // без @Inject — абстрактный класс существует в рантайме
}
```

## useFactory

```ts
export const REDIS = Symbol('REDIS');

@Module({
  providers: [
    {
      provide: REDIS,
      inject: [ConfigService],
      useFactory: async (config: ConfigService) => {
        const client = new Redis(config.getOrThrow<string>('REDIS_URL'));
        await client.ping();                 // приложение не стартует без Redis
        return client;
      },
    },
  ],
  exports: [REDIS],
})
export class RedisModule {}
```

Асинхронная фабрика задерживает старт приложения, пока промис не выполнится. `inject` может содержать и необязательные зависимости: `inject: [ConfigService, { token: LOGGER, optional: true }]`.

## useExisting

```ts
providers: [
  LegacyMailService,
  { provide: MailService, useExisting: LegacyMailService },   // один экземпляр под двумя токенами
]
```

## Закрытие ресурсов

```ts
@Injectable()
export class RedisShutdown implements OnApplicationShutdown {
  constructor(@Inject(REDIS) private readonly redis: Redis) {}
  async onApplicationShutdown() {
    await this.redis.quit();
  }
}
```

Значения из `useFactory` не получают lifecycle hooks — закрывайте ресурсы через отдельный провайдер или обёртку-класс.

## Сравнение

| Вариант | Когда |
| --- | --- |
| `useValue` | Константы, конфигурация, моки |
| `useClass` | Разные реализации одного контракта |
| `useFactory` | Нужна логика создания, async, зависимости |
| `useExisting` | Псевдоним, миграция со старого токена |

## Частые ошибки

- Забыть `inject` в фабрике — параметры будут `undefined`.
- Экспортировать класс реализации вместо токена контракта.
- Создавать в `useFactory` ресурсы, которые никто не закрывает при остановке.
- Использовать строковые токены, которые легко перепутать (лучше `Symbol` или абстрактный класс).

## Что важно помнить

- Custom provider = `{ provide, useValue | useClass | useFactory | useExisting }`.
- `useFactory` + `inject` — для клиентов внешних систем, может быть async.
- Абстрактный класс — удобный контракт и токен одновременно.

## Мини-шпаргалка

- `{ provide: T, useValue: v }`.
- `{ provide: Abstract, useClass: Impl }`.
- `{ provide: T, useFactory: (a) => ..., inject: [A] }`.
- `{ provide: Alias, useExisting: Real }`.
