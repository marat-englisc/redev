# Что такое module в NestJS

> [!NOTE]
> **Модуль** — класс с декоратором `@Module()`, метаданные которого описывают кусок приложения: `controllers` (обработчики маршрутов этого модуля), `providers` (сервисы, которые контейнер создаёт в **области видимости модуля**), `imports` (модули, чьи экспорты нужны здесь) и `exports` (провайдеры или модули, доступные тем, кто импортирует этот модуль). Каждый модуль — отдельная DI-область: провайдер виден только внутри своего модуля, пока его не экспортируют. Модули — **синглтоны**: один и тот же модуль, импортированный в разные места, создаётся один раз и делится экземплярами своих провайдеров. Сам класс модуля тоже может внедрять провайдеры (например, для конфигурации в `onModuleInit`), а модуль можно **реэкспортировать**, отдавая наружу чужие модули.

## Вопрос

Что такое модуль в NestJS и из чего состоят его метаданные?

## Метаданные @Module

```ts
@Module({
  imports: [PrismaModule, MailModule],          // чьи экспорты нужны здесь
  controllers: [OrdersController],              // маршруты модуля
  providers: [OrdersService, OrdersRepository], // что создаёт контейнер модуля
  exports: [OrdersService],                     // что видят импортирующие модули
})
export class OrdersModule {}
```

| Поле | Что указывать |
| --- | --- |
| `imports` | Модули (обычные или динамические: `ConfigModule.forFeature(...)`) |
| `controllers` | Контроллеры, которые надо инстанцировать и зарегистрировать в роутере |
| `providers` | Классы `@Injectable()`, custom providers (`useValue`, `useFactory`, `useClass`, `useExisting`) |
| `exports` | Подмножество своих провайдеров (или их токенов) и/или импортированные модули |

## Модуль как DI-область

```text
OrdersModule
├── OrdersService       ← видит OrdersRepository (свой) и MailService (экспорт MailModule)
├── OrdersRepository    ← видит PrismaService (экспорт PrismaModule)
└── exports: OrdersService
```

Провайдер разрешается сначала в своём модуле, затем среди экспортов импортированных модулей, затем среди глобальных модулей.

## Реэкспорт

```ts
@Module({
  imports: [PrismaModule, RedisModule],
  exports: [PrismaModule, RedisModule],   // CoreModule отдаёт наружу всё инфраструктурное
})
export class CoreModule {}

@Module({ imports: [CoreModule] })        // теперь доступны PrismaService и RedisService
export class UsersModule {}
```

## Класс модуля с зависимостями

```ts
@Module({ providers: [CacheWarmer] })
export class CatalogModule implements OnModuleInit {
  constructor(private readonly warmer: CacheWarmer) {}

  async onModuleInit() {
    await this.warmer.warmUp();
  }
}
```

Сам класс модуля нельзя внедрить как провайдер в другие классы — это контейнер, а не сервис.

## Один провайдер — в одном модуле

```ts
// ✗ PrismaService объявлен в двух модулях → два экземпляра и два пула соединений
@Module({ providers: [PrismaService, UsersService] }) export class UsersModule {}
@Module({ providers: [PrismaService, OrdersService] }) export class OrdersModule {}

// ✓ один PrismaModule, его импортируют
@Module({ providers: [PrismaService], exports: [PrismaService] }) export class PrismaModule {}
```

## Частые ошибки

- Импортировать в модуль сервис (`imports: [UsersService]`) вместо модуля.
- Экспортировать провайдер, которого нет в `providers` (и он не реэкспортируется из импортированного модуля).
- Регистрировать один класс в `providers` нескольких модулей.
- Забыть добавить новый модуль в `imports` родителя.

## Что важно помнить

- Модуль = DI-область + регистрация контроллеров.
- Провайдеры видны снаружи только через `exports`.
- Модули — синглтоны, их можно реэкспортировать.

## Мини-шпаргалка

- `imports` — модули.
- `providers` — то, что создаёт контейнер.
- `exports` — публичный API модуля.
- `controllers` — маршруты.
- Реэкспорт: `exports: [OtherModule]`.
