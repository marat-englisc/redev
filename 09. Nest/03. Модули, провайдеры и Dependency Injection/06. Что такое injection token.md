# Что такое injection token

> [!NOTE]
> **Injection token** — ключ, по которому DI-контейнер регистрирует и находит провайдер. Для обычных сервисов токеном служит **сам класс**, и Nest определяет его по типу параметра конструктора. Когда нужно внедрить то, что не существует в рантайме как класс — **интерфейс**, конфигурацию, экземпляр SDK, примитив, — используют явный токен: **строку**, **`Symbol`** или **абстрактный класс**, и внедряют через `@Inject(TOKEN)`. `Symbol` надёжнее строк (нет случайных совпадений имён), абстрактный класс удобнее всего (он и тип, и токен, `@Inject` не нужен). Токены экспортируют из одного файла, чтобы не дублировать литералы, и для типобезопасности используют `InjectionToken`/`Symbol` вместе с интерфейсом.

## Вопрос

Что такое injection token и когда нужен `@Inject()`?

## Класс как токен

```ts
providers: [UsersService]                          // токен = UsersService
constructor(private readonly users: UsersService)  // @Inject не нужен
```

## Symbol + интерфейс

```ts
// payments/payments.tokens.ts
export interface PaymentsGateway {
  charge(amountCents: number, customerId: string): Promise<{ id: string }>;
}
export const PAYMENTS_GATEWAY = Symbol('PAYMENTS_GATEWAY');

// payments.module.ts
@Module({
  providers: [{ provide: PAYMENTS_GATEWAY, useClass: StripeGateway }],
  exports: [PAYMENTS_GATEWAY],
})
export class PaymentsModule {}

// orders.service.ts
@Injectable()
export class OrdersService {
  constructor(@Inject(PAYMENTS_GATEWAY) private readonly payments: PaymentsGateway) {}
}
```

## Абстрактный класс как токен

```ts
export abstract class PaymentsGateway {
  abstract charge(amountCents: number, customerId: string): Promise<{ id: string }>;
}

providers: [{ provide: PaymentsGateway, useClass: StripeGateway }]

constructor(private readonly payments: PaymentsGateway) {}   // без @Inject
```

## Сравнение типов токенов

| Токен | Плюсы | Минусы |
| --- | --- | --- |
| Класс | Не нужен `@Inject`, автоматически | Только для классов |
| Строка `'REDIS'` | Просто | Опечатки, коллизии имён между библиотеками |
| `Symbol('REDIS')` | Уникален | Нужен `@Inject` и общий импорт |
| Абстрактный класс | Тип + токен, без `@Inject` | Чуть больше кода, чем интерфейс |

## Токены в тестах

```ts
const moduleRef = await Test.createTestingModule({
  providers: [
    OrdersService,
    { provide: PAYMENTS_GATEWAY, useValue: { charge: vi.fn().mockResolvedValue({ id: 'ch_1' }) } },
  ],
}).compile();

const gateway = moduleRef.get<PaymentsGateway>(PAYMENTS_GATEWAY);
```

## Готовые токены Nest

| Токен | Что внедряет |
| --- | --- |
| `APP_GUARD`, `APP_PIPE`, `APP_INTERCEPTOR`, `APP_FILTER` | Регистрация глобальных элементов с DI |
| `REQUEST` | Текущий запрос (делает провайдер request-scoped) |
| `INQUIRER` | Класс, в который внедряется провайдер (например, для логгера с контекстом) |
| `getRepositoryToken(User)` | Репозиторий TypeORM (для моков) |
| `getQueueToken('emails')` | Очередь BullMQ |

## Частые ошибки

- Внедрять интерфейс без токена — Nest получит `Object` и упадёт.
- Строковые токены, разбросанные по коду литералами.
- Экспортировать класс-реализацию, а внедрять по токену (или наоборот).
- Два разных `Symbol('X')` в разных файлах — это разные токены.

## Что важно помнить

- Токен — ключ провайдера в контейнере.
- Классы — токены сами по себе; интерфейсы — нет.
- Предпочтительно `Symbol` или абстрактный класс.

## Мини-шпаргалка

- `export const TOKEN = Symbol('TOKEN')`.
- `{ provide: TOKEN, useClass | useValue | useFactory }`.
- `@Inject(TOKEN) private readonly x: Interface`.
- `moduleRef.get(TOKEN)` в тестах.
