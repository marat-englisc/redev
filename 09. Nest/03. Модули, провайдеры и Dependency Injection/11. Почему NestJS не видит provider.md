# Почему NestJS не видит provider

> [!NOTE]
> Самая частая ошибка NestJS — `Nest can't resolve dependencies of the X (?, Y). Please make sure that the argument Z at index [0] is available in the XModule context.` Она означает, что при создании `X` контейнер не нашёл провайдер для параметра конструктора **в области видимости модуля X**. Типичные причины: провайдер не добавлен в `providers`; он живёт в другом модуле, который **не экспортирует** его или **не импортирован**; внедряется интерфейс или тип без `@Inject(TOKEN)`; класс импортирован через `import type`; **циклический импорт** файлов, из-за которого в момент чтения метаданных класс равен `undefined` (в сообщении — `?` вместо имени); в `imports` указан сервис вместо модуля; две копии `@nestjs/core` в `node_modules`. Читать сообщение нужно внимательно: оно называет **какой** класс, **какой** параметр и **в каком** модуле не найден.

## Вопрос

Почему NestJS не может разрешить зависимость и как найти причину?

## Как читать ошибку

```text
Nest can't resolve dependencies of the OrdersService (OrdersRepository, ?).
Please make sure that the argument UsersService at index [1] is available in the OrdersModule context.
```

- Создаётся: `OrdersService`.
- Не найден: параметр с индексом 1 — `UsersService`.
- Искали в: `OrdersModule`.

## Причины и исправления

| Причина | Признак | Исправление |
| --- | --- | --- |
| Провайдер не зарегистрирован | Сервис есть только как файл | Добавить в `providers` своего модуля |
| Не экспортирован | Сервис в `providers` другого модуля | Добавить в `exports` того модуля |
| Модуль не импортирован | `exports` есть | Добавить модуль в `imports` |
| Интерфейс без токена | `argument Object at index [n]` | `@Inject(TOKEN)` или абстрактный класс |
| `import type` / только тип | `Object` или `?` | Обычный `import` |
| Циклический импорт файлов | `?` вместо имени | Разорвать цикл, `forwardRef(() => X)` |
| Сервис в `imports` | Ошибка про модуль | В `imports` — модули |
| Guard/interceptor из другого модуля через `@UseGuards` | Ошибка в контексте модуля контроллера | Зависимости guard должны быть доступны в модуле контроллера |
| Дубли пакета `@nestjs/core` | Всё зарегистрировано, но не видно | Выровнять версии, `npm ls @nestjs/core` |

## Пример исправления

```ts
// ✗
@Module({ providers: [UsersService] })
export class UsersModule {}

@Module({ providers: [OrdersService] })      // UsersModule не импортирован
export class OrdersModule {}

// ✓
@Module({ providers: [UsersService], exports: [UsersService] })
export class UsersModule {}

@Module({ imports: [UsersModule], providers: [OrdersService] })
export class OrdersModule {}
```

## Guards и зависимости

```ts
@Controller('admin')
@UseGuards(RolesGuard)              // RolesGuard создаётся в контексте модуля этого контроллера
export class AdminController {}

// RolesGuard нужен UsersService → UsersService должен быть доступен в AdminModule
```

## Ошибки в тестах

```text
Nest can't resolve dependencies of the UsersService (?). Please make sure that the argument PrismaService at index [0] is available in the RootTestModule context.
```

В тестовом модуле нужно зарегистрировать или замокать **все** зависимости тестируемого класса либо использовать `useMocker`:

```ts
await Test.createTestingModule({ providers: [UsersService] })
  .useMocker(() => ({}))            // автоматические заглушки для недостающих зависимостей
  .compile();
```

## Отладка

```bash
npm ls @nestjs/core @nestjs/common        # нет ли дублей и разных мажорных версий
```

Также помогает сокращение графа: временно убрать зависимости из конструктора, пока ошибка не исчезнет, и проверить, нет ли цикла импортов между файлами (`madge --circular src`).

## Частые ошибки

- Добавить провайдер другого модуля в свой `providers` — ошибка уходит, но появляется второй экземпляр.
- Сделать модуль `@Global()` «чтобы заработало», не разобравшись в причине.
- Не дочитать сообщение до слова `context` — там указан модуль, где искали.

## Что важно помнить

- Ошибка называет класс, индекс параметра и модуль-контекст.
- Чаще всего: нет в `providers`, нет `exports`, нет `imports`.
- `?` в сообщении — обычно цикл импортов или проблема с типом.

## Мини-шпаргалка

- `providers` → `exports` → `imports`.
- Интерфейс → `@Inject(TOKEN)`.
- `?` → цикл файлов, `forwardRef`.
- Тесты → моки или `useMocker`.
