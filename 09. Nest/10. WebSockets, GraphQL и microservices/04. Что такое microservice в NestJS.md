# Что такое microservice в NestJS

> [!NOTE]
> Пакет `@nestjs/microservices` позволяет строить сервисы, которые общаются **не по HTTP**, а через **транспорт**: TCP, Redis, NATS, MQTT, RabbitMQ, Kafka, gRPC (или свой). Микросервис создаётся `NestFactory.createMicroservice(AppModule, { transport, options })` или подключается к обычному HTTP-приложению как **гибридный** (`app.connectMicroservice()` + `app.startAllMicroservices()`). Обработчики помечаются `@MessagePattern('pattern')` — **request-response** (вызывающий ждёт ответ) — или `@EventPattern('event')` — **события** (fire-and-forget, без ответа). Данные — `@Payload()`, метаданные транспорта — `@Ctx()`. Вызывающая сторона использует `ClientProxy` (`ClientsModule.register`) с методами `send()` и `emit()`. Важно, что «микросервисы в Nest» — это инструмент транспорта; архитектурное решение «делить ли систему на сервисы» принимается отдельно: модульный монолит часто проще и дешевле.

## Вопрос

Что такое микросервисы в NestJS и как их создать?

## Сервис-обработчик

```ts
// inventory-service/main.ts
const app = await NestFactory.createMicroservice<MicroserviceOptions>(AppModule, {
  transport: Transport.RMQ,
  options: {
    urls: [process.env.RABBITMQ_URL!],
    queue: 'inventory',
    queueOptions: { durable: true },
    noAck: false,
  },
});
await app.listen();

@Controller()
export class InventoryController {
  constructor(private readonly inventory: InventoryService) {}

  @MessagePattern('inventory.reserve')                      // request-response
  reserve(@Payload() dto: ReserveDto) {
    return this.inventory.reserve(dto);                     // ответ вернётся вызывающему
  }

  @EventPattern('order.cancelled')                          // событие
  async onCancelled(@Payload() e: OrderCancelledEvent, @Ctx() ctx: RmqContext) {
    await this.inventory.release(e.orderId);
    ctx.getChannelRef().ack(ctx.getMessage());              // ручное подтверждение
  }
}
```

## Вызывающая сторона

```ts
@Module({
  imports: [
    ClientsModule.registerAsync([
      {
        name: 'INVENTORY',
        inject: [ConfigService],
        useFactory: (c: ConfigService) => ({
          transport: Transport.RMQ,
          options: { urls: [c.getOrThrow('RABBITMQ_URL')], queue: 'inventory', queueOptions: { durable: true } },
        }),
      },
    ]),
  ],
})
export class OrdersModule {}

@Injectable()
export class OrdersService {
  constructor(@Inject('INVENTORY') private readonly inventory: ClientProxy) {}

  async create(dto: CreateOrderDto) {
    const reservation = await firstValueFrom(
      this.inventory.send<Reservation>('inventory.reserve', { items: dto.items }).pipe(timeout(3_000)),
    );
    // ...
    this.inventory.emit('order.created', { orderId: '...' });
  }
}
```

## Гибридное приложение

```ts
const app = await NestFactory.create(AppModule);                 // HTTP API
app.connectMicroservice<MicroserviceOptions>({ transport: Transport.KAFKA, options: { ... } }, { inheritAppConfig: true });
await app.startAllMicroservices();
await app.listen(3000);
```

`inheritAppConfig: true` применяет глобальные pipes/filters HTTP-приложения и к микросервису.

## Транспорты

| Транспорт | Особенности |
| --- | --- |
| TCP | Просто, без брокера, но без персистентности |
| Redis | Pub/sub, быстро, сообщения не хранятся |
| NATS | Лёгкий брокер, request-reply, JetStream для персистентности (NestJS 12 — NATS v3) |
| RabbitMQ | Очереди, подтверждения, маршрутизация, DLQ |
| Kafka | Лог событий, партиции, replay, высокая пропускная способность |
| gRPC | Строгий контракт `.proto`, бинарный протокол, стриминг |

## Монолит или микросервисы

| Модульный монолит | Микросервисы |
| --- | --- |
| Один деплой, транзакции в одной БД | Независимые деплои и масштабирование |
| Простая отладка | Распределённые транзакции (саги), трассировка |
| Подходит большинству продуктов на старте | Нужны при нескольких командах и разных требованиях к нагрузке |

## Частые ошибки

- `send()` без таймаута — запрос висит, если сервис не ответил.
- Синхронные цепочки `send()` через 4–5 сервисов — распределённый монолит.
- Нет идемпотентности обработчиков событий при повторной доставке.
- Общая база данных у нескольких «микросервисов».
- Ошибки обработчика не превращаются в `RpcException` и теряются.

## Что важно помнить

- Транспорт + `@MessagePattern` (запрос-ответ) / `@EventPattern` (событие).
- Клиент — `ClientProxy` с `send` и `emit`.
- Микросервисы — архитектурное решение с высокой стоимостью; модульный монолит — частая альтернатива.

## Мини-шпаргалка

- `NestFactory.createMicroservice(App, { transport, options })`.
- `app.connectMicroservice()` + `startAllMicroservices()` — гибрид.
- `@MessagePattern`, `@EventPattern`, `@Payload()`, `@Ctx()`.
- `ClientsModule.register([{ name, transport, options }])`.
