# Как работать с WebSocket client и server events

> [!NOTE]
> В WebSocket-gateway обмен идёт **событиями**: клиент отправляет `emit('event', data)`, сервер обрабатывает его методом `@SubscribeMessage('event')`. Ответить можно тремя способами: **вернуть значение** из обработчика — оно уйдёт как **ack** (подтверждение) на этот вызов; вернуть `{ event, data }` (или `WsResponse`) — сервер отправит отдельное событие этому клиенту; или отправить вручную через `client.emit` / `server.emit`. Адресация в Socket.IO: `client.emit` — одному клиенту, `client.broadcast.emit` — всем, кроме отправителя, `server.to(room).emit` — участникам **комнаты**, `server.emit` — всем в namespace. Комнаты (`client.join('room:42')`) — основной способ группировать получателей: по чату, по пользователю (`user:<id>` для всех его вкладок и устройств), по тенанту. Именуйте события единообразно (`message:send`, `message:new`), валидируйте payload DTO и проверяйте права на комнату.

## Вопрос

Как организовать обмен событиями между WebSocket-клиентом и сервером в NestJS?

## Варианты ответа

```ts
@WebSocketGateway({ namespace: '/rooms' })
export class RoomsGateway {
  @WebSocketServer() server: Server;

  // 1. ack — значение вернётся в колбэк клиента
  @SubscribeMessage('ping')
  ping() {
    return { pong: Date.now() };
  }

  // 2. отдельное событие отправителю
  @SubscribeMessage('profile:get')
  profile(@ConnectedSocket() client: Socket): WsResponse<UserProfile> {
    return { event: 'profile:data', data: client.data.user };
  }

  // 3. вручную — в комнату
  @SubscribeMessage('room:join')
  async join(@MessageBody() { roomId }: JoinRoomDto, @ConnectedSocket() client: Socket) {
    await this.rooms.assertMember(roomId, client.data.user.id);       // права!
    await client.join(`room:${roomId}`);
    client.to(`room:${roomId}`).emit('room:user-joined', { userId: client.data.user.id });
    return { joined: roomId };
  }

  @SubscribeMessage('room:leave')
  async leave(@MessageBody() { roomId }: JoinRoomDto, @ConnectedSocket() client: Socket) {
    await client.leave(`room:${roomId}`);
  }
}
```

## Клиент

```ts
const socket = io('/rooms', { auth: { token } });

const res = await socket.emitWithAck('ping');                // ack как промис
socket.emit('room:join', { roomId: '42' }, (ack) => {});
socket.on('room:user-joined', ({ userId }) => {});
socket.on('exception', (err) => console.error(err));          // WsException
socket.on('connect_error', (err) => {});                      // отказ при подключении
```

## Адресация

| Кому | Socket.IO |
| --- | --- |
| Отправителю | `client.emit(evt, data)` или `return` |
| Всем, кроме отправителя | `client.broadcast.emit(evt, data)` |
| Комнате, кроме отправителя | `client.to(room).emit(evt, data)` |
| Комнате, включая отправителя | `server.to(room).emit(evt, data)` |
| Нескольким комнатам | `server.to([r1, r2]).emit(...)` |
| Всем в namespace | `server.emit(evt, data)` |
| Всем устройствам пользователя | `server.to(\`user:${id}\`).emit(...)` |

## Валидация payload

```ts
export class SendMessageDto {
  @IsUUID() roomId: string;
  @IsString() @Length(1, 2000) text: string;
}

@UsePipes(new ValidationPipe({ whitelist: true, exceptionFactory: (errors) => new WsException(errors) }))
@SubscribeMessage('message:send')
send(@MessageBody() dto: SendMessageDto) {}
```

## Соглашения о событиях

- Имена `сущность:действие`: `message:send` (клиент → сервер), `message:new` (сервер → клиенты).
- Общий тип событий для клиента и сервера (`interface ServerToClientEvents`, `ClientToServerEvents` в Socket.IO).
- Версионирование протокола при ломающих изменениях.
- Идемпотентность: клиент может повторить отправку после переподключения — используйте `clientMessageId`.

## Переподключение и пропущенные события

Socket.IO переподключается автоматически, но события, отправленные во время разрыва, теряются. Для важных данных: после `connect` клиент запрашивает изменения с последнего известного id или включается [connection state recovery](https://socket.io/docs/v4/connection-state-recovery).

## Частые ошибки

- Подписка на комнату без проверки прав.
- `server.emit` всем там, где нужна комната.
- Отсутствие ack и обработки ошибок на клиенте.
- Передача больших объектов в каждом событии вместо id и дельт.

## Что важно помнить

- Ответ: `return` (ack), `{ event, data }`, или ручной `emit`.
- Комнаты — основа адресации.
- Валидация payload и проверка прав — как в HTTP.

## Мини-шпаргалка

- `@SubscribeMessage('a:b')` + `@MessageBody()` + `@ConnectedSocket()`.
- `client.join(room)`, `client.leave(room)`.
- `server.to(room).emit()`, `client.to(room).emit()`, `client.broadcast.emit()`.
- `socket.emitWithAck()` на клиенте.
