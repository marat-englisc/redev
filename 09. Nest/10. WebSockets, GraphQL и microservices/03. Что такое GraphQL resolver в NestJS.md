# Что такое GraphQL resolver в NestJS

> [!NOTE]
> **Resolver** в GraphQL — аналог контроллера: класс с `@Resolver()`, методы которого обрабатывают операции схемы — `@Query()` (чтение), `@Mutation()` (изменение), `@Subscription()` (поток событий, в NestJS 12 — только через `graphql-ws`) и `@ResolveField()` (вычисление поля типа, например `Post.author`). Пакет `@nestjs/graphql` с драйвером Apollo или Mercurius поддерживает два подхода: **code first** — схема генерируется из TypeScript-классов с `@ObjectType`, `@Field`, `@InputType`, `@Args`; **schema first** — пишется SDL (`.graphql`), а Nest генерирует типы. Resolver получает зависимости через DI и поддерживает guards, pipes, interceptors и filters (контекст — через `GqlExecutionContext`). Главная ловушка — **N+1** в `@ResolveField`: для списка из 50 постов поле `author` вызовет 50 запросов, если не использовать **DataLoader**.

## Вопрос

Что такое resolver в GraphQL и как он устроен в NestJS?

## Подключение (code first)

```bash
npm install @nestjs/graphql @nestjs/apollo @apollo/server graphql
```

```ts
GraphQLModule.forRoot<ApolloDriverConfig>({
  driver: ApolloDriver,
  autoSchemaFile: true,             // схема в памяти из классов
  sortSchema: true,
  context: ({ req }) => ({ req }),
  subscriptions: { 'graphql-ws': true },
});
```

## Типы

```ts
@ObjectType()
export class Post {
  @Field(() => ID) id: string;
  @Field() title: string;
  @Field({ nullable: true }) body?: string;
  @Field(() => GraphQLISODateTime) createdAt: Date;
  authorId: string;                 // не в схеме
}

@InputType()
export class CreatePostInput {
  @Field() @Length(3, 120) title: string;
  @Field({ nullable: true }) @MaxLength(10_000) body?: string;
}
```

## Resolver

```ts
@Resolver(() => Post)
export class PostsResolver {
  constructor(private readonly posts: PostsService, private readonly users: UsersService) {}

  @Query(() => [Post])
  posts(@Args('first', { type: () => Int, defaultValue: 20 }) first: number) {
    return this.posts.list(Math.min(first, 100));
  }

  @Query(() => Post, { nullable: true })
  post(@Args('id', { type: () => ID }) id: string) {
    return this.posts.findOne(id);
  }

  @UseGuards(GqlAuthGuard)
  @Mutation(() => Post)
  createPost(@Args('input') input: CreatePostInput, @CurrentUser() user: AuthUser) {
    return this.posts.create(user.id, input);
  }

  @ResolveField(() => User)
  author(@Parent() post: Post, @Context('loaders') loaders: Loaders) {
    return loaders.userById.load(post.authorId);       // DataLoader, не this.users.findOne — иначе N+1
  }
}
```

```graphql
query {
  posts(first: 10) { id title author { id name } }
}
```

## Guards и контекст

```ts
@Injectable()
export class GqlAuthGuard extends JwtAuthGuard {
  getRequest(context: ExecutionContext) {
    return GqlExecutionContext.create(context).getContext().req;
  }
}
```

## Code first или schema first

| Code first | Schema first |
| --- | --- |
| Схема из TS-классов, один источник правды в коде | SDL — контракт, удобен для согласования с фронтендом |
| Валидация `class-validator` прямо на `InputType` | Типы генерируются из SDL |
| Чаще используется в Nest-проектах | Подходит для schema-driven команд |

## Защита GraphQL API

- Ограничение глубины и сложности запросов (`graphql-depth-limit`, query complexity плагины).
- Лимиты на размер списков (`first ≤ 100`).
- Отключить introspection и playground в проде или закрыть авторизацией.
- Persisted queries для публичных клиентов.
- Авторизация на уровне полей, а не только запросов.

## Частые ошибки

- N+1 в `@ResolveField` без DataLoader — см. [N+1 в NestJS](<../11. Production, архитектура и собеседования/05. Как избежать N плюс 1 в NestJS.md>).
- `switchToHttp()` в guard вместо `GqlExecutionContext`.
- Неограниченные списки и глубина запросов.
- Ошибки сервиса как 500 без `extensions.code`.

## Что важно помнить

- Resolver = контроллер GraphQL: `@Query`, `@Mutation`, `@Subscription`, `@ResolveField`.
- Code first: `@ObjectType`, `@Field`, `@InputType`, `@Args`.
- Связи — через DataLoader, контекст — `GqlExecutionContext`.

## Мини-шпаргалка

- `GraphQLModule.forRoot({ driver: ApolloDriver, autoSchemaFile: true })`.
- `@Resolver(() => T)`, `@Query(() => [T])`, `@Mutation(() => T)`.
- `@ResolveField() f(@Parent() p)`.
- `GqlExecutionContext.create(ctx).getContext().req`.
