# Как отправлять события через Server-Sent Events

> [!NOTE]
> **Server-Sent Events (SSE)** — односторонний поток событий **от сервера к клиенту** поверх обычного HTTP (`Content-Type: text/event-stream`). Браузер подключается через встроенный `EventSource`, который сам переподключается и передаёт `Last-Event-ID`, чтобы сервер мог дослать пропущенное. SSE проще WebSocket: не нужен отдельный протокол и библиотеки, работает через обычные прокси и HTTP/2, не требует отдельной аутентификации соединения. Подходит для уведомлений, прогресса фоновых задач, live-ленты, стриминга ответов LLM; если нужен двусторонний обмен с высокой частотой — WebSocket. В NestJS метод помечается `@Sse('path')` и возвращает `Observable<MessageEvent>` (`{ data, id?, type?, retry? }`). Источником обычно служит `Subject` или поток из Redis pub/sub/EventEmitter; при отключении клиента подписка завершается.

## Вопрос

Как реализовать Server-Sent Events в NestJS?

## Простой поток

```ts
@Controller('jobs')
export class JobsController {
  constructor(private readonly progress: JobProgressService) {}

  @Sse(':id/progress')
  progressStream(@Param('id', ParseUUIDPipe) id: string, @CurrentUser() user: AuthUser): Observable<MessageEvent> {
    return this.progress.stream(id, user.id).pipe(
      map((p) => ({ id: String(p.seq), type: 'progress', data: { percent: p.percent, stage: p.stage } })),
      takeWhile((e) => e.data.percent < 100, true),        // закрыть поток после 100%
    );
  }
}
```

## Источник событий

```ts
@Injectable()
export class JobProgressService {
  private readonly subject = new Subject<{ jobId: string; userId: string; seq: number; percent: number; stage: string }>();

  // вызывается воркером (или из Redis pub/sub в кластере)
  publish(update: { jobId: string; userId: string; seq: number; percent: number; stage: string }) {
    this.subject.next(update);
  }

  stream(jobId: string, userId: string) {
    return this.subject.asObservable().pipe(filter((u) => u.jobId === jobId && u.userId === userId));
  }
}
```

## Keep-alive

```ts
@Sse('notifications')
notifications(@CurrentUser() user: AuthUser): Observable<MessageEvent> {
  const heartbeat$ = interval(25_000).pipe(map(() => ({ type: 'ping', data: '' })));
  const events$ = this.notifications.forUser(user.id).pipe(map((n) => ({ id: n.id, type: 'notification', data: n })));
  return merge(events$, heartbeat$);
}
```

Периодический ping не даёт прокси и балансировщикам закрыть «тихое» соединение по таймауту.

## Клиент

```ts
const source = new EventSource('/api/jobs/42/progress', { withCredentials: true });
source.addEventListener('progress', (e) => {
  const { percent } = JSON.parse(e.data);
  setProgress(percent);
});
source.onerror = () => { /* EventSource переподключится сам */ };
```

`EventSource` не позволяет задать заголовок `Authorization` — используют cookie-аутентификацию или `fetch` с потоковым чтением (`ReadableStream`), если нужен Bearer-токен.

## SSE, WebSocket, polling

| | SSE | WebSocket | Polling |
| --- | --- | --- | --- |
| Направление | Сервер → клиент | Двустороннее | Клиент → сервер |
| Протокол | HTTP | Отдельный (upgrade) | HTTP |
| Переподключение | Встроено в `EventSource` | Socket.IO — да, ws — вручную | — |
| Бинарные данные | Нет (текст) | Да | Да |
| Когда | Уведомления, прогресс, стриминг | Чаты, совместная работа, игры | Редкие обновления |

## Масштабирование

В кластере событие, опубликованное в одном инстансе, должно дойти до клиента, подключённого к другому: источник событий делают на Redis pub/sub, NATS или аналогах. Также учитывают лимит открытых соединений на процесс и настройки прокси (`proxy_buffering off` в nginx, чтобы события не копились в буфере).

## Частые ошибки

- nginx буферизует ответ — события приходят пачкой в конце.
- Нет heartbeat — соединение рвётся через 60 с простоя.
- Поток без фильтра по пользователю — утечка чужих событий.
- In-memory `Subject` в нескольких репликах.
- Попытка передать токен в заголовке через `EventSource`.

## Что важно помнить

- SSE — простой однонаправленный поток по HTTP.
- `@Sse()` + `Observable<MessageEvent>`.
- Heartbeat, отключение буферизации прокси, общая шина событий в кластере.

## Мини-шпаргалка

- `@Sse('path') f(): Observable<MessageEvent>`.
- `{ id, type, data, retry }`.
- `new EventSource(url, { withCredentials: true })`.
- nginx: `proxy_buffering off`.
