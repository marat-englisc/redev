# Какие production-настройки важны для NestJS

> [!NOTE]
> Продакшен-готовность NestJS-приложения — это набор настроек, которые не видны в разработке. **Сборка и запуск**: `nest build` (часто со SWC), запуск `node dist/main.js` (не `start:dev`), `NODE_ENV=production`, multi-stage Docker-образ без dev-зависимостей, непривилегированный пользователь. **Конфигурация**: валидация env при старте, секреты из окружения. **HTTP**: `helmet`, строгий CORS, `trust proxy` за балансировщиком, лимит размера тела, сжатие на прокси, таймауты. **Конвейер**: глобальные `ValidationPipe`, exception filter, rate limiting, guards «закрыто по умолчанию». **Надёжность**: `enableShutdownHooks()`, health checks, пул соединений под число реплик, миграции отдельным шагом, идемпотентные фоновые задачи. **Наблюдаемость**: JSON-логи, метрики, трейсы, Sentry. **Безопасность**: Swagger закрыт или выключен, `/metrics` не наружу, обновлённые зависимости.

## Вопрос

Какие настройки нужны NestJS-приложению для работы в продакшене?

## main.ts для продакшена

```ts
async function bootstrap() {
  const app = await NestFactory.create<NestExpressApplication>(AppModule, { bufferLogs: true });
  const config = app.get(ConfigService<EnvVars, true>);

  app.useLogger(app.get(Logger));                       // nestjs-pino
  app.set('trust proxy', 1);                            // корректный req.ip и protocol за балансировщиком
  app.use(helmet());
  app.useBodyParser('json', { limit: '100kb' });
  app.enableCors({ origin: config.get('CORS_ORIGINS', { infer: true }), credentials: true });

  app.setGlobalPrefix('api', { exclude: ['health/live', 'health/ready', 'metrics'] });
  app.enableVersioning({ type: VersioningType.URI, defaultVersion: '1' });
  app.useGlobalPipes(new ValidationPipe({ whitelist: true, forbidNonWhitelisted: true, transform: true }));
  app.enableShutdownHooks();

  if (config.get('SWAGGER_ENABLED', { infer: true })) setupSwagger(app);   // по умолчанию выключен

  const server = await app.listen(config.get('PORT', { infer: true }), '0.0.0.0');
  server.keepAliveTimeout = 65_000;                     // больше, чем idle timeout балансировщика (часто 60 с)
  server.headersTimeout = 66_000;
}
```

## Dockerfile

```dockerfile
FROM node:24-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npx prisma generate && npm run build && npm prune --omit=dev

FROM node:24-alpine
WORKDIR /app
ENV NODE_ENV=production
COPY --from=build --chown=node:node /app/node_modules ./node_modules
COPY --from=build --chown=node:node /app/dist ./dist
COPY --from=build --chown=node:node /app/package.json ./
USER node
EXPOSE 3000
CMD ["node", "dist/main.js"]
```

## Чек-лист

| Область | Настройка |
| --- | --- |
| Запуск | `node dist/main.js`, `NODE_ENV=production`, exec-форма `CMD` |
| Конфиг | Валидация env, секреты из secret manager |
| HTTP | `helmet`, CORS allowlist, `trust proxy`, лимит тела, keep-alive > таймаута балансировщика |
| Валидация | Глобальный `ValidationPipe` с `whitelist` |
| Ошибки | Глобальный filter, 5xx без деталей |
| Доступ | Глобальные guards, rate limiting |
| БД | Пул под число реплик, миграции в CI/CD, без `synchronize` |
| Остановка | `enableShutdownHooks()`, readiness, grace period |
| Наблюдаемость | JSON-логи, `/metrics` (внутренний), трейсы, Sentry |
| Документация | Swagger выключен или за авторизацией |
| Зависимости | `npm audit`, Dependabot/Renovate, фиксированные версии |
| Производительность | Компрессия и TLS на прокси, кеш, профилирование при необходимости |

## Масштабирование

- Stateless-приложение: сессии, кеш, rate-limit счётчики, WebSocket-адаптер — в Redis.
- Несколько реплик за балансировщиком лучше, чем `cluster` внутри контейнера.
- Тяжёлые задачи — в отдельные воркеры (BullMQ), cron — один исполнитель.

## Частые ошибки

- `npm run start:dev` в контейнере.
- `synchronize: true` или `prisma db push` в проде.
- Открытый Swagger с «Try it out» на проде.
- `keepAliveTimeout` меньше таймаута балансировщика — спорадические 502.
- Нет лимита тела запроса.

## Что важно помнить

- Прод отличается сборкой, конфигурацией, защитой, надёжностью и наблюдаемостью.
- Всё глобальное — в `main.ts` или через `APP_*` и одинаково в тестах.
- Приложение stateless, состояние — во внешних хранилищах.

## Мини-шпаргалка

- `nest build` → `node dist/main.js`.
- `helmet`, CORS, `trust proxy`, `useBodyParser(limit)`.
- `ValidationPipe`, filter, guards, throttler.
- `enableShutdownHooks()`, health, метрики, логи.
