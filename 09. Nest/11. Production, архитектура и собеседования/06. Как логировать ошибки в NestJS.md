# Как логировать ошибки в NestJS

> [!NOTE]
> В NestJS есть встроенный `Logger` (`new Logger(Context)` в классах, уровни `log`, `error`, `warn`, `debug`, `verbose`, `fatal`), а в NestJS 12 стандартный логгер по умолчанию пишет **структурированные параметры**. Для продакшена логи делают **структурированными (JSON)** и отправляют в систему сбора (Loki, ELK, Datadog, CloudWatch) — обычно через `nestjs-pino` (быстрый `pino` + автоматический лог HTTP-запросов) или Winston. Обязательные элементы: **request/correlation id** в каждой записи (через AsyncLocalStorage), уровень, контекст (модуль/класс), сообщение, данные ошибки со **стеком** для 5xx, пользователь/тенант (без персональных данных сверх необходимого). Ошибки логируют **в одном месте** — в глобальном exception filter (5xx — `error`, ожидаемые 4xx — `warn`/`debug` или вовсе нет), а не `console.log` в каждом `catch`. Чувствительные данные (пароли, токены, cookies, номера карт) маскируют (`redact`). Для алертинга и анализа ошибок добавляют Sentry или аналог.

## Вопрос

Как организовать логирование ошибок в NestJS-приложении?

## Встроенный Logger

```ts
@Injectable()
export class PaymentsService {
  private readonly logger = new Logger(PaymentsService.name);

  async charge(orderId: string) {
    this.logger.log({ orderId }, 'Charging order');
    try {
      // ...
    } catch (err) {
      this.logger.error({ orderId, err }, 'Charge failed');
      throw err;
    }
  }
}
```

## nestjs-pino

```bash
npm install nestjs-pino pino-http pino-pretty
```

```ts
@Module({
  imports: [
    LoggerModule.forRootAsync({
      inject: [ConfigService],
      useFactory: (c: ConfigService) => ({
        pinoHttp: {
          level: c.get('LOG_LEVEL', 'info'),
          genReqId: (req) => (req.headers['x-request-id'] as string) ?? randomUUID(),
          redact: ['req.headers.authorization', 'req.headers.cookie', '*.password', '*.token'],
          customLogLevel: (_req, res, err) => (err || res.statusCode >= 500 ? 'error' : res.statusCode >= 400 ? 'warn' : 'info'),
          autoLogging: { ignore: (req) => req.url === '/health/live' },
          transport: c.get('NODE_ENV') === 'development' ? { target: 'pino-pretty' } : undefined,
        },
      }),
    }),
  ],
})
export class AppModule {}

// main.ts
const app = await NestFactory.create(AppModule, { bufferLogs: true });
app.useLogger(app.get(Logger));        // Logger из nestjs-pino
```

## Глобальный filter — единая точка

```ts
@Catch()
export class GlobalExceptionFilter implements ExceptionFilter {
  private readonly logger = new Logger('Exceptions');

  catch(exception: unknown, host: ArgumentsHost) {
    const status = exception instanceof HttpException ? exception.getStatus() : 500;
    const req = host.switchToHttp().getRequest();

    if (status >= 500) {
      this.logger.error({ err: exception, path: req.url, userId: req.user?.id }, 'Unhandled exception');
      Sentry.captureException(exception);
    } else if (status !== 404) {
      this.logger.warn({ status, path: req.url, message: (exception as Error).message }, 'Client error');
    }
    // ... ответ клиенту
  }
}
```

## Уровни

| Уровень | Что писать |
| --- | --- |
| `fatal` | Приложение не может работать |
| `error` | Ошибки 5xx, сбои интеграций, упавшие задачи после всех повторов |
| `warn` | Подозрительное: повторы, деградация, отказ в доступе |
| `info` | Ключевые бизнес-события, старт/остановка |
| `debug` | Детали для отладки (выключены в проде) |

## Что не логировать

- Пароли, токены, cookies, секреты, полные номера карт.
- Тела запросов целиком (особенно с персональными данными).
- Ожидаемые 404 и 401 на уровне `error` — шум скрывает реальные проблемы.

## Необработанные ошибки процесса

```ts
process.on('unhandledRejection', (reason) => logger.fatal({ err: reason }, 'Unhandled rejection'));
```

Лучше исправлять источник: каждая `async`-функция должна быть `await`-нута или явно обработана.

## Частые ошибки

- `console.log` по всему коду — без уровней, контекста и requestId.
- Логировать одну ошибку в каждом слое (`catch → log → throw`) — дубли.
- Нет стека у 5xx.
- Логирование секретов.
- Текстовые логи в проде, которые невозможно фильтровать.

## Что важно помнить

- Структурированные JSON-логи с requestId.
- Ошибки — в глобальном exception filter, 5xx со стеком.
- `redact` для чувствительных данных, Sentry для алертов.

## Мини-шпаргалка

- `new Logger(Ctx)`, `logger.error({ err, ...ctx }, msg)`.
- `nestjs-pino`: `LoggerModule.forRoot`, `app.useLogger(app.get(Logger))`.
- `bufferLogs: true`.
- `redact: ['req.headers.authorization', ...]`.
