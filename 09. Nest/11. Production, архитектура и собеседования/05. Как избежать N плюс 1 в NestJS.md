# Как избежать N+1 в NestJS

> [!NOTE]
> **Проблема N+1** — один запрос получает список из N сущностей, а затем для каждой выполняется ещё по запросу за связанными данными. В NestJS она появляется в трёх местах: в **сервисах** (`await` внутри цикла или `Promise.all(items.map(i => repo.find...))`), в **ORM** (ленивые связи TypeORM, обращение к связям в цикле) и особенно в **GraphQL** — `@ResolveField('author')` вызывается для **каждого** поста в списке. Решения: загрузить связи **одним запросом** (`include`/`select` в Prisma, `relations`/`leftJoinAndSelect` в TypeORM), сделать **второй запрос по списку id** (`where: { id: { in: ids } }`) и собрать данные в памяти, а в GraphQL — **DataLoader**, который за один тик собирает все `load(id)` в один батч-запрос. DataLoader создаётся **на каждый запрос** (через контекст GraphQL или request-scoped/CLS-провайдер), чтобы его кеш не протекал между пользователями. Обнаруживают N+1 по логам SQL, APM-трейсам и тестам на число запросов.

## Вопрос

Как обнаружить и устранить проблему N+1 в NestJS-приложении (REST и GraphQL)?

## N+1 в сервисе

```ts
// ✗ 1 + N запросов
const posts = await this.prisma.post.findMany({ take: 20 });
for (const post of posts) {
  post.author = await this.prisma.user.findUnique({ where: { id: post.authorId } });
}

// ✓ один запрос с join
const posts = await this.prisma.post.findMany({
  take: 20,
  include: { author: { select: { id: true, name: true } } },
});

// ✓ два запроса: список + связи по id
const posts = await this.prisma.post.findMany({ take: 20 });
const authors = await this.prisma.user.findMany({ where: { id: { in: [...new Set(posts.map((p) => p.authorId))] } } });
const byId = new Map(authors.map((a) => [a.id, a]));
```

```ts
// TypeORM
this.posts.find({ take: 20, relations: { author: true } });
this.posts.createQueryBuilder('p').leftJoinAndSelect('p.author', 'a').take(20).getMany();
```

## N+1 в GraphQL

```graphql
query { posts(first: 50) { id title author { name } } }   # 1 запрос постов + 50 запросов авторов
```

## DataLoader

```ts
// loaders.factory.ts
@Injectable()
export class LoadersFactory {
  constructor(private readonly prisma: PrismaService) {}

  create() {
    return {
      userById: new DataLoader<string, User | null>(async (ids) => {
        const users = await this.prisma.user.findMany({ where: { id: { in: [...ids] } } });
        const map = new Map(users.map((u) => [u.id, u]));
        return ids.map((id) => map.get(id) ?? null);           // порядок как у ids!
      }),
      commentsByPostId: new DataLoader<string, Comment[]>(async (postIds) => {
        const rows = await this.prisma.comment.findMany({ where: { postId: { in: [...postIds] } } });
        return postIds.map((id) => rows.filter((c) => c.postId === id));
      }),
    };
  }
}
export type Loaders = ReturnType<LoadersFactory['create']>;

// новый набор loaders на каждый запрос
GraphQLModule.forRootAsync<ApolloDriverConfig>({
  driver: ApolloDriver,
  imports: [LoadersModule],
  inject: [LoadersFactory],
  useFactory: (factory: LoadersFactory) => ({
    autoSchemaFile: true,
    context: ({ req }) => ({ req, loaders: factory.create() }),
  }),
});

// resolver
@ResolveField(() => User)
author(@Parent() post: Post, @Context('loaders') loaders: Loaders) {
  return loaders.userById.load(post.authorId);
}
```

Теперь `posts(first: 50) { author }` — 2 запроса вместо 51.

## Частые ошибки

- `Promise.all(items.map(fetchOne))` — параллельный N+1, всё равно N запросов.
- DataLoader как синглтон — кеш между пользователями и устаревшие данные.
- Batch-функция возвращает результаты не в порядке `ids`.
- Гигантский `include` нескольких one-to-many связей — взрыв данных вместо N+1.
- `eager: true` в TypeORM «на всякий случай».

## Что важно помнить

- N+1 = запрос на каждый элемент списка.
- REST/сервисы: `include`/`relations` или второй запрос с `IN`.
- GraphQL: DataLoader на каждый запрос.

## Мини-шпаргалка

- Prisma `include` / `select` вложенных связей.
- `where: { id: { in: ids } }` + `Map`.
- `new DataLoader(async (ids) => ids.map(...))`.
- Loaders в контексте GraphQL на запрос.
