# Что такое graceful shutdown в NestJS

> [!NOTE]
> **Graceful shutdown** — корректная остановка приложения при сигнале завершения (`SIGTERM` от Kubernetes, Docker, systemd): перестать принимать новые запросы, **дождаться завершения текущих** (HTTP, фоновые задачи, обработчики сообщений), закрыть соединения с БД, Redis, брокером и сбросить буферы логов — и только потом выйти. Без этого rolling deploy обрывает запросы пользователей и оставляет задачи в «полуготовом» состоянии. В NestJS это включается вызовом **`app.enableShutdownHooks()`**: при сигнале Nest вызывает `onModuleDestroy`, `beforeApplicationShutdown(signal)`, закрывает HTTP-сервер и вызывает `onApplicationShutdown(signal)`. Важно учитывать оркестратор: в Kubernetes под сначала исключается из балансировки, но это происходит не мгновенно, поэтому часто добавляют короткую задержку (`preStop` sleep) и readiness-проверку, переключающуюся в «не готов» при остановке; а `terminationGracePeriodSeconds` должен быть больше времени завершения.

## Вопрос

Что такое graceful shutdown и как его реализовать в NestJS?

## Включение

```ts
// main.ts
const app = await NestFactory.create(AppModule);
app.enableShutdownHooks();             // SIGTERM, SIGINT и др.
await app.listen(3000);
```

## Хуки

```ts
@Injectable()
export class PrismaService extends PrismaClient implements OnModuleInit, OnApplicationShutdown {
  async onModuleInit() { await this.$connect(); }
  async onApplicationShutdown() { await this.$disconnect(); }
}

@Injectable()
export class ShutdownState implements BeforeApplicationShutdown {
  private shuttingDown = false;
  get isShuttingDown() { return this.shuttingDown; }

  async beforeApplicationShutdown(signal?: string) {
    this.shuttingDown = true;                        // readiness → 503
    await new Promise((r) => setTimeout(r, 5_000));  // дать балансировщику убрать под
  }
}
```

## Readiness при остановке

```ts
@Controller('health')
export class HealthController {
  constructor(private readonly health: HealthCheckService, private readonly db: PrismaHealthIndicator,
              private readonly prisma: PrismaService, private readonly state: ShutdownState) {}

  @Get('live')
  live() { return { status: 'ok' }; }                // процесс жив

  @Get('ready')
  @HealthCheck()
  ready() {
    if (this.state.isShuttingDown) throw new ServiceUnavailableException();
    return this.health.check([() => this.db.pingCheck('db', this.prisma)]);
  }
}
```

## Последовательность в Kubernetes

```text
1. Под помечается Terminating, kubelet выполняет preStop (например, sleep 5)
2. Параллельно endpoint пода удаляется из Service (не мгновенно!)
3. Приложение получает SIGTERM
   → beforeApplicationShutdown: readiness=503, ждём
   → HTTP-сервер перестаёт принимать соединения, ждёт текущие запросы
   → onApplicationShutdown: закрываем БД, Redis, воркеры очередей
4. Процесс завершается до terminationGracePeriodSeconds (по умолчанию 30 с), иначе SIGKILL
```

## Фоновые воркеры

BullMQ-воркеры `@nestjs/bullmq` закрываются при остановке модуля и дожидаются текущих задач; задачи, которые не успели завершиться, вернутся в очередь (поэтому обработчики должны быть идемпотентны). Для своих циклов обработки — флаг остановки и ожидание текущей итерации в `beforeApplicationShutdown`.

## Docker и PID 1

Сигнал должен дойти до Node.js: запускать `CMD ["node", "dist/main.js"]` (exec-форма), а не через `npm start` или shell-форму, которые могут не пробрасывать `SIGTERM`. Подробнее — [PID 1 и сигналы](<../../13. Docker/07. Production безопасность и отладка/06. Как работают PID 1, сигналы и graceful shutdown.md>).

## Частые ошибки

- Нет `enableShutdownHooks()` — хуки остановки не вызываются.
- `npm start` как PID 1 — Node не получает `SIGTERM`.
- Время завершения больше `terminationGracePeriodSeconds` — SIGKILL посреди работы.
- Readiness продолжает отвечать 200 во время остановки — трафик идёт на умирающий под.
- Неидемпотентные задачи, которые при повторе после остановки дублируют эффекты.

## Что важно помнить

- Graceful shutdown: не принимать новое, доделать текущее, закрыть ресурсы.
- `app.enableShutdownHooks()` + `beforeApplicationShutdown` / `onApplicationShutdown`.
- Согласовать с оркестратором: readiness, `preStop`, grace period, exec-форма `CMD`.

## Мини-шпаргалка

- `app.enableShutdownHooks()`.
- `beforeApplicationShutdown(signal)` — readiness=503, пауза.
- `onApplicationShutdown()` — закрыть соединения.
- K8s: `preStop`, `terminationGracePeriodSeconds`.
- Docker: `CMD ["node", "dist/main.js"]`.
