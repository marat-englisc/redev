# Как построить учебный CRUD проект на NestJS

> [!NOTE]
> Учебный проект лучше строить **слоями**, добавляя по одной технологии и закрепляя каждую: сначала ресурс без базы (in-memory), затем валидация и обработка ошибок, затем база данных и миграции, аутентификация и авторизация, документация OpenAPI, тесты (unit + e2e с реальной БД), и в конце — production-настройки (Docker, логи, health checks, CI). Так NestJS перестаёт быть набором декораторов и становится понятной системой, а результат — портфолио-проект, который можно показать и подробно обсудить на собеседовании. Хорошая предметная область — небольшой магазин, трекер задач или блог: есть пользователи, роли, связи один-ко-многим и многие-ко-многим, пагинация, загрузка файлов и фоновые задачи.

## Вопрос

Как построить учебный CRUD-проект на NestJS, чтобы освоить фреймворк?

## Предметная область: трекер задач

```text
User 1──N Project 1──N Task N──M Tag
User 1──N Comment N──1 Task
```

## План по шагам

| Шаг | Что сделать | Что освоить |
| --- | --- | --- |
| 1 | `nest new`, `nest g resource projects` с in-memory массивом | Модули, контроллеры, сервисы, DTO |
| 2 | `ValidationPipe`, DTO с `class-validator` или Zod, `ParseUUIDPipe`, `NotFoundException` | Pipes, исключения |
| 3 | PostgreSQL в Docker Compose, Prisma, миграции, `PrismaService` | БД, lifecycle hooks |
| 4 | Пагинация, фильтры, сортировка по белому списку | Query DTO, cursor-пагинация |
| 5 | Регистрация и вход, JWT + refresh в cookie (или Better Auth) | Guards, Passport/JWT, cookies |
| 6 | Роли (`owner`, `member`), проверка участника проекта | `RolesGuard`, `Reflector`, IDOR |
| 7 | Единый формат ошибок и ответов, `@CurrentUser()` | Filters, interceptors, декораторы |
| 8 | Swagger с CLI-плагином, `ApiBearerAuth`, примеры | OpenAPI |
| 9 | Unit-тесты сервисов, e2e с Testcontainers | Тестирование |
| 10 | Вложения к задачам (S3/MinIO), письмо о назначении через BullMQ | Файлы, очереди |
| 11 | Dockerfile, health checks, pino-логи, GitHub Actions (lint, test, build) | Production |

## Пример: шаг 1 → 3

```ts
// шаг 1: in-memory
@Injectable()
export class ProjectsService {
  private projects: Project[] = [];
  create(dto: CreateProjectDto) {
    const project = { id: randomUUID(), ...dto, createdAt: new Date() };
    this.projects.push(project);
    return project;
  }
}

// шаг 3: тот же интерфейс сервиса, но Prisma
@Injectable()
export class ProjectsService {
  constructor(private readonly prisma: PrismaService) {}
  create(ownerId: string, dto: CreateProjectDto) {
    return this.prisma.project.create({ data: { ...dto, ownerId, members: { create: { userId: ownerId, role: 'OWNER' } } } });
  }
}
```

Контроллер и e2e-тесты почти не меняются — это наглядно показывает пользу слоёв.

## Минимальный набор эндпоинтов

```text
POST   /api/v1/auth/register | login | refresh | logout
GET    /api/v1/users/me
GET    /api/v1/projects?cursor=&limit=
POST   /api/v1/projects
GET    /api/v1/projects/:id
PATCH  /api/v1/projects/:id
DELETE /api/v1/projects/:id
POST   /api/v1/projects/:id/members
GET    /api/v1/projects/:id/tasks?status=&assignee=&sort=
POST   /api/v1/projects/:id/tasks
PATCH  /api/v1/tasks/:id
POST   /api/v1/tasks/:id/attachments
GET    /health/live, /health/ready
```

## Что рассказать на собеседовании

- Почему так разделены модули и где граница транзакции при создании проекта с участником.
- Как устроена авторизация: аутентификация в guard, роль участника, проверка доступа к задаче.
- Как защищено от N+1 и как сделана пагинация.
- Как устроены тесты и что проверяет e2e.
- Что сделано для продакшена и что бы улучшили дальше.

## Частые ошибки

- Подключить всё сразу и не понять, как части связаны.
- Писать только «счастливый путь» без ошибок, прав и валидации.
- Нет тестов — проект трудно менять и нечего показать.
- Секреты в репозитории.

## Что важно помнить

- Учиться слоями: ресурс → валидация → БД → auth → документация → тесты → прод.
- Предметная область со связями и ролями раскрывает больше тем.
- Проект — основа для рассказа на собеседовании.

## Мини-шпаргалка

- In-memory → Prisma без изменения контроллеров.
- Auth + роли + проверка владельца.
- Swagger, unit + e2e (Testcontainers).
- Docker, health, логи, CI.
