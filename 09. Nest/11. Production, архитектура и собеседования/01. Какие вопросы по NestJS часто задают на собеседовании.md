# Какие вопросы по NestJS часто задают на собеседовании

> [!NOTE]
> На собеседовании по NestJS обычно проверяют четыре блока. **Архитектура и DI**: модули, провайдеры, `imports`/`exports`, токены, custom providers, dynamic и global modules, scopes, циклические зависимости. **Конвейер запроса**: порядок middleware → guards → interceptors → pipes → handler → filters, разница между ними и где что применять. **Прикладные задачи**: валидация DTO, обработка ошибок, аутентификация (JWT, сессии, Passport/Better Auth), авторизация (роли, владелец ресурса), работа с БД и транзакциями, конфигурация, тестирование. **Production**: логирование, мониторинг и health checks, graceful shutdown, масштабирование (в том числе WebSocket), очереди, кеш, безопасность. Ниже — карта типичных вопросов со ссылками на уроки раздела для повторения.

## Как отвечать

- Определение → пример кода → подводный камень («а если guard глобальный, то…»).
- Связывайте с практикой: «в проекте у нас было так…».
- Для архитектурных вопросов называйте компромиссы, а не «правильный ответ».

## Частые ошибки

- Путать порядок guards, interceptors и pipes.
- Не знать, почему импорт модуля не даёт доступ к его неэкспортированным провайдерам.
- Отвечать про JWT без refresh, хранения и отзыва.
- Не уметь объяснить, где граница транзакции.

## Что важно помнить

- Блоки: DI, конвейер запроса, прикладные задачи, production.
- Самые частые темы: lifecycle, DI-ошибки, валидация, auth, транзакции, тесты.
- Ответ = определение + код + нюанс.

## Мини-шпаргалка

- Middleware → Guards → Interceptors → Pipes → Handler → Filters.
- `providers` + `exports` + `imports`.
- 401 ≠ 403.
- `whitelist`, `transform`.
- `enableShutdownHooks()`.
