# Как описывать модели Prisma

> [!NOTE]
> Модель Prisma описывает таблицу: каждое поле имеет **имя**, **тип** (`String`, `Int`, `BigInt`, `Boolean`, `DateTime`, `Decimal`, `Float`, `Json`, `Bytes`, enum или другая модель для связи) и **модификатор**: без него поле обязательное (`NOT NULL`), `?` — необязательное (nullable), `[]` — список (связь «многие» или scalar list в PostgreSQL). Атрибуты задают первичный ключ (`@id`), значения по умолчанию (`@default`), уникальность (`@unique`, `@@unique`), индексы (`@@index`), нативные типы СУБД (`@db.*`) и имена в БД (`@map`). Хорошая модель отражает правила предметной области на уровне базы: обязательность, уникальность, точные типы (деньги — `Decimal`, моменты времени — `DateTime @db.Timestamptz`), индексы под реальные запросы. Подробно о выборе типов — [типы данных Prisma](<14. Какие типы данных поддерживает Prisma.md>).

## Вопрос

Как правильно описывать модели в Prisma?

## Пример

```prisma
model Product {
  id          String        @id @default(uuid(7)) @db.Uuid
  sku         String        @unique @db.VarChar(64)
  title       String        @db.VarChar(200)
  description String?       @db.Text
  price       Decimal       @db.Decimal(12, 2)
  stock       Int           @default(0)
  status      ProductStatus @default(DRAFT)
  attributes  Json          @default("{}")
  tags        String[]      @default([])
  categoryId  String        @map("category_id") @db.Uuid
  deletedAt   DateTime?     @map("deleted_at") @db.Timestamptz(3)
  createdAt   DateTime      @default(now()) @map("created_at") @db.Timestamptz(3)
  updatedAt   DateTime      @updatedAt @map("updated_at") @db.Timestamptz(3)

  category Category @relation(fields: [categoryId], references: [id])

  @@index([categoryId, status])
  @@index([title(ops: raw("gin_trgm_ops"))], type: Gin)   // поиск по подстроке (pg_trgm)
  @@map("products")
}

enum ProductStatus {
  DRAFT
  PUBLISHED
  ARCHIVED
}
```

## Модификаторы

| Запись | В БД | В TypeScript |
| --- | --- | --- |
| `title String` | `NOT NULL` | `string` |
| `description String?` | nullable | `string \| null` |
| `tags String[]` | `text[]` | `string[]` |
| `orders Order[]` | — (обратная сторона связи) | `Order[]` при `include` |

## Значения по умолчанию

```prisma
id        String   @id @default(uuid(7))     // UUIDv7, генерирует Prisma
id        Int      @id @default(autoincrement())
code      String   @default(cuid())
createdAt DateTime @default(now())
publicId  String   @default(dbgenerated("gen_random_uuid()")) @db.Uuid   // генерирует БД
```

`uuid()`/`cuid()` вычисляет Prisma Client, `dbgenerated(...)` — база (значение появится и при вставке не через Prisma).

## Составные ключи и уникальность

```prisma
model ProjectMember {
  projectId String @db.Uuid
  userId    String @db.Uuid
  role      MemberRole @default(MEMBER)

  @@id([projectId, userId])
  @@index([userId])
}

model Slug {
  tenantId String
  value    String

  @@unique([tenantId, value], name: "tenant_slug")
}
// prisma.slug.findUnique({ where: { tenant_slug: { tenantId, value } } })
```

## Мягкое удаление

```prisma
deletedAt DateTime? @db.Timestamptz(3)
```

Частичные уникальные индексы (`WHERE deleted_at IS NULL`) Prisma-схема напрямую не описывает — их добавляют вручную в SQL-миграцию.

## Чек-лист модели

- [ ] PK: `uuid(7)` или `autoincrement` — осознанно ([выбор PK](<../../10. SQL/07. Схема данных, DDL и constraints/09. Как выбрать первичный ключ - identity, UUID и естественные ключи.md>)).
- [ ] Обязательные поля без `?`.
- [ ] Бизнес-уникальность — `@unique`/`@@unique`.
- [ ] Деньги — `Decimal`, время — `DateTime @db.Timestamptz`.
- [ ] Индексы на FK и полях фильтрации/сортировки.
- [ ] `@map`/`@@map` для `snake_case` в БД.
- [ ] `createdAt`/`updatedAt`.

## Частые ошибки

- `Float` для денег.
- Всё nullable «на всякий случай».
- Нет индекса на внешнем ключе.
- `Json` вместо нормальных полей для того, по чему фильтруют.
- Переименовать поле без `@map` — миграция удалит данные.

## Что важно помнить

- Поле = имя + тип + модификатор (`?`, `[]`) + атрибуты.
- Ограничения и индексы — в схеме, а не только в коде.
- Типы выбираются по смыслу данных.

## Мини-шпаргалка

- `field Type?`, `field Type[]`.
- `@id`, `@default`, `@unique`, `@updatedAt`, `@map`, `@db.*`.
- `@@id`, `@@unique`, `@@index`, `@@map`.
- `enum` для небольших стабильных наборов.
