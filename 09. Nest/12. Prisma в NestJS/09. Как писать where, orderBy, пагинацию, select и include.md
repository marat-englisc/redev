# Как писать where, orderBy, пагинацию, select и include

> [!NOTE]
> Запрос Prisma — это объект аргументов. **`where`** фильтрует: равенство, операторы `equals`, `not`, `in`, `notIn`, `lt`/`lte`/`gt`/`gte`, строковые `contains`/`startsWith`/`endsWith` с `mode: 'insensitive'`, логические `AND`/`OR`/`NOT`, фильтры по связям. **`orderBy`** — объект или массив объектов (`[{ createdAt: 'desc' }, { id: 'desc' }]`), включая `nulls: 'last'` и сортировку по полю связи или `_count`. **Пагинация**: offset — `skip` + `take`; cursor — `cursor: { id }` + `skip: 1` + `take` (быстро на больших данных, требует уникального и стабильного порядка). **`select`** выбирает конкретные поля (и вложенные связи), **`include`** добавляет связи ко всем полям модели; на одном уровне их не смешивают. От `select`/`include` зависит **тип результата**, поэтому их выбор влияет и на безопасность (не отдать `passwordHash`), и на производительность (не тащить лишнее).

## Вопрос

Как фильтровать, сортировать, пагинировать и выбирать поля в Prisma?

## where

```ts
const where: Prisma.ProductWhereInput = {
  status: 'PUBLISHED',
  price: { gte: 100, lte: 5_000 },
  title: { contains: q, mode: 'insensitive' },          // ILIKE '%q%' — нужен trigram-индекс на больших таблицах
  categoryId: { in: categoryIds },
  deletedAt: null,
  OR: [{ stock: { gt: 0 } }, { allowBackorder: true }],
  NOT: { tags: { has: 'hidden' } },                     // scalar list
};
```

Условия объекта объединяются через `AND`. Динамические фильтры удобно собирать из необязательных частей:

```ts
const where: Prisma.OrderWhereInput = {
  userId,
  ...(q.status && { status: q.status }),
  ...(q.from && { createdAt: { gte: q.from } }),
};
```

## orderBy

```ts
orderBy: [{ price: 'asc' }, { id: 'asc' }]                    // tie-breaker
orderBy: { rating: { sort: 'desc', nulls: 'last' } }
orderBy: { category: { name: 'asc' } }                         // по полю связи
orderBy: { reviews: { _count: 'desc' } }                       // по количеству связанных
```

Поле сортировки из query — только из белого списка.

## Offset-пагинация

```ts
const [items, total] = await this.prisma.$transaction([
  this.prisma.product.findMany({ where, orderBy: [{ createdAt: 'desc' }, { id: 'desc' }], skip: (page - 1) * limit, take: limit }),
  this.prisma.product.count({ where }),
]);
```

## Cursor-пагинация

```ts
const rows = await this.prisma.post.findMany({
  where: { published: true },
  orderBy: [{ createdAt: 'desc' }, { id: 'desc' }],
  take: limit + 1,
  ...(cursor && { cursor: { id: cursor }, skip: 1 }),   // skip: 1 — не повторять запись-курсор
});
const hasMore = rows.length > limit;
const items = rows.slice(0, limit);
const nextCursor = hasMore ? items.at(-1)!.id : null;
```

Для стабильности курсор должен соответствовать сортировке; при сортировке по `createdAt` надёжнее кодировать в курсор пару `(createdAt, id)` и фильтровать через `where`, как в [keyset-пагинации](<../../10. SQL/11. Практика Backend и собеседования/02. Как делать пагинацию в SQL.md>).

## select и include

```ts
// select — только нужные поля, включая вложенные
const posts = await this.prisma.post.findMany({
  select: {
    id: true,
    title: true,
    author: { select: { id: true, name: true } },
    _count: { select: { comments: true } },
  },
});
// тип: { id; title; author: { id; name }; _count: { comments } }[]

// include — все поля модели + связи
const post = await this.prisma.post.findUnique({
  where: { id },
  include: { author: true, tags: true },
});
```

| | `select` | `include` |
| --- | --- | --- |
| Поля модели | Только перечисленные | Все |
| Связи | Перечисленные (с вложенным `select`) | Перечисленные |
| Безопасность | Явно, ничего лишнего | Легко отдать секретное поле |
| На одном уровне | Нельзя вместе с `include` | Нельзя вместе с `select` |

## omit

```ts
const users = await this.prisma.user.findMany({ omit: { passwordHash: true } });

// или глобально
new PrismaClient({ adapter, omit: { user: { passwordHash: true } } });
```

## Частые ошибки

- `include` целой связи на списке — тяжёлые ответы и запросы.
- `contains` с `mode: 'insensitive'` на миллионах строк без индекса.
- `skip` на глубоких страницах — медленно; используйте cursor.
- Нет tie-breaker в `orderBy`.
- Смешать `select` и `include` на одном уровне — ошибка.

## Что важно помнить

- `where` — фильтры и логика, `orderBy` — массив с tie-breaker.
- Offset: `skip/take`; cursor: `cursor + skip: 1 + take`.
- `select` для ответов API, `include` — когда нужны все поля; `omit` — исключить поля.

## Мини-шпаргалка

- `{ contains, mode: 'insensitive' }`, `{ in: [...] }`, `{ gte, lte }`, `OR`, `NOT`.
- `orderBy: [{ a: 'desc' }, { id: 'desc' }]`.
- `skip/take` или `cursor/skip: 1/take: n + 1`.
- `select: { rel: { select: {...} }, _count: { select: { rel: true } } }`.
