# Что такое Prisma и зачем она в NestJS

> [!NOTE]
> **Prisma ORM** — schema-first ORM для TypeScript: модели описываются в `schema.prisma`, из неё **генерируется типизированный клиент** (`prisma.user.findMany(...)` с автодополнением и проверкой типов полей, фильтров и результата с учётом `select`/`include`), а **Prisma Migrate** превращает изменения схемы в SQL-миграции. В NestJS клиент оформляют провайдером `PrismaService` в `PrismaModule`, и сервисы/репозитории получают его через DI. Сильные стороны: отличный DX и типобезопасность, вложенные запросы и записи по связям, понятные миграции. Ограничения: сложные SQL (оконные функции, CTE, `LATERAL`) пишут через `$queryRaw` или TypedSQL; ORM не отменяет понимания индексов, N+1 и транзакций. Актуальная мажорная версия — **Prisma 7**: новый генератор `prisma-client` с обязательным `output`, обязательный **driver adapter** (`@prisma/adapter-pg` для PostgreSQL), настройки подключения в `prisma.config.ts`, `.env` больше не загружается автоматически.

## Вопрос

Что такое Prisma и зачем её использовать в NestJS?

## Место в архитектуре

```text
HTTP → Controller → Service → Repository (опционально) → PrismaService (PrismaClient + adapter) → PostgreSQL
```

## Как выглядит работа

```prisma
model User {
  id    String @id @default(uuid(7)) @db.Uuid
  email String @unique
  name  String
  posts Post[]
}

model Post {
  id       String @id @default(uuid(7)) @db.Uuid
  title    String
  authorId String @db.Uuid
  author   User   @relation(fields: [authorId], references: [id])
}
```

```ts
const users = await this.prisma.user.findMany({
  where: { posts: { some: {} } },
  select: { id: true, email: true, _count: { select: { posts: true } } },
  orderBy: { email: 'asc' },
  take: 20,
});
// тип: { id: string; email: string; _count: { posts: number } }[]
```

## Что даёт Prisma

| Возможность | Пример |
| --- | --- |
| Типизированный клиент | Ошибка компиляции при опечатке в поле или неверном типе фильтра |
| Запросы по связям | `include`, `select`, фильтры `some`/`none`/`every` |
| Вложенные записи | Создать заказ с позициями одним вызовом |
| Миграции | `prisma migrate dev` / `deploy` |
| Транзакции | `$transaction` (массив или interactive) |
| Raw SQL | `$queryRaw` с параметрами, TypedSQL |
| Расширения | `$extends` для своих методов, мягкого удаления, логирования |

## Prisma и TypeORM

| | Prisma | TypeORM |
| --- | --- | --- |
| Источник схемы | `schema.prisma` | Entity-классы с декораторами |
| Типы результатов | Генерируются точно под `select`/`include` | Тип entity целиком |
| Модель данных | Plain-объекты | Экземпляры классов |
| Интеграция с Nest | Рецепт + свой `PrismaService` | Официальный `@nestjs/typeorm` |
| Миграции | Из diff схемы | Генерация из entity / вручную |

## Prisma не заменяет SQL-мышление

- Индексы описываются в схеме (`@@index`) под реальные запросы.
- Большие `include` и связи в цикле — N+1 и тяжёлые ответы.
- Транзакции, блокировки и lost update — как в обычном SQL.
- Для отчётов и сложной аналитики — raw SQL.

## Частые ошибки

- `new PrismaClient()` в каждом сервисе.
- Забыть `prisma generate` после изменения схемы — типы устарели.
- `prisma db push` в проде вместо миграций.
- Возвращать модели целиком вместе с `passwordHash`.

## Что важно помнить

- Prisma = схема + сгенерированный типизированный клиент + миграции.
- В Nest — провайдер `PrismaService` в `PrismaModule`.
- Prisma 7: `prisma-client`, driver adapter, `prisma.config.ts`.

## Мини-шпаргалка

- `schema.prisma` → `prisma generate` → типизированный клиент.
- `prisma migrate dev` / `prisma migrate deploy`.
- `select`/`include` определяют тип результата.
- Сложный SQL — `$queryRaw`.
