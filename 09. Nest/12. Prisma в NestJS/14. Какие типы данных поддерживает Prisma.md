# Какие типы данных поддерживает Prisma

> [!NOTE]
> Prisma использует собственные **скалярные типы**, которые отображаются на типы конкретной СУБД и на типы TypeScript: `String` → `string`, `Boolean` → `boolean`, `Int` → `number` (32 бита), `BigInt` → `bigint`, `Float` → `number`, `Decimal` → объект `Prisma.Decimal` (decimal.js), `DateTime` → `Date`, `Json` → `JsonValue`, `Bytes` → `Uint8Array`. Плюс **enum**, **списки** (`String[]` в PostgreSQL), **relation-поля** (не столбцы) и **нативные типы** через `@db.*` (`@db.VarChar(200)`, `@db.Text`, `@db.Uuid`, `@db.Timestamptz(3)`, `@db.Decimal(12, 2)`, `@db.JsonB`), а для неподдерживаемых — `Unsupported("...")`. Выбор типа — это решение о данных: деньги — `Decimal` (не `Float`), моменты времени — `DateTime @db.Timestamptz`, идентификаторы — `String @db.Uuid` или `Int/BigInt autoincrement`, гибкие метаданные — `Json`. На границе API важно помнить о сериализации: `BigInt` не сериализуется `JSON.stringify` (ошибка), `Decimal` сериализуется в строку, `DateTime` — в ISO-строку.

## Вопрос

Какие типы данных поддерживает Prisma и как выбирать их для полей?

## Основные типы

| Prisma | PostgreSQL по умолчанию | TypeScript | Где использовать |
| --- | --- | --- | --- |
| `String` | `text` | `string` | Текст, email, slug |
| `String @db.Uuid` | `uuid` | `string` | Идентификаторы |
| `Boolean` | `boolean` | `boolean` | Флаги |
| `Int` | `integer` | `number` | Счётчики, позиции |
| `BigInt` | `bigint` | `bigint` | Большие id, внешние идентификаторы |
| `Float` | `double precision` | `number` | Координаты, рейтинги |
| `Decimal` | `decimal(65,30)` | `Prisma.Decimal` | Деньги, проценты (`@db.Decimal(12, 2)`) |
| `DateTime` | `timestamp(3)` | `Date` | Время (`@db.Timestamptz(3)`) |
| `Json` | `jsonb` | `Prisma.JsonValue` | Метаданные, настройки |
| `Bytes` | `bytea` | `Uint8Array` | Бинарные данные |
| `Unsupported("geography")` | как указано | — (raw SQL) | PostGIS и др. |

## Строки

```prisma
title   String  @db.VarChar(200)       // ограничение длины на уровне БД
content String  @db.Text
email   String  @unique @db.Citext      // регистронезависимая уникальность (расширение citext)
```

## Числа и деньги

```prisma
price    Decimal @db.Decimal(12, 2)
rating   Float
views    BigInt  @default(0)
```

```ts
import { Prisma } from '../generated/prisma/client';

await prisma.product.create({ data: { price: new Prisma.Decimal('199.90'), /* ... */ } });

const p = await prisma.product.findUniqueOrThrow({ where: { id } });
p.price.toFixed(2);        // '199.90'
p.price.add(10);           // арифметика без ошибок округления
```

```ts
// BigInt в ответе API
JSON.stringify({ views: 10n });   // TypeError: Do not know how to serialize a BigInt
// → преобразовать в строку или number в сериализаторе / select
```

## Дата и время

```prisma
createdAt DateTime @default(now()) @db.Timestamptz(3)
updatedAt DateTime @updatedAt @db.Timestamptz(3)
birthday  DateTime @db.Date        // только дата
```

Без `@db.Timestamptz` в PostgreSQL создаётся `timestamp without time zone`; Prisma пишет и читает время в UTC, но другие клиенты БД могут интерпретировать такие значения иначе.

## Json

```prisma
settings Json @default("{}")
```

```ts
await prisma.user.update({ where: { id }, data: { settings: { theme: 'dark', locale: 'ru' } } });

// фильтр по пути (PostgreSQL)
await prisma.user.findMany({ where: { settings: { path: ['theme'], equals: 'dark' } } });

// NULL в Json-поле
data: { settings: Prisma.DbNull }     // SQL NULL
data: { settings: Prisma.JsonNull }   // JSON-значение null
```

Если по полю часто фильтруют, сортируют или строят связи — выносите его в обычный столбец ([JSON в SQL](<../../10. SQL/07. Схема данных, DDL и constraints/06. Когда использовать JSON в SQL базе.md>)).

## Enum

```prisma
enum OrderStatus {
  PENDING
  PAID
  CANCELLED
  @@map("order_status")
}
```

```ts
import { OrderStatus } from '../generated/prisma/client';
await prisma.order.findMany({ where: { status: OrderStatus.PAID } });
```

Enum хорош для небольших стабильных наборов. Если значения редактирует админка, у них есть подписи и порядок — справочная таблица.

## Списки

```prisma
tags String[] @default([])
```

```ts
where: { tags: { has: 'sql' } }          // содержит
where: { tags: { hasSome: ['a', 'b'] } }
data:  { tags: { push: 'new' } }
```

Для тегов с поиском, статистикой и уникальностью лучше many-to-many с моделью `Tag`.

## Optional и undefined

```prisma
nickname String?    // nullable столбец
```

```ts
data: { nickname: undefined }   // не менять
data: { nickname: null }        // записать NULL
```

`String?` в схеме — «может быть NULL в базе», а не «необязательно в DTO»; это разные решения.

## Частые ошибки

- `Float` для денег.
- `DateTime` без `@db.Timestamptz` в PostgreSQL.
- `BigInt` прямо в JSON-ответе.
- `Json` для данных, по которым нужны связи и фильтры.
- `String` без ограничения длины для полей с бизнес-лимитом.

## Что важно помнить

- Скалярные типы Prisma + `@db.*` для точного типа СУБД.
- Деньги — `Decimal`, время — `Timestamptz`, id — `Uuid`/`BigInt`.
- Учитывайте сериализацию `BigInt`, `Decimal`, `DateTime` на границе API.

## Мини-шпаргалка

- `String @db.VarChar(n)`, `@db.Text`, `@db.Uuid`.
- `Decimal @db.Decimal(12, 2)` → `Prisma.Decimal`.
- `DateTime @db.Timestamptz(3)`.
- `Json` + `Prisma.DbNull` / `Prisma.JsonNull`.
- `String[]` + `has`, `hasSome`, `push`.
