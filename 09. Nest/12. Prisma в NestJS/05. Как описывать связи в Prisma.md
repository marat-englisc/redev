# Как описывать связи в Prisma

> [!NOTE]
> Связь в Prisma описывается двумя видами полей: **scalar-полем внешнего ключа** (`authorId String`) — это реальный столбец в БД, и **relation-полем** (`author User @relation(fields: [authorId], references: [id])`) — оно существует только на уровне Prisma Client и позволяет делать `include`, вложенные записи и фильтры по связям. Обратная сторона связи (`posts Post[]` в модели `User`) столбцом не является. Виды: **one-to-many** (FK на стороне «многих»), **one-to-one** (FK с `@unique`), **many-to-many** — **неявная** (Prisma сама создаёт таблицу `_PostToTag`) или **явная** через модель-связку (рекомендуется, если у связи есть атрибуты: роль, дата, порядок). `onDelete`/`onUpdate` задают ссылочные действия (`Cascade`, `Restrict`, `SetNull`, `NoAction`). Для PostgreSQL Prisma **не создаёт индексы на FK** автоматически — их добавляют через `@@index`.

## Вопрос

Как описывать связи между моделями в Prisma?

## One-to-many

```prisma
model User {
  id    String @id @default(uuid(7)) @db.Uuid
  posts Post[]                                   // обратная сторона, не столбец
}

model Post {
  id       String @id @default(uuid(7)) @db.Uuid
  authorId String @db.Uuid                         // столбец FK
  author   User   @relation(fields: [authorId], references: [id], onDelete: Cascade)

  @@index([authorId])
}
```

## One-to-one

```prisma
model User {
  id      String   @id @default(uuid(7)) @db.Uuid
  profile Profile?
}

model Profile {
  userId String @id @db.Uuid                       // PK = FK → не больше одного профиля
  bio    String?
  user   User   @relation(fields: [userId], references: [id], onDelete: Cascade)
}
```

## Many-to-many: неявная

```prisma
model Post {
  id   String @id @default(uuid(7)) @db.Uuid
  tags Tag[]
}

model Tag {
  id    String @id @default(uuid(7)) @db.Uuid
  name  String @unique
  posts Post[]
}
```

```ts
await prisma.post.update({ where: { id }, data: { tags: { connect: [{ name: 'sql' }] } } });
```

Удобно, но нельзя добавить атрибуты связи и сложнее управлять таблицей-связкой.

## Many-to-many: явная

```prisma
model Project {
  id      String          @id @default(uuid(7)) @db.Uuid
  members ProjectMember[]
}

model ProjectMember {
  projectId String     @db.Uuid
  userId    String     @db.Uuid
  role      MemberRole @default(MEMBER)
  joinedAt  DateTime   @default(now()) @db.Timestamptz(3)

  project Project @relation(fields: [projectId], references: [id], onDelete: Cascade)
  user    User    @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@id([projectId, userId])
  @@index([userId])
}
```

```ts
const projects = await prisma.project.findMany({
  where: { members: { some: { userId, role: { in: ['OWNER', 'ADMIN'] } } } },
  include: { members: { include: { user: { select: { id: true, name: true } } } } },
});
```

## Self-relation

```prisma
model Category {
  id       String     @id @default(uuid(7)) @db.Uuid
  parentId String?    @db.Uuid
  parent   Category?  @relation("CategoryTree", fields: [parentId], references: [id])
  children Category[] @relation("CategoryTree")

  @@index([parentId])
}
```

Для связей, которые иначе неоднозначны (две связи между одними моделями), указывают имя `@relation("Name")`.

## Ссылочные действия

| `onDelete` | Поведение при удалении родителя |
| --- | --- |
| `Restrict` / `NoAction` | Запрет, если есть дети |
| `Cascade` | Удалить детей |
| `SetNull` | Обнулить FK (поле должно быть `?`) |
| `SetDefault` | Значение по умолчанию |

По умолчанию для обязательной связи — `Restrict`, для необязательной — `SetNull`.

## Частые ошибки

- Нет `@@index` на FK — медленные JOIN и удаления родителей.
- Неявная many-to-many, когда понадобилась роль/дата связи — болезненная миграция.
- `Cascade` на критичных данных (удаление пользователя стирает платежи).
- Путать relation-поле со столбцом (`author` нельзя записать строкой — только `authorId` или `connect`).

## Что важно помнить

- FK-столбец + relation-поле; обратная сторона — без столбца.
- 1:1 — FK с `@unique`/`@id`; M:N — лучше явная модель-связка.
- Индексы на FK добавляйте сами.

## Мини-шпаргалка

- `field Model @relation(fields: [fk], references: [id], onDelete: X)`.
- `items Model[]` — обратная сторона.
- `@@id([a, b])` в модели-связке.
- `@relation("Name")` для неоднозначных связей.
