# Как писать сложные запросы по связям Prisma

> [!NOTE]
> Prisma позволяет фильтровать, сортировать и агрегировать **через связи** без ручных JOIN. Для списковых связей (one-to-many, many-to-many) есть фильтры **`some`** (есть хотя бы одна подходящая связанная запись — аналог `EXISTS`), **`none`** (нет ни одной — `NOT EXISTS`) и **`every`** (все связанные удовлетворяют условию; пустой набор тоже подходит!); для одиночных — **`is`** / **`isNot`** или вложенный объект. Внутри `include`/`select` у связей можно задать свои `where`, `orderBy`, `take` — например, «последние 3 комментария каждого поста». **`_count`** считает связанные записи (в том числе с фильтром), `orderBy` умеет сортировать по полю связи и по количеству связанных. Под капотом Prisma строит либо один запрос с JOIN/LATERAL (`relationLoadStrategy: 'join'`), либо несколько запросов по `IN` (`'query'`) — стратегию можно выбрать явно для каждого запроса. Для того, что не выражается API (оконные функции, сложные агрегаты), — `$queryRaw` или TypedSQL.

## Вопрос

Как писать сложные запросы по связям в Prisma?

## some, none, every

```ts
// пользователи, у которых есть оплаченный заказ за 30 дней
await prisma.user.findMany({
  where: { orders: { some: { status: 'PAID', createdAt: { gte: daysAgo(30) } } } },
});

// пользователи без заказов
await prisma.user.findMany({ where: { orders: { none: {} } } });

// проекты, где все задачи закрыты (и проекты без задач тоже!)
await prisma.project.findMany({ where: { tasks: { every: { status: 'DONE' } } } });

// только проекты с задачами, и все закрыты
await prisma.project.findMany({
  where: { tasks: { some: {}, every: { status: 'DONE' } } },
});
```

## Фильтр по одиночной связи

```ts
await prisma.post.findMany({
  where: { author: { is: { email: { endsWith: '@company.com' } } } },   // или author: { email: ... }
});

await prisma.order.findMany({ where: { coupon: { isNot: null } } });
```

## Вложенные выборки с ограничениями

```ts
const posts = await prisma.post.findMany({
  where: { published: true },
  orderBy: { createdAt: 'desc' },
  take: 20,
  select: {
    id: true,
    title: true,
    author: { select: { id: true, name: true } },
    comments: {
      where: { hidden: false },
      orderBy: { createdAt: 'desc' },
      take: 3,                                     // топ-3 комментария каждого поста
      select: { id: true, body: true, createdAt: true },
    },
    _count: { select: { comments: { where: { hidden: false } } } },
  },
});
```

## Сортировка по связям

```ts
await prisma.product.findMany({ orderBy: { reviews: { _count: 'desc' } }, take: 10 });   // самые обсуждаемые
await prisma.post.findMany({ orderBy: { author: { name: 'asc' } } });
```

## Агрегаты и группировка

```ts
const stats = await prisma.order.groupBy({
  by: ['status'],
  where: { createdAt: { gte: startOfMonth } },
  _count: { _all: true },
  _sum: { total: true },
  having: { total: { _sum: { gt: 0 } } },
  orderBy: { _sum: { total: 'desc' } },
});
```

## Стратегия загрузки связей

```ts
await prisma.user.findMany({
  relationLoadStrategy: 'join',      // один SQL-запрос (LATERAL JOIN + JSON)
  include: { posts: true },
});

await prisma.user.findMany({
  relationLoadStrategy: 'query',     // отдельный запрос для связей по IN (...)
  include: { posts: true },
});
```

## Когда API не хватает

```ts
// топ-3 товара по выручке в каждой категории — оконная функция
const rows = await prisma.$queryRaw<{ categoryId: string; productId: string; revenue: number }[]>`
  SELECT category_id AS "categoryId", product_id AS "productId", revenue
  FROM (
    SELECT p.category_id, oi.product_id, SUM(oi.qty * oi.unit_price) AS revenue,
           ROW_NUMBER() OVER (PARTITION BY p.category_id ORDER BY SUM(oi.qty * oi.unit_price) DESC) AS rn
    FROM order_items oi JOIN products p ON p.id = oi.product_id
    WHERE oi.created_at >= ${from}
    GROUP BY p.category_id, oi.product_id
  ) t
  WHERE rn <= 3`;
```

Значения передаются через шаблонные плейсхолдеры — это параметризованный запрос. TypedSQL (`prisma/sql/*.sql` + `$queryRawTyped`) даёт типы результата для raw-запросов.

## Частые ошибки

- `every` без `some` — пустые связи проходят фильтр.
- `include` больших связей без `take` в списках.
- Ожидать, что `_count` с фильтром посчитает без индекса быстро.
- Склеивать SQL строками в `$queryRawUnsafe`.

## Что важно помнить

- `some` ≈ `EXISTS`, `none` ≈ `NOT EXISTS`, `every` включает пустые наборы.
- У связей в `select`/`include` есть свои `where`/`orderBy`/`take`.
- Сложная аналитика — `$queryRaw`/TypedSQL.

## Мини-шпаргалка

- `where: { rel: { some | none | every: {...} } }`.
- `where: { rel: { is | isNot: {...} } }`.
- `_count: { select: { rel: { where } } }`.
- `orderBy: { rel: { _count: 'desc' } }`.
- `relationLoadStrategy: 'join' | 'query'`.
