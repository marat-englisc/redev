# Какие методы Prisma Client нужно знать

> [!NOTE]
> Prisma Client генерирует для каждой модели свойство в lower camel case (`UserProfile` → `prisma.userProfile`) с одинаковым набором методов. **Чтение**: `findUnique` / `findUniqueOrThrow` (по уникальному полю или составному ключу), `findFirst` / `findFirstOrThrow` (первая запись по фильтру — с `orderBy`), `findMany`. **Создание**: `create`, `createMany` (возвращает `{ count }`, `skipDuplicates`), `createManyAndReturn`. **Изменение**: `update` (одна запись, P2025 если нет), `updateMany` (возвращает `{ count }`), `updateManyAndReturn`, `upsert`. **Удаление**: `delete`, `deleteMany`. **Агрегаты**: `count`, `aggregate` (`_sum`, `_avg`, `_min`, `_max`, `_count` без группировки), `groupBy` (с `having`). **Клиентские методы**: `$transaction`, `$queryRaw` / `$executeRaw` (параметризованный SQL), `$queryRawTyped` (TypedSQL), `$extends` (расширения), `$connect` / `$disconnect`. Важно выбирать метод по сценарию: уникальность, нужен ли результат, нужна ли атомарность.

## Вопрос

Какие методы Prisma Client нужно знать и когда какой использовать?

## Чтение

| Метод | Когда | Возвращает |
| --- | --- | --- |
| `findUnique` | По `@id`, `@unique`, `@@unique`, `@@id` | Объект или `null` |
| `findUniqueOrThrow` | Отсутствие — ошибка (P2025) | Объект |
| `findFirst` | Первая по неуникальному фильтру, с `orderBy` | Объект или `null` |
| `findFirstOrThrow` | То же, но отсутствие — ошибка | Объект |
| `findMany` | Списки, фильтры, пагинация | Массив |

```ts
// составной ключ: имя генерируется как поле1_поле2 (или name из @@unique)
await prisma.projectMember.findUnique({ where: { projectId_userId: { projectId, userId } } });

// последний опубликованный пост автора
await prisma.post.findFirst({ where: { authorId, published: true }, orderBy: { createdAt: 'desc' } });
```

## Создание

```ts
await prisma.user.create({ data: { email, name }, select: { id: true } });
await prisma.tag.createMany({ data: tags, skipDuplicates: true });              // { count }
await prisma.tag.createManyAndReturn({ data: tags, select: { id: true, name: true } });
```

## Изменение

```ts
await prisma.user.update({ where: { id }, data: { name } });                                   // P2025, если нет
await prisma.post.updateMany({ where: { authorId, published: false }, data: { published: true } }); // { count }
await prisma.post.updateManyAndReturn({ where: { authorId }, data: { archived: true }, select: { id: true } });
await prisma.counter.update({ where: { key }, data: { value: { increment: 1 } } });            // атомарно

await prisma.userSettings.upsert({
  where: { userId },
  create: { userId, theme: 'dark' },
  update: { theme: 'dark' },
});
```

## Удаление

```ts
await prisma.user.delete({ where: { id } });                               // P2025, если нет
await prisma.session.deleteMany({ where: { expiresAt: { lt: new Date() } } });   // { count }
```

## Агрегаты

```ts
await prisma.user.count({ where: { role: 'ADMIN' } });

await prisma.order.aggregate({
  where: { status: 'PAID' },
  _sum: { total: true },
  _avg: { total: true },
  _max: { createdAt: true },
  _count: { _all: true },
});

await prisma.order.groupBy({
  by: ['status'],
  _count: { _all: true },
  _sum: { total: true },
  having: { total: { _sum: { gt: 1000 } } },
  orderBy: { _sum: { total: 'desc' } },
});
```

`aggregate` — агрегаты по всей выборке, `groupBy` — аналог SQL `GROUP BY` (+ `HAVING`).

## Транзакции

```ts
await prisma.$transaction([prisma.a.update(...), prisma.b.update(...)]);   // batch
await prisma.$transaction(async (tx) => { ... }, { timeout: 5_000 });       // interactive
```

## Raw SQL

```ts
const rows = await prisma.$queryRaw<{ id: string; total: Prisma.Decimal }[]>`
  SELECT id, total FROM orders WHERE user_id = ${userId}::uuid AND created_at >= ${from}`;

const affected = await prisma.$executeRaw`UPDATE sessions SET revoked = true WHERE expires_at < now()`;

// динамическая часть — только Prisma.sql / Prisma.join, без склейки строк
const ids = Prisma.join(idList);
await prisma.$queryRaw`SELECT * FROM products WHERE id IN (${ids})`;
```

`$queryRawUnsafe` с подстановкой строк — источник SQL-инъекций.

## Расширения

```ts
const xprisma = prisma.$extends({
  model: {
    user: {
      findByEmail(email: string) {
        return prisma.user.findUnique({ where: { email: email.toLowerCase() } });
      },
    },
  },
  result: {
    user: { displayName: { needs: { name: true, email: true }, compute: (u) => u.name || u.email } },
  },
});
```

`$extends` заменил удалённый в Prisma 7 `$use` (middleware).

## Как выбрать метод

| Задача | Метод |
| --- | --- |
| Получить по id / email | `findUnique` |
| Последняя запись по условию | `findFirst` + `orderBy` |
| Страница списка | `findMany` + `skip/take` или `cursor` |
| Создать одну / много | `create` / `createMany` |
| Изменить одну / по фильтру | `update` / `updateMany` |
| Создать или обновить | `upsert` |
| Атомарно изменить число | `update` + `increment`/`decrement` |
| Удалить одну / по фильтру | `delete` / `deleteMany` |
| Посчитать / агрегировать / сгруппировать | `count` / `aggregate` / `groupBy` |
| Несколько операций атомарно | `$transaction` |
| То, чего нет в API | `$queryRaw` / TypedSQL |

## Частые ошибки

- `findFirst` без `orderBy`.
- Ожидать, что `updateMany` вернёт записи (возвращает `count`; для записей — `updateManyAndReturn`).
- `update` без обработки P2025.
- `$queryRawUnsafe` со строками от пользователя.
- `$use` из старых примеров в Prisma 7.

## Что важно помнить

- `findUnique` — только уникальные поля, `findFirst` — с `orderBy`.
- `*Many` возвращают `{ count }`, `*AndReturn` — записи.
- Raw SQL — только через шаблонные плейсхолдеры; расширения — `$extends`.

## Мини-шпаргалка

- `findUnique(OrThrow)`, `findFirst(OrThrow)`, `findMany`.
- `create`, `createMany`, `createManyAndReturn`.
- `update`, `updateMany`, `updateManyAndReturn`, `upsert`.
- `delete`, `deleteMany`, `count`, `aggregate`, `groupBy`.
- `$transaction`, `$queryRaw`, `$executeRaw`, `$extends`.
