# Как устроен schema.prisma

> [!NOTE]
> `schema.prisma` — единый источник правды о модели данных. Он состоит из блоков: **`generator`** — какой клиент генерировать и куда (`provider = "prisma-client"`, `output`, `moduleFormat`, `previewFeatures`); **`datasource`** — тип СУБД (`provider = "postgresql"`; URL в Prisma 7 задаётся в конфиге Prisma, а не здесь); **`model`** — таблицы с полями, типами и атрибутами; **`enum`** — перечисления; **`view`** и `type` (составные типы для MongoDB) — реже. Атрибуты полей начинаются с `@` (`@id`, `@unique`, `@default`, `@relation`, `@map`, `@db.*`), атрибуты модели — с `@@` (`@@index`, `@@unique`, `@@id`, `@@map`, `@@schema`). Из схемы Prisma строит миграции (`migrate dev` сравнивает схему с БД) и генерирует клиент. Большие схемы можно разбить на **несколько файлов** в папке `prisma/schema/`.

## Вопрос

Как устроен файл `schema.prisma`?

## Пример схемы

```prisma
generator client {
  provider     = "prisma-client"
  output       = "../src/generated/prisma"
  moduleFormat = "cjs"
}

datasource db {
  provider = "postgresql"
}

enum Role {
  USER
  ADMIN
}

model User {
  id        String   @id @default(uuid(7)) @db.Uuid
  email     String   @unique
  name      String   @db.VarChar(100)
  role      Role     @default(USER)
  createdAt DateTime @default(now()) @map("created_at") @db.Timestamptz(3)
  updatedAt DateTime @updatedAt @map("updated_at") @db.Timestamptz(3)

  orders Order[]

  @@map("users")
}

model Order {
  id        String      @id @default(uuid(7)) @db.Uuid
  userId    String      @map("user_id") @db.Uuid
  status    OrderStatus @default(PENDING)
  total     Decimal     @db.Decimal(12, 2)
  createdAt DateTime    @default(now()) @map("created_at") @db.Timestamptz(3)

  user User @relation(fields: [userId], references: [id], onDelete: Restrict)

  @@index([userId, createdAt(sort: Desc)])
  @@map("orders")
}

enum OrderStatus {
  PENDING
  PAID
  CANCELLED
}
```

## Блоки

| Блок | Назначение |
| --- | --- |
| `generator` | Генерация клиента: `provider`, `output`, `moduleFormat`, `previewFeatures` |
| `datasource` | Провайдер БД (`postgresql`, `mysql`, `sqlite`, `sqlserver`, `cockroachdb`), `schemas` для multi-schema |
| `model` | Таблица |
| `enum` | Перечисление (тип `ENUM` в PostgreSQL) |
| `view` | Представление (preview) |

## Атрибуты

| Атрибут | Уровень | Назначение |
| --- | --- | --- |
| `@id`, `@@id([a, b])` | Поле / модель | Первичный ключ (составной) |
| `@default(...)` | Поле | `now()`, `uuid()`, `uuid(7)`, `cuid()`, `autoincrement()`, `dbgenerated("...")`, литерал |
| `@unique`, `@@unique([a, b])` | Поле / модель | Уникальность |
| `@updatedAt` | Поле | Prisma сама проставляет время обновления |
| `@relation(...)` | Поле | Связь, `onDelete`, `onUpdate` |
| `@map("col")`, `@@map("table")` | Поле / модель | Имя в БД отличается от имени в коде |
| `@db.VarChar(100)`, `@db.Uuid`, `@db.Timestamptz(3)` | Поле | Нативный тип СУБД |
| `@@index([...])` | Модель | Индекс (с порядком, типом `type: Gin` и др.) |

## Соглашения об именах

```text
в коде:  User.createdAt, prisma.user
в БД:    users.created_at   ← через @map / @@map
```

Так схема БД остаётся в привычном `snake_case`, а код — в `camelCase`.

## Многофайловая схема

```text
prisma/schema/
├── schema.prisma      # generator + datasource
├── user.prisma
└── order.prisma
```

```ts
// prisma.config.ts
export default defineConfig({ schema: 'prisma/schema', /* ... */ });
```

## Форматирование и проверка

```bash
npx prisma format      # выравнивание и добавление обратных связей
npx prisma validate    # проверка схемы
```

## Частые ошибки

- `url = env(...)` в `datasource` по старым примерам (Prisma 7 — в конфиге).
- `DateTime` без `@db.Timestamptz` — в PostgreSQL получится `timestamp(3)` без часового пояса.
- Нет индексов на FK-полях (Prisma не создаёт их автоматически для PostgreSQL).
- Переименование поля в схеме без `@map` — миграция удалит столбец и создаст новый.

## Что важно помнить

- `generator` + `datasource` + `model`/`enum`.
- `@` — атрибуты полей, `@@` — модели.
- `@map`/`@@map` разделяют имена в коде и в БД.

## Мини-шпаргалка

- `@id @default(uuid(7)) @db.Uuid`.
- `@unique`, `@@unique([a, b])`, `@@index([a, b(sort: Desc)])`.
- `@updatedAt`, `@default(now())`.
- `@map("snake_case")`, `@@map("table")`.
