# Как выполнять CRUD через Prisma

> [!NOTE]
> Для каждой модели Prisma Client генерирует методы: чтение — `findUnique` (только по уникальному полю или составному ключу), `findFirst` (первая запись по любому фильтру — с `orderBy`!), `findMany` (список), их варианты `*OrThrow`; создание — `create`, `createMany`, `createManyAndReturn`; обновление — `update` (одна запись по уникальному полю, ошибка P2025, если нет), `updateMany` (по фильтру, возвращает `{ count }`), `updateManyAndReturn`, `upsert`; удаление — `delete`, `deleteMany`; агрегаты — `count`, `aggregate`, `groupBy`. Для атомарных изменений числовых полей есть операции `increment`/`decrement`/`multiply` — они выполняются в базе и не теряют конкурентные обновления. Обычно в CRUD-сервисе сразу указывают `select` (что вернуть клиенту) и переводят P2025/P2002 в 404/409. Полный справочник — [методы Prisma Client](<15. Какие методы Prisma Client нужно знать.md>).

## Вопрос

Как реализовать CRUD-операции через Prisma в NestJS?

## Сервис

```ts
const productSelect = { id: true, sku: true, title: true, price: true, stock: true } satisfies Prisma.ProductSelect;

@Injectable()
export class ProductsService {
  constructor(private readonly prisma: PrismaService) {}

  // Create
  create(dto: CreateProductDto) {
    return this.prisma.product.create({
      data: { sku: dto.sku, title: dto.title, price: dto.price, category: { connect: { id: dto.categoryId } } },
      select: productSelect,
    });
  }

  // Read one
  async findOne(id: string) {
    const product = await this.prisma.product.findUnique({ where: { id }, select: productSelect });
    if (!product) throw new NotFoundException();
    return product;
  }

  // Read many
  findAll({ page, limit }: { page: number; limit: number }) {
    return this.prisma.product.findMany({
      where: { status: 'PUBLISHED' },
      orderBy: [{ createdAt: 'desc' }, { id: 'desc' }],
      skip: (page - 1) * limit,
      take: limit,
      select: productSelect,
    });
  }

  // Update
  update(id: string, dto: UpdateProductDto) {
    return this.prisma.product.update({ where: { id }, data: dto, select: productSelect });   // P2025 → 404
  }

  // Delete
  async remove(id: string) {
    await this.prisma.product.delete({ where: { id } });
  }
}
```

## Атомарные операции с числами

```ts
// ✗ read-modify-write: потерянное обновление при параллельных запросах
const p = await this.prisma.product.findUniqueOrThrow({ where: { id } });
await this.prisma.product.update({ where: { id }, data: { stock: p.stock - 1 } });

// ✓ вычисление в БД + условие
const { count } = await this.prisma.product.updateMany({
  where: { id, stock: { gte: 1 } },
  data: { stock: { decrement: 1 } },
});
if (count === 0) throw new UnprocessableEntityException('Out of stock');
```

## Массовые операции

```ts
await this.prisma.tag.createMany({ data: names.map((name) => ({ name })), skipDuplicates: true });

const created = await this.prisma.tag.createManyAndReturn({ data: [{ name: 'a' }, { name: 'b' }], select: { id: true, name: true } });

await this.prisma.session.deleteMany({ where: { expiresAt: { lt: new Date() } } });
```

## Upsert

```ts
await this.prisma.userSettings.upsert({
  where: { userId },
  create: { userId, theme: 'dark' },
  update: { theme: 'dark' },
});
```

`upsert` в PostgreSQL обычно выполняется как `INSERT ... ON CONFLICT`, если условие совпадает с уникальным ключом; иначе — как последовательность запросов, где возможна гонка.

## Мягкое удаление

```ts
softRemove(id: string) {
  return this.prisma.product.update({ where: { id }, data: { deletedAt: new Date() } });
}
// и фильтр deletedAt: null во всех чтениях (или через $extends)
```

## undefined и null

```ts
data: { description: undefined }   // поле не меняется
data: { description: null }        // записать NULL
```

Это удобно для `PATCH`: поля, которых нет в DTO, не трогаются.

## Частые ошибки

- `findFirst` без `orderBy` — результат не детерминирован.
- `findUnique` по неуникальному полю — ошибка типов (используйте `findFirst`).
- Read-modify-write для счётчиков вместо `increment`/`decrement`.
- `update` для «может не существовать» без обработки P2025.
- Цикл из `create` вместо `createMany`.

## Что важно помнить

- `findUnique` — по уникальному, `findFirst` — с `orderBy`, `findMany` — списки.
- `update`/`delete` бросают P2025, `*Many` возвращают `count`.
- Числа — атомарно через `increment`/`decrement`.

## Мини-шпаргалка

- `create`, `findUnique`, `findMany`, `update`, `delete`.
- `createMany({ skipDuplicates })`, `updateMany`, `deleteMany` → `{ count }`.
- `upsert({ where, create, update })`.
- `{ stock: { decrement: n } }`.
