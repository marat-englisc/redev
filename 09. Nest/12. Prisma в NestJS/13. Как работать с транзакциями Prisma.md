# Как работать с транзакциями Prisma

> [!NOTE]
> В Prisma три способа атомарности. **Nested writes** — изменение записи с дочерними данными одним вызовом (уже транзакционно). **Batch transaction** `prisma.$transaction([op1, op2])` — массив независимых операций, выполняемых в одной транзакции (например, страница + `count` в одном снимке, или несколько обновлений). **Interactive transaction** `prisma.$transaction(async (tx) => {...}, options)` — произвольная логика между запросами: прочитать, проверить, записать; внутри колбэка нужно использовать **`tx`**, а не `this.prisma`, иначе запрос уйдёт вне транзакции. Опции: `isolationLevel` (`ReadCommitted`, `RepeatableRead`, `Serializable`), `timeout` (по умолчанию 5 с), `maxWait` (ожидание соединения). При конфликтах сериализации и дедлоках Prisma бросает **P2034** — транзакцию повторяют. Правила те же, что для любой БД: транзакции короткие, без внешних HTTP-вызовов, а инварианты (остатки, баланс) — через атомарные `updateMany` с условием или блокировки `SELECT … FOR UPDATE` (через `$queryRaw`).

## Вопрос

Как использовать транзакции в Prisma?

## Batch transaction

```ts
const [items, total] = await this.prisma.$transaction([
  this.prisma.product.findMany({ where, skip, take }),
  this.prisma.product.count({ where }),
]);

await this.prisma.$transaction([
  this.prisma.account.update({ where: { id: from }, data: { balance: { decrement: amount } } }),
  this.prisma.account.update({ where: { id: to }, data: { balance: { increment: amount } } }),
]);
```

Операции не могут зависеть друг от друга (нельзя использовать результат первой во второй).

## Interactive transaction

```ts
async transfer(fromId: string, toId: string, amount: Prisma.Decimal) {
  return this.prisma.$transaction(
    async (tx) => {
      const debited = await tx.account.updateMany({
        where: { id: fromId, balance: { gte: amount } },      // проверка и списание атомарно
        data: { balance: { decrement: amount } },
      });
      if (debited.count === 0) throw new UnprocessableEntityException('Insufficient funds');

      await tx.account.update({ where: { id: toId }, data: { balance: { increment: amount } } });
      return tx.transfer.create({ data: { fromId, toId, amount } });
    },
    { isolationLevel: Prisma.TransactionIsolationLevel.ReadCommitted, timeout: 5_000, maxWait: 2_000 },
  );
}
```

Исключение внутри колбэка откатывает всё.

## Блокировка строки

```ts
await this.prisma.$transaction(async (tx) => {
  const [seat] = await tx.$queryRaw<{ id: string; booked_by: string | null }[]>`
    SELECT id, booked_by FROM seats WHERE id = ${seatId}::uuid FOR UPDATE`;
  if (seat.booked_by) throw new ConflictException('Seat already booked');
  await tx.seat.update({ where: { id: seatId }, data: { bookedBy: userId } });
});
```

## Повтор при конфликтах

```ts
async function withTxRetry<T>(fn: () => Promise<T>, attempts = 3): Promise<T> {
  for (let i = 1; ; i++) {
    try {
      return await fn();
    } catch (e) {
      const retry = e instanceof Prisma.PrismaClientKnownRequestError && e.code === 'P2034';
      if (!retry || i >= attempts) throw e;
      await new Promise((r) => setTimeout(r, 20 * i + Math.random() * 30));
    }
  }
}

await withTxRetry(() =>
  this.prisma.$transaction(async (tx) => { /* ... */ }, { isolationLevel: 'Serializable' }),
);
```

## Транзакция через несколько репозиториев

```ts
// передавать tx явно
await this.prisma.$transaction(async (tx) => {
  await this.orders.create(data, tx);
  await this.stock.reserve(items, tx);
});

// или @nestjs-cls/transactional — без передачи tx вручную
```

## Выбор способа

| Задача | Способ |
| --- | --- |
| Запись с дочерними данными | Nested write |
| Несколько независимых операций, общий снимок | `$transaction([...])` |
| Чтение → проверка → запись | Interactive `$transaction(async tx => ...)` |
| Счётчики, остатки | Атомарный `update`/`updateMany` с `increment`/`decrement` и условием |

## Частые ошибки

- `this.prisma` вместо `tx` внутри колбэка.
- Долгие операции и HTTP-вызовы внутри interactive transaction — превышение `timeout`, удержание блокировок.
- Проверка баланса `findUnique` + `update` без условия — lost update.
- Нет повторов при `Serializable` — пользователи видят ошибки P2034.
- Вложенные `$transaction` внутри `tx` — не поддерживается.

## Что важно помнить

- Nested write, batch и interactive transaction — три уровня атомарности.
- Внутри interactive transaction — только `tx`, коротко, с таймаутом.
- P2034 — повторить; инварианты — атомарными условными обновлениями.

## Мини-шпаргалка

- `$transaction([a, b])`.
- `$transaction(async (tx) => ..., { isolationLevel, timeout, maxWait })`.
- `updateMany({ where: { balance: { gte } }, data: { balance: { decrement } } })`.
- `SELECT ... FOR UPDATE` через `tx.$queryRaw`.
