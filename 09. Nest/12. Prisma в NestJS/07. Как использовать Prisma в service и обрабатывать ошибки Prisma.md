# Как использовать Prisma в service и обрабатывать ошибки Prisma

> [!NOTE]
> В небольших фичах сервис внедряет `PrismaService` напрямую — сгенерированный клиент уже работает как типизированный репозиторий для каждой модели; при сложных запросах или для изоляции бизнес-логики выделяют [репозиторий](<../08. Config, database и интеграции/05. Как проектировать repository layer в NestJS.md>). Типы для параметров и результатов берут из сгенерированного клиента: `Prisma.UserCreateInput`, `Prisma.UserWhereInput`, а тип результата с конкретным `select` — через `Prisma.UserGetPayload<{ select: ... }>` или `satisfies Prisma.UserSelect`. Ошибки Prisma — классы `Prisma.PrismaClientKnownRequestError` с кодами: **P2002** — нарушение уникальности (→ 409), **P2025** — запись не найдена для `update`/`delete`/`*OrThrow` (→ 404), **P2003** — нарушение внешнего ключа (→ 400/409), **P2034** — конфликт транзакции/deadlock (→ повтор). Их переводят в HTTP-исключения в сервисе там, где нужен конкретный текст, или централизованно — exception filter-ом.

## Вопрос

Как правильно использовать Prisma в сервисах NestJS и обрабатывать её ошибки?

## Сервис с типами Prisma

```ts
import { Prisma } from '../generated/prisma/client';

const userPublicSelect = {
  id: true,
  email: true,
  name: true,
  createdAt: true,
} satisfies Prisma.UserSelect;

export type UserPublic = Prisma.UserGetPayload<{ select: typeof userPublicSelect }>;

@Injectable()
export class UsersService {
  constructor(private readonly prisma: PrismaService) {}

  async findOne(id: string): Promise<UserPublic> {
    const user = await this.prisma.user.findUnique({ where: { id }, select: userPublicSelect });
    if (!user) throw new NotFoundException(`User ${id} not found`);
    return user;
  }

  async create(dto: CreateUserDto): Promise<UserPublic> {
    try {
      return await this.prisma.user.create({
        data: { email: dto.email, name: dto.name, passwordHash: await hash(dto.password) },
        select: userPublicSelect,
      });
    } catch (e) {
      if (e instanceof Prisma.PrismaClientKnownRequestError && e.code === 'P2002') {
        throw new ConflictException('Email already registered', { cause: e });
      }
      throw e;
    }
  }

  async update(id: string, dto: UpdateUserDto): Promise<UserPublic> {
    try {
      return await this.prisma.user.update({ where: { id }, data: dto, select: userPublicSelect });
    } catch (e) {
      if (e instanceof Prisma.PrismaClientKnownRequestError && e.code === 'P2025') throw new NotFoundException();
      throw e;
    }
  }
}
```

## Коды ошибок

| Код | Значение | HTTP |
| --- | --- | --- |
| `P2002` | Unique constraint failed (`e.meta.target` — поля) | 409 |
| `P2025` | Record to update/delete not found | 404 |
| `P2003` | Foreign key constraint failed | 400 / 409 |
| `P2014` | Нарушение обязательной связи | 400 |
| `P2034` | Transaction failed due to write conflict or deadlock | Повторить |

## Централизованно — filter

```ts
@Catch(Prisma.PrismaClientKnownRequestError)
export class PrismaExceptionFilter implements ExceptionFilter {
  catch(e: Prisma.PrismaClientKnownRequestError, host: ArgumentsHost) {
    const res = host.switchToHttp().getResponse<Response>();
    const map: Record<string, [number, string]> = {
      P2002: [409, 'Resource already exists'],
      P2025: [404, 'Resource not found'],
      P2003: [409, 'Related resource constraint failed'],
    };
    const [status, message] = map[e.code] ?? [500, 'Internal server error'];
    res.status(status).json({ statusCode: status, message });
  }
}
```

## findUniqueOrThrow

```ts
const user = await this.prisma.user.findUniqueOrThrow({ where: { id } });   // P2025 → filter → 404
```

## Контроллер не трогает Prisma

```ts
@Get(':id')
findOne(@Param('id', ParseUUIDPipe) id: string) {
  return this.users.findOne(id);       // не this.prisma.user.findUnique(...)
}
```

## Частые ошибки

- Возвращать модель целиком (`passwordHash` уходит клиенту) вместо `select`.
- Ловить все ошибки и превращать в 500 или, наоборот, в 400 без разбора кода.
- Проверка «существует ли email» через `findUnique` перед `create` вместо обработки P2002 — гонка двух запросов.
- `import { Prisma } from '@prisma/client'` в Prisma 7 — типы берутся из сгенерированного пути.

## Что важно помнить

- Типы — из сгенерированного клиента (`Prisma.XxxSelect`, `GetPayload`).
- `select` определяет форму ответа и защищает от утечки полей.
- P2002 → 409, P2025 → 404; можно централизовать фильтром.

## Мини-шпаргалка

- `const sel = {...} satisfies Prisma.UserSelect`.
- `Prisma.UserGetPayload<{ select: typeof sel }>`.
- `e instanceof Prisma.PrismaClientKnownRequestError && e.code === 'P2002'`.
- `findUniqueOrThrow` + filter.
