# Что такое PrismaService и PrismaModule

> [!NOTE]
> **`PrismaService`** — Nest-провайдер, который **наследует `PrismaClient`** (и поэтому сам является клиентом со всеми методами `this.prisma.user...`) и управляет его жизненным циклом: в конструкторе создаётся driver adapter (в Prisma 7 обязателен, например `PrismaPg`) с URL из `ConfigService`, в `onModuleInit` — `$connect()`, в `onModuleDestroy` — `$disconnect()`. **`PrismaModule`** регистрирует и экспортирует `PrismaService` (часто как `@Global()`), чтобы во всём приложении был **один клиент и один пул соединений**. Создавать `new PrismaClient()` в каждом сервисе нельзя: каждый экземпляр открывает свой пул, и соединения базы быстро заканчиваются. Событие `beforeExit` в Prisma 7 не поддерживается — корректное закрытие обеспечивается `app.enableShutdownHooks()` и хуками Nest. При использовании `$extends` (расширения клиента) сервис оборачивают иначе: возвращают расширенный клиент через фабричный провайдер.

## Вопрос

Что такое `PrismaService` и `PrismaModule` и как их правильно написать?

## PrismaService (Prisma 7)

```ts
import { Injectable, OnModuleDestroy, OnModuleInit } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';
import { PrismaPg } from '@prisma/adapter-pg';
import { PrismaClient } from '../generated/prisma/client';

@Injectable()
export class PrismaService extends PrismaClient implements OnModuleInit, OnModuleDestroy {
  constructor(config: ConfigService) {
    const adapter = new PrismaPg({
      connectionString: config.getOrThrow<string>('DATABASE_URL'),
      max: config.get<number>('DB_POOL_SIZE', 10),          // опции пула pg
    });
    super({
      adapter,
      log: config.get('NODE_ENV') === 'development' ? ['query', 'warn', 'error'] : ['warn', 'error'],
    });
  }

  async onModuleInit() {
    await this.$connect();          // упасть при старте, если БД недоступна
  }

  async onModuleDestroy() {
    await this.$disconnect();
  }
}
```

## PrismaModule

```ts
@Global()
@Module({
  providers: [PrismaService],
  exports: [PrismaService],
})
export class PrismaModule {}

@Module({
  imports: [ConfigModule.forRoot({ isGlobal: true }), PrismaModule, UsersModule],
})
export class AppModule {}

// main.ts
app.enableShutdownHooks();
```

## Использование

```ts
@Injectable()
export class UsersService {
  constructor(private readonly prisma: PrismaService) {}

  findByEmail(email: string) {
    return this.prisma.user.findUnique({ where: { email } });
  }
}
```

## Расширенный клиент ($extends)

```ts
export const PRISMA = Symbol('PRISMA');

function createClient(config: ConfigService) {
  const base = new PrismaClient({ adapter: new PrismaPg({ connectionString: config.getOrThrow('DATABASE_URL') }) });
  return base.$extends({
    query: {
      $allModels: {
        async findMany({ args, query }) {
          args.where = { ...args.where, deletedAt: null };   // мягкое удаление по умолчанию
          return query(args);
        },
      },
    },
  });
}
export type ExtendedPrisma = ReturnType<typeof createClient>;

@Global()
@Module({
  providers: [{ provide: PRISMA, inject: [ConfigService], useFactory: createClient }],
  exports: [PRISMA],
})
export class PrismaModule {}

// constructor(@Inject(PRISMA) private readonly prisma: ExtendedPrisma) {}
```

`$extends` возвращает новый объект, поэтому подход «`extends PrismaClient`» с ним не сочетается напрямую.

## Пул соединений

```text
max соединений БД ≥ (реплики × pool) + миграции + админ-доступ
пример: 4 пода × 10 = 40 при max_connections = 100
```

В serverless и при большом числе реплик используют пулер (PgBouncer, Supavisor, Prisma Postgres) — тогда в адаптер передают URL пулера, а для миграций в конфиге Prisma — прямой URL. Подробнее — [пул соединений](<../../10. SQL/11. Практика Backend и собеседования/11. Что такое пул соединений и как с ним работать.md>).

## Частые ошибки

- `new PrismaClient()` в нескольких сервисах.
- Prisma 7 без адаптера — клиент не создаётся.
- Подписка на `beforeExit` — не поддерживается в Prisma 7.
- Не экспортировать `PrismaService` и получить ошибку DI в других модулях.
- `PrismaService` в `providers` нескольких модулей — несколько клиентов.

## Что важно помнить

- `PrismaService extends PrismaClient` + адаптер + `$connect`/`$disconnect` в хуках.
- `PrismaModule` (часто глобальный) — один клиент на приложение.
- Для `$extends` — фабричный провайдер с токеном.

## Мини-шпаргалка

- `super({ adapter: new PrismaPg({ connectionString }) })`.
- `onModuleInit → $connect()`, `onModuleDestroy → $disconnect()`.
- `@Global() @Module({ providers: [PrismaService], exports: [PrismaService] })`.
- `app.enableShutdownHooks()`.
