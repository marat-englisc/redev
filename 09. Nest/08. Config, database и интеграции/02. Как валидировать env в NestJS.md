# Как валидировать env в NestJS

> [!NOTE]
> Переменные окружения нужно проверять **при старте**: если `DATABASE_URL` не задан или `JWT_SECRET` слишком короткий, приложение должно упасть сразу с понятной ошибкой, а не через час на первом запросе. В `@nestjs/config` есть два способа. **`validationSchema`** — в NestJS 12 принимает любую **Standard Schema** (Zod, Valibot, ArkType) или Joi v18+; значения по умолчанию в схеме делают переменную необязательной, без `default` — обязательной; библиотечные опции передаются в `validationOptions.libraryOptions`. **`validate(config)`** — своя функция (например, на `class-validator` + `plainToInstance` или `schema.parse`), которая возвращает провалидированный объект или бросает ошибку. Помните: env-значения **всегда строки** — числа и boolean нужно явно приводить (`z.coerce.number()`, `z.stringbool()`); `z.coerce.boolean()` превратит `"false"` в `true`. Секреты проверяют на длину, но не логируют.

## Вопрос

Как валидировать переменные окружения в NestJS?

## Zod через validationSchema (NestJS 12)

```ts
// config/env.schema.ts
import { z } from 'zod';

export const envSchema = z.object({
  NODE_ENV: z.enum(['development', 'test', 'production']).default('development'),
  PORT: z.coerce.number().int().min(1).max(65535).default(3000),
  DATABASE_URL: z.url(),
  REDIS_URL: z.url(),
  JWT_ACCESS_SECRET: z.string().min(32),
  JWT_REFRESH_SECRET: z.string().min(32),
  CORS_ORIGINS: z.string().transform((s) => s.split(',').map((x) => x.trim())),
  SWAGGER_ENABLED: z.stringbool().default(false),      // 'true'/'false'/'1'/'0'/'yes'/'no'
  LOG_LEVEL: z.enum(['debug', 'info', 'warn', 'error']).default('info'),
});

export type EnvVars = z.infer<typeof envSchema>;

// app.module.ts
ConfigModule.forRoot({ isGlobal: true, validationSchema: envSchema });
```

Ошибка при старте:

```text
Error: Config validation error: DATABASE_URL: Invalid URL; JWT_ACCESS_SECRET: Too small: expected string to have >=32 characters
```

## Своя функция validate

```ts
ConfigModule.forRoot({
  isGlobal: true,
  validate: (raw) => {
    const result = envSchema.safeParse(raw);
    if (!result.success) {
      throw new Error(`Invalid environment:\n${z.prettifyError(result.error)}`);
    }
    return result.data;                       // значения с приведёнными типами попадут в ConfigService
  },
});
```

## class-validator

```ts
class EnvironmentVariables {
  @IsEnum(['development', 'test', 'production']) NODE_ENV: string;
  @IsInt() @Min(1) @Max(65535) PORT: number;
  @IsUrl({ require_tld: false, protocols: ['postgres', 'postgresql'] }) DATABASE_URL: string;
  @IsString() @MinLength(32) JWT_ACCESS_SECRET: string;
}

export function validate(config: Record<string, unknown>) {
  const validated = plainToInstance(EnvironmentVariables, config, { enableImplicitConversion: true });
  const errors = validateSync(validated, { skipMissingProperties: false });
  if (errors.length) throw new Error(errors.toString());
  return validated;
}
```

## Joi

```ts
ConfigModule.forRoot({
  validationSchema: Joi.object({
    NODE_ENV: Joi.string().valid('development', 'test', 'production').default('development'),
    PORT: Joi.number().port().default(3000),
    DATABASE_URL: Joi.string().uri().required(),
  }),
  validationOptions: { libraryOptions: { allowUnknown: true, abortEarly: false } },   // NestJS 12
});
```

## Типизированный доступ

```ts
@Injectable()
export class AppConfig {
  constructor(private readonly config: ConfigService<EnvVars, true>) {}

  get port() { return this.config.get('PORT', { infer: true }); }           // number
  get corsOrigins() { return this.config.get('CORS_ORIGINS', { infer: true }); }   // string[]
}
```

## Вне Nest (скрипты, Prisma config)

```ts
// env.ts — одна точка правды и для скриптов
export const env = envSchema.parse(process.env);
```

## Частые ошибки

- `z.coerce.boolean()` для флагов — `'false'` станет `true`.
- Нет валидации, и приложение падает с `undefined` глубоко в коде.
- Логировать весь `process.env` при ошибке — секреты попадают в логи.
- Схема отличается от `.env.example`.

## Что важно помнить

- Валидация env — при старте, падение с понятным сообщением.
- NestJS 12: `validationSchema` принимает Zod/Valibot/ArkType и Joi v18+.
- Env — строки; приводить типы явно.

## Мини-шпаргалка

- `ConfigModule.forRoot({ validationSchema: zodSchema })`.
- `validate: (raw) => schema.parse(raw)`.
- `z.coerce.number()`, `z.stringbool()`, `z.url()`, `z.string().min(32)`.
- `ConfigService<EnvVars, true>` + `{ infer: true }`.
