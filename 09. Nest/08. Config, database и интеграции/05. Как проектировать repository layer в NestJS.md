# Как проектировать repository layer в NestJS

> [!NOTE]
> **Репозиторий** — слой, который инкапсулирует доступ к данным одной агрегатной сущности: сервис говорит «найди активные заказы пользователя», а не строит запрос ORM. Это отделяет бизнес-логику от деталей хранения, концентрирует запросы (и оптимизации, индексы, `select`) в одном месте, упрощает unit-тесты сервисов (мок репозитория вместо мока ORM) и делает возможной замену хранилища. В NestJS репозиторий — обычный `@Injectable()`-провайдер, приватный для своего модуля; при необходимости абстракция оформляется **абстрактным классом-контрактом** с реализацией на Prisma/TypeORM (`{ provide: OrdersRepository, useClass: PrismaOrdersRepository }`). Не нужно создавать репозиторий ради репозитория: для простого CRUD на Prisma сервис может обращаться к `PrismaService` напрямую — слой окупается, когда запросов много, они сложные или их нужно тестировать изолированно.

## Вопрос

Как спроектировать слой репозиториев в NestJS и когда он нужен?

## Репозиторий на Prisma

```ts
@Injectable()
export class OrdersRepository {
  constructor(private readonly prisma: PrismaService) {}

  findByIdForUser(id: string, userId: string) {
    return this.prisma.order.findFirst({
      where: { id, userId },
      include: { items: { include: { product: { select: { id: true, title: true } } } } },
    });
  }

  listForUser(userId: string, { cursor, limit }: { cursor?: string; limit: number }) {
    return this.prisma.order.findMany({
      where: { userId },
      orderBy: [{ createdAt: 'desc' }, { id: 'desc' }],
      take: limit + 1,
      ...(cursor && { cursor: { id: cursor }, skip: 1 }),
      select: { id: true, status: true, total: true, createdAt: true },
    });
  }

  markPaid(id: string, tx: Prisma.TransactionClient = this.prisma) {
    return tx.order.updateMany({ where: { id, status: 'PENDING' }, data: { status: 'PAID', paidAt: new Date() } });
  }
}
```

## Сервис

```ts
@Injectable()
export class OrdersService {
  constructor(private readonly orders: OrdersRepository, private readonly payments: PaymentsGateway) {}

  async getOrder(id: string, user: AuthUser) {
    const order = await this.orders.findByIdForUser(id, user.id);
    if (!order) throw new NotFoundException();
    return order;
  }
}
```

## Контракт и реализации

```ts
export abstract class OrdersRepository {
  abstract findByIdForUser(id: string, userId: string): Promise<Order | null>;
  abstract save(order: Order): Promise<void>;
}

@Injectable()
export class PrismaOrdersRepository extends OrdersRepository { ... }

@Module({
  providers: [OrdersService, { provide: OrdersRepository, useClass: PrismaOrdersRepository }],
})
export class OrdersModule {}

// unit-тест сервиса: in-memory реализация вместо БД
{ provide: OrdersRepository, useClass: InMemoryOrdersRepository }
```

## Что принимает и возвращает репозиторий

| Да | Нет |
| --- | --- |
| Доменные параметры (`userId`, фильтр, курсор) | HTTP-объекты, DTO запроса целиком |
| Доменные объекты или узкие «проекции» | Бизнес-решения («можно ли отменить заказ») |
| Опциональный транзакционный клиент | Бросание HTTP-исключений |

## Транзакции через несколько репозиториев

```ts
await this.prisma.$transaction(async (tx) => {
  await this.orders.markPaid(orderId, tx);
  await this.stock.reserve(items, tx);
});
```

Либо — `@nestjs-cls/transactional`, который прокидывает транзакционный клиент автоматически: см. [транзакции в NestJS](<06. Как работать с транзакциями в NestJS.md>).

## Когда репозиторий не нужен

- Простой CRUD без сложных запросов.
- Маленький сервис, где ORM-вызовы и так читаемы.
- Prisma уже даёт типизированный «репозиторий» на каждую модель — обёртка 1-к-1 над `findUnique/create` ничего не добавляет.

## Частые ошибки

- Generic `BaseRepository<T>` с `findAll()` для всего — запросы без `where`, `select` и лимитов.
- Бизнес-логика в репозитории.
- Утечка ORM-типов во все слои, хотя цель была изоляция.
- Репозиторий бросает `NotFoundException` — HTTP-знание в слое данных.

## Что важно помнить

- Репозиторий концентрирует доступ к данным агрегата.
- Сервис — бизнес-правила, репозиторий — запросы.
- Слой вводят, когда он окупается: сложные запросы, тесты, замена хранилища.

## Мини-шпаргалка

- `@Injectable() class XRepository { constructor(prisma) }`.
- Абстрактный класс-контракт + `useClass`.
- Методы с доменными именами (`listForUser`, `markPaid`).
- Опциональный `tx` для транзакций.
