# Как делать background jobs и cron в NestJS

> [!NOTE]
> Долгие или ненадёжные операции (отправка писем, генерация PDF, обработка изображений, вебхуки партнёрам, импорт файлов) выносят из HTTP-запроса в **фоновые задачи**: API быстро отвечает, а задача выполняется воркером с повторами при ошибках. В NestJS стандарт — **BullMQ** на Redis через `@nestjs/bullmq`: `BullModule.registerQueue({ name })`, производитель добавляет задачу `queue.add(name, data, { attempts, backoff, delay, jobId })`, потребитель — класс с `@Processor('queue')`, наследующий `WorkerHost` с методом `process(job)`. Для расписаний — `@nestjs/schedule` (`@Cron('0 3 * * *')`, `@Interval`, `@Timeout`), но cron в каждом инстансе выполнится **столько раз, сколько реплик**, поэтому в кластере используют повторяющиеся задачи BullMQ (`repeat`/job schedulers) или распределённую блокировку. Задачи должны быть **идемпотентными**: доставка — «как минимум один раз».

## Вопрос

Как реализовать фоновые задачи и задачи по расписанию в NestJS?

## Подключение BullMQ

```bash
npm install @nestjs/bullmq bullmq
```

```ts
@Module({
  imports: [
    BullModule.forRootAsync({
      inject: [ConfigService],
      useFactory: (c: ConfigService) => ({ connection: { url: c.getOrThrow('REDIS_URL') } }),
    }),
    BullModule.registerQueue({ name: 'emails' }),
  ],
  providers: [EmailsProcessor, NotificationsService],
})
export class NotificationsModule {}
```

## Производитель

```ts
@Injectable()
export class NotificationsService {
  constructor(@InjectQueue('emails') private readonly emails: Queue) {}

  async sendWelcome(userId: string) {
    await this.emails.add(
      'welcome',
      { userId },
      {
        jobId: `welcome:${userId}`,                    // дедупликация
        attempts: 5,
        backoff: { type: 'exponential', delay: 2_000 },
        removeOnComplete: 1000,
        removeOnFail: 5000,
      },
    );
  }
}
```

## Потребитель

```ts
@Processor('emails', { concurrency: 5 })
export class EmailsProcessor extends WorkerHost {
  private readonly logger = new Logger(EmailsProcessor.name);

  constructor(private readonly mailer: MailService, private readonly users: UsersService) { super(); }

  async process(job: Job<{ userId: string }>) {
    switch (job.name) {
      case 'welcome': {
        const user = await this.users.findOne(job.data.userId);
        await this.mailer.send(user.email, 'Добро пожаловать!', 'welcome', { name: user.name });
        return { sent: true };
      }
      default:
        throw new Error(`Unknown job ${job.name}`);
    }
  }

  @OnWorkerEvent('failed')
  onFailed(job: Job, err: Error) {
    this.logger.error(`Job ${job.id} (${job.name}) failed after ${job.attemptsMade} attempts: ${err.message}`);
  }
}
```

Воркеры можно запускать в отдельном процессе (тот же код, `createApplicationContext` без HTTP), чтобы тяжёлые задачи не влияли на задержку API.

## Расписание

```ts
// @nestjs/schedule — подходит для одного инстанса
@Module({ imports: [ScheduleModule.forRoot()] })
export class AppModule {}

@Injectable()
export class CleanupTask {
  @Cron('0 3 * * *', { timeZone: 'Europe/Moscow' })
  async purgeExpiredSessions() { ... }
}
```

```ts
// в кластере — повторяющаяся задача BullMQ выполняется одним воркером
await this.maintenance.upsertJobScheduler('purge-sessions', { pattern: '0 3 * * *', tz: 'Europe/Moscow' }, { name: 'purge-sessions' });
```

## Что выбрать

| Задача | Инструмент |
| --- | --- |
| Отложенная или ресурсоёмкая работа с повторами | BullMQ |
| Задача после транзакции БД (гарантированно) | Outbox + воркер |
| Простой cron в одном инстансе | `@nestjs/schedule` |
| Cron в нескольких репликах | BullMQ job scheduler / advisory lock |
| Внутрипроцессная реакция на событие | [EventEmitter](<08. Как использовать события в NestJS - EventEmitter.md>) |
| Очередь в Postgres без Redis | pg-boss, `SKIP LOCKED` |

## Частые ошибки

- Тяжёлая работа прямо в HTTP-обработчике — таймауты и медленный API.
- `@Cron` при нескольких репликах — задача выполняется N раз.
- Неидемпотентные обработчики — повтор после сбоя дублирует письма и платежи.
- Класть в задачу большие объекты вместо id.
- Нет мониторинга очередей (Bull Board, метрики длины очереди и ошибок).

## Что важно помнить

- Фоновые задачи — BullMQ: `Queue.add` + `@Processor`/`WorkerHost`.
- Повторы, backoff, дедупликация через `jobId`, идемпотентность.
- Cron в кластере — через очередь или распределённую блокировку.

## Мини-шпаргалка

- `BullModule.forRoot`, `registerQueue({ name })`.
- `@InjectQueue('q') queue.add(name, data, { attempts, backoff, jobId })`.
- `@Processor('q') class P extends WorkerHost { process(job) }`.
- `@Cron(expr, { timeZone })` + `ScheduleModule.forRoot()`.
