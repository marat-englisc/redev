# Как использовать события в NestJS - EventEmitter

> [!NOTE]
> `@nestjs/event-emitter` реализует **внутрипроцессные события** (на базе `eventemitter2`): один модуль публикует событие `this.events.emit('order.created', payload)`, а другие подписываются методами с `@OnEvent('order.created')`. Это ослабляет связанность: `OrdersService` не знает, что после заказа нужно отправить письмо, начислить бонусы и обновить аналитику, — каждый модуль реагирует сам; события также помогают **разорвать циклические зависимости** между модулями. Поддерживаются wildcard (`order.*`), асинхронные обработчики (`{ async: true }`), `emitAsync` для ожидания результатов. Ограничения: события **живут в памяти процесса** — не доходят до других инстансов, теряются при падении, не имеют повторов, а обработчик, выполняющийся синхронно, может замедлить или сломать исходный запрос. Для надёжной доставки (письма, интеграции) используют очередь (BullMQ) или outbox; EventEmitter — для лёгких внутренних реакций.

## Вопрос

Как использовать события внутри NestJS-приложения и когда это уместно?

## Подключение

```bash
npm install @nestjs/event-emitter
```

```ts
@Module({
  imports: [EventEmitterModule.forRoot({ wildcard: true, delimiter: '.' })],
})
export class AppModule {}
```

## Событие и публикация

```ts
// orders/events/order-created.event.ts
export class OrderCreatedEvent {
  constructor(public readonly orderId: string, public readonly userId: string, public readonly total: number) {}
}

@Injectable()
export class OrdersService {
  constructor(private readonly repo: OrdersRepository, private readonly events: EventEmitter2) {}

  async create(userId: string, dto: CreateOrderDto) {
    const order = await this.repo.create(userId, dto);
    this.events.emit('order.created', new OrderCreatedEvent(order.id, userId, order.total));
    return order;
  }
}
```

## Подписчики в других модулях

```ts
@Injectable()
export class LoyaltyListener {
  constructor(private readonly loyalty: LoyaltyService) {}

  @OnEvent('order.created', { async: true })
  async award(event: OrderCreatedEvent) {
    await this.loyalty.addPoints(event.userId, Math.floor(event.total / 100));
  }
}

@Injectable()
export class NotificationsListener {
  constructor(@InjectQueue('emails') private readonly emails: Queue) {}

  @OnEvent('order.created')
  enqueueEmail(event: OrderCreatedEvent) {
    return this.emails.add('order-confirmation', { orderId: event.orderId });   // надёжная доставка — в очередь
  }
}

@Injectable()
export class AuditListener {
  @OnEvent('order.*')
  log(event: unknown) { /* все события заказов */ }
}
```

## Ошибки в обработчиках

По умолчанию исключение в синхронном обработчике всплывает в `emit` и может сломать исходный запрос. Варианты: `{ async: true }` + try/catch внутри обработчика, `suppressErrors` в опциях `@OnEvent`, или вынос работы в очередь.

## Транзакции

```ts
// ✗ событие отправлено до COMMIT: если транзакция откатится, бонусы уже начислены
await this.prisma.$transaction(async (tx) => {
  const order = await tx.order.create(...);
  this.events.emit('order.created', ...);
});

// ✓ после успешного завершения транзакции
const order = await this.prisma.$transaction(async (tx) => tx.order.create(...));
this.events.emit('order.created', new OrderCreatedEvent(order.id, ...));
```

## EventEmitter, очередь, брокер

| | EventEmitter | Очередь (BullMQ) | Брокер (Kafka, RabbitMQ) |
| --- | --- | --- | --- |
| Границы | Один процесс | Несколько воркеров | Несколько сервисов |
| Надёжность | Теряется при падении | Хранится в Redis, повторы | Персистентность, replay |
| Задержка | Минимальная | Небольшая | Небольшая |
| Применение | Лёгкие внутренние реакции, развязка модулей | Фоновые задачи | Межсервисная интеграция |

## Частые ошибки

- Использовать EventEmitter для критичных операций (платежи, письма) без очереди.
- Отправлять событие внутри незавершённой транзакции.
- Строковые имена событий с опечатками — держите константы рядом с классом события.
- Подписчик не зарегистрирован как провайдер — `@OnEvent` не сработает.

## Что важно помнить

- `emit` + `@OnEvent` — развязка модулей внутри процесса.
- События не надёжны: для гарантий — очередь или outbox.
- Эмитить после фиксации транзакции.

## Мини-шпаргалка

- `EventEmitterModule.forRoot({ wildcard: true })`.
- `eventEmitter.emit('x.y', new XEvent(...))`, `emitAsync`.
- `@OnEvent('x.y', { async: true })`, `@OnEvent('x.*')`.
- Критичное — в BullMQ.
