# Как работать с транзакциями в NestJS

> [!NOTE]
> Транзакция объединяет несколько операций с БД в одну атомарную единицу: оформление заказа, списание остатков и запись платежа либо выполняются все, либо ни одна. В NestJS **транзакционная граница — в сервисе** (use case), а не в контроллере и не в репозитории. Способы: **Prisma** — `prisma.$transaction(async (tx) => {...})` (interactive, с опциями `isolationLevel`, `timeout`, `maxWait`) или массив операций; **TypeORM** — `dataSource.transaction(async (manager) => {...})` или `QueryRunner`; **`@nestjs-cls/transactional`** — декоратор `@Transactional()` и `TransactionHost`, которые прокидывают транзакционный клиент во все репозитории через AsyncLocalStorage, не передавая `tx` вручную. Правила: транзакции **короткие**, без HTTP-вызовов и отправки писем внутри (для них — паттерн **outbox**), с повтором при конфликтах сериализации и дедлоках, а инварианты остатков — атомарными `UPDATE ... WHERE stock >= qty`.

## Вопрос

Как работать с транзакциями в NestJS-приложении?

## Prisma

```ts
@Injectable()
export class CheckoutService {
  constructor(private readonly prisma: PrismaService) {}

  checkout(userId: string, items: { productId: string; qty: number }[]) {
    return this.prisma.$transaction(
      async (tx) => {
        for (const item of items) {
          const { count } = await tx.product.updateMany({
            where: { id: item.productId, stock: { gte: item.qty } },
            data: { stock: { decrement: item.qty } },
          });
          if (count === 0) throw new UnprocessableEntityException(`Out of stock: ${item.productId}`);
        }

        const order = await tx.order.create({
          data: { userId, status: 'PENDING', items: { create: items } },
        });

        await tx.outbox.create({ data: { type: 'order.created', payload: { orderId: order.id } } });
        return order;
      },
      { timeout: 5_000, isolationLevel: Prisma.TransactionIsolationLevel.ReadCommitted },
    );
  }
}
```

Исключение внутри колбэка откатывает транзакцию целиком.

## TypeORM

```ts
@Injectable()
export class TransfersService {
  constructor(private readonly dataSource: DataSource) {}

  transfer(fromId: string, toId: string, amount: number) {
    return this.dataSource.transaction(async (manager) => {
      const [from, to] = await manager.find(Account, {
        where: { id: In([fromId, toId]) },
        order: { id: 'ASC' },                      // единый порядок блокировок против deadlock
        lock: { mode: 'pessimistic_write' },
      });
      // ... проверки и изменения через manager
      await manager.save([from, to]);
    });
  }
}
```

## @nestjs-cls/transactional

```ts
// app.module.ts
ClsModule.forRoot({
  global: true,
  plugins: [new ClsPluginTransactional({ imports: [PrismaModule], adapter: new TransactionalAdapterPrisma({ prismaInjectionToken: PrismaService }) })],
});

// репозиторий не знает о транзакции
@Injectable()
export class OrdersRepository {
  constructor(private readonly txHost: TransactionHost<TransactionalAdapterPrisma>) {}
  create(data: Prisma.OrderCreateInput) { return this.txHost.tx.order.create({ data }); }
}

// сервис объявляет границу
@Transactional()
async checkout(...) {
  await this.stock.reserve(items);     // оба вызова — в одной транзакции
  return this.orders.create(...);
}
```

## Outbox вместо внешних вызовов в транзакции

```text
Транзакция: заказ + запись в outbox → COMMIT
Фоновый воркер: читает outbox → отправляет письмо / событие → отмечает обработанным
```

Так письмо не уйдёт для откатившегося заказа и не потеряется, если процесс упадёт после `COMMIT`.

## Повтор при конфликтах

```ts
async function withRetry<T>(fn: () => Promise<T>, attempts = 3): Promise<T> {
  for (let i = 1; ; i++) {
    try { return await fn(); }
    catch (e) {
      const retryable = e instanceof Prisma.PrismaClientKnownRequestError && e.code === 'P2034';   // write conflict / deadlock
      if (!retryable || i >= attempts) throw e;
    }
  }
}
```

## Частые ошибки

- Использовать `this.prisma` вместо `tx` внутри колбэка — операция выполнится вне транзакции.
- HTTP-запросы к платёжке внутри транзакции — блокировки держатся секундами.
- Проверка остатка через `SELECT`, затем `UPDATE` без блокировки — lost update.
- Транзакция в контроллере.
- Нет таймаута у interactive transaction.

## Что важно помнить

- Граница транзакции — в сервисе.
- Prisma `$transaction(tx => ...)`, TypeORM `dataSource.transaction(manager => ...)`, CLS — `@Transactional()`.
- Короткие транзакции, outbox для внешних эффектов, retry для конфликтов.

## Мини-шпаргалка

- `prisma.$transaction(async (tx) => ..., { timeout, isolationLevel })`.
- `dataSource.transaction(async (manager) => ...)`.
- `@Transactional()` + `TransactionHost.tx`.
- `updateMany({ where: { stock: { gte } } })` → `count === 0` → ошибка.
