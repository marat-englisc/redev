# Как подключить TypeORM к NestJS

> [!NOTE]
> **TypeORM** подключается официальным пакетом `@nestjs/typeorm`. В корне вызывают `TypeOrmModule.forRootAsync()` с конфигурацией из `ConfigService` (тип БД, URL, `autoLoadEntities`, пул), в feature-модулях — `TypeOrmModule.forFeature([User, Order])`, после чего репозиторий внедряется через `@InjectRepository(User) private readonly repo: Repository<User>`. Модели описываются **entity-классами** с декораторами (`@Entity`, `@PrimaryGeneratedColumn`, `@Column`, `@ManyToOne`, `@OneToMany`, `@Index`). Для запросов есть методы репозитория (`find`, `findOne`, `save`, `update`, `delete`), `QueryBuilder` для сложных случаев и `DataSource` для транзакций. Схема в проде меняется **миграциями** (`typeorm migration:generate` / `migration:run`), а `synchronize: true` используют только локально — в проде он может удалить столбцы с данными.

## Вопрос

Как подключить TypeORM к NestJS и как с ним работать?

## Установка и корневой модуль

```bash
npm install @nestjs/typeorm typeorm pg
```

```ts
@Module({
  imports: [
    TypeOrmModule.forRootAsync({
      inject: [ConfigService],
      useFactory: (config: ConfigService) => ({
        type: 'postgres',
        url: config.getOrThrow('DATABASE_URL'),
        autoLoadEntities: true,              // entity из forFeature подхватываются сами
        synchronize: false,                  // только миграции
        extra: { max: 10 },                  // размер пула pg
        logging: config.get('NODE_ENV') === 'development' ? ['query', 'error'] : ['error'],
      }),
    }),
  ],
})
export class AppModule {}
```

## Entity

```ts
@Entity('users')
export class User {
  @PrimaryGeneratedColumn('uuid')
  id: string;

  @Index({ unique: true })
  @Column({ type: 'citext' })
  email: string;

  @Column({ length: 100 })
  name: string;

  @Column({ select: false })              // не выбирается по умолчанию
  passwordHash: string;

  @OneToMany(() => Order, (order) => order.user)
  orders: Order[];

  @CreateDateColumn({ type: 'timestamptz' })
  createdAt: Date;
}

@Entity('orders')
@Index(['user', 'createdAt'])
export class Order {
  @PrimaryGeneratedColumn('uuid') id: string;
  @Column({ type: 'numeric', precision: 12, scale: 2 }) total: string;   // numeric → string в pg
  @ManyToOne(() => User, (u) => u.orders, { onDelete: 'CASCADE' }) user: User;
  @CreateDateColumn({ type: 'timestamptz' }) createdAt: Date;
}
```

## Репозиторий в сервисе

```ts
@Module({ imports: [TypeOrmModule.forFeature([User])], providers: [UsersService], exports: [UsersService] })
export class UsersModule {}

@Injectable()
export class UsersService {
  constructor(@InjectRepository(User) private readonly users: Repository<User>) {}

  findOne(id: string) {
    return this.users.findOne({ where: { id }, relations: { orders: true } });
  }

  async create(dto: CreateUserDto) {
    const user = this.users.create({ ...dto, passwordHash: await hash(dto.password) });
    return this.users.save(user);
  }

  topCustomers(limit = 10) {
    return this.users
      .createQueryBuilder('u')
      .leftJoin('u.orders', 'o')
      .select(['u.id', 'u.email'])
      .addSelect('COALESCE(SUM(o.total), 0)', 'revenue')
      .groupBy('u.id')
      .orderBy('revenue', 'DESC')
      .limit(limit)
      .getRawMany();
  }
}
```

## Миграции

```ts
// data-source.ts — для CLI
export default new DataSource({
  type: 'postgres',
  url: process.env.DATABASE_URL,
  entities: ['dist/**/*.entity.js'],
  migrations: ['dist/migrations/*.js'],
});
```

```bash
npx typeorm migration:generate src/migrations/AddUserName -d dist/data-source.js
npx typeorm migration:run -d dist/data-source.js
```

Сгенерированную миграцию обязательно просматривают: TypeORM может предложить `DROP COLUMN` + `ADD COLUMN` вместо переименования.

## Подводные камни

| Ловушка | Решение |
| --- | --- |
| `synchronize: true` в проде | Миграции |
| `numeric`/`bigint` приходят строками | Трансформер столбца или осознанная работа со строками |
| `save()` делает лишний `SELECT` и обновляет все поля | `update()`/`insert()` для простых операций |
| Ленивые связи и `eager: true` | Явные `relations` или join в QueryBuilder |
| N+1 при обращении к связям в цикле | Загрузка связей одним запросом |

## Частые ошибки

- Забыть `forFeature([Entity])` — `@InjectRepository` не найдёт репозиторий.
- Возвращать entity с `passwordHash` (используйте `select: false` и DTO ответа).
- Мокать в тестах `Repository` без токена `getRepositoryToken(User)`.

## Что важно помнить

- `forRootAsync` в корне, `forFeature` в фичах, `@InjectRepository` в сервисах.
- Entity-классы с декораторами описывают схему.
- В проде — только миграции.

## Мини-шпаргалка

- `TypeOrmModule.forRootAsync({ useFactory: () => ({ type, url, autoLoadEntities }) })`.
- `TypeOrmModule.forFeature([User])`.
- `@InjectRepository(User) repo: Repository<User>`.
- `createQueryBuilder`, `getRepositoryToken(User)` в тестах.
