# Когда использовать @Req и @Res

> [!NOTE]
> `@Req()` и `@Res()` дают доступ к **платформенным объектам** запроса и ответа (Express или Fastify). `@Req()` безопасен, но обычно не нужен: для частей запроса есть `@Body`, `@Query`, `@Param`, `@Headers`, `@Ip`, а для пользователя — свой декоратор. `@Res()` опаснее: при его использовании Nest переходит в **library-specific mode** — перестаёт сам отправлять ответ, и метод обязан вызвать `res.json()`/`res.send()`, иначе запрос зависнет; при этом не работают interceptors, преобразующие результат, и `@HttpCode`. Если нужно лишь поставить cookie, заголовок или статус динамически, используют **`@Res({ passthrough: true })`** — объект доступен, а `return` продолжает работать. Полный `@Res()` оправдан для потоковых ответов, которые нельзя выразить через `StreamableFile`, проксирования и интеграций со сторонними обработчиками.

## Вопрос

Когда стоит использовать `@Req()` и `@Res()` в NestJS?

## @Req — чаще есть лучший вариант

```ts
// ✗
@Get()
list(@Req() req: Request) {
  return this.service.list(req.query.page, (req as any).user.id);
}

// ✓
@Get()
list(@Query() query: ListDto, @CurrentUser() user: AuthUser) {
  return this.service.list(query, user.id);
}
```

`@Req()` оправдан для `req.rawBody` (проверка подписи вебхука), сессии `express-session`, редких платформенных полей.

```ts
// main.ts: NestFactory.create(AppModule, { rawBody: true })
@Post('webhooks/stripe')
handle(@Req() req: RawBodyRequest<Request>, @Headers('stripe-signature') sig: string) {
  return this.payments.verifyAndHandle(req.rawBody!, sig);
}
```

## @Res({ passthrough: true })

```ts
@Post('logout')
@HttpCode(204)
logout(@Res({ passthrough: true }) res: Response) {
  res.clearCookie('refresh_token', { path: '/auth' });
}

@Get(':id')
async findOne(@Param('id') id: string, @Res({ passthrough: true }) res: Response) {
  const { data, etag } = await this.service.findWithEtag(id);
  res.setHeader('ETag', etag);
  return data;                      // стандартная отправка сохраняется
}
```

## Полный @Res

```ts
@Get('legacy-export')
export(@Res() res: Response) {
  res.setHeader('Content-Type', 'text/csv');
  const cursor = this.reports.cursor();
  cursor.pipe(csvStringify()).pipe(res);   // Nest не отправляет ответ — это делаем мы
}
```

## Сравнение

| Режим | `return` работает | Interceptors (map ответа) | `@HttpCode` | Переносимость |
| --- | --- | --- | --- | --- |
| Без `@Res` | Да | Да | Да | Express и Fastify |
| `@Res({ passthrough: true })` | Да | Да | Да | Код зависит от API платформы |
| `@Res()` | Нет | Нет | Нет | Только одна платформа |

## Альтернативы

| Нужно | Без `@Res` |
| --- | --- |
| Статус | `@HttpCode()` или исключение |
| Статический заголовок | `@Header()` |
| Файл | `StreamableFile` |
| Редирект | `@Redirect()` |
| Cookie | `@Res({ passthrough: true })` |
| Поток событий | `@Sse()` |

## Частые ошибки

- `@Res()` + `return value` — ответ не отправится, клиент ждёт до таймаута.
- `@Res()` ради одной cookie.
- Типы `Request`/`Response` из глобального DOM вместо `express` — неправильные типы.
- `@Req()` для чтения `req.user` во всех методах.

## Что важно помнить

- Сначала специализированные декораторы, `@Req` — в редких случаях.
- `@Res()` отключает стандартную обработку ответа.
- `passthrough: true` — компромисс для cookies и заголовков.

## Мини-шпаргалка

- `@Req() req: Request` (из `express`).
- `@Res({ passthrough: true }) res: Response`.
- `@Res()` → обязательно `res.send/json/end`.
- Файлы — `StreamableFile`.
