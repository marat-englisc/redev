# Как получать params, query, body и headers

> [!NOTE]
> NestJS предоставляет **parameter decorators** для частей запроса: `@Param()` — параметры пути (`/users/:id`), `@Query()` — строка запроса (`?page=2`), `@Body()` — тело, `@Headers()` — заголовки, `@Ip()`, `@HostParam()`, а также `@Req()`/`@Res()` для «сырых» объектов платформы. Каждый декоратор можно вызвать с именем поля (`@Query('page')`) или без него (весь объект), и к каждому можно подключить **pipes**: `@Param('id', ParseIntPipe)`. Важно: **params и query всегда приходят строками** (`'42'`, `'true'`), поэтому их нужно преобразовывать pipes, DTO с `transform: true` или схемой Zod с coercion. Вместо ручного разбора заголовка `Authorization` в каждом методе используют guard и [декоратор текущего пользователя](<../07. Middleware, interceptors и request lifecycle/06. Что такое custom decorator в NestJS.md>).

## Вопрос

Как получить параметры пути, query, тело и заголовки запроса?

## Параметры пути

```ts
// GET /users/42
@Get(':id')
findOne(@Param('id', ParseIntPipe) id: number) {   // '42' → 42, 'abc' → 400
  return this.usersService.findOne(id);
}

// GET /orgs/acme/projects/7
@Get(':org/projects/:projectId')
findProject(@Param() params: { org: string; projectId: string }) {}
```

## Query

```ts
// GET /users?page=2&limit=20
@Get()
findAll(
  @Query('page', new DefaultValuePipe(1), ParseIntPipe) page: number,
  @Query('limit', new DefaultValuePipe(20), ParseIntPipe) limit: number,
) {}

// сложный query — объект с валидацией
@Get()
findAll(@Query() query: ListUsersQueryDto) {}
```

```ts
export class ListUsersQueryDto {
  @Type(() => Number) @IsInt() @Min(1) page = 1;
  @Type(() => Number) @IsInt() @Min(1) @Max(100) limit = 20;
  @IsOptional() @IsString() search?: string;
  @IsOptional() @IsIn(['createdAt', 'email']) sortBy: 'createdAt' | 'email' = 'createdAt';
}
```

Массивы: `?tag=a&tag=b` придут как `['a', 'b']`, а `?tag=a` — как строка `'a'`; для единообразия используют `ParseArrayPipe` или трансформацию в DTO.

## Body

```ts
@Post()
create(@Body() dto: CreateUserDto) {}

@Patch(':id')
update(@Param('id', ParseIntPipe) id: number, @Body() dto: UpdateUserDto) {}

@Post('bulk')
createMany(@Body(new ParseArrayPipe({ items: CreateUserDto, whitelist: true })) dtos: CreateUserDto[]) {}
```

Тело парсится платформой (JSON и `urlencoded` по умолчанию); лимит размера настраивается (`app.useBodyParser('json', { limit: '1mb' })` для Express).

## Headers

```ts
@Get()
list(
  @Headers('accept-language') lang = 'ru',
  @Headers('x-request-id') requestId?: string,
) {}
```

Имена заголовков — в нижнем регистре.

## IP и host

```ts
@Post('login')
login(@Ip() ip: string, @Body() dto: LoginDto) {}   // за прокси нужен trust proxy

@Controller({ host: ':tenant.example.com' })
export class TenantController {
  @Get() info(@HostParam('tenant') tenant: string) {}
}
```

## Сводная таблица

| Декоратор | Источник | Тип по умолчанию |
| --- | --- | --- |
| `@Param('x')` | `/path/:x` | `string` |
| `@Query('x')` | `?x=...` | `string` или `string[]` |
| `@Body()` | Тело | Распарсенный JSON |
| `@Headers('x')` | Заголовок | `string` |
| `@Ip()` | IP клиента | `string` |
| `@HostParam('x')` | Поддомен | `string` |
| `@Req()` / `@Res()` | Объекты платформы | `Request` / `Response` |

## Частые ошибки

- Считать `@Param('id')` числом без pipe.
- `Number(query.page)` вручную в каждом методе.
- Читать и проверять токен из `@Headers('authorization')` в контроллере вместо guard.
- `@Req()` для получения body/query — теряется декларативность и переносимость.
- `@Body() body: any`.

## Что важно помнить

- Каждая часть запроса — свой декоратор.
- Params и query — строки; преобразуйте pipes или DTO.
- Авторизация — в guards, а не в разборе заголовков.

## Мини-шпаргалка

- `@Param('id', ParseIntPipe | ParseUUIDPipe)`.
- `@Query() dto` + `ValidationPipe({ transform: true })`.
- `@Body() dto`.
- `@Headers('x-request-id')`, `@Ip()`.
