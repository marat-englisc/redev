# Как возвращать response из controller

> [!NOTE]
> В стандартном режиме метод контроллера просто **возвращает значение** — объект, массив, примитив, `Promise` или RxJS `Observable`, — а Nest сериализует его в JSON (строки и примитивы отправляются как есть) и выставляет статус: **200**, для `POST` — **201**, при `undefined` — пустое тело. Статус меняют `@HttpCode()`, заголовки — `@Header()`, ошибки выражают **исключениями** (`throw new NotFoundException()`), которые exception filter превращает в ответ. Этот режим совместим с interceptors (трансформация ответа, кеш, логирование) и с любым адаптером. Для динамических заголовков, cookies и статусов используют `@Res({ passthrough: true })`, для файлов — `StreamableFile`. Полный ручной контроль через `@Res()` без `passthrough` отключает стандартную обработку — им пользуются редко.

## Вопрос

Как правильно возвращать ответ из метода контроллера?

## Стандартный режим

```ts
@Get(':id')
async findOne(@Param('id', ParseIntPipe) id: number): Promise<UserResponseDto> {
  const user = await this.usersService.findOne(id);   // NotFoundException внутри → 404
  return user;                                         // 200 + JSON
}

@Post()
create(@Body() dto: CreateUserDto) {
  return this.usersService.create(dto);                // 201
}

@Delete(':id')
@HttpCode(204)
async remove(@Param('id', ParseIntPipe) id: number): Promise<void> {
  await this.usersService.remove(id);                  // 204 без тела
}
```

## Ошибки — исключениями

```ts
async findOne(id: number) {
  const user = await this.repo.findById(id);
  if (!user) throw new NotFoundException(`User ${id} not found`);
  return user;
}
```

```json
{ "statusCode": 404, "message": "User 1 not found", "error": "Not Found" }
```

Формат ошибок унифицируют [exception filter](<../05. Pipes, validation и exception filters/07. Как сделать единый формат ошибок.md>).

## Динамические заголовки и cookies

```ts
@Post('login')
@HttpCode(200)
async login(@Body() dto: LoginDto, @Res({ passthrough: true }) res: Response) {
  const { accessToken, refreshToken } = await this.auth.login(dto);
  res.cookie('refresh_token', refreshToken, { httpOnly: true, secure: true, sameSite: 'lax', path: '/auth' });
  res.setHeader('X-Auth-Version', '2');
  return { accessToken };                    // return по-прежнему работает
}
```

## Файлы — StreamableFile

```ts
@Get('reports/:id')
async download(@Param('id') id: string): Promise<StreamableFile> {
  const stream = await this.reports.getStream(id);
  return new StreamableFile(stream, {
    type: 'application/pdf',
    disposition: `attachment; filename="report-${id}.pdf"`,
  });
}
```

`StreamableFile` работает с interceptors и обоими адаптерами, в отличие от `res.download()`.

## Что можно вернуть

| Значение | Ответ |
| --- | --- |
| Объект / массив | JSON |
| Строка, число, boolean | Тело как есть (`text/html` для строк в Express) |
| `undefined` / `void` | Пустое тело |
| `Promise<T>` | Дожидается и отправляет `T` |
| `Observable<T>` | Последнее значение потока |
| `StreamableFile` | Поток файла |

## Форма ответа

```ts
// ✗ отдаём сущность целиком
return this.prisma.user.findUnique({ where: { id } });   // passwordHash уйдёт клиенту

// ✓ выбираем поля или используем DTO ответа
return this.prisma.user.findUnique({ where: { id }, select: { id: true, email: true, name: true } });
```

## Частые ошибки

- `@Res()` без `passthrough` и `return` — запрос «повисает», interceptors не работают.
- `res.status(404).json(...)` вместо исключения.
- Возврат ORM-сущности со служебными и секретными полями.
- `bigint` в ответе — `JSON.stringify` бросит ошибку (нужно преобразовать в строку).

## Что важно помнить

- Возвращайте значение — Nest сделает остальное.
- Ошибки — исключениями, статус — `@HttpCode`.
- Cookies и динамические заголовки — `@Res({ passthrough: true })`, файлы — `StreamableFile`.

## Мини-шпаргалка

- `return value` → 200/201 + JSON.
- `throw new XxxException()`.
- `@HttpCode(204)`.
- `@Res({ passthrough: true })`.
- `new StreamableFile(stream, { type, disposition })`.
