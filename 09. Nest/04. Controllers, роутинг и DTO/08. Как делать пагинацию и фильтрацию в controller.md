# Как делать пагинацию и фильтрацию в controller

> [!NOTE]
> Параметры списка (страница, размер, поиск, фильтры, сортировка) приходят в **query** и описываются **одним DTO** (или Zod-схемой) с валидацией и преобразованием типов: `page` и `limit` — целые числа с ограничениями (`limit` ≤ 100), `sortBy` — только из **белого списка** полей, `sortOrder` — `asc`/`desc`, фильтры — опциональные поля с конкретными типами. Контроллер передаёт валидированный объект в сервис, сервис строит запрос к БД и возвращает **единый формат** `{ items, meta }`. Для небольших списков подходит offset-пагинация (`page`/`limit` + `total`), для лент и больших таблиц — **cursor (keyset)** пагинация (`cursor` + `limit` → `nextCursor`), которая не замедляется на глубоких страницах. Сортировку по произвольному полю из query без белого списка делать нельзя — это и уязвимость, и способ «положить» базу запросом без индекса.

## Вопрос

Как реализовать пагинацию, фильтрацию и сортировку списка в NestJS?

## Query DTO

```ts
export class ListProductsQueryDto {
  @Type(() => Number) @IsInt() @Min(1)
  page = 1;

  @Type(() => Number) @IsInt() @Min(1) @Max(100)
  limit = 20;

  @IsOptional() @IsString() @MaxLength(100)
  search?: string;

  @IsOptional() @Type(() => Number) @IsInt()
  categoryId?: number;

  @IsOptional() @Type(() => Number) @Min(0)
  minPrice?: number;

  @IsOptional() @Transform(({ value }) => value === 'true' || value === true)
  @IsBoolean()
  inStock?: boolean;

  @IsIn(['createdAt', 'price', 'title'])
  sortBy: 'createdAt' | 'price' | 'title' = 'createdAt';

  @IsIn(['asc', 'desc'])
  sortOrder: 'asc' | 'desc' = 'desc';
}
```

`@Type(() => Boolean)` превращает строку `'false'` в `true` (непустая строка) — для boolean из query нужна явная трансформация, как выше.

## Контроллер

```ts
@Get()
findAll(@Query() query: ListProductsQueryDto) {     // ValidationPipe({ transform: true })
  return this.productsService.findAll(query);
}
```

## Сервис (Prisma)

```ts
async findAll(q: ListProductsQueryDto): Promise<Paginated<ProductListItem>> {
  const where: Prisma.ProductWhereInput = {
    ...(q.search && { title: { contains: q.search, mode: 'insensitive' } }),
    ...(q.categoryId && { categoryId: q.categoryId }),
    ...(q.minPrice !== undefined && { price: { gte: q.minPrice } }),
    ...(q.inStock !== undefined && { stock: q.inStock ? { gt: 0 } : 0 }),
  };

  const [items, total] = await this.prisma.$transaction([
    this.prisma.product.findMany({
      where,
      orderBy: [{ [q.sortBy]: q.sortOrder }, { id: 'asc' }],   // tie-breaker
      skip: (q.page - 1) * q.limit,
      take: q.limit,
      select: { id: true, title: true, price: true, stock: true },
    }),
    this.prisma.product.count({ where }),
  ]);

  return { items, meta: { page: q.page, limit: q.limit, total, totalPages: Math.ceil(total / q.limit) } };
}
```

## Cursor-пагинация

```ts
export class FeedQueryDto {
  @IsOptional() @IsString() cursor?: string;   // непрозрачный base64 { createdAt, id }
  @Type(() => Number) @IsInt() @Min(1) @Max(50) limit = 20;
}

async feed(q: FeedQueryDto) {
  const after = q.cursor ? decodeCursor(q.cursor) : undefined;
  const rows = await this.prisma.post.findMany({
    where: after
      ? { OR: [{ createdAt: { lt: after.createdAt } }, { createdAt: after.createdAt, id: { lt: after.id } }] }
      : {},
    orderBy: [{ createdAt: 'desc' }, { id: 'desc' }],
    take: q.limit + 1,                          // +1 — узнать, есть ли следующая страница
  });
  const hasMore = rows.length > q.limit;
  const items = rows.slice(0, q.limit);
  return { items, nextCursor: hasMore ? encodeCursor(items.at(-1)!) : null };
}
```

## Общий тип ответа

```ts
export interface Paginated<T> {
  items: T[];
  meta: { page: number; limit: number; total: number; totalPages: number };
}
```

## Частые ошибки

- `orderBy: { [query.sortBy]: ... }` без белого списка.
- Нет верхней границы `limit`.
- Сортировка без уникального tie-breaker — дубли и пропуски между страницами.
- `@Type(() => Boolean)` для `?inStock=false`.
- Точный `count` на огромной таблице при каждом запросе.

## Что важно помнить

- Параметры списка — один валидируемый query DTO.
- Сортировка — только по разрешённым полям, с tie-breaker.
- Offset — для небольших списков, cursor — для лент и больших данных.

## Мини-шпаргалка

- `@Type(() => Number) @IsInt() @Min(1) @Max(100) limit = 20`.
- `@IsIn([...]) sortBy`.
- `skip/take` + `count` → `{ items, meta }`.
- Cursor: `take: limit + 1`, `nextCursor`.
