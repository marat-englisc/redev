# Какие бывают route decorators

> [!NOTE]
> **Route decorators** привязывают методы контроллера к HTTP-методам и путям: `@Get()`, `@Post()`, `@Put()`, `@Patch()`, `@Delete()`, `@Options()`, `@Head()`, `@All()`, а также `@Search()`. Путь может содержать **параметры** (`':id'`), несколько параметров (`':userId/orders/:orderId'`) и **wildcard**: в NestJS 11+ с Express 5 используется именованная форма `'files/*path'` (старый синтаксис `'files/*'` устарел). Рядом с ними работают декораторы ответа: `@HttpCode(204)` меняет статус по умолчанию (200 для всех методов, кроме `POST` — 201), `@Header('Cache-Control', 'no-store')` добавляет заголовок, `@Redirect(url, 302)` делает редирект, `@Sse()` — Server-Sent Events. Порядок объявления важен: статические пути (`'me'`, `'stats'`) объявляют **раньше** параметризованных (`':id'`).

## Вопрос

Какие route decorators есть в NestJS и как задавать пути?

## HTTP-методы

```ts
@Controller('articles')
export class ArticlesController {
  @Get()            findAll() {}               // GET    /articles
  @Get('popular')   popular() {}               // GET    /articles/popular  — раньше :id!
  @Get(':id')       findOne() {}               // GET    /articles/:id
  @Post()           create() {}                // POST   /articles          — 201
  @Put(':id')       replace() {}               // PUT    /articles/:id      — полная замена
  @Patch(':id')     update() {}                // PATCH  /articles/:id      — частичное обновление
  @Delete(':id')    remove() {}                // DELETE /articles/:id
  @Post(':id/publish') publish() {}            // действие над ресурсом
}
```

## Параметры и wildcard

```ts
@Get(':userId/orders/:orderId')
findOrder(@Param('userId') userId: string, @Param('orderId') orderId: string) {}

@Get('files/*path')                     // Express 5: именованный wildcard
getFile(@Param('path') path: string[]) {} // сегменты пути

@Get(['list', 'all'])                   // несколько путей
list() {}
```

## Статус, заголовки, редирект

```ts
@Delete(':id')
@HttpCode(HttpStatus.NO_CONTENT)                   // 204 вместо 200
remove(@Param('id') id: string) {}

@Post('login')
@HttpCode(200)                                     // логин — не создание ресурса
login(@Body() dto: LoginDto) {}

@Get('export')
@Header('Content-Type', 'text/csv')
@Header('Content-Disposition', 'attachment; filename="report.csv"')
export() { return 'id,name\n1,Anna'; }

@Get('docs')
@Redirect('https://docs.example.com', 302)
docs(@Query('version') version?: string) {
  if (version === '2') return { url: 'https://docs.example.com/v2' };   // динамический редирект
}
```

## Server-Sent Events

```ts
@Sse('events')
events(): Observable<MessageEvent> {
  return interval(1000).pipe(map((n) => ({ data: { tick: n } })));
}
```

## Порядок маршрутов

```ts
// ✗ GET /users/me попадёт в findOne('me')
@Get(':id') findOne() {}
@Get('me')  me() {}

// ✓
@Get('me')  me() {}
@Get(':id') findOne() {}
```

Альтернатива — ограничить параметр через pipe (`ParseUUIDPipe`), тогда `'me'` вызовет 400, а не попадёт в обработчик — но порядок всё равно стоит соблюдать.

## Декораторы ответа

| Декоратор | Что делает |
| --- | --- |
| `@HttpCode(n)` | Статус по умолчанию |
| `@Header(name, value)` | Статический заголовок |
| `@Redirect(url, status)` | Редирект; метод может вернуть `{ url, statusCode }` |
| `@Sse(path)` | Поток SSE |
| `@Render(view)` | Рендер шаблона (MVC) |

## Частые ошибки

- `@Get(':id')` выше `@Get('me')`.
- Старый синтаксис wildcard `'*'` с Express 5.
- `POST /login` возвращает 201 — без `@HttpCode(200)`.
- Глаголы в путях (`/getUsers`, `/deleteUser`) вместо HTTP-методов.

## Что важно помнить

- Метод + путь задаются декоратором, итоговый путь складывается с prefix и version.
- Статус по умолчанию: 200, у `POST` — 201; меняется `@HttpCode`.
- Статические пути раньше параметризованных.

## Мини-шпаргалка

- `@Get/@Post/@Put/@Patch/@Delete/@All(path)`.
- `':id'`, `'files/*path'`.
- `@HttpCode(204)`, `@Header()`, `@Redirect()`.
- `@Sse()` — поток событий.
