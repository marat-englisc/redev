# Как загружать файлы в NestJS

> [!NOTE]
> Для приёма файлов (`multipart/form-data`) в Express-адаптере NestJS использует **Multer** через interceptors: `FileInterceptor('file')` — один файл, `FilesInterceptor('files', 10)` — массив, `FileFieldsInterceptor` — несколько полей, `AnyFilesInterceptor` — любые. Файл извлекается декоратором `@UploadedFile()` / `@UploadedFiles()`, а проверяется `ParseFilePipe` с валидаторами `MaxFileSizeValidator` и `FileTypeValidator` (или `ParseFilePipeBuilder`). Ограничения размера стоит задавать и в Multer (`limits.fileSize`) — он прервёт чтение потока, а не только отклонит файл после загрузки. По умолчанию файл хранится **в памяти** (`buffer`); для больших файлов используют `diskStorage` или потоковую загрузку, а в продакшене — **прямую загрузку в объектное хранилище** (S3) через presigned URL, чтобы файлы вообще не шли через API. Тип файла проверяют не только по `mimetype` из заголовка (его легко подделать), но и по содержимому («magic numbers»).

## Вопрос

Как принимать и валидировать загружаемые файлы в NestJS?

## Один файл

```ts
@Post('avatar')
@UseInterceptors(FileInterceptor('file', { limits: { fileSize: 2 * 1024 * 1024 } }))
uploadAvatar(
  @UploadedFile(
    new ParseFilePipe({
      validators: [
        new MaxFileSizeValidator({ maxSize: 2 * 1024 * 1024, message: 'Max 2 MB' }),
        new FileTypeValidator({ fileType: /^image\/(png|jpeg|webp)$/ }),
      ],
    }),
  )
  file: Express.Multer.File,
  @CurrentUser() user: AuthUser,
) {
  return this.avatars.save(user.id, file);
}
```

```ts
// file: { fieldname, originalname, mimetype, size, buffer }
```

Типы Multer: `npm i -D @types/multer`.

## Несколько файлов и поля формы

```ts
@Post('gallery')
@UseInterceptors(FilesInterceptor('photos', 10))
upload(@UploadedFiles() photos: Express.Multer.File[], @Body() dto: CreateGalleryDto) {}

@Post('document')
@UseInterceptors(FileFieldsInterceptor([{ name: 'passport', maxCount: 1 }, { name: 'selfie', maxCount: 1 }]))
kyc(@UploadedFiles() files: { passport?: Express.Multer.File[]; selfie?: Express.Multer.File[] }) {}
```

Текстовые поля формы приходят в `@Body()` **строками** — DTO с `@Type()`-преобразованиями.

## ParseFilePipeBuilder

```ts
@UploadedFile(
  new ParseFilePipeBuilder()
    .addFileTypeValidator({ fileType: 'application/pdf' })
    .addMaxSizeValidator({ maxSize: 10 * 1024 * 1024 })
    .build({ errorHttpStatusCode: HttpStatus.UNPROCESSABLE_ENTITY, fileIsRequired: true }),
)
file: Express.Multer.File
```

## Хранение

```ts
// на диск
MulterModule.register({
  storage: diskStorage({
    destination: './uploads',
    filename: (_req, file, cb) => cb(null, `${randomUUID()}${extname(file.originalname)}`),
  }),
});
```

| Способ | Плюсы | Минусы |
| --- | --- | --- |
| Память (`buffer`) | Просто, удобно передать в S3 SDK | Большие файлы съедают RAM |
| Диск | Не держит в памяти | Не работает при нескольких инстансах без общего хранилища |
| Поток в S3 | Масштабируется | Сложнее обработка ошибок |
| Presigned URL (клиент → S3 напрямую) | API не передаёт байты | Нужна проверка после загрузки |

## Presigned URL

```ts
@Post('uploads')
async createUpload(@Body() dto: CreateUploadDto, @CurrentUser() user: AuthUser) {
  const key = `users/${user.id}/${randomUUID()}`;
  const url = await getSignedUrl(this.s3, new PutObjectCommand({
    Bucket: this.bucket, Key: key, ContentType: dto.contentType,
  }), { expiresIn: 300 });
  return { url, key };       // клиент делает PUT по url, затем сообщает API о завершении
}
```

## Безопасность

- Ограничение размера в `limits` Multer и в прокси (nginx `client_max_body_size`).
- Белый список типов; проверка содержимого (`file-type` по `buffer`).
- Имя файла генерировать на сервере, не использовать `originalname` в пути (path traversal).
- Не отдавать загруженные файлы с того же домена, что и приложение, без `Content-Disposition`/`Content-Type` — риск XSS через SVG/HTML.
- Антивирусная проверка для пользовательских документов.

## Fastify

`FileInterceptor` основан на Multer и работает только с Express; для Fastify используют `@fastify/multipart` и собственную обёртку.

## Частые ошибки

- Нет `limits.fileSize` — сервер принимает гигабайтный файл, прежде чем pipe его отклонит.
- Доверять `mimetype` из запроса.
- Хранить файлы на локальном диске контейнера — пропадут при перезапуске.
- Использовать `originalname` как путь сохранения.

## Что важно помнить

- `FileInterceptor` + `@UploadedFile` + `ParseFilePipe`.
- Размер — ограничивать на уровне Multer, тип — проверять по содержимому.
- В проде — объектное хранилище, часто через presigned URL.

## Мини-шпаргалка

- `FileInterceptor('file', { limits })`, `FilesInterceptor`, `FileFieldsInterceptor`.
- `ParseFilePipe` + `MaxFileSizeValidator`, `FileTypeValidator`.
- `Express.Multer.File` (`@types/multer`).
- Presigned URL для больших файлов.
