# Что такое controller в NestJS

> [!NOTE]
> **Контроллер** — класс с декоратором `@Controller('path')`, который отвечает за **HTTP-слой**: принимает запросы на свои маршруты, извлекает и валидирует входные данные (через parameter decorators и pipes), вызывает сервис и возвращает результат. Методы помечаются `@Get`, `@Post`, `@Patch`, `@Put`, `@Delete`; итоговый путь = global prefix + версия + префикс контроллера + путь метода. Контроллер должен быть **тонким**: никаких запросов к БД, бизнес-правил и форматирования ответов вручную — это задачи сервисов, interceptors и filters. Контроллеры регистрируются в `controllers` модуля и, как провайдеры, получают зависимости через конструктор. Аналоги для других транспортов — resolvers (GraphQL), gateways (WebSocket), `@MessagePattern`-обработчики (микросервисы).

## Вопрос

Что такое контроллер в NestJS и за что он отвечает?

## Пример

```ts
@Controller('products')
export class ProductsController {
  constructor(private readonly productsService: ProductsService) {}

  @Get()
  findAll(@Query() query: ListProductsQueryDto) {
    return this.productsService.findAll(query);
  }

  @Get(':id')
  findOne(@Param('id', ParseUUIDPipe) id: string) {
    return this.productsService.findOne(id);
  }

  @Post()
  @UseGuards(JwtAuthGuard, RolesGuard)
  @Roles(['admin'])
  create(@Body() dto: CreateProductDto) {
    return this.productsService.create(dto);
  }

  @Patch(':id')
  update(@Param('id', ParseUUIDPipe) id: string, @Body() dto: UpdateProductDto) {
    return this.productsService.update(id, dto);
  }

  @Delete(':id')
  @HttpCode(204)
  async remove(@Param('id', ParseUUIDPipe) id: string) {
    await this.productsService.remove(id);
  }
}

@Module({ controllers: [ProductsController], providers: [ProductsService] })
export class ProductsModule {}
```

С `app.setGlobalPrefix('api')` маршруты: `GET /api/products`, `GET /api/products/:id` и т. д.

## Ответственность

| Контроллер делает | Контроллер не делает |
| --- | --- |
| Объявляет маршруты и HTTP-методы | Запросы к БД |
| Принимает DTO, параметры, заголовки | Бизнес-правила и расчёты |
| Задаёт статус, заголовки, редиректы | Ручную валидацию полей |
| Подключает guards, pipes, interceptors | Обработку ошибок `try/catch` → `res.status()` |
| Вызывает сервис | Знание о том, как хранятся данные |

## Опции @Controller

```ts
@Controller({ path: 'products', version: '2', host: 'admin.example.com' })
```

- `path` — префикс маршрутов (можно массив).
- `version` — версия API ([versioning](<../02. CLI, структура проекта и bootstrap/04. Как настроить global prefix, CORS и versioning.md>)).
- `host` — маршрутизация по поддомену.

## Тонкий контроллер

```ts
// ✗ толстый контроллер
@Post()
async create(@Body() body: any) {
  if (!body.email?.includes('@')) throw new BadRequestException();
  const exists = await this.prisma.user.findUnique({ where: { email: body.email } });
  if (exists) throw new ConflictException();
  const hash = await bcrypt.hash(body.password, 10);
  return this.prisma.user.create({ data: { ...body, password: hash } });
}

// ✓
@Post()
create(@Body() dto: CreateUserDto) {
  return this.usersService.register(dto);
}
```

Бизнес-логика в сервисе переиспользуется из GraphQL, очередей и CLI-скриптов и тестируется без HTTP.

## Частые ошибки

- Контроллер не добавлен в `controllers` модуля — 404.
- Prisma/TypeORM прямо в контроллере.
- `body: any` без DTO.
- Порядок маршрутов: `@Get(':id')` объявлен раньше `@Get('stats')` — `stats` попадёт в `:id` (в Express-адаптере совпадение по порядку объявления).

## Что важно помнить

- Контроллер — HTTP-адаптер к сервисам.
- Путь = prefix + version + controller path + method path.
- Тонкий контроллер, логика — в сервисах.

## Мини-шпаргалка

- `@Controller('path')` + `@Get/@Post/@Patch/@Put/@Delete`.
- `controllers: [X]` в модуле.
- Статические пути (`'stats'`) — раньше параметризованных (`':id'`).
- Логика — в сервисе.
