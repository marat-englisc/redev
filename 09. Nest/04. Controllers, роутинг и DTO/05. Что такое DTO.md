# Что такое DTO

> [!NOTE]
> **DTO (Data Transfer Object)** — описание формы данных, которые пересекают границу приложения: тело запроса, query-параметры, ответ API. В NestJS DTO принято оформлять **классами**, а не интерфейсами: класс существует в рантайме, поэтому `ValidationPipe` может по его декораторам (`class-validator`) проверить и преобразовать вход (`class-transformer`), а `@nestjs/swagger` — сгенерировать OpenAPI-схему. Для производных DTO используют **mapped types**: `PartialType` (все поля необязательны — для `PATCH`), `PickType`, `OmitType`, `IntersectionType` — из `@nestjs/swagger`, если проект документируется Swagger, иначе из `@nestjs/mapped-types`. DTO — это **контракт API**, а не модель БД: входной DTO не должен содержать полей, которые клиент не вправе задавать (`role`, `id`, `createdAt`), а выходной — секретов (`passwordHash`). Альтернатива классам — схемы Zod через Standard Schema.

## Вопрос

Что такое DTO и как их проектировать в NestJS?

## DTO запроса

```ts
export class CreateUserDto {
  @IsEmail()
  @Transform(({ value }) => value?.trim().toLowerCase())
  email: string;

  @IsString()
  @Length(2, 100)
  name: string;

  @IsString()
  @MinLength(8)
  password: string;

  @IsOptional()
  @IsIn(['ru', 'en'])
  locale?: 'ru' | 'en';
}
```

```ts
app.useGlobalPipes(new ValidationPipe({ whitelist: true, forbidNonWhitelisted: true, transform: true }));
```

`whitelist` отбрасывает поля без декораторов — клиент не сможет прислать `role: 'admin'`.

## Mapped types

```ts
import { PartialType, OmitType, PickType, IntersectionType } from '@nestjs/swagger';

export class UpdateUserDto extends PartialType(OmitType(CreateUserDto, ['email', 'password'] as const)) {}
export class ChangeEmailDto extends PickType(CreateUserDto, ['email'] as const) {}
export class CreateAdminDto extends IntersectionType(CreateUserDto, AdminExtraDto) {}
```

Валидационные декораторы наследуются, `PartialType` добавляет `@IsOptional()` ко всем полям.

## DTO ответа

```ts
export class UserResponseDto {
  id: number;
  email: string;
  name: string;
  createdAt: Date;
}

// сервис отдаёт только нужные поля
return this.prisma.user.findUniqueOrThrow({
  where: { id },
  select: { id: true, email: true, name: true, createdAt: true },
});
```

Ответный DTO документирует форму ответа (Swagger) и защищает от утечки полей.

## Класс или интерфейс

| | Класс | Интерфейс / type |
| --- | --- | --- |
| Существует в рантайме | Да | Нет |
| Валидация `ValidationPipe` | Да | Нет — ничего не проверится |
| Swagger-схема | Да | Нет |
| Mapped types | Да | Нет |

## DTO и сущность

| DTO | Entity / модель БД |
| --- | --- |
| Контракт с клиентом | Структура хранения |
| Разный для create / update / response | Одна |
| Валидация входа | Ограничения БД |
| Без `passwordHash`, служебных полей | Содержит всё |

Связь «один DTO = одна таблица» — ловушка: при изменении схемы ломается API, а клиент получает лишние поля.

## Zod как альтернатива

```ts
export const createUserSchema = z.object({ email: z.email(), name: z.string().min(2).max(100) });
export type CreateUserDto = z.infer<typeof createUserSchema>;

@Post()
create(@Body({ schema: createUserSchema }) dto: CreateUserDto) {}
```

## Частые ошибки

- DTO-интерфейс — валидация молча не работает.
- Использовать entity как входной DTO — клиент может задать `id`, `role`.
- Нет `whitelist` — лишние поля проходят в сервис и в ORM.
- `PartialType` из `@nestjs/mapped-types` в проекте со Swagger — схема в документации неполная.

## Что важно помнить

- DTO — контракт API, оформляется классом.
- Отдельные DTO для создания, обновления и ответа.
- `whitelist` + `forbidNonWhitelisted` защищают от лишних полей.

## Мини-шпаргалка

- `class CreateXDto { @IsString() name: string }`.
- `PartialType`, `PickType`, `OmitType`, `IntersectionType`.
- `ValidationPipe({ whitelist, forbidNonWhitelisted, transform })`.
- Ответ — `select` или response DTO.
