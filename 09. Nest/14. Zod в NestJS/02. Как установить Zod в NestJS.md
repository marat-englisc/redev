# Как установить Zod в NestJS

> [!NOTE]
> Для работы достаточно пакета `zod` (Zod 4; импорт `import { z } from 'zod'`). Zod требует `strict: true` (как минимум `strictNullChecks`) в `tsconfig.json`, иначе выводимые типы теряют `null`/`undefined`. В **NestJS 12** схемы подключаются без дополнительных библиотек: глобально регистрируют `StandardSchemaValidationPipe`, а схему передают опцией `schema` в `@Body()`, `@Query()`, `@Param()`, `@MessageBody()`, `@Payload()`. В более старых версиях Nest пишут собственный `ZodValidationPipe` или используют пакет `nestjs-zod` (он же даёт `createZodDto` для Swagger). Схемы хранят рядом с фичей (`users/schemas/*.schema.ts`) или в общем пакете монорепозитория, если они разделяются с фронтендом. Если в проекте одновременно используются DTO-классы с `class-validator`, глобально можно держать оба пайпа — `ValidationPipe` проверяет классы, `StandardSchemaValidationPipe` — параметры с `schema`.

## Вопрос

Как установить и подключить Zod в NestJS-проекте?

## Установка

```bash
npm install zod
```

```json
// tsconfig.json
{ "compilerOptions": { "strict": true } }
```

## Глобальное подключение (NestJS 12)

```ts
// main.ts
app.useGlobalPipes(new StandardSchemaValidationPipe());

// или с DI
providers: [{ provide: APP_PIPE, useClass: StandardSchemaValidationPipe }]
```

```ts
@Post()
create(@Body({ schema: createUserSchema }) dto: CreateUserDto) {}

@Get()
list(@Query({ schema: listUsersQuerySchema }) query: ListUsersQuery) {}

@Get(':id')
findOne(@Param('id', { schema: z.uuid() }) id: string) {}
```

## Где хранить схемы

```text
src/users/
├── schemas/
│   ├── create-user.schema.ts      # createUserSchema + type CreateUserDto
│   ├── update-user.schema.ts
│   └── list-users-query.schema.ts
├── users.controller.ts
└── users.service.ts
```

```text
# монорепозиторий: общие схемы для фронтенда и API
packages/contracts/src/users.ts    → импортируют apps/web и apps/api
```

## Совместно с class-validator

```ts
app.useGlobalPipes(
  new ValidationPipe({ whitelist: true, transform: true }),   // DTO-классы
  new StandardSchemaValidationPipe(),                          // параметры с { schema }
);
```

Лучше выбрать один стиль для новых модулей, а смешение оставить на период миграции.

## Старые версии Nest

```bash
npm install nestjs-zod
```

```ts
class CreateUserDto extends createZodDto(createUserSchema) {}   // класс для Swagger и ZodValidationPipe
```

Или собственный pipe — см. [подключение Zod](<05. Как подключить Zod к NestJS - ZodValidationPipe и StandardSchemaValidationPipe.md>).

## Частые ошибки

- `strict: false` — `z.infer` выдаёт неточные типы.
- Схема объявлена, но параметр без `{ schema }` и pipe не подключён — данные не проверяются.
- Разные версии `zod` во фронтенде и бэкенде при общих схемах.
- Импорт из `zod/v3` по старым примерам в новом коде.

## Что важно помнить

- `npm i zod`, `strict: true`.
- NestJS 12: `StandardSchemaValidationPipe` + `@Body({ schema })`.
- Схемы — рядом с фичей или в общем пакете контрактов.

## Мини-шпаргалка

- `import { z } from 'zod'`.
- `app.useGlobalPipes(new StandardSchemaValidationPipe())`.
- `@Body({ schema })`, `@Query({ schema })`, `@Param('id', { schema })`.
- Старые версии — `nestjs-zod` или свой pipe.
