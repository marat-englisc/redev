# Как составлять валидаторы Zod по шагам

> [!NOTE]
> Хороший валидатор строится от **границы доверия** к бизнес-правилам: (1) определить, какие данные приходят извне (тело, query, params, env, вебхук, ответ внешнего API, сообщение очереди); (2) описать **форму** — поля и типы; (3) добавить **ограничения**, согласованные с базой и продуктом (длины как в `@db.VarChar(120)`, диапазоны, максимальные размеры массивов); (4) **нормализовать** (`trim`, `toLowerCase`, приведение типов для query через `coerce`/`stringbool`); (5) разделить схемы **create / update / response** через `omit`/`partial`/`extend`, убрав поля, которые клиент не вправе задавать; (6) добавить **межполевые правила** (`refine`/`superRefine` с `path`) или варианты (`discriminatedUnion`); (7) вывести **типы** (`z.input` для входа, `z.output`/`z.infer` для обработчика); (8) подключить к NestJS (`@Body({ schema })`); (9) привести **ошибки** к формату с `field`, `message`, `code`; (10) покрыть схему **тестами** на граничных значениях.

## Вопрос

Как по шагам составить хороший валидатор на Zod для NestJS?

## Шаг 1–2. Граница и форма

```ts
export const createArticleSchema = z.object({
  title: z.string(),
  content: z.string(),
  tags: z.array(z.string()),
  published: z.boolean(),
});
```

## Шаг 3. Ограничения (согласованы с БД)

```prisma
model Article {
  title   String  @db.VarChar(120)
  content String  @db.Text
}
```

```ts
export const createArticleSchema = z.object({
  title: z.string().trim().min(3).max(120),
  content: z.string().trim().min(20).max(20_000),
  tags: z.array(z.string().trim().min(1).max(30)).max(10).default([]),
  published: z.boolean().default(false),
});
```

## Шаг 4. Нормализация и query

```ts
export const listArticlesQuerySchema = z.object({
  page: z.coerce.number().int().min(1).default(1),
  limit: z.coerce.number().int().min(1).max(100).default(20),
  search: z.string().trim().min(1).max(100).optional(),
  published: z.stringbool().optional(),                       // не z.coerce.boolean()!
  sortBy: z.enum(['createdAt', 'title']).default('createdAt'),
  sortOrder: z.enum(['asc', 'desc']).default('desc'),
});

const emailField = z.string().trim().toLowerCase().pipe(z.email());
```

## Шаг 5. Create, update, response

```ts
const userBase = z.object({
  email: emailField,
  name: z.string().trim().min(2).max(100),
});

export const createUserSchema = userBase.extend({ password: z.string().min(10).max(128) });

export const updateUserSchema = userBase.omit({ email: true }).partial();      // email меняется отдельным сценарием

export const userResponseSchema = userBase.extend({ id: z.uuid(), createdAt: z.date() });   // без password
```

## Шаг 6. Межполевые правила и варианты

```ts
export const registerSchema = createUserSchema
  .extend({ confirmPassword: z.string() })
  .refine((d) => d.password === d.confirmPassword, { message: 'Passwords do not match', path: ['confirmPassword'] });

export const paymentSchema = z.discriminatedUnion('method', [
  z.object({ method: z.literal('card'), cardToken: z.string().min(10) }),
  z.object({ method: z.literal('invoice'), companyInn: z.string().regex(/^\d{10,12}$/) }),
]);
```

## Шаг 7. Типы

```ts
export type CreateArticleInput = z.input<typeof createArticleSchema>;   // tags?: string[] — для клиента/форм
export type CreateArticleDto = z.output<typeof createArticleSchema>;    // tags: string[] — для сервиса
export type ListArticlesQuery = z.output<typeof listArticlesQuerySchema>;
```

## Шаг 8. Подключение к NestJS

```ts
@Post()
create(@Body({ schema: createArticleSchema }) dto: CreateArticleDto) {
  return this.articles.create(dto);
}

@Get()
list(@Query({ schema: listArticlesQuerySchema }) query: ListArticlesQuery) {
  return this.articles.list(query);
}
```

## Шаг 9. Формат ошибок

```ts
// в ZodValidationPipe или в глобальном exception filter
issues.map((i) => ({ field: i.path.join('.'), message: i.message, code: i.code }));
```

```json
{ "statusCode": 400, "code": "VALIDATION_FAILED",
  "details": [{ "field": "tags.2", "message": "Too big: expected string to have <=30 characters", "code": "too_big" }] }
```

## Шаг 10. Тесты схемы

```ts
describe('createArticleSchema', () => {
  it('подставляет значения по умолчанию', () => {
    expect(createArticleSchema.parse({ title: 'Hello', content: 'x'.repeat(20) })).toMatchObject({ tags: [], published: false });
  });
  it('обрезает пробелы и проверяет длину', () => {
    expect(createArticleSchema.safeParse({ title: '  ab  ', content: 'x'.repeat(20) }).success).toBe(false);
  });
  it('ограничивает число тегов', () => {
    const r = createArticleSchema.safeParse({ title: 'Hello', content: 'x'.repeat(20), tags: Array(11).fill('t') });
    expect(r.success).toBe(false);
  });
});
```

## Связь с Prisma

Zod-схема входа не обязана повторять модель Prisma один в один, но ограничения должны быть **совместимы**: длины строк, обязательность, допустимые значения enum. Деньги из `z.number()` сервис превращает в `Prisma.Decimal`, а id связей проверяются форматом (`z.uuid()`) — существование записи проверяет база (FK) и сервис.

## Частые ошибки

| Ошибка | Как лучше |
| --- | --- |
| Только TypeScript-тип без рантайм-проверки | Схема + pipe |
| Все поля `optional` в create | Отдельные create / update схемы |
| Нет `max` у `limit`, строк и массивов | Явные верхние границы |
| Email без нормализации | `trim().toLowerCase().pipe(z.email())` |
| `z.coerce.boolean()` для флагов | `z.stringbool()` |
| `superRefine` без `path` | `ctx.addIssue({ path: [...] })` |
| Уникальность email в схеме | Уникальный индекс + обработка P2002 |

## Что важно помнить

- Порядок: граница → форма → ограничения → нормализация → create/update/response → правила → типы → подключение → ошибки → тесты.
- Ограничения схемы согласуются с базой.
- Тип обработчика — `z.output`, тип клиента — `z.input`.

## Мини-шпаргалка

- `z.object({...})` → `.min/.max/.trim` → `.default`.
- `omit/partial/extend` для вариантов DTO.
- `refine({ path })`, `discriminatedUnion`.
- `@Body({ schema })`, `@Query({ schema })`.
- Тесты `safeParse` на границах.
