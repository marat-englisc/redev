# Как подключить Zod к NestJS - ZodValidationPipe и StandardSchemaValidationPipe

> [!NOTE]
> Есть два способа проверять параметры обработчиков схемами Zod. **Встроенный (NestJS 12)**: глобально регистрируется `StandardSchemaValidationPipe`, а схема передаётся опцией `schema` в parameter decorator — `@Body({ schema })`, `@Query({ schema })`, `@Param('id', { schema })`, `@MessageBody({ schema })`, `@Payload({ schema })`. Пайп работает с любой библиотекой стандарта Standard Schema (Zod, Valibot, ArkType), возвращает **разобранное значение** (с `default`, `coerce`, `transform`) и при ошибке бросает `BadRequestException`. **Собственный `ZodValidationPipe`** — класс с `transform(value)`, который вызывает `schema.safeParse(value)` и формирует исключение в нужном формате; его подключают как параметр-пайп `@Body(new ZodValidationPipe(schema))`. Свой пайп полезен в старых версиях Nest или когда нужен особый формат ошибок; документация Nest рекомендует для продакшена встроенный вариант. Валидацию любого параметра без схемы пайп пропускает.

## Вопрос

Как подключить валидацию Zod к контроллерам NestJS?

## Встроенный StandardSchemaValidationPipe

```ts
// main.ts
app.useGlobalPipes(new StandardSchemaValidationPipe());
```

```ts
const createProductSchema = z.object({
  title: z.string().trim().min(2).max(120),
  price: z.number().positive(),
  tags: z.array(z.string().max(30)).max(10).default([]),
});
type CreateProductDto = z.infer<typeof createProductSchema>;

@Controller('products')
export class ProductsController {
  @Post()
  create(@Body({ schema: createProductSchema }) dto: CreateProductDto) {
    return this.products.create(dto);          // dto.tags всегда массив (default)
  }

  @Get(':id')
  findOne(@Param('id', { schema: z.uuid() }) id: string) {
    return this.products.findOne(id);
  }
}
```

## Свой ZodValidationPipe

```ts
import { ArgumentMetadata, BadRequestException, Injectable, PipeTransform } from '@nestjs/common';
import { z, ZodType } from 'zod';

@Injectable()
export class ZodValidationPipe<T extends ZodType> implements PipeTransform<unknown, z.output<T>> {
  constructor(private readonly schema: T) {}

  transform(value: unknown, _metadata: ArgumentMetadata): z.output<T> {
    const result = this.schema.safeParse(value);
    if (!result.success) {
      throw new BadRequestException({
        code: 'VALIDATION_FAILED',
        message: 'Validation failed',
        details: result.error.issues.map((i) => ({ field: i.path.join('.'), message: i.message, code: i.code })),
      });
    }
    return result.data;                         // именно data, а не value
  }
}
```

```ts
@Post()
create(@Body(new ZodValidationPipe(createProductSchema)) dto: CreateProductDto) {}

@UsePipes(new ZodValidationPipe(createProductSchema))   // для метода с одним аргументом-телом
@Post('v2')
createV2(@Body() dto: CreateProductDto) {}
```

`@UsePipes` применит пайп ко **всем** аргументам метода — с несколькими параметрами используйте параметр-пайп.

## Формат ошибок встроенного пайпа

Если нужен единый формат ошибок API, его приводят к общему виду в глобальном [exception filter](<../05. Pipes, validation и exception filters/07. Как сделать единый формат ошибок.md>), а не в каждом пайпе.

## WebSocket и микросервисы

```ts
@SubscribeMessage('message:send')
send(@MessageBody({ schema: sendMessageSchema }) dto: SendMessageDto) {}

@MessagePattern('inventory.reserve')
reserve(@Payload({ schema: reserveSchema }) dto: ReserveDto) {}
```

## Сравнение

| | `StandardSchemaValidationPipe` | Свой `ZodValidationPipe` |
| --- | --- | --- |
| Версия Nest | 12+ | Любая |
| Подключение | Глобально + `{ schema }` в декораторе | На параметр или метод |
| Библиотеки | Любые Standard Schema | Только Zod (или по реализации) |
| Формат ошибок | Стандартный 400 (меняется filter-ом) | Любой |

## Частые ошибки

- Вернуть из пайпа исходный `value` — теряются `default`/`transform`/`coerce`.
- `@UsePipes(new ZodValidationPipe(schema))` на методе с `@Param` и `@Body` — схема тела применится к id.
- Схема указана, но глобальный `StandardSchemaValidationPipe` не зарегистрирован — проверки нет.
- Async-схема в синхронном `safeParse`.

## Что важно помнить

- NestJS 12: `StandardSchemaValidationPipe` + `@Body({ schema })` — рекомендуемый путь.
- Свой пайп — `safeParse` → `BadRequestException`, вернуть `result.data`.
- Единый формат ошибок — в exception filter.

## Мини-шпаргалка

- `app.useGlobalPipes(new StandardSchemaValidationPipe())`.
- `@Body({ schema })`, `@Query({ schema })`, `@Param('id', { schema })`.
- `@Body(new ZodValidationPipe(schema))`.
- `@MessageBody({ schema })`, `@Payload({ schema })`.
