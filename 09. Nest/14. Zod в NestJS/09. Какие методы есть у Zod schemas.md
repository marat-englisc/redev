# Какие методы есть у Zod schemas

> [!NOTE]
> Zod-схема строится из **конструкторов** (`z.string`, `z.object`, `z.array`…) и уточняется **методами**, каждый из которых возвращает **новую** схему (исходная не меняется). Группы методов: **разбор** — `parse`, `safeParse`, `parseAsync`, `safeParseAsync`; **строки** — `min`, `max`, `length`, `regex`, `startsWith`, `includes`, `trim`, `toLowerCase`, `toUpperCase` (форматы в Zod 4 — отдельные конструкторы `z.email()`, `z.uuid()`, `z.url()`, `z.iso.datetime()`); **числа** — `int`, `min`/`gte`, `max`/`lte`, `gt`, `lt`, `positive`, `nonnegative`, `multipleOf`; **отсутствие значения** — `optional`, `nullable`, `nullish`, `default`, `prefault`, `catch`; **объекты** — `pick`, `omit`, `partial`, `required`, `extend`, `safeExtend`, `keyof`, `shape`; **массивы** — `min`, `max`, `length`, `nonempty`; **проверки и преобразования** — `refine`, `superRefine`, `check`, `transform`, `pipe`, `z.coerce.*`, `z.preprocess`; **метаданные** — `describe`, `meta`; **типы** — `z.infer`, `z.input`, `z.output`. На границах API избегайте `z.any()` — вместо неё `z.unknown()` с дальнейшей проверкой.

## Вопрос

Какие методы схем Zod нужно знать для работы в NestJS?

## Разбор

| Метод | Результат |
| --- | --- |
| `parse(x)` | Данные или `ZodError` |
| `safeParse(x)` | `{ success, data }` / `{ success: false, error }` |
| `parseAsync`, `safeParseAsync` | Для async `refine`/`transform` |

## Строки

```ts
const username = z.string().trim().toLowerCase().min(3).max(30).regex(/^[a-z0-9_]+$/);
const email = z.string().trim().toLowerCase().pipe(z.email());   // нормализация, затем формат
```

| Метод | Назначение |
| --- | --- |
| `min`, `max`, `length` | Длина |
| `regex`, `startsWith`, `endsWith`, `includes` | Содержимое |
| `trim`, `toLowerCase`, `toUpperCase` | Нормализация (меняет значение) |
| `z.email()`, `z.uuid()`, `z.url()`, `z.jwt()`, `z.ipv4()` | Форматы (Zod 4) |
| `z.iso.date()`, `z.iso.datetime()`, `z.iso.time()` | ISO-строки дат |

## Числа

```ts
const price = z.number().positive().multipleOf(0.01).max(1_000_000);
const qty = z.int().min(1).max(100);                    // z.int() — целое в безопасном диапазоне
```

| Метод | Назначение |
| --- | --- |
| `int()` / `z.int()` | Целое |
| `min`/`gte`, `max`/`lte`, `gt`, `lt` | Границы |
| `positive`, `nonnegative`, `negative` | Знак |
| `multipleOf(n)` | Кратность |

## Отсутствие значения

```ts
z.object({
  nickname: z.string().optional(),          // string | undefined
  middleName: z.string().nullable(),        // string | null
  bio: z.string().nullish(),                // string | null | undefined
  role: z.enum(['user', 'admin']).default('user'),
  pageSize: z.coerce.number().catch(20),     // при ошибке — 20
});
```

| Метод | Поведение |
| --- | --- |
| `optional()` | Разрешает `undefined` / отсутствие |
| `nullable()` | Разрешает `null` |
| `nullish()` | `null` и `undefined` |
| `default(v)` | Подставляет `v` вместо `undefined` (короткое замыкание, без проверки `v`) |
| `prefault(v)` | Подставляет `v` и **проверяет** его схемой |
| `catch(v)` | Возвращает `v` при любой ошибке проверки |

## Объекты

```ts
const user = z.object({ email: z.email(), name: z.string().min(2), password: z.string().min(10), role: z.enum(['user', 'admin']) });

const createUser = user.omit({ role: true });
const updateUser = user.pick({ name: true }).partial();
const publicUser = user.omit({ password: true }).extend({ id: z.uuid(), createdAt: z.date() });
const userKeys = user.keyof();                              // z.enum(['email', 'name', 'password', 'role'])
user.shape.email;                                           // схема поля
```

| Метод | Назначение |
| --- | --- |
| `pick`, `omit` | Выбрать / убрать поля |
| `partial`, `required` | Сделать поля необязательными / обязательными |
| `extend`, `safeExtend` | Добавить поля (`safeExtend` — без потери `refine`) |
| `keyof` | Enum ключей |
| `z.strictObject`, `z.looseObject` | Поведение для лишних ключей |

## Массивы, записи, кортежи

```ts
z.array(z.uuid()).min(1).max(100);
z.array(z.string()).nonempty();
z.record(z.string(), z.number());                // { [key: string]: number }
z.tuple([z.number(), z.number()]);               // [lat, lng]
```

## Проверки и преобразования

```ts
z.string().refine((s) => !s.includes('..'), 'Invalid path');
z.string().transform((s) => s.split(',').map((x) => x.trim()));
z.string().pipe(z.coerce.number());              // строка → число с проверкой
z.coerce.number(); z.coerce.date(); z.stringbool();
z.preprocess((v) => (v === '' ? undefined : v), z.coerce.number().optional());
```

`pipe` передаёт результат одной схемы на вход другой — удобно для «нормализовать, затем проверить».

## Метаданные и типы

```ts
const schema = z.string().min(2).meta({ description: 'Имя пользователя', example: 'Anna' });

type In = z.input<typeof schema>;      // тип до преобразований (для тел запросов, форм)
type Out = z.output<typeof schema>;    // после (= z.infer)
```

## Частые ошибки

- `z.any()` на границе API.
- `z.coerce.boolean()` для query — `'false'` → `true` (нужен `z.stringbool()`).
- `.default()` с вычисляемым значением без функции — одно значение на все вызовы (`.default(() => new Date())`).
- `extend` у схемы с `refine` — refine теряется (используйте `safeExtend` или повторите проверку).
- Путать `z.input` и `z.output` для схем с `transform`/`default`.

## Что важно помнить

- Методы возвращают новые схемы — композиция без мутаций.
- `pick`/`omit`/`partial`/`extend` собирают DTO из базовой схемы.
- Для query — `coerce`/`stringbool`, для нормализации — `trim`/`toLowerCase` + `pipe`.

## Мини-шпаргалка

- Строки: `min/max/regex/trim/toLowerCase`, форматы `z.email()`, `z.uuid()`.
- Числа: `int/min/max/positive/multipleOf`.
- `optional/nullable/nullish/default/prefault/catch`.
- `pick/omit/partial/required/extend/safeExtend/keyof`.
- `refine/superRefine/transform/pipe/coerce/preprocess`.
- `z.infer`, `z.input`, `z.output`, `.meta()`.
