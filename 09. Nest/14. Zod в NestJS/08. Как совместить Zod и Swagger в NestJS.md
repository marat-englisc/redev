# Как совместить Zod и Swagger в NestJS

> [!NOTE]
> `@nestjs/swagger` строит OpenAPI-схемы из **классов** (метаданные `@ApiProperty` или CLI-плагина), а схема Zod — обычное значение, которое Swagger сам не видит. Поэтому при валидации через Zod документацию подключают одним из способов: **`z.toJSONSchema(schema)`** (встроено в Zod 4) — конвертировать схему в JSON Schema и передать в `@ApiBody({ schema })`/`@ApiResponse({ schema })`; пакет **`nestjs-zod`** — `createZodDto(schema)` создаёт класс-DTO, понятный и Swagger, и валидации, а `cleanupOpenApiDoc` приводит документ к корректному виду; **отдельный doc-DTO** с `@ApiProperty` для документации (просто, но схемы легко «разъезжаются»). Важно учитывать различия форматов: OpenAPI 3.0 использует свой диалект JSON Schema (например, `nullable` вместо `type: [..., 'null']`), OpenAPI 3.1 совместим с JSON Schema 2020-12; у `z.toJSONSchema` есть параметр `target` для выбора диалекта. Входная и выходная формы схем с `transform`/`default` различаются — для тела запроса берут **input**-представление (`io: 'input'`).

## Вопрос

Как документировать в Swagger эндпоинты, которые валидируются схемами Zod?

## Вариант 1: z.toJSONSchema + @ApiBody

```ts
export const createProductSchema = z.object({
  title: z.string().min(2).max(120).meta({ description: 'Название товара', example: 'Клавиатура' }),
  price: z.number().positive(),
  tags: z.array(z.string()).max(10).default([]),
});

const createProductJsonSchema = z.toJSONSchema(createProductSchema, {
  target: 'openapi-3.0',          // диалект под версию документа
  io: 'input',                    // форма входа: tags необязателен (есть default)
});

@ApiBody({ schema: createProductJsonSchema as SchemaObject })
@ApiCreatedResponse({ description: 'Created' })
@Post()
create(@Body({ schema: createProductSchema }) dto: z.infer<typeof createProductSchema>) {}
```

Метаданные (`description`, `example`) задаются через `.meta()` / `.describe()` и попадают в JSON Schema.

## Вариант 2: nestjs-zod

```bash
npm install nestjs-zod
```

```ts
import { createZodDto, cleanupOpenApiDoc } from 'nestjs-zod';

export class CreateProductDto extends createZodDto(createProductSchema) {}

@Post()
create(@Body() dto: CreateProductDto) {}          // Swagger видит класс; валидация — ZodValidationPipe из nestjs-zod

// main.ts
const document = SwaggerModule.createDocument(app, config);
SwaggerModule.setup('docs', app, cleanupOpenApiDoc(document));
```

Перед использованием проверьте совместимость версии пакета с вашими Nest и Zod.

## Вариант 3: doc-DTO

```ts
export class CreateProductDocDto {
  @ApiProperty({ example: 'Клавиатура', minLength: 2, maxLength: 120 }) title: string;
  @ApiProperty({ example: 4990, minimum: 0, exclusiveMinimum: true }) price: number;
  @ApiPropertyOptional({ type: [String], maxItems: 10 }) tags?: string[];
}

@ApiBody({ type: CreateProductDocDto })
@Post()
create(@Body({ schema: createProductSchema }) dto: CreateProductInput) {}
```

Нужен тест, сверяющий doc-DTO и схему, иначе они разойдутся.

## Ответы

```ts
const productResponseSchema = z.object({ id: z.uuid(), title: z.string(), price: z.number() });

@ApiOkResponse({ schema: z.toJSONSchema(productResponseSchema, { target: 'openapi-3.0', io: 'output' }) as SchemaObject })
@Get(':id')
findOne() {}
```

## Сравнение

| Способ | Плюсы | Минусы |
| --- | --- | --- |
| `z.toJSONSchema` + `@ApiBody` | Без зависимостей, один источник правды | Больше декораторов, ручной `$ref` для переиспользования |
| `nestjs-zod` | Удобные DTO-классы, автоматическая документация | Сторонний пакет, зависимость от версий |
| Doc-DTO | Привычный Swagger | Дублирование, риск расхождения |

## Частые ошибки

- Документировать output-форму схемы для тела запроса (поля с `default` выглядят обязательными).
- Генерировать JSON Schema 2020-12 и вставлять в документ OpenAPI 3.0 без `target`.
- Doc-DTO без проверки соответствия схеме.
- `transform`-схемы, которые нельзя выразить в JSON Schema, без `unrepresentable`-обработки.

## Что важно помнить

- Swagger не видит схемы Zod сам — нужна конвертация или DTO-класс.
- `z.toJSONSchema(schema, { target, io })` — встроенный способ Zod 4.
- `nestjs-zod` — DTO-классы из схем; doc-DTO — только с контролем расхождений.

## Мини-шпаргалка

- `z.toJSONSchema(s, { target: 'openapi-3.0', io: 'input' })`.
- `@ApiBody({ schema })`, `@ApiOkResponse({ schema })`.
- `.meta({ description, example })`.
- `createZodDto(schema)` + `cleanupOpenApiDoc(doc)`.
