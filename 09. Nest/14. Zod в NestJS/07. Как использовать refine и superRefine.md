# Как использовать refine и superRefine

> [!NOTE]
> `refine(check, params)` добавляет к схеме **произвольную проверку**: функция получает уже провалидированное значение и возвращает `true`/`false` (или промис — тогда нужен `parseAsync`); параметры задают сообщение (`message` или `error` в Zod 4), `path` (к какому полю отнести ошибку — важно для форм) и `abort`. `superRefine((value, ctx) => ...)` даёт контекст: можно добавить **несколько** ошибок `ctx.addIssue({ code: 'custom', path, message })` с разными путями — удобно для правил, зависящих от нескольких полей. В Zod 4 есть и `.check()` с тем же контекстом. Проверки выполняются **после** базовой валидации объекта: если поле не прошло тип, `refine` объекта по умолчанию не запустится. Важно: refine-функции **не должны бросать исключения**, а проверки, требующие базы данных (уникальность email), лучше делать в сервисе — схема не защищает от гонки двух запросов.

## Вопрос

Как добавлять в Zod собственные проверки через `refine` и `superRefine`?

## refine для одного значения

```ts
const passwordSchema = z
  .string()
  .min(10)
  .refine((v) => /[A-Z]/.test(v), { message: 'Must contain an uppercase letter' })
  .refine((v) => /\d/.test(v), { message: 'Must contain a digit' });

const slugSchema = z.string().refine((s) => !RESERVED_SLUGS.has(s), { error: 'This slug is reserved' });
```

## refine объекта с path

```ts
const changePasswordSchema = z
  .object({
    password: passwordSchema,
    confirmPassword: z.string(),
  })
  .refine((d) => d.password === d.confirmPassword, {
    message: 'Passwords do not match',
    path: ['confirmPassword'],                 // ошибка будет у поля confirmPassword
  });
```

## superRefine для нескольких правил

```ts
const bookingSchema = z
  .object({
    checkIn: z.iso.date(),
    checkOut: z.iso.date(),
    guests: z.int().min(1),
    childAges: z.array(z.int().min(0).max(17)).default([]),
    children: z.int().min(0).default(0),
  })
  .superRefine((b, ctx) => {
    if (b.checkOut <= b.checkIn) {
      ctx.addIssue({ code: 'custom', path: ['checkOut'], message: 'Check-out must be after check-in' });
    }
    if (b.childAges.length !== b.children) {
      ctx.addIssue({ code: 'custom', path: ['childAges'], message: `Provide ages for ${b.children} children` });
    }
    if (b.guests + b.children > 8) {
      ctx.addIssue({ code: 'custom', path: ['guests'], message: 'Max 8 people per booking' });
    }
  });
```

## Условно обязательные поля

```ts
const deliverySchema = z
  .object({
    method: z.enum(['pickup', 'courier']),
    address: z.string().min(5).optional(),
  })
  .refine((d) => d.method !== 'courier' || !!d.address, {
    message: 'Address is required for courier delivery',
    path: ['address'],
  });
```

Часто такие случаи чище выражаются через `z.discriminatedUnion('method', [...])`.

## Асинхронная проверка

```ts
const inviteSchema = z.object({
  email: z.email().refine(async (e) => !(await this.blocklist.has(e)), 'Email is blocked'),
});

await inviteSchema.parseAsync(body);
```

## Где проверять уникальность

```ts
// ✗ схема: проверила «свободен» → параллельный запрос успел создать такой же email
z.email().refine(async (e) => !(await users.exists(e)));

// ✓ уникальный индекс в БД + обработка P2002 → 409 в сервисе
```

## refine или transform

| Нужно | Метод |
| --- | --- |
| Проверить и оставить значение | `refine` / `superRefine` |
| Изменить значение | `transform` (`trim`, `toLowerCase`, разбор строки) |
| Изменить и, если нельзя, добавить ошибку | `transform((v, ctx) => { ctx.addIssue(...); return z.NEVER; })` |

## Частые ошибки

- Нет `path` у ошибки объекта — форма не знает, какое поле подсветить.
- Бросать исключение внутри `refine` вместо `return false`.
- Синхронный `parse` при async `refine`.
- Ожидать, что `refine` объекта сработает, если одно из полей не прошло базовую проверку.
- Бизнес-правила с доступом к БД в схеме вместо сервиса.

## Что важно помнить

- `refine` — одна проверка, `superRefine` — несколько ошибок с разными путями.
- `path` связывает ошибку с полем.
- Проверки уникальности и состояния — в сервисе и БД.

## Мини-шпаргалка

- `.refine(fn, { message, path })`.
- `.superRefine((v, ctx) => ctx.addIssue({ code: 'custom', path, message }))`.
- Async — `parseAsync`.
- Варианты — `discriminatedUnion`.
