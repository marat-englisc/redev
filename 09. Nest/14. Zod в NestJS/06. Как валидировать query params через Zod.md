# Как валидировать query params через Zod

> [!NOTE]
> Query-параметры и параметры пути **всегда приходят строками** (`?page=2&active=false` → `{ page: '2', active: 'false' }`), а повторяющийся ключ — массивом или строкой в зависимости от количества значений. Поэтому схема query использует **приведение типов**: `z.coerce.number()` для чисел (с `.int()`, `.min()`, `.max()`), **`z.stringbool()`** для флагов — `z.coerce.boolean()` здесь ошибочен, потому что любая непустая строка, включая `'false'`, превращается в `true`; `z.coerce.date()` или `z.iso.date()` для дат; `z.preprocess`/`transform` для списков (`'a,b,c'` → `['a','b','c']`). Обязательные практики: значения по умолчанию через `.default()`, верхняя граница `limit`, сортировка **только по белому списку** (`z.enum([...])`), поиск — с `trim` и ограничением длины. Тип результата — `z.output` (после преобразований), именно его получает обработчик.

## Вопрос

Как валидировать и приводить типы query-параметров с помощью Zod?

## Схема списка

```ts
const csv = (item: z.ZodType) =>
  z.preprocess(
    (v) => (Array.isArray(v) ? v : typeof v === 'string' ? v.split(',').filter(Boolean) : v),
    z.array(item).max(50),
  );

export const listProductsQuerySchema = z.object({
  page: z.coerce.number().int().min(1).default(1),
  limit: z.coerce.number().int().min(1).max(100).default(20),
  search: z.string().trim().min(1).max(100).optional(),
  categoryIds: csv(z.uuid()).optional(),                          // ?categoryIds=a,b или ?categoryIds=a&categoryIds=b
  minPrice: z.coerce.number().nonnegative().optional(),
  inStock: z.stringbool().optional(),                            // 'true'/'false'/'1'/'0'/'yes'/'no'
  from: z.iso.date().optional(),                                 // '2026-10-01'
  sortBy: z.enum(['createdAt', 'price', 'title']).default('createdAt'),
  sortOrder: z.enum(['asc', 'desc']).default('desc'),
});

export type ListProductsQuery = z.output<typeof listProductsQuerySchema>;
```

## Контроллер

```ts
@Get()
list(@Query({ schema: listProductsQuerySchema }) query: ListProductsQuery) {
  return this.products.list(query);      // query.page — number, query.inStock — boolean | undefined
}
```

## Почему не coerce.boolean

```ts
z.coerce.boolean().parse('false');   // true  ✗ (Boolean('false'))
z.coerce.boolean().parse('');        // false
z.stringbool().parse('false');       // false ✓
z.stringbool().parse('maybe');       // ошибка ✓
```

## Связанные поля

```ts
export const reportQuerySchema = z
  .object({
    from: z.coerce.date(),
    to: z.coerce.date(),
  })
  .refine((q) => q.from < q.to, { message: '`from` must be before `to`', path: ['to'] })
  .refine((q) => q.to.getTime() - q.from.getTime() <= 366 * 24 * 3600_000, { message: 'Range is too large', path: ['to'] });
```

## Курсорная пагинация

```ts
export const feedQuerySchema = z.object({
  cursor: z.string().max(200).optional(),          // непрозрачный base64
  limit: z.coerce.number().int().min(1).max(50).default(20),
});
```

## Безопасность

```ts
// ✗ произвольное поле сортировки
orderBy: { [query.sortBy]: query.sortOrder }      // без enum — любое поле, включая passwordHash

// ✓ sortBy ограничен z.enum([...]) и проиндексированными полями
```

## Частые ошибки

- `z.number()` без `coerce` — `'2'` не пройдёт проверку.
- `z.coerce.boolean()` для флагов.
- `z.coerce.number()` с пустой строкой `?page=` — `Number('')` = 0, и `min(1)` вернёт ошибку; иногда нужно сначала превратить `''` в `undefined`.
- Нет `max` у `limit` и списков id.
- Тип обработчика `z.input` вместо `z.output`.

## Что важно помнить

- Query — строки: `coerce.number`, `stringbool`, `iso.date`, preprocess для списков.
- Defaults, верхние границы, белый список сортировки.
- Обработчик получает `z.output` схемы.

## Мини-шпаргалка

- `z.coerce.number().int().min(1).max(100).default(20)`.
- `z.stringbool()`.
- `z.enum([...]).default(...)` для `sortBy`.
- `z.preprocess(split, z.array(...).max(n))`.
