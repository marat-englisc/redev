# Как создавать Zod schemas

> [!NOTE]
> Схема Zod собирается из конструкторов и методов-уточнений. Примитивы: `z.string()`, `z.number()`, `z.int()`, `z.boolean()`, `z.bigint()`, `z.date()`; форматы (Zod 4) — отдельными функциями: `z.email()`, `z.url()`, `z.uuid()`, `z.iso.datetime()`, `z.iso.date()`. Структуры: `z.object({...})` (по умолчанию **лишние ключи отбрасываются**; `z.strictObject` — ошибка на лишние, `z.looseObject` — пропускает), `z.array(schema)`, `z.tuple`, `z.record`. Перечисления: `z.enum([...])`, `z.literal(...)`, `z.nativeEnum` для TS-enum. Варианты: `z.union([...])` и **`z.discriminatedUnion('type', [...])`** — для payload-ов с полем-дискриминатором. Отсутствие значения: `.optional()`, `.nullable()`, `.nullish()`, `.default(value)`. Схемы **неизменяемы**: каждый метод возвращает новую схему, поэтому их удобно переиспользовать и комбинировать (`extend`, `pick`, `omit`, `partial`). Тип получают через `z.infer` (а для схем с преобразованиями — `z.input`/`z.output`).

## Вопрос

Как создавать схемы Zod для объектов, массивов, перечислений и вариантов?

## Объект

```ts
export const addressSchema = z.object({
  city: z.string().trim().min(1).max(100),
  street: z.string().trim().min(1).max(200),
  zip: z.string().regex(/^\d{6}$/),
});

export const createOrderSchema = z.object({
  items: z
    .array(z.object({ productId: z.uuid(), qty: z.int().min(1).max(100) }))
    .min(1)
    .max(50),
  address: addressSchema,
  comment: z.string().max(500).optional(),
  deliverAt: z.iso.datetime().optional(),
  promoCode: z.string().toUpperCase().nullish(),
});

export type CreateOrderDto = z.infer<typeof createOrderSchema>;
```

## Лишние поля

```ts
z.object({ name: z.string() }).parse({ name: 'A', role: 'admin' });         // { name: 'A' } — role отброшен
z.strictObject({ name: z.string() }).parse({ name: 'A', role: 'admin' });   // ошибка: unrecognized key "role"
z.looseObject({ name: z.string() }).parse({ name: 'A', role: 'admin' });    // { name: 'A', role: 'admin' }
```

Для входных данных API безопасно поведение по умолчанию или `strictObject` (явная ошибка клиенту).

## Перечисления

```ts
const roleSchema = z.enum(['user', 'editor', 'admin']);
type Role = z.infer<typeof roleSchema>;          // 'user' | 'editor' | 'admin'
roleSchema.options;                              // ['user', 'editor', 'admin']

const sortOrder = z.literal(['asc', 'desc']);   // Zod 4: несколько литералов

enum OrderStatus { Pending = 'pending', Paid = 'paid' }
const statusSchema = z.enum(OrderStatus);        // Zod 4 принимает TS-enum в z.enum
```

## Discriminated union

```ts
const paymentSchema = z.discriminatedUnion('method', [
  z.object({ method: z.literal('card'), cardToken: z.string().min(10) }),
  z.object({ method: z.literal('invoice'), companyInn: z.string().regex(/^\d{10,12}$/) }),
  z.object({ method: z.literal('cash') }),
]);

type Payment = z.infer<typeof paymentSchema>;

function handle(p: Payment) {
  if (p.method === 'card') p.cardToken;          // тип сужается
}
```

Ошибки у `discriminatedUnion` понятнее, чем у `union`: Zod сразу выбирает вариант по полю `method`.

## Переиспользование

```ts
const baseUser = z.object({ email: z.email(), name: z.string().min(2) });

export const createUserSchema = baseUser.extend({ password: z.string().min(10) });
export const updateUserSchema = baseUser.partial();
export const publicUserSchema = baseUser.extend({ id: z.uuid(), createdAt: z.date() });
```

## Рекурсивные схемы

```ts
type Category = { name: string; children: Category[] };

const categorySchema: z.ZodType<Category> = z.object({
  name: z.string(),
  get children() { return z.array(categorySchema); },   // Zod 4: getter для рекурсии
});
```

## Частые ошибки

- `z.number()` для query-параметров — придут строки (нужен `z.coerce.number()`).
- `.optional()` там, где нужен `.default()` — в коде придётся проверять `undefined`.
- `z.union` вместо `z.discriminatedUnion` для вариантов с дискриминатором — непонятные ошибки.
- Нет ограничений `max` у массивов и строк — огромные payload-ы.

## Что важно помнить

- Схемы собираются из конструкторов и методов, неизменяемы и переиспользуемы.
- `z.object` отбрасывает лишние ключи, `strictObject` — запрещает.
- Варианты payload — `discriminatedUnion`.

## Мини-шпаргалка

- `z.object`, `z.array(...).min().max()`, `z.record`, `z.tuple`.
- `z.email()`, `z.uuid()`, `z.url()`, `z.iso.datetime()`.
- `z.enum([...])`, `z.literal([...])`, `z.discriminatedUnion('k', [...])`.
- `.optional()`, `.nullable()`, `.nullish()`, `.default()`.
