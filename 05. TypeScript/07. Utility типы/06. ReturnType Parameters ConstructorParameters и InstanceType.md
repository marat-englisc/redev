# ReturnType, Parameters, ConstructorParameters и InstanceType

> [!NOTE]
> Эти utility-типы извлекают типы из функций и классов. `ReturnType<F>` — тип возвращаемого значения функции, `Parameters<F>` — кортеж типов ее параметров, `ConstructorParameters<C>` — кортеж параметров конструктора класса, `InstanceType<C>` — тип экземпляра класса. Они принимают **тип**, поэтому для значений используют `typeof`: `ReturnType<typeof createStore>`.

## Вопрос

Что делают `ReturnType`, `Parameters`, `ConstructorParameters` и `InstanceType`? Когда они полезны?

## ReturnType

```typescript
function createUser(name: string) {
  return { id: crypto.randomUUID(), name, createdAt: new Date() };
}

type User = ReturnType<typeof createUser>;
// { id: string; name: string; createdAt: Date }

type Data = Awaited<ReturnType<typeof fetchUser>>; // для async-функций разворачиваем Promise
```

Полезно, когда тип результата «рождается» в функции: фабрики, store, хуки, конфигурация.

```typescript
const store = configureStore({ reducer });
type RootState = ReturnType<typeof store.getState>; // Redux Toolkit
type AppDispatch = typeof store.dispatch;
```

## Parameters

```typescript
function sendEmail(to: string, subject: string, options?: { html: boolean }) {}

type SendEmailArgs = Parameters<typeof sendEmail>;
// [to: string, subject: string, options?: { html: boolean }]

type Options = Parameters<typeof sendEmail>[2]; // { html: boolean } | undefined

function withLogging<F extends (...args: any[]) => any>(fn: F) {
  return (...args: Parameters<F>): ReturnType<F> => {
    console.log(args);
    return fn(...args);
  };
}
```

## ConstructorParameters и InstanceType

```typescript
class ApiClient {
  constructor(public baseUrl: string, public timeout = 5000) {}
}

type ClientArgs = ConstructorParameters<typeof ApiClient>; // [baseUrl: string, timeout?: number]
type Client = InstanceType<typeof ApiClient>;             // ApiClient

function create<C extends new (...args: any) => any>(Cls: C, ...args: ConstructorParameters<C>): InstanceType<C> {
  return new Cls(...args);
}

const client = create(ApiClient, "/api"); // ApiClient
```

`typeof ApiClient` — тип самого класса (конструктора), а `ApiClient` в позиции типа — тип экземпляра.

## Как они устроены

```typescript
type MyReturnType<T extends (...args: any) => any> = T extends (...args: any) => infer R ? R : any;
type MyParameters<T extends (...args: any) => any> = T extends (...args: infer P) => any ? P : never;
type MyInstanceType<T extends abstract new (...args: any) => any> =
  T extends abstract new (...args: any) => infer R ? R : any;
```

Все они построены на условных типах с `infer`.

## Что важно помнить

- Без `typeof` будет ошибка: `ReturnType<createUser>` — `createUser` это значение, а не тип.
- Для перегруженных функций `ReturnType` и `Parameters` берут **последнюю** сигнатуру.
- `Awaited<T>` рекурсивно разворачивает `Promise` — нужен для async-функций.
- Выводить типы из реализации удобно, но для публичных API лучше явный тип: так изменение реализации не сломает контракт незаметно.

## Мини-шпаргалка

- `ReturnType<typeof fn>` — тип результата.
- `Parameters<typeof fn>` — кортеж параметров.
- `ConstructorParameters<typeof Class>` — параметры конструктора.
- `InstanceType<typeof Class>` — тип экземпляра.
- Для async — `Awaited<ReturnType<...>>`.
