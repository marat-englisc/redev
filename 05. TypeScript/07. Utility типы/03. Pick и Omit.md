# Pick и Omit

> [!NOTE]
> `Pick<T, K>` создает тип только из перечисленных свойств `K` типа `T`, `Omit<T, K>` — из всех свойств, **кроме** `K`. Pick проверяет, что ключи существуют в `T`, а Omit принимает любые ключи — опечатка в Omit не вызовет ошибки. Оба сохраняют модификаторы `?` и `readonly`.

## Вопрос

Что делают utility-типы `Pick` и `Omit`? Чем они отличаются и когда что использовать?

## Pick

```typescript
type User = {
  id: number;
  name: string;
  email: string;
  passwordHash: string;
  createdAt: Date;
};

type UserPreview = Pick<User, "id" | "name">;
// { id: number; name: string }

type Bad = Pick<User, "age">; // ошибка: "age" не является ключом User
```

## Omit

```typescript
type PublicUser = Omit<User, "passwordHash">;
// { id; name; email; createdAt }

type NewUser = Omit<User, "id" | "createdAt">; // поля, которые задает сервер, убираем

type Typo = Omit<User, "pasword">; // ошибки нет — опечатка не замечена!
```

## Когда что

| Задача | Выбор |
| --- | --- |
| Нужно 2–3 поля из большого типа | `Pick` |
| Нужно всё, кроме нескольких полей | `Omit` |
| Важна защита от опечаток в ключах | `Pick` или строгий Omit |
| Тип для формы создания (без `id`) | `Omit<Entity, "id">` |
| Props компонента-обертки | `Omit<ComponentProps<"button">, "onClick"> & { onClick: ... }` |

## Как они устроены

```typescript
type MyPick<T, K extends keyof T> = { [P in K]: T[P] };

type MyOmit<T, K extends keyof any> = Pick<T, Exclude<keyof T, K>>;

// строгий Omit: ключи должны существовать
type StrictOmit<T, K extends keyof T> = Omit<T, K>;
```

## Комбинации

```typescript
type UserForm = Partial<Pick<User, "name" | "email">>;
type UpdateUser = Pick<User, "id"> & Partial<Omit<User, "id">>; // id обязателен, остальное — по желанию

type ButtonProps = Omit<React.ComponentProps<"button">, "type"> & {
  variant: "primary" | "ghost";
};
```

## Что важно помнить

- `Omit` с union-типом работает не дистрибутивно: `Omit<A | B, "x">` оставит только общие ключи. Для union нужен distributive вариант: `T extends unknown ? Omit<T, K> : never`.
- `Pick` и `Omit` поверхностные — вложенные объекты не меняются.
- Типы для API (DTO) удобно выводить из одной модели через `Pick`/`Omit`, чтобы они не расходились.
- Длинные цепочки utility-типов ухудшают подсказки IDE — давайте им понятные имена.

## Мини-шпаргалка

- `Pick<T, "a" | "b">` — только указанные поля.
- `Omit<T, "a">` — все поля, кроме указанных.
- Pick проверяет ключи, Omit — нет.
- Omit на union не распределяется.
- Комбинируются с `Partial`, `Required`, `&`.
