# Generic-функции: объявление, вывод типов и несколько параметров

> [!NOTE]
> Параметр типа объявляют в угловых скобках перед списком аргументов: `function wrap<T>(value: T)` или `const wrap = <T,>(value: T) => ...`. При вызове TypeScript обычно **выводит** `T` из аргументов (type argument inference), но его можно указать явно: `wrap<string>("a")`. Параметров типа может быть несколько (`<K, V>`), и они могут зависеть друг от друга.

## Вопрос

Как объявить функцию с generic-параметром? Как работает вывод типов в дженериках и как использовать несколько дженериков?

## Объявление

```typescript
function wrap<T>(value: T): { value: T } {
  return { value };
}

const wrapArrow = <T,>(value: T) => ({ value });   // запятая нужна в .tsx

const result = wrap(42);           // { value: number } — T выведен
const explicit = wrap<string>("a"); // T указан явно
```

## Вывод типов (inference)

```typescript
function last<T>(items: T[]): T | undefined {
  return items.at(-1);
}

last([1, 2, 3]);          // T = number
last(["a", "b"]);         // T = string
last([1, "a"]);           // T = string | number
last([]);                 // T = never — пустой массив без контекста
```

TypeScript выводит наиболее подходящий тип из аргументов. Когда вывод невозможен или слишком широк, указывают тип явно:

```typescript
const [items, setItems] = useState<Product[]>([]); // иначе never[]
const ref = useRef<HTMLDivElement>(null);
const empty = new Set<string>();
```

`const`-параметры типа (TS 5.0) выводят литеральные типы, как при `as const`:

```typescript
function routes<const T extends readonly string[]>(paths: T) { return paths; }
const r = routes(["/home", "/about"]); // readonly ["/home", "/about"]
```

## Несколько параметров типа

```typescript
function pair<K, V>(key: K, value: V): [K, V] {
  return [key, value];
}
pair("id", 42); // [string, number]

function mapValues<T, R>(obj: Record<string, T>, fn: (value: T) => R): Record<string, R> {
  return Object.fromEntries(Object.entries(obj).map(([k, v]) => [k, fn(v)]));
}

mapValues({ a: 1, b: 2 }, (n) => String(n)); // Record<string, string>
```

Параметры могут ссылаться друг на друга:

```typescript
function getProp<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

getProp({ name: "Анна", age: 25 }, "age");  // number
getProp({ name: "Анна" }, "email");         // ошибка: "email" не ключ объекта
```

## Частичное указание невозможно

```typescript
function convert<From, To>(value: From, fn: (v: From) => To): To { return fn(value); }

convert<string>("1", Number); // ошибка: нужно указать оба параметра или ни одного
```

Решение — каррирование функции или значения по умолчанию для параметров типа.

## Что важно помнить

- Чем меньше явных аннотаций при вызове, тем лучше: хороший дженерик выводит типы сам.
- Если `T` используется только один раз, дженерик, скорее всего, не нужен.
- Вывод работает слева направо по параметрам — колбэки, зависящие от `T`, ставят после аргумента, из которого `T` выводится.
- `NoInfer<T>` (TS 5.4) запрещает выводить `T` из конкретного аргумента.

## Мини-шпаргалка

- `function f<T>(x: T)` или `<T,>(x: T) => ...`.
- `T` выводится из аргументов, явно — `f<string>(...)`.
- Пустые коллекции и `useState([])` — указывайте тип.
- Несколько параметров: `<K, V>`, зависимые: `<T, K extends keyof T>`.
- `const T` — вывод литеральных типов.
