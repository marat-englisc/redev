# Ограничения дженериков: extends, keyof и ошибки ограничений

> [!NOTE]
> Ограничение `T extends Constraint` говорит: «T может быть любым типом, но он должен быть совместим с Constraint». Благодаря этому внутри функции можно использовать свойства из ограничения, а при вызове TypeScript отклонит неподходящий тип с ошибкой «does not satisfy the constraint». Частый прием — ограничить параметр ключами другого типа: `K extends keyof T`.

## Вопрос

Как ограничить дженерик? Что делает `extends` в generic-параметрах и что произойдет, если тип не проходит ограничение? Как ограничить тип ключами другого типа?

## Зачем нужны ограничения

```typescript
function getLength<T>(value: T) {
  return value.length; // ошибка: Property 'length' does not exist on type 'T'
}

function getLengthOk<T extends { length: number }>(value: T): number {
  return value.length;  // OK — у T гарантированно есть length
}

getLengthOk("текст");      // OK
getLengthOk([1, 2, 3]);    // OK
getLengthOk({ length: 5 }); // OK
getLengthOk(42);           // ошибка
```

## Ошибка ограничения

```typescript
function save<T extends { id: string }>(entity: T) {}

save({ id: "1", name: "Анна" }); // OK — лишние поля допустимы
save({ name: "Анна" });
// Argument of type '{ name: string; }' is not assignable to parameter of type '{ id: string; }'.
// Property 'id' is missing...
```

При явном указании: `save<number>(1)` → `Type 'number' does not satisfy the constraint '{ id: string; }'`.

## Ключи другого типа: keyof

```typescript
function pick<T, K extends keyof T>(obj: T, keys: K[]): Pick<T, K> {
  const result = {} as Pick<T, K>;
  for (const key of keys) result[key] = obj[key];
  return result;
}

const user = { id: 1, name: "Анна", email: "a@example.com" };

pick(user, ["id", "name"]);   // { id: number; name: string }
pick(user, ["age"]);          // ошибка: "age" не входит в keyof typeof user
```

```typescript
function sortBy<T, K extends keyof T>(items: T[], key: K): T[] {
  return items.toSorted((a, b) => (a[key] < b[key] ? -1 : a[key] > b[key] ? 1 : 0));
}

sortBy(products, "price");
sortBy(products, "prise"); // опечатка — ошибка компиляции
```

## Ограничение другим параметром

```typescript
function merge<T extends object, U extends Partial<T>>(base: T, patch: U): T & U {
  return { ...base, ...patch };
}
```

## Типичные ограничения

| Ограничение | Смысл |
| --- | --- |
| `T extends string` | только строки и строковые литералы |
| `T extends object` | любой непримитив |
| `T extends Record<string, unknown>` | объект с строковыми ключами |
| `T extends unknown[]` / `readonly unknown[]` | массивы и кортежи |
| `T extends (...args: never[]) => unknown` | функции |
| `K extends keyof T` | ключи типа T |
| `T extends { id: string }` | объекты с полем id |

## Что важно помнить

- `extends` в ограничении — это «совместим с», а не наследование классов.
- Внутри функции `T` может быть **подтипом** ограничения: `T extends string` может оказаться литералом `"a"`, поэтому нельзя вернуть произвольную строку как `T`.
- Слишком общее ограничение (`T extends any`) ничего не дает, слишком узкое — лишает функцию универсальности.
- Ограничение `T extends {}` исключает `null` и `undefined`.

## Мини-шпаргалка

- `T extends C` — T должен быть совместим с C.
- Внутри доступны члены C.
- Неподходящий тип → «does not satisfy the constraint».
- `K extends keyof T` — ключи другого типа, защита от опечаток.
- Параметры могут ограничивать друг друга.
