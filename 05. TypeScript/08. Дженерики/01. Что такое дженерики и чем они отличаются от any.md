# Что такое дженерики и чем они отличаются от any

> [!NOTE]
> **Дженерики (generics)** — параметры типов: функция, тип или класс принимает тип как аргумент (`<T>`) и сохраняет связь между входом и выходом. `function first<T>(items: T[]): T` вернет `string` для `string[]` и `User` для `User[]`. В отличие от `any`, который стирает информацию о типе, дженерик ее **сохраняет** и позволяет писать универсальный, но типобезопасный код.

## Вопрос

Что такое дженерики в TypeScript и зачем они нужны? Чем дженерики отличаются от `any`?

## Проблема без дженериков

```typescript
function firstNumber(items: number[]): number { return items[0]; }
function firstString(items: string[]): string { return items[0]; }
// дублирование для каждого типа

function firstAny(items: any[]): any { return items[0]; }
const value = firstAny(["a", "b"]);   // any — тип потерян
value.toFixed();                       // компилируется, падает в runtime
```

## С дженериком

```typescript
function first<T>(items: T[]): T | undefined {
  return items[0];
}

const name = first(["Анна", "Иван"]);  // string | undefined
const user = first(users);             // User | undefined
name?.toFixed();                        // ошибка: toFixed не существует у string
```

`T` выводится из аргумента автоматически, явно писать `first<string>(...)` обычно не нужно.

## Дженерики и any

| | `any` | Дженерик `<T>` |
| --- | --- | --- |
| Принимает любой тип | да | да |
| Помнит, какой тип передали | нет | да |
| Связь вход → выход | теряется | сохраняется |
| Проверка операций | отключена | работает (по ограничениям `T`) |
| Автодополнение | нет | есть |

```typescript
function identityAny(value: any): any { return value; }
function identity<T>(value: T): T { return value; }

identityAny(42).toUpperCase(); // компилируется — ошибка в runtime
identity(42).toUpperCase();    // ошибка компиляции
```

## Где встречаются

```typescript
const list: Array<string> = [];
const map = new Map<string, User>();
const promise: Promise<User> = fetchUser();
const [count, setCount] = useState<number>(0);
const ref = useRef<HTMLInputElement>(null);

type ApiResponse<T> = { data: T; error: string | null };
interface Repository<T> {
  findById(id: string): Promise<T | null>;
  save(entity: T): Promise<void>;
}

class Stack<T> {
  #items: T[] = [];
  push(item: T) { this.#items.push(item); }
  pop(): T | undefined { return this.#items.pop(); }
}
```

## Именование

`T`, `U`, `K`, `V` — традиция для коротких дженериков; для сложных лучше говорящие имена: `TItem`, `TResponse`, `TKey`.

## Что важно помнить

- Дженерик полезен, только если `T` связывает несколько мест: параметр и результат, два параметра. `function log<T>(x: T): void` — лишний дженерик, хватит `unknown`.
- Ограничения (`T extends ...`) позволяют использовать свойства `T` внутри функции.
- В `.tsx` стрелочный дженерик пишут как `<T,>(x: T) => x` или `<T extends unknown>`, чтобы не путать с JSX.
- Типы дженериков стираются в runtime: `T` нельзя проверить через `typeof` или `instanceof`.

## Мини-шпаргалка

- Дженерик — параметр типа `<T>`.
- Сохраняет связь между типами входа и выхода.
- `any` теряет тип, дженерик — нет.
- `T` обычно выводится автоматически.
- `Array<T>`, `Promise<T>`, `Map<K, V>`, `useState<T>` — всё дженерики.
