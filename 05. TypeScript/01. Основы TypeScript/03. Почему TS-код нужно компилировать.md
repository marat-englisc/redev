# Почему TS-код нужно компилировать?

> [!NOTE]
> TypeScript нужно компилировать, потому что браузер и Node.js выполняют JavaScript, а не TypeScript-аннотации типов.

## Вопрос

Почему TypeScript-код нельзя просто отдать браузеру как есть?

## Определение

TypeScript содержит синтаксис, которого нет в JavaScript: аннотации типов, интерфейсы, type aliases, generics. Перед выполнением этот код нужно преобразовать в JavaScript.

Компилятор TypeScript проверяет типы и удаляет type-only конструкции.

## Пример TypeScript

```typescript
function sum(a: number, b: number): number {
  return a + b;
}
```

## После компиляции

```javascript
function sum(a, b) {
  return a + b;
}
```

Типы исчезли, осталась исполняемая JavaScript-функция.

## Что делает компиляция

- проверяет типы;
- удаляет типовые аннотации;
- преобразует часть синтаксиса под нужную версию JS;
- может генерировать `.d.ts` файлы для библиотек;
- сообщает об ошибках до запуска.

## tsc и сборщики

TS можно компилировать через `tsc`, Vite, Webpack, esbuild, SWC и другие инструменты. В современных frontend-проектах компиляция часто встроена в сборку.

## Что важно помнить

- Браузеры не понимают типы TypeScript — их нужно удалить (transpile) и при желании проверить (type check).
- Vite, esbuild, SWC и Babel только удаляют типы без проверки, поэтому `tsc --noEmit` запускают отдельно в CI.
- `target` в tsconfig определяет, в какую версию JavaScript преобразуется синтаксис.
- Node.js 22.6+ умеет запускать `.ts` через type stripping, но без проверки типов и без `enum`/`namespace`.

## Мини-шпаргалка

```text
.ts/.tsx -> TypeScript compiler/build tool -> .js
```
