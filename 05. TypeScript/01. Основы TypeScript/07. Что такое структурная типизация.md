# Структурная типизация

> [!NOTE]
> TypeScript использует **структурную типизацию** («утиную»): совместимость типов определяется формой — набором свойств и их типов, а не именем типа. Если у объекта есть все требуемые свойства нужных типов, он подходит, даже если объявлен под другим именем или вообще без типа. В номинальных языках (Java, C#) совместимость определяется явным объявлением. Исключение — проверка лишних свойств (excess property check) для объектных литералов.

## Вопрос

Что означает структурная типизация? Как она работает с интерфейсами и чем отличается от номинальной?

## Совместимость по форме

```typescript
interface Point {
  x: number;
  y: number;
}

type Coordinates = {
  x: number;
  y: number;
};

const a: Point = { x: 1, y: 2 };
const b: Coordinates = a; // OK — формы совпадают, имена не важны

function log(point: Point) {
  console.log(point.x, point.y);
}

const pixel = { x: 10, y: 20, color: "red" };
log(pixel); // OK — лишнее свойство color допустимо
```

Объект с **большим** набором свойств совместим с типом, который требует меньше (подтип).

## Классы тоже структурны

```typescript
class Cat {
  name = "";
}

class Dog {
  name = "";
}

const pet: Cat = new Dog(); // OK — одинаковая структура
```

Исключение: классы с `private`/`protected` или `#private` полями совместимы только со своими наследниками.

## Проверка лишних свойств

```typescript
log({ x: 1, y: 2, color: "red" }); // ошибка: Object literal may only specify known properties
```

Для **свежих объектных литералов** TypeScript дополнительно проверяет лишние свойства — чтобы ловить опечатки (`colr` вместо `color`). Если объект сначала положить в переменную, проверка не сработает.

## Структурная и номинальная

| | Структурная (TypeScript, Go) | Номинальная (Java, C#) |
| --- | --- | --- |
| Совместимость | по форме | по имени и явному наследованию |
| Нужен ли `implements` | нет, совпадения формы достаточно | да |
| Гибкость | высокая, удобно с JS-объектами | ниже |
| Риск | разные по смыслу типы одной формы смешиваются | меньше |

## Branded types: имитация номинальности

```typescript
type UserId = string & { readonly __brand: "UserId" };
type OrderId = string & { readonly __brand: "OrderId" };

const toUserId = (id: string) => id as UserId;

function getUser(id: UserId) {}

const orderId = "o-1" as OrderId;
getUser(orderId); // ошибка — бренды разные, хотя оба string
```

Так защищаются от путаницы id разных сущностей, валют, единиц измерения.

## Что важно помнить

- Структурная типизация — причина, по которой `Object.keys(obj)` возвращает `string[]`: у объекта могут быть лишние ключи.
- Пустой интерфейс `{}` совместим почти с любым значением, кроме `null` и `undefined`.
- Функции тоже сравниваются структурно: функция с меньшим числом параметров совместима с типом, ожидающим больше.
- `implements` в классе лишь проверяет форму, но не создает номинальную связь.

## Мини-шпаргалка

- Совместимость по форме, а не по имени.
- Лишние свойства допустимы, кроме свежих литералов.
- Классы тоже структурны, кроме приватных полей.
- Номинальность имитируют branded types.
- `{}` принимает почти всё.
