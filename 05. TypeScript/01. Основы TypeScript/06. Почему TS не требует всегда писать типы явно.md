# Почему TS не требует всегда писать типы явно?

> [!NOTE]
> TypeScript умеет выводить типы автоматически, поэтому явные аннотации нужны не везде.

## Вопрос

Почему в TypeScript не обязательно писать тип у каждой переменной?

## Определение

TypeScript использует type inference - вывод типов. Компилятор анализирует значение и сам понимает, какой тип у переменной, результата функции или выражения.

## Пример

```typescript
const name = 'Ann';
const age = 25;

// name: string
// age: number
```

Писать `const name: string = 'Ann'` обычно избыточно.

## Когда тип лучше написать явно

```typescript
function getUser(id: number): User {
  return usersById[id];
}
```

Явный тип полезен:

- у параметров функций;
- у публичных API;
- у сложных возвращаемых значений;
- когда нужно зафиксировать контракт;
- когда inference выводит слишком широкий или слишком узкий тип.

## Вывод типа объекта

```typescript
const user = {
  id: 1,
  name: 'Ann',
};
```

TypeScript поймет тип объекта автоматически:

```typescript
{
  id: number;
  name: string;
}
```

## Практическое правило

Не нужно типизировать очевидное. Лучше явно типизировать границы: параметры функций, API, данные от сервера, публичные типы модулей.

## Что важно помнить

- Вывод типов работает для переменных, возвращаемых значений и параметров колбэков (contextual typing).
- Параметры функций TypeScript не выводит из использования — их нужно типизировать.
- `const` выводит литеральный тип, `let` — расширенный (`"a"` против `string`).
- `satisfies` проверяет значение на соответствие типу, сохраняя точный выведенный тип.

## Мини-шпаргалка

```typescript
const count = 1; // number inferred

function sum(a: number, b: number): number {
  return a + b;
}
```
