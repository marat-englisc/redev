# Что такое TypeScript и почему он улучшает качество кода

> [!NOTE]
> **TypeScript** — надстройка (superset) над JavaScript от Microsoft, которая добавляет статическую систему типов. Любой валидный JavaScript — валидный TypeScript. Код на TS проверяется компилятором и превращается в обычный JavaScript, а типы при этом полностью стираются. TypeScript улучшает качество кода: ловит ошибки до запуска, дает автодополнение и безопасный рефакторинг, документирует контракты функций и компонентов.

## Вопрос

Что такое TypeScript? Почему его называют надстройкой над JavaScript и как он улучшает качество кода?

## Надстройка над JavaScript

```text
TypeScript = JavaScript + типы + проверка на этапе компиляции
```

```typescript
// валидный JS — валидный TS
function sum(a, b) {
  return a + b;
}

// TS добавляет типы
function sumTyped(a: number, b: number): number {
  return a + b;
}

sumTyped(1, "2"); // ошибка компиляции: Argument of type 'string' is not assignable to parameter of type 'number'
```

После компиляции типы исчезают:

```javascript
function sumTyped(a, b) {
  return a + b;
}
```

TypeScript не меняет поведение программы в runtime (за редкими исключениями вроде `enum`), а только проверяет код.

## Что дает TypeScript

| Польза | Пример |
| --- | --- |
| Ошибки до запуска | опечатка в свойстве, `undefined` вместо объекта, неверный аргумент |
| Автодополнение и навигация | IDE знает поля объектов и сигнатуры функций |
| Безопасный рефакторинг | переименование поля подсвечивает все места использования |
| Документация в коде | типы props и ответов API читаются как контракт |
| Моделирование домена | union-типы, discriminated unions, литеральные типы |
| Масштабируемость | большой команде проще поддерживать кодовую базу |

```typescript
type User = { id: number; name: string; email?: string };

function sendEmail(user: User) {
  user.email.toLowerCase(); // ошибка: 'user.email' is possibly 'undefined'
}
```

## Чего TypeScript не делает

- не проверяет данные в runtime: ответ API может не совпасть с типом — нужна валидация (Zod, Valibot);
- не ускоряет код;
- не заменяет тесты: логические ошибки типами не поймать;
- не защищает от `any` и `as`, которыми проверку можно отключить.

## Где используется

- фронтенд-фреймворки: React, Angular (TS по умолчанию), Vue, Next.js;
- Node.js-бэкенды (NestJS), библиотеки и SDK;
- типы для JS-библиотек публикуются в пакетах `@types/*` или вместе с библиотекой.

## Что важно помнить

- TypeScript проверяется отдельно от сборки: Vite и esbuild удаляют типы без проверки, поэтому `tsc --noEmit` запускают в CI.
- Node.js умеет запускать TS напрямую через type stripping, но только для «стираемого» синтаксиса (без `enum` и `namespace`).
- Строгий режим (`strict: true`) — основа пользы TypeScript; без него многие ошибки пропускаются.
- Хороший TS-код опирается на вывод типов, а не на аннотации везде.

## Мини-шпаргалка

- TypeScript — JavaScript + статические типы.
- Любой JS — валидный TS.
- Типы стираются при компиляции.
- Польза: ошибки до запуска, автодополнение, рефакторинг, документация.
- Runtime-данные нужно валидировать отдельно.
