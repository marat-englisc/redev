# Модификаторы доступа: public, private, protected и #private

> [!NOTE]
> TypeScript добавляет к классам модификаторы доступа. `public` (по умолчанию) — член доступен везде, `protected` — только в классе и его наследниках, `private` — только внутри объявившего класса. Эти модификаторы проверяются **только компилятором** и исчезают в JavaScript. Настоящую приватность в runtime дают поля JavaScript `#field`. Отдельно есть `readonly` — запрет переназначения после инициализации.

## Вопрос

Какие модификаторы доступа есть в TypeScript? Что делают `public`, `private` и `protected` и чем `private` отличается от `#private`?

## Модификаторы

```typescript
class BankAccount {
  public owner: string;              // доступно везде (public можно не писать)
  protected balance = 0;             // класс и наследники
  private pin: string;               // только этот класс
  readonly createdAt = new Date();   // нельзя переназначить
  #history: number[] = [];           // приватность JavaScript в runtime

  constructor(owner: string, pin: string) {
    this.owner = owner;
    this.pin = pin;
  }

  deposit(amount: number) {
    this.balance += amount;
    this.#history.push(amount);
  }
}

class SavingsAccount extends BankAccount {
  addInterest() {
    this.balance *= 1.05;  // OK — protected доступен наследнику
    this.pin;              // ошибка: private
  }
}

const acc = new BankAccount("Анна", "1234");
acc.owner;     // OK
acc.balance;   // ошибка: protected
acc.pin;       // ошибка: private
```

## Сводная таблица

| Модификатор | Класс | Наследник | Снаружи | В runtime |
| --- | :---: | :---: | :---: | --- |
| `public` | ✅ | ✅ | ✅ | обычное свойство |
| `protected` | ✅ | ✅ | ❌ | обычное свойство |
| `private` | ✅ | ❌ | ❌ | обычное свойство |
| `#field` | ✅ | ❌ | ❌ | настоящая приватность |
| `readonly` | запись в конструкторе | чтение | чтение | обычное свойство |

## private и #private

```typescript
class A {
  private secret = 1;
  #realSecret = 2;
}

const a = new A();
(a as any).secret;       // 1 — private обходится приведением
a["secret"];             // тоже работает (bracket notation не проверяется)
Object.keys(a);          // ["secret"] — поле видно
// a.#realSecret         — SyntaxError, обойти нельзя
```

| | `private` (TS) | `#field` (JS) |
| --- | --- | --- |
| Проверка | только компилятором | движком в runtime |
| Обход через `as any` / `obj["x"]` | возможен | невозможен |
| Видно в `Object.keys`, JSON | да | нет |
| Совместимость типов | номинальная (только с наследниками) | номинальная |
| Работает с `Proxy` | да | нет |

Для библиотек и чувствительных данных выбирайте `#field`, в прикладном коде команды часто используют `private` за удобство.

## Parameter properties

```typescript
class UserService {
  constructor(
    private readonly api: ApiClient,
    protected logger: Logger,
    public name = "users",
  ) {}
}
```

Модификатор в параметре конструктора объявляет и сразу инициализирует поле. Это не стираемый синтаксис — он несовместим с `erasableSyntaxOnly` и Node.js type stripping.

## Что важно помнить

- `protected` удобен для расширения в наследниках, но создает связанность иерархии.
- Модификаторы доступны и для методов, геттеров, статических членов.
- Класс с `private` или `protected` полями несовместим с другим классом той же структуры — это исключение из структурной типизации.
- `readonly` поверхностный: объект внутри поля можно менять.

## Мини-шпаргалка

- `public` — везде, `protected` — класс и наследники, `private` — только класс.
- TS-модификаторы стираются, `#field` приватен в runtime.
- `readonly` — нельзя переназначить после конструктора.
- Parameter properties: `constructor(private api: Api) {}`.
- Для настоящей инкапсуляции — `#field`.
