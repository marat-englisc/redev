# Типизация конструктора и перегрузка конструктора

> [!NOTE]
> Параметры конструктора типизируют так же, как параметры функции, а поля класса объявляют с типами в теле класса или через parameter properties (`constructor(private api: Api)`). Реализация конструктора в классе одна, но TypeScript позволяет описать **несколько сигнатур перегрузки** — разные варианты вызова `new` с одной общей реализацией. Часто вместо перегрузок удобнее статические фабричные методы.

## Вопрос

Как типизировать конструктор класса в TypeScript? Можно ли перегрузить конструктор?

## Типизация

```typescript
class User {
  id: string;
  name: string;
  email?: string;

  constructor(id: string, name: string, email?: string) {
    this.id = id;
    this.name = name;
    this.email = email;
  }
}
```

С `strictPropertyInitialization` поле без значения по умолчанию должно быть присвоено в конструкторе, иначе ошибка. Если поле инициализируется позже (например, в `init()`), используют `!`: `db!: Database` — но это обещание компилятору, а не проверка.

## Parameter properties

```typescript
class ApiClient {
  constructor(
    private readonly baseUrl: string,
    private timeout = 5000,
  ) {}

  get(path: string) {
    return fetch(`${this.baseUrl}${path}`, { signal: AbortSignal.timeout(this.timeout) });
  }
}
```

## Перегрузка конструктора

```typescript
class Point {
  x: number;
  y: number;

  constructor();                         // сигнатура 1
  constructor(x: number, y: number);     // сигнатура 2
  constructor(point: { x: number; y: number }); // сигнатура 3
  constructor(a?: number | { x: number; y: number }, b?: number) { // реализация
    if (typeof a === "object") {
      this.x = a.x;
      this.y = a.y;
    } else {
      this.x = a ?? 0;
      this.y = b ?? 0;
    }
  }
}

new Point();
new Point(1, 2);
new Point({ x: 1, y: 2 });
new Point(1);   // ошибка: нет такой сигнатуры
```

Сигнатура реализации снаружи не видна — вызывать можно только по объявленным перегрузкам.

## Альтернатива: статические фабрики

```typescript
class Money {
  private constructor(readonly amount: number, readonly currency: string) {}

  static rub(amount: number) {
    return new Money(amount, "RUB");
  }

  static parse(text: string) {
    const [amount, currency] = text.split(" ");
    return new Money(Number(amount), currency);
  }
}

Money.rub(100);
Money.parse("15 USD");
new Money(1, "RUB"); // ошибка: конструктор private
```

Фабрики с понятными именами читаются лучше перегрузок, а `private constructor` запрещает создание в обход них.

## Тип конструктора

```typescript
type Constructor<T = object> = new (...args: any[]) => T;

function createAll<T>(Cls: Constructor<T>, count: number): T[] {
  return Array.from({ length: count }, () => new Cls());
}

type Args = ConstructorParameters<typeof ApiClient>; // [baseUrl: string, timeout?: number]
```

## Что важно помнить

- Конструктор не может быть `async` и не может иметь возвращаемый тип в аннотации.
- В наследнике `super(...)` нужно вызвать до обращения к `this`, а параметры родителя тоже типизируются.
- `private constructor` используют для синглтонов и фабрик.
- Для многих необязательных параметров удобнее один объект настроек, чем перегрузки.

## Мини-шпаргалка

- Параметры конструктора — как у функции, поля — с типами в классе.
- Parameter properties: `constructor(private x: T)`.
- Перегрузка: несколько сигнатур + одна реализация.
- Альтернатива — статические фабрики и `private constructor`.
- Тип класса: `new (...args) => T`, `ConstructorParameters`.
