# type и interface: что это, чем отличаются и что выбрать

> [!NOTE]
> **Type alias** (`type`) дает имя любому типу: объекту, union, кортежу, функции, примитиву, результату utility- или условного типа. **Interface** (`interface`) описывает только форму объекта (или класса) и поддерживает declaration merging — объединение одноименных объявлений. Для объектов они почти взаимозаменяемы. Практическое правило: `interface` — для объектных контрактов и публичных API, `type` — для union, кортежей, функций и вычисляемых типов.

## Вопрос

Что такое тип (type) и интерфейс в TypeScript? В чем их отличие и почему интерфейсы чаще применяются для объектов?

## Type alias

```typescript
type Id = string | number;                       // union
type Point = { x: number; y: number };           // объект
type Pair = [string, number];                    // кортеж
type Handler = (event: Event) => void;           // функция
type Status = "idle" | "loading" | "done";       // литералы
type ReadonlyUser = Readonly<User>;              // utility
type EventName = `on${Capitalize<string>}`;      // template literal
type ElementOf<T> = T extends (infer U)[] ? U : never; // условный
```

## Interface

```typescript
interface User {
  id: number;
  name: string;
  greet(): string;
}

interface Admin extends User {
  permissions: string[];
}

class Account implements User {
  constructor(public id: number, public name: string) {}
  greet() { return this.name; }
}
```

## Сравнение

| Возможность | `interface` | `type` |
| --- | --- | --- |
| Описать объект | да | да |
| Union, кортежи, примитивы, функции | нет напрямую | да |
| Mapped и conditional types | нет | да |
| Расширение | `extends` | `&` (пересечение) |
| Declaration merging | да | нет — повторное имя дает ошибку |
| `implements` у класса | да | да, если тип объектный |
| Сообщения об ошибках и кеширование | обычно лучше | пересечения бывают громоздкими |

## Declaration merging

```typescript
interface Window {
  analytics: { track(event: string): void };
}

window.analytics.track("open"); // интерфейс Window из lib.dom расширен

interface Config { apiUrl: string }
interface Config { timeout: number }
// итоговый Config: { apiUrl: string; timeout: number }
```

Полезно для расширения глобальных типов и типов библиотек (module augmentation). Опасно, если имя интерфейса случайно совпало — поля «сольются» незаметно.

## Почему интерфейсы чаще для объектов

- `extends` дает понятные ошибки при конфликте полей, а `&` молча создает `never`;
- компилятор кеширует интерфейсы, и проверка больших иерархий быстрее;
- в подсказках IDE отображается имя интерфейса, а не развернутая структура;
- declaration merging позволяет расширять типы библиотек;
- исторически документация TypeScript рекомендовала `interface` для публичных объектных API.

## Что выбрать на практике

```typescript
// объект-контракт: props, модели, API
interface ProductCardProps {
  product: Product;
  onAddToCart(id: string): void;
}

// всё остальное
type ProductId = string;
type SortOrder = "asc" | "desc";
type LoadState = { status: "loading" } | { status: "ready"; data: Product[] };
```

Главное — единообразие в проекте: многие команды выбирают «везде `type`» или «`interface` для объектов, `type` для остального» и закрепляют правилом `@typescript-eslint/consistent-type-definitions`.

## Что важно помнить

- И `type`, и `interface` стираются при компиляции.
- Интерфейс не может описать union — для discriminated union нужен `type`.
- Type alias не создает новый тип, а только дает имя; два alias с одинаковой структурой совместимы.
- Index signature в интерфейсе и `Record` в type решают одну задачу.

## Мини-шпаргалка

- `type` — имя для любого типа.
- `interface` — форма объекта, `extends`, declaration merging.
- Union, кортежи, функции, вычисляемые типы — только `type`.
- Объектные контракты — чаще `interface`.
- Главное — единый стиль в проекте.
