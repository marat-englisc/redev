# Наследование интерфейсов и типов: extends, множественное наследование, пересечение

> [!NOTE]
> Интерфейс расширяют через `extends`: он получает все поля родителя и добавляет свои. Интерфейс может наследовать **несколько** интерфейсов сразу (`extends A, B`) и даже type alias объектного типа. Type alias «наследуют» через пересечение `&`. Разница проявляется при конфликтах: `extends` сразу сообщает о несовместимом поле, а `&` молча дает `never` в этом поле.

## Вопрос

Как работает наследование в интерфейсах? Можно ли наследовать несколько интерфейсов? Как интерфейс может наследовать тип и наоборот?

## extends

```typescript
interface Entity {
  id: string;
  createdAt: Date;
}

interface User extends Entity {
  name: string;
  email: string;
}

const user: User = { id: "1", createdAt: new Date(), name: "Анна", email: "a@example.com" };
```

Можно сузить тип унаследованного поля, но не сделать его несовместимым:

```typescript
interface Animal { kind: string }
interface Dog extends Animal { kind: "dog" }   // OK — "dog" подтип string
interface Bad extends Animal { kind: number }  // ошибка
```

## Множественное наследование

```typescript
interface Timestamps {
  createdAt: Date;
  updatedAt: Date;
}

interface SoftDelete {
  deletedAt: Date | null;
}

interface Article extends Entity, Timestamps, SoftDelete {
  title: string;
}
```

Если в родителях одинаковые поля разных типов — ошибка компиляции.

## Интерфейс наследует тип

```typescript
type WithId = { id: string };

interface Product extends WithId {
  title: string;
}
```

Работает, если тип — объектный (или пересечение объектных). Union наследовать нельзя:

```typescript
type Shape = { kind: "circle" } | { kind: "square" };
interface Colored extends Shape {} // ошибка: An interface can only extend an object type
```

## Тип «наследует» интерфейс

```typescript
interface Base { id: string }

type Admin = Base & {
  permissions: string[];
};
```

## extends или &

| | `interface ... extends` | `type ... = A & B` |
| --- | --- | --- |
| Конфликт полей | ошибка сразу | поле становится `never` |
| Работает с union | нет | да (распределяется) |
| Сообщения об ошибках | понятнее | бывают громоздкими |
| Производительность компилятора | кешируется лучше | пересечения пересчитываются |

```typescript
type A = { value: string };
type B = { value: number };
type C = A & B;              // value: never — объект невозможно создать
```

## Что важно помнить

- Для иерархий объектных типов команда TypeScript рекомендует `interface extends` — он быстрее проверяется и дает понятные ошибки.
- Пересечения удобны для композиции «миксинов» и union-типов.
- Глубокая иерархия интерфейсов так же трудно поддерживается, как и классов — предпочитайте композицию.
- Класс может реализовать (`implements`) несколько интерфейсов, но наследовать (`extends`) только один класс.

## Мини-шпаргалка

- `interface B extends A` — наследование полей.
- `extends A, B, C` — множественное наследование.
- Интерфейс может наследовать объектный type alias.
- Тип расширяют пересечением `&`.
- Конфликт: `extends` — ошибка, `&` — `never`.
