# Тип never и never в функциях

> [!NOTE]
> `never` — тип значения, которого **не может существовать**: пустое множество значений. Его возвращают функции, которые никогда не завершаются нормально (всегда бросают ошибку или работают бесконечно). Он появляется при полном сужении union-типа и используется для проверки полноты (`exhaustive check`), а также в условных типах — чтобы «отфильтровать» варианты.

## Вопрос

Что такое тип `never`? Когда функция возвращает `never` и чем он отличается от `void`?

## Функции, которые не возвращают управление

```typescript
function fail(message: string): never {
  throw new Error(message);
}

function loop(): never {
  while (true) {}
}

function getUser(id: string) {
  const user = findUser(id);
  if (!user) fail("Пользователь не найден");
  return user; // TypeScript знает, что после fail выполнение не продолжится
}
```

## never и void

| | `void` | `never` |
| --- | --- | --- |
| Смысл | функция завершается, но не возвращает полезного значения | функция не завершается нормально |
| Возвращаемое значение | `undefined` | его нет |
| Пример | `console.log`, обработчик события | `throw`, бесконечный цикл |
| Присваивание | `undefined` совместим с `void` | ничего не совместимо с `never` (кроме самого `never`) |

## Полное сужение и exhaustive check

```typescript
type Shape =
  | { kind: "circle"; radius: number }
  | { kind: "square"; size: number };

function area(shape: Shape): number {
  switch (shape.kind) {
    case "circle":
      return Math.PI * shape.radius ** 2;
    case "square":
      return shape.size ** 2;
    default: {
      const unreachable: never = shape; // если добавят новый вид — ошибка компиляции
      throw new Error(`Неизвестная фигура: ${JSON.stringify(unreachable)}`);
    }
  }
}
```

После обработки всех вариантов тип `shape` в `default` сужается до `never`. Если в `Shape` добавят `triangle`, присваивание в `never` станет ошибкой — компилятор укажет на необработанный случай.

Удобный хелпер:

```typescript
function assertNever(value: never): never {
  throw new Error(`Необработанное значение: ${value}`);
}
```

## never в типах

```typescript
type NonString<T> = T extends string ? never : T;
type R = NonString<string | number | boolean>; // number | boolean

type A = string & number;         // never — пересечение несовместимых типов
type B = string | never;          // string — never исчезает из union
type Keys = keyof never;          // string | number | symbol
```

`never` — **нижний тип (bottom type)**: он совместим с любым типом, но никакой тип (кроме `never`) не совместим с ним.

## Что важно помнить

- Пустой массив без аннотации в некоторых контекстах получает тип `never[]` — в него нельзя добавить элементы; аннотируйте: `const items: string[] = []`.
- Функциональное выражение с `throw` выводится как `never`, а Function Declaration — как `void`; для сужения после вызова нужна явная аннотация `: never`.
- `never` в union исчезает, в intersection — «поглощает» всё.
- Exhaustive check через `never` — один из самых полезных паттернов TypeScript в редьюсерах и обработке состояний.

## Мини-шпаргалка

- `never` — значения не существует, пустое множество.
- Функции с `throw` или бесконечным циклом → `: never`.
- `void` — завершается без значения, `never` — не завершается.
- Exhaustive check: `const x: never = value` в `default`.
- `T | never = T`, `string & number = never`.
