# Тип unknown и его отличие от any

> [!NOTE]
> `unknown` — безопасный «верхний» тип: в переменную типа `unknown` можно положить что угодно, но использовать значение нельзя, пока тип не будет сужен проверкой (`typeof`, `instanceof`, type guard, валидация схемой). `any` тоже принимает всё, но полностью отключает проверку: с ним можно делать что угодно, и ошибки уходят в runtime. Для данных неизвестной формы — API, `JSON.parse`, `catch` — используйте `unknown`.

## Вопрос

Что означает тип `unknown`? Чем `unknown` отличается от `any` и когда его использовать?

## unknown требует проверки

```typescript
function handle(value: unknown) {
  value.toUpperCase();           // ошибка: 'value' is of type 'unknown'

  if (typeof value === "string") {
    value.toUpperCase();         // OK — тип сужен до string
  }

  if (value instanceof Date) {
    value.toISOString();         // OK
  }

  if (typeof value === "object" && value !== null && "id" in value) {
    console.log(value.id);       // OK — TS 4.9+ сужает и такие проверки
  }
}
```

## any отключает проверку

```typescript
function handleAny(value: any) {
  value.toUpperCase();     // компилируется, но может упасть в runtime
  value.foo.bar.baz();     // тоже компилируется
  const n: number = value; // any совместим со всем
}
```

## Сравнение

| | `unknown` | `any` |
| --- | --- | --- |
| Можно присвоить любое значение | да | да |
| Можно присвоить в другой тип | только в `unknown` и `any` | в любой |
| Доступ к свойствам и вызов | только после сужения | без ограничений |
| Безопасность | высокая | нет |
| «Заражает» код | нет | да: результат операций тоже `any` |
| Где уместен | внешние данные, `catch`, универсальные функции | миграция JS, обход багов типов |

## Где использовать unknown

```typescript
// ответ API — через валидацию
import { z } from "zod";

const UserSchema = z.object({ id: z.number(), name: z.string() });

async function loadUser(id: number) {
  const data: unknown = await fetch(`/api/users/${id}`).then((r) => r.json());
  return UserSchema.parse(data); // тип User + проверка в runtime
}

// ошибки в catch (при strict — по умолчанию unknown)
try {
  risky();
} catch (error: unknown) {
  const message = error instanceof Error ? error.message : String(error);
}

// безопасный JSON.parse
function safeParse(text: string): unknown {
  return JSON.parse(text);
}
```

## Type guard для unknown

```typescript
type User = { id: number; name: string };

function isUser(value: unknown): value is User {
  return (
    typeof value === "object" &&
    value !== null &&
    typeof (value as Record<string, unknown>).id === "number" &&
    typeof (value as Record<string, unknown>).name === "string"
  );
}
```

## Что важно помнить

- `unknown` — верхний тип (top type), `never` — нижний; `any` — «выход» из системы типов.
- `JSON.parse` и `response.json()` возвращают `any` — сразу присваивайте результат в `unknown` или валидируйте.
- `as` поверх `unknown` (`data as User`) не проверяет данные — это тоже доверие на слово.
- В union `unknown` поглощает остальные типы: `unknown | string` — это `unknown`.

## Мини-шпаргалка

- `unknown` — принимает всё, но использовать можно только после сужения.
- `any` — принимает всё и отключает проверки.
- Внешние данные → `unknown` → валидация → точный тип.
- В `catch` ошибка — `unknown`.
- Предпочитайте `unknown` вместо `any`.
