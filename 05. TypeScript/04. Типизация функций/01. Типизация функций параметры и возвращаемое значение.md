# Типизация функций: параметры, возвращаемое значение и вывод типов

> [!NOTE]
> С точки зрения типов функция — это сигнатура: типы параметров и тип возвращаемого значения. Параметры нужно типизировать явно (TypeScript не выводит их из использования), а возвращаемый тип обычно **выводится автоматически** из `return`. Явную аннотацию результата пишут для публичных API, рекурсивных функций и когда нужно зафиксировать контракт.

## Вопрос

Как TypeScript смотрит на функцию? Как типизировать параметры и возвращаемое значение? Когда тип результата можно не писать?

## Сигнатура

```typescript
function calculateTotal(price: number, quantity: number): number {
  return price * quantity;
}

const greet = (name: string): string => `Привет, ${name}`;
```

Тип самой функции:

```typescript
type Calculate = (price: number, quantity: number) => number;
```

## Параметры

```typescript
function createUser(name: string, age: number, isAdmin: boolean) {}

createUser("Анна", 25);          // ошибка: Expected 3 arguments, but got 2
createUser("Анна", "25", false); // ошибка: string не number

// объект параметров — удобно для 3+ аргументов
function createOrder({ items, promo }: { items: string[]; promo?: string }) {}
```

Без аннотации параметр при `noImplicitAny` — ошибка, без флага — `any`.

## Возвращаемый тип

```typescript
function getUser(id: number) {
  if (id < 0) return null;
  return { id, name: "Анна" };
}
// выведен тип: { id: number; name: string } | null
```

Когда явная аннотация полезна:

- **публичный API модуля и библиотеки** — контракт не меняется случайно при правке реализации;
- **рекурсивные функции** — TypeScript не всегда может вывести тип;
- **сложный результат** — читателю проще понять сигнатуру;
- **проверка реализации** — компилятор укажет, если какая-то ветка вернула не то.

```typescript
function parsePrice(text: string): number {
  if (!text) return "0"; // ошибка видна сразу благодаря аннотации
  return Number(text);
}
```

## Вывод типов

```typescript
const double = (x: number) => x * 2;      // возвращает number
const toUpper = (s: string) => s.toUpperCase();

[1, 2, 3].map((n) => n * 2);              // n: number выведен из массива (contextual typing)
button.addEventListener("click", (e) => e.clientX); // e: MouseEvent
```

Контекстная типизация выводит типы параметров колбэков из места использования, поэтому в `map`, обработчиках событий и `useState` аннотации обычно не нужны.

## Async-функции

```typescript
async function fetchUser(id: number): Promise<User> {
  const response = await fetch(`/api/users/${id}`);
  return response.json(); // any → совместим с User, но не проверен!
}
```

## Что важно помнить

- Правило ESLint `explicit-module-boundary-types` требует типы результата у экспортируемых функций — включайте по договоренности команды.
- Возвращаемый тип `Promise<T>` обязателен у async-функций, если пишете аннотацию.
- Функция, которая иногда возвращает значение, а иногда нет, получит тип `T | undefined` — часто это признак ошибки.
- Перегрузки функций описывают разные сигнатуры для разных наборов аргументов.

## Мини-шпаргалка

- Сигнатура = типы параметров + тип результата.
- Параметры типизируем явно.
- Результат выводится автоматически; явно — для публичных API и рекурсии.
- Колбэки получают типы из контекста.
- Async → `Promise<T>`.
