# Задача: retry с экспоненциальной задержкой

> [!NOTE]
> `retry(fn, options)` вызывает асинхронную функцию и при ошибке повторяет ее до `retries` раз с паузой между попытками. Паузу обычно увеличивают экспоненциально (`base * 2 ** attempt`) и добавляют **jitter** (случайную составляющую), чтобы клиенты после сбоя не повторяли запросы одновременно. Хорошая реализация позволяет решать, **какие ошибки повторять** (сеть и 5xx — да, 4xx — нет), ограничивает максимальную задержку и поддерживает отмену через `AbortSignal`.

## Вопрос

Реализуйте `retry(fn, { retries, baseDelay, maxDelay, shouldRetry, signal })`. Как выбрать задержку между попытками и какие ошибки не нужно повторять?

## Решение

```javascript
const sleep = (ms, signal) =>
  new Promise((resolve, reject) => {
    const id = setTimeout(resolve, ms);
    signal?.addEventListener("abort", () => { clearTimeout(id); reject(signal.reason); }, { once: true });
  });

async function retry(fn, {
  retries = 3,
  baseDelay = 300,
  maxDelay = 10_000,
  shouldRetry = () => true,
  onRetry,
  signal,
} = {}) {
  for (let attempt = 0; ; attempt++) {
    signal?.throwIfAborted();
    try {
      return await fn(attempt);
    } catch (error) {
      const canRetry = attempt < retries && shouldRetry(error, attempt);
      if (!canRetry) throw error;

      const exp = Math.min(maxDelay, baseDelay * 2 ** attempt);
      const delay = Math.random() * exp;                       // full jitter
      onRetry?.(error, attempt + 1, delay);
      await sleep(delay, signal);
    }
  }
}
```

## Проверка

```javascript
let calls = 0;
const flaky = async () => {
  calls += 1;
  if (calls < 3) throw new Error(`сбой ${calls}`);
  return "успех";
};

await retry(flaky, { retries: 5, baseDelay: 100, onRetry: (e, n) => console.log("повтор", n, e.message) });
// повтор 1 сбой 1
// повтор 2 сбой 2
// "успех"

await retry(async () => { throw new Error("всегда"); }, { retries: 2, baseDelay: 10 }).catch((e) => e.message);
// "всегда" — после 1 вызова + 2 повторов
```

## Повторять только временные ошибки

```javascript
class HttpError extends Error {
  constructor(status) { super(`HTTP ${status}`); this.status = status; }
}

async function getJson(url, signal) {
  const res = await fetch(url, { signal });
  if (!res.ok) throw new HttpError(res.status);
  return res.json();
}

const isRetriable = (error) =>
  error.name !== "AbortError" &&
  (!(error instanceof HttpError) || error.status >= 500 || error.status === 429);

const data = await retry(() => getJson("/api/report"), { retries: 4, shouldRetry: isRetriable });
```

| Ошибка | Повторять? |
| --- | --- |
| сетевой сбой, таймаут | да |
| 5xx, 503 Service Unavailable | да |
| 429 Too Many Requests | да, с учетом `Retry-After` |
| 400, 401, 403, 404, 422 | нет — повтор даст то же самое |
| отмена пользователем (`AbortError`) | нет |

## Стратегии задержки

| Стратегия | Задержка | Минус |
| --- | --- | --- |
| фиксированная | `base` | после сбоя все клиенты бьют одновременно |
| экспоненциальная | `base * 2^n` | клиенты синхронизированы |
| экспоненциальная + full jitter | `random(0, base * 2^n)` | рекомендуемый вариант |

## Доп. вопросы интервьюера

- **Можно ли повторять POST?** только если операция идемпотентна (есть `Idempotency-Key`), иначе возможен дубль заказа.
- **Чем `retry` отличается от circuit breaker?** circuit breaker перестает отправлять запросы на какое-то время после серии ошибок, чтобы не добивать упавший сервис.
- **Как учесть `Retry-After`?** если сервер вернул заголовок, использовать его как задержку.

## Что важно помнить

- Всегда ограничивайте число попыток и максимальную задержку.
- Jitter обязателен для массовых клиентов.
- Не повторяйте ошибки клиента (4xx, кроме 429) и отмену.
- В TanStack Query и RTK Query повторы встроены — свою функцию пишут для остального кода.
- Связанные темы: [надежность и повторы в system design](<../../17. Frontend System Design/03. Нефункциональные требования/03. Как обеспечить надежность, обработку ошибок и офлайн.md>).

## Мини-шпаргалка

Цикл попыток: `try { return await fn() } catch { if (!canRetry) throw; await sleep(delay) }`. Задержка `random(0, min(max, base * 2 ** n))`. `shouldRetry`: сеть, 5xx, 429 — да; 4xx, Abort — нет. `signal` для отмены, POST — только идемпотентный.
