# Задача: sleep и таймаут для промиса

> [!NOTE]
> **`sleep(ms)`** — промис, который выполняется через `ms` миллисекунд: `await sleep(1000)`. **`withTimeout(promise, ms)`** — обертка, которая отклоняется ошибкой `TimeoutError`, если исходный промис не завершился за `ms`. Решение строится на `setTimeout` и `Promise.race`; важная деталь — **очищать таймер**, когда исходный промис завершился, и понимать, что таймаут **не отменяет** саму операцию: для этого нужен `AbortSignal`.

## Вопрос

Реализуйте `sleep(ms)` и `withTimeout(promise, ms)`. Как сделать так, чтобы операция действительно отменялась по таймауту?

## sleep

```javascript
const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function demo() {
  console.log("старт");
  await sleep(1000);
  console.log("через секунду");
}
```

С возможностью отмены:

```javascript
function sleep(ms, { signal } = {}) {
  return new Promise((resolve, reject) => {
    if (signal?.aborted) return reject(signal.reason);
    const id = setTimeout(resolve, ms);
    signal?.addEventListener("abort", () => {
      clearTimeout(id);
      reject(signal.reason);
    }, { once: true });
  });
}
```

В Node.js есть встроенный `import { setTimeout as sleep } from "node:timers/promises"`.

## withTimeout

```javascript
class TimeoutError extends Error {
  constructor(ms) {
    super(`Операция не завершилась за ${ms} мс`);
    this.name = "TimeoutError";
  }
}

function withTimeout(promise, ms) {
  let timerId;
  const timeout = new Promise((_, reject) => {
    timerId = setTimeout(() => reject(new TimeoutError(ms)), ms);
  });

  return Promise.race([promise, timeout]).finally(() => clearTimeout(timerId)); // не держать таймер
}
```

```javascript
await withTimeout(sleep(100).then(() => "готово"), 500);   // "готово"
await withTimeout(sleep(1000), 200).catch((e) => e.name);  // "TimeoutError"
```

## Настоящая отмена запроса

`withTimeout` перестает ждать, но `fetch` продолжит выполняться. Чтобы отменить сам запрос:

```javascript
async function fetchWithTimeout(url, ms, init = {}) {
  const res = await fetch(url, { ...init, signal: AbortSignal.timeout(ms) });
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.json();
}

// своя версия, если нужен и внешний сигнал отмены
async function fetchWithTimeout2(url, ms, { signal, ...init } = {}) {
  const timeoutSignal = AbortSignal.timeout(ms);
  const combined = signal ? AbortSignal.any([signal, timeoutSignal]) : timeoutSignal;
  return fetch(url, { ...init, signal: combined });
}
```

При таймауте `fetch` отклоняется `DOMException` с `name === "TimeoutError"`, при ручной отмене — `"AbortError"`.

## Доп. вопросы интервьюера

- **Почему `finally` с `clearTimeout`?** иначе таймер останется в event loop: в Node.js процесс не завершится до его срабатывания, лишний `reject` уйдет в никуда.
- **Насколько точен `sleep(1000)`?** это минимальная задержка: если поток занят, срабатывание будет позже.
- **Как сделать `sleep` синхронным?** никак правильно — блокировка потока (`while (Date.now() < end)`) замораживает интерфейс.

## Что важно помнить

- Таймаут через `race` не отменяет операцию — только перестает ждать.
- Для `fetch` используйте `AbortSignal.timeout` и `AbortSignal.any`.
- Свой класс ошибки (`TimeoutError`) позволяет отличать таймаут от других ошибок.
- Теория: [отмена промисов и AbortController](<../../04. JavaScript/05. Асинхронность и Event Loop/15. Отмена промисов AbortController и AbortSignal.md>), [setTimeout](<../../04. JavaScript/05. Асинхронность и Event Loop/08. setTimeout и setInterval.md>).

## Мини-шпаргалка

`sleep = ms => new Promise(r => setTimeout(r, ms))`. `withTimeout = Promise.race([promise, timeout])` + `finally(clearTimeout)`. Настоящая отмена — `fetch(url, { signal: AbortSignal.timeout(ms) })`, объединение сигналов — `AbortSignal.any`.
