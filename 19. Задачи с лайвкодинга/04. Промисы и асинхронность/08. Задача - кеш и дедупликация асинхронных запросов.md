# Задача: кеш и дедупликация асинхронных запросов

> [!NOTE]
> Две связанные задачи: **дедупликация** — если запрос с тем же ключом уже выполняется, вернуть **тот же промис**, а не отправлять второй; и **кеш с TTL** — хранить результат какое-то время и отдавать его без нового запроса. Решение — `Map` ключ → промис (а не результат), удаление ключа **при ошибке**, чтобы следующий вызов мог повторить запрос, и время жизни записи. Третья связанная задача — **«побеждает последний запрос»**: игнорировать ответы устаревших запросов.

## Вопрос

Реализуйте `cachedFetch(key, fetcher, ttl)`: одинаковые одновременные вызовы делают один запрос, результат кешируется на `ttl` мс, ошибка не кешируется. Как сделать так, чтобы ответ устаревшего запроса не перезаписал новый?

## Дедупликация + кеш

```javascript
function createAsyncCache({ ttl = 60_000 } = {}) {
  const cache = new Map();          // key → { promise, expiresAt }

  return function cached(key, fetcher) {
    const entry = cache.get(key);
    if (entry && entry.expiresAt > Date.now()) return entry.promise;   // в работе или свежий результат

    const promise = Promise.resolve()
      .then(fetcher)
      .catch((error) => {
        cache.delete(key);          // ошибку не кешируем — следующий вызов повторит
        throw error;
      });

    cache.set(key, { promise, expiresAt: Date.now() + ttl });
    return promise;
  };
}
```

```javascript
const cached = createAsyncCache({ ttl: 30_000 });
let requests = 0;
const loadUser = (id) => cached(`user:${id}`, async () => {
  requests += 1;
  const res = await fetch(`/api/users/${id}`);
  return res.json();
});

await Promise.all([loadUser(1), loadUser(1), loadUser(1)]);
requests;          // 1 — три вызова, один запрос
await loadUser(1);
requests;          // 1 — из кеша
```

Кешируется **промис**: второй вызов во время выполнения получает тот же промис — это и есть дедупликация.

## «Побеждает последний запрос»

```javascript
function latest(fn) {
  let callId = 0;
  return async (...args) => {
    const id = ++callId;
    const result = await fn(...args);
    if (id !== callId) throw new DOMException("Устаревший запрос", "AbortError");  // пришел ответ на старый вызов
    return result;
  };
}

const search = latest((q) => fetch(`/api/search?q=${encodeURIComponent(q)}`).then((r) => r.json()));
```

Лучше — отменять предыдущий запрос:

```javascript
function latestAbortable(fn) {
  let controller = null;
  return (...args) => {
    controller?.abort();
    controller = new AbortController();
    return fn(...args, controller.signal);
  };
}

const search = latestAbortable((q, signal) =>
  fetch(`/api/search?q=${encodeURIComponent(q)}`, { signal }).then((r) => r.json()),
);
```

## Stale-while-revalidate (продолжение)

```javascript
const store = new Map();

function swr(key, fetcher, { staleAfter = 10_000 } = {}) {
  const entry = store.get(key);
  const now = Date.now();

  if (entry) {
    if (now - entry.time > staleAfter && !entry.revalidating) {
      entry.revalidating = true;
      fetcher().then((data) => store.set(key, { data, time: Date.now() }))
               .finally(() => { entry.revalidating = false; });
    }
    return Promise.resolve(entry.data);           // сразу отдаем старое
  }

  return fetcher().then((data) => { store.set(key, { data, time: now }); return data; });
}
```

## Доп. вопросы интервьюера

- **Почему кешировать промис, а не результат?** чтобы одновременные вызовы не создавали дубли до прихода ответа.
- **Как ограничить размер кеша?** LRU или периодическая очистка устаревших записей.
- **Как инвалидировать?** `cache.delete(key)` после мутации или по событию.
- **Готовые решения?** TanStack Query, SWR, RTK Query — дедупликация, кеш, повторы и инвалидация из коробки.

## Что важно помнить

- Ошибку удаляйте из кеша, иначе запрос никогда не повторится.
- Ключ кеша должен включать все параметры запроса.
- Для поиска по вводу нужна защита от гонок: отмена или проверка «последний ли это вызов».

## Мини-шпаргалка

`Map key → { promise, expiresAt }`: свежая запись → тот же промис (дедупликация + кеш), ошибка → `delete`. Последний запрос побеждает: счетчик вызовов или `AbortController` предыдущего. SWR — отдать старое, обновить в фоне.
