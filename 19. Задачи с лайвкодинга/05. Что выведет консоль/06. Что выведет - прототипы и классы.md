# Что выведет: прототипы и классы

> [!NOTE]
> Задачи на прототипы проверяют, что методы ищутся **по цепочке прототипов**: сначала в самом объекте, затем в `Object.getPrototypeOf(obj)` и выше до `Object.prototype` и `null`. Изменение прототипа видно **всем** уже созданным объектам, а присваивание свойства экземпляру **затеняет** свойство прототипа. Классы — синтаксис над той же моделью: методы лежат в `Class.prototype`, поля — в каждом экземпляре, `super.method()` вызывает метод родителя, а `instanceof` проверяет цепочку прототипов.

## Вопрос

Что выведет каждый фрагмент? Объясните поиск свойств по цепочке прототипов и поведение классов.

## Задача 1: функция-конструктор

```javascript
function Animal(name) { this.name = name; }
Animal.prototype.speak = function () { return `${this.name} издает звук`; };

const cat = new Animal("Мурка");
console.log(cat.speak());
console.log(cat.hasOwnProperty("speak"), "speak" in cat);
console.log(Object.getPrototypeOf(cat) === Animal.prototype);

Animal.prototype.speak = function () { return "новый звук"; };
console.log(cat.speak());
```

> [!TIP]- Ответ
> `Мурка издает звук`, `false true`, `true`, `новый звук`. Метод не собственный — он в прототипе; `in` ищет по всей цепочке. Изменение прототипа сразу видно существующим объектам.

## Задача 2: затенение свойства

```javascript
const base = { greeting: "привет", items: [] };
const a = Object.create(base);
const b = Object.create(base);

a.greeting = "hello";
a.items.push(1);

console.log(b.greeting, a.greeting);
console.log(b.items);
```

> [!TIP]- Ответ
> `привет hello`, затем `[1]`. Присваивание `a.greeting` создает собственное свойство `a`. А `a.items.push` не присваивает, а изменяет общий массив из прототипа — изменение видят все наследники. Поэтому изменяемые данные кладут в экземпляр, а не в прототип.

## Задача 3: классы и super

```javascript
class A {
  name = "A";
  hi() { return `A:${this.name}`; }
  static create() { return new this(); }
}

class B extends A {
  name = "B";
  hi() { return `B+${super.hi()}`; }
}

const b = B.create();
console.log(b.hi());
console.log(b instanceof A, b instanceof B);
console.log(Object.getOwnPropertyNames(B.prototype));
console.log(b.hasOwnProperty("name"), b.hasOwnProperty("hi"));
```

> [!TIP]- Ответ
> `B+A:B`, `true true`, `["constructor", "hi"]`, `true false`.
> `super.hi()` вызывает метод родителя с текущим `this` (у которого `name === "B"`). Статический метод с `new this()` создает экземпляр того класса, у которого вызван. Поля лежат в экземпляре, методы — в прототипе.

## Задача 4: объект без прототипа

```javascript
const dict = Object.create(null);
dict.key = "value";
console.log(typeof dict.toString);
console.log("key" in dict);
```

> [!TIP]- Ответ
> `undefined`, `true`. У объекта нет прототипа — нет и методов `Object.prototype`. Такие объекты используют как словари без конфликтов с ключами вроде `toString` или `__proto__`.

## Задача 5: порядок инициализации полей

```javascript
class Parent {
  value = "parent";
  constructor() {
    console.log("Parent constructor:", this.value, this.describe());
  }
  describe() { return "parent describe"; }
}

class Child extends Parent {
  value = "child";
  describe() { return `child describe (${this.value})`; }
}

new Child();
```

> [!TIP]- Ответ
> `Parent constructor: parent child describe (parent)`. Поля `Child` инициализируются **после** завершения конструктора `Parent`, поэтому в момент его выполнения `this.value === "parent"`. А метод `describe` уже переопределен — он берется из прототипа `Child`. Вызов переопределяемых методов в конструкторе — источник ошибок.

## Задача 6: приватные поля и getter

```javascript
class Temperature {
  #celsius = 0;
  get fahrenheit() { return this.#celsius * 9 / 5 + 32; }
  set celsius(v) { this.#celsius = v; }
}

const t = new Temperature();
t.celsius = 100;
console.log(t.fahrenheit);
console.log(Object.keys(t));
console.log("#celsius" in t);
```

> [!TIP]- Ответ
> `212`, `[]`, `false`. Приватные поля не видны снаружи, не перечисляются и недоступны по строковому имени. Геттер и сеттер лежат в прототипе.

## Цепочка прототипов

```text
cat ──▶ Animal.prototype ──▶ Object.prototype ──▶ null
 name     speak, constructor    toString, hasOwnProperty

b ──▶ B.prototype ──▶ A.prototype ──▶ Object.prototype ──▶ null
 name   hi (B)          hi (A), constructor
```

## Что важно помнить

- Поиск свойства: объект → прототип → … → `null`; запись — всегда в сам объект.
- Изменяемые значения в прототипе общие для всех экземпляров.
- В классах методы в `prototype`, поля и стрелочные поля — в каждом экземпляре.
- Поля наследника инициализируются после `super()`.

## Мини-шпаргалка

Чтение — по цепочке прототипов, запись — в объект (затенение). Мутация общего массива в прототипе видна всем. `hasOwnProperty` — только свои, `in` — вся цепочка. Класс: методы в prototype, поля в экземпляре, `super.m()` с текущим this, поля потомка — после конструктора родителя. `Object.create(null)` — без методов.
