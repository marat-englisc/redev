# Что выведет: this и потеря контекста

> [!NOTE]
> `this` в обычной функции определяется **способом вызова**: `obj.method()` → `obj`; просто `fn()` → `undefined` в строгом режиме (или глобальный объект в нестрогом); `fn.call(ctx)` → `ctx`; `new Fn()` → новый объект. **Стрелочная функция** своего `this` не имеет и берет его из внешней области **в момент создания**. `bind` фиксирует `this` навсегда — повторный `bind` и `call` его не меняют. Классические ловушки: метод, переданный как колбэк, деструктуризация метода и стрелка в литерале объекта.

## Вопрос

Что выведет каждый фрагмент? Объясните, чем определяется `this` в каждом вызове.

## Задача 1: способы вызова (строгий режим)

```javascript
"use strict";
const user = {
  name: "Анна",
  regular() { return this?.name; },
  nested() {
    const inner = () => this.name;
    return inner();
  },
  delayed() {
    return function () { return this; };
  },
};

console.log(user.regular());
const fn = user.regular;
console.log(fn());
console.log(user.nested());
console.log(user.delayed()());
```

> [!TIP]- Ответ
> `Анна`, `undefined`, `Анна`, `undefined`.
> - `user.regular()` — вызов как метода.
> - `fn()` — метод «оторван» от объекта, в строгом режиме `this === undefined` (оператор `?.` спасает от ошибки).
> - стрелка `inner` берет `this` из `nested`, где он равен `user`.
> - внутренняя обычная функция вызвана без объекта — `undefined`.

## Задача 2: стрелка в литерале объекта

```javascript
const counter = {
  count: 10,
  getArrow: () => this?.count,
  getRegular() { return this.count; },
};

console.log(counter.getArrow());
console.log(counter.getRegular());
```

> [!TIP]- Ответ
> `undefined` и `10`. Литерал объекта не создает свою область для `this`: стрелка берет `this` модуля или скрипта — в ES-модуле это `undefined`, в обычном скрипте браузера — `window` (у которого нет `count`).

## Задача 3: call, bind и заимствование метода

```javascript
const obj = {
  value: 42,
  getValue() { return this.value; },
};
const other = { value: 7, getValue: obj.getValue };

console.log(other.getValue());
console.log(obj.getValue.call({ value: 1 }));
const bound = obj.getValue.bind({ value: 100 });
console.log(bound.call({ value: 5 }));
console.log(bound.bind({ value: 6 })());
```

> [!TIP]- Ответ
> `7`, `1`, `100`, `100`. `this` определяется объектом слева от точки при вызове, а не местом объявления. Связанная функция игнорирует последующие `call` и `bind`.

## Задача 4: колбэки и таймеры

```javascript
const timer = {
  seconds: 0,
  startWrong() {
    setTimeout(function () {
      this.seconds++;                    // this — не timer
      console.log("wrong", this.seconds);
    }, 0);
  },
  startRight() {
    setTimeout(() => {
      this.seconds++;
      console.log("right", this.seconds);
    }, 0);
  },
};

timer.startWrong();
timer.startRight();
```

> [!TIP]- Ответ
> В браузере: `wrong NaN` (обычная функция в `setTimeout` получает `this === window`, `undefined + 1`), затем `right 1`. В Node.js `this` внутри колбэка таймера — объект `Timeout`, тоже `wrong NaN`. Стрелочная функция берет `this` из метода.

## Задача 5: методы класса и деструктуризация

```javascript
class Counter {
  count = 0;
  inc() { this.count++; return this.count; }
  incArrow = () => { this.count++; return this.count; };
}

const c = new Counter();
const { inc, incArrow } = c;

console.log(incArrow());
try { inc(); } catch (e) { console.log(e.constructor.name); }
```

> [!TIP]- Ответ
> `1`, затем `TypeError`. Код классов всегда в строгом режиме: у `inc` после деструктуризации `this === undefined`, и `this.count` бросает ошибку. Поле-стрелка `incArrow` создается в конструкторе и замыкает `this` экземпляра.

## Задача 6: косвенный вызов

```javascript
const obj = { value: 1, get() { return this?.value; } };

console.log(obj.get());
console.log((obj.get)());
console.log((0, obj.get)());
```

> [!TIP]- Ответ
> `1`, `1`, `undefined`. Скобки вокруг `obj.get` сохраняют ссылку на метод с объектом, а оператор запятая возвращает **просто функцию** — вызов без объекта. В нестрогом режиме `this` будет глобальным объектом, у которого нет `value`.

## Таблица правил

| Вызов | `this` |
| --- | --- |
| `obj.method()` | `obj` |
| `fn()` | `undefined` (strict) / глобальный объект (sloppy) |
| `fn.call(ctx)`, `fn.apply(ctx)` | `ctx` |
| `fn.bind(ctx)()` | `ctx` навсегда |
| `new Fn()` | новый объект |
| стрелочная функция | `this` внешней области в момент создания |
| обработчик `addEventListener` (обычная функция) | элемент `currentTarget` |

## Что важно помнить

- Передавая метод как колбэк (`onClick={obj.method}`, `setTimeout(obj.method)`), вы теряете `this` — используйте стрелку или `bind`.
- Классы и ES-модули всегда в строгом режиме.
- Стрелку нельзя «привязать» через `call`/`bind` и нельзя вызвать с `new`.
- Теория: [this](<../../04. JavaScript/02. Функции/15. this в JavaScript.md>), [потеря контекста](<../../04. JavaScript/02. Функции/16. Потеря контекста.md>), [стрелочные функции](<../../04. JavaScript/02. Функции/01. Стрелочные функции и когда их не использовать.md>).

## Мини-шпаргалка

this = объект слева от точки в момент вызова. Без объекта — `undefined` в strict. call/apply/bind задают явно, bind — навсегда. new — новый объект. Стрелка — this снаружи, литерал объекта область не создает. Деструктуризация метода и колбэк — потеря контекста.
