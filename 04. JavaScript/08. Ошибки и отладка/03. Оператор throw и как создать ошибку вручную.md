# Оператор throw и как создать ошибку вручную

> [!NOTE]
> `throw` генерирует исключение: выполнение текущей функции прекращается, и управление переходит в ближайший `catch`. Бросить можно любое значение, но правильно бросать экземпляр `Error` или его наследника (`TypeError`, собственный `ValidationError`) — так сохраняются `message`, `stack` и можно передать причину через `{ cause }`.

## Вопрос

Что делает оператор `throw`? Как создать ошибку вручную и что лучше бросать — строку или объект `Error`?

## Синтаксис

```javascript
function divide(a, b) {
  if (b === 0) {
    throw new RangeError("Деление на ноль");
  }
  return a / b;
}

try {
  divide(10, 0);
} catch (error) {
  console.log(error.name);    // "RangeError"
  console.log(error.message); // "Деление на ноль"
}
```

После `throw` код функции не выполняется. `throw` — оператор, а не функция: скобки не нужны, а перенос строки сразу после `throw` — синтаксическая ошибка.

## Как создать ошибку

```javascript
new Error("Сообщение");
Error("Сообщение");                  // то же самое, new необязателен
new TypeError("Ожидалось число");
new Error("Не удалось сохранить заказ", { cause: originalError });
```

| Конструктор | Когда бросать |
| --- | --- |
| `Error` | общая ошибка |
| `TypeError` | значение не того типа |
| `RangeError` | значение вне допустимого диапазона |
| `SyntaxError` | некорректный формат (например, при парсинге) |
| Собственный класс | доменные ошибки: `ValidationError`, `NotFoundError` |

## Почему не строка

```javascript
throw "Что-то пошло не так"; // работает, но плохо
```

- у строки нет `stack` — непонятно, где возникла ошибка;
- нельзя проверить тип через `instanceof`;
- мониторинг и логирование ожидают объект `Error`.

## Цепочка причин: cause

```javascript
async function loadProfile(id) {
  try {
    const response = await fetch(`/api/users/${id}`);
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    return await response.json();
  } catch (error) {
    throw new Error("Не удалось загрузить профиль", { cause: error });
  }
}
```

Обертка добавляет контекст, а исходная ошибка остается в `error.cause` — в консоли браузера видны обе.

## Повторный выброс

Если `catch` не умеет обработать ошибку, ее нужно пробросить дальше:

```javascript
try {
  saveForm(data);
} catch (error) {
  if (error instanceof ValidationError) {
    showFieldErrors(error.fields);
  } else {
    throw error; // неизвестная ошибка — пусть обработает уровень выше
  }
}
```

## Что важно помнить

- `throw` внутри `async`-функции превращается в отклоненный Promise.
- Бросайте ошибки для исключительных ситуаций; ожидаемые результаты (пустой список, «не найдено» в поиске) лучше возвращать значением.
- Сообщение ошибки пишите для разработчика, а текст для пользователя формируйте отдельно.
- `Error.captureStackTrace` (V8) позволяет убрать из стека вспомогательные функции.

## Мини-шпаргалка

- `throw value` прерывает выполнение и ищет `catch`.
- Бросайте `new Error()` или наследника.
- `{ cause }` сохраняет исходную ошибку.
- Неизвестную ошибку в `catch` пробрасывают дальше: `throw error`.
- `throw` в `async` = rejected Promise.
