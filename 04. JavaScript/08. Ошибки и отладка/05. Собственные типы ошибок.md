# Собственные типы ошибок

> [!NOTE]
> Собственный тип ошибки создают наследованием от `Error`: `class ValidationError extends Error`. В конструкторе вызывают `super(message, { cause })`, задают `this.name` и добавляют свои поля (`field`, `status`, `code`). Это позволяет различать ошибки через `instanceof`, передавать структурированные данные и строить иерархии: `HttpError` → `NotFoundError`.

## Вопрос

Как создать собственный тип ошибки? Как расширить `Error` своими свойствами?

## Базовый класс

```javascript
class ValidationError extends Error {
  constructor(message, { field, cause } = {}) {
    super(message, { cause });
    this.name = "ValidationError";
    this.field = field;
  }
}

try {
  throw new ValidationError("Введите email", { field: "email" });
} catch (error) {
  error instanceof ValidationError; // true
  error instanceof Error;           // true
  error.name;                       // "ValidationError"
  error.field;                      // "email"
  error.stack;                      // стек сохранен
}
```

## Иерархия ошибок

```javascript
class AppError extends Error {
  constructor(message, options) {
    super(message, options);
    this.name = new.target.name; // имя класса-наследника автоматически
  }
}

class HttpError extends AppError {
  constructor(status, message, options) {
    super(message ?? `HTTP ${status}`, options);
    this.status = status;
  }
}

class NotFoundError extends HttpError {
  constructor(resource) {
    super(404, `${resource} не найден`);
    this.resource = resource;
  }
}

class UnauthorizedError extends HttpError {
  constructor() {
    super(401, "Требуется вход");
  }
}
```

## Использование

```javascript
async function request(url) {
  const response = await fetch(url);
  if (response.status === 404) throw new NotFoundError(url);
  if (response.status === 401) throw new UnauthorizedError();
  if (!response.ok) throw new HttpError(response.status);
  return response.json();
}

try {
  await request("/api/orders/42");
} catch (error) {
  if (error instanceof UnauthorizedError) redirectToLogin();
  else if (error instanceof NotFoundError) showNotFound();
  else if (error instanceof HttpError) showToast(`Ошибка сервера: ${error.status}`);
  else throw error; // неизвестную ошибку — выше
}
```

## Сериализация

Поля `message` и `stack` неперечисляемы, поэтому `JSON.stringify(error)` дает `{}` или только собственные поля. Для логов добавьте `toJSON`:

```javascript
class AppError extends Error {
  toJSON() {
    return { name: this.name, message: this.message, ...this, cause: this.cause };
  }
}
```

## Что важно помнить

- Задавайте `this.name`, иначе в консоли и стеке будет просто `Error`.
- `new.target.name` избавляет от ручного `name` в каждом наследнике, но минификаторы могут переименовать классы — в production надежнее явная строка или поле `code`.
- Проверка через `instanceof` не работает между разными realm и копиями пакета; для таких случаев используйте поле `code` (`error.code === "NOT_FOUND"`).
- Не путайте ошибки для разработчика и сообщения для пользователя: в UI показывайте понятный текст по `code`.
- Библиотеки часто экспортируют свои классы ошибок (`AxiosError`, `ZodError`) — проверяйте их через `instanceof` или type guard.

## Мини-шпаргалка

- `class MyError extends Error`.
- `super(message, { cause })`, `this.name = "MyError"`.
- Свои поля: `field`, `status`, `code`.
- Различение: `instanceof`, для надежности — `code`.
- Иерархия: `AppError` → `HttpError` → `NotFoundError`.
