# try...catch: когда выполняется catch и что будет при ошибке в catch

> [!NOTE]
> `try...catch` перехватывает исключения, брошенные **синхронно** внутри блока `try` (и в функциях, которые он вызывает). Блок `catch` выполняется только если в `try` возникла ошибка, и получает ее объект. Если ошибка возникнет в самом `catch`, она не перехватится этим же `catch` и уйдет к внешнему обработчику — но `finally` всё равно выполнится.

## Вопрос

Что делает конструкция `try...catch`? Когда выполняется блок `catch`? Что произойдет, если в `catch` возникнет новая ошибка?

## Синтаксис

```javascript
try {
  const data = JSON.parse(rawText);
  render(data);
} catch (error) {
  console.error("Некорректный JSON", error);
  showFallback();
}

// параметр можно опустить (ES2019)
try {
  localStorage.setItem("key", value);
} catch {
  // хранилище недоступно — молча игнорируем
}
```

## Когда выполняется catch

- если в `try` брошена ошибка — выполнение `try` прерывается и управление переходит в `catch`;
- если ошибок нет — `catch` пропускается;
- ловятся ошибки и из вложенных вызовов функций на любой глубине.

```javascript
function level3() { throw new Error("глубоко"); }
function level2() { level3(); }

try {
  level2();
} catch (error) {
  console.log(error.message); // "глубоко"
}
```

## Что try...catch НЕ ловит

```javascript
// синтаксическая ошибка в самом файле: скрипт не запустится, try не выполнится
// (а вот SyntaxError в runtime — из JSON.parse или eval — try поймает)
try { JSON.parse("{"); } catch (e) {} // пойман

// асинхронные ошибки
try {
  setTimeout(() => { throw new Error("позже"); });
} catch (e) {} // не сработает

try {
  fetchData(); // без await
} catch (e) {} // отклонение промиса не поймано
```

Для асинхронного кода — `try` вокруг `await` внутри async-функции или `.catch()`.

## Ошибка внутри catch

```javascript
try {
  try {
    throw new Error("первая");
  } catch (error) {
    throw new Error("ошибка в catch", { cause: error }); // уходит наружу
  } finally {
    console.log("finally выполнится");
  }
} catch (outer) {
  console.log(outer.message);       // "ошибка в catch"
  console.log(outer.cause.message); // "первая"
}
```

Если внешнего обработчика нет, ошибка из `catch` становится необработанной.

## Хорошие практики

```javascript
try {
  await saveOrder(order);
} catch (error) {
  if (error instanceof ValidationError) {
    showFieldErrors(error.fields); // ожидаемая ошибка — обработали
  } else {
    reportError(error);            // неожиданная — залогировали
    throw error;                   // и пробросили выше
  }
}
```

- ловите только то, что умеете обработать;
- не оставляйте пустой `catch` без комментария;
- держите `try` коротким: только код, который может бросить нужную ошибку;
- сохраняйте исходную ошибку в `cause` при обертывании.

## Что важно помнить

- Переменная `error` видна только внутри `catch`.
- `catch` может поймать не только `Error`: бросить можно любое значение, поэтому `error.message` не всегда существует — в TypeScript `error` имеет тип `unknown`.
- В React ошибки рендера ловит Error Boundary, а не `try...catch` вокруг JSX.
- `try...catch` почти не влияет на производительность в современных движках.

## Мини-шпаргалка

- `try` — код, `catch (error)` — обработка, параметр можно опустить.
- `catch` выполняется только при ошибке в `try`.
- Ловит синхронные ошибки и ошибки из вложенных вызовов.
- Асинхронные — только с `await` или `.catch()`.
- Ошибка в `catch` уходит наружу, `finally` всё равно выполнится.
