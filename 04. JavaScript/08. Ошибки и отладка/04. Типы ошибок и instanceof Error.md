# Типы ошибок в JavaScript и instanceof Error

> [!NOTE]
> Встроенные типы ошибок наследуют `Error`: `SyntaxError` (неверный синтаксис), `ReferenceError` (обращение к несуществующей переменной или TDZ), `TypeError` (операция с неподходящим типом, например вызов не-функции), `RangeError` (значение вне диапазона), `URIError`, `EvalError` и `AggregateError` (несколько ошибок сразу). Проверка `error instanceof Error` отличает настоящие ошибки от брошенных строк и объектов.

## Вопрос

Какие типы ошибок бывают в JavaScript? Что делает `instanceof Error` и как определить тип пойманной ошибки?

## Встроенные типы

| Тип | Когда возникает | Пример |
| --- | --- | --- |
| `SyntaxError` | код или данные нельзя разобрать | `JSON.parse("{a:1}")`, `eval("if (")` |
| `ReferenceError` | переменная не объявлена или в TDZ | `undefinedVar`, `let` до объявления |
| `TypeError` | неподходящий тип значения | `null.name`, `undefined()`, присваивание `const` |
| `RangeError` | число вне допустимого диапазона | `new Array(-1)`, `(1).toFixed(200)`, переполнение стека |
| `URIError` | неверный URI | `decodeURIComponent("%")` |
| `EvalError` | исторический, сейчас не используется | — |
| `AggregateError` | несколько ошибок | `Promise.any` при всех отклонениях |
| `DOMException` | ошибки Web API | `AbortError`, `QuotaExceededError`, `NotAllowedError` |

```javascript
null.length;          // TypeError: Cannot read properties of null
const x = 1; x = 2;   // TypeError: Assignment to constant variable
notDefined;           // ReferenceError: notDefined is not defined
function f() { f(); } f(); // RangeError: Maximum call stack size exceeded
```

## Самые частые на практике

- `TypeError: Cannot read properties of undefined (reading 'x')` — данные еще не загружены или пришли в другом формате → optional chaining, проверки, значения по умолчанию;
- `TypeError: x is not a function` — опечатка, неверный импорт, потерянный `this`;
- `ReferenceError` — опечатка в имени или обращение до объявления;
- `SyntaxError: Unexpected token '<'` при `response.json()` — сервер вернул HTML вместо JSON.

## instanceof Error

```javascript
try {
  riskyOperation();
} catch (error) {
  if (error instanceof TypeError) {
    // конкретный тип
  } else if (error instanceof Error) {
    console.error(error.message, error.stack);
  } else {
    console.error("Брошено не-Error значение:", error); // throw "строка"
  }
}
```

Поскольку все встроенные типы наследуют `Error`, `instanceof Error` истинно для любого из них и для собственных классов-наследников.

## Ограничения instanceof

- ошибка из iframe или worker создана другим конструктором `Error` → `instanceof` вернет `false`;
- две копии одной библиотеки в бандле дают разные классы ошибок.

Надежные альтернативы:

```javascript
error?.name === "AbortError";               // по имени
error?.code === "ERR_NETWORK";              // по коду
Error.isError?.(error);                     // новый метод, работает между realm
Object.prototype.toString.call(error) === "[object Error]";
```

## TypeScript

```typescript
try {
  ...
} catch (error: unknown) {
  if (error instanceof Error) {
    console.log(error.message); // тип сужен до Error
  }
}
```

С `useUnknownInCatchVariables` (часть `strict`) переменная в `catch` имеет тип `unknown`, поэтому проверка обязательна.

## Что важно помнить

- `fetch` не бросает ошибку на 404/500 — это не исключение, а ответ.
- Сетевая ошибка `fetch` — `TypeError: Failed to fetch`, отмена — `DOMException` с именем `AbortError`.
- Сообщения встроенных ошибок различаются в разных браузерах — не завязывайте логику на текст `message`.
- `RangeError` при переполнении стека говорит о бесконечной рекурсии.

## Мини-шпаргалка

- Основные: `SyntaxError`, `ReferenceError`, `TypeError`, `RangeError`.
- Плюс `URIError`, `AggregateError`, `DOMException`.
- Все наследуют `Error`.
- `instanceof Error` — настоящая ли это ошибка.
- Между realm — проверяйте `name` или `code`.
