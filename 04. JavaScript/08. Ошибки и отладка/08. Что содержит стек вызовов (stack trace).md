# Что содержит стек вызовов (stack trace)?

> [!NOTE]
> Stack trace показывает цепочку вызовов функций, которая привела к месту возникновения ошибки.

## Вопрос

Что такое stack trace и как его читать?

## Определение

Stack trace - отладочная информация внутри ошибки. Он показывает, в какой функции возникла ошибка, кто вызвал эту функцию, и по каким строкам кода шел путь выполнения.

Обычно stack trace доступен через свойство `error.stack`.

## Пример

```javascript
function first() {
  second();
}

function second() {
  throw new Error('Boom');
}

try {
  first();
} catch (error) {
  console.log(error.stack);
}
```

В стеке будет видно, что ошибка возникла в `second`, а вызов пришел из `first`.

## Что обычно есть в stack trace

- имя ошибки;
- сообщение ошибки;
- имя функции;
- путь к файлу;
- номер строки;
- номер колонки;
- цепочка вызовов.

## Как использовать

```text
Error: Boom
  at second (app.js:6:9)
  at first (app.js:2:3)
```

Читать удобно сверху вниз: верхняя строка обычно ближе всего к месту падения.

## Важный нюанс

Формат `stack` не полностью стандартизирован и может отличаться между браузерами и Node.js. Но для отладки он все равно крайне полезен.

## Что важно помнить

- Стек формируется при создании `Error`, а не при `throw`.
- Формат `stack` не стандартизирован и отличается в браузерах.
- В production стек минифицирован — нужны source maps, загруженные в сервис мониторинга.
- Асинхронные стеки (через `await`) DevTools показывают, а `error.stack` — частично.

## Мини-шпаргалка

```javascript
try {
  riskyCode();
} catch (error) {
  console.log(error.stack);
}
```
