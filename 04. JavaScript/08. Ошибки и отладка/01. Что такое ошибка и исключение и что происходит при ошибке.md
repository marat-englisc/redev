# Что такое ошибка и исключение и что происходит при ошибке?

> [!NOTE]
> Ошибка в JavaScript — объект (обычно экземпляр `Error`) с полями `name`, `message` и `stack`. **Исключение** — механизм, который прерывает обычное выполнение: когда ошибка брошена (`throw`), движок разматывает стек вызовов в поисках ближайшего `try...catch`. Если обработчика нет, ошибка становится необработанной: выполнение текущей задачи прекращается, а в браузере срабатывают `window.onerror` или `unhandledrejection`.

## Вопрос

Что такое ошибка в JavaScript? Что такое исключение и что происходит, когда в коде возникает ошибка?

## Ошибка как объект

```javascript
const error = new Error("Не удалось загрузить профиль");

error.name;    // "Error"
error.message; // "Не удалось загрузить профиль"
error.stack;   // "Error: Не удалось загрузить профиль\n    at loadProfile (app.js:12:9) ..."
```

Ошибки бывают двух видов:

- **синтаксические** (`SyntaxError`) — код не удалось разобрать, он не выполнится вовсе;
- **ошибки выполнения (runtime)** — `TypeError`, `ReferenceError`, `RangeError` и собственные ошибки приложения.

## Исключение и размотка стека

```javascript
function parsePrice(text) {
  const value = Number(text);
  if (Number.isNaN(value)) {
    throw new TypeError(`Некорректная цена: ${text}`);
  }
  return value;
}

function calculateTotal(items) {
  return items.reduce((sum, item) => sum + parsePrice(item.price), 0);
}

try {
  calculateTotal([{ price: "100" }, { price: "abc" }]);
} catch (error) {
  console.error(error.message); // "Некорректная цена: abc"
}
```

Что происходит:

1. `throw` прерывает `parsePrice` — код после него не выполняется.
2. Движок выходит из `reduce` и `calculateTotal`, разматывая стек вызовов.
3. Управление передается в ближайший `catch` выше по стеку.
4. Если `catch` не найден, ошибка становится **необработанной** (uncaught).

## Необработанные ошибки

| Окружение | Что происходит |
| --- | --- |
| Браузер, синхронный код | ошибка в консоли, событие `error` на `window`, остальные задачи event loop продолжают работать |
| Браузер, промис | событие `unhandledrejection` |
| Node.js | `uncaughtException` / `unhandledRejection`, по умолчанию процесс завершается |
| React | ошибка при рендере размонтирует дерево до ближайшего Error Boundary |

```javascript
window.addEventListener("error", (event) => {
  sendToMonitoring(event.error);
});

window.addEventListener("unhandledrejection", (event) => {
  sendToMonitoring(event.reason);
});
```

## Ошибка и исключение

На практике термины часто используют как синонимы. Строго: **ошибка** — объект с информацией о проблеме, **исключение** — ситуация, когда этот объект брошен и прерывает выполнение. Бросить можно любое значение (`throw "текст"`), но правильно бросать экземпляр `Error`, чтобы сохранить `stack`.

## Что важно помнить

- Ошибка в одном обработчике события не останавливает приложение целиком: event loop продолжит выполнять другие задачи.
- `try...catch` ловит только синхронные ошибки своего блока: ошибка в `setTimeout` внутри `try` не будет поймана.
- Не глушите ошибки пустым `catch {}` — потеряете информацию о баге.
- В production ошибки отправляют в системы мониторинга (Sentry) вместе со стеком и source maps.

## Мини-шпаргалка

- Ошибка — объект `Error` с `name`, `message`, `stack`.
- `throw` прерывает выполнение и разматывает стек.
- Ближайший `try...catch` перехватывает исключение.
- Без обработчика — uncaught error: `error` / `unhandledrejection`.
- Бросайте `Error`, а не строки.
