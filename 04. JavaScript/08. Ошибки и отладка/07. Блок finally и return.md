# Блок finally и return

> [!NOTE]
> `finally` выполняется **всегда** после `try` и `catch` — и при успехе, и при ошибке, и даже если в `try` или `catch` стоит `return`, `break` или `throw`. Его используют для освобождения ресурсов: скрыть индикатор загрузки, закрыть соединение, снять блокировку. Если `finally` сам делает `return`, он **перезаписывает** результат и может «проглотить» ошибку — так писать не стоит.

## Вопрос

Что делает блок `finally`? Выполнится ли `finally`, если в `try` есть `return`?

## Базовое использование

```javascript
async function submit(form) {
  setLoading(true);
  try {
    await api.save(form);
    showToast("Сохранено");
  } catch (error) {
    showError(error);
  } finally {
    setLoading(false); // выполнится в любом случае
  }
}
```

Можно писать `try...finally` без `catch` — ошибка уйдет наружу, но очистка произойдет:

```javascript
const lock = acquireLock();
try {
  processQueue();
} finally {
  lock.release();
}
```

## finally и return

```javascript
function test() {
  try {
    return "из try";
  } finally {
    console.log("finally выполнился");
  }
}

test(); // выведет "finally выполнился", вернет "из try"
```

Порядок: значение `return` вычисляется, затем выполняется `finally`, затем функция возвращает сохраненное значение.

```javascript
function counter() {
  let x = 1;
  try {
    return x;      // возвращаемое значение зафиксировано: 1
  } finally {
    x = 2;         // не влияет на результат
  }
}
counter(); // 1
```

## return внутри finally — антипаттерн

```javascript
function risky() {
  try {
    throw new Error("сбой");
  } finally {
    return "всё хорошо"; // ошибка потеряна!
  }
}

risky(); // "всё хорошо" — исключение «проглочено»
```

```javascript
function override() {
  try {
    return "try";
  } finally {
    return "finally"; // перезаписывает результат
  }
}
override(); // "finally"
```

Линтер (`no-unsafe-finally`) предупреждает о таких конструкциях.

## Таблица поведения

| В `try` | В `finally` | Результат |
| --- | --- | --- |
| `return a` | нет `return` | `a`, `finally` выполнен |
| `throw e` | нет `return` | ошибка `e` уходит наружу после `finally` |
| `return a` | `return b` | `b` |
| `throw e` | `return b` | `b`, ошибка потеряна |
| `throw e` | `throw f` | `f`, ошибка `e` потеряна |

## В промисах

```javascript
fetchData()
  .then(render)
  .catch(showError)
  .finally(() => setLoading(false));
```

`Promise.prototype.finally` не получает аргументов и не меняет результат цепочки, если сам не бросает ошибку.

## Что важно помнить

- `finally` выполняется и при `break`/`continue` внутри цикла.
- `finally` не выполнится, только если процесс завершен (`process.exit()`), вкладка закрыта или бесконечный цикл в `try`.
- Новый синтаксис `using` (явное управление ресурсами, `Symbol.dispose`) автоматизирует очистку без `finally`.
- Не кладите в `finally` код, который может бросить ошибку, — она заменит исходную.

## Мини-шпаргалка

- `finally` выполняется всегда.
- После `return` в `try` `finally` выполнится, результат сохранится.
- `return` в `finally` перезаписывает результат и глотает ошибки — избегать.
- `try...finally` без `catch` — очистка с пробросом ошибки.
- В промисах — `.finally()`.
