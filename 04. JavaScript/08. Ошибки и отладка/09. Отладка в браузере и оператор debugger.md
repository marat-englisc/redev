# Отладка в браузере и оператор debugger

> [!NOTE]
> **Отладка** — поиск и устранение причины ошибки. В браузере для этого используют DevTools: консоль, точки останова (breakpoints) во вкладке Sources, пошаговое выполнение, просмотр переменных и стека вызовов, вкладку Network и Performance. Оператор `debugger;` в коде останавливает выполнение, если DevTools открыты, — это точка останова прямо в исходнике.

## Вопрос

Что такое отладка? Какие способы отладки есть в браузере? Что делает оператор `debugger`?

## Процесс отладки

1. **Воспроизвести** баг стабильно: шаги, данные, окружение.
2. **Локализовать**: где именно поведение расходится с ожидаемым.
3. **Понять причину** — не симптом.
4. **Исправить** и добавить регрессионный тест.
5. **Проверить**, что не сломалось остальное.

## Console

```javascript
console.log("значение", value);
console.table(users);              // таблица из массива объектов
console.dir(element);              // свойства объекта, а не HTML
console.error("ошибка", error);    // со стеком
console.warn("предупреждение");
console.group("Заказ"); console.log(order); console.groupEnd();
console.time("render"); render(); console.timeEnd("render");
console.trace("кто вызвал?");      // текущий стек вызовов
console.assert(total > 0, "Сумма должна быть положительной");
```

Объекты в консоли показываются «живыми»: если раскрыть их позже, вы увидите текущее, а не залогированное состояние. Для снимка используйте `console.log(structuredClone(obj))` или `JSON.stringify`.

## Точки останова

Во вкладке Sources:

| Вид | Когда останавливается |
| --- | --- |
| Line breakpoint | на строке кода |
| Conditional breakpoint | на строке, если условие истинно (`id === 42`) |
| Logpoint | ничего не останавливает, выводит сообщение — `console.log` без правки кода |
| DOM breakpoint | при изменении поддерева, атрибутов или удалении узла |
| XHR/fetch breakpoint | при запросе на URL, содержащий строку |
| Event listener breakpoint | на событии (`click`, `keydown`, `setTimeout`) |
| Exception breakpoint | при брошенном или необработанном исключении |

На паузе доступны:

- **Scope** — значения переменных текущей области и замыканий;
- **Call Stack** — цепочка вызовов, включая async-предков;
- **Watch** — выражения, за которыми следить;
- пошаговые команды: Step over (F10), Step into (F11), Step out (Shift+F11), Resume (F8).

## debugger

```javascript
function calculateDiscount(cart) {
  const subtotal = sum(cart.items);
  debugger; // остановка здесь, если DevTools открыты
  return subtotal * cart.discount;
}
```

- если DevTools закрыты, оператор ничего не делает;
- удобен, когда сложно найти нужную строку в собранном коде;
- не оставляйте `debugger` в коммитах — правило ESLint `no-debugger`.

## Другие инструменты

- **Network** — запросы, статусы, тела ответов, CORS и cookies;
- **Elements** — DOM, стили, вычисленные значения, события;
- **Performance** — долгие задачи, рендер, layout thrashing;
- **Memory** — heap snapshots для поиска утечек;
- **Application** — storage, cookies, Service Worker, cache;
- **React DevTools / Vue DevTools** — дерево компонентов, props, state, профайлер;
- **source maps** — отладка исходного TypeScript вместо минифицированного бандла;
- отладка Node.js: `node --inspect` и `chrome://inspect`, отладчик VS Code.

## Что важно помнить

- Сначала прочитайте сообщение и стек ошибки — часто они указывают на точную строку.
- «Отладка удалением»: уменьшайте код до минимального воспроизводимого примера.
- `git bisect` находит коммит, в котором появился баг.
- В production ошибки собирают Sentry и подобные сервисы — вместе с source maps и контекстом пользователя.
- Логи должны быть информативными: что произошло, с какими данными и где.

## Мини-шпаргалка

- Отладка: воспроизвести → локализовать → понять причину → исправить → тест.
- `console.log/table/dir/trace/time`.
- Breakpoints: строки, условия, logpoints, DOM, fetch, исключения.
- `debugger;` — точка останова в коде при открытых DevTools.
- Source maps для отладки исходников.
