# preventDefault и отмена отправки формы

> [!NOTE]
> `event.preventDefault()` отменяет **действие браузера по умолчанию**: переход по ссылке, отправку формы с перезагрузкой страницы, отметку чекбокса, контекстное меню, прокрутку колесом. Событие при этом продолжает всплывать. Чтобы отправить форму через `fetch`, обработчик вешают на событие `submit` формы и вызывают `preventDefault()`.

## Вопрос

Что делает `event.preventDefault()`? Как отменить отправку формы и чем `preventDefault` отличается от `stopPropagation`?

## Действия по умолчанию

| Событие | Действие браузера |
| --- | --- |
| `click` на `<a href>` | переход по ссылке |
| `submit` формы | отправка и перезагрузка страницы |
| `click` на checkbox | переключение состояния |
| `keydown` в поле | ввод символа |
| `contextmenu` | контекстное меню |
| `wheel` / `touchmove` | прокрутка |
| `dragover` | запрет drop (нужен `preventDefault`, чтобы разрешить) |

## Отмена отправки формы

```html
<form id="login">
  <input name="email" type="email" required>
  <input name="password" type="password" required>
  <button type="submit">Войти</button>
</form>
```

```javascript
const form = document.querySelector("#login");

form.addEventListener("submit", async (event) => {
  event.preventDefault(); // без этого страница перезагрузится

  const data = new FormData(form);
  const response = await fetch("/api/login", { method: "POST", body: data });
  if (!response.ok) showError("Неверный логин или пароль");
});
```

Почему `submit`, а не `click` на кнопке:

- форма отправляется и по Enter в поле;
- встроенная валидация (`required`, `type="email"`) срабатывает перед `submit`;
- семантика и доступность сохраняются.

`event.submitter` показывает, какая кнопка отправила форму.

## preventDefault и stopPropagation

```javascript
link.addEventListener("click", (event) => {
  event.preventDefault();  // не переходить по ссылке
  // событие всё равно всплывет к родителям
});
```

| | `preventDefault()` | `stopPropagation()` |
| --- | --- | --- |
| Отменяет | действие браузера | распространение события |
| Событие всплывает | да | нет |
| Обработчики выше | сработают | не сработают |

`return false` в обработчике `onclick` = `preventDefault()`; в `addEventListener` он ничего не делает.

## Пассивные обработчики

```javascript
window.addEventListener("wheel", (e) => e.preventDefault(), { passive: true });
// preventDefault игнорируется, в консоли предупреждение
```

Браузер по умолчанию делает `touchstart`, `touchmove` и `wheel` на `window`/`document` пассивными, чтобы скролл был плавным. Если отменять прокрутку действительно нужно — `{ passive: false }`.

## Проверка

```javascript
event.cancelable;        // можно ли отменить действие
event.defaultPrevented;  // было ли оно отменено
```

## Форма: reset

```javascript
form.reset();              // вернуть начальные значения полей (атрибуты value, checked)
form.requestSubmit();      // отправить с валидацией и событием submit
form.submit();             // отправить БЕЗ валидации и без события submit
```

## Что важно помнить

- В React `onSubmit={(e) => { e.preventDefault(); ... }}` — тот же прием; Server Actions в React 19 и Next.js отправляют форму без ручного `preventDefault`.
- Отмена `click` на ссылке не отменяет навигацию по среднему клику (событие `auxclick`).
- Не отменяйте поведение браузера без замены: ссылка, которая не переходит, — плохой UX и доступность.
- После `await` вызывать `preventDefault` поздно — действие уже выполнено.

## Мини-шпаргалка

- `preventDefault()` — отменить действие браузера.
- Форма — слушать `submit` и вызвать `preventDefault()`.
- Событие продолжает всплывать.
- `passive: true` запрещает `preventDefault` ради плавного скролла.
- `form.reset()`, `form.requestSubmit()`.
