# События загрузки и закрытия страницы: DOMContentLoaded, load, beforeunload, unload

> [!NOTE]
> `DOMContentLoaded` срабатывает, когда HTML полностью распарсен и DOM построен (после выполнения `defer`-скриптов), не дожидаясь картинок и стилей. `load` срабатывает, когда загружены все ресурсы: изображения, стили, шрифты, iframe. `beforeunload` позволяет спросить пользователя перед уходом со страницы, а `unload` устарел и ненадежен — вместо него используют `pagehide` и `visibilitychange`.

## Вопрос

Чем `DOMContentLoaded` отличается от `load`? Что делают события `beforeunload` и `unload` и что использовать вместо `unload`?

## Порядок событий

```text
загрузка HTML
├── парсинг, выполнение обычных скриптов
├── defer-скрипты
├── DOMContentLoaded  ← DOM готов
├── картинки, стили, iframe догружаются
└── load              ← всё загружено

уход со страницы
├── beforeunload      ← можно попросить подтверждение
├── pagehide
└── unload            ← устарел
```

```javascript
document.addEventListener("DOMContentLoaded", () => {
  initMenu(); // DOM доступен
});

window.addEventListener("load", () => {
  measureImages(); // размеры картинок известны
});

document.readyState; // "loading" → "interactive" (≈ DOMContentLoaded) → "complete" (≈ load)
```

## DOMContentLoaded и load

| | `DOMContentLoaded` | `load` |
| --- | --- | --- |
| Где слушать | `document` | `window` (и отдельные `img`, `script`) |
| Ждет DOM | да | да |
| Ждет `defer`-скрипты | да | да |
| Ждет `async`-скрипты | нет | да |
| Ждет картинки, шрифты, iframe | нет | да |
| Типичное применение | инициализация интерфейса | работа с размерами медиа, метрики |

Скрипты с `defer` и `type="module"` выполняются до `DOMContentLoaded`, поэтому обработчик в них часто не нужен — DOM уже готов. Если скрипт может загрузиться после события, проверяйте `document.readyState`:

```javascript
if (document.readyState === "loading") {
  document.addEventListener("DOMContentLoaded", init);
} else {
  init();
}
```

## beforeunload

```javascript
window.addEventListener("beforeunload", (event) => {
  if (!hasUnsavedChanges) return;
  event.preventDefault();
  event.returnValue = ""; // для старых браузеров
});
```

Браузер покажет стандартный диалог «Покинуть сайт?». Свой текст сообщения браузеры не показывают уже много лет. Регистрируйте обработчик только когда есть несохраненные данные: он мешает bfcache (мгновенному возврату назад).

## unload и замена

`unload`:

- ненадежен на мобильных: при сворачивании и закрытии вкладки системой он часто не срабатывает;
- ломает back/forward cache;
- в Chrome постепенно отключается.

Для отправки аналитики и сохранения состояния используйте `visibilitychange` и `pagehide`:

```javascript
document.addEventListener("visibilitychange", () => {
  if (document.visibilityState === "hidden") {
    navigator.sendBeacon("/analytics", JSON.stringify(sessionStats));
  }
});

window.addEventListener("pagehide", (event) => {
  if (event.persisted) {
    // страница уходит в bfcache и может вернуться
  }
});
```

`navigator.sendBeacon` и `fetch(..., { keepalive: true })` гарантируют отправку небольших данных даже при закрытии страницы.

## Что важно помнить

- В SPA эти события срабатывают один раз при первой загрузке — переходы между страницами роутера их не вызывают.
- Для возврата из bfcache слушайте `pageshow` с `event.persisted === true`.
- В React `useEffect` выполняется после монтирования — `DOMContentLoaded` внутри компонента обычно уже прошел.
- Lighthouse и Core Web Vitals меряют не `load`, а LCP, INP и CLS.

## Мини-шпаргалка

- `DOMContentLoaded` — DOM построен, ресурсы еще грузятся.
- `load` — загружено всё.
- `beforeunload` — подтверждение ухода, только при несохраненных данных.
- `unload` устарел — используйте `visibilitychange` и `pagehide`.
- Отправка при уходе — `sendBeacon` или `fetch` с `keepalive`.
