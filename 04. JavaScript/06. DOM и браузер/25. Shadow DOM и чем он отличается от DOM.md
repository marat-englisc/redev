# Shadow DOM и чем он отличается от обычного DOM

> [!NOTE]
> **Shadow DOM** — скрытое изолированное поддерево DOM, прикрепленное к элементу-хосту через `attachShadow()`. Стили внутри shadow root не протекают наружу, а внешние стили не проникают внутрь (кроме наследуемых свойств и CSS-переменных). Это основа Web Components и встроенных элементов браузера вроде `<video>` и `<input type="range">`. Обычный DOM — общий для всей страницы, с глобальными стилями и селекторами.

## Вопрос

Что такое Shadow DOM? Чем Shadow DOM отличается от обычного DOM и где он используется?

## Создание

```javascript
class UserCard extends HTMLElement {
  constructor() {
    super();
    const shadow = this.attachShadow({ mode: "open" });
    shadow.innerHTML = `
      <style>
        .card { padding: 16px; border: 1px solid var(--card-border, #ddd); }
        h2 { color: tomato; } /* не повлияет на h2 страницы */
      </style>
      <div class="card">
        <h2><slot name="title">Без имени</slot></h2>
        <slot></slot>
      </div>
    `;
  }
}

customElements.define("user-card", UserCard);
```

```html
<user-card>
  <span slot="title">Анна</span>
  <p>Frontend-разработчик</p>
</user-card>
```

## Термины

| Термин | Что это |
| --- | --- |
| Shadow host | обычный элемент, к которому прикреплен shadow root |
| Shadow root | корень скрытого дерева |
| Shadow tree | содержимое внутри shadow root |
| Light DOM | обычные дети хоста, переданные снаружи |
| `<slot>` | место, куда «проецируется» light DOM |
| `mode: "open"` | доступ снаружи через `host.shadowRoot` |
| `mode: "closed"` | `shadowRoot` возвращает `null` |

## Shadow DOM и обычный DOM

| | Обычный DOM | Shadow DOM |
| --- | --- | --- |
| Стили | глобальные, каскад на всю страницу | изолированы внутри shadow root |
| `document.querySelector` | находит всё | не заходит внутрь shadow root |
| `id` | должны быть уникальны на странице | уникальны только внутри своего дерева |
| События | `target` — реальный элемент | снаружи `target` ретаргетится на хост |
| Назначение | структура документа | инкапсуляция компонента |

## Стилизация

```css
/* внутри компонента */
:host { display: block; }
:host([variant="danger"]) .card { border-color: red; }
::slotted(p) { margin: 0; }

/* снаружи */
user-card { --card-border: #2563eb; }   /* CSS-переменные проходят внутрь */
user-card::part(title) { font-size: 2rem; } /* если внутри есть part="title" */
```

Наследуемые свойства (`color`, `font-family`) тоже проникают внутрь через хост.

## Где используется

- Web Components и дизайн-системы, независимые от фреймворка (Shoelace / Web Awesome, Lit);
- встроенные элементы браузера: `<video controls>`, `<details>`, поля форм;
- виджеты, которые встраиваются на чужие сайты и не должны конфликтовать со стилями страницы;
- Declarative Shadow DOM (`<template shadowrootmode="open">`) — Shadow DOM прямо в HTML, удобно для SSR.

## Что важно помнить

- Shadow DOM — не механизм безопасности: при `mode: "open"` содержимое доступно скриптам, а `closed` лишь усложняет доступ.
- Глобальные стили (reset, шрифты, Tailwind) не применяются внутри — их нужно подключать в компонент или через `adoptedStyleSheets`.
- Формы: элементы внутри shadow root не участвуют в родительской `<form>`, пока компонент не использует `ElementInternals` (`static formAssociated = true`).
- Testing Library и Playwright умеют искать элементы внутри открытых shadow root.
- React-компоненты рендерятся в обычный DOM; Shadow DOM в React используют редко, через `attachShadow` в ref.

## Мини-шпаргалка

- Shadow DOM — изолированное поддерево, `el.attachShadow({ mode })`.
- Стили не протекают ни внутрь, ни наружу (кроме наследуемых и CSS-переменных).
- `<slot>` проецирует light DOM.
- Стилизация: `:host`, `::slotted()`, `::part()`.
- Основа Web Components и встроенных элементов.
