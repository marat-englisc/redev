# localStorage и sessionStorage

> [!NOTE]
> `localStorage` и `sessionStorage` — синхронные хранилища пар «строка — строка» для одного origin (около 5 МБ). `localStorage` хранит данные бессрочно и делит их между всеми вкладками сайта. `sessionStorage` живет, пока открыта **конкретная вкладка**, и не делится с другими вкладками. Оба доступны любому JavaScript на странице, поэтому не подходят для токенов и секретов.

## Вопрос

Что делают `localStorage` и `sessionStorage`? Чем они отличаются и для чего их использовать?

## API

API у обоих одинаковый:

```javascript
localStorage.setItem("theme", "dark");
localStorage.getItem("theme");    // "dark"
localStorage.getItem("missing");  // null
localStorage.removeItem("theme");
localStorage.clear();
localStorage.length;
localStorage.key(0);              // имя первого ключа
```

Значения — **только строки**. Объекты сериализуют вручную:

```javascript
localStorage.setItem("cart", JSON.stringify(cart));
const saved = JSON.parse(localStorage.getItem("cart") ?? "[]");

localStorage.setItem("count", 5);
localStorage.getItem("count"); // "5" — строка
```

## Сравнение

| | `localStorage` | `sessionStorage` | Cookies |
| --- | --- | --- | --- |
| Время жизни | бессрочно, до очистки | пока открыта вкладка | до `Expires`/`Max-Age` или закрытия браузера |
| Видимость | все вкладки origin | одна вкладка | все вкладки, отправляется на сервер |
| Объем | ~5–10 МБ | ~5 МБ | ~4 КБ на cookie |
| Отправка на сервер | нет | нет | с каждым запросом |
| Доступ из JS | да | да | да, кроме `HttpOnly` |
| API | синхронный | синхронный | строка `document.cookie` |

Особенность `sessionStorage`: при дублировании вкладки данные копируются, а при открытии ссылки в новой вкладке — нет. Перезагрузка страницы данные сохраняет.

## Синхронизация между вкладками

```javascript
window.addEventListener("storage", (event) => {
  if (event.key === "theme") applyTheme(event.newValue);
});
```

Событие `storage` срабатывает в **других** вкладках того же origin при изменении `localStorage`. Удобно для синхронного logout или смены темы.

## Безопасная обертка

```javascript
function readStorage(key, fallback) {
  try {
    const raw = localStorage.getItem(key);
    return raw === null ? fallback : JSON.parse(raw);
  } catch {
    return fallback; // приватный режим, отключенное хранилище, битый JSON
  }
}

function writeStorage(key, value) {
  try {
    localStorage.setItem(key, JSON.stringify(value));
  } catch (error) {
    if (error.name === "QuotaExceededError") console.warn("Хранилище заполнено");
  }
}
```

## Что хранить

| Подходит | Не подходит |
| --- | --- |
| тема, язык, свернутые панели | access/refresh-токены, пароли |
| черновики форм | персональные данные без необходимости |
| недавние поиски | большие объемы (берите IndexedDB) |
| данные мастера на одну сессию (`sessionStorage`) | данные, которые должен видеть сервер |

## Что важно помнить

- Хранилище доступно любому скрипту страницы — при XSS всё содержимое можно украсть.
- API синхронный и блокирует поток — не пишите в него большие объемы часто.
- При SSR (Next.js) обращайтесь к storage только на клиенте: в `useEffect` или после проверки `typeof window`.
- Пользователь и браузер могут очистить хранилище в любой момент — не храните там единственную копию важных данных.
- В Safari в приватном режиме и при ограничениях ITP данные могут удаляться через 7 дней бездействия.

## Мини-шпаргалка

- `localStorage` — навсегда, все вкладки.
- `sessionStorage` — одна вкладка, до ее закрытия.
- Только строки — `JSON.stringify`/`parse`.
- Событие `storage` — синхронизация вкладок.
- Не для токенов и секретов.
