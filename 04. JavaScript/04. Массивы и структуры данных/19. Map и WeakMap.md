# Map и WeakMap

> [!NOTE]
> `Map` — коллекция пар «ключ — значение», где ключом может быть **любое** значение, включая объекты и функции. Она сохраняет порядок вставки, имеет `size` и быстрые `get`, `set`, `has`, `delete`. `WeakMap` принимает в качестве ключей только объекты (и незарегистрированные символы), держит их слабо и не мешает сборщику мусора — поэтому подходит для приватных данных и кешей, привязанных к объектам.

## Вопрос

Что такое `Map` и чем она отличается от обычного объекта? Что такое `WeakMap` и как `WeakMap` и `WeakSet` помогают сборщику мусора?

## Map

```javascript
const cart = new Map();

cart.set("tea", 2).set("coffee", 1); // set возвращает Map
cart.get("tea");      // 2
cart.has("cake");     // false
cart.size;            // 2
cart.delete("tea");

const userObj = { id: 1 };
const visits = new Map([[userObj, 5]]); // объект как ключ
visits.get(userObj);  // 5

for (const [key, value] of cart) console.log(key, value);
```

Преобразования:

```javascript
const fromObject = new Map(Object.entries({ a: 1 }));
const toObject = Object.fromEntries(cart);
const keys = [...cart.keys()];
const grouped = Map.groupBy(products, (p) => p.category); // ES2024
```

## Map или объект

| | `Object` | `Map` |
| --- | --- | --- |
| Типы ключей | строки и символы | любые значения |
| Порядок | особые правила для числовых ключей | порядок вставки |
| Размер | `Object.keys(o).length` | `map.size` |
| Унаследованные ключи | есть (`toString`, `__proto__`) | нет |
| Частые добавления/удаления | медленнее | оптимизирована |
| JSON | напрямую | нужно преобразовать |
| Подходит для | записи с известными полями | словари и кеши с динамическими ключами |

## WeakMap

```javascript
const metadata = new WeakMap();

function track(element) {
  metadata.set(element, { clicks: 0, firstSeen: Date.now() });
}

// когда element удален из DOM и на него нет ссылок,
// запись в WeakMap будет собрана автоматически
```

| | `Map` | `WeakMap` |
| --- | --- | --- |
| Ключи | любые | только объекты и незарегистрированные символы |
| Удержание ключей | сильное — объект не будет собран | слабое |
| `size`, перебор, `clear` | есть | нет |
| Методы | `get`, `set`, `has`, `delete`, итераторы | `get`, `set`, `has`, `delete` |

## Как WeakMap и WeakSet помогают сборщику мусора

Сборщик мусора удаляет объекты, на которые нет достижимых ссылок. Обычная `Map` хранит **сильную** ссылку на ключ: пока объект лежит в `Map`, он считается живым — это частая причина утечек (кеш, который растет вечно). В `WeakMap` ссылка на ключ **слабая**: если других ссылок нет, объект и значение собираются.

```javascript
// утечка: кеш держит каждый когда-либо переданный объект
const cache = new Map();

// без утечки
const safeCache = new WeakMap();
function getComputed(obj) {
  if (!safeCache.has(obj)) safeCache.set(obj, expensiveCompute(obj));
  return safeCache.get(obj);
}
```

Применения `WeakMap`:

- кеш результатов для объектов (мемоизация по объекту);
- данные, привязанные к DOM-узлам;
- «приватные» поля до появления `#private`;
- метаданные для чужих объектов, которые нельзя модифицировать.

## Что важно помнить

- `map[key] = value` не работает с `Map` — это запись обычного свойства объекта; используйте `set`.
- Ключи `Map` сравниваются по SameValueZero: `NaN` — один ключ, объекты — по ссылке.
- `WeakMap` не перечислима: невозможно узнать, какие ключи в ней есть, — это гарантия для сборщика мусора.
- Для слабых ссылок на значения (а не ключи) есть `WeakRef` и `FinalizationRegistry`.

## Мини-шпаргалка

- `Map` — любые ключи, порядок вставки, `size`.
- `set`/`get`/`has`/`delete`, перебор `for...of`.
- Для динамических словарей `Map` лучше объекта.
- `WeakMap` — ключи-объекты, слабые ссылки, без перебора.
- Слабые коллекции предотвращают утечки в кешах и метаданных.
