# Прототипы и цепочка прототипов

> [!NOTE]
> У каждого объекта есть скрытая ссылка `[[Prototype]]` на другой объект — его **прототип**. Если свойства нет в самом объекте, движок ищет его в прототипе, затем в прототипе прототипа и так далее до `null` — это **цепочка прототипов**. Так объекты наследуют методы: массивы получают `map` из `Array.prototype`, а все объекты — `toString` из `Object.prototype`. Доступ к прототипу — `Object.getPrototypeOf()`, устаревший аксессор — `__proto__`.

## Вопрос

Что такое прототип? Как работает цепочка прототипов и поиск свойств в ней? Что хранится в `__proto__` и чем он отличается от `prototype`?

## Цепочка прототипов

```javascript
const animal = {
  eats: true,
  walk() { return "идет"; },
};

const rabbit = Object.create(animal); // прототип rabbit — animal
rabbit.jumps = true;

rabbit.jumps;   // true — собственное
rabbit.eats;    // true — найдено в animal
rabbit.walk();  // "идет"
rabbit.fly;     // undefined — дошли до null, не нашли
```

```text
rabbit ──► animal ──► Object.prototype ──► null
{jumps}    {eats,walk}  {toString, hasOwnProperty...}
```

## Поиск свойств

**Чтение** идет по цепочке до первого совпадения. **Запись** почти всегда создает собственное свойство и не меняет прототип:

```javascript
rabbit.eats = false;   // собственное свойство rabbit
animal.eats;           // true — прототип не изменился
```

Исключения: если в прототипе есть сеттер — вызовется он; если в прототипе свойство `writable: false` — запись запрещена.

`this` в унаследованном методе указывает на объект, у которого метод вызван, а не на прототип:

```javascript
animal.setName = function (name) { this.name = name; };
rabbit.setName("Кролик"); // name записан в rabbit
```

## prototype и __proto__

| | `obj.__proto__` / `Object.getPrototypeOf(obj)` | `Fn.prototype` |
| --- | --- | --- |
| Что это | прототип конкретного объекта | объект, который станет прототипом экземпляров `new Fn()` |
| У кого есть | у всех объектов | у функций-конструкторов и классов |

```javascript
function User(name) { this.name = name; }
User.prototype.hello = function () { return `Привет, ${this.name}`; };

const anna = new User("Анна");

Object.getPrototypeOf(anna) === User.prototype; // true
anna.__proto__ === User.prototype;               // true (устаревший способ)
User.prototype.constructor === User;             // true
anna.hello();                                    // метод из прототипа
```

Методы в прототипе существуют в одном экземпляре на все объекты — это экономит память.

## Встроенные цепочки

```text
[1, 2]         → Array.prototype     → Object.prototype → null
function f(){} → Function.prototype  → Object.prototype → null
"строка" (обертка) → String.prototype → Object.prototype → null
```

## Работа с прототипами

```javascript
Object.getPrototypeOf(obj);           // получить
Object.setPrototypeOf(obj, proto);    // установить (медленно, избегать)
Object.create(proto);                 // создать объект с прототипом
proto.isPrototypeOf(obj);             // проверить
Object.hasOwn(obj, "key");            // собственное ли свойство
```

## Что важно помнить

- `__proto__` — устаревший аксессор из `Object.prototype`; в коде используйте `Object.getPrototypeOf` / `Object.create`.
- Не расширяйте встроенные прототипы (`Array.prototype.myMethod`) — это ломает чужой код и будущие стандарты.
- Классы в JavaScript — синтаксис поверх прототипов.
- Длинная цепочка замедляет поиск отсутствующих свойств, а изменение прототипа существующего объекта ломает оптимизации движка.
- Prototype pollution — уязвимость, когда данные пользователя с ключом `__proto__` попадают в `Object.prototype` через небезопасный merge.

## Мини-шпаргалка

- Прототип — объект, из которого наследуются свойства.
- Поиск: объект → прототип → ... → `Object.prototype` → `null`.
- Запись создает собственное свойство.
- `Fn.prototype` → прототип экземпляров `new Fn()`.
- `Object.getPrototypeOf`, `Object.create` вместо `__proto__`.
