# Object.create и объект без прототипа

> [!NOTE]
> `Object.create(proto, descriptors?)` создает новый объект с указанным прототипом и, при необходимости, свойствами с дескрипторами. `Object.create(null)` создает «чистый» объект без прототипа: у него нет `toString`, `hasOwnProperty` и других унаследованных свойств, поэтому он безопасен как словарь произвольных ключей.

## Вопрос

Что делает `Object.create()`? Как создать объект без прототипа и зачем это нужно?

## Создание с прототипом

```javascript
const animal = {
  speak() {
    return `${this.name} издает звук`;
  },
};

const dog = Object.create(animal);
dog.name = "Рекс";

dog.speak();                              // "Рекс издает звук"
Object.getPrototypeOf(dog) === animal;    // true
```

Со свойствами:

```javascript
const cat = Object.create(animal, {
  name: { value: "Мурка", enumerable: true },
  age: { value: 3, writable: true, enumerable: true },
});
```

## Наследование до классов

```javascript
function Animal(name) { this.name = name; }
Animal.prototype.speak = function () { return `${this.name} издает звук`; };

function Dog(name) { Animal.call(this, name); }
Dog.prototype = Object.create(Animal.prototype); // наследуем методы
Dog.prototype.constructor = Dog;                 // восстанавливаем constructor
```

Классы с `extends` делают то же самое под капотом.

## Объект без прототипа

```javascript
const dict = Object.create(null);

dict.apple = 1;
dict.toString;            // undefined — нет унаследованных свойств
"constructor" in dict;    // false
dict.__proto__ = "x";     // обычное свойство, а не смена прототипа
Object.keys(dict);        // ["apple", "__proto__"]
```

Зачем это нужно:

- словарь с ключами от пользователя без конфликтов с `toString`, `constructor`, `__proto__`;
- защита от prototype pollution при парсинге данных;
- быстрые lookup-таблицы в библиотеках.

Ограничения:

- `dict.hasOwnProperty("a")` — `TypeError`, используйте `Object.hasOwn(dict, "a")`;
- `` `${dict}` `` — `TypeError`: нет `toString`;
- `dict instanceof Object` — `false`.

Современная альтернатива для словаря — `Map`: любые типы ключей, `size`, порядок вставки, нет проблем с прототипом.

## Сравнение

| | `{}` | `Object.create(null)` | `new Map()` |
| --- | --- | --- | --- |
| Прототип | `Object.prototype` | нет | `Map.prototype` |
| Ключи | строки, символы | строки, символы | любые значения |
| Конфликт с `toString` | возможен | нет | нет |
| Размер | `Object.keys().length` | `Object.keys().length` | `size` |
| JSON | да | да | нужно преобразовать |

## Что важно помнить

- `Object.create(proto)` не вызывает конструктор — инициализацию делайте вручную.
- Литерал `{ __proto__: null }` тоже создает объект без прототипа.
- Объекты без прототипа неудобно отлаживать: консоль показывает их без привычных методов.
- `Object.create(Object.prototype)` эквивалентен `{}`.

## Мини-шпаргалка

- `Object.create(proto)` — новый объект с прототипом `proto`.
- Второй аргумент — дескрипторы свойств.
- `Object.create(null)` — без прототипа, безопасный словарь.
- Для такого объекта — `Object.hasOwn`, а не `hasOwnProperty`.
- Альтернатива словарю — `Map`.
