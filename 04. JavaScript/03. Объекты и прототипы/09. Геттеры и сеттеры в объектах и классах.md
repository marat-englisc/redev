# Геттеры и сеттеры в объектах и классах

> [!NOTE]
> **Геттер** (`get`) — свойство-аксессор, которое вычисляет значение при чтении, **сеттер** (`set`) — функция, которая срабатывает при присваивании. Снаружи они выглядят как обычные свойства: `obj.fullName`, `obj.fullName = "..."`. Используются для вычисляемых значений, валидации, обратной совместимости и инкапсуляции. Работают одинаково в объектных литералах, классах и через `Object.defineProperty`.

## Вопрос

Что такое геттеры и сеттеры? Как их объявить в объекте и в классе и когда их стоит использовать?

## В объектном литерале

```javascript
const user = {
  firstName: "Анна",
  lastName: "Петрова",

  get fullName() {
    return `${this.firstName} ${this.lastName}`;
  },

  set fullName(value) {
    [this.firstName, this.lastName] = value.split(" ");
  },
};

user.fullName;               // "Анна Петрова" — вызывается get, без скобок
user.fullName = "Мария Иванова"; // вызывается set
user.firstName;              // "Мария"
```

## В классе с валидацией

```javascript
class Product {
  #price = 0;

  get price() {
    return this.#price;
  }

  set price(value) {
    if (typeof value !== "number" || value < 0) {
      throw new RangeError("Цена должна быть неотрицательным числом");
    }
    this.#price = value;
  }

  get priceWithVat() {          // только геттер — свойство только для чтения
    return Math.round(this.#price * 1.2);
  }
}

const p = new Product();
p.price = 1000;
p.priceWithVat;     // 1200
p.priceWithVat = 5; // игнорируется (в strict mode — TypeError)
p.price = -1;       // RangeError
```

Геттеры и сеттеры классов находятся в **прототипе**, а не в экземпляре.

## Через Object.defineProperty

```javascript
const temperature = { celsius: 20 };

Object.defineProperty(temperature, "fahrenheit", {
  get() { return this.celsius * 1.8 + 32; },
  set(f) { this.celsius = (f - 32) / 1.8; },
  enumerable: true,
});
```

## Когда использовать

- вычисляемые свойства (`fullName`, `total`), которые зависят от других полей;
- валидация и нормализация при записи;
- «только для чтения» снаружи с приватным полем внутри;
- ленивые вычисления с кешированием;
- обратная совместимость: поле стало вычисляемым, а API не изменилось.

## Подводные камни

```javascript
const bad = {
  get name() {
    return this.name; // бесконечная рекурсия: геттер вызывает сам себя
  },
};
```

Значение храните в другом поле (`_name` или `#name`).

- Геттер выполняется при **каждом** чтении — тяжелые вычисления кешируйте.
- `JSON.stringify` и spread вычисляют геттеры и копируют значения, а не аксессоры.
- `structuredClone` тоже сохраняет только значения.
- Сеттер без геттера дает `undefined` при чтении.

## Что важно помнить

- Не прячьте в геттер побочные эффекты (запросы, мутации) — чтение свойства должно быть безопасным.
- Vue 2 строил реактивность на `Object.defineProperty` с геттерами и сеттерами, Vue 3 — на `Proxy`.
- В TypeScript можно объявить `get` без `set` — свойство станет `readonly`.
- Для проверки, что свойство — аксессор: `Object.getOwnPropertyDescriptor(Product.prototype, "price")`.

## Мини-шпаргалка

- `get prop() {}` — вычисление при чтении, `set prop(v) {}` — при записи.
- Снаружи — как обычное свойство, без скобок.
- В классах аксессоры живут в прототипе.
- Только `get` — свойство только для чтения.
- Значение храните в отдельном поле, иначе рекурсия.
