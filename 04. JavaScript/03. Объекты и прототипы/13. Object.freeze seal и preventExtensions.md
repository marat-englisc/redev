# Object.freeze, Object.seal и Object.preventExtensions

> [!NOTE]
> Три уровня защиты объекта. `Object.preventExtensions(obj)` запрещает добавлять новые свойства. `Object.seal(obj)` дополнительно запрещает удалять свойства и менять их флаги, но значения менять можно. `Object.freeze(obj)` запрещает всё: добавлять, удалять и изменять. Все три — **поверхностные**: вложенные объекты остаются изменяемыми.

## Вопрос

Что делают `Object.freeze()`, `Object.seal()` и `Object.preventExtensions()`? Чем они отличаются и как сделать глубокую заморозку?

## Сравнение

| Операция | `preventExtensions` | `seal` | `freeze` |
| --- | :---: | :---: | :---: |
| Добавить свойство | ❌ | ❌ | ❌ |
| Удалить свойство | ✅ | ❌ | ❌ |
| Изменить значение | ✅ | ✅ | ❌ |
| Изменить флаги | ✅ | ❌ | ❌ |
| Проверка | `Object.isExtensible` | `Object.isSealed` | `Object.isFrozen` |

## Примеры

```javascript
"use strict";

const settings = Object.preventExtensions({ theme: "light" });
settings.theme = "dark";   // OK
delete settings.theme;     // OK
settings.lang = "ru";      // TypeError

const user = Object.seal({ name: "Анна" });
user.name = "Мария";       // OK
delete user.name;          // TypeError
user.age = 25;             // TypeError

const config = Object.freeze({ apiUrl: "/api", retries: 3 });
config.retries = 5;        // TypeError
```

Без strict mode нарушения **молча игнорируются**, что усложняет поиск ошибок. Модули и классы всегда работают в strict mode.

## Заморозка поверхностная

```javascript
const state = Object.freeze({ user: { name: "Анна" }, tags: ["a"] });

state.user.name = "Мария"; // работает!
state.tags.push("b");      // работает!
```

Глубокая заморозка:

```javascript
function deepFreeze(obj) {
  for (const value of Object.values(obj)) {
    if (value !== null && typeof value === "object" && !Object.isFrozen(value)) {
      deepFreeze(value);
    }
  }
  return Object.freeze(obj);
}
```

## Где применяется

- константы и конфигурация, которые не должны меняться;
- защита от случайной мутации state в dev-режиме (Immer и Redux Toolkit замораживают результат);
- перечисления до появления `enum` в TypeScript:

```javascript
const Status = Object.freeze({
  Pending: "pending",
  Done: "done",
});
```

- массивы: `Object.freeze([1, 2])` запрещает `push`, `sort` и присваивание по индексу.

## Что важно помнить

- `freeze` необратим: «разморозить» объект нельзя, можно только создать копию.
- `const` и `freeze` решают разные задачи: `const` запрещает переназначить переменную, `freeze` — менять объект.
- Прототип нерасширяемого объекта (после любого из трех методов) сменить нельзя: `Object.setPrototypeOf` бросит `TypeError`.
- `Map` и `Set` не замораживаются по содержимому: `Object.freeze(new Map()).set(1, 1)` работает — данные хранятся во внутренних слотах.
- В TypeScript `Readonly<T>` и `as const` дают похожую защиту на этапе компиляции без runtime-затрат.

## Мини-шпаргалка

- `preventExtensions` — нельзя добавлять.
- `seal` — нельзя добавлять и удалять.
- `freeze` — нельзя ничего.
- Все три поверхностные — для вложенных нужен `deepFreeze`.
- Без strict mode ошибки молчат.
