# Как копировать объекты и массивы: поверхностно и глубоко

> [!NOTE]
> Оператор `=` копирует только ссылку — обе переменные указывают на один объект. **Поверхностная копия** (`{ ...obj }`, `Object.assign({}, obj)`, `[...arr]`, `arr.slice()`) создает новый объект верхнего уровня, но вложенные объекты остаются общими. **Глубокая копия** (`structuredClone`) рекурсивно копирует все уровни. Старый прием `JSON.parse(JSON.stringify(obj))` теряет `Date`, `Map`, `undefined` и функции.

## Вопрос

Почему нельзя скопировать объект оператором `=`? Чем поверхностная копия отличается от глубокой? Как работают `Object.assign` и `structuredClone` и как скопировать массив?

## Почему не =

```javascript
const original = { name: "Анна" };
const copy = original;

copy.name = "Мария";
console.log(original.name); // "Мария" — это один и тот же объект
original === copy;          // true
```

## Поверхностная копия

```javascript
const user = { name: "Анна", address: { city: "Казань" } };

const a = { ...user };
const b = Object.assign({}, user);

a.name = "Мария";          // исходный объект не изменился
a.address.city = "Москва"; // изменился и user.address.city!
a.address === user.address; // true
```

Массивы:

```javascript
const items = [{ id: 1 }, { id: 2 }];

const c1 = [...items];
const c2 = items.slice();
const c3 = Array.from(items);
const c4 = items.concat();

c1[0].id = 99; // меняет и items[0] — объекты внутри общие
```

## Глубокая копия: structuredClone

```javascript
const order = {
  id: 1,
  createdAt: new Date(),
  items: [{ id: 10, tags: new Set(["new"]) }],
};

const clone = structuredClone(order);

clone.items[0].id = 99;
order.items[0].id;            // 10
clone.createdAt instanceof Date; // true
```

`structuredClone` поддерживает: объекты, массивы, `Date`, `RegExp`, `Map`, `Set`, `ArrayBuffer`, typed arrays, `Blob`, `File`, `Error` и **циклические ссылки**.

Не поддерживает:

- функции и методы (`DataCloneError`);
- DOM-узлы;
- прототипы и классы — экземпляр класса превратится в обычный объект;
- геттеры и сеттеры (копируются значения), неперечисляемые свойства, символы.

## Сравнение способов

| Способ | Глубина | `Date`, `Map`, `Set` | Функции | Циклы |
| --- | --- | --- | --- | --- |
| `=` | ссылка | — | — | — |
| `{ ...obj }`, `Object.assign` | 1 уровень | ссылки на те же объекты | копирует ссылку | — |
| `JSON.parse(JSON.stringify())` | глубокая | `Date` → строка, `Map` → `{}` | теряются | `TypeError` |
| `structuredClone()` | глубокая | да | `DataCloneError` | да |
| `_.cloneDeep` (lodash) | глубокая | да | ссылки | да, сохраняет прототипы |

## Иммутабельное обновление вместо глубокой копии

Часто глубокая копия не нужна: достаточно скопировать путь до изменяемого поля (structural sharing):

```javascript
const next = {
  ...state,
  user: { ...state.user, address: { ...state.user.address, city: "Москва" } },
};
```

Неизмененные ветки остаются общими — это экономнее и позволяет React понять, что изменилось.

## Что важно помнить

- `Object.assign` вызывает сеттеры целевого объекта, spread — нет; оба копируют только собственные перечисляемые свойства.
- Копия через spread теряет прототип: копия экземпляра класса — обычный объект.
- Глубокое копирование больших структур дорого — копируйте только то, что меняете.
- `structuredClone` используется браузером и для `postMessage` между воркерами.

## Мини-шпаргалка

- `=` — копия ссылки.
- Поверхностно: `{ ...obj }`, `Object.assign({}, obj)`, `[...arr]`, `slice()`.
- Глубоко: `structuredClone(obj)`.
- JSON-трюк теряет `Date`, `Map`, `undefined`, функции.
- Для state — копирование пути, а не всего дерева.
