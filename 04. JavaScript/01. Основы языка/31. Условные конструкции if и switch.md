# Условные конструкции if и switch. Зачем break в switch

> [!NOTE]
> Условные конструкции выполняют код в зависимости от условия: `if/else`, тернарный оператор `? :`, `switch`, логические операторы и объекты-словари. В `switch` значение сравнивается со случаями через строгое равенство `===`, а `break` нужен, чтобы выйти после совпавшего `case` — без него выполнение «проваливается» (fall-through) в следующие ветки.

## Вопрос

Какие условные конструкции есть в JavaScript? Как работает `switch` и что будет, если не поставить `break`?

## if / else

```javascript
if (score >= 90) {
  grade = "A";
} else if (score >= 70) {
  grade = "B";
} else {
  grade = "C";
}
```

Условие приводится к boolean, поэтому `if ("0")` выполнится, а `if (0)` — нет.

**Ранний выход (guard clause)** уменьшает вложенность:

```javascript
function checkout(cart) {
  if (!cart.items.length) return;
  if (!cart.address) throw new Error("Укажите адрес");
  submitOrder(cart);
}
```

## Тернарный оператор

```javascript
const label = isOpen ? "Скрыть" : "Показать";
```

Подходит для простого выбора значения. Вложенные тернарники ухудшают читаемость.

## switch

```javascript
switch (status) {
  case "pending":
    showSpinner();
    break;
  case "success":
    showData();
    break;
  case "error":
  case "timeout":        // несколько case для одной ветки
    showError();
    break;
  default:
    console.warn("Неизвестный статус", status);
}
```

- сравнение строгое: `switch (1)` не совпадет с `case "1"`;
- `default` выполняется, если ни один `case` не подошел, и может стоять в любом месте;
- `break` выходит из `switch`; вместо него можно `return` внутри функции.

## Fall-through без break

```javascript
switch (level) {
  case 1:
    console.log("уровень 1");
  case 2:
    console.log("уровень 2");
  default:
    console.log("по умолчанию");
}
// при level === 1 выведет все три строки
```

Иногда провал используют намеренно — тогда пишут комментарий `// falls through`, иначе линтер (`no-fallthrough`) сообщит об ошибке.

## Области видимости в case

Все `case` делят один блок, поэтому `let` в двух ветках с одним именем — ошибка. Решение — фигурные скобки:

```javascript
switch (action.type) {
  case "add": {
    const item = action.payload;
    return [...state, item];
  }
  case "remove": {
    const item = action.payload; // OK — другой блок
    return state.filter((i) => i.id !== item.id);
  }
}
```

## Объект вместо switch

```javascript
const statusText = {
  pending: "Ожидание",
  success: "Готово",
  error: "Ошибка",
};

const text = statusText[status] ?? "Неизвестно";
```

Словарь удобен для сопоставления значений и легко расширяется.

## Что важно помнить

- `switch (true) { case age > 18: ... }` — допустимый, но спорный прием; обычно `if/else` понятнее.
- Редьюсеры в React и Redux традиционно пишут через `switch` по `action.type`.
- В TypeScript `switch` по discriminated union с `default: assertNever(x)` дает проверку полноты.
- Optional chaining и `??` часто заменяют цепочки `if` для проверки вложенных значений.

## Мини-шпаргалка

- `if/else`, тернарник, `switch`, словарь.
- `switch` сравнивает через `===`.
- Без `break` — провал в следующие `case`.
- Несколько `case` подряд — одна ветка.
- `{}` внутри `case` для `let`/`const`.
