# Динамическая типизация

> [!NOTE]
> JavaScript - динамически типизированный язык: тип проверяется во время выполнения, а одна переменная может хранить значения разных типов в разные моменты времени.

## Вопрос

Что такое динамическая типизация в JavaScript? Чем она отличается от статической?

## Основная идея

В JavaScript тип принадлежит значению, а не переменной.

```javascript
let value = 10;      // number
value = "10";        // string
value = true;        // boolean
value = { id: 1 };   // object
```

Это удобно для быстрого написания кода, но требует внимательности.

## Статическая типизация

При статической типизации типы известны и проверяются до запуска программы.

```typescript
let count: number = 10;

count = "10"; // ошибка TypeScript
```

TypeScript добавляет статическую проверку типов поверх JavaScript, но в браузере все равно выполняется обычный JavaScript.

## Динамическая типизация на практике

```javascript
function double(value) {
  return value * 2;
}

double(5);   // 10
double("5"); // 10
double("x"); // NaN
```

Функция не запрещает передать строку. JavaScript попытается выполнить операцию и приведет типы автоматически.

## Чем отличается от слабой типизации

Динамическая типизация отвечает на вопрос "когда проверяется тип".

Слабая типизация отвечает на вопрос "насколько охотно язык приводит типы сам".

JavaScript одновременно:

- динамически типизированный;
- слабо типизированный;
- поддерживает неявные преобразования типов.

```javascript
"5" - 2; // 3
"5" + 2; // "52"
```

## Плюсы

- Быстро писать простой код.
- Не нужно заранее описывать все типы.
- Удобно для небольших скриптов и прототипов.

## Минусы

- Ошибки типов часто всплывают только во время выполнения.
- Неочевидные преобразования могут дать странный результат.
- Сложнее поддерживать большой код без TypeScript, тестов и дисциплины.

## Что важно помнить

- Тип принадлежит значению, а не переменной: одна переменная может хранить значения разных типов.
- Динамическая типизация не означает слабую: JavaScript еще и слабо типизирован, потому что неявно приводит типы.
- TypeScript добавляет статическую проверку типов поверх JavaScript, но в runtime типы стираются.
- Переиспользование переменной для значений разных типов ухудшает читаемость и мешает оптимизациям движка.

## Мини-шпаргалка

| Подход | Когда проверяются типы | Пример |
| --- | --- | --- |
| Динамический | во время выполнения | JavaScript |
| Статический | до выполнения | TypeScript, Java, C# |
| Слабый | язык сам часто приводит типы | JavaScript |
| Сильный | язык строже относится к разным типам | Python, TypeScript на этапе проверки |
