# `BigInt` vs обычные числа

> [!NOTE]
> `BigInt` нужен для целых чисел больше безопасного диапазона `Number`. В JavaScript нет отдельного типа `int`: обычные числа имеют тип `number`, а большие целые - `bigint`.

## Вопрос

Что делает `BigInt` и зачем он нужен? В чем разница от обычного числа?

## Обычный `number`

Все обычные числа в JavaScript имеют тип `number`.

```javascript
typeof 10;   // "number"
typeof 3.14; // "number"
```

`number` основан на формате IEEE 754 double precision. Он хранит и целые, и дробные числа.

Проблема: не все большие целые числа можно представить точно.

```javascript
Number.MAX_SAFE_INTEGER; // 9007199254740991
```

После этого предела точность ломается:

```javascript
9007199254740991 + 1; // 9007199254740992
9007199254740991 + 2; // 9007199254740992
```

## `BigInt`

`BigInt` хранит целые числа произвольной длины.

```javascript
const id = 9007199254740993n;

typeof id; // "bigint"
```

Создать можно через суффикс `n` или функцию `BigInt()`.

```javascript
const a = 10n;
const b = BigInt("9007199254740993");
```

## Арифметика

```javascript
10n + 5n; // 15n
10n * 2n; // 20n
```

Но нельзя смешивать `bigint` и `number` в арифметике:

```javascript
10n + 5; // TypeError
```

Нужно привести явно:

```javascript
10n + BigInt(5); // 15n
Number(10n) + 5; // 15
```

Второй вариант может потерять точность для больших значений.

## Деление

`BigInt` работает только с целыми числами.

```javascript
5n / 2n; // 2n
```

Дробная часть отбрасывается.

## Когда использовать

`BigInt` полезен для:

- больших id;
- криптографии;
- точной целочисленной арифметики;
- счетчиков, которые могут выйти за `Number.MAX_SAFE_INTEGER`.

Для обычных цен, размеров, координат и большинства UI-расчетов обычно хватает `number`.

## JSON и BigInt

`JSON.stringify` не умеет сериализовать `bigint` напрямую.

```javascript
JSON.stringify({ id: 10n }); // TypeError
```

Часто `BigInt` передают как строку:

```javascript
JSON.stringify({ id: String(10n) }); // '{"id":"10"}'
```

## Что важно помнить

- `BigInt` нельзя смешивать с `number` в арифметике: `1n + 1` — `TypeError`.
- Деление `BigInt` отбрасывает дробную часть: `7n / 2n` → `3n`.
- `JSON.stringify` не поддерживает `BigInt` — нужен `toJSON` или replacer.
- Используйте `BigInt` для идентификаторов из БД больше `2^53` и точной целочисленной арифметики, а не для денег с копейками.

## Мини-шпаргалка

| Значение | Тип |
| --- | --- |
| `10` | `number` |
| `10n` | `bigint` |
| `Number.MAX_SAFE_INTEGER` | максимальное безопасное целое |
| `10n + 5` | `TypeError` |
| `5n / 2n` | `2n` |
