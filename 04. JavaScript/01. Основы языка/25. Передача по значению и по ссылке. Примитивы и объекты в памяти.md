# Передача по значению и по ссылке. Примитивы и объекты в памяти

> [!NOTE]
> Примитивы (`number`, `string`, `boolean`, `null`, `undefined`, `symbol`, `bigint`) копируются **по значению**: переменная содержит само значение. Объекты (включая массивы и функции) хранятся в куче, а переменная содержит **ссылку** на них: при присваивании копируется ссылка, а не объект. Аргументы функций в JavaScript всегда передаются по значению — но для объекта этим значением является ссылка (call by sharing).

## Вопрос

Как в JavaScript хранятся примитивы и объекты в памяти? Передаются ли данные по ссылке или по значению? Можно ли изменить аргумент внутри функции?

## Примитивы — по значению

```javascript
let a = 10;
let b = a; // копия значения
b = 20;

console.log(a); // 10
```

Примитивы неизменяемы: `str.toUpperCase()` создает новую строку, а не меняет исходную.

## Объекты — по ссылке

```javascript
const user = { name: "Анна" };
const admin = user; // копия ссылки

admin.name = "Мария";
console.log(user.name); // "Мария" — один объект на две переменные
```

```text
Стек (переменные)        Куча (объекты)
user  ──────────┐
                ├──► { name: "Мария" }
admin ──────────┘
```

## Сравнение

```javascript
"abc" === "abc";       // true — сравниваются значения
{} === {};             // false — два разных объекта
[1, 2] === [1, 2];     // false

const a = {};
const b = a;
a === b;               // true — одна ссылка
```

Поэтому `===` для объектов проверяет идентичность, а не содержимое. Для сравнения содержимого нужна поэлементная проверка (или `structuredClone` + deep equal из библиотеки).

## Аргументы функций

```javascript
function rename(person) {
  person.name = "Иван";     // меняем объект по полученной ссылке
}

function replace(person) {
  person = { name: "Петр" }; // меняем локальную переменную, внешний объект не затронут
}

const user = { name: "Анна" };
rename(user);  // user.name === "Иван"
replace(user); // user.name всё еще "Иван"
```

Это и называют **call by sharing**: функция получает копию ссылки. Мутировать объект через нее можно, переназначить внешнюю переменную — нельзя.

## Почему это важно

- Случайная мутация общего объекта — частый источник багов.
- React сравнивает state и props по ссылке (`Object.is`): мутация объекта не вызовет ререндер, нужен новый объект.
- `const` запрещает переназначить переменную, но не запрещает менять объект.

```javascript
const settings = { theme: "light" };
settings.theme = "dark"; // OK
settings = {};           // TypeError
```

## Что важно помнить

- Чтобы не мутировать аргумент, создавайте копию: `{ ...obj }`, `[...arr]`, `structuredClone(obj)`.
- Копия через spread поверхностная: вложенные объекты остаются общими.
- Строки большой длины тоже передаются эффективно: движки не копируют их побайтово, но для программиста они ведут себя как значения.
- В JavaScript нет передачи по ссылке в смысле C++ (`&`), нельзя написать функцию `swap(a, b)` для переменных вызывающего кода.

## Мини-шпаргалка

- Примитивы — по значению, неизменяемы.
- Объекты — переменная хранит ссылку.
- Присваивание объекта копирует ссылку.
- `===` для объектов сравнивает ссылки.
- Аргументы — call by sharing: мутировать можно, переназначить — нет.
