# Mutable и immutable данные. Иммутабельность в функциях

> [!NOTE]
> **Mutable** данные можно изменить после создания (объекты, массивы), **immutable** — нельзя (примитивы, замороженные объекты). Иммутабельный подход означает: не менять существующие данные, а создавать новые копии с изменениями. Это делает поток данных предсказуемым и лежит в основе React и Redux, где изменения определяются сравнением ссылок.

## Вопрос

Что такое mutable и immutable данные? Зачем писать функции, которые не мутируют аргументы, и как обновлять объекты и массивы иммутабельно?

## Примитивы неизменяемы

```javascript
let name = "анна";
name.toUpperCase(); // возвращает "АННА", но name не изменился
name[0] = "А";      // молча игнорируется
```

## Объекты и массивы изменяемы

```javascript
const cart = [{ id: 1, qty: 1 }];

cart.push({ id: 2, qty: 1 });  // мутация
cart[0].qty = 5;               // мутация вложенного объекта
```

## Мутирующие и немутирующие методы

| Мутируют | Создают новое |
| --- | --- |
| `push`, `pop`, `shift`, `unshift` | `concat`, `[...arr, x]` |
| `splice` | `slice`, `toSpliced` |
| `sort`, `reverse` | `toSorted`, `toReversed` |
| `arr[i] = x` | `arr.with(i, x)`, `map` |
| `fill`, `copyWithin` | `filter`, `map`, `reduce` |
| `Object.assign(target, ...)` | `{ ...obj }`, `Object.assign({}, ...)` |
| `delete obj.key` | `const { key, ...rest } = obj` |

## Иммутабельные обновления

```javascript
// объект
const updatedUser = { ...user, name: "Мария" };

// вложенный объект — копировать каждый уровень пути
const updated = {
  ...state,
  profile: { ...state.profile, city: "Казань" },
};

// массив
const added = [...items, newItem];
const removed = items.filter((item) => item.id !== id);
const changed = items.map((item) => (item.id === id ? { ...item, done: true } : item));
```

## Иммутабельность в функциях

```javascript
// плохо: функция меняет аргумент
function addDiscount(order) {
  order.total *= 0.9;
  return order;
}

// хорошо: возвращает новый объект
function withDiscount(order) {
  return { ...order, total: order.total * 0.9 };
}
```

Функция без мутаций проще тестировать, ее результат зависит только от аргументов, и она не ломает код, который держит ссылку на исходный объект.

## Зачем это React и Redux

```javascript
setTodos((prev) => [...prev, todo]); // новая ссылка → React видит изменение
```

React сравнивает старое и новое значение через `Object.is`. Если мутировать массив и передать ту же ссылку, компонент не перерисуется. `React.memo`, `useMemo` и селекторы Redux тоже опираются на смену ссылок.

## Защита от мутаций

- `Object.freeze(obj)` — поверхностная заморозка;
- TypeScript `readonly` и `ReadonlyArray<T>` — проверка на этапе компиляции;
- Immer — пишете «мутирующий» код, получаете иммутабельный результат (используется в Redux Toolkit и middleware Zustand).

## Что важно помнить

- Иммутабельность — договоренность, а не свойство языка: `const` не делает объект неизменяемым.
- Копирование больших структур на каждое изменение стоит памяти; structural sharing (копировать только измененный путь) решает это.
- Мутации локальных объектов, которые никто больше не видит, безопасны и иногда быстрее.
- Вложенные spread-ы быстро становятся громоздкими — нормализуйте state или используйте Immer.

## Мини-шпаргалка

- Примитивы — immutable, объекты и массивы — mutable.
- Иммутабельность — создавать новое вместо изменения старого.
- `toSorted`, `toReversed`, `toSpliced`, `with`, spread — без мутаций.
- React видит изменения по новой ссылке.
- `Object.freeze`, `readonly`, Immer помогают соблюдать правило.
