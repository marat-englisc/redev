# Глобальные переменные и глобальный объект

> [!NOTE]
> **Глобальный объект** — объект верхнего уровня окружения: `window` в браузере, `global` в Node.js, `self` в воркерах. Универсальное имя — `globalThis`. В обычном скрипте `var` и Function Declaration на верхнем уровне становятся свойствами глобального объекта, а `let`, `const` и `class` — глобальными переменными, но не свойствами. В модулях верхнеуровневые объявления вообще не глобальны.

## Вопрос

Что такое глобальные переменные и глобальный объект? Чем отличаются `window`, `global` и `globalThis`? Почему глобальные переменные считаются плохой практикой?

## Глобальный объект в разных окружениях

| Окружение | Глобальный объект |
| --- | --- |
| Браузер, основной поток | `window` (= `self` = `frames`) |
| Web Worker | `self` |
| Node.js | `global` |
| Везде | `globalThis` (ES2020) |

```javascript
globalThis.setTimeout === setTimeout; // true в любом окружении
```

На глобальном объекте живут встроенные функции и API: `setTimeout`, `fetch`, `console`, `JSON`, `Math`, `document` (в браузере).

## Как создаются глобальные переменные

```html
<script>
  var a = 1;           // window.a === 1
  function f() {}      // window.f — функция
  let b = 2;           // глобальная, но window.b === undefined
  const c = 3;         // то же самое
  d = 4;               // без объявления: window.d === 4 (в strict mode — ReferenceError)
</script>
```

`let` и `const` верхнего уровня хранятся в отдельном декларативном окружении (script scope), общем для всех классических скриптов страницы.

## В модулях иначе

```html
<script type="module">
  const config = {};   // видна только в этом модуле
  var x = 1;           // window.x === undefined
</script>
```

У модуля своя область видимости, `this` на верхнем уровне — `undefined`. Чтобы сделать что-то глобальным, нужно явно написать `globalThis.something = ...`.

## Почему глобальные переменные — плохо

- **конфликты имен**: два скрипта с `var config` перезапишут друг друга;
- **неявные зависимости**: функция читает глобальную переменную — непонятно, откуда приходят данные;
- **сложное тестирование**: состояние живет между тестами;
- **утечки памяти**: глобальные объекты никогда не собираются сборщиком мусора;
- **затенение встроенных API**: `var name` в браузере пишет в `window.name`, которое сохраняется между переходами.

## Случайные глобальные переменные

```javascript
function count() {
  total = 0; // забыли let — создали window.total
}
```

`"use strict"` и модули превращают это в `ReferenceError`, а ESLint (`no-undef`, `no-implicit-globals`) ловит при разработке.

## Когда глобальные значения оправданы

- полифилы и регистрация API (`globalThis.structuredClone ??= ...`);
- конфигурация, вставленная сервером в HTML (`window.__INITIAL_STATE__`);
- отладка в консоли.

В TypeScript такие свойства описывают через `declare global { interface Window { ... } }`.

## Что важно помнить

- Проверка окружения: `typeof window !== "undefined"` — частый прием в SSR-коде.
- Элементы с `id` создают одноименные глобальные свойства `window` — не полагайтесь на это.
- В Node.js в CommonJS-модуле `var` на верхнем уровне не становится свойством `global`: у каждого файла своя обертка-функция.
- Глобальное состояние приложения храните в модулях, store или контексте, а не на `window`.

## Мини-шпаргалка

- Глобальный объект: `window`, `self`, `global`, универсально `globalThis`.
- `var` и FD на верхнем уровне скрипта → свойства `window`.
- `let`/`const` — глобальные, но не свойства `window`.
- В модулях ничего не глобально без явного `globalThis.x`.
- Глобальные переменные — конфликты, утечки, неявные зависимости.
