# Оператор instanceof и проверка экземпляра класса

> [!NOTE]
> `obj instanceof Constructor` проверяет, есть ли `Constructor.prototype` в цепочке прототипов `obj`. Так проверяют, создан ли объект классом или его наследником. Проверку можно переопределить статическим методом `Symbol.hasInstance`. `instanceof` не работает с примитивами и между разными realm (iframe, worker).

## Вопрос

Что делает оператор `instanceof`? Как он связан с прототипами и как проверить, что объект — экземпляр класса?

## Базовое использование

```javascript
class Animal {}
class Dog extends Animal {}

const rex = new Dog();

rex instanceof Dog;     // true
rex instanceof Animal;  // true — наследник
rex instanceof Object;  // true — почти всё наследует Object
[] instanceof Array;    // true
new Date() instanceof Date; // true
```

## Как это работает

`instanceof` идет по цепочке `__proto__` и сравнивает каждое звено с `Constructor.prototype`:

```javascript
function myInstanceof(obj, Constructor) {
  if (obj === null || (typeof obj !== "object" && typeof obj !== "function")) {
    return false;
  }
  let proto = Object.getPrototypeOf(obj);
  while (proto !== null) {
    if (proto === Constructor.prototype) return true;
    proto = Object.getPrototypeOf(proto);
  }
  return false;
}
```

Отсюда следствия:

```javascript
"текст" instanceof String;               // false — примитив
new String("текст") instanceof String;   // true — объект-обертка

const obj = Object.create(Dog.prototype);
obj instanceof Dog;                      // true, хотя конструктор не вызывался

Object.create(null) instanceof Object;   // false — нет прототипа
```

## Проверка экземпляра: способы

| Способ | Что проверяет |
| --- | --- |
| `obj instanceof Dog` | `Dog.prototype` в цепочке, учитывает наследников |
| `obj.constructor === Dog` | точный класс без наследников, можно подменить |
| `Object.getPrototypeOf(obj) === Dog.prototype` | прямой прототип |
| `Dog.prototype.isPrototypeOf(obj)` | то же, что `instanceof`, без `Symbol.hasInstance` |
| `#field in obj` | brand check по приватному полю — нельзя подделать |

```javascript
class Money {
  #amount = 0;
  static isMoney(value) {
    return #amount in value; // true только для настоящих экземпляров Money
  }
}

const fake = Object.create(Money.prototype);
fake instanceof Money;  // true — прототип подделан
Money.isMoney(fake);    // false — приватного поля нет
```

## Symbol.hasInstance

```javascript
class Even {
  static [Symbol.hasInstance](value) {
    return Number.isInteger(value) && value % 2 === 0;
  }
}

4 instanceof Even; // true
```

## Проблема realm

Массив из iframe создан другим `Array`, поэтому `arr instanceof Array` — `false`. Для массивов используйте `Array.isArray`, для ошибок — проверку `error?.name` или `Error.isError()` в новых движках.

## Что важно помнить

- `instanceof` — проверка по прототипам, а не по «форме» объекта: в TypeScript со структурной типизацией это разные вещи.
- Ошибки удобно различать через `instanceof`: `if (error instanceof ValidationError)`.
- Слева должен быть объект, справа — функция с `prototype`; иначе `TypeError: Right-hand side of 'instanceof' is not callable`.
- В TypeScript `instanceof` сужает тип в условии.

## Мини-шпаргалка

- `obj instanceof C` — есть ли `C.prototype` в цепочке `obj`.
- Учитывает наследование.
- Для примитивов — `false`.
- Не работает между iframe — для массивов `Array.isArray`.
- `Symbol.hasInstance` переопределяет поведение.
