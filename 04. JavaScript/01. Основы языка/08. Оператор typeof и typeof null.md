# Оператор typeof и почему typeof null === "object"

> [!NOTE]
> `typeof` возвращает строку с типом значения: `"number"`, `"string"`, `"boolean"`, `"undefined"`, `"bigint"`, `"symbol"`, `"object"` или `"function"`. Особенность: `typeof null` возвращает `"object"` — это историческая ошибка первой реализации JavaScript, которую не исправили ради совместимости.

## Вопрос

Что делает оператор `typeof`? Почему `typeof null` равен `"object"` и как правильно проверять `null`, массивы и объекты?

## Результаты typeof

| Значение | `typeof` |
| --- | --- |
| `42`, `NaN`, `Infinity` | `"number"` |
| `10n` | `"bigint"` |
| `"text"` | `"string"` |
| `true` | `"boolean"` |
| `undefined` | `"undefined"` |
| `Symbol()` | `"symbol"` |
| `function () {}`, `class {}` | `"function"` |
| `{}`, `[]`, `new Date()`, `/re/` | `"object"` |
| `null` | `"object"` ⚠️ |

```javascript
typeof 42;         // "number"
typeof typeof 42;  // "string" — typeof всегда возвращает строку
typeof undeclared; // "undefined" — без ReferenceError
```

## Почему typeof null === "object"

В первой реализации JavaScript (1995) значения хранились с меткой типа в младших битах. У объектов метка была `000`, а `null` представлялся нулевым указателем — то есть тоже нулями. Поэтому `typeof` относил `null` к объектам. Исправление (`typeof null === "null"`) предлагали в ES2015, но отклонили: оно сломало бы существующие сайты.

При этом `null` — примитив, а не объект: у него нет свойств, и `null.x` бросает `TypeError`.

## Как проверять правильно

```javascript
value === null;                       // null
value === undefined;                  // undefined
value == null;                        // null или undefined (единственный уместный ==)
Array.isArray(value);                 // массив
typeof value === "function";          // функция
value !== null && typeof value === "object"; // объект (включая массивы)
value instanceof Date;                // конкретный класс
Number.isNaN(value);                  // NaN
Object.prototype.toString.call(value); // "[object Array]", "[object Null]" ...
```

## typeof как защита

`typeof` не бросает ошибку для необъявленной переменной, поэтому раньше так проверяли окружение:

```javascript
if (typeof window !== "undefined") {
  // код выполняется в браузере, а не в Node.js или при SSR
}
```

Для переменных в TDZ (`let`/`const` до объявления) `typeof` всё же бросит `ReferenceError`.

## Что важно помнить

- `typeof NaN === "number"` — NaN считается числом.
- `typeof class {}` — `"function"`: классы — это функции.
- `typeof new String("a")` — `"object"`, а `typeof "a"` — `"string"`: обертки дают объект.
- Для `document.all` `typeof` возвращает `"undefined"` — исторический костыль браузеров.
- В TypeScript `typeof` в условии сужает тип (type narrowing).

## Мини-шпаргалка

- `typeof` → строка с одним из 8 значений.
- `typeof null === "object"` — историческая ошибка.
- `null` проверяют через `=== null`.
- Массив — `Array.isArray()`.
- `typeof` безопасен для необъявленных переменных, но не для TDZ.
