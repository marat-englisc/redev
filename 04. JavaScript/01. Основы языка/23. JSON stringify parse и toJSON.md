# JSON: JSON.stringify, JSON.parse и toJSON

> [!NOTE]
> **JSON** — текстовый формат обмена данными, основанный на синтаксисе литералов JavaScript. `JSON.stringify(value)` превращает значение в JSON-строку, `JSON.parse(text)` — обратно в значение. Метод `toJSON()` у объекта позволяет самому решить, как он сериализуется (так работает `Date`). JSON поддерживает только объекты, массивы, строки, числа, `true`, `false` и `null`.

## Вопрос

Что такое JSON? Что делают `JSON.stringify()`, `JSON.parse()` и метод `toJSON()`? Какие значения теряются при сериализации?

## Формат JSON

```json
{
  "id": 42,
  "name": "Анна",
  "tags": ["admin", "editor"],
  "active": true,
  "manager": null
}
```

Отличия от объектного литерала JavaScript:

- ключи только в двойных кавычках;
- строки только в двойных кавычках;
- нет комментариев, висячих запятых, `undefined`, функций, `NaN`, `Infinity`;
- числа только десятичные.

## JSON.stringify

```javascript
JSON.stringify({ a: 1, b: [1, 2] });        // '{"a":1,"b":[1,2]}'
JSON.stringify(user, null, 2);              // с отступами для чтения
JSON.stringify(user, ["id", "name"]);       // только указанные ключи
JSON.stringify(user, (key, value) =>        // replacer-функция
  key === "password" ? undefined : value,
);
```

Что происходит с особыми значениями:

| Значение | В объекте | В массиве | Само по себе |
| --- | --- | --- | --- |
| `undefined`, функция, `Symbol` | свойство пропускается | `null` | `undefined` (не строка) |
| `NaN`, `Infinity` | `null` | `null` | `"null"` |
| `Date` | ISO-строка (через `toJSON`) | ISO-строка | ISO-строка |
| `Map`, `Set` | `{}` | `{}` | `"{}"` |
| `BigInt` | `TypeError` | `TypeError` | `TypeError` |
| Циклическая ссылка | `TypeError` | `TypeError` | — |

## toJSON

Если у объекта есть метод `toJSON`, `stringify` сериализует его результат:

```javascript
const money = {
  amount: 1500,
  currency: "RUB",
  toJSON() {
    return `${this.amount} ${this.currency}`;
  },
};

JSON.stringify({ price: money }); // '{"price":"1500 RUB"}'

new Date(2026, 0, 15).toJSON();   // "2026-01-14T21:00:00.000Z" — в UTC
```

## JSON.parse

```javascript
JSON.parse('{"a":1}');   // { a: 1 }
JSON.parse("[1,2]");     // [1, 2]
JSON.parse("{a:1}");     // SyntaxError — ключ без кавычек

// reviver — преобразование значений при разборе
const data = JSON.parse(text, (key, value) =>
  key === "createdAt" ? new Date(value) : value,
);
```

Невалидный JSON бросает `SyntaxError`, поэтому разбор данных извне оборачивают в `try...catch`:

```javascript
function safeParse(text, fallback = null) {
  try {
    return JSON.parse(text);
  } catch {
    return fallback;
  }
}
```

## Что важно помнить

- `JSON.parse(JSON.stringify(obj))` — старый способ глубокого копирования: он теряет `Date`, `Map`, `undefined` и функции. Используйте `structuredClone`.
- Порядок ключей в результате `stringify` совпадает с порядком свойств — для сравнения объектов по строке это ненадежно.
- Вставка JSON в HTML (`<script>window.__DATA__ = ${json}</script>`) требует экранирования `</script>` и `<` — иначе XSS.
- `response.json()` в `fetch` — это `JSON.parse` текста ответа.
- Данные после `JSON.parse` не типизированы: в TypeScript их проверяют схемой (Zod).

## Мини-шпаргалка

- JSON — текстовый формат: объекты, массивы, строки, числа, boolean, `null`.
- `stringify(value, replacer, space)` → строка.
- `parse(text, reviver)` → значение, `SyntaxError` при ошибке.
- `toJSON()` управляет сериализацией, у `Date` — ISO-строка.
- Теряются `undefined`, функции, символы; `BigInt` и циклы — ошибка.
