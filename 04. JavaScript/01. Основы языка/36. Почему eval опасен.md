# Почему `eval` опасен?

> [!NOTE]
> `eval()` выполняет строку как JavaScript-код. Это опасно из-за инъекций, XSS, проблем с производительностью, отладкой и поддержкой.

## Вопрос

Что делает `eval()` и почему его не рекомендуется использовать?

## Что делает `eval`

```javascript
eval("2 + 2"); // 4
```

`eval` принимает строку и выполняет ее как код в текущем контексте.

```javascript
const name = "Anna";

eval("console.log(name)"); // "Anna"
```

## Главная проблема: безопасность

Если строка приходит от пользователя, сервера, URL или DOM, злоумышленник может выполнить произвольный код.

```javascript
const code = userInput;

eval(code); // очень опасно
```

Например, вместо математического выражения пользователь может передать код, который украдет данные или изменит страницу.

## XSS

В браузере `eval` может стать частью XSS-уязвимости.

```javascript
eval(location.hash.slice(1));
```

Если код зависит от URL, пользователь может сформировать вредоносную ссылку.

## Производительность

Движку сложнее оптимизировать код с `eval`, потому что строка может содержать почти что угодно:

```javascript
eval("var x = 10");
```

Движок не может заранее надежно понять, какие переменные появятся и что изменится.

## Поддержка и отладка

Код внутри строки:

- сложнее подсвечивать;
- сложнее проверять линтером;
- сложнее типизировать;
- сложнее искать через поиск;
- сложнее отлаживать по stack trace.

## Что использовать вместо

Для JSON:

```javascript
JSON.parse(jsonString);
```

Для выбора функции:

```javascript
const actions = {
  save() {},
  remove() {},
};

actions[actionName]?.();
```

Для математических выражений лучше использовать специальный парсер, а не `eval`.

## Есть ли безопасные случаи

В обычной frontend-разработке почти всегда можно обойтись без `eval`. Если кажется, что он нужен, обычно это сигнал пересмотреть архитектуру.

## Что важно помнить

- `eval` выполняет строку как код — инъекция пользовательских данных дает выполнение произвольного кода.
- CSP без `'unsafe-eval'` блокирует `eval`, `new Function` и строковые аргументы `setTimeout`.
- `eval` мешает оптимизациям движка и минификации.
- Для разбора данных используйте `JSON.parse`, для вычислений — явные функции или безопасные парсеры.

## Мини-шпаргалка

| Задача | Вместо `eval` |
| --- | --- |
| разобрать JSON | `JSON.parse()` |
| вызвать действие по имени | объект-словарь функций |
| вычислить пользовательскую формулу | специализированный парсер |
| создать функцию динамически | чаще пересмотреть дизайн |
