# Promise.all, allSettled, race и any

> [!NOTE]
> Комбинаторы промисов принимают итерируемый набор промисов и возвращают один промис. `Promise.all` ждет всех и отклоняется при **первой** ошибке. `Promise.allSettled` ждет всех и возвращает статус каждого, никогда не отклоняясь. `Promise.race` завершается вместе с **первым settled** промисом — успешным или нет. `Promise.any` выполняется с **первым успешным** и отклоняется `AggregateError`, только если упали все.

## Вопрос

Что делают `Promise.all()`, `Promise.allSettled()`, `Promise.race()` и `Promise.any()`? Чем они отличаются и когда какой использовать?

## Сравнение

| Метод | Выполняется | Отклоняется | Результат |
| --- | --- | --- | --- |
| `all` | когда все успешны | при первой ошибке | массив значений в исходном порядке |
| `allSettled` | когда все завершились | никогда | массив `{ status, value \| reason }` |
| `race` | первый settled — успех | первый settled — ошибка | значение или ошибка первого |
| `any` | первый успешный | когда все упали | значение первого успешного или `AggregateError` |

## Promise.all

```javascript
const [user, orders, settings] = await Promise.all([
  fetchUser(id),
  fetchOrders(id),
  fetchSettings(id),
]);
```

- результаты в порядке входного массива, а не порядке завершения;
- при первой ошибке весь `all` отклоняется, но остальные запросы **не отменяются**;
- пустой массив → сразу `[]`;
- не-промисы в массиве считаются уже выполненными.

## Promise.allSettled

```javascript
const results = await Promise.allSettled(files.map(upload));

const failed = results.filter((r) => r.status === "rejected");
const uploaded = results
  .filter((r) => r.status === "fulfilled")
  .map((r) => r.value);
```

Подходит, когда операции независимы и нужно знать судьбу каждой: массовая загрузка, отправка уведомлений, дашборд из нескольких виджетов.

## Promise.race

```javascript
const timeout = (ms) =>
  new Promise((_, reject) => setTimeout(() => reject(new Error("Таймаут")), ms));

const data = await Promise.race([fetch("/api/slow"), timeout(5000)]);
```

`race` не отменяет «проигравший» запрос. Для настоящего таймаута `fetch` используйте `AbortSignal.timeout(5000)`.

## Promise.any

```javascript
const fastest = await Promise.any([
  fetch("https://mirror1.example.com/data"),
  fetch("https://mirror2.example.com/data"),
]);
```

Ошибки игнорируются, пока есть шанс на успех. Если упали все:

```javascript
try {
  await Promise.any([Promise.reject(new Error("a")), Promise.reject(new Error("b"))]);
} catch (error) {
  error instanceof AggregateError; // true
  error.errors;                    // [Error("a"), Error("b")]
}
```

## Реализация Promise.all (частый вопрос)

```javascript
function promiseAll(iterable) {
  return new Promise((resolve, reject) => {
    const items = Array.from(iterable);
    const results = new Array(items.length);
    let done = 0;
    if (items.length === 0) return resolve(results);

    items.forEach((item, index) => {
      Promise.resolve(item).then((value) => {
        results[index] = value;
        if (++done === items.length) resolve(results);
      }, reject);
    });
  });
}
```

## Что важно помнить

- Для очень большого числа запросов `Promise.all` запустит их одновременно — ограничивайте конкурентность (пул по N запросов, библиотека `p-limit`).
- Чтобы отменить остальные запросы после ошибки в `all`, передайте всем один `AbortController` и вызовите `abort()` в `catch`.
- `allSettled` не бросает ошибок — не забудьте проверить статусы, иначе ошибки «пропадут».
- В TypeScript `Promise.all` с кортежем сохраняет типы каждого элемента.

## Мини-шпаргалка

- `all` — все успешны, иначе первая ошибка.
- `allSettled` — все завершились, статус каждого.
- `race` — первый завершившийся (успех или ошибка).
- `any` — первый успешный, иначе `AggregateError`.
- Ни один комбинатор не отменяет остальные операции.
