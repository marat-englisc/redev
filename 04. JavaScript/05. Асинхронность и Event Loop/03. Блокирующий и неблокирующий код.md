# Блокирующий и неблокирующий код. Почему нельзя блокировать event loop

> [!NOTE]
> **Блокирующая операция** занимает поток до своего завершения: тяжелый цикл, синхронное чтение файла, `alert()`, синхронный XHR. **Неблокирующий (non-blocking) код** запускает долгую операцию, сразу возвращает управление и получает результат позже через колбэк, промис или событие. Пока основной поток заблокирован, event loop не может обработать клики, таймеры, ответы сети и перерисовать страницу.

## Вопрос

Что означает термин «non-blocking»? Что такое блокирующая операция? Почему не стоит блокировать event loop?

## Блокирующий код

```javascript
function findPrimes(limit) {
  const primes = [];
  for (let n = 2; n < limit; n++) {
    if (primes.every((p) => n % p !== 0)) primes.push(n);
  }
  return primes;
}

findPrimes(200_000); // несколько секунд страница не реагирует
```

Примеры блокирующих операций:

- долгие синхронные вычисления и циклы;
- огромные `JSON.parse` / `JSON.stringify`, сортировка больших массивов;
- `alert`, `confirm`, `prompt`;
- синхронный XHR (`open(..., false)`), `localStorage` на больших объемах;
- в Node.js — `fs.readFileSync`, `crypto.pbkdf2Sync`, тяжелые регулярные выражения.

## Неблокирующий код

```javascript
console.log("запрос отправлен");
fetch("/api/report")
  .then((r) => r.json())
  .then(render);
console.log("UI продолжает работать");
```

`fetch` передает работу браузеру и сразу возвращает промис. Поток свободен.

## Что ломает блокировка

```text
основной поток занят 2 секунды
├── клики и ввод — ждут в очереди
├── setTimeout(fn, 0) — выполнится через 2 секунды
├── анимации на JS — замерли
├── рендер — не происходит
└── в Node.js все входящие запросы ждут
```

Для пользователя это «зависшая» страница, а для метрик — плохой INP (Interaction to Next Paint). Браузер считает долгой задачу (long task) длиннее 50 мс.

## Как не блокировать

| Подход | Когда |
| --- | --- |
| Асинхронные API (`fetch`, `fs/promises`) | ввод-вывод |
| Разбиение задачи на части (`setTimeout`, `scheduler.yield()`) | большие циклы в основном потоке |
| `requestIdleCallback` | некритичная фоновая работа |
| Web Worker / worker_threads | тяжелые вычисления |
| Виртуализация списков | рендер тысяч элементов |
| Стриминг (`ReadableStream`) | большие данные по частям |

```javascript
async function processInChunks(items, handle) {
  for (let i = 0; i < items.length; i++) {
    handle(items[i]);
    if (i % 500 === 0) {
      await new Promise((r) => setTimeout(r)); // отдаем управление event loop
    }
  }
}
```

## Что важно помнить

- `async` не делает код неблокирующим: синхронный цикл внутри async-функции блокирует поток так же.
- Бесконечная цепочка микрозадач тоже блокирует рендер — event loop не перейдет к отрисовке.
- В Node.js блокировка event loop — одна сервер-процесс перестает отвечать всем клиентам.
- Найти долгие задачи помогает вкладка Performance (красные метки Long task) и `PerformanceObserver` с типом `longtask`.

## Мини-шпаргалка

- Блокирующая операция держит поток до завершения.
- Non-blocking — запустить и получить результат позже.
- Блокировка = нет кликов, таймеров, рендера.
- Long task — дольше 50 мс.
- Решения: async API, разбиение задач, воркеры.
