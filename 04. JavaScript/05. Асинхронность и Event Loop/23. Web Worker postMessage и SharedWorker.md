# Web Worker, postMessage и SharedWorker

> [!NOTE]
> **Web Worker** выполняет JavaScript в отдельном фоновом потоке, не блокируя основной поток и интерфейс. Общение с ним идет через `postMessage` и событие `message`: данные копируются алгоритмом structured clone или передаются (transfer) без копирования. У воркера нет доступа к DOM, `window` и `document` — DOM не потокобезопасен. **SharedWorker** — один воркер, общий для нескольких вкладок того же origin.

## Вопрос

Что делает Web Worker? Как работает `postMessage()` между потоками? Почему у Web Worker нет доступа к DOM? Что делает SharedWorker?

## Создание воркера

```javascript
// main.js
const worker = new Worker(new URL("./primes.worker.js", import.meta.url), { type: "module" });

worker.postMessage({ limit: 1_000_000 });

worker.addEventListener("message", (event) => {
  console.log("Простых чисел:", event.data.count);
});

worker.addEventListener("error", (event) => console.error(event.message));

// когда воркер больше не нужен
worker.terminate();
```

```javascript
// primes.worker.js
self.addEventListener("message", (event) => {
  const { limit } = event.data;
  let count = 0;
  for (let n = 2; n < limit; n++) if (isPrime(n)) count++;
  self.postMessage({ count });
});
```

Тяжелый подсчет идет в отдельном потоке, а интерфейс остается отзывчивым.

## Как работает postMessage

```text
main thread                         worker thread
postMessage(data) ──structured clone──► message event
message event ◄──structured clone────── postMessage(result)
```

- **structured clone** копирует объекты, массивы, `Map`, `Set`, `Date`, `Blob`, typed arrays; функции и DOM-узлы передать нельзя (`DataCloneError`);
- **transferable objects** (`ArrayBuffer`, `MessagePort`, `ImageBitmap`, `OffscreenCanvas`) передаются без копирования — исходный объект становится недоступен:

```javascript
const buffer = new ArrayBuffer(50_000_000);
worker.postMessage(buffer, [buffer]); // мгновенно, buffer.byteLength теперь 0
```

- общая память — `SharedArrayBuffer` + `Atomics` (нужна cross-origin isolation).

## Почему нет доступа к DOM

DOM и движок рендеринга работают в основном потоке и не рассчитаны на одновременные изменения из нескольких потоков. Если бы два потока меняли DOM параллельно, понадобились бы блокировки, а гонки данных ломали бы страницу. Поэтому воркеру доступны только «безопасные» API:

| Доступно в воркере | Недоступно |
| --- | --- |
| `fetch`, `WebSocket`, `IndexedDB` | `document`, `window`, DOM |
| `setTimeout`, `setInterval` | `localStorage`, `sessionStorage` |
| `crypto`, `TextEncoder`, `Cache API` | `alert`, `confirm` |
| `importScripts` / модули, `OffscreenCanvas` | прямое изменение интерфейса |

Результат воркер отправляет в основной поток, и уже тот обновляет DOM.

## SharedWorker

```javascript
// в каждой вкладке
const shared = new SharedWorker("/sync.worker.js");
shared.port.start();
shared.port.postMessage({ type: "subscribe" });
shared.port.onmessage = (event) => render(event.data);
```

```javascript
// sync.worker.js
const ports = new Set();
self.onconnect = (event) => {
  const port = event.ports[0];
  ports.add(port);
  port.onmessage = (e) => {
    for (const p of ports) p.postMessage(e.data); // рассылка всем вкладкам
  };
};
```

Применение: одно WebSocket-соединение на все вкладки, общий кеш, синхронизация состояния. Поддерживается не везде (на мобильных хуже), поэтому часто используют `BroadcastChannel`.

## Виды воркеров

| Воркер | Назначение |
| --- | --- |
| Dedicated Worker | фоновые вычисления для одной страницы |
| SharedWorker | общий для вкладок одного origin |
| Service Worker | прокси для сети, кеш, офлайн, push |
| Worklet | аудио, CSS Paint API, анимации |

## Что важно помнить

- Создание воркера и копирование больших данных стоит времени — воркер выгоден для задач от десятков миллисекунд.
- Библиотека Comlink превращает `postMessage` в удобный вызов функций через Proxy.
- В Vite и webpack воркер подключают через `new Worker(new URL(...), import.meta.url)`.
- Ошибка внутри воркера не роняет страницу, но ее нужно обработать событием `error`.

## Мини-шпаргалка

- Worker — отдельный поток для тяжелых вычислений.
- Общение: `postMessage` + `message`, structured clone или transfer.
- Нет DOM, `window`, `localStorage`.
- DOM не потокобезопасен — поэтому только основной поток.
- SharedWorker — общий для вкладок, альтернатива — `BroadcastChannel`.
