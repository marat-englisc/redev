# Почему JavaScript однопоточный и есть ли в нем многопоточность

> [!NOTE]
> JavaScript называют однопоточным, потому что пользовательский код в одном окружении (вкладке, воркере, процессе Node.js) выполняется в **одном потоке** с одним стеком вызовов: в каждый момент выполняется только одна функция. При этом браузер и Node.js многопоточны внутри — сеть, таймеры и файловый ввод-вывод работают параллельно. Настоящую многопоточность для JS-кода дают Web Workers, worker_threads и `SharedArrayBuffer` с `Atomics`.

## Вопрос

Почему JavaScript считается однопоточным? Есть ли в JavaScript многопоточность?

## Один поток выполнения

```javascript
function heavy() {
  const end = Date.now() + 3000;
  while (Date.now() < end) {} // 3 секунды занято
}

button.addEventListener("click", () => console.log("клик"));
heavy(); // клики, анимации и рендер ждут
```

У основного потока одна очередь задач и один стек. Пока он занят, браузер не может обработать ввод и перерисовать страницу.

Почему так задумано: JavaScript создавался для работы с DOM. Если бы несколько потоков меняли DOM одновременно, понадобились бы блокировки и появились бы гонки данных. Однопоточная модель с event loop проще и безопаснее.

## Кто работает параллельно

```text
Вкладка браузера
├── основной поток: JS, стили, layout, paint, события
├── сетевой поток: HTTP-запросы
├── потоки таймеров, декодирования изображений, компоновки (compositor)
└── Web Workers: отдельный JS-код
```

JS запускает операцию, браузер выполняет ее в другом потоке, а результат возвращается в основной поток через очередь задач.

## Многопоточность для JS-кода

| Инструмент | Окружение | Особенности |
| --- | --- | --- |
| Web Worker | браузер | отдельный поток, нет DOM, обмен через `postMessage` |
| SharedWorker | браузер | один воркер на несколько вкладок |
| Service Worker | браузер | прокси для сети, офлайн, push |
| Worklets | браузер | аудио, рисование (CSS Paint API) |
| `worker_threads` | Node.js | потоки внутри процесса |
| `child_process`, cluster | Node.js | отдельные процессы |
| `SharedArrayBuffer` + `Atomics` | оба | общая память между потоками |

```javascript
const worker = new Worker(new URL("./heavy.worker.js", import.meta.url), { type: "module" });
worker.postMessage(bigData);
worker.onmessage = (event) => render(event.data);
```

Каждый воркер — отдельное окружение со своим стеком, памятью и event loop. По умолчанию память не общая: данные копируются через structured clone или передаются (transferable).

## Что важно помнить

- Асинхронность (event loop) и многопоточность (воркеры) — разные механизмы.
- Тяжелые вычисления в основном потоке вредят INP — выносите их в Worker или разбивайте на части.
- `SharedArrayBuffer` доступен только на cross-origin isolated страницах (`COOP` + `COEP` headers).
- В Node.js libuv использует пул потоков для файлов и криптографии, но ваш JS-код всё равно в одном потоке.

## Мини-шпаргалка

- Один поток и один стек на окружение — однопоточность.
- Среда (браузер, Node.js) многопоточна внутри.
- Однопоточность защищает DOM от гонок.
- Многопоточность для JS — Web Workers, worker_threads.
- Общая память — `SharedArrayBuffer` + `Atomics`.
