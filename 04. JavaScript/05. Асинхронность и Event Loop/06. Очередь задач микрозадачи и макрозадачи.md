# Очередь задач, микрозадачи и макрозадачи

> [!NOTE]
> **Макрозадачи (tasks)** — крупные события среды: `setTimeout`, `setInterval`, события DOM, сообщения `postMessage`, I/O. Они берутся из очереди **по одной** за оборот event loop. **Микрозадачи** — короткие продолжения: `Promise.then/catch/finally`, продолжение после `await`, `queueMicrotask`, `MutationObserver`. После каждой макрозадачи очередь микрозадач выполняется **полностью**, включая микрозадачи, добавленные по ходу, — и только потом браузер может отрисовать кадр.

## Вопрос

Что такое очередь задач и микрозадачи? Чем микротаски отличаются от макротасок? Как работает «микротаска промиса»?

## Основное правило

```text
sync code
  → все микрозадачи
  → одна макрозадача → все микрозадачи
  → (рендер, если пора)
  → одна макрозадача → все микрозадачи → ...
```

## Источники задач

| Макрозадачи | Микрозадачи |
| --- | --- |
| `setTimeout`, `setInterval` | `Promise.then`, `catch`, `finally` |
| события: `click`, `input`, `load` | продолжение после `await` |
| `postMessage`, `MessageChannel` | `queueMicrotask(fn)` |
| сетевые колбэки, I/O | `MutationObserver` |
| `setImmediate` (Node.js) | `process.nextTick` (Node.js, своя очередь — еще раньше) |

## Классическая задача

```javascript
console.log("1");

setTimeout(() => console.log("2"), 0);

Promise.resolve()
  .then(() => console.log("3"))
  .then(() => console.log("4"));

queueMicrotask(() => console.log("5"));

console.log("6");

// 1, 6, 3, 5, 4, 2
```

Почему: синхронно `1` и `6`; затем микрозадачи в порядке постановки — `3` и `5`; `then` после `3` поставил новую микрозадачу `4` — она выполнится в этом же сбросе очереди; только потом макрозадача таймера — `2`.

## Микрозадача промиса

Колбэк `then` не выполняется сразу, даже если промис уже выполнен: он ставится в очередь микрозадач.

```javascript
const p = Promise.resolve("готово");
p.then(console.log);
console.log("после then");
// "после then", затем "готово"
```

С `await` то же самое: всё, что идет после `await`, — продолжение, которое выполнится как микрозадача.

```javascript
async function run() {
  console.log("A");
  await undefined;
  console.log("C");
}
run();
console.log("B");
// A, B, C
```

## Микрозадачи внутри макрозадач

```javascript
setTimeout(() => {
  console.log("timeout 1");
  Promise.resolve().then(() => console.log("micro inside timeout"));
}, 0);

setTimeout(() => console.log("timeout 2"), 0);

// timeout 1, micro inside timeout, timeout 2
```

## Сравнение

| | Микрозадачи | Макрозадачи |
| --- | --- | --- |
| Приоритет | выше | ниже |
| Выполнение | все подряд до опустошения | по одной за оборот |
| Рендер между ними | нет | возможен |
| Риск | бесконечная цепочка заблокирует рендер | долгая задача тоже блокирует |
| Типичный способ | `Promise`, `queueMicrotask` | `setTimeout`, события |

## Что важно помнить

- Рекурсивное добавление микрозадач (`function loop() { queueMicrotask(loop) }`) «подвешивает» страницу: event loop никогда не дойдет до рендера и таймеров.
- `setTimeout(fn, 0)` — способ отложить работу до следующей макрозадачи и дать браузеру отрисовать кадр.
- `queueMicrotask` полезен, чтобы выполнить код сразу после текущей синхронной работы, но до рендера — например, сгруппировать обновления.
- В Node.js порядок: `process.nextTick` → промисы → фазы event loop (timers, poll, check).

## Мини-шпаргалка

- Микрозадачи: `then`, `await`, `queueMicrotask`, `MutationObserver`.
- Макрозадачи: таймеры, события, `postMessage`, I/O.
- После каждой макрозадачи — все микрозадачи.
- Колбэк `then` всегда асинхронный, даже для выполненного промиса.
- `sync → micro → macro → micro → ...`.
