# Что такое Promise и его состояния

> [!NOTE]
> **Promise** — объект, представляющий результат асинхронной операции, который будет известен позже. У промиса три состояния: `pending` (ожидание), `fulfilled` (выполнен успешно) и `rejected` (отклонен с ошибкой). Промис **«выполнен» (settled)**, когда он перешел из `pending` в `fulfilled` или `rejected`; после этого его состояние больше не меняется. `resolve(value)` переводит промис в `fulfilled`, `reject(reason)` — в `rejected`.

## Вопрос

Что такое Promise? Какие состояния у промиса и когда он считается выполненным? Чем `resolve` отличается от `reject`?

## Создание

```javascript
const delay = (ms) =>
  new Promise((resolve) => {
    setTimeout(resolve, ms);
  });

const loadImage = (src) =>
  new Promise((resolve, reject) => {
    const img = new Image();
    img.onload = () => resolve(img);
    img.onerror = () => reject(new Error(`Не удалось загрузить ${src}`));
    img.src = src;
  });
```

Функция-исполнитель (executor) вызывается **синхронно**, сразу при создании промиса.

## Состояния

```text
              resolve(value)
pending ───────────────────────► fulfilled (value)
   │
   └──────────────────────────► rejected (reason)
              reject(error) или throw
```

| Состояние | Значение | Когда |
| --- | --- | --- |
| `pending` | — | операция еще идет |
| `fulfilled` | результат | вызван `resolve` |
| `rejected` | причина (обычно `Error`) | вызван `reject` или брошена ошибка в executor |

**Settled** — общее название для `fulfilled` и `rejected`. Термин **resolved** означает «судьба промиса решена»: промис мог быть разрешен другим промисом и всё еще ждать его.

## Неизменность

```javascript
new Promise((resolve, reject) => {
  resolve("первый");
  resolve("второй");   // игнорируется
  reject(new Error()); // игнорируется
});
```

После перехода в settled состояние повторные вызовы ничего не делают.

## resolve и reject

| | `resolve(value)` | `reject(reason)` |
| --- | --- | --- |
| Состояние | `fulfilled` (или «перенимает» состояние промиса-аргумента) | `rejected` |
| Обработчик | `then(onFulfilled)` | `catch`, `then(_, onRejected)` |
| Аргумент | любое значение или промис | обычно `Error` |

```javascript
const outer = new Promise((resolve) => resolve(Promise.reject(new Error("внутри"))));
outer.catch((e) => console.log(e.message)); // "внутри" — resolve с отклоненным промисом
```

## Готовые промисы

```javascript
Promise.resolve(42);          // уже fulfilled
Promise.reject(new Error());  // уже rejected
const { promise, resolve, reject } = Promise.withResolvers(); // ES2024
```

## Что важно помнить

- Ошибка, брошенная внутри executor, автоматически отклоняет промис.
- Асинхронная ошибка внутри executor (в `setTimeout`) **не** отклонит промис — вызывайте `reject` явно.
- Отклоненный промис без обработчика вызывает `unhandledrejection`.
- Узнать состояние промиса синхронно нельзя — только через обработчики (в DevTools оно видно).
- Промис не отменяется: отмену делают через `AbortController`.

## Мини-шпаргалка

- Promise — будущий результат асинхронной операции.
- Состояния: `pending` → `fulfilled` | `rejected`.
- Settled — завершен, состояние больше не меняется.
- `resolve` — успех, `reject` — ошибка.
- Executor выполняется синхронно.
