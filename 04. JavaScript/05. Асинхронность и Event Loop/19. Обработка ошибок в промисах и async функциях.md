# Обработка ошибок в промисах и async-функциях

> [!NOTE]
> Ошибка внутри промиса переводит его в состояние `rejected`. В цепочке промисов ее ловит ближайший `.catch()`, в async-функции — обычный `try...catch` вокруг `await`. Отклоненный промис без обработчика — **необработанное отклонение**: в браузере событие `unhandledrejection`, в Node.js по умолчанию завершение процесса. Внешний `try...catch` не ловит ошибки промисов без `await`.

## Вопрос

Как обрабатывать ошибки в промисах? Что делает `catch()` в промисах? Как работают ошибки в async-функциях и что будет, если их не обработать?

## catch в цепочке

```javascript
fetch("/api/user")
  .then((res) => {
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return res.json();
  })
  .then(render)
  .catch((error) => {
    showError(error.message);
    return null; // цепочка восстановлена
  });
```

`catch(fn)` — это `then(undefined, fn)`. Он ловит ошибки всех предыдущих шагов: и `reject`, и `throw` в обработчиках.

## try...catch в async-функциях

```javascript
async function loadProfile(id) {
  try {
    const res = await fetch(`/api/users/${id}`);
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return await res.json();
  } catch (error) {
    logError(error);
    throw new Error("Профиль недоступен", { cause: error });
  } finally {
    hideSpinner();
  }
}
```

Ошибка, брошенная в async-функции, превращается в отклоненный промис — вызывающий код обработает ее через `await` в `try` или `.catch()`.

## Где try...catch не помогает

```javascript
try {
  fetchData(); // промис отклонится позже — try уже закончился
} catch (e) {
  // не сработает
}

try {
  setTimeout(() => { throw new Error("в таймере"); });
} catch (e) {
  // не сработает — колбэк выполнится в другой задаче
}

async function process(items) {
  try {
    items.forEach(async (item) => await save(item)); // ошибки в колбэках не дойдут до catch
  } catch (e) {}
}
```

Решения: `await fetchData()` внутри `try`, `.catch()` на промисе, `for...of` с `await` или `await Promise.all(items.map(save))`.

## return await внутри try

```javascript
async function getData() {
  try {
    return fetchData();        // ошибка НЕ попадет в catch этой функции
  } catch (e) {}
}

async function getDataSafe() {
  try {
    return await fetchData();  // ошибка попадет в catch
  } catch (e) {}
}
```

## Необработанные отклонения

```javascript
window.addEventListener("unhandledrejection", (event) => {
  reportToSentry(event.reason);
  event.preventDefault(); // убрать стандартное сообщение в консоли
});
```

```javascript
// Node.js
process.on("unhandledRejection", (reason) => {
  logger.error(reason);
  process.exit(1);
});
```

## Паттерн «результат или ошибка»

```javascript
async function to(promise) {
  try {
    return [null, await promise];
  } catch (error) {
    return [error, null];
  }
}

const [error, user] = await to(fetchUser(id));
if (error) return showError(error);
```

Позволяет избежать вложенных `try` для нескольких независимых шагов.

## Что важно помнить

- `fetch` не отклоняет промис на 404 и 500 — проверяйте `response.ok` и бросайте ошибку сами.
- Обработчик `catch`, который ничего не возвращает, превращает ошибку в успешный `undefined` — дальнейшие `then` выполнятся.
- В React ошибки асинхронного кода не ловит Error Boundary — обрабатывайте их в state или пробрасывайте через `use` / Suspense-библиотеки.
- Отмена через `AbortController` дает `AbortError` — отличайте ее от настоящих ошибок.

## Мини-шпаргалка

- Промисы: `.catch()` в конце цепочки.
- Async: `try...catch` вокруг `await`.
- Без `await` внешний `try` не ловит ошибку промиса.
- `return await` в `try`, чтобы поймать ошибку.
- Необработанные — `unhandledrejection`.
