# setTimeout и setInterval: как работают таймеры

> [!NOTE]
> `setTimeout(fn, delay, ...args)` планирует однократный вызов функции не раньше чем через `delay` мс и возвращает числовой идентификатор (в Node.js — объект `Timeout`), по которому таймер отменяют через `clearTimeout`. `setInterval` вызывает функцию повторно с интервалом до `clearInterval`. Задержка — **минимальная**, а не точная: колбэк выполнится, когда истечет время и освободится стек. `setTimeout(fn, 0)` откладывает выполнение до следующей макрозадачи — после текущего кода и всех микрозадач.

## Вопрос

Что делает и возвращает `setTimeout()`? Что делает `setInterval()`? Зачем нужен `setTimeout(fn, 0)`, есть ли гарантия точного выполнения таймера и как работают вложенные таймеры?

## setTimeout

```javascript
const id = setTimeout((name) => {
  console.log(`Привет, ${name}`);
}, 1000, "Анна");

clearTimeout(id); // отменить, если еще не выполнился
```

- возвращает идентификатор таймера (число больше 0 в браузере);
- лишние аргументы передаются в колбэк;
- передавайте функцию, а не строку: `setTimeout("code()")` работает как `eval`.

## setInterval

```javascript
let seconds = 0;
const timerId = setInterval(() => {
  seconds++;
  if (seconds === 5) clearInterval(timerId);
}, 1000);
```

Если колбэк выполняется дольше интервала или поток занят, вызовы не накапливаются бесконечно, но интервал между ними плавает. Для точных повторов используют **рекурсивный setTimeout**:

```javascript
function poll() {
  fetch("/api/status")
    .then((r) => r.json())
    .then(render)
    .finally(() => {
      setTimeout(poll, 5000); // следующий запрос — только после завершения текущего
    });
}
poll();
```

| | `setInterval` | рекурсивный `setTimeout` |
| --- | --- | --- |
| Интервал | между стартами | между окончанием и следующим стартом |
| Наложение долгих операций | возможно | нет |
| Изменить задержку на ходу | нельзя | можно (backoff) |

## setTimeout(fn, 0)

```javascript
console.log("1");
setTimeout(() => console.log("3"), 0);
Promise.resolve().then(() => console.log("2"));
console.log("1.5");
// 1, 1.5, 2, 3
```

Колбэк не выполнится «сразу»: он попадет в очередь макрозадач и выполнится после всего синхронного кода и всех микрозадач. Применения:

- дать браузеру отрисовать изменения перед следующей частью работы;
- разбить долгую задачу на части;
- выполнить код после того, как текущий обработчик события завершится.

## Нет гарантии точного выполнения

Таймер гарантирует только **минимальную** задержку. Колбэк может выполниться позже, если:

- стек занят синхронным кодом или другими задачами;
- вкладка в фоне — браузер ограничивает таймеры до раза в секунду (и реже при долгом бездействии);
- устройство экономит энергию;
- задержка больше `2^31 - 1` мс (~24,8 дня) — тогда она переполняется и таймер срабатывает сразу.

```javascript
const start = performance.now();
setTimeout(() => console.log(performance.now() - start), 100); // 100+ мс, иногда заметно больше
```

## Вложенные таймеры

```javascript
let start = performance.now();
let level = 0;
function nested() {
  console.log(level, Math.round(performance.now() - start));
  if (++level < 10) setTimeout(nested, 0);
}
setTimeout(nested, 0);
```

По спецификации HTML после 5 уровней вложенности минимальная задержка становится **4 мс**, даже если указан 0. Это защита от «бесконечного» опроса, нагружающего процессор.

## Что важно помнить

- В React таймеры в `useEffect` нужно очищать в cleanup-функции, иначе после размонтирования будут ошибки и утечки.
- Колбэк таймера, переданный как метод объекта, теряет `this` — используйте стрелку.
- Для анимаций используйте `requestAnimationFrame`, а не `setInterval(fn, 16)`.
- Fake timers в тестах (`vi.useFakeTimers()`) позволяют проверять таймеры без реального ожидания.
- В Node.js есть `timers/promises`: `await setTimeout(1000)`.

## Мини-шпаргалка

- `setTimeout` — один раз, `setInterval` — повторно; отмена — `clearTimeout`/`clearInterval`.
- Возвращают идентификатор.
- Задержка минимальная, не точная.
- `setTimeout(fn, 0)` — следующая макрозадача, после микрозадач.
- Вложенные таймеры после 5 уровней — минимум 4 мс; фоновые вкладки — ~1 с.
