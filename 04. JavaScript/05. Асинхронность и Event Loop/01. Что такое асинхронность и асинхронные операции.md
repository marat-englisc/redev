# Что такое асинхронность и асинхронные операции?

> [!NOTE]
> **Асинхронность** — способ выполнять долгие операции (сеть, таймеры, файлы, ожидание пользователя) без блокировки основного потока. Синхронный код выполняется строка за строкой, и следующая ждет предыдущую. Асинхронная операция запускается, а ее результат обрабатывается позже — колбэком, промисом или `await`, когда event loop возьмет готовую задачу из очереди.

## Вопрос

Что такое асинхронность в JavaScript? Чем синхронный код отличается от асинхронного? Какие бывают асинхронные операции?

## Синхронный и асинхронный код

```javascript
console.log("1");
console.log("2");
console.log("3");
// 1, 2, 3 — строго по порядку
```

```javascript
console.log("1");
setTimeout(() => console.log("2"), 0);
console.log("3");
// 1, 3, 2 — колбэк таймера выполнится позже
```

| | Синхронный | Асинхронный |
| --- | --- | --- |
| Порядок | строго сверху вниз | результат приходит позже |
| Ожидание | блокирует поток | поток свободен |
| Результат | сразу | через колбэк, Promise, `await` |
| Примеры | вычисления, `JSON.parse` | `fetch`, `setTimeout`, события |

## Зачем нужна асинхронность

JavaScript в браузере выполняется в одном основном потоке, который также отвечает за отрисовку и реакцию на ввод. Если ждать ответ сервера синхронно, страница «замерзнет» на всё время запроса. Асинхронная модель позволяет запустить операцию, отдать ее среде (браузеру или Node.js) и продолжить работу.

```text
JS: fetch(url) ──► Web API выполняет запрос в сети
JS продолжает выполнять код, рендер работает
ответ готов ──► задача в очереди ──► event loop ──► колбэк / then / продолжение await
```

## Типы асинхронных операций

| Тип | Примеры |
| --- | --- |
| Таймеры | `setTimeout`, `setInterval`, `requestAnimationFrame`, `requestIdleCallback` |
| Сеть | `fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource` |
| События пользователя | `click`, `input`, `scroll`, `keydown` |
| Ввод-вывод | `FileReader`, IndexedDB, в Node.js — `fs`, `net` |
| Микрозадачи | `Promise.then`, `queueMicrotask`, `MutationObserver` |
| Наблюдатели | `IntersectionObserver`, `ResizeObserver` |
| Потоки | Web Workers и `postMessage` |
| Медиа и железо | геолокация, камера, Clipboard API |

## Способы работы с асинхронностью

```javascript
// колбэк
setTimeout(() => console.log("готово"), 1000);

// Promise
fetch("/api/user").then((r) => r.json()).then(render);

// async/await
const user = await fetch("/api/user").then((r) => r.json());

// события
button.addEventListener("click", handleClick);
```

## Что важно помнить

- Асинхронность — не параллельность: JS-код по-прежнему выполняется в одном потоке, параллельно работает только среда (сеть, таймеры, ОС).
- Тяжелые вычисления асинхронность не ускоряет — их выносят в Web Worker.
- Ошибки асинхронного кода не ловятся внешним `try...catch` вокруг запуска — только через `catch`, `try` внутри `async` или колбэк ошибки.
- Порядок выполнения асинхронных задач определяется event loop: микрозадачи раньше макрозадач.

## Мини-шпаргалка

- Асинхронность — не блокировать поток долгими операциями.
- Синхронный код — по порядку, асинхронный — результат позже.
- Операции: таймеры, сеть, события, I/O, промисы, воркеры.
- Обработка: колбэки → промисы → `async/await`.
- Асинхронность ≠ многопоточность.
