# Что делает requestAnimationFrame()?

> [!NOTE]
> `requestAnimationFrame()` планирует callback перед следующей перерисовкой браузера и подходит для анимаций.

## Вопрос

Почему для анимаций лучше использовать `requestAnimationFrame()`, а не `setInterval()`? Где rAF находится в цикле event loop?

## Определение

`requestAnimationFrame(callback)` просит браузер вызвать callback перед следующим кадром отрисовки. Браузер сам выбирает подходящий момент, синхронизированный с частотой экрана.

Метод возвращает id, который можно передать в `cancelAnimationFrame()`.

## Пример

```javascript
let x = 0;

function animate() {
  x += 2;
  element.style.transform = `translateX(${x}px)`;

  requestAnimationFrame(animate);
}

requestAnimationFrame(animate);
```

Callback вызывается перед каждым новым кадром.

## Аргумент timestamp

```javascript
function step(timestamp) {
  console.log(timestamp);

  requestAnimationFrame(step);
}

requestAnimationFrame(step);
```

`timestamp` - время текущего кадра. Его используют, чтобы считать движение по времени, а не по количеству кадров.

## Отмена

```javascript
const id = requestAnimationFrame(() => {
  console.log('frame');
});

cancelAnimationFrame(id);
```

## Место rAF в event loop

```text
макрозадача (клик, таймер, сообщение)
  → все микрозадачи (Promise, queueMicrotask)
  → [если пришло время кадра] шаг рендеринга:
       колбэки requestAnimationFrame (+ микрозадачи после каждого)
       → style → layout → paint → composite
  → следующая макрозадача
```

- rAF — **не макрозадача и не микрозадача**: у него своя очередь, которая выполняется на шаге рендеринга.
- Шаг рендеринга бывает не после каждой макрозадачи, а примерно раз в кадр (≈16,7 мс при 60 Гц). Если между кадрами выполнилось несколько таймеров, rAF вызовется один раз.
- Колбэки, добавленные **внутри** rAF, выполнятся только в следующем кадре — поэтому рекурсивный `requestAnimationFrame(animate)` не зависает.
- Если изменить стиль в rAF и сразу прочитать `offsetHeight`, браузер выполнит layout синхронно (forced reflow). Сначала читайте, потом пишите.

```javascript
setTimeout(() => console.log("timeout"), 0);
requestAnimationFrame(() => console.log("rAF"));
Promise.resolve().then(() => console.log("microtask"));
console.log("sync");
// sync → microtask → затем timeout и rAF; их взаимный порядок не гарантирован,
// он зависит от того, когда наступит кадр
```

## Отличие от таймеров

| Метод | Для чего |
| --- | --- |
| `setTimeout` | выполнить позже |
| `setInterval` | повторять по времени |
| `requestAnimationFrame` | обновлять UI перед кадром |

## Что важно помнить

- Колбэк rAF вызывается перед отрисовкой следующего кадра и получает `DOMHighResTimeStamp`.
- rAF не вызывается в фоновых вкладках — анимации сами ставятся на паузу.
- Скорость анимации считайте по времени (`timestamp`), а не по количеству кадров: частота экрана бывает 60, 120 и 144 Гц.
- Отмена — `cancelAnimationFrame(id)`; для CSS-анимаций rAF не нужен.

## Мини-шпаргалка

```javascript
const id = requestAnimationFrame(callback);
cancelAnimationFrame(id);
```
