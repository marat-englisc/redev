# async и await

> [!NOTE]
> `async` перед функцией делает так, что она **всегда возвращает Promise**: результат `return` оборачивается в `Promise.resolve`, а брошенная ошибка — в `Promise.reject`. `await` приостанавливает выполнение **только текущей async-функции**, пока промис не выполнится, и возвращает его результат (или бросает ошибку). Остальной код и event loop в это время продолжают работать. Продолжение после `await` выполняется как микрозадача.

## Вопрос

Что делают ключевые слова `async` и `await`? Что возвращает async-функция? Блокирует ли `await` выполнение? Можно ли использовать `await` в стрелочных функциях?

## async

```javascript
async function getAnswer() {
  return 42;
}

getAnswer();                    // Promise {<fulfilled>: 42}
getAnswer().then(console.log);  // 42

async function fail() {
  throw new Error("Сбой");
}
fail().catch((e) => console.log(e.message)); // "Сбой"
```

Если вернуть промис, async-функция «примет» его состояние.

## await

```javascript
async function loadUser(id) {
  const response = await fetch(`/api/users/${id}`);
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  const user = await response.json();
  return user;
}
```

`await` можно ставить перед любым значением: не-промис просто вернется (`await 5` → `5`), но продолжение всё равно станет микрозадачей.

## await не блокирует поток

```javascript
async function task() {
  console.log("1. начало task");
  await null;
  console.log("4. после await");
}

console.log("0. sync");
task();
console.log("2. task вернула промис");
Promise.resolve().then(() => console.log("3. другая микрозадача"));

// 0. sync
// 1. начало task
// 2. task вернула промис
// 3. другая микрозадача
// 4. после await
```

Функция «засыпает» на `await`, управление возвращается вызывающему коду, а продолжение ставится в очередь микрозадач, когда промис выполнится. Блокируется только сама async-функция — не браузер и не event loop.

## Последовательно и параллельно

```javascript
// последовательно: ~2 секунды
const user = await getUser();
const posts = await getPosts();

// параллельно: ~1 секунда
const [user2, posts2] = await Promise.all([getUser(), getPosts()]);

// запустить сразу, дождаться позже
const userPromise = getUser();
const settings = await getSettings();
const user3 = await userPromise;
```

## await и стрелочные функции

```javascript
const load = async () => {
  const data = await fetchData();
  return data;
};

button.addEventListener("click", async () => {
  await save();
});

// await внутри обычного колбэка — SyntaxError
items.forEach((item) => {
  await process(item); // нельзя: колбэк не async
});

// forEach с async-колбэком не ждет результатов
items.forEach(async (item) => await process(item)); // все запустятся, но forEach не дождется

for (const item of items) await process(item);      // последовательно
await Promise.all(items.map(process));              // параллельно
```

## Top-level await

В ES-модулях `await` можно писать на верхнем уровне:

```javascript
// config.js (type="module")
const config = await fetch("/config.json").then((r) => r.json());
export default config;
```

Модули, импортирующие этот, дождутся его загрузки.

## Что важно помнить

- `async`-функцию без `await` или `.catch` легко оставить с необработанной ошибкой — `unhandledrejection`.
- `return await promise` внутри `try` нужен, чтобы `catch` поймал ошибку; вне `try` можно просто `return promise`.
- `useEffect` в React не может быть `async` напрямую — объявите async-функцию внутри и вызовите ее.
- Конструкторы классов и геттеры не бывают `async`.
- Для асинхронной итерации — `for await...of`.

## Мини-шпаргалка

- `async` → функция всегда возвращает Promise.
- `await` ждет промис и возвращает результат, ошибку бросает.
- Блокируется только текущая async-функция.
- Независимые операции — `Promise.all`.
- Стрелка может быть `async`; `await` в обычном колбэке — ошибка, `forEach` не ждет.
