# Что произойдёт, если не поставить await?

> [!NOTE]
> Если не поставить `await`, вы получите сам `Promise`, а не его итоговое значение.

## Вопрос

Что будет, если вызвать async-функцию без `await`?

## Определение

Async-функции и многие асинхронные API возвращают промисы. Без `await` код не ждет завершения операции и сразу продолжает выполнение.

Это нормально, если вам действительно нужно запустить задачу в фоне. Но часто это приводит к ошибкам: попытке работать с промисом как с готовыми данными.

## Пример ошибки

```javascript
async function getUser() {
  return { name: 'Ann' };
}

const user = getUser();

console.log(user.name); // undefined
```

`user` - это `Promise`, поэтому у него нет свойства `name`.

## Правильно

```javascript
const user = await getUser();

console.log(user.name); // 'Ann'
```

## Ошибка может стать необработанной

```javascript
async function fail() {
  throw new Error('Broken');
}

fail(); // промис отклонится, но здесь нет обработки
```

Если не поставить `await` и не добавить `.catch()`, ошибка может стать unhandled rejection.

## Когда await можно не ставить

```javascript
sendAnalytics().catch(console.error);
```

Иногда задачу запускают в фоне. В таком случае ошибку все равно стоит обработать.

## Что важно помнить

- Без `await` вы получаете промис вместо значения: `if (await isValid())` и `if (isValid())` ведут себя по-разному — промис всегда truthy.
- Ошибка такого промиса не попадет в окружающий `try...catch`.
- Иногда отсутствие `await` намеренно (fire-and-forget) — тогда явно обработайте ошибку `.catch()`.
- Правило `@typescript-eslint/no-floating-promises` находит забытые `await`.

## Мини-шпаргалка

```javascript
const promise = getData();      // Promise
const data = await getData();   // result
getData().catch(handleError);   // fire-and-handle
```
