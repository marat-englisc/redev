# Отмена промисов: AbortController и AbortSignal

> [!NOTE]
> Промис нельзя отменить: он лишь представляет результат уже запущенной операции. Отменяют **саму операцию** через `AbortController`: его `signal` передают в `fetch`, `addEventListener` и собственные функции, а вызов `controller.abort()` прерывает их — `fetch` отклоняется с `DOMException` с именем `AbortError`. Для таймаутов есть `AbortSignal.timeout(ms)`, для объединения сигналов — `AbortSignal.any([...])`.

## Вопрос

Можно ли отменить выполнение промиса? Что делают `AbortController` и `AbortSignal` и как ими пользоваться?

## Почему промис не отменяется

```javascript
const p = fetch("/api/report");
// у p нет метода cancel — промис только «ждет» результат
```

Даже если результат больше не нужен (пользователь ушел со страницы, ввел новый запрос), операция продолжится. Можно проигнорировать результат флагом, но запрос всё равно потратит трафик.

## AbortController

```javascript
const controller = new AbortController();

fetch("/api/search?q=чайник", { signal: controller.signal })
  .then((r) => r.json())
  .then(render)
  .catch((error) => {
    if (error.name === "AbortError") return; // отмена — не ошибка для пользователя
    showError(error);
  });

controller.abort(); // запрос прерван
```

- `controller.signal` — объект `AbortSignal`, который передают в операцию;
- `controller.abort(reason?)` — отменить, `signal.aborted` станет `true`, `signal.reason` — причина;
- один сигнал можно передать в несколько операций и отменить их разом;
- контроллер одноразовый: после `abort` нужен новый.

## Типичные сценарии

```javascript
// поиск: отменять предыдущий запрос при новом вводе
let current;
input.addEventListener("input", async (event) => {
  current?.abort();
  current = new AbortController();
  try {
    const res = await fetch(`/api/search?q=${encodeURIComponent(event.target.value)}`, {
      signal: current.signal,
    });
    render(await res.json());
  } catch (error) {
    if (error.name !== "AbortError") throw error;
  }
});

// React: отмена при размонтировании
useEffect(() => {
  const controller = new AbortController();
  fetch(`/api/users/${id}`, { signal: controller.signal })
    .then((r) => r.json())
    .then(setUser)
    .catch((e) => e.name !== "AbortError" && setError(e));
  return () => controller.abort();
}, [id]);

// таймаут
await fetch("/api/slow", { signal: AbortSignal.timeout(5000) }); // TimeoutError через 5 с

// таймаут ИЛИ ручная отмена
const signal = AbortSignal.any([controller.signal, AbortSignal.timeout(5000)]);

// удаление нескольких обработчиков одним вызовом
window.addEventListener("resize", onResize, { signal: controller.signal });
window.addEventListener("scroll", onScroll, { signal: controller.signal });
controller.abort(); // оба обработчика удалены
```

## Поддержка сигнала в своей функции

```javascript
function delay(ms, { signal } = {}) {
  return new Promise((resolve, reject) => {
    if (signal?.aborted) return reject(signal.reason);

    const id = setTimeout(resolve, ms);
    signal?.addEventListener("abort", () => {
      clearTimeout(id);
      reject(signal.reason);
    }, { once: true });
  });
}
```

## Что важно помнить

- Отмена запроса не гарантирует, что сервер не выполнил операцию: для `POST` отмена на клиенте не откатывает изменения на сервере.
- `AbortSignal.timeout` отклоняет с `TimeoutError`, а не `AbortError` — проверяйте оба имени.
- TanStack Query и axios поддерживают `signal` и отменяют запросы автоматически.
- В Node.js `AbortController` поддерживают `fetch`, `fs`, `timers/promises`, `child_process`.

## Мини-шпаргалка

- Промис не отменяется — отменяется операция.
- `const c = new AbortController()`, `fetch(url, { signal: c.signal })`, `c.abort()`.
- Отмена → `AbortError`, не показывать пользователю.
- `AbortSignal.timeout(ms)` — таймаут, `AbortSignal.any()` — объединение.
- Сигнал в `addEventListener` удаляет обработчики.
