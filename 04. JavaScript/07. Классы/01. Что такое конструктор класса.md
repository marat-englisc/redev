# Конструктор класса

> [!NOTE]
> `constructor` — специальный метод класса, который вызывается при `new` и инициализирует экземпляр. Он необязателен: без него используется пустой конструктор (а в наследнике — конструктор, вызывающий `super(...args)`). В классе может быть только **один** `constructor`; «несколько конструкторов» имитируют параметрами по умолчанию или статическими фабричными методами. `return` объекта из конструктора заменяет экземпляр, `return` примитива игнорируется.

## Вопрос

Что такое конструктор класса? Можно ли не определять конструктор? Может ли быть несколько конструкторов и что делает `return` внутри конструктора?

## Базовый пример

```javascript
class User {
  constructor(name, role = "user") {
    this.name = name;
    this.role = role;
    this.createdAt = new Date();
  }
}

const anna = new User("Анна");       // { name: "Анна", role: "user", createdAt: ... }
User("Анна");                         // TypeError: Class constructor cannot be invoked without 'new'
```

При `new User(...)`:

1. создается пустой объект с прототипом `User.prototype`;
2. инициализируются поля класса;
3. выполняется `constructor` с `this`, указывающим на новый объект;
4. объект возвращается.

## Можно ли не определять

```javascript
class Point {
  x = 0;
  y = 0;
}
new Point(); // { x: 0, y: 0 }

class Admin extends User {}
new Admin("Мария"); // автоматически: constructor(...args) { super(...args) }
```

Если инициализация сводится к значениям по умолчанию, хватает полей класса.

## Несколько конструкторов

В JavaScript перегрузки нет: второй `constructor` — `SyntaxError`. Варианты:

```javascript
class Money {
  constructor(amount, currency = "RUB") {
    this.amount = amount;
    this.currency = currency;
  }

  static fromString(text) {           // фабричный метод
    const [amount, currency] = text.split(" ");
    return new Money(Number(amount), currency);
  }

  static zero() {
    return new Money(0);
  }
}

Money.fromString("1500 USD");
Money.zero();
```

Можно также принимать объект настроек: `new Request({ url, method = "GET", headers = {} })`.

## return в конструкторе

```javascript
class A {
  constructor() {
    this.x = 1;
    return { custom: true };   // вернется этот объект вместо экземпляра
  }
}
new A();               // { custom: true }
new A() instanceof A;  // false

class B {
  constructor() {
    this.x = 1;
    return 42;             // примитив игнорируется
  }
}
new B();               // { x: 1 }
```

Возвращать объект из конструктора стоит только в особых случаях (например, кеширование экземпляров — синглтон). В наследнике `return` примитива, кроме `undefined`, — `TypeError`.

## В наследнике

```javascript
class Admin extends User {
  constructor(name, permissions) {
    super(name, "admin");          // обязательно до обращения к this
    this.permissions = permissions;
  }
}
```

## Что важно помнить

- Асинхронного конструктора нет — для асинхронной инициализации используйте `static async create()`.
- Тяжелую логику и побочные эффекты (запросы, подписки) в конструкторе лучше избегать: усложняет тестирование.
- `new.target` внутри конструктора указывает на класс, который вызвали через `new` — так делают «абстрактные» классы.
- Методы, объявленные в теле класса, не копируются в каждый экземпляр, а поля и свойства из `constructor` — копируются.

## Мини-шпаргалка

- `constructor` вызывается при `new` и инициализирует `this`.
- Необязателен: по умолчанию пустой или с `super(...args)`.
- Только один — вместо перегрузки статические фабрики.
- `return` объекта заменяет экземпляр, примитив игнорируется.
- В наследнике сначала `super()`, потом `this`.
