# extends и super

> [!NOTE]
> `extends` создает класс-наследник: его прототип наследует прототип родителя, а сам класс — статические свойства родителя. `super(...)` в конструкторе наследника вызывает конструктор родителя и **обязателен до первого обращения к `this`**. `super.method()` вызывает метод родителя из переопределенного метода. Наследоваться можно и от встроенных классов (`Error`, `Array`, `HTMLElement`).

## Вопрос

Что делает ключевое слово `extends`? Что делает `super()` и почему его нужно вызывать до `this`?

## extends

```javascript
class Animal {
  constructor(name) {
    this.name = name;
  }
  speak() {
    return `${this.name} издает звук`;
  }
  static create(name) {
    return new this(name);
  }
}

class Dog extends Animal {
  speak() {
    return `${this.name} лает`;   // переопределение метода
  }
}

const rex = new Dog("Рекс");
rex.speak();              // "Рекс лает"
rex instanceof Animal;    // true
Dog.create("Шарик");      // статический метод унаследован, вернет Dog
```

Цепочки:

```text
rex → Dog.prototype → Animal.prototype → Object.prototype → null
Dog → Animal → Function.prototype
```

## super() в конструкторе

```javascript
class Admin extends User {
  constructor(name, permissions) {
    // this.permissions = permissions; — ReferenceError: Must call super constructor
    super(name, "admin");
    this.permissions = permissions;
  }
}
```

Почему до `this`: в наследнике объект создает **родительский** конструктор. Пока `super()` не вызван, `this` не существует. Это гарантирует, что родитель инициализирует свою часть объекта первым.

Если конструктор в наследнике не объявлен, он создается автоматически: `constructor(...args) { super(...args); }`.

## super.method()

```javascript
class Logger {
  log(message) {
    console.log(`[LOG] ${message}`);
  }
}

class TimestampLogger extends Logger {
  log(message) {
    super.log(`${new Date().toISOString()} ${message}`); // расширяем, а не заменяем
  }
}
```

`super` работает в методах и в статических методах (`super.create()`), но не в стрелочных полях класса и не в обычных функциях.

## Наследование от встроенных классов

```javascript
class ValidationError extends Error {
  constructor(message, field) {
    super(message);
    this.name = "ValidationError";
    this.field = field;
  }
}

class Stack extends Array {
  peek() { return this.at(-1); }
}

class UserCard extends HTMLElement {
  connectedCallback() { this.textContent = "Привет"; }
}
```

## Поля и порядок инициализации

```javascript
class Base {
  greeting = "base";
  constructor() {
    console.log(this.greeting); // "base" — поля наследника еще не созданы
  }
}

class Child extends Base {
  greeting = "child";
}

new Child(); // выведет "base"
```

Поля наследника инициализируются после возврата из `super()`.

## Что важно помнить

- JavaScript поддерживает только одиночное наследование; несколько поведений комбинируют миксинами или композицией.
- Глубокие иерархии классов трудно поддерживать — часто лучше композиция («has-a» вместо «is-a»).
- `extends null` возможен, но почти бесполезен.
- В TypeScript `override` помечает переопределенные методы и помогает ловить опечатки.

## Мини-шпаргалка

- `class B extends A` — B наследует методы и статику A.
- `super(...)` — конструктор родителя, обязательно до `this`.
- `super.method()` — метод родителя.
- Конструктор по умолчанию передает все аргументы в `super`.
- Можно наследоваться от `Error`, `Array`, `HTMLElement`.
