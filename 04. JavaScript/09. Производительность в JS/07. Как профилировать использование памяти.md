# Как профилировать использование памяти?

> [!NOTE]
> Память профилируют через DevTools: heap snapshots, allocation timeline и поиск объектов, которые не освобождаются после сценария.

## Вопрос

Как найти утечку памяти в JavaScript-приложении?

## Основная идея

Нужно не просто посмотреть, что память выросла, а понять, какие объекты удерживаются и почему Garbage Collector не может их удалить.

## Heap snapshot

Heap snapshot показывает снимок объектов в памяти.

Типичный сценарий:

1. Открыть DevTools.
2. Перейти во вкладку Memory.
3. Сделать первый heap snapshot.
4. Выполнить сценарий: открыть/закрыть модалку, перейти по роуту.
5. Запустить GC, если DevTools дает такую кнопку.
6. Сделать второй snapshot.
7. Сравнить, какие объекты остались.

## Что искать

- detached DOM nodes;
- растущие массивы и кэши;
- listeners, которые не снялись;
- замыкания с большими объектами;
- подписки, которые не отписались.

## Allocation timeline

Allocation timeline помогает увидеть, когда именно создавались объекты и освобождаются ли они после завершения сценария.

## Пример подозрительного кода

```javascript
const cache = [];

function mountPage(data) {
  cache.push(data);
}
```

Если `cache` не ограничен и не очищается, snapshots покажут рост памяти.

## Практический цикл

```text
snapshot -> perform action -> cleanup -> GC -> snapshot -> compare
```

## Что важно помнить

- Heap snapshot показывает объекты и пути удержания (Retainers) — ключ к поиску утечек.
- Allocation timeline показывает, где выделяется память во время сценария.
- Сравнивайте снимки до и после повторяемого действия, после принудительной сборки мусора.
- Ищите Detached DOM-узлы и растущие массивы и Map.

## Мини-шпаргалка

```text
Memory tab:
Heap snapshot -> compare snapshots -> inspect retaining path
```
