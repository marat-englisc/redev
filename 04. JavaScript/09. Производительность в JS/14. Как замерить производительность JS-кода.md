# Как замерить производительность JS-кода?

> [!NOTE]
> Производительность JS-кода измеряют через `performance.now()`, Performance API, DevTools Profiler и повторяемые сценарии.

## Вопрос

Как правильно замерить время выполнения JavaScript-кода?

## Быстрый замер

```javascript
const start = performance.now();

doWork();

const end = performance.now();

console.log(`Duration: ${end - start}ms`);
```

`performance.now()` подходит для точных измерений времени выполнения.

## console.time()

```javascript
console.time('work');

doWork();

console.timeEnd('work');
```

Удобно для быстрых локальных проверок.

## Performance marks

```javascript
performance.mark('work-start');

doWork();

performance.mark('work-end');
performance.measure('work', 'work-start', 'work-end');

console.log(performance.getEntriesByName('work'));
```

Так можно оставлять именованные измерения.

## DevTools Performance

Performance tab показывает:

- long tasks;
- call stack;
- scripting time;
- rendering;
- layout/repaint;
- network;
- memory.

## Важные правила

- прогревать код перед сравнением;
- запускать несколько раз;
- тестировать на реалистичных данных;
- не делать выводы по одному запуску;
- проверять production-сборку;
- помнить, что DevTools сам добавляет overhead.

## Что важно помнить

- `performance.now()` точнее `Date.now()` и монотонен.
- `performance.mark`/`measure` отображаются в DevTools Performance и доступны через `PerformanceObserver`.
- Замеряйте несколько прогонов и в production-сборке: dev-режим React и JIT искажают результат.
- Для пользовательских метрик в production — `web-vitals` и RUM.

## Мини-шпаргалка

```javascript
const start = performance.now();
task();
console.log(performance.now() - start);
```
