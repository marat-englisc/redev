# Метрики производительности и Core Web Vitals

> [!NOTE]
> Производительность сайта измеряют пользовательскими метриками. **Core Web Vitals** — три ключевые метрики Google: **LCP** (Largest Contentful Paint, скорость загрузки главного контента, хорошо ≤ 2,5 с), **INP** (Interaction to Next Paint, отзывчивость на действия, хорошо ≤ 200 мс) и **CLS** (Cumulative Layout Shift, визуальная стабильность, хорошо ≤ 0,1). Дополнительно смотрят TTFB, FCP, TBT, размер бандла и долгие задачи.

## Вопрос

Какие метрики используют для оценки производительности? Что измеряет Core Web Vitals и как улучшить каждую метрику?

## Core Web Vitals

| Метрика | Что измеряет | Хорошо | Плохо |
| --- | --- | --- | --- |
| LCP | когда отрисован самый крупный элемент первого экрана | ≤ 2,5 с | > 4 с |
| INP | задержка от взаимодействия до следующего кадра (худшие из взаимодействий) | ≤ 200 мс | > 500 мс |
| CLS | сумма неожиданных сдвигов layout | ≤ 0,1 | > 0,25 |

Оценка идет по 75-му перцентилю реальных пользователей. INP в 2024 году заменил FID (First Input Delay), который учитывал только задержку первого ввода.

## Дополнительные метрики

| Метрика | Что показывает |
| --- | --- |
| TTFB | время до первого байта ответа сервера |
| FCP | первая отрисовка любого контента |
| TBT | суммарное время блокировки основного потока (лабораторная замена INP) |
| Long tasks | задачи основного потока дольше 50 мс |
| Размер JS / CSS | объем загружаемого и выполняемого кода |
| Memory | потребление памяти, утечки |

## Как улучшить

**LCP:**

- быстрый сервер, CDN, кеширование (TTFB);
- `fetchpriority="high"` и без `loading="lazy"` для главного изображения;
- современные форматы и правильный размер изображений;
- SSR/SSG вместо рендера контента только на клиенте;
- меньше блокирующих CSS и JS.

**INP:**

- разбивать долгие задачи (`scheduler.yield()`, `setTimeout`);
- выносить тяжелые вычисления в Web Worker;
- уменьшать объем JS и гидрации;
- в React — `useTransition`, мемоизация, виртуализация списков;
- быстро показывать отклик (состояние нажатия), а тяжелую работу откладывать.

**CLS:**

- `width`/`height` или `aspect-ratio` у изображений и видео;
- резервировать место под баннеры, рекламу и асинхронный контент;
- `font-display` и подбор метрик fallback-шрифта;
- анимировать `transform`, а не размеры и позицию.

## Как измерять

```javascript
import { onLCP, onINP, onCLS } from "web-vitals";

onLCP(sendToAnalytics);
onINP(sendToAnalytics);
onCLS(sendToAnalytics);
```

| Тип данных | Инструменты |
| --- | --- |
| Лабораторные (lab) | Lighthouse, DevTools Performance, WebPageTest |
| Полевые (field, RUM) | Chrome UX Report, PageSpeed Insights, библиотека `web-vitals`, Search Console |

Лабораторные данные удобны для отладки, но решения принимают по полевым — реальным пользователям на реальных устройствах.

## Что важно помнить

- Core Web Vitals влияют на ранжирование в Google.
- Тестируйте на слабых устройствах и медленной сети (throttling в DevTools): у разработчика быстрый ноутбук.
- Улучшение метрик без реального улучшения UX — ложная цель; метрики лишь отражают опыт пользователя.
- В Next.js есть `useReportWebVitals` для отправки метрик.

## Мини-шпаргалка

- Core Web Vitals: LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1.
- INP заменил FID в 2024 году.
- Дополнительно: TTFB, FCP, TBT, long tasks.
- Lab — Lighthouse, field — CrUX и `web-vitals`.
- LCP — загрузка, INP — отзывчивость, CLS — стабильность.
