# Ошибки внутри функций

> [!NOTE]
> Ошибки внутри функций можно обработать через `try...catch`, вернуть безопасное значение или выбросить ошибку выше через `throw`. Главное - не скрывать ошибку там, где вызывающий код должен о ней знать.

## Вопрос

Как обрабатывать ошибки внутри функции?

## Синхронные ошибки

```javascript
function parseJson(json) {
  try {
    return JSON.parse(json);
  } catch (error) {
    return null;
  }
}

parseJson("{bad json}"); // null
```

`try...catch` подходит для операций, которые реально могут упасть.

## Проверка и `throw`

Если функция получила некорректные аргументы, можно выбросить ошибку.

```javascript
function divide(a, b) {
  if (b === 0) {
    throw new Error("Деление на ноль");
  }

  return a / b;
}
```

Так функция явно сообщает, что ее контракт нарушен.

## Ошибка наверх

Иногда функция не должна сама решать, что делать с ошибкой.

```javascript
function getConfig(json) {
  return JSON.parse(json);
}

try {
  const config = getConfig(rawConfig);
} catch (error) {
  showConfigError(error);
}
```

Обработка находится на уровне, где понятно, как реагировать.

## Асинхронные функции

```javascript
async function loadUser(id) {
  try {
    const response = await fetch(`/api/users/${id}`);

    if (!response.ok) {
      throw new Error("Не удалось загрузить пользователя");
    }

    return await response.json();
  } catch (error) {
    console.error(error);
    return null;
  }
}
```

В `async`-функциях ошибки от `await` ловятся обычным `try...catch`.

## Не глотайте ошибки без причины

Плохо:

```javascript
function save() {
  try {
    riskySave();
  } catch (error) {}
}
```

Так ошибка исчезает, и отладка становится тяжелой.

Лучше хотя бы залогировать или вернуть понятный результат:

```javascript
function save() {
  try {
    riskySave();
    return true;
  } catch (error) {
    console.error(error);
    return false;
  }
}
```

## Что важно помнить

- Ошибка в функции поднимается по стеку вызовов до ближайшего `try...catch`.
- Валидируйте аргументы на границе: бросайте `TypeError`/`RangeError` с понятным сообщением.
- Ошибка в колбэке, переданном в асинхронный API, не дойдет до `try` вокруг его запуска.
- Не возвращайте `null` вместо ошибки молча — вызывающий код может не проверить результат.

## Мини-шпаргалка

| Подход | Когда использовать |
| --- | --- |
| `try...catch` | можно восстановиться на месте |
| `throw new Error()` | нарушение контракта функции |
| вернуть `null`/fallback | безопасная ожидаемая ошибка |
| пробросить ошибку выше | текущий уровень не знает, что делать |
| логировать | если ошибка важна для диагностики |
