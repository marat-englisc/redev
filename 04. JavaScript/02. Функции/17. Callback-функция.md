# Callback-функция и передача функции в другую функцию

> [!NOTE]
> **Callback** — функция, которую передают в другую функцию как аргумент, чтобы та вызвала ее позже: по событию, после асинхронной операции или для каждого элемента. Это возможно, потому что функции в JavaScript — значения первого класса. Колбэки бывают синхронными (`map`, `sort`) и асинхронными (`setTimeout`, `addEventListener`).

## Вопрос

Что такое callback-функция? Как передать функцию в другую функцию и чем синхронные колбэки отличаются от асинхронных?

## Передача функции в функцию

```javascript
function processOrder(order, onSuccess, onError) {
  if (order.items.length === 0) {
    onError(new Error("Корзина пуста"));
    return;
  }
  onSuccess({ id: Date.now(), ...order });
}

processOrder(
  { items: ["чайник"] },
  (result) => console.log("Заказ создан", result.id),
  (error) => console.error(error.message),
);
```

Передается **ссылка** на функцию, без скобок: `button.addEventListener("click", handleClick)`. Со скобками (`handleClick()`) функция выполнится сразу, а в обработчик попадет ее результат.

## Синхронные и асинхронные колбэки

```javascript
// синхронный: вызывается сразу, во время работы map
const doubled = [1, 2, 3].map((n) => n * 2);

// асинхронный: вызывается позже, через event loop
setTimeout(() => console.log("через секунду"), 1000);
button.addEventListener("click", () => console.log("клик"));
```

| | Синхронный | Асинхронный |
| --- | --- | --- |
| Когда вызывается | до возврата из функции | позже, отдельной задачей |
| Примеры | `map`, `filter`, `forEach`, `sort`, `reduce` | `setTimeout`, события, `fs.readFile` |
| Ошибки | ловит `try...catch` вокруг вызова | не ловит внешний `try...catch` |

## Error-first callback (Node.js)

```javascript
import { readFile } from "node:fs";

readFile("config.json", "utf8", (error, data) => {
  if (error) {
    console.error("Не удалось прочитать", error);
    return;
  }
  console.log(JSON.parse(data));
});
```

Соглашение Node.js: первый аргумент — ошибка или `null`, дальше — результат.

## Проблемы колбэков

- **callback hell** — глубокая вложенность при последовательных асинхронных шагах;
- **inversion of control** — вы доверяете чужой функции вызвать колбэк ровно один раз и вовремя;
- сложная обработка ошибок — каждый уровень проверяет ошибку сам.

Поэтому для асинхронности перешли на промисы и `async/await`, а колбэки остались для событий и функций высшего порядка.

## Что важно помнить

- Колбэк теряет `this`, если передать метод объекта: `setTimeout(user.greet)` — используйте стрелку или `bind`.
- Не смешивайте синхронный и асинхронный вызов одного колбэка в разных ветках («Zalgo»): это ломает порядок выполнения.
- Колбэки в `useEffect`, `useCallback` и обработчики событий — главный источник «устаревших замыканий» в React.
- Промисифицировать callback-API можно через `util.promisify` в Node.js или вручную через `new Promise`.

## Мини-шпаргалка

- Callback — функция, переданная в другую функцию для последующего вызова.
- Передается ссылка без скобок.
- Синхронные: `map`, `sort`. Асинхронные: `setTimeout`, события.
- Node.js — error-first: `(error, data) => {}`.
- Для асинхронных цепочек — промисы и `async/await`.
