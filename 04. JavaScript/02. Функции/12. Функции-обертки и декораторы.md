# Функции-обертки и декораторы

> [!NOTE]
> **Функция-обертка** принимает функцию и возвращает новую функцию, которая вызывает исходную, добавляя поведение до или после вызова. Если обертка универсальна и не меняет контракт функции (аргументы и результат), ее называют **декоратором**: логирование, кеширование, debounce, retry, замер времени. Важно передавать `this` и все аргументы через `fn.apply(this, args)`.

## Вопрос

Что такое функция-обертка? Что такое функция-декоратор и как правильно ее написать?

## Простая обертка

```javascript
function withLogging(fn) {
  return function (...args) {
    console.log(`Вызов ${fn.name}`, args);
    const result = fn.apply(this, args);
    console.log(`Результат ${fn.name}`, result);
    return result;
  };
}

const add = (a, b) => a + b;
const loggedAdd = withLogging(add);
loggedAdd(2, 3); // логирует и возвращает 5
```

Исходная функция не меняется — создается новая, с тем же интерфейсом.

## Почему fn.apply(this, args)

```javascript
const user = {
  name: "Анна",
  greet() { return `Привет, ${this.name}`; },
};

user.greet = withLogging(user.greet);
user.greet(); // "Привет, Анна" — this передан через apply
```

Если в обертке вызвать просто `fn(...args)`, метод потеряет `this`. Стрелочная функция в качестве обертки тоже не подойдет: у нее нет своего `this`.

## Типичные декораторы

```javascript
// замер времени
function measure(fn) {
  return function (...args) {
    const start = performance.now();
    try {
      return fn.apply(this, args);
    } finally {
      console.log(`${fn.name}: ${(performance.now() - start).toFixed(1)} мс`);
    }
  };
}

// кеширование (мемоизация)
function memoize(fn) {
  const cache = new Map();
  return function (arg) {
    if (!cache.has(arg)) cache.set(arg, fn.call(this, arg));
    return cache.get(arg);
  };
}

// однократный вызов
function once(fn) {
  let called = false;
  let result;
  return function (...args) {
    if (!called) {
      called = true;
      result = fn.apply(this, args);
    }
    return result;
  };
}

// повтор асинхронной операции
function withRetry(fn, attempts = 3) {
  return async function (...args) {
    for (let i = 1; ; i++) {
      try {
        return await fn.apply(this, args);
      } catch (error) {
        if (i === attempts) throw error;
      }
    }
  };
}
```

Декораторы можно комбинировать: `const safeFetch = withRetry(measure(fetchUser))`.

## Обертка или декоратор

| | Обертка | Декоратор |
| --- | --- | --- |
| Суть | любая функция поверх другой | обертка, добавляющая сквозное поведение |
| Контракт | может менять аргументы и результат | сохраняет аргументы и результат |
| Примеры | адаптер API, валидация входа | лог, кеш, debounce, retry, once |

На практике термины часто используют как синонимы.

## Декораторы в синтаксисе языка

```typescript
class Api {
  @logged
  load() {}
}
```

Синтаксис `@decorator` для классов — предложение TC39 (стадия 3) и давно поддерживается в TypeScript. Он применяет ту же идею к методам и классам.

## Что важно помнить

- Обертка теряет свойства исходной функции (`fn.length`, собственные поля) — при необходимости копируйте их.
- Декоратор с кешем держит ссылки на результаты — следите за утечками памяти, используйте `WeakMap` для объектов-ключей.
- HOC в React — тот же паттерн для компонентов.
- `debounce` и `throttle` — тоже декораторы.

## Мини-шпаргалка

- Обертка: принимает функцию, возвращает новую.
- Декоратор — обертка со сквозным поведением без изменения контракта.
- Передавайте контекст: `fn.apply(this, args)`.
- Примеры: лог, замер, memoize, once, retry, debounce.
- Синтаксис `@decorator` — для классов и методов.
