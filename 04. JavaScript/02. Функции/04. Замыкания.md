# Замыкания

> [!NOTE]
> Замыкание - это функция вместе с лексическим окружением, которое она запомнила при создании. Благодаря этому функция может использовать внешние переменные даже после завершения внешней функции.

## Вопрос

Что такое замыкание?

## Базовый пример

```javascript
function createCounter() {
  let count = 0;

  return function increment() {
    count++;
    return count;
  };
}

const counter = createCounter();

counter(); // 1
counter(); // 2
counter(); // 3
```

Функция `increment` помнит переменную `count`, хотя `createCounter` уже завершилась.

## Почему это работает

JavaScript использует лексическую область видимости. Функция запоминает переменные из того места, где была создана.

```javascript
function outer() {
  const message = "Hello";

  function inner() {
    console.log(message);
  }

  return inner;
}
```

`inner` замыкает переменную `message`.

## Где замыкания встречаются

### Состояние без глобальных переменных

```javascript
function createStore(initialValue) {
  let value = initialValue;

  return {
    get() {
      return value;
    },
    set(nextValue) {
      value = nextValue;
    },
  };
}
```

### Callback

```javascript
function delayedLog(message) {
  setTimeout(() => {
    console.log(message);
  }, 1000);
}

delayedLog("Hello");
```

Callback выполнится позже, но сохранит доступ к `message`.

### Фабрики функций

```javascript
function multiplyBy(multiplier) {
  return function (value) {
    return value * multiplier;
  };
}

const double = multiplyBy(2);
double(10); // 20
```

## Типичная ловушка

С `var` в цикле все callback могут увидеть одно и то же значение.

```javascript
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 3, 3, 3
```

С `let` создается новая привязка на каждую итерацию.

```javascript
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 0, 1, 2
```

## Что важно помнить

- Замыкание создается при каждом создании функции, а не только при «возврате функции из функции».
- Замыкание держит ссылку на переменную, а не копию значения — поэтому видит ее последующие изменения.
- Устаревшие замыкания (stale closures) — частая проблема React: колбэк видит state предыдущего рендера; помогают зависимости хуков, функциональный `setState` и `useRef`.
- Замыкание может удерживать большие объекты в памяти, пока жива функция.

## Мини-шпаргалка

| Идея | Объяснение |
| --- | --- |
| Замыкание | функция + внешние переменные |
| Возникает | когда функция использует переменные снаружи |
| Работает из-за | лексической области видимости |
| Используется для | состояния, callback, фабрик, декораторов |
| Риск | случайно удержать лишние данные в памяти |
