# Каррирование и частичное применение

> [!NOTE]
> **Каррирование** превращает функцию от нескольких аргументов в цепочку функций от одного аргумента: `f(a, b, c)` → `f(a)(b)(c)`. **Частичное применение** фиксирует часть аргументов и возвращает функцию от оставшихся: `f(a, b, c)` → `g(b, c)`. Обе техники позволяют создавать специализированные функции из общих и строятся на замыканиях.

## Вопрос

Что такое каррирование? Что такое частичное применение и чем оно отличается от каррирования? Как реализовать `curry`?

## Каррирование

```javascript
const add = (a, b, c) => a + b + c;
const curriedAdd = (a) => (b) => (c) => a + b + c;

add(1, 2, 3);          // 6
curriedAdd(1)(2)(3);   // 6

const addTen = curriedAdd(10);
addTen(5)(1);          // 16
```

## Частичное применение

```javascript
function partial(fn, ...fixed) {
  return (...rest) => fn(...fixed, ...rest);
}

const log = (level, module, message) => console[level](`[${module}] ${message}`);

const warnApi = partial(log, "warn", "API");
warnApi("Медленный ответ"); // [API] Медленный ответ

// встроенный способ
const errorAuth = log.bind(null, "error", "Auth");
```

## Разница

| | Каррирование | Частичное применение |
| --- | --- | --- |
| Результат | цепочка функций по одному аргументу | одна функция от оставшихся аргументов |
| Вызов | `f(a)(b)(c)` | `g(b, c)` |
| Количество шагов | столько, сколько аргументов | одно фиксирование |
| Инструменты | `curry` из lodash / Ramda | `bind`, `partial` |

## Универсальный curry (частый вопрос на собеседовании)

```javascript
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn.apply(this, args);
    }
    return (...next) => curried.apply(this, [...args, ...next]);
  };
}

const sum3 = curry((a, b, c) => a + b + c);

sum3(1)(2)(3);  // 6
sum3(1, 2)(3);  // 6 — «гибкое» каррирование
sum3(1)(2, 3);  // 6
```

Реализация опирается на `fn.length` — количество объявленных параметров. Для функций с rest-параметрами или значениями по умолчанию `length` меньше, и такой `curry` сработает некорректно.

## Где применяется

```javascript
// конфигурируемые функции
const formatPrice = (currency) => (amount) =>
  new Intl.NumberFormat("ru-RU", { style: "currency", currency }).format(amount);
const toRub = formatPrice("RUB");
prices.map(toRub);

// обработчики с параметром в React
const handleChange = (field) => (event) => setForm({ ...form, [field]: event.target.value });
<input onChange={handleChange("email")} />;

// композиция функций
const pipe = (...fns) => (x) => fns.reduce((v, f) => f(v), x);
const process = pipe(trim, toLowerCase, removeSpaces);
```

## Что важно помнить

- Каррирование удобно в функциональном стиле (Ramda, fp-ts), но в обычном коде лишние уровни функций ухудшают читаемость.
- Порядок аргументов важен: то, что фиксируют чаще, ставят первым («данные — последними»).
- Каждый уровень создает новую функцию и замыкание — в горячем коде это лишние аллокации.
- В TypeScript типизация универсального `curry` сложна; для конкретных случаев пишут явные стрелки.

## Мини-шпаргалка

- Каррирование: `f(a, b, c)` → `f(a)(b)(c)`.
- Частичное применение: зафиксировать часть аргументов → `g(c)`.
- `bind(null, ...args)` — встроенное частичное применение.
- `curry` опирается на `fn.length`.
- Основа — замыкания.
