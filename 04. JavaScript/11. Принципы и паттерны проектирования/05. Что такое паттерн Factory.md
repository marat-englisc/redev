# Что такое паттерн Factory

> [!NOTE]
> **Factory (Фабрика)** — порождающий паттерн: создание объектов выносится в отдельную функцию или метод, который решает, **какой** объект создать и **как** его настроить. Вызывающий код получает готовый объект через общий интерфейс и не зависит от конкретных классов. В JavaScript чаще используют **фабричные функции** вместо классов: они проще, позволяют замыкания и приватное состояние.

## Вопрос

Что такое паттерн Factory? Чем фабричная функция отличается от конструктора и класса? Где фабрики используются во фронтенде?

## Фабричная функция

```typescript
function createUser(name: string, role: "admin" | "user" = "user") {
  let loginCount = 0;                        // приватное состояние через замыкание

  return {
    name,
    role,
    login() { loginCount += 1; },
    get logins() { return loginCount; },
  };
}

const anna = createUser("Анна", "admin");
anna.login();
anna.logins; // 1
```

## Фабрика, выбирающая реализацию

```typescript
interface Notifier { send(message: string): Promise<void>; }

class EmailNotifier implements Notifier { async send(m: string) { /* ... */ } }
class PushNotifier implements Notifier { async send(m: string) { /* ... */ } }
class TelegramNotifier implements Notifier { async send(m: string) { /* ... */ } }

function createNotifier(channel: "email" | "push" | "telegram"): Notifier {
  switch (channel) {
    case "email": return new EmailNotifier();
    case "push": return new PushNotifier();
    case "telegram": return new TelegramNotifier();
  }
}

const notifier = createNotifier(user.preferredChannel);
await notifier.send("Заказ отправлен");   // код не знает конкретный класс
```

## Фабрика с конфигурацией

```typescript
function createApiClient({ baseUrl, token }: { baseUrl: string; token?: string }) {
  return {
    async get<T>(path: string): Promise<T> {
      const res = await fetch(baseUrl + path, {
        headers: token ? { Authorization: `Bearer ${token}` } : {},
      });
      if (!res.ok) throw new Error(`HTTP ${res.status}`);
      return res.json();
    },
  };
}

const publicApi = createApiClient({ baseUrl: "/api" });
const adminApi = createApiClient({ baseUrl: "/admin-api", token });
```

## Фабрика, класс, конструктор

| | Фабричная функция | Класс / конструктор |
| --- | --- | --- |
| Вызов | `createX()` | `new X()` |
| Приватность | замыкания | `#private` поля |
| Выбор типа объекта | легко вернуть разные реализации | конструктор всегда создает свой класс |
| `instanceof` | не работает | работает |
| Наследование | композиция | `extends` |

## Где встречается

- `React.createElement`, `createRoot`, `createContext`;
- `axios.create()`, `createStore` (Redux, Zustand), `createSlice`, `createBrowserRouter`;
- генерация тестовых данных: `buildUser({ role: "admin" })`;
- фабрики компонентов по типу: `{ text: TextField, date: DatePicker }[field.type]`.

## Что важно помнить

- Фабрика скрывает детали создания: при замене реализации меняется одно место.
- Для выбора реализации по ключу вместо `switch` удобен реестр-объект — так проще добавлять новые типы (Open/Closed).
- Фабрики хорошо сочетаются с DI: зависимости передаются аргументами, их легко подменить в тестах.
- **Abstract Factory** создает семейство связанных объектов (например, набор UI-компонентов для темы), **Factory Method** — метод, который переопределяется в подклассах.

## Мини-шпаргалка

Factory — функция, которая создает и настраивает объект и решает, какую реализацию вернуть. В JS — `createX()` с замыканиями вместо `new`. Примеры: `createStore`, `axios.create`, тестовые билдеры. Реестр вместо `switch`.
