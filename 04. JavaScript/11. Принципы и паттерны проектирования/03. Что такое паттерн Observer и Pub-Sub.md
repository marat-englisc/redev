# Что такое паттерн Observer и Pub/Sub

> [!NOTE]
> **Observer (Наблюдатель)** — поведенческий паттерн: объект-**субъект** хранит список подписчиков и уведомляет их об изменениях. Подписчики не опрашивают субъект — он сам их вызывает. **Pub/Sub** — вариация, где между издателем и подписчиками стоит посредник (шина событий, брокер), и они не знают друг о друге. На Observer построены `addEventListener`, `EventEmitter`, store-менеджеры (Redux, Zustand), RxJS и реактивность.

## Вопрос

Что такое паттерн Observer? Чем он отличается от Pub/Sub и где встречается во фронтенде? Как реализовать EventEmitter?

## Реализация Observer

```typescript
type Listener<T> = (value: T) => void;

function createStore<T>(initial: T) {
  let state = initial;
  const listeners = new Set<Listener<T>>();

  return {
    getState: () => state,
    setState(next: T) {
      state = next;
      listeners.forEach((l) => l(state));        // уведомить всех
    },
    subscribe(listener: Listener<T>) {
      listeners.add(listener);
      return () => listeners.delete(listener);   // функция отписки
    },
  };
}

const counter = createStore(0);
const unsubscribe = counter.subscribe((v) => console.log("count:", v));
counter.setState(1); // count: 1
unsubscribe();
```

Такой store можно подключить к React через `useSyncExternalStore`.

## EventEmitter (Pub/Sub) — частая задача на лайвкодинге

```typescript
type Handler = (...args: any[]) => void;

class EventEmitter {
  private events = new Map<string, Set<Handler>>();

  on(event: string, handler: Handler) {
    if (!this.events.has(event)) this.events.set(event, new Set());
    this.events.get(event)!.add(handler);
    return () => this.off(event, handler);
  }

  off(event: string, handler: Handler) {
    this.events.get(event)?.delete(handler);
  }

  once(event: string, handler: Handler) {
    const off = this.on(event, (...args) => {
      off();
      handler(...args);
    });
    return off;
  }

  emit(event: string, ...args: unknown[]) {
    [...(this.events.get(event) ?? [])].forEach((h) => h(...args)); // копия: подписчик может отписаться во время emit
  }
}

const bus = new EventEmitter();
bus.once("login", (user) => console.log("привет,", user));
bus.emit("login", "Анна"); // привет, Анна
bus.emit("login", "Анна"); // ничего
```

## Observer и Pub/Sub

| | Observer | Pub/Sub |
| --- | --- | --- |
| Связь | подписчик знает субъект | издатель и подписчик не знают друг о друге |
| Посредник | нет | шина, канал, брокер |
| Пример | `button.addEventListener`, store.subscribe | глобальная шина событий, `BroadcastChannel`, Redis pub/sub |

## Где встречается

- DOM-события: `addEventListener`, `CustomEvent`;
- Node.js `EventEmitter`;
- `IntersectionObserver`, `MutationObserver`, `ResizeObserver`;
- Redux, Zustand, MobX, сигналы;
- RxJS `Observable` — поток событий с операторами;
- WebSocket-сообщения и межвкладочная связь (`BroadcastChannel`).

## Что важно помнить

- Всегда возвращайте и вызывайте **отписку**, иначе — утечки памяти и лишние вызовы (в React — в cleanup `useEffect`).
- Порядок уведомления подписчиков обычно не гарантируйте — не стройте на нем логику.
- Ошибка в одном подписчике не должна ломать остальных: в продакшен-реализациях вызовы оборачивают в `try/catch`.
- Глобальная шина событий удобна, но делает поток данных неявным — сложно понять, кто и почему изменил состояние.

## Мини-шпаргалка

Observer: субъект хранит подписчиков и вызывает их при изменении; `subscribe` возвращает `unsubscribe`. Pub/Sub — через посредника, стороны не знают друг о друге. EventEmitter: `on`, `off`, `once`, `emit`. Не забывать отписку.
