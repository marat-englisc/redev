# import и export

> [!NOTE]
> `export` делает значения доступными из модуля, а `import` подключает их в другом файле.

## Вопрос

Что делают `import` и `export`, и чем `export default` отличается от именованного экспорта?

## Определение

ES Modules позволяют делить код на файлы. Один файл экспортирует функции, классы, константы или объекты, а другой импортирует их.

Модули помогают организовать код, переиспользовать логику и контролировать зависимости.

## Именованный export

```javascript
// math.js
export function sum(a, b) {
  return a + b;
}

export const PI = 3.14;
```

## Именованный import

```javascript
// app.js
import { sum, PI } from './math.js';

console.log(sum(2, 3));
console.log(PI);
```

Имя при импорте должно совпадать с именем экспорта.

## Переименование

```javascript
import { sum as add } from './math.js';

console.log(add(2, 3));
```

## export default

```javascript
// User.js
export default class User {}
```

```javascript
// app.js
import User from './User.js';
```

Default export в модуле может быть только один, а импортировать его можно под любым именем.

## Сравнение

| Вид | Сколько в модуле | Как импортировать |
| --- | --- | --- |
| named export | много | `import { name } from './file.js'` |
| default export | один | `import AnyName from './file.js'` |

## Что важно помнить

- Импорты — живые привязки (live bindings): изменение экспортированной переменной видно импортерам.
- Статические `import` поднимаются и выполняются до кода модуля; динамический `import()` — по требованию.
- Модуль выполняется один раз, даже если импортирован из многих мест.
- Именованные экспорты лучше для tree shaking и автоимпорта, чем `default`.

## Мини-шпаргалка

```javascript
export const value = 1;
export default function fn() {}

import { value } from './module.js';
import fn from './module.js';
```
