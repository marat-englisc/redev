# Scope chain и лексическая область видимости

> [!NOTE]
> **Лексическая область видимости** означает, что доступ к переменным определяется местом объявления функции в коде, а не местом ее вызова. Каждая функция при создании запоминает ссылку на внешнее лексическое окружение. **Цепочка областей видимости (scope chain)** — путь от текущего окружения к внешним вплоть до глобального: переменная ищется изнутри наружу до первого совпадения, а если не найдена — `ReferenceError`.

## Вопрос

Что такое scope chain? Что значит «лексическая область видимости» и как она связана с замыканиями?

## Как ищется переменная

```javascript
const appName = "Shop";               // глобальное окружение

function createCart() {
  const currency = "RUB";             // окружение createCart

  function addItem(price) {
    const total = price * 2;          // окружение addItem
    return `${appName}: ${total} ${currency}`;
  }

  return addItem;
}

createCart()(100); // "Shop: 200 RUB"
```

```text
addItem: { price, total }
   ↓ outer
createCart: { currency, addItem }
   ↓ outer
global: { appName, createCart }
   ↓ outer
null → ReferenceError
```

Поиск `appName` из `addItem`: собственное окружение → `createCart` → глобальное — найдено.

## Лексическая, а не динамическая

```javascript
const value = "глобальное";

function show() {
  console.log(value);
}

function run() {
  const value = "из run";
  show();
}

run(); // "глобальное" — show видит окружение, где ее объявили
```

В языках с динамической областью видимости результат был бы «из run». В JavaScript лексическая область определяется при написании кода — единственное динамическое значение — `this`.

## Лексическое окружение

Каждый вызов функции, блок и модуль создают **Lexical Environment**:

- **Environment Record** — переменные и функции этой области;
- **ссылка на внешнее окружение** (`[[OuterEnv]]`), заданная при создании функции.

Функция хранит ссылку на окружение, в котором была создана (`[[Environment]]`). Поэтому после завершения `createCart` ее переменные не исчезают, пока на них ссылается `addItem`, — это и есть **замыкание**.

## Затенение

```javascript
const name = "внешнее";
function greet() {
  const name = "внутреннее"; // затеняет внешнее
  console.log(name);
}
```

Поиск останавливается на первом совпадении, поэтому внутреннее имя «закрывает» внешнее.

## Блоки и циклы

```javascript
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i)); // 0, 1, 2 — новое окружение на каждой итерации
}
```

`let` в цикле создает новое лексическое окружение на каждой итерации, поэтому каждый колбэк замыкает свою `i`.

## Что важно помнить

- Длинная цепочка областей видимости почти не влияет на скорость — движки оптимизируют доступ.
- `eval` и `with` ломают лексическую предсказуемость — поэтому они запрещены или нежелательны в strict mode.
- Переменные модуля видны функциям модуля, но не другим модулям без `export`.
- На собеседовании связка «лексическое окружение → scope chain → замыкание» — один из базовых вопросов.

## Мини-шпаргалка

- Лексическая область — по месту объявления, а не вызова.
- Scope chain — поиск переменной изнутри наружу.
- Не найдено до глобальной области — `ReferenceError`.
- Функция хранит ссылку на окружение создания — замыкание.
- Внутреннее имя затеняет внешнее.
