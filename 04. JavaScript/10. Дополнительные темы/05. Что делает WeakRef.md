# Что делает WeakRef?

> [!NOTE]
> `WeakRef` создает слабую ссылку на объект, которая не мешает сборщику мусора удалить этот объект.

## Вопрос

Для чего нужен `WeakRef` и почему его используют редко?

## Определение

`WeakRef` позволяет хранить ссылку на объект, не делая этот объект достижимым для Garbage Collector. Если других сильных ссылок нет, объект может быть собран, а `weakRef.deref()` вернет `undefined`.

## Пример

```javascript
let user = { name: 'Ann' };

const weakRef = new WeakRef(user);

console.log(weakRef.deref()); // { name: 'Ann' }

user = null;
```

После сборки мусора объект может исчезнуть, но момент этого исчезновения нельзя предсказать.

## deref()

```javascript
const value = weakRef.deref();

if (value) {
  console.log(value.name);
}
```

`deref()` возвращает объект, если он еще жив, или `undefined`, если объект уже собран.

## Почему осторожно

- GC работает недетерминированно;
- нельзя строить бизнес-логику на точном моменте удаления;
- код становится сложнее;
- для большинства кэшей лучше подходят обычные структуры с явной очисткой.

## Когда может пригодиться

- низкоуровневые кэши;
- вспомогательные структуры;
- связь с `FinalizationRegistry`;
- редкие случаи, где важно не продлевать жизнь объекта.

## Что важно помнить

- `WeakRef` держит слабую ссылку на объект; `deref()` вернет объект или `undefined`, если его собрали.
- Момент сборки мусора непредсказуем — логика не должна от него зависеть.
- `FinalizationRegistry` позволяет выполнить код после сборки объекта, но без гарантий времени.
- В обычном коде WeakRef почти не нужен — сначала рассмотрите `WeakMap`.

## Мини-шпаргалка

```javascript
const ref = new WeakRef(object);
const objectOrUndefined = ref.deref();
```
