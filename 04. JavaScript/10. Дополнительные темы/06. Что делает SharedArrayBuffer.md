# Что делает SharedArrayBuffer?

> [!NOTE]
> `SharedArrayBuffer` создает участок памяти, которым могут совместно пользоваться несколько потоков JavaScript.

## Вопрос

Зачем нужен `SharedArrayBuffer` и чем он отличается от обычного `ArrayBuffer`?

## Определение

`SharedArrayBuffer` - бинарный буфер памяти, доступный одновременно из нескольких потоков: например, из main thread и Web Worker. Это позволяет обмениваться данными без копирования.

Для безопасной синхронизации обычно используют `Atomics`.

## Пример

```javascript
const buffer = new SharedArrayBuffer(4);
const view = new Int32Array(buffer);

view[0] = 42;

worker.postMessage(buffer);
```

Worker получит доступ к той же области памяти.

## worker.js

```javascript
self.onmessage = (event) => {
  const view = new Int32Array(event.data);

  Atomics.add(view, 0, 1);
  self.postMessage(view[0]);
};
```

## Отличие от ArrayBuffer

| Буфер | Поведение |
| --- | --- |
| `ArrayBuffer` | обычно передается копированием или transfer |
| `SharedArrayBuffer` | одна общая память для нескольких потоков |

## Важные ограничения

Из-за требований безопасности `SharedArrayBuffer` в браузере обычно требует cross-origin isolation: специальные HTTP-заголовки `COOP` и `COEP`.

Также нужно аккуратно работать с гонками данных: несколько потоков могут читать и писать одновременно.

## Что важно помнить

- `SharedArrayBuffer` дает общую память между потоками без копирования.
- Доступен только на cross-origin isolated страницах (заголовки COOP и COEP) — из-за атак Spectre.
- Для безопасной синхронизации используйте `Atomics` (`add`, `wait`, `notify`).
- Применяется в WebAssembly с потоками, обработке медиа и тяжелых вычислениях.

## Мини-шпаргалка

```javascript
const buffer = new SharedArrayBuffer(bytes);
const view = new Int32Array(buffer);
Atomics.add(view, 0, 1);
```
