# Как оптимизировать отрисовку на canvas

> [!NOTE]
> Бюджет кадра при 60 FPS — **16,6 мс** на всё: логику, физику и отрисовку (на 120 Гц — 8,3 мс). Главные приёмы для canvas 2D: **не рисовать невидимое** (culling по камере), **кешировать** сложную или статичную графику в offscreen-canvas и рисовать её одним `drawImage`, **разделять слои** (статичный фон в отдельном canvas под игровым), **меньше переключать состояние** контекста (группировать объекты по цвету/текстуре), **избегать дорогих операций** в цикле (`shadowBlur`, `filter`, `getImageData`, создание градиентов) и не плодить мусор. Сначала измеряйте в DevTools → Performance, потом оптимизируйте. Если упираетесь в тысячи спрайтов — переходите на WebGL (PixiJS).

## Вопрос

Как ускорить отрисовку игры на canvas 2D? Какие операции дорогие и как их избежать?

## Предварительный рендер в offscreen-canvas

Сложную фигуру (с градиентом, тенью, текстом) рисуют **один раз** и потом копируют:

```ts
function prerender(w: number, h: number, draw: (ctx: OffscreenCanvasRenderingContext2D) => void) {
  const c = new OffscreenCanvas(w, h);
  draw(c.getContext('2d')!);
  return c;
}

// неоновый враг: тень считается один раз, а не 500 раз за кадр
const enemySprite = prerender(48, 48, (g) => {
  g.shadowColor = '#f0f';
  g.shadowBlur = 12;
  g.fillStyle = '#f0f';
  g.beginPath();
  g.arc(24, 24, 12, 0, Math.PI * 2);
  g.fill();
});

for (const e of enemies) ctx.drawImage(enemySprite, e.x - 24, e.y - 24);
```

То же для текста, который редко меняется:

```ts
let scoreCache: OffscreenCanvas | null = null;
let cachedScore = -1;

function drawScore(score: number) {
  if (score !== cachedScore) {
    scoreCache = prerender(200, 32, (g) => {
      g.font = 'bold 24px monospace';
      g.fillStyle = 'white';
      g.fillText(`Score: ${score}`, 0, 24);
    });
    cachedScore = score;
  }
  ctx.drawImage(scoreCache!, 16, 16);
}
```

## Несколько canvas-слоёв

```html
<div class="stage">
  <canvas id="bg"></canvas>    <!-- фон: рисуется один раз или при скролле -->
  <canvas id="game"></canvas>  <!-- игровые объекты: каждый кадр -->
  <canvas id="ui"></canvas>    <!-- интерфейс: при изменении -->
</div>
```

```css
.stage { position: relative; }
.stage canvas { position: absolute; inset: 0; }
```

Каждый слой перерисовывается только когда меняется. Статичный HUD поверх игры вообще можно сделать HTML-разметкой.

## Меньше смен состояния

Каждое изменение `fillStyle`, `font`, `globalAlpha`, `globalCompositeOperation` стоит времени. Группируйте:

```ts
// ❌ смена цвета на каждый объект
for (const b of bullets) {
  ctx.fillStyle = b.color;
  ctx.fillRect(b.x, b.y, 4, 4);
}

// ✅ пакет по цветам, один путь на группу
const byColor = groupBy(bullets, (b) => b.color);
for (const [color, list] of byColor) {
  ctx.fillStyle = color;
  ctx.beginPath();
  for (const b of list) ctx.rect(b.x, b.y, 4, 4);
  ctx.fill();
}
```

## Дорогие операции

| Операция | Почему дорого | Чем заменить |
| --- | --- | --- |
| `shadowBlur`, `filter` | размытие на каждый вызов | готовый спрайт со свечением |
| `getImageData`/`putImageData` | копирование пикселей GPU ↔ CPU | логика без чтения пикселей, WebGL-шейдер |
| `createLinearGradient` в цикле | новый объект каждый кадр | создать один раз |
| `measureText` каждый кадр | раскладка текста | кешировать ширину |
| `save`/`restore` на тысячи объектов | копирование всего состояния | `setTransform` напрямую |
| `drawImage` с масштабированием | ресемплинг | рисовать в исходном размере, заранее отмасштабировать |
| дробные координаты | субпиксельное сглаживание | `Math.round` / `x | 0` |

Вместо `save/translate/rotate/restore` для каждого спрайта можно задавать матрицу сразу:

```ts
for (const s of sprites) {
  const cos = Math.cos(s.angle), sin = Math.sin(s.angle);
  ctx.setTransform(cos, sin, -sin, cos, s.x, s.y);  // поворот + перенос одной командой
  ctx.drawImage(s.img, -s.w / 2, -s.h / 2);
}
ctx.setTransform(1, 0, 0, 1, 0, 0);
```

## Culling и частичная перерисовка

```ts
for (const e of entities) {
  if (!camera.isVisible(e.bounds)) continue;   // самая дешёвая оптимизация
  e.draw(ctx);
}
```

В играх с редкими изменениями (настольные, головоломки) можно перерисовывать только изменившиеся области («грязные прямоугольники») или вообще рисовать кадр только при изменении состояния.

## Опции контекста

```ts
const ctx = canvas.getContext('2d', {
  alpha: false,              // фон непрозрачный — композитинг проще
  desynchronized: true,      // меньше задержка (для рисовалок/стилуса), поддерживается не везде
});
```

## Профилирование

1. DevTools → **Performance** → запись 5–10 секунд игры.
2. Смотрите полоску **Frames**: красные кадры — дольше бюджета.
3. В **Bottom-Up** — какие функции занимают время (`draw`, `fillText`, `GC`).
4. **Memory** / пилообразный график JS Heap — признак мусора в цикле.
5. Rendering → **Frame Rendering Stats** — FPS прямо на странице.

```ts
// замер своих частей
performance.mark('update-start');
update(dt);
performance.measure('update', 'update-start');
```

## Когда 2D уже не хватает

Canvas 2D рисует на GPU, но каждый `drawImage` — отдельная команда. Ориентир: несколько тысяч спрайтов на средних устройствах. Если нужно больше, или нужны шейдеры, освещение, фильтры — WebGL/WebGPU-рендерер (PixiJS) рисует десятки тысяч спрайтов пакетами за единицы draw calls.

## Частые ошибки

- Оптимизировать без замеров.
- Перерисовывать статичный фон каждый кадр.
- Использовать `shadowBlur` и `filter` для массовых объектов.
- Читать пиксели через `getImageData` в игровом цикле.
- Огромный canvas на всё окно с `devicePixelRatio = 3` на телефоне — 9× пикселей. Иногда стоит ограничить `dpr` до 2.

## Что важно помнить

- Бюджет: 16,6 мс на кадр (8,3 мс при 120 Гц).
- Culling, кеширование в offscreen-canvas, слои.
- Группировка по стилю, меньше смен состояния.
- Дорого: тени, фильтры, `getImageData`, создание объектов в цикле.
- Тысячи спрайтов — повод перейти на WebGL.

## Мини-шпаргалка

```ts
const cache = new OffscreenCanvas(w, h); /* рисуем один раз */ ctx.drawImage(cache, x, y);
if (!camera.isVisible(e)) continue;
ctx.setTransform(cos, sin, -sin, cos, x, y);
Math.min(devicePixelRatio, 2);
```
