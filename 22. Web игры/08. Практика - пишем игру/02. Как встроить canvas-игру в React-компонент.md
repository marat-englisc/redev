# Как встроить canvas-игру в React-компонент

> [!NOTE]
> React и игровой цикл работают по-разному: React перерисовывает компонент при изменении state, а игра обновляется 60+ раз в секунду. Поэтому **состояние игры не кладут в `useState`** — это вызвало бы ререндер каждый кадр. Игровой мир живёт в обычных объектах или классе (хранится в `useRef`), цикл запускается в `useEffect` и **обязательно останавливается в cleanup** (`cancelAnimationFrame`, снятие слушателей). В React state попадает только то, что нужно интерфейсу: счёт, экран паузы, меню — и только при изменении, а не каждый кадр. В режиме Strict Mode эффект в dev вызывается дважды — правильная очистка гарантирует, что не будет двух циклов одновременно.

## Вопрос

Как правильно встроить canvas-игру в React-приложение (или Next.js), чтобы не было утечек, двойных циклов и лишних ререндеров?

## Игра отдельно от React

```ts
// game/Game.ts — чистый TypeScript, ничего не знает о React
export interface GameEvents {
  onScore?(score: number): void;
  onGameOver?(score: number): void;
}

export class Game {
  private rafId = 0;
  private last = 0;
  private running = false;
  private score = 0;
  private keys = new Set<string>();

  constructor(private canvas: HTMLCanvasElement, private events: GameEvents = {}) {}

  start() {
    addEventListener('keydown', this.onKeyDown);
    addEventListener('keyup', this.onKeyUp);
    this.resume();
  }

  destroy() {                                   // всё, что запустили, — останавливаем
    this.pause();
    removeEventListener('keydown', this.onKeyDown);
    removeEventListener('keyup', this.onKeyUp);
  }

  pause() {
    this.running = false;
    cancelAnimationFrame(this.rafId);
  }

  resume() {
    if (this.running) return;                   // защита от второго цикла
    this.running = true;
    this.last = performance.now();
    this.rafId = requestAnimationFrame(this.loop);
  }

  private addScore(n: number) {
    this.score += n;
    this.events.onScore?.(this.score);          // наружу — только события
  }

  private onKeyDown = (e: KeyboardEvent) => this.keys.add(e.code);
  private onKeyUp = (e: KeyboardEvent) => this.keys.delete(e.code);

  private loop = (now: number) => {
    const dt = Math.min((now - this.last) / 1000, 0.1);
    this.last = now;
    this.update(dt);
    this.render();
    if (this.running) this.rafId = requestAnimationFrame(this.loop);
  };

  private update(dt: number) { /* … */ }
  private render() { /* … */ }
}
```

Так игру легко тестировать и переиспользовать, а React-компонент остаётся тонкой обёрткой.

## Компонент-обёртка

```tsx
'use client'; // в Next.js App Router: canvas и rAF есть только в браузере

import { useEffect, useRef, useState } from 'react';
import { Game } from './game/Game';

export function GameCanvas() {
  const canvasRef = useRef<HTMLCanvasElement>(null);
  const gameRef = useRef<Game | null>(null);
  const [score, setScore] = useState(0);
  const [paused, setPaused] = useState(false);
  const [gameOver, setGameOver] = useState<number | null>(null);

  useEffect(() => {
    const game = new Game(canvasRef.current!, {
      onScore: setScore,              // ререндер только при изменении счёта
      onGameOver: setGameOver,
    });
    gameRef.current = game;
    game.start();

    return () => {                    // cleanup: размонтирование и Strict Mode
      game.destroy();
      gameRef.current = null;
    };
  }, []);

  useEffect(() => {
    if (paused) gameRef.current?.pause();
    else gameRef.current?.resume();
  }, [paused]);

  return (
    <div className="relative">
      <canvas ref={canvasRef} width={800} height={450} className="block w-full" />

      {/* интерфейс — обычный React поверх canvas */}
      <div className="absolute left-3 top-3 font-mono text-white">Счёт: {score}</div>
      <button className="absolute right-3 top-3" onClick={() => setPaused((p) => !p)}>
        {paused ? '▶' : '⏸'}
      </button>
      {gameOver !== null && (
        <div className="absolute inset-0 grid place-items-center bg-black/60 text-white">
          Игра окончена: {gameOver}
        </div>
      )}
    </div>
  );
}
```

HUD, меню и модальные окна удобнее делать разметкой React/HTML поверх canvas: доступность, шрифты, вёрстка и кнопки «из коробки».

## Next.js: без SSR

`'use client'` достаточно, если `window` и `canvas` трогаются только в `useEffect`. Если же игровой модуль обращается к `window` при импорте (так делают некоторые библиотеки), отключите SSR для компонента:

```tsx
'use client';
import dynamic from 'next/dynamic';

const GameCanvas = dynamic(() => import('./GameCanvas').then((m) => m.GameCanvas), {
  ssr: false,
  loading: () => <p>Загрузка игры…</p>,
});
```

## Чего не делать

```tsx
// ❌ позиция в state: 60 ререндеров в секунду всего дерева
const [player, setPlayer] = useState({ x: 0, y: 0 });
useEffect(() => {
  const loop = () => {
    setPlayer((p) => ({ ...p, x: p.x + 1 }));
    requestAnimationFrame(loop);         // и id не сохранён — остановить нельзя
  };
  loop();
}, []);

// ❌ игровой объект создаётся в теле компонента — новый при каждом ререндере
const game = new Game(canvas);
```

## Хук для цикла

Для небольших визуализаций без отдельного класса:

```tsx
function useAnimationFrame(callback: (dt: number) => void) {
  const cbRef = useRef(callback);
  cbRef.current = callback;                      // всегда свежий колбэк без перезапуска цикла

  useEffect(() => {
    let id = 0;
    let last = performance.now();
    const loop = (now: number) => {
      cbRef.current(Math.min((now - last) / 1000, 0.1));
      last = now;
      id = requestAnimationFrame(loop);
    };
    id = requestAnimationFrame(loop);
    return () => cancelAnimationFrame(id);
  }, []);
}

function Bouncer() {
  const ref = useRef<HTMLCanvasElement>(null);
  const ball = useRef({ x: 50, vx: 200 });       // изменяемое состояние — в ref

  useAnimationFrame((dt) => {
    const ctx = ref.current!.getContext('2d')!;
    const b = ball.current;
    b.x += b.vx * dt;
    if (b.x < 10 || b.x > 290) b.vx *= -1;
    ctx.clearRect(0, 0, 300, 100);
    ctx.beginPath();
    ctx.arc(b.x, 50, 10, 0, Math.PI * 2);
    ctx.fill();
  });

  return <canvas ref={ref} width={300} height={100} />;
}
```

## Библиотеки с React-интеграцией

- **@pixi/react** — PixiJS-сцена как JSX-дерево, хук `useTick`.
- **React Three Fiber** — Three.js в React, хук `useFrame`.
- **Phaser** — официальный шаблон `create-phaser-game` с React, игра живёт отдельно, общение через EventBus.

## Частые ошибки

- Хранить позиции объектов в `useState` — ререндер каждый кадр.
- Не останавливать цикл в cleanup — после навигации игра продолжает работать в фоне, при возврате — два цикла.
- Подписываться на `window`-события без отписки.
- Передавать в зависимости `useEffect` объекты, которые меняются каждый рендер, — игра пересоздаётся.
- Обращаться к `window`/`document` вне эффектов в Next.js — ошибка при SSR.

## Что важно помнить

- Игровой мир — в классе/ref, не в React state.
- Цикл стартует в `useEffect` и останавливается в cleanup.
- Наружу — события (`onScore`), в React state — только данные для UI.
- HUD и меню удобно делать разметкой поверх canvas.
- В Next.js — `'use client'`, при необходимости `dynamic(…, { ssr: false })`.

## Мини-шпаргалка

```tsx
useEffect(() => {
  const game = new Game(canvasRef.current!, { onScore: setScore });
  game.start();
  return () => game.destroy();
}, []);
```
