# Application — опции init, свойства и методы

> [!NOTE]
> `Application` — удобная обёртка, которая создаёт **рендерер** (WebGL или WebGPU), корневой контейнер **`stage`**, **`ticker`** с циклом отрисовки и, по желанию, следит за размером элемента (`resizeTo`). Создаётся в два шага: `new Application()` + `await app.init(options)`. Главные свойства: `app.canvas` (элемент для DOM), `app.stage`, `app.renderer`, `app.screen` (видимая область), `app.ticker`. Методы: `render()` — отрисовать кадр вручную, `resize()`/`queueResize()` — пересчитать размер, `start()`/`stop()` — запустить или остановить автоматическую отрисовку, `destroy()` — освободить ресурсы. Если нужен полный контроль над циклом (свой фиксированный шаг), отключают `autoStart` и вызывают `app.render()` сами.

## Вопрос

Какие опции, свойства и методы есть у `Application` в PixiJS v8 и как управлять им вручную?

## Опции init

| Опция | Тип / по умолчанию | Назначение |
| --- | --- | --- |
| `width`, `height` | `800`, `600` | размер в CSS-пикселях, если нет `resizeTo` |
| `resizeTo` | `Window \| HTMLElement` | подгонять размер под окно или элемент |
| `background` / `backgroundColor` | `ColorSource`, `'black'` | цвет очистки кадра: `'#1e293b'`, `0x1e293b`, `[0.1, 0.2, 0.3]` |
| `backgroundAlpha` | `1` | прозрачность фона (0 — canvas прозрачный, видно страницу) |
| `antialias` | `false` | сглаживание краёв Graphics и полигонов |
| `resolution` | `1` | плотность пикселей, обычно `Math.min(devicePixelRatio, 2)` |
| `autoDensity` | `false` | CSS-размер canvas = логический размер при `resolution > 1` |
| `roundPixels` | `false` | округлять позиции при отрисовке — чёткий пиксель-арт |
| `preference` | `'webgl'` | `'webgl'` или `'webgpu'` — предпочитаемый рендерер с фолбэком |
| `canvas` | — | использовать существующий `<canvas>` |
| `clearBeforeRender` | `true` | очищать кадр перед отрисовкой |
| `powerPreference` | — | `'high-performance'` / `'low-power'` для выбора GPU |
| `autoStart` | `true` | запустить ticker сразу после init |
| `sharedTicker` | `false` | использовать `Ticker.shared` вместо собственного |
| `eventMode` | `'passive'` | `eventMode` по умолчанию для всех объектов |
| `eventFeatures` | все `true` | `{ move, globalMove, click, wheel }` — отключить ненужные ради производительности |
| `hello` | `false` | вывести в консоль версию PixiJS и тип рендерера |
| `webgl`, `webgpu` | — | опции, которые применяются только к конкретному рендереру |

```ts
import { Application } from 'pixi.js';

const app = new Application();
await app.init({
  resizeTo: document.getElementById('game')!,
  background: '#0f172a',
  antialias: true,
  resolution: Math.min(devicePixelRatio, 2),
  autoDensity: true,
  preference: 'webgpu',
  hello: true,
});
document.getElementById('game')!.appendChild(app.canvas);
```

## Свойства

| Свойство | Что это |
| --- | --- |
| `app.canvas` | `HTMLCanvasElement`, который нужно вставить в DOM |
| `app.stage` | корневой `Container` сцены |
| `app.renderer` | `WebGLRenderer` или `WebGPURenderer` |
| `app.screen` | `Rectangle` видимой области в CSS-пикселях — удобен для позиционирования и `hitArea` |
| `app.ticker` | `Ticker`, который вызывает `render()` каждый кадр |
| `app.resizeTo` | элемент, за размером которого следит приложение (можно поменять) |

```ts
// центр экрана и правый верхний угол — всегда через app.screen
logo.position.set(app.screen.width / 2, app.screen.height / 2);
pauseButton.position.set(app.screen.width - 60, 16);

// какой рендерер выбран
console.log(app.renderer.name);       // 'webgl' | 'webgpu'
```

## Методы

| Метод | Назначение |
| --- | --- |
| `init(options)` | асинхронная инициализация |
| `render()` | отрисовать `stage` один раз |
| `resize()` | немедленно подогнать размер под `resizeTo` |
| `queueResize()` / `cancelResize()` | отложенный ресайз в следующем кадре (так работает слушатель окна) |
| `start()` / `stop()` | запустить или остановить ticker |
| `destroy(rendererOptions?, options?)` | уничтожить приложение |
| `renderer.resize(w, h)` | задать размер вручную |

## Ручная отрисовка

Свой игровой цикл с фиксированным шагом — PixiJS только рисует:

```ts
await app.init({ autoStart: false, resizeTo: window });

const STEP = 1 / 60;
let acc = 0;
let last = performance.now();

function loop(now: number) {
  acc += Math.min((now - last) / 1000, 0.25);
  last = now;
  while (acc >= STEP) { world.update(STEP); acc -= STEP; }
  world.syncSprites(acc / STEP);     // интерполяция позиций спрайтов
  app.render();                      // один кадр
  requestAnimationFrame(loop);
}
requestAnimationFrame(loop);
```

Отрисовка «по требованию» — для редакторов и визуализаций, где ничего не двигается:

```ts
await app.init({ autoStart: false });
function invalidate() { requestAnimationFrame(() => app.render()); }
slider.addEventListener('input', () => { chart.update(slider.value); invalidate(); });
```

## Ресайз

```ts
// событие рендерера — перестроить интерфейс
app.renderer.on('resize', (width: number, height: number) => {
  hud.position.set(width - 200, 16);
  background.setSize(width, height);
});

// сменить элемент, за которым следим
app.resizeTo = otherElement;
app.resize();
```

## Уничтожение

```ts
app.destroy(
  { removeView: true },                                  // удалить canvas из DOM
  { children: true, texture: true, textureSource: true } // уничтожить детей stage и их текстуры
);
```

| Опция второго аргумента | Что уничтожается |
| --- | --- |
| `children` | все объекты внутри `stage` |
| `texture` | `Texture` у спрайтов (осторожно с общими текстурами) |
| `textureSource` | исходные данные текстур на GPU |
| `context` | `GraphicsContext` у Graphics |
| `style` | стили текста |

Ресурсы из `Assets` (кеш) лучше выгружать через `Assets.unload` — иначе повторная загрузка вернёт уничтоженную текстуру.

## Без Application

Application — необязательная обёртка. Можно создать только рендерер:

```ts
import { autoDetectRenderer, Container } from 'pixi.js';

const renderer = await autoDetectRenderer({ width: 800, height: 600, preference: 'webgpu' });
document.body.appendChild(renderer.canvas);
const stage = new Container();

function frame() {
  renderer.render(stage);
  requestAnimationFrame(frame);
}
requestAnimationFrame(frame);
```

## Частые ошибки

- Использовать `app.canvas`, `app.renderer` до завершения `await app.init()`.
- Задавать `resolution: devicePixelRatio` без ограничения — на телефонах с dpr 3 в 9 раз больше пикселей.
- Забыть `autoDensity` при `resolution > 1` — canvas на странице становится в 2 раза больше.
- Вызывать `app.render()` при включённом `autoStart` — двойная отрисовка каждого кадра.
- Использовать `app.view` из v7 — в v8 это `app.canvas`.

## Что важно помнить

- `new Application()` → `await app.init({...})` → `appendChild(app.canvas)`.
- `stage`, `renderer`, `screen`, `ticker`, `canvas` — главные свойства.
- `autoStart: false` + `app.render()` — свой цикл или отрисовка по требованию.
- `destroy({ removeView: true }, { children: true })` при уходе со страницы.

## Мини-шпаргалка

```ts
await app.init({ resizeTo: window, background: '#000', resolution: 2, autoDensity: true });
app.screen.width; app.renderer.name;
app.stop(); app.start(); app.render();
app.renderer.on('resize', (w, h) => {});
app.destroy({ removeView: true }, { children: true });
```
