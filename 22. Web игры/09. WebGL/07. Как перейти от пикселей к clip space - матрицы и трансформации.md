# Как перейти от пикселей к clip space — матрицы и трансформации

> [!NOTE]
> В игре удобно думать в пикселях: «спрайт 64×64 в точке (300, 200), повёрнут на 30°». Шейдеру же нужен clip space от −1 до 1. Мост между ними — **матрицы**. Для 2D достаточно матриц 3×3 (`mat3`): **модельная** матрица переносит, поворачивает и масштабирует объект, **матрица камеры** (view) сдвигает и приближает мир, а **проекционная** переводит пиксели в clip space и переворачивает ось `y`. Перемножив их один раз на CPU (`projection × view × model`), отправляем результат в шейдер uniform-ом, и шейдер делает одно умножение на вершину: `(uMatrix * vec3(aPosition, 1.0)).xy`. Порядок умножения важен — матрицы применяются справа налево. В 3D то же самое с `mat4`, а проекция бывает перспективной; готовые функции даёт библиотека **gl-matrix**.

## Вопрос

Как в WebGL перевести координаты в пикселях в clip space и как с помощью матриц двигать, вращать и масштабировать объекты?

## Простой способ: формула в шейдере

```glsl
#version 300 es
in vec2 aPosition;            // в пикселях
uniform vec2 uResolution;     // размер canvas

void main() {
  vec2 zeroToOne = aPosition / uResolution;       // 0..1
  vec2 clip = zeroToOne * 2.0 - 1.0;              // -1..1
  gl_Position = vec4(clip * vec2(1, -1), 0, 1);   // y вниз, как в canvas 2D
}
```

Для неподвижных прямоугольников этого хватает, но для вращения, масштаба и камеры удобнее матрицы.

## Матрицы 3×3 для 2D

Точка `(x, y)` записывается как `(x, y, 1)` — третья единица позволяет выразить перенос умножением.

```text
перенос T(tx, ty)     поворот R(a)              масштаб S(sx, sy)
| 1  0  tx |          | cos -sin  0 |           | sx 0  0 |
| 0  1  ty |          | sin  cos  0 |           | 0  sy 0 |
| 0  0  1  |          | 0    0    1 |           | 0  0  1 |
```

WebGL хранит матрицы **по столбцам** (column-major): массив из 9 чисел — это столбец 1, столбец 2, столбец 3.

```ts
type Mat3 = Float32Array;

export const m3 = {
  identity: (): Mat3 => new Float32Array([1, 0, 0, 0, 1, 0, 0, 0, 1]),

  // пиксели → clip space, y вниз
  projection: (w: number, h: number): Mat3 => new Float32Array([
    2 / w, 0, 0,
    0, -2 / h, 0,
    -1, 1, 1,
  ]),

  translation: (tx: number, ty: number): Mat3 => new Float32Array([1, 0, 0, 0, 1, 0, tx, ty, 1]),

  rotation: (a: number): Mat3 => {
    const c = Math.cos(a), s = Math.sin(a);
    return new Float32Array([c, s, 0, -s, c, 0, 0, 0, 1]);
  },

  scaling: (sx: number, sy: number): Mat3 => new Float32Array([sx, 0, 0, 0, sy, 0, 0, 0, 1]),

  // a × b
  multiply: (a: Mat3, b: Mat3): Mat3 => {
    const out = new Float32Array(9);
    for (let col = 0; col < 3; col++) {
      for (let row = 0; row < 3; row++) {
        out[col * 3 + row] =
          a[0 * 3 + row] * b[col * 3 + 0] +
          a[1 * 3 + row] * b[col * 3 + 1] +
          a[2 * 3 + row] * b[col * 3 + 2];
      }
    }
    return out;
  },
};
```

## Шейдер с матрицей

```glsl
#version 300 es
layout(location = 0) in vec2 aPosition;   // локальные координаты квада: -0.5..0.5
layout(location = 1) in vec2 aUV;
uniform mat3 uMatrix;
out vec2 vUV;

void main() {
  vUV = aUV;
  vec2 pos = (uMatrix * vec3(aPosition, 1.0)).xy;
  gl_Position = vec4(pos, 0.0, 1.0);
}
```

## Сборка матрицы спрайта

```ts
function spriteMatrix(
  sprite: { x: number; y: number; rotation: number; width: number; height: number },
  camera: { x: number; y: number; zoom: number },
) {
  // читается справа налево: масштаб → поворот → перенос → камера → проекция
  let m = m3.projection(canvas.width, canvas.height);
  m = m3.multiply(m, m3.scaling(camera.zoom, camera.zoom));
  m = m3.multiply(m, m3.translation(-camera.x, -camera.y));
  m = m3.multiply(m, m3.translation(sprite.x, sprite.y));
  m = m3.multiply(m, m3.rotation(sprite.rotation));
  m = m3.multiply(m, m3.scaling(sprite.width, sprite.height)); // квад 1×1 → размер спрайта
  return m;
}

gl.uniformMatrix3fv(uMatrix, false, spriteMatrix(hero, camera));
gl.drawElements(gl.TRIANGLES, 6, gl.UNSIGNED_SHORT, 0);
```

Сравните с canvas 2D: `ctx.translate(x, y); ctx.rotate(a); ctx.scale(w, h)` — тот же порядок, только в canvas матрицу контекста перемножает браузер.

## Почему порядок важен

```text
перенос, затем поворот:   объект вращается вокруг начала координат (летит по дуге)
поворот, затем перенос:   объект вращается вокруг своего центра
```

Матрица, ближайшая к вектору (справа), применяется первой. Поэтому `scale` и `rotation` объекта стоят правее `translation`.

## Иерархия

```ts
// мир → танк → башня
const tankWorld = m3.multiply(m3.translation(tank.x, tank.y), m3.rotation(tank.angle));
const turretWorld = m3.multiply(tankWorld, m3.rotation(turret.angle)); // родитель × локальная
```

Именно так устроен `worldTransform` в PixiJS и `matrixWorld` в Three.js.

## Экран → мир

Чтобы понять, куда в мире кликнули, нужна **обратная** матрица:

```ts
import { mat3, vec2 } from 'gl-matrix';

const viewProj = mat3.create();
mat3.multiply(viewProj, projection, view);
const inv = mat3.invert(mat3.create(), viewProj)!;

// пиксели canvas → clip space → мир
const clipX = (mouseX / canvas.clientWidth) * 2 - 1;
const clipY = -((mouseY / canvas.clientHeight) * 2 - 1);
const world = vec2.transformMat3(vec2.create(), [clipX, clipY], inv);
```

## gl-matrix и 3D

```ts
import { mat4 } from 'gl-matrix';

const projection = mat4.perspective(mat4.create(), (60 * Math.PI) / 180, w / h, 0.1, 100);
const view = mat4.lookAt(mat4.create(), [3, 3, 5], [0, 0, 0], [0, 1, 0]);
const model = mat4.fromYRotation(mat4.create(), time);

const mvp = mat4.create();
mat4.multiply(mvp, projection, view);
mat4.multiply(mvp, mvp, model);
gl.uniformMatrix4fv(uMVP, false, mvp);
```

```glsl
uniform mat4 uMVP;
in vec3 aPosition;
void main() { gl_Position = uMVP * vec4(aPosition, 1.0); }
```

В 3D `gl_Position.w` после перспективы не равен 1 — GPU делит `xyz` на `w` («перспективное деление»), из-за этого дальние объекты меньше.

## Частые ошибки

- Перепутать порядок умножения — объект вращается вокруг угла экрана.
- Передать матрицу по строкам (row-major) — всё искажается; WebGL ждёт столбцы, `transpose` должен быть `false`.
- Пересчитывать проекцию для каждого спрайта вместо одного раза за кадр.
- Создавать `new Float32Array` для каждой матрицы каждый кадр в горячем цикле — лишний мусор (у gl-matrix есть функции с `out`).
- Забыть инвертировать `y` в проекции — изображение вверх ногами.

## Что важно помнить

- 2D — `mat3` и однородные координаты `(x, y, 1)`, 3D — `mat4`.
- Итог: `projection × view × model`, применяется справа налево.
- Порядок модели: масштаб → поворот → перенос.
- Иерархия = произведение матриц родителей; экран → мир — обратная матрица.
- Готовые функции — gl-matrix.

## Мини-шпаргалка

```glsl
gl_Position = vec4((uMatrix * vec3(aPosition, 1.0)).xy, 0.0, 1.0);
```
