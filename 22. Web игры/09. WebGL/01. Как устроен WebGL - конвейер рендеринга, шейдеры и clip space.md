# Как устроен WebGL — конвейер рендеринга, шейдеры и clip space

> [!NOTE]
> WebGL — JavaScript-API к видеокарте на основе OpenGL ES (WebGL 2 = OpenGL ES 3.0). Он **не умеет рисовать** «прямоугольники» или «спрайты» — только точки, линии и **треугольники**. Вы загружаете на GPU данные (координаты вершин, цвета, текстуры) и две маленькие программы — **шейдеры** на языке GLSL. **Вершинный шейдер** выполняется для каждой вершины и возвращает её позицию в **clip space** — координатах от −1 до 1 по каждой оси. GPU собирает треугольники, отсекает невидимое и **растеризует** их — определяет, какие пиксели покрыты. **Фрагментный шейдер** выполняется для каждого такого пикселя и возвращает его цвет. Шейдеры работают параллельно на тысячах ядер GPU — поэтому WebGL так быстр, но поэтому же каждый шаг нужно настраивать вручную.

## Вопрос

Как устроен WebGL изнутри: что такое конвейер рендеринга, вершинный и фрагментный шейдеры и clip space?

## Конвейер рендеринга

```text
JavaScript (CPU)                           GPU
─────────────────                          ──────────────────────────────────────────────
буферы с вершинами  ──► вершинный шейдер ──► сборка треугольников ──► растеризация
uniforms (время,         (для каждой          + отсечение по            (какие пиксели
матрицы, цвета)          вершины →            clip space               покрыты)
текстуры                 gl_Position)                                      │
                                                                           ▼
                         кадр на экране ◄── смешивание, тест глубины ◄── фрагментный шейдер
                                            (blending, depth)          (для каждого пикселя → цвет)
```

Программируемые этапы — только два шейдера. Остальное (сборка, растеризация, смешивание) — фиксированные блоки, которые настраиваются вызовами `gl.enable`, `gl.blendFunc` и т.п.

## Clip space

```text
            y = 1
              ▲
              │
 x = -1 ──────┼──────► x = 1
              │
              │
            y = -1
```

- Координаты всегда от −1 до 1, независимо от размера canvas.
- `y` направлен **вверх** (в canvas 2D — вниз).
- Всё за пределами куба [−1, 1] отсекается.
- Перевод «пиксели → clip space» делается в вершинном шейдере (обычно матрицей).

## Шейдеры на примере треугольника

```glsl
#version 300 es
// вершинный шейдер: выполняется 3 раза — по разу на вершину
in vec2 aPosition;             // атрибут: свои данные для каждой вершины
in vec3 aColor;
out vec3 vColor;               // varying: передаём во фрагментный шейдер

void main() {
  vColor = aColor;
  gl_Position = vec4(aPosition, 0.0, 1.0); // обязательный выход: позиция в clip space
}
```

```glsl
#version 300 es
// фрагментный шейдер: выполняется для каждого пикселя треугольника
precision mediump float;
in vec3 vColor;                // интерполированное значение между вершинами
out vec4 outColor;

void main() {
  outColor = vec4(vColor, 1.0);  // RGBA, каждый канал от 0 до 1
}
```

Если у трёх вершин цвета красный, зелёный и синий, пиксели между ними получат **плавный градиент**: значения `out`-переменных вершинного шейдера автоматически интерполируются по поверхности треугольника.

## Три вида входных данных

| Вид | Что это | Пример |
| --- | --- | --- |
| **Attribute** (`in` в вершинном) | своё значение у каждой вершины, берётся из буфера | позиция, UV, цвет вершины |
| **Uniform** | одно значение на весь вызов отрисовки | время, матрица камеры, цвет, разрешение |
| **Texture** (`sampler2D`) | картинка, из которой читают в шейдере | спрайт, атлас, карта нормалей |
| **Varying** (`out` → `in`) | из вершинного во фрагментный, с интерполяцией | UV-координаты, цвет |

## Порядок работы любой WebGL-программы

```text
Инициализация (один раз)
1. canvas.getContext('webgl2')
2. скомпилировать шейдеры, слинковать программу
3. создать буферы и загрузить в них вершины
4. описать, как атрибуты читают буферы (VAO)
5. загрузить текстуры

Каждый кадр
6. gl.viewport, gl.clear
7. gl.useProgram, gl.bindVertexArray
8. установить uniforms (время, матрицы)
9. gl.drawArrays / gl.drawElements  ← draw call
```

## Почему WebGL быстрый и почему он сложный

- Вершинный и фрагментный шейдеры выполняются **параллельно**: миллион пикселей обрабатывается одновременно.
- Данные живут на GPU: если не менять буферы, CPU почти не работает.
- Каждый **draw call** — дорогая команда от CPU к GPU, поэтому объекты собирают в один буфер (батчинг) или рисуют инстансингом.
- Но нет ничего «высокоуровневого»: текст, спрайты, иерархия, события, загрузка — всё пишете сами или берёте PixiJS/Three.js.

## WebGL 1 и WebGL 2

| | WebGL 1 | WebGL 2 |
| --- | --- | --- |
| Основа | OpenGL ES 2.0 | OpenGL ES 3.0 |
| GLSL | `attribute`, `varying`, `gl_FragColor` | `#version 300 es`, `in`/`out` |
| VAO, инстансинг | через расширения | встроены |
| Текстуры | только степени двойки для mipmap/repeat | любые размеры, 3D-текстуры, массивы текстур |
| Поддержка | везде | практически везде (с 2021 года и в Safari) |

Новый код стоит писать на WebGL 2 — все примеры раздела используют его.

## Частые ошибки

- Ожидать координаты в пикселях — вершинный шейдер должен выдать clip space (−1..1).
- Забыть, что `y` в clip space направлен вверх.
- Путать attribute (на вершину) и uniform (на весь вызов отрисовки).
- Писать WebGL с нуля там, где хватает PixiJS или Three.js.

## Что важно помнить

- WebGL рисует только треугольники (и точки/линии).
- Вершинный шейдер → `gl_Position` в clip space, фрагментный → цвет пикселя.
- Входные данные: атрибуты, uniforms, текстуры; между шейдерами — varying с интерполяцией.
- Инициализация один раз, в кадре — `clear`, `useProgram`, uniforms, `draw*`.

## Мини-шпаргалка

```text
vertex:   in → gl_Position (clip space −1..1)
fragment: in (интерполированные) → out vec4 color
attribute = на вершину, uniform = на draw call, sampler2D = текстура
```
