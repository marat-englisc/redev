# Как отлаживать WebGL — ошибки, потеря контекста и Spector.js

> [!NOTE]
> Самая неприятная особенность WebGL — ошибки **молчаливые**: неправильный вызов не бросает исключение, а просто ничего не рисует и ставит флаг, который читается через `gl.getError()`. Поэтому при разработке проверяют логи компиляции шейдеров, `getError` после подозрительных вызовов и `checkFramebufferStatus`, а для «почему чёрный экран» снимают кадр в **Spector.js** — он показывает каждый вызов, состояние, текстуры и содержимое буферов. Второй важный сценарий — **потеря контекста** (`webglcontextlost`): GPU сбросился, вкладка ушла в фон на мобильном, превышен лимит контекстов. Все ресурсы GPU пропадают, и приложение должно уметь их пересоздать по `webglcontextrestored`. Перед выпуском проверяют лимиты устройства (`MAX_TEXTURE_SIZE`) и нужные расширения.

## Вопрос

Как искать ошибки в WebGL, что делать при потере контекста и какие инструменты помогают в отладке?

## «Ничего не рисуется»: чек-лист

1. Шейдеры скомпилировались? Проверены `COMPILE_STATUS` и `LINK_STATUS`, прочитаны логи.
2. Вызван `gl.viewport` с размером буфера canvas?
3. Вершины в clip space (−1..1)? Попробуйте временно выводить `gl_Position = vec4(aPosition * 0.1, 0, 1)`.
4. Включены атрибуты (`enableVertexAttribArray`), привязан нужный VAO, верны `stride`/`offset` в байтах?
5. Привязана программа (`useProgram`) до установки uniforms?
6. Текстура загружена, у неё нет mipmap-требования без mipmaps, слот и `uniform1i` совпадают?
7. Не включено ли `CULL_FACE` при «не том» обходе вершин?
8. Альфа не нулевая? Попробуйте во фрагментном шейдере `outColor = vec4(1, 0, 1, 1)` — ярко-розовый покажет, растеризуются ли треугольники.
9. Не забыт ли `bindFramebuffer(null)` — может, рисуете в текстуру, а не на экран?
10. `gl.getError()` после проблемного места.

## getError

```ts
const errors: Record<number, string> = {
  [WebGL2RenderingContext.INVALID_ENUM]: 'INVALID_ENUM',
  [WebGL2RenderingContext.INVALID_VALUE]: 'INVALID_VALUE',
  [WebGL2RenderingContext.INVALID_OPERATION]: 'INVALID_OPERATION',
  [WebGL2RenderingContext.INVALID_FRAMEBUFFER_OPERATION]: 'INVALID_FRAMEBUFFER_OPERATION',
  [WebGL2RenderingContext.OUT_OF_MEMORY]: 'OUT_OF_MEMORY',
  [WebGL2RenderingContext.CONTEXT_LOST_WEBGL]: 'CONTEXT_LOST_WEBGL',
};

function check(gl: WebGL2RenderingContext, label: string) {
  if (!import.meta.env.DEV) return;                 // только в разработке
  let err: number;
  while ((err = gl.getError()) !== gl.NO_ERROR) {
    console.error(`[WebGL] ${label}: ${errors[err] ?? err}`);
  }
}

gl.drawElements(gl.TRIANGLES, 6, gl.UNSIGNED_SHORT, 0);
check(gl, 'draw sprites');
```

> [!WARNING]
> `getError` синхронизирует CPU и GPU и сильно замедляет отрисовку. Используйте только в режиме разработки.

Браузер также пишет предупреждения WebGL в консоль: `GL_INVALID_OPERATION: glDrawElements: Insufficient buffer size`, `texture bound to texture unit 0 is not renderable` — их стоит читать в первую очередь.

## Spector.js

Расширение для Chrome/Firefox (или npm-пакет `spectorjs`), которое «захватывает» один кадр:

- список всех вызовов WebGL по порядку с аргументами;
- состояние контекста на каждом вызове (blend, depth, привязанные буферы);
- содержимое текстур и framebuffer после каждого draw call;
- исходники шейдеров и значения uniforms;
- количество draw calls — сразу видно, работает ли батчинг.

```ts
// программный захват в нужный момент
import { Spector } from 'spectorjs';
const spector = new Spector();
spector.displayUI();
spector.captureCanvas(canvas);
```

Для PixiJS дополнительно есть **PixiJS DevTools**, для Three.js — расширение **three.js devtools**.

## Потеря контекста

```ts
canvas.addEventListener('webglcontextlost', (e) => {
  e.preventDefault();          // без этого контекст не будет восстановлен
  cancelAnimationFrame(rafId); // все gl-объекты стали недействительны
  showMessage('Восстанавливаем графику…');
});

canvas.addEventListener('webglcontextrestored', () => {
  initGL();                    // заново: программы, буферы, текстуры, framebuffers
  rafId = requestAnimationFrame(frame);
  hideMessage();
});
```

Поэтому полезно хранить **исходные данные** ресурсов (URL текстур, массивы вершин), чтобы их можно было загрузить повторно. PixiJS и Three.js умеют восстанавливаться сами.

Проверить обработку можно искусственно:

```ts
const ext = gl.getExtension('WEBGL_lose_context')!;
ext.loseContext();
setTimeout(() => ext.restoreContext(), 1000);
```

## Лимиты и расширения

```ts
console.table({
  renderer: gl.getParameter(gl.RENDERER),
  maxTextureSize: gl.getParameter(gl.MAX_TEXTURE_SIZE),           // часто 4096–16384
  maxTextureUnits: gl.getParameter(gl.MAX_TEXTURE_IMAGE_UNITS),   // обычно 16
  maxVertexAttribs: gl.getParameter(gl.MAX_VERTEX_ATTRIBS),       // обычно 16
  maxSamples: gl.getParameter(gl.MAX_SAMPLES),                    // MSAA
});

// реальное имя видеокарты (если браузер разрешает)
const dbg = gl.getExtension('WEBGL_debug_renderer_info');
if (dbg) console.log(gl.getParameter(dbg.UNMASKED_RENDERER_WEBGL));

// расширения — проверять перед использованием
const floatRT = gl.getExtension('EXT_color_buffer_float');       // рендер во float-текстуры (HDR, bloom)
const anisotropic = gl.getExtension('EXT_texture_filter_anisotropic');
const astc = gl.getExtension('WEBGL_compressed_texture_astc');    // сжатые текстуры на мобильных
```

Атлас 8192×8192 откроется на ПК, но на части телефонов не загрузится — держите атласы до 4096 или проверяйте `MAX_TEXTURE_SIZE`.

## Производительность: что измерять

| Симптом | Где искать |
| --- | --- |
| Высокое время JS в кадре | Chrome Performance: обновление объектов, сборка батчей, GC |
| Много draw calls | Spector.js: батчинг прерывается текстурами или состоянием |
| Тормозит только на большом экране | фрагментный шейдер: снизить `dpr`, упростить эффекты, уменьшить overdraw |
| Фризы при появлении новых объектов | компиляция шейдеров или загрузка текстур во время игры — делайте заранее (PixiJS `prepare`) |
| Память растёт | не вызываются `deleteTexture`/`deleteBuffer` |

**Overdraw** — сколько раз за кадр перекрашивается один и тот же пиксель (большие полупрозрачные спрайты друг на друге). На мобильных это частая причина низкого FPS.

## Частые ошибки

- Оставлять `getError` в продакшене — потеря производительности.
- Не обрабатывать `webglcontextlost` — после сна телефона игра показывает чёрный экран.
- Не вызывать `preventDefault()` в `webglcontextlost` — контекст не восстановится.
- Использовать расширение без проверки на `null`.
- Рассчитывать на огромные текстуры и много слотов, проверив только на своём ПК.

## Что важно помнить

- Ошибки WebGL молчаливые: проверяйте логи шейдеров, `getError` (в dev), консоль браузера.
- Spector.js — лучший инструмент для «почему ничего не рисуется» и подсчёта draw calls.
- Потеря контекста неизбежна: `preventDefault` + пересоздание ресурсов по `webglcontextrestored`.
- Проверяйте лимиты (`MAX_TEXTURE_SIZE`) и расширения на целевых устройствах.

## Мини-шпаргалка

```ts
gl.getError();                               // только dev
gl.getShaderInfoLog(shader);
canvas.addEventListener('webglcontextlost', (e) => e.preventDefault());
gl.getExtension('WEBGL_lose_context')!.loseContext();
gl.getParameter(gl.MAX_TEXTURE_SIZE);
```
