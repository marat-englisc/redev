# Как работают смешивание, глубина и состояние WebGL

> [!NOTE]
> WebGL — **машина состояний**: `enable`, `blendFunc`, `bindTexture`, `useProgram`, `bindFramebuffer` меняют глобальное состояние контекста, и оно действует на все следующие вызовы, пока его не поменяют. Для прозрачности включают **смешивание** `gl.enable(gl.BLEND)` и задают формулу `blendFunc(src, dst)`: для обычных PNG с премультиплицированной альфой — `ONE, ONE_MINUS_SRC_ALPHA`, для свечения и огня — аддитивное `ONE, ONE`. Для 3D включают **тест глубины** `gl.enable(gl.DEPTH_TEST)`: ближний пиксель перекрывает дальний независимо от порядка рисования; полупрозрачные объекты всё равно рисуют после непрозрачных и от дальних к ближним. **Отсечение граней** `CULL_FACE` не рисует задние стороны треугольников. Смена состояния стоит времени, поэтому объекты сортируют так, чтобы менять его реже.

## Вопрос

Как в WebGL работает прозрачность, тест глубины и отсечение граней, и почему WebGL называют машиной состояний?

## Смешивание (blending)

Итоговый цвет пикселя считается так: `result = src × srcFactor + dst × dstFactor`, где `src` — цвет из фрагментного шейдера, `dst` — то, что уже лежит в буфере.

```ts
gl.enable(gl.BLEND);

// обычная прозрачность для премультиплицированной альфы (PixiJS по умолчанию)
gl.blendFunc(gl.ONE, gl.ONE_MINUS_SRC_ALPHA);

// обычная прозрачность для «прямой» (straight) альфы
gl.blendFunc(gl.SRC_ALPHA, gl.ONE_MINUS_SRC_ALPHA);

// аддитивное — огонь, искры, свечение, «lighter» в canvas 2D
gl.blendFunc(gl.ONE, gl.ONE);

// умножение — тени, затемнение
gl.blendFunc(gl.DST_COLOR, gl.ZERO);

// отдельные формулы для RGB и альфы
gl.blendFuncSeparate(gl.SRC_ALPHA, gl.ONE_MINUS_SRC_ALPHA, gl.ONE, gl.ONE_MINUS_SRC_ALPHA);

// операция: сложение (по умолчанию), вычитание, min, max
gl.blendEquation(gl.FUNC_ADD);
gl.blendEquation(gl.MAX);
```

| Режим PixiJS / canvas | `blendFunc` (premultiplied) |
| --- | --- |
| `normal` / `source-over` | `ONE, ONE_MINUS_SRC_ALPHA` |
| `add` / `lighter` | `ONE, ONE` |
| `multiply` | `DST_COLOR, ONE_MINUS_SRC_ALPHA` |
| `screen` | `ONE, ONE_MINUS_SRC_COLOR` |

Более сложные режимы (`overlay`, `color-dodge`) формулой `blendFunc` не выражаются — их делают шейдером с чтением фона из текстуры (так работают `advanced-blend-modes` в PixiJS).

## Премультиплицированная альфа

```text
straight:       (r, g, b, a)         = (1.0, 0.0, 0.0, 0.5) — красный, полупрозрачный
premultiplied:  (r·a, g·a, b·a, a)   = (0.5, 0.0, 0.0, 0.5)
```

Премультиплицированная альфа даёт правильные края при фильтрации текстур (без тёмных ореолов) и единую формулу для обычного и аддитивного смешивания. Её включают при загрузке: `gl.pixelStorei(gl.UNPACK_PREMULTIPLY_ALPHA_WEBGL, true)`. Главное — чтобы режим загрузки текстур совпадал с `blendFunc`.

## Тест глубины (3D)

```ts
gl.enable(gl.DEPTH_TEST);
gl.depthFunc(gl.LEQUAL);                 // пройти, если ближе или так же
gl.clearDepth(1.0);

// каждый кадр очищаем и цвет, и глубину
gl.clear(gl.COLOR_BUFFER_BIT | gl.DEPTH_BUFFER_BIT);
```

Буфер глубины хранит для каждого пикселя расстояние до ближайшего уже нарисованного объекта. Фрагмент дальше этого значения отбрасывается. Требует `depth: true` в опциях контекста (по умолчанию так и есть).

### Прозрачность + глубина

```ts
// 1. непрозрачные объекты — в любом порядке (лучше спереди назад: меньше лишней работы)
gl.disable(gl.BLEND);
gl.depthMask(true);
drawOpaque();

// 2. прозрачные — от дальних к ближним, не записывая глубину
gl.enable(gl.BLEND);
gl.depthMask(false);           // читаем глубину, но не пишем — прозрачные не перекрывают друг друга
transparent.sort((a, b) => b.distance - a.distance);
drawTransparent();
gl.depthMask(true);
```

В 2D-играх глубина обычно не нужна: порядок слоёв задаётся порядком отрисовки (painter's algorithm).

## Отсечение граней

```ts
gl.enable(gl.CULL_FACE);
gl.cullFace(gl.BACK);          // не рисовать задние грани
gl.frontFace(gl.CCW);          // лицевая — с обходом вершин против часовой стрелки
```

Для закрытых 3D-моделей это вдвое уменьшает число растеризуемых треугольников. Для 2D-спрайтов, отражённых `scale.x = -1`, отсечение выключают — иначе отзеркаленный спрайт пропадёт.

## Scissor и stencil

```ts
// scissor: рисовать только в прямоугольнике (в пикселях от левого нижнего угла)
gl.enable(gl.SCISSOR_TEST);
gl.scissor(x, canvas.height - y - h, w, h);
drawMinimap();
gl.disable(gl.SCISSOR_TEST);
```

**Stencil buffer** — маска произвольной формы: сначала рисуем фигуру маски, записывая в stencil, потом рисуем содержимое только там, где stencil совпадает. Так PixiJS реализует маски из `Graphics`. Требует `stencil: true` в опциях контекста.

## Машина состояний

```text
состояние контекста
├── текущая программа        useProgram
├── VAO                      bindVertexArray
├── буферы                   bindBuffer(ARRAY_BUFFER / ELEMENT_ARRAY_BUFFER / UNIFORM_BUFFER)
├── текстуры в слотах 0..15  activeTexture + bindTexture
├── framebuffer              bindFramebuffer
├── viewport, scissor
├── blend, depth, cull, stencil — enable/disable + параметры
└── clearColor, pixelStorei…
```

Проблемы, которые из этого следуют:

- Функция, которая «случайно» оставила `BLEND` выключенным или привязала другой framebuffer, ломает отрисовку дальше — состояние «протекает».
- Если на одном контексте работают две библиотеки (например, свой WebGL-код внутри PixiJS), после своего кода нужно восстановить состояние — в PixiJS есть `renderer.resetState()`.
- Смена программы и текстуры — самые дорогие изменения. Рендереры сортируют объекты по программе → текстуре → режиму смешивания.

```ts
// сортировка «по состоянию» перед отрисовкой
drawList.sort((a, b) =>
  a.programId - b.programId || a.textureId - b.textureId || a.blendMode - b.blendMode);
```

## Частые ошибки

- Включить смешивание и не задать `blendFunc` под формат альфы — тёмные или светлые ореолы вокруг спрайтов.
- Рисовать прозрачные объекты до непрозрачных с включённой записью глубины — за стеклом «пропадают» объекты.
- Забыть очистить `DEPTH_BUFFER_BIT` — на следующем кадре ничего не рисуется.
- Оставить `CULL_FACE` включённым для отражённых спрайтов.
- Не восстановить состояние после своего кода внутри чужого рендерера.

## Что важно помнить

- WebGL — машина состояний: каждый `enable`/`bind` действует до следующего изменения.
- Прозрачность: `enable(BLEND)` + `blendFunc`, обычный режим для premultiplied — `ONE, ONE_MINUS_SRC_ALPHA`, аддитивный — `ONE, ONE`.
- 3D: `DEPTH_TEST`, очистка глубины, прозрачные — после непрозрачных, от дальних к ближним, без записи глубины.
- Минимизируйте смены программы и текстуры сортировкой.

## Мини-шпаргалка

```ts
gl.enable(gl.BLEND); gl.blendFunc(gl.ONE, gl.ONE_MINUS_SRC_ALPHA);
gl.blendFunc(gl.ONE, gl.ONE); // add
gl.enable(gl.DEPTH_TEST); gl.clear(gl.COLOR_BUFFER_BIT | gl.DEPTH_BUFFER_BIT);
gl.depthMask(false);
gl.enable(gl.CULL_FACE); gl.cullFace(gl.BACK);
```
