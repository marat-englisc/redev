# Как организовать сцены и состояния игры

> [!NOTE]
> Игра состоит из **сцен** (экранов): меню, уровень, пауза, game over. У каждой сцены свои `enter`, `exit`, `update` и `draw`, а **менеджер сцен** хранит текущую и переключает их. Часто используют **стек сцен**: пауза кладётся поверх уровня, уровень под ней не обновляется, но продолжает рисоваться, а снятие паузы возвращает игру ровно в то же состояние. Внутри объектов поведение удобно описывать **конечным автоматом** (FSM): у врага состояния `patrol → chase → attack`, и каждое состояние знает, в какое переходить. Это убирает лавину `if`-флагов вида `isJumping && !isAttacking && wasHit`.

## Вопрос

Как организовать в игре экраны (меню, уровень, пауза) и поведение объектов, чтобы код не превратился в набор флагов?

## Интерфейс сцены

```ts
export interface Scene {
  enter?(data?: unknown): void;   // вход: создать объекты, подписаться
  exit?(): void;                  // выход: отписаться, остановить звук
  update(dt: number): void;
  draw(ctx: CanvasRenderingContext2D): void;
  /** true — сцена под ней тоже рисуется (полупрозрачная пауза) */
  transparent?: boolean;
}
```

## Стек сцен

```ts
export class SceneManager {
  private stack: Scene[] = [];

  /** заменить всё на новую сцену */
  switch(scene: Scene, data?: unknown) {
    while (this.stack.length) this.stack.pop()!.exit?.();
    this.push(scene, data);
  }

  push(scene: Scene, data?: unknown) {
    this.stack.push(scene);
    scene.enter?.(data);
  }

  pop() {
    this.stack.pop()?.exit?.();
  }

  update(dt: number) {
    this.stack.at(-1)?.update(dt);          // обновляется только верхняя
  }

  draw(ctx: CanvasRenderingContext2D) {
    // ищем самую нижнюю сцену, которую видно
    let start = this.stack.length - 1;
    while (start > 0 && this.stack[start].transparent) start--;
    for (let i = start; i < this.stack.length; i++) this.stack[i].draw(ctx);
  }
}
```

## Сцены

```ts
class MenuScene implements Scene {
  constructor(private game: Game) {}
  update() {
    if (this.game.input.pressed('Enter')) this.game.scenes.switch(new LevelScene(this.game), { level: 1 });
  }
  draw(ctx: CanvasRenderingContext2D) {
    ctx.fillStyle = '#0f172a';
    ctx.fillRect(0, 0, 800, 450);
    ctx.fillStyle = 'white';
    ctx.textAlign = 'center';
    ctx.fillText('Нажмите Enter', 400, 225);
  }
}

class LevelScene implements Scene {
  private world!: World;
  constructor(private game: Game) {}

  enter(data: { level: number }) {
    this.world = createLevel(data.level);
  }
  update(dt: number) {
    if (this.game.input.pressed('Escape')) return this.game.scenes.push(new PauseScene(this.game));
    this.world.update(dt);
    if (this.world.player.hp <= 0) this.game.scenes.switch(new GameOverScene(this.game), { score: this.world.score });
  }
  draw(ctx: CanvasRenderingContext2D) {
    this.world.draw(ctx);
  }
}

class PauseScene implements Scene {
  transparent = true;                       // уровень виден под затемнением
  constructor(private game: Game) {}
  update() {
    if (this.game.input.pressed('Escape')) this.game.scenes.pop();
  }
  draw(ctx: CanvasRenderingContext2D) {
    ctx.fillStyle = 'rgb(0 0 0 / 0.5)';
    ctx.fillRect(0, 0, 800, 450);
    ctx.fillStyle = 'white';
    ctx.fillText('ПАУЗА', 400, 225);
  }
}
```

Пауза работает сама собой: пока сверху лежит `PauseScene`, `LevelScene.update` не вызывается.

## Конечный автомат для объекта

```ts
type EnemyState = 'patrol' | 'chase' | 'attack' | 'hurt';

class Guard extends Entity {
  state: EnemyState = 'patrol';
  stateTime = 0;

  setState(next: EnemyState) {
    if (next === this.state) return;
    this.state = next;
    this.stateTime = 0;              // время в текущем состоянии
  }

  update(dt: number, world: World) {
    this.stateTime += dt;
    const dist = Math.hypot(world.player.x - this.x, world.player.y - this.y);

    switch (this.state) {
      case 'patrol':
        this.vx = Math.sin(this.stateTime) * 60;
        if (dist < 200) this.setState('chase');
        break;
      case 'chase':
        this.vx = Math.sign(world.player.x - this.x) * 140;
        if (dist < 30) this.setState('attack');
        else if (dist > 300) this.setState('patrol');
        break;
      case 'attack':
        this.vx = 0;
        if (this.stateTime > 0.4) {          // атака длится 0,4 с
          if (dist < 40) world.player.hit(1);
          this.setState('chase');
        }
        break;
      case 'hurt':
        if (this.stateTime > 0.3) this.setState('chase');
        break;
    }
    super.update(dt, world);
  }
}
```

```text
         dist < 200          dist < 30
 patrol ───────────► chase ───────────► attack
   ▲                  │  ▲                │
   └── dist > 300 ────┘  └── через 0,4 с ─┘
```

Для сложного ИИ состояния выносят в отдельные классы (паттерн State) или используют behavior trees. Для UI-логики и сложных автоматов в JS есть библиотека XState.

## Состояние игрока и анимация

FSM хорошо сочетается с анимациями: каждому состоянию соответствует своя анимация, а переходы описаны в одном месте.

```ts
const animByState = { idle: 'idle', run: 'run', jump: 'jump', fall: 'fall', hurt: 'hurt' } as const;
animator.play(animByState[player.state]);
```

## Частые ошибки

- Хранить экран в глобальной переменной `screen = 'menu' | 'game'` и проверять её в каждом объекте.
- Не вызывать `exit` у сцены — остаются подписки на события, звуки и таймеры.
- Пауза через `if (paused) return` в каждом объекте вместо того, чтобы не обновлять сцену.
- Описывать поведение набором булевых флагов: невозможные комбинации (`isDead && isJumping`) становятся возможными.

## Что важно помнить

- Сцена = `enter`/`exit`/`update`/`draw`; менеджер переключает сцены.
- Стек сцен решает паузу и всплывающие окна.
- Поведение объектов — конечный автомат: одно текущее состояние и явные переходы.
- `stateTime` — время в состоянии, удобно для атак, неуязвимости, таймеров.

## Мини-шпаргалка

```ts
scenes.switch(new LevelScene(), { level: 1 });
scenes.push(new PauseScene());   // поверх
scenes.pop();                    // вернуться
setState('chase'); stateTime = 0;
```
