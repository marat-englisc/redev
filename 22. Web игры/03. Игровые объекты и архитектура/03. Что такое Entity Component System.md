# Что такое Entity Component System

> [!NOTE]
> **ECS** — архитектура, в которой нет классов «Игрок» и «Враг». **Entity** — просто числовой id. **Component** — чистые данные без методов (`Position`, `Velocity`, `Sprite`, `Health`). **System** — функция, которая каждый кадр обрабатывает все сущности с нужным набором компонентов (`MovementSystem` берёт всех, у кого есть `Position` и `Velocity`). Поведение собирается из компонентов как из кубиков: добавил `Velocity` — объект поехал, убрал `Health` — стал бессмертным. Плюсы: нет хрупкого наследования, системы легко тестировать, данные лежат плотно и быстро обходятся. Минусы: больше «церемоний» для маленьких игр. В JS популярны `bitECS`, `miniplex`, `koota`.

## Вопрос

Что такое Entity Component System, чем он отличается от ООП-подхода с классами и когда его стоит использовать?

## Проблема наследования

```text
Entity
├── Player
├── Enemy
│   ├── FlyingEnemy
│   └── ShootingEnemy
│       └── FlyingShootingEnemy ← дублирование или множественное наследование?
└── Bullet
```

## Идея ECS

```text
Entity:     1        2        3        4
Position:   ✓        ✓        ✓        ✓
Velocity:   ✓        ✓        ✓
Sprite:     ✓        ✓                 ✓
Health:     ✓        ✓
Input:      ✓
Shooter:             ✓
            игрок    враг     пуля     декорация

MovementSystem → все с Position + Velocity → 1, 2, 3
RenderSystem   → все с Position + Sprite   → 1, 2, 4
```

## Минимальный ECS своими руками

```ts
type Entity = number;

// компоненты — только данные
interface Position { x: number; y: number }
interface Velocity { x: number; y: number }
interface Sprite { color: string; size: number }
interface Health { hp: number }

class World {
  private nextId = 0;
  position = new Map<Entity, Position>();
  velocity = new Map<Entity, Velocity>();
  sprite = new Map<Entity, Sprite>();
  health = new Map<Entity, Health>();
  playerControlled = new Set<Entity>();

  create(): Entity { return this.nextId++; }

  destroy(e: Entity) {
    this.position.delete(e);
    this.velocity.delete(e);
    this.sprite.delete(e);
    this.health.delete(e);
    this.playerControlled.delete(e);
  }
}
```

## Системы — обычные функции

```ts
function inputSystem(w: World, keys: Set<string>) {
  for (const e of w.playerControlled) {
    const v = w.velocity.get(e)!;
    v.x = (Number(keys.has('ArrowRight')) - Number(keys.has('ArrowLeft'))) * 200;
    v.y = (Number(keys.has('ArrowDown')) - Number(keys.has('ArrowUp'))) * 200;
  }
}

function movementSystem(w: World, dt: number) {
  for (const [e, v] of w.velocity) {
    const p = w.position.get(e);
    if (!p) continue;
    p.x += v.x * dt;
    p.y += v.y * dt;
  }
}

function deathSystem(w: World) {
  for (const [e, h] of w.health) if (h.hp <= 0) w.destroy(e);
}

function renderSystem(w: World, ctx: CanvasRenderingContext2D) {
  for (const [e, s] of w.sprite) {
    const p = w.position.get(e);
    if (!p) continue;
    ctx.fillStyle = s.color;
    ctx.fillRect(p.x - s.size / 2, p.y - s.size / 2, s.size, s.size);
  }
}
```

## Сборка сущностей

```ts
function createPlayer(w: World, x: number, y: number) {
  const e = w.create();
  w.position.set(e, { x, y });
  w.velocity.set(e, { x: 0, y: 0 });
  w.sprite.set(e, { color: '#38bdf8', size: 20 });
  w.health.set(e, { hp: 3 });
  w.playerControlled.add(e);
  return e;
}

function createRock(w: World, x: number, y: number) {
  const e = w.create();
  w.position.set(e, { x, y });
  w.sprite.set(e, { color: '#78716c', size: 30 }); // нет Velocity — не двигается
  return e;
}

// игровой цикл — просто порядок систем
function update(dt: number) {
  inputSystem(world, keys);
  movementSystem(world, dt);
  collisionSystem(world);
  deathSystem(world);
}
function render() {
  ctx.clearRect(0, 0, w, h);
  renderSystem(world, ctx);
}
```

Хотите, чтобы камень начал двигаться? `w.velocity.set(rock, { x: 50, y: 0 })` — и `movementSystem` его подхватит. Никаких новых классов.

## Библиотеки

```ts
// miniplex — объекты как сущности, удобно в TypeScript и React
import { World } from 'miniplex';

type E = { position?: { x: number; y: number }; velocity?: { x: number; y: number } };
const world = new World<E>();
world.add({ position: { x: 0, y: 0 }, velocity: { x: 10, y: 0 } });

const moving = world.with('position', 'velocity');  // запрос, кешируется
for (const e of moving) { e.position.x += e.velocity.x * dt; }
```

| Библиотека | Особенность |
| --- | --- |
| `bitECS` | компоненты в TypedArray (Structure of Arrays), максимальная скорость, десятки тысяч сущностей |
| `miniplex` | сущности — обычные объекты, простой API, интеграция с React |
| `koota` | от авторов pmndrs, хорошо работает с React Three Fiber |
| Phaser, PixiJS | ECS не навязывают — используют scene graph |

## ООП или ECS

| | Классы с update/draw | ECS |
| --- | --- | --- |
| Порог входа | низкий | выше |
| Новые комбинации поведения | наследование или композиция вручную | добавить компонент |
| Тысячи объектов | обычно норм | лучше кеш и обход |
| Подходит | небольшие игры, прототипы, геймджемы | симуляции, много типов объектов, большие проекты |

## Частые ошибки

- Класть методы и логику в компоненты — это уже не ECS, а снова классы.
- Делать системы, которые знают о конкретных «типах» сущностей (`if (isPlayer)`), вместо компонентов-маркеров.
- Удалять сущности посреди обхода в системе без отложенного удаления.
- Тащить ECS в маленькую игру ради «правильности».

## Что важно помнить

- Entity — id, Component — данные, System — логика над набором компонентов.
- Поведение = набор компонентов; меняется добавлением/удалением.
- Игровой цикл — упорядоченный вызов систем.
- Для больших и производительных проектов — `bitECS`, для удобства в TS/React — `miniplex`/`koota`.

