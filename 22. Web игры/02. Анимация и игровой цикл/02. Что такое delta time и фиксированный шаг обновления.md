# Что такое delta time и фиксированный шаг обновления

> [!NOTE]
> **Delta time (`dt`)** — время, прошедшее с прошлого кадра. Если задавать скорость в «пикселях в секунду» и умножать на `dt` (`x += speed * dt`), игра идёт одинаково на 30, 60 и 144 FPS. Но переменный `dt` делает физику **недетерминированной**: при большом шаге быстрый объект проскакивает сквозь стену, прыжок получается разной высоты. Поэтому физику часто считают с **фиксированным шагом** (например, 1/60 с): реальное время копится в аккумуляторе, а `update` вызывается столько раз, сколько целых шагов накопилось. Отрисовка остаётся раз в кадр, а остаток аккумулятора используют для **интерполяции**, чтобы движение было плавным.

## Вопрос

Зачем в игровом цикле нужен delta time? Что такое фиксированный шаг (fixed timestep) и когда он нужен?

## Проблема: скорость зависит от FPS

```ts
// ❌ 5 пикселей за кадр
player.x += 5;
// 60 FPS  → 300 px/с
// 144 FPS → 720 px/с
// лаг до 20 FPS → 100 px/с
```

## Переменный шаг: умножаем на dt

```ts
const SPEED = 300; // пикселей в СЕКУНДУ

function update(dt: number) {     // dt в секундах, например 0.016
  player.x += SPEED * dt;
}
```

Так же со всем, что зависит от времени:

```ts
player.vy += GRAVITY * dt;            // ускорение: px/с²
player.y += player.vy * dt;           // скорость: px/с
enemy.cooldown -= dt;                 // таймеры — в секундах
sprite.rotation += Math.PI * dt;      // пол-оборота в секунду
```

Этого достаточно для многих простых игр. Ограничивайте `dt` сверху (`Math.min(dt, 0.1)`), чтобы после паузы не случилось «прыжка во времени».

## Проблема переменного шага

```text
Пуля 2000 px/с, стена толщиной 10 px.

60 FPS:  шаг 33 px — пуля попадает в стену в одном из кадров? Не всегда.
15 FPS:  шаг 133 px — пуля перелетает стену, проверка коллизии её не видит.
```

Кроме «туннелирования», при разном `dt` численное интегрирование даёт разные результаты: высота прыжка на слабом и мощном устройстве немного отличается, повторы (реплеи) и мультиплеер расходятся.

## Фиксированный шаг с аккумулятором

```ts
const STEP = 1 / 60;           // физика всегда 60 раз в секунду
let accumulator = 0;
let last = performance.now();

function loop(now: number) {
  let frameTime = (now - last) / 1000;
  last = now;
  frameTime = Math.min(frameTime, 0.25); // защита от «спирали смерти»

  accumulator += frameTime;

  while (accumulator >= STEP) {
    savePreviousState();       // для интерполяции
    update(STEP);              // всегда одинаковый шаг
    accumulator -= STEP;
  }

  const alpha = accumulator / STEP; // 0..1 — насколько мы между шагами
  render(alpha);

  requestAnimationFrame(loop);
}
requestAnimationFrame(loop);
```

- На 144 Гц: в некоторых кадрах `update` не вызывается ни разу, отрисовка интерполирует.
- На 30 Гц: за кадр `update` вызывается 2 раза.
- «Спираль смерти»: если `update` медленнее реального времени, шагов становится всё больше. Ограничение `frameTime` это предотвращает — игра просто замедлится.

## Интерполяция

```ts
interface Body { x: number; y: number; prevX: number; prevY: number; vx: number; vy: number }

function savePreviousState() {
  for (const b of bodies) { b.prevX = b.x; b.prevY = b.y; }
}

function render(alpha: number) {
  ctx.clearRect(0, 0, w, h);
  for (const b of bodies) {
    const x = b.prevX + (b.x - b.prevX) * alpha; // lerp между прошлым и текущим
    const y = b.prevY + (b.y - b.prevY) * alpha;
    ctx.fillRect(x - 8, y - 8, 16, 16);
  }
}
```

Без интерполяции на 144 Гц движение будет слегка дёрганым: объект стоит 2 кадра, потом прыгает.

## Что выбрать

| Подход | Когда |
| --- | --- |
| Переменный `dt` | простые игры, UI-анимации, нет сложной физики |
| Фиксированный шаг | платформеры, физика, столкновения быстрых объектов |
| Фиксированный шаг + интерполяция | всё выше + плавность на мониторах > 60 Гц |
| Фиксированный шаг + детерминизм | реплеи, мультиплеер с lockstep, rollback-неткод |

Phaser, Matter.js и физические движки внутри используют фиксированный шаг; в PixiJS `ticker.deltaTime` — это переменный шаг.

## Частые ошибки

- Задавать скорость в «пикселях за кадр» и забыть про `dt`.
- Умножать на `dt` в миллисекундах и в секундах в разных местах — скорость отличается в 1000 раз.
- Не ограничивать `frameTime` — после возврата во вкладку игра «догоняет» минуты времени.
- Использовать фиксированный шаг без интерполяции на высокочастотных мониторах и удивляться микрорывкам.

## Что важно помнить

- Скорости — в единицах в секунду, в `update` умножаем на `dt`.
- Переменный шаг прост, но физика с ним нестабильна и недетерминирована.
- Fixed timestep: аккумулятор + `while (acc >= STEP)`.
- `alpha = acc / STEP` — для интерполяции отрисовки.

## Мини-шпаргалка

```ts
acc += Math.min(frameTime, 0.25);
while (acc >= STEP) { update(STEP); acc -= STEP; }
render(acc / STEP);
x = prev + (cur - prev) * alpha;
```
