# Как оптимизировать PixiJS — батчинг, ParticleContainer и culling

> [!NOTE]
> Скорость PixiJS держится на **батчинге**: подряд идущие спрайты с совместимыми текстурами и режимом смешивания собираются в один **draw call**. Батч прерывают смена текстуры сверх лимита GPU, `Graphics` между спрайтами, другой `blendMode`, фильтры и маски. Поэтому главное правило — **атласы**: всё, что рисуется вместе, должно лежать в одной-двух текстурах. Для десятков и сотен тысяч одинаковых объектов (частицы, пули, снег) есть **`ParticleContainer`** с лёгкими `Particle` — без иерархии и событий, зато очень быстро. Невидимое не рисуют: `cullable = true` + `Culler`. Статичные группы запекают в текстуру через `cacheAsTexture()`. И никаких созданий/уничтожений объектов в каждом кадре — пулы.

## Вопрос

Как ускорить сцену на PixiJS, когда объектов становится очень много?

## Батчинг и атласы

```text
❌ 6 draw calls                         ✅ 1 draw call
sprite(hero.png)                        sprite(atlas: hero)
graphics (rect)      ← прерывает батч   sprite(atlas: coin)
sprite(coin.png)                        sprite(atlas: enemy)
sprite(enemy.png) blendMode = 'add'     sprite(atlas: tile) …
sprite(tile.png)  filters = [...]
```

- Собирайте спрайты в атласы (TexturePacker, free-tex-packer, `@assetpack/core`).
- Не перемешивайте `Graphics` со спрайтами в одном слое — запекайте фигуры в текстуру (`renderer.generateTexture`).
- Группируйте объекты с одинаковым `blendMode`.
- Фильтры и маски — на контейнеры, а не на отдельные спрайты.

## ParticleContainer

`ParticleContainer` (в v8 переписан) содержит не обычные `Sprite`, а лёгкие объекты `Particle`. Вы указываете, какие свойства меняются каждый кадр, — остальные не отправляются на GPU повторно:

```ts
import { ParticleContainer, Particle, Assets } from 'pixi.js';

const texture = await Assets.load('/assets/spark.png');

const container = new ParticleContainer({
  dynamicProperties: {
    position: true,    // меняем каждый кадр
    rotation: false,
    vertex: false,     // scale/размер
    color: true,       // tint и alpha
  },
});
app.stage.addChild(container);

interface Spark { p: Particle; vx: number; vy: number; life: number }
const sparks: Spark[] = [];

for (let i = 0; i < 50_000; i++) {
  const p = new Particle({
    texture,
    x: Math.random() * app.screen.width,
    y: Math.random() * app.screen.height,
    anchorX: 0.5,
    anchorY: 0.5,
  });
  container.addParticle(p);
  sparks.push({ p, vx: (Math.random() - 0.5) * 100, vy: (Math.random() - 0.5) * 100, life: 1 });
}

app.ticker.add((t) => {
  const dt = t.deltaMS / 1000;
  for (const s of sparks) {
    s.p.x += s.vx * dt;
    s.p.y += s.vy * dt;
    s.life = (s.life - dt * 0.3 + 1) % 1;
    s.p.alpha = s.life;
  }
});
```

Ограничения: все частицы — одна базовая текстура (атлас), нет вложенности, фильтров на отдельных частицах и событий.

## Culling — не рисовать невидимое

```ts
import { extensions, CullerPlugin } from 'pixi.js';

extensions.add(CullerPlugin);   // автоматический culling перед каждым рендером

for (const enemy of enemies) enemy.cullable = true;  // скрывается, если вне экрана
world.cullableChildren = true;
```

Для огромного мира (тайлы) эффективнее не держать в сцене весь уровень: создавать и переиспользовать спрайты только для видимых чанков.

## cacheAsTexture — запечь статичное

```ts
// фон из 2000 тайлов и декораций, который не меняется
levelBackground.cacheAsTexture(true);       // теперь рисуется как одна текстура

// после изменения содержимого
levelBackground.updateCacheTexture();

// выключить
levelBackground.cacheAsTexture(false);
```

Подходит для статичных слоёв, сложных `Graphics`, контейнеров с фильтрами. Не подходит для того, что меняется каждый кадр, и для очень больших областей (ограничение размера текстуры GPU).

## Пулы и отказ от лишних объектов

```ts
// ❌ каждый выстрел: new Sprite → destroy
// ✅ пул спрайтов
const pool: Sprite[] = [];
function getBullet() {
  const s = pool.pop() ?? new Sprite(bulletTexture);
  s.visible = true;
  bulletsLayer.addChild(s);
  return s;
}
function releaseBullet(s: Sprite) {
  s.visible = false;
  s.removeFromParent();
  pool.push(s);
}
```

Также:

- `eventMode = 'none'` для контейнеров с декорациями и частицами — PixiJS не проверяет их при движении мыши.
- `BitmapText` вместо `Text` для часто меняющихся надписей.
- Не вызывайте `getBounds()` для сотен объектов каждый кадр.
- Ограничьте `resolution` на мобильных: `Math.min(devicePixelRatio, 2)`.

## Как измерять

```ts
app.ticker.add(() => fpsText.text = `${Math.round(app.ticker.FPS)}`);
```

- **PixiJS DevTools** (расширение для Chrome) — дерево сцены, количество объектов, текстуры.
- **Spector.js** — захват кадра WebGL: видно каждый draw call и что прервало батч.
- Chrome DevTools → Performance — время в `update` и `render`, GC.

## Ориентиры

| Задача | Решение |
| --- | --- |
| Сотни спрайтов | что угодно, оптимизация не нужна |
| Тысячи спрайтов | атласы, пулы, culling |
| Десятки тысяч одинаковых объектов | `ParticleContainer` |
| Большой статичный уровень | `cacheAsTexture` или чанки |
| Много `Text`, меняющихся каждый кадр | `BitmapText` |
| Фильтры | на контейнер, `filterArea`, пониженный `resolution` |

## Частые ошибки

- Отдельный PNG на каждый объект — батчинг ломается.
- `Graphics` вперемешку со спрайтами в одном контейнере.
- Создание и `destroy()` спрайтов каждый кадр.
- `cacheAsTexture` для контейнера, который постоянно меняется, — перезапекание каждый кадр медленнее обычного рендера.
- Использовать обычный `Container` с 50 000 `Sprite` вместо `ParticleContainer`.

## Что важно помнить

- Батчинг: одна текстура (атлас), одинаковый `blendMode`, без фильтров между спрайтами.
- `ParticleContainer` + `Particle` — для десятков тысяч простых объектов.
- `cullable` + `CullerPlugin` — не рисовать невидимое.
- `cacheAsTexture(true)` — запечь статичный слой.
- Пулы спрайтов, `eventMode = 'none'`, `BitmapText`.
