# Что такое hydration и hydration mismatch

> [!NOTE]
> **Гидрация** — этап, на котором Vue в браузере сопоставляет HTML, пришедший с сервера, со своим виртуальным деревом, привязывает обработчики событий и делает страницу интерактивной — без перерисовки DOM. **Hydration mismatch** — ситуация, когда первый рендер на клиенте отличается от серверного HTML: Vue пишет предупреждение и исправляет DOM (с мерцанием, а иногда со сломанными обработчиками). Причины — недетерминированные значения (`Date.now()`, `Math.random()`), различия окружения (`window`, часовой пояс, `localStorage`), невалидный HTML.

## Вопрос

Что такое гидрация и почему возникает hydration mismatch?

## Как работает гидрация

```text
сервер:  setup → render → <button>Купить (3)</button> + payload { cart: 3 }
клиент:  загрузка JS → setup (берёт cart=3 из payload) → виртуальный DOM
         → сравнение с существующим DOM → совпало → привязать @click
```

Ключевое условие — **первый клиентский рендер должен быть идентичен серверному**. Для данных это обеспечивает payload (`useFetch`, `useState`), для остального — дисциплина в коде.

## Пример mismatch

```vue
<template>
  <p>Сгенерировано: {{ new Date().toLocaleTimeString() }}</p>
</template>
```

Сервер отрендерит `12:00:01`, клиент через секунду — `12:00:02`:

```text
[Vue warn]: Hydration text content mismatch on <p>
  - rendered on server: Сгенерировано: 12:00:01
  - expected on client: Сгенерировано: 12:00:02
```

## Частые причины и решения

| Причина | Решение |
| --- | --- |
| `Date.now()`, `new Date()` в шаблоне | Значение в `useState` или рендер после `onMounted` |
| `Math.random()`, `crypto.randomUUID()` для `id` | `useId()` из Vue 3.5 или `useState` |
| `window.innerWidth`, `localStorage` в `setup` | `onMounted`, `<ClientOnly>`, `useCookie` вместо `localStorage` |
| Разные часовые пояса и локали сервера и клиента | Явно передавать `timeZone` в `Intl.DateTimeFormat` |
| Тема из `localStorage` | Хранить в cookie (`useCookie`), чтобы сервер знал её |
| Невалидный HTML: `<div>` внутри `<p>`, `<a>` в `<a>` | Исправить разметку — браузер «чинит» её по-своему |
| Браузерные расширения, меняющие DOM | Не баг приложения, но учитывать при отладке |

## Стабильные значения

```vue
<script setup lang="ts">
const id = useId();                                                // одинаков на сервере и клиенте
const renderedAt = useState("rendered-at", () => new Date().toISOString());
const theme = useCookie<"light" | "dark">("theme", { default: () => "light" });
</script>

<template>
  <div :class="`theme-${theme}`">
    <label :for="id">Email</label>
    <input :id="id" />
    <time :datetime="renderedAt">{{ renderedAt }}</time>
  </div>
</template>
```

## Если различие неизбежно

```vue
<script setup lang="ts">
const isClient = ref(false);
onMounted(() => (isClient.value = true));
</script>

<template>
  <span v-if="isClient">{{ localTime }}</span>
  <span v-else>—</span>
</template>
```

Для отдельных атрибутов Vue 3.5 поддерживает `data-allow-mismatch` — подавить предупреждение там, где различие ожидаемо (например, относительное время).

## Почему mismatch — не мелочь

- Мерцание и сдвиг контента ухудшают CLS.
- При структурном расхождении Vue может пересоздать часть DOM — потеря фокуса, состояния полей.
- Некоторые обработчики событий могут не привязаться.

## Частые ошибки

- Игнорировать предупреждения в консоли dev-режима.
- «Лечить» mismatch через `ssr: false` для всей страницы.
- Генерировать `id` через `Math.random()`.
- Читать тему или авторизацию из `localStorage` при SSR.

## Что важно помнить

- Гидрация сверяет, а не перерисовывает — отсюда требование совпадения.
- Данные для первого рендера должны приходить через payload.
- Браузерно-зависимое отображение — после `onMounted` или в `<ClientOnly>`.

## Мини-шпаргалка

- Гидрация = привязка Vue к серверному HTML.
- Mismatch = первый клиентский рендер ≠ серверный.
- `useId`, `useState`, `useCookie` — стабильные значения.
- `onMounted`, `<ClientOnly>` — браузерное.
- `data-allow-mismatch` — ожидаемые различия.
