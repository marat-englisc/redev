# Что такое payload и payload extraction

> [!NOTE]
> **Payload** — сериализованное состояние, которое сервер вставляет в HTML вместе с разметкой: результаты `useFetch`/`useAsyncData`, значения `useState`, состояние Pinia. При гидрации клиент читает его и **не повторяет запросы**. **Payload extraction** — для пререндеренных страниц Nuxt выносит payload в отдельный файл `_payload.json`, который при клиентском переходе на эту страницу загружается вместо запроса к API (а может и предзагружаться вместе с ссылкой). Сериализация идёт через `devalue`, поэтому поддерживаются `Date`, `Map`, `Set`, `ref`, но не функции и экземпляры классов.

## Вопрос

Что такое payload в Nuxt и зачем нужна payload extraction?

## Без payload

```text
сервер: $fetch('/api/products') → HTML со списком
клиент: setup → $fetch('/api/products') ещё раз → тот же список
```

Двойной запрос, лишняя нагрузка на API, и если данные успели измениться — hydration mismatch.

## С payload

```ts
const { data } = await useFetch("/api/products");
```

```html
<script type="application/json" data-nuxt-data="nuxt-app" id="__NUXT_DATA__">
  [{"data":1}, {"$fproducts":2}, [3], {"id":4,"title":5}, 1, "Keyboard"]
</script>
```

Клиент восстанавливает данные из этого блока, `useFetch` при гидрации запроса не делает.

## Что попадает в payload

| Источник | В payload |
| --- | --- |
| `useFetch`, `useAsyncData` | Да |
| `useState` | Да |
| Состояние Pinia (через `@pinia/nuxt`) | Да |
| `$fetch` в `setup` | **Нет** — отсюда двойной запрос |
| `ref` в компоненте | Нет — пересчитается на клиенте |

## Размер payload

Всё, что вернул API, попадает в HTML. Если ответ большой, а используется три поля, отрежьте лишнее:

```ts
const { data } = await useFetch("/api/products", {
  pick: ["id", "title", "price"],                    // для объекта
});

const { data: list } = await useFetch("/api/products", {
  transform: (items) => items.map(({ id, title, price }) => ({ id, title, price })),
});
```

Большой payload увеличивает вес HTML и время гидрации. Никогда не кладите в payload секреты: он виден в исходном коде страницы.

## Payload extraction

Для пререндеренных страниц:

```text
.output/public/blog/nuxt-ssr/index.html
.output/public/blog/nuxt-ssr/_payload.json
```

При переходе с `/` на `/blog/nuxt-ssr` через `<NuxtLink>` клиент загружает статичный `_payload.json` с CDN, а не вызывает API — пререндеренный сайт работает без бэкенда даже при клиентской навигации. Поведение управляется опцией `experimental.payloadExtraction` и по умолчанию включено для prerender.

## Нестандартные типы

```ts
// app/plugins/payload-money.ts
export default definePayloadPlugin(() => {
  definePayloadReducer("Money", (v) => v instanceof Money && v.toJSON());
  definePayloadReviver("Money", (v) => new Money(v));
});
```

Так экземпляры собственных классов переживают передачу с сервера на клиент.

## Частые ошибки

- `$fetch` в `setup` вместо `useFetch` — данные не в payload.
- Передавать огромные ответы API целиком.
- Класть в `useState` функции и классы.
- Ждать, что `_payload.json` появится у SSR-страниц без prerender.

## Что важно помнить

- Payload — мост между серверным и клиентским рендером; без него гидрация ломается или удваивает запросы.
- Всё в payload публично.
- Payload extraction делает пререндеренный сайт самодостаточным при навигации.

## Мини-шпаргалка

- Payload = данные SSR в HTML.
- `useFetch`, `useAsyncData`, `useState`, Pinia → payload.
- `$fetch` в setup → двойной запрос.
- `pick`, `transform` — уменьшить payload.
- `_payload.json` — для prerender-страниц.
