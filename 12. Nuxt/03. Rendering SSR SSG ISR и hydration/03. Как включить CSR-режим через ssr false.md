# Как включить CSR-режим через ssr false

> [!NOTE]
> `ssr: false` в `nuxt.config.ts` превращает всё приложение в **SPA**: сервер отдаёт HTML-оболочку, а страницы рендерятся в браузере. Для части маршрутов то же делает `routeRules: { '/admin/**': { ssr: false } }` — публичная часть остаётся SSR/SSG. Серверные API в `server/` продолжают работать, если приложение запущено как Nitro-сервер; при статическом деплое (`nuxt generate`) их нет. CSR уместен для закрытых разделов без SEO, но не как способ «починить» ошибку `window is not defined`.

## Вопрос

Как включить клиентский рендеринг в Nuxt и когда это оправдано?

## Глобально

```ts
export default defineNuxtConfig({
  ssr: false,
});
```

```bash
nuxt generate   # получится статическая SPA: index.html + 200.html/404.html для fallback
```

Такое приложение можно положить на любой статический хостинг или CDN. Настройте сервер так, чтобы неизвестные пути отдавали `200.html` (или `index.html`) — иначе прямой переход на `/admin/users` вернёт 404.

## Для части маршрутов

```ts
export default defineNuxtConfig({
  routeRules: {
    "/admin/**": { ssr: false },
    "/app/**": { ssr: false },
  },
});
```

Лендинг и блог рендерятся на сервере ради SEO, а тяжёлый личный кабинет — в браузере, без нагрузки на сервер.

## Что меняется при CSR

- Первый HTML почти пустой — контент появляется после загрузки JS.
- `useFetch` выполняется в браузере (payload с сервера нет).
- Нет гидрации и, соответственно, hydration mismatch.
- Можно свободно использовать `window`, `localStorage` в `setup`.
- Мета-теги, заданные в `useSeoMeta`, появятся только после выполнения JS.

## Индикатор загрузки SPA

```html
<!-- app/spa-loading-template.html -->
<div class="spinner" aria-label="Загрузка"></div>
```

Nuxt вставит этот шаблон в HTML-оболочку, чтобы пользователь не видел белый экран до старта приложения.

## Когда CSR оправдан

- Админка, CRM, дашборды за логином.
- Тяжёлые интерактивные инструменты (редакторы, карты), где SSR ничего не даёт.
- Деплой только на статический хостинг без сервера.

## Когда это ошибка

```ts
// ✗ «библиотека карт требует window — отключим SSR всему сайту»
export default defineNuxtConfig({ ssr: false });
```

Правильнее изолировать браузерную часть:

```vue
<ClientOnly>
  <MapWidget />
</ClientOnly>
```

или подключить библиотеку плагином `*.client.ts` — см. [SSR-safe код](<07. Как писать SSR-safe код.md>).

## Частые ошибки

- Отключать SSR публичному сайту и терять SEO и скорость первого отображения.
- Не настроить fallback на `index.html`/`200.html` при статическом деплое.
- Ждать работы `server/api` после `nuxt generate`.

## Что важно помнить

- `ssr: false` — режим приложения, а не исправление ошибок SSR.
- Per-route CSR — главный способ сочетать SEO-страницы и тяжёлые клиентские разделы в одном проекте.
- Для закрытых разделов CSR ещё и безопаснее с точки зрения кэша — нет риска закэшировать чужой HTML.

## Мини-шпаргалка

- `ssr: false` — всё приложение SPA.
- `routeRules: { '/admin/**': { ssr: false } }` — частично.
- `nuxt generate` + fallback `200.html`.
- `spa-loading-template.html` — экран загрузки.
- Браузерные библиотеки → `<ClientOnly>` или `.client`.
