# Как работают SSG и prerender

> [!NOTE]
> **Prerender** — рендер страниц в HTML на этапе сборки. `nuxt generate` пререндерит всё приложение в статику (SSG) для CDN без сервера; `routeRules: { '/about': { prerender: true } }` пререндерит выбранные маршруты, оставляя остальные динамическими. Nitro находит страницы, **переходя по ссылкам** из уже отрендеренных, поэтому страницы без входящих ссылок нужно указать явно (`nitro.prerender.routes` или хук). Данные страниц сохраняются в `_payload.json`, чтобы клиентские переходы не делали запросов к API.

## Вопрос

Как работает статическая генерация и prerender в Nuxt?

## Полная статическая генерация

```bash
nuxt generate
```

```text
.output/public/
├── index.html
├── about/index.html
├── blog/nuxt-ssr/index.html
├── blog/nuxt-ssr/_payload.json
├── 200.html / 404.html
└── _nuxt/*.js
```

Результат — набор файлов для Netlify, Cloudflare Pages, GitHub Pages, S3 + CDN. Сервер не нужен.

## Prerender отдельных маршрутов

```ts
export default defineNuxtConfig({
  routeRules: {
    "/": { prerender: true },
    "/about": { prerender: true },
    "/blog/**": { prerender: true },
    "/api/search": { prerender: false },
  },
});
```

При обычном `nuxt build` эти страницы будут сгенерированы заранее, а остальные — рендериться на сервере. Внутри страницы можно объявить то же через `defineRouteRules({ prerender: true })` (экспериментально, `experimental.inlineRouteRules`).

## Как Nitro находит страницы

```text
старт с "/" → рендер → поиск <a href> в HTML → рендер найденных → ...
```

Это crawler. Страницы, на которые нет ссылок, он не найдёт:

```ts
export default defineNuxtConfig({
  nitro: {
    prerender: {
      crawlLinks: true,
      routes: ["/sitemap.xml", "/landing/promo"],
      ignore: ["/admin"],
    },
  },
});
```

Список можно получить из CMS динамически:

```ts
export default defineNuxtConfig({
  hooks: {
    async "prerender:routes"(ctx) {
      const posts = await fetch("https://cms.example.com/posts").then((r) => r.json());
      for (const post of posts) ctx.routes.add(`/blog/${post.slug}`);
    },
  },
});
```

## Обновление контента

Статика устаревает до следующей сборки. Варианты:

- пересобирать по вебхуку CMS при публикации;
- переключить раздел на `swr`/`isr`, если страниц много или они часто меняются;
- оставить статичным каркас, а изменчивые данные (цены, остатки) загружать на клиенте.

## Когда SSG неудобен

- Тысячи или миллионы страниц — сборка длится часами.
- Данные меняются часто.
- Контент зависит от пользователя, cookie или query-параметров (поиск, фильтры).
- Нельзя заранее перечислить URL.

## Частые ошибки

- Ждать, что страница без ссылок на неё сгенерируется сама.
- Пререндерить страницу, читающую cookie, — сохранится вариант для «пустого» пользователя.
- Использовать в пререндеренной странице `server/api`, которого нет на статическом хостинге.
- Не проверять, что неизвестные URL отдают 404, а не 200.

## Что важно помнить

- Prerender — это SSR, выполненный один раз при сборке; код страниц тот же.
- Гибрид «prerender для части маршрутов» обычно лучше, чем «всё статика» или «всё SSR».
- Ошибки рендера при prerender по умолчанию прерывают сборку — это защищает от публикации сломанных страниц.

## Мини-шпаргалка

- `nuxt generate` — всё в статику.
- `routeRules: { prerender: true }` — выборочно.
- Crawler идёт по ссылкам; остальное — `nitro.prerender.routes` или хук `prerender:routes`.
- Обновление — пересборка, `swr`/`isr` или клиентская загрузка.
