# Что такое Nitro в Nuxt

> [!NOTE]
> **Nitro** — серверный движок Nuxt (отдельный проект UnJS). Он запускает SSR-рендер, обслуживает файлы из `server/` (API-маршруты, middleware, plugins), применяет `routeRules`, даёт кэш и key-value хранилище (`useStorage`, `cachedEventHandler`), фоновые задачи и prerender. При сборке Nitro создаёт автономный сервер в `.output/server`, адаптированный **presets** под Node.js, Bun, Deno, serverless (Vercel, Netlify, AWS Lambda) и edge (Cloudflare Workers). Обработчики пишутся на **h3** — минималистичном HTTP-фреймворке.

## Вопрос

Что такое Nitro и какую роль он играет в Nuxt?

## Место Nitro в Nuxt

```text
запрос
  └─▶ Nitro
       ├─ server/middleware/*        (каждый запрос)
       ├─ routeRules                 (кэш, редиректы, заголовки)
       ├─ server/api/*, server/routes/*  → ответ JSON/текст
       └─ иначе → рендер Vue-приложения (SSR) → HTML
```

Nuxt-приложение (Vue) — это одна из «точек входа», которую Nitro вызывает для страниц.

## Что умеет

| Возможность | Как |
| --- | --- |
| API-маршруты | `server/api/users.get.ts` |
| Произвольные маршруты | `server/routes/sitemap.xml.ts` |
| Middleware | `server/middleware/log.ts` |
| Плагины и хуки | `server/plugins/*.ts`, `defineNitroPlugin` |
| Утилиты с auto-import | `server/utils/*.ts` |
| Кэш | `cachedEventHandler`, `defineCachedFunction`, `routeRules.swr` |
| Хранилище | `useStorage("redis")` — общий интерфейс к памяти, ФС, Redis, S3 |
| Задачи | `server/tasks/*.ts`, `runTask()` (экспериментально) |
| Деплой | Presets: `node-server`, `vercel`, `netlify`, `cloudflare-pages`, `bun`, `deno`... |

## Пример

```ts
// server/api/health.get.ts
export default defineEventHandler(() => ({ status: "ok", uptime: process.uptime() }));
```

```ts
// server/utils/db.ts — auto-import во всех файлах server/
import { drizzle } from "drizzle-orm/node-postgres";

export const db = drizzle(useRuntimeConfig().databaseUrl);
```

## Хранилище

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  nitro: {
    storage: {
      kv: { driver: "redis", url: process.env.REDIS_URL },
    },
  },
});
```

```ts
// server/api/counter.post.ts
export default defineEventHandler(async () => {
  const storage = useStorage("kv");
  const value = ((await storage.getItem<number>("visits")) ?? 0) + 1;
  await storage.setItem("visits", value);
  return { value };
});
```

Драйвер меняется в конфиге без изменения кода — память в dev, Redis в production.

## Почему это важно

- Один код деплоится на любую платформу — vendor lock-in минимален.
- Сборка самодостаточна: `.output/` содержит всё нужное, `node_modules` на сервере не требуется.
- На serverless и edge действуют ограничения платформы (время выполнения, отсутствие `node:fs`), и код в `server/` должен их учитывать.

## Частые ошибки

- Путать Nitro и Vite: Vite собирает клиент, Nitro — сервер.
- Использовать Node-специфичные API на edge-preset.
- Хранить состояние в памяти процесса при serverless-деплое — каждый вызов может попасть в новый экземпляр.

## Что важно помнить

- Nitro можно использовать и без Nuxt — как самостоятельный backend.
- `server/` — это код Nitro, а не Vue: здесь нет компонентов и composables Vue (кроме `useRuntimeConfig`, `useStorage` и утилит Nitro).
- Preset определяет, как будет запускаться сервер, и обычно выбирается автоматически на CI платформы.

## Мини-шпаргалка

- Nitro = сервер Nuxt на h3.
- `server/api`, `routes`, `middleware`, `plugins`, `utils`.
- `useStorage`, `cachedEventHandler`.
- Presets: Node, serverless, edge.
- `.output/server/index.mjs` — точка входа.
