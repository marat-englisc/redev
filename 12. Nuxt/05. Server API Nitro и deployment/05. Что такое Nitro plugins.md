# Что такое Nitro plugins

> [!NOTE]
> **Nitro plugins** (`server/plugins/*.ts`, `defineNitroPlugin`) выполняются **один раз при старте сервера** — не на каждый запрос, в отличие от плагинов Vue-приложения в `app/plugins`. В них подключаются к хукам Nitro (`request`, `beforeResponse`, `afterResponse`, `error`, `close`, `render:html`), инициализируют интеграции (Sentry, OpenTelemetry), прогревают соединения и освобождают ресурсы при остановке. Код выполняется только на сервере.

## Вопрос

Что такое Nitro plugins и чем они отличаются от плагинов Nuxt-приложения?

## Пример: логирование и ошибки

```ts
// server/plugins/observability.ts
export default defineNitroPlugin((nitroApp) => {
  nitroApp.hooks.hook("request", (event) => {
    event.context.startedAt = performance.now();
  });

  nitroApp.hooks.hook("afterResponse", (event) => {
    const ms = Math.round(performance.now() - event.context.startedAt);
    console.log(JSON.stringify({ method: event.method, path: event.path, ms }));
  });

  nitroApp.hooks.hook("error", (error, { event }) => {
    reportToSentry(error, { path: event?.path });
  });
});
```

## Пример: изменение HTML

```ts
// server/plugins/html.ts
export default defineNitroPlugin((nitroApp) => {
  nitroApp.hooks.hook("render:html", (html) => {
    html.head.push('<meta name="build" content="2026.10.24">');
  });
});
```

## Пример: корректное завершение

```ts
// server/plugins/db.ts
export default defineNitroPlugin((nitroApp) => {
  nitroApp.hooks.hook("close", async () => {
    await pool.end();   // закрыть соединения с БД при остановке сервера
  });
});
```

## Nuxt plugin или Nitro plugin

| | `app/plugins` | `server/plugins` |
| --- | --- | --- |
| Функция | `defineNuxtPlugin` | `defineNitroPlugin` |
| Когда выполняется | На каждый SSR-запрос и при старте в браузере | Один раз при старте сервера |
| Окружение | Сервер и браузер | Только сервер |
| Доступ | `nuxtApp`, Vue, composables | `nitroApp`, хуки HTTP и рендера |
| Типичные задачи | Vue-плагины, API-клиент, директивы | Логи, мониторинг, соединения, `render:html` |

## Основные хуки Nitro

| Хук | Когда |
| --- | --- |
| `request` | Начало обработки запроса |
| `beforeResponse` | Перед отправкой ответа (можно изменить тело) |
| `afterResponse` | Ответ отправлен |
| `error` | Необработанная ошибка |
| `render:html` | HTML страницы сформирован (Nuxt) |
| `render:response` | Ответ рендера готов |
| `close` | Сервер останавливается |

## Частые ошибки

- Ожидать, что Nitro plugin выполняется на каждый запрос, и класть туда данные пользователя.
- Использовать браузерные API — это серверный код.
- Путать с `app/plugins/*.server.ts` (тот выполняется при каждом SSR-рендере, в контексте Vue-приложения).
- Тяжёлая асинхронная инициализация без обработки ошибок — сервер может не стартовать.

## Что важно помнить

- Nitro plugin — уровень процесса сервера, Nuxt plugin — уровень экземпляра приложения.
- Хуки `request`/`afterResponse` — удобное место для метрик и трассировки.
- В serverless «старт сервера» происходит при холодном старте функции.

## Мини-шпаргалка

- `server/plugins/x.ts` + `defineNitroPlugin((nitroApp) => ...)`.
- `nitroApp.hooks.hook("request" | "afterResponse" | "error" | "close" | "render:html")`.
- Один раз при старте, только сервер.
