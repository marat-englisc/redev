# Как работает caching в Nitro

> [!NOTE]
> Nitro кэширует на трёх уровнях. **Маршруты** — `routeRules` с `swr`, `isr` или `cache` для страниц и API. **Обработчики** — `defineCachedEventHandler(handler, { maxAge, swr, getKey, varies })` кэширует ответ целиком. **Функции** — `defineCachedFunction(fn, { maxAge, getKey })` кэширует результат дорогой операции (запрос к CMS, внешнему API). Кэш хранится в хранилище `cache` (по умолчанию — в памяти, в production — Redis). Главное правило: общий кэш не должен содержать данные, зависящие от пользователя.

## Вопрос

Как работает кэширование в Nitro и что безопасно кэшировать?

## Кэш на уровне маршрута

```ts
export default defineNuxtConfig({
  routeRules: {
    "/blog/**": { swr: 3600 },                         // HTML страниц
    "/api/products": { cache: { maxAge: 300, swr: true } }, // ответ API
  },
});
```

## Кэшированный обработчик

```ts
// server/api/rates.get.ts
export default defineCachedEventHandler(
  async () => $fetch("https://api.exchange.example/latest"),
  {
    maxAge: 60 * 10,         // 10 минут
    swr: true,               // по истечении отдавать старое и обновлять в фоне
    name: "rates",
    getKey: (event) => getQuery(event).base?.toString() ?? "USD",
  },
);
```

## Кэшированная функция

```ts
// server/utils/cms.ts
export const getPost = defineCachedFunction(
  async (slug: string) => $fetch(`https://cms.example.com/posts/${slug}`),
  { maxAge: 60 * 60, name: "cms-post", getKey: (slug: string) => slug },
);
```

```ts
// server/api/posts/[slug].get.ts
export default defineEventHandler((event) => getPost(getRouterParam(event, "slug")!));
```

Функцию удобнее переиспользовать в нескольких обработчиках, а кэш строится по аргументам.

## Хранилище кэша

```ts
export default defineNuxtConfig({
  nitro: {
    storage: {
      cache: { driver: "redis", url: process.env.REDIS_URL },
    },
    devStorage: {
      cache: { driver: "memory" },
    },
  },
});
```

In-memory кэш у каждого экземпляра свой и сбрасывается при перезапуске; в serverless он почти бесполезен.

## Инвалидация

```ts
// после публикации поста в CMS
await useStorage("cache").removeItem("nitro:functions:cms-post:my-slug.json");
```

Ключи кэша имеют вид `nitro:<handlers|functions|routes>:<name>:<key>.json`. Простые альтернативы — короткий `maxAge` с `swr` или вебхук, очищающий нужные ключи.

## Что кэшировать

| Безопасно | Опасно |
| --- | --- |
| Публичный каталог, статьи, справочники | Профиль, корзина, заказы |
| Ответы внешних API, курсы валют | Ответы, зависящие от cookie или `Authorization` |
| Sitemap, RSS | Админские данные |

Если ответ зависит от заголовка (язык), добавьте его в ключ: `varies: ["accept-language"]` или `getKey`.

## Частые ошибки

- Кэшировать ответ, построенный на основе сессии пользователя.
- Не включить заголовок языка или региона в ключ — пользователи получают чужую локаль.
- Полагаться на in-memory кэш при нескольких репликах.
- Кэшировать ошибки: результат-исключение не кэшируется, но «пустой» успешный ответ — кэшируется.

## Что важно помнить

- `swr: true` даёт мгновенные ответы ценой небольшой устарелости.
- Ключ кэша — ваша ответственность: всё, от чего зависит ответ, должно в него входить.
- Кэш HTTP-клиента (браузера, CDN) настраивается отдельно заголовками `cache-control`.

## Мини-шпаргалка

- `routeRules`: `swr`, `isr`, `cache`.
- `defineCachedEventHandler(fn, { maxAge, swr, getKey })`.
- `defineCachedFunction(fn, { maxAge, getKey })`.
- Хранилище `cache` → Redis в production.
- Персональное не кэшировать.
