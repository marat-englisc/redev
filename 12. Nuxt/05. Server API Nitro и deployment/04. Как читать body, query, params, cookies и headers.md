# Как читать body, query, params, cookies и headers

> [!NOTE]
> В обработчиках Nitro данные запроса читают утилитами h3, передавая им `event`: `readBody` (тело), `getQuery` (query-строка), `getRouterParam` (параметр пути), `getCookie`/`setCookie`/`deleteCookie`, `getHeader`/`setHeader`, `getRequestIP`. Для всех входных данных есть **валидирующие** версии — `readValidatedBody`, `getValidatedQuery`, `getValidatedRouterParams` — которые принимают функцию-валидатор (например, `schema.parse` из Zod) и при ошибке отвечают 400. Всё, что пришло от клиента, — недоверенные данные.

## Вопрос

Как в серверном обработчике Nuxt читать данные запроса и работать с cookies и заголовками?

## Тело запроса

```ts
// server/api/orders.post.ts
import { z } from "zod";

const OrderSchema = z.object({
  productId: z.number().int().positive(),
  quantity: z.number().int().min(1).max(99),
});

export default defineEventHandler(async (event) => {
  const order = await readValidatedBody(event, OrderSchema.parse);
  // order: { productId: number; quantity: number }
  return createOrder(order);
});
```

`readBody(event)` без валидации вернёт `any` — используйте его только для быстрых экспериментов. Для форм `multipart/form-data` — `readMultipartFormData(event)` или `readFormData(event)`.

## Query

```ts
// GET /api/products?page=2&sort=price
const QuerySchema = z.object({
  page: z.coerce.number().int().min(1).default(1),
  sort: z.enum(["price", "date"]).default("date"),
});

export default defineEventHandler(async (event) => {
  const { page, sort } = await getValidatedQuery(event, QuerySchema.parse);
  return listProducts({ page, sort });
});
```

Значения query всегда строки (или массивы строк) — `z.coerce` приводит типы.

## Параметры пути

```ts
// server/api/users/[id].get.ts
export default defineEventHandler(async (event) => {
  const { id } = await getValidatedRouterParams(event, z.object({ id: z.coerce.number() }).parse);
  return findUser(id);
});
```

## Cookies

```ts
export default defineEventHandler((event) => {
  const theme = getCookie(event, "theme") ?? "light";

  setCookie(event, "session", "token-value", {
    httpOnly: true,                       // недоступна JS — защита от XSS
    secure: true,                         // только HTTPS
    sameSite: "lax",                      // базовая защита от CSRF
    path: "/",
    maxAge: 60 * 60 * 24 * 7,             // 7 дней
  });

  deleteCookie(event, "legacy");
  return { theme };
});
```

В компонентах для cookies есть `useCookie("theme")` — он работает и при SSR (читает заголовок запроса и устанавливает `Set-Cookie`), и в браузере.

## Заголовки и прочее

```ts
export default defineEventHandler((event) => {
  const ua = getHeader(event, "user-agent");
  const ip = getRequestIP(event, { xForwardedFor: true });
  const url = getRequestURL(event);

  setHeader(event, "cache-control", "no-store");
  setResponseStatus(event, 202);
  return { ua, ip, path: url.pathname };
});
```

## Контекст запроса

```ts
event.context.params;      // параметры маршрута
event.context.requestId;   // то, что положил server middleware
```

## Частые ошибки

- Доверять `readBody` без валидации.
- Ожидать числа в `getQuery` — там строки.
- Ставить сессионную cookie без `httpOnly` и `secure`.
- Доверять `X-Forwarded-For` без reverse proxy — заголовок легко подделать.

## Что важно помнить

- Валидирующие утилиты — стандартная практика: они и проверяют данные, и выводят типы.
- Cookie для сессии: `httpOnly`, `secure`, `sameSite: "lax"` или `"strict"`.
- Те же утилиты h3 используются в server middleware.

## Мини-шпаргалка

- `readValidatedBody`, `getValidatedQuery`, `getValidatedRouterParams`.
- `getCookie`, `setCookie(..., { httpOnly, secure, sameSite })`, `deleteCookie`.
- `getHeader`, `setHeader`, `setResponseStatus`.
- `getRequestIP`, `getRequestURL`.
