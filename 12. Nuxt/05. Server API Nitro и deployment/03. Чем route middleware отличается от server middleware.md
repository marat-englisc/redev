# Чем route middleware отличается от server middleware

> [!NOTE]
> **Route middleware** (`app/middleware`) — часть Vue-приложения: выполняется перед **переходом на страницу** (на сервере при первом запросе и в браузере при навигации), умеет `navigateTo` и `abortNavigation`, не видит API-запросы. **Server middleware** (`server/middleware`) — часть Nitro: выполняется на **каждый HTTP-запрос** к серверу (страницы, API, статика) до обработчика, не выполняется в браузере и не участвует в клиентской навигации. Первый — про UX навигации, второй — про HTTP: логирование, заголовки, контекст запроса, проверку сессии для API.

## Вопрос

Чем route middleware отличается от server middleware в Nuxt?

## Сравнение

| | Route middleware | Server middleware |
| --- | --- | --- |
| Каталог | `app/middleware/` | `server/middleware/` |
| Функция | `defineNuxtRouteMiddleware` | `defineEventHandler` |
| Когда | Перед переходом на страницу | Перед любым HTTP-запросом |
| Где выполняется | Сервер (первый рендер) и браузер | Только сервер |
| Клиентская навигация | Да | Нет (запроса к серверу нет) |
| API-запросы | Нет | Да |
| Подключение | Именованные, `.global`, inline | Все файлы, на каждый запрос |
| Инструменты | `navigateTo`, `abortNavigation`, composables Nuxt | `event`, утилиты h3, `useRuntimeConfig(event)` |

## Route middleware

```ts
// app/middleware/auth.ts
export default defineNuxtRouteMiddleware((to) => {
  const { loggedIn } = useUserSession();
  if (!loggedIn.value) return navigateTo(`/login?redirect=${encodeURIComponent(to.fullPath)}`);
});
```

Защищает **страницу** от показа гостю, но API этим не защищён.

## Server middleware

```ts
// server/middleware/01.request-id.ts
export default defineEventHandler((event) => {
  const id = getHeader(event, "x-request-id") ?? crypto.randomUUID();
  event.context.requestId = id;              // доступно во всех обработчиках этого запроса
  setHeader(event, "x-request-id", id);
});
```

```ts
// server/middleware/02.auth.ts
export default defineEventHandler(async (event) => {
  if (!event.path.startsWith("/api/admin")) return;
  const session = await getUserSession(event);
  if (session.user?.role !== "admin") {
    throw createError({ statusCode: 403 });
  }
});
```

Server middleware **не должен ничего возвращать**, если запрос нужно пропустить дальше: возвращённое значение станет ответом, и до обработчика дело не дойдёт.

## Что куда

| Задача | Middleware |
| --- | --- |
| Не пускать гостя на `/account` | Route |
| Выбрать layout по пути | Route |
| Логировать все HTTP-запросы | Server |
| Добавить `request-id`, распарсить сессию в `event.context` | Server |
| Запретить доступ к `/api/admin/*` | Server (или проверка в обработчике) |
| Редирект со старых URL | `routeRules.redirect` |

## Частые ошибки

- Полагаться на route middleware для защиты API.
- Тяжёлая логика в server middleware для всех путей, включая статику и `/_nuxt/*`.
- Возврат значения из server middleware.
- Использовать `navigateTo` в server middleware — там есть `sendRedirect(event, url)`.

## Что важно помнить

- Клиентская навигация вообще не обращается к серверу за HTML — server middleware её не видит.
- `event.context` — способ передать данные из server middleware в обработчики.
- Безопасность данных — всегда на сервере: в обработчике или server middleware.

## Мини-шпаргалка

- `app/middleware` — навигация, `server/middleware` — HTTP.
- Route: `navigateTo`, `abortNavigation`.
- Server: `event.context`, ничего не возвращать.
- Авторизация API — на сервере.
