# Что такое Nuxt

> [!NOTE]
> **Nuxt** — full-stack фреймворк поверх Vue (аналог Next.js в мире React). Vue отвечает за компоненты и реактивность, а Nuxt добавляет архитектуру приложения: файловый роутинг, SSR по умолчанию и гибридный рендеринг по маршрутам, SSR-совместимую загрузку данных (`useFetch`, `useAsyncData`), auto-imports, управление `<head>`, систему модулей и серверную часть на **Nitro** — API-маршруты, middleware, кэш и сборку под любой хостинг.

## Вопрос

Что такое Nuxt и какие задачи он решает поверх Vue?

## Основная идея

Чистый Vue — библиотека для UI. Чтобы собрать из неё production-приложение, нужно самостоятельно подключить и настроить роутер, SSR, загрузку данных без двойных запросов, мета-теги, code splitting, сборку и сервер. Nuxt даёт всё это по соглашениям:

```text
Nuxt = Vue + Vue Router + SSR/SSG + data fetching + head + auto-imports + модули + Nitro
```

## Минимальное приложение

```vue
<!-- app/app.vue -->
<template>
  <NuxtLayout>
    <NuxtPage />
  </NuxtLayout>
</template>
```

```vue
<!-- app/pages/products/[id].vue → /products/42 -->
<script setup lang="ts">
const route = useRoute();
const { data: product } = await useFetch(() => `/api/products/${route.params.id}`);

useSeoMeta({ title: () => product.value?.title });
</script>

<template>
  <h1>{{ product?.title }}</h1>
</template>
```

```ts
// server/api/products/[id].get.ts → GET /api/products/42
export default defineEventHandler((event) => {
  const id = getRouterParam(event, "id");
  return db.product.findUnique({ where: { id: Number(id) } });
});
```

Ни одного импорта: `useRoute`, `useFetch`, `useSeoMeta`, `defineEventHandler` подставляются автоматически. Страница рендерится на сервере, данные передаются клиенту в payload, повторного запроса при гидрации нет.

## Что Nuxt даёт из коробки

| Возможность | Зачем |
| --- | --- |
| Файловый роутинг | Маршруты из структуры `app/pages` |
| SSR по умолчанию | Готовый HTML для SEO и быстрого первого отображения |
| Гибридный рендеринг | SSR, SSG, SWR, ISR или SPA для каждого маршрута через `routeRules` |
| `useFetch` / `useAsyncData` | Загрузка данных без двойного запроса на сервере и клиенте |
| Auto-imports | Компоненты, composables и утилиты без ручных импортов |
| `useHead`, `useSeoMeta` | Управление мета-тегами |
| Nitro | API-маршруты, middleware, кэш, деплой на Node, serverless и edge |
| Модули | Готовые интеграции: изображения, шрифты, SEO, i18n, Pinia, UI-киты |
| DevTools и TypeScript | Типы генерируются автоматически |

## Где Nuxt особенно уместен

- Публичные сайты с важным SEO: контент, блоги, документация, e-commerce.
- Гибридные приложения: публичная часть с SSR/SSG и закрытый кабинет как SPA.
- Fullstack-проекты, где удобно держать UI и BFF-слой в одном репозитории.

Для закрытой внутренней админки без SEO обычный Vue SPA на Vite проще — но и там Nuxt с `ssr: false` даёт роутинг и структуру.

## Частые ошибки

- Думать, что Nuxt заменяет Vue: это надстройка, всё знание Vue остаётся нужным.
- Писать код, будто он выполняется только в браузере, — в Nuxt он по умолчанию выполняется и на сервере.
- Путать Nuxt (фреймворк) и Nitro (его серверный движок).

## Что важно помнить

- Nuxt построен на соглашениях: имя файла и папка определяют роль кода.
- SSR включён по умолчанию, поэтому код страниц должен быть SSR-safe.
- Актуальная мажорная версия — Nuxt 4 со структурой `app/` (см. [что изменилось в Nuxt 4](<08. Что изменилось в Nuxt 4.md>)).
- Если вы знаете Next.js, многие идеи совпадают — см. [сравнение Nuxt и Next.js](<07. Чем Nuxt отличается от Next.js.md>).

## Мини-шпаргалка

- Nuxt = Vue + роутинг + SSR + данные + Nitro + модули.
- `app/` — Vue-приложение, `server/` — Nitro.
- SSR по умолчанию, режимы рендеринга — по маршрутам.
- Auto-imports для компонентов и composables.
