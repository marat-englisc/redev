# Чем Nuxt отличается от Vue SPA

> [!NOTE]
> Vue SPA отдаёт браузеру почти пустой HTML и строит интерфейс JavaScript'ом на клиенте. Nuxt по умолчанию **рендерит страницу на сервере** и отдаёт готовый HTML, который затем гидрируется, а также умеет генерировать статические страницы, смешивать режимы по маршрутам и содержит серверную часть (Nitro). Плюсы Nuxt — SEO, быстрый первый контент, готовая архитектура; цена — нужен сервер (или prerender) и SSR-safe код.

## Вопрос

Чем Nuxt отличается от обычного Vue SPA и когда что выбрать?

## Основная идея

**Vue SPA (Vite + Vue Router):**

```html
<!-- ответ сервера -->
<div id="app"></div>
<script type="module" src="/assets/index-a1b2.js"></script>
```

```text
HTML (пусто) → загрузка JS → запуск Vue → запрос данных → отрисовка
```

**Nuxt (SSR):**

```html
<!-- ответ сервера -->
<div id="__nuxt">
  <h1>Каталог клавиатур</h1>
  <article>Keychron K2 — 9 990 ₽</article>
</div>
<script>/* payload с данными */</script>
```

```text
HTML с контентом → видно сразу → загрузка JS → гидрация → интерактивность
```

## Сравнение

| | Vue SPA | Nuxt |
| --- | --- | --- |
| Первый HTML | Пустой контейнер | Готовая разметка с данными |
| SEO | Зависит от выполнения JS поисковиком | Контент в HTML сразу |
| Роутинг | Vue Router настраивается вручную | Файловый, генерируется |
| Загрузка данных | Своя логика (`onMounted`, TanStack Query) | `useFetch` с передачей через payload |
| Meta-теги | Вручную или `@unhead/vue` | `useSeoMeta` из коробки |
| Сервер | Не нужен, статический хостинг | Node/serverless/edge или prerender |
| Backend в проекте | Нет | `server/api` на Nitro |
| Сложность | Ниже | Нужно понимать SSR и гидрацию |

## Когда достаточно Vue SPA

- Приложение доступно только после входа (админка, CRM, внутренний инструмент).
- SEO не нужно, а backend уже существует отдельно.
- Нужен самый простой деплой на CDN.

## Когда выбрать Nuxt

- Публичные страницы должны индексироваться и быстро отображаться.
- Нужен гибрид: лендинг — prerender, каталог — SWR, кабинет — SPA.
- Удобно держать BFF-слой рядом с фронтендом.
- Хочется готовую структуру проекта, а не собирать её из библиотек.

Nuxt можно использовать и как SPA: `ssr: false` глобально или `routeRules: { '/admin/**': { ssr: false } }` для части маршрутов.

## Частые ошибки

- Переносить SPA-привычки в Nuxt: `window` в `setup`, загрузка данных в `onMounted`.
- Выбирать Nuxt для закрытой админки только «ради структуры» и потом бороться с SSR.
- Считать, что SSR автоматически даёт хорошее SEO, — мета-теги, canonical и статус-коды всё равно нужны.

## Что важно помнить

- Главная разница — где формируется первый HTML: в браузере или на сервере.
- После гидрации Nuxt-приложение работает как обычное SPA: переходы между страницами — клиентские.
- Выбор зависит от SEO, требований к первому отображению и инфраструктуры.

## Мини-шпаргалка

- SPA: пустой HTML → JS рендерит.
- Nuxt: готовый HTML → гидрация.
- SPA — для закрытых приложений, Nuxt — для публичных и гибридных.
- `ssr: false` превращает Nuxt в SPA.
