# Чем Nuxt отличается от Next.js

> [!NOTE]
> Nuxt и Next.js решают одну задачу — full-stack фреймворк с SSR, файловым роутингом и гибридным рендерингом — для разных UI-библиотек: Vue и React. Ключевые различия: в Nuxt **нет Server Components** по умолчанию — все компоненты изоморфные и гидрируются, данные грузятся composables (`useFetch`) с передачей через payload; режим рендеринга задаётся **централизованно в `routeRules`**, а не экспортами из файлов; серверная часть — независимый от хостинга **Nitro**; широко используются **auto-imports** и модули.

## Вопрос

Чем Nuxt отличается от Next.js и как перенести опыт React/Next на Nuxt?

## Соответствие понятий

| Next.js (App Router) | Nuxt |
| --- | --- |
| `app/page.tsx` | `app/pages/index.vue` |
| `app/blog/[slug]/page.tsx` | `app/pages/blog/[slug].vue` |
| `app/[...slug]/page.tsx` | `app/pages/[...slug].vue` |
| `layout.tsx` | `app/layouts/default.vue` + `<NuxtLayout>` |
| `<Link>` | `<NuxtLink>` |
| `useRouter().push()` | `navigateTo()` |
| `middleware.ts` / `proxy.ts` | `app/middleware/*.ts` (навигация) и `server/middleware/*.ts` (HTTP) |
| Route Handlers `route.ts` | `server/api/*.get.ts` |
| Server Actions | Нет прямого аналога: `server/api` + `$fetch` |
| `fetch` в Server Component | `useFetch` / `useAsyncData` в `setup` |
| `revalidate`, `dynamic` | `routeRules`: `swr`, `isr`, `prerender`, `ssr: false` |
| `generateMetadata` | `useSeoMeta` / `useHead` |
| `next/image`, `next/font` | `@nuxt/image`, `@nuxt/fonts` |
| `NEXT_PUBLIC_*` | `runtimeConfig.public` + `NUXT_PUBLIC_*` |
| `error.tsx`, `not-found.tsx` | `error.vue`, `createError({ statusCode: 404 })` |
| `loading.tsx` / Suspense | `status` из `useFetch`, `<NuxtLoadingIndicator>` |
| `"use client"` | Не нужно: все компоненты клиентские; `.client.vue`, `<ClientOnly>` для браузерных |

## Принципиальные различия

**Компонентная модель.** В Next.js App Router компоненты по умолчанию серверные, их код не попадает в бандл. В Nuxt каждый компонент рендерится на сервере **и** гидрируется на клиенте. Ближайший аналог RSC — серверные компоненты-«острова» (`.server.vue`, `<NuxtIsland>`), но это экспериментальная опция (`experimental.componentIslands`), а не основа.

**Загрузка данных.** В Next `await fetch()` прямо в серверном компоненте. В Nuxt — `await useFetch()` в `setup`: запрос выполняется на сервере, результат сериализуется в payload, и клиент при гидрации его переиспользует. Вызов «голого» `$fetch` в `setup` приведёт к двойному запросу.

**Кэш и рендеринг.** Next настраивает кэш на уровне `fetch` и сегментов маршрутов. Nuxt — на уровне маршрутов в одном месте (`routeRules`) и серверных обработчиков (`cachedEventHandler`).

**Сервер.** Nitro собирает сервер под десятки платформ (Node, Vercel, Netlify, Cloudflare, Deno, Bun) через presets. Next.js максимально полно работает на Vercel, self-hosting требует больше внимания.

**Мутации.** Server Actions нет; формы отправляют `$fetch` в API-маршрут, после чего обновляют данные через `refresh()` или `refreshNuxtData()`.

**Auto-imports.** В Nuxt `ref`, `computed`, `useFetch`, компоненты из `app/components` доступны без импортов. В Next всё импортируется явно.

## Что общее

- SSR, SSG, ISR, SPA-режим и их смешение по маршрутам.
- Гидрация и ошибки hydration mismatch с теми же причинами (даты, `Math.random`, `window`).
- Необходимость отделять серверные секреты от публичных переменных.
- Файловый роутинг с динамическими и catch-all сегментами.

## Частые ошибки при переходе с Next.js

- Ждать, что код компонента не попадёт в бандл, как у Server Components.
- Писать `fetch` в `setup` без `useFetch` — двойной запрос.
- Искать Server Actions вместо обычного API-маршрута.
- Объявлять глобальное состояние на уровне модуля — на сервере оно общее для всех запросов (используйте `useState` или Pinia).

## Что важно помнить

- Концепции рендеринга одинаковые, различаются компонентная модель и место настройки кэша.
- В Nuxt всё изоморфно по умолчанию: код страниц выполняется в обоих окружениях.
- Опыт с гидрацией, SEO и кэшированием в Next.js переносится почти полностью.

## Мини-шпаргалка

- Pages: `[slug].vue` ↔ `[slug]/page.tsx`.
- Данные: `useFetch` ↔ `fetch` в RSC.
- Кэш: `routeRules` ↔ `revalidate`/`dynamic`.
- API: `server/api` ↔ Route Handlers.
- RSC нет, есть острова `.server.vue`.
