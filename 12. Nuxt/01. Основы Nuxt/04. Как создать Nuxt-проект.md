# Как создать Nuxt-проект

> [!NOTE]
> Новый проект создают командой `npm create nuxt@latest <name>` (официальный CLI `nuxi`/`@nuxt/cli` с шаблонами). Основные скрипты: `nuxt dev` — разработка с HMR на `localhost:3000`, `nuxt build` — production-сборка в `.output/`, `nuxt generate` — статический сайт, `nuxt preview` — локальный запуск сборки. Модули добавляют через `npx nuxt module add <name>`. Каталоги `.nuxt/` и `.output/` генерируются и в git не коммитятся.

## Вопрос

Как создать Nuxt-проект и что в нём есть сразу после создания?

## Создание

```bash
npm create nuxt@latest my-app
cd my-app
npm run dev
```

CLI предложит шаблон, пакетный менеджер и инициализацию git. Альтернатива для pnpm — `pnpm create nuxt my-app`.

## Скрипты

```json
{
  "scripts": {
    "dev": "nuxt dev",
    "build": "nuxt build",
    "generate": "nuxt generate",
    "preview": "nuxt preview",
    "postinstall": "nuxt prepare"
  }
}
```

| Команда | Что делает |
| --- | --- |
| `nuxt dev` | Dev-сервер с HMR и DevTools |
| `nuxt build` | Production-сборка: `.output/public` (статика) и `.output/server` (Nitro) |
| `nuxt generate` | Prerender всех маршрутов в статику |
| `nuxt preview` | Запуск production-сборки локально |
| `nuxt prepare` | Генерация `.nuxt/` и типов (после `npm install`) |
| `nuxt typecheck` | Проверка типов через `vue-tsc` |
| `nuxt module add image` | Установить модуль и добавить его в `nuxt.config.ts` |
| `nuxt upgrade` | Обновить Nuxt |

Запуск production-сборки на Node.js: `node .output/server/index.mjs`.

## Структура после создания

```text
my-app/
├── app/
│   └── app.vue          # корневой компонент
├── public/              # статика как есть: favicon.ico, robots.txt
├── server/              # появится, когда добавишь API
├── nuxt.config.ts
├── package.json
└── tsconfig.json
```

Дальше по мере необходимости добавляют:

```text
app/pages/index.vue        → маршрут /
app/components/AppHeader.vue
app/composables/useCart.ts
server/api/hello.get.ts    → GET /api/hello
```

Как только появляется `app/pages`, Nuxt подключает Vue Router; в `app.vue` тогда нужен `<NuxtPage />`.

## Сгенерированные каталоги

| Каталог | Что это | В git? |
| --- | --- | --- |
| `.nuxt/` | Сгенерированный код и типы для dev | Нет |
| `.output/` | Результат `nuxt build` | Нет |
| `node_modules/` | Зависимости | Нет |

Руками `.nuxt/` не редактируют — он перезаписывается. Если IDE не видит auto-imports, помогает `npx nuxt prepare`.

## Частые ошибки

- Использовать устаревшие команды `npx nuxi init` и `create-nuxt-app` (это Nuxt 2) из старых статей.
- Коммитить `.nuxt/` и `.output/`.
- Править файлы в `.nuxt/`.
- Запускать production через `nuxt dev`.

## Что важно помнить

- `nuxt build` собирает сервер, `nuxt generate` — статику; это разные стратегии деплоя.
- Типы и auto-imports берутся из `.nuxt/`, поэтому после установки зависимостей выполняется `nuxt prepare`.
- Модули проще ставить командой `nuxt module add` — она обновляет конфиг сама.

## Мини-шпаргалка

- `npm create nuxt@latest my-app`.
- `dev`, `build`, `generate`, `preview`.
- `.output/server/index.mjs` — запуск на Node.js.
- `.nuxt/` и `.output/` — в `.gitignore`.
