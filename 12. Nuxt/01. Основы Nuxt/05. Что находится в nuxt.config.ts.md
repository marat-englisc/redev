# Что находится в nuxt.config.ts

> [!NOTE]
> `nuxt.config.ts` — главный файл конфигурации, обёрнутый в `defineNuxtConfig` для типизации. В нём подключают **модули** (`modules`), глобальные стили (`css`), базовый `<head>` (`app.head`), **`runtimeConfig`** (переменные окружения: серверные и `public`), **`routeRules`** (режим рендеринга и кэш по маршрутам), настройки Nitro, Vite, TypeScript и `devtools`. Конфиг читается при сборке — бизнес-логике и секретам в виде значений в нём не место.

## Вопрос

Что настраивается в `nuxt.config.ts`?

## Пример конфига

```ts
export default defineNuxtConfig({
  compatibilityDate: "2025-07-15",
  devtools: { enabled: true },

  modules: ["@nuxt/image", "@nuxt/fonts", "@pinia/nuxt", "@nuxtjs/seo"],

  css: ["~/assets/css/main.css"],

  app: {
    head: {
      htmlAttrs: { lang: "ru" },
      titleTemplate: "%s · Магазин",
      link: [{ rel: "icon", href: "/favicon.ico" }],
    },
  },

  runtimeConfig: {
    apiSecret: "",                  // NUXT_API_SECRET, только сервер
    public: {
      apiBase: "/api",              // NUXT_PUBLIC_API_BASE, доступно клиенту
    },
  },

  routeRules: {
    "/": { prerender: true },
    "/blog/**": { swr: 3600 },
    "/admin/**": { ssr: false },
    "/old": { redirect: "/new" },
  },

  nitro: {
    preset: "node-server",
  },

  typescript: {
    typeCheck: true,
  },
});
```

## Основные разделы

| Поле | Зачем |
| --- | --- |
| `modules` | Подключение модулей и их опций |
| `css` | Глобальные стили (`~` указывает на `app/`) |
| `app.head` | Общие мета-теги, `lang`, `titleTemplate` |
| `runtimeConfig` | Конфигурация, переопределяемая переменными окружения |
| `routeRules` | Рендеринг, кэш, редиректы, заголовки по маршрутам |
| `ssr` | `false` — режим SPA для всего приложения |
| `nitro` | Preset деплоя, хранилища, prerender |
| `vite` | Плагины и настройки Vite |
| `components`, `imports` | Настройка auto-imports |
| `alias` | Свои псевдонимы путей |
| `experimental`, `future` | Включение новых возможностей |
| `compatibilityDate` | Дата, по которой фиксируется поведение пресетов Nitro |

## Окружения в одном файле

```ts
export default defineNuxtConfig({
  $development: { devtools: { enabled: true } },
  $production: { routeRules: { "/**": { headers: { "x-frame-options": "DENY" } } } },
});
```

## Что куда класть

| Что | Куда |
| --- | --- |
| Модули, сборка, рендеринг | `nuxt.config.ts` |
| Значения, зависящие от окружения (URL API, ключи) | `runtimeConfig` + переменные `NUXT_*` |
| Публичные настройки UI, которые можно менять в рантайме | `app.config.ts` |
| Бизнес-логика | composables, `server/utils` |

## Частые ошибки

- Писать `apiSecret: process.env.SECRET` и ожидать, что значение поменяется без пересборки: подставляется значение на момент сборки. В рантайме значения переопределяют только переменные `NUXT_*`.
- Класть секреты в `runtimeConfig.public`.
- Ставить в `modules` пакет, не являющийся Nuxt-модулем (обычные Vue-плагины подключают через `app/plugins`).

## Что важно помнить

- `nuxt.config.ts` выполняется при сборке, а не в браузере и не на каждом запросе.
- Ключи `runtimeConfig` в camelCase сопоставляются с переменными `NUXT_` в SCREAMING_SNAKE_CASE: `apiSecret` → `NUXT_API_SECRET`.
- Изменения в конфиге требуют перезапуска dev-сервера (часть применяется автоматически).

## Мини-шпаргалка

- `defineNuxtConfig({ ... })`.
- `modules`, `css`, `app.head`.
- `runtimeConfig` + `public`.
- `routeRules` — гибридный рендеринг.
- `$development` / `$production` — переопределения по окружению.
