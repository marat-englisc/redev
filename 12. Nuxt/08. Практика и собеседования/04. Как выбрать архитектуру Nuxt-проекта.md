# Как выбрать архитектуру Nuxt-проекта

> [!NOTE]
> Архитектура Nuxt-проекта определяется типом продукта и тем, где живёт бизнес-логика. Небольшому сайту достаточно стандартной структуры `app/`. Контентный проект строится вокруг Nuxt Content и prerender. Продукт с публичной частью и кабинетом — гибрид: SSR/SWR для витрины, CSR для кабинета, `server/` как BFF к основному backend. Большое приложение делят на **доменные слои** (`layers/catalog`, `layers/checkout`) или фичи с явными границами. Общие правила: UI — в компонентах, состояние и сценарии — в composables/stores, серверная логика — в `server/utils`, общие типы и схемы — в `shared/`.

## Вопрос

Как спроектировать архитектуру Nuxt-проекта под разные типы продуктов?

## Небольшой сайт

```text
app/
├── pages/
├── components/
├── layouts/default.vue
└── assets/css/main.css
nuxt.config.ts            # routeRules: { "/**": { prerender: true } }
```

Лендинг, портфолио, сайт компании. Статика на CDN, без сервера.

## Контент: блог, документация

```text
content/
├── blog/*.md
└── docs/**/*.md
app/
├── pages/blog/[...slug].vue
└── components/content/   # компоненты для MDC в markdown
nuxt.config.ts            # @nuxt/content, @nuxtjs/seo, prerender или swr
```

Контент — в git или headless CMS, страницы пререндерятся, поиск и навигация — из Nuxt Content.

## Продукт: витрина + кабинет

```text
app/
├── pages/
│   ├── index.vue                 # prerender
│   ├── catalog/[...slug].vue     # swr
│   └── account/                  # ssr: false или SSR без кэша
├── composables/                  # useCart, useAuth
├── stores/                       # Pinia: корзина, фильтры
└── middleware/auth.ts
server/
├── api/                          # BFF: агрегация, сессии, прокси к backend
└── utils/backend.ts              # клиент основного API с секретами
shared/
├── types/                        # DTO, общие для app и server
└── utils/validation.ts           # Zod-схемы для форм и API
```

```ts
routeRules: {
  "/": { prerender: true },
  "/catalog/**": { swr: 600 },
  "/account/**": { ssr: false },
  "/api/backend/**": { proxy: "https://backend.internal/**" },
}
```

## Большое приложение: доменные слои

```text
layers/
├── base/        # дизайн-система, layout, обработка ошибок, auth-утилиты
├── catalog/     # страницы, компоненты, composables, server/api каталога
├── checkout/    # корзина, оформление заказа
└── account/     # личный кабинет
app/             # точка сборки: app.vue, глобальная конфигурация
```

Каждый слой — самостоятельный кусок приложения со своими страницами и API; зависимости между доменами идут через явный публичный интерфейс (composables, типы), а не через импорт внутренних файлов. См. [Nuxt Layers](<../07. Оптимизация и Nuxt модули/10. Что такое Nuxt Layers.md>).

## Где держать логику

| Логика | Место |
| --- | --- |
| Отображение, локальное UI-состояние | Компоненты |
| Сценарии и общее состояние фичи | `app/composables`, Pinia |
| Доступ к БД, секреты, внешние API | `server/utils`, `server/api` |
| Типы, схемы валидации, чистые функции | `shared/` |
| Глобальная инициализация | `app/plugins`, `server/plugins` |
| Повторное использование между проектами | Layers, модули |

## Nuxt как BFF или как backend

| | Nuxt как BFF | Nuxt как полноценный backend |
| --- | --- | --- |
| Бизнес-логика | В отдельном сервисе (NestJS и др.) | В `server/` |
| Задачи Nuxt-сервера | Сессии, агрегация, кэш, прокси | Всё, включая БД и транзакции |
| Когда | Сложный домен, несколько клиентов, отдельная команда | Небольшой продукт, одна команда |

## Частые ошибки

- Один гигантский каталог `components/` без структуры по доменам.
- Бизнес-логика в компонентах страниц.
- Прямые вызовы внешнего backend из браузера с токенами вместо BFF.
- Импорт внутренних файлов одного домена из другого.
- Один режим рендеринга для всего приложения.

## Что важно помнить

- Архитектура начинается с карты страниц и их режимов рендеринга.
- `shared/` — контракт между клиентом и сервером: типы и схемы пишутся один раз.
- Слои масштабируют проект по доменам без отдельного монорепозитория.

## Мини-шпаргалка

- Сайт — `app/` + prerender.
- Контент — Nuxt Content + prerender/swr.
- Продукт — гибрид `routeRules` + BFF в `server/`.
- Большое приложение — `layers/` по доменам.
- UI → composables/stores → server/utils → shared.
