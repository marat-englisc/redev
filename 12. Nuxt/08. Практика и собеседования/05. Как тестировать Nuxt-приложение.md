# Как тестировать Nuxt-приложение

> [!NOTE]
> Для Nuxt есть официальный пакет `@nuxt/test-utils`. **Unit-тесты** компонентов и composables запускают в Vitest с окружением `nuxt`: оно поднимает экземпляр Nuxt-приложения, поэтому работают auto-imports, `useState`, `useRuntimeConfig`, плагины; монтируют через `mountSuspended`/`renderSuspended`, подменяют auto-imports через `mockNuxtImport`, эндпоинты — через `registerEndpoint`. **E2E-тесты** запускают собранное приложение (`setup()` + `$fetch`) или используют Playwright — так проверяют SSR-HTML, статус-коды и гидрацию. Чистые утилиты и серверную логику тестируют обычным Vitest без окружения Nuxt.

## Вопрос

Как тестировать Nuxt-приложение: компоненты, composables, API и SSR?

## Установка

```bash
npm i -D @nuxt/test-utils vitest @vue/test-utils happy-dom @testing-library/vue playwright-core
```

```ts
// vitest.config.ts
import { defineVitestConfig } from "@nuxt/test-utils/config";

export default defineVitestConfig({
  test: {
    environment: "nuxt",
  },
});
```

Для скорости часто разделяют проекты Vitest: `unit` (окружение `node`, чистые функции) и `nuxt` (компоненты и composables).

## Компонент

```ts
// app/components/ProductCard.nuxt.spec.ts
import { mountSuspended } from "@nuxt/test-utils/runtime";
import ProductCard from "./ProductCard.vue";

it("показывает название и цену", async () => {
  const wrapper = await mountSuspended(ProductCard, {
    props: { product: { id: 1, title: "Keychron K2", price: 9990 } },
  });
  expect(wrapper.text()).toContain("Keychron K2");
  expect(wrapper.text()).toContain("9 990");
});
```

`mountSuspended` поддерживает асинхронный `setup` (`await useFetch`) и контекст Nuxt.

## Подмена auto-imports и API

```ts
import { mockNuxtImport, registerEndpoint, mountSuspended } from "@nuxt/test-utils/runtime";

mockNuxtImport("useUserSession", () => () => ({ loggedIn: ref(true), user: ref({ name: "Анна" }) }));

registerEndpoint("/api/orders", () => [{ id: 1, total: 1500 }]);

it("показывает заказы пользователя", async () => {
  const page = await mountSuspended(OrdersPage);
  expect(page.text()).toContain("1 500");
});
```

## Composable

```ts
import { useCart } from "~/composables/useCart";

it("считает итог корзины", () => {
  const { add, total } = useCart();
  add({ id: 1, price: 100, qty: 2 });
  expect(total.value).toBe(200);
});
```

В окружении `nuxt` `useState` внутри `useCart` работает как в приложении.

## Серверные маршруты и SSR

```ts
// test/e2e/products.test.ts
import { setup, $fetch, fetch } from "@nuxt/test-utils/e2e";

await setup({ server: true });   // сборка и запуск приложения

it("SSR отдаёт товар в HTML", async () => {
  const html = await $fetch("/products/keychron-k2");
  expect(html).toContain("<h1>Keychron K2</h1>");
});

it("несуществующий товар — 404", async () => {
  const res = await fetch("/products/unknown");
  expect(res.status).toBe(404);
});
```

Для пользовательских сценариев (вход, корзина, оформление заказа) — Playwright: `@nuxt/test-utils/playwright` или обычный Playwright против `nuxt preview`.

## Что тестировать в Nuxt

| Уровень | Что проверить |
| --- | --- |
| Unit | Утилиты, схемы Zod, вычисления в composables |
| Компоненты | Рендер по пропсам, события, состояния loading/error |
| Серверные обработчики | Валидация, коды ошибок, проверка прав |
| E2E/SSR | HTML с контентом, мета-теги, 404/301, гидрация без ошибок |
| Пользовательские сценарии | Вход, защищённые страницы, формы |

## Частые ошибки

- Монтировать компоненты с `await useFetch` обычным `mount` — нет контекста Nuxt и Suspense.
- Гонять все тесты в окружении `nuxt` — медленно; чистую логику тестируют в `node`.
- Не проверять SSR-ответ: тесты в jsdom не покажут, что контент рендерится только на клиенте.
- Мокать всё подряд и тестировать моки.

## Что важно помнить

- `environment: "nuxt"` + `mountSuspended` — основа тестирования компонентов.
- `mockNuxtImport` и `registerEndpoint` изолируют компонент от сессии и API.
- E2E на собранном приложении — единственный способ проверить SSR и статус-коды.
- Общие подходы к тестированию — в разделе [Тестирование](<../../14. Тестирование/00. Карта раздела и маршрут изучения.md>).

## Мини-шпаргалка

- `@nuxt/test-utils` + Vitest, `environment: "nuxt"`.
- `mountSuspended`, `renderSuspended`.
- `mockNuxtImport`, `mockComponent`, `registerEndpoint`.
- E2E: `setup({ server: true })`, `$fetch`, `fetch`, Playwright.
