# Production checklist для Nuxt

> [!NOTE]
> Перед выпуском Nuxt-приложение проверяют по шести направлениям: **рендеринг** (режимы и кэш в `routeRules`, отсутствие hydration-ошибок), **данные и конфигурация** (`useFetch` для начальных данных, секреты вне `public`, переменные `NUXT_*` в окружении), **безопасность** (проверки прав в API, httpOnly-cookies, заголовки, валидация), **SEO** (мета-теги, canonical, sitemap, robots, 404), **производительность** (Core Web Vitals, бандл, изображения, шрифты, сторонние скрипты) и **эксплуатация** (логи, мониторинг ошибок, healthcheck, общее хранилище кэша и сессий).

## Вопрос

Что проверить в Nuxt-приложении перед выпуском в production?

## Рендеринг

- [ ] Режимы выбраны осознанно: prerender для статичного, `swr`/`isr` для публичного динамического, SSR или CSR для личного.
- [ ] `routeRules` не кэшируют страницы, зависящие от cookie и сессии.
- [ ] В консоли нет предупреждений hydration mismatch.
- [ ] Браузерные библиотеки изолированы в `<ClientOnly>`, `.client.vue`, `*.client.ts`.
- [ ] `nuxt build` и `nuxt preview` проходят без предупреждений.

## Данные и конфигурация

- [ ] Начальные данные — через `useFetch`/`useAsyncData`, нет двойных запросов (проверить в DevTools → Payload).
- [ ] Нет `ref` и синглтонов с пользовательскими данными на уровне модулей.
- [ ] Секреты только в серверной части `runtimeConfig`, `public` проверен.
- [ ] Переменные `NUXT_*` заданы на платформе (`.env` в production не читается).
- [ ] Payload не содержит лишних полей и персональных данных.

## Безопасность

- [ ] Каждый защищённый `server/api` проверяет сессию и права, а не полагается на route middleware.
- [ ] Входные данные валидируются (`readValidatedBody`, `getValidatedQuery`).
- [ ] Сессионные cookies: `httpOnly`, `secure`, `sameSite`.
- [ ] Заголовки безопасности и CSP (Nuxt Security), защита от CSRF для мутаций.
- [ ] Ошибки API не раскрывают стек и детали БД.
- [ ] `v-html` только с санитизированным контентом.
- [ ] Rate limiting для логина и тяжёлых эндпоинтов.

## SEO

- [ ] Уникальные title и description, один `<h1>`.
- [ ] Canonical и `site.url` указывают на production-домен.
- [ ] `/sitemap.xml` и `/robots.txt` отдают 200; на production нет `Disallow: /`.
- [ ] Staging и preview закрыты `noindex`.
- [ ] Несуществующие страницы и сущности отдают 404.
- [ ] OG-картинки абсолютные и проверены в отладчиках.

## Производительность

- [ ] LCP-изображение с `preload` и `fetchpriority="high"`, остальные — `loading="lazy"` и `sizes`.
- [ ] Шрифты через Nuxt Fonts, только нужные начертания и subsets.
- [ ] Сторонние скрипты через Nuxt Scripts с триггерами и согласием.
- [ ] Тяжёлые компоненты — `Lazy` и `hydrate-on-*`.
- [ ] `nuxt analyze` — нет неожиданно больших зависимостей.
- [ ] `/_nuxt/**` отдаётся с `immutable`, включено сжатие.
- [ ] Lighthouse и полевые Core Web Vitals в зелёной зоне для ключевых страниц.

## Эксплуатация

- [ ] Ошибки отправляются в Sentry или аналог (клиент и сервер).
- [ ] Структурированные логи сервера в stdout.
- [ ] `/api/health` для балансировщика.
- [ ] При нескольких экземплярах кэш Nitro, сессии и rate limiter — в общем хранилище (Redis).
- [ ] Graceful shutdown: закрытие соединений с БД в хуке `close`.
- [ ] План отката: предыдущий образ или деплой доступны.

## Что важно помнить

- Чек-лист полезно превратить в автоматические проверки: тесты на 404 и мета-теги, Lighthouse CI, Link Checker, сканирование заголовков.
- Самые дорогие ошибки — утечки данных через кэш и состояние, их проверяют в первую очередь.
- Production-окружение должно быть максимально похоже на staging: тот же образ, другие переменные.

## Мини-шпаргалка

- Рендеринг: режимы, кэш, hydration.
- Данные: payload, нет глобального состояния, секреты.
- Безопасность: права в API, cookies, CSP, валидация.
- SEO: мета, canonical, sitemap, robots, 404.
- Скорость: изображения, шрифты, скрипты, бандл.
- Эксплуатация: мониторинг, логи, healthcheck, Redis.
