# Как работает lazy hydration в Nuxt

> [!NOTE]
> **Отложенная гидрация** позволяет отрендерить компонент на сервере (HTML виден сразу), но подключить его JavaScript и интерактивность **позже** — когда он попадёт в viewport, браузер освободится, пользователь начнёт взаимодействие или выполнится условие. В Nuxt это делается пропами на `Lazy`-компонентах: `hydrate-on-visible`, `hydrate-on-idle`, `hydrate-on-interaction`, `hydrate-on-media-query`, `hydrate-after`, `hydrate-when`, `hydrate-never`. Это уменьшает работу основного потока при загрузке и улучшает INP и TBT. Не путать с `Lazy`-загрузкой без гидрации: та откладывает код компонента, который рендерится только на клиенте.

## Вопрос

Что такое lazy hydration и как её использовать в Nuxt?

## Проблема

SSR отдаёт HTML быстро, но затем браузер должен загрузить и выполнить JS **всех** компонентов страницы, чтобы гидрировать их. Карусель, комментарии, карта и подвал гидрируются одновременно с кнопкой «Купить» — основной поток занят, первые клики тормозят.

## Стратегии

```vue
<template>
  <ProductHero />                                    <!-- критичное — гидрируется сразу -->

  <LazyProductReviews hydrate-on-visible />          <!-- при попадании в viewport -->
  <LazyRecommendations hydrate-on-idle />            <!-- когда браузер свободен -->
  <LazySupportChat hydrate-on-interaction />         <!-- при pointerenter, click или focus -->
  <LazyMobileMenu hydrate-on-media-query="(max-width: 768px)" />
  <LazyPromoBanner :hydrate-after="3000" />          <!-- через 3 секунды -->
  <LazyFilters :hydrate-when="filtersReady" />       <!-- когда условие станет true -->
  <LazySiteFooter hydrate-never />                   <!-- статичный HTML, без JS -->
</template>
```

| Стратегия | Когда подходит |
| --- | --- |
| `hydrate-on-visible` | Блоки ниже первого экрана |
| `hydrate-on-idle` | Второстепенные виджеты |
| `hydrate-on-interaction` | Чаты, раскрывающиеся меню, формы, которые трогают редко |
| `hydrate-on-media-query` | Компоненты только для мобильных или десктопа |
| `hydrate-when` | Гидрация по бизнес-условию |
| `hydrate-never` | Полностью статичный контент |

```vue
<LazyProductReviews hydrate-on-visible @hydrated="trackReviewsShown" />
```

## Два разных «lazy»

| | `<LazyX v-if="show">` | `<LazyX hydrate-on-visible>` |
| --- | --- | --- |
| HTML на сервере | Нет (если условие ложно) | Да |
| Когда грузится JS | Когда условие станет true | По стратегии гидрации |
| SEO | Контента нет в HTML | Контент в HTML |
| Для чего | Модалки, тяжёлые редакторы по требованию | Видимые, но не срочные блоки |

## Ограничения

- Работает только для `Lazy`-компонентов в SFC с пропами, заданными в шаблоне (не через `v-bind="obj"`).
- Любое изменение пропсов гидрирует компонент немедленно.
- До гидрации компонент не реагирует на клики — не применяйте к критичным элементам управления.

## Когда не использовать

- Навигация, кнопки покупки, формы первого экрана.
- Компоненты, от которых зависят соседние (общее состояние меняется при гидрации).
- Лёгкие компоненты — накладные расходы не окупятся.

## Частые ошибки

- Откладывать гидрацию кнопок первого экрана — пользователь кликает, ничего не происходит.
- Путать с `v-if` + `Lazy` и терять контент из HTML.
- Не измерять эффект: смотреть TBT и INP до и после.

## Что важно помнить

- Отложенная гидрация сохраняет SEO (HTML есть) и экономит JS при загрузке.
- Лучшие кандидаты — тяжёлые блоки ниже первого экрана и редко используемые виджеты.
- Vue 3.5 предоставляет те же стратегии для `defineAsyncComponent({ hydrate: hydrateOnVisible() })` — Nuxt делает их удобными через пропы.

## Мини-шпаргалка

- `<LazyX hydrate-on-visible | hydrate-on-idle | hydrate-on-interaction>`.
- `hydrate-after`, `hydrate-when`, `hydrate-on-media-query`, `hydrate-never`.
- `@hydrated` — событие.
- HTML сразу, JS позже.
- Не для критичного UI.
