# Что такое Nuxt Layers

> [!NOTE]
> **Layer** — частичное Nuxt-приложение (свои `app/components`, `pages`, `composables`, `server/`, `nuxt.config.ts`, `app.config.ts`), которое другой проект подключает через `extends`. Файлы слоёв объединяются с проектом, при совпадении имён побеждает проект (он «выше»), конфиги сливаются. Слои используют для **дизайн-системы и общих компонентов** нескольких приложений, тем, базовой настройки (ESLint, модули, авторизация) и **модульной архитектуры** большого приложения: каталог `layers/` в корне подключается автоматически. Слой может быть локальной папкой, npm-пакетом или git-репозиторием.

## Вопрос

Что такое Nuxt Layers и когда их использовать?

## Подключение

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  extends: [
    "../base",                         // локальная папка
    "@acme/nuxt-ui-layer",             // npm-пакет
    ["github:acme/nuxt-theme#v2", { install: true }], // git
  ],
});
```

Каталоги в `layers/` проекта подключаются без `extends`:

```text
project/
├── layers/
│   ├── auth/          # страницы входа, middleware, server/api/auth
│   ├── catalog/       # каталог товаров
│   └── checkout/      # оформление заказа
├── app/
└── nuxt.config.ts
```

## Структура слоя

```text
base/
├── app/
│   ├── components/BaseButton.vue
│   ├── composables/useToast.ts
│   ├── layouts/default.vue
│   └── app.config.ts
├── server/api/health.get.ts
└── nuxt.config.ts               # модули, CSS, runtimeConfig по умолчанию
```

Проект, расширяющий `base`, получает `<BaseButton>`, `useToast()`, layout и `/api/health` без копирования кода.

## Переопределение

```text
base/app/components/AppHeader.vue     ← из слоя
app/components/AppHeader.vue          ← в проекте: заменяет слой
```

`app.config.ts` сливается глубоко — проект может переопределить один цвет темы, а не весь объект:

```ts
// app/app.config.ts проекта
export default defineAppConfig({ theme: { primary: "violet" } });
```

## Сценарии

| Сценарий | Как помогают слои |
| --- | --- |
| Несколько сайтов одной компании | Общий слой с дизайн-системой, SEO-настройками, аналитикой |
| White-label продукт | Базовое приложение + слой бренда с цветами, логотипом, текстами |
| Большое приложение | Доменные слои `layers/catalog`, `layers/checkout` с чёткими границами |
| Стартовый шаблон команды | Слой с модулями, ESLint, авторизацией, обработкой ошибок |

## Слой или модуль

| | Layer | Module |
| --- | --- | --- |
| Что это | Кусок приложения с файлами по соглашениям | Код, выполняемый при сборке |
| Для чего | Компоненты, страницы, конфиг, тема | Интеграции, генерация, изменение сборки |
| Сложность создания | Обычный Nuxt-проект | `@nuxt/kit` и API модулей |

## Частые ошибки

- Неявные конфликты имён: компонент в проекте случайно переопределил компонент слоя.
- Относительные пути внутри слоя (`./assets`) — используйте алиасы с учётом слоя или `createResolver`.
- Слишком «толстый» слой, от которого зависят все проекты, — любое изменение ломает всех; версионируйте его как пакет.

## Что важно помнить

- Слой — это Nuxt-приложение, его можно разрабатывать и запускать отдельно.
- Приоритет: проект → слои по порядку в `extends` (первый важнее) → автоматические из `layers/`.
- Слои — встроенный способ модульности, альтернатива монорепозиторию с копированием кода.

## Мини-шпаргалка

- `extends: ["../base", "npm-pkg", "github:org/repo"]`.
- `layers/*` — подключаются автоматически.
- Проект переопределяет слой по имени файла.
- `app.config.ts` сливается глубоко.
- Слой — файлы приложения, модуль — логика сборки.
