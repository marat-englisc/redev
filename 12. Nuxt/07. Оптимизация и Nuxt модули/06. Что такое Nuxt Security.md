# Что такое Nuxt Security

> [!NOTE]
> `nuxt-security` применяет рекомендации OWASP к Nuxt-приложению: выставляет **заголовки безопасности** (Content-Security-Policy, Strict-Transport-Security, X-Content-Type-Options, X-Frame-Options/`frame-ancestors`, Referrer-Policy, Permissions-Policy, COOP/COEP) и добавляет серверные middleware: **rate limiter**, ограничение размера запроса, валидатор XSS, CORS, CSRF (через `nuxt-csurf`). Его сильная сторона — CSP с **nonce** и `strict-dynamic`, которую в SSR-приложении сложно настроить вручную. Модуль не заменяет безопасную архитектуру: авторизацию, проверку прав, валидацию и экранирование.

## Вопрос

Что такое Nuxt Security и какие угрозы он помогает закрыть?

## Подключение

```bash
npx nuxt module add security
```

```ts
export default defineNuxtConfig({
  modules: ["nuxt-security"],
  security: {
    nonce: true,                                   // уникальный nonce для каждого SSR-ответа
    headers: {
      contentSecurityPolicy: {
        "script-src": ["'self'", "'nonce-{{nonce}}'", "'strict-dynamic'"],
        "img-src": ["'self'", "data:", "https://images.cms.example.com"],
        "connect-src": ["'self'", "https://api.example.com"],
      },
      strictTransportSecurity: { maxAge: 31536000, includeSubdomains: true },
      crossOriginEmbedderPolicy: false,            // часто мешает сторонним виджетам
    },
    rateLimiter: { tokensPerInterval: 100, interval: 60_000 },
    requestSizeLimiter: { maxRequestSizeInBytes: 2_000_000 },
  },
  routeRules: {
    "/api/auth/**": {
      security: { rateLimiter: { tokensPerInterval: 5, interval: 60_000 } },  // строже для логина
    },
  },
});
```

## Что закрывает

| Механизм | От чего защищает |
| --- | --- |
| CSP с nonce | Выполнение внедрённых скриптов (XSS) |
| HSTS | Понижение до HTTP, перехват трафика |
| `frame-ancestors` / X-Frame-Options | Clickjacking |
| X-Content-Type-Options | MIME-sniffing |
| Referrer-Policy | Утечка URL с токенами в Referer |
| Permissions-Policy | Доступ к камере, геолокации без необходимости |
| Rate limiter | Перебор паролей, DoS отдельных эндпоинтов |
| Request size limiter | Огромные тела запросов |

## CSP и сторонние скрипты

Строгая CSP ломает аналитику, карты и платёжные виджеты, пока их домены не добавлены. Порядок внедрения:

1. Включить в режиме `Content-Security-Policy-Report-Only` и собрать нарушения.
2. Добавить нужные источники.
3. Перевести в обязательный режим.

С `strict-dynamic` скрипты, загруженные доверенным скриптом с nonce (например, через Nuxt Scripts), разрешаются автоматически.

## Чего модуль не делает

- Не проверяет права доступа к данным.
- Не валидирует бизнес-логику входных данных.
- Не защищает от `v-html` с пользовательским контентом — его нужно санитизировать (DOMPurify).
- Rate limiter в памяти не общий для нескольких экземпляров — для кластера нужен внешний storage.

## Частые ошибки

- Включить строгую CSP сразу в production и сломать аналитику и оплату.
- Считать модуль «включил — и безопасно».
- `'unsafe-inline'` в `script-src` «чтобы заработало» — CSP перестаёт защищать от XSS.
- Забыть, что при SWR-кэше страниц nonce в HTML общий, — для кэшируемых страниц используют hash-based CSP.

## Что важно помнить

- Заголовки безопасности — дешёвая и эффективная защита, их стоит настроить в каждом проекте.
- CSP с nonce — главный слой защиты от XSS после экранирования.
- Безопасность данных обеспечивают серверные проверки, а не модуль.

## Мини-шпаргалка

- `nuxt-security`: заголовки + rate limiter + size limiter + XSS validator.
- `nonce: true` + `'nonce-{{nonce}}'` + `'strict-dynamic'`.
- Внедрять CSP через Report-Only.
- `routeRules.security` — настройки на маршрут.
