# Что такое Nuxt DevTools

> [!NOTE]
> **Nuxt DevTools** — панель разработки внутри приложения (кнопка внизу экрана или `Shift+Alt+D`), включённая по умолчанию в `nuxt dev`. Она показывает то, что в Nuxt скрыто за соглашениями: маршруты и их `routeRules`, компоненты и auto-imports с местом использования, модули, состояние (`useState`, payload, Pinia), runtime config, серверные маршруты с возможностью отправить запрос, время загрузки плагинов, граф модулей Vite, SEO-мета и OG-превью. В production DevTools не попадает.

## Вопрос

Что такое Nuxt DevTools и чем он помогает в разработке?

## Включение

```ts
export default defineNuxtConfig({
  devtools: { enabled: true },   // по умолчанию в новых проектах
});
```

## Основные вкладки

| Вкладка | Что видно | Зачем |
| --- | --- | --- |
| Pages | Все маршруты, параметры, middleware, layout | Понять роутинг чужого проекта |
| Components | Компоненты, откуда взялись, где используются, граф связей | Найти неиспользуемые и тяжёлые компоненты |
| Imports | Auto-imports и места использования | Понять, откуда пришла функция |
| Modules | Установленные модули, их документация | Аудит зависимостей |
| Payload / State | `useState`, данные `useAsyncData`, их ключи | Отладка SSR-данных и гидрации |
| Runtime Config | Публичные и серверные значения | Проверить переменные окружения |
| Server Routes | `server/api` с формой для запроса | Тестировать API без Postman |
| Timeline | Время плагинов, хуков, рендера | Найти медленный плагин |
| Vite Inspect | Трансформации файлов | Отладка сборки |
| Render Tree, Inspector | Дерево компонентов, клик по элементу → открыть файл | Навигация по коду |
| SEO / OG Image | Мета-теги, превью (с модулями Nuxt SEO) | Проверка SEO в dev |

Модули добавляют свои вкладки: Pinia, Nuxt Content, Nuxt Image, Nuxt SEO.

## Сценарии

- **Чужой проект**: Pages + Components + Modules дают карту приложения за несколько минут.
- **Двойной запрос**: Payload показывает, попали ли данные в payload; если нет — где-то голый `$fetch`.
- **Медленный старт**: Timeline показывает плагины, блокирующие рендер.
- **«Откуда этот компонент»**: Inspector открывает файл в редакторе по клику на элемент.

## Ограничения

DevTools — инструмент разработки. Он не заменяет мониторинг production: для этого нужны логи, трассировка (Sentry, OpenTelemetry), RUM-метрики Web Vitals и алерты.

## Частые ошибки

- Не знать о существовании DevTools и отлаживать auto-imports вслепую.
- Принимать время в dev-режиме за production-производительность — dev без оптимизаций.
- Пытаться использовать DevTools для диагностики production-проблем.

## Что важно помнить

- Самая полезная вкладка для понимания SSR — Payload/State.
- DevTools особенно ценен в Nuxt из-за неявности auto-imports и соглашений.
- Есть и Vue DevTools (вкладка внутри Nuxt DevTools) для инспекции компонентов и Pinia.

## Мини-шпаргалка

- `devtools.enabled: true`, `Shift+Alt+D`.
- Pages, Components, Imports, Modules.
- Payload/State — SSR-данные.
- Server Routes — тест API.
- Timeline — медленные плагины.
