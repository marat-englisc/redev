# Как устроены Nuxt-модули и какие нужно знать

> [!NOTE]
> **Nuxt-модуль** — функция, которая выполняется **при запуске сборки** (`nuxt dev`, `nuxt build`) и расширяет приложение: регистрирует компоненты, composables и плагины, добавляет серверные маршруты, меняет конфиги Vite и Nitro, генерирует типы и вкладки DevTools. Подключаются в `modules` в `nuxt.config.ts` (проще — `npx nuxt module add <name>`), настраиваются своим ключом конфига. В отличие от плагина, модуль не попадает в рантайм сам по себе — он влияет на то, *что* окажется в сборке. Для собеседования важно знать официальные модули и уметь объяснить, какую проблему каждый решает.

## Вопрос

Что такое Nuxt-модули, как они работают и какие из них нужно знать?

## Подключение

```bash
npx nuxt module add image
```

```ts
export default defineNuxtConfig({
  modules: ["@nuxt/image", "@nuxt/fonts", "@pinia/nuxt", ["@nuxtjs/i18n", { defaultLocale: "ru" }]],
  image: { quality: 80 },        // настройки модуля — его ключ
});
```

## Модуль или плагин

| | Модуль | Плагин |
| --- | --- | --- |
| Когда выполняется | При сборке/запуске dev-сервера | В рантайме: на каждый SSR-запрос и в браузере |
| Что может | Менять конфиг, сборку, добавлять файлы и маршруты | Работать с экземпляром приложения |
| Где | `modules/` или npm-пакет | `app/plugins/` |

Модуль часто добавляет плагин — так библиотека попадает в рантайм.

## Свой локальный модуль

```ts
// modules/analytics/index.ts
import { defineNuxtModule, addPlugin, createResolver } from "@nuxt/kit";

export default defineNuxtModule({
  meta: { name: "analytics", configKey: "analytics" },
  defaults: { enabled: true },
  setup(options, nuxt) {
    if (!options.enabled) return;
    const { resolve } = createResolver(import.meta.url);
    addPlugin(resolve("./runtime/plugin.client"));
    nuxt.options.runtimeConfig.public.analytics = options;
  },
});
```

Файлы в `modules/` подключаются автоматически.

## Официальные и популярные модули

| Область | Модуль | Задача |
| --- | --- | --- |
| Производительность | `@nuxt/image` | Оптимизация изображений |
| | `@nuxt/fonts` | Self-hosting шрифтов, метрики против CLS |
| | `@nuxt/scripts` | Управляемая загрузка стороннего JS |
| UI | `@nuxt/icon` | Иконки Iconify |
| | `@nuxt/ui` | UI-кит на Tailwind и Reka UI |
| Контент | `@nuxt/content` | Markdown/YAML как база данных, документация, блоги |
| SEO | `@nuxtjs/seo` | Sitemap, robots, Schema.org, OG |
| Состояние | `@pinia/nuxt` | Pinia с SSR |
| i18n | `@nuxtjs/i18n` | Локализация, маршруты по языкам, hreflang |
| Утилиты | `@vueuse/nuxt` | VueUse с auto-imports |
| Стили | `@nuxtjs/tailwindcss` или Tailwind v4 через Vite-плагин | Tailwind CSS |
| Авторизация | `nuxt-auth-utils`, Better Auth | Сессии, OAuth |
| Безопасность | `nuxt-security` | Заголовки, rate limiting |
| Качество | `@nuxt/eslint`, `@nuxt/test-utils` | Линтинг, тесты |
| Ошибки | `@sentry/nuxt` | Мониторинг |

Каталог — nuxt.com/modules.

## Как выбирать модуль

- Совместим ли с Nuxt 4 (метка в каталоге, дата последнего релиза).
- Активно ли поддерживается: issues, коммиты, мейнтейнеры.
- Влияние на бандл и рантайм: добавляет ли он клиентский JS на каждую страницу.
- Не решается ли задача десятью строками composable.
- Как он ведёт себя при SSR.

## Частые ошибки

- Ставить модуль ради одной функции и тянуть лишний JS.
- Добавлять обычный Vue-плагин в `modules` — его подключают в `app/plugins`.
- Не читать раздел совместимости при обновлении Nuxt.

## Что важно помнить

- Модули работают на этапе сборки и почти не стоят ничего в рантайме, если не добавляют плагины.
- Кит для авторов модулей — `@nuxt/kit`: `addComponent`, `addImports`, `addServerHandler`, `addPlugin`.
- Для повторного использования целого приложения (страницы, компоненты, конфиг) есть [Nuxt Layers](<10. Что такое Nuxt Layers.md>).

## Мини-шпаргалка

- `npx nuxt module add <name>` → `modules: [...]`.
- Модуль — сборка, плагин — рантайм.
- `defineNuxtModule` + `@nuxt/kit`, локально в `modules/`.
- Знать: image, fonts, scripts, icon, content, ui, seo, pinia, i18n, test-utils.
