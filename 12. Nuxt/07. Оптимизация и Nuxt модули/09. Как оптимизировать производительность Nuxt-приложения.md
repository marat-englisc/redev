# Как оптимизировать производительность Nuxt-приложения

> [!NOTE]
> Производительность Nuxt складывается из трёх частей. **Сервер (TTFB)**: правильный режим рендеринга и кэш через `routeRules`, параллельная загрузка данных, кэш дорогих функций. **Загрузка (LCP, CLS)**: Nuxt Image и Nuxt Fonts, `preload` LCP-ресурса, минимум стороннего JS через Nuxt Scripts. **Интерактивность (INP, TBT)**: меньше JS и гидрации — ленивые компоненты, отложенная гидрация, server components, анализ бандла, маленький payload. Оптимизация начинается с измерений: Lighthouse, PageSpeed Insights (полевые данные), `nuxi analyze`, Nuxt DevTools.

## Вопрос

Как оптимизировать производительность Nuxt-приложения?

## Измерение

```bash
npx nuxt analyze               # визуализация бандла клиента и сервера
```

- Lighthouse / PageSpeed Insights — LCP, CLS, INP, TBT.
- Полевые данные (CrUX, RUM) важнее лабораторных.
- Nuxt DevTools → Timeline (плагины), Payload (размер данных).

## Сервер: TTFB

```ts
export default defineNuxtConfig({
  routeRules: {
    "/": { prerender: true },
    "/blog/**": { swr: 3600 },
    "/products/**": { swr: 300 },
    "/account/**": { ssr: true },
  },
});
```

```ts
// ✗ последовательно: 300 мс + 300 мс
const { data: product } = await useFetch(`/api/products/${id}`);
const { data: reviews } = await useFetch(`/api/products/${id}/reviews`);

// ✓ параллельно
const [{ data: product }, { data: reviews }] = await Promise.all([
  useFetch(`/api/products/${id}`),
  useFetch(`/api/products/${id}/reviews`),
]);
```

Дорогие вызовы к CMS и внешним API кэшируют через `defineCachedFunction`.

## Загрузка: LCP и CLS

| Проблема | Решение |
| --- | --- |
| Тяжёлое LCP-изображение | `<NuxtImg preload fetchpriority="high" sizes>`, AVIF/WebP |
| Сдвиг из-за картинок | `width` и `height` |
| Шрифты | `@nuxt/fonts`: self-hosting, preload, fallback-метрики |
| Сторонние скрипты | `@nuxt/scripts` с триггерами, фасады для видео и карт |
| Большой HTML | `pick`/`transform` в `useFetch`, меньше payload |

## Интерактивность: INP и TBT

```vue
<template>
  <ProductHero />
  <LazyReviews hydrate-on-visible />        <!-- отложенная гидрация -->
  <LazyCompareModal v-if="compareOpen" />   <!-- код по требованию -->
  <ArticleBody :html="html" />              <!-- ArticleBody.server.vue: рендер только на сервере, без клиентского JS -->
</template>
```

Server components (`*.server.vue`, «острова») пока экспериментальные и включаются через `experimental.componentIslands: true`.

- Тяжёлые библиотеки (графики, редакторы) — динамический `import()` и `Lazy`.
- Проверять бандл: нет ли `lodash` целиком, `moment`, полифиллов.
- Не делать тяжёлую синхронную работу в плагинах — они выполняются до рендера.
- Длинные списки — виртуализация.

## Навигация

- `<NuxtLink>` предзагружает чанки видимых ссылок — не отключайте prefetch без причины.
- `lazy: true` для второстепенных данных — переход не ждёт их загрузки.
- `getCachedData` для справочников, которые не нужно перезапрашивать при каждом переходе.

## Сборка и доставка

- Сжатие Brotli/gzip на CDN или `nitro.compressPublicAssets: true`.
- Долгий кэш для `/_nuxt/**` (файлы с хэшем) через `routeRules.headers`.
- CDN перед сервером для статики и кэшируемых страниц.

## Частые ошибки

- Оптимизировать вслепую, без измерений.
- SSR без кэша для страниц, одинаковых для всех.
- Последовательные `await` независимых запросов.
- Гидрировать всё сразу, включая подвал и комментарии.
- Подключать аналитику и чат в `<head>` блокирующими скриптами.

## Что важно помнить

- У каждой метрики свои рычаги: TTFB — сервер и кэш, LCP — ресурсы первого экрана, INP — объём JS и гидрации.
- Nuxt даёт инструменты, но выбор режима рендеринга и бюджета JS — инженерное решение.
- Подробно о Core Web Vitals — в разделе [SEO: Performance и Core Web Vitals](<../../16. SEO/05. Performance UX и Core Web Vitals/>).

## Мини-шпаргалка

- Измерить: Lighthouse, PSI, `nuxt analyze`, DevTools.
- TTFB: `routeRules` (prerender/swr), `Promise.all`, кэш функций.
- LCP/CLS: Nuxt Image, Nuxt Fonts, Nuxt Scripts.
- INP: `Lazy`, `hydrate-on-*`, server components, разбор бандла.
- Доставка: сжатие, `immutable` для `/_nuxt/`, CDN.
