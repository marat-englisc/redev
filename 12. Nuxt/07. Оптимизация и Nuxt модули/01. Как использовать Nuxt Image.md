# Как использовать Nuxt Image

> [!NOTE]
> `@nuxt/image` даёт компоненты `<NuxtImg>` (замена `<img>`) и `<NuxtPicture>` (замена `<picture>` с несколькими форматами), которые **оптимизируют изображения на лету или при сборке**: меняют размер, конвертируют в WebP/AVIF, генерируют `srcset` по `sizes` и плотностям экрана. Оптимизацию выполняет **provider**: по умолчанию IPX на вашем сервере, либо CDN — Cloudinary, imgix, Vercel, Cloudflare. Для LCP-картинки ставят `preload` и `fetchpriority="high"`, для остальных — `loading="lazy"`, всегда — `width`/`height` против CLS и `alt`.

## Вопрос

Как оптимизировать изображения в Nuxt с помощью Nuxt Image?

## Подключение

```bash
npx nuxt module add image
```

```ts
export default defineNuxtConfig({
  modules: ["@nuxt/image"],
  image: {
    quality: 80,
    format: ["avif", "webp"],
    screens: { sm: 640, md: 768, lg: 1024, xl: 1280 },
    domains: ["images.cms.example.com"],   // внешние источники, которые разрешено оптимизировать
  },
});
```

## NuxtImg

```vue
<template>
  <!-- LCP-изображение первого экрана -->
  <NuxtImg
    src="/images/hero.jpg"
    alt="Рабочее место разработчика с механической клавиатурой"
    width="1200"
    height="630"
    sizes="100vw md:80vw lg:1200px"
    format="webp"
    preload
    fetchpriority="high"
  />

  <!-- карточка ниже первого экрана -->
  <NuxtImg
    :src="product.image"
    :alt="product.title"
    width="320"
    height="320"
    sizes="50vw sm:320px"
    loading="lazy"
    placeholder
  />
</template>
```

```html
<!-- результат -->
<img src="/_ipx/w_1200&f_webp/images/hero.jpg"
     srcset="/_ipx/w_640&f_webp/... 640w, /_ipx/w_1024&f_webp/... 1024w, ..."
     sizes="(max-width: 768px) 100vw, (max-width: 1024px) 80vw, 1200px"
     width="1200" height="630" fetchpriority="high">
```

Пути без домена ищутся в `public/`.

## NuxtPicture

```vue
<NuxtPicture
  src="/images/banner.png"
  :img-attrs="{ alt: 'Скидки недели', class: 'rounded-xl' }"
  format="avif,webp"
  width="800"
  height="400"
/>
```

Рендерит `<picture>` с `<source>` для AVIF и WebP и fallback на исходный формат.

## Providers

```ts
export default defineNuxtConfig({
  image: {
    provider: "cloudinary",
    cloudinary: { baseURL: "https://res.cloudinary.com/demo/image/upload/" },
  },
});
```

| Provider | Где оптимизация |
| --- | --- |
| `ipx` (по умолчанию) | На вашем Nitro-сервере, с кэшем |
| `vercel`, `netlify`, `cloudflare` | Встроенный сервис платформы |
| `cloudinary`, `imgix`, `twicpics` | Внешний CDN изображений |
| `none` | Без обработки |

При `nuxt generate` IPX оптимизирует изображения при сборке и кладёт в статику.

## useImage

```ts
const img = useImage();
const bg = computed(() => `url(${img("/images/bg.jpg", { width: 1600, format: "webp" })})`);
```

Для фоновых изображений в CSS, где компонент неприменим.

## Частые ошибки

- Нет `width`/`height` — сдвиг макета (CLS).
- `loading="lazy"` у LCP-картинки — она загружается позже, LCP растёт.
- Без `sizes` — браузер скачивает самую большую версию.
- Внешний домен не добавлен в `domains` — картинка отдаётся без оптимизации.
- Большие исходники в `public/` без оптимизации и с IPX на serverless — долгий холодный старт.

## Что важно помнить

- `sizes` описывает, какую ширину картинка займёт в макете, — от этого зависит выбранный вариант `srcset`.
- LCP-изображение: `preload` + `fetchpriority="high"`, без lazy.
- Provider выбирают по инфраструктуре: CDN изображений снимает нагрузку с сервера.

## Мини-шпаргалка

- `<NuxtImg src width height sizes alt>`.
- LCP: `preload`, `fetchpriority="high"`; остальное: `loading="lazy"`.
- `<NuxtPicture format="avif,webp">`.
- `image.domains`, `image.provider`.
- `useImage()` — для CSS-фонов.
