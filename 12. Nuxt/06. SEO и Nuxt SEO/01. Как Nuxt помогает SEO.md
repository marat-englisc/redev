# Как Nuxt помогает SEO

> [!NOTE]
> Nuxt закрывает техническую базу SEO: **SSR/SSG** отдают поисковику готовый HTML с контентом, `useSeoMeta`/`useHead` управляют title, description, canonical и Open Graph при серверном рендере, `createError({ statusCode: 404 })` даёт корректные коды ответа, `<NuxtLink>` рендерит настоящие ссылки для обхода, а экосистема **Nuxt SEO** добавляет sitemap, robots, Schema.org и OG-картинки. Но фреймворк не делает SEO за вас: контент, структура заголовков, уникальные мета-теги, скорость (Core Web Vitals) и отсутствие дублей — ответственность разработчика.

## Вопрос

Как Nuxt помогает SEO и что остаётся на разработчике?

## Что даёт SSR

```html
<!-- Nuxt: ответ сервера -->
<title>Механические клавиатуры — купить в Магазине</title>
<meta name="description" content="120 моделей с доставкой за 1 день">
<link rel="canonical" href="https://shop.example.com/keyboards">
<h1>Механические клавиатуры</h1>
<a href="/keyboards/keychron-k2">Keychron K2</a>
```

```html
<!-- SPA: ответ сервера -->
<div id="app"></div>
```

Google умеет выполнять JS, но с задержкой и не всегда полностью; другие поисковики, соцсети и мессенджеры (превью ссылок) — нет.

## Инструменты Nuxt для SEO

| Задача | Инструмент |
| --- | --- |
| HTML с контентом | SSR, prerender, `routeRules` |
| Title, description, OG | `useSeoMeta`, `app.head`, `titleTemplate` |
| Canonical, hreflang, `lang` | `useHead`, Nuxt SEO, `@nuxtjs/i18n` |
| Корректные коды 404/301 | `createError`, `navigateTo(..., { redirectCode: 301 })`, `routeRules.redirect` |
| Sitemap, robots.txt | `@nuxtjs/sitemap`, `@nuxtjs/robots` |
| Структурированные данные | `nuxt-schema-org` |
| Превью в соцсетях | `nuxt-og-image` |
| Скорость (LCP, CLS, INP) | `@nuxt/image`, `@nuxt/fonts`, `@nuxt/scripts`, lazy hydration |
| Проверка ссылок | `nuxt-link-checker` |

## Что остаётся на разработчике

- Один осмысленный `<h1>`, логичная иерархия заголовков, семантическая разметка.
- Уникальные title и description для каждой страницы.
- Отсутствие дублей: canonical, единый формат URL (слеш на конце, регистр).
- 404 для несуществующих страниц, а не 200 с пустым шаблоном.
- Контент в HTML, а не только после клиентской загрузки (`server: false`).
- Скорость: оптимизированные изображения и шрифты, минимум стороннего JS.
- Отсутствие hydration mismatch и ошибок в консоли.

## Частые ошибки

- Загружать основной контент с `server: false` или в `onMounted`.
- Одинаковый title на всех страницах.
- `ssr: false` для публичного сайта.
- «Мягкие» 404: страница «Не найдено» со статусом 200.
- Закрыть сайт в `robots.txt` на staging и выкатить так в production.

## Что важно помнить

- SSR — необходимое, но не достаточное условие SEO.
- Проверять нужно итоговый HTML ответа сервера, а не код компонентов.
- Подробно о SEO в целом — в разделе [SEO](<../../16. SEO/00. Карта раздела и маршрут изучения.md>).

## Мини-шпаргалка

- SSR/SSG → контент в HTML.
- `useSeoMeta` → мета-теги при SSR.
- `createError` → правильные коды.
- Nuxt SEO → sitemap, robots, Schema.org, OG.
- Контент, структура и скорость — на разработчике.
