# Как настроить robots.txt в Nuxt

> [!NOTE]
> `robots.txt` сообщает поисковым роботам, какие разделы **не обходить**; это рекомендация, а не защита: закрытые страницы защищают авторизацией. В Nuxt им управляет модуль `@nuxtjs/robots` (часть Nuxt SEO): правила задаются в конфиге, файле `public/_robots.txt` или через `routeRules: { robots: false }`, а модуль сам добавляет ссылку на sitemap, мета-тег и заголовок `X-Robots-Tag` и **закрывает от индексации** все окружения, кроме production. Важно различать: `Disallow` запрещает обход, `noindex` запрещает индексацию.

## Вопрос

Как настроить `robots.txt` и правила индексации в Nuxt?

## Простейший вариант

```text
# public/robots.txt — отдаётся как есть
User-agent: *
Disallow: /admin
Disallow: /api
Sitemap: https://shop.example.com/sitemap.xml
```

Подходит для небольших сайтов, но не учитывает окружения.

## Модуль Nuxt Robots

```ts
export default defineNuxtConfig({
  modules: ["@nuxtjs/robots"],
  site: { url: "https://shop.example.com" },
  robots: {
    disallow: ["/admin", "/account", "/cart"],
  },
  routeRules: {
    "/search": { robots: false },           // <meta name="robots" content="noindex, nofollow">
    "/drafts/**": { robots: "noindex, follow" },
  },
});
```

```vue
<script setup lang="ts">
useRobotsRule(false); // noindex для конкретной страницы, например пустого результата фильтра
</script>
```

## Окружения

Модуль определяет, индексируемо ли окружение (`site.indexable`, по умолчанию `true` только в production). На staging и preview он отдаёт `Disallow: /` и `noindex` — тестовые стенды не попадут в выдачу. Явно:

```env
NUXT_SITE_ENV=staging
```

## Disallow и noindex

| | `Disallow` в robots.txt | `noindex` (мета или заголовок) |
| --- | --- | --- |
| Запрещает | Обход страницы | Индексацию |
| Робот видит контент | Нет | Да |
| Может попасть в выдачу | Да, если на неё ссылаются (без описания) | Нет |
| Когда | Технические разделы, бесконечные фильтры | Страницы, которые не должны быть в поиске |

Нельзя одновременно закрыть страницу в `robots.txt` и поставить ей `noindex`: робот не зайдёт и не увидит запрет индексации.

## AI-боты

```ts
robots: {
  groups: [
    { userAgent: ["GPTBot", "ClaudeBot", "CCBot"], disallow: ["/"] },
  ],
},
```

Решение блокировать AI-краулеры — бизнесовое, и соблюдение `robots.txt` остаётся на совести ботов.

## Частые ошибки

- Выкатить в production `Disallow: /`, оставшийся со staging.
- Защищать приватные страницы только `robots.txt` — файл публичен и сам подсказывает, где «интересное».
- `Disallow` вместо `noindex` для удаления страницы из выдачи.
- Закрыть `/_nuxt/` — роботу нужны JS и CSS для рендеринга.

## Что важно помнить

- `robots.txt` управляет обходом, `noindex` — индексацией.
- Автоматический `noindex` вне production — главное преимущество модуля.
- Доступ к данным ограничивает только авторизация на сервере.

## Мини-шпаргалка

- `robots.disallow`, `routeRules.robots`, `useRobotsRule()`.
- `site.indexable` / `NUXT_SITE_ENV`.
- Disallow ≠ noindex.
- Не закрывать `/_nuxt/`.
