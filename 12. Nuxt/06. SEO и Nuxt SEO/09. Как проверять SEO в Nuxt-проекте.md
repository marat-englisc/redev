# Как проверять SEO в Nuxt-проекте

> [!NOTE]
> SEO проверяют по **итоговому ответу сервера**, а не по коду компонентов: есть ли контент и мета-теги в HTML (`curl`, «Просмотр кода страницы»), правильные ли статус-коды (404, 301), корректны ли canonical, sitemap и robots, валидна ли разметка Schema.org, нет ли hydration-ошибок, как обстоят дела с Core Web Vitals. Инструменты: Nuxt DevTools (вкладки SEO и OG Image), Lighthouse, Rich Results Test, Google Search Console и Яндекс Вебмастер, Link Checker при сборке.

## Вопрос

Как проверить SEO Nuxt-приложения перед релизом и после него?

## Проверка HTML

```bash
curl -s https://shop.example.com/keyboards | grep -E "<title>|description|canonical|og:image|<h1"
curl -sI https://shop.example.com/not-exists        # HTTP/2 404
curl -sI https://shop.example.com/old-catalog       # HTTP/2 301 + location
```

Если контента или мета-тегов нет в ответе `curl`, значит они появляются только после выполнения JS — ищите `server: false`, `onMounted`, `<ClientOnly>` вокруг важного контента.

## Чек-лист страницы

- `<title>` уникален, 50–60 символов.
- `description` уникальна и осмысленна.
- Ровно один `<h1>`, иерархия `h2`–`h3` без пропусков.
- Canonical абсолютный и указывает на саму страницу (или на оригинал дубля).
- OG-теги с абсолютным `og:image`.
- Ссылки — настоящие `<a href>` (`<NuxtLink>`), а не `@click` на `div`.
- Изображения с `alt`, `width`/`height`.
- Нет предупреждений hydration mismatch в консоли.

## Чек-лист сайта

```text
/robots.txt          → 200, production без Disallow: /
/sitemap.xml         → 200, абсолютные URL, только канонические страницы со статусом 200
/несуществующий-url  → 404 и error.vue
/staging-домен       → noindex
http:// → https://   → 301
/page/ и /page       → один вариант, второй — 301
```

## Инструменты

| Инструмент | Что проверяет |
| --- | --- |
| Nuxt DevTools → SEO, OG Image, Schema.org | Мета-теги, превью, граф JSON-LD в dev |
| Nuxt Link Checker | Битые ссылки, редиректы, ссылки без trailing slash при сборке |
| Lighthouse (вкладка SEO и Performance) | Базовые SEO-проверки, LCP/CLS/INP |
| PageSpeed Insights | Полевые данные Core Web Vitals (CrUX) |
| Rich Results Test | Structured data |
| Google Search Console, Яндекс Вебмастер | Индексация, ошибки обхода, запросы |
| Отладчики соцсетей | Превью ссылок |

## Автоматизация

- Link Checker в CI ломает сборку при битых ссылках.
- Lighthouse CI с порогами для ключевых страниц.
- E2E-тест на Playwright, проверяющий title, canonical и статус 404:

```ts
test("товар отдаёт мета-теги и 404 для несуществующего", async ({ page, request }) => {
  await page.goto("/products/keychron-k2");
  await expect(page).toHaveTitle(/Keychron K2/);
  await expect(page.locator('link[rel="canonical"]')).toHaveAttribute("href", /\/products\/keychron-k2$/);

  const res = await request.get("/products/does-not-exist");
  expect(res.status()).toBe(404);
});
```

## Частые ошибки

- Проверять SEO только в DevTools браузера, где JS уже выполнен.
- Не проверять статус-коды.
- Оставить `noindex` после переезда со staging.
- Игнорировать Search Console после релиза.

## Что важно помнить

- Источник истины — ответ сервера, а не DOM после гидрации.
- SEO-регрессии дешевле ловить автотестами, чем падением трафика.
- Индексация занимает дни и недели — мониторинг после релиза обязателен.

## Мини-шпаргалка

- `curl` → контент, мета-теги, статусы.
- robots, sitemap, 404, 301, noindex на staging.
- DevTools, Link Checker, Lighthouse, Rich Results Test.
- Search Console после релиза.
