# Что такое Nuxt SEO

> [!NOTE]
> **Nuxt SEO** (`@nuxtjs/seo`) — мета-модуль, объединяющий модули технического SEO с общей конфигурацией сайта: **Site Config** (URL, название, язык — единый источник для всех модулей), **Robots** (`robots.txt`, `noindex`), **Sitemap** (`sitemap.xml`), **Schema.org** (JSON-LD), **OG Image** (генерация превью), **Link Checker** (битые ссылки) и **SEO Utils** (canonical, favicon, хлебные крошки). Модули можно ставить вместе или по отдельности. Главная настройка — `site.url`: без неё нельзя построить абсолютные ссылки в sitemap, canonical и OG.

## Вопрос

Что такое Nuxt SEO и какие задачи он решает?

## Установка

```bash
npx nuxt module add @nuxtjs/seo
```

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ["@nuxtjs/seo"],
  site: {
    url: "https://shop.example.com",
    name: "Магазин",
    description: "Техника для разработчиков",
    defaultLocale: "ru",
  },
});
```

Для разных окружений URL переопределяют переменной `NUXT_SITE_URL` — staging не попадёт в canonical production.

## Состав

| Модуль | Пакет | Что делает |
| --- | --- | --- |
| Site Config | `nuxt-site-config` | Единые `url`, `name`, `indexable` для всех модулей |
| Robots | `@nuxtjs/robots` | `robots.txt`, `X-Robots-Tag`, `noindex` для неиндексируемых окружений |
| Sitemap | `@nuxtjs/sitemap` | `sitemap.xml` из маршрутов и динамических источников |
| Schema.org | `nuxt-schema-org` | Типизированный JSON-LD |
| OG Image | `nuxt-og-image` | Превью-картинки из Vue-компонентов |
| Link Checker | `nuxt-link-checker` | Битые и неоптимальные ссылки при сборке и в DevTools |
| SEO Utils | `nuxt-seo-utils` | Canonical, `og:url`, favicon, хлебные крошки, дефолтные мета-теги |

## Что происходит автоматически

- В не-production окружениях (`indexable: false`) сайт закрывается от индексации.
- Генерируется canonical и `og:url` на основе `site.url` и текущего пути.
- Sitemap собирается из файловых маршрутов, prerender-страниц и источников.
- `robots.txt` ссылается на sitemap.
- Базовый граф Schema.org (`WebSite`, `WebPage`) добавляется на все страницы.

## Отключение частей

```ts
export default defineNuxtConfig({
  modules: ["@nuxtjs/seo"],
  ogImage: { enabled: false },
  linkChecker: { enabled: false },
});
```

Каждый модуль настраивается своим ключом в конфиге: `robots`, `sitemap`, `schemaOrg`, `ogImage`.

## Когда ставить весь стек

Для публичного контентного сайта или магазина — сразу весь. Для приложения за логином достаточно Robots с `noindex` — индексировать нечего.

## Частые ошибки

- Не задать `site.url` или задать адрес staging в production.
- Ставить мета-модуль в закрытое приложение и тянуть лишние зависимости.
- Думать, что модуль улучшит позиции сам: он автоматизирует технику, но не контент.

## Что важно помнить

- Site Config — общий источник истины для URL и названия.
- Автоматический `noindex` вне production защищает от индексации тестовых стендов.
- Детали — в уроках про [sitemap](<04. Как настроить sitemap в Nuxt.md>), [robots](<05. Как настроить robots.txt в Nuxt.md>), [Schema.org](<06. Как добавить Schema.org structured data.md>), [OG Image](<08. Что такое Nuxt OG Image.md>).

## Мини-шпаргалка

- `@nuxtjs/seo` = Site Config + Robots + Sitemap + Schema.org + OG Image + Link Checker + SEO Utils.
- `site.url` обязателен, `NUXT_SITE_URL` — по окружениям.
- Модули отключаются своими ключами.
