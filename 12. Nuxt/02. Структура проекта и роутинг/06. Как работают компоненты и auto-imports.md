# Как работают компоненты и auto-imports

> [!NOTE]
> Компоненты из `app/components` доступны в шаблонах **без импорта**: Nuxt сканирует каталог и регистрирует их с именем по пути (`components/base/Button.vue` → `<BaseButton>`), импортируя только реально использованные, — дерево-шейкинг сохраняется. Префикс **`Lazy`** (`<LazyHeavyChart>`) загружает компонент отдельным чанком по требованию, а `hydrate-on-*` откладывает гидрацию. Суффиксы `.client.vue` и `.server.vue` ограничивают рендер одним окружением. Явный импорт — `#components`.

## Вопрос

Как в Nuxt работают auto-imports компонентов и ленивые компоненты?

## Именование по пути

```text
app/components/
├── AppHeader.vue              → <AppHeader>
├── base/
│   └── Button.vue             → <BaseButton>
└── product/
    ├── Card.vue               → <ProductCard>
    └── ProductGallery.vue     → <ProductGallery> (повтор префикса не дублируется)
```

```vue
<template>
  <AppHeader />
  <BaseButton>Купить</BaseButton>
  <ProductCard :product="product" />
</template>
```

Отключить префиксы для каталога можно в конфиге: `components: [{ path: "~/components/ui", pathPrefix: false }]`.

## Ленивые компоненты

```vue
<template>
  <button @click="showChart = true">Показать график</button>
  <LazyHeavyChart v-if="showChart" :data="stats" />
</template>
```

Код `HeavyChart` попадает в отдельный чанк и загружается, только когда условие станет истинным. Хорош для модалок, графиков, редакторов — того, что не нужно на первом экране.

## Отложенная гидрация

```vue
<template>
  <LazyCommentsWidget hydrate-on-visible />
  <LazyChatWidget hydrate-on-interaction />
  <LazyFooterMap hydrate-never />
</template>
```

HTML рендерится на сервере сразу, а JavaScript подключается позже — подробнее в [уроке про lazy hydration](<../07. Оптимизация и Nuxt модули/08. Как работает lazy hydration в Nuxt.md>).

## Клиентские и серверные компоненты

```text
MapWidget.client.vue    → рендерится только в браузере (на сервере — пустое место)
Markdown.server.vue     → рендерится только на сервере, код не попадает в бандл (server island)
```

Server components пока экспериментальные: нужен `experimental.componentIslands: true`.

```vue
<ClientOnly>
  <MapWidget />
  <template #fallback>
    <MapSkeleton />
  </template>
</ClientOnly>
```

## Явный импорт

```ts
import { BaseButton, LazyHeavyChart } from "#components";
```

Нужен для `<component :is="...">` и в render-функциях, где имя компонента неизвестно при сборке.

## Компоненты из библиотек

Компоненты UI-китов (Nuxt UI, Vuetify через модуль) регистрируются модулями так же автоматически. Для своих пакетов — `addComponentsDir` в модуле или `components.dirs` в конфиге.

## Частые ошибки

- Ожидать, что `<component :is="'BaseButton'">` со строкой найдёт компонент — нужен импорт из `#components` или `resolveComponent`.
- Класть сотни компонентов в один каталог без структуры и путаться в именах.
- Делать `Lazy` компонент, видимый на первом экране, — он появится с задержкой.
- Использовать `.client.vue` для SEO-важного контента — его нет в HTML.

## Что важно помнить

- Auto-import не означает глобальную регистрацию: в бандл страницы попадают только используемые компоненты.
- `Lazy` откладывает загрузку кода, `hydrate-*` — подключение интерактивности; это разные оптимизации.
- Типы для всех auto-imports генерируются в `.nuxt/components.d.ts`.

## Мини-шпаргалка

- `components/a/B.vue` → `<AB>`.
- `<LazyX>` — отдельный чанк по требованию.
- `hydrate-on-visible`, `hydrate-on-idle`, `hydrate-on-interaction`.
- `.client.vue`, `.server.vue`, `<ClientOnly>`.
- `#components` — явный импорт.
