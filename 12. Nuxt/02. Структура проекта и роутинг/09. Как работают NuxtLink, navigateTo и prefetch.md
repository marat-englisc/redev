# Как работают NuxtLink, navigateTo и prefetch

> [!NOTE]
> `<NuxtLink>` — компонент ссылки: для внутренних путей делает **клиентский переход** без перезагрузки (обёртка над `<RouterLink>`), для внешних рендерит обычный `<a>` с `rel="noopener noreferrer"`. По умолчанию он **предзагружает** JS-чанк страницы, когда ссылка попадает в viewport (`prefetchOn: 'visibility'`), можно переключить на `interaction`. `navigateTo()` — программная навигация, работающая и на клиенте, и на сервере (там она превращается в HTTP-редирект), поэтому её результат нужно `return`/`await`.

## Вопрос

Как в Nuxt делать навигацию и как работает предзагрузка страниц?

## NuxtLink

```vue
<template>
  <NuxtLink to="/catalog">Каталог</NuxtLink>
  <NuxtLink :to="{ name: 'products-id', params: { id: 42 } }">Товар</NuxtLink>
  <NuxtLink to="https://vuejs.org">Vue</NuxtLink>          <!-- внешняя: обычный <a> -->
  <NuxtLink to="/docs" active-class="font-bold">Документация</NuxtLink>
  <NuxtLink to="/files/report.pdf" external>PDF</NuxtLink>  <!-- принудительно без роутера -->
</template>
```

Активной ссылке добавляются классы `router-link-active` и `router-link-exact-active` (переопределяются через `activeClass` и `exactActiveClass`).

## Prefetch

```text
ссылка появилась в viewport → idle-время браузера → загрузка JS-чанка страницы
                                                  → (для prerender-страниц) загрузка _payload.json
клик → страница уже в кэше → мгновенный переход
```

```vue
<NuxtLink to="/heavy" :prefetch="false">Без предзагрузки</NuxtLink>
<NuxtLink to="/pricing" prefetch-on="interaction">При наведении или фокусе</NuxtLink>
```

```ts
// глобально в nuxt.config.ts
export default defineNuxtConfig({
  experimental: {
    defaults: {
      nuxtLink: { prefetchOn: { visibility: false, interaction: true } },
    },
  },
});
```

На медленном соединении (`navigator.connection.saveData` или 2G) Nuxt не делает prefetch автоматически.

## Свой компонент ссылки

```ts
// app/components/AppLink.ts
export default defineNuxtLink({
  componentName: "AppLink",
  trailingSlash: "remove",
  prefetchOn: { interaction: true },
});
```

## navigateTo

```ts
await navigateTo("/dashboard");
await navigateTo({ path: "/search", query: { q: "vue" } });
await navigateTo("/login", { replace: true });              // без записи в историю
await navigateTo("/moved", { redirectCode: 301 });           // на сервере — 301
await navigateTo("https://pay.example.com", { external: true });
await navigateTo("/docs", { open: { target: "_blank" } });   // новая вкладка (только клиент)
```

В middleware и `setup` результат **возвращают**, иначе редирект на сервере может не сработать:

```ts
export default defineNuxtRouteMiddleware(() => {
  if (!isLoggedIn()) return navigateTo("/login");
});
```

## Другие инструменты

| Функция | Назначение |
| --- | --- |
| `useRouter().push()` / `back()` | Низкоуровневое API Vue Router |
| `prefetchComponents("HeavyChart")` | Заранее загрузить код компонента |
| `preloadRouteComponents("/checkout")` | Загрузить код страницы до перехода |
| `reloadNuxtApp()` | Полная перезагрузка приложения |
| `clearError({ redirect: "/" })` | Выйти со страницы ошибки |

## Частые ошибки

- Использовать `<a href="/catalog">` для внутренних ссылок — полная перезагрузка, потеря состояния.
- Вызывать `navigateTo` без `return`/`await` в middleware.
- Отключать prefetch везде из страха перед трафиком — переходы станут заметно медленнее.
- Использовать `router.push` для внешних URL.

## Что важно помнить

- Prefetch загружает **код** страницы (и payload для prerender-страниц), а не выполняет её `useFetch`.
- `navigateTo` на сервере отправляет редирект с кодом 302 по умолчанию.
- Для SEO важно, что `<NuxtLink>` рендерит настоящий `<a href>` — поисковик видит ссылки.

## Мини-шпаргалка

- `<NuxtLink to>` — внутренние и внешние ссылки.
- Prefetch по видимости или `prefetch-on="interaction"`.
- `return navigateTo("/x")` в middleware.
- `redirectCode`, `replace`, `external`, `open`.
- `defineNuxtLink` — своя ссылка с настройками.
