# Как обрабатывать ошибки страниц - error.vue, createError и NuxtErrorBoundary

> [!NOTE]
> В Nuxt два уровня ошибок. **Фатальные** — страница не может быть показана (404, 500): их бросают через `throw createError({ statusCode: 404 })` или `showError()`, и Nuxt вместо приложения рендерит **`app/error.vue`** с правильным HTTP-статусом при SSR. **Локальные** — сломался виджет, а страница в целом работает: их ловит `<NuxtErrorBoundary>`. Выйти из состояния ошибки — `clearError({ redirect: "/" })`. Отдельно данные запросов: `useFetch` возвращает `error`, не прерывая рендер.

## Вопрос

Как в Nuxt обрабатывать ошибки страниц и показывать 404?

## 404 для несуществующей сущности

```vue
<!-- app/pages/products/[id].vue -->
<script setup lang="ts">
const route = useRoute();
const { data: product, error } = await useFetch(() => `/api/products/${route.params.id}`);

if (error.value?.statusCode === 404 || !product.value) {
  throw createError({ statusCode: 404, statusMessage: "Товар не найден", fatal: true });
}
</script>
```

При SSR пользователь и поисковик получат HTTP 404, а не 200 с пустой страницей. Это важно для SEO: «мягкие 404» мешают индексации.

## error.vue

```vue
<!-- app/error.vue — рендерится ВМЕСТО app.vue, layouts не применяются -->
<script setup lang="ts">
import type { NuxtError } from "#app";

const props = defineProps<{ error: NuxtError }>();

useSeoMeta({ title: props.error.statusCode === 404 ? "Страница не найдена" : "Ошибка" });

const goHome = () => clearError({ redirect: "/" });
</script>

<template>
  <NuxtLayout>
    <h1>{{ error.statusCode }}</h1>
    <p>{{ error.statusCode === 404 ? "Такой страницы нет" : "Что-то пошло не так" }}</p>
    <button @click="goHome">На главную</button>
  </NuxtLayout>
</template>
```

`error.vue` — не страница из `pages/`, поэтому layout нужно обернуть вручную через `<NuxtLayout>`. В production `error.message` и стек для 500 не показываются пользователю.

## createError и showError

```ts
throw createError({ statusCode: 403, statusMessage: "Нет доступа" }); // в setup, middleware, plugin
showError({ statusCode: 500 });                                         // вне setup, например в обработчике
```

На клиенте `createError` по умолчанию **не фатальна** — для перехода на `error.vue` нужен `fatal: true`. На сервере любая выброшенная ошибка фатальна.

Неизвестный маршрут (нет подходящего файла в `pages/`) Nuxt сам превращает в 404 и показывает `error.vue`.

## Локальные ошибки: NuxtErrorBoundary

```vue
<template>
  <ProductInfo :product="product" />

  <NuxtErrorBoundary @error="logError">
    <RecommendationsWidget />
    <template #error="{ error, clearError }">
      <p>Не удалось загрузить рекомендации</p>
      <button @click="clearError">Повторить</button>
    </template>
  </NuxtErrorBoundary>
</template>
```

Ошибка в `RecommendationsWidget` не уронит страницу. Компонент работает на клиенте (аналог Error Boundary в React).

## Ошибки данных

```ts
const { data, error, status, refresh } = await useFetch("/api/stats");
```

`useFetch` не бросает исключение: ошибка попадает в `error`, и разработчик решает — показать сообщение, повторить или превратить в фатальную через `createError`.

## Централизованная обработка

```ts
// app/plugins/errors.ts
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook("vue:error", (err, instance, info) => reportToSentry(err, { info }));
  nuxtApp.hook("app:error", (err) => reportToSentry(err));
});
```

## Частые ошибки

- Показывать «Не найдено» внутри страницы со статусом 200.
- Забыть `fatal: true` на клиенте и удивляться, что `error.vue` не открылся.
- Ожидать, что layout применится к `error.vue` автоматически.
- Выводить пользователю стек и детали серверной ошибки.

## Что важно помнить

- `createError` в `setup` при SSR даёт правильный HTTP-статус ответа.
- `error.vue` — для фатальных ошибок, `<NuxtErrorBoundary>` — для частей страницы.
- Ошибки API-маршрутов обрабатываются отдельно — см. [ошибки в server routes](<../05. Server API Nitro и deployment/06. Как обрабатывать ошибки в server routes.md>).

## Мини-шпаргалка

- `throw createError({ statusCode: 404, fatal: true })`.
- `app/error.vue` + `defineProps<{ error: NuxtError }>()`.
- `clearError({ redirect: "/" })`.
- `<NuxtErrorBoundary>` с `#error`.
- Хуки `vue:error`, `app:error` — для Sentry.
