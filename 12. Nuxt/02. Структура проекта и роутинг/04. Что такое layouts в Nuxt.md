# Что такое layouts в Nuxt

> [!NOTE]
> **Layout** — общая оболочка для группы страниц: шапка, боковое меню, подвал. Layouts лежат в `app/layouts`, содержимое страницы выводится через `<slot />`, а применяются они через `<NuxtLayout>` в `app.vue`. По умолчанию используется `default.vue`; странице другой layout задают в `definePageMeta({ layout: "admin" })`, отключают — `layout: false`, меняют динамически — `setPageLayout()`. Layout не пересоздаётся при переходах между страницами с одинаковой оболочкой.

## Вопрос

Что такое layouts в Nuxt и как ими управлять?

## Layout по умолчанию

```vue
<!-- app/layouts/default.vue -->
<template>
  <div class="min-h-screen flex flex-col">
    <AppHeader />
    <main class="flex-1">
      <slot />
    </main>
    <AppFooter />
  </div>
</template>
```

```vue
<!-- app/app.vue -->
<template>
  <NuxtLayout>
    <NuxtPage />
  </NuxtLayout>
</template>
```

## Другой layout для страницы

```vue
<!-- app/layouts/admin.vue -->
<template>
  <div class="admin">
    <AdminSidebar />
    <section><slot /></section>
  </div>
</template>
```

```vue
<!-- app/pages/admin/index.vue -->
<script setup lang="ts">
definePageMeta({ layout: "admin" });
</script>
```

```vue
<!-- app/pages/login.vue — без оболочки -->
<script setup lang="ts">
definePageMeta({ layout: false });
</script>
```

## Динамическая смена

```ts
function enterFocusMode() {
  setPageLayout("focus");
}
```

В route middleware layout можно выбрать до рендера:

```ts
export default defineNuxtRouteMiddleware((to) => {
  if (to.path.startsWith("/docs")) setPageLayout("docs");
});
```

## Несколько слотов

```vue
<!-- app/layouts/dashboard.vue -->
<template>
  <aside><slot name="sidebar" /></aside>
  <main><slot /></main>
</template>
```

```vue
<!-- страница с layout: false оборачивает себя сама -->
<template>
  <NuxtLayout name="dashboard">
    <template #sidebar><FiltersPanel /></template>
    <ProductsTable />
  </NuxtLayout>
</template>
```

## Когда нужны разные layouts

Публичный сайт, авторизация, личный кабинет, админка, документация — у каждой зоны своя оболочка. Это лучше, чем один layout с цепочкой `v-if` на тип страницы.

## Частые ошибки

- Не обернуть `<NuxtPage>` в `<NuxtLayout>` — layouts не применяются.
- Писать в layout больше одного корневого элемента без необходимости: для анимаций переходов layout должен иметь один корень.
- Делать один универсальный layout с условиями вместо нескольких.
- Загружать в layout данные, нужные только одной странице.

## Что важно помнить

- Layout переживает навигацию между страницами с тем же layout — состояние шапки и меню сохраняется.
- Имя layout — имя файла в kebab-case: `custom-admin.vue` → `"custom-admin"`.
- Layout выбирается до рендера страницы, поэтому смена через middleware не вызывает мерцания.

## Мини-шпаргалка

- `app/layouts/default.vue` — по умолчанию.
- `definePageMeta({ layout: "admin" })`, `layout: false`.
- `setPageLayout("name")` — динамически.
- `<NuxtLayout name="x">` — вручную со слотами.
