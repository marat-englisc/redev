# Как работают pages и файловый роутинг

> [!NOTE]
> Nuxt генерирует конфигурацию Vue Router из файлов в `app/pages`: путь файла становится URL, `index.vue` — корнем каталога, `[id]` — динамическим параметром, `[[id]]` — необязательным, `[...slug]` — catch-all. Файл `parent.vue` рядом с каталогом `parent/` создаёт **вложенный маршрут** с `<NuxtPage />` внутри. Мета страницы (layout, middleware, имя, валидация параметров) задают через `definePageMeta`. Каждая страница автоматически выделяется в отдельный чанк.

## Вопрос

Как работает файловый роутинг в Nuxt?

## Основные правила

```text
app/pages/
├── index.vue                  → /
├── about.vue                  → /about
├── blog/
│   ├── index.vue              → /blog
│   └── [slug].vue             → /blog/:slug
├── users/
│   └── [[tab]].vue            → /users и /users/:tab (необязательный параметр)
├── [...slug].vue              → любой путь, например 404-страница
└── (marketing)/
    └── pricing.vue            → /pricing (группа не влияет на URL)
```

## Параметры

```vue
<!-- app/pages/products/[id].vue -->
<script setup lang="ts">
const route = useRoute();
const id = computed(() => route.params.id as string);

const { data: product } = await useFetch(() => `/api/products/${id.value}`);
</script>
```

Параметр catch-all — массив: `/docs/a/b` → `route.params.slug === ["a", "b"]`.

## Вложенные маршруты

```text
app/pages/
├── account.vue          → оболочка, содержит <NuxtPage />
└── account/
    ├── index.vue        → /account
    └── orders.vue       → /account/orders
```

```vue
<!-- app/pages/account.vue -->
<template>
  <div class="account">
    <AccountSidebar />
    <NuxtPage />
  </div>
</template>
```

## definePageMeta

```vue
<script setup lang="ts">
definePageMeta({
  layout: "admin",
  middleware: ["auth"],
  name: "product",
  alias: ["/item/:id"],
  validate: (route) => /^\d+$/.test(route.params.id as string), // false → 404
  keepalive: true,
});
</script>
```

`definePageMeta` — макрос: его аргумент извлекается при сборке, поэтому внутри нельзя использовать переменные из `setup`.

## Навигация

```vue
<NuxtLink to="/blog">Блог</NuxtLink>
<NuxtLink :to="{ name: 'product', params: { id: 42 } }">Товар</NuxtLink>
```

```ts
await navigateTo("/login");
await navigateTo({ path: "/search", query: { q: "nuxt" } });
await navigateTo("https://example.com", { external: true });
```

Подробнее — в [уроке про NuxtLink и navigateTo](<09. Как работают NuxtLink, navigateTo и prefetch.md>).

## Свои маршруты

Если файлового роутинга не хватает, можно дополнить маршруты через хук `pages:extend` в `nuxt.config.ts` или файл `app/router.options.ts` (в том числе `scrollBehavior`).

## Частые ошибки

- Читать `route.params.id` один раз в константу и не реагировать на смену параметра при переходе между товарами.
- Использовать в `definePageMeta` значения из `setup`.
- Забыть `<NuxtPage />` в родительском файле вложенного маршрута.
- Не возвращать 404 для несуществующего `id` — страница отдаёт 200 с пустым контентом.

## Что важно помнить

- Маршрут = путь файла; квадратные скобки — параметры.
- Каждая страница — отдельный чанк, код делится автоматически.
- Для несуществующей сущности бросают `createError({ statusCode: 404 })`, а не показывают пустую страницу.

## Мини-шпаргалка

- `index.vue` → корень, `[id]` → параметр, `[[id]]` → необязательный, `[...slug]` → catch-all.
- `parent.vue` + `parent/` → вложенный маршрут.
- `(group)/` — группировка без влияния на URL.
- `definePageMeta({ layout, middleware, validate })`.
