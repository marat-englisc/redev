# Что такое route middleware

> [!NOTE]
> **Route middleware** — функция, которая выполняется **перед переходом на страницу** (и при первом SSR-рендере, и при клиентской навигации). Её используют для редиректов, проверки авторизации на уровне UI, выбора layout, feature-флагов. Виды: именованные (`app/middleware/auth.ts`, подключаются через `definePageMeta`), глобальные (суффикс `.global`, на каждый переход) и inline. Вернуть можно `navigateTo()` — редирект, `abortNavigation()` — отмена, ничего — пропустить. Route middleware **не защищает API**: проверка прав обязательна и на сервере.

## Вопрос

Что такое route middleware в Nuxt и как его использовать?

## Именованный middleware

```ts
// app/middleware/auth.ts
export default defineNuxtRouteMiddleware((to) => {
  const { loggedIn } = useUserSession(); // или свой useAuth()

  if (!loggedIn.value) {
    return navigateTo({ path: "/login", query: { redirect: to.fullPath } });
  }
});
```

```vue
<!-- app/pages/account.vue -->
<script setup lang="ts">
definePageMeta({ middleware: ["auth"] });
</script>
```

## Глобальный middleware

```ts
// app/middleware/01.analytics.global.ts
export default defineNuxtRouteMiddleware((to, from) => {
  if (import.meta.client) trackPageView(to.fullPath);
});
```

Глобальные выполняются на каждый переход в алфавитном порядке имён — для явного порядка используют числовые префиксы.

## Inline middleware

```vue
<script setup lang="ts">
definePageMeta({
  middleware: [
    (to) => {
      if (to.params.id === "0") return abortNavigation();
    },
  ],
});
</script>
```

## Что можно вернуть

| Возврат | Результат |
| --- | --- |
| Ничего | Переход продолжается |
| `navigateTo("/login")` | Редирект (на сервере — HTTP 302) |
| `navigateTo("/new", { redirectCode: 301 })` | Постоянный редирект |
| `abortNavigation()` | Отмена перехода |
| `abortNavigation(createError({ statusCode: 403 }))` | Отмена с ошибкой |

## Где и когда выполняется

- При первом запросе — **на сервере** во время SSR и **ещё раз в браузере** при старте приложения.
- При клиентских переходах — **в браузере**.

Поэтому код должен работать в обоих окружениях и не делать дорогую работу дважды. Пропустить повторный запуск при гидрации можно так:

```ts
export default defineNuxtRouteMiddleware(() => {
  const nuxtApp = useNuxtApp();
  if (import.meta.client && nuxtApp.isHydrating && nuxtApp.payload.serverRendered) return;
  // ...
});
```

Чтобы запустить логику только в одном окружении, используют `import.meta.client` / `import.meta.server`. Внутри middleware можно вызывать composables (`useState`, `useCookie`, `useNuxtApp`) — контекст Nuxt доступен.

## Динамическое добавление

```ts
// app/plugins/admin-guard.ts
export default defineNuxtPlugin(() => {
  addRouteMiddleware("admin", (to) => { /* ... */ }, { global: true });
});
```

## Частые ошибки

- Защищать данные только route middleware — API-маршрут без проверки сессии отдаст данные любому.
- Бесконечный редирект: middleware на `/login` перенаправляет на `/login`.
- Проверять авторизацию по `localStorage` — на сервере его нет, SSR и клиент разойдутся.
- Путать `app/middleware` с `server/middleware` (тот работает на каждый HTTP-запрос, включая API).

## Что важно помнить

- Route middleware — про навигацию и UX, а не про безопасность данных.
- Для авторизации на сервере доступны cookies, поэтому сессию хранят в cookie, а не в `localStorage`.
- Сравнение с серверным middleware — в [отдельном уроке](<../05. Server API Nitro и deployment/03. Чем route middleware отличается от server middleware.md>).

## Мини-шпаргалка

- `defineNuxtRouteMiddleware((to, from) => ...)`.
- `app/middleware/name.ts` + `definePageMeta({ middleware: ["name"] })`.
- `.global.ts` — на каждый переход.
- `navigateTo`, `abortNavigation`.
- API защищают на сервере.
