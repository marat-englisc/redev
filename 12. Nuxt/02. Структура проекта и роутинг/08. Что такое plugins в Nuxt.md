# Что такое plugins в Nuxt

> [!NOTE]
> **Плагин** — код, который выполняется один раз при создании Vue-приложения (на сервере для каждого запроса и в браузере при старте). Плагины из `app/plugins` регистрируются автоматически; через `defineNuxtPlugin` подключают Vue-плагины (`nuxtApp.vueApp.use`), директивы, создают API-клиенты и отдают их через `provide` (доступ как `$name` из `useNuxtApp()`), вешают хуки Nuxt. Суффиксы `.client.ts` и `.server.ts` ограничивают окружение, порядок задаётся префиксами или `dependsOn`.

## Вопрос

Что такое плагины в Nuxt и когда их использовать?

## Пример: API-клиент

```ts
// app/plugins/api.ts
export default defineNuxtPlugin(() => {
  const config = useRuntimeConfig();

  const api = $fetch.create({ baseURL: config.public.apiBase });

  return {
    provide: { api },
  };
});
```

```ts
const { $api } = useNuxtApp();
const user = await $api<User>("/users/me");
```

Тип `$api` выводится автоматически.

## Пример: Vue-плагин и директива

```ts
// app/plugins/vue-libs.ts
import VueGtag from "vue-gtag";

export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.vueApp.use(VueGtag, { config: { id: useRuntimeConfig().public.gaId } });

  nuxtApp.vueApp.directive("focus", {
    mounted: (el) => el.focus(),
    getSSRProps: () => ({}), // директиве нужно описать поведение при SSR
  });
});
```

## Окружение и порядок

```text
app/plugins/
├── 01.sentry.client.ts     # только браузер, выполняется первым
├── 02.api.ts               # сервер и клиент
└── analytics.client.ts     # только браузер
```

Объектный синтаксис даёт больше контроля:

```ts
export default defineNuxtPlugin({
  name: "auth",
  dependsOn: ["api"],      // дождаться плагина api
  parallel: true,          // не блокировать остальные асинхронные плагины
  async setup(nuxtApp) { /* ... */ },
  hooks: {
    "page:finish": () => { /* после смены страницы */ },
  },
});
```

## Хуки приложения

```ts
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook("app:error", (error) => reportError(error));
  nuxtApp.hook("page:start", () => startProgress());
});
```

## Плагин или composable

| Задача | Выбор |
| --- | --- |
| Подключить Vue-библиотеку, директиву | Плагин |
| Глобальная инициализация (Sentry, аналитика) | Плагин |
| Один экземпляр клиента на приложение | Плагин с `provide` |
| Логика для отдельных компонентов | Composable |

Каждый плагин выполняется при каждом SSR-запросе и при старте в браузере — тяжёлые синхронные плагины замедляют TTFB и гидрацию.

## Частые ошибки

- Использовать `window` в универсальном плагине — нужен суффикс `.client`.
- Делать долгий `await` в плагине без `parallel` — блокирует рендер всего приложения.
- Хранить состояние запроса в переменной модуля плагина — на сервере она общая для всех пользователей.
- Путать `app/plugins` и `server/plugins` (плагины Nitro).

## Что важно помнить

- Плагины выполняются до рендера страниц, поэтому `provide` доступен везде.
- На сервере плагины выполняются **для каждого запроса** — это нормально и безопасно, если состояние создаётся внутри функции.
- Предпочитай composables, а плагины оставляй для инициализации уровня приложения.

## Мини-шпаргалка

- `defineNuxtPlugin((nuxtApp) => ...)`.
- `return { provide: { api } }` → `useNuxtApp().$api`.
- `.client.ts`, `.server.ts`, числовые префиксы.
- `nuxtApp.vueApp.use()`, `nuxtApp.hook()`.
