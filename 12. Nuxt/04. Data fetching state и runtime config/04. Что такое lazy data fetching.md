# Что такое lazy data fetching

> [!NOTE]
> По умолчанию `await useFetch()` **блокирует навигацию**: при клиентском переходе новая страница не покажется, пока данные не загрузятся (на сервере — HTML не отправится). **Lazy-режим** (`lazy: true`, `useLazyFetch`, `useLazyAsyncData`) разрешает показать страницу сразу, а данные дозагрузить, — поэтому шаблон обязан обрабатывать `status === "pending"`. На SSR lazy-данные всё равно загружаются до отправки HTML, разница проявляется при клиентской навигации. Для данных, которые не нужны в HTML вовсе, есть `server: false`.

## Вопрос

Что такое lazy data fetching в Nuxt и когда его применять?

## Блокирующая загрузка

```ts
const { data } = await useFetch("/api/products");
```

```text
клик по ссылке → ждём ответ (виден NuxtLoadingIndicator) → показываем страницу с данными
```

Подходит, когда страница без данных бессмысленна.

## Lazy-загрузка

```vue
<script setup lang="ts">
const { data: reviews, status } = useLazyFetch("/api/reviews");
// то же: useFetch("/api/reviews", { lazy: true })
</script>

<template>
  <ReviewsSkeleton v-if="status === 'pending'" />
  <ReviewsList v-else :reviews="reviews ?? []" />
</template>
```

```text
клик по ссылке → страница сразу со скелетоном → данные приходят → список
```

## Только на клиенте

```ts
const { data: recommendations } = useFetch("/api/recommendations", {
  lazy: true,
  server: false,
});
```

Сервер не делает этот запрос, в HTML его нет, рендер не замедляется. Подходит для персональных блоков на кэшируемой странице и второстепенных данных.

## Сочетание на одной странице

```ts
// критичное для SEO и первого экрана — блокирующе
const { data: product } = await useFetch(() => `/api/products/${id.value}`);

// второстепенное — лениво
const { data: reviews, status: reviewsStatus } = useLazyFetch(() => `/api/products/${id.value}/reviews`);

// персональное — только на клиенте
const { data: wishlist } = useFetch("/api/wishlist", { lazy: true, server: false });
```

## Режимы

| Режим | SSR | Клиентская навигация | В HTML |
| --- | --- | --- | --- |
| `await useFetch()` | Ждёт | Ждёт | Да |
| `lazy: true` | Ждёт | Не ждёт | Да |
| `server: false` | Не выполняется | Зависит от `lazy` | Нет |
| `immediate: false` | Не выполняется | По `execute()` | Нет |

## Когда lazy, когда нет

**Lazy** — блоки ниже первого экрана, комментарии, рекомендации, тяжёлые запросы, где скелетон лучше задержки перехода.

**Блокирующе** — основной контент страницы, данные для мета-тегов, данные, влияющие на HTTP-статус (404).

## Частые ошибки

- `lazy: true` без обработки `pending` — пустой блок или ошибка `undefined`.
- `server: false` для SEO-контента — его не будет в HTML.
- Строить `useSeoMeta` на lazy-данных и ждать их в первом HTML при клиентских переходах.
- Последовательные `await` для независимых данных — используйте `Promise.all` или lazy.

## Что важно помнить

- Lazy меняет UX клиентских переходов, а не содержимое SSR-ответа.
- `server: false` — единственный способ исключить данные из серверного рендера.
- Каждый lazy-блок требует состояний loading и error.

## Мини-шпаргалка

- `await useFetch` — ждать, `lazy: true` / `useLazyFetch` — не ждать.
- `server: false` — только браузер.
- `status === "pending"` — скелетон.
- Критичное — блокирующе, второстепенное — лениво.
