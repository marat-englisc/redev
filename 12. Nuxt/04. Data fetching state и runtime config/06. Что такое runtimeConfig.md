# Что такое runtimeConfig

> [!NOTE]
> `runtimeConfig` — конфигурация, которую можно **переопределить переменными окружения при запуске** без пересборки. Ключи верхнего уровня доступны **только на сервере** (секреты, URL внутренних сервисов), ключи внутри `public` — и на сервере, и в браузере (они попадают в payload). Значения задают в `nuxt.config.ts` как значения по умолчанию, а в окружении — переменными с префиксом `NUXT_` и `NUXT_PUBLIC_`: `apiSecret` → `NUXT_API_SECRET`, `public.apiBase` → `NUXT_PUBLIC_API_BASE`. Читают через `useRuntimeConfig()`.

## Вопрос

Что такое `runtimeConfig` и как безопасно работать с переменными окружения в Nuxt?

## Объявление

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  runtimeConfig: {
    apiSecret: "",                     // NUXT_API_SECRET
    databaseUrl: "",                   // NUXT_DATABASE_URL
    stripe: { secretKey: "" },         // NUXT_STRIPE_SECRET_KEY
    public: {
      apiBase: "/api",                 // NUXT_PUBLIC_API_BASE
      siteUrl: "http://localhost:3000",// NUXT_PUBLIC_SITE_URL
      gaId: "",                        // NUXT_PUBLIC_GA_ID
    },
  },
});
```

```env
# .env (локально, не в git)
NUXT_API_SECRET=dev-secret
NUXT_PUBLIC_API_BASE=https://api.example.com
```

## Чтение

```vue
<script setup lang="ts">
const config = useRuntimeConfig();
config.public.apiBase;   // ✓ на сервере и в браузере
config.apiSecret;        // на сервере — значение, в браузере — undefined
</script>
```

```ts
// server/api/payment.post.ts
export default defineEventHandler(async (event) => {
  const { stripe } = useRuntimeConfig(event);   // в server/ передают event
  // ...
});
```

## Как это работает

```text
сборка:  значения из nuxt.config.ts → в .output как значения по умолчанию
запуск:  NUXT_* из окружения процесса → переопределяют значения
сервер:  весь объект
клиент:  только public (через payload)
```

`.env` читается только в `nuxt dev`, `nuxt build` и `nuxt generate`. В production `.env` не загружается — переменные задаёт платформа или `node --env-file=.env .output/server/index.mjs`.

## Ловушка process.env

```ts
// ✗ значение «запекается» на момент сборки и не меняется при запуске
runtimeConfig: { apiSecret: process.env.API_SECRET }
```

Это работает только если переменная есть во время сборки. Надёжнее оставить пустое значение по умолчанию и задать `NUXT_API_SECRET` при запуске. Так один и тот же собранный образ работает в staging и production.

## Что куда

| Значение | Где |
| --- | --- |
| Пароли, токены, ключи API, URL БД | `runtimeConfig` (верхний уровень) |
| Публичный URL API, сайта, ID аналитики | `runtimeConfig.public` |
| Тема, тексты UI, настройки компонентов | `app.config.ts` |
| Флаги сборки | `nuxt.config.ts` |

## Частые ошибки

- Секрет в `public` — он окажется в HTML каждой страницы.
- Ждать, что `.env` загрузится в production.
- Использовать `process.env.X` в коде приложения вместо `useRuntimeConfig()` — в браузере `process.env` нет.
- Неправильное имя переменной: для `public.apiBase` нужно `NUXT_PUBLIC_API_BASE`, а не `NUXT_API_BASE`.
- Добавить переменную окружения, не объявив ключ в `runtimeConfig`, — Nuxt её не подхватит.

## Что важно помнить

- Переопределяются только ключи, объявленные в `nuxt.config.ts`.
- `public` = публично, без исключений.
- В `server/` вызывайте `useRuntimeConfig(event)` — это позволяет корректно работать на edge-платформах.

## Мини-шпаргалка

- Верхний уровень — сервер, `public` — всем.
- `NUXT_<KEY>`, `NUXT_PUBLIC_<KEY>`, camelCase → SNAKE_CASE.
- `useRuntimeConfig()` / `useRuntimeConfig(event)`.
- `.env` — только dev/build.
- Пустые значения по умолчанию + переменные при запуске.
