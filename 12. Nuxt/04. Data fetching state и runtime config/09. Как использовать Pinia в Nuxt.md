# Как использовать Pinia в Nuxt

> [!NOTE]
> Pinia подключают модулем `@pinia/nuxt`: он создаёт **отдельный экземпляр Pinia на каждый SSR-запрос**, сериализует состояние stores в payload и восстанавливает его при гидрации, а `defineStore`, `storeToRefs` и сами stores из `app/stores` становятся auto-imports. Данные в store загружают через `callOnce` или `useAsyncData`, а не в `onMounted`, чтобы они попали в HTML. Pinia выбирают вместо `useState`, когда нужна доменная модель с actions, getters, DevTools и плагинами (например, persisted state).

## Вопрос

Как подключить Pinia в Nuxt и правильно работать с ней при SSR?

## Подключение

```bash
npx nuxt module add pinia
```

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ["@pinia/nuxt"],
  pinia: { storesDirs: ["./app/stores/**"] },
});
```

## Store

```ts
// app/stores/cart.ts
export const useCartStore = defineStore("cart", () => {
  const items = ref<CartItem[]>([]);
  const total = computed(() => items.value.reduce((s, i) => s + i.price * i.qty, 0));

  async function load() {
    items.value = await $fetch<CartItem[]>("/api/cart");
  }

  async function add(productId: number) {
    const item = await $fetch<CartItem>("/api/cart", { method: "POST", body: { productId } });
    items.value.push(item);
  }

  return { items, total, load, add };
});
```

## Загрузка данных при SSR

```vue
<script setup lang="ts">
const cart = useCartStore();
const { items, total } = storeToRefs(cart);

await callOnce("cart", () => cart.load()); // выполнится один раз: на сервере, а на клиенте возьмётся из payload
</script>
```

Альтернатива — `useAsyncData`, возвращающий значение:

```ts
await useAsyncData("cart", () => cart.load().then(() => true));
```

Без этого `cart.load()` в `setup` выполнится и на сервере, и при гидрации, а в `onMounted` — данных не будет в HTML.

## Store внутри middleware и плагинов

```ts
export default defineNuxtRouteMiddleware(async () => {
  const auth = useAuthStore();       // контекст Nuxt доступен — получим store текущего запроса
  if (!auth.user) return navigateTo("/login");
});
```

Вне контекста Nuxt (на уровне модуля) `useXStore()` вызывать нельзя: на сервере неизвестно, к какому запросу относится store.

## Сохранение в localStorage

```ts
export const useSettingsStore = defineStore("settings", () => {
  const theme = ref<"light" | "dark">("light");
  return { theme };
}, {
  persist: { storage: piniaPluginPersistedstate.cookies() }, // с модулем @pinia-plugin-persistedstate/nuxt
});
```

Для значений, влияющих на первый рендер (тема, язык), выбирайте cookie: сервер прочитает её и отрендерит правильный вариант без мерцания.

## useState или Pinia

| | `useState` | Pinia |
| --- | --- | --- |
| Сложность | Минимальная | Store с actions и getters |
| DevTools | Нет отдельной вкладки | Timeline, инспектор |
| Плагины | Нет | Persisted state, свои плагины |
| Тестирование | Через composable | `createTestingPinia` |
| Типичное | Флаги, пользователь, тема | Корзина, фильтры каталога, сложные формы |

## Частые ошибки

- Загружать данные store в `onMounted` и терять SSR.
- Деструктурировать store без `storeToRefs` — теряется реактивность.
- Хранить в store несериализуемое (экземпляры классов, функции в state).
- Подключать Pinia через `createPinia()` в плагине вручную вместо модуля — ломается изоляция запросов и передача состояния.

## Что важно помнить

- `@pinia/nuxt` решает SSR-проблемы: изоляцию запросов и гидрацию состояния.
- `callOnce` — идиоматичный способ один раз инициализировать store на SSR.
- Подробно о Pinia — в разделе [Vue: Pinia](<../../11. Vue/11. Pinia/01. Как подключить Pinia к Vue проекту.md>).

## Мини-шпаргалка

- `modules: ["@pinia/nuxt"]`, stores в `app/stores`.
- `defineStore` в setup-стиле.
- `await callOnce("key", () => store.load())`.
- `storeToRefs` для деструктуризации.
- Persisted state — лучше в cookies.
