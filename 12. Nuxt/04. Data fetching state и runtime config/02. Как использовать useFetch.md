# Как использовать useFetch

> [!NOTE]
> `useFetch(url, options)` — основной способ загрузить данные страницы. Он выполняется на сервере, передаёт результат через payload и возвращает `{ data, status, error, refresh, clear }`. URL может быть строкой, `ref` или функцией, а `query`, `body`, `headers` — реактивными: при их изменении запрос **повторяется автоматически**. Ключевые опции: `query`, `method`, `body`, `headers`, `transform`, `pick`, `default`, `lazy`, `server`, `immediate`, `watch`, `deep`, `key`, `getCachedData`.

## Вопрос

Как использовать `useFetch` и какие у него опции?

## Базовый пример

```vue
<script setup lang="ts">
const { data: products, status, error, refresh } = await useFetch("/api/products");
</script>

<template>
  <p v-if="status === 'pending'">Загрузка…</p>
  <p v-else-if="error">Не удалось загрузить: {{ error.statusMessage }}</p>
  <ul v-else>
    <li v-for="p in products" :key="p.id">{{ p.title }}</li>
  </ul>
  <button @click="refresh()">Обновить</button>
</template>
```

## Реактивные параметры

```ts
const route = useRoute();
const page = ref(1);
const search = ref("");

const { data } = await useFetch("/api/products", {
  query: { page, search },          // ref'ы отслеживаются: смена page → новый запрос
});

const { data: product } = await useFetch(
  () => `/api/products/${route.params.id}`, // функция — URL пересчитается при смене параметра
);
```

Частая ошибка — шаблонная строка без функции:

```ts
// ✗ URL вычислен один раз, при переходе /products/1 → /products/2 данные не обновятся
await useFetch(`/api/products/${route.params.id}`);
```

## Преобразование и значение по умолчанию

```ts
const { data } = await useFetch("/api/products", {
  transform: (items) => items.map((p) => ({ ...p, priceLabel: formatPrice(p.price) })),
  default: () => [],                 // data не будет undefined
});

const { data: user } = await useFetch("/api/me", {
  pick: ["id", "name", "avatar"],    // только эти поля попадут в payload
});
```

## Управление запуском

| Опция | Поведение |
| --- | --- |
| `lazy: true` | Не блокировать навигацию, показывать loading |
| `server: false` | Выполнять только в браузере (данные не в HTML) |
| `immediate: false` | Не запускать сразу, ждать `execute()` |
| `watch: [x]` | Перезапуск при изменении дополнительных источников |
| `watch: false` | Не следить за реактивными опциями |
| `deep: true` | Сделать `data` глубоко реактивным (по умолчанию `shallowRef`) |
| `dedupe: "cancel" \| "defer"` | Что делать с параллельным повторным запросом |
| `timeout` | Ограничение времени запроса |

```ts
const { data, execute, status } = useFetch("/api/report", {
  immediate: false,
  server: false,
});

async function generate() {
  await execute();
}
```

## Перехватчики

```ts
const { data } = await useFetch("/api/profile", {
  onRequest({ options }) {
    options.headers.set("X-Locale", "ru");
  },
  onResponseError({ response }) {
    console.error(response.status);
  },
});
```

## POST через useFetch

`useFetch` допустим для POST, если это **загрузка** данных (поиск с телом запроса). Для мутаций по действию пользователя используют `$fetch` — иначе запрос выполнится при каждом рендере и повторится при изменении реактивного `body`.

## Кэш между переходами

```ts
const { data } = await useFetch("/api/categories", {
  key: "categories",
  getCachedData: (key, nuxtApp, ctx) =>
    ctx.cause === "refresh:manual" ? undefined : nuxtApp.payload.data[key] ?? nuxtApp.static.data[key],
});
```

Так справочник не перезапрашивается при каждом возвращении на страницу, но `refresh()` по-прежнему идёт в сеть.

## Частые ошибки

- Шаблонная строка вместо функции для URL с параметрами.
- `useFetch` для отправки формы.
- Забыть обработать `status === "pending"` при `lazy: true`.
- Обращаться к `data.value.items` без проверки — в Nuxt 4 начальное значение `undefined`.

## Что важно помнить

- Реактивные `query` и функция-URL — встроенный способ «перезапрашивать при смене фильтров».
- `transform` и `pick` уменьшают payload и вес HTML.
- Ключ генерируется автоматически из URL и опций; явный `key` нужен для общего доступа к данным и `refreshNuxtData`.

## Мини-шпаргалка

- `const { data, status, error, refresh } = await useFetch(url, opts)`.
- URL — функция, `query` — ref'ы.
- `transform`, `pick`, `default`.
- `lazy`, `server: false`, `immediate: false`.
- Мутации — `$fetch`.
