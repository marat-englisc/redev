# Как использовать useAsyncData

> [!NOTE]
> `useAsyncData(key, handler, options)` выполняет **произвольную** асинхронную функцию с SSR-поддержкой: результат кэшируется по ключу и передаётся через payload. Его выбирают, когда источник — не один HTTP-эндпоинт: несколько параллельных запросов, SDK CMS, Nuxt Content, GraphQL, свой API-клиент из плагина. Ключ должен быть **уникальным и стабильным**: по нему данные находятся в payload, обновляются через `refreshNuxtData(key)` и (в Nuxt 4) **разделяются** между всеми компонентами с тем же ключом. Опции те же, что у `useFetch`: `lazy`, `server`, `transform`, `pick`, `default`, `watch`, `deep`.

## Вопрос

Когда использовать `useAsyncData` и как правильно задавать ключ?

## Несколько источников

```ts
const route = useRoute();

const { data, status } = await useAsyncData(
  () => `product:${route.params.id}`,               // реактивный ключ
  async () => {
    const id = route.params.id as string;
    const [product, reviews] = await Promise.all([
      $fetch(`/api/products/${id}`),
      $fetch(`/api/products/${id}/reviews`),
    ]);
    return { product, reviews };
  },
);
```

При смене `id` меняется ключ — Nuxt загрузит новые данные. Запросы внутри выполняются параллельно.

## Nuxt Content

```ts
const route = useRoute();
const { data: post } = await useAsyncData(`post:${route.path}`, () =>
  queryCollection("blog").path(route.path).first(),
);
```

`queryCollection` — API Nuxt Content v3 (в v2 был `queryContent`).

## Свой API-клиент

```ts
const { $api } = useNuxtApp();

const { data: orders } = await useAsyncData("orders", () => $api<Order[]>("/orders"));
```

Голый вызов `await $api("/orders")` в `setup` не попал бы в payload — был бы двойной запрос.

## Ключи

| Ключ | Когда |
| --- | --- |
| Строка `"orders"` | Данные не зависят от параметров |
| Функция `() => \`user:${id.value}\`` | Данные зависят от реактивных значений |
| Без ключа | Ключ сгенерируется из файла и строки — работает, но к данным нельзя обратиться по имени |

С одним ключом в разных компонентах Nuxt 4 использует одни и те же `data`/`status`/`error` — удобно, но опции (`transform`, `default`, `deep`) должны совпадать, иначе будет предупреждение.

## Перезапуск по зависимостям

```ts
const category = ref("books");
const sort = ref("price");

const { data } = await useAsyncData(
  "catalog",
  () => $fetch("/api/products", { query: { category: category.value, sort: sort.value } }),
  { watch: [category, sort] },
);
```

В отличие от `useFetch`, `useAsyncData` не знает, какие ref'ы используются внутри функции, — их перечисляют в `watch` или делают реактивным ключ.

## Отмена запроса

```ts
const { data } = await useAsyncData("search", (_nuxtApp, { signal }) =>
  $fetch("/api/search", { query: { q: q.value }, signal }),
  { watch: [q] },
);
```

`signal` позволяет отменить устаревший запрос при быстром изменении `q`.

## Частые ошибки

- Один и тот же ключ для разных данных.
- Ключ, зависящий от `Math.random()` или времени, — данные не найдутся в payload.
- Забыть `watch` и удивляться, что данные не обновляются.
- Бросать исключение из обработчика вместо использования `error` — ошибка попадёт в `error`, это нормальный путь.

## Что важно помнить

- `useAsyncData` — фундамент, `useFetch` — его частный случай.
- Ключ — идентификатор данных в payload и кэше приложения.
- Параллельные запросы в одном обработчике быстрее последовательных `await useFetch`.

## Мини-шпаргалка

- `useAsyncData(key, () => ..., opts)`.
- Реактивный ключ — функция.
- `watch: [...]` для зависимостей внутри обработчика.
- `signal` — отмена.
- Content v3: `queryCollection(...)`.
