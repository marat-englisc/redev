# Как обновлять и очищать данные useAsyncData

> [!NOTE]
> После мутации данные нужно перезагрузить: `refresh()` из результата `useFetch`/`useAsyncData` обновляет конкретный запрос, `refreshNuxtData(key)` — по ключу из любого места (без аргумента — все), `clearNuxtData(key)` сбрасывает данные (например, при выходе), `useNuxtData(key)` даёт доступ к уже загруженным данным — для оптимистичного обновления и показа кэша. Всё это работает по **ключу**, поэтому для данных, которые будут обновляться извне, ключ задают явно.

## Вопрос

Как обновить данные после мутации и очистить их при выходе пользователя?

## refresh из результата

```vue
<script setup lang="ts">
const { data: todos, refresh } = await useFetch("/api/todos", { key: "todos" });

async function addTodo(title: string) {
  await $fetch("/api/todos", { method: "POST", body: { title } });
  await refresh();
}
</script>
```

## refreshNuxtData — из другого компонента

```ts
// компонент формы ничего не знает о списке, кроме ключа
await $fetch("/api/todos", { method: "POST", body });
await refreshNuxtData("todos");            // один ключ
await refreshNuxtData(["todos", "stats"]); // несколько
await refreshNuxtData();                   // все данные страницы
```

## Оптимистичное обновление

```ts
const { data: todos } = useNuxtData<Todo[]>("todos");

async function toggle(todo: Todo) {
  const previous = todos.value;
  todos.value = todos.value?.map((t) => (t.id === todo.id ? { ...t, done: !t.done } : t));

  try {
    await $fetch(`/api/todos/${todo.id}`, { method: "PATCH", body: { done: !todo.done } });
  } catch {
    todos.value = previous;                     // откат
  } finally {
    await refreshNuxtData("todos");             // сверка с сервером
  }
}
```

Обратите внимание: обновляем `todos.value` целиком — в Nuxt 4 `data` является `shallowRef`, мутация внутреннего поля UI не обновит.

## Кэш при возврате на страницу

```ts
const { data: product } = useNuxtData<Product>(`product:${id}`);

const { data } = await useFetch(`/api/products/${id}`, {
  key: `product:${id}`,
  default: () => product.value,   // показать уже загруженное в списке, пока идёт запрос
});
```

## Очистка

```ts
async function logout() {
  await $fetch("/api/auth/logout", { method: "POST" });
  clearNuxtData();                          // все данные
  clearNuxtState();                         // все useState
  await navigateTo("/login");
}
```

`clearNuxtData(key)` или массив ключей — для частичной очистки. Без очистки после выхода новый пользователь на том же устройстве может на мгновение увидеть данные предыдущего.

## Конкурирующие запросы

```ts
await refresh({ dedupe: "cancel" });   // отменить текущий запрос и начать новый (по умолчанию)
await refresh({ dedupe: "defer" });    // если запрос уже идёт — дождаться его, новый не начинать
```

## Частые ошибки

- Автоматический ключ — потом нечем обновить данные извне.
- Мутировать `data.value.items.push()` вместо замены значения.
- Не чистить данные при выходе.
- Обновлять всё (`refreshNuxtData()`) там, где нужен один ключ, — лишние запросы.

## Что важно помнить

- Явный ключ — контракт между тем, кто загружает данные, и тем, кто их обновляет.
- Оптимистичное обновление нужно сопровождать откатом и финальной сверкой.
- Для сложной инвалидации кэша иногда удобнее TanStack Query для Vue или Pinia Colada.

## Мини-шпаргалка

- `refresh()` — свой запрос.
- `refreshNuxtData(key)` — по ключу откуда угодно.
- `useNuxtData(key)` — доступ к кэшу, оптимистичные обновления.
- `clearNuxtData()` + `clearNuxtState()` — при выходе.
- `dedupe: "cancel" | "defer"`.
