# Как SEO связано с frontend-разработкой

> [!NOTE]
> Frontend-разработчик отвечает за **техническую основу SEO**: в каком виде поисковик получает страницу (режим рендеринга — SSR, SSG, CSR), её HTML-структуру и семантику, `<head>` (title, description, canonical, robots, Open Graph, hreflang), маршрутизацию и статус-коды, ссылки, изображения, structured data, Core Web Vitals и доступность. Решения, принятые на уровне архитектуры и шаблонов, влияют на тысячи страниц сразу, поэтому SEO-требования выясняют до разработки, а после релиза проверяют итоговый HTML.

## Вопрос

Как frontend-разработка влияет на SEO?

## Зоны ответственности frontend

| Область | Что важно |
| --- | --- |
| Рендеринг | Публичные страницы отдают контент в HTML (SSR, SSG, prerender) |
| `<head>` | Уникальные title и description, canonical, `robots`, OG, hreflang для каждого маршрута |
| Маршруты | Стабильные понятные URL, корректные 404 и 301 |
| Семантика | Один `h1`, иерархия заголовков, `main`, `nav`, `article` |
| Ссылки | Настоящие `<a href>`, а не `div` с `onClick` |
| Медиа | `alt`, размеры, современные форматы, lazy loading вне первого экрана |
| Производительность | LCP, INP, CLS: размер JS, гидрация, шрифты, сторонние скрипты |
| Structured data | JSON-LD, соответствующий видимому контенту |
| Доступность | Связана с семантикой и качеством страницы |

## Плохо и лучше

```html
<!-- CSR: поисковик и соцсети видят пустую оболочку -->
<title>App</title>
<div id="app"></div>
```

```html
<!-- SSR/SSG: контент, мета-теги и ссылки сразу в HTML -->
<title>Курс по Nuxt: SSR, SSG и SEO</title>
<meta name="description" content="Разбираем рендеринг и SEO во Vue-приложениях">
<link rel="canonical" href="https://example.com/courses/nuxt">
<main>
  <h1>Курс по Nuxt</h1>
  <a href="/courses/nuxt/ssr">Что такое SSR</a>
</main>
```

## Типовые ошибки разработчиков

- Ссылки через `div @click` или `button` с `router.push` — робот не видит переходов.
- Одинаковый title на всех страницах SPA.
- Canonical не меняется при клиентской навигации.
- Несуществующая страница отдаёт 200 («мягкий» 404).
- Важный контент загружается только по клику или скроллу.
- Картинки без размеров — сдвиг макета (CLS).
- Фильтры генерируют тысячи индексируемых URL.
- Hydration-ошибки и тяжёлый JS ухудшают INP.
- Staging-настройка `noindex` попала в production.

## Как работать с SEO-специалистом

Договоритесь о правилах для каждого шаблона: какие страницы индексируются, как строятся title и canonical, какие фильтры получают отдельные URL, какие structured data нужны. Подробнее — в уроке [Как frontend-разработчику говорить про SEO](<../09. Практика и собеседования/05. Как frontend-разработчику говорить про SEO.md>).

## Что важно помнить

- SEO начинается с доступного HTML.
- Выбор SSR/SSG/CSR — архитектурное SEO-решение.
- Проверять нужно ответ сервера (`curl`, URL Inspection), а не DOM после выполнения JS.

## Мини-шпаргалка

- Контент и мета — в HTML.
- `<a href>` для навигации.
- Уникальные title, description, canonical.
- Правильные статус-коды.
- Core Web Vitals и доступность.
