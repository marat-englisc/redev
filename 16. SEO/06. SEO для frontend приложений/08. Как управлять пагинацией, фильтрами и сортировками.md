# Как управлять пагинацией, фильтрами и сортировками

> [!NOTE]
> Пагинация, фильтры и сортировки удобны пользователю, но порождают множество URL. Правила: **пагинация** — каждая страница имеет свой URL (`?page=2`), self-canonical и ссылки `<a href>` на соседние страницы, чтобы робот дошёл до всех товаров (`rel="prev/next"` Google больше не использует). **Фильтры** — индексируются только комбинации со спросом и уникальным набором (получают «чистый» URL и свой контент), остальные не получают индексируемых ссылок и закрываются. **Сортировки и вид** не создают новой страницы — canonical на базовую страницу, без индексации. Бесконечную ленту дополняют пагинацией с URL.

## Вопрос

Как правильно настроить пагинацию, фильтры и сортировки для SEO?

## Пагинация

```html
<!-- /catalog/keyboards?page=2 -->
<link rel="canonical" href="https://shop.example.com/catalog/keyboards?page=2">
<title>Механические клавиатуры — страница 2 · Магазин</title>

<nav aria-label="Страницы">
  <a href="/catalog/keyboards">1</a>
  <a href="/catalog/keyboards?page=2" aria-current="page">2</a>
  <a href="/catalog/keyboards?page=3">3</a>
</nav>
```

- Страница 1 — канонический URL без `?page=1` (с `?page=1` — 301 на базовый).
- Canonical **на себя**, а не на первую страницу: иначе товары со второй страницы и далее могут перестать находиться.
- Ссылки на страницы — обычные `<a href>`.
- Несуществующая страница (`?page=999`) — 404.

## «Показать ещё» и бесконечная лента

```text
✓ Кнопка «Показать ещё» подгружает следующую порцию И меняет URL на ?page=2 (History API)
✓ Параллельно существуют обычные ссылки на страницы пагинации
✗ Только бесконечный скролл без URL — робот видит первую порцию
```

## Фильтры

```text
/catalog/laptops?brand=apple            → полезный фильтр со спросом
/catalog/laptops/apple                  → его «чистая» индексируемая версия

/catalog/laptops?brand=apple&ram=16&color=silver&sort=price  → мусорная комбинация
```

| Тип фильтра | Решение |
| --- | --- |
| Со спросом и уникальным набором | Отдельный URL, индекс, self-canonical, уникальные title/h1/текст, ссылки из навигации, в sitemap |
| Без спроса, полезный пользователю | Без индексируемых ссылок, `noindex` или canonical на категорию |
| Комбинации многих фильтров | Без ссылок `<a href>`, закрыть в robots.txt |
| Пустой результат | 404 или `noindex` |

Фильтры, которые не нужно индексировать, можно применять через форму или кнопки с изменением состояния и `history.replaceState`, не создавая индексируемых ссылок.

## Сортировки и вид

```html
<!-- /catalog/keyboards?sort=price_asc -->
<link rel="canonical" href="https://shop.example.com/catalog/keyboards">
<meta name="robots" content="noindex, follow">
```

Сортировка меняет порядок, а не содержание — новой страницы нет.

## Параметры

- Единый порядок параметров (`?brand=apple&ram=16`, а не случайный).
- Строчные значения.
- Трекинговые и сессионные параметры — не в canonical, `Clean-param` для Яндекса.

## Частые ошибки

- Canonical всех страниц пагинации на первую.
- `noindex` на пагинации — со временем перестают учитываться ссылки на товары.
- Ссылки на все комбинации фильтров в сайдбаре.
- Бесконечный скролл без URL.
- Индексируемые сортировки.

## Что важно помнить

- Каждая страница пагинации — самостоятельная страница списка.
- Индексируемые фильтры — продуктовое решение на основе спроса.
- Главный способ управлять фильтрами — не порождать на них индексируемые ссылки.

## Мини-шпаргалка

- Пагинация: свой URL, self-canonical, `<a href>`.
- Бесконечная лента + URL страниц.
- Фильтры со спросом — чистый URL и контент, остальные — без ссылок и индекса.
- Сортировки — canonical на базовую + noindex.
- Нормализация параметров.
