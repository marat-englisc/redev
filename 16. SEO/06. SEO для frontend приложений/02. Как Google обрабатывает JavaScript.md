# Как Google обрабатывает JavaScript

> [!NOTE]
> Google обрабатывает JS-страницы в три фазы: **обход** (скачивает HTML, находит ссылки из `<a href>`), **рендеринг** (ставит страницу в очередь и выполняет JavaScript в актуальном headless Chromium — evergreen Googlebot) и **индексация** итогового DOM. Рендеринг может быть отложен, а робот не кликает, не скроллит как человек, не сохраняет cookies и `localStorage` между страницами и ограничен по времени. Поэтому контент, ссылки и мета-теги, появляющиеся только после действий или долгих запросов, могут не попасть в индекс. Dynamic rendering (отдельная версия для ботов) Google считает временным обходным решением, а не рекомендацией.

## Вопрос

Как Google индексирует сайты на JavaScript и какие у этого ограничения?

## Три фазы

```text
1. Crawl:   GET /products/42 → исходный HTML → ссылки <a href> в очередь обхода
2. Render:  очередь рендеринга → Chromium выполняет JS → итоговый DOM
3. Index:   контент, ссылки, мета-теги из отрендеренного DOM → индекс
```

Если в исходном HTML есть `noindex`, Google может не перейти к рендерингу — убрать `noindex` JavaScript'ом не получится.

## Что робот делает и не делает

| Делает | Не делает |
| --- | --- |
| Выполняет современный JS (evergreen Chromium) | Не кликает, не вводит текст, не наводит курсор |
| Загружает ресурсы, не закрытые robots.txt | Не скроллит как пользователь (использует высокий viewport) |
| Видит ссылки `<a href>` | Не переходит по `onclick` без `href` |
| Использует History API URL | Не индексирует фрагменты `#/route` как отдельные страницы |
| | Не сохраняет cookies, `localStorage` между страницами |
| | Не разрешает запросы геолокации, уведомлений, камеры |
| | Не ждёт бесконечно долгих запросов |

## Что может пойти не так

- JS, CSS или API закрыты в robots.txt.
- Ошибка JS в старом коде ломает рендер.
- Данные приходят только после авторизации или с проверкой антибота.
- Контент загружается при скролле через JS без пагинации со ссылками.
- Мета-теги и canonical меняются только на клиенте (и противоречат серверным).
- Страница отдаёт 200, а «404» рисует JS — soft 404.
- Бесконечная лента без URL для страниц.

## Как проверять

- **URL Inspection** в Search Console → «Проверить страницу на сайте» → отрендеренный HTML и скриншот, список заблокированных ресурсов, ошибки консоли.
- **Rich Results Test** — тоже показывает отрендеренный HTML.
- `curl` — что приходит без JS (то, что видят Яндекс, соцсети и ИИ-краулеры).
- Сравнение `view-source:` и DevTools Elements.

## Рекомендуемые подходы

| Подход | Когда |
| --- | --- |
| SSR / стриминг SSR | Динамические публичные страницы |
| SSG / prerender | Стабильный контент |
| ISR / SWR | Много страниц, обновляемых периодически |
| Гибрид | Публичное — серверно, закрытое — CSR |
| Dynamic rendering | Только как временная мера для старых систем |

## Ленивая загрузка контента

Для бесконечной ленты используйте пагинацию с реальными URL (`?page=2`) и ссылками на страницы — так робот может пройти все элементы. Изображения — нативный `loading="lazy"`, который Google понимает; ленивая подгрузка через `IntersectionObserver` работает, если не требует реального скролла пользователя.

## Частые ошибки

- Полагаться на то, что «Google всё выполнит».
- `noindex` в шаблоне SPA с расчётом снять его JS-ом.
- Hash-роутинг для публичного сайта.
- Блокировать `/_next/` или `/assets/` в robots.txt.

## Что важно помнить

- Google умеет JS, но это дополнительная и отложенная фаза.
- Другие поисковики и боты рассчитывают на исходный HTML.
- Самое надёжное — критичный контент, ссылки и мета-теги в серверном HTML.

## Мини-шпаргалка

- Crawl → Render (очередь) → Index.
- Робот не кликает, не скроллит, не хранит состояние.
- `<a href>`, History API, ресурсы открыты.
- URL Inspection — что увидел Google.
- SSR/SSG вместо dynamic rendering.
