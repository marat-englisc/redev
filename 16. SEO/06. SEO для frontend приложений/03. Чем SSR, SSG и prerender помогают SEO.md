# Чем SSR, SSG и prerender помогают SEO

> [!NOTE]
> SSR, SSG и prerender отдают поисковику и пользователю **готовый HTML** с контентом, мета-тегами, ссылками и structured data — без ожидания выполнения JavaScript. **SSR** рендерит страницу на сервере на каждый запрос (свежие данные, нужен сервер). **SSG** генерирует HTML при сборке (максимальная скорость, данные устаревают до пересборки). **ISR/SWR** — статика с периодическим обновлением кэша. **Prerender** — генерация HTML для части маршрутов SPA. Для SEO это делает индексацию предсказуемой, ускоряет LCP и позволяет отдавать корректные статус-коды.

## Вопрос

Чем SSR, SSG и prerender помогают SEO и как выбрать режим?

## Режимы

```text
SSR:       GET /product/42 → сервер получает данные → HTML → ответ
SSG:       build → /blog/vue-seo/index.html → CDN → ответ
ISR/SWR:   ответ из кэша → в фоне перегенерация по TTL или по событию
Prerender: build → HTML для выбранных маршрутов SPA, остальное — CSR
CSR:       пустой HTML → JS → запрос данных → рендер в браузере
```

## Что получает поисковик

| Режим | Контент в HTML | Мета-теги в HTML | Статус-коды | Свежесть |
| --- | --- | --- | --- | --- |
| SSR | Да | Да | Любые, на лету | Всегда |
| SSG | Да | Да | 200/404 на уровне хостинга | До пересборки |
| ISR/SWR | Да | Да | Да | С задержкой TTL |
| Prerender | Да, для выбранных | Да, для выбранных | Ограниченно | До пересборки |
| CSR | Нет | Нет | Обычно 200 на всё | Всегда |

## Что выбрать

| Сценарий | Режим |
| --- | --- |
| Блог, документация, лендинги | SSG |
| Каталог, карточки товаров | ISR/SWR или SSR с кэшем |
| Поиск, фильтры с параметрами | SSR |
| Новости, частые обновления | SSR или ISR с коротким TTL |
| Личный кабинет, админка | CSR |
| SPA с несколькими публичными страницами | Prerender этих страниц |

## Реализация во фреймворках

| Фреймворк | Как |
| --- | --- |
| Next.js | Server Components по умолчанию, `generateStaticParams`, `revalidate`, `export const dynamic` |
| Nuxt | SSR по умолчанию, `routeRules`: `prerender`, `swr`, `isr`, `ssr: false` |
| Astro | SSG по умолчанию, островная гидрация |
| Vite SPA | Плагины prerender (vite-ssg, vite-plugin-ssr/Vike) |

Подробно о режимах Nuxt — в разделе [Nuxt: рендеринг](<../../12. Nuxt/03. Rendering SSR SSG ISR и hydration/02. Чем отличаются SSR, CSR, SSG, ISR и SWR.md>).

## Ограничения

- SSR требует сервера и следит за TTFB: медленные запросы к API делают медленным весь ответ.
- SSG неудобен для миллионов страниц и часто меняющихся данных.
- Гидрация остаётся: HTML виден сразу, но интерактивность зависит от объёма JS.
- Персональный контент нельзя кэшировать общим кэшем (ISR/SWR/SSG).

## Частые ошибки

- Включить SSR, но загружать основной контент на клиенте после монтирования.
- SSG для каталога с ценами, меняющимися ежечасно.
- Кэшировать SWR страницы, зависящие от сессии.
- Prerender страниц, которые затем отдают 200 на несуществующие пути.

## Что важно помнить

- Цель — контент, мета-теги и правильный статус в первом ответе сервера.
- Режим выбирается по каждому типу страницы, а не для всего приложения.
- SSR без кэша — дорогой и медленный; кэш HTML — ключ к хорошему TTFB.

## Мини-шпаргалка

- SSR — на запрос, SSG — при сборке, ISR/SWR — статика с обновлением.
- Prerender — для части SPA.
- Публичное — серверно, закрытое — CSR.
- Кэш HTML и TTFB.
