# Как делать international SEO и hreflang

> [!NOTE]
> International SEO — показ пользователю правильной **языковой или региональной** версии страницы. Нужны: отдельный URL на каждую версию (подкаталоги `/en/`, поддомены или домены), полноценно локализованный контент (не только перевод, но и валюта, единицы, примеры), атрибут `lang` у `<html>` и **hreflang** — аннотации `<link rel="alternate" hreflang="..." href="...">`, связывающие версии между собой. Hreflang должен быть **взаимным** (каждая версия ссылается на все остальные и на себя), указывать на канонические URL со статусом 200 и включать `x-default` для страницы по умолчанию. Автоматический редирект по IP без возможности выбрать версию вредит и пользователям, и роботам.

## Вопрос

Как настроить мультиязычный сайт и hreflang?

## Структура URL

| Вариант | Пример | Плюсы | Минусы |
| --- | --- | --- | --- |
| Подкаталоги | `example.com/en/` | Один домен, проще поддержка, общий авторитет | Слабее сигнал страны |
| Поддомены | `en.example.com` | Отдельная инфраструктура | Авторитет делится |
| Национальные домены | `example.de`, `example.ru` | Сильный сигнал страны | Дорого, отдельное продвижение |
| Параметры `?lang=en` | | | Не рекомендуется |

Чаще всего выбирают подкаталоги.

## Hreflang

```html
<!-- на каждой из версий — один и тот же полный набор -->
<link rel="alternate" hreflang="ru" href="https://example.com/pricing">
<link rel="alternate" hreflang="en" href="https://example.com/en/pricing">
<link rel="alternate" hreflang="de-AT" href="https://example.com/de-at/pricing">
<link rel="alternate" hreflang="x-default" href="https://example.com/en/pricing">
```

- Коды: язык ISO 639-1 (`ru`, `en`), опционально регион ISO 3166-1 (`en-GB`, `de-AT`). Только регион (`gb`) — ошибка.
- **Взаимность**: если `/pricing` ссылается на `/en/pricing`, то `/en/pricing` обязан ссылаться на `/pricing`.
- **Self-reference**: каждая версия включает ссылку на себя.
- `x-default` — для пользователей, чей язык не подходит ни под одну версию (часто страница выбора языка или английская).
- Альтернатива HTML-тегам — hreflang в sitemap (`<xhtml:link>`) или HTTP-заголовок `Link` для PDF.

## Hreflang и canonical

Каждая языковая версия канонична **сама себе**. Canonical с английской версии на русскую сломает hreflang: поисковик решит, что английской версии нет.

## Определение языка пользователя

```text
✗ IP из Германии → принудительный редирект на /de/   (робот из США никогда не увидит /de/)
✓ Предложить баннер «Перейти на немецкую версию?» + запомнить выбор
✓ Переключатель языка — ссылки <a href> на версии текущей страницы
```

## Локализация — не только перевод

- Валюта, цены, налоги, единицы измерения.
- Форматы дат и телефонов.
- Локальные примеры, отзывы, способы оплаты и доставки.
- Ключевые слова — исследовать отдельно для каждого языка: прямой перевод запроса часто не совпадает с тем, как ищут.

## Во фреймворках

- Nuxt: `@nuxtjs/i18n` генерирует маршруты по языкам и hreflang, Nuxt SEO добавляет их в sitemap.
- Next.js: подкаталоги `[locale]`, `alternates.languages` в `generateMetadata`.

## Частые ошибки

- Нет обратных ссылок между версиями.
- Hreflang на не-канонические URL, редиректы или 404.
- Canonical всех версий на основную.
- Неверные коды (`en-UK` вместо `en-GB`, `ua` вместо `uk`).
- Частично переведённые страницы (шапка переведена, контент — нет).
- `lang` у `<html>` не совпадает с языком страницы.

## Что важно помнить

- Hreflang — подсказка, а не директива, но ошибки в нём часто приводят к показу не той версии.
- Каждая версия — самостоятельная каноническая страница.
- Яндекс тоже поддерживает hreflang; для локальной выдачи Яндекса важен и регион сайта.

## Мини-шпаргалка

- Отдельный URL на версию, лучше подкаталоги.
- Hreflang: взаимно, с self-reference, `x-default`.
- Каждая версия — self-canonical.
- Без принудительного редиректа по IP.
- Локализация, а не машинный перевод.
