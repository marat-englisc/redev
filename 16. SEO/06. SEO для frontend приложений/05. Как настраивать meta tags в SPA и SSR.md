# Как настраивать meta tags в SPA и SSR

> [!NOTE]
> Мета-теги должны соответствовать **конкретной странице**: уникальные `<title>` и `description`, canonical на её URL, `robots` при необходимости, Open Graph и Twitter Cards для превью, `hreflang` для языковых версий, `lang` у `<html>`. Важно не только *что*, но и *когда* они появляются: в SSR/SSG — сразу в HTML, и их видят все роботы, включая соцсети и мессенджеры; в SPA — только после выполнения JS, и многие боты их не увидят. При клиентской навигации head-менеджер (`@unhead`, `react-helmet`, Metadata API Next.js) обязан обновлять и удалять старые теги.

## Вопрос

Как настраивать мета-теги в SPA и SSR-приложениях?

## Базовый набор

```html
<html lang="ru">
<head>
  <title>SEO-аудит сайта: чек-лист и примеры</title>
  <meta name="description" content="Пошаговый SEO-аудит: индексация, скорость, structured data и контент.">
  <link rel="canonical" href="https://example.com/seo-audit">
  <meta name="robots" content="index, follow, max-image-preview:large">

  <meta property="og:type" content="article">
  <meta property="og:title" content="SEO-аудит сайта">
  <meta property="og:description" content="Чек-лист и примеры технического SEO-аудита.">
  <meta property="og:image" content="https://example.com/og/seo-audit.png">
  <meta property="og:url" content="https://example.com/seo-audit">
  <meta name="twitter:card" content="summary_large_image">

  <link rel="alternate" hreflang="en" href="https://example.com/en/seo-audit">
  <link rel="alternate" hreflang="ru" href="https://example.com/seo-audit">
</head>
```

## Проблема SPA

```html
<!-- index.html одинаковый для всех маршрутов -->
<title>App</title>
<div id="app"></div>
```

JS меняет `document.title` и мета-теги после загрузки. Google увидит их после рендеринга, но боты Telegram, VK, Slack, Facebook, X и многие ИИ-краулеры читают только исходный HTML — превью ссылки будет «App» без картинки.

Решения: SSR/SSG, prerender публичных страниц или серверная подстановка мета-тегов в `index.html` по URL (edge-функция, middleware).

## SSR: мета-теги из данных

```tsx
// Next.js App Router
export async function generateMetadata({ params }): Promise<Metadata> {
  const product = await getProduct(params.slug);
  return {
    title: `${product.title} — купить`,
    description: product.summary,
    alternates: { canonical: `/products/${params.slug}` },
    openGraph: { images: [product.image] },
  };
}
```

```ts
// Nuxt
const { data: product } = await useFetch(() => `/api/products/${route.params.slug}`);
useSeoMeta({
  title: () => `${product.value?.title} — купить`,
  description: () => product.value?.summary,
  ogImage: () => product.value?.image,
});
```

Данные для мета-тегов загружаются **до** рендера, в том же запросе, что и контент.

## Клиентская навигация

При переходе `/a → /b` head-менеджер должен:

- заменить title, description, canonical, OG;
- удалить теги, которых нет на новой странице (например, `noindex` или JSON-LD товара);
- не оставлять дублей (два canonical, два description).

## Что проверить

- Уникальный title и description для каждого шаблона.
- Canonical соответствует текущему URL.
- OG-картинка абсолютная, 1200×630.
- После клиентских переходов в DOM нет «хвостов» прошлой страницы.
- `noindex` только на тех страницах, где задуман.
- Превью ссылки — в отладчиках соцсетей и мессенджерах.

## Частые ошибки

- Мета-теги только на клиенте для публичных страниц.
- Дубли тегов от нескольких источников (CMS + фреймворк + плагин).
- Canonical на главную для всех страниц.
- Относительный `og:image`.
- Шаблон без данных: `undefined — купить`.

## Что важно помнить

- Для поиска и превью важен серверный HTML.
- Мета-теги — часть данных страницы и загружаются вместе с контентом.
- Head-менеджер отвечает и за добавление, и за удаление тегов.

## Мини-шпаргалка

- title, description, canonical, robots, OG, Twitter, hreflang, `lang`.
- SSR/SSG — мета в HTML для всех ботов.
- SPA — только после JS, соцсети не увидят.
- `generateMetadata`, `useSeoMeta`, `@unhead`.
- Проверять хвосты после навигации.
