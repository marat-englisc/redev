# Как делать SEO во Vue SPA и Nuxt

> [!NOTE]
> В **Vue SPA** (Vite + Vue Router) HTML пустой, поэтому для SEO нужно: History-режим роутера, мета-теги на каждый маршрут через `@unhead/vue`, настоящие ссылки `<RouterLink>`, серверный fallback на `index.html` и корректные 404, а для публичных страниц — **prerender** или переход на SSR. **Nuxt** решает основу из коробки: SSR по умолчанию, гибридный рендеринг через `routeRules`, `useSeoMeta`/`useHead` при SSR, правильные статусы через `createError`, модули Nuxt SEO для sitemap, robots, Schema.org и OG-картинок. Подробный разбор Nuxt — в разделе [Nuxt: SEO](<../../12. Nuxt/06. SEO и Nuxt SEO/01. Как Nuxt помогает SEO.md>).

## Вопрос

Как сделать SEO во Vue SPA и в Nuxt?

## Vue SPA: обязательный минимум

```ts
// router.ts — History API вместо #
import { createRouter, createWebHistory } from "vue-router";

export const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: "/", component: () => import("./pages/Home.vue") },
    { path: "/products/:slug", component: () => import("./pages/Product.vue") },
    { path: "/:pathMatch(.*)*", component: () => import("./pages/NotFound.vue") },
  ],
});
```

```vue
<!-- Product.vue -->
<script setup lang="ts">
import { useSeoMeta, useHead } from "@unhead/vue";

const product = await loadProduct(route.params.slug);

useSeoMeta({
  title: () => `${product.value?.title} — купить`,
  description: () => product.value?.description,
  ogImage: () => product.value?.image,
});
useHead({ link: [{ rel: "canonical", href: () => `https://shop.example.com${route.path}` }] });
</script>
```

- Сервер (Nginx, CDN) отдаёт `index.html` на любой путь — значит, 404 не будет; для несуществующих страниц добавляют `noindex` в компоненте NotFound или отдают 404 на уровне сервера по списку маршрутов.
- Для публичных страниц — prerender при сборке (`vite-ssg` и аналоги) или переход на Nuxt.

## Nuxt: что даёт фреймворк

| Задача | Nuxt |
| --- | --- |
| Контент в HTML | SSR по умолчанию |
| Режимы по разделам | `routeRules`: `prerender`, `swr`, `isr`, `ssr: false` |
| Мета-теги | `useSeoMeta`, `useHead`, `titleTemplate` — при SSR |
| 404 | `throw createError({ statusCode: 404 })` |
| Редиректы | `navigateTo(url, { redirectCode: 301 })`, `routeRules.redirect` |
| Sitemap, robots | `@nuxtjs/sitemap`, `@nuxtjs/robots` |
| Structured data | `nuxt-schema-org` |
| OG-картинки | `nuxt-og-image` |
| Скорость | `@nuxt/image`, `@nuxt/fonts`, `@nuxt/scripts`, lazy hydration |

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ["@nuxtjs/seo"],
  site: { url: "https://shop.example.com", name: "Магазин" },
  routeRules: {
    "/": { prerender: true },
    "/blog/**": { prerender: true },
    "/catalog/**": { swr: 600 },
    "/account/**": { ssr: false, robots: false },
  },
});
```

```vue
<script setup lang="ts">
const route = useRoute();
const { data: post } = await useFetch(() => `/api/posts/${route.params.slug}`);
if (!post.value) throw createError({ statusCode: 404, fatal: true });

useSeoMeta({ title: () => post.value?.title, description: () => post.value?.excerpt });
</script>
```

## Общие правила для обоих

- Ссылки — `<RouterLink>`/`<NuxtLink>`, рендерят `<a href>`.
- Уникальные title, description, canonical на каждый маршрут.
- Мета-теги вычисляются из данных, загруженных до рендера (в Nuxt — `await useFetch`).
- Проверка итогового HTML через `curl` и URL Inspection.

## Частые ошибки

- `createWebHashHistory()` в публичном SPA.
- Один title в `index.html` на все страницы.
- В Nuxt — загрузка контента с `server: false` или в `onMounted`.
- Пустая страница «Не найдено» со статусом 200.

## Что важно помнить

- Vue SPA можно привести к приемлемому SEO, но это ручная работа; Nuxt даёт это по умолчанию.
- Режим рендеринга выбирается по разделам: публичное — SSR/SSG, закрытое — CSR.
- Мета-теги и статусы должны быть в серверном ответе.

## Мини-шпаргалка

- SPA: History API, `@unhead/vue`, prerender, 404-стратегия.
- Nuxt: SSR, `routeRules`, `useSeoMeta`, `createError`, Nuxt SEO.
- `<a href>`, уникальные мета, проверка HTML.
