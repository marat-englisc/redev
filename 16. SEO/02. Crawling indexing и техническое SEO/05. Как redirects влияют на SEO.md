# Как redirects влияют на SEO

> [!NOTE]
> Редирект перенаправляет пользователя и робота со старого URL на новый. **Постоянные** (301, 308) говорят поисковику заменить старый URL новым в индексе и передать ему сигналы; **временные** (302, 307) — сохранить старый URL основным. 308 и 307 дополнительно сохраняют HTTP-метод запроса. Серверный редирект надёжнее JavaScript-редиректа и `meta refresh`. Редиректы ведут на **максимально релевантную** страницу, без цепочек и циклов, и при миграциях держатся минимум год.

## Вопрос

Как редиректы влияют на SEO и какой код использовать?

## Коды редиректов

| Код | Тип | Метод при повторе | SEO-сценарий |
| --- | --- | --- | --- |
| 301 Moved Permanently | Постоянный | Может смениться на GET | Смена URL, домена, HTTPS |
| 308 Permanent Redirect | Постоянный | Сохраняется | То же, когда важен метод (API, формы) |
| 302 Found | Временный | Может смениться на GET | Временная акция, A/B-тест |
| 307 Temporary Redirect | Временный | Сохраняется | Временный редирект с сохранением метода |
| 303 See Other | — | Всегда GET | После POST формы, не для SEO |

```http
HTTP/1.1 301 Moved Permanently
Location: https://example.com/new-page
```

Для поисковика 301 и 308 равнозначны, как и 302 и 307. Если «временный» редирект держится долго, Google со временем может считать его постоянным.

## Типы по реализации

| Реализация | Надёжность |
| --- | --- |
| HTTP-редирект на сервере, CDN, в фреймворке | Лучший вариант |
| `<meta http-equiv="refresh" content="0;url=...">` | Учитывается, но хуже |
| JavaScript `location.replace()` | Работает только после рендеринга — крайний случай |

Во фреймворках: Next.js — `redirects` в `next.config` или `redirect()`/`permanentRedirect()`, Nuxt — `routeRules: { "/old": { redirect: { to: "/new", statusCode: 301 } } }`.

## Цепочки и циклы

```text
✗ /old → /older → /newer → /new    (цепочка: замедляет, робот может прервать обход)
✓ /old → /new

✗ /a → /b → /a                      (цикл: страница недоступна)
```

При каждой миграции старые редиректы обновляют так, чтобы вели сразу на конечный URL. Google проходит до 10 переходов, но каждый шаг — потеря скорости и риск.

## Куда редиректить

- На страницу с тем же содержанием или ближайшую замену (старый товар → новая модель, категория).
- Не на главную «массово»: Google считает такие редиректы soft 404, сигналы не передаются.
- Если замены нет — 404 или 410.

## Типичные сценарии

```text
http://example.com/*      → https://example.com/*          301
https://www.example.com/* → https://example.com/*          301
/catalog/Phones/          → /catalog/phones/               301 (единый регистр)
/blog/2019/old-post       → /blog/new-post                 301
/sale                     → /sale/black-friday             302 (на время акции)
```

## Частые ошибки

- 302 для постоянного переезда.
- Массовые редиректы на главную.
- Цепочки после нескольких миграций.
- Снять редиректы через месяц после переезда.
- Внутренние ссылки ведут на URL с редиректом вместо конечного.
- Редирект по IP или языку без возможности выбрать версию — робот видит только одну.

## Что важно помнить

- Постоянный редирект — основной инструмент сохранения трафика при смене URL.
- Цель редиректа должна быть релевантной, иначе сигналы теряются.
- После миграции обновляют внутренние ссылки, canonical и sitemap на новые URL.

## Мини-шпаргалка

- 301/308 — навсегда, 302/307 — временно.
- Серверный редирект > meta refresh > JS.
- Один переход, без цепочек и циклов.
- На релевантную страницу, не на главную.
- Держать минимум год.
