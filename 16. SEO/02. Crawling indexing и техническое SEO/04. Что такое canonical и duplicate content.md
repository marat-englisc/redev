# Что такое canonical и duplicate content

> [!NOTE]
> **Дубли** — одинаковый или почти одинаковый контент, доступный по разным URL (параметры, UTM, слеш на конце, `http`/`https`, `www`, версии для печати). Поисковик группирует такие URL и выбирает одну **каноническую** версию для индекса, объединяя на ней сигналы. Указать предпочтительную версию можно тегом `<link rel="canonical" href="...">` (или HTTP-заголовком `Link`), 301-редиректом, ссылками и sitemap. Canonical — **сильная подсказка, а не директива**: если сигналы противоречат, поисковик выберет свой вариант. Canonical не заменяет `noindex` и не подходит для страниц с разным контентом.

## Вопрос

Что такое canonical и как бороться с дублями?

## Откуда берутся дубли

```text
https://shop.example.com/product/phone
https://shop.example.com/product/phone/
https://shop.example.com/product/phone?utm_source=newsletter
https://shop.example.com/product/phone?color=black      ← если контент тот же
http://shop.example.com/product/phone
https://www.shop.example.com/product/phone
https://shop.example.com/catalog/phones/phone           ← товар в нескольких категориях
```

## Тег canonical

```html
<link rel="canonical" href="https://shop.example.com/product/phone">
```

```http
Link: <https://shop.example.com/files/guide.pdf>; rel="canonical"
```

- Абсолютный URL.
- Одна каноническая ссылка на страницу, в `<head>` серверного HTML.
- **Self-canonical** на каноничной странице — хорошая практика, защищает от дублей с параметрами.

## Способы указать каноническую версию

| Способ | Сила сигнала | Когда |
| --- | --- | --- |
| 301-редирект | Сильный | Дубль не нужен пользователям (`http` → `https`, `www` → без `www`, слеш) |
| `rel="canonical"` | Сильный | Дубль нужен пользователям (UTM, сортировка, товар в разных категориях) |
| Ссылки внутри сайта | Слабее | Всегда ссылаться на канонический URL |
| Sitemap | Слабее | Только канонические URL |

## Сигналы должны совпадать

Canonical, внутренние ссылки, sitemap, hreflang и редиректы должны указывать на один и тот же URL. Если canonical указывает на `/phone`, а ссылки и sitemap — на `/phone/`, Google может проигнорировать canonical. В Search Console это видно как «Google выбрал другую каноническую страницу, чем пользователь».

## Пагинация

```html
<!-- /blog?page=2 -->
<link rel="canonical" href="https://example.com/blog?page=2">
```

Не делайте canonical всех страниц пагинации на первую: на них другие элементы списка, и поисковик может перестать видеть товары с дальних страниц. `rel="prev/next"` Google больше не использует.

## Похожие, но разные страницы

Canonical не подходит для страниц с разным содержанием («красные кроссовки» и «синие кроссовки» с разными товарами) — поисковик его проигнорирует. Для них решают: отдельная индексируемая страница со своим контентом или `noindex`.

## Во frontend-приложениях

- Canonical должен приходить в серверном HTML и меняться при клиентской навигации.
- Canonical с домена staging или `localhost` в production — частая ошибка шаблона.
- Canonical строят из `pathname` без трекинговых параметров, но с параметрами, меняющими контент (пагинация).

## Частые ошибки

- Canonical на главную для всех страниц.
- Относительный URL или URL с другим протоколом.
- Несколько canonical на странице (от CMS и от фреймворка).
- Canonical на страницу с `noindex` или редиректом.
- Canonical на 404.

## Что важно помнить

- Canonical — подсказка; поисковик учитывает совокупность сигналов.
- Для дублей, ненужных пользователям, лучше 301.
- Self-canonical на всех индексируемых страницах — разумное значение по умолчанию.

## Мини-шпаргалка

- `<link rel="canonical" href="абсолютный URL">`.
- Self-canonical по умолчанию.
- Редирект для технических дублей, canonical — для пользовательских.
- Canonical = ссылки = sitemap.
- Пагинация — каждая страница сама себе canonical.
