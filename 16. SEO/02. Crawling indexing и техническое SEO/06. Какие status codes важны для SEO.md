# Какие status codes важны для SEO

> [!NOTE]
> HTTP-статус говорит поисковику, что произошло с URL. **200** — страница существует и может индексироваться. **301/308** — переехала навсегда, **302/307** — временно. **404** — не найдена, **410** — удалена навсегда: URL выпадает из индекса. **5xx** — ошибка сервера: при длительных ошибках страницы выпадают, а обход сайта замедляется. **503 + Retry-After** — правильный ответ на время технических работ. Главная ошибка frontend-приложений — **soft 404**: страница «не найдено» со статусом 200.

## Вопрос

Какие HTTP-статусы важны для SEO и как они влияют на индексацию?

## Основные статусы

| Код | Значение | Влияние на SEO |
| --- | --- | --- |
| 200 OK | Страница доступна | Может индексироваться |
| 301 / 308 | Постоянный переезд | Новый URL заменяет старый, сигналы передаются |
| 302 / 307 | Временный переезд | Старый URL остаётся в индексе |
| 304 Not Modified | Не изменилась | Экономит обход, контент из кэша |
| 401 / 403 | Нужна авторизация / запрещено | Не индексируется |
| 404 Not Found | Не найдена | Выпадает из индекса после повторных проверок |
| 410 Gone | Удалена навсегда | Выпадает немного быстрее, чем при 404 |
| 429 Too Many Requests | Перегрузка | Google снижает скорость обхода |
| 500 / 502 / 504 | Ошибка сервера | Обход замедляется, при длительных ошибках URL выпадают |
| 503 Service Unavailable | Временно недоступно | Google подождёт, не удаляя страницы сразу |

## Soft 404

```http
HTTP/1.1 200 OK
```

```html
<h1>Товар не найден</h1>
```

Поисковик видит «пустую» страницу с успешным статусом и помечает её как soft 404 — это засоряет индекс и сбивает отчёты. Правильно:

```http
HTTP/1.1 404 Not Found
```

Во фреймворках: Next.js — `notFound()`, Nuxt — `throw createError({ statusCode: 404 })`, Express — `res.status(404)`. В чистом SPA сервер обычно отдаёт 200 на любой путь; тогда для несуществующих страниц добавляют `<meta name="robots" content="noindex">` или редирект на настоящую 404-страницу сервера.

## Пустой поиск и пустая категория

- Поиск без результатов — 200 нормально, но такие страницы обычно закрывают `noindex`.
- Пустая категория (товары временно закончились) — 200 с полезным контентом и альтернативами.
- Категория удалена — 301 на родительскую или 404.

## Технические работы

```http
HTTP/1.1 503 Service Unavailable
Retry-After: 3600
```

Google воспринимает 503 как временную проблему и вернётся позже. Если отдавать 200 со страницей «Ведутся работы», она может проиндексироваться вместо контента; если отдавать 500 — обход замедлится. Держать 503 дольше пары дней нельзя — страницы начнут выпадать.

## Как проверять

```bash
curl -sI https://example.com/products/unknown | head -1    # ожидаем 404
curl -sIL https://example.com/old-page | grep -E "^HTTP|^location"  # цепочка редиректов
```

Отчёт «Индексирование страниц» в Search Console группирует URL по статусам: «Не найдено (404)», «Ошибка сервера (5xx)», «Ложная ошибка 404».

## Частые ошибки

- Soft 404 для несуществующих сущностей.
- 500 на технических работах вместо 503.
- 200 для страницы ошибки сервера.
- 302 для постоянного переезда.
- 403 для Googlebot из-за агрессивной защиты от ботов (WAF, антибот-сервисы).

## Что важно помнить

- Статус-код — первое, что поисковик узнаёт о странице.
- Индексируемая страница всегда 200; всё остальное — осознанное решение.
- Мониторинг 5xx важен для SEO не меньше, чем для пользователей.

## Мини-шпаргалка

- 200 — индексировать.
- 301/308 — переезд, 302/307 — временно.
- 404/410 — удалено.
- 503 + Retry-After — работы.
- Soft 404 — ошибка шаблона.
