# SEO checklist перед релизом

> [!NOTE]
> Перед релизом новых страниц, редизайна или изменений роутинга проверяют пять блоков: **индексация** (200, нет случайного `noindex` и `Disallow`, canonical, sitemap, редиректы), **HTML и мета** (контент и мета-теги в серверном ответе, уникальные title и description, один `h1`, `<a href>`), **разметка и статусы** (404 для несуществующего, structured data совпадает с UI), **производительность** (LCP, CLS, INP на ключевых шаблонах, мобильная версия) и **аналитика** (события, Search Console, отметка даты релиза). Значительную часть чек-листа стоит автоматизировать в CI.

## Вопрос

Что проверить перед релизом, чтобы не сломать SEO?

## Индексация

- [ ] Важные страницы отдают 200.
- [ ] Нет случайного `noindex` (мета-тег и заголовок `X-Robots-Tag`).
- [ ] `robots.txt` production не содержит `Disallow: /` и не блокирует CSS/JS.
- [ ] Canonical указывает на правильный production-URL.
- [ ] Sitemap обновлён и содержит только канонические URL со статусом 200.
- [ ] Старые URL ведут 301 на новые, без цепочек.
- [ ] Закрытые разделы (кабинет, корзина, поиск) не индексируются.

## HTML и мета-теги

- [ ] Контент, мета-теги и ссылки — в серверном HTML (`curl`).
- [ ] Уникальные title и description по шаблонам, без `undefined`.
- [ ] Один `h1`, логичная иерархия заголовков.
- [ ] Навигация — `<a href>`.
- [ ] Open Graph с абсолютным `og:image`, превью проверено.
- [ ] `lang` и hreflang (если есть языковые версии).
- [ ] Мета-теги обновляются при клиентской навигации без «хвостов».

## Статусы и разметка

- [ ] Несуществующие страницы и сущности отдают 404.
- [ ] Structured data валидна и соответствует видимому контенту.
- [ ] Нет placeholder-контента («Lorem ipsum», тестовые товары).

## Производительность

- [ ] LCP-изображение без lazy, с `fetchpriority="high"`.
- [ ] У изображений и embed есть размеры (нет CLS).
- [ ] Бандл не вырос неожиданно, сторонние скрипты под контролем.
- [ ] Lighthouse на ключевых шаблонах — без регрессий.
- [ ] Проверено на мобильных.

## Аналитика

- [ ] `page_view` отправляется при смене маршрута (SPA).
- [ ] Ключевые события работают.
- [ ] Search Console и Вебмастер подключены, sitemap отправлен.
- [ ] Дата релиза зафиксирована для последующего анализа.

## Автоматизация

```ts
// Playwright: SEO-смоук ключевых шаблонов
for (const url of ["/", "/catalog/keyboards", "/products/keychron-k2"]) {
  test(`SEO ${url}`, async ({ page, request }) => {
    const res = await request.get(url);
    expect(res.status()).toBe(200);
    const html = await res.text();
    expect(html).toMatch(/<title>[^<]{10,}<\/title>/);
    expect(html).toContain('rel="canonical"');
    expect(html).not.toMatch(/name="robots" content="[^"]*noindex/);
  });
}

test("404 для несуществующего товара", async ({ request }) => {
  expect((await request.get("/products/does-not-exist")).status()).toBe(404);
});
```

## После релиза

- Проверить выборку URL через URL Inspection.
- Следить за 404/5xx и отчётом «Индексирование» 2–4 недели.
- Сравнить клики и показы по шаблонам с периодом до релиза.

## Что важно помнить

- Самые дорогие ошибки — массовые: `noindex`, robots, canonical, статусы.
- Проверяют итоговый HTML, а не код.
- Автотесты на шаблоны дешевле, чем восстановление трафика.

## Мини-шпаргалка

- Индексация: 200, noindex, robots, canonical, sitemap, 301.
- HTML: контент и мета в ответе сервера, `h1`, `<a href>`, OG.
- 404 и structured data.
- LCP, CLS, мобильная версия.
- Аналитика и мониторинг после релиза.
