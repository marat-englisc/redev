# Как frontend-разработчику говорить про SEO

> [!NOTE]
> Frontend-разработчик не обязан быть SEO-стратегом, но должен говорить о SEO **языком инженерных решений**: какой режим рендеринга у публичных страниц, что приходит в серверном HTML, как формируются мета-теги и canonical, какие статус-коды и редиректы отдаёт приложение, как устроены ссылки и фильтры, какие structured data генерируются, как обстоят дела с Core Web Vitals и как всё это проверяется в CI. С SEO-специалистом договариваются о **правилах для шаблонов страниц**, а не о правках отдельных URL.

## Вопрос

Как frontend-разработчику обсуждать SEO с командой и на собеседовании?

## Зоны ответственности frontend

- Режим рендеринга: SSR, SSG, ISR, CSR по разделам.
- Head-менеджмент: title, description, canonical, robots, OG, hreflang.
- Роутинг: стабильные URL, 404, 301, нормализация параметров.
- Семантический HTML и ссылки `<a href>`.
- Изображения, шрифты, сторонние скрипты, размер JS — Core Web Vitals.
- Structured data из данных интерфейса.
- Доступность.
- Автотесты и мониторинг SEO-регрессий.

## Как звучит зрелый ответ

```text
Я смотрю на SEO не как на мета-теги, а как на свойство архитектуры.
Публичные страницы рендерятся на сервере, контент и мета-теги — в HTML, ссылки — настоящие <a href>.
Несуществующее отдаёт 404, переезды — 301. Фильтры со спросом получают чистые URL,
остальные не индексируются. Structured data генерируется из тех же данных, что UI.
В CI проверяем статусы, canonical и noindex на ключевых шаблонах, Lighthouse с порогами,
после релиза смотрим Search Console.
```

## Что спросить у SEO-специалиста

- Какие типы страниц должны индексироваться, а какие — нет?
- Какие правила canonical и нормализации URL?
- Какие шаблоны title и description для каждого типа?
- Какие фильтры и комбинации имеют спрос и заслуживают своей страницы?
- Нужны ли языковые версии и hreflang?
- Какие типы structured data нужны?
- Какие KPI у релиза и как будем измерять?
- Какой план редиректов, если меняются URL?

## Как объяснить команде

```text
Для публичных страниц CSR усложняет индексацию и делает пустыми превью в мессенджерах.
Предлагаю: каталог и статьи — SSR с кэшем, лендинги — SSG, личный кабинет оставить CSR.
Это ещё и улучшит LCP.
```

```text
Если сделать фильтры ссылками на каждую комбинацию, получим сотни тысяч дублей.
Давайте выберем 20 фильтров со спросом для отдельных страниц, а остальные будем применять без индексируемых ссылок.
```

## Как оформлять SEO-задачи

```text
Шаблон: карточка товара.
Проблема: canonical содержит query-параметры (?color=black) — дубли в индексе.
Решение: canonical = origin + pathname; цвет — не отдельная страница.
Проверка: curl → <link rel="canonical" href="https://shop.example.com/products/k2">.
```

## Частые ошибки в общении

- «SEO — не моя зона» — архитектура страниц именно ваша зона.
- Обещать рост позиций от технических правок.
- Править мета-теги по одной странице вместо шаблона.
- Не спрашивать критерии успеха.

## Что важно помнить

- Говорить о SEO через решения: рендеринг, HTML, URL, статусы, скорость.
- Договариваться о правилах шаблонов.
- SEO-проверки — часть Definition of Done для публичных страниц.

## Мини-шпаргалка

- Рендеринг, head, роутинг, семантика, CWV, разметка, тесты.
- Вопросы SEO-специалисту: индексация, canonical, шаблоны, фильтры, hreflang, KPI.
- Задача = шаблон + проблема + решение + проверка.
