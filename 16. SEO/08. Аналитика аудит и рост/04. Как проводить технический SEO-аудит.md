# Как проводить технический SEO-аудит

> [!NOTE]
> Технический аудит отвечает на вопрос, может ли поисковик **найти, скачать, отрендерить, понять и проиндексировать** важные страницы. Его проводят по **шаблонам** (главная, категория, товар, статья, фильтр, поиск, 404), а не по одной странице: статусы и редиректы, robots.txt и sitemap, canonical и дубли, индексируемость, отрендеренный HTML, мета-теги и заголовки, внутренние ссылки, structured data, производительность и мобильная версия. Источники — краулер сайта, Search Console и Вебмастер, `curl`, логи сервера. Результат аудита — **приоритизированный бэклог** с URL-примерами и критериями проверки, а не список «всего плохого».

## Вопрос

Как провести технический SEO-аудит сайта?

## Этапы

1. **Шаблоны** — выбрать типовые URL каждого шаблона.
2. **Краулинг** — Screaming Frog, Netpeak Spider, Sitebulb (с рендерингом JS и без).
3. **Статусы и редиректы** — 4xx, 5xx, soft 404, цепочки, петли.
4. **robots.txt и sitemap** — не закрыто ли нужное, нет ли мусора в sitemap.
5. **Canonical и дубли** — self-canonical, параметры, слеш, регистр, `http`/`www`.
6. **Индексируемость** — `noindex`, отчёт «Индексирование страниц».
7. **Рендеринг** — контент и ссылки в исходном HTML и после JS, URL Inspection.
8. **Мета и заголовки** — уникальность title/description, один `h1`.
9. **Внутренние ссылки** — сироты, глубина, ссылки на редиректы.
10. **Structured data** — ошибки, соответствие контенту.
11. **Производительность и мобильная версия** — CWV по шаблонам.
12. **Международность** — hreflang, если есть языковые версии.
13. **Бэклог** — приоритеты, владельцы, проверка.

## Быстрые проверки разработчика

```bash
curl -sI https://example.com/page | head -1                         # статус
curl -sIL https://example.com/old-page | grep -iE "^HTTP|^location" # цепочка редиректов
curl -s https://example.com/robots.txt                              # правила обхода
curl -s https://example.com/page | grep -iE "<title>|canonical|robots|<h1"  # что в исходном HTML
curl -sI -A "Googlebot" https://example.com/page | head -1          # не блокирует ли защита ботов
```

## Какие шаблоны брать

- Главная, категории, подкатегории.
- Карточки товаров (в наличии, нет в наличии, удалённый).
- Статьи и хабы.
- Фильтры (полезные и мусорные), сортировки, пагинация.
- Внутренний поиск.
- 404 и несуществующие сущности.
- Личный кабинет и корзина — убедиться, что закрыты.

## Приоритеты

| Приоритет | Пример |
| --- | --- |
| Critical | Важные разделы под `noindex` или `Disallow`, сайт отдаёт 5xx роботу |
| High | Soft 404 на тысячах товаров, контент только после JS, canonical на главную |
| Medium | Дубли title/description, цепочки редиректов, плохой LCP шаблона |
| Low | Предупреждения structured data, отдельные битые ссылки |

## Формат задачи

```text
Проблема:   карточки удалённых товаров отдают 200 с текстом «Товар не найден» (soft 404).
Примеры:    /products/old-1, /products/old-2 (ещё 2 340 URL в выгрузке).
Влияние:    мусор в индексе, расход crawl budget, «Ложные 404» в Search Console.
Решение:    404 для удалённых без замены, 301 на преемника, если он есть.
Проверка:   curl -sI → 404/301; отчёт «Индексирование» через 2–4 недели.
Владелец:   frontend, шаблон product page.
```

## Частые ошибки

- Проверять только главную.
- Отчёт на 200 пунктов без приоритетов.
- Не проверять отрендеренный HTML.
- Не повторять краулинг после исправлений.

## Что важно помнить

- Сначала доступность и индексация, затем всё остальное.
- Каждая проблема — с примерами URL, влиянием и способом проверки.
- Повторный аудит после исправлений обязателен.

## Мини-шпаргалка

- Шаблоны → краулер → статусы → robots/sitemap → canonical → индекс → рендер → мета → ссылки → structured data → CWV.
- `curl` для быстрых проверок.
- Critical / High / Medium / Low.
- Задача = проблема + примеры + влияние + решение + проверка.
