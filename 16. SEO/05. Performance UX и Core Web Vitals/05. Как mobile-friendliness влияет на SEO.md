# Как mobile-friendliness влияет на SEO

> [!NOTE]
> Google использует **mobile-first indexing**: страницы обходит и индексирует преимущественно мобильный Googlebot, поэтому именно **мобильная версия** определяет, какой контент, ссылки, structured data и мета-теги попадут в индекс. Если на мобильных скрыт текст, отзывы или навигация, для поиска их нет. Удобство на телефоне — viewport, читаемый текст, крупные области нажатия, отсутствие горизонтального скролла и навязчивых интерстициалов — часть page experience и сильно влияет на поведение и конверсию. Mobile-Friendly Test Google отключил в 2023 году; проверяют через Lighthouse, DevTools и URL Inspection.

## Вопрос

Как мобильная версия сайта влияет на SEO?

## Mobile-first indexing

```text
Googlebot Smartphone → мобильная версия страницы → индекс
```

Следствия:

- контент, ссылки и structured data должны быть **одинаковыми** на мобильных и десктопе;
- мета-теги (title, description, robots, canonical) — одинаковые;
- изображения на мобильных — с `alt` и доступны роботу;
- ленивая загрузка не должна требовать действий пользователя (свайпа, клика).

## Что проверить

- `<meta name="viewport" content="width=device-width, initial-scale=1">`.
- Текст читается без зума (базовый размер от 16 px).
- Области нажатия ≥ 48×48 CSS px с отступами.
- Нет горизонтального скролла.
- Навигация работает без hover.
- Формы: правильные `type` и `inputmode`, `autocomplete`.
- Модальные окна и баннеры не закрывают контент.
- Таблицы адаптированы или прокручиваются в контейнере.

## Интерстициалы

Google понижает страницы, где при переходе из поиска контент сразу закрывает навязчивое окно (подписка, реклама на весь экран). Допустимы: уведомления о cookies и возрастные ограничения, требуемые законом, и небольшие баннеры, не мешающие чтению.

## Адаптивность против отдельной мобильной версии

| Подход | Для SEO |
| --- | --- |
| Адаптивная вёрстка (один URL, CSS media queries) | Рекомендуется: один контент, один URL |
| Динамическая выдача по User-Agent | Нужен `Vary: User-Agent`, риск расхождения контента |
| Отдельный `m.example.com` | Устаревший подход: нужны `rel="alternate"`/canonical между версиями, легко ошибиться |

## Частые ошибки

- Скрывать на мобильных SEO-важный текст, отзывы, FAQ «для экономии места».
- Урезанная навигация на мобильных — роботу не хватает ссылок.
- Мелкие ссылки, расположенные вплотную.
- Тяжёлые изображения для десктопа на мобильных.
- Проверять только эмуляцию в DevTools, не на реальных устройствах и медленной сети.

## Что важно помнить

- Для поиска «главная» версия сайта — мобильная.
- Контент и мета-теги мобильной и десктопной версий должны совпадать.
- Core Web Vitals на мобильных обычно хуже — их оптимизируют в первую очередь.

## Мини-шпаргалка

- Mobile-first indexing.
- Viewport, 16 px, области нажатия 48 px.
- Одинаковый контент на всех устройствах.
- Без навязчивых интерстициалов.
- Адаптивная вёрстка, один URL.
