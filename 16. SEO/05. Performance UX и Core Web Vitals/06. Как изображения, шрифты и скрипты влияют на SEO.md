# Как изображения, шрифты и скрипты влияют на SEO

> [!NOTE]
> Три главных источника проблем со скоростью. **Изображения** чаще всего определяют LCP и вес страницы и вызывают CLS без размеров. **Шрифты** задерживают отображение текста и сдвигают макет при подмене. **JavaScript** (свой и сторонний) блокирует основной поток — ухудшает INP и TBT — и задерживает рендер, а при клиентском рендеринге откладывает появление контента для поисковика. Оптимизация: правильные форматы и размеры изображений с приоритетом для LCP, self-hosting шрифтов с `font-display` и fallback-метриками, минимум JS, code splitting, `defer`, отложенная загрузка сторонних скриптов.

## Вопрос

Как изображения, шрифты и скрипты влияют на производительность и SEO?

## Изображения

| Влияние | Решение |
| --- | --- |
| LCP | LCP-изображение в HTML, `fetchpriority="high"`, без lazy, AVIF/WebP |
| CLS | `width`/`height` или `aspect-ratio` |
| Вес страницы | `srcset`/`sizes`, сжатие, CDN изображений |
| Лишняя загрузка | `loading="lazy"` для всего ниже первого экрана |

Подробнее — в [уроке про изображения](<../03. On-page SEO и контент/08. Как оптимизировать изображения для SEO.md>).

## Шрифты

```html
<link rel="preload" href="/fonts/inter-var.woff2" as="font" type="font/woff2" crossorigin>
```

```css
@font-face {
  font-family: "Inter";
  src: url("/fonts/inter-var.woff2") format("woff2");
  font-weight: 100 900;
  font-display: swap;
  unicode-range: U+0000-00FF, U+0400-04FF; /* латиница и кириллица */
}
```

| Значение `font-display` | Поведение |
| --- | --- |
| `swap` | Текст сразу системным шрифтом, затем подмена — риск CLS |
| `optional` | Если шрифт не успел за ~100 мс — остаётся системный, без сдвига |
| `block` | Невидимый текст до загрузки — плохо для LCP |

Практики: woff2, вариативный шрифт вместо нескольких начертаний, subsets, self-hosting (без сторонних доменов), fallback с подогнанными метриками.

## Скрипты

```html
<script src="/app.js" defer></script>                 <!-- после парсинга, по порядку -->
<script src="/widget.js" async></script>              <!-- как загрузится, без порядка -->
<script type="module" src="/main.js"></script>        <!-- модули ведут себя как defer -->
```

| Проблема | Решение |
| --- | --- |
| Большой бандл | Code splitting, динамический `import()`, удаление лишних зависимостей |
| Тяжёлая гидрация | SSR с частичной/отложенной гидрацией, Server Components |
| Синхронные скрипты в `<head>` | `defer`/`async` |
| Аналитика, чаты, A/B-тесты | Загрузка после взаимодействия или по согласию, Partytown, фасады |
| Полифиллы для всех | Современный таргет сборки |

## Сторонние скрипты

Каждый подключённый тег-менеджер, пиксель, виджет чата — это чужой код в вашем основном потоке. Ведите реестр сторонних скриптов с владельцем и целью, измеряйте их вклад (Lighthouse → «Сторонний код») и удаляйте неиспользуемые.

## Частые ошибки

- Шрифты с Google Fonts через `@import` в CSS — цепочка запросов.
- Пять начертаний шрифта, из которых используются два.
- Все скрипты в `<head>` без `defer`.
- Тег-менеджер с десятками забытых тегов.
- Ленивая загрузка LCP-изображения.

## Что важно помнить

- Изображения — LCP и CLS, шрифты — LCP и CLS, скрипты — INP и LCP.
- Сторонний JS — главная неконтролируемая часть производительности.
- Оптимизируют по данным: сначала найти виновника в PSI и DevTools.

## Мини-шпаргалка

- Изображения: размеры, форматы, приоритет LCP, lazy остальным.
- Шрифты: woff2, self-host, preload, `font-display`, subsets.
- Скрипты: `defer`, code splitting, меньше JS.
- Сторонние: позже, по согласию, фасады.
