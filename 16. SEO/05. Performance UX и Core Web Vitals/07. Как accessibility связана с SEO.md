# Как accessibility связана с SEO

> [!NOTE]
> Доступность (a11y) и SEO — разные дисциплины, но у них общая основа: **понятная машине структура страницы**. Скринридер и поисковый робот одинаково полагаются на семантический HTML, иерархию заголовков, `alt` у изображений, текст ссылок, подписи полей форм, текстовые альтернативы для медиа. Доступность сама по себе не является прямым фактором ранжирования, но плохая доступность почти всегда совпадает со слабой структурой и плохим UX, а исправления для a11y часто улучшают и индексацию, и сниппеты, и поведенческие сигналы.

## Вопрос

Как доступность связана с SEO?

## Где они пересекаются

| Практика | Для доступности | Для SEO |
| --- | --- | --- |
| Семантический HTML (`main`, `nav`, `article`) | Навигация по областям | Выделение основного контента |
| Иерархия заголовков | Навигация скринридера по заголовкам | Понимание структуры и подтем |
| `alt` у изображений | Описание для незрячих | Понимание изображения, поиск по картинкам |
| Описательный текст ссылок | Понятность ссылки вне контекста | Анкорный текст |
| `<a href>` и `<button>` | Клавиатура и скринридер | Обнаружение ссылок роботом |
| Субтитры и транскрипты | Глухие и слабослышащие | Текстовый контент видео |
| `lang` у `<html>` | Правильное произношение | Определение языка |
| Читаемость, контраст | Слабовидящие | Поведение пользователей |

## Пример

```html
✗ <div class="link" onclick="goToProduct()">Подробнее</div>

✓ <a href="/products/backpack">Рюкзак для ноутбука 16″</a>
```

Ссылка доступна с клавиатуры, понятна скринридеру, видна поисковику и передаёт анкор.

## Чего доступность не гарантирует

Идеальная доступность не поднимет нерелевантную страницу. Но доступный сайт обычно лучше структурирован, быстрее понятен пользователям и реже теряет их.

## Как проверять

- Lighthouse → Accessibility (базовые автоматические проверки).
- axe DevTools — более полный аудит.
- Навигация только с клавиатуры: `Tab`, `Shift+Tab`, `Enter`, видимый фокус.
- Скринридер: NVDA, VoiceOver.
- Структура заголовков и ориентиров (DevTools → Accessibility tree).
- Контраст текста (WCAG AA: 4,5:1 для основного текста).

## Частые ошибки

- Кнопки и ссылки из `div`.
- Изображения без `alt` или с `alt="image"`.
- Ссылки «здесь», «подробнее».
- Поля форм без `<label>`.
- Пропуск уровней заголовков, `h1` в логотипе.
- Убранная обводка фокуса без замены.

## Что важно помнить

- Общая основа a11y и SEO — семантический, понятный машине HTML.
- Исправления доступности часто бесплатно улучшают SEO.
- Автоматические проверки ловят около трети проблем — нужна ручная проверка.

## Мини-шпаргалка

- Семантика, заголовки, `alt`, текст ссылок.
- `<a href>` и `<button>`, а не `div`.
- `lang`, контраст, фокус.
- Lighthouse + axe + клавиатура + скринридер.
