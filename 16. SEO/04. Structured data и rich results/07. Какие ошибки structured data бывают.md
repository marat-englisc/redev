# Какие ошибки structured data бывают

> [!NOTE]
> Ошибки structured data бывают **техническими** (невалидный JSON, неверный тип, нет обязательных полей, неправильный формат дат и цен, относительные URL, дубли и противоречия) и **смысловыми** — самыми опасными: разметка описывает не то, что видит пользователь (Product на категории, отзывы, которых нет, цена, отличающаяся от интерфейса, скрытый FAQ). Технические ошибки лишают rich results, смысловые могут привести к **ручным мерам** против всего сайта. Поскольку разметку генерирует шаблон, одна ошибка тиражируется на тысячи страниц.

## Вопрос

Какие ошибки structured data встречаются чаще всего и как их исправлять?

## Технические

| Ошибка | Пример | Исправление |
| --- | --- | --- |
| Невалидный JSON | Висячая запятая, кавычки | Генерировать через `JSON.stringify` |
| Неверный тип | `"@type": "Products"` | Сверка со schema.org |
| Нет обязательных полей | `Product` без `name` | Заполнить из данных |
| Формат даты | `"20.07.2026"` | ISO 8601 |
| Формат цены | `"9 990 ₽"` | `"9990"` + `priceCurrency` |
| Относительный URL | `"/logo.png"` | Абсолютный URL |
| Дубли | CMS и фреймворк выводят по Organization с разными данными | Один источник разметки |
| Устаревшая разметка в SPA | После перехода осталась разметка прошлой страницы | Управлять через head-менеджер |

## Смысловые

- `Product` на странице категории с десятками товаров (для списков — `ItemList` или без разметки).
- Рейтинг и отзывы, которых нет на странице.
- Цена или наличие в разметке не совпадают с интерфейсом.
- FAQ размечен, но вопросы скрыты или их нет.
- Автор указан в разметке, но не на странице.
- Хлебные крошки в разметке не совпадают с навигацией.
- Отзывы компании о себе как «рейтинг организации».
- Разметка «на всякий случай» для типов, к которым страница не относится.

## Пример

```json
{
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "Ноутбуки Apple"
}
```

Если это категория со списком ноутбуков, `Product` неверен: это не конкретный товар, у него нет единой цены и рейтинга.

## Как исправлять

1. Определить тип страницы (товар, категория, статья, организация).
2. Выбрать подходящий тип Schema.org и проверить требования Google к rich result.
3. Генерировать разметку из тех же данных, что и UI.
4. Сравнить разметку с видимым HTML.
5. Проверить Rich Results Test и валидатором Schema.org.
6. После деплоя отследить отчёты Search Console и запросить проверку исправления.

## Ручные меры за structured data

Если Google считает разметку манипулятивной, в Search Console появляется уведомление «Спам в структурированных данных», и rich results пропадают для сайта. После исправления отправляют запрос на пересмотр с описанием изменений.

## Частые ошибки в процессе

- Добавлять разметку вручную в шаблон, не связывая с данными.
- Не тестировать шаблоны — ошибка замечается через недели.
- Исправлять предупреждения выдуманными данными.

## Что важно помнить

- Валидный JSON не означает правильную разметку.
- Главное правило — соответствие видимому контенту.
- Ошибка шаблона масштабируется на весь сайт.

## Мини-шпаргалка

- Технические: JSON, тип, поля, форматы, URL, дубли.
- Смысловые: не тот тип, невидимые данные, расхождения с UI.
- Генерировать из данных, тестировать шаблоны.
- Spam в structured data → ручные меры.
