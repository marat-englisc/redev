# Как валидировать structured data

> [!NOTE]
> Structured data проверяют на трёх уровнях. **Синтаксис и словарь** — Schema Markup Validator (validator.schema.org): JSON корректен, типы и свойства существуют. **Требования поисковика** — Rich Results Test (Google) и валидатор микроразметки в Яндекс Вебмастере: заполнены ли обязательные поля конкретного rich result. **Состояние на сайте** — отчёты «Улучшения» в Search Console после индексации. Во frontend-приложениях проверяют **итоговый HTML по URL**, а не исходник компонента, и добавляют автотесты на шаблоны страниц.

## Вопрос

Как проверить structured data до и после релиза?

## Инструменты

| Инструмент | Что проверяет |
| --- | --- |
| [Rich Results Test](https://search.google.com/test/rich-results) | Пригодность для rich results Google, рендерит страницу по URL или код |
| [Schema Markup Validator](https://validator.schema.org/) | Соответствие словарю Schema.org для любых типов |
| Яндекс Вебмастер → «Микроразметка» | Валидность для Яндекса |
| Search Console → «Улучшения» | Ошибки и предупреждения на проиндексированных страницах |
| URL Inspection | Что Google увидел в отрендеренной странице |

## Ручной чек-лист

- JSON валиден, нет висячих запятых.
- `@context` и `@type` указаны.
- Обязательные свойства rich result заполнены.
- URL абсолютные, даты в ISO 8601.
- Данные совпадают с видимыми на странице.
- Нет противоречивых дублей одной сущности (от CMS и от фреймворка).

## Проверка во frontend-приложении

```bash
# SSR/SSG: разметка должна быть в ответе сервера
curl -s https://example.com/products/keychron-k2 | grep -o '<script type="application/ld+json">[^<]*'
```

Автотест на шаблон:

```ts
// Playwright
test("товар содержит Product JSON-LD", async ({ page }) => {
  await page.goto("/products/keychron-k2");
  const raw = await page.locator('script[type="application/ld+json"]').allTextContents();
  const product = raw.map((s) => JSON.parse(s)).find((d) => d["@type"] === "Product");

  expect(product).toBeDefined();
  expect(product.offers.priceCurrency).toBe("RUB");
  expect(Number(product.offers.price)).toBeGreaterThan(0);
});
```

Такой тест ловит регрессии шаблона до того, как ошибки появятся на тысячах страниц.

## Ошибки и предупреждения

- **Ошибка** — отсутствует обязательное свойство: rich result невозможен.
- **Предупреждение** — нет рекомендуемого свойства: rich result возможен, но беднее.

Предупреждения исправляют, если данные действительно есть и их можно честно заполнить; добавлять выдуманные значения ради «зелёного» отчёта нельзя.

## После релиза

- Search Console обновляет отчёты по мере переобхода — от нескольких дней до недель.
- После исправления шаблона можно нажать «Проверить исправление» в отчёте.
- Следить за ростом ошибок после деплоя — признак сломанного шаблона.

## Частые ошибки

- Проверять только код компонента, а не HTML по URL.
- Игнорировать отчёты Search Console после релиза.
- Заполнять предупреждения фиктивными значениями.
- Не тестировать шаблоны автоматически.

## Что важно помнить

- Валидатор Schema.org и Rich Results Test проверяют разное — полезны оба.
- Structured data — часть шаблона и тестируется как код.
- Итоговый HTML важнее исходника.

## Мини-шпаргалка

- Rich Results Test — требования Google.
- validator.schema.org — словарь.
- Search Console «Улучшения» — состояние сайта.
- `curl` + автотест на шаблоны.
