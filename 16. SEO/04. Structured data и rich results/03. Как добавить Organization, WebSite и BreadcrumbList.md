# Как добавить Organization, WebSite и BreadcrumbList

> [!NOTE]
> Три базовых типа почти для любого сайта. **`Organization`** описывает компанию: название, логотип, URL, контакты, профили в соцсетях (`sameAs`) — помогает поисковику связать сайт с брендом и показывать логотип. **`WebSite`** описывает сайт и его название — Google использует его для отображения **названия сайта** в выдаче. **`BreadcrumbList`** описывает путь страницы в иерархии и может заменить URL в сниппете хлебными крошками. Организацию и сайт обычно описывают на главной (или во всём графе), крошки — на каждой вложенной странице, и они должны совпадать с видимой навигацией.

## Вопрос

Как добавить разметку Organization, WebSite и BreadcrumbList?

## Organization

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Organization",
  "@id": "https://example.com/#organization",
  "name": "Frontend Academy",
  "url": "https://example.com",
  "logo": "https://example.com/logo-512.png",
  "sameAs": [
    "https://github.com/frontend-academy",
    "https://t.me/frontend_academy"
  ],
  "contactPoint": {
    "@type": "ContactPoint",
    "telephone": "+7-800-000-00-00",
    "contactType": "customer support",
    "availableLanguage": ["ru"]
  }
}
</script>
```

Для офлайн-бизнеса используют подтип `LocalBusiness` (или точнее: `Store`, `Restaurant`, `MedicalClinic`) с адресом и часами работы.

## WebSite

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "WebSite",
  "@id": "https://example.com/#website",
  "name": "Frontend Academy",
  "alternateName": ["FA", "frontend-academy.ru"],
  "url": "https://example.com",
  "publisher": { "@id": "https://example.com/#organization" }
}
</script>
```

`name` и `alternateName` помогают Google выбрать название сайта в выдаче. Блок «поле поиска по сайту» (`SearchAction`) Google с конца 2024 года больше не показывает — добавлять его ради этой функции бессмысленно.

## BreadcrumbList

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "BreadcrumbList",
  "itemListElement": [
    { "@type": "ListItem", "position": 1, "name": "Главная", "item": "https://example.com/" },
    { "@type": "ListItem", "position": 2, "name": "SEO", "item": "https://example.com/seo" },
    { "@type": "ListItem", "position": 3, "name": "Как работает sitemap.xml" }
  ]
}
</script>
```

У последнего элемента (текущей страницы) `item` можно не указывать.

```html
<nav aria-label="Хлебные крошки">
  <ol>
    <li><a href="/">Главная</a></li>
    <li><a href="/seo">SEO</a></li>
    <li aria-current="page">Как работает sitemap.xml</li>
  </ol>
</nav>
```

Видимые крошки и разметка строятся из одних данных.

## Правила

- Крошки совпадают с видимой навигацией и отражают реальную иерархию.
- URL абсолютные и канонические.
- Логотип — доступное роботу изображение с достаточным разрешением (от 112×112 px).
- Не создавать разные `Organization` с противоречивыми данными на разных страницах.

## Частые ошибки

- Крошки в разметке есть, а на странице — нет.
- Позиции не по порядку или пропуски.
- `SearchAction` «для сниппета», которого уже нет.
- Логотип по относительному URL.

## Что важно помнить

- `Organization` и `WebSite` описывают сайт, `BreadcrumbList` — место страницы в нём.
- `@id` связывает сущности между собой и между страницами.
- Крошки улучшают и сниппет, и навигацию пользователя.

## Мини-шпаргалка

- `Organization`: name, url, logo, sameAs.
- `WebSite`: name, alternateName, url.
- `BreadcrumbList`: ListItem с position, name, item.
- Совпадение с видимым UI.
