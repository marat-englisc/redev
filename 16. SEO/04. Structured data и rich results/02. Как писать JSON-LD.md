# Как писать JSON-LD

> [!NOTE]
> **JSON-LD** — structured data в виде JSON внутри `<script type="application/ld+json">`. Каждый объект содержит `@context` (`https://schema.org`) и `@type`, вложенные сущности описываются объектами со своим `@type`, а связи между сущностями на странице — через `@id` и `@graph`. Во frontend-приложениях JSON-LD **генерируют из данных** через `JSON.stringify`, а не склеивают строки; отдают в серверном HTML и обновляют при клиентской навигации. Даты — ISO 8601, URL — абсолютные.

## Вопрос

Как правильно писать и генерировать JSON-LD?

## Базовая структура

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "Как работает robots.txt",
  "datePublished": "2026-07-20T10:00:00+03:00",
  "dateModified": "2026-09-02T12:00:00+03:00",
  "image": ["https://example.com/images/robots-txt.png"],
  "author": {
    "@type": "Person",
    "name": "Мария Иванова",
    "url": "https://example.com/authors/maria-ivanova"
  },
  "publisher": {
    "@type": "Organization",
    "name": "Frontend Academy",
    "logo": { "@type": "ImageObject", "url": "https://example.com/logo.png" }
  }
}
</script>
```

| Поле | Смысл |
| --- | --- |
| `@context` | Словарь, почти всегда `https://schema.org` |
| `@type` | Тип сущности (можно массив: `["Product", "Car"]`) |
| `@id` | Уникальный идентификатор сущности для ссылок между объектами |
| `@graph` | Массив связанных сущностей в одном блоке |

## Граф связанных сущностей

```json
{
  "@context": "https://schema.org",
  "@graph": [
    { "@type": "Organization", "@id": "https://example.com/#org", "name": "Frontend Academy" },
    { "@type": "WebSite", "@id": "https://example.com/#website", "url": "https://example.com", "publisher": { "@id": "https://example.com/#org" } },
    { "@type": "Article", "headline": "…", "publisher": { "@id": "https://example.com/#org" } }
  ]
}
```

`@id` позволяет не дублировать организацию в каждом объекте и явно связать сущности.

## Генерация в коде

```ts
const schema = {
  "@context": "https://schema.org",
  "@type": "BreadcrumbList",
  itemListElement: breadcrumbs.map((item, index) => ({
    "@type": "ListItem",
    position: index + 1,
    name: item.name,
    item: new URL(item.path, SITE_URL).toString(),
  })),
};

const json = JSON.stringify(schema).replace(/</g, "\\u003c");
```

`replace(/</g, "\\u003c")` защищает от XSS: строка `</script>` из пользовательских данных не закроет тег.

```tsx
// Next.js (App Router)
<script type="application/ld+json" dangerouslySetInnerHTML={{ __html: json }} />
```

```ts
// Nuxt
useHead({ script: [{ type: "application/ld+json", innerHTML: json }] });
```

## Где размещать

В `<head>` или в `<body>` — оба варианта поддерживаются. Главное — в серверном HTML. В SPA при переходе между страницами старая разметка должна удаляться, а новая — добавляться (библиотеки управления head делают это сами).

## Форматы значений

| Значение | Формат |
| --- | --- |
| Дата и время | ISO 8601: `2026-07-20T10:00:00+03:00` |
| Длительность | ISO 8601: `PT12M30S` |
| Цена | Строка или число без символа валюты: `"9990"` |
| Валюта | ISO 4217: `RUB`, `USD` |
| Наличие | URL перечисления: `https://schema.org/InStock` |
| URL | Абсолютный |

## Частые ошибки

- Склеивание JSON строками — невалидный JSON и XSS.
- Относительные URL.
- Дата в формате `20.07.2026`.
- Цена с символом: `"9 990 ₽"`.
- Разметка «застревает» от предыдущей страницы в SPA.

## Что важно помнить

- JSON-LD строят из объекта и сериализуют, экранируя `<`.
- `@id` и `@graph` — способ описать связанные сущности без дублирования.
- Результат проверяют в Rich Results Test по URL, а не по коду компонента.

## Мини-шпаргалка

- `<script type="application/ld+json">`.
- `@context`, `@type`, `@id`, `@graph`.
- ISO 8601, ISO 4217, абсолютные URL.
- `JSON.stringify(...).replace(/</g, "\\u003c")`.
- В серверном HTML, обновлять при навигации.
