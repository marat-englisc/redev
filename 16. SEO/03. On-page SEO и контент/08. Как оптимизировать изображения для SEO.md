# Как оптимизировать изображения для SEO

> [!NOTE]
> Оптимизация изображений решает две задачи. **Понимание**: описательный `alt`, осмысленное имя файла, подпись и текст рядом, structured data — чтобы картинка находилась в поиске по изображениям и помогала понять страницу. **Скорость**: правильный размер через `srcset`/`sizes`, современные форматы (AVIF, WebP), сжатие, `width`/`height` против сдвига макета, `loading="lazy"` для изображений ниже первого экрана и, наоборот, приоритетная загрузка (`fetchpriority="high"`, preload) для LCP-изображения. Изображение должно быть в HTML как `<img>`, а не только CSS-фоном, если оно важно для поиска.

## Вопрос

Как оптимизировать изображения для SEO и скорости?

## Понимание изображения

```html
<figure>
  <img
    src="/images/lcp-waterfall.png"
    alt="Waterfall загрузки страницы, LCP-изображение загружается последним"
    width="960"
    height="540"
  >
  <figcaption>LCP задерживается из-за позднего обнаружения изображения</figcaption>
</figure>
```

- `alt` описывает смысл изображения в контексте страницы.
- Имя файла: `keychron-k2-black.webp`, а не `IMG_2048.jpg`.
- Текст рядом и подпись помогают понять, что изображено.
- Декоративные изображения — `alt=""` (скринридер их пропустит) или CSS.

```html
<img src="/decor-line.svg" alt="">
```

## Адаптивные размеры

```html
<img
  src="/images/product-800.webp"
  srcset="/images/product-400.webp 400w, /images/product-800.webp 800w, /images/product-1200.webp 1200w"
  sizes="(max-width: 600px) 100vw, 400px"
  alt="Чёрный рюкзак с отделением для ноутбука 16 дюймов"
  width="800"
  height="600"
  loading="lazy"
  decoding="async"
>
```

`sizes` говорит браузеру, какую ширину картинка займёт в макете, и он выбирает подходящий файл из `srcset`.

## Форматы

```html
<picture>
  <source srcset="/hero.avif" type="image/avif">
  <source srcset="/hero.webp" type="image/webp">
  <img src="/hero.jpg" alt="…" width="1200" height="630" fetchpriority="high">
</picture>
```

| Формат | Когда |
| --- | --- |
| AVIF | Лучшее сжатие фото, поддерживается современными браузерами |
| WebP | Хорошее сжатие, универсальная поддержка |
| JPEG | Fallback для фото |
| PNG | Прозрачность и графика с чёткими краями, если WebP не подходит |
| SVG | Иконки, логотипы, простая векторная графика |

## Изображения и Core Web Vitals

| Метрика | Влияние | Что делать |
| --- | --- | --- |
| LCP | Главное изображение часто и есть LCP-элемент | `fetchpriority="high"`, preload, без lazy, сжатие, CDN |
| CLS | Без размеров макет «прыгает» | `width`/`height` или `aspect-ratio` |
| Вес страницы | Медленная загрузка на мобильных | Правильный размер, форматы, lazy для остального |

## Поиск по изображениям

- Изображение должно быть в `<img src>` — CSS-фоны поисковик индексирует хуже.
- Не закрывать изображения в robots.txt.
- Для важных изображений — `image` в structured data (Product, Article) и sitemap изображений.
- `max-image-preview:large` в robots-meta разрешает крупные превью в выдаче и Discover.

## Частые ошибки

- `alt`, набитый ключами, или `alt="image"`.
- `loading="lazy"` у LCP-изображения.
- Нет `width`/`height`.
- Отдавать изображение 4000 px для превью 300 px.
- Ленивая загрузка через JS-библиотеку, которая подставляет `src` только при скролле — робот может не увидеть картинку (используйте нативный `loading="lazy"`).

## Что важно помнить

- `alt` — для смысла и доступности, а не для ключевых слов.
- LCP-изображение загружают как можно раньше, остальные — лениво.
- Фреймворки берут работу на себя: `next/image`, `<NuxtImg>`.

## Мини-шпаргалка

- `alt`, имя файла, подпись.
- `srcset` + `sizes`, AVIF/WebP.
- `width`/`height` всегда.
- LCP: `fetchpriority="high"`, без lazy.
- Остальное: `loading="lazy"`.
