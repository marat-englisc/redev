# Как работает HMR

> [!NOTE]
> **HMR (Hot Module Replacement)** — замена измененного модуля в работающем приложении без полной перезагрузки страницы. Dev-сервер следит за файлами, по **WebSocket** сообщает браузеру, какой модуль изменился, браузер загружает новую версию, а модуль или его родитель **принимает** обновление (`import.meta.hot.accept`). В React это делает **React Fast Refresh**: компоненты перерисовываются с сохранением состояния (`useState`), а при ошибке или изменении не-компонентного кода — состояние сбрасывается или страница перезагружается.

## Вопрос

Как работает HMR? Чем он отличается от live reload и почему иногда состояние React сбрасывается после изменения файла?

## Live reload и HMR

| | Live reload | HMR |
| --- | --- | --- |
| Что происходит | полная перезагрузка страницы | замена одного модуля |
| Состояние приложения | теряется | обычно сохраняется |
| Скорость | секунды | миллисекунды |

## Механизм

```text
1. Вы сохранили Button.tsx
2. Dev-сервер (Vite/webpack) видит изменение, трансформирует файл
3. По WebSocket: { type: "update", path: "/src/Button.tsx", timestamp }
4. Браузер: import("/src/Button.tsx?t=1729...")   — новая версия модуля
5. Ищется граница HMR — модуль, который «принимает» обновление
6. Fast Refresh перерисовывает затронутые компоненты, сохраняя их state
7. Если границы нет — обновление поднимается к корню → полная перезагрузка
```

## HMR API (Vite)

```typescript
// обычно пишут плагины, а не прикладной код
if (import.meta.hot) {
  import.meta.hot.accept((newModule) => {
    // применить новую версию модуля
  });
  import.meta.hot.dispose(() => {
    clearInterval(timerId);          // очистить побочные эффекты старой версии
  });
}
```

В webpack — `module.hot.accept()`.

## Когда React Fast Refresh сбрасывает состояние

- файл экспортирует не только компоненты (константы, утилиты вместе с компонентом) — обновление поднимется выше или будет полная перезагрузка;
- компонент объявлен анонимно или не с заглавной буквы;
- классовые компоненты — всегда перемонтируются;
- изменился порядок или количество хуков;
- ошибка в коде — после исправления компонент перемонтируется.

Правило: **один файл — компоненты** (или явно разделять компоненты и утилиты). Линтер `eslint-plugin-react-refresh` подсказывает нарушения.

## Типичные проблемы

| Проблема | Причина | Решение |
| --- | --- | --- |
| HMR не работает в Docker/WSL | файловые события не доходят | `server.watch.usePolling: true` |
| Постоянная полная перезагрузка | модуль без границы HMR, смешанные экспорты | разделить файлы |
| Дублируются слушатели и таймеры | побочные эффекты на уровне модуля | `import.meta.hot.dispose`, эффекты в компонентах |
| WebSocket не подключается за прокси | прокси не пропускает upgrade | `server.hmr.clientPort`, настройка прокси |

## Что важно помнить

- HMR существует только в режиме разработки.
- Состояние сохраняется для функциональных компонентов при изменении только их кода.
- Глобальные side effects в модулях (подписки, интервалы) при HMR дублируются — держите их в эффектах с очисткой.
- Strict Mode и Fast Refresh вместе проверяют, что эффекты корректно очищаются.

## Мини-шпаргалка

HMR: сервер следит за файлами → WebSocket → браузер грузит новую версию модуля → граница `hot.accept` применяет → иначе полная перезагрузка. React Fast Refresh сохраняет state функциональных компонентов. Сброс — смешанные экспорты, классы, смена хуков, ошибки. `dispose` для очистки.
