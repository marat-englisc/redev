# Что такое полифилы, core-js и browserslist

> [!NOTE]
> **Полифил** — код, который добавляет в старый браузер отсутствующий API: `Array.prototype.at`, `Object.groupBy`, `structuredClone`. **core-js** — самая полная библиотека полифилов стандартной библиотеки JavaScript. **browserslist** — общий список целевых браузеров проекта (`"> 0.5%, last 2 versions, not dead"`), который читают Babel, SWC, Autoprefixer, Lightning CSS и другие инструменты, чтобы решить, какой синтаксис понижать, какие полифилы и вендорные префиксы добавлять.

## Вопрос

Что такое полифилы и чем они отличаются от транспиляции? Как работают core-js и browserslist и как не раздуть бандл полифилами?

## browserslist

```json
// package.json
{
  "browserslist": {
    "production": ["> 0.5%", "last 2 versions", "Firefox ESR", "not dead"],
    "development": ["last 1 chrome version", "last 1 firefox version", "last 1 safari version"]
  }
}
```

или файл `.browserslistrc`. Проверить, какие браузеры попадают в запрос:

```bash
npx browserslist "> 0.5%, last 2 versions, not dead"
```

Обновляйте базу данных использования браузеров: `npx update-browserslist-db@latest`.

## Кто использует browserslist

| Инструмент | Что делает по списку |
| --- | --- |
| `@babel/preset-env`, SWC | какие синтаксические трансформации нужны |
| core-js через Babel | какие полифилы добавить |
| Autoprefixer, Lightning CSS | какие вендорные префиксы CSS добавить |
| ESLint `eslint-plugin-compat` | предупреждение об API, которых нет в целевых браузерах |

Vite использует свое поле `build.target` (по умолчанию — современные браузеры с поддержкой ESM); для старых браузеров есть `@vitejs/plugin-legacy`.

## Полифилы через core-js

```json
// babel.config.json
{ "presets": [["@babel/preset-env", { "useBuiltIns": "usage", "corejs": "3.40" }]] }
```

| `useBuiltIns` | Поведение |
| --- | --- |
| `false` | полифилы не добавляются |
| `"entry"` | `import "core-js"` заменяется полифилами для всех API, которых нет у целевых браузеров |
| `"usage"` | в каждый файл добавляются только полифилы для реально используемых API |

## Синтаксис и API — повторим

```javascript
const last = items.at(-1);        // API → нужен полифил Array.prototype.at
const name = user?.name;          // синтаксис → нужна транспиляция
```

Полифил для `?.` невозможен — это синтаксис, его нужно переписать на этапе сборки.

## Feature detection вместо полифила

```javascript
if ("IntersectionObserver" in window) {
  lazyLoadWithObserver();
} else {
  loadAllImages();             // запасной вариант
}
```

Для браузерных API (не стандартной библиотеки JS) часто достаточно проверки возможностей и деградации функциональности.

## Что важно помнить

- Полифилы увеличивают бандл: узкий список браузеров = меньше кода и быстрее страница.
- `useBuiltIns: "usage"` обычно лучший выбор для приложений; библиотеки не должны глобально добавлять полифилы.
- Не все API можно полифилить полноценно (например, Proxy или некоторые CSS-возможности).
- Проверяйте поддержку на caniuse.com и Baseline-статус возможностей на MDN.
- Связанные темы: [Babel и SWC](<01. Что такое Babel и SWC.md>), [PostCSS и Autoprefixer](<04. Как обрабатывается CSS в сборке.md>).

## Мини-шпаргалка

Полифил — недостающий API в рантайме, транспиляция — новый синтаксис при сборке. core-js — полифилы JS, `useBuiltIns: "usage"`. browserslist — общий список браузеров для Babel, SWC, Autoprefixer, eslint-plugin-compat. Vite — `build.target`, legacy-плагин. Узкий список = меньше бандл.
