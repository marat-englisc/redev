# Как собрать и опубликовать npm-библиотеку

> [!NOTE]
> Библиотеку собирают иначе, чем приложение: нужен не один бандл для браузера, а **модули для других сборщиков** — ESM (и при необходимости CommonJS), **типы `.d.ts`**, корректное поле **`exports`** в `package.json`, внешние (`external`) зависимости вместо встроенных копий, `peerDependencies` для React и пометка **`sideEffects`** для tree shaking. Сборку обычно делают через **tsup**, **tsdown** или Vite в library mode, публикацию — через `npm publish` с provenance из CI.

## Вопрос

Как собрать и опубликовать npm-библиотеку компонентов или утилит? Какие поля `package.json` важны и почему React должен быть `peerDependency`?

## package.json библиотеки

```json
{
  "name": "@acme/ui",
  "version": "1.2.0",
  "type": "module",
  "files": ["dist"],
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.js",
      "require": "./dist/index.cjs"
    },
    "./styles.css": "./dist/styles.css"
  },
  "main": "./dist/index.cjs",
  "module": "./dist/index.js",
  "types": "./dist/index.d.ts",
  "sideEffects": ["*.css"],
  "peerDependencies": { "react": "^18.0.0 || ^19.0.0", "react-dom": "^18.0.0 || ^19.0.0" },
  "devDependencies": { "react": "^19.2.0", "react-dom": "^19.2.0", "tsup": "^8.0.0", "typescript": "^5.9.0" },
  "scripts": { "build": "tsup", "prepublishOnly": "npm run build" }
}
```

| Поле | Зачем |
| --- | --- |
| `exports` | публичные точки входа и условия `types` / `import` / `require`; `types` — первым |
| `files` | что попадет в пакет (без исходников тестов и конфигов) |
| `sideEffects` | разрешает tree shaking; CSS-импорты помечаются как побочные эффекты |
| `peerDependencies` | React ставит приложение — нет второй копии и ошибки «Invalid hook call» |
| `main` / `module` / `types` | для старых инструментов без поддержки `exports` |

## Сборка через tsup

```typescript
// tsup.config.ts
import { defineConfig } from "tsup";

export default defineConfig({
  entry: ["src/index.ts"],
  format: ["esm", "cjs"],
  dts: true,                 // .d.ts
  sourcemap: true,
  clean: true,
  treeshake: true,
  external: ["react", "react-dom"],
});
```

Для нового пакета, который нужен только современным потребителям, достаточно одного формата ESM — так проще и нет dual package hazard.

## Проверка перед публикацией

```bash
npm pack --dry-run                   # какие файлы попадут в пакет
npx publint                          # ошибки в package.json и exports
npx @arethetypeswrong/cli --pack .   # корректность типов для разных резолверов
```

## Публикация

```bash
npm login
npm version minor                    # 1.2.0 → 1.3.0 + git tag
npm publish --access public          # для scoped-пакетов
```

Из CI (GitHub Actions) с provenance — подтверждением, что пакет собран из конкретного коммита:

```yaml
- run: npm publish --provenance --access public
  env:
    NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
```

В монорепозитории версии и changelog удобно вести через Changesets.

## Что важно помнить

- Библиотека не должна встраивать React, а также крупные зависимости, которые есть у потребителя, — указывайте их в `external`/`peerDependencies`.
- `"use client"` в начале файлов компонентов нужен, чтобы библиотеку можно было использовать в Next.js App Router (бандлер должен сохранить директиву).
- Не публикуйте `src` и тесты — используйте `files`.
- Ломающие изменения — только в major-версии с описанием миграции.

## Мини-шпаргалка

Библиотека: ESM (+CJS при необходимости), `.d.ts`, `exports` с `types` первым, `files`, `sideEffects`, React в `peerDependencies` и `external`. Сборка: tsup/tsdown/Vite library mode. Проверка: `npm pack --dry-run`, publint, arethetypeswrong. Публикация: `npm version`, `npm publish --provenance` из CI.
