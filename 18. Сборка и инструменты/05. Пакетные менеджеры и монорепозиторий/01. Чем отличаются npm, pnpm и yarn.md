# Чем отличаются npm, pnpm и yarn

> [!NOTE]
> **npm**, **pnpm** и **yarn** устанавливают зависимости из реестра npm, ведут lockfile и запускают скрипты. Различаются они устройством `node_modules`, скоростью и строгостью. **npm** идет вместе с Node.js и создает плоский `node_modules`. **pnpm** хранит каждую версию пакета один раз в **глобальном content-addressable store** и связывает ее в проекты жесткими ссылками и симлинками — это экономит место, ускоряет установку и запрещает **фантомные зависимости**. **yarn** (Berry, v2+) предлагает режим **Plug'n'Play** без `node_modules`. Версию менеджера в проекте фиксируют полем `packageManager` и Corepack.

## Вопрос

Чем отличаются npm, pnpm и yarn? Что такое фантомные зависимости и почему pnpm их запрещает? Какой менеджер выбрать?

## Сравнение

| | npm | pnpm | yarn (Berry) |
| --- | --- | --- | --- |
| Установлен с Node.js | да | через Corepack / отдельно | через Corepack / отдельно |
| `node_modules` | плоский (hoisting) | симлинки на глобальный store | Plug'n'Play или `node-modules` linker |
| Место на диске | копия в каждом проекте | одна копия на машину | zip-архивы в кеше |
| Фантомные зависимости | разрешены | запрещены | запрещены в PnP |
| Workspaces | да | да, сильная поддержка | да |
| Lockfile | `package-lock.json` | `pnpm-lock.yaml` | `yarn.lock` |
| Строгий CI-режим | `npm ci` | `pnpm install --frozen-lockfile` | `yarn install --immutable` |

## Фантомные зависимости

```text
ваш package.json: { "dependencies": { "express": "..." } }
express зависит от debug

npm (плоский node_modules):
  node_modules/express
  node_modules/debug      ← поднят наверх
→ import "debug" в вашем коде работает, хотя debug не указан в package.json
```

Если express обновится и перестанет зависеть от `debug`, ваш код сломается. pnpm кладет в корень `node_modules` только прямые зависимости, поэтому такой импорт сразу дает ошибку.

## Как устроен node_modules в pnpm

```text
~/.pnpm-store/…/react@19.2.0          ← одна копия на машину
project/node_modules/
  react → .pnpm/react@19.2.0/node_modules/react     (симлинк)
  .pnpm/react@19.2.0/node_modules/react              (жесткая ссылка на store)
```

## Основные команды

| Действие | npm | pnpm | yarn |
| --- | --- | --- | --- |
| Установить всё | `npm install` | `pnpm install` | `yarn` |
| Добавить пакет | `npm i zod` | `pnpm add zod` | `yarn add zod` |
| Dev-зависимость | `npm i -D vitest` | `pnpm add -D vitest` | `yarn add -D vitest` |
| Удалить | `npm uninstall zod` | `pnpm remove zod` | `yarn remove zod` |
| Запустить скрипт | `npm run build` | `pnpm build` | `yarn build` |
| Выполнить бинарник | `npx vite` | `pnpm exec vite` / `pnpm dlx` | `yarn dlx` |
| Почему установлен пакет | `npm explain debug` | `pnpm why debug` | `yarn why debug` |
| Устаревшие пакеты | `npm outdated` | `pnpm outdated` | `yarn outdated` |

## Фиксация менеджера

```json
// package.json
{ "packageManager": "pnpm@10.18.0" }
```

```bash
corepack enable          # Node.js скачает и использует указанную версию
```

Так у всех разработчиков и в CI одинаковая версия менеджера.

## Что выбрать

- **npm** — по умолчанию, без дополнительной установки, подходит для большинства проектов;
- **pnpm** — монорепозитории, много проектов на машине, строгие зависимости, быстрый CI;
- **yarn** — если проект уже на нем; PnP требует поддержки инструментов.

## Что важно помнить

- Не смешивайте менеджеры в одном проекте: один lockfile, остальные — в `.gitignore` или удалить.
- В CI всегда устанавливайте строго по lockfile.
- Фантомные зависимости — частый вопрос на собеседовании: объясните hoisting и почему pnpm строже.
- Скрипты установки пакетов (`postinstall`) — вектор атак; pnpm 10 по умолчанию не запускает их у зависимостей без разрешения.

## Мини-шпаргалка

npm — плоский `node_modules`, идет с Node.js. pnpm — глобальный store + симлинки, экономия места, нет фантомных зависимостей, сильные workspaces. yarn Berry — Plug'n'Play. CI: `npm ci` / `pnpm install --frozen-lockfile` / `yarn install --immutable`. Версия — `packageManager` + Corepack. Один менеджер на проект.
