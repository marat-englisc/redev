# Что такое ESLint и как его настроить

> [!NOTE]
> **ESLint** — статический анализатор JavaScript и TypeScript: он находит ошибки и опасные паттерны **до запуска кода** (неиспользуемые переменные, нарушение правил хуков, забытый `await`, отсутствие зависимостей эффекта, проблемы доступности). Правила подключаются из плагинов (`typescript-eslint`, `eslint-plugin-react-hooks`, `jsx-a11y`, `import`), многие исправляются автоматически (`--fix`). С ESLint 9 по умолчанию используется **flat config** — файл `eslint.config.js` с массивом объектов конфигурации. Форматирование (отступы, кавычки) обычно отдают Prettier.

## Вопрос

Что такое ESLint и зачем он нужен? Как настроить ESLint для React и TypeScript в формате flat config и как он сочетается с Prettier?

## Flat config для React + TypeScript

```javascript
// eslint.config.js
import js from "@eslint/js";
import tseslint from "typescript-eslint";
import reactHooks from "eslint-plugin-react-hooks";
import reactRefresh from "eslint-plugin-react-refresh";
import jsxA11y from "eslint-plugin-jsx-a11y";
import prettier from "eslint-config-prettier";
import globals from "globals";

export default tseslint.config(
  { ignores: ["dist", "coverage", "*.config.js"] },
  js.configs.recommended,
  ...tseslint.configs.recommendedTypeChecked,
  {
    files: ["**/*.{ts,tsx}"],
    languageOptions: {
      globals: globals.browser,
      parserOptions: { projectService: true, tsconfigRootDir: import.meta.dirname },
    },
    plugins: {
      "react-hooks": reactHooks,
      "react-refresh": reactRefresh,
      "jsx-a11y": jsxA11y,
    },
    rules: {
      ...reactHooks.configs.recommended.rules,
      ...jsxA11y.configs.recommended.rules,
      "react-refresh/only-export-components": "warn",
      "@typescript-eslint/no-floating-promises": "error",
      "@typescript-eslint/no-unused-vars": ["error", { argsIgnorePattern: "^_" }],
      "no-console": ["warn", { allow: ["warn", "error"] }],
    },
  },
  prettier,                                  // отключает правила, конфликтующие с Prettier — последним
);
```

```json
// package.json
{ "scripts": { "lint": "eslint .", "lint:fix": "eslint . --fix" } }
```

## Как устроен flat config

| Часть | Назначение |
| --- | --- |
| массив объектов | применяются по порядку, последующие переопределяют предыдущие |
| `files` / `ignores` | к каким файлам относится объект |
| `languageOptions` | парсер, глобальные переменные, версия ECMAScript |
| `plugins` | объекты плагинов, подключенные напрямую через import |
| `rules` | `"off"` / `"warn"` / `"error"` + настройки |

Старый формат `.eslintrc` с `extends` строками и `env` устарел.

## Полезные правила и плагины

| Плагин / правило | Что ловит |
| --- | --- |
| `react-hooks/rules-of-hooks`, `exhaustive-deps` | хуки в условиях, недостающие зависимости эффектов |
| `@typescript-eslint/no-floating-promises` | Promise без `await` / `.catch` |
| `@typescript-eslint/no-explicit-any` | `any` |
| `jsx-a11y/*` | `img` без `alt`, клик на `div` без роли и клавиатуры |
| `import/no-cycle`, `import/order` | циклические зависимости, порядок импортов |
| `eslint-plugin-boundaries` | нарушение границ модулей (FSD, слои) |
| `@tanstack/eslint-plugin-query` | ошибки ключей запросов |
| `eslint-plugin-react-compiler` | код, несовместимый с React Compiler |

Type-aware правила (`recommendedTypeChecked`) используют информацию TypeScript и находят больше ошибок, но работают медленнее.

## Где запускать

- в редакторе (расширение ESLint) — подсветка сразу;
- в pre-commit через lint-staged — только измененные файлы;
- в CI — `eslint . --max-warnings=0` блокирует merge при нарушениях.

## Что важно помнить

- ESLint — про **ошибки и качество**, Prettier — про **форматирование**; конфликты отключает `eslint-config-prettier`.
- Не отключайте `exhaustive-deps` без причины — это основной источник багов с эффектами.
- `// eslint-disable-next-line rule -- причина` — точечно и с объяснением.
- Альтернативы: **Biome** (линтер и форматтер на Rust в одном инструменте) и **oxlint** (очень быстрый линтер на Rust).
- Для CSS есть Stylelint с похожей моделью.

## Мини-шпаргалка

ESLint — статический анализ ошибок. ESLint 9: `eslint.config.js`, массив объектов с `files`, `languageOptions`, `plugins`, `rules`. Для React+TS: `@eslint/js`, `typescript-eslint`, `react-hooks`, `jsx-a11y`, `react-refresh`, в конце `eslint-config-prettier`. Запуск: редактор, lint-staged, CI с `--max-warnings=0`.
