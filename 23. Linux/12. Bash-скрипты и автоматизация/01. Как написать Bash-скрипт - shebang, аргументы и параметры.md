# Как написать Bash-скрипт - shebang, аргументы и параметры

> [!NOTE]
> Скрипт — сохранённая последовательность команд с явным интерпретатором и контрактом входа/выхода. `$1` — первый аргумент, `$#` — их число, `"$@"` сохраняет каждый аргумент отдельно, `$0` описывает вызванный скрипт. Для обязательных параметров проверяют наличие и допустимость, сообщения об ошибках направляют в stderr, результат — в stdout.

## Вопрос

Как передать имя с пробелом в скрипт и вернуть понятную ошибку, если параметра нет?

## Первый скрипт

Сохрани `greet.sh` в `~/linux-lab/scripts`:

```bash
#!/usr/bin/env bash
set -u

if (( $# != 1 )); then
  printf 'Usage: %s NAME\n' "$0" >&2
  exit 2
fi

name=$1
if [[ -z "$name" ]]; then
  printf 'NAME must not be empty\n' >&2
  exit 2
fi

printf 'Hello, %s!\n' "$name"
```

```bash
chmod u+x greet.sh
./greet.sh 'Anna Maria'
./greet.sh
```

Первый запуск печатает одну строку с полным именем, второй — usage в stderr и код 2. Проверка `$#` выполнена до чтения `$1`, поэтому `set -u` не прерывает скрипт из-за отсутствующего аргумента.

## Передача списка дальше

```bash
for arg in "$@"; do
  printf '<%s>\n' "$arg"
done
```

`"$@"` раскрывается в отдельный аргумент для каждого входного значения. `"$*"` склеивает их в одну строку, а незакавыченные варианты допускают нежелательное разбиение и glob.

## Опции

Для небольшого скрипта с короткими опциями подходит встроенный `getopts`. После обработки опций обычно делают `shift "$((OPTIND - 1))"`, чтобы остались позиционные аргументы. Не смешивай сложный ручной парсинг с исполнением пользовательского текста.

## Исполнение и source

`./greet.sh` запускает отдельный процесс. `source greet.sh` исполняет файл в текущем shell: `exit`, переменные и `cd` повлияют на текущую сессию. Для обычной утилиты source не нужен.

## Практика

Проверь имя с пробелом, пустую строку, отсутствие параметра и два параметра. После каждого запуска сохрани `$?` и объясни результат. Контракт скрипта должен быть понятен без чтения всего исходника.
