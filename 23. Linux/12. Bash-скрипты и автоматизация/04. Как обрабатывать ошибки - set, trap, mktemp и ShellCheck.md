# Как обрабатывать ошибки - set, trap, mktemp и ShellCheck

> [!NOTE]
> `set -u` выявляет необъявленные переменные, `pipefail` помогает не скрывать ошибки конвейера, а `set -e` прерывает выполнение лишь по своим контекстным правилам. Это полезные настройки, но не замена явной проверке важных операций. `mktemp` создаёт временный объект без предсказуемого имени, `trap` помогает убрать его при выходе. Скрипт проверяют и синтаксически, и на ожидаемых отказах.

## Вопрос

Почему `set -e` не делает скрипт автоматически надёжным? Как не оставить временный файл после ошибки?

## Минимальный шаблон

```bash
#!/usr/bin/env bash
set -euo pipefail
umask 077

tmp=$(mktemp)
cleanup() {
  rm -f -- "$tmp"
}
trap cleanup EXIT
trap 'exit 130' INT
trap 'exit 143' TERM

if ! printf 'study result\n' > "$tmp"; then
  printf 'Cannot write temporary result\n' >&2
  exit 1
fi

cat -- "$tmp"
```

Временный путь заключён в кавычки, cleanup удаляет только созданный файл. Trap на EXIT выполняется при обычном завершении shell, а обработчики INT и TERM переводят событие в выход с понятным статусом. SIGKILL и аварийное выключение обработать так нельзя.

## Особенности errexit

Неуспех команды в условии `if`, в некоторых списках `&&`/`||`, после `!` и в других контекстах не приводит к ожидаемому новичком выходу. Даже поведение тела функции зависит от контекста её вызова. Поэтому для критичного backup, загрузки или публикации проверяй успех явно.

Не пиши `if ! command; then code=$?`: внутри ветки это статус инвертированного условия. Для сохранения исходного кода:

```bash
if some_command; then
  printf 'ok\n'
else
  code=$?
  printf 'failed: %s\n' "$code" >&2
  exit "$code"
fi
```

Здесь `some_command` — место для реальной операции.

## Проверка

```bash
bash -n script.sh
shellcheck script.sh
```

`bash -n` проверяет синтаксис без выполнения. ShellCheck устанавливается отдельно и находит многие проблемы quoting и переносимости. Оба инструмента не доказывают корректность работы с реальными данными.

`set -x` показывает выполняемые команды и может вывести секреты: не включай его бездумно на production-заданиях.

## Практика

Запусти шаблон, затем намеренно замени путь вывода на недоступный в своей учебной папке. Проверь ненулевой статус и удаление временного файла. Не используй чужие каталоги для моделирования отказа.
