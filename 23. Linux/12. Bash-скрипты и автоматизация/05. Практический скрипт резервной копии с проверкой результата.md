# Практический скрипт резервной копии с проверкой результата

> [!NOTE]
> Надёжный учебный backup-скрипт проверяет аргументы, отделяет источник от назначения, блокирует параллельный запуск, создаёт временный архив и публикует его только после проверки. Успешный tar ещё не доказывает восстановление приложения: архив нужно отдельно распаковать и сравнить. Для живой БД такой скрипт не заменяет согласованный backup средствами СУБД.

## Вопрос

Как объединить аргументы, кавычки, trap, блокировку и tar в небольшой полезной автоматизации?

## Предусловия

GNU/Linux, Bash, GNU tar, GNU coreutils (realpath и mktemp), flock из util-linux. Источник — неподвижное дерево обычных учебных файлов, не `/`, не БД. Назначение находится **вне источника**. Сохрани код как `backup.sh`:

```bash
#!/usr/bin/env bash
set -euo pipefail
umask 077

for tool in realpath flock mktemp tar mv; do
  if ! command -v "$tool" > /dev/null 2>&1; then
    printf 'Required command is missing: %s\n' "$tool" >&2
    exit 1
  fi
done

if (( $# != 2 )); then
  printf 'Usage: %s SOURCE DESTINATION\n' "$0" >&2
  exit 2
fi

src=$(realpath -e -- "$1")
[[ -d "$src" ]] || { printf 'Source is not a directory\n' >&2; exit 2; }
mkdir -p -- "$2"
dest=$(realpath -e -- "$2")
if [[ "$src" == / || "$dest" == "$src" || "$dest" == "$src/"* ]]; then
  printf 'Destination must be outside a non-root source\n' >&2
  exit 2
fi

exec 9> "$dest/.backup.lock"
flock -n 9 || { printf 'Backup is already running\n' >&2; exit 1; }

tmp=$(mktemp "$dest/.backup.XXXXXXXX.tar.gz")
trap 'rm -f -- "$tmp"' EXIT
trap 'exit 130' INT
trap 'exit 143' TERM

if ! tar -czf "$tmp" -C "$src" .; then
  printf 'Archive creation failed\n' >&2
  exit 1
fi
tar -tzf "$tmp" > /dev/null

name=${tmp##*/}
final="$dest/backup-${name#.backup.}"
mv -- "$tmp" "$final"
printf '%s\n' "$final"
```

Случайная часть имени уменьшает риск совпадения. Временный и финальный файл находятся в одной ФС, поэтому `mv` публикует завершённый архив переименованием. Lock-файл оставляют на месте: удаление открытого lock-файла способно создать гонку между процессами.

## Запуск и восстановление

```bash
mkdir -p "$HOME/linux-lab/backup-source" "$HOME/linux-lab/backup-output" "$HOME/linux-lab/backup-restored"
printf 'important\n' > "$HOME/linux-lab/backup-source/note.txt"
archive=$(bash backup.sh "$HOME/linux-lab/backup-source" "$HOME/linux-lab/backup-output")
tar -xzf "$archive" -C "$HOME/linux-lab/backup-restored"
diff -r "$HOME/linux-lab/backup-source" "$HOME/linux-lab/backup-restored"
```

Результат diff должен быть пустым. Для новой проверки используй пустой каталог восстановления.

## Ограничения и проверки отказа

Пример не обеспечивает согласованность меняющихся файлов, шифрование, удалённое хранение и политику retention. Проверка путей рассчитана на доверенные учебные каталоги: она не защищает от враждебной смены symlink между проверкой и использованием.

Проверь отсутствие аргументов, путь с пробелом, отсутствующий источник и назначение внутри источника. Файл архива с нулевым статусом — лишь один уровень проверки; возможность восстановления важнее.
