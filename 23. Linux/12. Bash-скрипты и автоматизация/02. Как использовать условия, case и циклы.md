# Как использовать условия, case и циклы

> [!NOTE]
> `if` проверяет exit status команды. В Bash `[[ ... ]]` удобно для строк и файловых условий, `(( ... ))` — для арифметики, `case` — для выбора по шаблонам. Циклы выполняют повторяемые действия, но ввод и список файлов нужно обрабатывать с сохранением границ аргументов. Для чтения строк обычно применяют `while IFS= read -r line`.

## Вопрос

Как проверить файл, разобрать режим работы и прочитать строки без потери пробелов и обратных слешей?

## Условия

```bash
file='report.txt'
if [[ -f "$file" && -r "$file" ]]; then
  printf 'Readable regular file\n'
else
  printf 'Missing or unreadable: %s\n' "$file" >&2
fi
```

`-f` проверяет обычный файл, `-r` — возможность чтения в текущем контексте. Между проверкой и использованием файл может измениться, поэтому реальная операция всё равно должна обрабатывать ошибку.

```bash
mode=${1:-check}
case "$mode" in
  check) printf 'checking\n' ;;
  report) printf 'reporting\n' ;;
  *) printf 'Unknown mode: %s\n' "$mode" >&2; exit 2 ;;
esac
```

`case` использует shell-шаблоны, не regex. Сравнение чисел лучше делать через `(( count > 10 ))` или числовые операторы test, а не лексикографическое сравнение строк.

## Читаем строки

```bash
while IFS= read -r line || [[ -n "$line" ]]; do
  printf '<%s>\n' "$line"
done < input.txt
```

`IFS=` сохраняет крайние пробелы, `-r` не интерпретирует обратный слеш как escape, дополнительное условие обрабатывает последнюю строку без перевода строки.

В Bash `cat input.txt | while ...` обычно запускает цикл в subshell; изменённый внутри счётчик после цикла может не сохраниться. Перенаправление `< input.txt` позволяет выполнить цикл в текущей оболочке.

## Перебор файлов

```bash
for file in ./*.log; do
  [[ -f "$file" ]] || continue
  printf '%s\n' "$file"
done
```

Проверка также позволяет пропустить буквальный `./*.log`, если совпадений нет при стандартных настройках Bash. Для произвольного рекурсивного списка используй find с `-exec` или NUL-разделением.

## Практика

Создай input.txt со строкой с пробелами, обратным слешем и последней строкой без `\n`. Сравни корректный цикл с `for line in $(cat input.txt)` и объясни, почему второй вариант разбивает данные.
