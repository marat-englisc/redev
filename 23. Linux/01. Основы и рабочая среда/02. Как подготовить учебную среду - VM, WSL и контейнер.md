# Как подготовить учебную среду - VM, WSL и контейнер

> [!NOTE]
> Для полного курса удобна отдельная виртуальная машина с Ubuntu Server или Debian и systemd. WSL 2 подходит для терминала, файлов и Bash; запуск systemd и сетевое поведение нужно проверять. Контейнер удобен для отдельных команд, но по умолчанию не воспроизводит загрузку полноценной ОС и управление её службами.

## Вопрос

Где безопасно практиковать Linux на Windows или macOS и почему контейнер не заменяет полноценный учебный сервер?

## Выбираем среду

| Среда | Что удобно изучать | Что учитывать |
| --- | --- | --- |
| Виртуальная машина | Все темы, включая загрузку, диски и службы | Нужны ресурсы и снимки состояния |
| WSL 2 | CLI, Bash, разработку, большинство утилит | Сеть и загрузка отличаются от обычного сервера |
| Контейнер | Изолированные упражнения с файлами и командами | Общее ядро с Linux-хостом; systemd обычно не запущен |
| Удалённый сервер | SSH и реальные сетевые сценарии | Возможна плата; ошибки влияют на доступность |

Для начала достаточно VM с примерно 2 CPU, 2–4 ГБ RAM и 20 ГБ диска. Это ориентир для учебного стенда, а не требование Linux. Перед темами про `/etc/fstab`, firewall и SSH сохрани снимок VM.

## WSL на Windows

В PowerShell с правами администратора:

```powershell
wsl --install -d Ubuntu
wsl --list --verbose
```

После установки и необходимой перезагрузки открой Ubuntu, создай обычного пользователя. Дальнейшие `bash`-примеры курса выполняются **в Linux-терминале**, а не в PowerShell.

```bash
cat /etc/os-release
ps -p 1 -o comm=
mkdir -p "$HOME/linux-lab"
cd "$HOME/linux-lab"
pwd
```

Если PID 1 не `systemd`, уроки с `systemctl` требуют отдельной настройки WSL по документации Microsoft либо VM. Ошибка «System has not been booted with systemd» здесь не означает поломку самой службы.

## Договорённости курса

- Основная среда — Ubuntu/Debian, Bash, GNU-утилиты; отличия отмечены отдельно.
- Рабочие файлы создаём в `~/linux-lab`; пути вроде `/srv/demo` появляются только в соответствующей лабораторной.
- `sudo` используют лишь команды, которым нужны системные права.
- Сеть, SSH и служебные пакеты могут потребовать установки. Проверяй инструмент через `command -v имя`.
- Блоки `text` показывают схему или пример вывода: вводить их как команды не нужно.

Примеры Shell на сайте нужно запускать в своей Linux-среде: браузерная JS-песочница не является Linux-терминалом.

## Практика

Создай `~/linux-lab`, узнай своего пользователя командой `id` и проверь PID 1. Критерий готовности: ты понимаешь, где выполняются команды и как вернуться к исходному состоянию стенда.
