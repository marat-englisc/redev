# Как работают mount, umount и fstab

> [!NOTE]
> `mount` подключает файловую систему в каталог, `umount` отсоединяет её. `/etc/fstab` описывает постоянные монтирования и параметры. Подключение поверх непустого каталога скрывает его прежнее содержимое до размонтирования, а не удаляет. Ошибка в обязательном монтировании способна нарушить загрузку ОС, поэтому изменения проверяют до перезагрузки.

## Вопрос

Что такое точка монтирования? Почему после mount «пропали» файлы и чем UUID лучше имени `/dev/sdb1` в fstab?

## Безопасная учебная ФС в памяти

В своей VM:

```bash
mkdir -p "$HOME/linux-lab/mountpoint"
printf 'underlying\n' > "$HOME/linux-lab/mountpoint/before.txt"
sudo mount -t tmpfs -o size=16M,mode=1777 tmpfs "$HOME/linux-lab/mountpoint"
findmnt -T "$HOME/linux-lab/mountpoint"
ls -la "$HOME/linux-lab/mountpoint"
sudo umount "$HOME/linux-lab/mountpoint"
cat "$HOME/linux-lab/mountpoint/before.txt"
```

После mount `before.txt` скрыт, после umount снова виден. Tmpfs хранит временные данные в виртуальной памяти и может использовать swap; его содержимое не предназначено для сохранения после размонтирования или перезагрузки.

## Постоянное монтирование

Схема записи fstab:

```text
UUID=фактический-uuid  /data  ext4  defaults  0  2
```

Это шаблон, а не готовая строка. Поля: источник, точка, тип ФС, опции, dump, порядок fsck. UUID меньше зависит от порядка обнаружения устройств, чем имя `/dev/sdb1`; значение берут с реальной ФС через `lsblk -f` или `blkid`.

После осознанной правки используют `findmnt --verify --verbose`, а в systemd-системе перечитывают конфигурацию через `systemctl daemon-reload`. Пробное монтирование делают для конкретной точки. `mount -a` затрагивает все подходящие записи и требует понимания всего fstab.

## Опции и ошибки

| Опция | Назначение |
| --- | --- |
| `ro` | Только чтение |
| `noexec` | Запрет непосредственного выполнения с ФС |
| `nosuid` | Не учитывать setuid/setgid при выполнении |
| `nodev` | Не использовать device nodes как устройства |
| `nofail` | Не считать отсутствие этого монтирования обязательной ошибкой загрузки |

`noexec` не запрещает интерпретатору читать скрипт как данные. При `target is busy` проверь процессы и cwd через `fuser -vm точка` или lsof; не начинай с принудительного отсоединения.

## Практика

Повтори tmpfs-пример и обязательно размонтируй его. Объясни различие между временным mount и изменением fstab.
