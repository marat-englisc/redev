# Как поддерживать базовую безопасность Linux-сервера

> [!NOTE]
> Базовая защита складывается из поддерживаемой ОС, своевременных обновлений, минимально необходимых служб и полномочий, проверенного удалённого доступа и наблюдения. Секреты не должны попадать в репозиторий, историю shell и публичные журналы. Изменения безопасности проверяют по фактическому поведению и сохраняют способ восстановления доступа.

## Вопрос

Какие меры ты применишь к новому серверу приложения и почему один firewall не решает всю задачу?

## Начни с поверхности доступа

```bash
ss -ltnu
systemctl list-units --type=service --state=running
sudo -l
timedatectl status
```

Найди, какие процессы принимают соединения, зачем они нужны и от чьего имени работают. Список портов — начало исследования, а не готовый список того, что надо отключить.

## Рабочие меры

| Мера | Какую проблему уменьшает |
| --- | --- |
| Поддерживаемый выпуск и security updates | Известные уязвимости |
| Отдельный пользователь службы | Область ущерба при компрометации |
| Минимальные открытые порты | Доступ к ненужным интерфейсам |
| SSH по ключам с проверкой host key | Подбор пароля и подмена сервера |
| Ограниченные права файлов | Чтение конфигов и секретов посторонними |
| Логи и оповещения по значимым событиям | Запоздалое обнаружение отказа |
| Проверяемое восстановление | Длительная потеря данных и доступности |

## Секреты

Не передавай пароль флагом командной строки, если приложение поддерживает более подходящий канал: args могут быть видны через ps и `/proc`. Окружение тоже не является безусловно секретным хранилищем.

Файл с секретами обычно доступен только нужному пользователю или узкой группе. При утечке токен **меняют**, а не только удаляют из последнего коммита: прежняя версия могла остаться в истории, кешах и логах.

## Время и сертификаты

Корректное время необходимо для TLS, сроков действия токенов и сопоставления журналов. `timedatectl` показывает timezone и состояние синхронизации на соответствующей системе. Сам факт включения NTP не доказывает успешную синхронизацию: проверь фактический статус используемой службы, например timesyncd или chrony.

## Изменения по одному

Не совмещай смену порта SSH, правил firewall, пользователя и ключей в одном непроверенном шаге. После каждого изменения проверь новый вход и журнал, сохрани старую сессию до успеха. Для VM заранее знай, как открыть консоль.

## Практика

Для стенда составь таблицу «порт → процесс → пользователь → причина доступности». Отметь, где лежат конфигурация, логи и backup. Ничего не отключай, пока не понимаешь назначение.
