# Почему прав rwx недостаточно - AppArmor, SELinux и capabilities

> [!NOTE]
> Обычные права и ACL — слой дискреционного доступа. AppArmor и SELinux добавляют обязательные политики, которые могут запретить действие даже при подходящем chmod. Capabilities разделяют часть root-полномочий на отдельные возможности. Sandbox-настройки systemd и mount options также влияют на доступ. При отказе выясняют, какой слой его вызвал, а не отключают защиту целиком.

## Вопрос

Файл читается обычным пользователем, но служба получает Permission denied. Какие причины есть кроме chmod?

## Несколько уровней проверки

```text
UID/GID + rwx/ACL
        + политика AppArmor/SELinux
        + mount options и namespace
        + sandbox службы
        = фактически разрешённое действие
```

У systemd-службы `ProtectHome=true` может скрывать домашние каталоги, а `ProtectSystem=strict` — делать файловое дерево недоступным для записи. `sudo` в другом терминале не воспроизводит этот контекст.

## Наблюдение на разных дистрибутивах

Ubuntu с AppArmor:

```bash
sudo aa-status
sudo journalctl -k --since '10 minutes ago' --no-pager
```

В сообщениях ищут AppArmor denial и профиль процесса. На системе с SELinux:

```bash
getenforce
ls -Z /srv
sudo ausearch -m AVC -ts recent
```

Команды требуют соответствующих пакетов и настроек audit. Отсутствие команды не доказывает отсутствие всех политик безопасности.

В SELinux важны метки и правила типов; перенесённый файл может иметь неподходящую метку. Для восстановления штатных меток используют соответствующие инструменты, например restorecon, после понимания политики. Не начинай с глобального permissive.

## Capabilities

```bash
getcap /usr/bin/ping
```

Пустой вывод допустим: способ предоставления нужных прав зависит от сборки и настроек. Пример capability — `CAP_NET_BIND_SERVICE` для привязки к привилегированным портам при соответствующих настройках ядра. Возможность не означает «безопасно выдать любому интерпретатору»: некоторые capabilities дают очень широкий доступ.

## Алгоритм диагностики

Проверь пользователя и группы службы, полный путь, ACL, mount options, effective unit и журнал политик. Изменяй минимальное правило или размещение данных, затем повторяй реальную операцию.

## Практика

Открой unit demo-web и объясни, почему его процесс не должен писать в `/home/alex`, даже если где-то выданы широкие права. Найди слой, который ограничивает действие.
