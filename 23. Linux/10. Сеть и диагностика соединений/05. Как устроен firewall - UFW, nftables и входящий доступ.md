# Как устроен firewall - UFW, nftables и входящий доступ

> [!NOTE]
> Firewall разрешает или блокирует пакеты по правилам. В Linux правила часто реализуются netfilter/nftables, а UFW или firewalld предоставляют интерфейс управления. Доступность сервиса зависит одновременно от bind-адреса, локального firewall, маршрутов, NAT и внешних правил. Перед изменением по SSH нужно сохранить путь доступа и иметь консоль восстановления.

## Вопрос

Почему открытый в UFW порт всё ещё недоступен? Как включить firewall в учебной VM и не потерять SSH?

## Сначала прочитать состояние

```bash
sudo ufw status verbose
sudo nft list ruleset
ss -ltn
```

Наличие инструментов зависит от дистрибутива. Не управляй одними правилами одновременно через несколько несогласованных менеджеров: один способен перезаписать изменения другого.

## Модель входящего запроса

```text
Клиент → внешний firewall/security group → NAT/маршрут
       → firewall хоста → слушающий сокет → приложение
```

Правило allow не создаёт слушатель. А слушатель `127.0.0.1:8080` недоступен снаружи даже при разрешённом порте.

## Изменение в отдельной Ubuntu VM

Только если SSH действительно использует TCP 22, проверен адрес администратора и есть консоль VM:

```bash
sudo ufw allow 22/tcp
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw enable
sudo ufw status numbered
```

Это пример политики для стенда, а не универсальный набор для сервера. Если SSH использует другой порт, сначала разрешают **его**. Ограничение источника доступа делают по реальной сети администратора. Существующую SSH-сессию не закрывай до успешного входа во второй.

## Stateful-подход

Правила часто учитывают состояние соединений: ответ на разрешённое исходящее соединение не требует открывать все случайные входящие порты. Но конкретный ruleset нужно читать целиком, включая порядок и цепочки.

Docker и другие сетевые системы могут создавать собственные правила. Опубликованный контейнерный порт не всегда контролируется так, как ожидается по простому `ufw status`; проверяй фактический путь пакета и документацию runtime.

## Практика

Для своей VM нарисуй путь к учебному серверу и укажи каждый уровень ограничения. Начни с read-only команд; политику меняй только в стенде с консолью. Для локального demo-web, слушающего loopback, открывать 8080 наружу не нужно.
