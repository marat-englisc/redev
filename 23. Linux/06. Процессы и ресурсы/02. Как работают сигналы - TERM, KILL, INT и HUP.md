# Как работают сигналы - TERM, KILL, INT и HUP

> [!NOTE]
> Сигнал уведомляет процесс о событии. `kill` отправляет сигнал, по умолчанию SIGTERM, а не обязательно немедленно «убивает». SIGTERM позволяет программе завершиться корректно, SIGKILL нельзя обработать или игнорировать. Сначала выясняют владельца процесса и способ управления им, затем применяют штатную остановку; для службы обычно используют systemctl.

## Вопрос

Чем `kill PID` отличается от `kill -9 PID`? Почему код 137 не доказывает нехватку памяти?

## Основные сигналы

| Сигнал | Типичный источник | Обычное назначение |
| --- | --- | --- |
| SIGINT | Ctrl C в терминале | Прервать foreground-задачу |
| SIGTERM | `kill`, менеджер служб | Запросить завершение |
| SIGKILL | Принудительная остановка | Завершить без обработчика приложения |
| SIGHUP | Разрыв терминала, явная отправка | Завершение или reload по соглашению программы |
| SIGSTOP / SIGCONT | Job control | Приостановить / продолжить |

Не все программы перечитывают конфиг по HUP. Это поведение конкретного приложения, а не универсальное свойство сигнала.

## Контролируемый пример

```bash
sleep 300 &
pid=$!
ps -p "$pid" -o pid,stat,comm
kill -TERM "$pid"
wait "$pid"
printf 'wait status=%s\n' "$?"
```

`$!` — PID последнего фонового задания. `wait` получает его статус. Bash обычно кодирует завершение по сигналу как `128 + номер сигнала`: для SIGTERM часто получится 143.

## Корректное завершение

Сервер при TERM может перестать принимать запросы, дождаться текущих, сбросить буферы и закрыть соединения. Менеджер служб задаёт время ожидания, после которого возможна принудительная остановка.

SIGKILL не выполняет обработчики приложения. При непрерываемом ожидании D видимое исчезновение процесса может задержаться, пока ядро не выйдет из такого ожидания.

## Как читать 137

В типичной shell-интерпретации `137 = 128 + 9`, что согласуется с SIGKILL. Причиной мог быть OOM killer, администратор или менеджер процессов. Для вывода об OOM нужны журнал ядра, события cgroup или метаданные контейнера. Кроме того, программа может сама вернуть число 137.

## Практика

Повтори опыт только со своим `sleep`. Перед любым сигналом проверяй PID и команду; не используй широкое `pkill` по приблизительному шаблону на общей машине.
