# Как работают nice, ulimit и лимиты службы

> [!NOTE]
> `nice` влияет на относительный приоритет обычных CPU-задач, но не гарантирует долю процессора. `ulimit` задаёт наследуемые ограничения ресурсов shell и его потомков, например число открытых дескрипторов. Soft limit действует сейчас, hard limit ограничивает его повышение. Для службы systemd лимиты задают в unit, а групповые ограничения CPU и памяти обычно реализуются cgroups.

## Вопрос

Почему `ulimit -n` в терминале не меняет лимит уже работающего API? Чем nice отличается от ограничения CPU?

## Приоритет CPU

```bash
nice -n 10 sleep 60 &
pid=$!
ps -p "$pid" -o pid,ni,comm
kill -TERM "$pid"
wait "$pid"
```

У обычных Linux-задач nice часто находится в диапазоне от `-20` до `19`: меньшее значение означает более высокий приоритет. Обычный пользователь обычно может понизить свой приоритет, но не произвольно повысить его. На спящем процессе эффект на CPU не виден, зато безопасно виден сам атрибут.

## Ограничения процесса

```bash
ulimit -Sn
ulimit -Hn
cat /proc/$$/limits
```

`-n` относится к открытым файловым дескрипторам. Сокеты тоже используют дескрипторы, поэтому сервер может получить `Too many open files` даже при малом числе обычных файлов.

Лимиты наследуются при запуске. Если изменить `ulimit` в одном терминале, уже запущенная служба или другая сессия не изменятся. Нужен корректный способ настройки контекста **нового процесса**.

## Служба systemd

Пример фрагмента unit:

```ini
[Service]
LimitNOFILE=8192
MemoryMax=512M
CPUQuota=100%
```

`LimitNOFILE` задаёт process resource limit, `MemoryMax` ограничивает память cgroup, `CPUQuota=100%` соответствует квоте примерно одного CPU по времени, а не «100% всех ядер». Эти значения — пример, а не универсальная production-настройка.

После правки unit требуются `daemon-reload` и перезапуск нужной службы. Итог проверяют по реальному PID и `/proc/PID/limits`, а не только по содержимому файла.

## Частые ошибки

- Поднимать лимиты вместо устранения утечки дескрипторов.
- Считать nice жёстким ограничителем потребления CPU.
- Забывать отдельные cgroup-лимиты контейнера или службы при достаточных ресурсах хоста.

## Практика

Найди soft и hard limit дескрипторов своей Bash. Объясни, почему 1000 соединений могут потребовать больше 1000 дескрипторов: у процесса есть логи, внутренние pipe и другие ресурсы.
