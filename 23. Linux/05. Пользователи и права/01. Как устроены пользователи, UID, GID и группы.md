# Как устроены пользователи, UID, GID и группы

> [!NOTE]
> Ядро проверяет числовые UID и GID, а имена пользователей — удобное отображение этих чисел. У процесса есть идентификатор пользователя, основная и дополнительные группы. Учётная запись не обязательно принадлежит человеку: отдельные системные пользователи ограничивают доступ служб. Изменение членства в группе обычно становится доступно в новой сессии.

## Вопрос

Что такое UID и GID? Почему после добавления в группу текущий терминал всё ещё не получает доступ?

## Узнаём свои полномочия

```bash
whoami
id
groups
getent passwd "$USER"
getent group
```

`id` показывает реальные числовые идентификаторы и группы текущего процесса. `getent` запрашивает настроенные источники учётных данных: это может быть не только локальный файл, но и каталог организации.

## Где хранятся локальные записи

| Файл | Содержимое |
| --- | --- |
| `/etc/passwd` | Имя, UID, основной GID, home и shell |
| `/etc/group` | Группы и часть сведений о членстве |
| `/etc/shadow` | Хеши паролей и параметры их срока действия, доступ ограничен |

В `/etc/passwd` обычно нет самого пароля. Поле `x` указывает на вынесенное хранение. Не копируй содержимое shadow в учебные отчёты или публичные логи.

## Учётные записи служб

В отдельной Ubuntu/Debian VM можно создать сервисную учётную запись:

```bash
sudo useradd --system --user-group --home-dir /nonexistent --shell /usr/sbin/nologin demoapp
getent passwd demoapp
id demoapp
```

Этот шаг нужен только один раз и меняет систему. `--system` выбирает диапазон системных идентификаторов по настройкам дистрибутива; `nologin` запрещает обычный интерактивный вход, но не мешает systemd запускать процесс с этим UID.

Для добавления существующего пользователя в дополнительную группу применяют `sudo usermod -aG имя_группы имя_пользователя`. **`-a` важен**: без него список дополнительных групп может быть заменён. Новая login-сессия получает обновлённые группы; старые процессы сохраняют прежние credentials.

## Частые ошибки

- Запускать все службы одним root-пользователем.
- Менять UID существующей учётной записи, не учитывая владельцев файлов.
- Давать группу `docker` как безобидное удобство: доступ к Docker daemon часто даёт контроль над хостом.

## Практика

Сравни `id` и `id demoapp`, если создал учебного пользователя. Объясни, почему отсутствие интерактивного входа не запрещает процессу читать разрешённый ему файл.
