# Что такое ACL, setgid, sticky bit и setuid

> [!NOTE]
> ACL дополняют обычные права адресными разрешениями для пользователей и групп; effective-права могут ограничиваться ACL mask. Setgid на каталоге помогает наследовать группу. Sticky bit ограничивает удаление и переименование чужих файлов в общем каталоге. Setuid на исполняемом файле может менять effective UID процесса и требует особой осторожности.

## Вопрос

Как дать одному пользователю доступ без `chmod 777`? Для чего `/tmp` обычно имеет режим `1777`?

## Общий каталог команды

Для каталога с режимом `2770` ведущая `2` означает setgid. Новые файлы обычно наследуют группу каталога, но права на запись зависят ещё от umask или default ACL.

```bash
mkdir -p "$HOME/linux-lab/team"
chmod 2770 "$HOME/linux-lab/team"
ls -ld "$HOME/linux-lab/team"
```

Это учебный каталог собственной группы. Для реальной команды назначают отдельную группу и проверяют проход по всем родительским каталогам.

## ACL

При наличии пакета `acl`:

```bash
touch "$HOME/linux-lab/team/report.txt"
getfacl "$HOME/linux-lab/team/report.txt"
```

Для предоставления существующему пользователю alex чтения использовали бы `setfacl -m u:alex:r-- файл`. Помимо файла, ему нужен проход к нему. `setfacl -m d:g:имя_группы:rwx каталог` задаёт default ACL для будущих объектов; существующие объекты автоматически не меняются.

Знак `+` после режима в `ls -l` часто указывает на расширенный ACL. Проверяй строки `mask` и `effective` в `getfacl`: перечисленное право может быть ограничено маской. `chmod` способен изменить эту маску, поэтому повторно проверь ACL после правки.

## Специальные биты

| Бит | Где полезен | Что не гарантирует |
| --- | --- | --- |
| Setgid на каталоге | Общая группа новых файлов | Нужный уровень записи без umask/ACL |
| Sticky на каталоге | Общий временный каталог | Секретность содержимого файлов |
| Setuid на бинарнике | Строго ограниченные привилегированные действия | Безопасность программы |

Sticky bit позволяет удалять запись владельцу файла, владельцу каталога или привилегированному процессу при выполнении остальных условий. Поэтому `1777` для `/tmp` не эквивалентен обычному `777`.

В Linux setuid на shell-скриптах не используется как надёжный способ повышения прав; ядро игнорирует соответствующие биты для таких скриптов. Не назначай setuid интерпретатору.

## Практика

Посмотри `ls -ld /tmp`, `getfacl /tmp`, затем объясни разницу между «можно прочитать чужой файл» и «можно удалить его имя».
