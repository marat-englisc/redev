# Как настроить SSH config, ProxyJump и диагностику входа

> [!NOTE]
> `~/.ssh/config` задаёт алиасы, пользователя, порт, ключ и jump host для отдельных серверов. `ProxyJump` проводит соединение через промежуточный хост без необходимости копировать приватный ключ на него. `ssh -v` показывает этапы подключения, а `ssh -G` — вычисленную конфигурацию клиента. Конкретные блоки Host обычно располагают раньше общих: для многих опций действует первое полученное значение.

## Вопрос

Как подключаться к внутреннему серверу через bastion и понять, почему SSH не принимает ожидаемый ключ?

## Пример клиентской конфигурации

Подставь адреса **своих** машин. Если bastion нет, достаточно одного блока `study`:

```sshconfig
Host study
    HostName 192.168.56.10
    User alex
    Port 22
    IdentityFile ~/.ssh/id_ed25519_linux_study
    IdentitiesOnly yes
    ServerAliveInterval 30

Host internal
    HostName 10.0.0.20
    User deploy
    ProxyJump study
    IdentityFile ~/.ssh/id_ed25519_linux_study

Host *
    ForwardAgent no
```

`ssh study` использует первый набор настроек. Для internal клиент подключается через study к целевому SSH-серверу; доступ к адресу `10.0.0.20` должен существовать со стороны jump host.

## Наблюдение

```bash
ssh -G study
ssh -v study
ssh study 'hostname; id'
```

Здесь `;` относится к удалённой командной строке. Для сложного пользовательского ввода помни, что удалённая команда может разбираться ещё одной оболочкой: локальные кавычки не решают автоматически все вопросы удалённого quoting.

## Типичные причины

| Симптом | Проверка |
| --- | --- |
| Timeout | Адрес, маршрут, firewall, порт |
| Refused | Служба SSH и listener |
| `Permission denied (publickey)` | Пользователь, выбранный ключ, authorized_keys и права |
| `Too many authentication failures` | Лишние ключи agent; явный IdentityFile и IdentitiesOnly |
| Host key mismatch | Проверка реальной смены серверного ключа |

`ServerAliveInterval` помогает обнаруживать неотвечающее соединение, но не сохраняет выполняемую команду при обрыве: для интерактивной работы полезен tmux.

Agent forwarding позволяет удалённой стороне пользоваться агентом в пределах соединения и несёт риск при компрометации хоста. Для обычного доступа через bastion часто достаточно ProxyJump.

## Практика

Создай один алиас для VM, проверь через `ssh -G`, какой ключ и пользователь выбраны. Найди в `-v` этап аутентификации, не публикуя полный диагностический вывод без проверки.
