# Как работают SSH-туннели и безопасная настройка sshd

> [!NOTE]
> Local forwarding `ssh -L` открывает порт на клиенте и передаёт соединения через SSH к адресу, доступному серверу. Remote forwarding `-R` открывает порт с удалённой стороны. Для локальной отладки привязывай вход туннеля к loopback. Настройки sshd проверяют `sshd -t`, а новый вход тестируют во второй сессии до закрытия старой.

## Вопрос

Как обратиться к локальному HTTP-сервису VM без открытия порта наружу? Как изменить SSH-настройки, сохранив доступ?

## Доступ к demo-web через туннель

Если demo-web слушает `127.0.0.1:8080` **в VM**, на клиенте:

```bash
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:18080:127.0.0.1:8080 study
```

В другом клиентском терминале:

```bash
curl --fail http://127.0.0.1:18080/
```

```text
Клиент:18080 → зашифрованный SSH → VM → VM:127.0.0.1:8080
```

Первый адрес `127.0.0.1` — bind на клиенте, второй — цель, к которой подключается SSH-сервер. `-N` не запускает удалённую команду. Ctrl C закрывает туннель. Успешное открытие локального порта ещё не гарантирует, что HTTP-цель отвечает.

## Изменение серверной конфигурации

Типичные меры: отдельный пользователь, ключевая аутентификация, ограничения root-входа и ненужных способов доступа. Не отключай пароль, пока вход по ключу не проверен.

```bash
sudo /usr/sbin/sshd -t
sudo /usr/sbin/sshd -T
```

`-t` проверяет синтаксис и пригодность ключей, `-T` показывает эффективные параметры. Match-блоки могут требовать проверки с конкретным контекстом через `-C`. Файлы `sshd_config.d` и порядок Include влияют на итоговые значения.

После проверки сделай reload **существующего на твоей системе** SSH-unit, открой второе соединение и проверь доступ. Имя может быть `ssh` или `sshd`; некоторые системы используют socket activation. Удалённый доступ требует консоли восстановления перед рискованными изменениями порта и firewall.

## Частые ошибки

- Путать конфиг клиента `ssh_config` и сервера `sshd_config`.
- Считать смену порта полноценной заменой аутентификации и обновлений.
- Открывать туннель на `0.0.0.0` без необходимости: он становится доступен другим клиентам сети.

## Практика

Проверь туннель к своему demo-web и закрой его. Объясни, почему HTTP-порт VM при этом не нужно разрешать для всей сети.
