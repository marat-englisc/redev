# Как планировать обновления и откат

> [!NOTE]
> Обновление пакетов меняет исполняемый код и иногда конфигурацию, службы и ядро. Перед изменением оценивают состав обновления, делают согласованную копию данных, готовят проверку и путь возврата. Откат версии пакета не равен откату базы данных или всей ОС. После обновления ядра новое ядро обычно начинает работать только после перезагрузки.

## Вопрос

Как обновить учебный или рабочий сервер с понятной проверкой результата? Почему downgrade одного пакета может оказаться недостаточным?

## До установки

```bash
sudo apt update
apt list --upgradable
apt-get -s upgrade
uname -r
df -h / /boot
```

`-s` моделирует операцию APT без установки. Список и решения могут отличаться между `upgrade` и `full-upgrade`: второй вариант способен удалять пакеты для разрешения зависимостей. Всегда читай предложенные изменения.

## План из пяти шагов

1. Зафиксировать версии и текущее состояние: службы, HTTP-проверки, свободное место.
2. Сделать подходящую резервную копию; для VM полезен snapshot, для БД — согласованный backup.
3. Выполнить обновление в подходящее окно; понимать, какие службы могут перезапуститься.
4. Проверить запуск, логи и пользовательский сценарий, при необходимости перезагрузить.
5. Наблюдать некоторое время и сохранить результат изменения.

Автоматические security updates уменьшают задержку исправлений, но политика перезапуска и перезагрузки всё равно требует настройки под сервис.

## Конфигурация и данные

Пакетный менеджер может спросить, сохранить ли изменённый конфиг или установить версию поставщика. Не выбирай ответ машинально: сравни изменения, сохрани локальные настройки и проверь совместимость.

Если приложение обновило схему БД, установка старого бинарника может уже не помочь. Возврат должен учитывать данные, конфигурацию, зависимости и совместимость. Старая версия пакета также может исчезнуть из обычного репозитория.

## Что проверить после перезагрузки

```bash
uname -r
systemctl --failed
journalctl -b -p err --no-pager
```

Отсутствие failed units не подтверждает работоспособность бизнес-сценария. Дополнительно проверь реальный HTTP-запрос или другое действие пользователя.

## Практика

Для учебной VM составь короткий план обновления: исходная проверка, снимок, операция, проверка после загрузки и условие возврата. Само обновление выполняй только после понимания предложенного списка пакетов.
