# vi.fn и vi.spyOn

> [!NOTE]
> `vi.fn()` создаёт новую функцию-мок, которая записывает вызовы и возвращает заданное значение. `vi.spyOn(obj, 'method')` подменяет существующий метод объекта шпионом, который можно восстановить. В Jest аналоги — `jest.fn` и `jest.spyOn`.

## Вопрос

Чем `vi.fn` отличается от `vi.spyOn`? Чем отличаются `mockClear`, `mockReset` и `mockRestore`?

## Основная идея

**`vi.fn(impl?)`** — функция «с нуля». Её передают туда, где ожидается callback: `onSubmit`, `onChange`, зависимость сервиса. Без реализации она возвращает `undefined`. Поведение задаётся методами:

| Метод | Что делает |
| --- | --- |
| `mockReturnValue(v)` | всегда возвращать `v` |
| `mockReturnValueOnce(v)` | вернуть `v` один раз, затем — обычное поведение |
| `mockResolvedValue(v)` | возвращать `Promise.resolve(v)` |
| `mockRejectedValue(e)` | возвращать `Promise.reject(e)` |
| `mockImplementation(fn)` | своя реализация |

Информация о вызовах хранится в `mock.calls` (аргументы), `mock.results` (результаты) и `mock.instances`. Обычно её читают через matchers `toHaveBeenCalledWith`, `toHaveBeenCalledTimes`.

**`vi.spyOn(object, 'method')`** нужен, когда метод уже существует: `console.error`, `window.scrollTo`, `Date.now`, метод сервиса. По умолчанию шпион **вызывает оригинал** и только записывает вызовы. Через `mockImplementation` оригинал можно заменить. Главное отличие от присваивания `obj.method = vi.fn()` — восстановление через `mockRestore()`.

Сброс:

| Метод | Очищает вызовы | Сбрасывает реализацию | Возвращает оригинал |
| --- | --- | --- | --- |
| `mockClear()` | да | нет | нет |
| `mockReset()` | да | да | нет |
| `mockRestore()` | да | да | да (для `spyOn`) |

Те же операции для всех моков сразу: `vi.clearAllMocks()`, `vi.resetAllMocks()`, `vi.restoreAllMocks()`, или глобально через опции `clearMocks`, `mockReset`, `restoreMocks` в конфиге.

## Пример

```tsx
import { it, expect, vi } from 'vitest';
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { TodoForm } from './TodoForm';

it('вызывает onAdd с текстом задачи', async () => {
  const user = userEvent.setup();
  const onAdd = vi.fn();
  render(<TodoForm onAdd={onAdd} />);

  await user.type(screen.getByLabelText('Задача'), 'Купить хлеб');
  await user.click(screen.getByRole('button', { name: 'Добавить' }));

  expect(onAdd).toHaveBeenCalledTimes(1);
  expect(onAdd).toHaveBeenCalledWith('Купить хлеб');
});

it('логирует ошибку без шума в консоли', () => {
  const errorSpy = vi.spyOn(console, 'error').mockImplementation(() => {});

  reportError(new Error('Сеть недоступна'));

  expect(errorSpy).toHaveBeenCalledWith(expect.stringContaining('Сеть недоступна'));
  errorSpy.mockRestore();
});
```

## Что важно помнить

- `toHaveBeenCalledWith` проверяет, что **хотя бы один** вызов был с такими аргументами. Для последнего вызова — `toHaveBeenLastCalledWith`, для n-го — `toHaveBeenNthCalledWith`.
- Для типизации: `vi.fn<(id: string) => Promise<User>>()` или `vi.mocked(fn)` для уже замоканного модуля.
- Шпион на `console.error` полезен, но не скрывайте настоящие предупреждения React — проверяйте их.
- Не проверяйте вызовы внутренних функций компонента — это детали реализации.

## Мини-шпаргалка

`vi.fn` — новая функция-мок. `vi.spyOn` — шпион на существующем методе, восстанавливается. Clear → вызовы, Reset → + реализация, Restore → + оригинал.
