# Мок модулей через vi.mock

> [!NOTE]
> `vi.mock(path, factory?)` заменяет импортируемый модуль во всём тестовом файле. Вызов поднимается (hoisting) над импортами, поэтому фабрика не может использовать обычные переменные из файла — для этого есть `vi.hoisted`.

## Вопрос

Как замокать импортированный модуль? Почему `vi.mock` нельзя использовать с переменными, объявленными выше?

## Основная идея

Компонент или сервис часто импортирует зависимости напрямую: `import { api } from '@/shared/api'`. Передать мок через параметр нельзя, поэтому подменяют сам модуль. Runner перехватывает импорт и отдаёт вместо реального модуля объект из фабрики.

`vi.mock` **поднимается** в начало файла — выше всех `import`. Иначе тестируемый модуль успел бы загрузить оригинальную зависимость. Из-за этого фабрика выполняется раньше объявления переменных файла. Обращение к ним приводит к ошибке. Если переменная нужна и в фабрике, и в тестах, её объявляют через `vi.hoisted`.

Варианты:

- **без фабрики** — `vi.mock('./api')`: автомок, все экспортированные функции становятся `vi.fn()`, возвращающими `undefined`;
- **с фабрикой** — явная замена;
- **частичный мок** — `importOriginal` позволяет взять реальный модуль и заменить только часть экспортов.

В Jest работает похожий `jest.mock` с тем же hoisting (через Babel-плагин).

## Пример

```ts
// userService.ts
import { api } from '@/shared/api';
export async function getUserName(id: string) {
  const user = await api.get(`/users/${id}`);
  return user.name.toUpperCase();
}
```

```ts
// userService.test.ts
import { it, expect, vi } from 'vitest';
import { getUserName } from './userService';
import { api } from '@/shared/api';

vi.mock('@/shared/api', () => ({
  api: { get: vi.fn() },
}));

it('возвращает имя в верхнем регистре', async () => {
  vi.mocked(api.get).mockResolvedValue({ name: 'Анна' });

  await expect(getUserName('1')).resolves.toBe('АННА');
  expect(api.get).toHaveBeenCalledWith('/users/1');
});
```

`vi.mocked` ничего не делает в runtime — только сообщает TypeScript, что это мок.

Частичный мок и `vi.hoisted`:

```ts
const { navigateMock } = vi.hoisted(() => ({ navigateMock: vi.fn() }));

vi.mock('react-router-dom', async (importOriginal) => {
  const actual = await importOriginal<typeof import('react-router-dom')>();
  return { ...actual, useNavigate: () => navigateMock };
});
```

Все экспорты роутера остаются настоящими, подменён только `useNavigate`.

## Что важно помнить

- Путь в `vi.mock` должен совпадать с тем, как модуль резолвится (алиасы учитываются).
- Мок действует на весь файл. Для разных ответов в разных тестах меняйте реализацию `vi.fn`, а не сам `vi.mock`.
- `vi.doMock` — вариант без hoisting, влияет только на последующие динамические `import()`.
- Мокать свои модули — крайняя мера. Для сети лучше MSW: тест проверяет настоящий код запросов.
- Мок, который возвращает данные «не той формы», делает тест зелёным при сломанном приложении.

## Мини-шпаргалка

`vi.mock(path, factory)` → замена модуля в файле, поднимается вверх. Переменные для фабрики → `vi.hoisted`. Частично → `importOriginal`. Типы → `vi.mocked`.
