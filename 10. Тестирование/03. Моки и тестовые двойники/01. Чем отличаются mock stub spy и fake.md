# Mock, stub, spy и fake

> [!NOTE]
> Тестовый двойник (test double) заменяет реальную зависимость в тесте. Stub возвращает заготовленный ответ, spy записывает вызовы, mock — двойник с ожиданиями о вызовах, fake — упрощённая рабочая реализация. В Vitest и Jest всё это обычно делается через `vi.fn` / `jest.fn`.

## Вопрос

Что такое моки? Чем mock отличается от stub, spy и fake?

## Основная идея

Зависимость заменяют, когда она медленная (сеть, БД), недетерминированная (время, `Math.random`), имеет побочные эффекты (отправка письма, оплата) или ещё не написана. Классификацию предложил Gerard Meszaros, её популяризировал Martin Fowler:

| Двойник | Что делает | Пример |
| --- | --- | --- |
| Dummy | передаётся, но не используется | пустой callback для обязательного prop |
| Stub | возвращает заранее заданный ответ | `getUser` всегда возвращает «Анна» |
| Spy | записывает вызовы, может вызывать оригинал | `vi.spyOn(console, 'error')` |
| Mock | заранее запрограммирован ожиданиями и проверяется по ним | «`track` должен быть вызван с `'purchase'`» |
| Fake | рабочая упрощённая реализация | in-memory репозиторий, MSW-сервер, fake timers |

На практике во фронтенде слово «мок» используют для всего сразу. На собеседовании достаточно показать разницу: **stub** управляет входами в тестируемый код, **spy/mock** проверяет выходы — вызовы зависимостей.

Есть два стиля тестирования. **Проверка состояния** (state verification): выполнить действие и проверить результат. **Проверка поведения** (behavior verification): проверить, что зависимость вызвана с нужными аргументами. Первый стиль устойчивее к рефакторингу. Второй нужен, когда результат — именно вызов: аналитика, `onChange`, `navigate`.

## Пример

```ts
import { it, expect, vi } from 'vitest';
import { checkout } from './checkout';

it('отправляет событие аналитики после оплаты', async () => {
  // stub: управляет входом
  const paymentApi = { pay: vi.fn().mockResolvedValue({ status: 'ok' }) };
  // mock/spy: проверяем выход
  const analytics = { track: vi.fn() };

  await checkout({ total: 500 }, { paymentApi, analytics });

  expect(paymentApi.pay).toHaveBeenCalledWith(500);
  expect(analytics.track).toHaveBeenCalledWith('purchase', { total: 500 });
});
```

```ts
// fake: простая рабочая реализация
class InMemoryTodoRepo {
  private items = new Map<string, Todo>();
  async save(todo: Todo) { this.items.set(todo.id, todo); }
  async findAll() { return [...this.items.values()]; }
}
```

## Что важно помнить

- Зависимость, переданную явно (параметром, через props или контекст), заменить проще, чем импортированную.
- Fake часто лучше mock: тест проверяет результат, а не цепочку вызовов.
- Мокать стоит границы системы — сеть, время, хранилище, — а не собственные модули.
- Чем больше моков, тем меньше тест похож на реальность.

## Мини-шпаргалка

Stub → заданный ответ. Spy → запись вызовов. Mock → ожидания вызовов. Fake → упрощённая реализация. Мокаем границы: сеть, время, side effects.
