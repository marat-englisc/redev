# Visual regression тесты и Storybook

> [!NOTE]
> Visual regression тест делает скриншот компонента или страницы и сравнивает его с эталоном по пикселям. Он ловит то, что не видят тесты DOM: сломанную вёрстку, сдвиги, неверные цвета. Storybook даёт изолированные состояния компонентов, которые удобно тестировать визуально и интерактивно.

## Вопрос

Как проверить, что вёрстка не сломалась? Что такое Storybook и как его используют в тестировании?

## Основная идея

Тест RTL пройдёт, даже если кнопка уехала за край экрана или стала белой на белом фоне: в DOM всё правильно. jsdom не считает layout и не применяет внешний CSS. Визуальные проблемы ловят скриншотами в настоящем браузере.

Процесс: при первом запуске создаётся эталонный снимок и коммитится в репозиторий (или хранится в сервисе). При следующих запусках новый скриншот сравнивается с эталоном. Если отличие больше порога, тест падает и показывает diff-картинку. Ожидаемые изменения принимают обновлением эталона.

**Storybook** — среда для разработки компонентов в изоляции. История (story) — компонент в конкретном состоянии: `Primary`, `Disabled`, `Loading`, `WithLongText`. Истории служат одновременно документацией дизайн-системы, площадкой для ручной проверки и базой для тестов:

- **visual tests** — скриншот каждой истории (Chromatic, Playwright, Storybook Test);
- **interaction tests** — функция `play` выполняет действия пользователя в истории и проверяет результат;
- **accessibility tests** — аддон a11y запускает axe для каждой истории;
- **переиспользование в unit-тестах** — `composeStories` позволяет отрендерить историю в Vitest.

Главная трудность визуальных тестов — **стабильность**: шрифты, сглаживание, анимации, даты и разные ОС дают разные пиксели. Поэтому снимки делают в одинаковом окружении (Docker, CI), отключают анимации и фиксируют данные.

## Пример

Playwright:

```ts
import { test, expect } from '@playwright/test';

test('карточка товара выглядит как эталон', async ({ page }) => {
  await page.goto('/product/42');
  await expect(page.getByTestId('product-card')).toHaveScreenshot('product-card.png', {
    maxDiffPixelRatio: 0.01,
    animations: 'disabled',
  });
});
```

Обновление эталонов: `npx playwright test --update-snapshots`.

Storybook-история с interaction test:

```tsx
// LoginForm.stories.tsx
import type { Meta, StoryObj } from '@storybook/react-vite';
import { expect, userEvent, within } from 'storybook/test';
import { LoginForm } from './LoginForm';

const meta = { component: LoginForm } satisfies Meta<typeof LoginForm>;
export default meta;
type Story = StoryObj<typeof meta>;

export const Default: Story = {};

export const EmptySubmit: Story = {
  play: async ({ canvasElement }) => {
    const canvas = within(canvasElement);
    await userEvent.click(canvas.getByRole('button', { name: 'Войти' }));
    await expect(canvas.getByRole('alert')).toHaveTextContent('Введите email');
  },
};
```

## Что важно помнить

- Скриншоты целых страниц хрупкие — снимайте ключевые компоненты и состояния.
- Эталоны для разных ОС различаются; Playwright добавляет платформу в имя файла.
- Динамические области (дата, аватар) маскируют опцией `mask` или подставляют фиксированные данные.
- Chromatic — облачный сервис от авторов Storybook для визуальных проверок и ревью изменений.
- Пути импорта Storybook зависят от версии: в новых версиях утилиты тестов импортируются из `storybook/test`.

## Мини-шпаргалка

Visual regression = скриншот vs эталон. Ловит вёрстку, которую не видит jsdom. Storybook = изолированные состояния → визуальные, interaction (`play`) и a11y-тесты. Стабильность: одно окружение, без анимаций, фиксированные данные.
