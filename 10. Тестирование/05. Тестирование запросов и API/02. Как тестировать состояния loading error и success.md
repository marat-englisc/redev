# Состояния loading, error, empty и success

> [!NOTE]
> Каждый компонент, загружающий данные, имеет минимум четыре состояния: загрузка, ошибка, пустой результат и данные. Тест должен проверить каждое, управляя ответом сервера через MSW: задержкой, статусом и телом ответа.

## Вопрос

Как протестировать индикатор загрузки, сообщение об ошибке и пустое состояние списка?

## Основная идея

В реальном приложении ответ может прийти не сразу, вернуть 500, 401, пустой массив или данные. Разработчики чаще всего проверяют только успешный сценарий, а ошибки и пустые списки ломаются незаметно. MSW позволяет задать каждый сценарий в одну строку через `server.use`.

| Состояние | Как вызвать в тесте | Что проверить |
| --- | --- | --- |
| Loading | сразу после `render` или `delay()` в обработчике | индикатор, заблокированные действия |
| Success | обработчик по умолчанию | данные на экране, индикатор исчез |
| Empty | `HttpResponse.json([])` | текст пустого состояния, призыв к действию |
| Error | статус `500` или `HttpResponse.error()` | сообщение, кнопка «Повторить» |
| Unauthorized | статус `401` | редирект на вход или сообщение |
| Retry | ошибка, затем успех | после «Повторить» появились данные |

Для сценария «сначала ошибка, потом успех» обработчику передают опцию `{ once: true }`: он сработает один раз, после чего запросы обработает следующий подходящий обработчик.

## Пример

```tsx
import { http, HttpResponse, delay } from 'msw';
import { server } from '@/test/server';
import { renderWithProviders, screen } from '@/test/utils';
import userEvent from '@testing-library/user-event';
import { OrdersPage } from './OrdersPage';

describe('OrdersPage', () => {
  it('показывает загрузку, затем заказы', async () => {
    server.use(
      http.get('/api/orders', async () => {
        await delay(50);
        return HttpResponse.json([{ id: 'A-1', total: 1500 }]);
      }),
    );
    renderWithProviders(<OrdersPage />);

    expect(screen.getByRole('status')).toHaveTextContent('Загружаем заказы');
    expect(await screen.findByText('Заказ A-1')).toBeInTheDocument();
    expect(screen.queryByRole('status')).not.toBeInTheDocument();
  });

  it('показывает пустое состояние', async () => {
    server.use(http.get('/api/orders', () => HttpResponse.json([])));
    renderWithProviders(<OrdersPage />);

    expect(await screen.findByText('У вас пока нет заказов')).toBeInTheDocument();
    expect(screen.getByRole('link', { name: 'Перейти в каталог' })).toBeInTheDocument();
  });

  it('позволяет повторить запрос после ошибки', async () => {
    server.use(
      http.get('/api/orders', () => new HttpResponse(null, { status: 500 }), { once: true }),
    );
    const user = userEvent.setup();
    renderWithProviders(<OrdersPage />);

    expect(await screen.findByRole('alert')).toHaveTextContent('Не удалось загрузить заказы');

    await user.click(screen.getByRole('button', { name: 'Повторить' }));

    // следующий запрос обработает handler по умолчанию
    expect(await screen.findByText(/Заказ/)).toBeInTheDocument();
  });
});
```

## Что важно помнить

- Loading проверяют синхронно сразу после `render`: к первому `await` данные могут уже прийти.
- `HttpResponse.error()` и статус 500 — разные ветки кода: `fetch` отклоняется только при сетевой ошибке, а на 500 возвращает `response.ok === false`.
- Для TanStack Query в тестах отключают `retry`, иначе ошибка появится только после повторов.
- Проверяйте, что при ошибке не теряются введённые пользователем данные.
- Состояния удобно показать и в Storybook с тем же MSW — так их видят дизайнеры.

## Мини-шпаргалка

4 состояния: loading → `delay`, success → handler по умолчанию, empty → `[]`, error → `status: 500` / `HttpResponse.error()`. Retry → `{ once: true }`.
