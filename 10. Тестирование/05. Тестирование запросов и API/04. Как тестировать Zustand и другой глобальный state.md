# Тестирование Zustand, Redux и глобального state

> [!NOTE]
> Store тестируют двумя способами: логику — напрямую через `getState()` и actions, связку с UI — через рендер компонента с настоящим store. Главное правило — сбрасывать store перед каждым тестом, потому что модульный синглтон живёт между тестами файла.

## Вопрос

Как тестировать Zustand store? Нужно ли мокать store в тестах компонентов?

## Основная идея

Store Zustand, созданный через `create`, — модульная переменная. В рамках одного тестового файла все тесты работают с одним экземпляром. Если первый тест добавил товар в корзину, второй увидит его. Поэтому перед каждым тестом состояние возвращают к начальному: `useStore.setState(initialState, true)`. Второй аргумент `true` заменяет состояние целиком, а не сливает его с текущим.

**Тест логики store** не требует React: вызываем action через `getState()` и проверяем результат. Это быстрые unit-тесты для расчётов, переходов состояния и граничных случаев.

**Тест компонента** использует настоящий store. Можно заранее задать состояние через `setState`, отрендерить компонент и проверить UI. Мокать store не нужно — иначе тест не заметит ошибки в селекторах.

Документация Zustand предлагает автоматический сброс всех store через мок модуля `zustand` в `__mocks__`. Для небольших проектов достаточно ручного `beforeEach`.

**Redux Toolkit** тестируют похоже: редьюсеры — как чистые функции (`reducer(state, action)`), компоненты — через custom render, который создаёт новый store с `preloadedState` для каждого теста.

## Пример

```ts
// cartStore.ts
import { create } from 'zustand';

type Item = { id: string; price: number; qty: number };
type CartState = {
  items: Item[];
  add: (item: Omit<Item, 'qty'>) => void;
  total: () => number;
};

export const useCartStore = create<CartState>()((set, get) => ({
  items: [],
  add: (item) =>
    set((state) => {
      const existing = state.items.find((i) => i.id === item.id);
      return existing
        ? { items: state.items.map((i) => (i.id === item.id ? { ...i, qty: i.qty + 1 } : i)) }
        : { items: [...state.items, { ...item, qty: 1 }] };
    }),
  total: () => get().items.reduce((sum, i) => sum + i.price * i.qty, 0),
}));
```

```ts
// cartStore.test.ts
import { useCartStore } from './cartStore';

const initialState = useCartStore.getState();
beforeEach(() => useCartStore.setState(initialState, true));

it('увеличивает количество при повторном добавлении', () => {
  const { add } = useCartStore.getState();
  add({ id: '1', price: 500 });
  add({ id: '1', price: 500 });

  expect(useCartStore.getState().items).toEqual([{ id: '1', price: 500, qty: 2 }]);
  expect(useCartStore.getState().total()).toBe(1000);
});
```

```tsx
// CartBadge.test.tsx
it('показывает количество товаров из store', () => {
  useCartStore.setState({ items: [{ id: '1', price: 500, qty: 3 }] });
  render(<CartBadge />);
  expect(screen.getByText('В корзине: 3')).toBeInTheDocument();
});
```

Redux Toolkit:

```ts
import { cartSlice, addItem } from './cartSlice';

it('редьюсер добавляет товар', () => {
  const state = cartSlice.reducer(undefined, addItem({ id: '1', price: 500 }));
  expect(state.items).toHaveLength(1);
});
```

## Что важно помнить

- Сохраняйте `initialState` до первого теста: `getState()` вместе с функциями-actions.
- С middleware `persist` очищайте `localStorage`, иначе состояние восстановится из хранилища.
- В SSR и в тестах, где нужен независимый store, удобнее фабрика `createStore` + Context.
- Для Redux Toolkit не тестируйте отдельно `createSlice`-генерированные action creators — это код библиотеки.

## Мини-шпаргалка

Store-синглтон → сброс в `beforeEach` через `setState(initial, true)`. Логика → `getState().action()`. UI → настоящий store с заданным состоянием. Redux → reducer как чистая функция + новый store на тест.
