# Code coverage и почему 100% не цель

> [!NOTE]
> Code coverage показывает, какая доля кода выполнялась во время тестов. Метрика помогает найти непокрытые участки, но не говорит о качестве проверок: можно выполнить строку и ничего не проверить.

## Вопрос

Что такое покрытие кода? Какие метрики покрытия бывают? Нужно ли стремиться к 100%?

## Основная идея

Инструмент покрытия отмечает, какие части кода выполнились во время прогона тестов, и строит отчёт. Обычно считают четыре метрики:

| Метрика | Что считает |
| --- | --- |
| Statements | выполненные инструкции |
| Branches | пройденные ветки `if`, `?:`, `&&`, `??`, `switch` |
| Functions | вызванные функции |
| Lines | выполненные строки |

Самая информативная — **branches**: строка `if (discount > 0)` может быть выполнена, но ветка без скидки так и не проверена.

Покрытие отвечает на вопрос «что точно **не** проверено», но не на вопрос «что проверено хорошо». Тест без `expect`, который просто рендерит компонент, даёт высокое покрытие и почти нулевую пользу. Погоня за 100% приводит к тестам ради цифры: проверкам геттеров, констант и деталей реализации. Последние проценты стоят дороже всего и приносят меньше всего.

Практичный подход — разумный порог (часто 70–80%) как защита от резкого падения, и обязательное внимание к покрытию критичных модулей: расчёта цен, авторизации, валидации.

## Пример

В Vitest покрытие включается флагом. Нужен провайдер `@vitest/coverage-v8` (или `istanbul`).

```bash
npm install -D @vitest/coverage-v8
npx vitest run --coverage
```

```ts
// vitest.config.ts
import { defineConfig } from 'vitest/config';

export default defineConfig({
  test: {
    coverage: {
      provider: 'v8',
      reporter: ['text', 'html'],
      include: ['src/**/*.{ts,tsx}'],
      exclude: ['src/**/*.stories.tsx', 'src/**/*.d.ts'],
      thresholds: { lines: 80, branches: 75 },
    },
  },
});
```

Если покрытие опустится ниже порога, команда завершится с ошибкой и CI упадёт. HTML-отчёт подсвечивает непройденные строки и ветки.

## Что важно помнить

- 100% покрытия не означает отсутствия багов: не проверены комбинации входов и интеграции.
- Высокое покрытие без assertions бессмысленно.
- Мутационное тестирование (например, Stryker) проверяет качество тестов: вносит мутации в код и смотрит, упадут ли тесты.
- Из отчёта исключают сгенерированный код, stories, типы, конфиги.
- Покрытие удобно смотреть на diff в PR: новый код без тестов виден сразу.

## Мини-шпаргалка

Coverage = что выполнилось, а не что проверено. Главная метрика — branches. Порог 70–80% как страховка, критичный код — плотнее.
