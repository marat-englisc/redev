# Unit, integration и e2e тесты

> [!NOTE]
> Unit-тест проверяет одну единицу кода в изоляции. Интеграционный — совместную работу нескольких частей. E2E-тест проходит сценарий пользователя в настоящем браузере через всё приложение.

## Вопрос

Чем отличаются unit, integration и e2e тесты? Приведите пример каждого для фронтенда.

## Основная идея

**Unit-тест** проверяет функцию, хук или маленький компонент. Внешние зависимости — сеть, таймеры, другие модули — заменяются или отсутствуют. Такие тесты выполняются за миллисекунды и точно показывают место поломки. Минус: они не видят ошибок на стыке частей.

**Интеграционный тест** во фронтенде обычно означает: отрендерить компонент страницы вместе с дочерними компонентами, контекстом и роутером, имитировать действия пользователя и проверить результат. Сеть мокается на уровне HTTP (например, через MSW), но весь код приложения работает по-настоящему. Это основная часть тестов UI.

**E2E-тест (end-to-end)** запускает собранное приложение и настоящий браузер. Тест открывает страницу, кликает, вводит текст и проверяет, что заказ появился. Иногда работает с реальным бэкендом и тестовой БД. Даёт максимальную уверенность, но медленный, требует инфраструктуры и чаще бывает нестабильным.

Граница между unit и integration размыта. На собеседовании полезно сказать: «я считаю unit-тестом проверку одной функции или хука, а интеграционным — компонент с реальными детьми и замоканной только сетью».

## Пример

```ts
// unit: чистая функция
it('форматирует цену', () => {
  expect(formatPrice(1500)).toBe('1 500 ₽');
});
```

```tsx
// integration: компонент + дети + события + мок сети
it('добавляет товар в корзину', async () => {
  const user = userEvent.setup();
  render(<ProductPage id="42" />);
  await user.click(await screen.findByRole('button', { name: 'В корзину' }));
  expect(screen.getByText('В корзине: 1')).toBeInTheDocument();
});
```

```ts
// e2e: настоящий браузер, Playwright
test('покупатель оформляет заказ', async ({ page }) => {
  await page.goto('/product/42');
  await page.getByRole('button', { name: 'В корзину' }).click();
  await page.getByRole('link', { name: 'Корзина' }).click();
  await page.getByRole('button', { name: 'Оформить' }).click();
  await expect(page.getByText('Заказ оформлен')).toBeVisible();
});
```

## Сравнение

| Критерий | Unit | Integration | E2E |
| --- | --- | --- | --- |
| Скорость | мс | десятки–сотни мс | секунды |
| Окружение | Node | Node + jsdom | настоящий браузер |
| Моки | много | только сеть/границы | почти нет |
| Уверенность | низкая | высокая | максимальная |
| Точность диагностики | высокая | средняя | низкая |
| Стабильность | высокая | высокая | ниже |

## Что важно помнить

- jsdom — эмуляция DOM в Node, а не браузер: нет layout, реальных размеров, CSS-анимаций.
- То, что зависит от layout и настоящего рендера, проверяют в e2e или в browser mode.
- E2E покрывают критичные пути: вход, оплата, регистрация.
- Компонентные тесты в настоящем браузере (Vitest Browser Mode, Playwright CT) — промежуточный вариант.

## Мини-шпаргалка

Unit — одна функция. Integration — компонент с детьми и моком сети. E2E — пользовательский сценарий в браузере.
