# Playwright и Cypress

> [!NOTE]
> Cypress выполняет тесты внутри браузера рядом с приложением и известен удобным интерактивным раннером. Playwright управляет браузером снаружи через протоколы, поддерживает Chromium, Firefox и WebKit, несколько вкладок и доменов, бесплатную параллельность и обычный `async/await`.

## Вопрос

Чем отличаются Playwright и Cypress? Что выбрать?

## Основная идея

**Cypress** появился раньше и сделал e2e-тесты популярными у фронтендеров. Тест запускается в том же браузере, что и приложение. Отсюда сильные стороны: интерактивный режим с «машиной времени», где видно состояние на каждом шаге, простой доступ к `window` приложения, удобный перехват сети через `cy.intercept`. Команды Cypress выстраиваются в очередь (`cy.get(...).click()`), а не являются промисами, поэтому `await` с ними не используют.

Архитектура накладывает ограничения: одна вкладка, сложности с переходами между доменами (решаются через `cy.origin`), ограниченная поддержка WebKit. Параллельный запуск на нескольких машинах обычно настраивают через платный Cypress Cloud или сторонние решения.

**Playwright** управляет браузером извне. Тест — обычный async-код. Можно открыть несколько вкладок, страниц и контекстов (например, два пользователя в одном тесте), переходить между доменами, скачивать файлы и работать с iframe. Параллельность и шардирование встроены.

## Сравнение

| Критерий | Playwright | Cypress |
| --- | --- | --- |
| Архитектура | вне браузера (CDP и аналоги) | внутри браузера |
| Браузеры | Chromium, Firefox, WebKit | Chromium-семейство, Firefox, WebKit (экспериментально) |
| Синтаксис | `async/await` | цепочки команд `cy.*` |
| Вкладки, несколько пользователей | да | нет / ограниченно |
| Разные домены | без ограничений | через `cy.origin` |
| Параллельность | встроенная, бесплатная | Cypress Cloud или сторонние решения |
| Языки | JS/TS, Python, Java, .NET | JS/TS |
| Отладка | UI mode, trace viewer | интерактивный раннер с time travel |
| Компонентные тесты | есть (экспериментально) | зрелые |

## Пример

Один сценарий в двух фреймворках:

```ts
// Playwright
test('вход в аккаунт', async ({ page }) => {
  await page.goto('/login');
  await page.getByLabel('Email').fill('anna@example.com');
  await page.getByLabel('Пароль').fill('Secret_123');
  await page.getByRole('button', { name: 'Войти' }).click();
  await expect(page.getByRole('heading', { name: 'Мои задачи' })).toBeVisible();
});
```

```ts
// Cypress (+ @testing-library/cypress для findByRole)
it('вход в аккаунт', () => {
  cy.visit('/login');
  cy.findByLabelText('Email').type('anna@example.com');
  cy.findByLabelText('Пароль').type('Secret_123');
  cy.findByRole('button', { name: 'Войти' }).click();
  cy.findByRole('heading', { name: 'Мои задачи' }).should('be.visible');
});
```

## Что важно помнить

- Новый проект чаще начинают с Playwright: шире возможности и бесплатная параллельность.
- Cypress разумно оставить, если он уже есть, команда его знает и тесты стабильны.
- Оба фреймворка автоматически ждут элементы — `sleep`/`wait(ms)` не нужен ни там, ни там.
- На собеседовании важнее объяснить компромиссы, чем назвать «лучший» инструмент.

## Мини-шпаргалка

Cypress — внутри браузера, цепочки `cy.*`, удобный раннер, одна вкладка. Playwright — снаружи, `async/await`, 3 движка, вкладки и домены, параллельность из коробки.
