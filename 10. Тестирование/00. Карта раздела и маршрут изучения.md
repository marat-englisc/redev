# Карта раздела «Тестирование»

> [!NOTE]
> Раздел покрывает тестирование фронтенда для собеседования на middle: виды тестов и стратегию, Vitest/Jest, моки, React Testing Library, мок сети через MSW, e2e на Playwright, визуальные тесты, доступность, типы и CI.

## Вопрос

С чего начать изучение тестирования и в каком порядке читать раздел?

## Основная идея

Тестирование на собеседовании проверяют в трёх плоскостях: **понимание** (зачем тесты, какие бывают, что покрывать), **инструменты** (Vitest, RTL, MSW, Playwright) и **опыт** (как было устроено на проекте). Раздел построен в том же порядке.

Основной стек примеров: Vite + React + TypeScript, Vitest с jsdom, React Testing Library, user-event, jest-dom, MSW, Playwright. API Jest почти полностью совпадает с Vitest: `jest.fn` ↔ `vi.fn`, `jest.mock` ↔ `vi.mock`.

| Глава | Что внутри |
| --- | --- |
| 01. Основы | зачем тесты, пирамида и трофей, виды тестов, AAA, что тестировать, coverage, TDD |
| 02. Jest и Vitest | runner, настройка, `describe/it/expect`, matchers, async, хуки, снапшоты, `each` |
| 03. Моки | mock/stub/spy/fake, `vi.fn`, `vi.spyOn`, `vi.mock`, fake timers, глобальные API, вред моков |
| 04. React Testing Library | философия, `render`/`screen`, приоритет запросов, `getBy/queryBy/findBy`, user-event, `waitFor`, формы, хуки, провайдеры, jest-dom |
| 05. Запросы и API | MSW, состояния loading/error/empty, TanStack Query, Zustand и Redux |
| 06. E2E | Playwright, сравнение с Cypress, локаторы, авторизация и данные, flaky-тесты |
| 07. Другие виды | скриншотные тесты и Storybook, доступность, типы, CI |
| 08. Собеседование | антипаттерны, частые вопросы, рассказ о своём опыте |

## Пример: маршрут изучения

1. Прочитай [зачем нужны тесты](<01. Основы тестирования/01. Зачем нужны автоматические тесты.md>), [пирамиду и трофей](<01. Основы тестирования/02. Что такое пирамида и трофей тестирования.md>) и [виды тестов](<01. Основы тестирования/03. Чем отличаются unit integration и e2e тесты.md>).
2. Разберись, [что тестировать](<01. Основы тестирования/05. Что нужно тестировать а что нет.md>), — это главный вопрос на собеседовании.
3. [Настрой Vitest](<02. Jest и Vitest/02. Как настроить Vitest в React проекте.md>) в учебном проекте и напиши тесты для утилит: [matchers](<02. Jest и Vitest/04. Какие matchers нужно знать.md>), [async](<02. Jest и Vitest/05. Как тестировать асинхронный код.md>), [test.each](<02. Jest и Vitest/08. Что такое параметризованные тесты test each.md>).
4. Освой моки: [виды двойников](<03. Моки и тестовые двойники/01. Чем отличаются mock stub spy и fake.md>), [vi.fn и vi.spyOn](<03. Моки и тестовые двойники/02. Что делают vi.fn и vi.spyOn.md>), [fake timers](<03. Моки и тестовые двойники/04. Как работают фейковые таймеры.md>) — напиши тест на свой `debounce`.
5. Перейди к компонентам: [философия RTL](<04. React Testing Library/01. Что такое React Testing Library и её философия.md>), [приоритет запросов](<04. React Testing Library/03. Какой приоритет запросов использовать.md>), [getBy/queryBy/findBy](<04. React Testing Library/04. Чем отличаются getBy queryBy и findBy.md>), [user-event](<04. React Testing Library/05. Чем userEvent отличается от fireEvent.md>).
6. Протестируй форму и асинхронную загрузку: [формы](<04. React Testing Library/07. Как тестировать формы.md>), [waitFor и act](<04. React Testing Library/06. Как тестировать асинхронный UI и waitFor.md>), [MSW](<05. Тестирование запросов и API/01. Что такое MSW и зачем мокать сеть.md>), [состояния загрузки](<05. Тестирование запросов и API/02. Как тестировать состояния loading error и success.md>).
7. Собери [custom render с провайдерами](<04. React Testing Library/09. Как тестировать компоненты с провайдерами.md>) и протестируй [TanStack Query](<05. Тестирование запросов и API/03. Как тестировать компоненты с TanStack Query.md>) или [store](<05. Тестирование запросов и API/04. Как тестировать Zustand и другой глобальный state.md>).
8. Напиши 2–3 e2e на [Playwright](<06. E2E тестирование/01. Что такое e2e тесты и Playwright.md>) с [локаторами](<06. E2E тестирование/03. Как работают локаторы и auto-waiting в Playwright.md>) и [авторизацией](<06. E2E тестирование/04. Как авторизоваться и готовить данные в e2e.md>).
9. Подключи всё к [CI](<07. Другие виды тестирования/04. Как запускать тесты в CI.md>).
10. Перед собеседованием пройди [антипаттерны](<08. Собеседование/01. Какие антипаттерны встречаются в тестах.md>), [список вопросов](<08. Собеседование/02. Какие вопросы по тестированию задают на собеседовании.md>) и подготовь [рассказ о своём опыте](<08. Собеседование/03. Как рассказать про тестирование в своём проекте.md>).

## Что важно помнить

- Самая ценная практика — написать тесты для своего пет-проекта: на собеседовании о нём можно рассказать.
- Главная идея всего раздела: тестировать поведение, а не реализацию.
- Примеры даны для Vitest; для Jest замените `vi` на `jest` и уберите импорты из `vitest`.
