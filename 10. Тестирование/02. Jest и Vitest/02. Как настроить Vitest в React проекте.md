# Настройка Vitest в React-проекте

> [!NOTE]
> Для тестов React-компонентов нужны Vitest, DOM-окружение (jsdom), React Testing Library, user-event и jest-dom. Окружение и setup-файл задаются в конфиге Vitest.

## Вопрос

Как с нуля настроить тестирование React-компонентов в проекте на Vite?

## Основная идея

Компоненты рендерятся в DOM, а Node.js его не имеет. Поэтому указывают окружение `jsdom` — JavaScript-реализацию DOM. Для удобных запросов к DOM подключают React Testing Library, для реалистичных действий пользователя — `@testing-library/user-event`, для читаемых проверок вроде `toBeInTheDocument` — `@testing-library/jest-dom`.

**Setup-файл** выполняется перед каждым тестовым файлом. В нём подключают matchers jest-dom, запускают MSW-сервер и добавляют глобальные заглушки браузерных API, которых нет в jsdom.

Опция `globals: true` делает `describe`, `it`, `expect`, `vi` глобальными, как в Jest. Она же позволяет Testing Library автоматически вызывать `cleanup` после каждого теста: библиотека регистрирует его через глобальный `afterEach`.

## Пример

```bash
npm install -D vitest jsdom @testing-library/react @testing-library/dom @testing-library/user-event @testing-library/jest-dom
```

```ts
// vitest.config.ts
import { defineConfig } from 'vitest/config';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  test: {
    environment: 'jsdom',
    globals: true,
    setupFiles: ['./src/test/setup.ts'],
    restoreMocks: true,
  },
});
```

```ts
// src/test/setup.ts
import '@testing-library/jest-dom/vitest';
```

```json
// tsconfig.json (фрагмент)
{
  "compilerOptions": {
    "types": ["vitest/globals", "@testing-library/jest-dom"]
  }
}
```

```tsx
// src/components/Greeting.test.tsx
import { render, screen } from '@testing-library/react';
import { Greeting } from './Greeting';

it('приветствует пользователя по имени', () => {
  render(<Greeting name="Анна" />);
  expect(screen.getByRole('heading', { name: 'Привет, Анна!' })).toBeInTheDocument();
});
```

Если конфиг Vite уже есть, блок `test` можно добавить прямо в `vite.config.ts`, тогда алиасы вроде `@/` подхватятся автоматически.

## Что важно помнить

- `restoreMocks: true` восстанавливает моки и шпионов перед каждым тестом — меньше утечек между тестами.
- `happy-dom` — более быстрая, но менее полная альтернатива jsdom.
- В jsdom нет `matchMedia`, `IntersectionObserver`, `ResizeObserver`, `scrollTo` — их мокают в setup-файле.
- `@testing-library/dom` — peer-зависимость `@testing-library/react`, её ставят явно.
- Для Next.js есть официальные инструкции по Vitest и Jest; асинхронные Server Components лучше проверять e2e.

## Мини-шпаргалка

vitest + jsdom + RTL + user-event + jest-dom. Конфиг: `environment: 'jsdom'`, `globals`, `setupFiles`. Setup: matchers, MSW, заглушки API.
