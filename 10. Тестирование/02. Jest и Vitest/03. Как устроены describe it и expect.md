# describe, it и expect

> [!NOTE]
> `describe` группирует тесты, `it` (или `test`) объявляет один тест, `expect` создаёт проверку значения через matcher. Модификаторы `.only`, `.skip`, `.todo` управляют запуском.

## Вопрос

Из чего состоит тестовый файл? Чем `it` отличается от `test`? Что делают `.only` и `.skip`?

## Основная идея

Тестовый файл — обычный модуль. **`describe(name, fn)`** создаёт группу: в отчёте она выглядит как заголовок, внутри можно объявлять хуки `beforeEach` и вложенные группы. **`it(name, fn)`** и **`test(name, fn)`** — синонимы. `it` удобно читается по-английски: «it renders the list».

**`expect(value)`** возвращает объект с matchers: `toBe`, `toEqual`, `toHaveBeenCalled` и другими. Если проверка не проходит, matcher бросает ошибку, и тест помечается упавшим. `.not` инвертирует любую проверку.

Тест считается упавшим, если функция бросила ошибку или вернула отклонённый Promise. Если функция завершилась без ошибок — тест прошёл, даже без единого `expect`. Поэтому важно не забывать проверки.

Модификаторы:

| Модификатор | Что делает |
| --- | --- |
| `it.only` / `describe.only` | запустить только этот тест/группу в файле |
| `it.skip` | пропустить |
| `it.todo('...')` | заметка о тесте, который нужно написать |
| `it.each` | один тест на набор данных |
| `it.fails` (Vitest) | тест ожидаемо падает |

## Пример

```ts
import { describe, it, expect } from 'vitest';
import { applyDiscount } from './price';

describe('applyDiscount', () => {
  it('уменьшает цену на процент скидки', () => {
    expect(applyDiscount(1000, 10)).toBe(900);
  });

  it('не делает цену отрицательной', () => {
    expect(applyDiscount(100, 150)).toBe(0);
  });

  describe('некорректная скидка', () => {
    it('бросает ошибку для отрицательного процента', () => {
      expect(() => applyDiscount(100, -5)).toThrow('Скидка не может быть отрицательной');
    });
  });

  it.todo('округляет копейки по правилам бухгалтерии');
});
```

Обратите внимание: для `toThrow` в `expect` передаётся **функция**, а не результат вызова. Иначе ошибка вылетит до `expect`.

## Что важно помнить

- Не коммитьте `.only` — в CI выполнится только часть тестов. Линтер (`eslint-plugin-vitest` / `jest`) ловит это правило.
- Названия `describe` + `it` вместе должны читаться как предложение.
- Глубокая вложенность `describe` ухудшает читаемость — обычно хватает двух уровней.
- Код внутри `describe`, но вне `it` и хуков, выполняется на этапе сбора тестов — не делайте там асинхронной подготовки.

## Мини-шпаргалка

`describe` — группа, `it` = `test` — тест, `expect(x).matcher()` — проверка. `.only` не коммитим. `toThrow` принимает функцию.
