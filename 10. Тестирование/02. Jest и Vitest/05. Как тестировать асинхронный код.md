# Тестирование асинхронного кода

> [!NOTE]
> Асинхронный тест должен вернуть Promise или быть `async`-функцией с `await`. Для проверки результата промиса используют `await expect(promise).resolves` и `.rejects`. Забытый `await` — самая частая причина ложнозелёных тестов.

## Вопрос

Как тестировать функции, которые возвращают Promise? Почему тест может пройти, хотя код сломан?

## Основная идея

Runner ждёт завершения теста, только если тест вернул Promise. `async`-функция всегда возвращает Promise, поэтому достаточно написать `async` и ставить `await` перед каждой асинхронной операцией.

Если `await` забыть, тест завершится синхронно. Проверка внутри `.then` выполнится позже, когда runner уже отметил тест как пройденный, и её ошибка потеряется или упадёт в другом тесте. Такой тест зелёный при любом поведении кода.

Для отклонённых промисов удобно `await expect(promise).rejects.toThrow(...)`. Альтернатива — `try/catch` с `expect.assertions(n)`: эта проверка гарантирует, что внутри теста выполнилось ровно `n` проверок, и тест упадёт, если промис неожиданно выполнился успешно.

Callback-API (`done`) — устаревший стиль: Vitest его не поддерживает в обычном виде. Callback-функции лучше обернуть в Promise.

## Пример

```ts
import { describe, it, expect } from 'vitest';
import { fetchUser } from './api';

describe('fetchUser', () => {
  it('возвращает пользователя', async () => {
    const user = await fetchUser('1');
    expect(user.name).toBe('Анна');
  });

  it('то же через resolves', async () => {
    await expect(fetchUser('1')).resolves.toMatchObject({ name: 'Анна' });
  });

  it('отклоняется для несуществующего id', async () => {
    await expect(fetchUser('404')).rejects.toThrow('Пользователь не найден');
  });

  it('через try/catch и expect.assertions', async () => {
    expect.assertions(1);
    try {
      await fetchUser('404');
    } catch (error) {
      expect(error).toBeInstanceOf(Error);
    }
  });
});
```

Ложнозелёный тест для сравнения:

```ts
it('плохо: нет await', () => {
  expect(fetchUser('404')).rejects.toThrow(); // промис не дождались
});
```

Без `await` (или `return`) тест завершится до проверки. Современные версии Vitest предупреждают о незавершённых `.resolves/.rejects`, но полагаться на это не стоит.

## Что важно помнить

- `await expect(...).rejects` — `await` ставится перед `expect`, а не внутри.
- Для кода с таймерами используйте fake timers, а не реальные `setTimeout` в тестах.
- Сетевые запросы в unit/integration-тестах мокают (MSW, `vi.fn`), а не ходят в реальный API.
- Правило ESLint `@typescript-eslint/no-floating-promises` ловит забытые `await`.
- Для асинхронного UI используются `findBy*` и `waitFor` из Testing Library.

## Мини-шпаргалка

Тест `async` + `await` везде. Успех → `await expect(p).resolves`. Ошибка → `await expect(p).rejects.toThrow()`. Нет `await` → ложнозелёный тест.
