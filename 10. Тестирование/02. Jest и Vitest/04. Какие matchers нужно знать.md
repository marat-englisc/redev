# Основные matchers

> [!NOTE]
> Matcher — метод `expect`, описывающий ожидание. Главное различие: `toBe` сравнивает через `Object.is` (по ссылке для объектов), `toEqual` — рекурсивно по содержимому, `toStrictEqual` — по содержимому с учётом `undefined`-полей и классов.

## Вопрос

Какие matchers используются чаще всего? Чем `toBe` отличается от `toEqual` и `toStrictEqual`?

## Основная идея

Для примитивов используют `toBe`: `5`, `'text'`, `true`. Для объектов и массивов `toBe` проверяет, что это **тот же самый** объект в памяти, поэтому `expect({ a: 1 }).toBe({ a: 1 })` падает. Для сравнения содержимого нужен `toEqual`.

`toEqual` игнорирует свойства со значением `undefined` и не проверяет класс объекта. `toStrictEqual` строже: `{ a: 1, b: undefined }` не равен `{ a: 1 }`, а экземпляр класса не равен обычному объекту с теми же полями.

Для частичного сравнения есть `toMatchObject` и асимметричные matchers: `expect.any(Number)`, `expect.stringContaining('...')`, `expect.objectContaining({...})`. Они полезны, когда часть данных непредсказуема, например `id` или дата.

## Пример

```ts
// Равенство
expect(2 + 2).toBe(4);
expect({ id: 1, tags: ['a'] }).toEqual({ id: 1, tags: ['a'] });
expect({ a: 1, b: undefined }).toEqual({ a: 1 });       // проходит
expect({ a: 1, b: undefined }).not.toStrictEqual({ a: 1 }); // не равны

// Истинность и null
expect(value).toBeTruthy();
expect(user).toBeNull();
expect(result).toBeDefined();

// Числа
expect(0.1 + 0.2).toBeCloseTo(0.3);
expect(items.length).toBeGreaterThan(0);

// Строки и коллекции
expect(message).toMatch(/ошибка/i);
expect(['чай', 'кофе']).toContain('чай');
expect([{ id: 1 }]).toContainEqual({ id: 1 });
expect(list).toHaveLength(3);
expect(user).toHaveProperty('address.city', 'Казань');

// Частичное сравнение
expect(order).toMatchObject({ status: 'paid' });
expect(order).toEqual({
  id: expect.any(String),
  status: 'paid',
  createdAt: expect.any(Date),
});

// Ошибки
expect(() => parse('')).toThrow('Пустая строка');
expect(() => parse('')).toThrow(ValidationError);

// Моки
expect(onSave).toHaveBeenCalledTimes(1);
expect(onSave).toHaveBeenCalledWith({ title: 'Купить хлеб' });
expect(onSave).toHaveBeenLastCalledWith(expect.objectContaining({ done: true }));
```

## Что важно помнить

- `0.1 + 0.2` не равно `0.3` из-за IEEE 754 — используйте `toBeCloseTo`.
- `toBeTruthy` слишком широк: `'0'`, `[]` и `{}` тоже truthy. Лучше проверять конкретное значение.
- Matchers для DOM (`toBeInTheDocument`, `toHaveTextContent`) приходят из jest-dom, а не из runner-а.
- Можно писать свои matchers через `expect.extend`.
- `expect.soft` в Vitest продолжает тест после неудачной проверки и собирает все ошибки.

## Мини-шпаргалка

Примитивы → `toBe`. Объекты → `toEqual`. Строго → `toStrictEqual`. Часть объекта → `toMatchObject` / `expect.objectContaining`. Дроби → `toBeCloseTo`. Ошибки → `toThrow(() => ...)`.
